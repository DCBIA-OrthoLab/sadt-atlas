MedX — resuma laudos e depois monte um painel

Apesar do nome, o MedX nunca olha para uma imagem: ele lê laudos clínicos escritos (.pdf, .docx, .txt), faz um modelo de linguagem local transformar cada um em um resumo estruturado e pode depois reunir uma coorte inteira desses resumos em uma única página de gráficos. São duas etapas distintas, e vale conhecê-las antes de começar.

Quando usar

Quando você tem uma pilha de laudos em texto livre — exame clínico, exame radiográfico, notas de consulta — e quer extrair deles os indicadores clínicos (idade, dor, sono, abertura bucal etc.) sem ler cada um à mão. Com esses resumos em mãos, a segunda metade do MedX permite ver a coorte inteira de relance: distribuição por idade, distúrbios associados, escores médios.

Dois caminhos independentes

O MedX tem duas abas, dois botões, e nada os encadeia automaticamente. Summarize (resumir) lê seus documentos e escreve um arquivo de resumo por paciente. Dashboard (painel) relê esses resumos e produz a página de gráficos. Quando a sumarização termina, cabe a você trocar de aba e lançar o painel — ele não começa sozinho.

O que ele precisa, o que você obtém

Caminho Summarize

A fornecer

  • Uma pasta plana de laudos em .pdf, .docx ou .txt (sem subpastas)
  • Nomes de arquivo em que tudo o que vem antes do primeiro "_" é o ID do paciente — vários arquivos com o mesmo ID são agrupados e resumidos juntos
  • O modelo de sumarização, baixado uma única vez

O que sai

  • Um arquivo <patient-id>_summary.txt por paciente, em texto livre
  • Seus documentos de origem ficam intactos

Caminho Dashboard

A fornecer

  • A pasta de resumos produzida pelo caminho Summarize (os arquivos devem terminar em _summary.txt)

O que sai

  • Uma imagem dashboard.png: idade, sono, dor articular e muscular, abertura bucal, para a coorte inteira
  • Uma tabela patient_data.csv com uma linha por paciente

Passo a passo

Resumir os laudos

  1. Baixe o modelo. Só é preciso uma vez; sem ele, o caminho Summarize não tem com o que trabalhar.
  2. Indique a pasta de laudos, nomeados com um ID de paciente antes do primeiro "_".
  3. Defina uma pasta de saída e execute. Uma barra de progresso acompanha os pacientes à medida que são processados.
  4. Leia os resumos obtidos antes de confiar neles — veja abaixo.

Montar o painel

  1. Passe para a aba Dashboard. Isso não acontece sozinho depois da sumarização.
  2. Defina como entrada a pasta de resumos da etapa anterior.
  3. Defina uma pasta de saída e execute. Na primeira execução, o Slicer pode pedir para instalar alguns pacotes Python (pandas, matplotlib) — aceite.
  4. Marque "Load in 3D Slicer" se quiser que a imagem do painel abra diretamente em uma vista da cena.

Lendo o resultado

O resumo de cada laudo vem de um modelo generativo: ele escreve texto livre, não um formulário garantido. O formato key: value que o painel espera é um hábito que o modelo aprendeu, não uma regra imposta — uma linha malformada é simplesmente descartada e fica faltando no painel, em silêncio. O modelo também sorteia parte da sua saída: rodar de novo o resumo sobre o mesmo documento não produz exatamente o mesmo texto duas vezes. Por esses dois motivos, um resumo gerado pelo MedX é um ponto de partida a ser relido, não um laudo validado — não o use tal como está para uma decisão clínica.

Se algo der errado

O botão de download do modelo não faz nada

Clicar no botão de download cria a pasta esperada, mas nunca coloca nenhum arquivo nela: o campo fica vazio e aparece uma mensagem de aviso. Baixe você mesmo o arquivo do modelo na página de releases do GitHub do repositório SlicerAutomatedDentalTools (o arquivo BART.zip, na release "MedX"), descompacte-o e aponte o módulo para essa pasta.

A barra de progresso do painel nunca se mexe

Ao contrário do caminho Summarize, a barra de progresso do Dashboard fica parada durante toda a execução. Isso não é sinal de travamento: deixe rodar e espere dashboard.png aparecer na pasta de saída.

Uma pasta de entrada vazia derruba o módulo

Rodar qualquer um dos caminhos numa pasta sem nenhum documento utilizável levanta um erro em vez de uma mensagem clara. Confira se a pasta escolhida realmente contém arquivos antes de executar.

Duas execuções, dois resumos diferentes

O modelo não é determinístico: rodar de novo o caminho Summarize sobre exatamente os mesmos documentos não reproduz o resumo anterior palavra por palavra. Se você precisa comparar resultados ao longo do tempo, guarde os arquivos _summary.txt que já tem em vez de regenerá-los.

Para saber mais

Sobre o próprio MedX

  • Gaydamour et al., CLIP 2025 (LNCS 16126) — AI-Driven Multimodal TMJ Patient Modeling: From Unstructured Notes to Precision Treatment. O artigo do pipeline no qual o MedX é o elo de texto: passar de relatórios livres a dados utilizáveis.

Em torno do método

  • Lewis et al., ACL 2020 — BART: Denoising Sequence-to-Sequence Pre-training for Natural Language Generation, Translation, and Comprehension. O modelo de base que o MedX ajusta (fine-tune). Explica o que o sumarizador consegue fazer — e que ele reformula, portanto pode inventar.
  • Bianchi et al., Seminars in Orthodontics 2021 — Decision Support Systems in Temporomandibular Joint Osteoarthritis. O contexto clínico: a qual decisão esses dados extraídos devem servir.

Usando o VISOR: execute as ferramentas em um servidor a partir do 3D Slicer

Com o VISOR, o cálculo deixa de rodar no seu computador. Você escolhe uma ferramenta no Slicer, os arquivos selecionados são enviados a um servidor, o servidor calcula e o resultado volta para a sua cena. Esta página cobre o que você precisa configurar, o que precisa fornecer e o que verificar antes de enviar dados de pacientes. Como o VISOR é construído está no Atlas do VISOR.

cliente: implementado e testado desidentificação: não implementada MRI2CBCT: não incluído
Antes de usar dados de pacientes

O cliente VISOR envia seus arquivos como estão em disco. Nada é desidentificado. Veja O que sai da sua máquina.

O que muda para você

O restante deste site descreve a extensão legada, SlicerAutomatedDentalTools: cada módulo roda no seu próprio computador. O VISOR é outra extensão do Slicer, AutomatedDentalToolsRemote. Seus módulos são painéis finos sobre um servidor remoto.

  • O cálculo sai do seu computador. Um laptop que não consegue executar uma segmentação ainda pode pedir uma.
  • Nada para instalar no Python do Slicer, e nenhum modelo para baixar: a extensão não declara dependência de outras extensões, e os modelos ficam no servidor.
  • O formulário vem do servidor. O painel de uma ferramenta é construído quando você o abre, a partir da descrição que o servidor publica. Um campo acrescentado no servidor aparece no Slicer sem um novo lançamento da extensão.
  • Você precisa de um servidor, um endereço e uma chave. Configurar um é assunto do servidor, não desta página; veja implantação.

Fontes: AutomatedDentalToolsRemote CMakeLists.txt:10,15 e README.md:3-8, 150-165 (commit 19b95e8).

Instalar a extensão

O README e o arquivo de build dizem o seguinte, e nada além disso é presumido aqui.

  • A extensão é a AutomatedDentalToolsRemote. Ela funciona com as versões estável e nightly do 3D Slicer, e seus módulos aparecem na categoria Automated Dental Tools Remote.
  • Ela não lista nenhuma dependência de extensão (EXTENSION_DEPENDS "NA"): você não precisa do SlicerConda, do SlicerDentalModelSeg nem do NNUNet para ela.
  • O README declara que ela está listada no Extensions Catalog durante a transição.
  • Não a instale ao lado da extensão legada. O README pede que se use uma ou a outra, porque muitos módulos têm o mesmo nome e o Slicer mantém apenas um de dois módulos de mesmo nome.

Conectar o Slicer a um servidor

Abra Server Tools Settings (categoria Automated Dental Tools Remote.Advanced). Até que você salve algo aqui, o endereço é um marcador (https://set-your-server.invalid) que não alcança nada, então nenhum arquivo sai da sua máquina.

A fornecer

  • URL do servidor: um endereço https:// cujo certificado seja assinado por uma autoridade pública.
  • Chave de API: o token de API do servidor (o campo é mascarado). O README diz para usar o token de API, nunca o token de administrador.
  • Timeout: de 1 a 3600 segundos, 600 por padrão.

O que você não pode mudar

  • Nenhum http://, nem mesmo http://localhost.
  • O certificado é sempre verificado: o painel mostra "Verify TLS: Always on", sem nada para marcar.
  • Os redirecionamentos nunca são seguidos.

Clique em Save. A mudança se aplica de imediato e é mantida entre reinicializações. Se você digitar um endereço http://, o Slicer o recusa antes de salvar qualquer coisa. Restore defaults apaga o que você salvou.

Um servidor no seu próprio computador segue a mesma regra: o cliente não aceita o certificado autoassinado do próprio servidor, então você o alcança por um endereço público, por exemplo um endereço tailscale serve (https://<name>.<tailnet>.ts.net), ou por um proxy reverso com um certificado Let's Encrypt ou institucional.

O servidor está acessível? Não há botão "Test connection". O painel mostra no topo uma linha "Server: online" ou "Server: offline", atualizada quando você abre o módulo e após cada salvamento. Ela só consulta a página /health do servidor, que não exige chave: "online" não prova que a sua chave é aceita. Uma chave errada aparece na primeira execução (veja Se algo der errado).

A chave é armazenada em texto claro

O Slicer salva a chave no seu próprio arquivo de configurações do seu usuário, em texto simples. O campo mascarado só a oculta na tela. Qualquer pessoa que possa ler as configurações do seu Slicer pode ler a chave.

O HTTPS não tem alternativa

Não há configuração, flag ou arquivo que relaxe a regra do HTTPS ou a verificação do certificado. Um endereço http:// salvo por uma versão mais antiga do cliente é ignorado na inicialização.

Executar uma ferramenta

  1. Escolha uma ferramenta na lista de módulos. Ela constrói o seu formulário a partir do servidor ao abrir. Se o servidor não puder ser alcançado, o painel informa que não conseguiu carregar a ferramenta e oferece um botão Retry.
  2. Preencha o formulário. O que você fornece depende da ferramenta; os nomes dos campos vêm do servidor, então leia a página de Guia de cada ferramenta.
  3. Clique em Apply. O painel verifica primeiro o formulário (argumento desconhecido, arquivo ausente, campo obrigatório ausente) antes de enviar qualquer coisa.
  4. Acompanhe o progresso e cancele se precisar.

O que você pode fornecer como entrada

  • Um arquivo é enviado como está, com o mesmo nome e os mesmos bytes.
  • Uma pasta é empacotada em um arquivo compactado que mantém os nomes de seus arquivos e subpastas, e então é enviada.
  • Um nó da cena do Slicer (um volume, um modelo, uma região de interesse) é exportado para um arquivo temporário, nomeado segundo a ferramenta e o argumento, não segundo o nó. O AutoCrop3D, por exemplo, obtém sua região de interesse da cena dessa forma.
  • Um arquivo de teste hospedado é um exemplo que o servidor oferece para a ferramenta. Escolher um o baixa primeiro (em segundo plano, a janela do Slicer continua utilizável) e depois o usa como entrada. Uma segunda escolha da mesma entrada na mesma sessão reutiliza o download.
  • Um modelo escolhido no servidor é selecionado pelo nome em uma lista que o servidor publica. Só o nome viaja; o arquivo do modelo nunca é enviado do seu computador. Se a lista estiver vazia e o argumento não tiver outra forma de ser informado, o painel mostra um aviso para consultar quem mantém o servidor.

Entradas grandes são enviadas em partes e verificadas parte por parte. Se o servidor publicar um plano de tamanho para uma pasta de coorte, o painel a divide em lotes, cada um uma execução comum.

Progresso, cancelamento, conexão perdida

  • O painel relata as próprias fases do servidor: pedido recebido, preparação dos arquivos de entrada, espera pela GPU, execução no servidor, empacotamento dos resultados, concluído. Um tempo decorrido corre ao lado. Uma execução na fila mostra "queued".
  • Cancel interrompe também a execução no servidor. Há um Cancel por execução; com várias execuções ele diz "Cancel all", e uma coorte diz "Cancel the cohort". Uma execução cancelada não é relatada como erro.
  • Se a conexão cair enquanto o servidor trabalha, o painel se reconecta sozinho ao fluxo de progresso e retoma de onde parou, sem repetir o que já mostrou. É o modo desacoplado (detached), ativado por padrão: o pedido termina assim que as entradas são preparadas e o resultado chega pelo fluxo de progresso, de modo que o timeout das configurações não limita mais a duração de uma execução.
Parar para revisão usa o modo bloqueante

Se você armar uma etapa "stop after" (veja Revisão de qualidade), a execução não usa o modo desacoplado: o servidor devolve o material de revisão na resposta ao pedido original. Nesse caso vale o timeout de Server Tools Settings, e uma conexão perdida perde a resposta.

Obter os resultados

  • Quando a execução termina, o painel baixa o resultado (em faixas paralelas), verifica o arquivo compactado e o descompacta na pasta de saída. Por padrão, essa pasta é "Slicer Output" em Documentos.
  • Um arquivo compactado é recusado antes que qualquer coisa seja gravada se contiver caminhos absolutos, .., links, mais de 100 000 entradas ou mais de 20 GB.
  • A caixa de seleção "Load the results into the scene when done" importa o que a ferramenta produziu: volumes, mapas de rótulos, modelos ou landmarks, conforme a ferramenta. No máximo 12 itens são carregados por padrão; acima disso, o painel avisa que são demais para carregar de uma vez.
  • Algumas ferramentas acrescentam suas próprias opções ou mensagens: o ALI resume o seu relatório de execução e pede confirmação acima de 20 arquivos de landmarks; o VFACE tem uma caixa "Load the heat maps"; o AutoMatrix tem uma caixa "Use the mirror matrix". O CNE não carrega nada na cena e mostra um resumo na barra de status.
  • A cópia do resultado no servidor é apagada depois do seu download.

Revisão de qualidade com o VISU

Algumas ferramentas podem parar depois de uma etapa para que você confira o resultado intermediário. O formulário mostra então uma seção "Quality control" com uma escolha múltipla stop_after; nada vem marcado por padrão. As ferramentas que chamam outras ferramentas a oferecem, por exemplo o ALI para scans intraorais ou o VFACE.

  1. Parar. O servidor faz uma pausa depois da etapa que você marcou. O painel mostra "Stopped after <step>, waiting for your review", baixa o que foi produzido até aqui e abre o VISU sobre isso.
  2. Revisar. O VISU mostra um paciente por vez: scan, máscaras, superfícies e landmarks juntos. As teclas de seta vão ao caso anterior ou ao seguinte. Use Flag para marcar um paciente e Go to next flagged para saltar. Leia a linha "Drawn on <scan>" (ela diz sobre qual scan os landmarks são desenhados e se ele foi encontrado ao lado dos pontos ou presumido).
  3. Corrigir. Para landmarks, você pode arrastar pontos e Save: só os pontos que você moveu são reescritos, associados pelo nome. Undo my changes e Revert to what is on disk os restauram. Um ajuste de registro é salvo como um arquivo de transformação separado ao lado da cena, nunca mesclado à transformação da própria ferramenta.
  4. Continuar. Só os arquivos cujo conteúdo mudou são enviados de volta, e então o servidor retoma a execução.
  5. Voltar. Quando uma etapa anterior pode ser corrigida (landmarks ou um registro), a bandeira diz "Go back and edit this patient". Depois que você sinalizar alguns, o botão verde diz "Go back to <step> for N patient(s)": suas correções são gravadas, os pacientes sinalizados são refeitos a partir dessa etapa e todos os outros mantêm o resultado que já têm.

Se o VISU não for encontrado, ou se a parada não tiver produzido nada para olhar, o painel informa isso e retoma a execução imediatamente, para que nada fique em pausa no servidor com os seus dados.

O VISU também funciona em qualquer pasta

Você pode abrir o VISU em qualquer pasta que uma ferramenta tenha gravado, sem servidor envolvido: ele associa o scan, as máscaras, as superfícies e os landmarks de cada paciente pelo nome do arquivo. A única coisa que ele busca em um servidor são conjuntos de dados de exemplo hospedados.

O que sai da sua máquina

Nada é desidentificado

Não existe hoje nenhuma ferramenta de desidentificação no VISOR. O que você seleciona é enviado ao servidor como está em disco: nomes de arquivos, cabeçalhos DICOM e todos os identificadores que eles carregam. Um pipeline de desidentificação está especificado no repositório do cliente, mas o README dele declara que não está implementado, e uma busca no código não encontra nenhuma implementação.

  • O aviso. Depois que você salva um endereço de servidor que não é este computador, o Slicer mostra uma vez por servidor: "Files are uploaded unmodified. This client does not de-identify anything... De-identify your data before selecting it, or confine use to data that carries no protected health information." É um aviso, não uma verificação: não impede nada.
  • As pastas mantêm seus nomes. Uma pasta é empacotada com os nomes originais de seus arquivos e subpastas. Um nó da cena é exportado com um nome genérico, então o nome do nó não sai.
  • O CNE envia notas clínicas. O modelo de texto roda no servidor: as notas sobem e as extrações voltam. A página do CNE legado, que diz que nada sai da sua máquina, não se aplica ao VISOR.
  • Somente transporte. O HTTPS protege a transferência. Não há criptografia dos arquivos além dela do lado do cliente.
  • O Medical Data Anonymizer ainda existe, mas trata documentos de texto nesta máquina e não faz parte do que é enviado.
  • Aponte o cliente apenas para um servidor que a sua instituição controle e confira se o acordo com quem o opera cobre os dados que você envia. O README pede o mesmo.

O quadro de segurança, incluindo o que o servidor protege e o que não protege, está em Segurança do VISOR.

Se algo der errado

Na maioria das falhas, o Slicer mostra a própria mensagem do servidor. Veja o que cada uma significa.

"The server URL must start with https://"

Você digitou um endereço http://, ou o Slicer encontrou um de uma versão mais antiga. Use o endereço público https://; não há como contornar a regra, inclusive para um servidor no seu próprio computador.

401: falha de autenticação

A chave está errada ou ausente. O painel ainda pode dizer "Server: online" porque a página de saúde não exige chave. Digite a chave de novo em Server Tools Settings e clique em Save.

503 durante uma janela de manutenção

Enquanto o servidor está sendo atualizado, ele recusa trabalho novo com um 503 e um cabeçalho Retry-After: 10, por no máximo 300 segundos. O cliente não lê esse cabeçalho: você vê a mensagem do servidor, ou "Server error (503)". Espere e clique em Apply de novo. A leitura de resultados já em andamento não é bloqueada.

422: argumentos inválidos

O servidor nomeia o argumento problemático, por exemplo uma opção fora da lista aceita. Corrija o campo que ele nomeia. Um "400" com uma mensagem sobre tipo de arquivo significa que a extensão do arquivo não é aceita por essa ferramenta.

413: arquivo grande demais

O servidor recusa um envio acima do seu limite, 500 MB por arquivo por padrão. Para uma coorte grande, forneça uma pasta em vez de um único arquivo compactado enorme, para que ela possa ser dividida em lotes.

500: "The tool failed on the server"

É tudo o que o cliente mostra para uma falha dentro de uma ferramenta, de propósito: os detalhes podem conter elementos internos do servidor. Peça a quem opera o servidor que leia o seu log.

  • Timeouts. O timeout em Server Tools Settings (600 s por padrão) vale para pedidos que permanecem abertos. No modo desacoplado, que é o padrão, uma execução longa não é interrompida por ele. O servidor não tem limite de tempo de execução por padrão.
  • Espera em uma fila. Uma execução pode esperar pela GPU: o painel diz "Waiting for the GPU", e você pode cancelar enquanto ela espera. O servidor também limita quantas execuções rodam ao mesmo tempo, então uma quinta execução pode esperar antes mesmo de aparecer como queued.
  • Servidor offline. Se a lista de ferramentas não puder ser carregada, o painel informa isso e mostra Retry. Confira o endereço e "Server: online" em Server Tools Settings.
  • Uma mudança em config.py não tem efeito. O que você salvou em Server Tools Settings sempre prevalece sobre os padrões compilados.

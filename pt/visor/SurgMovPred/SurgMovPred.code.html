3. O pipeline

Explicação em linguagem simples e matemática: página do atlas.

3.1 Carga dos pacotes de modelo

Explicação em linguagem simples e matemática: página do atlas.

model é opcional e oculto. Quando está vazio, run() usa <data_root>/Surg_Mov_Pred/models (__init__.py:19,22-34,71). load_model_packages então pega todo stacking_package.pkl abaixo dele, em ordem alfabética, e carrega cada um com joblib (pipeline.py:162-195):

package_files = sorted(model.glob("**/stacking_package.pkl"))   # legacy: list(...), filesystem order
for pkl_path in package_files:
    package = joblib.load(pkl_path)        # {target_name, features_names, scaler, model}
    packages[package["target_name"]] = package

Um pacote ilegível é registrado no log e ignorado; se nenhum carrega, RuntimeError (pipeline.py:180-192). O comentário em layout.py:16-24 descreve o conjunto distribuído: 112 pacotes, cada um pedindo as mesmas 145 colunas, das quais 28 levam o sufixo _T0 (estado pré-operatório) e 25 o sufixo _Total (o movimento total planejado). A tabela, portanto, contém o plano e também as medidas, daí o rótulo "Measurements and plan". Os stacking regressors contêm subestimadores LightGBM, então o lightgbm precisa estar instalado para que joblib.load funcione (pyproject.toml:18-20). Os pacotes foram serializados com pickle no scikit-learn 1.6.1 e são carregados no 1.7.2; o aviso de versão é silenciado de propósito, como fazia o upstream (pipeline.py:101-115, README.md:72-75).

3.2 Leitura das medidas

Explicação em linguagem simples e matemática: página do atlas.

  • Um arquivo ou uma pasta plana. Um arquivo é lido pela extensão: .csv com read_csv, .xlsx com read_excel, .ods com read_excel(engine="odf") (pipeline.py:22,118-129). Uma pasta não é percorrida recursivamente: seus arquivos com uma das três extensões, sem distinguir maiúsculas de minúsculas, são ordenados e concatenados linha a linha (:132-159). O legado lia apenas uma pasta, listando extensões em minúsculas e em maiúsculas e removendo duplicatas com set(), de modo que a ordem das linhas mudava entre execuções (legado SurgMovPred_CLI/SurgMovPred_CLI.py:151-157).
  • Identificador do paciente. find_id_column tenta oito padrões em ordem (#, id, id patient, patient id, patient number, subject id, patient, subject, sem distinguir maiúsculas de minúsculas), depois qualquer coluna cujo nome contenha "patient" e "id" (pipeline.py:65-98). Sem nenhuma, IDPatient fica vazio, com um aviso (:303-312).
  • Os nomes de colunas são limpos para a forma usada no treino por clean_name: remove espaços das pontas, tira aspas, barras invertidas e colchetes, toda sequência de caracteres que não sejam letras, dígitos, sublinhado e apóstrofo vira um único sublinhado, total vira Total, e um dígito inicial recebe f_ (pipeline.py:27-50). Um nome que não pode ser limpo levanta ValueError (:51-60); o legado devolvia 'f_unnamed', então duas colunas assim se sobrepunham (legado SurgMovPred_CLI.py:63-66).

A única tolerância é o sufixo _T0 ausente; qualquer outra coluna ausente remove aquele alvo da saída, com um aviso (pipeline.py:224-236). Uma exceção ao predizer um alvo é registrada no log e o laço continua (:249-250). Uma célula em branco não é preenchida: ela chega ao scaler como NaN e o modelo levanta erro nela, então aquele alvo é descartado para todas as linhas (os pacotes contêm um ElasticNetCV; um stack substituto em um scikit-learn atual levantou ValueError: Input X contains NaN; os pacotes distribuídos não foram executados). Se nenhum alvo foi predito, a execução levanta RuntimeError em vez de gravar tabelas sem predições (:252-264). O legado gravava essas tabelas.

8. Constatações no VISOR

Explicação em linguagem simples e matemática: página do atlas.

Coluna de índice sem nome nas duas tabelas

Os dois arquivos de resultado começam com uma coluna contendo 0, 1, 2 e assim por diante, antes de IDPatient (pipeline.py:283-284). A CLI legada faz o mesmo (legado SurgMovPred_CLI/SurgMovPred_CLI.py:268-269). Leve isso em conta ao ler as posições das colunas.

Comentários desatualizados no cliente

O cliente diz que output_kind "is file" (Remote SurgMovPredRemote/SurgMovPredRemote.py:44) e o widget base dá "SurgMovPred's single predictions_outputs.xlsx" como exemplo (Remote ServerToolsCore/ServerToolsCoreLib/base_widget.py:1390-1391). A ferramenta devolve dois arquivos, que o código de schema publica como um conjunto de arquivos (VISOR-serve server/registry/schema_tool.py:100-103). O painel ainda os trata, já que descompacta qualquer zip que receba.

Caminho de dados desatualizado no README

O README da ferramenta dá a pasta de modelos como /DATA/SurgMovPred/models (README.md:45), enquanto o código procura em Surg_Mov_Pred (__init__.py:19,34), o nome que o manifesto de dados também usa (VISOR-serve scripts/data-manifest.yml:91). O código é a referência.

Ainda vale do legado: alvos independentes, nada aplicado à cena

Cada alvo é um model.predict separado sobre a mesma linha (pipeline.py:216-247), então os deslocamentos preditos dos pontos de um mesmo segmento rígido não são forçados a concordar entre si (página legada, armadilhas). A saída são apenas as duas tabelas: nenhuma transformação, nenhum nó do Slicer, e o painel salva o arquivo compactado em vez de carregar qualquer coisa (RESULT_KIND = "save_as", Remote SurgMovPredRemote.py:46). Lido no código.

Um alvo ignorado só é visível no log do servidor

Um pacote cujas features faltam na tabela é ignorado com um logger.warning, e um alvo que falha ao predizer, com um logger.exception (pipeline.py:234-236,249-250). A execução então termina com sucesso e menos colunas. Não há arquivo de relatório, então o usuário só percebe os alvos ausentes contando as colunas. A única proteção é o caso do tudo ou nada (:252-264). Lido no código.

Verificado: ordem reprodutível e nenhum resultado vazio silencioso

Pacotes e tabelas são ordenados, então duas execuções sobre a mesma entrada dão as mesmas linhas e colunas na mesma ordem (pipeline.py:143-147,173); uma execução em que nenhum modelo prediz é um erro, não duas tabelas vazias (:252-264); um nome de coluna ruim é um erro, não uma feature sobreposta (:51-60). Lido no código.

SurgMovPred

Entra uma planilha de medidas cefalométricas, sai uma planilha de deslocamentos ósseos preditos: 112 regressores scikit-learn empilhados, um por alvo, sem rede neural, sem imagem e sem malha.

não publicado SurgMovPred_CLI sem conda — o próprio Python do Slicer Bibliografia

Predição dos movimentos cirúrgicos de uma cirurgia ortognática a partir de uma planilha de medidas cefalométricas. Sem rede neural, sem imagem, sem malha: 112 regressores scikit-learn empilhados, um por valor a predizer, aplicados linha a linha a um arquivo Excel/CSV.

1. Onde se situa no pipeline

Ferramenta isolada. Nada no repositório a chama, e ela não chama nada do repositório: não lê nenhum volume, nenhuma malha, nenhum landmark. Sua entrada é uma pasta de planilhas, sua saída outra planilha.

ChamadoComo
SurgMovPred_CLIslicer.cli.run(slicer.modules.surgmovpred_cli, …) (SurgMovPred.py:842)

O módulo não está ligado à cena MRML: nenhum vtkMRMLNode é criado, lido ou transformado. É uma interface de lançamento sobre um script pandas.

Armadilha

Restos de copiar e colar do módulo CNE (resumo de notas clínicas), que não devem ser confundidos com o pipeline real: o helpText diz "This tool helps to create summaries of clinical notes", o parameterNodeWrapper é documentado com notesFolder_input / modelType / notesType, e process() ainda nomeia seus argumentos notesFolder_input / notesFolder_output (SurgMovPred.py:236, SurgMovPred.py:815).

3. Entradas e pré-processamento

Formato aceito. load_data_from_directory() (SurgMovPred_CLI.py:141) coleta todos os arquivos *.csv, *.xlsx, *.ods da pasta (extensão em minúsculas e maiúsculas), lê cada um (read_csv, read_excel, read_excel(engine='odf')) e os concatena (pd.concat(..., ignore_index=True)). Sem recursão em subpastas. Em uma pasta de trabalho Excel, somente a primeira aba é lida — o arquivo de teste oficial contém sete (all_data, demographics, Invivo_ceph, surgical_mov, dolp_ceph_T0, dolp_ceph_T1, dolp_ceph_total), e é all_data que está na primeira posição.

Normalização dos nomes de colunas, clean_name() (SurgMovPred_CLI.py:39), aplicada na entrada para recair na grafia usada no treinamento:

  1. remoção de ", \, [, ];
  2. todo caractere fora de [0-9a-zA-Z_'] vira _ — o apóstrofo é mantido de propósito (comentário do código: para Jarabak's e SM_A'_CP);
  3. redução dos _ repetidos, com corte nas duas extremidades;
  4. "total" → "Total";
  5. prefixo f_ se o nome começa com um dígito.

Essa limpeza explica os nomes reais das features: SM-A-FH   (com dois espaços no final, no arquivo de teste) vira SM_A_FH, Jarabak's ratio   vira Jarabak's_ratio, FMA(MP-FH) Ang_2D vira FMA_MP_FH_Ang_2D.

Identificador do paciente. find_id_column() (SurgMovPred_CLI.py:81) testa 8 padrões sem distinção de maiúsculas (#, id, patient id, patient number, subject, …) e, em último caso, qualquer coluna que contenha ao mesmo tempo "patient" e "id". No arquivo de teste, a coluna é #. Em caso de falha, a coluna de saída IDPatient é preenchida com pd.NA, com um simples aviso.

Normalização dos valores. Cada pacote de modelo traz o seu próprio StandardScaler calculado (centralização + escala, with_mean=True, with_std=True), aplicado logo antes da predição (SurgMovPred_CLI.py:237). Sem imputação: um valor ausente se propaga como NaN até a saída.

Tolerância ao sufixo _T0 (SurgMovPred_CLI.py:223): se o modelo espera X_T0 e a coluna se chama X, ela é aceita.

Nota

É a única tolerância; qualquer outra feature ausente faz o modelo inteiro ser pulado com um aviso, e a coluna correspondente fica ausente do resultado.

4. Os modelos

Os pesos não estão no repositório. onDownloadDefaultModel() (SurgMovPred.py:782) baixa e descompacta:

https://github.com/DCBIA-OrthoLab/SlicerAutomatedDentalTools/releases/download/SurgMovPred/all_models.zip
  -> Documents/SlicerDownloads/SurgMovPred/Models/all_models/

706 MB, 112 pastas, um stacking_package.pkl de ~13 MB em cada. load_all_model_packages() faz um Path.glob("**/stacking_package.pkl") recursivo e indexa por package['target_name']: apontar o seletor para all_models/ carrega os 112 modelos, apontar para uma subpasta carrega apenas um. O texto de ajuda da CLI menciona pastas saved_models/class_1, saved_models/class_None — essa hierarquia por classe esquelética não existe no arquivo publicado, que é plano.

4.1 Conteúdo de um pacote

Cada .pkl é um dict joblib de quatro chaves, usado tal como está por SurgMovPred_CLI.py:212:

ChaveConteúdo
target_namenome do alvo, p. ex. Mx_ALL_APoint_P-/A+_Pred (forma bruta, com -, /, +)
features_nameslista ordenada de 145 nomes de features
scalersklearn.preprocessing.StandardScaler ajustado
modelsklearn.ensemble.StackingRegressor ajustado
Verificado

Essas informações foram lidas diretamente de all_models/Mn_MB_Genioplasty_Total_Pred/stacking_package.pkl e all_models/Mx_ALL_APoint_P-_A_Pred/stacking_package.pkl (inspeção do fluxo pickle, sem execução). As 145 features são idênticas nos dois pacotes; nada garante formalmente que o mesmo vale para os outros 110, mas seus tamanhos quase idênticos (13,17–13,19 MB) sugerem isso fortemente.

4.2 A arquitetura

Nenhuma rede. Um ensemble de stacking com três regressores de base e um meta-regressor linear, serializado com _sklearn_version = 1.6.1:

PapelEstimadorParâmetros legíveis no pickle
base multitask_elasticnetElasticNetCVgrade de l1_ratio, n_alphas, eps, selection='cyclic'
base lgbmlightgbm.sklearn.LGBMRegressorboosting_type='gbdt', objective='regression', num_leaves=31
base gaussian_processGaussianProcessRegressorkernel Product(ConstantKernel, RBF), optimizer='fmin_l_bfgs_b', normalize_y
metaLinearRegressionstack_method='predict', passthrough=False

passthrough=False significa que o metamodelo vê apenas as predições dos três modelos de base, não as 145 features originais. stack_method='predict': um valor escalar por modelo de base, daí uma regressão linear de três entradas.

O peso dominante do arquivo (13 MB para 145 features) vem do GaussianProcessRegressor, que guarda sua matriz de treino, e do booster LightGBM.

O treinamento não está no repositório: nenhum script, nenhum conjunto de dados, nenhuma métrica, nenhuma seed. Não determinável a partir do repositório: tamanho da coorte, protocolo de validação, desempenho por alvo.

4.3 As 145 features

Quatro famílias, reconstruídas a partir de features_names e conferidas com a aba all_data do arquivo de teste:

FamíliaQuantidadeExemplos
Posições de pontos em relação aos três planos de referência — FH (horizontal de Frankfurt), MSP (plano sagital mediano), CP (plano coronal) ~76 SM_A_FH, SM_GoL_MSP, SM_PNS_CP, SM_CoR_FH
Pontos de tecido mole, marcados pelo apóstrofo ~20 SM_N'_FH, SM_Sn'_MSP, SM_ULip'_FH, SM_Pg'_MSP
Medidas cefalométricas 2D clássicas ~12 SNA, SM_ANB_signed, SM_Witts, LAFH, Jarabak's_ratio, UAFH_LAFH, FMA_MP_FH_Ang_2D, IMPA_L1_MP_Ang_2D, U1_to_SN_Ang_2D, SM_Mx_Width, SM_Mn_Width, OP_to_FH_Ang_2D
Medidas oclusais/dentárias, em dois conjuntos com os sufixos _T0 e _Total 2 × ~18 MxMn_Overjet_R_T0 / MxMn_Overjet_R_Total, MxMn_Molar_Relationship_L_T0, Mn_Gonions_to_Midline_Distances_R_Total

O significado exato dos dois conjuntos _T0 / _Total não está documentado em lugar nenhum do repositório. A nomenclatura (T0 = antes, Total = variação total) e o fato de ambos estarem do lado da entrada sugerem que o modelo recebe o estado pré-cirúrgico e o resultado oclusal visado, para inferir os deslocamentos ósseos a realizar — isto é uma dedução, não uma afirmação feita pelo código.

As colunas Gender, Surg, Genio, 3piece, assymetry, Skl_Cl_2 do arquivo de teste não aparecem entre as 145 features dos dois pacotes inspecionados: são lidas e depois ignoradas.

4.4 O que é predito

112 alvos = 28 estruturas × 4 componentes.

Componentes, segundo os nomes dos alvos: P-/A+ (posterior negativo / anterior positivo), R-/L+ (direita negativo / esquerda positivo), Down+ (vertical, para baixo positivo), e Total. Os três primeiros são portanto as componentes com sinal de um vetor de deslocamento no referencial cefalométrico (CP, MSP, FH), o quarto muito provavelmente sua magnitude — deduzido da nomenclatura, a unidade (mm) não está escrita em lugar nenhum.

As 28 estruturas:

SegmentoPontos
Maxila, Mx_ALL_* (10)APoint, ANS, PNS, U3CanineTip L/R, U6MesialCuspTip L/R, UpperIncisorTip L/R, UpperIncisorTipMidpoint
Mandíbula, Mn_ALL_* (17)BPoint, Gnathion, Menton, Pogonion, Gonion L/R, ChinSideCut L/R, MandibleBackCut L/R, L3CanineTip L/R, L6MesialCuspTip L/R, LowerIncisorTip L/R, LowerIncisorTipMidpoint
Mentoplastia, Mn_MB_Genioplasty (1)—

ALL designa o segmento ósseo inteiro (maxila ou mandíbula mobilizada em bloco), MB o segmento da mentoplastia. O que é predito, portanto, é o deslocamento de pontos de referência rigidamente ligados a cada segmento, predito, e não uma transformação rígida: nada obriga os 10 pontos da maxila a serem coerentes entre si (ver §7).

5. O processamento central

predict_all_targets() (SurgMovPred_CLI.py:194), por inteiro:

for target_name, pack in packages.items():
    X_target = df_cleaned[[feature_source[f] for f in pack['features_names']]]
    X_target.columns = pack['features_names']
    X_scaled = pack['scaler'].transform(X_target)
    predictions_by_target[target_name] = pack['model'].predict(
        pd.DataFrame(X_scaled, columns=..., index=df_cleaned.index))

Nenhuma pós-correção, nenhum limite, nenhuma coerência entre alvos, nenhum intervalo de confiança — o GaussianProcessRegressor pode produzir um desvio-padrão, mas isso não lhe é pedido. Cada alvo é tratado de forma independente, com um try/except por alvo: um alvo que falha não interrompe os outros, sua coluna simplesmente desaparece.

Os 112 modelos são carregados na memória de uma só vez (load_all_model_packages), ou seja, ~1,5 GB de RAM antes mesmo de os dados serem lidos.

6. Saídas

save_results() grava dois arquivos, de mesmo conteúdo, na pasta de saída:

ArquivoConteúdo
predictions_outputs.xlsxuma linha por paciente de entrada, coluna IDPatient e depois uma coluna por alvo predito
predictions_outputs.csvidem

index=True nos dois casos: o índice pandas (0, 1, 2…) vira uma coluna sem nome. Os nomes das colunas são os target_name brutos dos pacotes, portanto com / e + (Mx_ALL_APoint_P-/A+_Pred).

Armadilha

Não há nenhuma reaplicação do resultado. Nada constrói uma matriz, move uma malha, cria um nó do Slicer ou abre uma vista: a predição termina na planilha. A pergunta "como a predição é reaplicada para produzir um resultado visualizável" não tem resposta neste repositório — cabe ao operador levar os valores para o seu software de planejamento.

Armadilha

Os 10 pontos da maxila são preditos por 40 modelos independentes. Nada garante que os deslocamentos preditos sejam compatíveis com um movimento de corpo rígido do bloco maxilar; uma etapa de pós-processamento (um ajuste rígido por mínimos quadrados sobre os pontos preditos) seria o complemento natural, e ela não existe.

Bug confirmado

pip_install("numpy==2.4.0") é executado incondicionalmente, a cada clique em Apply. Substituir o numpy sob uma sessão ativa do Slicer é exatamente o que quebra o import do scipy em outros pontos da extensão (o scipy do Slicer é compilado contra o seu numpy). De longe o ponto mais perigoso do módulo, acionado pelo botão principal.

A instalação acontece sem conda, sem GPU, sem torch.

A CLI silencia o InconsistentVersionWarning do scikit-learn (SurgMovPred_CLI.py:19): os pacotes foram serializados com o scikit-learn 1.6.1 e são desserializados com qualquer versão que esteja instalada. O comentário assume o risco ("models are tested for compatibility before being shipped").

9. Armadilhas e pontos frágeis

  • pip_install("numpy==2.4.0") a cada execução. Substituir o numpy sob uma sessão ativa do Slicer é exatamente o que quebra o import do scipy em outros pontos da extensão (o scipy do Slicer é compilado contra o seu numpy). De longe o ponto mais perigoso do módulo, e ele é acionado pelo botão principal.
  • Botão "test files" inoperante: DownloadTestFiles() (SurgMovPred.py:763) baixa de fato TestFiles.zip, mas só preenche os campos de entrada/saída if os.path.exists(.../V_FACE/DefaultList) — um resto de copiar e colar do módulo VFACE. Sem os dados de teste do VFACE, o arquivo é baixado e depois ignorado.
  • .ods anunciado, odfpy não instalado por check_dependencies (ele é, porém, instalado pelo módulo Anonymizer, o que pode mascarar o problema em uma máquina em que os dois foram usados).
  • Uma feature ausente = um modelo pulado em silêncio. O log diz "Model 'X' skipped: missing N input feature(s)", mas o arquivo de saída simplesmente fica com uma coluna a menos. Uma planilha com nomes errados pode produzir um predictions_outputs.xlsx com zero colunas de predição e sem nenhuma falha.
  • Concatenação cega dos arquivos de entrada: duas planilhas com colunas diferentes geram NaN, e model.predict sobre NaN lança uma exceção — o erro é capturado por alvo, então o resultado sai parcial sem que isso fique muito visível.
  • Apenas uma aba do Excel é lida. Uma pasta de trabalho cuja primeira aba não é a de dados produz um resultado vazio.
  • 1,5 GB de modelos carregados sistematicamente, mesmo para uma única linha a predizer, mesmo que o operador só se interesse por um alvo.
  • Nenhuma incerteza na saída, embora um dos três modelos de base seja um processo gaussiano.
  • Nenhuma coerência rígida entre os pontos de um mesmo segmento (§7).
  • O helpText, a docstring do nó de parâmetros e os nomes dos argumentos de process() descrevem uma ferramenta totalmente diferente (resumo de notas clínicas).

10. Literatura

Nenhum artigo cobre o SurgMovPred. Nem o repositório, nem a release, nem o README citam qualquer referência, e uma busca pelo nome do módulo não retorna nada. O módulo nem sequer consta no README da extensão.

O contexto publicado, que não deve ser confundido com uma descrição deste código:

  • Machine-learning-based approach for predicting postoperative skeletal changes for orthognathic surgical planning (PubMed 35132764) — o problema proposto é o mesmo (predizer deslocamentos esqueléticos pós-operatórios a partir de medidas pré-operatórias), mas nada indica que seja este o trabalho por trás destes pesos.
  • Oliveira, Cevidanes, Bianchi et al., Artificial intelligence as a prediction tool for orthognathic surgery assessment, Orthodontics & Craniofacial Research, 2024 — mesma equipe (UNC/Pacific), mas outro alvo: predizer a necessidade de cirurgia a partir de telerradiografias laterais, não os movimentos em si.
  • Prediction of orthognathic surgery plan from 3D cephalometric analysis via deep learning (PMC10024836) — mesmo objetivo, abordagem de deep learning; o SurgMovPred, por sua vez, é um modelo tabular clássico.

As ferramentas subjacentes, por sua vez, são documentadas: StackingRegressor e LightGBM.

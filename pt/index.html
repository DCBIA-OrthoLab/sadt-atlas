SlicerAutomatedDentalTools — como cada ferramenta funciona

Uma página por ferramenta, organizada em torno do pipeline: o que é calculado, o que é predito por uma rede, quando o modelo é chamado, o que ele realmente faz, qual é o pré-processamento e o que sai no final.

Isto não é um manual do usuário. Os links de código apontam para o repositório ~/Projects/UNC/SlicerAutomatedDentalTools.

Por onde começar

De baixo para cima na cadeia. As duas primeiras etapas são aquelas de que todo o resto depende.

#PáginaPor que esta primeiro
1FlexRegA mais simples, tudo é explícito. Apresenta as convenções LPS/RAS, a segmentação das coroas e o ICP sobre patch.
2ALI e AMASSSOs dois fornecedores de landmarks dos quais todo o resto depende.
3ASOA orientação, pré-requisito da maioria dos registros.
4AREG_IOS e depois AREG_CBCTOs registros propriamente ditos.
5VFACEO mais alto da cadeia: empilha todos os outros.

Os três blocos compartilhados

Quase todos os módulos se apoiam nos mesmos três componentes. Entendê-los uma vez evita reler a mesma mecânica em cinco páginas.

Texto e linguagem natural

Estes não processam imagem alguma: executam um modelo de linguagem, sobre texto clínico nos três primeiros, sobre o pedido do operador no último. Ficam num grupo à parte porque o nome não o deixa claro.

Ambiente conda compartilhado

Acoplamento a conhecer

ALI, AREG, ASO, DOCShapeAXI e FlexReg compartilham o mesmo ambiente conda shapeaxi, em Python 3.12. Uma mudança na versão do Python quebra todos eles de uma vez. Detalhes em FlexReg, seção Ambiente.

Organização das pastas

Uma pasta por ferramenta. Cada uma contém:

  • <Tool>.html — o pipeline, lido a partir do código;
  • SOURCES.html — a bibliografia: o que está depositado aqui, o que é para ler online e a "vizinhança" (trabalhos relacionados que não descrevem o código);
  • os documentos recuperados, em PDF quando a editora permite, senão em .xml (JATS, o texto completo) com um .txt legível ao lado.

Os arquivos .md originais são mantidos ao lado das páginas HTML.

29 PDFs e 54 textos completos, todos verificados: os PDFs são paginados, os arquivos XML contêm um corpo de texto. Nada foi obtido contornando um paywall — arXiv, PLOS, PMC/NCBI, HAL, repositórios institucionais, páginas de autores e versões depositadas pelos autores. Tudo o que está atrás de paywall é dado como link com seu DOI.

Recuperar um texto que a editora não serve

Os manuscritos de autor depositados no NIH são de leitura livre, mas muitas vezes invisíveis pelas vias habituais. O que funciona, testado:

curl -sL "https://eutils.ncbi.nlm.nih.gov/entrez/eutils/efetch.fcgi?db=pmc&id=<number without PMC>"

O que falha nos mesmos artigos: pmc.ncbi.nlm.nih.gov/.../pdf/ (HTML antibot), o fullTextXML da Europe PMC (vazio), a API BioC (só o open access subset). E, para a MDPI, mdpi-res.com/d_attachment/... serve o PDF real onde mdpi.com/.../pdf retorna uma página.

O que não está publicado em lugar algum

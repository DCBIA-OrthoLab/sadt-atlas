MRI2CBCT : sources

Ce que le module doit à la littérature, ce qui a été récupéré en texte intégral, et ce qui reste derrière un accès payant ou introuvable.

bibliographie Page du pipeline

Publié en partie, et publié en décalage avec le code. Deux textes concernent ce module : l'article de méthode (Leroux et al., CLIP 2024, payant) et une série de cas cliniques qui documente son usage (Caleme et al., Seminars in Orthodontics 2025, récupérée ici). Aucun ne décrit la version qui tourne aujourd'hui : l'article CLIP 2024 et la série de cas 2025 couvrent la séquence antérieure (orientation, rééchantillonnage, inversion, normalisation, elastix rigide sur l'information mutuelle, avec une approximation par torchreg puis par les condyles) ; le code recale désormais deux surfaces de base du crâne prédites par réseau au moyen de FPFH + RANSAC + ICP, et rien dans ce dossier ne le décrit. Un troisième texte (Gaydamour et al., CLIP 2025, payant) rapporte en passant la seule évaluation numérique publiée à ce jour : précision sub-millimétrique, taux de réussite de 98,75 %. Elle évalue l'ancien pipeline ; rien de publié ne mesure l'actuel.

Remplacé

Cette page consignait autrefois, comme confirmé dans le code, un elastix rigide sur l'information mutuelle de Mattes. C'était vrai de la version antérieure ; le code actuel n'a aucun appel à elastix.

Travaux voisins

Travaux connexes qui ne décrivent pas ce module.

  • Al-Saleh 2016 et 2017 (récupérés plus haut) : une équipe de l'University of Alberta, sans lien avec DCBIA. Ils posent le problème, le recalage IRM/CBCT de l'TMJ, ses écueils, l'état de l'art avant ce module, et servent de point de comparaison, non de description du code.
  • elastix (Klein 2010, récupéré) : la bibliothèque de recalage de la version antérieure du module, via l'enveloppe ITKElastix avec la carte de paramètres rigid par défaut. Le code actuel ne l'utilise pas. Seconde citation usuelle, non récupérée ici : Shamonin D.P. et al., Fast parallel image registration on CPU and GPU…, Front. Neuroinform. 7:50, 2014 (10.3389/fninf.2013.00050, CC-BY).
  • nnU-Net (Isensee, récupéré) : la méthode autoconfigurée derrière le réseau IRM de base du crâne (Dataset516, exécuté en processus par seg516.py) et derrière AMASSS. Ni l'entraînement, ni le jeu de données, ni l'évaluation des poids de Dataset516 ne sont documentés nulle part, publication comprise. Les commentaires du code qualifient de « published » les réglages du recalage et citent des scripts extérieurs au dépôt ; aucune publication n'a été trouvée.
  • Modules de l'extension que le code actuel appelle (CLI d'ASO, d'ALI et d'AMASSS, voir la page du pipeline) : ASO/AREG, Anchling L. et al., Automated Orientation and Registration of Cone-Beam Computed Tomography Scans, CLIP 2023, LNCS (PMC11104011) ; AMASSS : Gillot M. et al., PLOS ONE 17(9):e0275033, 2022 (10.1371/journal.pone.0275033).
  • FPFH et Open3D (non récupérés) : Rusu R.B. et al., Fast Point Feature Histograms (FPFH) for 3D registration, ICRA 2009 ; Zhou Q.-Y. et al., Open3D: A Modern Library for 3D Data Processing, 2018. Les briques du recalage actuel.
  • TorchReg (github.com/codingfisch/torchreg) : la voie d'approximation de l'article CLIP 2024 et du rapport PW43, depuis retirée du code. Aucune publication.

GreedyReg : sources

Bibliographie de GreedyReg : ce qui est déposé dans ce dossier, ce qui est consultable en ligne, et son voisinage, des travaux qui décrivent le moteur ou les composants empruntés, jamais ce module lui-même.

2 documents récupérés ← Page du pipeline

Le module lui-même n'est publié nulle part. Aucun article, aucun résumé, aucun rapport de Project Week ne porte sur GreedyReg. Ce qui est publié, c'est le moteur qu'il pilote, greedy, l'outil de Paul Yushkevich (PICSL, University of Pennsylvania, livré avec ITK-SNAP), et le réseau qu'il emprunte pour le mode « Distant Registration », ALI_CBCT. Ces deux travaux relèvent du voisinage : ils décrivent des composants, pas ce code, et la distinction compte ici (voir plus bas : GreedyReg n'utilise aucune des méthodes que met en avant l'article de greedy).

Voisinage

Aucun des travaux ci-dessous ne décrit GreedyReg. Ils décrivent le moteur ou les composants empruntés.

  • L'article de greedy (Venet 2019, récupéré) décrit ce que GreedyReg n'utilise pas. Il présente un recalage difféomorphe en deux étapes : une étape affine d'initialisation, suivie de l'estimation d'un champ de déformation. GreedyReg n'appelle jamais que la première : greedy -a avec -dof 6 ou -dof 12, et greedy -rf/-rm pour le rééchantillonnage. Le champ de déformation, le « greedy » du nom de l'outil, la métrique NCC difféomorphe : rien de tout cela n'est jamais exécuté. Citer cet article pour décrire GreedyReg reviendrait à décrire une méthode que le module n'emploie pas.
  • ITK-SNAP (Yushkevich 2006, ci-dessus) : le module est une transposition dans Slicer du panneau Registration d'ITK-SNAP, pré-alignement manuel, puis affine fondé sur l'intensité avec un masque. C'est la seule filiation que le code peut revendiquer, et elle est architecturale, pas méthodologique.
  • ALI_CBCT (Gillot 2023, récupéré) : des agents virtuels naviguant dans un espace volumétrique multi-échelle, 1,54 ± 0,87 mm sur 32 landmarks. Effectivement appelé par GreedyReg, mais seulement en mode « Distant Registration », pour produire les landmarks que le module aligne ensuite par Kabsch. L'article ne dit rien de cet usage. Dépôt d'origine : Maxlo24/ALI_CBCT.
  • Fondements du recalage difféomorphe cités par le site de greedy, sans rapport avec ce que GreedyReg exécute réellement : Joshi S., Davis B., Jomier M., Gerig G., Unbiased diffeomorphic atlas construction for computational anatomy, NeuroImage 23:S151-S160, 2004 (10.1016/j.neuroimage.2004.07.068) ; Avants B.B., Epstein C.L., Grossman M., Gee J.C., Symmetric diffeomorphic image registration with cross-correlation, Medical Image Analysis 12(1):26-41, 2008 (10.1016/j.media.2007.06.004) ; Avants B.B. et al., A reproducible evaluation of ANTs similarity metrics, NeuroImage 54(3):2033-2044, 2011 (10.1016/j.neuroimage.2010.09.025).
  • Documentation et code : greedy.readthedocs.io, sites.google.com/view/greedyreg (le site officiel de greedy, attention à l'homonymie : ce n'est pas ce module), github.com/pyushkevich/greedy.

Recherche plein texte de GreedyReg dans Europe PMC et OpenAlex : 3 résultats chacun, tous des homonymes (CaPTk, une étude sur l'anévrisme aortique, une étude sur l'hippocampe) qui renvoient au moteur, jamais à ce module.

GreedyReg : recalage affine avec greedy

Recalage affine ou rigide de scans CBCT T1 et T2, en pilotant le moteur de recalage Greedy comme sous-processus, sans réseau dans le chemin principal. Cette page explique comment, pas à pas, avec les maths ; les fichiers, les lignes et les pièges sont sur la page de code.

Code (développeurs) Guide Venet 2019 · arXiv GreedyReg_CLI env conda : aucun (Python de Slicer) VISOR Bibliographie

Vue d'ensemble : ce qui entre, ce qui sort

À la seconde visite, le patient n'est jamais couché exactement comme à la première. GreedyReg ramène le second CBCT (T2, le scan mobile) dans le repère du premier (T1, le scan fixe). Il offre trois modes : aligner à la main, laisser Greedy optimiser, ou partir de landmarks quand les deux scans sont très éloignés.

Ce que c'est
Entréeun CBCT T1 et un CBCT T2 (.nii.gz), seuls ou sous forme de deux dossiers appariés par patient ; en option, un masque d'une structure stable et une matrice de départ
IdéeGreedy optimise une mesure de similarité du grossier au fin sur 6 (rigide) ou 12 (affine) nombres
SortieT2 rééchantillonné dans la grille de T1, et la matrice trouvée

Tout ce qui est numéroté ci-dessous décrit le module Slicer legacy (SlicerAutomatedDentalTools à 3c67957, 2026-10-26). Le portage VISOR, qui exécute une partie de cet outil sur un serveur, est décrit dans VISOR : comment cet outil tourne aujourd'hui. C'est un portage partiel : seul le recalage Greedy de dossier à dossier y existe. Le mode Manual et le mode Distant (par landmarks) n'ont pas d'équivalent dans l'outil serveur.

1. Situation dans la chaîne

Rien dans le dépôt n'appelle GreedyReg. C'est un outil de terminal, piloté par l'opérateur, et il n'alimente aucun autre module. Le widget assemble les paramètres et laisse un outil en ligne de commande lancer Greedy ; le seul autre outil en jeu est ALI_CBCT, en mode Distant.

Dans le codeLes appels, qui lance quoi, et pourquoi le widget n'exécute jamais greedy lui-même

2. Fichiers en jeu

Le widget (environ 1600 lignes, dont 700 d'interface utilisateur) porte les trois modes ; un fichier d'aide fait l'appariement, l'algèbre matricielle et l'analyse de la sortie d'ALI ; l'outil en ligne de commande boucle sur les paires et construit les deux commandes Greedy. Greedy lui-même est un exécutable externe. Tout tourne dans le Python de Slicer, sans environnement conda et sans GPU.

Dans le codeChaque fichier avec son rôle et l'endroit où il tourne

3. Le binaire greedy : d'où il vient

L'exécutable n'est pas dans le dépôt : s'il manque, un bandeau propose de télécharger l'archive ITK-SNAP 4.2.2 de la plateforme et d'en extraire seulement greedy. Le chemin Windows est le plus fragile (l'installateur est lancé en silence, puis désinstallé). Il n'y a aucune vérification d'intégrité sur l'archive téléchargée.

4. Les trois modes, et ce qui les distingue vraiment

ModeCe qui est calculéSortie
Manual Alignmentrien : l'opérateur déplace une transformation dans la scèneune matrice dans la scène, utilisée comme point de départ
Automatic Registrationcalculé Greedy optimise une métrique d'intensité, rigide ou affinevolume recalé et matrice
Distant Registrationprédit calculé landmarks par ALI_CBCT, puis un ajustement rigide en forme closeseulement une matrice, à affiner ensuite

“Distant” ne désigne pas un calcul à distance : il vise deux scans qui partent éloignés géométriquement. Tout s'exécute en local ; les seules requêtes sortantes sont les téléchargements de l'outil et des poids d'ALI, jamais de données de patients.

Dans le codeLe piège de vocabulaire et les fichiers que touche chaque mode

4.1 Mode manuel

L'opérateur déplace T2 avec des curseurs (trois rotations, trois translations), avec un bouton “Center T2 on T1”, ou avec les poignées de Slicer. Aucune intensité n'est comparée. La matrice obtenue est remise à Greedy comme point de départ.

Dans le codeL'ordre de composition des curseurs, le centrage et la roue prototype

4.2 Mode automatique

Le widget exporte les deux volumes dans un dossier temporaire sous un faux nom fixe, écrit la matrice de départ, et lance l'outil en ligne de commande en mode lot sur un dossier contenant une seule paire. Il n'y a pas de chemin dédié au cas unique. Le volume recalé est chargé à la fin ; le dossier temporaire n'est jamais supprimé.

Dans le codeL'arborescence temporaire, l'interrogation périodique et le bouton d'enregistrement

4.3 Mode Distant

Une seule région est retenue, par priorité (base du crâne, puis mandibule, puis maxillaire) : en cocher plusieurs n'additionne pas leurs landmarks. ALI_CBCT, un agent qui parcourt le volume, place 4 ou 5 landmarks de cette région sur les deux scans ; les coordonnées sont converties de LPS en RAS, et si au moins 3 landmarks sont communs aux deux scans, une transformation rigide en est calculée.

Dans le codeLe tableau des régions, les paramètres d'ALI et le code de la SVD

5. La ligne de commande greedy

La commande est toujours la même, sans autre option exposée que la métrique et les degrés de liberté. Les options, en termes simples :

  • Mode affine : le mode difféomorphe de Greedy, son défaut et sa raison d'être, n'est jamais utilisé ici.
  • La métrique : NMI (information mutuelle normalisée, le défaut legacy, pour des intensités hétérogènes), NCC sur une fenêtre de rayon 4 voxels (9×9×9), ou SSD (somme des différences au carré, pour la même modalité).
  • L'ordre : T1 est l'image fixe, T2 l'image mobile.
  • Le calendrier : quatre niveaux de résolution, 100, 100, 50 et 25 itérations à partir du plus grossier.
  • Une recherche aléatoire sur 100 transformations rigides précède l'optimisation, avec une dispersion de 10 degrés en angle et de 20 en décalage ; l'unité du décalage est ambiguë dans la documentation même de Greedy.
  • Les degrés de liberté : 6 pour le rigide, 12 pour l'affine ; 7 (rigide plus une échelle) n'est pas proposé.
  • Le départ : toujours une matrice donnée.
  • Le masque, s'il y en a un, appartient au volume fixe : la métrique n'est calculée qu'à l'intérieur.

Un second appel, toujours exécuté, rééchantillonne T2 dans la grille de T1 par interpolation linéaire avec la matrice trouvée. Chaque appel est plafonné à 600 secondes ; une paire fait deux appels.

Dans le codeLes lignes de commande exactes et le tableau de chaque option

6. Entrées, appariement, masques, initialisation

Un patient est reconnu aux lettres et aux chiffres qui commencent le nom de fichier, mis en majuscules : A01_t1.nii.gz donne A01. Une paire existe quand le même identifiant se trouve dans le dossier T1 et dans le dossier T2 ; un fichier nommé 01_T1.nii.gz (chiffres d'abord) n'est jamais apparié, silencieusement. Un masque est exporté depuis une segmentation ou une labelmap et transformé en image 0/1 : tous les segments d'une segmentation multi-étiquettes sont fusionnés. Sans matrice de départ, l'outil écrit une identité avec un coup de pouce d'un micron en x, parce qu'une identité exacte fait se comporter Greedy différemment (le commentaire d'origine du code dit qu'il la traiterait comme une absence d'initialisation). Il n'y a aucun prétraitement d'intensité : les fichiers sont donnés tels quels.

Dans le codeL'expression régulière, le code du masque et l'identité décalée

7. Mode lot

Il y a deux lots indépendants. Automatic : une seule exécution en ligne de commande sur les dossiers, qui boucle sur les paires ; la sortie va dans le dossier T2 lui-même, le dossier de masques (s'il est rempli) est transmis et transformé en image 0/1 par l'outil en ligne de commande, aucune matrice de départ n'est transmise, et le premier cas qui échoue arrête tout le lot. Distant : le widget boucle cas par cas avec une file ALI par paire, et le résultat n'est pas un volume recalé mais un en-tête réécrit : les voxels ne bougent pas, seule l'affine voxel-vers-monde est corrigée par la rotation et la translation trouvées.

Dans le codeLes deux boucles et la réécriture de l'en-tête

8. Sorties

Pour chaque patient : <ID>_registered.nii.gz (T2 dans la grille de T1), <ID>_warp.mat (la matrice texte de quatre lignes de Greedy) et, dans le lot Distant, <ID>_t2_aligned.nii.gz. La matrice est dans la convention propre à Greedy : elle envoie les coordonnées RAS du volume fixe vers celles du volume mobile.

[xmoving;1]=M[xfixed;1]

Ce n'est pas un fichier de transformation ITK et il ne se charge pas dans Slicer malgré son extension .mat. Une transformation ITK ou Slicer sur disque est en LPS, donc une conversion (une conjugaison par le retournement de x et de y, et peut-être une inversion) serait nécessaire, et rien dans le module ne la fait. GreedyReg est une impasse : personne ne consomme sa matrice.

Dans le codeLe tableau des fichiers, le format et la conversion qui n'existe pas

9. Convention d'initialisation : très probablement inversée

La matrice manuelle est une transformation Slicer, qui envoie le volume mobile vers le monde : mobile vers fixe. La matrice de départ de Greedy est de la nature de sa sortie, qui envoie fixe vers mobile. Les deux sont inverses l'une de l'autre, donc le pré-alignement manuel est très probablement transmis à Greedy à l'envers. Pour un décalage pur de 20 mm, le bon départ est le décalage dans un sens et le mauvais est le décalage opposé, ce qui laisse la recherche à 40 mm de la réponse au lieu de 0. Cela ne se voit pas toujours : la recherche aléatoire et le calendrier à quatre niveaux pardonnent beaucoup, et un mauvais départ ne fait que ralentir la convergence. Ce n'est pas confirmé ; il faut le vérifier avec une translation pure de 20 mm avant de corriger.

11. Environnement

Le Python de Slicer exécute à la fois le widget et l'outil en ligne de commande ; l'outil en ligne de commande n'a besoin que de nibabel, installé après confirmation. Le mode Distant ajoute des bibliothèques plus lourdes (conversion DICOM, MONAI), avec des versions épinglées qui comptent : un autre choix casse les propres modules DICOM de Slicer. torch est supposé déjà présent. Greedy n'a pas besoin de GPU ; ALI peut en utiliser un. Il n'y a ni conda ni WSL.

Dans le codeLes bibliothèques, leurs versions et le commit qui les a épinglées

12. Pièges et points fragiles

  • Le lot écrit ses sorties dans le dossier d'entrée T2, donc une seconde exécution peut recaler à nouveau le résultat précédent (détails).
  • La matrice n'est pas une transformation Slicer : mauvais format, mauvais repère, mauvais sens (détails).
  • L'initialisation manuelle est probablement inversée (détails).
  • L'option de pas de temps n'a aucun effet en mode affine (détails).
  • En mode Distant, le bouton “Save Registered Volume” n'a jamais rien à enregistrer (détails), et les trois cases de structure ne combinent pas leurs landmarks (détails).
  • ALI peut échouer en silence, ne laissant à l'utilisateur que “0 matched landmarks” (détails).
  • Les dossiers temporaires ne sont jamais nettoyés côté widget (détails).
  • Une seule paire en échec arrête tout le lot (détails).
  • Un masque multi-segments est aplati et son espace n'est pas vérifié (détails).

13. Littérature

Le moteur est publié, le module ne l'est pas.

  • greedy : un outil de Paul Yushkevich (PICSL, UPenn), livré avec ITK-SNAP. La référence habituelle pour le citer est Venet, Pati, Yushkevich, Bakas, Accurate and Robust Alignment of Variable-Stained Histologic Images Using a General-Purpose Greedy Diffeomorphic Registration Tool (arXiv:1904.11929). Documentation : greedy.readthedocs.io, code : pyushkevich/greedy. À noter : l'article et l'outil portent sur le recalage difféomorphe ; GreedyReg n'utilise que le mode affine/rigide (-a), qui n'en est que l'étape d'initialisation.
  • ALI_CBCT : Gillot et al., Automatic landmark identification in cone-beam computed tomography, Orthodontics & Craniofacial Research, 2023, des agents virtuels naviguant dans un espace volumétrique multi-échelle, erreur moyenne rapportée de 1,54 ± 0,87 mm sur 32 landmarks. Dépôt d'origine : Maxlo24/ALI_CBCT.
  • GreedyReg lui-même : aucune publication. L'approche, « pré-alignement manuel puis affine fondé sur l'intensité, avec un masque », est celle du panneau Registration d'ITK-SNAP, dont ce module est une transposition dans Slicer ; c'est la seule filiation que le code peut revendiquer.

VFACE, legacy : le code

Pour les développeurs : ce que fait le module Slicer legacy dans le code, avec des références file:line, des signatures, des tables et des pièges. L'explication lisible du même pipeline, avec les maths et le visualiseur 3D, se trouve sur la page de l'atlas.

Code Atlas (explication) SPIE Medical Imaging 2026 vface_cli env conda : aucun (Python de Slicer) Bibliographie VISOR

Classification automatique de l'asymétrie faciale squelettique sur CBCT. VFACE n'apprend rien et ne segmente rien lui-même : c'est un orchestrateur qui enchaîne six autres modules du dépôt, en extrait des mesures linéaires et angulaires, et termine par trois classifieurs LightGBM. C'est le module de plus haut niveau de la chaîne : l'arbre d'appels est ici l'information centrale.

Le principe clinique tient en une phrase : T2 est l'image miroir du patient lui-même. Il n'y a pas de second scan. Le scan est orienté, reflété par rapport au plan médio-sagittal, recalé sur l'original, et tout ce qui est mesuré est un écart entre le patient et son propre reflet.

Deux bases de code

Tout ce qui est numéroté ci-dessous décrit le module Slicer legacy (SlicerAutomatedDentalTools à 3c67957, 2026-10-26). Le portage VISOR, qui exécute le même outil sur un serveur, est décrit sur sa page VISOR. Ce portage n'existe que sur des branches de fonctionnalité (SADT-VISOR tool/vface et VISOR-serve conf/vface-deployment, aucune n'étant sur main) et n'a jamais été exécuté avec ses six vrais appelés.

L'arbre d'appels, en mode « Full pipeline » + « Asymmetry Assessment » + « Quantitative + Visualization »

Explication en langage courant et maths : page de l'atlas.

T1 : un CBCT brut, rien d'autre

Préparation

  1. rééchantillonnage à 0,3 mm isotrope, centré T1 Resample/CBCT
  2. PRE_ASO ×2, pour le maxillaire et la base du crâne Centered T1 Scans/{MAX,CB} + .tfm
  3. ALI place 6 landmarks maxillaires, puis SEMI_ASO oriente sur l'occlusal + le plan médio-sagittal Oriented T1 Scans/MAX
  4. ALI place 7 landmarks de la base du crâne, puis SEMI_ASO oriente sur Francfort + le plan médio-sagittal Oriented T1 Scans/CB
  5. AMASSS segmente CBMASK et MANDMASK sur le scan CB, MAXMASK sur le scan MAX T1 Masks

Miroir

  1. AutoMatrix applique Matrix_mirror.tfm aux scans orientés : c'est de là que vient le « T2 » T2_Scan/{CB,MAX}

Recalage

  1. AREG ×3, une fois par région : base du crâne, maxillaire, mandibule Registered Scan/<region>/<pat>_OutReg/

Mesures

  1. ALI place chaque landmark de mesure, sur le scan CB (les scans sont d'abord complétés de 30 mm de marge pour que les landmarks du bord restent atteignables) T1 Landmarks/CB
  2. derive_landmarks les reporte de CB → MAX par un ajustement rigide T1 Landmarks/MAX
  3. AutoMatrix reflète les landmarks Mirrored Landmarks/{CB,MAX}
  4. AutoMatrix leur applique les trois matrices AREG Mirrored & Registered Landmarks/{CB,MAND,MAX}
  5. AQ3DC ×3 mesure les distances et les angles Measurements/Measurements_*.xlsx
  6. le post-traitement assemble la ligne de caractéristiques Measurements/PostProcess_Measurements.xlsx
  7. VFACE_CLI exécute les trois modèles LightGBM Classification/Classification.xlsx

Visualisation

  1. BatchDentalSeg ×5 construit les surfaces osseuses VTK Files/{T1 CB,T1 MAX,T2 CB,T2 MAND,T2 MAX}
  2. ModelToModel Distance ×3 écrit les cartes d'asymétrie Heatmaps/

Les noms de phase sont ceux du module lui-même, tirés de VFACE_utils/review_steps.py ; mirror_masks est omis parce qu'il n'existe qu'en mode CMFReg.

Le PDF Janson module.pdf est le schéma de ce pipeline (extractible avec pdftotext), utile pour lire le code.

3. Entrées et prétraitement

Explication en langage courant et maths : page de l'atlas.

Entrée : un dossier de CBCT T1, un par patient (.nii, .nii.gz, .nrrd, .nrrd.gz, .gipl, .gipl.gz). Aucune segmentation, aucun landmark : VFACE part du volume brut. checkInputFolder() (VFACE.py:1322) refuse de démarrer sur un dossier vide.

Identité du patient : patientIdFromFileName (functionaq3dc.py:1360) coupe le nom sur _Scan, _Or, _MAND, _MD, _MAX, _MX, _CB, _lm, _T2, _T1, _Cl, .. La même chaîne est dupliquée trois fois dans createlistprocess (marquée TIMEPOINT-SUFFIX) : seuls _T1/_T2 sont reconnus, un _T3 casse silencieusement l'appariement.

Rééchantillonnage : espacement [0.3, 0.3, 0.3], resample_size = "None", center = "True", la taille propre du volume est conservée, seul l'espacement change. Sortie dans <out>/T1 Resample/CBCT.

Centrage (pre_aso_cbct, model_folder=False) : purement géométrique, translation du centre du volume vers l'origine, plus un .tfm écrit à côté (PRE_ASO_CBCT.py:154). Aucun réseau n'intervient ici.

Orientation : deux repères distincts, construits sur le même scan centré.

RepèreLandmarks demandés à ALIGold standardSuffixe
MAXANS, IF, PNS, UL6O, UR1O, UR6OPlan occlusal et médio-sagittal_MAX_Or
CBBa, LPo, N, RPo, S, LOr, ROrPlan horizontal de Francfort et médio-sagittal_CB_Or

semi_aso_cbct fait une initialisation sur 3 landmarks puis un vtkIterativeClosestPointTransform rigide (1000 itérations, StartByMatchingCentroidsOn) des landmarks du patient sur ceux du gold (ASO_CBCT/ASO_CBCT_utils/utils.py:538-543 pour l'ICP ; le départ sur trois landmarks est InitICP, :556-647, et le triplet est celui à la plus petite distance moyenne parmi jusqu'à 2500 tirages, FindOptimalLandmarks, :166-191), et écrit <pat>_<suffix>_transform.tfm = l'inverse de (ASO ∘ centrage). Ensuite, le plan médio-sagittal se trouve en x = 0, condition pour que le miroir soit valide.

Le miroir. Matrix_mirror.tfm (livré avec la release AutoMatrixMirror) est une AffineTransform de paramètres -1 0 0 0 1 0 0 0 1, translation nulle : une pure réflexion selon l'axe x en LPS, c'est-à-dire une symétrie par rapport au plan médio-sagittal. AutoMatrix l'applique aux volumes via sitk.ResampleImageFilter et aux fichiers .mrk.json via transform.GetInverse().TransformPoint (Automatrix_CLI.py:149-156).

Système de coordonnées : tout est en LPS. ALI écrit "coordinateSystem": "LPS" (io.py:39), derive_landmarks aussi, et createDictPatient lit le champ brut position sans conversion. Les signes des composantes de mesure en découlent directement (§5.1). Les seules bascules RAS↔LPS du module sont dans saveAdjustedRegistration() (revue manuelle) et dans les exports VTK de segmentation_logic (Scale(-1,-1,1) avant l'écriture).

4.3 BDS / DentalSegmentator : les surfaces

Explication en langage courant et maths : page de l'atlas.

réseau nnU-Net 3d_fullres.

run_bds appelle run_dental_segmentation(model="DentalSegmentator", device="cuda", export_formats = VTK | VTK_MERGED). nnU-Net produit une carte d'étiquettes à 5 classes (Upper Skull, Mandible, Upper Teeth, Lower Teeth, Mandibular canal, segmentation_logic.py:601), convertie en surfaces :

  • _exportMergedVTK : vtkDiscreteMarchingCubes (un contour par valeur d'étiquette présente, indexé par position plutôt que par valeur, le commentaire du code explique le bug corrigé), vtkWindowedSincPolyDataFilter 60 itérations, passe-bande 0.05, normales par cellule, vtkQuadricDecimation 0.4 par étiquette, puis IJK→RAS→LPS avant l'écriture ;
  • _exportVTKPerLabel : la même chaîne sur la représentation « Closed surface » de chaque segment, un fichier par structure.

Les poids ne sont pas dans le dépôt : seuls dataset.json et plans.json sont versionnés, et PythonDependencyChecker teste la présence de Dataset111_453CT/nnUNetTrainer__nnUNetPlans__3d_fullres/fold_0/checkpoint_final.pth avant de télécharger l'URL de download_info.json (~220 MB). Les trois autres modèles proposés (PediatricDentalsegmentator, NasoMaxillaDentSeg, UniversalLabDentalsegmentator) ont leur code de téléchargement mais ne sont jamais sélectionnés par VFACE : du code mort ici, et leurs chemins Path(__file__).parent/"Resources" sont d'ailleurs décalés d'un niveau (VFACE_utils/Resources/...), contrairement au chemin corrigé du modèle par défaut (segmentation_logic.py:458).

4.4 Le recalage : AREG-CBCT

Explication en langage courant et maths : page de l'atlas.

calculé Elastix, sans apprentissage.

VoxelBasedRegistration masque T1 avec le masque AMASSS correspondant puis lance Elastix rigide (make_rigid_param_map_deterministic, AREG_CBCT/AREG_CBCT_utils/utils.py:408-435) : 3 résolutions, pyramide 8,8 4,4 2,2, AdvancedMattesMutualInformation 64 bins, ConjugateGradient 1500 itérations, ImageSampler = Grid, NumberOfThreads = 1 (déterminisme). Pas d'apprentissage.

Sorties : Registered Scan/<Cranial Base|Maxilla|Mandible>/<pat>_OutReg/ contenant <pat>_<CB|MAX|MAND>Scan_Reg.nii.gz et <pat>_<CB|MAX|MAND>_Reg_matrix.tfm.

Piège (legacy, 3c67957)

Legacy uniquement (3c67957). Dans VISOR, cette fonction par mots-clés a disparu : VFACE n'apparie pas lui-même les masques, il remet tout le dossier de masques à AREG_CBCT comme t1_masks (VISOR:SADT-VISOR tools/VFACE/src/sadt_vface/tools.py:225-233) et l'appariement relève d'AREG.

Détail fragile : le masque est choisi par mot-clé dans le nom de fichier (CB→["cb"], MAND→["mand","md"], MAX→["max","mx"]) et le premier trouvé l'emporte (utils.py:42). Or <pat>_CB_Or_seg_MANDMASK.nii.gz contient aussi « cb ». Seul l'ordre alphabétique (CBMASK < MANDMASK) empêche le recalage de la base du crâne d'être masqué par la mandibule. Tout renommage casse cela.

5.1 Les types de mesure (sept lignes, dix chaînes exactes)

Explication en langage courant et maths : page de l'atlas.

Tous instanciés par AQ3DCLogic.createMeasurement (functionaq3dc.py:1985), à partir de la colonne Type of measurement du xlsx : appariés par égalité exacte de chaîne. Les positions sont en LPS (x = gauche, y = postérieur, z = supérieur).

Formule de l'angle (Angle.__computeAngles, Measure.py:664). u = p2 − p1, v = p4 − p3. Pour chaque axe a de [2, 0, 1], respectivement lacet (plan axial), tangage (plan sagittal), roulis (plan coronal) :

  1. supprimer la composante a (projection 2D), normaliser ;
  2. θ = degrees(arctan2(‖u × v‖, u · v));
  3. si p2 == p3 (les deux droites partagent leur sommet) : θ ← 180 − θ, c'est ce qui transforme RCo-RGo / RGo-Me en un angle goniaque anatomique ;
  4. signe : z = u_x·v_y − u_y·v_x ; pour l'axe de lacet le signe suit z, pour le tangage et le roulis il est inversé.

Le bloc complement_checkbox (complément à 180°) est commenté : Measure.py:669.

Sens des composantes. manageMeaningComponent() renseigne les libellés (R/L, A/P, S/I pour les mesures squelettiques ; M/D, B/L, E/I pour les dents ; ClockWise/CounterC pour les angles T1↔T2). Les valeurs *_Component renvoyées sont des valeurs absolues ; c'est reorganizeStat (createlistprocess.py:1620) qui leur rend un signe à partir du libellé.

Piège

Deux conventions opposées coexistent ici : pour une droite squelettique, Vertical = −|si| quand la direction est S (supérieur), alors que pour une droite dentaire Vertical = −|si| quand la direction est I. À vérifier avant de réutiliser ces colonnes. Un angle Angle between 2 lines T1 ne tombe dans aucune branche de manageMeaningComponent (ni dentaire, ni T1↔T2) : ses libellés restent vides et sa valeur reste non signée.

Aussi vrai dans VISOR pour les deux conventions Vertical : la branche dentaire signe sur "I" et la branche squelettique sur "S", toutes deux conservées volontairement (VISOR:SADT-VISOR tools/VFACE/src/sadt_vface/features.py:140 et :158).

Inverser l'ordre des points dans la droite T2 est voulu : puisque le miroir a échangé la gauche et la droite, écrire RAF-LAF du côté T2 ramène les deux vecteurs à être presque colinéaires, si bien que l'angle mesuré tend vers 0 pour un patient symétrique.

Cela ne se voit pas avec la liste par défaut parce que ses 9 landmarks d'angle figurent tous aussi dans la feuille des distances.

Absent de VISOR : read_measurement_list lit toutes les feuilles du classeur avec sheet_name=None (VISOR:SADT-VISOR tools/VFACE/src/sadt_vface/aq3dc.py:122).

5.3 derive_landmarks : les landmarks MAX sans second passage ALI

Explication en langage courant et maths : page de l'atlas.

createlistprocess.py:1451. ALI n'est exécuté qu'une fois, dans le repère CB. Les landmarks dans le repère MAX s'obtiennent par composition rigide :

to_centred   = sitk.ReadTransform(<pat>_CB_Or_transform.tfm)
from_centred = sitk.ReadTransform(<pat>_MAX_Or_transform.tfm).GetInverse()
moved = from_centred.TransformPoint(to_centred.TransformPoint(p))

Les deux fichiers .tfm d'ASO partagent le même scan centré comme référence, donc le centrage s'annule et la composition est exacte. Gain : quelques minutes par patient, et un seul point d'édition manuelle : corriger un landmark à la pause t1_landmarks se propage automatiquement au repère MAX. Le regroupement en fichiers de sortie réutilise les GROUP_LABELS d'ALI, lus via ast.parse sur constants.py pour éviter d'importer torch (createlistprocess.py:1397).

5.4 reorganizeStat puis postprocess : de la mesure à la caractéristique

Explication en langage courant et maths : page de l'atlas.

run_aq3dc produit une ligne par (patient × mesure) avec 16 colonnes (R-L Component/Meaning, A-P, S-I, 3D Distance, Yaw, Pitch, Roll). reorganizeStat l'aplatit en colonnes signées Transverse, AP, Vertical, 3D, Yaw, Pitch, Roll, plus BL, MD, Rotation, Arch, Segment pour les droites dentaires. Trois natures, trois comportements :

  • VIEW : chargé et affiché, rien n'est réécrit.
  • LANDMARKS : loadEditableMarkups force SetLocked(False) sur le nœud et sur chaque point, et rend l'affichage visible, alors qu'ALI écrit ses points verrouillés et masqués. Les positions de départ sont enregistrées ; à Continue, savePauseEdits ne réécrit que les fichiers où au moins un point a bougé (VFACE.py:2313).
  • REGISTRATION : setUpAdjustment superpose le scan recalé à demi-opacité sur T1, le rattache à un vtkMRMLLinearTransformNode avec des poignées d'interaction. À Continue, saveAdjustedRegistration (VFACE.py:2344) convertit le déplacement RAS en LPS (flip = diag(-1,-1,1), lps = flip @ ras @ flip) et le compose dans le .tfm propre d'AREG : sitk.CompositeTransform([areg, nudge.GetInverse()]), parce qu'AutoMatrix en aval ne peut appliquer qu'une seule matrice. Le volume corrigé est ensuite figé et réécrit.

Deux contraintes d'ordre importantes dans le plan : le bloc de quantification est placé avant le bloc de visualisation, pour que la seule pause modifiable utile (t1_landmarks) n'arrive pas après cinq segmentations nnU-Net ; et enterPauseForReview ne charge rien directement, il arme un QTimer.singleShot(0, self.beginReview), parce que cela se produit dans un rappel d'observateur VTK, où la boucle d'événements Qt ne tourne pas et où charger un volume remplirait le tube stdout de Slicer sans lecteur (la même famille de bug que _briefCliOutput et outputToFile).

buildPauseQueue (VFACE.py:1876) filtre les fichiers trouvés par identité du patient, jamais par date : un dossier de sortie réutilisé contient les patients des exécutions précédentes. belongsToRun accepte un identifiant qui prolonge un identifiant attendu à une frontière _ (les heatmaps sortent sous la forme C_0001_Mandible_ModelDistance). Si le filtre vide entièrement la revue alors que des fichiers existaient, elle est désarmée plutôt que de sauter une pause demandée.

7.3 Navigation par lot : ce qui manque vraiment

Explication en langage courant et maths : page de l'atlas.

Le manque se trouve dans INPUT_KEYS (review_steps.py:168) :

INPUT_KEYS = ("input", "input_patient", "input_matrix")
Bug confirmé · Legacy uniquement

Legacy uniquement (3c67957) ; absent de VISOR, qui n'a ni navigation par lot ni étape de revue (VISOR:SADT-VISOR tools/VFACE/README.md:29-32).

Seuls ALI, PRE_ASO, SEMI_ASO (input) et AutoMatrix (input_patient, input_matrix) peuvent être restreints. Manquent, pour le pipeline VFACE : inputVolume (AMASSS), t1_folder / t2_folder / mask_folder_t1 (AREG), input_folder_CBCT (resample), input_path (BDS), t1_path / t2_path (AQ3DC), t1_dir / t2_dir (heatmaps), source_folder &co (derive_landmarks). AREG, de son côté, couvre inputVolume, t1_folder, t2_folder, T1, T2, IOS_folder, CBCT_folder, input_folder_CBCT (Review.py:836-843).

Conséquences concrètes :

  • retour arrière depuis t1_masks → ASO est rejoué pour le seul patient signalé, mais les deux exécutions d'AMASSS repartent sur tout le lot (l'étape la plus lente) ;
  • retour arrière depuis registration_max ou _mand → le recalage Elastix est rejoué pour tout le lot ;
  • retour arrière depuis bone_surfaces → les cinq exécutions de BDS repartent sur tout le lot.

À noter avant de « corriger » cela : restreindre AQ3DC / postprocess / la classification serait nuisible, car ces étapes écrivent un xlsx agrégé reconstruit de zéro, et les restreindre effacerait les lignes des patients non signalés. La bonne correction consiste à ajouter les clés de volume/scan, pas toutes les clés de dossier.

Deux autres limites, moindres :

  • previousCorrectableStep cherche l'étape courante dans executed_steps par identité ; après un premier retour arrière, l'historique contient à la fois les étapes d'origine et leurs copies restreintes, et un second retour arrière rejoue une liste plus longue que nécessaire ;
  • le compteur affiché (Paused at step N/M) n'est pas rembobiné par un retour arrière : NumberProcess augmente, ActualProcess ne redescend pas.

VFACE n'a pas non plus l'équivalent de _normalisedId / _matchAcrossNaming d'AREG (appariement P1 ↔ P_0001), mais cela n'a pas d'importance pour lui : il n'a qu'une seule modalité.

Les heatmaps (batch_process, createlistprocess.py:2303) sont des résultats signés de vtkDistancePolyDataFilter entre la surface T1 et la surface T2 appariée, sur trois zones (merged CB, Mandible, Upper_Skull). Chaque paire s'exécute dans son propre processus (_batch_worker.py) parce que le filtre VTK alloue côté C++ des localisateurs que gc.collect() ne libère pas ; jusqu'à min(4, cpu_count // 2) workers en parallèle, délai de 600 s, stdout/stderr envoyés dans des fichiers (jamais dans des tubes : un worker bavard bloquerait). Au-delà de 1 M de points cumulés le worker décime à 0,5, au-delà de 2 M à 0,7, calcule la distance sur les maillages décimés puis la réinterpole sur le maillage d'origine via vtkPointLocator. Le tableau de sortie s'appelle Distance.

Le nettoyage, et son piège. OnEndProcess (VFACE.py:3214), si « Keep Intermediate files » est décoché, supprime chaque sous-dossier d'OutputFolder sauf ceux de la liste ci-dessus. Deux bugs y ont été corrigés et méritent d'être connus :

output = (self._parameterNode.OutputFolder or "").strip()

10. Pièges et points fragiles

Explication en langage courant et maths : page de l'atlas.

  • derive_landmarks ne peut pas fonctionner hors de « Full pipeline ». En mode « File already Oriented » / « already Registered », SplitOriented (createlistprocess.py:1900) ne copie que les fichiers .nii* / .nrrd* dans Oriented T1 Scans/, pas les fichiers .tfm. L'étape « Deriving T1 Landmarks (MAX) » consigne alors missing an orientation transform pour chaque patient, T1 Landmarks/MAX reste vide, Measurements_MAX.xlsx aussi, et la classification perd cinq caractéristiques sur quatorze.
  • CMFReg ne change pas le recalage, il ajoute seulement un dossier T2_Masks que rien ne lit (§1).
  • Suffixes _T1/_T2 codés en dur, trois copies marquées TIMEPOINT-SUFFIX dans createlistprocess. Un _T3 casse silencieusement l'appariement. La note de référence se trouve au-dessus de GetPatients dans AREG_CBCT/AREG_CBCT_utils/utils.py:60-79.
  • Sélection de masque par mot-clé : CBMASK ne l'emporte sur MANDMASK que par l'ordre alphabétique (§4.4).
  • _index_measurements garde la première ligne pour une étiquette de landmark répétée. Deux mesures de types différents sur la même paire de points (par ex. B/B en T1 et en T1↔T2) se masqueraient l'une l'autre.
  • writeMeasurementExcel écrit sans index=False : les fichiers xlsx portent une colonne parasite Unnamed: 0.
  • Les listes de mesures sont appariées par nom de fichier (CB, MAND, MAX, FEAT en majuscules dans le nom). Un fichier nommé MAX_and_MAND.xlsx tomberait dans la première branche qui correspond.
  • Les étapes Python figent l'interface. Pas de thread : startPythonProcess appelle directement la fonction, avec les fd 1 et 2 redirigés vers un fichier temporaire (outputToFile, VFACE.py:3495), torch et nnU-Net écrivent depuis du C, où remplacer sys.stdout ne suffirait pas.
  • Le paramètre spacing est passé comme liste Python ([0.3,0.3,0.3]) à un paramètre déclaré <string> dans le XML, et la CLI fait spacing.split(","). Cela fonctionne grâce à la sérialisation de Slicer, et MRI2CBCT fait la même chose, mais c'est implicite.
  • Code mort notable : tout le widget AQ3DCWidget (~1200 lignes de functionaq3dc.py, jamais instancié hors des tests) ; Measure.isUtilMeasure (l'appel est commenté, functionaq3dc.py:2172) ; check_skeletal et SKELETAL_LM_RL dans Measure.py ; GetDictPatients / GetMatrixPatients ; les variables T1/T2 calculées et jamais utilisées dans reorganizeStat ; l'initialisation par QCheckBox de keep_sign dans run_aq3dc (la valeur est déjà True, jamais None) ; VFACELogic.process, VFACETest et registerSampleData (code passe-partout du modèle Slicer, les URL VFACE1/VFACE2 pointent vers des données de test génériques) ; les trois modèles de segmentation alternatifs de segmentation_logic.py.
  • Le bouton « Test Files » télécharge l'archive d'AREG (Or_FullyAuto.zip), en supprime le T2 (VFACE construit le sien) et pointe l'entrée vers le T1. VFACE n'a pas d'archive de test à lui.

Le résumé public décrit 170 patients de classe III, et la même chaîne amont : prétraitement standardisé, miroir, recalage voxel, extraction de mesures anatomiques.

Divergence entre code et article

Le code diverge de l'article à la dernière étape. Le résumé décrit une approche non supervisée : réduction de dimension (PCA, t-SNE, UMAP) puis Spectral Clustering, UMAP+RBF donnant le meilleur score de silhouette. Le module, lui, embarque trois classifieurs LightGBM binaires supervisés entraînés sur 14 caractéristiques fixes. Ce n'est pas le même modèle ; rien dans le dépôt ne relie les étiquettes d'entraînement des LightGBM aux clusters de l'article, et le script d'entraînement n'est pas versionné.

Aussi vrai dans VISOR : le portage lit la table de caractéristiques avec trois classifieurs à gradient boosting (LightGBM), pas avec une étape de clustering (VISOR:SADT-VISOR tools/VFACE/src/sadt_vface/classify.py:1-8 ; README.md:34-36).

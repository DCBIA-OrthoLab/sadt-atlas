MRI2CBCT : non porté sur VISOR

MRI2CBCT ne s'exécute pas sur un serveur VISOR. Cette page dit exactement ce qui en existe dans les dépôts VISOR : aucun outil serveur, un ancien module client conservé mais non compilé, et des fichiers de modèles listés pour un serveur qui n'a aucun outil pour s'en servir. Le module lui-même est décrit sur sa page legacy.

VISOR : non porté Page legacy Guide (VISOR)

État aux commits de référence : SADT-VISOR 6ba2a78, VISOR-serve e9a7e5d, AutomatedDentalToolsRemote 19b95e8 ; legacy désigne SlicerAutomatedDentalTools à 3c67957. Tout ce qui suit a été lu dans le code et les manifestes. Le MRI2CBCT que la page legacy documente est le module réécrit de 3c67957 (MRI2CBCT_core/, les modules en ligne de commande PREPARE, SEGMENT_MRI et REGISTER) ; il n'est porté nulle part, ni comme outil serveur ni comme panneau client.

Ce qu'est la copie client, et ce qu'elle n'est pas

AutomatedDentalToolsRemote conserve MRI2CBCTRemote/MRI2CBCTRemote.py (2397 lignes) et MRI2CBCT_CLIRemote/, six modules en ligne de commande : APPROX, ORIENT_CENTER_MRI, RESAMPLE_CBCT_MRI, REG, LR_CROP, TMJ_CROP. C'est le module antérieur, celui que la réécriture legacy a remplacé (voir la page legacy, section 1). Ce n'est pas un client de serveur : c'est un widget local qui lance ses modules en ligne de commande par slicer.cli.run et installe torch lui-même (pip_install("torch==2.2.0 ..."), MRI2CBCTRemote.py:117). Comme il n'est pas compilé, aucun utilisateur de l'extension VISOR ne le reçoit. Un futur portage partirait de la réécriture legacy, non de cette copie.

Le modèle listé appartient à l'ancien module

Le commentaire du manifeste dit que le réseau de recadrage TMJ est « fetched by MRI2CBCT's install_nnunet() » (VISOR-serve scripts/data-manifest.yml:708). Cette fonction n'existe que dans la copie client non compilée (MRI2CBCTRemote.py:1244). Dans la réécriture legacy, la constante correspondante TMJ_CROP_MODEL n'est référencée par rien (legacy ADT/ADTLib/model_registry.py:70 ; voir la liste de code mort de la page legacy). Placer ce fichier sur un serveur ne prépare pas un portage du module actuel.

Ce que VISOR a réutilisé

Seulement l'étape de rééchantillonnage, et sous forme de copie. SADT-VISOR tools/VFACE/src/sadt_vface/resample.py embarque le comportement générique « mettre la cohorte sur une même grille de voxels et la recentrer » que le VFACE legacy obtient de MRI2CBCT_RESAMPLE_CBCT_MRI, toutes les branches propres à l'IRM étant désactivées (resample.py:1-34). SADT-VISOR PROVENANCE.md:53-56 consigne le coût : si MRI2CBCT est un jour porté, les deux copies peuvent diverger sans que rien n'échoue. Voir VFACE sur VISOR.

Aucun des constats de la page legacy ne peut être vérifié contre du code VISOR, puisqu'il n'y en a pas : ils décrivent tous la réécriture legacy à 3c67957.

AREG_CBCT sur VISOR : le code

Pour les développeurs : ce que fait le portage VISOR d'AREG_CBCT dans le code, avec des références file:line, les signatures, les arguments, l'environnement, les différences avec le code legacy et les constats. L'explication lisible de la même chaîne, avec les maths, se trouve sur la page de l'atlas. Le module legacy a sa propre page.

Code Atlas (explication) VISOR AREG_CBCT atteint comme AREG, mode CBCT moteur CPU seulement, elastix Page legacy Guide (VISOR) Bibliographie

AREG_CBCT recale un CBCT de suivi (T2) sur le CBCT de référence (T1) du même patient par un recalage rigide elastix, confiné à une région stable de T1. Dans VISOR, tout le calcul s'exécute sur un serveur ; Slicer ne fait qu'afficher le formulaire, envoyer les dossiers et ouvrir ce qui revient. Cette page décrit ce portage, lu à SADT-VISOR 6ba2a78 (branche tool/vface), VISOR-serve e9a7e5d et AutomatedDentalToolsRemote 19b95e8. Le module legacy auquel on le compare est SlicerAutomatedDentalTools 3c67957, décrit sur sa propre page ; les chemins legacy ci-dessous sont à ce commit.

Abréviations utilisées sur cette page : cbct/ est SADT-VISOR tools/AREG/AREG_CBCT/src/sadt_areg_cbct/, common/ est SADT-VISOR tools/AREG/common/src/sadt_areg_common/, et les chemins server/ sont dans VISOR-serve. “Observé” marque ce qui a été exécuté (tests, scripts/describe.py, courtes sondes Python) pendant l'étude du portage ; tout le reste a été lu dans le code.

1. Situation dans la chaîne

Explication en langage courant et maths : page de l'atlas.

Un client ne nomme jamais AREG_CBCT. Le module Slicer envoie AREG, une façade déclarée dans le fichier de déploiement du serveur, avec mode = "CBCT" ; le serveur remplace la façade par sa cible et exécute ce moteur. Le moteur lui-même ne calcule que l'appariement et le recalage : les masques et l'orientation viennent de deux autres outils qu'il appelle par le superviseur (sup.run), chacun dans son propre environnement.

Le README d'AREG dit qu'aucune chaîne supervisée n'a été exécutée de bout en bout avec les vrais outils et que rien n'a été comparé à l'implémentation d'avant le portage (SADT-VISOR tools/AREG/README.md:132-137).

3.1 Entrées, DICOM et appariement

Explication en langage courant et maths : page de l'atlas.

Forme des entrées. register crée <output_dir>/.areg_work/ et transforme chaque entrée en dossier : un dossier est utilisé tel quel, un fichier seul est lié en dur (ou copié) dans un dossier à lui, parce que le serveur place chaque envoi d'une requête dans un seul dossier de travail et que le dossier parent d'un fichier contiendrait sinon l'autre instant (cbct/dispatch.py:360-378,420-424). Les fichiers de scan sont reconnus par leur extension, .nii.gz .nrrd.gz .gipl.gz .nii .nrrd .gipl (common/pairing.py:36) ; les sélecteurs ne filtrent rien, à dessein, parce que la façade refuserait de publier un t1 qui désigne un volume dans un mode et une surface dans un autre (cbct/__init__.py:24-31).

DICOM. Avec dicom_input activé, chaque arborescence est convertie dans .areg_work/dicom_t1 et dicom_t2 (cbct/dispatch.py:211-213). convert_tree parcourt toute l'arborescence, lit chaque série avec le lecteur GDCM de SimpleITK et se rabat sur dicom2nifti dans un dossier de transit vide (cbct/dicom.py:39,81-107). Sa docstring liste les trois comportements du legacy qu'il supprime : écrire dans <input>/NIFTI/, ne regarder qu'un niveau plus bas, et renommer un fichier antérieur arbitraire dans le repli (cbct/dicom.py:1-22).

Dossiers de cohorte. timepoint_root descend dans <cohort>/T1 et <cohort>/T2 quand le dossier envoyé est une cohorte entière, ce qui est la façon dont sont organisées les entrées de test hébergées ; un dossier qui contient plusieurs instants mélangés est refusé plutôt qu'apparié au hasard (cbct/dispatch.py:219-220, common/pairing.py:313-361).

Clé de patient. Un fichier appartient au sujet nommé par patient_stem : l'extension est retirée, puis tout ce qui suit un suffixe laissé par une exécution précédente (_lm_Pred _Scanreg _MERGED _OutReg _SegOr _scan _Scan _Seg _seg _Or _OR _lm) est coupé, à condition que le suffixe se trouve sur des frontières d'éléments, puis les éléments d'instant t1 t2 t0 sont retirés comme éléments entiers (common/pairing.py:175-211, common/catalogs.py:148,158-161). La clé est le dossier relatif plus ce radical, si bien que P1_T1_scan.nii.gz dans le dossier T1 s'apparie avec P1_T2.nii.gz dans le dossier T2. Observé pendant l'étude : P1.2_scan donne P1_2, P001_T3 reste P001_T3.

matched = pairing.pair(t1_root, t2_root, suffix)          # dispatch.py:259
report["unmatched"] = matched.unmatched_report()
if not matched:
    raise ToolInputError("No subject appears in both the T1 and the T2 folder. ...")

Un sujet présent à un seul instant est listé sous unmatched ; une exécution où rien ne s'apparie s'arrête avec une erreur qui énonce la règle de nommage et les décomptes (cbct/dispatch.py:259-268).

3.2 Orientation et masques : les deux appels supervisés

Explication en langage courant et maths : page de l'atlas.

Avant qu'un fichier soit lu, main refuse ce qui ne peut pas marcher : aucune région sélectionnée, Semi-Automated sans t1_masks, un mode automatique sans superviseur (tools.require, avec un conseil sur le mode à utiliser à la place), le mode Oriented sans référence, un mode automatique sans bundle AMASSS (cbct/dispatch.py:105-153, cbct/tools.py:45-69). Un segmentation_model vide est résolu en DATA/AREG/models/AMASSS_Models quand ce dossier existe (cbct/dispatch.py:83-102,504-505) ; la reference n'est jamais résolue pour vous dans ce moteur.

Orientation, Oriented + Fully-Automated seulement (cbct/dispatch.py:229-236, cbct/tools.py:93-107). Seul le dossier T1 est envoyé ; le T2 n'est jamais orienté.

sup.run("ASO",
        input=<T1 folder>, reference=<orientation reference>,
        modality="CBCT", automation="Fully-Automated",
        output_suffix="Or"
        [, landmark_model=...])        # only if one was named; hidden in the panel

Aucun cbct_landmarks n'est envoyé, donc ASO utilise son défaut, le jeu Francfort Ba S N RPo LPo ROr LOr (SADT-VISOR tools/ASO/src/sadt_aso/__init__.py:51), et demande ces sept points à ALI_CBCT. Le dossier que renvoie ASO remplace la racine du T1 pour le reste de l'exécution, et le rapport note oriented_t1: true.

Masks, Fully-Automated et Oriented (cbct/dispatch.py:246-256, cbct/tools.py:110-139). Un seul appel à AMASSS couvre les masques de région et les structures cochées sous « AMASSS segmentation » :

structures = ["CBMASK" | "MANDMASK" | "MAXMASK" for each ticked region]
           + [codes of ticked segmentations not already there]   # CB CV MAND MAX SKIN UAW
sup.run("AMASSS",
        scans=<T1 folder>, model=<AMASSS_Models>,
        structures=structures, merge=["SEPARATE"],
        prediction_ID="seg", generate_surface=False)

Les codes de région viennent de common/catalogs.py:68-84, les codes de segmentation de :96-103. Le dossier que renvoie AMASSS est lu comme une racine de masques de plus. Les structures qu'on a demandé de récupérer sont copiées depuis l'espace de travail du superviseur vers <output_dir>/Segmentations/<AMASSS folder>/, appariées sur le code qui termine le nom de fichier sans extension (cbct/dispatch.py:160-195). Seul le T1 est segmenté.

Trouver le masque d'une région (cbct/pipeline.py:102-139, common/pairing.py:376-404). Les racines de masques sont essayées dans l'ordre, d'abord le t1_masks de l'appelant, puis le dossier du T1 (Semi-Automated) ou la sortie d'AMASSS ; la première racine qui contient un masque du patient l'emporte. Un fichier est un masque de la région CB seulement si son nom sans extension porte un jeton de segmentation (mask seg pred segmentation) et un des jetons de la région (cb cbmask cranialbase cranial ; mand md mandmask mandible ; max mx maxmask maxilla), chacun comme jeton entier (common/catalogs.py:117-125). AMASSS écrit un dossier <scan>_<id>_SegOut/ par scan, si bien que ses masques ont une clé de chemin relatif différente de celle de leurs scans ; find_masks se rabat sur le dernier composant de la clé, et seulement si cette feuille est non ambiguë dans toute l'arborescence. Un patient sans masque pour une région obtient status: "failed" pour cette région, avec une raison qui donne la règle de nommage en mode Semi-Automated (cbct/dispatch.py:283-289,309-321).

3.3 Le recalage

Explication en langage courant et maths : page de l'atlas.

register_patient fait tout le travail pour un patient et une région (cbct/pipeline.py:38-99) :

fixed = sitk.ReadImage(t1_path)
mask = sitk.ReadImage(mask_path)
masked, note = elastix.apply_mask(fixed, mask, label=segmentation_label)
moving = sitk.ReadImage(t2_path)
transform = elastix.register(masked, moving)        # fixed = the masked T1
resampler = sitk.ResampleImageFilter()
resampler.SetReferenceImage(moving)                 # the T2's own grid
resampler.SetTransform(transform)
resampler.SetInterpolator(sitk.sitkLinear)
resampler.SetDefaultPixelValue(0)
registered = sitk.Cast(resampler.Execute(moving), sitk.sitkInt16)

Application du masque (cbct/elastix.py:133-183). apply_mask refuse un masque dont la taille diffère de celle du scan, ou dont l'espacement diffère de plus de 1e-4, puis copie la géométrie du scan sur le masque (un échantillonnage identique signifie que toute différence restante d'origine ou de direction est une dérive de flottants). Avec segmentation_label renseigné, elle binarise sur ce label et refuse un label que le masque ne contient pas, en nommant les labels présents ; avec 0, elle utilise le masque entier et, si le masque contient plusieurs labels, renvoie une note qui finit dans le rapport. Les voxels hors du masque sont mis à zéro avec sitk.Mask : elastix ne reçoit aucun masque fixe séparé, ce qui explique que ErodeMask soit inerte (cbct/elastix.py:109-112).

elastix (cbct/elastix.py:190-209). Les deux images vont à itk.ElastixRegistrationMethod sous forme d'images itk float32 construites en mémoire avec leur origine, leur espacement et leur direction (cbct/elastix.py:253-264) ; rien n'est écrit sur disque et l'image résultat n'est pas demandée. La carte de paramètres est la carte rigid par défaut d'elastix, dont ces entrées sont écrasées (cbct/elastix.py:82-126) :

ParamètreValeurCommentaire dans le code
TransformationEulerTransform (issu de la carte rigid)6 degrés de liberté
NumberOfThreads, ImageSampler, NewSamplesEveryIteration1, Grid, falsedéterminisme : deux exécutions donnent la même transformation
NumberOfResolutions3, pyramides de lissagedu grossier au fin
MetricAdvancedMattesMutualInformation, 64 classes, gradient normalisé
OptimizerConjugateGradient, 1500 itérations, pas de 2.0 à 0.001, tolérances 1e-6
AutomaticTransformInitializationtrue, GeometricalCenterajouté explicitement : il remplace le pré-centrage legacy du T2
AutomaticScalesEstimationtrue
ImagePyramidSchedulesupprimésix valeurs pour une image 3D sur trois niveaux étaient écartées par elastix ; leur suppression a été vérifiée identique au bit près (cbct/elastix.py:68-75)
ErodeMask, NumberOfSpatialSamplestrue, 30000conservés par fidélité, tous deux inertes ici

Transformer le résultat en transformation (cbct/elastix.py:212-250). elastix rapporte trois angles d'Euler, une translation et un centre de rotation, la transformation étant y = R(x − c) + c + t. Le port lit CenterOfRotationPoint et le pose sur la transformation SimpleITK :

transform = sitk.Euler3DTransform()
transform.SetCenter(center)                       # CenterOfRotationPoint
transform.SetRotation(angleX=values[0], angleY=values[1], angleZ=values[2])
transform.SetTranslation(values[3:6])

Une AffineTransform est convertie de la même façon ; tout autre type lève une exception au lieu de produire un résultat plausible mais faux (cbct/elastix.py:235-250). La transformation fait passer un point du repère T1 au point correspondant du repère T2, le sens que consomme ResampleImageFilter, et le rapport le dit en toutes lettres (cbct/elastix.py:190-196, cbct/pipeline.py:92).

Les erreurs sont gérées par région. Une RegistrationError (géométrie du masque, label absent, type de transformation inconnu) ou une RuntimeError d'elastix marque cette région comme échouée avec sa raison, et la boucle continue (cbct/dispatch.py:290-304). Un patient est « ok » dès qu'au moins une région a été recalée (cbct/dispatch.py:324-328).

3.4 Sorties et rapport

Explication en langage courant et maths : page de l'atlas.

L'outil renvoie un seul chemin, il n'y a donc pas de sorties nommées : le dossier de sortie est archivé puis envoyé en flux. Pour chaque région et chaque patient (cbct/pipeline.py:72-83) :

<output_dir>/
  <CB|MAND|MAX>/<relative folder>/
      <patient>_<CODE>_<suffix><ext>              # registered T2, T2 grid, Int16
      <patient>_<CODE>_<suffix>_transform.tfm     # T1 frame -> T2 frame
  Segmentations/<AMASSS folder>/...               # only the structures ticked
  AREG_report.json

L'extension suit celle du T2 sous sa forme compressée : .nii devient .nii.gz, .gipl devient .gipl.gz, et l'image est écrite avec compression (common/pairing.py:40,58-59, cbct/pipeline.py:76-80). Le .tfm est écrit par sitk.WriteTransform, dans la convention ITK (LPS). Le suffixe par défaut est Reg ; un suffixe contenant un séparateur de chemin est refusé (cbct/dispatch.py:489-491). Le dossier de travail .areg_work/ est supprimé avant l'écriture du rapport (cbct/dispatch.py:455).

AREG_report.json (cbct/dispatch.py:43,426-431,457-459) a cette forme ; les clés marquées optionnelles n'apparaissent que dans les modes qui les produisent :

{"modality": "CBCT", "automation": "...", "output_suffix": "Reg",
 "regions": ["Cranial base", ...], "segmentation_label": null,
 "oriented_t1": true,                  # optional, Oriented mode
 "segmented_t1": ["CBMASK", ...],      # optional, automatic modes
 "segmentations": ["Segmentations/..."],   # optional, ticked structures
 "unmatched": {...},
 "patients": {"<key>": {"status": "ok" | "failed",
     "regions": {"CB": {"status": "ok", "region": "Cranial base",
                        "mask": "<mask file>",
                        "transform_maps": "T1 space -> T2 space (...)",
                        "outputs": [...], "note": "..."}}}},
 "summary": {"patients": N, "registered": n, "failed": m}}

L'entrée par région est construite en cbct/pipeline.py:85-99, le résumé en cbct/dispatch.py:381-387.

8. Constats dans VISOR

Explication en langage courant et maths : page de l'atlas.

Transformation elastix désormais exacte

Le centre de rotation est lu et appliqué, et le centre parvient à la transformation (cbct/elastix.py:212-240, SADT-VISOR tools/AREG/AREG_CBCT/tests/test_elastix.py:50) et les tests unitaires retrouvent une transformation rigide connue sur un fantôme à moins de 0,2 mm près (tests/test_run.py:69-98, TestElastix). Observé : pytest dans l'environnement de l'outil, 101 réussis.

Les sujets non appariés sont signalés

Un sujet présent à un seul point temporel est listé sous unmatched dans AREG_report.json au lieu de disparaître (cbct/dispatch.py:259-260). Lu dans le code.

Mode Oriented avec la référence Occlusal

Le code legacy déduisait la liste de landmarks de la référence choisie (AREG/AREG_Method/CBCT.py:629-630@3c67957 : six landmarks Occlusal ou sept Francfort). L'appel VISOR à ASO n'en envoie aucune (cbct/tools.py:93-107), le défaut d'ASO est le jeu Francfort Ba S N RPo LPo ROr LOr (SADT-VISOR tools/ASO/src/sadt_aso/__init__.py:51), et ASO refuse une sélection que la référence ne peut pas supporter, parce que les deux références publiées portent des jeux de landmarks disjoints (SADT-VISOR tools/ASO/src/sadt_aso/dispatch.py:435-458, appelé à la ligne 629). Une référence Occlusal choisie dans ce mode devrait donc se terminer par ce refus. Lu dans le code ; la chaîne n'a pas été exécutée.

Le dossier de travail temporaire n'est pas supprimé quand une exécution échoue

register supprime .areg_work/ après le retour du moteur, sans try/finally (cbct/dispatch.py:397-460, shutil.rmtree à la ligne 455 ; le moteur s'exécute aux lignes 433-450), alors que son commentaire dit qu'il est supprimé que l'exécution réussisse ou non (cbct/dispatch.py:452-454). AREG_IOSCBCT a le finally (SADT-VISOR tools/AREG/AREG_IOSCBCT/src/sadt_areg_ioscbct/dispatch.py:357-358). Une exception non interceptée par patient laisserait les copies des entrées, le DICOM converti et le T1 orienté dans le dossier de sortie que le serveur archive. Lu dans le code ; non déclenché.

Déclaré mais inutilisé

torch==2.8.0 est une dépendance du moteur (SADT-VISOR tools/AREG/AREG_CBCT/pyproject.toml:11) qu'aucun module de cbct/ n'importe (observé : grep de import torch et from torch, aucune correspondance). Le README d'AREG chiffre la synchronisation complète de l'environnement, avec les wheels CUDA, à environ 5,8 GB (SADT-VISOR tools/AREG/README.md:143). Dans le paquet partagé, common/scans.py n'est importé par aucun fichier de tools/AREG (grep, lu dans le code) ; la table d'extensions réellement utilisée est common/pairing.py:36.

Une docstring promet une règle de masque que le code n'a pas

La docstring de discover_masks dit qu'un fichier compte aussi comme masque « when it is the only candidate in a folder that holds nothing but masks » (common/pairing.py:379-382). La boucle n'accepte un fichier que s'il porte à la fois un jeton de segmentation et un jeton de région (common/pairing.py:397-401). Les noms propres à AMASSS (<scan>_seg_CBMASK) satisfont les deux, donc les modes automatiques ne sont pas touchés ; un dossier de masques envoyé en mode Semi-Automated avec des noms qui n'ont ni l'un ni l'autre jeton ne trouve aucun masque. Lu dans le code.

AutoMatrix avec VISOR

Ce qui change quand vous lancez AutoMatrix via un serveur VISOR depuis 3D Slicer : ce qu'il faut fournir, ce qui reste pareil, ce qui diffère. Le module legacy a sa propre page.

VISOR Page legacy Atlas (VISOR)

Avec un serveur VISOR, le module s'appelle AutoMatrix Remote. Vous choisissez les fichiers et les transformations dans Slicer ; ils sont envoyés au serveur, qui les apparie par patient, les déplace, et renvoie les résultats dans un dossier de votre choix. Le panneau est construit à partir de ce que publie le serveur. Rien n'est installé ni téléchargé sur votre ordinateur.

Ce que vous fournissez

  • Files to transform : un scan, une segmentation, un fichier de landmarks (.mrk.json) ou un dossier de ces fichiers. Un serveur peut héberger des jeux de test (AutoMatrixRelease1 à 4) qui apparaissent dans la liste déroulante.
  • Transforms : .tfm, .mat, .h5, .hdf5 ou .txt, un fichier ou un dossier. Un fichier contenant une simple matrice 4×4 (quatre lignes de quatre nombres, ce que GreedyReg écrit en .mat) est lu aussi, comme une matrice affine prise telle qu'écrite.
  • Same transform for every patient : cochez-la quand vous donnez une seule transformation pour tout le dossier. Sans elle, une transformation dont le nom ne correspond à aucun patient n'est utilisée que s'il y a exactement un patient ; avec plusieurs patients, rien n'est écrit et l'exécution s'arrête avec une erreur.
  • Include the transform name et Output suffix (Reg par défaut, de sorte que P1_T1.nii.gz revient sous le nom P1_T1_Reg.nii.gz).
  • Use the mirror matrix : une case remplit Transforms avec la matrice miroir hébergée par le serveur et coche « Same transform for every patient ». Elle est grisée si le serveur n'héberge pas ce fichier.

Deux réglages sont masqués dans le panneau : la façon de rééchantillonner (le serveur décide fichier par fichier si un volume est une labelmap, il n'y a donc plus de case segmentation) et le volume de référence.

Ce qui reste pareil

  • Les volumes sont rééchantillonnés avec la transformation ; les points de landmarks se déplacent par son inverse, de sorte qu'un scan et ses landmarks gardent le même mouvement.
  • Plusieurs transformations pour un patient donnent une sortie chacune, jamais une chaîne. Le coordinateSystem des landmarks n'est toujours pas lu.
  • La sortie conserve l'arborescence des dossiers d'entrée ; jusqu'à 12 résultats sont chargés dans la scène.

Ce qui diffère

  • Une seule règle de nommage pour les scans et les matrices (P1_scan.nii.gz s'apparie avec P1_matrix.tfm). Là où elle échoue, un repli imite les coupes du legacy, et le rapport dit quels patients ont été appariés ainsi (paired_by).
  • Les fichiers non appariés sont signalés dans AutoMatrix_report.json.
  • Pas de maillages ni de .npy ; les volumes pris en charge sont .nii.gz .nii .nrrd .gipl et leurs formes .gz (.nrrd.gz est recherché mais ne peut pas être lu).
  • Une transformation non inversible (un champ de déformation) fait échouer le fichier de landmarks de ce patient ; l'échec figure dans le rapport.
La ligne d'état finale est fausse

Le message affiché dans la barre d'état de Slicer à la fin de l'exécution dit toujours « AutoMatrix: 0 file(s) written. », et ne mentionne jamais les fichiers non appariés. Il lit deux champs que le rapport n'a pas. Jugez l'exécution d'après le dossier de sortie et d'après AutoMatrix_report.json (summary.files_written, without_a_transform, transforms_without_a_file).

Sans volume de référence, le résultat peut atterrir à côté des données

Le panneau n'offre aucun volume de référence. Sans lui, la sortie garde la taille de l'entrée mais prend pour origine l'image de l'origine par la transformation. Testé le 2026-11-09 en appelant directement l'outil du serveur avec une matrice de réflexion de substitution sur un petit volume centré sur l'origine : la sortie était vide, et elle était complète quand le volume était sa propre référence. Une simple translation décale aussi le contenu et peut en couper une partie. C'est ce qu'utilise la boîte miroir. Un correctif existe sur une branche non fusionnée (fix/automatrix-mirrors-into-an-empty-box, commit ce4f6fb) : regardez donc le résultat avant de vous y fier. Détails sur la page de l'atlas.

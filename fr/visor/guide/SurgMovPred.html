SurgMovPred avec VISOR

Ce qui change quand vous lancez SurgMovPred via un serveur VISOR depuis 3D Slicer : ce qu'il faut fournir, ce qui reste pareil, ce qui diffère. Le module legacy a sa propre page.

VISOR Page legacy Atlas (VISOR)

Avec VISOR, SurgMovPred s'exécute sur un serveur et Slicer n'affiche que son panneau. La prédiction elle-même est la même : les mêmes 112 modèles, appliqués ligne par ligne à votre table. Ce qui change, c'est ce que vous devez fournir.

  • Une seule entrée au lieu de deux dossiers. Le panneau legacy demandait un dossier d'entrée et un dossier de modèles ; ici vous ne donnez que les mesures, une seule table .csv, .xlsx ou .ods, ou un dossier de tables. Il n'y a pas de dossier de modèles à télécharger ni à désigner : le serveur détient les modèles et le panneau masque ce choix. Le serveur peut aussi proposer sa table d'exemple hébergée (patients_to_predict.xlsx, 101 patients) comme fichier de test.
  • Les règles d'entrée sont inchangées. Un dossier est lu à plat, sans ses sous-dossiers ; seule la première feuille d'un classeur est lue ; les en-têtes sont nettoyés de la même façon ; la colonne d'identifiant du patient est détectée par les mêmes noms ; un modèle dont les colonnes ne sont pas toutes présentes est sauté, avec la même tolérance _T0 (VISOR:SADT-VISOR tools/Surg_Mov_Pred/src/sadt_surgmovpred/pipeline.py:143-147,223-236).
  • Le résultat est enregistré, pas chargé. Comme avant, vous choisissez un dossier de sortie. Le serveur renvoie un zip contenant predictions_outputs.xlsx et predictions_outputs.csv, le panneau le décompresse à cet endroit, et rien n'apparaît dans la scène Slicer. Les deux fichiers commencent par une colonne sans nom de numéros de ligne avant IDPatient (pipeline.py:283-284).
  • Aucune dépendance n'est installée sur votre machine. La réinstallation de numpy à chaque Apply ne concerne que le module legacy ; le serveur exécute l'outil dans son propre environnement.
  • Ordre de sortie stable. Les modèles sont lus dans l'ordre trié, les colonnes arrivent donc dans le même ordre à chaque exécution, et les fichiers d'un dossier sont empilés dans l'ordre trié (pipeline.py:143-147,173).
Deux cas s'arrêtent désormais avec une erreur

Si un en-tête ne peut pas être nettoyé en nom de colonne, l'exécution s'arrête et nomme la colonne (VISOR:SADT-VISOR tools/Surg_Mov_Pred/src/sadt_surgmovpred/pipeline.py:57). Si aucun modèle ne peut prédire à partir de votre table, l'exécution s'arrête avec une erreur au lieu de produire des fichiers vides (pipeline.py:260). Une table à laquelle il manque seulement certaines colonnes donne simplement moins de colonnes prédites, sans erreur.

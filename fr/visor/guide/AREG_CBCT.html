AREG_CBCT avec VISOR

Ce qui change quand vous lancez AREG_CBCT via un serveur VISOR depuis 3D Slicer : ce qu'il faut fournir, ce qui reste pareil, ce qui diffère. Le module legacy a sa propre page.

VISOR Page legacy Atlas (VISOR)

AREG_CBCT recale un CBCT de suivi (T2) sur le CBCT de référence (T1) du même patient, sur une région qui n'a pas changé entre les deux. Avec VISOR, le recalage est calculé sur un serveur : dans Slicer, vous remplissez un formulaire, envoyez les dossiers et récupérez les résultats. Ce que vous faites est identique dans l'esprit, mais le panneau et quelques détails diffèrent. Cette page a été écrite à partir du code de VISOR (SADT-VISOR 6ba2a78, VISOR-serve e9a7e5d, AutomatedDentalToolsRemote 19b95e8) ; le comment et le pourquoi sont sur la page de l'atlas.

Ce qui change dans le panneau

  • Ouvrez le module AREG Remote (catégorie “Automated Dental Tools Remote”). Un seul module sert les trois sortes de recalage AREG : le premier champ, Mode, est celui où vous choisissez CBCT. Les autres champs suivent ensuite le mode.
  • Automation garde les trois choix (Semi-Automated, Fully-Automated, Oriented + Fully-Automated) et démarre sur Fully-Automated.
  • Rien à télécharger : les modèles de segmentation et d'orientation restent sur le serveur, et le champ du modèle de segmentation n'est pas affiché.
  • Les pauses de revue (“Review and manual adjustment”), la case Merge Segmentations et Include Approximation Step ne sont pas dans le panneau.
  • La case Load the results into the scene when done est cochée par défaut. Elle charge les volumes recalés, jamais le .tfm, et ne charge rien du tout quand plus de 12 fichiers reviennent.

Ce que vous fournissez

  • T1 et T2 : un dossier chacun, ou une cohorte de test hébergée choisie dans la liste au-dessus des sélecteurs. Un seul dossier de cohorte contenant T1/ et T2/ est accepté. Formats acceptés : .nii.gz .nrrd.gz .gipl.gz .nii .nrrd .gipl. Cochez Input is DICOM pour des séries DICOM.
  • Register on : les régions, comme avant. Chacune donne son propre recalage et son propre dossier de sortie.
  • En Semi-Automated, les T1 masks, qui sont obligatoires. Un masque est reconnu quand son nom contient un mot de masque (mask, seg, pred ou segmentation) et un mot de région comme parties distinctes du nom.
  • En Oriented + Fully-Automated, la Orientation reference, qui est obligatoire.
  • AMASSS segmentation (modes automatiques) : coche les structures que vous voulez aussi récupérer pour les examiner. Elles ne changent pas ce qu'utilise le recalage.

Ce qui reste pareil

Un recalage rigide elastix, confiné à la région que vous avez choisie sur T1, avec T2 amené dans le repère de T1. Pour chaque patient et chaque région, vous obtenez le T2 recalé et son .tfm. Vos entrées ne sont pas modifiées.

Ce qui diffère dans les résultats

  • Les résultats sont dans un dossier par code de région (CB, MAND, MAX), plus AREG_report.json à la racine : pour chaque patient et chaque région, si cela a fonctionné, quel masque a été utilisé, et une note quand quelque chose sortait de l'ordinaire.
  • La transformation écrite inclut désormais le centre de rotation utilisé par elastix. Le module legacy l'omettait, si bien que sa transformation pouvait différer du recalage qu'elastix avait réellement trouvé, d'un écart qui croît avec la distance du scan à l'origine ; la page de l'atlas donne les chiffres.
  • T2 n'est plus centré au préalable, et en mode Oriented seul T1 est orienté.
  • Seul T1 est segmenté : les segmentations du T2 recalé que le module legacy pouvait renvoyer ne sont pas produites.
  • Un sujet trouvé dans un seul des deux dossiers n'est pas écarté en silence : il est listé dans le rapport, et une exécution où rien ne s'apparie s'arrête avec une erreur qui explique la règle d'appariement.
Mode Oriented : choisissez la référence Frankfurt

L'étape d'orientation demande à ASO ses landmarks par défaut, le jeu Frankfurt, quelle que soit la référence que vous avez choisie. La référence Occlusal porte d'autres landmarks, et ASO refuse une combinaison qu'il ne peut pas prendre en charge. Si vous choisissez la référence Occlusal dans ce mode, attendez-vous à ce refus. Cela a été lu dans le code ; la chaîne n'a pas été exécutée.

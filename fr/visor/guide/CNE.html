CNE avec VISOR

Ce qui change quand vous lancez CNE via un serveur VISOR depuis 3D Slicer : ce qu'il faut fournir, ce qui reste pareil, ce qui diffère. Le module legacy a sa propre page.

VISOR Page legacy Atlas (VISOR)

Avec un serveur VISOR, l'extraction s'exécute sur le serveur, pas sur votre ordinateur, et le panneau CNE est un formulaire qui y envoie vos notes. Le détail du code est sur la page de l'atlas ; la connexion et l'exécution en général sont dans Utiliser VISOR.

Vos notes sont envoyées

Le texte des notes que vous sélectionnez quitte votre poste de travail et est lu par le serveur. Le client actuel ne désidentifie rien avant l'envoi, donc le « Nothing leaves your machine » du guide legacy ne s'applique pas ici. Retirez d'abord les informations identifiantes, et n'utilisez qu'un serveur que votre établissement a approuvé pour du texte clinique. Ce qui est protégé et ce qui ne l'est pas est expliqué dans Sécurité et confidentialité dans VISOR.

Ce qui change dans le panneau

  • Rien n'est installé dans Slicer : pas de paquets supplémentaires, pas de téléchargement de modèle de plusieurs gigaoctets. Le modèle est sur le serveur.
  • Le modèle est celui qui est sélectionné dans le champ Model, pas un modèle choisi pour votre type de note. Certains textes du client disent qu'on peut laisser le modèle sur « automatic » et que le serveur choisit alors celui de votre type de note. C'est obsolète : le champ n'a pas d'entrée « automatic », il liste les modèles hébergés sur le serveur, et rien ne vérifie que votre choix correspond au type de note, hormis un avertissement dans le rapport.
  • Seul le modèle TMJ est hébergé pour le moment. Vous pouvez toujours choisir Ortho comme type de note, mais il n'existe aucun modèle Ortho à lui associer. Si le modèle que vous choisissez est nommé pour l'autre type, l'exécution se poursuit et place un avertissement dans le rapport.
  • Les notes peuvent être dans des sous-dossiers (un dossier par patient fonctionne), et les extensions telles que .PDF sont trouvées quelle que soit leur casse.
  • Vous pouvez aussi fixer la réponse la plus longue par note (2048 tokens par défaut), la température et la fenêtre de contexte. Le processeur n'est pas un choix dans le panneau : le moteur de modèle de langage du serveur est la version CPU, l'extraction s'exécute donc sur le CPU.
  • Le champ des notes peut proposer une note de test hébergée sur le serveur (une note TMJ synthétique).

Ce qui diffère dans les résultats

  • Pour chaque note, vous obtenez deux fichiers, Extraction_<note file name>.json et un .txt lisible, avec l'extension source conservée : B_001.txt donne Extraction_B_001.txt.txt. Les notes qui partagent un nom mais pas une extension ne s'écrasent plus mutuellement.
  • Un fichier CNE_report.json indique quel modèle a tourné, avec quels réglages, quelles notes ont été extraites et pourquoi d'autres ne l'ont pas été. La barre d'état affiche un résumé d'une ligne et le nombre d'avertissements.
  • La réponse du modèle n'est jamais enregistrée en texte brut quand elle ne peut pas être lue : la note est signalée comme échouée. Un PDF scanné, composé d'images seules, est refusé nommément au lieu de produire une extraction inventée, et une réponse coupée à la limite de longueur est un échec, pas un fichier. Le contenu des tableaux des fichiers Word est lu.
  • Il n'y a pas de bouton Dashboard dans le panneau VISOR. Le Dashboard legacy lit des fichiers Extraction_*.txt avec les anciens noms, il ne s'applique donc pas tel quel à ces résultats.

Toujours vrai : le contenu vient du seul modèle, lisez donc chaque extraction avant de vous y fier. Rien ne découpe une longue note en morceaux pour qu'elle tienne dans la fenêtre de contexte, et le mode Ortho n'envoie aucune instruction à son modèle.

ALI avec VISOR

Ce qui change quand vous lancez ALI via un serveur VISOR depuis 3D Slicer : ce qu'il faut fournir, ce qui reste pareil, ce qui diffère. Le module legacy a sa propre page.

VISOR Page legacy Atlas (VISOR)

Avec un serveur VISOR, l'analyse s'exécute sur le serveur, pas sur votre ordinateur. Le module dans Slicer s'appelle ALIRemote. C'est un panneau qui envoie vos scans au serveur et rapporte les fichiers de landmarks. Comment se connecter et ce que le serveur fait de vos données est expliqué dans Utiliser VISOR ; cette page ne couvre que ce qui change pour ALI par rapport au module legacy. Elle est écrite à partir du code du serveur et du panneau, pas d'une session sur un serveur en service. Le détail, avec les références au code, se trouve dans ALI sur VISOR.

Ce qui change dans le panneau

  • Une seule fenêtre, un choix en haut. Le premier champ est le Mode, CBCT ou IOS. Il joue le rôle du type de données dans la fenêtre legacy. La liste de points qui suit change avec lui (119 points pour un CBCT, 153 pour un scan intraoral).
  • Aucun modèle à télécharger. Les poids entraînés restent sur le serveur. Le modèle, le périphérique et les réglages de recherche ne sont pas affichés dans le panneau.
  • L'entrée. Un fichier ou un dossier. Un dossier est zippé et envoyé pour vous. Le panneau peut aussi proposer les fichiers de test que le serveur héberge.
  • Les points se choisissent dans des onglets, un onglet par groupe. Si vous ne cochez rien, l'exécution CBCT place les 119.
  • Le résultat revient sous forme d'archive. Le panneau la décompresse, l'enregistre dans le dossier que vous avez choisi et, avec la case « Load the predicted landmarks into the scene » cochée (par défaut), charge les fichiers dans Slicer.

Ce qui reste pareil

Les noms de landmarks, les deux manières de travailler (un volume parcouru par un agent, une surface photographiée sous plusieurs angles), le format .mrk.json, et vos fichiers d'origine laissés intacts. Les points arrivent toujours verrouillés, comme dans les fichiers legacy : déverrouillez un point dans le module Markups avant de le déplacer.

Ce qui diffère dans les fichiers et dans les résultats

  • Un fichier par scan avec tous les groupes réunis, nommé <scan>_lm_Pred.mrk.json, là où le module legacy écrivait un fichier par groupe (CBCT) ou par mâchoire et par réseau (IOS). L'arborescence de vos dossiers d'entrée est reproduite dans le résultat.
  • Un rapport l'accompagne : run_report.json liste, scan par scan, les points placés et les points qui n'ont pas convergé.
  • Les formats intraoraux acceptés sont .vtk et .stl. Les maillages qui portent déjà des numéros de dents sont traités en premier ; un maillage qui n'en a pas passe par la segmentation des couronnes du serveur (Crown_Seg), puis suit.
  • Les fichiers de landmarks s'affichent au chargement. Les fichiers legacy étaient écrits avec leur affichage désactivé, si bien qu'en ouvrir un directement n'affichait rien ; les fichiers du serveur sont écrits visibles.
  • Les résultats intraoraux ne sont pas identiques à ceux du legacy. Sur le maillage comparé par les développeurs, 54 points sur 73 sont sortis exactement identiques et les autres sont tombés sur la bonne dent (README de VISOR, SADT-VISOR tools/ALI/README.md:213-226). Les points mucogingivaux passent par moins d'étapes de correction que dans le dernier module legacy.
  • DICOM. Le serveur convertit lui-même une série DICOM, rien n'est écrit dans votre dossier.
  • Temps. Le serveur indique 128 s pour 119 landmarks sur un scan avec 8 agents simultanés sur une carte RTX 6000 Ada (une mesure écrite dans la configuration du serveur, pas refaite ici). La configuration par défaut du serveur ne fixe aucune limite de durée pour une exécution.
Le message de fin d'exécution dit « 0 scan(s), 0 landmark(s) written »

Quoi qu'il se soit passé. Le panneau cherche la liste des scans sous un nom que le serveur n'utilise plus (ALIRemote.py:216 dans AutomatedDentalToolsRemote 19b95e8, contre cases dans le rapport du serveur). Lisez plutôt les fichiers chargés et le run_report.json du dossier de résultat ; les échecs y sont listés, et le message du panneau ne les liste jamais.

Choisir le dossier d'une seule série DICOM

Si vous désignez le dossier qui contient exactement une série DICOM, le fichier de résultat s'appelle ._lm_Pred.mrk.json, un fichier caché, qui n'apparaît pas dans une liste de fichiers ordinaire. Mettez la série dans un sous-dossier du dossier que vous choisissez, ou affichez les fichiers cachés. La cause a été vérifiée dans le code (les deux fonctions de nommage ont été exécutées) ; une exécution complète sur une vraie série n'a pas été refaite.

CBCT stocké dans une autre orientation

Le module legacy remet chaque CBCT dans une orientation standard (LPS) avant la recherche. La version serveur ne le fait pas. L'effet sur les points placés n'a pas été mesuré : regardez donc les landmarks sur le scan avant de les utiliser, surtout si votre volume ne provient pas d'un export DICOM.

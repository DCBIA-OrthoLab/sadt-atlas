AREG_CBCT

AREG_CBCT met un CBCT de suivi (T2) dans la même position que le CBCT initial (T1) du même patient, en utilisant seulement une région osseuse qui n'aurait pas dû changer : la base du crâne, la mandibule ou le maxillaire. C'est de l'elastix pur avec de l'information mutuelle et aucun réseau propre ; tout ce qui est appris se trouve en amont, dans les masques et les landmarks. Cette page explique la méthode pas à pas, avec les maths ; les développeurs trouveront le code, avec les références de fichier et de ligne, sur la page de code.

Tout sur cette page décrit le module Slicer legacy (SlicerAutomatedDentalTools à 3c67957, 2026-10-26). Le portage VISOR, qui exécute le même outil sur un serveur, a sa propre page : AREG_CBCT sur VISOR. Là où les deux diffèrent, la différence est nommée dans le texte par « Legacy uniquement » ou « aussi vrai dans VISOR ». Le code, avec les références de fichier et de ligne, est sur la page de code.

Vue d'ensemble : ce qui entre, ce qui sort

Un patient est scanné deux fois : au début (T1, l'état initial) et plus tard (T2, le suivi). Pour voir ce que le traitement ou la croissance ont réellement changé, les deux scans doivent être mis dans la même position. AREG_CBCT trouve le mouvement rigide (une rotation et une translation, six nombres) qui amène le T2 sur le T1, en utilisant seulement une région osseuse qui n'aurait pas dû changer : la base du crâne, la mandibule ou le maxillaire.

Ce qu'il prend et ce qu'il donne
Entréeun CBCT T1 et un CBCT T2 du même patient (.nii.gz, .nii, .nrrd, .gipl ou DICOM) ; en mode Semi-Automated, aussi les masques T1
Méthodele T1 est masqué sur la région choisie, puis elastix cherche les six nombres du mouvement par information mutuelle, du grossier au fin (section 5)
Sortiepour chaque région cochée : le T2 amené sur le T1 (sur la grille de la copie centrée du T2 : même taille et même espacement, origine déplacée) et son fichier de transformation (.tfm)
ModesSemi-Automated, Fully-Automated, Orientation & Registration (section 3)

Le recalage lui-même est de l'elastix pur sans réseau : tout ce qui est appris se trouve en amont, dans les masques et les landmarks.

1. Situation dans la chaîne

Le widget AREG dans Slicer pilote trois modalités (CBCT, IOS et IOS sur CBCT). Il ne calcule rien lui-même : pour chaque mode, il construit une liste d'étapes et les exécute l'une après l'autre, chaque étape étant un programme séparé. Le mode CBCT appelle, dans l'ordre :

ÉtapeModesRôle
Centrer le T2 (et le T1 en mode Orientation)les 3une translation du centre de l'image ; pas de réseau
ALI_CBCTOrientation uniquementplace 6 ou 7 landmarks sur le T1 prédit
Orientation du T1Orientation uniquementICP rigide de ces landmarks sur un gold standard calculé
AMASSSFully-Automated, Orientationles masques de la région de référence sur le T1 prédit
AREG_CBCTles 3le recalage lui-même, une fois par région cochée calculé
AMASSS de nouveaules 3, optionnelsegmentations finales du T1 et du T2 recalé prédit

Rien dans le dépôt n'appelle AREG : c'est un outil terminal. Ses fichiers .tfm sont en revanche réutilisés par AutoMatrix et les modules d'analyse.

2. Fichiers en jeu

Le module est un widget Slicer (le formulaire, l'enchaînement des étapes, les pauses de revue), une classe par mode qui construit les listes d'étapes, et un programme en ligne de commande qui fait le recalage dans un processus séparé. Contrairement au chemin IOS, rien du côté CBCT ne passe par conda : les paquets sont installés dans le Python propre à Slicer. Le recalage n'a pas besoin de GPU ; AMASSS en a besoin.

3. Les trois modes et la chaîne exacte

Le mode est choisi dans le widget. Les trois partagent la même fin de chaîne, centrer le T2, recaler pour chaque région, lancer l'AMASSS final, et ne diffèrent qu'en amont :

ModeEn amontMasques T1
Semi-Automatedaucunfournis par l'opérateur (champ « T1 Masks »)
Fully-AutomatedaucunAMASSS les prédit, écrits dans le dossier T1 d'entrée prédit
Orientation & Registrationcentrer le T1, ALI_CBCT, orienter le T1AMASSS sur le T1 orienté prédit

La région de référence est un choix de l'opérateur, pas quelque chose d'inféré : les cases Cranial Base, Mandible, Maxilla. Cocher deux régions lance deux recalages indépendants, chacun avec son propre dossier de sortie.

La chaîne du mode Orientation & Registration, étape par étape

T1 et T2 : deux CBCT du même patient

Préparation : ce mode uniquement

  1. PRE_ASO recentre le T1 : pas de réseau, une translation <T1 folder>Or
  2. ALI_CBCT place les landmarks d'orientation prédit landmarks du T1
  3. SEMI_ASO oriente le T1 sur le gold standard <T1 folder>Or

Segmentation : ce que le recalage aura le droit de voir

  1. AMASSS prédit CBMASK, MANDMASK, MAXMASK sur le T1 orienté prédit <base>_seg_<STRUCT>.nii.gz, à côté des scans

Recalage : une fois par région cochée

  1. centrer le T2 mobile une copie centrée du T2, dans un dossier à côté du dossier T2
  2. masquer le T1 fixe : tout ce qui est hors de la région est mis à 0 le T1 masqué, un fichier temporaire
  3. une passe elastix : information mutuelle de Mattes, 3 niveaux de pyramide, jusqu'à 1500 itérations chacun une transformation rigide
  4. le résultat est relu comme trois angles et une translation, et reconstruit en transformation rigide <pat>_<REG>Reg_matrix.tfm
  5. rééchantillonner le T2 : sur la grille du T2 centré, pas celle du T1 Registered/<Region>/<pat>_OutReg/

Fin

  1. AMASSS s'exécute de nouveau pour les segmentations finales, deux fois, sur le dossier d'entrée, puis récursivement sur l'arborescence de sortie, en écrivant aussi des modèles de surface 3D <Region>/<pat>_OutReg/

Les étapes 5 à 10 forment la fin de chaîne que les trois modes partagent. Les deux autres ne diffèrent qu'en amont : Fully-Automated saute 1–3 et laisse AMASSS prédire les masques (étape 4) sur le T1 tel que fourni ; Semi-Automated saute entièrement 1–4 et prend les masques dans le champ « T1 Masks » de l'opérateur. Cocher deux régions de référence lance deux recalages indépendants, chacun avec son propre dossier de sortie.

4. Entrées, appariement, prétraitement

Les formats acceptés sont .nii.gz, .nii, .nrrd, .nrrd.gz, .gipl et .gipl.gz ; une série DICOM est convertie par patient en un fichier NIfTI écrit dans le dossier d'entrée.

Appariement. L'identifiant d'un patient est ce qui reste du nom de fichier après avoir coupé une liste fixe de marqueurs (_Scan, _Or, _MAND, _CB, _lm, _T2, _T1 et quelques autres). Un fichier dont le nom contient mask, seg ou pred est pris pour une segmentation, tout autre est un scan T1 ou T2. Le masque d'une région est cherché par mot-clé dans le nom (cb, mand ou md, max ou mx), et le premier fichier trouvé l'emporte : la recherche ne vérifie jamais que le fichier est bien un masque, donc un scan nommé P1_T1_MAX.nii.gz serait pris pour la segmentation.

Centrage du T2. Malgré son nom et le dossier de modèles qu'on lui donne, cette étape n'utilise aucun réseau. Elle calcule la translation qui met le centre de l'image à l'origine, rééchantillonne le T2 et écrit cette translation en .tfm à côté de la copie. La prédiction de direction par un réseau a existé puis a été retirée.

Seule l'image fixe est masquée. Le T2 est lu sans masque. Le masque est appliqué au T1 avec un label si on en demande un, sinon tout voxel non nul du masque est conservé ; en pratique, aucun label n'est jamais demandé, parce que cette liste déroulante est masquée.

5. Le cœur algorithmique : le recalage

Une fois les masques et le T2 centré prêts, le recalage tient en six étapes : lire le T2, masquer le T1, lancer une seule passe d'elastix, lire son résultat, le composer, et rééchantillonner le T2. La scène ci-dessous les rejoue sur un jeu de test publié ; les cartes qui la suivent expliquent ce que calcule chaque étape.

La bibliothèque est itk-elastix, pas SimpleITK ni ANTs. Par-dessus la carte rigide par défaut d'elastix, le code fixe : six degrés de liberté, l'information mutuelle de Mattes sur 64 classes, un optimiseur à gradient conjugué (pas de 2,0 à 0,001, tolérances 1e-6), trois niveaux de résolution de jusqu'à 1500 itérations, une grille d'échantillonnage régulière avec un seul thread pour le déterminisme, une initialisation automatique sur les centres des images et une estimation automatique de l'échelle.

Il n'y a plus d'étape grossière. La case « Include Approximation Step » descend jusqu'au bout et n'est jamais lue : le pré-recalage sur les images non masquées a été supprimé en septembre 2025. Le seul « du grossier au fin » qui reste est la pyramide à trois niveaux ; le pré-alignement grossier est désormais fait par le centrage du T2 et par l'initialisation propre d'elastix.

Legacy uniquement. En lisant le résultat d'elastix, le module garde les trois angles et la translation mais jamais le centre de rotation. La transformation reconstruite tourne donc autour de l'origine au lieu de c. Les deux ne concordent que si c est l'origine ou si la rotation est l'identité. Le T2 est d'abord centré, et en mode Orientation le T1 est centré et orienté, ce qui peut garder c près de l'origine et l'écart petit ; c'est une hypothèse à tester, pas un fait vérifié (détails), et dans les deux autres modes le T1 n'est pas centré. Le volume recalé est reconstruit à partir de cette même matrice, donc le fichier et le volume concordent entre eux et s'écartent ensemble de ce qu'elastix a optimisé. VISOR corrige cela (détails).

L'étape de composition multiplie les rotations et additionne les translations ; avec une seule transformation, c'est une simple copie, donc ce code n'est jamais exercé.

6. Ce qui s'exécute en amont : les arguments exacts

AMASSS, pour les masques. Il est appelé sur le T1 avec les structures des régions cochées (masques de la base du crâne, de la mandibule, du maxillaire) et écrit un fichier par structure à côté des scans. AMASSS est aujourd'hui un nnU-Net v2 avec un modèle séparé par groupe prédit. AMASSS, pour les segmentations finales, est appelé deux fois de plus, sur le dossier d'entrée puis récursivement sur l'arborescence de sortie, en ignorant ses propres sorties.

ALI_CBCT (mode Orientation uniquement) place les landmarks dont l'orientation a besoin. Il fonctionne avec des agents d'apprentissage par renforcement multi-échelles (1 mm puis 0,3 mm) ; voir ALI pour la façon dont un agent marche jusqu'à un landmark prédit. La liste dépend du plan de référence : N, S, Ba, RPo, LPo, LOr, ROr pour le plan de Francfort, ou IF, ANS, PNS, UR1O, UR6O, UL6O pour le plan occlusal.

L'orientation du T1 est un ICP rigide de ces landmarks sur un gold standard, après avoir écarté les aberrants calculé. Le résultat est écrit dans un dossier à côté du T1, avec le suffixe Or.

7. Sorties

Pour chaque région et chaque patient, dans le dossier de sortie : le T2 recalé (entiers 16 bits, sur la grille de la copie centrée du T2) et sa transformation, dans un sous-dossier par région et par patient. Le suffixe est concaténé au nom sans séparateur.

Le .tfm est écrit dans la convention ITK, donc en LPS, et envoie l'espace de sortie vers l'espace d'entrée ; aucune inversion n'est nécessaire nulle part dans le programme de recalage. Le seul endroit qui bascule entre RAS et LPS est la correction manuelle d'une pause de revue. La transformation de centrage écrite quand le T2 est centré n'est pas composée avec la transformation de recalage : pour ramener le T2 d'origine sur le T1, il faut chaîner les deux fichiers à la main.

8. Pauses de revue et navigation dans le lot

Dans « Review and manual adjustment », l'opérateur coche les étapes après lesquelles l'exécution doit s'arrêter pour un contrôle visuel. Jusqu'à six peuvent être cochées, selon le mode (trois en Semi-Automated, quatre en Fully-Automated, six en Orientation & Registration), dans le mode CBCT : les landmarks (modifiables, les points peuvent être déplacés et sont réécrits), le T1 orienté, les masques, le T2 centré, le recalage (ajustable : le scan recalé est chargé sur le T1 à demi-opacité et peut être déplacé à la main), et la segmentation finale du T2. Une correction manuelle est composée dans le .tfm existant, donc ce qui l'utilise en aval applique toujours une seule matrice par patient.

La revue ne couvre que les patients de l'exécution en cours, et pour le recalage elle est limitée à une région, si bien qu'un ajustement de la mandibule ne se fond jamais dans la matrice de la base du crâne. Dans le lot, l'opérateur peut passer au patient précédent ou suivant sans faire avancer l'exécution, signaler un patient à refaire, revenir en arrière jusqu'à la dernière étape corrigeable (les étapes intermédiaires ne sont rejouées que pour les patients signalés, par des liens plutôt que par des copies des scans), et enfin passer à l'étape suivante, qui journalise combien de patients ont été acceptés sans être ouverts.

10. Environnement

Tout est installé dans le Python propre à Slicer la première fois qu'on clique sur le bouton, après une boîte de confirmation : le moteur de recalage lui-même (itk-elastix), la conversion DICOM, les bibliothèques d'apprentissage profond dont AMASSS a besoin, et quelques paquets numériques. Il n'y a pas de conda. Les versions sont vérifiées au démarrage du module. Le recalage seul tourne sur le CPU ; AMASSS veut un GPU. Les numéros de version, et une note sur la façon dont la pile GPU est choisie, sont sur la page de code.

11. Pièges et points fragiles

Chaque point est vérifié dans le code et rédigé, avec sa preuve, sur la page de code ; la liste figure aussi dans les constats.

  • Un point temporel autre que T1 ou T2 ne s'apparie avec rien. Un fichier se terminant par _T3 garde ce suffixe dans son identifiant de patient et la paire est écartée silencieusement. La réponse supportée est de renommer les entrées. Aussi vrai dans VISOR, mais là l'orphelin est signalé. Preuve.
  • Le centre de rotation d'elastix est perdu lors de la conversion du résultat (legacy uniquement, corrigé dans VISOR). Preuve, et une hypothèse expliquant pourquoi les résultats sont malgré tout généralement justes.
  • La recherche de masque est un test de mot-clé. Un scan dont le nom contient max peut être pris pour un masque. Legacy uniquement. Preuve.
  • L'image masquée est écrite sous un nom de fichier fixe dans un dossier temporaire partagé par tout le lot : sans danger en séquentiel, fatal si le programme était un jour exécuté en parallèle. Legacy uniquement. Preuve.
  • La case d'approximation ne fait rien depuis septembre 2025 et reste cochée par défaut.
  • Les dossiers de sortie sont créés à côté des entrées (T2 centré, T1 orienté) et réutilisés lors d'une seconde exécution, si bien que des entrées modifiées peuvent être ignorées ; en mode Fully-Automated, les masques sont écrits dans le dossier T1 d'entrée, donc à la pause de recalage chaque masque est chargé à côté du scan.
  • L'entrée DICOM n'est proposée qu'en mode Orientation, l'inverse de ce que le code semble vouloir.
  • Un .tfm corrigé manuellement devient une transformation composite, qu'un consommateur en aval qui en attend une simple peut échouer à lire.
  • Du code mort subsiste : plusieurs fonctions et arguments inutilisés sont listés sur la page de code.

12. Littérature

L'article de référence est Anchling, Hutin, Huang, Barone, Roberts, Miranda, Gurgel, Al Turkestani, Tinawi, Bianchi, Yatabe, Ruellas, Prieto, Cevidanes, « Automated Orientation and Registration of Cone-Beam Computed Tomography Scans », LNCS 14242, 2023, p. 43-58 : Springer, PMC11104011. Précision rapportée : < 3° et < 2 mm par rapport aux experts, moins de 5 min par cas.

Le code diverge de l'article sur trois points vérifiés :

  1. l'article décrit un recalage en deux temps : « VBR entre les images entières, puis avec l'image masquée comme étape de raffinement », 10 000 itérations sur la passe masquée. Le code n'exécute plus qu'une seule passe masquée de jusqu'à 1500 itérations ;
  2. l'article rapporte SimpleElastix ; le code utilise itk-elastix (itk.ElastixRegistrationMethod) ;
  3. l'article obtient ses masques par AMASSS / UNETR MONAI ; AMASSS est aujourd'hui un nnU-Net v2.

Sur la question de fond, la superposition voxel à voxel sur la base du crâne, la référence historique du laboratoire est Cevidanes et al., Superimposition of 3D cone-beam CT models of orthognathic surgery patients (2005, PubMed 16227481).

À ne pas confondre avec Accuracy and Reproducibility of Voxel Based Superimposition…, PLOS One 2011, qui n'est pas du laboratoire : il est de Nada, Maal, Kuijpers-Jagtman et al. (Radboud UMC, Nimègue). C'est une validation indépendante de la méthode, ce qui lui donne plus de poids, pas moins, mais l'attribuer au groupe serait une erreur.

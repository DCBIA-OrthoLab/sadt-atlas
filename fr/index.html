SlicerAutomatedDentalTools — comment chaque outil fonctionne

Une fiche par outil, orientée pipeline : ce qui est calculé, ce qui est prédit par un réseau, à quel moment le modèle est appelé, ce qu'il fait exactement, quels sont les prétraitements et ce qui sort.

Ce n'est pas un manuel utilisateur. Les liens de code pointent vers le dépôt ~/Projects/UNC/SlicerAutomatedDentalTools.

Par où commencer

Du bas de la chaîne vers le haut. Les deux premières étapes sont celles dont tout le reste dépend.

#FichePourquoi celle-ci d'abord
1FlexRegLe plus simple, tout est explicite. Introduit les conventions LPS/RAS, la segmentation des couronnes et l'ICP sur patch.
2ALI et AMASSSLes deux fournisseurs de repères dont tout le reste dépend.
3ASOL'orientation, prérequis de la plupart des recalages.
4AREG_IOS puis AREG_CBCTLes recalages proprement dits.
5VFACELe plus haut dans la chaîne : il empile tous les autres.

Les trois briques partagées

Presque tous les modules reposent sur les mêmes trois composants. Les comprendre une fois évite de relire la même mécanique dans cinq fiches.

Environnement conda partagé

Couplage à connaître

ALI, AREG, ASO, DOCShapeAXI et FlexReg partagent le même environnement conda shapeaxi, en Python 3.12. Un changement de version de Python les casse tous en même temps. Détails dans FlexReg, section Environnement.

Organisation des dossiers

Un dossier par outil. Chacun contient :

  • <Outil>.html — le pipeline, lu dans le code ;
  • SOURCES.html — la bibliographie : ce qui est déposé ici, ce qui est à lire en ligne, et le « voisinage » (travaux proches qui ne décrivent pas le code) ;
  • les documents récupérés, en PDF quand l'éditeur le permet, sinon en .xml (JATS, le texte intégral) accompagné d'un .txt lisible.

Les fichiers .md d'origine sont conservés à côté des pages HTML.

29 PDF et 54 textes intégraux, tous vérifiés : les PDF sont paginés, les XML portent un corps de texte. Rien n'a été obtenu en contournant un péage — arXiv, PLOS, PMC/NCBI, HAL, dépôts institutionnels, pages d'auteurs et versions déposées par les auteurs eux-mêmes. Ce qui est payant est donné en lien avec son DOI.

Récupérer un texte que l'éditeur ne sert pas

Les manuscrits auteur déposés au NIH sont libres à la lecture mais souvent invisibles aux voies habituelles. Ce qui marche, testé :

curl -sL "https://eutils.ncbi.nlm.nih.gov/entrez/eutils/efetch.fcgi?db=pmc&id=<numéro sans PMC>"

Ce qui échoue sur ces mêmes articles : pmc.ncbi.nlm.nih.gov/.../pdf/ (HTML anti-bot), fullTextXML d'Europe PMC (vide), l'API BioC (open access subset seulement). Et pour MDPI, mdpi-res.com/d_attachment/... sert le vrai PDF là où mdpi.com/.../pdf renvoie une page.

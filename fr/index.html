SlicerAutomatedDentalTools : comment fonctionne chaque outil

Une page par outil, organisée autour du pipeline : ce qui est calculé, ce qui est prédit par un réseau, quand le modèle est appelé, ce qu'il fait réellement, quel est le prétraitement, et ce qui sort.

Ce n'est pas un manuel d'utilisation. Les liens de code pointent vers le dépôt ~/Projects/UNC/slicer/SlicerAutomatedDentalTools.

Deux bases de code : legacy et VISOR

Les pages d'outils listées ci-dessous décrivent les modules Slicer legacy (SlicerAutomatedDentalTools à 3c67957, 2026-10-26). L'équipe est en train de porter les outils vers VISOR : un client Slicer qui envoie le travail à un serveur d'inférence, où chaque outil tourne dans son propre environnement Python.

Chaque module a donc jusqu'à quatre pages. En haut de la barre latérale, le sélecteur Legacy | VISOR choisit la génération, et le sélecteur Guide | Atlas en dessous choisit entre la vue de l'utilisateur et le code : Guide legacy, Atlas legacy, Guide VISOR, Atlas VISOR. Changer de sélecteur vous garde sur le même outil. Les pages VISOR ci-dessous expliquent comment le système est construit. Les autres langues ne décrivent pour l'instant que le code legacy.

Environnement conda partagé

Couplage à connaître

ALI, AREG, ASO, DOCShapeAXI et FlexReg partagent le même environnement conda shapeaxi, sous Python 3.12. Un changement de version de Python les casse tous d'un coup. Détails dans FlexReg, section Environnement.

Organisation des dossiers

Un dossier par outil. Chacun contient :

  • <Tool>.html : le pipeline, lu dans le code ;
  • SOURCES.html, la bibliographie : ce qui est déposé ici, ce qui est à lire en ligne, et le « voisinage » (travaux liés qui ne décrivent pas le code) ;
  • les documents récupérés, en PDF quand l'éditeur le permet, sinon en .xml (JATS, le texte intégral) avec un .txt lisible à côté.

Les fichiers .md d'origine sont conservés à côté des pages HTML.

29 PDF et 54 textes intégraux, tous vérifiés : les PDF sont paginés, les fichiers XML portent un corps de texte. Rien n'a été obtenu en contournant un accès payant : arXiv, PLOS, PMC/NCBI, HAL, dépôts institutionnels, pages d'auteurs et versions déposées par les auteurs. Tout ce qui est derrière un accès payant est donné sous forme de lien avec son DOI.

Récupérer un texte que l'éditeur ne sert pas

Les manuscrits d'auteurs déposés auprès des NIH sont en lecture libre mais souvent invisibles par les voies habituelles. Ce qui fonctionne, testé :

curl -sL "https://eutils.ncbi.nlm.nih.gov/entrez/eutils/efetch.fcgi?db=pmc&id=<number without PMC>"

Ce qui échoue sur les mêmes articles : pmc.ncbi.nlm.nih.gov/.../pdf/ (HTML anti-robot), le fullTextXML d'Europe PMC (vide), l'API BioC (sous-ensemble en accès libre seulement). Et pour MDPI, mdpi-res.com/d_attachment/... sert le vrai PDF là où mdpi.com/.../pdf renvoie une page.

Ce qui n'est publié nulle part

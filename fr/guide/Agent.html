Agent — demander à un assistant local de choisir l'outil

Agent est un assistant conversationnel qui tourne entièrement en local. Vous décrivez ce que vous voulez faire, en langage naturel, et il propose un outil de l'extension déjà rempli avec ses paramètres — ou se contente de répondre, selon le mode choisi.

À lire avant d'essayer

Tel que le dépôt est installé aujourd'hui, Agent ne parvient pas à retrouver les outils qu'il veut lancer. Sauf réglage manuel particulier, toute tentative d'exécution échoue. Le mode qui se contente de répondre, sans rien exécuter, n'est pas concerné et fonctionne normalement.

Quand s'en servir

Quand vous ne voulez pas chercher vous-même quel module de l'extension correspond à votre besoin, ni construire une ligne de commande à la main : vous décrivez ce que vous voulez faire — « oriente ces CBCT », « segmente ces empreintes » — et Agent propose un outil avec les paramètres qu'il a compris à partir de votre demande. Il sert aussi de simple consultant, en mode « Ask », pour poser une question sans rien lancer.

Ce qu'il faut installer avant

Agent s'appuie sur un serveur de modèle de langage qui tourne en local sur votre machine, Ollama. S'il n'est pas déjà présent, le module propose de le télécharger et de le démarrer lui-même. Dans tous les cas, comptez sur un premier lancement qui télécharge plusieurs gigaoctets — le modèle de langage à lui seul pèse un peu plus de 5 Go — avant de pouvoir poser votre première question.

Rien à installer à la main côté Slicer

Les paquets Python nécessaires s'installent automatiquement au premier lancement, dans le Python de Slicer.

Ce qu'il vous faut, ce que vous obtenez

À fournir

  • Une demande écrite en langage naturel, en français ou en anglais
  • Le mode voulu : Agent (Automated) pour exécuter, Ask (Interactive) pour seulement discuter
  • Au besoin, les dossiers concernés, glissés dans la zone de dépôt

Ce qui sort

  • En mode Agent : un outil choisi, ses paramètres, une confirmation, puis l'exécution si vous validez
  • En mode Ask : une réponse en texte libre, rien n'est lancé
  • Si l'outil échoue, jusqu'à deux tentatives de correction automatique, chacune avec sa propre confirmation

Marche à suivre

  1. Assurez-vous qu'Ollama tourne. Si besoin, laissez Agent l'installer et le démarrer lui-même, et patientez pendant le téléchargement du modèle au premier lancement.
  2. Choisissez le mode. « Agent (Automated) » pour qu'un outil soit réellement lancé, « Ask (Interactive) » pour n'obtenir qu'une réponse.
  3. Décrivez ce que vous voulez faire, en langage naturel, comme vous le diriez à un collègue.
  4. Glissez les dossiers concernés dans la zone de dépôt si votre demande porte sur des données précises — Agent essaiera de deviner lequel est lequel.
  5. Envoyez le message. En mode Agent, un outil et ses paramètres sont proposés ; en mode Ask, la réponse arrive directement.

Lire la fenêtre de confirmation

En mode Agent, rien ne se lance sans un « Oui » de votre part dans une fenêtre qui liste chaque paramètre retenu, sous la forme clé=valeur. C'est le seul moment où vous pouvez repérer un dossier mal deviné ou une valeur qui ne correspond pas à ce que vous vouliez, avant que l'outil ne démarre pour de bon.

Relisez chaque ligne, sérieusement

Sur la plupart des outils, la correspondance entre ce qu'Agent croit devoir passer et ce que l'outil attend réellement est décalée. Un lancement peut donc partir avec de mauvaises valeurs sans qu'aucun message d'erreur ne le signale à l'avance — la fenêtre de confirmation est votre seule vérification réelle.

Une fois que vous avez validé, l'interface de Slicer se fige jusqu'à la fin de l'exécution de l'outil lancé : c'est normal, il n'y a rien d'autre à faire qu'attendre.

Si ça coince

« Rien ne se lance, ou une erreur qui n'a aucun sens »

Dans l'état actuel du dépôt, Agent ne retrouve pas de lui-même l'emplacement des scripts qu'il veut exécuter : sauf à indiquer vous-même où ils se trouvent, l'exécution échoue avant même de commencer. La correction automatique proposée ensuite ne peut rien réparer dans ce cas — le problème n'est pas dans les paramètres, il est dans le chemin du script.

Un lancement qui part avec de mauvaises valeurs

Voir plus haut : vérifiez toujours la fenêtre de confirmation avant de valider. Un décalage de paramètres ne se voit généralement qu'à l'œil, dans cette fenêtre — pas dans un message d'erreur.

Tout est lent sans carte graphique

Si le serveur de modèle tourne sans GPU, chaque réponse peut prendre de l'ordre d'une minute et demie. Une conversation à plusieurs échanges se compte alors en minutes, pas en secondes.

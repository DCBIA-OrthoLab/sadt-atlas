Agent : laissez un assistant local choisir l'outil

Agent est un assistant conversationnel qui tourne entièrement sur votre machine. Vous décrivez ce que vous voulez faire, en langage courant, et il propose un outil de l'extension déjà rempli avec ses paramètres, ou il se contente de vous répondre, selon le mode choisi.

Page du module legacy

Cette page décrit le module Slicer legacy. L'extension VISOR embarque une copie de ce panneau qui tourne toujours sur votre ordinateur, et le serveur VISOR a un outil Agent distinct qu'aucun panneau n'appelle : voir Agent avec VISOR et Utiliser VISOR.

À lire avant d'essayer

Dans l'état actuel du dépôt, Agent ne sait pas localiser les outils qu'il veut lancer. Sauf configuration manuelle de votre part, toute tentative d'exécuter un outil échoue. Le mode qui se contente de répondre, sans rien exécuter, n'est pas touché et fonctionne normalement.

Quand s'en servir

Servez-vous-en quand vous ne voulez pas chercher quel module de l'extension correspond à votre besoin, ni construire une ligne de commande à la main : vous décrivez la tâche, "orienter ces CBCT", "segmenter ces scans", et Agent propose un outil avec les paramètres qu'il a compris de votre demande. Il sert aussi de simple consultant, en mode "Ask", pour les questions qui n'exigent rien d'exécuté.

À installer d'abord

Agent s'appuie sur un serveur de modèle de langage qui tourne localement sur votre machine, Ollama. S'il n'est pas déjà présent, le module propose de le télécharger et de le démarrer pour vous. Dans les deux cas, attendez-vous à ce que le premier lancement télécharge plusieurs gigaoctets, le modèle de langage seul pèse un peu plus de 5 GB, avant que vous puissiez poser votre première question.

Rien à installer à la main côté Slicer

Les paquets Python requis s'installent tout seuls au premier lancement, dans le Python propre à Slicer.

Ce qu'il vous faut, ce que vous obtenez

À fournir

  • Une demande écrite en langage courant, en anglais ou en français
  • Le mode voulu : Agent (Automated) pour réellement exécuter quelque chose, Ask (Interactive) pour simplement discuter
  • Le cas échéant, les dossiers concernés, déposés dans la zone de dépôt

Ce qui sort

  • En mode Agent : un outil choisi, ses paramètres, une boîte de confirmation, puis l'exécution si vous approuvez
  • En mode Ask : une réponse en texte libre, rien n'est lancé
  • Si l'outil échoue, jusqu'à deux tentatives de réparation automatiques, chacune avec sa propre confirmation

Étapes

  1. Assurez-vous qu'Ollama tourne. Si besoin, laissez Agent l'installer et le démarrer pour vous, et attendez la fin du téléchargement du modèle au premier lancement.
  2. Choisissez un mode. "Agent (Automated)" pour réellement lancer un outil, "Ask (Interactive)" pour obtenir seulement une réponse.
  3. Décrivez ce que vous voulez, en langage courant, comme vous l'expliqueriez à un collègue.
  4. Déposez les dossiers concernés dans la zone de dépôt si votre demande porte sur des données précises : Agent essaiera de deviner lequel est lequel.
  5. Envoyez le message. En mode Agent, un outil et ses paramètres sont proposés ; en mode Ask, la réponse revient directement.

Lire la boîte de confirmation

En mode Agent, rien ne s'exécute sans un "Yes" de votre part, dans une boîte qui liste chaque paramètre retenu, sous forme de paires key=value. C'est le seul moment où vous pouvez repérer un dossier deviné à tort ou une valeur qui ne correspond pas à votre intention, avant que l'outil ne démarre réellement.

Lisez chaque ligne, attentivement

Pour la plupart des outils, la correspondance entre ce qu'Agent croit transmettre et ce que l'outil attend réellement est décalée. Une exécution peut donc démarrer avec de mauvaises valeurs sans qu'aucune erreur ne vous prévienne : la boîte de confirmation est votre seul vrai contrôle.

Une fois que vous avez approuvé, l'interface de Slicer se fige jusqu'à la fin de l'outil lancé : c'est normal, il n'y a qu'à attendre.

Si ça coince

"Rien ne se lance, ou l'erreur n'a aucun sens"

Dans l'état du dépôt, Agent ne trouve pas tout seul les scripts qu'il veut exécuter : sauf si vous lui dites vous-même où ils se trouvent, l'exécution échoue avant même de commencer. L'étape de réparation automatique qui suit ne peut pas y remédier : le problème n'est pas dans les paramètres, il est dans le chemin du script.

Une exécution qui démarre avec de mauvaises valeurs

Voir plus haut : vérifiez toujours la boîte de confirmation avant d'approuver. Un décalage de paramètre ne se voit en général qu'à l'œil, dans cette boîte, pas dans un message d'erreur.

Tout est lent sans carte graphique

Si le serveur de modèle tourne sans GPU, attendez-vous à ce que chaque réponse prenne environ une minute et demie. Un échange en va-et-vient se compte en minutes, pas en secondes.

Comment citer

Pas de publication : le module est un travail en cours, décrit par un seul rapport de projet NA-MIC.

Si vous avez utilisé Agent dans un travail de recherche, citez :

Dumont P, Buisson A, Prieto JC, Cevidanes L, Pieper S. AI-Agent for SlicerAutomatedDentalTools. 45th NA-MIC Project Week, Boston, 2026.

projectweek.na-mic.org. Le rapport de projet : ce que l'agent est censé savoir faire, et jusqu'où le travail est allé.

Contexte, à ne pas citer pour l'outil

  • Qwen Team, arXiv 2025: Qwen3 Technical Report. Le modèle qui décide vers quel outil vous envoyer et qui en extrait les paramètres.
  • Reimers & Gurevych, EMNLP 2019: Sentence-BERT: Sentence Embeddings using Siamese BERT-Networks. Comment une question est comparée à la documentation indexée : c'est l'étape qui décide de ce que l'agent a sous les yeux avant de répondre.
  • Nogueira & Cho, arXiv 2019: Passage Re-ranking with BERT. Le reclassement appliqué ensuite aux passages retrouvés, qui améliore nettement ce qui remonte en tête.

La bibliographie complète de l'outil, ce qui a été trouvé, et ce qui a été cherché sans rien trouver, est dans ses sources.

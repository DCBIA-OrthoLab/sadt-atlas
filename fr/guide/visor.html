Utiliser VISOR : exécuter les outils sur un serveur depuis 3D Slicer

Avec VISOR, le calcul ne se fait plus sur votre ordinateur. Vous choisissez un outil dans Slicer, les fichiers que vous sélectionnez sont envoyés à un serveur, le serveur calcule, et le résultat revient dans votre scène. Cette page couvre ce qu'il faut configurer, ce que vous fournissez, et ce qu'il faut vérifier avant d'envoyer des données de patients. La construction de VISOR est décrite dans l'Atlas VISOR.

client : implémenté et testé anonymisation : non implémentée MRI2CBCT : non livré
Avant d'utiliser des données de patients

Le client VISOR envoie vos fichiers tels qu'ils sont sur le disque. Rien n'est anonymisé. Voir Ce qui quitte votre machine.

Ce qui change pour vous

Le reste de ce site décrit l'extension legacy, SlicerAutomatedDentalTools : chaque module tourne sur votre propre ordinateur. VISOR est une autre extension Slicer, AutomatedDentalToolsRemote. Ses modules sont de fins panneaux au-dessus d'un serveur distant.

  • Le calcul quitte votre ordinateur. Un portable incapable de lancer une segmentation peut tout de même en demander une.
  • Rien à installer dans le Python de Slicer, et aucun modèle à télécharger : l'extension ne déclare aucune dépendance à d'autres extensions, et les modèles vivent sur le serveur.
  • Le formulaire vient du serveur. Le panneau d'un outil est construit à son ouverture, d'après la description que publie le serveur. Un champ ajouté côté serveur apparaît dans Slicer sans nouvelle version de l'extension.
  • Il vous faut un serveur, une adresse et une clé. En installer un est le sujet du serveur, pas de cette page ; voir le déploiement.

Sources : AutomatedDentalToolsRemote CMakeLists.txt:10,15 et README.md:3-8, 150-165 (commit 19b95e8).

Installer l'extension

Le README et le fichier de build disent ce qui suit, et rien de plus n'est supposé ici.

  • L'extension est AutomatedDentalToolsRemote. Elle fonctionne avec les versions stable et nightly de 3D Slicer, et ses modules apparaissent dans la catégorie Automated Dental Tools Remote.
  • Elle ne liste aucune dépendance d'extension (EXTENSION_DEPENDS "NA") : vous n'avez besoin ni de SlicerConda, ni de SlicerDentalModelSeg, ni de NNUNet pour elle.
  • Le README indique qu'elle figure au Extensions Catalog pendant la transition.
  • Ne l'installez pas à côté de l'extension legacy. Le README demande d'utiliser l'une ou l'autre, parce que de nombreux modules portent les mêmes noms et que Slicer ne garde qu'un seul de deux modules homonymes.

Connecter Slicer à un serveur

Ouvrez Server Tools Settings (catégorie Automated Dental Tools Remote.Advanced). Tant que vous n'y avez rien enregistré, l'adresse est un espace réservé (https://set-your-server.invalid) qui n'atteint rien, donc aucun fichier ne quitte votre machine.

À fournir

  • Server URL : une adresse https:// dont le certificat est signé par une autorité publique.
  • API key : le jeton d'API du serveur (le champ est masqué). Le README dit d'utiliser le jeton d'API, jamais le jeton d'administration.
  • Timeout : de 1 à 3600 secondes, 600 par défaut.

Ce que vous ne pouvez pas changer

  • Pas de http://, pas même http://localhost.
  • Le certificat est toujours vérifié : le panneau affiche « Verify TLS: Always on », sans rien à cocher.
  • Les redirections ne sont jamais suivies.

Cliquez sur Save. Le changement s'applique aussitôt et est conservé d'un redémarrage à l'autre. Si vous saisissez une adresse http://, Slicer la refuse avant d'enregistrer quoi que ce soit. Restore defaults efface ce que vous avez enregistré.

Un serveur sur votre propre ordinateur suit la même règle : le client n'accepte pas le certificat auto-signé du serveur lui-même, donc vous l'atteignez par une adresse publique, par exemple une adresse tailscale serve (https://<name>.<tailnet>.ts.net), ou un reverse proxy avec un certificat Let's Encrypt ou institutionnel.

Le serveur est-il joignable ? Il n'y a pas de bouton « Test connection ». Le panneau affiche en haut une ligne « Server: online » ou « Server: offline », rafraîchie à l'ouverture du module et après chaque enregistrement. Elle interroge seulement la page /health du serveur, qui n'a pas besoin de clé : « online » ne prouve pas que votre clé est acceptée. Une mauvaise clé se voit au premier lancement (voir Si quelque chose se passe mal).

La clé est stockée en clair

Slicer enregistre la clé dans son propre fichier de réglages pour votre utilisateur, en texte brut. Le champ masqué ne la cache qu'à l'écran. Quiconque peut lire vos réglages Slicer peut lire la clé.

HTTPS sans repli

Il n'existe aucun réglage, indicateur ni fichier qui assouplisse la règle HTTPS ou la vérification du certificat. Une adresse http:// enregistrée par une ancienne version du client est ignorée au démarrage.

Lancer un outil

  1. Choisissez un outil dans la liste des modules. Il construit son formulaire à partir du serveur à l'ouverture. Si le serveur est injoignable, le panneau indique qu'il n'a pas pu charger l'outil et propose un bouton Retry.
  2. Remplissez le formulaire. Ce que vous fournissez dépend de l'outil ; les noms des champs viennent du serveur, donc lisez la page Guide propre à chaque outil.
  3. Appuyez sur Apply. Le panneau vérifie d'abord le formulaire (argument inconnu, fichier manquant, champ obligatoire manquant) avant d'envoyer quoi que ce soit.
  4. Suivez la progression et annulez si besoin.

Ce que vous pouvez donner en entrée

  • Un fichier est envoyé tel quel, même nom, mêmes octets.
  • Un dossier est empaqueté dans une archive qui conserve les noms de ses fichiers et sous-dossiers, puis envoyé.
  • Un nœud de la scène Slicer (un volume, un modèle, une région d'intérêt) est exporté dans un fichier temporaire, nommé d'après l'outil et l'argument, pas d'après le nœud. AutoCrop3D, par exemple, prend ainsi sa région d'intérêt dans la scène.
  • Un fichier de test hébergé est un échantillon que le serveur propose pour l'outil. En choisir un le télécharge d'abord (en arrière-plan, la fenêtre Slicer reste utilisable), puis l'utilise comme entrée. Un second choix de la même entrée dans la même session réutilise le téléchargement.
  • Un modèle choisi sur le serveur est sélectionné par son nom dans une liste que publie le serveur. Seul le nom voyage ; le fichier du modèle n'est jamais envoyé depuis votre ordinateur. Si la liste est vide et que l'argument n'a pas d'autre moyen d'être donné, le panneau affiche un avertissement pour demander au responsable du serveur.

Les grosses entrées sont envoyées par parties et vérifiées partie par partie. Si le serveur publie un plan de découpage pour un dossier de cohorte, le panneau le divise en lots, chacun étant une exécution ordinaire.

Progression, annulation, connexion perdue

  • Le panneau rapporte les phases propres du serveur : requête reçue, préparation des fichiers d'entrée, attente du GPU, exécution sur le serveur, empaquetage des résultats, terminé. Un temps écoulé défile à côté. Une exécution en file affiche « queued ».
  • Cancel arrête aussi l'exécution sur le serveur. Il y a un Cancel par exécution ; avec plusieurs exécutions il devient « Cancel all », et pour une cohorte « Cancel the cohort ». Une exécution annulée n'est pas signalée comme une erreur.
  • Si la connexion tombe pendant que le serveur travaille, le panneau se reconnecte tout seul au flux de progression et reprend là où il s'était arrêté, sans répéter ce qu'il avait déjà montré. C'est le mode détaché, activé par défaut : la requête se termine dès que les entrées sont déposées et le résultat arrive sur le flux de progression, donc le timeout des réglages ne plafonne plus la durée d'une exécution.
S'arrêter pour une revue passe par la voie bloquante

Si vous armez une étape « stop after » (voir Revue qualité), l'exécution n'utilise pas le mode détaché : le serveur renvoie le matériel de revue dans la réponse à la requête d'origine. Le timeout de Server Tools Settings s'y applique, et une connexion perdue fait perdre la réponse.

Récupérer les résultats

  • Quand l'exécution se termine, le panneau télécharge le résultat (par plages en parallèle), vérifie l'archive et la décompresse dans le dossier de sortie. Par défaut, ce dossier est « Slicer Output » dans vos Documents.
  • Une archive est refusée avant que rien soit écrit si elle contient des chemins absolus, .., des liens, plus de 100 000 entrées ou plus de 20 Go.
  • La case « Load the results into the scene when done » importe ce que l'outil a produit : volumes, cartes de labels, modèles ou landmarks, selon l'outil. Au plus 12 éléments sont chargés par défaut ; au-delà, le panneau indique qu'il y en a trop pour tout charger d'un coup.
  • Certains outils ajoutent leurs propres options ou messages : ALI résume son rapport d'exécution et demande confirmation au-delà de 20 fichiers de landmarks ; VFACE a une case « Load the heat maps » ; AutoMatrix a une case « Use the mirror matrix ». CNE ne charge rien dans la scène et affiche un résumé dans la barre d'état.
  • La copie du résultat sur le serveur est supprimée après votre téléchargement.

Revue qualité avec VISU

Certains outils peuvent s'arrêter après une étape pour que vous contrôliez le résultat intermédiaire. Le formulaire affiche alors une section « Quality control » avec un choix multiple stop_after ; rien n'est coché par défaut. Les outils qui en appellent d'autres le proposent, par exemple ALI pour les scans intra-oraux ou VFACE.

  1. Arrêt. Le serveur se met en pause après l'étape que vous avez cochée. Le panneau affiche « Stopped after <step>, waiting for your review », télécharge ce qui a été produit jusque-là, et ouvre VISU dessus.
  2. Revue. VISU montre un patient à la fois : scan, masques, surfaces et landmarks ensemble. Les flèches du clavier vont au cas précédent ou suivant. Utilisez Flag pour marquer un patient, et Go to next flagged pour y sauter. Lisez la ligne « Drawn on <scan> » (elle indique sur quel scan les landmarks sont dessinés, et s'il a été trouvé à côté des points ou supposé).
  3. Correction. Pour les landmarks, vous pouvez faire glisser des points puis Save : seuls les points déplacés sont réécrits, appariés par nom. Undo my changes et Revert to what is on disk les restaurent. Un ajustement de recalage est enregistré dans un fichier de transformation séparé à côté de la scène, jamais fusionné avec la transformation propre à l'outil.
  4. Continuer. Seuls les fichiers dont le contenu a changé sont renvoyés, puis le serveur reprend l'exécution.
  5. Revenir en arrière. Quand une étape antérieure peut être corrigée (landmarks ou recalage), le drapeau indique « Go back and edit this patient ». Une fois que vous en avez marqué quelques-uns, le bouton vert indique « Go back to <step> for N patient(s) » : vos corrections sont écrites, les patients marqués sont refaits à partir de cette étape, et tous les autres gardent le résultat qu'ils ont déjà.

Si VISU est introuvable, ou si l'arrêt n'a rien produit à regarder, le panneau le dit et reprend aussitôt l'exécution, pour que rien ne reste en pause sur le serveur avec vos données dedans.

VISU fonctionne aussi sur n'importe quel dossier

Vous pouvez ouvrir VISU sur n'importe quel dossier qu'un outil a écrit, sans serveur : il apparie le scan, les masques, les surfaces et les landmarks de chaque patient par nom de fichier. La seule chose qu'il récupère auprès d'un serveur, ce sont des jeux de données d'exemple hébergés.

Sources : AutomatedDentalToolsRemote ServerToolsCoreLib/client.py:82-88,1551-1578 ; base_widget.py:2290-2345,2529-2582 ; VISU/VISU.py:164-180,725-865,1037-1081,1411,1622-1686 ; VISULib/edits.py:75-95 ; VISULib/review.py:20-25 (commit 19b95e8). Les outils qui exposent l'arrêt sont publiés par le serveur, voir le cycle de vie d'une exécution.

Ce qui quitte votre machine

Rien n'est anonymisé

Aucun outil d'anonymisation n'existe aujourd'hui dans VISOR. Ce que vous sélectionnez est envoyé au serveur tel quel sur le disque : noms de fichiers, en-têtes DICOM et tous les identifiants qu'ils portent. Un pipeline d'anonymisation est spécifié dans le dépôt du client mais son README dit qu'il n'est pas implémenté, et une recherche dans le code n'en trouve aucune implémentation.

  • L'avertissement. Après l'enregistrement d'une adresse de serveur qui n'est pas cet ordinateur, Slicer affiche une fois par serveur : « Files are uploaded unmodified. This client does not de-identify anything... De-identify your data before selecting it, or confine use to data that carries no protected health information. » C'est un avertissement, pas un contrôle : il n'empêche rien.
  • Les dossiers gardent leurs noms. Un dossier est empaqueté avec les noms d'origine de ses fichiers et sous-dossiers. Un nœud de la scène est exporté sous un nom générique, donc son nom de nœud ne sort pas.
  • CNE envoie des notes cliniques. Le modèle de texte tourne sur le serveur : les notes montent et les extractions redescendent. La page CNE legacy, qui dit que rien ne quitte votre machine, ne s'applique pas à VISOR.
  • Transport seulement. HTTPS protège le transfert. Il n'y a aucun chiffrement des fichiers au-delà, côté client.
  • Le Medical Data Anonymizer existe toujours, mais il traite des documents texte sur cette machine et ne fait pas partie de ce qui est envoyé.
  • Ne pointez le client que vers un serveur que votre établissement contrôle, et vérifiez que l'accord passé avec celui qui l'exploite couvre les données que vous envoyez. Le README demande la même chose.

Le tableau de la sécurité, y compris ce que le serveur protège et ne protège pas, est dans Sécurité de VISOR.

Si quelque chose se passe mal

Pour la plupart des échecs, Slicer affiche le message propre du serveur. Voici ce que signifie chacun.

« The server URL must start with https:// »

Vous avez saisi une adresse http://, ou Slicer en a trouvé une d'une ancienne version. Utilisez l'adresse publique https:// ; il n'y a aucun moyen de contourner la règle, y compris pour un serveur sur votre propre ordinateur.

401 : échec d'authentification

La clé est fausse ou manquante. Le panneau peut quand même afficher « Server: online » parce que la page de santé n'a pas besoin de clé. Ressaisissez la clé dans Server Tools Settings et faites Save.

503 pendant une fenêtre de maintenance

Pendant la mise à jour du serveur, il refuse tout nouveau travail avec un 503 et un en-tête Retry-After: 10, pendant 300 secondes au plus. Le client ne lit pas cet en-tête : vous voyez le message du serveur, ou « Server error (503) ». Attendez et appuyez de nouveau sur Apply. La lecture des résultats déjà en cours n'est pas bloquée.

422 : arguments invalides

Le serveur nomme l'argument fautif, par exemple une option hors de la liste acceptée. Corrigez le champ qu'il nomme. Un « 400 » avec un message sur le type de fichier signifie que l'extension du fichier n'est pas acceptée par cet outil.

413 : fichier trop volumineux

Le serveur refuse un envoi au-delà de sa limite, 500 Mo par fichier par défaut. Pour une grosse cohorte, donnez un dossier plutôt qu'une seule énorme archive, afin qu'il puisse être découpé en lots.

500 : « The tool failed on the server »

C'est tout ce que le client affiche pour un plantage à l'intérieur d'un outil, volontairement : les détails peuvent contenir des éléments internes du serveur. Demandez à celui qui exploite le serveur de lire son journal.

  • Timeouts. Le timeout de Server Tools Settings (600 s par défaut) s'applique aux requêtes qui restent ouvertes. En mode détaché, qui est le mode par défaut, une longue exécution n'est pas coupée par lui. Le serveur n'a pas de limite de durée d'exécution par défaut.
  • Attente dans une file. Une exécution peut attendre le GPU : le panneau affiche « Waiting for the GPU », et vous pouvez annuler pendant l'attente. Le serveur limite aussi le nombre d'exécutions simultanées, donc une cinquième exécution peut attendre avant même d'apparaître comme « queued ».
  • Serveur hors ligne. Si la liste des outils ne peut pas être chargée, le panneau le dit et affiche Retry. Vérifiez l'adresse et « Server: online » dans Server Tools Settings.
  • Un changement dans config.py n'a aucun effet. Ce que vous avez enregistré dans Server Tools Settings l'emporte toujours sur les valeurs par défaut compilées.

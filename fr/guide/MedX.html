MedX : résumer des comptes rendus, puis construire un tableau de bord

Malgré son nom, MedX ne regarde jamais d'image : il lit des comptes rendus cliniques écrits (.pdf, .docx, .txt), fait transformer chacun en résumé structuré par un modèle de langage local, puis peut agréger toute une cohorte de ces résumés en une seule page de figures. Deux étapes distinctes, à connaître avant de commencer.

Page du module legacy

Cette page décrit le module tel qu'il était avant son retrait de l'extension legacy le 2026-09-17 ; il n'est plus dans la version actuelle. Il n'a jamais été disponible via un serveur VISOR : voir MedX et VISOR et Utiliser VISOR.

Quand s'en servir

Quand vous avez une pile de comptes rendus en texte libre, examen clinique, examen radiographique, notes de consultation, et que vous voulez en tirer les indicateurs cliniques (âge, douleur, sommeil, ouverture buccale, etc.) sans les lire un par un. Une fois ces résumés obtenus, la seconde moitié de MedX permet de voir toute la cohorte d'un coup d'œil : répartition par âge, troubles associés, scores moyens.

Deux chemins indépendants

MedX a deux onglets, deux boutons, et rien ne les enchaîne automatiquement. Summarize lit vos documents et écrit un fichier de résumé par patient. Dashboard relit ces résumés et produit la page de figures. Une fois la synthèse terminée, c'est à vous de changer d'onglet et de lancer vous-même le tableau de bord : il ne démarre pas tout seul.

Ce qu'il vous faut, ce que vous obtenez

Chemin Summarize

À fournir

  • Un dossier plat de comptes rendus en .pdf, .docx ou .txt (pas de sous-dossiers)
  • Des noms de fichiers où tout ce qui précède le premier « _ » est l'identifiant du patient : plusieurs fichiers qui partagent cet identifiant sont regroupés et résumés ensemble
  • Le modèle de résumé, téléchargé une seule fois

Ce qui sort

  • Un fichier <patient-id>_summary.txt par patient, en texte libre
  • Vos documents sources ne sont pas modifiés

Chemin Dashboard

À fournir

  • Le dossier de résumés produit par le chemin Summarize (les fichiers doivent finir par _summary.txt)

Ce qui sort

  • Une image dashboard.png : âge, sommeil, douleur articulaire et musculaire, ouverture buccale, sur toute la cohorte
  • Un tableau patient_data.csv avec une ligne par patient

Étapes

Résumer les comptes rendus

  1. Téléchargez le modèle. À faire une seule fois ; sans lui, le chemin Summarize n'a rien pour travailler.
  2. Désignez le dossier des comptes rendus, nommés avec un identifiant de patient avant le premier « _ ».
  3. Indiquez un dossier de sortie, puis lancez. Une barre de progression suit les patients au fil du traitement.
  4. Relisez les résumés obtenus avant de vous y fier : voir plus bas.

Construire le tableau de bord

  1. Passez à l'onglet Dashboard. Cela ne se fait pas tout seul après la synthèse.
  2. Indiquez en entrée le dossier de résumés de l'étape précédente.
  3. Indiquez un dossier de sortie, puis lancez. Au premier lancement, Slicer peut proposer d'installer deux paquets Python (pandas, matplotlib) : acceptez.
  4. Cochez « Load in 3D Slicer » si vous voulez que l'image du tableau de bord s'ouvre directement dans une vue de la scène.

Lire le résultat

Le résumé de chaque compte rendu vient d'un modèle génératif : il écrit du texte libre, pas une forme garantie. Le format key: value qu'attend le tableau de bord est une habitude apprise par le modèle, pas une règle imposée : une ligne mal formée est simplement abandonnée, et manque en silence dans le tableau de bord. Le modèle échantillonne aussi une partie de sa sortie : relancer le résumé sur le même document ne produit pas deux fois exactement le même texte. Pour ces deux raisons, un résumé généré par MedX est un point de départ à relire, pas un compte rendu validé : ne l'utilisez pas tel quel pour une décision clinique.

Si ça coince

Le bouton de téléchargement du modèle ne fait rien

Cliquer sur le bouton de téléchargement crée le dossier attendu mais n'y met jamais de fichier : le champ reste vide et un message d'avertissement apparaît. Récupérez vous-même l'archive du modèle sur la page des versions GitHub du dépôt SlicerAutomatedDentalTools (le fichier BART.zip, dans la version « MedX »), décompressez-la, puis pointez le module vers ce dossier.

La barre de progression du tableau de bord ne bouge jamais

Contrairement au chemin Summarize, la barre de progression du Dashboard reste immobile pendant toute l'exécution. Ce n'est pas le signe d'un blocage : laissez tourner et attendez que dashboard.png apparaisse dans le dossier de sortie.

Un dossier d'entrée vide fait planter le module

Lancer l'un ou l'autre chemin sur un dossier sans document exploitable déclenche une erreur au lieu d'un message propre. Vérifiez que le dossier choisi contient bien des fichiers avant de lancer.

Deux exécutions, deux résumés différents

Le modèle n'est pas déterministe : relancer le chemin Summarize sur exactement les mêmes documents ne reproduira pas le résumé précédent mot pour mot. Si vous devez comparer des résultats dans le temps, conservez les fichiers _summary.txt que vous avez déjà plutôt que de les régénérer.

Comment citer

Si vous avez utilisé MedX dans un travail de recherche, citez :

In: Clinical Image-Based Procedures (CLIP 2025), held with MICCAI 2025, Lecture Notes in Computer Science vol. 16126, Springer, 2025, p. 42-52.

doi:10.1007/978-3-032-05479-1_5. Le papier de la chaîne dont MedX est le maillon texte : passer de comptes rendus libres à des données exploitables.

Contexte, à ne pas citer pour l'outil

  • Lewis et al., ACL 2020: BART: Denoising Sequence-to-Sequence Pre-training for Natural Language Generation, Translation, and Comprehension. Le modèle amont que MedX affine. Explique ce que le résumé sait faire , et qu'il reformule, donc qu'il peut inventer.
  • Bianchi et al., Seminars in Orthodontics 2021: Decision Support Systems in Temporomandibular Joint Osteoarthritis. Le contexte clinique : à quelle décision ces données extraites sont censées servir.

La bibliographie complète de l'outil, ce qui a été trouvé, et ce qui a été cherché sans rien trouver, est dans ses sources.

MRI2CBCT : aligner une IRM et un CBCT de l'ATM

MRI2CBCT recale une IRM sur un CBCT de l'articulation temporo-mandibulaire (ATM), pour pouvoir regarder les deux examens dans le même repère. C'est désormais un seul bouton : choisissez les dossiers, appuyez sur Run, et le module prépare, oriente, segmente et recale chaque patient.

Quand s'en servir

Dès que vous avez, pour un même patient, une IRM et un CBCT de l'ATM et que vous voulez les superposer : l'os se voit mieux sur le CBCT, les tissus mous (disque, capsule) mieux sur l'IRM, et le recalage permet de regarder les deux à la fois plutôt que de les comparer de mémoire. Vous ne passez plus par les onglets un à un : un seul Run exécute toute la chaîne pour chaque patient trouvé dans les deux dossiers.

Ce qu'il recale

Le module n'apparie pas la luminosité des deux images. Il demande à un réseau de trouver la base du crâne sur le CBCT et à un autre de la trouver sur l'IRM, puis ajuste les deux surfaces l'une sur l'autre. Le résultat vaut donc ce que valent ces deux contours, ce qui explique qu'il puisse s'interrompre pour vous laisser les vérifier.

Ce qu'il vous faut, ce que vous obtenez

À fournir

  • Un dossier d'IRM et un dossier de CBCT (.nii.gz, .nii ou .nrrd)
  • Des fichiers dont le nom commence par l'identifiant du patient (P01, B038…) : c'est ainsi que les deux dossiers sont appariés. Un CBCT par patient, une ou deux IRM.
  • Un dossier de sortie
  • Une mise en place unique : paquets Python et modèles, environ 5 Go, téléchargés pour vous

Ce qui sort

  • Par patient, un dossier avec chaque articulation d'IRM recalée sur le CBCT d'origine, son masque de base du crâne et le fichier de transformation
  • Un summary.csv avec un verdict pour chaque articulation : OK, SMALL, FLAG ou FLIP
  • Deux volumes superposables dans la même scène, pas un fichier fusionné ; le CBCT n'est jamais modifié

Ce qui se passe quand vous appuyez sur Run

  1. Préparation des IRM. Apparie les patients et, par défaut, rééchantillonne chaque IRM à 0,3 mm et sépare en moitiés gauche et droite un volume qui contient les deux articulations. Un volume avec un intervalle entre deux piles est reconstruit avec l'« acquisition slice spacing » que vous réglez (3,0 mm par défaut). Le côté d'une IRM à une seule articulation est lu d'après sa position dans le fichier.
  2. Orientation du CBCT. Trois étapes automatiques (celles du module ASO) mettent la tête dans l'orientation standard de Francfort et médio-sagittale.
  3. Base du crâne sur le CBCT. Le réseau AMASSS la contourne.
  4. Base du crâne sur l'IRM. Un second réseau, Dataset516, la contourne sur chaque articulation. Par défaut il utilise cinq plis de modèle ; un seul pli est plus rapide sur un ordinateur sans GPU.
  5. Recalage. Ajuste le contour de l'IRM sur celui du CBCT. Si la première réponse est un flip (tournée dans le mauvais sens), le module tente plus d'essais, un demi-tour, l'autre côté de la tête, et enfin une IRM en miroir, avant d'abandonner et de marquer le résultat _FLAGGED.

Options et vérifications

  • Use test files télécharge un patient d'exemple (un CBCT, deux IRM), remplit les trois dossiers et conserve le résultat attendu dans un dossier reference pour que vous puissiez comparer.
  • Resample et Separate left and right sont actifs par défaut. Désactivez la séparation si chacune de vos IRM est déjà une seule articulation ou une tête entière.
  • Advanced : poser l'IRM recalée sur la grille de voxels du CBCT (désactivé par défaut : l'IRM garde ses propres voxels et seule sa position change), conserver les fichiers intermédiaires, régler le nombre de workers de recalage.
  • Review : cochez « Pause during the run » et choisissez où. À chaque pause, les images s'ouvrent dans Slicer avec le contour par-dessus. À la première pause, vous pouvez échanger gauche et droite pour un patient si le côté est faux.

Si ça coince

Redémarrer après la première mise en place

Si PyTorch a dû être installé ou remplacé pour votre carte graphique, le panneau vous demande de redémarrer Slicer et d'appuyer de nouveau sur Run. Sous Linux, la bibliothèque de recalage exige un système avec glibc 2.31 ou plus récente.

Un patient est ignoré

Un fichier sans identifiant au début de son nom, une IRM sans CBCT (ou l'inverse), ou un patient avec plus d'un CBCT est écarté, et le panneau les liste avant de démarrer. Gardez votre dossier de sortie en dehors des dossiers d'IRM et de CBCT : les dossiers sont lus récursivement, si bien que les résultats d'un run précédent pourraient être pris pour de nouveaux examens.

Lisez le verdict, pas seulement le nom du fichier

Une articulation peut sortir FLAG (recouvrement faible) et être pourtant enregistrée sous un nom de fichier normal ; seuls summary.csv et le message de fin le disent. SMALL signifie que le contour de l'IRM était très petit, le cas qui échoue le plus souvent. Tout ce qui est étiqueté _FLAGGED, FLIP ou _MIRRORED mérite un coup d'œil avant que vous vous y fiiez.

Mauvais côté

Le côté d'une IRM à une seule articulation vient de sa position dans le fichier. S'il est faux, échangez-le à la première pause. Si vous n'avez pas fait de pause, le module peut encore se rattraper en essayant l'autre côté, mais seulement quand la première réponse était un flip.

Le journal disparaît

Le journal du run vit avec les fichiers intermédiaires, qui sont supprimés après un run réussi sauf si vous cochez « Keep the intermediate files ».

Ensuite

Le CBCT d'origine n'est jamais modifié. Ouvrez l'IRM recalée et le CBCT ensemble dans Slicer pour vérifier la superposition avant de l'utiliser pour une mesure. Si vous avez besoin de la transformation pour autre chose, chargez l'IRM d'origine et appliquez-lui le .tfm : rien n'est interpolé de cette façon. Un recalage que le verdict marque comme défaillant vaut mieux relancé avec une pause de relecture sur les deux contours que corrigé à la main.

Contexte, à ne pas citer pour l'outil

  • Al-Saleh et al., J Otolaryngol Head Neck Surg 2016: MRI and CBCT image registration of temporomandibular joint: a systematic review. Pourquoi ce recalage est difficile, et ce que les méthodes publiées obtiennent. En accès libre.
  • Al-Saleh et al., PLOS ONE 2017: Three-Dimensional Assessment of Temporomandibular Joint Using MRI-CBCT Image Registration. Ce qu'on gagne cliniquement à superposer les deux modalités plutôt qu'à les lire côte à côte.
  • Klein et al., IEEE TMI 2010: elastix: A Toolbox for Intensity-Based Medical Image Registration. Le moteur de recalage de la version antérieure du module ; la version actuelle ne l'utilise pas.

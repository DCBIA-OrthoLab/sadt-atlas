Uso de VISOR: ejecutar las herramientas en un servidor desde 3D Slicer

Con VISOR, el cálculo ya no se ejecuta en su ordenador. Elige una herramienta en Slicer, los archivos que selecciona se envían a un servidor, el servidor calcula y el resultado vuelve a su escena. Esta página cubre lo que debe configurar, lo que debe proporcionar y lo que debe comprobar antes de enviar datos de pacientes. Cómo está construido VISOR se explica en el Atlas de VISOR.

cliente: implementado y probado desidentificación: no implementada MRI2CBCT: no incluido
Antes de usar datos de pacientes

El cliente VISOR envía sus archivos tal como están en disco. Nada se desidentifica. Vea Qué sale de su equipo.

Qué cambia para usted

El resto de este sitio describe la extensión legacy, SlicerAutomatedDentalTools: cada módulo se ejecuta en su propio ordenador. VISOR es una extensión de Slicer distinta, AutomatedDentalToolsRemote. Sus módulos son paneles ligeros sobre un servidor remoto.

  • El cálculo sale de su ordenador. Un portátil que no puede ejecutar una segmentación puede aun así pedir una.
  • Nada que instalar en el Python de Slicer y ningún modelo que descargar: la extensión no declara dependencia de otras extensiones, y los modelos residen en el servidor.
  • El formulario procede del servidor. El panel de una herramienta se construye al abrirla, a partir de la descripción que publica el servidor. Un campo añadido en el servidor aparece en Slicer sin una nueva versión de la extensión.
  • Necesita un servidor, una dirección y una clave. Montar uno es asunto del servidor, no de esta página; vea el despliegue.

Instalar la extensión

El README y el archivo de compilación dicen lo siguiente, y aquí no se supone nada más.

  • La extensión es AutomatedDentalToolsRemote. Funciona con las versiones estable y nightly de 3D Slicer, y sus módulos aparecen bajo la categoría Automated Dental Tools Remote.
  • No declara ninguna dependencia de extensiones (EXTENSION_DEPENDS "NA"): no necesita SlicerConda, SlicerDentalModelSeg ni NNUNet para usarla.
  • El README indica que figura en el Extensions Catalog durante la transición.
  • No la instale junto a la extensión legacy. El README pide usar una u otra, porque muchos módulos comparten nombre y Slicer conserva solo uno de dos módulos con el mismo nombre.

Conectar Slicer a un servidor

Abra Server Tools Settings (categoría Automated Dental Tools Remote.Advanced). Hasta que guarde algo aquí, la dirección es un marcador de posición (https://set-your-server.invalid) que no llega a ninguna parte, de modo que ningún archivo sale de su equipo.

Qué proporcionar

  • Server URL: una dirección https:// cuyo certificado esté firmado por una autoridad pública.
  • API key: el token de API del servidor (el campo está enmascarado). El README indica que se use el token de API, nunca el de administrador.
  • Timeout: de 1 a 3600 segundos, 600 por defecto.

Lo que no puede cambiar

  • Nada de http://, ni siquiera http://localhost.
  • El certificado se comprueba siempre: el panel muestra «Verify TLS: Always on», sin nada que marcar.
  • Las redirecciones nunca se siguen.

Haga clic en Save. El cambio se aplica de inmediato y se conserva entre reinicios. Si escribe una dirección http://, Slicer la rechaza antes de guardar nada. Restore defaults borra lo que haya guardado.

Un servidor en su propio ordenador sigue la misma regla: el cliente no acepta el certificado autofirmado del propio servidor, así que se accede a él mediante una dirección pública, por ejemplo una dirección tailscale serve (https://<name>.<tailnet>.ts.net), o un proxy inverso con un certificado de Let's Encrypt o institucional.

¿Es accesible el servidor? No hay botón «Test connection». El panel muestra arriba una línea «Server: online» o «Server: offline», actualizada al abrir el módulo y tras cada guardado. Solo consulta la página /health del servidor, que no necesita clave: «online» no demuestra que su clave sea aceptada. Una clave incorrecta se manifiesta en la primera ejecución (vea Si algo va mal).

La clave se almacena en texto claro

Slicer guarda la clave en su propio archivo de ajustes para su usuario, como texto plano. El campo enmascarado solo la oculta en pantalla. Cualquiera que pueda leer los ajustes de su Slicer puede leer la clave.

HTTPS no tiene alternativa

No hay ningún ajuste, indicador ni archivo que relaje la regla de HTTPS o la comprobación del certificado. Una dirección http:// guardada por una versión anterior del cliente se ignora al arrancar.

Ejecutar una herramienta

  1. Elija una herramienta en la lista de módulos. Construye su formulario desde el servidor al abrirse. Si no se puede contactar con el servidor, el panel indica que no pudo cargar la herramienta y ofrece un botón Retry.
  2. Rellene el formulario. Lo que debe proporcionar depende de la herramienta; los nombres de los campos proceden del servidor, así que lea la página de la Guía propia de cada herramienta.
  3. Pulse Apply. El panel comprueba primero el formulario (argumento desconocido, archivo ausente, campo obligatorio ausente) antes de enviar nada.
  4. Siga el progreso y cancele si lo necesita.

Lo que puede dar como entrada

  • Un archivo se envía tal cual, con el mismo nombre y los mismos bytes.
  • Una carpeta se empaqueta en un archivo comprimido que conserva los nombres de sus archivos y subcarpetas, y luego se envía.
  • Un nodo de la escena de Slicer (un volumen, un modelo, una región de interés) se exporta a un archivo temporal, con el nombre de la herramienta y del argumento, no del nodo. AutoCrop3D, por ejemplo, toma así su región de interés de la escena.
  • Un archivo de prueba alojado es una muestra que el servidor ofrece para la herramienta. Al elegir uno se descarga primero (en segundo plano, la ventana de Slicer sigue siendo utilizable) y luego se usa como entrada. Una segunda elección de la misma entrada en la misma sesión reutiliza la descarga.
  • Un modelo elegido en el servidor se escoge por su nombre en una lista que publica el servidor. Solo viaja el nombre; el archivo del modelo nunca se envía desde su ordenador. Si la lista está vacía y el argumento no tiene otra forma de darse, el panel muestra una advertencia para que consulte al responsable del servidor.

Las entradas grandes se envían en partes y se comprueban parte por parte. Si el servidor publica un plan de tamaños para una carpeta de cohorte, el panel la divide en lotes, cada uno una ejecución ordinaria.

Progreso, cancelación, conexión perdida

  • El panel informa de las propias fases del servidor: solicitud recibida, preparación de los archivos de entrada, espera de la GPU, ejecución en el servidor, empaquetado de los resultados, terminado. Al lado corre un tiempo transcurrido. Una ejecución en cola muestra «queued».
  • Cancel detiene también la ejecución en el servidor. Hay un Cancel por ejecución; con varias ejecuciones dice «Cancel all», y una cohorte dice «Cancel the cohort». Una ejecución cancelada no se notifica como error.
  • Si se corta la conexión mientras el servidor trabaja, el panel se reconecta por sí solo al flujo de progreso y retoma donde se había quedado, sin repetir lo que ya mostró. Este es el modo desacoplado (detached), activado por defecto: la solicitud termina en cuanto se han preparado las entradas y el resultado llega por el flujo de progreso, de modo que el timeout de los ajustes ya no limita cuánto puede durar una ejecución.
Detenerse para revisar usa la vía bloqueante

Si activa un paso «stop after» (vea Revisión de calidad), la ejecución no usa el modo desacoplado: el servidor devuelve el material de revisión en la respuesta a la solicitud original. Allí se aplica el timeout de Server Tools Settings, y una conexión perdida pierde la respuesta.

Obtener los resultados

  • Cuando termina la ejecución, el panel descarga el resultado (en rangos paralelos), comprueba el archivo comprimido y lo descomprime en la carpeta de salida. Por defecto esa carpeta es «Slicer Output» en sus Documentos.
  • Un archivo comprimido se rechaza antes de escribir nada si contiene rutas absolutas, .., enlaces, más de 100 000 entradas o más de 20 GB.
  • La casilla «Load the results into the scene when done» importa lo que produjo la herramienta: volúmenes, mapas de etiquetas, modelos o landmarks, según la herramienta. Por defecto se cargan como máximo 12 elementos; por encima, el panel le avisa de que hay demasiados para cargarlos de una vez.
  • Algunas herramientas añaden sus propias opciones o mensajes: ALI resume su informe de ejecución y pide confirmación por encima de 20 archivos de landmarks; VFACE tiene una casilla «Load the heat maps»; AutoMatrix tiene una casilla «Use the mirror matrix». CNE no carga nada en la escena y muestra un resumen en la barra de estado.
  • La copia del resultado en el servidor se elimina tras su descarga.

Revisión de calidad con VISU

Algunas herramientas pueden detenerse tras un paso para que usted compruebe el resultado intermedio. El formulario muestra entonces una sección «Quality control» con una elección múltiple stop_after; no hay nada marcado por defecto. La ofrecen las herramientas que llaman a otras herramientas, por ejemplo ALI para escaneos intraorales o VFACE.

  1. Detener. El servidor se pausa tras el paso que marcó. El panel muestra «Stopped after <step>, waiting for your review», descarga lo producido hasta ese momento y abre VISU sobre ello.
  2. Revisar. VISU muestra un paciente a la vez: escaneo, máscaras, superficies y landmarks juntos. Las teclas de flecha van al caso anterior o al siguiente. Use Flag para marcar a un paciente y Go to next flagged para saltar a él. Lea la línea «Drawn on <scan>» (indica sobre qué escaneo se dibujan los landmarks y si se encontró junto a los puntos o se supuso).
  3. Corregir. Para los landmarks, puede arrastrar puntos y Save: solo se reescriben los puntos que movió, emparejados por nombre. Undo my changes y Revert to what is on disk los restauran. Un ajuste de registro se guarda como un archivo de transformación aparte junto a la escena, nunca fusionado con la transformación propia de la herramienta.
  4. Continuar. Solo se devuelven los archivos cuyo contenido cambió, y luego el servidor reanuda la ejecución.
  5. Volver atrás. Cuando se puede corregir un paso anterior (landmarks o un registro), el indicador dice «Go back and edit this patient». Cuando ha marcado algunos, el botón verde dice «Go back to <step> for N patient(s)»: se escriben sus correcciones, los pacientes marcados se rehacen desde ese paso y todos los demás conservan el resultado que ya tienen.

Si no se encuentra VISU, o la parada no produjo nada que mirar, el panel lo indica y reanuda la ejecución de inmediato, para que nada quede en pausa en el servidor con sus datos dentro.

VISU también funciona con cualquier carpeta

Puede abrir VISU sobre cualquier carpeta que haya escrito una herramienta, sin ningún servidor de por medio: empareja por nombre de archivo el escaneo, las máscaras, las superficies y los landmarks de cada paciente. Lo único que obtiene de un servidor son conjuntos de datos de muestra alojados.

Qué sale de su equipo

Nada se desidentifica

Hoy no existe ninguna herramienta de desidentificación en VISOR. Lo que selecciona se envía al servidor tal como está en disco: nombres de archivo, cabeceras DICOM y todos los identificadores que contienen. Un pipeline de desidentificación está especificado en el repositorio del cliente, pero su README indica que no está implementado, y una búsqueda en el código no encuentra ninguna implementación.

  • El aviso. Tras guardar una dirección de servidor que no sea este ordenador, Slicer muestra una vez por servidor: «Files are uploaded unmodified. This client does not de-identify anything... De-identify your data before selecting it, or confine use to data that carries no protected health information.» Es una advertencia, no una comprobación: no detiene nada.
  • Las carpetas conservan sus nombres. Una carpeta se empaqueta con los nombres originales de sus archivos y subcarpetas. Un nodo de la escena se exporta con un nombre genérico, de modo que el nombre del nodo no sale.
  • CNE envía notas clínicas. El modelo de texto se ejecuta en el servidor: las notas suben y las extracciones vuelven. La página de CNE legacy, que dice que nada sale de su equipo, no se aplica a VISOR.
  • Solo el transporte. HTTPS protege la transferencia. Más allá de eso, el cliente no cifra los archivos.
  • El Medical Data Anonymizer sigue existiendo, pero trata documentos de texto en este equipo y no forma parte de lo que se envía.
  • Dirija el cliente solo a un servidor que su institución controle, y compruebe que el acuerdo con quien lo opera cubre los datos que envía. El README pide lo mismo.

El panorama de seguridad, incluido lo que el servidor protege y lo que no, está en Seguridad de VISOR.

Si algo sale mal

En la mayoría de los fallos, Slicer muestra el propio mensaje del servidor. Esto es lo que significa cada uno.

«The server URL must start with https://»

Escribió una dirección http://, o Slicer encontró una de una versión anterior. Use la dirección pública https://; no hay forma de eludir la regla, tampoco para un servidor en su propio ordenador.

401: fallo de autenticación

La clave es incorrecta o falta. El panel puede seguir diciendo «Server: online» porque la página de salud no necesita clave. Vuelva a introducir la clave en Server Tools Settings y pulse Save.

503 durante una ventana de mantenimiento

Mientras se actualiza el servidor, rechaza el trabajo nuevo con un 503 y una cabecera Retry-After: 10, durante 300 segundos como máximo. El cliente no lee esa cabecera: usted ve el mensaje del servidor, o «Server error (503)». Espere y pulse Apply de nuevo. La lectura de resultados que ya estaban en curso no se bloquea.

422: argumentos no válidos

El servidor nombra el argumento problemático, por ejemplo una opción fuera de la lista aceptada. Corrija el campo que nombra. Un «400» con un mensaje sobre el tipo de archivo significa que la extensión del archivo no es aceptada por esa herramienta.

413: archivo demasiado grande

El servidor rechaza una subida por encima de su límite, 500 MB por archivo por defecto. Para una cohorte grande, dé una carpeta en lugar de un único archivo comprimido enorme, para que pueda dividirse en lotes.

500: «The tool failed on the server»

Es todo lo que el cliente muestra ante un fallo dentro de una herramienta, a propósito: los detalles pueden contener elementos internos del servidor. Pida a quien gestiona el servidor que lea su registro.

  • Timeouts. El timeout de Server Tools Settings (600 s por defecto) se aplica a las solicitudes que permanecen abiertas. En el modo desacoplado, que es el predeterminado, una ejecución larga no se corta por él. El servidor no tiene por defecto ningún límite de tiempo de ejecución.
  • Espera en una cola. Una ejecución puede esperar a la GPU: el panel indica «Waiting for the GPU», y puede cancelar mientras espera. El servidor también limita cuántas ejecuciones se ejecutan a la vez, así que una quinta ejecución puede esperar incluso antes de aparecer como en cola.
  • Servidor sin conexión. Si no se puede cargar la lista de herramientas, el panel lo indica y muestra Retry. Compruebe la dirección y «Server: online» en Server Tools Settings.
  • Un cambio en config.py no tiene efecto. Lo que guardó en Server Tools Settings prevalece siempre sobre los valores predeterminados compilados.

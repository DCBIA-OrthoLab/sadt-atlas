3. El pipeline

Explicación en lenguaje llano y matemáticas: página del atlas.

3.1 Carga de los paquetes de modelo

Explicación en lenguaje llano y matemáticas: página del atlas.

model es opcional y está oculto. Cuando está vacío, run() usa <data_root>/Surg_Mov_Pred/models (__init__.py:19,22-34,71). load_model_packages toma entonces todo stacking_package.pkl que haya debajo, en orden alfabético, y carga cada uno con joblib (pipeline.py:162-195):

package_files = sorted(model.glob("**/stacking_package.pkl"))   # legacy: list(...), filesystem order
for pkl_path in package_files:
    package = joblib.load(pkl_path)        # {target_name, features_names, scaler, model}
    packages[package["target_name"]] = package

Un paquete ilegible se registra en el log y se omite; si ninguno se carga, RuntimeError (pipeline.py:180-192). El comentario de layout.py:16-24 describe el conjunto incluido: 112 paquetes, cada uno pide las mismas 145 columnas, de las cuales 28 llevan el sufijo _T0 (estado preoperatorio) y 25 el sufijo _Total (el movimiento total planificado). La tabla contiene por tanto el plan además de las mediciones, de ahí la etiqueta «Measurements and plan». Los regresores de stacking contienen subestimadores de LightGBM, así que lightgbm debe estar instalado para que joblib.load funcione (pyproject.toml:18-20). Los paquetes se serializaron con scikit-learn 1.6.1 y se cargan con 1.7.2; el aviso de versión se silencia a propósito, como hacía upstream (pipeline.py:101-115, README.md:72-75).

3.2 Lectura de las mediciones

Explicación en lenguaje llano y matemáticas: página del atlas.

  • Un archivo o una carpeta plana. Un archivo se lee según su extensión: .csv con read_csv, .xlsx con read_excel, .ods con read_excel(engine="odf") (pipeline.py:22,118-129). Una carpeta no se recorre de forma recursiva: sus archivos con una de las tres extensiones, sin distinguir mayúsculas, se ordenan y se concatenan fila a fila (:132-159). Legacy solo leía una carpeta, buscaba con glob extensiones en minúsculas y en mayúsculas y eliminaba duplicados con set(), de modo que el orden de las filas cambiaba entre ejecuciones (legacy SurgMovPred_CLI/SurgMovPred_CLI.py:151-157).
  • Identificador del paciente. find_id_column prueba ocho patrones en orden (#, id, id patient, patient id, patient number, subject id, patient, subject, sin distinguir mayúsculas), y luego cualquier columna cuyo nombre contenga a la vez «patient» e «id» (pipeline.py:65-98). Sin ninguna, IDPatient queda vacío con un aviso (:303-312).
  • Los nombres de columna se limpian hasta la forma del momento del entrenamiento con clean_name: se recortan los espacios, se eliminan comillas, barras invertidas y corchetes, toda secuencia de caracteres que no sean letras, dígitos, guion bajo y apóstrofo se convierte en un solo guion bajo, total pasa a Total, y un dígito inicial recibe f_ (pipeline.py:27-50). Un nombre que no se puede limpiar lanza ValueError (:51-60); legacy devolvía 'f_unnamed', así que dos columnas así se pisaban entre sí (legacy SurgMovPred_CLI.py:63-66).

La única tolerancia es el sufijo _T0 ausente; cualquier otra columna que falte elimina ese objetivo de la salida con un aviso (pipeline.py:224-236). Una excepción al predecir un objetivo se registra y el bucle continúa (:249-250). Una celda en blanco no se rellena: llega al scaler como NaN y el modelo lanza una excepción, de modo que ese objetivo se descarta para todas las filas (los paquetes contienen un ElasticNetCV; un stack de sustitución sobre un scikit-learn actual lanzó ValueError: Input X contains NaN; los paquetes incluidos no se ejecutaron). Si no se predijo ningún objetivo, la ejecución lanza RuntimeError en lugar de escribir tablas sin predicciones (:252-264). Legacy escribía esas tablas.

8. Hallazgos en VISOR

Explicación en lenguaje llano y matemáticas: página del atlas.

Columna de índice sin nombre en las dos tablas

Los dos archivos de resultados empiezan con una columna que contiene 0, 1, 2 y así sucesivamente, antes de IDPatient (pipeline.py:283-284). La CLI legacy hace lo mismo (legacy SurgMovPred_CLI/SurgMovPred_CLI.py:268-269). Hay que tenerlo en cuenta al leer las posiciones de las columnas.

Comentarios obsoletos en el cliente

El cliente dice que output_kind «is file» (Remote SurgMovPredRemote/SurgMovPredRemote.py:44) y el widget base da «SurgMovPred's single predictions_outputs.xlsx» como ejemplo (Remote ServerToolsCore/ServerToolsCoreLib/base_widget.py:1390-1391). La herramienta devuelve dos archivos, que el código de esquemas publica como un conjunto de archivos (VISOR-serve server/registry/schema_tool.py:100-103). El panel los sigue manejando, ya que descomprime cualquier zip que recibe.

Ruta de datos obsoleta en el README

El README de la herramienta da la carpeta de modelos como /DATA/SurgMovPred/models (README.md:45), mientras que el código busca bajo Surg_Mov_Pred (__init__.py:19,34), el nombre que usa también el manifiesto de datos (VISOR-serve scripts/data-manifest.yml:91). El código es la referencia.

Sigue siendo cierto desde legacy: objetivos independientes, nada se aplica a la escena

Cada objetivo es un model.predict distinto sobre la misma fila (pipeline.py:216-247), de modo que no se obliga a que los desplazamientos predichos de los puntos de un mismo segmento rígido concuerden entre sí (página legacy, trampas). La salida son solo las dos tablas: ninguna transformación, ningún nodo de Slicer, y el panel guarda el archivo comprimido en lugar de cargar nada (RESULT_KIND = "save_as", Remote SurgMovPredRemote.py:46). Leído en el código.

Un objetivo omitido solo se ve en el log del servidor

Un paquete cuyas características faltan en la tabla se omite con un logger.warning, y un objetivo que falla al predecir con logger.exception (pipeline.py:234-236,249-250). La ejecución termina entonces con éxito pero con menos columnas. No hay archivo de informe, así que el usuario solo ve los objetivos que faltan contando columnas. La única protección es el caso de todo o nada (:252-264). Leído en el código.

Verificado: orden reproducible y ningún resultado vacío en silencio

Los paquetes y las tablas se ordenan, así que dos ejecuciones con la misma entrada dan las mismas filas y columnas en el mismo orden (pipeline.py:143-147,173); una ejecución en la que ningún modelo predice es un error, no dos tablas vacías (:252-264); un nombre de columna incorrecto es un error, no una característica pisada (:51-60). Leído en el código.

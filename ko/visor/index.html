VISOR: 도구의 차세대

이 아틀라스의 나머지는 모든 알고리즘이 Slicer 안에서 실행되는 레거시 확장을 다룬다. VISOR는 계산을 서버로 옮기는 새로운 세대로, 얇은 Slicer 클라이언트, 치과 도구를 하나도 알지 못하는 범용 추론 서버, 그리고 각각 자기 폴더와 자기 Python 환경을 가진 도구의 카탈로그로 이루어진다. 이 페이지는 개요이며, 맨 아래에 나열된 페이지들이 내부 구조를 다룬다.

감사 스냅샷 · 2026-11-09 저장소 세 개 영어 전용
다른 언어

이 사이트의 프랑스어, 스페인어, 이탈리아어, 한국어, 포르투갈어, 태국어 버전은 레거시 코드만(SlicerAutomatedDentalTools, 커밋 3c67957) 설명한다. VISOR 페이지는 없다. 번역된 도구 페이지가 계산이 어디서 실행되는지, 또는 어떤 환경이 필요한지에 대해 말하는 것은 모두 레거시에 대한 진술이다. 번역은 나중에 다시 할 것이다.

1. VISOR란 무엇인가

VISOR는 각각 한 계층을 맡는 저장소 세 개다. 어느 것도 레거시 확장의 포크가 아니다. 알고리즘은 이식된 것이고("다시 쓰기가 아니라 재패키징 작업", SADT-VISOR CONTRIBUTING.md:309-315), 그 주변의 구조는 새것이다.

Remote, 클라이언트AutomatedDentalToolsRemote, 클라이언트: 모듈 폴더 23개로 이루어진 Slicer 확장이며, 각각은 서버 위의 얇은 패널이다. 패널은 서버의 도구 기술자로부터 실행 시점에 생성되므로, 서버에 추가된 필드는 클라이언트 릴리스 없이 Slicer에 나타난다. 이식된 모듈에 대해 Slicer는 아무것도 설치하지 않고 모델도 내려받지 않는다.
VISOR-serve, 서버추론 서버: FastAPI, Python 3.13, torch 없음. 도구를 발견하고, 그 스키마를 게시하며, 실행을 대기열에 넣고 접수하고, 각각을 도구 자신의 인터프리터에서 시작한다. 이름으로 치과 도구를 하나도 알지 못하도록 설계되어 있다.
SADT-VISOR, 도구카탈로그: 도구마다 격리된 Python 프로젝트 하나, 총 19개이며, 각각 자기 .venv와 커밋된 uv.lock을 가진다. 도구는 공개 함수 하나 run()이며, 그 스키마는 시그니처에서 도출된다.

코드: 클라이언트 AutomatedDentalToolsRemote CMakeLists.txt:24-48, ServerToolsCoreLib/formgen.py:1-30, 서버 VISOR-serve server/registry/__init__.py:114, 카탈로그 SADT-VISOR README.md:3-5, 41-58.

2. 왜 존재하는가

레거시는 모든 것을 Slicer에 넣는다. 위젯, 모델 다운로드, 그리고 각 모듈이 스스로 만드는 Python 환경이다. 이 아틀라스의 레거시 페이지들에서 반복되는 결과가 둘 있다. GPU가 없는 노트북은 분할을 실행할 수 없고, 서로 호환되지 않는 라이브러리 버전을 고정한 도구는 사용자의 컴퓨터에 만들어진 별도의 conda 환경에 있어야 한다. SADT-VISOR 자체의 README는 upstream 고정 버전의 재현 가능한 충돌을 나열한다. SurgMovPred는 numpy==2.4.0을 요구하는 반면 AREG, MedX, CLIC는 numpy<2.0.0을 필요로 하고, conda 환경 둘이 모두 shapeaxi라는 이름이며(Python 3.9와 3.12), torch는 모듈 다섯 개에서 2.2.0으로 고정되어 있고 나머지에서는 고정되어 있지 않다(SADT-VISOR README.md:10-28).

VISOR는 두 가지 조치로 답한다. 계산은 GPU를 가진 한 대의 머신으로 가고, 각 도구는 자기 버전을 유지한다. "버전은 과학의 일부"이기 때문이다(SADT-VISOR README.md:25-28). 많은 환경의 디스크 비용은 동일한 wheel이 inode를 공유하도록 환경을 만드는 것으로 처리된다. scripts/audit.py는 읽은 체크아웃에서 가상 환경 7개가 겉보기 19.6 GB, 고유 8.3 GB로 있음을 측정했다(SADT-VISOR scripts/audit.py:201-204, 2026-11-09 실행).

3. 레거시와 VISOR, 나란히

양쪽 코드가 보여 주는 것만 담는다. "레거시"는 SlicerAutomatedDentalTools의 3c67957이고, "VISOR"는 아래에 나열된 커밋의 저장소 세 개다.

질문레거시VISOR
계산이 실행되는 곳 사용자의 컴퓨터, Slicer 안: 위젯, CLI 모듈, Slicer의 Python의 하위 프로세스 서버. SchemaTool.invoke는 항상 dispatch를 거치며, 서버는 패키징된 도구를 결코 import하지 않는다(VISOR-serve server/registry/schema_tool.py:812-822)
Python 환경 대부분의 모듈에서 ADTLib/env/conda.py가 사용자의 컴퓨터에 만든다. GreedyReg는 환경이 없고 Slicer 자체의 Python을 쓴다 도구마다 .venv 하나와 커밋된 uv.lock 하나, 공유 워크스페이스 lockfile은 없다(SADT-VISOR CONTRIBUTING.md:578-583)
인터페이스 모듈마다 손으로 작성한 Qt 위젯(GreedyReg 위젯은 1,704줄이며 그중 약 700줄이 Qt UI) formgen.py가 스키마에서 생성한다. 대부분의 Remote 클래스는 TOOL_NAME과 몇 개의 훅 정도만 담고 있다(AutomatedDentalToolsRemote ServerToolsCoreLib/formgen.py:1-30)
인자 목록이 오는 곳 서버 쪽 스키마 없음: 인자는 각 모듈 자신의 위젯과 CLI에 있다 run()의 시그니처에서 scripts/describe.py가 도출한다. 손으로 쓴 예전 표는 "어긋났다"(SADT-VISOR scripts/describe.py:8-11). 스키마 절을 참고한다
데이터 이동 로컬 경로와 파일 조각으로 업로드하며, 이어받기가 가능하고, 각 조각을 SHA-256으로 검사한 뒤 결과를 스트리밍 또는 range 다운로드로 받는다(VISOR-serve server/main.py:857-912, server/wire/transfer.py). 실행 과정, 단계별을 참고한다
한 도구가 다른 도구를 호출 Slicer에서: slicer.cli.run(slicer.modules.ali_cbct, …)(GreedyReg, Distant 모드) 도구에서, 감독자를 통해: sup.run("ALI_CBCT", …)는 부모의 하위 프로세스를 시작하며, 새 HTTP 요청도 새 접수(admission)도 없다(VISOR-serve server/execution/runner.py:1808). 감독자를 참고한다
품질 검사 뒤의 검토 Slicer 모듈이 스스로 멈추고, 수정 사항을 모으고, 되돌린다(예: AREG_CBCT, Review.py) 서버는 선언된 호출 뒤에 멈추고(stop_after), 작업을 유지하며, 수정 사항과 함께 POST /runs/{id}/resume 또는 /rewind를 받는다(VISOR-serve server/main.py:1685, 1750)
실행의 시간 제한 모듈 안의 호출별 타임아웃(GreedyReg: 하위 프로세스 호출당 600 s) 기본값은 없음: TOOL_TIMEOUT_SECONDS = 0이며 timeout_seconds가 deployment.toml에도 없다(VISOR-serve server/config.py:77)
의도적으로 이 목록에 없는 것

속도, 정확도, 출력의 동등성은 여기서 비교하지 않는다. 서버 벤치마크(VISOR-serve benchmarks/)는 2026-09-21에 admission 엔진이 다시 쓰이기 전에 측정되었고, 기록에 남은 유일한 동등성 세션은 도구 여섯 중 하나에서만 바이트 단위로 동일한 출력을 발견했다. 이 사이트의 어느 것도 VISOR가 레거시 결과를 비트 단위로 재현한다고 주장하지 않는다.

4. 각 도구의 상태

"제공됨(served)"은 폴더가 SADT-VISOR 카탈로그에 있고 VISOR-serve가 이를 발견해 로드한다는 뜻이며, 실행 중인 인스턴스가 2026-10-20에 같은 23개 이름을 나열했다. 이는 운영 배포를 뜻하지 않으며, 여기에 있는 어느 것도 이를 입증하지 않는다. "Slicer 모듈"은 도구를 호출하는 AutomatedDentalToolsRemote의 폴더다. 각 도구는 이 아틀라스에 페이지가 둘 있다. VISOR 페이지는 서버에서 무엇이 실행되고 무엇이 바뀌었는지를 말하고, 레거시 페이지는 원래의 Slicer 모듈을 설명한다.

Remote 모듈이 순수한 패널과 다른 곳

ALIRemote와 AREGRemote는 파사드에 요청 하나를 보내고 서버가 엔진을 고른다(파사드 참고). FlexRegRemote는 조이스틱이 반응하도록 패치의 윤곽을 로컬에서, 294,000점 아치에서 약 18 ms로 다시 계산한다. 실제 패치는 Apply 때 서버에서 계산된다(FlexRegRemote.py:14-18).

5. 보안, 한 문장으로

전송은 클라이언트가 검증하는 인증서를 쓰는 HTTPS와 대부분의 경로에서 공유 Bearer 토큰이며, 비식별화는 명세되어 있지만 구현되지 않았고, 증명(attestation)과 키 교환은 별도의 연구 프로토타입에만 있을 뿐 이 저장소 세 개에는 없다. 자세한 내용과 근거는 보안 페이지에 있다.

6. 무엇을, 언제 읽었는가

이 절은 스냅샷이다. 이 페이지들은 모든 브랜치의 끝이 아니라 2026-11-09에 아래의 작업 트리를 읽은 것이다. 코드는 움직이며, 이 페이지들의 줄 번호나 개수는 여기에 명시된 커밋에 대해서만 참이고 다음 주에는 참이 아닐 수 있다. 저장소 자신의 문서가 코드와 어긋나는 곳에서는 이 페이지들이 코드를 따르며 그렇다고 밝힌다.

7. 나머지를 읽는 방법

아키텍처클라이언트와 서버, 세 규칙, registry, 스키마, deployment.toml, 파사드, 호출 그래프, 감독자. 실행 과정, 단계별업로드, 스테이징, admission, 실행, 이벤트, 결과, 취소, 검토. 패키징과 배포이미지, 환경, compose 프로파일, 업데이트. 보안과 개인정보무엇이 구현되었고, 무엇이 명세만 있으며, 무엇이 프로토타입인지. 테스트와 출처도구가 어떻게 테스트되는지, 이름과 출처가 어떻게 검사되는지. VISOR 사용하기가이드 페이지: 서버에 연결하고, 도구를 실행하고, 결과를 읽는다.

이식된 모든 도구에는 페이지가 넷 있다. 레거시 모듈의 가이드 페이지와 아틀라스 페이지, 그리고 VISOR의 같은 둘이다. 사이드바 맨 위의 Legacy | VISOR 선택기는 지금 읽는 페이지의 두 세대를 오가게 하고, 그 아래의 Guide | Atlas 선택기는 사용자의 시점과 코드를 오가게 한다. 레거시 페이지는 원래의 Slicer 모듈(커밋 3c67957)을 설명한다. 그 매개변수, 모델, 실패 양상, 그리고 어디서 실행되는지다. 4절의 표는 모든 도구의 두 페이지를 연결한다.

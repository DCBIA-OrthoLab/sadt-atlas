VISOR의 SurgMovPred: 코드

개발자용: SurgMovPred의 VISOR 포팅이 코드에서 하는 일을 file:line 참조, 코드, 인자, 환경, 레거시 코드와의 차이, 발견 사항과 함께 다룬다. 수식이 포함된 쉬운 설명은 아틀라스 페이지에 있다.

코드 아틀라스 (해설) VISOR 회귀기 112개 CPU 전용 레거시 페이지 가이드 (VISOR)

이 페이지의 참조는 저장소 이름, 그 안의 경로, 줄 번호 순으로 적는다. SADT-VISOR는 도구 카탈로그(커밋 6ba2a78), VISOR-serve는 서버(e9a7e5d), Remote는 Slicer 클라이언트(AutomatedDentalToolsRemote 19b95e8), legacy는 3c67957 시점의 SlicerAutomatedDentalTools이다. pipeline.py:173 같은 경로만 있는 것은 SADT-VISOR의 tools/Surg_Mov_Pred/src/sadt_surgmovpred/에 있고, 저장소 표시가 없는 README.md와 pyproject.toml은 tools/Surg_Mov_Pred/에 있다. 모두 코드에서 읽은 것이며, 이 페이지의 어떤 내용도 실행 결과에서 나온 것이 아니다. 스택의 개요는 VISOR와 그 아키텍처를 참고하라.

1. 체인에서의 위치

쉬운 설명과 수식: 아틀라스 페이지.

항목값
API 이름Surg_Mov_Pred. Slicer 패널의 이름은 SurgMovPred이다. 도구는 Surg_Mov_Pred라는 이름으로 패키징되었고, 서버는 조회 시 예전 철자도 받아들인다(VISOR-serve server/registry/__init__.py:282-293).
도구 폴더SADT-VISOR tools/Surg_Mov_Pred: src/sadt_surgmovpred/{__init__,pipeline,layout}.py.
Slicer 모듈SurgMovPredRemote, 얇은 패널: TOOL_NAME = "Surg_Mov_Pred"(Remote SurgMovPredRemote/SurgMovPredRemote.py:33), RESULT_KIND = "save_as"(:46), Remote CMakeLists.txt:45이 빌드한다.
호출하는 것, 호출되는 것둘 다 없다. sup 인자가 없다(__init__.py:37-46). 다른 도구를 호출하지도, 다른 도구가 이 도구를 호출하지도 않는 말단이며, 레거시 모듈과 같다.
서버 선언[tools.Surg_Mov_Pred] 섹션이 VISOR-serve server/deployment.toml에 없다. 서버의 기본 규칙으로 실행된다. 데이터 매니페스트에는 모델(all_models.zip, 740 MB, 압축 해제)과 테스트 파일(TestFiles.zip)이 올라 있다(VISOR-serve scripts/data-manifest.yml:89-105).
상태구현되어 있으며, tests/ 아래 파일 다섯 개에 테스트 함수가 105개 있다(이 페이지를 위해 실행하지는 않았다). README는 이전 서버 구현(레거시 Slicer 모듈이 아니다)과의 비교를 보고한다. 환자 101명과 패키지 112개가 같고, 최대 절대 차이는 0.000e+00이다(README.md:90-104). 이 비교는 README에서 읽은 것이며 이 페이지를 위해 다시 실행하지는 않았다.
출처SurgMovPred_CLI/SurgMovPred_CLI.py를 업스트림 커밋 d7702ae(2026-06-24) 시점에서 포팅했으며, 이전 서버의 tools/SurgMovPred/를 거쳤다(README.md:7-14).

1.1 무엇이 어디서 실행되는가

쉬운 설명과 수식: 아틀라스 페이지.

위치하는 일
서버전부 한다. 표 읽기, 열 이름 정리, 스태킹 회귀기 112개, 표 두 개 쓰기. CPU 전용이다. 도구 환경에 torch가 설치되어 있지 않으며 테스트가 이를 확인한다(README.md:106-107). Python 3.12, numpy 2.2.6, scikit-learn 1.7.2, LightGBM 4.7.0(pyproject.toml:7,14-20).
클라이언트(Slicer)필드가 하나뿐인 생성형 패널로, 필드는 측정값이다(layout.py:25: "Measurements and plan"). 표(또는 보낼 때 압축한 폴더)가 업로드된다. 결과 표 두 개는 zip 하나로 돌아오며, 패널이 이를 사용자가 고른 파일 옆에 푼다(RESULT_KIND = "save_as", Remote ServerToolsCore/ServerToolsCoreLib/base_widget.py:1397-1413). 장면에는 아무것도 불러오지 않는다.

실행의 메커니즘: 실행의 구조. 업로드를 보호하는 것: 보안과 개인정보.

3.1 모델 패키지 불러오기

쉬운 설명과 수식: 아틀라스 페이지.

model은 선택 사항이며 숨겨져 있다. 비어 있으면 run()이 <data_root>/Surg_Mov_Pred/models를 쓴다(__init__.py:19,22-34,71). 그다음 load_model_packages가 그 아래의 stacking_package.pkl을 모두 정렬된 순서로 모아 각각 joblib으로 불러온다(pipeline.py:162-195).

package_files = sorted(model.glob("**/stacking_package.pkl"))   # legacy: list(...), filesystem order
for pkl_path in package_files:
    package = joblib.load(pkl_path)        # {target_name, features_names, scaler, model}
    packages[package["target_name"]] = package

읽을 수 없는 패키지는 로그에 남기고 건너뛴다. 하나도 불러오지 못하면 RuntimeError가 난다(pipeline.py:180-192). layout.py:16-24의 주석은 배포된 세트를 설명한다. 패키지 112개가 모두 같은 145개 열을 요구하며, 그중 28개는 접미사 _T0(수술 전 상태), 25개는 접미사 _Total(계획된 총 이동량)을 가진다. 그래서 표에는 측정값뿐 아니라 계획도 들어 있어야 하며, 라벨이 "Measurements and plan"인 것도 이 때문이다. 스태킹 회귀기에는 LightGBM 하위 추정기가 들어 있으므로 lightgbm이 설치되어 있어야 joblib.load가 성공한다(pyproject.toml:18-20). 패키지는 scikit-learn 1.6.1에서 피클되었고 1.7.2에서 불러온다. 버전 경고는 업스트림이 한 대로 일부러 끈다(pipeline.py:101-115, README.md:72-75).

3.2 측정값 읽기

쉬운 설명과 수식: 아틀라스 페이지.

  • 파일 하나 또는 평평한 폴더. 파일은 확장자에 따라 읽는다. .csv는 read_csv, .xlsx는 read_excel, .ods는 read_excel(engine="odf")로 읽는다(pipeline.py:22,118-129). 폴더는 재귀적으로 탐색하지 않는다. 세 확장자 중 하나를 가진 파일(대소문자 무시)을 정렬해 행 방향으로 이어 붙인다(:132-159). 레거시는 폴더만 읽었고, 소문자와 대문자 확장자를 glob으로 모은 뒤 set()으로 중복을 제거했기 때문에 실행마다 행 순서가 달라졌다(레거시 SurgMovPred_CLI/SurgMovPred_CLI.py:151-157).
  • 환자 식별자. find_id_column은 패턴 여덟 개를 순서대로 시도하고(#, id, id patient, patient id, patient number, subject id, patient, subject, 대소문자 무시), 그다음에는 이름에 "patient"와 "id"가 모두 들어 있는 열을 찾는다(pipeline.py:65-98). 찾지 못하면 경고와 함께 IDPatient를 비워 둔다(:303-312).
  • 열 이름은 clean_name이 학습 때의 형태로 정리한다. 앞뒤 공백을 제거하고, 따옴표, 역슬래시, 괄호를 없애며, 글자, 숫자, 밑줄, 아포스트로피가 아닌 문자가 이어진 부분은 밑줄 하나로 바꾸고, total은 Total이 되며, 숫자로 시작하면 f_가 붙는다(pipeline.py:27-50). 정리할 수 없는 이름은 ValueError를 일으킨다(:51-60). 레거시는 'f_unnamed'를 반환했기 때문에 그런 열 두 개가 서로를 가렸다(레거시 SurgMovPred_CLI.py:63-66).

    for f in pack["features_names"]:

허용되는 것은 _T0 접미사가 없는 경우뿐이며, 그 밖의 열이 하나라도 없으면 경고와 함께 그 타깃이 출력에서 빠진다(pipeline.py:224-236). 타깃 하나를 예측하다 예외가 나면 로그에 남기고 루프는 계속된다(:249-250). 빈 셀은 채워지지 않는다. 스케일러를 거쳐도 NaN으로 남고 모델이 이에 대해 예외를 일으키므로, 그 타깃은 모든 행에서 제외된다(패키지에는 ElasticNetCV가 들어 있다. 최신 scikit-learn에서 대용 스택은 ValueError: Input X contains NaN을 일으켰으며, 배포된 패키지는 실행하지 않았다). 예측된 타깃이 하나도 없으면 예측 없는 표를 쓰는 대신 RuntimeError로 실행이 중단된다(:252-264). 레거시는 그런 표를 썼다.

8. VISOR의 발견 사항

쉬운 설명과 수식: 아틀라스 페이지.

두 표 모두에 이름 없는 인덱스 열

두 결과 파일 모두 IDPatient 앞에 0, 1, 2 같은 값이 든 열로 시작한다(pipeline.py:283-284). 레거시 CLI도 같다(레거시 SurgMovPred_CLI/SurgMovPred_CLI.py:268-269). 열 위치를 읽을 때 이를 감안해야 한다.

클라이언트의 낡은 주석

클라이언트는 output_kind가 "is file"이라고 하고(Remote SurgMovPredRemote/SurgMovPredRemote.py:44), 베이스 위젯은 예시로 "SurgMovPred's single predictions_outputs.xlsx"를 든다(Remote ServerToolsCore/ServerToolsCoreLib/base_widget.py:1390-1391). 도구는 파일 두 개를 반환하며, 스키마 코드는 이를 파일 묶음으로 공개한다(VISOR-serve server/registry/schema_tool.py:100-103). 패널은 받은 zip을 무엇이든 푸므로 그래도 처리한다.

README의 낡은 데이터 경로

도구 README는 모델 폴더를 /DATA/SurgMovPred/models라고 적고 있지만(README.md:45), 코드는 Surg_Mov_Pred 아래에서 찾는다(__init__.py:19,34). 데이터 매니페스트도 이 이름을 쓴다(VISOR-serve scripts/data-manifest.yml:91). 기준은 코드다.

레거시에서 여전히 참인 것: 독립된 타깃, 장면에 적용되는 것 없음

타깃은 모두 같은 행에 대한 별개의 model.predict이므로(pipeline.py:216-247), 하나의 강체 분절에 속한 점들의 예측 변위가 서로 일치하도록 제약되지 않는다(레거시 페이지, 함정). 출력은 표 두 개뿐이다. 변환도, Slicer 노드도 없으며, 패널은 아무것도 불러오지 않고 압축 파일을 저장한다(RESULT_KIND = "save_as", Remote SurgMovPredRemote.py:46). 코드에서 읽은 것이다.

건너뛴 타깃은 서버 로그에서만 보인다

특징이 표에 없는 패키지는 logger.warning과 함께 건너뛰어지고, 예측에 실패한 타깃은 logger.exception으로 남는다(pipeline.py:234-236,249-250). 실행은 열이 줄어든 채로 성공한다. 보고서 파일이 없으므로, 사용자는 열을 세어 보아야 빠진 타깃을 알 수 있다. 유일한 안전장치는 전부 아니면 전무인 경우다(:252-264). 코드에서 읽은 것이다.

확인됨: 재현 가능한 순서, 조용한 빈 결과 없음

패키지와 표가 정렬되므로 같은 입력으로 두 번 실행하면 행과 열이 같은 순서로 나온다(pipeline.py:143-147,173). 예측하는 모델이 하나도 없는 실행은 빈 표 두 개가 아니라 오류다(:252-264). 잘못된 열 이름은 가려진 특징이 아니라 오류다(:51-60). 코드에서 읽은 것이다.

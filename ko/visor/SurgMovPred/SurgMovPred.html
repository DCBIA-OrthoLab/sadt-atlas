VISOR의 SurgMovPred

SurgMovPred는 측정값 표와 수술 계획으로부터 28개 랜드마크 점의 수술 후 이동량을 예측한다. 이 페이지는 수식과 함께 방법을 단계별로 설명한다. 무엇이 들어가고, 각 단계가 그것을 어떻게 바꾸며, 무엇이 나오는지를 다룬다. 파일, 줄, 인자, 발견 사항은 코드 페이지에 있다. 레거시 Slicer 모듈은 별도 페이지에 있다.

코드(개발자용) VISOR 회귀기 112개 CPU 전용 레거시 페이지 가이드 (VISOR)

파일 이름, 줄 번호, 모든 발견 사항은 코드 페이지에 있다. 여기서 언급하는 저장소는 6ba2a78 시점의 SADT-VISOR 도구 카탈로그, e9a7e5d 시점의 VISOR-serve, 19b95e8 시점의 Slicer 클라이언트 AutomatedDentalToolsRemote, 3c67957 시점의 레거시 모듈 SlicerAutomatedDentalTools이다. 모두 코드에서 읽은 것이며, 이 페이지를 위해 실행한 것은 없다.

개요: 무엇이 들어가고 무엇이 나오는가

SurgMovPred는 악교정 수술에서 뼈가 얼마나 움직일지를 예측한다. 환자 한 명당 한 행으로 이루어진 표(수술 전 두부 계측 측정값과 계획된 이동량)를 읽고, 수술 후 이동량 예측값의 표를 반환한다. 28개 랜드마크 점에 각각 값이 네 개씩이다. 스캔이나 메시는 읽지 않으며 Slicer에서는 아무것도 바꾸지 않는다.

VISOR의 SurgMovPred
입력측정값과 계획이 담긴 CSV, XLSX, ODS 표 하나, 또는 그런 표들이 든 평평한 폴더
방법학습된 모델 112개, 타깃당 하나. 각 모델은 145개 입력을 다시 스케일하고 회귀기 세 개의 스택으로 예측한다
출력내용이 같은 표 두 개, predictions_outputs.xlsx와 .csv: 환자 식별자, 그다음 예측된 타깃당 한 열
위치서버에서, 프로세서만으로. Slicer 패널은 표를 업로드하고 결과 두 개를 저장한다

알고리즘은 레거시와 같고 바뀐 것이 없다. 바뀐 것은 순서, 오류 처리, 환경이다(바뀐 점).

1. 체인에서의 위치

SurgMovPred는 말단이다. 다른 도구를 호출하지도, 다른 도구가 이를 호출하지도 않으며, 레거시 모듈과 같다. Slicer 패널은 서버가 제공하는 도구 설명으로 생성되는 얇은 클라이언트다. 도구는 Surg_Mov_Pred라는 이름으로 패키징되었으며 서버는 예전 철자도 받아들인다. 저장소에 자동화 테스트가 있고, README는 출력이 이전 서버 구현과 환자 101명, 모델 112개에서 일치했다고 보고한다(읽은 것이며, 이 페이지를 위해 다시 실행하지는 않았다).

코드에서API 이름, 도구 폴더, 서버 선언, 출처, 테스트 수

1.1 무엇이 어디서 실행되는가

서버가 전부 한다. 표 읽기, 열 이름 정리, 프로세서에서 모델 112개 실행, 표 두 개 쓰기. 패널에는 측정값이라는 필드가 하나뿐이며, 표를 업로드하고(폴더는 보낼 때 압축한다) 돌려받은 압축 파일을 사용자가 고른 파일 옆에 저장한다. Slicer 장면에는 아무것도 불러오지 않는다.

코드에서서버와 클라이언트의 역할, 그리고 그것을 결정하는 줄

2. 관련 파일

도구는 작은 Python 파일 두 개(실행 함수와 파이프라인), model 인자를 숨기고 필드 이름을 바꾸는 레이아웃 파일, 환경 정의, 테스트로 이루어진다. 레거시 모듈은 878줄짜리 패널에 323줄짜리 명령줄 스크립트였다.

코드에서줄 수가 적힌 파일 표

3. 파이프라인

실행 한 번에 도구는 모델 파일을 모두 불러오고 표를 읽는다. 그다음 타깃 112개를 차례로 돌며 그 모델이 필요로 하는 열을 찾고, 스케일하고, 예측하고, 결과를 보관한다. 마지막에 표 하나를 조립한다. 상자를 클릭하면 해당 절을 읽을 수 있다.

코드에서다이어그램의 각 상자 뒤에 있는 함수

3.1 모델 패키지 불러오기

타깃마다 폴더가 하나씩 있고 그 안에 파일이 하나 있다. 이 패키지에는 네 가지가 들어 있다. 타깃의 이름, 그 모델이 기대하는 145개 입력 열의 순서 있는 목록, 학습된 스케일러, 학습된 모델이다. 도구는 models 폴더 아래에서 찾은 패키지를 모두 정렬된 순서로 불러오므로 결과의 열은 매번 같은 순서로 나온다. 읽을 수 없는 패키지는 로그에 남기고 건너뛰며, 하나도 불러오지 못하면 실행이 멈춘다. 패키지 112개는 모두 같은 145개 열을 기대한다. 그중 28개는 _T0(수술 전 상태)로, 25개는 _Total(계획된 총 이동량)로 끝나며, 그래서 표에는 측정값뿐 아니라 계획도 들어 있어야 한다.

코드에서불러오기 루프, 패키지 키, LightGBM 요구 사항, 꺼 둔 버전 경고

3.2 측정값 읽기

파일은 확장자(CSV, XLSX, ODS)에 따라 읽는다. 폴더는 재귀적으로 탐색하지 않으며, 그 안의 표는 정렬되어 위아래로 쌓인다. 환자 식별자 열은 흔한 이름(#, id, patient id 등)의 목록을 차례로 시도해 찾으며, 없으면 출력의 식별자 열은 경고와 함께 비워 둔다. 열 이름은 모델을 학습할 때 쓴 철자로 정리된다. 따옴표와 괄호는 제거되고, 글자, 숫자, 밑줄, 아포스트로피가 아닌 것은 밑줄이 되며, 숫자로 시작하는 이름에는 접두사가 붙는다. 정리할 수 없는 이름은 오류다.

코드에서읽기 코드, 식별자 패턴 여덟 개, 정리 규칙과 줄 번호

3.3 패키지당 타깃 하나

도구는 패키지마다 필요한 열을 표에서 하나씩 찾는다. 허용되는 것은 _T0 접미사가 없는 경우뿐이다. X_T0를 요구하는 모델은 X라는 열을 받아들인다. 그 밖의 열이 하나라도 없으면 경고와 함께 그 타깃이 출력에서 빠진다. 빈 셀은 채워지지 않는다. 모델이 이를 거부하고, 오류가 로그에 남으며, 그 타깃은 모든 환자에서 제외된다. 열은 모델이 기대하는 순서로 정렬되고, 스케일되어 모델에 전달된다.

타깃 하나를 예측하다 실패하면 로그에 남기고 루프는 계속된다. 예측된 타깃이 하나도 없을 때만, 예측 없는 표를 쓰는 대신 오류로 실행이 멈춘다.

코드에서특징 확인, 건너뛰기 규칙, 오류 사례가 있는 루프

3.4 출력

예측값은 환자 식별자를 첫 데이터 열로 하는 표 하나가 되어, Excel과 CSV로 두 번 기록된다. 둘 다 행 번호를 매긴 이름 없는 열로 시작하므로 열 위치를 읽을 때 유의해야 한다. 두 파일 모두 클라이언트에 돌려주며, 보고서 파일은 없다.

코드에서파일 두 개, 열 구성, 반환값

4. 선택할 수 있는 것

  • 측정값: 표 하나, 또는 표들이 든 평평한 폴더. 패널에 표시되는 유일한 필드다.
  • 제공하지 않음: 모델(서버 자체의 세트를 쓴다), 출력 폴더(서버가 정한다), 타깃이나 임계값에 대한 모든 옵션. 112개 타깃은 항상 모두 시도된다.
코드에서인자 표, 출력 형식, 서버가 자원에 대해 선언하는 것

6. 환경

도구는 서버에 자체 Python 환경이 있고(Python 3.12에 numpy, pandas, scikit-learn, LightGBM, 스프레드시트 리더의 버전이 고정되어 있다) 그래픽 카드 소프트웨어는 전혀 없다. 모델은 약 740 MB(706 MiB)의 압축 파일 하나로 서버에 준비되어 있다. 실행 시점에 설치하는 것은 없다.

코드에서줄 번호가 적힌 고정 버전, 모델 압축 파일, 소요 시간 주석

7. 레거시 로직에서 달라진 점

  • 도구는 Apply마다 패키지를 설치하는 Slicer의 Python 안이 아니라, 서버의 자체 환경에서 실행된다.
  • 입력은 파일 하나 또는 평평한 폴더가 될 수 있다. 레거시는 폴더만 받았고, 폴더 읽기에는 안정된 순서가 없었다.
  • 모델과 표를 정렬된 순서로 읽으므로 두 번 실행하면 행과 열이 같은 순서로 나온다.
  • 정리할 수 없는 열 이름은 열 두 개가 충돌하게 만들던 공용 자리 표시 이름 대신 오류가 된다.
  • 예측하는 모델이 없는 실행은 예측 없는 표 두 개 대신 오류가 된다.
  • 출력 파일 두 개를 모두 반환하며, 리더가 설치되어 있으므로 ODS 파일도 읽을 수 있다.
코드에서줄 번호가 적힌 레거시와 VISOR 비교 표

8. 알려진 문제

  • 두 결과 파일 모두 이름 없는 인덱스 열로 시작한다. 해당 발견 사항을 참고하라.
  • 클라이언트의 일부 주석은 출력 파일이 하나라고 설명한다. 해당 발견 사항을 참고하라.
  • 도구 README가 낡은 데이터 폴더 이름을 적고 있다. 해당 발견 사항을 참고하라.
  • 타깃은 독립적으로 예측되므로 한 뼈 분절에 속한 점들의 이동량이 서로 일치할 필요가 없고, 장면에 적용되는 것도 없다. 해당 발견 사항을 참고하라.
  • 건너뛴 타깃은 서버 로그에서만 보인다. 해당 발견 사항을 참고하라.
  • 긍정적인 면으로, 순서는 재현 가능하고 빈 결과는 더 이상 조용히 넘어가지 않는다. 해당 점검을 참고하라.
코드에서근거가 붙은 콜아웃 여섯 개

9. 문헌

방법과 그 출판물은 무엇이 실행하든 도구의 것이다. SurgMovPred 출처 페이지를 참고하라. VISOR는 새 모델을 추가하지 않는다.

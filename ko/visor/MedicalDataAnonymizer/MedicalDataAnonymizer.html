MedicalDataAnonymizer: VISOR에 이식되지 않음

서버 쪽 Medical Data Anonymizer는 없다. VISOR 클라이언트 확장은 Slicer 안에서 텍스트 문서에 대해 실행되는 레거시 모듈의 오래된 사본을 포함하며, 이 사본은 VISOR가 업로드하는 파일을 비식별화하지 않는다. 모듈 자체는 레거시 페이지에 설명되어 있다.

VISOR: 로컬 사본만 레거시 페이지 가이드 (VISOR)

기준 커밋의 상태: SADT-VISOR 6ba2a78, VISOR-serve e9a7e5d, AutomatedDentalToolsRemote 19b95e8. 레거시는 3c67957 시점의 SlicerAutomatedDentalTools다. 아래의 MDA-Remote는 AutomatedDentalToolsRemote Medical_Data_Anonymizer_ModuleRemote/Medical_Data_Anonymizer_ModuleRemote.py를 뜻한다. 모든 내용은 코드에서 읽은 것이며, 실행한 것은 없다.

계층별로 존재하는 것

계층존재 여부근거
서버 도구아니오SADT-VISOR tools/ 아래에 폴더가 없고, VISOR-serve scripts/data-manifest.yml에 항목이 없으며, server/deployment.toml에 섹션이 없다
클라이언트 모듈예, 빌드됨, 로컬MDA-Remote(768줄), AutomatedDentalToolsRemote CMakeLists.txt:37이 추가. 서버를 호출하는 패널의 기반 클래스인 ServerToolWidgetBase를 상속하지 않는다
계산하는 곳Slicer에서클라이언트 README는 이를 "run on this machine and send nothing" 모듈 중 하나로 나열한다(README.md:28-30)
읽는 것텍스트 문서만DOCX, PDF, TXT, CSV, XML, ODT(README.md:215). 영상도 DICOM 헤더도 없음

무엇이 어디서 실행되는가

모든 작업이 레거시 모듈과 마찬가지로 Slicer 프로세스 안에서 실행된다. install_dependencies가 presidio-analyzer, presidio-anonymizer, pandas, python-docx, pdfplumber, odfpy, lxml, langdetect, reportlab을 Slicer의 Python에 pip로 설치한 다음, spaCy 모델 en_core_web_lg를 내려받는다(MDA-Remote:392-441). 서버로 보내는 것도, 호스팅하는 것도 없다.

사본이 레거시 모듈과 다른 점

배포된 사본은 모듈의 이전 리비전이며 포팅한 것이 아니다. 3c67957 시점의 레거시 파일(Medical_Data_Anonymizer_Module/Medical_Data_Anonymizer_Module.py)이 774줄인 데 비해 768줄이다. 그 뒤 레거시 파일은 로컬 로거 대신 ADTLib.logging_setup을 쓰도록 바뀌었고, 위젯에 별도의 Logic 객체가 주어졌으며, 변수 이름도 바뀌었다. 사본의 모듈 카테고리는 "Automated Dental Tools" 대신 "Automated Dental Tools Remote"이다(MDA-Remote:41). 탐지 로직은 둘 다 같다. 고정된 언어, 매핑 파일, 조용한 실패에 대한 레거시 페이지의 발견은 사본에도 이 줄들에서 그대로 적용된다.

동작사본(MDA-Remote)레거시(3c67957)
언어는 영어로 고정되며, langdetect는 설치되지만 쓰이지 않는다(레거시 페이지 3절):716, :405:724, :413
file_mappings.csv가 문서 옆에 기록된다(레거시 페이지 5절):500, :649-670:508, :656-677
Presidio 오류가 나면 원본 텍스트가 그대로 반환되고, 패널은 그래도 "Complete!"라고 표시한다(레거시 페이지 7절):750-751, :673:758-759, :680
VISOR가 업로드하는 데이터의 비식별화가 아니다

이 모듈은 사용자가 지정한 텍스트 문서를 익명화한다. 다른 어떤 패널의 업로드 경로에도 놓여 있지 않으며, ServerToolsCore, SlicerCloud, ServerToolsSettings의 어떤 코드에도 Presidio나 익명화에 대한 언급이 없다. 클라이언트 README는 현재 클라이언트에 비식별화가 없다고 밝히며, 파일은 "디스크에 있는 그대로, 파일 이름과 DICOM 헤더와 그 안의 모든 식별자와 함께" 스트리밍된다고 적고 있다(README.md:32-35). 클라이언트도 원격 서버마다 한 번씩 같은 경고 "Files are uploaded unmodified"를 보여 준다(ServerToolsCore/ServerToolsCoreLib/settings_qt.py:101-127). 업로드를 비식별화할 파이프라인은 명세만 있고 구현되지 않았다. 어떤 모듈이든 업로드 데이터의 보호 장치로 여기기 전에 VISOR의 비식별화를 읽어 보라.

VISOR로 AutoCrop3D 사용하기

3D Slicer에서 VISOR 서버를 통해 AutoCrop3D를 실행할 때 달라지는 점을 다룬다. 무엇을 제공해야 하는지, 무엇이 같은지, 무엇이 다른지다. 레거시 모듈은 별도의 페이지가 있다.

VISOR 레거시 페이지 아틀라스 (VISOR)

VISOR 서버를 거치면 모듈 이름은 AutoCrop3D Remote다. 상자는 여전히 Slicer에서 그리며, 파일은 서버로 전송되어 그곳에서 잘리고, 결과는 사용자가 고른 폴더로 돌아온다. 패널은 서버가 게시하는 내용으로 구성되며 입력, 옵션, 출력의 세 그룹이다. 사용자의 컴퓨터에는 아무것도 설치되거나 내려받아지지 않으며, 자르기에는 모델이 필요 없다.

제공해야 하는 것

  • 스캔: 볼륨 하나 또는 폴더 하나(.nii.gz, .nii, .nrrd, .gipl.gz, .gipl)가 서버로 업로드된다. .nrrd.gz는 메시지와 함께 거부된다. 먼저 .nrrd로 압축을 풀어야 한다. 서버는 테스트 파일도 호스팅할 수 있으며, 그러면 드롭다운이 MG_test_scan.nii.gz를 제안한다. 기본 업로드 한도는 500 MB이며, AutoCrop3D는 환자별로 나눌 수 없으므로 폴더는 단일 요청으로 올라간다.
  • 관심 영역: 그린 ROI를 장면에서 바로 고르거나(ROI 행에는 장면의 ROI 노드가 나열된다), .mrk.json 파일 또는 그 폴더를 지정한다. 호스팅된 테스트 상자의 이름은 ROI_box다.
  • 옵션: 원본 크기 유지, 메시 생성 여부(surfaces), 밀리미터 단위의 메시 여유, 메시 스무딩, 출력 접미사(기본값 cropped). 그런 다음 출력 폴더를 고른다.

달라지지 않는 점

  • 자르기는 같은 산술이다. 상자는 원본 격자의 복셀 인덱스로 매핑되고 블록이 추출되며, 리샘플링은 없다. 이식 버전은 0 방향 절사까지도 의도적으로 그대로 유지한다.
  • 모두에게 하나의 ROI를 쓰거나, 이름으로 짝지은 환자별 ROI를 쓴다. 출력 파일은 입력 폴더 구조를 유지한다.
  • 결과는 사용자가 고른 출력 폴더에 풀리며, 최대 12개가 장면에 불러와져 CT-AAA 볼륨 렌더링 프리셋으로 표시된다.

달라지는 점

  • "Crop Volume for tilted images"는 없다. 회전된 ROI는 축 정렬 상자로 잘리며 보고서에 roi_orientation_ignored가 실린다.
  • RAS로 저장된 ROI는 이해된다. 파일에 선언된 좌표계를 읽는다.
  • 이름 실수는 이름이 밝혀진다. 패널은 "N of M scan(s) cropped. No ROI for: …"와 같은 줄로 끝난다. 실행 보고서도 같은 스캔을 나열한다.
  • 볼륨을 벗어난 상자는 오류다(ROI가 이 볼륨과 겹치지 않는다). 일부만 겹치는 상자는 잘리고 clamped_to_the_volume으로 표시된다.
  • 이전 결과는 다시 잘리지 않는다. 스캔 폴더에 이전 실행의 _cropped(또는 사용자의 접미사)로 끝나는 파일도 있으면 그 파일들은 제외된다.
  • 스캔별 진행 상황이 없다. 도구는 실행 중에 진행 상황을 보고하지 않는다. 결과와 함께 풀리는 실행 보고서 AutoCrop3D_report.json이 스캔마다 소요 시간과 결과를 알려 준다.
메시에는 분할 같은 파일 이름이 필요하다

기본값 surfaces = segmentations에서는 P1_Seg.nii.gz라는 파일은 메시가 만들어지고 Mandible.nii.gz라는 파일은 만들어지지 않는다(2026-11-09에 이식 버전 자체의 규칙에 대해 확인함). 폴더 이름은 고려되지 않는다. 파일 이름을 바꾸거나 surfaces를 all로 설정한다. 메시는 스캔 자체의 공간에 놓이므로 Slicer에서 잘린 스캔 위에 겹쳐 놓인다.

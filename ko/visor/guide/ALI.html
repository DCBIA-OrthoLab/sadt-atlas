VISOR로 ALI 사용하기

3D Slicer에서 VISOR 서버를 통해 ALI를 실행할 때 달라지는 점을 다룬다. 무엇을 제공해야 하는지, 무엇이 같은지, 무엇이 다른지다. 레거시 모듈은 별도의 페이지가 있다.

VISOR 레거시 페이지 아틀라스 (VISOR)

VISOR 서버를 거치면 분석은 사용자의 컴퓨터가 아니라 서버에서 실행된다. Slicer의 모듈 이름은 ALIRemote다. 스캔을 서버로 보내고 landmark 파일을 가져오는 패널이다. 연결하는 방법과 서버가 데이터로 무엇을 하는지는 VISOR 사용하기에 있으며, 이 페이지는 레거시 모듈과 비교해 ALI에서 달라지는 점만 다룬다. 이 페이지는 실제 서버에서의 세션이 아니라 서버와 패널의 코드를 바탕으로 작성되었다. 코드 참조를 포함한 자세한 내용은 VISOR에서의 ALI에 있다.

패널에서 달라지는 점

  • 창 하나, 맨 위에서 고른다. 첫 필드는 모드이며 CBCT 또는 IOS다. 레거시 창의 데이터 유형 역할을 한다. 이어지는 점 목록은 이에 따라 바뀐다(CBCT는 119점, 구강 내 스캔은 153점).
  • 내려받을 모델이 없다. 학습된 가중치는 서버에 보관된다. 모델, 장치, 탐색 설정은 패널에 표시되지 않는다.
  • 입력. 파일 하나 또는 폴더 하나. 폴더는 알아서 zip으로 묶여 전송된다. 패널은 서버가 호스팅하는 테스트 파일도 제안할 수 있다.
  • 점은 탭에서 고르며, 그룹마다 탭이 하나다. 아무것도 선택하지 않으면 CBCT 실행은 119점을 모두 배치한다.
  • 결과는 아카이브로 돌아온다. 패널이 이를 풀어 사용자가 고른 폴더에 저장하고, "예측된 landmark를 장면에 불러오기" 상자가 선택되어 있으면(기본값) Slicer에 파일을 불러온다.

달라지지 않는 점

landmark 이름, 두 가지 작업 방식(에이전트가 훑는 볼륨, 여러 방향에서 촬영한 표면), .mrk.json 형식, 그리고 건드리지 않고 그대로 두는 원본 파일. 점은 레거시 파일처럼 여전히 잠긴 채로 도착한다. 점을 옮기기 전에 Markups 모듈에서 잠금을 해제한다.

파일과 결과에서 달라지는 점

  • 스캔마다 파일 하나에 모든 그룹이 함께 들어 있으며 이름은 <scan>_lm_Pred.mrk.json이다. 레거시 모듈은 그룹마다(CBCT) 또는 턱마다, 네트워크마다(IOS) 파일 하나를 썼다. 입력의 폴더 구조는 결과에 그대로 재현된다.
  • 보고서가 함께 온다. run_report.json이 스캔별로 배치된 점과 수렴하지 못한 점을 나열한다.
  • 지원되는 구강 내 형식은 .vtk와 .stl이다. 치아 번호가 이미 붙은 메시를 먼저 처리하고, 번호가 없는 메시는 서버의 크라운 분할(Crown_Seg)을 거친 뒤 이어서 처리된다.
  • landmark 파일은 불러오면 보인다. 레거시 파일은 표시가 꺼진 채로 기록되어서 직접 열면 아무것도 보이지 않았다. 서버의 파일은 보이는 상태로 기록된다.
  • 구강 내 결과는 레거시와 동일하지 않다. 개발자들이 비교한 메시에서는 73점 중 54점이 정확히 같았고 나머지는 올바른 치아 위에 놓였다(VISOR README, SADT-VISOR tools/ALI/README.md:213-226). 점막치은 경계(mucogingival) 점은 최신 레거시 모듈보다 보정 단계를 적게 거친다.
  • DICOM. 서버가 DICOM 시리즈를 직접 변환하며, 사용자의 폴더에는 아무것도 기록되지 않는다.
  • 시간. 서버는 RTX 6000 Ada 카드에서 에이전트 8개를 동시에 돌려 스캔 하나의 landmark 119개에 128 s가 걸렸다고 기록한다(서버 설정에 적힌 측정값이며 여기서 다시 실행하지 않았다). 서버의 기본 설정은 실행에 시간 제한을 두지 않는다.
실행 종료 메시지가 "0 scan(s), 0 landmark(s) written"이라고 한다

무슨 일이 있었든 그렇게 나온다. 패널은 서버가 더 이상 쓰지 않는 이름으로 스캔 목록을 찾는다(AutomatedDentalToolsRemote 19b95e8의 ALIRemote.py:216이며, 서버 보고서에서는 cases다). 대신 불러온 파일과 결과 폴더의 run_report.json을 읽는다. 실패는 그곳에 나열되어 있고, 패널 메시지는 이를 결코 나열하지 않는다.

DICOM 시리즈 하나만 든 폴더를 고를 때

DICOM 시리즈가 정확히 하나 들어 있는 폴더를 지정하면 결과 파일 이름이 숨김 파일인 ._lm_Pred.mrk.json이 되어 일반 파일 목록에 보이지 않는다. 시리즈를 선택한 폴더의 하위 폴더에 넣거나, 숨김 파일을 표시한다. 원인은 코드에서 확인했고(이름을 짓는 두 함수를 실행했다), 실제 시리즈로 전체 실행을 다시 하지는 않았다.

다른 방향으로 저장된 CBCT

레거시 모듈은 탐색 전에 모든 CBCT를 표준 방향(LPS)으로 돌린다. 서버 버전은 그렇게 하지 않는다. 배치된 점에 미치는 영향은 측정되지 않았으므로, 특히 볼륨이 DICOM 내보내기에서 온 것이 아니라면 쓰기 전에 스캔 위에서 landmark를 확인한다.

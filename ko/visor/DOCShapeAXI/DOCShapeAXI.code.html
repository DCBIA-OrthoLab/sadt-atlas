VISOR의 DOCShapeAXI: 코드

개발자용: DOCShapeAXI의 VISOR 이식판이 코드에서 하는 일을 file:line 참조, 시그니처, 인자, 환경, 레거시 코드와의 차이, 발견 사항과 함께 다룬다. 같은 파이프라인에 대한 읽기 쉬운 설명과 수식은 아틀라스 페이지에 있다.

VISOR 코드 아틀라스 (해설) 레거시 페이지 가이드 (VISOR)

이 페이지의 참조는 저장소, 그 안의 경로, 줄 순서로 적는다. SADT-VISOR는 도구 카탈로그(커밋 6ba2a78), VISOR-serve는 서버(e9a7e5d), Remote는 Slicer 클라이언트(AutomatedDentalToolsRemote 19b95e8), 레거시는 3c67957 시점의 SlicerAutomatedDentalTools다. catalog.py:50 같은 경로만 적힌 것은 SADT-VISOR의 tools/DOCShapeAXI/src/sadt_docshapeaxi/에 있다. 모든 내용은 코드에서 읽은 것이며, 이 페이지에서 실행한 것은 나오는 곳에 명시한 두 가지 검사(shapeaxi 1.0.10과 1.1.1의 파일 비교, 반복 인덱스에 대한 작은 CPU 테스트)뿐이다. 스택 개요: VISOR.

1. 체인에서의 위치

쉬운 설명과 수식: 아틀라스 페이지.

  • 상태: 이식 완료, 코드로 구현되었고 도구에 테스트가 있다(SADT-VISOR tools/DOCShapeAXI/tests/test_run.py, 테스트 함수 91개, 이 페이지를 위해 실행하지는 않음). VISOR-serve 준비 스크립트만으로 설정한 서버는 이를 실행할 수 없다. 필요한 EfficientNet 백본을 준비하는 스크립트가 하나도 없기 때문이다(VISOR의 발견 사항 참조).
  • API 이름 DOCShapeAXI(SADT-VISOR tools/DOCShapeAXI/pyproject.toml:57-59), 모듈 __init__.py, catalog.py, engine.py, pipeline.py.
  • 클라이언트 패널 DOCShapeAXIRemote, 얇은 패널이다(Remote DOCShapeAXIRemote/DOCShapeAXIRemote.py:63,67,69, 빌드됨, CMakeLists.txt:34). .vtk와 .vtp 결과를 모델로 불러오며, 최대 12개다(:82,88-92).
  • 호출함 / 호출됨: 없음. sup 인자가 없고(__init__.py:18-25), DOCShapeAXI를 이름으로 부르는 다른 도구도 없다.
  • 호스팅 데이터: 체크포인트 다섯 개가 데이터 매니페스트에 있다(VISOR-serve scripts/data-manifest.yml:597-614). 테스트 표면은 일부러 두지 않았다. 공개된 것 중에 기도, 하악과두, 구순구개열인 것이 없기 때문이다(:616-622). 매니페스트 머리말에는 여전히 "NOT PORTED YET"(:595)라고 적혀 있는데, 이는 틀렸다. 도구와 그 클라이언트가 존재한다.

3. 파이프라인

쉬운 설명과 수식: 아틀라스 페이지.

3.1 체크포인트 이름 하나가 분석을 정한다

쉬운 설명과 수식: 아틀라스 페이지.

레거시는 호출자에게 data_type, task, model, nn, num_classes를 별도의 위치 인자로 요구했으므로(레거시 DOCShapeAXI_CLI/DOCShapeAXI_CLI.py:299-307), 2클래스 체크포인트를 4클래스 척도로 실행할 수 있었다. VISOR는 인자 하나 model만 받고, 그 기본 이름을 테이블에서 찾는다(catalog.py:50-71, __init__.py:54). 알 수 없는 이름은 알려진 다섯 개를 나열하는 ValueError가 된다(catalog.py:74-88). 조회는 파일의 존재를 확인하기 전에 이루어진다(__init__.py:54-57).

파일 이름해부학 부위작업클래스신경망
airways_2_class.ckpt비인두 기도 폐쇄binary2SaxiMHAFBClassification
airways_4_class.ckpt비인두 기도 폐쇄severity4SaxiMHAFBClassification
airways_4_regress.ckpt비인두 기도 폐쇄regression1SaxiMHAFBRegression
condyles_4_class.ckpt하악과두severity4SaxiMHAFBClassification
cleft_4_class.ckpt구개열의 치조골 결손severity4SaxiMHAFBClassification

테이블은 준비된 파일 이름을 키로 삼는다. cleft_4_class.ckpt이며, 레거시 패널의 조회는 clefts_4_class를 반환했다(catalog.py:44-49의 주석, 레거시 페이지 모델).

3.2 표면, 장치, 네트워크

쉬운 설명과 수식: 아틀라스 페이지.

  • 탐색: 단일 .vtk 하나, 또는 재귀적으로 훑는 폴더이며, 숨김 파일은 건너뛰고 정렬한다(pipeline.py:22,40-64). 아무것도 찾지 못하면 ValueError, "DOCShapeAXI reads surfaces, not volumes"가 된다(__init__.py:59-64). shapeaxi에 주는 마운트 지점은 입력 폴더이고, 단일 파일이면 그 파일이 있는 폴더다(:71).
  • 장치: 보이는 카드가 없으면 cuda는 경고와 함께 cpu로 대체된다(pipeline.py:67-72).
  • 네트워크: load_network는 카탈로그가 지정한 클래스가 shapeaxi.saxi_nets_lightning에 있는지 확인하고, 이어서 EfficientNet 백본이 준비되어 있는지 확인한 다음, 체크포인트가 pickle하는 클래스를 허용 목록에 올리고 불러온다(pipeline.py:130-151).
network_class = getattr(saxi_nets_lightning, network_name, None)   # else ValueError
check_backbone_is_staged()      # <torch hub dir>/checkpoints/efficientnet-b0-355c32eb.pth, else FileNotFoundError
allow_checkpoint_globals()      # shapeaxi transform classes + torchvision Compose
model = network_class.load_from_checkpoint(checkpoint, strict=False)
model.eval(); model.to(device)

허용 목록이 있는 이유는 torch 2.6이 weights_only=True를 기본값으로 삼았고, 이 체크포인트들이 학습 변환을 hyper_parameters에 담고 있기 때문이다(pipeline.py:108-127). strict=False는 레거시에서 그대로 유지했다(레거시 DOCShapeAXI_CLI.py:135,201).

3.3 예측 패스

쉬운 설명과 수식: 아틀라스 페이지.

파일 목록은 메모리에 만든 pandas DataFrame이며(레거시는 출력 폴더에 모드 'a'로 CSV를 썼다, DOCShapeAXI_CLI.py:111-118), shapeaxi의 SaxiDataset에 EvalTransform(scale_factor)와 함께 입력된다. 스케일 인자는 체크포인트의 하이퍼파라미터에서 읽지만(engine.py:11-34), shapeaxi 1.1.1은 이를 무시한다(아래 확인 참조). 그다음 표면을 하나씩 처리한다(engine.py:37-64).

mesh = model.create_mesh(vertices, faces, normals)
points = model.sample_points_from_meshes(mesh, model.hparams.sample_levels[0])
views, _ = model.render(mesh)
output = model(points, views)
if not analysis.is_regression:
    output = torch.argmax(softmax(output).detach(), dim=1, keepdim=True)
predictions.append(float(output.reshape(-1)[0].cpu()))

각 예측은 마운트 지점에 대한 표면의 상대 경로와 class(정수) 또는 score(실수, 회귀) 중 하나와 함께 기록된다(__init__.py:81-90). 점 샘플링과 렌더링은 shapeaxi의 것이며, 도구도 레거시도 난수 시드를 고정하지 않는다(도구 소스에 seed나 manual_seed가 없다).

3.4 설명 패스 (Grad-CAM)

쉬운 설명과 수식: 아틀라스 페이지.

explain이 true일 때만 실행된다(__init__.py:92-95). 데이터셋을 다시 만들고 각 표면을 다시 렌더링한 뒤, 각 클래스 k(range(analysis.classes))에 대해 다음을 한다(engine.py:67-114).

cam = LayerGradCam(model, model.convnet.module._blocks[-1], device_ids=[0])
attribution = cam.attribute(inputs=(points, views), target=k, attr_dim_summation=False)
attribution = attribution.sum(dim=1).cpu().detach()
scaled = scale_attribution(attribution.numpy(), (224, 224))   # resize, clip 1/99 percentiles, rescale to [-1, 1]
projected = gradcam_process(_Namespace(device, target_class=k), scaled, faces, per_face, vertices)
surface.GetPointData().AddArray(projected)                    # array grad_cam_target_class_<k>
post_process.MedianFilter(surface, projected)
  • 리사이즈: torch.nn.functional.interpolate, 쌍선형, align_corners=False를 쓰며, 레거시의 cv2.resize를 대신한다. 주석에 따르면 테스트가 두 결과를 1e-5까지 맞춰 고정한다(pipeline.py:163-184, pyproject.toml:45-51).
  • 정규화: 1번째와 99번째 백분위수로 클립한 다음 [-1, 1]로 매핑한다. 평평한 맵은 NaN이 아니라 0이 된다(pipeline.py:186-199).
  • 어느 층인가: 레거시와 같이 2D EfficientNet 갈래의 마지막 블록이다(DOCShapeAXI_CLI.py:150-151). 이 맵은 다중 뷰 갈래를 설명하며, 포인트 클라우드 갈래는 설명하지 않는다.
  • 투영: gradcam_process는 shapeaxi의 것이다(1.0.10과 1.1.1의 saxi_gradcam.py:112-144, 같은 코드). 면은 0에서 시작하여 뷰를 거듭할 때마다 maximum(old, new)를 취하므로, 메시에서 한 면은 max(0, max over views)를 가지며 범위는 [0, 1]이다. 값은 면의 첫 번째 정점으로 가고, 누구의 첫 번째 정점도 아닌 정점은 0으로 초기화된다(:134). 하나의 뷰 안에서 같은 면을 보여 주는 픽셀들은 인덱스를 공유하며, 남는 기록이 무엇인지는 정해져 있지 않다(CPU에서는 마지막 것이고, 최댓값이 아니다). 배경 픽셀은 인덱스 -1을 가지며 마지막 면에 기록된다. CPU 테스트와 세부 사항은 레거시 코드 페이지의 5d절에 있으며, GPU에서는 아무것도 실행하지 않았다.
  • 중앙값 필터: post_process.MedianFilter(post_process.py:294-308)는 채워진 정점이든 빈 정점이든 모든 정점을, 자기 자신을 제외한 이웃의 중앙값으로 바꾼다(utils.py:363-376). 빈 정점만 바꾸는 것이 아니다.
  • 배열 이름: 클래스 인덱스는 항상 target_class로 전달되며, 이것이 배열의 이름이 된다(engine.py:104-106,117-129). 레거시는 num_classes > 1일 때만 이를 설정했으므로(DOCShapeAXI_CLI.py:171-174), 회귀 체크포인트도 이제 클래스별 이름 grad_cam_target_class_0을 받는다. 코드에서 읽은 내용이다.
  • 기록: 모든 클래스를 거친 뒤 표면마다 한 번, 입력의 기본 이름으로 output_dir에 평평하게 기록한다(engine.py:111-113). 레거시는 클래스 루프 안에서 <out>/explainability/<task>/에 기록했다(DOCShapeAXI_CLI.py:153,185-186).

3.5 출력과 보고서

쉬운 설명과 수식: 아틀라스 페이지.

기록된 표면은 확장자 앞에 output_suffix를 붙여 이름이 바뀌므로(__init__.py:118-133), P01.vtk는 P01_pred.vtk가 된다. DOCShapeAXI_report.json은 항상 기록된다(:97-110).

{
  "model": "condyles_4_class.ckpt", "anatomy": "Mandibular condyle", "task": "severity",
  "classes": 4, "network": "SaxiMHAFBClassification", "device": "cuda",
  "explained": true, "surfaces": 2,
  "predictions": [ {"surface": "left/P01.vtk", "class": 2},
                   {"surface": "right/P01.vtk", "class": 0} ]
}

값은 예시이고, 키는 코드의 것이다. 이 예시는 발견 사항에 나오는 충돌의 예이기도 하다. 두 표면이 모두 같은 output_dir/P01.vtk에 기록되게 된다. run()은 {"outputs": {...}, "predictions": [...], "report": path}를 반환하는데, 주석은 -> Path로 되어 있다(__init__.py:25,112-115). CSV는 없다.

4. 인자와 스키마

쉬운 설명과 수식: 아틀라스 페이지.

시그니처: SADT-VISOR tools/DOCShapeAXI/src/sadt_docshapeaxi/__init__.py:18-25. 게시된 형태는 도구에서 scripts/describe.py를 실행해 확인했으며, 인자는 여섯 개다. 이 도구에는 layout.py가 없다.

인자게시된 타입기본값사용자에게 표시됨의미
surfaces경로, 필수–예.vtk 하나, 또는 재귀적으로 탐색하는 폴더(pipeline.py:22,40-60)
model경로, 필수–예(호스팅된 이름)체크포인트. 파일 이름이 해부학 부위, 작업, 클래스 수, 네트워크를 정한다(catalog.py:50-71). 알 수 없는 이름은 알려진 이름을 나열하는 ValueError가 된다(:74-88)

8. VISOR의 발견 사항

쉬운 설명과 수식: 아틀라스 페이지.

EfficientNet 백본은 아무도 준비하지 않는 전제 조건이다

shapeaxi는 모든 체크포인트 둘레에 EfficientNet-B0을 만든다. 도구는 요청 도중에 이를 내려받는 것을 거부하고 FileNotFoundError를 발생시키며, 이를 피하려면 efficientnet-b0-355c32eb.pth가 <torch hub dir>/checkpoints/ 아래에 이미 있어야 한다(SADT-VISOR tools/DOCShapeAXI/src/sadt_docshapeaxi/pipeline.py:80-105, load_network가 :146에서 호출, README.md:112-121). 데이터 매니페스트도 VISOR-serve의 어떤 스크립트도 이 파일을 언급하지 않는다(세 저장소에서 "efficientnet"을 검색했고, 도구 자체의 README.md, pipeline.py, tests/test_run.py에만 나온다). 따라서 일반적인 준비 절차를 따르는 배포는 표면이 업로드된 뒤 첫 호출에서 실패한다. 코드에서 읽은 내용이며, 특정 서버의 캐시에 이 파일이 있는지는 확인하지 않았다.

상태 줄에 물음표가 표시된다

클라이언트는 report.get("data_type")과 report.get("checkpoint")로 요약을 만든다(Remote DOCShapeAXIRemote/DOCShapeAXIRemote.py:122-130). 도구가 쓰는 보고서에는 이 두 키가 모두 없고, model, anatomy, task, classes, network가 있다(SADT-VISOR __init__.py:97-110). 그래서 패널의 요약은 해부학 부위와 체크포인트 자리에 "?"로 읽히고, task와 표면 수는 채워진다. 코드에서 읽은 내용이며 Slicer에서 실행하지는 않았다.

클라이언트는 존재하지 않는 예측 테이블과 작업 선택기를 설명한다

클라이언트의 주석은 결과가 CSV 형태의 "prediction table"이라고 하고(DOCShapeAXIRemote.py:76-86), task 인자가 options_when 규칙을 통해 해부학 부위에 맞게 좁혀진다고 한다(:12-17). 도구는 CSV를 기록하지 않으며(__init__.py:97-110), 스키마에는 인자가 여섯 개 있고 그중 task라는 것은 없으며 options_when도 없다(scripts/describe.py의 출력). 작업은 체크포인트 파일을 고르는 것으로 정해지므로, 사용자는 airways_2_class.ckpt와 airways_4_regress.ckpt가 무엇을 뜻하는지 알아야 한다.

파일 이름이 같은 두 입력은 출력에서 충돌한다

표면은 재귀적으로 찾지만 평평하게 기록된다. a/s.vtk와 b/s.vtk는 모두 output_dir/s.vtk로 가므로(engine.py:111-112) 두 번째가 첫 번째를 대체하는데, 보고서는 상대 경로로 둘을 구분해 둔다(__init__.py:84). 그러면 이름 바꾸기 단계가 항목마다 한 번씩 s.vtk를 s_pred.vtk로 옮기는데(__init__.py:128-132), 두 번째 이동은 파일을 찾지 못하므로 모든 계산이 끝난 뒤 실행이 FileNotFoundError로 끝나게 된다. output_suffix가 비어 있으면 덮어쓰기는 조용히 일어난다. CLIC와 CNE는 바로 이를 피하려고 입력 트리를 그대로 재현한다. 코드에서 읽은 내용이며 실행하지는 않았다.

레거시에서 그대로인 것: 시드 없는 샘플링, 한 갈래만 보는 현저성

도구의 소스 어디에도 시드가 설정되어 있지 않고 seed 인자도 없으므로, shapeaxi 안의 무작위 점 샘플링(engine.py:54,92)은 레거시와 마찬가지로 실행마다 고정되지 않는다(레거시 페이지 함정). Grad-CAM 층은 2D 뷰 갈래의 마지막 블록이므로(engine.py:82-83), 맵은 포인트 클라우드 갈래에 대해서는 아무것도 말해 주지 않는다. 코드에서 읽은 내용이다.

핀과 맞지 않는 주석

captum 핀 위의 주석은 0.9.0을 말하지만 핀은 captum==0.8.0이다(pyproject.toml:39-44). 데이터 매니페스트는 여전히 도구에 "NOT PORTED YET"라는 라벨을 붙이고 있다(data-manifest.yml:595). 어느 쪽도 실행되는 것을 바꾸지 않는다.

확인됨: 레거시의 shapeaxi 불일치는 여기서 해결되었다

레거시 코드는 shapeaxi 1.x API에 맞춰 쓰였지만, 그 설치 프로그램은 2.0.2 이상을 요구한다(레거시 ADT/ADTLib/env/install_pytorch.py:385). VISOR는 shapeaxi==1.1.1로 고정하고 이유를 주석에 적었으며(pyproject.toml:18-30), 네트워크 클래스를 그것이 들어 있는 saxi_nets_lightning에서 가져온다(pipeline.py:135-145). 체크포인트는 더 이상 출력 폴더로 복사되지 않는다. shapeaxi 1.1.1의 EvalTransform도 scale_factor를 따르지 않는다. UnitSurfTransform.__call__이 이를 전달하지 않기 때문이다(saxi_transforms.py:48-57). 1.0.10과 1.1.1이 같다(두 패키지는 __about__.py만 다르며, 이번 확인을 위해 파일 하나하나 비교했고, 1.1.1은 패키지 인덱스에서 내려받았다).

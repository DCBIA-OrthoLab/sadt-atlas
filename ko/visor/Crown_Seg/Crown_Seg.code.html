VISOR의 Crown_Seg: 코드

개발자용: VISOR 도구 Crown_Seg가 코드에서 하는 일을 file:line 참조, 시그니처, 인수, 환경, 레거시와의 대응, 발견 사항과 함께 다룬다. 같은 파이프라인을 수식과 함께 읽기 쉽게 설명한 것은 아틀라스 페이지에 있다.

VISOR 전용 코드 아틀라스 (해설) SADT-VISOR 6ba2a78 VISOR-serve e9a7e5d Remote 19b95e8
레거시 모듈 없음

레거시 저장소(3c67957 시점의 SlicerAutomatedDentalTools)에는 Crown_Seg 모듈이 없고, 경로에 “crown”이나 “dentalmodelseg”가 들어간 파일도 없다(그 커밋에 대한 git ls-tree, 관찰됨). 있는 것은 별도의 SlicerDentalModelSeg 확장의 CrownSegmentationcli 모듈에 대한 호출과, ALI_IOS 명령줄 안에 있는 같은 호출의 작은 사본이다. 정확한 대응은 레거시 대응물에 있다. VISOR가 서버에서 도구를 실행하는 방식은 아키텍처에 설명되어 있다.

경로: SADT-VISOR cs/는 tools/Crown_Seg/src/sadt_crownseg/, ali_ios/는 tools/ALI/ALI_IOS/src/sadt_ali_ios/이며, VISOR-serve 경로는 server/로 시작하며, docs/나 scripts/를 명시하는 경우는 예외다. “Observed”는 이 페이지를 쓰는 동안 다시 실행해 본 것을 표시하며, 나머지는 모두 코드에서 읽은 것이다.

4. 파이프라인

쉬운 설명과 수식: 아틀라스 페이지.

4.1 엔진 주변에서 도구가 하는 일

쉬운 설명과 수식: 아틀라스 페이지.

  1. 체크포인트가 먼저: find_checkpoint는 .pth 파일, 또는 이름에 val-loss가 들어간 파일을 재귀적으로 찾는 폴더를 받아들이며, 없거나 둘이면 이를 이름으로 든 ToolInputError가 난다(cs/pipeline.py:186-262). model이 비어 있으면 <data_root>/Crown_Seg/models를 뜻한다(cs/__init__.py:18-29,104). 이것은 무엇이든 만들기 전에 일어난다(cs/pipeline.py:407-413).
  2. 탐색: .vtk 또는 .stl 하나, 또는 재귀적으로 훑어 정렬한 폴더. 아무것도 찾지 못하면 422다(cs/pipeline.py:292-320). 트리를 그대로 재현하는 데 쓰는 입력 루트는 폴더, 또는 파일 하나일 때는 그 부모다(:323-330).
  3. 분류: skip_segmented(기본값 true)이면 is_segmented가 각 메시를 열어 점 배열의 이름만 읽는다. PredictedID, UniversalID, Universal_ID, FDI_ID 중 하나라도 있으면 복사 분기로 보낸다(cs/pipeline.py:56,267-289,449-451).
  4. 복사 분기: 레이블이 붙은 각 메시는 .vtk polydata로 <output>/<relative folder>/<base>_<suffix>.vtk에 기록되며, .stl은 변환된다(cs/pipeline.py:480-487,594-613). 레이블은 건드리지 않는다.
  5. 분할 분기: 남은 경로는 .crownseg_work/crownseg_input.csv에 surf 헤더 아래로 들어가고, 장치는 cuda:0 또는 cpu로 결정되며(:170-178), shapeaxi는 이 namespace로 전체 목록에 대해 한 번 호출된다(cs/pipeline.py:336-366,508-531):
Namespace(surf=None, csv=csv_path, model=checkpoint, suffix=suffix, out=output_dir,
          num_workers=max(1, num_workers), crown_segmentation=0, array_name=array_name,
          fdi=1 if numbering == "FDI" else 0, overwrite=0, device=device,
          vtk_folder=input_root)
with contextlib.redirect_stdout(io.StringIO()):
    dental_model_seg.main(args)

호출 전에 _import_dental_model_seg가 shapeaxi를 지연 import하며, saxi_nets에 DentalModelSeg가 없으면(주석에 따르면 모든 2.0.x 릴리스에서) 그것을 saxi_nets_lightning.DentalModelSeg로 향하게 한다(cs/pipeline.py:105-167). import가 실패하면 실행은 복사 분기를 위해 계속되고 오류와 함께 engine_available: false를 기록하며(cs/pipeline.py:466-472), 신경망이 필요했던 메시는 출력이 없고 failed가 된다.

4.2 shapeaxi 내부

쉬운 설명과 수식: 아틀라스 페이지.

ShapeAXI 체크아웃 2b34042의 dental_model_seg.py에서 읽었다. 잠금 파일은 shapeaxi를 2.0.2로 결정하는데, 그 소스는 여기서 열어 보지 않았다. 아래에 인용한 줄은 열어 본 사본들(설치된 shapeaxi 1.0.10과 2.0.3, 그리고 uv 캐시의 1.1.1)에서 동일하다:

  • 신경망은 saxi_nets_lightning.DentalModelSeg(custom_model=args.model, device=device)이며, out_channels = 34다(:23,26).
  • 각 표면은 SaxiDataset을 통해 UnitSurfTransform(), 배치 크기 1, persistent_workers=True로 불러오며(:82-84), 그래서 num_workers는 최소 1이어야 한다.
  • 신경망은 뷰별 예측과 각 픽셀이 보여 주는 면을 돌려준다. 예측에 (PF >= 0)(픽셀이 면을 보여 주지 않으면 0)를 곱한 다음 softmax를 통과시키므로(:97), 면이 없는 픽셀은 건너뛰어지지 않고 균일한 1/34를 주며 이것이 면 표의 한 항목에 더해진다(:103-104). 면마다의 합과 arg-max(:106)가 면마다 레이블 하나를 주고, 각 면의 레이블은 그 첫 번째 꼭짓점에 부여된다(:107-108).
  • 후처리: 잇몸 레이블 33에 대해 임계값 500으로 RemoveIslands, 그다음 모든 레이블에 대해 200으로, 그다음 레이블마다 닫기(closing), 즉 DilateLabel 다음에 ErodeLabel을 각각 두 번 반복(:118-130).
  • ConvertFDI는 fdi == 1이면 실행된다(:52,225-236, 다음 절).
  • overwrite=0과 csv 입력에서는 결과가 <out>/<csv stem>_<suffix>/<input path without vtk_folder>_<suffix>.vtk로 간다(:154-176). Crown_Seg는 shapeaxi의 출력을 파싱하는 대신 이 경로를 다시 계산하며(cs/pipeline.py:369-381), 파일이 있으면 각 메시를 segmented로, 없으면 failed로 표시한다(:533-546).

4.3 치아 번호 체계: Universal과 FDI

쉬운 설명과 수식: 아틀라스 페이지.

신경망은 항상 Universal 번호를 예측한다. 치아는 1에서 32, 잇몸은 33이다. numbering = "FDI"이면 shapeaxi의 ConvertFDI가 모든 값을 하나의 룩업 테이블로 변환한다(ShapeAXI 2b34042 dental_model_seg.py:225-236):

LUT = [0, 18,17,16,15,14,13,12,11, 21,22,23,24,25,26,27,28,
          38,37,36,35,34,33,32,31, 41,42,43,44,45,46,47,48, 0]
labels = LUT[labels]          # index = Universal value, entry = FDI value
Universal 값FDI 값치아
1~818에서 11로 내려감오른쪽 위, 제3대구치에서 중절치까지
9~1621에서 28로 올라감왼쪽 위, 중절치에서 제3대구치까지
17~2438에서 31로 내려감왼쪽 아래, 제3대구치에서 중절치까지
25~3241에서 48로 올라감오른쪽 아래, 중절치에서 제3대구치까지

00–

shapeaxi는 변환된 정수를 같은 배열 이름으로 다시 기록한다(vtk_id.SetName(args.array_name), :233-235). 두 체계가 값의 범위 대부분을 공유하므로, Universal_ID라는 이름의 FDI 배열은 오류 없이 다른 치아로 읽힌다. FDI 18은 오른쪽 위 제3대구치이고 Universal 18은 왼쪽 아래 대구치이며, FDI 33은 왼쪽 아래 견치이고 Universal 33은 잇몸이다(cs/pipeline.py:62-80의 주석). 그래서 Crown_Seg는 배열 이름을 번호 체계에 따라 붙인다. 비워 둔 array_name은 Universal_ID 또는 FDI_ID가 된다(array_name_for, cs/pipeline.py:58-85. cs/__init__.py:44,106). 모든 하위 리더는 Universal 이름만 찾으므로, FDI 메시는 잘못 읽히는 대신 ALI_IOS, ASO, AREG_IOS에서 거부된다(발견 사항 참조). 레거시 호출자는 모두 fdi 0을 넘겼다. FDI 출력은 실질적으로 새것이며 Universal이 여전히 기본값이다(cs/__init__.py:46).

5. 인수와 입출력

쉬운 설명과 수식: 아틀라스 페이지.

형식과 기본값은 발행된 스키마의 것이다(관찰됨: vtk가 있는 AREG_IOS의 인터프리터로 도구에 실행한 scripts/describe.py. 도구 자체의 환경은 여기 없다). 스키마는 extensions를 meshes에 대해 선언하지 않는다.

인자게시된 타입기본값위젯과 규칙
meshes경로, 필수–파일 하나 또는 폴더 하나. .vtk와 .stl만, 폴더는 재귀적으로 찾음(cs/pipeline.py:51,292-320)
output_dir경로, 필수–표시되지 않음. 서버가 채운다
model경로비어 있음숨김(cs/layout.py:5-15). 비어 있으면 DATA/Crown_Seg/models를 뜻함(cs/__init__.py:18-29,104)
array_namestr비어 있음숨김(cs/layout.py:17-30). 비어 있으면 번호 체계를 따름: Universal_ID 또는 FDI_ID(cs/pipeline.py:58-84)

출력. 도구는 출력 폴더를 돌려주므로 이름 붙은 출력은 없다. 각 메시에 무슨 일이 있었는지에 따라 두 개의 트리가 나타날 수 있다. 신경망이 분할한 메시는 <output>/crownseg_input_<suffix>/<relative path without extension>_<suffix>.vtk에 기록되고(cs/pipeline.py:369-381,514), 이미 레이블이 붙어 있던 메시는 .vtk로 변환되어 <output>/<relative folder>/<base>_<suffix>.vtk로 복사된다(cs/pipeline.py:480-487,594-613). 호출하는 쪽은 짐작하지 말고 run_report.json을 읽어야 한다. 임시 폴더 .crownseg_work/는 finally에서 삭제되며(cs/pipeline.py:87,435-439), 체크포인트는 그것이 생기기 전에 결정되므로, 거부된 요청은 출력 폴더를 찾았던 그대로 둔다(cs/pipeline.py:407-413).

run_report.json. tool, checkpoint(이름으로), array_name, suffix, numbering, device, cases(메시별로 status, input, produced, 실패하면 error), segmented_meshes, engine_available, engine_error, summary(total, segmented, already_segmented, engine_unavailable, failed의 개수 포함), 그리고 duration_seconds(cs/pipeline.py:556-590). shapeaxi가 아무것도 기록하지 않은 메시는 failed 케이스이며, 실행 전체는 메시가 하나도 만들어지지 않았을 때만 실패한다(cs/pipeline.py:540-551).

로그의 개인정보. shapeaxi는 저장하는 모든 메시의 경로를 출력하며, 그 경로에는 환자의 파일 이름이 들어 있다. 그 표준 출력은 삼켜지고(cs/pipeline.py:341-345,365-366), 출력의 경로는 그것에서 파싱하지 않고 다시 계산된다(cs/pipeline.py:369-381).

7. 레거시 대응물

쉬운 설명과 수식: 아틀라스 페이지.

줄 단위로 비교할 레거시 Crown_Seg는 없다. 3c67957 시점의 레거시 저장소에서 네 곳이 작업을 하며, 표는 각각이 Crown_Seg의 어느 부분에 대응하는지 말해 준다. ADTLib는 여기에 관여하지 않는다. 공유 계층은 설치된 라이브러리의 복구 하나(ADT/ADTLib/env/install_pytorch.py:404-444)를 제외하면 분할을 언급하지 않는다.

레거시 조각(3c67957)하는 일VISOR 대응물

8. VISOR의 발견 사항

쉬운 설명과 수식: 아틀라스 페이지.

이미 레이블이 붙은 메시 위의 FDI 번호 체계

numbering = "FDI"이고 skip_segmented가 켜져 있으면, 이미 레이블 배열을 가진 메시는 변경 없이 복사되는데(cs/pipeline.py:480-487. _write_as_vtk는 레이블이 아니라 파일 형식을 변환한다), 보고서에는 array_name = "FDI_ID"와 numbering = "FDI"가 적힌다(cs/pipeline.py:556-561). 복사본은 Universal 정수를 Universal 이름으로 유지하므로, 보고서는 파일이 담고 있지 않은 번호 체계를 알린다. 관찰됨: Universal_ID 배열을 가진 합성 메시를 segment_crowns에 fdi=True와 array_name="FDI_ID"로 통과시켰다. 보고서는 numbering: "FDI"와 array_name: "FDI_ID"라고 읽혔고, 출력 파일에는 원래 값 그대로의 Universal_ID만 있었다. 사용한 환경에는 분할 엔진이 설치되어 있지 않으므로 케이스 상태는 engine_unavailable로 읽혔고 already_segmented가 아니었으며, 복사 경로는 같다. 테스트는 이 교차를 다루지 않는다(tests/test_run.py:488-503).

여기서는 이름 네 개를 인식하고, 하위에서는 세 개

Crown_Seg는 메시가 PredictedID, UniversalID, Universal_ID, FDI_ID 중 하나라도 가지면 분할된 것으로 본다(cs/pipeline.py:56). ALI_IOS, ASO, AREG_IOS는 앞의 세 개만 읽는다(ali_ios/surface.py:19, SADT-VISOR tools/ASO/src/sadt_aso/markups.py:19, AREG_IOS/src/sadt_areg_ios/surfaces.py:39). 따라서 FDI_ID만 가진 메시는 Crown_Seg는 통과하고 다음 도구에서 거부된다. 의도된 것이지만(도구 자체의 주석이 그렇게 말한다, cs/pipeline.py:64-80), 그 다음 도구에 이르기 전까지는 아무 증상이 없다. 이 세 개가 “the same three names CrownSeg writes and recognizes”라는 ALI_IOS의 주석(ali_ios/surface.py:18)은 부정확하다. 코드에서 읽음.

.vtp나 .obj 메시는 Crown_Seg에게 보이지 않는다

Crown_Seg는 .vtk와 .stl만 찾는다(cs/pipeline.py:51,292-320). 반면 AREG_IOS는 .vtk .vtp .stl .obj를 입력으로 받아들이며(AREG_IOS/src/sadt_areg_ios/surfaces.py:35) Fully-Automated 모드에서는 자기 폴더를 Crown_Seg에 넘긴다(dispatch.py:172-173). 그런 메시만 든 폴더는 거부되고(“No surface mesh found in the input”, cs/pipeline.py:314-319), 섞인 폴더에서는 그런 메시가 Crown_Seg의 출력에서 빠지며, 그 출력이 AREG_IOS가 이어서 쓰는 폴더다. 레거시 ALI_IOS의 호출 사본은 .vtp를 읽었다(segmentation.py:33-56). 코드에서 읽었으며 실행하지는 않았다.

출력 트리 두 개: 보고서를 읽을 것

분할된 메시는 crownseg_input_<suffix>/ 아래에 놓이고, 이미 레이블이 붙어 있던 메시는 자기 상대 경로 옆에 놓이므로, 한 트리에 대한 glob은 다른 쪽을 놓친다(cs/pipeline.py:369-381,480-487). ALI_IOS는 대신 cases[key].produced를 run_report.json에서 읽으며(ali_ios/dispatch.py:240-252), 보고서는 바로 그것을 위해 있다. 성능이 저하된 설치의 메시는 상태 engine_unavailable을 가지면서도 자신의 produced 경로와 함께 복사되므로(cs/pipeline.py:495-505), already_segmented만으로 거르는 클라이언트는 그것을 건너뛸 것이다. 코드에서 읽음.

서버 문서의 도구 그래프가 낡았다

VISOR-serve docs/TOOL_GRAPH.md:27-28,43은 ALI_IOS를 말단으로 나열한다. ALI_IOS가 발행하는 스키마는 calls = ['Crown_Seg']를 선언하며(ALI_IOS 환경에서 scripts/describe.py로 관찰), 그 dispatch가 모듈 상수를 통해 Crown_Seg를 호출하기 때문이다(ali_ios/dispatch.py:58,229). 문서는 그 스키마들에서 생성되고 부팅 시 검사된다고 말하지만, 저장소에 있는 사본은 코드보다 오래되었다.

코드와 어긋나는 문서

README는 모델이 필수 인수라고 말하고(README.md:33), 파이프라인의 docstring도 마찬가지이지만(cs/pipeline.py:16-23), 인수는 선택 사항이며 빈 기본값은 도구 자체의 폴더로 결정된다(cs/__init__.py:41, 주석은 cs/__init__.py:35-40). README는 또한 폴더를 DATA/CrownSeg/testfiles라고 부르지만(README.md:178) 코드와 매니페스트는 DATA/Crown_Seg를 쓰고, 테스트가 176개라고 세지만(README.md:225,232) tests/에 정의된 테스트 함수는 162개다(def test_를 센 값이며, 매개변수화가 차이를 설명할 수 있다). AREG는 ALI_IOS와 달리 Crown_Seg에 device를 결코 넘기지 않으므로(SADT-VISOR tools/AREG/AREG_IOS/src/sadt_areg_ios/tools.py:113-130), CPU 전용 서버에서는 기본값 cuda가 경고와 함께 CPU로 대체되거나 서버의 DEVICE로 교체된다. 코드에서 읽음.

도구가 보호하는 것

체크포인트는 파일이 만들어지기 전에 결정되므로, 거부된 요청은 아무것도 남기지 않는다(cs/pipeline.py:407-413). 체크포인트를 둘 가진 폴더는 둘 다 이름으로 들어 거부되므로 가중치의 시기가 조용히 넘어가는 일이 없다(cs/pipeline.py:244-251). 파일 이름을 싣고 있는 shapeaxi의 표준 출력은 삼켜진다(cs/pipeline.py:365). 임시 폴더는 finally에서 삭제된다(cs/pipeline.py:435-439). 입력은 결코 수정되지 않는다. 코드에서 읽음.

재현성

도구의 README는 원시 예측 PredictedID가 참조 이식과 비트 단위로 같으며, 후처리된 Universal_ID는 같은 코드의 두 실행 사이에서도 실행마다 달라진다고 보고한다(294,260개 점 중 826개에서 2,607개). 이것은 README의 측정이며(SADT-VISOR tools/Crown_Seg/README.md:176-209, “Validated against” 절), 여기서 다시 실행하지 않았다.

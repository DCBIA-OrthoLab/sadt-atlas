VISOR의 Agent

Agent는 “이 스캔들의 두개골을 분할해 줘” 같은 문장을 읽고 다른 도구 중 무엇을 어떤 설정으로 실행할지 제안한다. Ollama가 서빙하는 언어 모델이 선택하고, 일반 코드가 모든 답을 검사하며, 요청하지 않으면 아무것도 실행되지 않는다. VISOR에는 Agent라고 불리는 서로 무관한 것이 둘 있다. 서버의 새 도구, 그리고 모든 것을 여전히 워크스테이션에서 실행하는 레거시 Slicer 패널의 사본인 AgentRemote이다. 이 페이지는 둘을 단계별로 설명한다. 개발자에게 필요한 세부 사항은 코드 페이지에 있고, 레거시 모듈은 별도 페이지에 있다.

VISOR: 부분 구현 언어 모델 1개, 호출 2회 또는 1회 코드 (개발자용) 레거시 페이지 가이드 (VISOR)

기준 커밋 시점의 상태: SADT-VISOR 6ba2a78, VISOR-serve e9a7e5d, AutomatedDentalToolsRemote 19b95e8(Remote). 레거시는 3c67957의 SlicerAutomatedDentalTools이다. 모든 것을 코드에서 읽었다. Ollama를 사용할 수 없었으므로 아무것도 실행하지 않았다.

개요: 무엇이 들어가고 무엇이 나오는가

출력제안: 어느 도구를, 어떤 인자 값으로, 모델이 얼마나 확신하는지, 어떤 필수 값이 아직 빠져 있는지. 선택적으로, 도구가 실행된 뒤의 출력Markdown으로 쓴 답. 아무것도 제안하거나 실행하지 않는다

1. 체인에서의 위치

서버 도구 Agent클라이언트 모듈 AgentRemote
상태구현되어 있으며 테스트 함수 206개가 있다(Ollama가 필요한 것은 기본적으로 건너뛴다. 이 페이지를 위해 실행한 것은 없다). 배포된 서버에서 실행한 기록은 여기에 없다. Ollama는 따로 제공해야 한다.배포되고 빌드되지만, 서버 클라이언트가 아니라 레거시 위젯의 사본이다.
패널클라이언트에는 없음: 이 도구를 이름으로 호출하는 것이 없다.자체 Qt 패널이며 서버 도구를 쓰지 않는다.
호출HTTP로 Ollama 엔드포인트 하나, 서버 자체의 도구 목록, 그리고 요청이 있으면 다른 서버 도구 하나.자체 명령줄 모듈, 그다음 워크스테이션에서 선택된 모듈의 스크립트.
호출하는 쪽이 페이지를 위해 읽은 저장소에는 없음.사용자.

클라이언트 README는 분명하게 말한다. Medical Data Anonymizer, VISU, Agent는 “run on this machine and send nothing”(이 머신에서 실행되며 아무것도 보내지 않는다)이다. 패널의 도움말 텍스트는 여전히 에이전트가 “powered locally by the qwen3:8b model through Ollama”(Ollama를 통해 qwen3:8b 모델로 로컬에서 구동된다)라고 말한다.

Ollama는 아무도 배포하지 않는 전제 조건이다. 서버 도구는 Ollama 엔드포인트가 필요하다. 인자로 준 것, 없으면 OLLAMA_HOST 변수가 가리키는 것, 없으면 머신 자신의 Ollama 포트이다. 모델을 설치하거나 시작하거나 pull하는 일은 결코 없으며, VISOR-serve의 어디에도 Ollama가 언급되지 않으므로 이미지에는 Ollama가 들어 있지 않다. 닿을 수 있는 엔드포인트가 없으면 도구는 “service unavailable”(서비스를 사용할 수 없음) 응답으로 멈춘다. 근거.

코드에서테스트 수, 파일 위치, 양쪽의 호출, Ollama 엔드포인트 규칙

2. 관련 파일

서버 도구는 짧은 파일 열두 개 정도로 이루어진 작은 Python 패키지이며, 각 파일은 하나의 일을 한다. 카탈로그 읽기, 순위 매기기, 모델과의 통신, 라우팅, 프롬프트 작성, 값 검증, 선택된 도구 실행, 기록 파싱, 패널 기술이다. 표준 라이브러리 밖의 의존성은 없다. 클라이언트 사본은 레거시 위젯에 명령줄 모듈과 매니페스트를 더한 것이다.

코드에서서버 도구, 레거시 모듈, 클라이언트 사본의 파일 목록과 줄 수

3. 서버 도구의 파이프라인

계산된 다섯 단계가 질문을 준비하고, 모델 호출 한두 번이 답하며, 코드가 모든 답을 사용하기 전에 검사한다.

3.1 카탈로그

레거시 agent는 도구와 인수를 손으로 적은 목록으로 직접 들고 있었고, 그 목록은 도구와 점점 어긋났다. 서버 도구는 카탈로그를 입력으로 받는다. 주어지면 서버가 발행하는 목록을 저장한 JSON 사본을, 아니면 서버 자신의 실시간 목록을 토큰 없이 읽으며, 둘 다 없으면 중단한다. 이어서 목록을 검사한다. 비어 있으면 안 되고, 대소문자와 구분자를 무시했을 때 이름이 둘 이상 같으면 안 되며, 모든 인수 유형은 알려진 것이어야 한다. 각 인수마다 도구는 유형, 필수 여부, 설명, 선택지, 기본값을 보관한다. 모델이 채울 수 있는 인수는 출력 폴더도 숨김 인수도 아닌 것들이다.

코드에서카탈로그를 읽는 곳, 거부되는 것, 인수마다 보관되는 것

3.2 후보 고르기

순위 매기기에 쓰는 동의어 표에는 도구 이름이 아니라 어휘가 들어 있다. 레거시 순위는 신경망 교차 인코더(cross-encoder)였고, 실패하면 말없이 파일의 처음 도구 세 개를 돌려주었다. 반면 서버의 순위는 추측하는 대신 오류로 멈춘다.

코드에서BM25 코드, 필드 가중치, 동의어 표, 전체 도구 대체 동작

3.3 첫 번째 모델 호출: 어떤 도구인가?

모델에는 요청과 후보가 보이며, 각 후보는 전체가 적혀 있다(레거시는 설명을 140자에서 잘랐다). 모델은 JSON 객체 하나로 답해야 한다. 도구 이름, 신뢰도, 한 문장 이유이며, 맞는 것이 없으면 도구 없음과 0.2 이하의 신뢰도를 답한다. 답을 읽기 전에 추론 블록과 답을 감싼 코드 펜스는 제거한다. 그다음 이름을 후보와 대조한다.

  • 도구가 없거나 “null”이라는 단어: 아무것도 선택되지 않는다.
  • 후보 중에서 그대로, 또는 대소문자와 구분자를 정규화한 뒤 발견된 이름: 선택된다.
  • 그 밖의 모든 것: 도구 없음, 신뢰도는 0.2로 제한되고, 지어낸 이름은 경고와 함께 기록된다.
코드에서Ollama로 보내는 요청, 라우터 프롬프트, JSON 추출, 이름 검사

3.4 두 번째 모델 호출: 어떤 값인가?

두 번째 호출은 선택된 도구의 채울 수 있는 인수의 값을, 유형, 선택지, 기본값, 그리고 사용자가 준 폴더와 함께 요청한다. 프롬프트는 값이나 경로를 지어내지 못하게 막는다. 기본값은 제안에 복사되지 않으며, 아직 값이 없는 필수 인수는 추측하지 않고 누락으로 나열된다.

코드에서추출 프롬프트, 검증 규칙, 불리언, 숫자, 목록의 강제 변환

3.5 무엇이 실행되는가

모든 조건이 충족되면 선택된 도구는 자신의 환경에서 이름 있는 인수와 함께 일반적인 감독 호출로 실행되고, 출력은 Agent 자신의 출력 안에 있는 run/ 폴더에 놓인다. 도구가 돌려준 것은 결정 파일에 기록된다. 서버 밖에서 감독자 없이 도구를 호출하면서 실행을 요청하는 것은 오류이다. Agent 자신을 고른 모델은 실행 시점에 감독자의 순환 검사에 의해 멈추게 된다.

코드에서코드 속 관문, 감독 호출, 순환 거부

3.6 Ask 모드

Ask 모드에서는 조언자 프롬프트와 후보 목록으로 모델을 한 번 호출하며, JSON으로 제한하지 않고 Markdown 답변을 만들어 advice.md에 쓴다. execute가 무엇이라 하든 아무것도 제안하거나 실행하지 않는다. 그 밖의 모드 값은 Agent 모드로 취급되며, 서버는 도구를 호출하기 전에 허용된 두 이름을 검증한다.

코드에서조언자 호출, 모드 검사, 검사 순서

6. 환경

  • Python 3.11, 표준 라이브러리 밖의 의존성 없음. Ollama와의 연결은 평범한 HTTP를 쓴다.
  • qwen3:8b(또는 선택한 태그)를 이미 받아 둔 Ollama 서버. 이미지에도, VISOR-serve에도 들어 있지 않다.
  • 호스팅된 데이터 없음, 선언된 자원 없음, 모델 호출마다 300초 허용.

레거시 모듈은 Ollama 바이너리를 직접 내려받아 시작했고 모델도 필요할 때 받았다(언어 모델). 서버 도구는 둘 다 하지 않는다. 클라이언트 사본은 여전히 로컬 Ollama와 Slicer의 Python에 있는 교차 인코더에 의존한다.

코드에서출처가 달린 환경 표

8. 알려진 문제

  • 클라이언트 없는 서버 도구, 서버 도구 없는 클라이언트. 어떤 패널도 서버 도구에 닿을 수 없고, 클라이언트 패널은 서버에 접속하지 않는다. 근거.
  • 실행은 기본적으로 꺼져 있으며 세 가지 거부가 있다. 이것은 문제가 아니라 보호 장치이다. 근거.
  • 시작할 때 호출된 도구가 존재하는지 검사하지 않는다. 이름은 레지스트리에서 오며 Agent 자신도 제외되지 않는다. 자기 호출은 실행 시점에 거부된다. 근거.
  • 경로는 여전히 모델의 말일 뿐이다. 제안된 경로가 존재하는지, 알맞은 종류인지 검사하는 것은 없으며, 실행된 도구가 잘못된 경로를 알려 준다. 근거.
  • 클라이언트 사본은 레거시 결함을 유지한다. 말없는 교차 인코더 대체 동작, 작업 중 Slicer가 멈추는 것, 더 이상 배포되지 않는 모듈 스크립트이다. 근거.
  • 클라이언트 사본의 매니페스트는 낡았다. 더 이상 존재하지 않는 MedX를 나열하고 MRI2CBCT는 지명하지 못한다. 근거.

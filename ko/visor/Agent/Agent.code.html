VISOR의 Agent: 코드

개발자용: VISOR 서버 도구 Agent와 클라이언트 사본 AgentRemote가 코드에서 하는 일을 file:line 참조, 시그니처, 인자, 환경, 레거시 코드와의 차이, 발견 사항과 함께 다룬다. 같은 파이프라인의 읽기 쉬운 설명과 수식은 아틀라스 페이지에 있다.

VISOR: 부분 구현 코드 아틀라스 (해설) 레거시 페이지 가이드 (VISOR)

기준 커밋 시점의 상태: SADT-VISOR 6ba2a78, VISOR-serve e9a7e5d, AutomatedDentalToolsRemote 19b95e8(Remote). 레거시는 3c67957의 SlicerAutomatedDentalTools이다. llm.py나 routing.py 같은 파일 이름만 쓴 것은 SADT-VISOR tools/Agent/src/sadt_agent/에 있고, AgentRemote.py는 Remote AgentRemote/에 있다. 모든 것을 코드에서 읽었다. Ollama를 사용할 수 없었으므로 아무것도 실행하지 않았다.

3. 서버 도구의 파이프라인

쉬운 설명과 수식: 아틀라스 페이지.

3.1 GET /tools로 읽는 카탈로그

쉬운 설명과 수식: 아틀라스 페이지.

레거시 에이전트는 도구와 매개변수의 손으로 쓴 자체 매니페스트를 가지고 있었고, 이것은 도구와 어긋나곤 했다. 서버 도구는 카탈로그를 입력으로 받는다(catalog.py:1-23,52-83).

  1. JSON 파일 catalog_file에 GET /tools가 반환하는 것이 담겨 있고 이것이 주어졌다면 그것.
  2. 그렇지 않으면 <SADT_API>/tools이며, urllib로 토큰 없이 읽는다(catalog.py:86-100). SADT_API는 도구에서 보이는 서버 자신의 주소이다(VISOR-serve server/config.py:75, server/execution/dispatch.py:575).
  3. 둘 다 없으면 둘을 모두 이름으로 밝히는 CatalogError, 422.

normalise는 목록 또는 {"tools": [...]}를 받으며 그 외의 것, 빈 카탈로그, 대소문자와 구분자를 무시하면 같아지는 두 이름, path, str, int, float, bool과 그 목록 바깥의 인자 타입, 목록이 아닌 choices는 거부한다(catalog.py:103-223). 각 인자에 대해 타입, 필수 여부, 설명, choices, 기본값, 그리고 표시용 키 hidden, label, section을 유지한다. 모델이 채울 수 있는 인자는 output_dir도 숨김도 아닌 것이다(fillable_arguments, catalog.py:250-262). catalog.py에는 Agent 자신을 카탈로그에서 제거하는 것이 없다.

3.2 후보 고르기

쉬운 설명과 수식: 아틀라스 페이지.

각 도구는 이름(가중치 4), 설명(3), 인자의 이름과 설명(1)에서 나온 단어 주머니가 되며, 도구가 아니라 어휘에 대한 동의어 표를 쓴다(ranking.py:32-110,148-169). 요청은 BM25로 점수가 매겨진다.

idf  = log(1 + (N - df + 0.5) / (df + 0.5))
norm = K1 * (1 - B + B * len(doc) / avg_len)          # K1 = 1.2, B = 0.4
score += weight * idf * tf * (K1 + 1) / (tf + norm)   # ranking.py:183-219

그 합에서 tf는 문서에서 그 용어의 가중 횟수이다. 각 출현은 필드에 따라 4, 3 또는 1을 더하며(ranking.py:156-168), len(doc)는 그 가중치의 합이다(:194). weight는 요청 용어의 가중치이다. 입력한 단어는 1.0, 동의어 부류에서 추가된 단어는 0.55(SYNONYM_DISCOUNT, :43,171-180)이다(:207,215).

select_candidates는 상위 candidates개(기본값 8)를 유지하지만, candidates가 0이거나, 카탈로그를 모두 덮거나, 점수가 0을 넘는 도구가 없으면 카탈로그 전체를 반환한다(ranking.py:222-239). 좁혔는지 여부는 보고서에 candidates_narrowed로 기록된다. 레거시 cross-encoder는 실패하면 파일 순서상 처음 세 도구를 반환했다(레거시 Agent_CLI/Agent_CLI_utils/utils.py:94).

3.3 라우터 호출

쉬운 설명과 수식: 아틀라스 페이지.

/api/chat POST 한 번, stream: false, keep_alive: "30m", format: "json", options {temperature, seed} 포함(llm.py:45,62-103). 시스템 프롬프트는 JSON 객체 하나 {"tool", "confidence", "reason"}를 요구하고, 도구는 CANDIDATES 목록에서만 고르며, 맞는 것이 없으면 null과 0.2 이하의 신뢰도를 요구한다(prompts.py:15-30). 후보는 레거시의 140자 절단 없이 전부 적힌다(prompts.py:1-8,67-103). parse_json_object는 <think> 블록과 코드 펜스를 제거한 뒤 처음으로 균형이 맞는 객체를 취한다(llm.py:131-181). 그다음 choose_tool이 이름을 검사한다(routing.py:22-55).

  • null, "null" 또는 "None": 도구 없음.
  • 후보 중에서 정확히, 또는 정규화한 뒤 찾은 이름(catalog.find_tool, catalog.py:236-247): 선택됨.
  • 그 외 모든 것: 도구 없음, 신뢰도는 0.2로 제한되고, 이름은 경고와 함께 rejected_tool_name으로 기록된다(__init__.py:197-222).

3.4 추출 호출과 검증

쉬운 설명과 수식: 아틀라스 페이지.

두 번째 호출은 {"extracted": {...}, "confidence", "notes"}를 요구하며, 선택된 도구의 채울 수 있는 인자와 그 타입, choices, 기본값, 그리고 폴더를 함께 준다(routing.py:58-84, prompts.py:32-48,105-140). 프롬프트는 값이나 경로를 지어내는 것을 금한다. 그다음 validation.validate가 다음을 한다(validation.py:39-77).

  • 도구가 받지 않는 이름은 모두 버리고 그 사실을 알린다.
  • null을 "명시되지 않음"으로 취급한다.
  • 불리언은 true/yes/y/1/on과 그 반대 값에서, 정수와 실수, 목록으로 변환하고, choices를 검사한다(validation.py:80-209). 실패는 결정의 오류이며 그 값은 버려진다.

오류가 하나라도 있으면 레거시와 마찬가지로 추출 신뢰도에 0.6을 곱한다(routing.py:78-83). 기본값은 제안에 복사되지 않으며, 여전히 없는 필수 인자는 missing_required에 나열된다(catalog.py:265-271, __init__.py:224-232).

3.5 무엇이 실행되는가

쉬운 설명과 수식: 아틀라스 페이지.

allowed, reason = routing.can_execute(decision)     # __init__.py:234
if not execute:          -> executed: false, proposal only
elif not allowed:        -> executed: false, execution_refused: reason
else:
    parameters = dict(values); parameters["output_dir"] = output_dir / "run"
    produced = supervisor.run(tool_name, **parameters)          # execution.py:58-70

can_execute는 도구가 선택되지 않았을 때, missing_required가 비어 있지 않을 때, 라우터의 신뢰도가 EXECUTE_MIN_CONFIDENCE = 0.5 미만일 때 거부한다(routing.py:19,104-125). 선택된 도구는 그다음 자체 venv에서 일반적인 감독되는 호출로 실행되며, 이름 있는 인자를 받고, 출력은 Agent의 출력 폴더 안의 run/ 아래에 놓인다. 반환한 것은 execution 아래, routing.json에 기록된다(__init__.py:245-252, execution.py:75-85). 감독자가 없으면(서버 밖에서 호출된 도구) execute는 SupervisorRequired를 발생시킨다(execution.py:51-56). 감독자는 순환을 이름으로 거부하므로, Agent 자신을 고르는 모델은 "Supervised call cycle"로 끝나게 된다(VISOR-serve server/execution/runner.py:1814-1817). 코드에서 읽은 것이다.

3.6 Ask 모드

쉬운 설명과 수식: 아틀라스 페이지.

mode = "Ask (Interactive)"이면 조언자 프롬프트와 후보 목록으로 한 번 호출하며, JSON 형식이 아니고, Markdown 답은 advice.md에 기록된다(__init__.py:161-188, routing.py:87-101, prompts.py:50-63). execute가 무엇이라 하든 아무것도 제안하거나 실행하지 않는다. 다른 mode 값은 Agent 모드로 취급된다(__init__.py:161-167). 서버는 Literal을 run()이 호출되기 전에 검증한다.

3.7 출력

쉬운 설명과 수식: 아틀라스 페이지.

output_dir/routing.json        {tool, arguments, confidence, reasoning, alternatives, mode,
                                missing_required, errors, executed, [parameter_confidence,
                                dropped_arguments, rejected_tool_name, execution_refused, execution]}
output_dir/Agent_report.json   {tool, mode, catalog_source, catalog_size, candidates,
                                candidates_narrowed, ranker_scores, endpoint, model_tag,
                                temperature, seed, history_turns, warnings, duration_seconds}
output_dir/advice.md           Ask mode only
output_dir/run/                the executed tool's own outputs, if any

키는 __init__.py:145-252에서 가져왔다. alternatives는 모델의 대안이 아니라 순위 매기기 점수가 붙은 다른 후보이다(:255-267).

4. 인자와 스키마

쉬운 설명과 수식: 아틀라스 페이지.

8. VISOR의 발견 사항

쉬운 설명과 수식: 아틀라스 페이지.

클라이언트가 없는 서버 도구, 서버 도구가 없는 클라이언트

서버 도구는 어떤 패널에서도 닿을 수 없고, 클라이언트 패널은 서버에 연락하지 않는다. AutomatedDentalToolsRemote에는 Agent에 대한 요청을 만드는 것이 없으며, AgentRemote.py는 ServerToolsCoreLib을 import하지 않는다. 둘이 공유하는 것은 이름과 모델 태그뿐이다.

실행은 기본적으로 꺼져 있으며 세 가지 거부가 있다

execute의 기본값은 false이다(__init__.py:43). true일 때도 도구가 선택되지 않았거나, 필수 인자가 빠졌거나, 신뢰도가 0.5 미만이면 실행은 여전히 거부된다(routing.py:104-125). 소스 주석은 그 임계값을 품질 기준이 아니라 모델이 추측하고 있다고 인정하는 것에 대한 하한이라고 부른다(routing.py:16-19).

시작할 때 호출될 도구가 존재하는지 검사하지 않는다

호출은 스키마 생성기가 고정된 의존성을 기록하지 않도록 일부러 supervisor.run(...)으로 쓴다. sup.run(...)이 아니다(execution.py:9-29,68-70). 여기에 들어오는 이름은 카탈로그에서 오므로, 이름은 그것을 읽은 레지스트리만큼만 믿을 수 있다. 카탈로그는 Agent를 제외하지 않으며, 자기 호출은 감독자의 순환 검사가 실행 시점에 거부한다(VISOR-serve server/execution/runner.py:1814-1817).

경로는 여전히 모델의 말일 뿐이다

모델이 보는 유일한 경로는 folders이며 이를 그대로 쓰라고 지시받지만(prompts.py:32-48), 제안된 경로가 존재하는지, 알맞은 종류인지 검사하는 것은 없다. 스키마는 파일인지 폴더인지 말하지 않고 path라고만 하며, 레거시의 확장자 검사는 일부러 빠졌다(validation.py:9-17). 잘못된 경로를 알리는 것은 실행된 도구이다. 서버에서는 그 경로도 사용자의 것이 아니라 서버의 경로이다. 코드에서 읽은 것이다.

클라이언트 사본은 레거시의 결함을 그대로 지닌다

AgentRemote와 Agent_CLIRemote는 레거시 설계이므로 레거시 발견 사항(레거시 함정)이 여전히 적용된다. cross-encoder는 여전히 처음 k개 도구로 되돌아가고(Remote Agent_CLIRemote/Agent_CLIRemote_utils/utils.py:94), 작업은 여전히 Slicer의 스레드에서 동기적으로 실행되며(AgentRemote.py:767), 모듈 경로는 여전히 AGENT_CLI_TOOLS_DIR을 통해 해석되는데(utils.py:150-156), 매니페스트가 지정한 CLI 모듈은 확장에서 삭제되었다(Remote CMakeLists.txt:49-56). 코드에서 읽은 것이며 Slicer에서 실행하지 않았다.

클라이언트 사본의 매니페스트는 낡았다

Agent_CLIRemote/manifest.yaml은 두 저장소 어디에도 MedX가 더 이상 없는데도(MedX 참조) medx_dashboard와 medx_summarize(491행과 509행)를 나열하며, 빌드되지 않는 MRI2CBCT는 지정할 수 없다.

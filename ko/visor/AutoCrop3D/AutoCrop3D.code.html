VISOR의 AutoCrop3D: 코드

개발자용: AutoCrop3D의 VISOR 이식이 코드에서 하는 일을 file:line 참조, 시그니처, 인수, 환경, 레거시 모듈과의 차이, 발견 사항과 함께 다룬다. 같은 파이프라인을 수식과 함께 읽기 쉽게 설명한 것은 아틀라스 페이지에 있다.

VISOR 코드 아틀라스 (해설) 레거시 페이지 가이드 (VISOR)

VISOR에서 AutoCrop3D는 서버에서 실행되는 Python 패키지이다. Slicer 쪽은 상자를 그리거나 고르고, 파일을 보내고, 돌아온 것을 불러오기만 한다. 자르기 자체는 일부러 유지한 레거시 산술이며, 바뀐 것은 그 주변 전부, 즉 스캔을 ROI와 짝짓는 방법, 무엇을 검사하는지, 무엇을 보고하는지이다. 이 페이지는 이식을 요청에서 돌아오는 파일까지 따라간다. 위치, 파일, 자르기와 표면의 각 단계와 그것을 수행하는 코드, 발행된 인수, 환경, 레거시 모듈과의 차이, 발견 사항이다. SADT-VISOR(브랜치 tool/vface, 6ba2a78, 2026-09-30)의 이식을 설명하며, 이는 VISOR-serve(e9a7e5d)가 서비스하고 AutomatedDentalToolsRemote 확장(19b95e8)이 Slicer에서 구동한다. 이식은 업스트림 커밋 b1ae78c(2026-05-26, SADT-VISOR AutoCrop3D/README.md:15-16)에서 만들어졌으며, 이는 레거시 페이지에 설명된 3c67957 상태보다 앞선다. 배포된 서버에 대해서는 아무것도 주장하지 않는다. 아래의 모든 것은 코드에서 읽은 것이며, 도구의 테스트 스위트는 패키지에서 실행했다.

이 페이지에서 참조를 읽는 방법

SADT-VISOR AutoCrop3D/pipeline.py:272는 6ba2a78 시점의 SADT-VISOR에 있는 tools/AutoCrop3D/src/sadt_autocrop3d/pipeline.py이다. 접두어 없는 pipeline.py나 __init__.py는 같은 패키지이고, 접두어 없는 README.md, pyproject.toml, tests/…는 tools/AutoCrop3D/ 아래에 있다. VISOR-serve server/…와 data-manifest.yml(VISOR-serve scripts/data-manifest.yml)은 e9a7e5d 시점이고, AutomatedDentalToolsRemote …는 19b95e8 시점이다. 레거시 참조(AutoCrop3D_CLI.py, FilesType.py, GenerateVTKfromSeg.py, AutoCrop3D.py)는 3c67957 시점의 SlicerAutomatedDentalTools에 있는 AutoCrop3D/의 파일이다.

1. 체인에서의 위치

쉬운 설명과 수식: 아틀라스 페이지.

AutoCrop3D는 체인의 맨 앞에 있는 유틸리티이다. 다른 도구가 작업하기 전에 CBCT 또는 그 분할을 임상의가 그린 영역으로 줄인다. VISOR에서는 아무것도 호출하지 않고 아무도 이를 호출하지 않는다. ROI는 Slicer에서 그려지므로 클라이언트가 그 부분을 유지한다.

항목값
상태도구 수준에서 구현되고 테스트되었다. pytest를 SADT-VISOR AutoCrop3D에서 실행: 2026-11-09에 103개 통과(6ba2a78, 깨끗한 트리). test_autocrop3d_client.py의 클라이언트 테스트 15개는 실행하지 않았다(발견 사항 참조).

3. 무엇이 어디서 실행되는가

쉬운 설명과 수식: 아틀라스 페이지.

단계서버클라이언트(Slicer)
상자 그리기–ROI는 이미 장면에 있는 Markups ROI 노드이며 ROI 행에서 고른다(AutomatedDentalToolsRemote ServerToolsCore/ServerToolsCoreLib/formgen.py:354). 또는 .mrk.json 파일이나 폴더이다.
보내기스캔과 ROI를 받으며, 기본 업로드 한도는 500 MB이다(VISOR-serve server/config.py:240). 스캔과 ROI는 필수 path 인수 두 개이므로 도구를 환자별로 나눌 수 없고 폴더는 한 번의 요청으로 올라간다(VISOR-serve server/registry/conventions.py:158-190).업로드하거나 호스팅된 테스트 파일의 이름을 지정한다.
자르기SimpleITK로 읽고, 상자를 인덱스에 대응시키고, 슬라이스하며, 선택적으로 자른 것을 원래 기하에 되돌려 놓는다(SADT-VISOR AutoCrop3D/pipeline.py:256-329).–
표면VTK 마칭 큐브와 Laplacian 평활화(SADT-VISOR AutoCrop3D/pipeline.py:438-499).–
반환run()은 Path를 돌려주고, 서버는 이를 output_kind "files"로 발행한다. 출력 폴더는 압축된다(VISOR-serve server/registry/schema_tool.py:95-107). 시간 제한 없음(TOOL_TIMEOUT_SECONDS = 0, VISOR-serve server/config.py:77), [tools.AutoCrop3D] 섹션이 deployment.toml에 없음.선택한 폴더에 압축을 풀고, AutoCrop3D_report.json을 읽고, 결과를 최대 12개 불러온다.

4. 파이프라인, 단계별

쉬운 설명과 수식: 아틀라스 페이지.

run()을 한 번 호출하면 찾은 모든 스캔을 자른다(SADT-VISOR AutoCrop3D/__init__.py:76-167).

4.1 스캔과 ROI 찾기 계산

쉬운 설명과 수식: 아틀라스 페이지.

_discover_scans는 파일 하나를 받거나 폴더를 재귀적으로 돌며 .nii.gz .nrrd.gz .gipl.gz .nii .nrrd .gipl(pipeline.py:26)을 남기고, 숨김 파일은 건너뛰며, 이번 실행의 이전 출력처럼 보이는 파일은 따로 둔다(pairing.is_previous_output, 끝의 토큰 전체를 보므로 Cropped_01은 제외되지 않는다). 이런 파일은 다른 것이 하나도 없을 때만 쓰인다(__init__.py:289-311). _discover_rois는 세 가지 형태를 받는다. .mrk.json 파일 하나, 정확히 하나를 담은 폴더(둘 다 모든 스캔에 쓰인다), 또는 여러 개가 든 폴더로 환자별로 대응시킨다(__init__.py:314-368). 같은 환자 키를 가진 ROI 둘은 하나가 말없이 이기는 대신 이름을 대며 거부된다(:345-367).

4.2 환자 키 계산

쉬운 설명과 수식: 아틀라스 페이지.

하나의 함수가 스캔과 ROI를 모두 처리한다(pipeline.py:60-113). 이 함수는 stem을 토큰으로 나누고, 레거시의 연쇄 split 어휘와 ROI 단어를 토큰 전체 단위로 버리되 첫 단어는 절대 버리지 않는다(pipeline.py:51-57, 97-108).

IDENTITY_TOKENS_TO_DROP = frozenset({
    "scan", "scans", "seg", "segmentation", "segmentations", "or", "mand",
    "md", "max", "mx", "cb", "lm", "cl", "merged", "mask", "pred",
    "roi", "rois", "mrk", "crop", "cropped", "box", "bbox",
})

시점은 유지되므로 P01_T1과 P01_T2는 상자를 둘 가질 수 있고, MAX_01이라는 환자는 MAX_01로 남는다(pipeline.py:75-81, 100-105). 2026-11-09에 실행: Patient_01_Scan과 Patient_01_ROI는 모두 Patient_01을 낸다. 키에 해당하는 ROI가 없는 스캔은 _NoRoi를 일으키고 without_a_roi에 나열된다(__init__.py:134-141, 206-208).

4.3 상자 읽기 계산

쉬운 설명과 수식: 아틀라스 페이지.

read_roi는 첫 번째 마크업의 center와 size를 가져오며, JSON이 아니거나 마크업이 없거나 상자가 없는 파일은 파일 이름을 대며 거부한다(pipeline.py:158-187). 그다음 좌표계이다(pipeline.py:194-201).

system = str(document.get("coordinateSystem", markup.get("coordinateSystem", "LPS"))).upper()
center = [float(value) for value in center]
if system in ("RAS", "0"):
    center = [-center[0], -center[1], center[2]]
elif system not in ("LPS", "1"):
    raise ValueError(...)

중심은 ITK의 물리적 점의 좌표계인 LPS로 끝난다. 크기는 절댓값으로 취한다(:215). orientation의 회전은 적용되지 않는다. 상자는 축에 정렬된 채로 남고, 경고가 기록되고 roi_orientation_ignored가 설정되지만, 실제 회전에 대해서만 그렇다. 상자를 자기 자신에게 대응시키는 부호 있는 축 순열은 세지 않는다(pipeline.py:203-211, 228-249).

4.4 상자에서 인덱스로, 그리고 자르기 계산

쉬운 설명과 수식: 아틀라스 페이지.

두 물리적 모서리는 TransformPhysicalPointToContinuousIndex를 거쳐 레거시의 .astype(int)와 똑같이 0 쪽으로 잘리고, 필요하면 축마다 모서리를 서로 바꾼 뒤 볼륨 안으로 클램프된다(pipeline.py:269-283).

lower_point = [c - s / 2.0 for c, s in zip(roi.center, roi.size)]
upper_point = [c + s / 2.0 for c, s in zip(roi.center, roi.size)]
lower = [int(value) for value in image.TransformPhysicalPointToContinuousIndex(lower_point)]
upper = [int(value) for value in image.TransformPhysicalPointToContinuousIndex(upper_point)]
...
clamped = any(lower[axis] < 0 or upper[axis] > size[axis] for axis in range(3))

자르기는 SimpleITK 슬라이스인 image[lower[0]:upper[0], lower[1]:upper[1], lower[2]:upper[2]]이다. 리샘플링도 보간도 없고 origin, spacing, direction이 그대로 이어지므로, 잘린 볼륨은 그 복셀이 있던 바로 그 자리에 놓인다. 빈 범위는 "The ROI does not overlap this volume"으로 거부된다(pipeline.py:286-301). keep_original_size가 있으면 자른 것을 원래 크기와 기하의 빈 이미지에 다시 복사하고 나머지는 모두 0으로 둔다(pipeline.py:304-329. numpy는 (z, y, x)로 인덱싱하고 경계는 (x, y, z)이다, :320-325).

4.5 쓰기와 이름 짓기 계산

쉬운 설명과 수식: 아틀라스 페이지.

출력은 output_dir 아래에 입력 트리를 그대로 반영하며(__init__.py:223-226, 277-286), 이름은 복합 확장자를 유지한다. P1_scan.nii.gz에 접미사 cropped를 붙이면 P1_scan_cropped.nii.gz가 되고, 빈 접미사는 아무것도 더하지 않는다(pipeline.py:332-344). 형식은 확장자를 따른다(sitk.WriteImage, __init__.py:226). .nrrd.gz는 그 스캔에 대해서만 이유와 함께 거부된다(__init__.py:210-214).

4.6 잘린 레이블 맵의 표면 계산

쉬운 설명과 수식: 아틀라스 페이지.

surfaces가 all이거나, segmentations이면서 파일 이름에 seg, segmentation, mask, pred, label, labels 중 하나가 토큰 전체로 들어 있을 때 만들어진다(__init__.py:246, 265-274, pipeline.py:124-134).

  1. 레이블. 실제로 존재하는 0이 아닌 값(pipeline.py:400-412). 없으면 파일은 쓰이지 않고 보고서에는 surface: null이라고 적힌다(pipeline.py:457-459, __init__.py:257-261).
  2. 여백. surface_padding_mm를 축마다 정수 복셀(최소 하나)로 바꾼 다음, 양쪽 경계에 sitk.ConstantPad(image, margin, margin, 0)을 적용하므로 상자에 닿은 구조가 닫힌다(pipeline.py:415-426, 461-462).
  3. 마칭 큐브. 패딩된 볼륨은 실행의 임시 디렉터리에 padded.nii.gz로 쓰였다가 vtkNIFTIImageReader로 다시 읽히며, 존재하는 레이블마다 윤곽 하나씩으로 vtkDiscreteMarchingCubes를 쓴다(pipeline.py:463-478).
  4. 평활화. vtkSmoothPolyDataFilter, surface_smoothing_iterations회 반복, 특징 각도 120과 이완 0.6은 상수이다(pipeline.py:434-435, 480-485).
  5. 환자 공간. NIfTI 리더는 qform을 호출자에게 맡기므로, 표면은 origin + direction @ diag(spacing / reader_spacing)로 이동한다. 4×4 행렬 하나이며 리샘플링은 없다(pipeline.py:502-541). 그러면 .vtk가 잘린 볼륨과 겹친다(tests/test_run.py:1242, 통과).
  6. 색과 쓰기. 각 셀은 자기 레이블의 색을 받는다. 레거시의 여섯 항목 표, 그다음 더 높은 레이블에는 황금비 색조이다(pipeline.py:359-384, 544-585). 기본 설정의 vtkPolyDataWriter로 볼륨 옆에 <stem>_<suffix>_vtk.vtk로 쓰며(pipeline.py:347-351, 491-494), 임시 볼륨은 finally에서 지운다(:495-497).

9. VISOR의 발견 사항

쉬운 설명과 수식: 아틀라스 페이지.

보고서 안의 서버 경로

표면이 쓰이면 보고서는 그것을 서버의 절대 경로로 지칭한다. entry["surface"] = str(surface_path)이고 같은 문자열이 produced에도 덧붙는다(SADT-VISOR AutoCrop3D/__init__.py:253-255). 반면 바로 위의 주석은 보고서가 클라이언트로 전달되므로 output_dir에 대한 상대 경로여야 한다고 말한다(:231-232). 볼륨 항목은 상대 경로이다(:236). 이 규칙의 유일한 테스트는 produced[0]을 검사하는데(tests/test_run.py:1424-1441), 이는 볼륨이다. 2026-11-09에 run()을 P1_Seg.nii.gz라는 합성 레이블 맵에 대해 호출해 재현했다. produced에는 P1_Seg_cropped.nii.gz와 절대 경로 …/out/P1_Seg_cropped_vtk.vtk가 들어 있었고, surface에는 같은 절대 경로가 들어 있었다.

기본 표면 규칙이 파일 이름에 좌우된다

기본값 surfaces = "segmentations"에서는 파일 이름에 seg, segmentation, mask, pred, label, labels 중 하나가 토큰 전체로 들어 있을 때만 표면이 만들어진다(SADT-VISOR AutoCrop3D/pipeline.py:124-134). 2026-11-09에 패키지 자체의 is_segmentation_name으로 확인했다. P1_Seg.nii.gz는 해당되고, Mandible.nii.gz는 해당되지 않아 surfaces = "all"이 아니면 표면을 얻지 못한다. 레거시의 검사는 출력 경로 어디에든 부분 문자열 seg가 있는지 보는 것이었다(AutoCrop3D_CLI.py:143@3c67957).

코호트는 나뉘지 않는다

scans와 roi는 둘 다 필수 path 인수이므로 서버는 배치 축을 제공하지 않으며(VISOR-serve server/registry/conventions.py:158-190, 주석이 AutoCrop3D를 지명한다) 폴더 전체가 500 MB 기본 업로드 한도 아래에서 한 번의 요청으로 올라간다(VISOR-serve server/config.py:240). 호스팅된 테스트 스캔 하나만 해도 98 611 496바이트이다(data-manifest.yml:792-794).

등록되지 않은 클라이언트 테스트

AutomatedDentalToolsRemote AutoCrop3DRemote/Testing/Python/test_autocrop3d_client.py에는 테스트가 15개 있지만, AutoCrop3DRemote/CMakeLists.txt에는 add_test도 add_subdirectory도 없고 Testing/에는 CMakeLists.txt가 없으므로 스위트가 ctest에 연결되어 있지 않다. 루트 CMakeLists.txt:29는 모듈을 추가한다. AutoMatrixRemote와 GreedyRegRemote는 자기 것을 등록한다(AutoMatrixRemote/CMakeLists.txt:34, GreedyRegRemote/CMakeLists.txt:34, 각각 add_subdirectory(Testing)).

이식 주변의 낡은 문서

AutomatedDentalToolsRemote README.md:508-546은 여전히 옛 모듈을 설명한다. AutoCrop3D/ 아래의 아이콘 경로(폴더는 AutoCrop3DRemote이다), 받아들여지는 .nrrd.gz(도구는 이를 거부한다, pipeline.py:37), "Seg somewhere in the name"(이제는 토큰 전체), "Volume Rendering"으로 만드는 ROI이다. 패키지 자체의 README도 테스트가 102개라고 알리는데(README.md:200) 스위트에는 103개가 있다. 이 페이지는 코드를 따른다.

회전된 ROI도 여전히 축에 정렬된 상자로 잘린다

회전은 적용되지 않는다. 자르기는 레거시 CLI와 같이 볼륨의 인덱스 축을 따라 상자의 중심과 크기를 쓰며, 보고서는 roi_orientation_ignored와 로그 경고로 이를 알린다(SADT-VISOR AutoCrop3D/pipeline.py:203-211). 기울어진 상자를 위한 레거시 모듈의 두 번째 엔진인 Slicer의 Crop Volume은 헤드리스 대응물이 없어 이식되지 않았다(README.md:159-177). 인덱스를 0 쪽으로 버리는 것도 일부러 유지된다(pipeline.py:257-264, 272-273).

레거시 결함 열세 가지를 수정했고, 각각 테스트가 있다

이식은 열세 가지 수정을 각각의 테스트 이름과 함께 SADT-VISOR AutoCrop3D/README.md:107-125에 나열한다. 스위트는 모두 통과했다(2026-11-09, 103개 통과). Slicer 패널의 짝이 맞지 않는 환자 메시지는 최대 다섯 명의 환자를 지명한다(AutomatedDentalToolsRemote AutoCrop3DRemote/AutoCrop3DRemote.py:129-136).

10. 문헌

쉬운 설명과 수식: 아틀라스 페이지.

AutoCrop3D는 인용할 자체 방법이 없는 기하이다. 도구의 참고문헌은 AutoCrop3D 출처에 있다. 모든 도구가 공유하는 VISOR의 동작 방식은 아키텍처와 실행의 단계별 과정을, 패널 사용법은 VISOR 가이드를 참조.

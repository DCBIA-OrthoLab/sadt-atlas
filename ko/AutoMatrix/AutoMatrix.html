AutoMatrix

다른 곳에서 이미 계산된 ITK 변환 하나 이상을 볼륨과 랜드마크 파일이 든 폴더에 일괄 적용한다 — 신경망도, conda도, GPU도 없다.

미발표 Automatrix_CLI 계산 — 신경망 없음 conda 없음, GPU 없음 참고문헌

볼륨과 랜드마크 파일이 든 폴더에 ITK 변환 하나 이상을 일괄 적용한다. 신경망도, conda도, GPU도 없다. sitk.ReadTransform + sitk.ResampleImageFilter, 그리고 이름 쪼개기로 하는 파일 ↔ 행렬 짝짓기가 전부다. 이 페이지의 요점은 변환 규약, 그리고 UI가 약속하는 것과 CLI가 실제로 하는 것 사이의 차이에 있다.

1. 파이프라인에서의 위치

저장소의 다른 모듈 중 AutoMatrix를 호출하는 것은 없다. 다만 AutoMatrix는 소비자로서 정합 모듈이 생성한 .tfm 파일을 쓴다.

3. 읽히는 변환 형식 — 그리고 읽히지 않는 형식

UI(AutoMatrix.py:1012)와 README는 .npy, .h5, .tfm, .mat, .txt를 내세운다. GetPatients는 이들을 모두 수집한다. 그다음 CLI는 구분 없이 다음을 실행한다 (Automatrix_CLI.py:285).

따라서 .npy 지원은 고장 나 있다. 모든 .npy 파일은 오류 한 줄을 남기고 건너뛴다. CLI로 옮기면서 생긴 회귀다 (커밋 7bc362b). 위젯 버전은 np.load(matrix)로 읽어 vtkMRMLTransformNode를 만들었다(extension_mat == ".npy" 분기, git show 7bc362b^:AutoMatrix/AutoMatrix.py로 볼 수 있다).

"텍스트 행렬"도 마찬가지다. 이는 행렬 형식이 아니라 ITK의 텍스트 형식이다.

읽기에 성공하면 구체적인 타입이 보존된 sitk.Transform이 반환된다 — isinstance(tfm, sitk.CompositeTransform)가 동작함을 확인했다.

4. 변환 규약 — 모든 것을 망가뜨리는 지점

4.1 변환의 방향

ITK는 fixed → moving이다. 리샘플러에 넘긴 sitk.Transform은 출력 물리 좌표점을 샘플링할 입력 물리 좌표점으로 매핑한다. 따라서 눈에 보이는 내용은 T⁻¹에 따라 움직인다.

코드는 양쪽에서 이를 활용하며, 일관성이 있다.

  • 볼륨(Automatrix_CLI.py:209): resampler.SetTransform(transform) — 변환을 그대로 넘기므로 내용이 T⁻¹만큼 움직인다.
  • 랜드마크(Automatrix_CLI.py:176): 
    tfm_inverted = transform.GetInverse()
point['position'] = list(tfm_inverted.TransformPoint(point['position']))
    T⁻¹를 점에 명시적으로 적용하므로 점이 볼륨의 내용과 똑같이 움직인다.
확인됨

핵심: 같은 .tfm을 스캔과 그 랜드마크에 적용하면 둘이 같은 움직임으로 옮겨진다. 이 모듈을 쓸 수 있게 해 주는 속성이며, 코드에서 역변환이 등장하는 유일한 곳이기도 하다.

함정

GetInverse()는 RuntimeError를 일으킬 수 있다(역변환할 수 없는 변환: 조밀 변위장, B-spline). 이 경우는 잡혀서 랜드마크 파일이 경고와 함께 그냥 건너뛰어지지만, 대응하는 볼륨은 이미 변환되어 있을 것이다. 따라서 두 출력이 조용히 어긋날 수 있다.

4.2 RAS / LPS: 축 반전은 어디서 일어나는가 — 어디에서도

AutoMatrix에는 축 반전이 없다. 이것이 옳으며, 그 이유는 다음과 같다.

  • ITK .tfm 파일은 구조상 LPS다.
  • sitk.ReadImage / WriteImage는 LPS로 동작한다. 양쪽이 일치하므로 볼륨에 대해서는 할 일이 없다.
  • 저장소의 .mrk.json 파일은 모든 곳에서 LPS로 하드코딩되어 있다: ALI_CBCT/io.py:36, ASO_CBCT/utils.py:278, AREG_CBCT/utils.py:373, ALI_IOS/io.py:85, mgl_patch.py:193, VFACE/functionaq3dc.py#L1733. 이는 Slicer가 기록할 때의 기본값이기도 하다. 따라서 point['position']은 이미 LPS이며, ITK 변환에 바로 적용하는 것이 옳다.
함정

취약한 부분은 coordinateSystem 필드를 전혀 읽지 않는다는 점이다. FlexReg는 이를 읽지만(FlexReg.py:2434) AutoMatrix는 읽지 않는다. "coordinateSystem": "RAS"를 선언한 json — 오래된 주석 데이터나 다른 도구가 기록하는 형태 — 은 x와 y의 부호가 뒤집힌 채 아무 메시지 없이 변환된다. json을 읽어 그대로 다시 쓰기 때문에 출력 파일은 원래의 coordinateSystem: RAS까지 그대로 유지한다.

참고로, 행렬을 생성하는 모듈은 축 반전을 스스로 처리한다. FlexReg_CLI.py:186은 flip @ M @ flip을 flip = np.diag([-1,-1,1,1])로 계산한 뒤 역변환하고 나서 .tfm을 기록한다. AutoMatrix는 그 결과를 소비하므로 다시 할 일이 없다.

4.3 합성

함정

합성은 없다. 환자에게 행렬이 여러 개 있으면 루프 (Automatrix_CLI.py:283)가 각 행렬을 원본 입력 파일에 독립적으로 적용하여 행렬마다 출력을 하나씩 만든다. 연쇄 적용은 없다.

존재하는 합성은 ITK가 이미 해 둔 것뿐이다. 여러 변환이 든 .tfm은 sitk.CompositeTransform으로 읽혀 통째로 적용된다.

4.4 Harden

없다. 파이프라인에는 더 이상 vtkMRMLTransformNode가 없다. CLI 이전 버전은 이를 만들고 model.SetAndObserveTransformNodeID(...), 이어서 model.HardenTransform()을 실행한 뒤 slicer.util.exportNode(..., world=True)를 호출했다. 그 블록 전체가 사라졌다. 위젯의 saveOutput 메서드 (AutoMatrix.py:861)는 exportNode를 호출하던 것으로, 아직 남아 있지만 더 이상 호출되지 않는다. 사용되지 않는 코드다.

6. 리샘플링과 기준 영상

resampler.SetInterpolator(sitk.sitkNearestNeighbor if is_seg else sitk.sitkLinear)
resampler.SetDefaultPixelValue(0)
resampler.SetReferenceImage(reference)

보간기는 "Check this box if using segmentations" 체크박스(is_seg)에서 정해진다. 레이블맵에는 최근접 이웃, 그 외에는 선형 — 올바르며, 이를 선언하는 것은 사용자의 몫이다. 자동 감지는 없다.

출력 격자는 다음과 같이 우선순위가 높은 것부터 정해진다 (Automatrix_CLI.py:191, :301).

  1. 합성 변환 → 기준 영상을 행렬의 경로에서 추측한다: matrix.replace("_transform.tfm", ".nii.gz"), 없으면 .nii. 버그가 아니다. ASO_CBCT는 <patient>_<add>_transform.tfm과 <patient>_<add>.nii.gz를 같은 폴더에 기록하므로, 행렬 옆의 방향 정렬된 스캔이 바로 올바른 격자다. 파일이 없으면 경고를 내고 입력 영상으로 대체한다.
  2. 행렬 이름에 mirror가 들어 있음(대소문자 무시) → 기준 영상이 입력 영상으로 강제되고, UI의 기준 파일은 무시된다. 파일 이름에 따른 분기다.
  3. 기준 파일 제공됨(reference_file != "None", 이 필드의 기본값, AutoMatrix.ui:255) → 그 기하가 모든 출력에 적용된다.
  4. 그 외에는 입력 영상 자체: 크기, 간격, 원점, 방향이 그대로다. 변환으로 내용이 촬영 범위 밖으로 밀려나면 사라지고, 그 자리는 DefaultPixelValue = 0으로 채워진다.
확인된 버그

reference is None 분기(ResampleImage 안, Automatrix_CLI.py:215)는 도달할 수 없다 — 호출자가 항상 기준 영상을 넘긴다. 게다가 틀렸다. new_origin = transform.TransformPoint(image.GetOrigin())를 계산하는데, 리샘플러의 규약대로라면 T⁻¹를 써야 한다.

7. Mirror 모드

Mirror()(AutoMatrix.py:304)는 개인 GitHub 릴리스에서 Mirror.zip을 내려받아 (GaelleLeroux/DCBIA_Apply_matrix) <Documents>/SlicerDownloads/Mirror_matrix/에 압축을 풀고, 행렬 필드를 Mirror/Matrix_mirror.tfm으로 채운다. 파일의 실제 내용:

#Insight Transform File V1.0
Transform: AffineTransform_double_3_3
Parameters: -1 0 0 0 1 0 0 0 1 0 0 0
FixedParameters: 0 0 0
함정

이는 원점을 중심으로 한 LPS의 diag(-1, 1, 1), 즉 평면 x_LPS = 0에 대한 반사다. x_LPS는 환자의 왼쪽을 향하므로 좌우 반전이 맞다 — 다만 환자 자신의 시상면이 아니라 월드 좌표계 원점의 시상면에 대한 반전이다. 중앙에 있지 않은 환자는 반전과 함께 평행이동까지 되어 나오며, 이는 이후 정합에서 보정해야 한다.

행렬식은 −1이다. 볼륨에서는 ResampleImageFilter가 이를 문제없이 처리한다. 메시라면 면의 방향과 법선이 뒤집히겠지만, 메시는 더 이상 처리되지 않으므로 여기서는 의미 없는 이야기다.

이 모드는 ComboBoxMatrix를 "File"로, 접미사를 _mir로 강제하고, checkBoxMatrixName의 체크를 해제한다.

8. 파일 ↔ 행렬 짝짓기

GetPatients(Automatrix_CLI.py:60)는 {patient_key: {'scan': [...], 'matrix': [...]}}를 만든다. 키는 .split() 호출의 연쇄로 얻는데, 이 연쇄는 양쪽이 같지 않다.

제거되는 토큰 (순서대로)
scan_Seg _seg _Scan _scan _Or _OR _MAND _MD _MAX _MX _CB _lm _T2 _T1 _Cl _MR, 다음 .split('.')[0], 다음 _T0…_T49
matrix_SegOr _Left _left _Right _right _Or _OR _MAND _MD _MAX _MX _CB _lm _T2 _T1 _Cl _MA _Mir _mir _Mirror _mirror _MR, 다음 .split('.')[0], 다음 _T0…_T49
함정

두 목록은 다르다. 행렬 쪽은 _MA, _Left/_Right, _Mir와 _SegOr 변형을 제거하고, 스캔 쪽은 _Seg, _Scan, _lm을 제거한다. 그래서 README의 요구 사항이 있다: 환자 이름을 먼저, 이어서 밑줄, 그 뒤에 나머지. 예시 patient1_T1_MA.nii.gz ↔ patient1_left_MA.tfm이 동작하는 것은 스캔 쪽에서 _T1이, 행렬 쪽에서 _left가 잘리기 때문이다. 그러나 시점 표시가 없는 patient1_MA.nii.gz는 스캔 쪽에서 키 patient1_MA를, 행렬 쪽에서는 patient1을 준다. 어떤 행렬도 짝지어지지 않으며, 메시지도 없다.

행렬 경로가 폴더가 아니라 파일이면, 그 행렬이 모든 환자에게 붙는다(Automatrix_CLI.py:167).

확인된 버그

중복된 코드가 이미 서로 달라졌다. GetPatients는 토큰 하나만 빼고 똑같은 복사본 두 개로 존재한다. CLI 버전은 맨 앞의 _SegOr를 제거하지만 General_tools.py:249는 그렇지 않다. 그리고 General_tools 복사본이 NbScan에 값을 공급하므로, 진행 표시줄의 분모가 실제로 처리된 파일 수와 다를 수 있다.

확인된 버그

세 가지 문제, 모두 확인 가능:

  1. _L과 _U가 뒤바뀌어 있다. 저장소의 나머지 부분에서 쓰는 규약과 반대다. AREG_IOS/dataset.py:231과 AREG/IOS.py:122는 Lower = ["Lower", "_L", "L_", "Mandibule", "Md"]와 Upper = ["Upper", "_U", "U_", "Maxilla", "Mx"]를 정의한다. 여기서는 _L이 Maxilla를, _U가 Mandible을 가리킨다.
  2. matrix_lineEdit는 존재하지 않는다. CLI의 argparse (Automatrix_CLI.py:329: 인자는 input_patient, input_matrix, reference_file, suffix, matrix_name, fromAreg, output_folder, log_path, is_seg)에 없다. 따라서 이 분기는 타는 즉시 AttributeError를 일으킨다.
  3. 이 분기는 결코 타지 않는다. CheckBoxSuffixBased("From AReg" 라벨)는 setup에서 self.ui.CheckBoxSuffixBased.setVisible(False)로 숨겨지므로 (AutoMatrix.py:296) fromAreg는 항상 "False"다. 사용되지 않는 코드다 — 1과 2가 한 번도 눈에 띄지 않은 이유다.

그래도 MAXReg_matrix.tfm이라는 이름은 AREG_CBCT의 실제와 맞다. AREG_CBCT는 patient + "_" + reg_type + add_name + "_matrix.tfm"을 기록하며, add_name의 기본값은 Reg다(AREG.ui:571). 따라서 이 경로는 다른 모듈에 속한 편집 가능한 텍스트 필드의 기본값에 의존한다.

9. 출력

matrix_suffix = f"_{Path(matrix).stem}" if args.matrix_name == "True" else ""
out_suffix    = f"{args.suffix}{matrix_suffix}"
out_file      = outpath.split(extension_scan)[0] + out_suffix + extension_scan

입력 디렉터리 트리가 출력 폴더에 재현된다 (scan.replace(input_patient, output_folder)). 기본 접미사는 _apply, checkBoxMatrixName은 기본으로 체크되어 있다 (AutoMatrix.ui:342).

함정

README는 이 점에서 낡았다. README는 patient1_T1_MA_apply_matrix1.nii.gz를 안내한다. 이전 버전은 행렬 이름에서 환자 키 뒤에 오는 부분을 추출했지만(basename.split(ext)[0].split(key)[1]), CLI는 전체 Path(matrix).stem을 쓴다. 따라서 patient1_MAXReg_matrix.tfm에 대한 실제 출력은 patient1_T1_MA_apply_patient1_MAXReg_matrix.nii.gz다.

함정

환자당 행렬이 여러 개일 때 "Add matrix name"의 체크를 해제하면 출력이 서로 덮어쓴다. 모든 행렬에 대해 파일 이름이 같기 때문이다.

.tfm은 결코 생성되지 않는다. AutoMatrix는 변환을 소비할 뿐, 기록하지 않는다.

11. 실행 환경

설치할 것이 없다. SimpleITK, numpy, vtk, qt는 이미 Slicer에 있다. conda도 CUDA도 없다. 유일한 네트워크 접근은 미러 행렬 다운로드이며, Mirror 체크박스를 체크했을 때만 일어난다.

확인된 버그

log_path 파라미터가 있음에도 진행 표시줄은 로그 파일로부터 값을 받지 않는다. DisplayAutomatrix.isProgress (Progress.py:39)는 log_path의 mtime을 확인하지만 CLI는 그 파일에 전혀 기록하지 않는다. 진행률은 실제로는 CLI가 스캔마다 내보내는 <filter-progress>0 / 2 / 0</filter-progress> 시퀀스 (Automatrix_CLI.py:314)와 if kwds["progress"] == 200(isProgress 안)를 거친다. 각 print 사이의 time.sleep(0.2)에 의존하는 간접적이고 취약한 프로토콜이다.

12. 함정과 취약 지점

요약
  • .npy는 동작하지 않는다(§3). UI와 README가 내세우는데도 그렇다.
  • 메시는 더 이상 동작하지 않는다(§5). UI와 README가 내세우는데도 그렇다. 커밋 7bc362b에서 생긴 회귀.
  • .txt는 원시 4×4 행렬을 받지 않는다(§3). ITK의 텍스트 형식만 받는다.
  • 랜드마크의 coordinateSystem을 전혀 읽지 않는다(§4.2).
  • 합성 없음: 한 환자에 행렬 N개면 연쇄가 아니라 파일 N개가 나온다(§4.3).
  • 출력 덮어쓰기: 행렬이 여러 개인데 checkBoxMatrixName의 체크를 해제한 경우(§9).
  • OnEndProcess가 self.nb_scans로 나눈다(AutoMatrix.py:953). 보호 장치가 없어, 입력 폴더가 비어 있으면 처리가 끝날 때 ZeroDivisionError가 난다.
  • CheckGoodEntre는 논리적으로 틀렸다(AutoMatrix.py:1013). 확장자 검사가 len(dico['.vtk'])==0 and len(dico['.vtp']) and len(dico['.stl']) and …인데, 비교인 것은 첫 항뿐이다. 나머지는 불리언으로 평가되는 정수이므로 "Folder empty or wrong type" 경고는 일어나기 힘든 조합에서만 뜬다. 정말로 빈 폴더는 검증을 통과한다.
  • onPredictButton은 오류가 나도 멈추지 않는다. TestProcess가 튜플 (ok, out)을 반환하므로 isinstance(error, str) 검사(AutoMatrix.py:766)는 항상 거짓이고, 필드가 비어 있어도 처리가 시작된다.
  • .split(extension_scan)[0]은 첫 번째 출현 위치에서 자른다. 폴더 이름에 확장자와 같은 부분 문자열이 들어 있는 경로는 잘려 버린다.
  • defined가 아닌 랜드마크는 이전 좌표계에 남아, 같은 파일 안에서 변환된 점과 섞인다(§5).
  • "From AReg" 경로는 사용되지 않으며 고장 나 있다(§8).
  • 사용되지 않는 코드: 위젯의 saveOutput / UpdateProgressBar / UpdateTime, AutoMatrixLogic.process, ResampleImage의 reference is None 분기, registerSampleData(존재하지 않는 .png 파일을 참조).
  • Automatrix_CLI.xml의 메타데이터는 여전히 Slicer 템플릿 그대로다(FirstName LastName (Institution), NIH grant NXNNXXNNNNNN-NNXN).

13. 문헌

AutoMatrix를 다룬 논문은 없다. 연구실을 위해 작성된 일괄 적용 유틸리티다 (Gaëlle Leroux, UoM/DCBIA). 과학적 내용은 전적으로 행렬을 생성하는 모듈들 — AREG, ASO, MRI2CBCT, FlexReg — 에 있으며, 각 모듈의 페이지에서 다룬다.

변환 규약에 관해 최신 참고 자료는 논문이 아니라 ITK / Slicer 문서다.

  • Transforms — Slicer user guide (fixed→moving 방향, Slicer의 RAS 대 ITK의 LPS)
  • Coordinate systems — Slicer developer guide
  • SimpleITK — Transforms and Resampling
  • SlicerAutomatedDentalTools
  • DCBIA_Apply_matrix — 원래 저장소. README가 인용하는 미러 행렬과 테스트 세트를 아직 호스팅한다

전체 참고문헌: SOURCES.html — 검색은 했으나 결과는 없다. AutoMatrix를 설명하거나 인용한 문헌은 없다. 받아 둘 자료가 없으므로 이 폴더에 받아 둔 것도 없다.

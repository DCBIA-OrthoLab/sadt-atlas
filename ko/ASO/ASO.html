ASO

CBCT 또는 구강 스캔을 기준 증례("gold")의 좌표계로 가져오는 강체 회전을 찾는다. 3점 초기화 후 ICP를 적용하는 방식이며, 최소제곱 최적 정합은 한 번도 쓰지 않는다.

1. 파이프라인에서의 위치

저장소 안에서 ASO를 호출하는 곳은 없다. 반면 ASO는 세 도구를 호출하며, AREG_IOS가 그 출력을 직접 사용한다. AREG_IOS.py:324는 T1과 T2 폴더에서 <patient>_SegOr.tfm을 찾는데, 이는 PRE_ASO_IOS.py:422가 쓰는 이름과 정확히 같다. 그리고 inv(areg_matrix @ inv(matrix_aso))를 합성해 원본 스캔에서 정합 결과까지 단일 행렬을 만든다.

3. 공통 기하학 원리

목표는 해석적 좌표계("교합평면 = z=0")가 아니라 릴리스에서 내려받는 기준 환자 증례다. CBCT는 스캔 + fiducial, IOS는 메시 두 개 + json 두 개다. 따라서 좌표계 선택은 데이터에 떠넘겨진다. Occlusal and Midsagittal Plane과 Frankfurt Horizontal and Midsagittal Plane (CBCT.py:68)은 서로 다른 두 gold이며, 같은 코드가 서로 다른 두 방향 정렬을 만든다.

두 백엔드 모두 추정은 같은 2단계 구조를 따른다.

  1. 3점 초기화: 평행이동 후, 손으로 구성한 축을 중심으로 두 번 회전한다. 최소제곱 Procrustes/Kabsch는 한 번도 쓰지 않는다.
  2. vtkIterativeClosestPointTransform을 RigidBody 모드로 기준점 점군에 적용해 정밀화한다.

기억할 점은 이것이다. 이 행렬은 N개 대응점에 대한 최소제곱 의미의 최적해가 아니다. 선택된 삼중점에서 연속 회전으로 만들고, 그다음 ICP로 다듬는데, 이 ICP는 점을 레이블이 아니라 최근접 이웃으로 다시 짝짓는다.

4.2 PRE_ASO_CBCT — 재중심화, 더 이상 신경망 없음 계산

이름과 인자 여섯 개에도 불구하고, 이 CLI는 이제 한 가지 일만 한다 (PRE_ASO_CBCT.py:163).

T = -np.array(img.TransformContinuousIndexToPhysicalPoint(np.array(img.GetSize()) / 2.0))
translation = sitk.TranslationTransform(3); translation.SetOffset(T.tolist())
img_trans = ResampleImage(img, translation.GetInverse())

ResampleImage는 크기(ratio = 1), 간격(spacing), 방향(direction)을 유지하고 new_origin = orig_origin - orig_center로 설정한다. 적용된 변환이 이 오프셋을 정확히 상쇄하므로 실제 보간은 일어나지 않는다. 물리적 원점만 이동하고, 볼륨은 월드 원점을 중심에 두게 된다. 이는 원점을 중심으로 회전을 적용하는 §4.4의 전제 조건이다.

인자 model_folder, SmallFOV, temp_folder는 파싱만 되고 쓰이지 않는다. PreASOResample (ResamplePreASO.py:199, 등방성 128³ 리샘플링)은 import되지만 호출되지 않으며, DenseNet (Net.py:39, 코사인 손실로 단위 방향 벡터를 회귀하는 3D monai DenseNet169)은 __init__.py에서 주석 처리되어 있다. ASO_CBCT에는 이제 사전 방향 정렬 신경망이 전혀 없다. 학습 코드는 남아 있고, PreASOModels.zip 가중치는 여전히 내려받아 검증되지만 (CBCT.py:133, TestModel은 .ckpt를 요구한다), 아무 쓸모가 없다.

출력: 원래 이름으로 저장된 재중심화 볼륨, 그리고 <name without extension>.tfm. 이 파일에는 평행이동 T가 역변환되지 않은 상태로 들어 있다. 볼륨에 실제로 적용된 것은 translation.GetInverse()인데도 그렇다.

확인된 버그

convertdicom2nifti(utils.py:504)는 sitk.ImageSeriesReader를 시도한 뒤 dicom2nifti로 대체한다. 이 대체 경로는 망가져 있다. search(output_folder, "nii.gz")를 호출하는데, search (utils.py:189)는 def search(self, path, *args)로 선언되어 있다. 첫 인자가 self에 흡수되고, args는 비어 있으며, 반환된 dict도 비어 있어 ["nii.gz"] 접근이 KeyError를 일으킨다.

4.3 ALI_CBCT — 랜드마크 공급원 예측

임시 폴더를 입력과 출력 모두로 지정해 호출하며, 상수는 하드코딩되어 있다 (CBCT.py:515): spacing="[1,0.3]", speed_per_scale="[1,1]", agent_FOV="[64,64,64]", spawn_radius="10", 그리고 lm_type(format_lm_string이 Python 리스트 리터럴로 다시 포맷함, CBCT.py:481). ALI_CBCT는 2단계 스케일의 탐색 에이전트 시스템이다(1 mm 후 0.3 mm, 에이전트 주변 64³ 복셀의 FOV). 해부학적 그룹마다 json 하나, <id>_lm_Pred_<group>.mrk.json (environment.py:138)을 LPS로 쓴다. 가중치는 <Landmark>_Net*.pth 파일로, 랜드마크마다 하나씩 ALI_CBCT/releases/download/models_v01/<LM>.zip에서 내려받는다.

SEMI_ASO_CBCT의 첫 호출인 MergeJson (utils.py:65)의 존재 이유가 바로 이것이다. 그룹별 json을 하나의 <patient>_lm_MERGED.mrk.json으로 다시 붙이고, 원본 파일을 삭제한다(os.remove).

4.4 SEMI_ASO_CBCT — 방향 정렬 계산

a) 이상치 랜드마크 제거. GetLandmarkToRemove (utils.py:413)는 스캔의 모든 랜드마크와 gold의 모든 랜드마크 사이의 전체 거리 행렬과 방향 행렬을 비교한다. 실제 상수: 거리 차이 > 15 mm, 각도 차이 > 0.4 rad(< 0.1 rad이면 -1, 즉 매우 일관된 쌍이 의심스러운 쌍을 상쇄한다). 전체 카운트가 랜드마크 수를 넘거나, 각도 카운트만으로 그 절반을 넘으면 랜드마크를 버린다. 분석 대상은 체크된 것만이 아니라 json의 모든 랜드마크다.

b) 최적 삼중점. FindOptimalLandmarks (utils.py:161)는 삼중점 (A, B, C)를 무작위로 뽑아 각각 초기화를 실행하고, 최종 평균 거리를 최소화하는 것을 남긴다. 상한: 서로 다른 삼중점 n(n-1)(n-2)개 또는 2500회 추출 중 먼저 도달하는 쪽.

c) 초기화, InitICP (utils.py:649):

  1. A_source를 A_target으로 옮기는 평행이동;
  2. 축 cross(v2, v1)을 중심으로 내적의 arccos 각도만큼 회전. 여기서 소스 쪽은 v1 = abs(B - A), 타깃 쪽은 v2 = abs(B - A)다. 성분별 절댓값이므로 두 벡터가 양의 팔분공간(octant)으로 접히며, 실제 벡터 사이의 각도가 아니다;
  3. 세 번째 회전. 그 축은 abs(B - A) 자체이며 외적이 아니다. 방금 정렬한 축을 중심으로 한 롤(roll) 회전이고, 각도는 C로부터 계산한다.

RotationMatrix(utils.py:921)는 쿼터니언 기반 Rodrigues 공식으로, FlexReg 및 ASO_IOS의 것과 동일하다. 핵심: TransformMatrix = RotationTransformMatrix # @ TranslationTransformMatrix. 1단계의 평행이동은 반환 행렬에서 의도적으로 제외된다. 평행이동은 회전 계산에만 쓰이고 볼륨을 움직이는 데는 쓰이지 않는다.

d) ICP. ICP_Transform(utils.py:620)은 두 딕셔너리를 정점 vtkPolyData로 변환하고 vtkIterativeClosestPointTransform을 실행한다: SetModeToRigidBody(), SetMaximumNumberOfIterations(1000), StartByMatchingCentroidsOn(). 이후 그 평행이동 성분은 0으로 지운다: TransformMatrixBis[:3, 3] = [0, 0, 0].

e) 합성. TransformList가 [translation, R2, R3, R_icp]를 누적한 뒤 (utils.py:803):

for i in range(len(TransformList) - 1, 0, -1):   # stops at 1: the translation is discarded
    TransformSITK.AddTransform(TransformList[i])
TransformSITKFinal = sitk.CompositeTransform(TransformSITK)
TransformSITKFinal.AddTransform(input_transform)   # the PRE_ASO .tfm
TransformSITKFinal = TransformSITKFinal.GetInverse()
TransformSITK = TransformSITK.GetInverse()

따라서 최종 결과는 월드 원점을 중심으로 한 순수 회전이다. PRE_ASO_CBCT가 볼륨을 그 원점에 중심 맞춤했기 때문에 일관성이 있다. 그리고 반자동 모드에 빠져 있는 것이 정확히 이 부분이다.

ResampleImage(utils.py:835)는 SetReferenceImage(image)를 호출한다. 같은 격자, 같은 크기, 같은 간격, 선형 보간, DefaultPixelValue = 0. 볼륨은 기존 상자 안에서 회전하며, 다른 해상도로 리샘플링되는 것은 없고, FOV 밖으로 나간 부분은 잃는다.

f) 출력: output_folder에 입력과 같은 상대 트리 구조로 기록된다.

파일내용
<patient>_<suffix>.nii.gz방향이 재정렬된 볼륨, 입력 형식과 관계없이 항상 .nii.gz
<patient>_lm_<suffix>.mrk.json회전된 랜드마크, WriteJson이 LPS로 기록
<patient>_<suffix>_transform.tfmTransformSITKFinal, ITK 규약(fixed → moving)

세 쓰기 모두 if not os.path.exists(...)로 보호된다. 비어 있지 않은 출력 폴더에 다시 실행하면 아무것도 다시 쓰지 않으며 그래도 성공으로 끝난다.

5. ASO_IOS

5.1 자동 모드 — 치관 중심점

a) 분할 우회. __BypassCrownseg__ (IOS.py:196)는 각 메시를 열어 PredictedID, UniversalID 또는 Universal_ID 배열을 찾는다. 이미 분할된 메시는 분할 단계의 출력 폴더로 바로 복사되며, 접미사 _Seg가 붙는다. 나머지는 분할을 위해 입력 폴더로 가며, 이때 특이한 형식은 .vtk로 변환된다.

b) DentalModelSeg 예측, conda 경유(IOS.py:275):

conda run -n shapeaxi python -m CrownSegmentationcli \
  None <csv> <out> 0 latest 0 Universal_ID 0 Seg <vtk_folder> <dentalmodelseg_path>

인자 순서: surf, input_csv, out, overwrite, model, crown_segmentation, array_name, fdi, suffix, vtk_folder, dentalmodelseg_path. overwrite = "0"이고 suffix = "Seg"다. FlexReg와 달리 ASO는 입력 파일을 덮어쓰지 않고, 임시 폴더에 <name>_Seg.vtk를 만든다. 신경망은 동일하며(멀티뷰 Fly-by-CNN, Universal_ID에 universal 1–32 번호), pip 패키지 shapeaxi에 포함되어 있다. latest의 구조와 가중치는 이 저장소만으로는 확인할 수 없다.

dentalmodelseg_path(Process에서 계산됨)는 사용되지 않는다. run_conda_tool (ASO.py:1417)이 이를 환경 안에서 실행한 which dentalmodelseg의 결과로 대체한다. if os.path.isfile(path_input) 분기(IOS.py:266)도 사용되지 않는다. path_input은 항상 os.makedirs로 만든 폴더이고, 게다가 이 분기는 존재하지 않는 self.input을 참조한다. path_preor는 생성되지만 쓰이지 않는다.

실행은 동기식이며 블로킹된다. run_conda_tool은 process.is_alive()를 반복 확인하면서 slicer.app.processEvents()를 호출하고, 로그를 다시 읽어 진행률을 추적한 다음, 큐에서 해당 단계를 제거한다. 그 후 onPredictButton이 다음 단계에 slicer.cli.run을 실행한다.

c) PrePreAso — 방향 정렬 계산, 핵심 부분 (pre_icp.py:103). organizeLandmark(pre_icp.py:43)는 선택된 치아 3개 또는 4개를 universal 번호 체계로 (left, middle(s), right)에 정렬한다. 상악 악궁(1–16)에서는 번호가 오른쪽에서 왼쪽으로 증가하므로 max → left이고, 하악 악궁(17–32)에서는 반대다.

vtkMeanTeeth(icp.py:415)는 각 Universal_ID를 가진 정점들의 평균을 낸다. 치아가 4개이면 가운데 두 중심점을 다시 평균하므로 → 항상 세 점으로 귀결된다.

make_vector는 각 삼중점에 대해 국소 기저를 만든다: normal = cross(m→d, m→g)(세 점을 지나는 평면의 법선), perpen = 오른쪽→왼쪽 방향, direction = cross(normal, perpen). 그다음:

  1. 축 cross(normal_source, normal_target)을 중심으로 각도 arccos(dot)만큼 회전. 스캔의 세 중심점이 이루는 평면을 gold의 평면에 맞춘다;
  2. direction_source를 이 행렬로 회전한 뒤, 축 cross(direction_source, direction_target)을 중심으로 한 두 번째 회전으로 평면 안의 롤을 고정한다;
  3. 두 삼중점의 중심점을 일치시키는 평행이동.

스케일 변환은 없다. 4×4 행렬이 변환된 메시와 함께 반환된다.

d) 정밀화. ICP([InitIcp(), vtkICP()], option=vtkMeanTeeth(dents)) (PRE_ASO_IOS.py:292). option은 연쇄 실행 전에 두 메시 모두에 적용된다. ICP는 3개 또는 4개의 중심점만 보며, 치관 형상은 전혀 보지 않는다. InitIcp (icp.py:136)는 ASO_CBCT의 InitICP의 클래스 버전이다. 같은 abs(), 같은 롤 축, 같은 2500회 추출의 FindOptimalLandmarks. vtkICP는 같은 강체 vtkIterativeClosestPointTransform이지만, 반복이 1000회가 아니라 100회이고 평행이동 성분을 지우지 않는다.

확인된 버그

눈에 띄는 세부 사항: InitIcp.__call__은 np.save로 source와 target을 ASO_IOS_utils/cache/에 저장하고, FindOptimalLandmarks는 메모리의 dict를 복사하는 대신 반복마다 .npy를 다시 읽는다. 변형(mutation) 문제를 피하는 우회책이지만, 그 대가로 모듈이 설치된 트리에 쓰기를 한다(두 .npy 파일은 한때 커밋되었다가 삭제되었다, 커밋 a334a10).

최종 행렬은 output_icp["matrix"] @ matrix다. PrePreAso 다음에 ICP.

5.2 반자동 모드 — 제공된 랜드마크 계산

SEMI_ASO_IOS.py. 같은 구조에서 option이 SelectKey(liste_de_landmarks)(icp.py:480)로 바뀐다. 랜드마크 딕셔너리에 대한 단순한 키 필터다. PrePreAso도, 분할도 없다. 이름이 지정된 랜드마크에 InitIcp 다음 vtkICP를 적용한다.

랜드마크 이름은 UI에서 데카르트 곱으로 만들어진다: {dent}{repère}, repère ∈ O, MB, DB(교합면) 또는 CB, CL, OIP, R, RIP (치경부). 그다음 listlandmark2diclandmark가 첫 글자 U/L만으로 악궁별로 나눈다(utils.py:272).

랜드마크로 얻은 행렬은 이후 전체 메시에 적용된다.

5.3 Occlusion(교합)

단일 악궁을 강제하는 체크박스다 (ASO.py:1850). 선택한 악궁이 방향 정렬을 결정하고, 교합 관계를 유지하기 위해 같은 행렬이 반대쪽 악궁에 적용된다(file[jaw.inv()], PRE_ASO_IOS.py:473). 상악/하악 짝짓기는 파일 이름으로 이루어지며, Files_vtk_link / Files_vtk_json_semilink (data_file.py)를 거친다. 인식되는 표시는 Upper/_U_와 Lower/_L_이다.

함정

UpperOrLower (utils.py:180)는 표시를 찾지 못하면 기본값으로 "Lower"를 반환한다. 이름이 잘못 붙은 파일은 조용히 하악으로 처리된다.

FlexReg_Method/orientation.py와 ASO_IOS_utils/pre_icp.py는 복사해 붙인 같은 알고리즘이다. make_vector는 한 글자도 다르지 않고, orientation()과 PrePreAso()의 본문은 세 가지에서만 다르다.

8. 실행 환경

서로 다른 두 체제가 있으며, 이것이 혼란의 원인이다.

CLI는 Slicer의 Python에서 실행된다. install_function (ASO.py:69)이 그곳에 없는 것을 pip_install한다: itk, torch==2.2.0, pytorch_lightning, dicom2nifti==2.6.2, pydicom==3.0.2, 그리고 monai 1.3.2(Python ≥ 3.10) 또는 그 외에는 0.7.0.

함정

torch, pytorch_lightning, monai는 Net.py와 ALI_CBCT에서만 쓰인다. 반자동 CBCT 모드와 IOS에서는 ASO가 이를 쓸데없이 설치하며, 다른 모듈의 torch 버전을 덮어쓸 위험이 있다(대화상자 자체가 "Doing it could break other modules"라고 말한다).

conda 환경은 자동 IOS 모드에서만 onCheckRequirements(ASO.py:1867)가 구성한다.

9. 함정과 취약 지점

확인된 버그

반자동 CBCT 모드는 현재 상태로는 망가져 있다. SEMI_ASO_CBCT.py:113은 data["tfm"]을 요구하는데, 이는 행렬 출력과 함께 커밋 1bfb51f에서 도입되었다. 이 .tfm은 PRE_ASO_CBCT가 쓰기 때문에만 존재한다. 그런데 반자동 모드는 PRE_ASO_CBCT를 실행하지 않고 사용자의 원본 폴더에서 작업한다. 결과: KeyError가 발생한다. 폴더에 .tfm이 아직 없는 모든 환자가 그렇다. 이 오류는 잡혀서 "missing required files"로 기록되며, 해당 환자는 다른 환자를 중단시키지 않은 채 실패로 집계된다. 따라서 이 모드는 스캔 옆에 우연히 .tfm이 있을 때만 동작한다. 대개 Fully 모드를 먼저 한 번 거친 뒤다. PRE_ASO_CBCT.py:217이 스캔 폴더에 자기 파일을 쓰기 때문이다. 확인됨: GetPatients (utils.py:1042)는 tfm 키를 입력 트리에 .tfm 파일이 있을 때만 채운다.

그리고 그 문제가 없더라도 반자동 모드에는 재중심화가 없다. 방향 정렬은 월드 원점을 중심으로 한 순수 회전이므로(§4.4e), 중심에서 벗어난 볼륨은 자기 FOV 밖으로 나가 DefaultPixelValue = 0이 된다.

확인된 버그

MergeJson은 입력 폴더의 파일을 삭제한다. 반자동 모드에서 input_dir는 사용자의 폴더다. 모든 .mrk.json 파일 중 이름에 MERGED가 없는 것은 병합된 뒤 지워진다 (utils.py:111).

함정

json의 좌표계는 한 번도 확인되지 않는다. LoadJsonLandmarks는 position을 그대로 읽는다. ALI와 ASO는 LPS로 쓰지만, Slicer에서 RAS로 내보낸 fiducial은 경고 없이 x와 y가 뒤집힌 채 읽힌다.

함정

최소 랜드마크 수가 일관되지 않다. UI는 체크된 랜드마크 3개를 요구하지만 (TestCheckbox, CBCT.py:85) ICP는 len(list_landmark) <= 3이면 바로 중단한다(utils.py:754). 따라서 실제로는 4개가 필요하고, 제거 단계에서 일부가 빠지면 더 필요하다.

  • ICP는 최근접 이웃으로 다시 짝짓는다. vtkIterativeClosestPointTransform은 레이블을 무시한다. 서로 가까운 랜드마크 쌍(좌/우 쌍)에서는 초기화가 이미 잘못 잡은 교차 짝짓기에 고착될 수 있다.
  • abs() 호출(InitICP 안). 두 백엔드 모두에서 각도 계산 전에 벡터가 양의 팔분공간으로 접힌다. 선택되는 삼중점은 측정 오차를 최소화하는 것이므로 탐색이 이를 보상한다. 그러나 이 단계의 기하를 따로 떼어 놓고 결론을 내려서는 안 된다.
함정

파일이 이미 있으면 아무것도 다시 쓰지 않는다. CBCT 출력 세 개 모두 if not os.path.exists로 보호된다. 매개변수를 고친 뒤 두 번째로 실행해도 눈에 보이는 효과가 없고 그래도 성공으로 끝난다.

확인된 버그

ASO와 AREG의 환자 식별자가 서로 다르다. PatientNumber(utils.py:295)는 _U/_L에서 자르는 반면, AREG_IOS는 이를 patient_id.split("_")[0]으로 다시 만든다(AREG_IOS.py:321). P01_T1_U.vtk 같은 이름은 한쪽에서는 P01_T1, 다른 쪽에서는 P01이 된다. ASO의 .tfm은 결코 찾아지지 않고, AREG는 logger.warning으로 넘어간다. 덧붙여 이 파일에는 PatientNumber 함수가 두 개 있으며, 229행의 것(첫 번째 숫자 그룹)은 295행의 것에 가려진다.

  • 사용되지 않는 코드: CBCT 쪽의 Net.py(DenseNet)와 PreASOResample, search(유령 self), DisplayALIIOS, Files_vtk_json_link, vtkMiddleTeeth, npSameNumberPoint(source.shape[0] < target.shape[0] 분기가 정의되지 않은 target_points를 참조함), 어디서도 참조되지 않는 고아 파일 LinearTransform_t.tfm.
  • PRE_ASO_CBCT의 .tfm은 역변환되지 않은 채 기록된다. 볼륨에 적용된 것은 그 역변환인데도 그렇다. 이후 SEMI_ASO_CBCT에서 합성된 뒤 한 덩어리로 역변환되므로, 이 파일을 단독으로 재사용하기 전에 확인할 필요가 있다.
  • 시점 접미사. PatientScanLandmark (CBCT.py:36)는 _T1/_T2에서만 자른다. _T3이면 짝짓기가 깨진다. 코드에 이미 그 주석이 있다.

10. 문헌

ASO_CBCT의 기준 논문은 Automated Orientation and Registration of Cone-Beam Computed Tomography Scans(Anchling, Hutin, Cevidanes et al., Lecture Notes in Computer Science, 2023)이다. 그 설명은 코드와 일치한다. ALI_CBCT가 입력 방향과 무관하게 랜드마크를 식별하고, 그다음 방향 정렬은 "무작위로 고른 랜드마크 3개를 먼저 정렬한 뒤 ICP로 정밀화하여" 얻는다. 보고된 오차: 전문가 대비 < 3°, < 2 mm. 논문은 DenseNet 사전 방향 정렬기를 언급하지 않는데, 이는 그것이 더 이상 연결되어 있지 않다는 사실과 부합한다.

ALI_CBCT 자체에 대해서는 Automatic landmark identification in cone-beam computed tomography(Gillot et al., Orthodontics & Craniofacial Research, 2023).

ASO_IOS에는 자체 논문이 없다. 가장 가까운 발표 문헌은 AReg IOS: Automatic Registration on IntraOral Scans(Hutin, Anchling, Cevidanes et al., LNCS 2023)로, 공유 치아 중심점을 이용한 초기 정렬, 즉 정확히 PrePreAso를 설명한다. 나머지(작업자의 치아 선택, 중심점 3개에 대한 ICP 정밀화, occlusion 모드)는 미발표 내부 개발이다.

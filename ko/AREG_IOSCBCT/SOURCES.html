AREG_IOSCBCT: 출처

이 모듈을 설명하는 논문은 없다. 발표된 것은 오케스트레이터가 CLI 앞에 쌓아 두는 상류 구성 요소들이다.

검증

시트가 그렇게 말했고, 검증이 이를 확인한다. Crossref도, OpenAlex도, Europe PMC도, arXiv도, HAL도, NA-MIC 프로젝트 주간 36부터 43까지도 이 그룹이 서명한, 등위면 위에서 교합 랜드마크 + ICP로 하는 IOS↔CBCT 정합에 관한 것을 담고 있지 않다. "Multimodal Registration"이라는 제목의 NA-MIC 프로젝트 둘(PW40 2024, PW41 2024)은 IOS↔CBCT가 아니라 MRI↔CBCT를 다룬다.

발표된 것은 오케스트레이터가 CLI 앞에 쌓아 두는 상류 구성 요소다. 볼륨 랜드마크를 위한 ALI_CBCT와 치관을 위한 DentalModelSeg다. CLI 자체(임계값 400에서 Procrustes + ICP + 마칭 큐브)에는 논문이 없다.

처음 넷은 파이프라인 자체가 아니라 파이프라인의 구성 요소다.

  • Gillot 2023은 볼륨 쪽 12개의 교합 랜드마크를 제공하는 ALI_CBCT를 설명한다(완전 자동 모드의 3단계와 7단계).
  • Fly-by-CNN과 이어서 DentalModelSeg는 CrownSegmentationcli를 설명하며, 이것이 IOS에 Universal_ID 배열을 설정한다. 여기서는 오직 ALI_IOS가 카메라를 치아별로 겨냥하게 하기 위한 것이다.
  • Anchling 2023은 CBCT 쪽의 AREG 논문이다. 같은 계열이고 같은 원본 저장소이지만 단일 모달 CBCT→CBCT 정합이다. 다중 모달의 경우는 설명하지 않는다.

마지막 둘은 주변 연구(아래 참조)이며, IOS↔CBCT 문제를 완전하고 자유롭게 읽을 수 있게 설명한 유일한 문헌이어서 여기에 둔다.

이웃

같은 문제를 다루지만 이 코드를 설명하지 않는 연구.

  • Kim 2023(2023_Kim_registration_CBCT_intraoral_scan.pdf): 같은 목표이지만 양쪽에 치아 분할이 있고, 이어서 RANSAC + ICP를 쓴다. 보고된 오차는 0.234 ± 0.019 mm다. AREG_IOSCBCT는 더 가벼운 길을 택한다. 체적 분할 대신 랜드마크, 분할된 치아 대신 임계값으로 만든 등위면이다.
  • Jang 2024(2024_Jang_CBCT_intraoral_impressions_integration.pdf): 치아별 식별과 인상의 스티칭 오차 보정. 완전히 학습 기반인 파이프라인이며 여기의 구현과는 무관하다.
  • Zheng 2025(위의 체계적 문헌 고찰): 일반적인 배경.
  • ALI_IOS는 메시 쪽 12개의 교합 랜드마크를 제공하며(8단계) 발표된 논문이 없다. 유일한 공개 설명은 NA-MIC Project Week 36(2022) 페이지 "ALIIOS, Automatic Landmarks Identification for Intra Oral Scans"(Baquero, Gillot, Cevidanes, Prieto)다. projectweek.na-mic.org이며, 이 페이지 자체도 어떤 참고문헌도 인용하지 않는다.

검색했으나 찾지 못한 것

Crossref, OpenAlex, Europe PMC, arXiv, HAL, Unpaywall에서 AREG / IOSCBCT / IOS-CBCT / 다중 모달 정합 + Cevidanes, Prieto, Anchling, Hutin, Leroux, Baquero의 모든 조합을 검색했고, NA-MIC Project Week 36 → 43 프로젝트 목록(두 "Multimodal Registration"은 MRI↔CBCT)과 표적 웹 검색도 했다. 이 저장소의 다중 모달 IOS↔CBCT 부분에 관한 것은 없었다.

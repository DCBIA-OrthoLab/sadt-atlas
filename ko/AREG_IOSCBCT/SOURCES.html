AREG_IOSCBCT — 출처

이 모듈을 기술하는 출판물은 없다. 출판된 것은 오케스트레이터가 CLI 앞에 쌓아 두는 상류 구성 요소들이다.

검증

문서가 그렇게 말했고, 검증 결과도 이를 확인한다. Crossref, OpenAlex, Europe PMC, arXiv, HAL, NA-MIC 프로젝트 위크 36~43 어디에도 이 그룹이 발표한, 교합 랜드마크 + ICP(등위면 대상)에 의한 IOS↔CBCT 정합은 없다. "Multimodal Registration"이라는 제목의 NA-MIC 프로젝트 두 개(PW40 2024, PW41 2024)는 IOS↔CBCT가 아니라 MRI↔CBCT를 다룬다.

출판된 것은 오케스트레이터가 CLI 앞에 쌓아 두는 상류 구성 요소들이다: 볼륨 랜드마크를 위한 ALI_CBCT, 치관을 위한 DentalModelSeg. CLI 자체(Procrustes + ICP + 임계값 400의 marching cubes)에 대한 논문은 없다.

처음 네 개는 파이프라인 자체가 아니라 파이프라인의 구성 요소다.

  • Gillot 2023은 볼륨 쪽에서 교합 랜드마크 12개를 공급하는 ALI_CBCT를 기술한다(Fully-Automated 모드의 3단계와 7단계);
  • Fly-by-CNN과 그 뒤의 DentalModelSeg는 CrownSegmentationcli를 기술한다. 이는 IOS에 Universal_ID 배열을 설정하며 — 여기서는 ALI_IOS가 치아별로 카메라를 조준하게 하는 용도뿐이다;
  • Anchling 2023은 CBCT 쪽 AREG 논문이다. 같은 계열, 같은 원본 저장소이지만, 단일 모달리티 CBCT→CBCT 정합이다. 다중 모달리티 경우는 기술하지 않는다.

마지막 두 개는 관련 연구(아래 참조)이며, IOS↔CBCT 문제에 대해 무료로 읽을 수 있는 유일한 완전한 기술이라서 여기에 보관했다.

관련 연구

같은 문제를 다루지만 이 코드를 기술하지는 않는 연구.

  • Kim 2023(2023_Kim_registration_CBCT_intraoral_scan.pdf): 같은 목표이지만, 치아 분할을 양쪽 모두 거친 뒤 RANSAC + ICP를 쓴다. 보고된 오차 0.234 ± 0.019 mm. AREG_IOSCBCT는 더 가벼운 길을 택한다. 볼륨 분할 대신 랜드마크, 분할된 치아 대신 임계값 등위면이다.
  • Jang 2024(2024_Jang_CBCT_intraoral_impressions_integration.pdf): 치아별 식별과 인상(impression)의 스티칭 오차 보정. 전부 학습 기반인 파이프라인이며, 여기의 구현과는 무관하다.
  • Zheng 2025(체계적 문헌고찰, 위 참조): 일반적 맥락.
  • 메시 쪽에서 교합 랜드마크 12개를 공급하는(8단계) ALI_IOS는 출판물이 없다. 유일한 공개 기술은 NA-MIC Project Week 36 (2022) 페이지 "ALIIOS — Automatic Landmarks Identification for Intra Oral Scans"(Baquero, Gillot, Cevidanes, Prieto)이다: projectweek.na-mic.org. 이 페이지 자체도 참고문헌을 인용하지 않는다.

검색했으나 찾지 못한 것

Crossref, OpenAlex, Europe PMC, arXiv, HAL, Unpaywall에서 AREG / IOSCBCT / IOS-CBCT / multimodal registration + Cevidanes, Prieto, Anchling, Hutin, Leroux, Baquero의 모든 조합을 검색했다. NA-MIC Project Week 36 → 43 프로젝트 목록도 훑었다("Multimodal Registration" 두 개는 MRI↔CBCT). 표적 웹 검색도 했다. 이 저장소의 다중 모달리티 IOS↔CBCT 부분에 대해서는 아무것도 없다.

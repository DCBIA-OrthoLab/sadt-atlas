SlicerAutomatedDentalTools: 각 도구의 동작 원리

도구마다 한 페이지이며, 파이프라인을 중심으로 구성됩니다. 무엇이 계산되는지, 무엇이 네트워크에 의해 예측되는지, 모델이 언제 호출되는지, 실제로 무엇을 하는지, 전처리는 무엇인지, 무엇이 나오는지를 다룹니다.

이것은 사용 설명서가 아닙니다. 코드 링크는 ~/Projects/UNC/slicer/SlicerAutomatedDentalTools 저장소를 가리킵니다.

코드베이스 둘: 레거시와 VISOR

아래에 나열된 도구 페이지는 레거시 Slicer 모듈(SlicerAutomatedDentalTools, 3c67957 시점, 2026-10-26)을 설명합니다. 팀은 도구를 VISOR로 옮기고 있습니다. 작업을 추론 서버로 보내는 Slicer 클라이언트이며, 각 도구는 서버에서 자체 Python 환경으로 실행됩니다.

따라서 각 모듈에는 최대 네 개의 페이지가 있다. 사이드바 맨 위에서 레거시 | VISOR 선택기가 세대를 고르고, 그 아래의 가이드 | 아틀라스 선택기가 사용자의 관점과 코드 중 하나를 고른다. 레거시 가이드, 레거시 아틀라스, VISOR 가이드, VISOR 아틀라스다. 전환해도 같은 도구에 머문다. 아래의 VISOR 페이지는 시스템이 어떻게 만들어졌는지 설명한다. 다른 언어는 지금으로서는 레거시 코드만 다룬다.

VISOR

개요VISOR가 무엇인지, 레거시와 VISOR의 비교, 어떤 도구가 이식되었는지, 이 조사를 읽은 커밋 아키텍처클라이언트와 서버, 도구 레지스트리와 스키마, 퍼사드, 호출 그래프 실행 한 번, 단계별로업로드, 접수, 실행, 진행 상황, 결과, 품질 관리 정지 패키징과 배포이미지, 도구마다 가상 환경 하나, 데이터, 설정, 벤치마크 보안과 개인정보현재 실행을 보호하는 것, 명세만 있는 것, 프로토타입으로만 존재하는 것 테스트와 출처도구를 테스트하고 이름 붙이고 레거시 코드까지 추적하는 방법 Crown_Seg치아 번호 매기기, VISOR에만 있는 도구 VISOR 사용하기(가이드)Slicer를 서버에 연결하고 도구 실행하기

시작 위치

체인의 맨 아래에서 맨 위로. 처음 두 단계는 나머지 모든 것이 의존하는 단계다.

#페이지왜 이것을 먼저 보는가
1FlexReg가장 단순하고 모든 것이 명시적이다. LPS/RAS 규약, 치관 분할, 패치 기반 ICP를 소개한다.
2ALI와 AMASSS다른 모든 것이 의존하는 두 랜드마크 공급원.
3ASO방향 맞추기, 대부분의 정합에 필요한 선행 조건.
4AREG_IOS 다음 AREG_CBCT정합 그 자체.
5VFACE체인에서 가장 위에 있다. 나머지를 모두 쌓아 올린다.

텍스트와 자연어

이들은 영상을 전혀 처리하지 않는다. 언어 모델을 실행하며, 앞의 셋은 임상 텍스트에 대해, 마지막 하나는 운영자의 요청에 대해 실행한다. 이름만으로는 알 수 없으므로 별도의 그룹으로 두었다.

도구가 아니라 스무 개 모듈이 import하는 코드다. 이제 모듈의 동작이 이 코드에 의존하므로 한 페이지로 다룬다.

읽다가 드러난 것

버그를 찾아다니다가가 아니라 문서화하는 도중에 발견했다. “verified” 열은 재현했거나 코드에서 직접 확인한 것과, 페이지가 보고하는 것이지만 아직 확인이 필요한 것을 구분한다.

공유되는 conda 환경

알아 둘 만한 결합

ALI, AREG, ASO, DOCShapeAXI, FlexReg는 Python 3.12의 같은 conda 환경 shapeaxi를 공유한다. Python 버전을 바꾸면 모두가 한꺼번에 깨진다. 자세한 내용은 FlexReg의 환경 절에 있다.

폴더 구성

도구마다 폴더 하나. 각 폴더에는 다음이 들어 있다.

  • <Tool>.html: 코드에서 읽어 낸 파이프라인.
  • SOURCES.html, 참고문헌: 여기에 보관된 것, 온라인에서 읽도록 의도된 것, 그리고 “이웃”(코드를 설명하지 않는 관련 연구).
  • 가져온 문서들. 출판사가 허용하는 경우 PDF로, 그렇지 않으면 .xml(JATS, 전문)로 보관하며 읽을 수 있는 .txt를 곁들인다.

원래의 .md 파일은 HTML 페이지 옆에 보관한다.

PDF 29개와 전문 54개이며 모두 검증했다. PDF는 쪽 번호가 있고 XML 파일은 본문을 담고 있다. 유료 장벽을 우회해서 얻은 것은 없다. arXiv, PLOS, PMC/NCBI, HAL, 기관 저장소, 저자 페이지, 저자가 올린 버전이다. 유료인 것은 DOI와 함께 링크로 제시한다.

출판사가 제공하지 않는 텍스트 가져오기

NIH에 보관된 저자 원고는 무료로 읽을 수 있지만 흔한 경로에는 잘 보이지 않는다. 시험해서 되는 방법은 다음과 같다.

curl -sL "https://eutils.ncbi.nlm.nih.gov/entrez/eutils/efetch.fcgi?db=pmc&id=<number without PMC>"

같은 논문에서 안 되는 것: pmc.ncbi.nlm.nih.gov/.../pdf/(봇 차단 HTML), Europe PMC의 fullTextXML(비어 있음), BioC API(오픈 액세스 부분집합만). 그리고 MDPI에서는 mdpi-res.com/d_attachment/...가 실제 PDF를 제공하는데, mdpi.com/.../pdf는 페이지를 돌려준다.

어디에도 발표되지 않은 것

Crossref, OpenAlex, Europe PMC, arXiv, HAL, NA-MIC 전체 트리에 대조해 확인했다. FlexReg와 그 MGL 트랙, ALI_IOS, AREG_IOSCBCT, CLIC, CNE, AutoCrop3D, AutoMatrix, MedicalDataAnonymizer, BatchDentalSeg의 세 변형, AMASSS의 nnU-Net 버전이다. 이 중 여럿은 NA-MIC Project Week 페이지가 존재하는 유일한 서면 설명이며, 해당 폴더에 보관되어 있다.

정적 사이트이며 외부 의존성이 없다. 이 폴더에서 python3 -m http.server로 서빙하거나 index.html을 직접 연다.

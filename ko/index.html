SlicerAutomatedDentalTools — 도구별 동작 방식

도구마다 한 페이지씩, 파이프라인을 중심으로 정리했다. 무엇이 계산되고 무엇을 신경망이 예측하는지, 모델이 언제 호출되고 실제로 무엇을 하는지, 전처리는 무엇이고, 무엇이 출력되는지.

사용자 매뉴얼이 아니다. 코드 링크는 ~/Projects/UNC/SlicerAutomatedDentalTools 저장소를 가리킨다.

어디서 시작할까

체인의 아래에서 위로. 처음 두 단계가 나머지 모두가 의존하는 것들이다.

#페이지먼저 읽는 이유
1FlexReg가장 단순하고 모든 것이 명시적이다. LPS/RAS 규약, 치관 분할, 패치 기반 ICP를 소개한다.
2ALI와 AMASSS나머지 모두가 의존하는 두 랜드마크 제공자.
3ASO방향 정렬. 대부분의 정합에 필요한 선행 단계.
4AREG_IOS 다음 AREG_CBCT정합 그 자체.
5VFACE체인의 가장 위: 다른 모든 것을 쌓아 올린다.

공통 구성 요소 세 가지

거의 모든 모듈이 같은 세 구성 요소 위에 서 있다. 이것들을 한 번 이해해 두면 다섯 페이지에 걸쳐 같은 메커니즘을 다시 읽지 않아도 된다.

전체 페이지

텍스트와 자연어

이 도구들은 영상을 전혀 처리하지 않는다. 언어 모델을 실행하는데, 앞의 셋은 임상 텍스트에 대해, 마지막 하나는 운영자의 요청에 대해 실행한다. 이름만으로는 알 수 없으므로 따로 묶어 두었다.

CNEClinical Notes Extraction — 임상 기록에서 정보 추출, 로컬 llama.cpp와 GGUF 모델 MedX보고서 요약(미세 조정된 로컬 BART-large-cnn)과 대시보드 MedicalDataAnonymizer텍스트 문서 비식별화(Presidio + spaCy) — DICOM 익명화 도구가 아니다 Agent자연어로 다른 모듈 실행하기

읽으면서 드러난 것

버그를 찾아다니다가가 아니라 문서화하다가 발견한 것들이다. "확인" 열은 코드에서 직접 재현하거나 확인한 것과, 페이지가 보고만 하고 아직 확인이 필요한 것을 구분한다.

위치증상확인
MedicalDataAnonymizeranonymize_text_presidio는 어떤 예외에서든 return text를 한다. _anonymized 파일에는 손대지 않은 텍스트가 들어가고, UI는 "Complete!"를 표시한다예, 한 줄씩 읽음
CLIC[SEG]/[PROGRESS] 표지가 접두사가 붙은 채 logger.info로 출력되는데, 읽는 쪽은 startswith로 검사한다. 분할이 Slicer에 결코 로드되지 않는다예
BatchDentalSegNasoMaxillaDentSeg: 이름 변경 목록의 순서가 어긋나, 마지막 4개 세그먼트가 잘못된 이름과 잘못된 색을 받는다예
AREG_CBCT · MRI2CBCTMatrixRetrieval이 CenterOfRotationPoint를 무시한다(저장소 전체에 없음). 출력 볼륨은 이 행렬로 다시 리샘플링되므로 .tfm과 영상 모두 elastix 결과에서 어긋난다예, 실제 증례로 측정 필요
MRI2CBCTinstall_function()이 존재하지 않는 패키지 nnunet_version==2.8.0을 요청한다(PyPI 404). 호출하는 7곳은 반환값을 무시한다예
ASOsemi-CBCT 모드는 PRE_ASO만 쓰는 .tfm을 요구한다. 폴더에 이미 .tfm이 있지 않으면 환자마다 실패한다예
AMASSS"small FOV"가 고장 나 있다(highDefinition이 .xml에 없음). DICOM 입력은 무시된다. temp_fold를 AREG, VFACE와 공유하며 무조건 rmtree한다보고됨
AutoMatrix.npy와 메시 지원을 내세우지만 7bc362b 이후로 읽을 수 없다에이전트가 테스트함
CNEOrtho 모델이 model-q4_0.gguf를 요청하지만, HF 저장소에는 model-q4_k_m.gguf만 있다(404)에이전트가 테스트함
DOCShapeAXICLI는 shapeaxi 1.0.x API에 맞춰 작성되었는데 install_pytorch는 >=2.0.2를 설치한다보고됨
Agentresolve_tool_path는 저장소에 없는 CLI files 폴더를 찾는다. 시그니처 23개 중 17개가 실제 argparse와 맞지 않는다보고됨
SurgMovPredpip_install("numpy==2.4.0")을 Apply할 때마다 무조건 실행한다보고됨
VFACEINPUT_KEYS가 inputVolume / t1_folder / input_path를 포함하지 않는다. 선택적 롤백이 느린 단계들을 배치 전체에 다시 실행한다보고됨

공유 conda 환경

알아 둘 만한 결합

ALI, AREG, ASO, DOCShapeAXI, FlexReg는 같은 conda 환경 shapeaxi를 Python 3.12에서 공유한다. Python 버전을 바꾸면 모두가 한꺼번에 깨진다. 자세한 내용은 FlexReg의 실행 환경 절에 있다.

폴더 구성

도구마다 폴더 하나. 각 폴더에는 다음이 있다:

  • <Tool>.html — 코드에서 읽어 낸 파이프라인;
  • SOURCES.html — 참고문헌: 여기에 받아 둔 것, 온라인으로 읽어야 할 것, 그리고 "주변"(코드를 설명하지 않는 관련 연구);
  • 확보한 문헌. 출판사가 허용하면 PDF로, 그렇지 않으면 .xml (JATS 전문)과 그 옆의 읽기 쉬운 .txt로.

원본 .md 파일은 HTML 페이지 옆에 보관되어 있다.

PDF 29개와 전문 54개, 모두 확인했다. PDF는 쪽 번호가 있고, XML 파일에는 본문이 들어 있다. 유료 벽을 우회해서 얻은 것은 없다 — arXiv, PLOS, PMC/NCBI, HAL, 기관 저장소, 저자 페이지, 저자 기탁본에서 얻었다. 유료인 것은 DOI와 함께 링크로 제시한다.

출판사가 제공하지 않는 텍스트 받기

NIH에 기탁된 저자 원고는 무료로 읽을 수 있지만 일반적인 경로로는 보이지 않는 경우가 많다. 시험해 보고 효과가 있었던 방법:

curl -sL "https://eutils.ncbi.nlm.nih.gov/entrez/eutils/efetch.fcgi?db=pmc&id=<number without PMC>"

같은 논문에서 실패하는 방법: pmc.ncbi.nlm.nih.gov/.../pdf/(봇 차단 HTML), Europe PMC의 fullTextXML(빈 결과), BioC API(open access subset만). 그리고 MDPI의 경우, mdpi-res.com/d_attachment/...는 실제 PDF를 제공한다. mdpi.com/.../pdf는 웹 페이지를 반환한다.

어디에도 출판되지 않은 것

Crossref, OpenAlex, Europe PMC, arXiv, HAL, 그리고 NA-MIC 전체 트리에서 확인했다: FlexReg와 그 MGL 경로, ALI_IOS, AREG_IOSCBCT, CLIC, CNE, AutoCrop3D, AutoMatrix, MedicalDataAnonymizer, BatchDentalSeg의 세 변형, 그리고 AMASSS의 nnU-Net 버전. 이 중 여러 도구는 NA-MIC Project Week 페이지가 존재하는 유일한 서면 설명이며, 해당 폴더에 받아 두었다.

외부 의존성이 없는 정적 사이트. 이 폴더에서 python3 -m http.server로 제공하거나, index.html을 직접 연다.

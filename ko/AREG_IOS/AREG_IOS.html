AREG_IOS

안정 영역으로 제한한 ICP로 구강 스캔(IOS)의 T1/T2 종단 정합을 수행한다. 안정 영역은 신경망이 예측한 구개 패치(Butterfly)이거나, 예측된 랜드마크로부터 계산한 치은-치조 점막 경계 띠(MGL)이며, 폴더 단위로 일괄 처리한다.

Hutin 2023 · LNCS 14350 AREG_IOS conda 환경: shapeaxi 참고문헌

구강 스캔의 T1/T2 종단 정합. 원리는 FlexReg.md와 같다(안정 영역으로 제한한 강체 ICP). 다만 영역을 사용자가 그리는 대신 신경망이 예측하며, 처리는 환자 단위가 아니라 폴더 단위 일괄 처리로 진행된다.

같은 CLI 안에 두 모드가 공존한다:

  • Butterfly — 상악궁. 다중 시점 MonaiUNetHRes가 구개 패치를 예측한다;
  • MGL — 하악궁. ALI_IOS가 예측한 MG 랜드마크 13개로 만든, 치은-치조 점막 경계선(mucogingival line) 주변의 측지선(geodesic) 띠. FlexReg의 MGL 경로와 같은 코드를 CLI에 복사한 것이다.

1. 파이프라인에서의 위치

AREG_IOS는 CLI다. 저장소 안에서 이를 호출하는 것은 AREG 모듈뿐이며, AREG/AREG_Method/IOS.py를 거친다. AREG_IOS 자체는 다른 모듈을 호출하지 않는다. 필요한 것(분할, 방향 정렬, 랜드마크)은 모두 오케스트레이터가 그 앞에 쌓아 두는 단계들이 상류에서 만들어 낸다.

AREG 모드AREG_IOS 앞에 쌓이는 단계출처
Auto_IOS / ButterflyCrownSegmentationcli T1과 T2 → PRE_ASO_IOS T1과 T2AREG/AREG_Method/IOS.py:594
Semi_IOS / Butterfly없음: 스캔에 이미 Universal_ID가 있고 방향 정렬이 되어 있어야 한다AREG/AREG_Method/IOS.py:743
Auto_IOS / MGLCrownSegmentationcli T1과 T2 → ALI_IOS T1과 T2AREG/AREG_Method/IOS.py:40

Butterfly/MGL 선택은 위젯의 콤보 박스 (AREG/AREG.py:660)로 하며, isMGLRegistration() (AREG/AREG.py:753)이 읽어 reg_type으로 넘긴다.

개념상 상류에서, FlexReg도 정확히 같은 입력을 만든다: Butterfly 또는 Bottom_MGL이라는 이름의 0/1 점 배열이다. FlexReg에서 손으로 패치를 그린 스캔은 그대로 AREG_IOS의 ICP로 넘어갈 수 있다.

conda run -n shapeaxi python -m AREG_IOS "<T1>" "<T2>" "<output>" "<model>" \

값은 매개변수 딕셔너리의 반복 순서대로 덧붙여진다. 그래서 AREG/AREG_Method/IOS.py에 "Key order matters"(키 순서가 중요함) 주석이 있다. 모듈을 찾을 수 있는 것은 give_pythonpath_windows()(AREG/AREG.py:3190)가 Slicer의 searchPaths를 conda 환경의 PYTHONPATH에 밀어 넣기 때문이다.

함정

결과적으로 AREG_IOS/AREG_IOS.xml은 죽은 파일이다. 매개변수를 7개만 선언하고, 인덱스 4를 건너뛰며, reg_type, patch_radius, lm_T1, lm_T2를 무시한다. 유일한 용도는 오케스트레이터가 모듈 객체를 참조할 수 있도록 slicer.modules.areg_ios를 등록하는 것이다.

3. 입력과 전처리

3.1 T1/T2 짝 맞추기

Sort()(AREG_IOS/AREG_IOS_utils/dataset.py:98)와 sort()(AREG_IOS/AREG_IOS_utils/dataset.py:267):

  2. 파일은 부분 문자열 검색으로 Upper/Lower로 분류된다: ["Lower","_L","L_","Mandibule","Md"]와 ["Upper","_U","U_","Maxilla","Mx"];
  3. 짝 맞추기는 파일 기본 이름에서 T1 / T2 부분 문자열을 글자 그대로 떼어 내고 남은 부분을 비교하는 방식이다;
  4. 같은 환자의 Upper↔Lower 대응은 Upper/Lower라는 단어까지 추가로 떼어 내고 비교해서 찾는다.
함정

협상 불가능한 가정: 이름에 T1 또는 T2가 글자 그대로 들어 있고, 악궁 표시도 들어 있어야 한다. _T4는 어떤 것과도 짝지어지지 않는다 (TIMEPOINT-SUFFIX 주석(AREG_IOS/AREG_IOS.py:318)이 AREG_CBCT/AREG_CBCT_utils/utils.py:83의 중심 메모를 가리킨다).

SortLower()(AREG_IOS/AREG_IOS_utils/dataset.py:173)는 MGL 변형이다. 재귀 glob(**/*)을 쓰는데, CrownSegmentationcli가 csv 이름을 딴 하위 폴더(liste_csv_file_T1_Seg)에 쓰기 때문이다. 또한 대응하는 상악 쌍을 요구하지 않고 하악궁만으로 짝을 맞춘다.

3.2 표준 방향 정렬 (Butterfly 전용)

DatasetPatch.__getitem__(AREG_IOS/AREG_IOS_utils/dataset.py:39)은 orientation()(AREG_IOS/AREG_IOS_utils/orientation.py:42)을 목표 [[-0.5,-0.5,0], [0,0,0], [0.5,-0.5,0]]와 치아 ["3","8","9","14"] = UR6, UR1, UL1, UL6으로 호출한다.

FlexReg.md §3과 같은 알고리즘(연속된 두 번의 Rodrigues 회전 + 평행 이동)이지만, 다른 랜드마크를 쓴다. FlexReg는 3, 5, 12, 14(UR6, UR4, UL4, UL6)를 쓰고, AREG_IOS는 대구치와 중절치를 쓰며, 두 중절치 중심점의 평균으로 중점을 얻는다. 결과는 같은 종류다: 교합평면 ≈ z=0, +y 전방, +x 환자의 왼쪽.

좌표계는 x = 환자의 왼쪽, y = 전방인 오른손 좌표계이므로, 상악에서 z = x × y는 아래쪽을 향한다. 따라서 z ≈ +0.9에 놓인 카메라 7대는 악궁을 교합면 쪽에서, 즉 구개 쪽에서 바라본다. (목표값에서 이끌어 낸 기하학적 추론이며, 코드가 주장하는 바는 아니다.)

함정

방향 정렬이 실패해도 예측은 멈추지 않는다. NoSegmentationSurf와 ToothNoExist가 잡히면 경고가 기록되고, 신경망은 스캔을 있는 그대로 두고 실행된다. 오류 메시지에는 "UR6, UR1, UL1 or UR6"라고 적혀 있는데, 오타이며 UL6이어야 한다.

3.3 정규화

ScaleSurf()(AREG_IOS/AREG_IOS_utils/transformation.py:181)는 경계 상자 중심으로 다시 중심을 맞추고 scale = 1 / ||bounds_max − center||를 적용한다. 이어서 ComputeNormals(점 법선, SplittingOff. 이것은 필수다. 그렇지 않으면 정점의 순서와 개수가 바뀐다).

이름과 달리 CN("color normal")은 실제로 정점별 색이다. GetColorArray(AREG_IOS/AREG_IOS_utils/utils.py:83)는 셀이 아니라 점을 순회한다. 0–255 정수를 거치는 왕복 변환은 법선을 8비트로 양자화한다. 의도된 것이며, 학습 때도 같은 것을 보았다.

중요한 점

신경망에는 방향 정렬·정규화된 표면이 입력되지만, 레이블 배열은 원래의 표면에 쓰인다 (dataset.getUpperSurf(idx, time)로 따로 읽음). 둘은 정점 순서가 같으므로 인덱싱은 유효하며, ICP는 표준 좌표계가 아니라 입력 파일의 좌표에서 실행된다.

4.2 다중 시점 렌더링

setup_ico_verts()(AREG_IOS/AREG_IOS_utils/net.py:114) — 카메라 위치 7개. ico_verts라는 이름과 달리 정이십면체 구(icosphere)가 아니다:

7개의 점이 z = 0.9에 모여 있고, 모두 원점을 바라본다 (look_at_rotation, T = -Rᵀ·C). 구 위를 도는 방식이 아니다. fly-by를 쓰는 DentalModelSeg나 ALI와 다르다. 교합면 단일 시점을 일곱 번 살짝 옮긴 것으로, 직전에 스캔을 표준 좌표계에 놓아 두었기 때문에만 의미가 있다.

4.3 2D 예측에서 정점별 레이블로

AREG_IOS/AREG_IOS_utils/PredPatch.py:36:

x, X, PF = self.model((V, F, CN))
x = self.softmax(x * (PF >= 0))          # softmax dim=2, over the 2 channels
P_faces = torch.zeros(2, F.shape[1])
for pf, pred in zip(PF.squeeze(), x.squeeze(0)):   # loop over the 7 views
    P_faces[:, pf] += pred
P_faces = torch.argmax(P_faces, dim=0)
V_labels_prediction[F[0, :, 0]] = P_faces

이해해야 할 세 가지:

  1. 배경 마스크. x * (PF >= 0)은 빈 픽셀의 로짓을 0으로 만든다. 소프트맥스 후에는 0이 아니라 (0.5, 0.5)가 된다. 따라서 두 클래스에 반 표씩 기여하며, 이는 argmax에서 상쇄되지만 실제 표를 희석한다. 인덱스가 -1인 면(배경)은 P_faces[:, -1], 즉 메시의 마지막 면에 쓰이며, 결국 이 면이 그 잡음을 떠안는다.
  2. 누적이 실제로는 누적되지 않는다. P_faces[:, pf] += pred는 index_put_이며 accumulate=True가 없다. 같은 시점의 여러 픽셀이 같은 면에 떨어지면(면 하나가 여러 픽셀을 덮으므로 일반적인 경우다), 기여 하나만 살아남으며, 어느 것이 남을지는 비결정적이다. 반면 7개 시점에 걸친 합은 제대로 동작한다(Python 루프의 별개 반복 7번).
  3. 면 → 정점 투표가 퇴화되어 있다. V_labels_prediction[F[0,:,0]] = P_faces는 각 삼각형의 첫 번째 정점에만 쓴다. 자기 면 목록에서 한 번도 0번 위치에 오지 않는 정점은 0으로 남는다. 따라서 패치는 구조적으로 구멍투성이로 나오며, 이를 고치는 것이 형태학적 후처리다. 미관상의 다듬기가 아니다.
확인된 버그

위 세 가지는 추측이 아니라 코드에 관한 사실이다. 배경 마스크는 argmax 결과를 바꾸지 않은 채 실제 표를 희석하고, index_put_ 누적은 accumulate=True가 없어 기여를 잃으며, 투표는 F[:,0]에만 써서 패치를 구조적으로 구멍투성이로 남긴다.

이어서 torch.where(>= 1, 1, 0), numpy_to_vtk를 거쳐 Butterfly라는 이름의 배열이 되고, 원래 표면의 PointData에 추가된다.

11. 함정과 취약 지점

확인된 버그

isLowerUpper()는 파일 기본 이름이 아니라 전체 경로를 검사한다 (AREG_IOS/AREG_IOS_utils/dataset.py:241. 호출 시 file은 Sort와 SortLower에서 넘어온 전체 경로다). _U, L_, Md…를 포함한 폴더는 모든 악궁을 잘못 분류한다. 또한 여기서는 단어를 대소문자를 구분해 검사하는 반면, 위젯 쪽의 Method.IsLower (AREG/AREG_Method/IOS.py:141)는 먼저 기본 이름을 소문자로 바꾼다. 두 곳의 분류 방식이 서로 다르다.

확인된 버그

면→정점 투표는 F[:,0]에만 쓴다. 또한 P_faces[:, pf] += pred는 같은 면에 떨어지는 픽셀들을 누적하지 않는다. 이는 추측이 아니라 코드에 관한 사실이며, 패치는 이후 형태학적 닫힘 연산으로 복구된다.

확인된 버그

RemoveIslands(..., 33, 500, ...)는 아무 일도 할 수 없다. 사용되지 않는 코드다.

확인된 버그

check_platform()은 대문자로 시작하는 'Microsoft'를 찾는다 (AREG_IOS/AREG_IOS.py:45). WSL2는 자신을 소문자 microsoft-standard-WSL2로 보고하므로, WSL 분기는 아마 한 번도 실행되지 않고 else 분기(패키지 임포트)가 대신 실행된다. 차라리 다행이다. WSL 분기는 from AREG_IOS_utils.transformation import ...와 from AREG_IOS.AREG_IOS_utils.transformation import ...를 섞어 쓰므로, 저장소 루트 그리고 AREG_IOS/가 모두 PYTHONPATH에 있어야 한다.

함정

T1의 .tfm을 찾지 못하는 경우가 많다. AREG_IOS는 <patient_id_short>_SegOr.tfm을 찾는데, 여기서 patient_id_short = name_t2.split("_T2")[0].split("_")[0]이다. 반면 PRE_ASO_IOS는 파일 이름을 PatientNumber() = basename.split('_U')[0].split('_L')[0] (ASO_IOS/ASO_IOS_utils/utils.py:295)로 지었다. 둘이 일치하는 것은 악궁 표시가 시점 표시보다 앞에 올 때뿐이다(P001_Upper_T1.vtk ✔, P001_T1_Upper.vtk ✘). 실패는 오류가 아니라 경고로만 나온다.

확인된 버그

WriteSurf는 항상 vtkPolyDataWriter를 쓰지만 입력 확장자를 유지한다. 입력이 .stl이면 레거시 VTK를 담은 .stl 파일이 나온다.

확인된 버그

os.mkdir(makedirs가 아님)이 WriteSurf에 쓰인다. 아직 존재하지 않는 중첩 출력 폴더가 있으면 쓰기가 실패한다.

확인된 버그

DatasetPatch.isLower()는 길이가 아니라 is not None을 검사한다. Sort가 빈 하악 목록을 반환하면 lower는 True로 평가되고, 모든 접근이 IndexError를 일으키며, 이는 경고로 처리된다.

확인된 버그

sort()와 insideLower()는 continue를 쓰는데, 원래 break가 의도되었을 것이다. 이름이 겹쳐지면 sort()가 같은 T1을 여러 T2 파일과 짝지을 수 있다.

함정

방향 정렬이 실패해도 아무것도 멈추지 않는다. 분할되지 않은 스캔도 임의의 좌표계 그대로 신경망에 들어가며, 카메라 7대가 엉뚱한 쪽에서 바라본다. 패치는 소리 없이 틀린 결과가 된다.

함정

AREG_IOS.xml은 CLI와 맞지 않는다(인덱스 4 누락, MGL 매개변수 4개 부재). 실행이 conda를 거치는 한 무해하지만, slicer.cli.run으로 되돌아가려는 시도는 모두 깨질 것이다.

함정

patch_radius는 위젯 쪽에서 [0, 20] mm로 제한된다 (AREG/AREG.py:734). 반면 FlexReg는 5 mm에서 멈춘다. 부착 치은의 높이를 넘어서면 띠가 가동 조직까지 넘쳐 나간다.

12. 문헌

발표된 기반은 AReg IOS: Automatic Registration on IntraOral Scans (Hutin, Anchling, Cevidanes et al., Lecture Notes in Computer Science, 2023, MICCAI)다. DentalModelSeg로 치관을 분할하고, 공유 중심점으로 초기 정렬을 하며, 다중 시점 3D 형상 분석으로 구개 ROI를 분할한 뒤, ICP를 수행한다.

논문과 이 저장소의 코드 사이에는 두 가지 불일치가 있다:

  • 논문은 공유 치관 중심점에 의한 초기 정렬을 기술한다. 코드에서는 상류의 PRE_ASO_IOS와 VTK의 StartByMatchingCentroidsOn()이 그 역할을 한다. AREG_IOS 자체에는 중심점 정렬 단계가 없다;
  • MGL 경로는 논문에 없다. 이후의 내부 개발이며 현재까지 발표되지 않았고, 코드에 인용된 수치 (예측 364건에서 4.2 mm 대 1.2 mm)는 주석 말고는 어디에도 출처가 없다.

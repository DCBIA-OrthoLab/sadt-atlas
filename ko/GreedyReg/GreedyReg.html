GreedyReg

ITK-SNAP의 greedy 바이너리를 서브프로세스로 구동하는 T1/T2 CBCT 어파인/강체 정합. 주 경로에 신경망이 없고, 전용 conda 환경도 없다.

Venet 2019 · arXiv GreedyReg_CLI conda 환경: 없음 (Slicer의 Python) 참고문헌

ITK-SNAP의 greedy 바이너리를 서브프로세스로 호출해 T1/T2 CBCT를 정합한다. 주 경로에서는 어떤 신경망도 학습되거나 호출되지 않는다. 모듈이 쓰는 유일한 신경망은 "원거리(distant)" 초기화용이며, 그대로 빌려 온 ALI_CBCT다.

1. 처리 사슬에서의 위치

저장소에서 GreedyReg를 호출하는 것은 없다. 운영자가 직접 구동하는 말단 도구이며, 다른 어떤 모듈의 입력도 되지 않는다.

호출 대상방식시점
GreedyReg_CLIslicer.cli.run(slicer.modules.greedyreg_cli, …)모든 자동 정합, 단일 증례든 일괄이든
greedy 바이너리subprocess.run, CLI에서 실행증례당 두 번 호출 (정합, 이어서 리샘플링)
ALI_CBCTslicer.cli.run(slicer.modules.ali_cbct, …)"Distant Registration" 모드에서만
확인됨

Slicer 모듈은 greedy를 직접 실행하지 않는다. 파라미터를 조립하고(Logic.py:286) CLI에 맡긴다. GreedyRegLogic의 docstring이 이를 명시하며, 실제로도 그렇다. 바이너리 다운로드를 제외하면 위젯에는 subprocess가 없다.

이 코드를 넘겨받는 사람에게 중요한 점: conda 환경이 없다. Logic.py:76의 주석이 이를 밝힌다 — CLI는 Slicer 자체의 Python에서 실행되므로, 위젯에서 호출한 slicer.util.pip_install이 서브프로세스에 곧바로 보인다. GPU도 없다. greedy는 CPU 전용이다.

GreedyReg.py의 첫 두 줄은 import할 때마다 모듈의 __pycache__를 지운다 — 개발 중에 남은 흔적이다.

3. greedy 바이너리: 어디서 오는가

greedyBinaryPath()는 GreedyReg_CLI/bin/{linux|mac|windows}/greedy[.exe]를 찾는다. 없으면 빨간 배너가 downloadGreedyBinary() (Logic.py:106)를 제안한다. 이 함수는 SourceForge에서 ITK-SNAP 4.2.2 아카이브를 받아 bin/greedy만 추출한다:

플랫폼출처추출
Linuxitksnap-4.2.2-20241202-Linux-x86_64.tar.gztarfile, 멤버 …/bin/greedy, chmod 755
macOS (arm64)itksnap-4.2.2-20241202-MacOS-arm64.tar.gz동일
Windowsitksnap-4.2.2-20241202-win64-AMD64.exe (NSIS 설치 프로그램)7-Zip이 있으면 7-Zip, 없으면 무인 설치 후 제거

Windows 경로가 가장 취약하며, 코드가 이를 잘 문서화하고 있다 (Logic.py:161). NSIS의 /D=는 따옴표를 지원하지 않으므로 설치는 %SystemDrive%\_greedyreg_nsis_tmp(공백 없는 경로)에서 이루어지고, greedy.exe를 밖으로 복사한 뒤 Uninstall.exe /S를 실행한다.

함정

다운로드한 아카이브에 대한 무결성 검사(체크섬)가 없다.

4. 세 가지 모드, 그리고 실제로 무엇이 다른가

모드계산하는 것계산 주체출력
Manual Alignment 없음: 운영자가 vtkMRMLLinearTransformNode를 움직인다 위젯 장면의 행렬, -ia로 사용
Automatic Registration 강도 메트릭을 최적화하는 어파인 또는 강체 정합 계산 greedy 바이너리, CLI 경유 정합된 .nii.gz + .mat
Distant Registration 예측된 랜드마크 3-5개에 대한 닫힌 형식(closed-form) 강체 정합(SVD/Kabsch) 예측 계산 위젯 + ALI_CBCT 행렬만. 이후 다듬어야 함
용어 함정

"Distant"라는 말은 원격 계산을 뜻하지 않는다. 패널 제목은 "Distant Registration (Large Misalignment)"이다. 처음에 기하학적으로 멀리 떨어진 두 스캔(초기 어긋남이 큼)을 가리킨다. 모든 것이 로컬에서 실행된다. 네트워크 통신도, 소켓도, 암호화도, 증명(attestation)도 없다. 모듈 안의 외부 요청은 urllib.request.urlretrieve뿐이며, 그 대상은 SourceForge(greedy 바이너리)와 저장소의 GitHub 릴리스(ALI 가중치)다. 따라서 외부와의 접촉은 도구 다운로드뿐이며, 환자 데이터를 보내는 일은 결코 없다.

4.1 수동 모드

두 벌의 컨트롤이 같은 변환 노드에 작용한다:

  • ctkSliderWidget 슬라이더 여섯 개(회전 ±180°, 평행 이동 ±200 mm). 합성 순서: Translate, 이어서 RotateX, RotateY, RotateZ (GreedyReg.py:1192);
  • "Center T2 on T1": 두 볼륨 중심 사이의 순수 평행 이동. IJK에서 계산한 뒤 RAS로 변환한다. 변환에는 GetIJKToRASMatrix를 쓴다(Logic.py:381);
  • Slicer의 기본 핸들(SetEditorScalingEnabled(False) → 스케일링은 절대 없음);
  • 스스로 프로토타입임을 인정한 "Sensitivity Demo": Red/Yellow/Green 뷰에 부모를 바꿔 붙인 Qt 휠. 회전축은 뷰에 따라 다르고(Red→Z, Yellow→X, Green→Y), 휠 밖에서 드래그하면 슬라이스 평면 안에서 평행 이동하며(0.5 mm/pixel × gain), 휠 크기는 줌을 따른다(baseFov / fovMean, 0.55-1.90으로 제한). GreedyReg.py:499의 주석이 이유를 설명한다. 기본 핸들은 원시 마우스 위치로부터 변위를 다시 계산하므로, 나중에 행렬을 감쇠시켜도 눈에 보이는 효과가 없다.

이동 볼륨은 내보내기 전에 harden되지 않는다. slicer.util.exportNode(node, path)의 기본값은 world=False이므로 (slicer/util.py에서 확인), 수동 변환은 오직 -ia 파일을 통해서만 greedy에 전달된다. 이로 인한 규약 문제는 §9를 참고하라.

4.2 자동 모드

onRunRegistration() (GreedyReg.py:1204)는 tempfile.mkdtemp() 안에 디렉터리 트리를 만든다: T1/, T2/, INIT/, MASK/, OUTPUT/. 두 볼륨을 가짜 식별자 CASE0001로 내보내고, init을 기록한 뒤, CLI를 쌍 하나짜리 일괄 모드로 호출한다. 단일 증례 실행을 위한 별도의 코드 경로는 없다. 파일 하나가 든 폴더에 대한 일괄 실행일 뿐이다.

1 s 간격의 QTimer가 cliNode를 폴링하고, 끝나면 정합된 볼륨을 임시 폴더에서 불러온다. 이 폴더는 결코 삭제되지 않는다 (위젯에 rmtree가 없음). 결과는 시스템 정리 때까지 남으며, "Save Registered Volume" 버튼도 이에 의존한다. 이 버튼은 단순한 shutil.copy이기 때문이다.

4.3 원거리(Distant) 모드

onRunDistantRegistration() (GreedyReg.py:1406):

  1. 우선순위 두개저 > 하악골 > 상악골에 따라 한 영역만 남긴다(_selectedDistantRegion, GreedyReg.py:1397). 여러 상자를 체크해도 랜드마크가 합산되지 않고, 처음 찾은 것이 이긴다;
  2. 두 볼륨을 .nii.gz로 임시 폴더에 내보낸다;
  3. ALI용 작업 대기열을 만든다. (스캔 × 모델 하위 폴더)마다 작업 하나이며, ModifiedEvent 옵저버를 연쇄시켜 순차 실행한다 (GreedyReg.py:1493);
  4. 출력 json 파일을 다시 읽고, 좌표를 LPS → RAS로 변환한다 ([-x, -y, z], Logic.py:517);
  5. 두 스캔에 공통인 랜드마크가 3개 이상이면 rigidFromLandmarks()가 SVD로 강체 변환을 계산하고, 아니면 명시적으로 실패한다.

영역과 랜드마크 (REGION_CONFIG, Logic.py:20):

영역랜드마크가중치 폴더
MANDMASKRGo, LGo, Gn, Me, PogLower_Bones_1, Lower_Bones_2
MAXMASKA, ANS, LOr, ROr, PNSUpper_Bones_v2
CBMASKS, N, RPo, LPoCranial_Base

가중치는 저장소의 v0.1-v2.0_models 릴리스에서 오며, 폴더마다 .zip 하나씩, Documents/SlicerDownloads/GreedyReg/ALIModels/<folder>/에 압축이 풀린다.

호출되는 신경망. ALI_CBCT는 히트맵을 만들지 않는다. 강화학습이다. 랜드마크마다 에이전트 하나가 볼륨 안을 이동하며, agent_FOV = [64,64,64] 복셀 크기의 정육면체를 관찰하고 MOVEMENTS에서 이동을 고른다. DNet 신경망(1024채널 전이 층, out_channels = len(MOVEMENTS["id"]))은 랜드마크마다 폴더의 .pth 파일에서 다시 불러온다(ALI_CBCT.py:159). GreedyReg가 지정하는 파라미터(Logic.py:471): spacing = [1, 0.3] mm(거친 탐색 후 정밀 탐색), speed_per_scale = [1,1], spawn_radius = 10, DCMInput = false.

강체 계산(Logic.py:535)은 계산 고전적 Kabsch다: 중심화, H = movingᵀ·fixed, SVD, R = Vᵀ·Uᵀ, det(R) < 0이면 반사 보정, t = c_fixed − R·c_moving. 따라서 결과 행렬은 이동에서 고정으로, RAS에서 간다 — Slicer 변환 노드의 규약과 정확히 같으며, 행렬은 그대로 노드에 들어간다.

확인됨

완료 메시지는 정직하다: "Distant registration complete! Now run Automatic Registration to refine." 이 모드는 정합하지 않고 초기화한다.

5. greedy 명령줄

buildRegistrationCommand() (GreedyReg_CLI.py:100)는 항상 정확히 다음을 만든다. 메트릭과 자유도 수 외에는 노출된 옵션이 없다:

greedy -d 3 -a \
  -m NMI | -m NCC 4x4x4 | -m SSD \
  -i <T1.nii.gz> <T2.nii.gz> \
  -o <ID>_warp.mat \
  -n 100x100x50x25 \
  -e 0.5 \
  -search 100 10 20 \
  -dof 6|12 \
  -ia <init.mat> \
  [-gm <binarized mask>]
플래그값의미 (greedy 문서)
-d 3고정영상 차원
-a고정어파인/강체 모드. greedy의 기본값이자 존재 이유인 미분동형(diffeomorphic) 모드는 여기서 전혀 쓰이지 않는다
-m NMI인덱스 0 (UI 기본값)정규화 상호 정보량, 강도가 이질적일 때
-m NCC 4x4x4인덱스 1국소 상호 상관, 반경은 복셀 단위
-m SSD인덱스 2차이 제곱합, 같은 모달리티
-i fixed movingT1, 이어서 T2순서 고정: -i <fixed> <moving>
-o<ID>_warp.mat4×4 어파인 행렬 (텍스트)
-n 100x100x50x25고정다중 해상도 피라미드 4단계, 가장 거친 단계부터 가장 정밀한 단계까지 100/100/50/25회 반복 (greedy의 기본값은 100x100, 2단계)
-e 0.5고정시간 간격 — 어파인 모드에서는 효과가 없다. greedy 문서는 "-s and -e have no effect"라고 분명히 밝힌다(-a의 경우). 사용되지 않는 줄
-search 100 10 20고정최적화 전 강체 변환 100개에 대한 무작위 탐색: σ_angle = 10°, σ_offset = 20 (문서 본문에 따르면 복셀 단위, 사용법 텍스트에 따르면 물리 단위 — 모호함은 greedy 쪽에 있으며, 여기 문제가 아니다)
-dof 6 / 12"Rigid"/"Affine" 콤보 박스6 = 강체, 12 = 완전 어파인. -dof 7(강체 + 균일 스케일)은 제공되지 않는다
-ia항상 제공초기화 행렬. -ia-identity도, -ia-image-centers도 결코 쓰지 않는다
-gm마스크가 주어진 경우고정 볼륨의 마스크: 메트릭의 기울기는 그 안에서만 계산된다

이어서 항상 실행되는 두 번째 호출, 리샘플링 모드:

greedy -d 3 -rf <T1> -rm <T2> <ID>_registered.nii.gz -r <ID>_warp.mat

-rf는 기준 공간(고정 볼륨)을, -rm은 입력/출력 쌍을 지정한다. 따라서 출력 볼륨은 T1 격자로 리샘플링된 원래의 T2이며, 선형 보간을 쓴다(-ri의 기본값). 각 호출은 timeout = 600 s로 제한된다.

6. 입력, 짝짓기, 마스크, 초기화

함정

짝짓기. ID_PATTERN = ^([A-Za-z]+\d+)를 대문자로 바꾼 파일 이름에 적용한다(GreedyReg_CLI.py:37). A01_t1.nii.gz → 식별자 A01. 같은 식별자가 T1 폴더와 T2 폴더 양쪽에 있으면 쌍이 성립한다. 마스크(.nii/.nii.gz)와 init(.mat)은 선택 사항이며 같은 식별자로 매칭된다. 이름이 01_T1.nii.gz(숫자로 시작)이거나 Patient-01.nii.gz인 파일은 결코 짝지어지지 않으며, 이는 조용히 일어난다.

위젯의 findBatchPairs()는 "Found N pairs" 레이블을 위해 이 로직을 중복 구현한다. 주석은 두 구현을 동기화된 상태로 유지해야 한다고 경고한다.

마스크. vtkMRMLSegmentationNode 또는 레이블맵에서 .nii.gz로 내보낸 뒤, CLI 쪽에서 이진화한다: (get_fdata() > 0).astype(float32) (GreedyReg_CLI.py:92). 따라서 다중 레이블 분할의 모든 세그먼트가 하나의 마스크로 합쳐진다. 원거리 일괄 처리의 어파인 재기록과 더불어, 이것이 nibabel의 유일한 실제 용도다.

함정

초기화. init 파일이 없으면 writeIdentityInit()이 matrix[0,3] = 0.001인 항등 행렬을 기록한다 — 1마이크론 평행 이동이다. 주석이 이유를 설명한다: "so Greedy doesn't treat it as identity." 이 동작은 greedy 쪽 어디에도 문서화되어 있지 않다. 경험적인 우회책이며, 그렇게 다루어야 한다.

강도 전처리 없음: 정규화도, 잘라내기도, 사전 리샘플링도, 방향 변환도 없다. NIfTI 파일은 그대로 전달되며, greedy는 헤더의 RAS 물리 공간에서 작업한다.

7. 일괄 모드

서로 독립적이며 하는 일도 다른 일괄 처리 두 가지가 있다.

자동 일괄 처리(GreedyReg.py:1537). 위젯은 반복하지 않는다. 폴더들에 대해 단 한 번 GreedyReg_CLI를 실행하고, 반복은 CLI가 한다(main(), GreedyReg_CLI.py:141). 이때 Slicer의 CLI 인프라가 읽는 <filter-progress> / <filter-comment> 태그를 내보낸다. 출력 폴더는 T2 폴더 자체다. 상류에서 이진화되는 마스크도 없고, init도 전달되지 않는다(initFolder=""). 일괄 처리는 항상 살짝 비튼 항등 행렬에서 시작한다. 처음 실패한 증례 → sys.exit(1) → 일괄 처리 전체가 멈춘다.

원거리 일괄 처리(GreedyReg.py:1606). 여기서는 위젯이 증례별로 반복하며, 쌍마다 ALI 작업 대기열을 둔다. 결과는 정합된 볼륨이 아니라 다시 쓴 헤더다(GreedyReg.py:1690):

newAffine[:3, :3] = R @ movingImg.affine[:3, :3]
newAffine[:3, 3]  = R @ movingImg.affine[:3, 3] + t
nib.save(nib.Nifti1Image(movingImg.get_fdata(), newAffine, movingImg.header), out)
확인됨

복셀은 움직이지 않고, 복셀→월드 어파인만 바뀐다. 이는 올바르다. NIfTI 어파인은 Kabsch 행렬과 마찬가지로 RAS다. 출력: <ID>_t2_aligned.nii.gz, T2 폴더에 기록된다. 이 일괄 처리에서는 greedy가 전혀 호출되지 않는다.

8. 출력

파일내용위치
<ID>_registered.nii.gzT1 격자로 리샘플링된 T2단일 증례: 임시 폴더, 일괄: T2 폴더
<ID>_warp.mat4×4 greedy 어파인 행렬동일
<ID>_t2_aligned.nii.gzT2 복셀은 그대로, 어파인만 보정T2 폴더 (원거리 일괄 처리)

변환 형식, 그리고 존재하지 않는 변환 과정. <ID>_warp.mat은 greedy 고유 규약을 따르는 단순한 네 줄짜리 텍스트 파일이다. 4×4 행렬로, 고정 볼륨의 RAS 좌표를 이동 볼륨의 RAS 좌표로 사상한다([ras(moving);1] = M · [ras(fixed);1], greedy 문서 "Affine mode" 절).

"Save Transform Matrix" 버튼은 이 파일을 단순히 shutil.copy한다 (GreedyReg.py:1288).

함정

모듈 어디에도 .tfm이나 ITK 관련 형식으로의 변환이 없다. 이 코드를 넘겨받는 사람이 알아야 할 것:

  • ITK 변환 파일(TxtTransform)이 아니므로, 확장자가 .mat이어도 Slicer에서 변환으로 불러와지지 않는다;
  • 디스크에 저장된 ITK/Slicer 변환은 LPS이고, 이것은 RAS다. 역변환이 필요할 수 있는 것에 더해 diag(-1,-1,1,1)에 의한 켤레 변환이 필요하다;
  • 예상되는 변환 경로는 c3d_affine_tool(greedy 문서 권장), 또는 FlexReg_CLI.py:186과 같은 코드다. 후자는 자체 행렬에 대해 정확히 그 작업을 한다.

FlexReg는 저장소의 다른 모듈이 사용하는 재사용 가능한 SimpleITK .tfm을 만든다. 이에 비해 GreedyReg는 막다른 길이다. 아무도 그 행렬을 사용하지 않는다.

9. 초기화 규약: 거꾸로일 가능성이 매우 높다

수동 모드는 Slicer 변환 노드의 행렬을 그대로 <ID>_init.mat에 기록한다(Logic.py:277).

  • 이 행렬은 MatrixTransformToParent이며, 이동 볼륨에 적용된다. 이동 볼륨 자체의 좌표를 월드 좌표로 사상한다. 즉 이동 → 고정이다.
  • -ia는 -o가 만드는 것과 같은 성격의 행렬, 즉 고정 → 이동을 기대한다.
가능성 높은 함정, 미확인

둘은 서로의 역행렬이다. 따라서 수동 사전 정렬은 greedy에 거꾸로 전달될 가능성이 매우 높다(회전은 전치, 평행 이동은 부호 반대). 저장소의 다른 부분은 이 규약을 알고 있다. FlexReg_CLI.py:186은 "ITK convention: fixed -> moving."이라는 주석과 함께 명시적으로 역변환한다.

항상 드러나지 않는 이유: -search 100 10 20이 최적화 전에 무작위 강체 변환 100개를 샘플링하고, 4단계 피라미드가 많은 것을 너그럽게 흡수한다. 나쁜 시작점은 수렴을 늦추고 더 취약하게 만들 뿐, 막지는 않는다. 수정하기 전에 간단한 테스트(X축 방향 순수 20 mm 평행 이동으로, 기록된 init과 반환된 행렬을 비교)로 확인해야 한다.

12. 함정과 취약 지점

확인된 버그

일괄 처리가 출력을 T2 입력 폴더에 쓴다. A01_registered.nii.gz와 A01_t2_aligned.nii.gz는 모두 A01 식별자로 대응된다 — 기준은 ID_PATTERN. 두 번째 실행에서 {id: path} 딕셔너리는 식별자마다 항목 하나만 유지하는데, 그것은 os.listdir에서 마지막으로 만난 것이다. 따라서 이전 실행의 결과가 비결정적으로 다시 정합될 수 있다. 생성된 접미사를 걸러 내는 필터가 없다.

함정

생성된 .mat은 Slicer 변환이 아니다(§8): RAS, 고정→이동 방향, 단순 텍스트 형식.

함정

수동 모드의 init은 거꾸로일 가능성이 높다(§9).

함정

-e 0.5는 어파인 모드에서 아무 효과가 없다. 최적화 스텝 크기를 조정한다고 생각하는 사람에게는 혼란스러울 수 있다.

확인된 버그

죽은 버튼: Distant 패널의 "Save Registered Volume"은 self._distantResult를 읽는데, 이 값은 한 번도 할당되지 않는다 — 항상 "No result to save!"라고 응답한다. 어차피 Distant 모드는 볼륨을 만들지 않는다.

확인된 버그

원거리 모드의 오해를 부르는 체크박스: 세 구조는 독립된 체크박스이지만, _selectedDistantRegion()은 고정된 우선순위에 따라 그중 하나만 반환한다. "Mandible + Maxilla"를 체크해도 랜드마크 10개가 합쳐지지 않는다.

함정

조용한 ALI 실패: ALI_CBCT는 가중치 문제를 경고로만 기록하고 코드 0으로 종료한다. 코드는 GetOutputText()를 체계적으로 출력해(GreedyReg.py:1508) 이를 방어하지만, 사용자에게는 "only 0 matched landmarks."만 보인다.

확인된 버그

위젯 쪽의 임시 폴더는 결코 정리되지 않는다 (mkdtemp ×3, rmtree 없음). 반면 CLI는 증례마다 caseTmpDir를 정리한다.

함정

한 번의 실패가 일괄 처리 전체를 멈춘다(CLI 루프 안의 sys.exit(1)). 재개도, 남은 증례 목록도 없다.

함정

다중 세그먼트 마스크가 하나로 뭉개진다(> 0 임계값 때문). 또한 마스크는 고정 볼륨의 공간에 있어야 한다. -gm은 고정 볼륨에 적용되며, UI가 이를 표시하지만("Mask (T1)") 아무것도 검증하지 않는다.

참고

채워지지 않은 모듈 메타데이터: contributors = ["Your Lab"], acknowledgementText = "".

함정

위젯에는 약 500줄의 Qt 스타일 시트와 위젯 (StandaloneRotationWheel, SliceTranslationOverlay)이 들어 있으며, 주석에서 명시적으로 프로토타입이라고 밝힌다. 이들은 슬라이더와 같은 변환 노드를 수정하므로, 두 벌의 컨트롤이 다시 동기화되지 않은 채 서로 간섭한다(휠을 움직인 뒤 슬라이더가 갱신되지 않는다).

13. 문헌

엔진은 발표되었고, 모듈은 발표되지 않았다.

  • greedy: Paul Yushkevich(PICSL, UPenn)의 도구로 ITK-SNAP에 포함되어 있다. 인용할 때 흔히 쓰는 문헌은 Venet, Pati, Yushkevich, Bakas, Accurate and Robust Alignment of Variable-Stained Histologic Images Using a General-Purpose Greedy Diffeomorphic Registration Tool (arXiv:1904.11929)이다. 문서: greedy.readthedocs.io, 코드: pyushkevich/greedy. 참고: 논문과 도구는 미분동형 정합을 다룬다. GreedyReg는 그 초기화 단계에 불과한 어파인/강체 모드(-a)만 쓴다.
  • ALI_CBCT: Gillot et al., Automatic landmark identification in cone-beam computed tomography, Orthodontics & Craniofacial Research, 2023 — 다중 스케일 볼륨 공간을 탐색하는 가상 에이전트, 랜드마크 32개에서 보고된 평균 오차 1.54 ± 0.87 mm. 원 저장소: Maxlo24/ALI_CBCT.
  • GreedyReg 자체: 발표 없음. 이 접근법 — "수동 사전 정렬 후 마스크를 쓰는 강도 기반 어파인" — 은 ITK-SNAP의 Registration 패널의 방식이며, 이 모듈은 이를 Slicer로 옮긴 것이다. 코드가 내세울 수 있는 계보는 이것뿐이다.

전체 참고문헌: SOURCES.html — 확인된 문헌, 이 폴더에 받아 둔 파일(greedy 논문, ALI_CBCT 논문), 그리고 greedy 논문이 설명하는 것과 이 모듈이 실제로 실행하는 것의 상세한 구분.

BatchDentalSeg

BatchDentalSeg는 CT와 CBCT 스캔의 치아와 턱에 레이블을 일괄로 붙입니다. 다중 레이블 신경망 하나가 모든 복셀에 한 번의 패스로 레이블을 줍니다. 이 페이지는 학습이 아니라 계산에 해당하는 부분의 수식과 함께 모듈을 단계별로 설명합니다. 스캔을 어떻게 정규화하는지, 신경망의 패치를 어떻게 섞는지, 메모리를 어떻게 추정하는지, 스캔을 어떻게 자르는지, 좌우를 어떻게 보정하는지를 다룹니다. 코드가 확인해 볼 만한 일을 하는 곳에는 코드 페이지로 가는 링크가 있습니다.

코드 (개발자용) Dot 2024 · J Dent BATCHDENTALSEG nnUNetv2_predict conda 없음: Slicer의 Python + nnunetv2 VISOR 참고문헌

개요: 무엇이 들어가고 무엇이 나오는가

BatchDentalSeg는 머리의 CT나 CBCT 스캔을 받아 각각에서 치아와 턱에 레이블을 붙입니다. 3D 신경망 하나가 스캔 전체를 보고 모든 복셀에 한 번의 패스로 레이블을 줍니다. AMASSS처럼 구조마다 신경망이 하나씩 있는 것이 아닙니다. 모듈 자체는 그 신경망을 둘러싼 대기열이며, 모델을 고르고, 메모리를 지키고, 기하를 복원하고, 내보내기를 씁니다.

입력처리 과정출력
스캔이 든 폴더(.nii, .nii.gz, .gipl, .gipl.gz)와 모델 넷 중 하나각 스캔은 한 번에 하나씩 nnU-Net을 거치며, 레이블 맵은 스캔 자체의 격자 위에 되돌려짐스캔마다 레이블 맵 하나(<scan>_Segmentation.nii.gz), 선택하면 STL, OBJ, VTK, glTF, 또는 세그먼트마다 NIfTI 파일 하나

이 페이지는 레거시 Slicer 모듈(3c67957 시점의 SlicerAutomatedDentalTools, 2026-10-26)을 설명합니다. 서버 포팅은 VISOR의 BatchDentalSeg입니다.

1. 파이프라인에서의 위치

저장소의 어떤 모듈도 BatchDentalSeg를 호출하지 않으며 BatchDentalSeg도 아무것도 호출하지 않습니다. 끝점에 있는 도구입니다. nnU-Net 설치, 모델 폴더 확인, 예측을 자식 프로세스로 실행하는 일을 위해 외부 Slicer 확장 NNUNet에 의존합니다. DentalSegmentator의 배치 변형이며, 위젯, 아이콘, 가중치 내려받기를 거기서 재사용합니다.

코드에서NNUNet 확장에서 호출하는 클래스 표

2. 관련 파일

코드 대부분은 약 3000줄의 위젯 파일 하나입니다. 인터페이스, 대기열, 모델 선택, 메모리 안전 장치, 크롭, 레이블, 내보내기가 거기에 있습니다. 작은 대기열 파일이 스캔 목록을 디스크에 보관하고, 체커가 DentalSegmentator 가중치를 내려받고 갱신합니다. 모든 것이 Slicer의 Python에서 실행되며 nnU-Net 자체는 한 번에 스캔 하나씩 자식 프로세스로 실행됩니다. 가중치는 실행 시에 들어옵니다.

코드에서줄 수가 있는 파일 표와, 빌드 파일이 설치하는 것

3. 입력, 폴더 순회, 이름 짓기

3.1 받아들이는 것

폴더는 하위 폴더로 들어가지 않고 네 패턴 .nii, .nii.gz, .gipl, .gipl.gz로 나열됩니다. Slicer의 기본 형식인 NRRD는 인식되지 않습니다.

3.2 대기열

항목 하나는 스캔 하나이며 폴더 하나가 아니므로, 모델이 다른 폴더 여럿을 같은 세션에 쌓아 둘 수 있습니다. 결과가 이미 있거나 이미 대기열에 있으면 스캔을 건너뜁니다. 대기열의 상태는 스캔이 끝날 때마다 다시 쓰이므로, 추론 도중 종료된 세션은 멈춘 곳에서 이어집니다. (기본값으로) 스캔 다섯 개마다 정리가 그래픽 카드와 메모리를 풀어 줍니다.

3.3 신경망이 실제로 보는 것

위젯은 아무것도 전처리하지 않습니다. 스캔을 NIfTI 파일로 내보내고, 나머지는 모두 nnU-Net의 몫입니다. nnU-Net은 계획이 요구하는 축을 따라 스캔의 순서를 바꾸고, 0이 아닌 영역으로 자르고, 강도를 정규화하고, 그런 다음에야 계획의 간격으로 리샘플합니다(nnU-Net 자체 코드의 순서이며 2.8.1 버전에서 확인함. 레거시 설치가 실행하는 버전은 기록되어 있지 않음). 아래에 보인 정규화는 DentalSegmentator의 계획이 선언한 것이며, 나머지 세 모델은 4.3절을 보십시오.

저장소에서(레거시 저장소에서) 읽을 수 있는 계획은 DentalSegmentator의 것뿐입니다. 백분위수 −110과 3067, 평균 1274, 표준편차 558입니다. 나머지 세 번들은 자기 계획 파일을 가져오므로, 그 모델들에 대해 이 방식은 가정일 뿐 확인하지 않았습니다.

이 저장소에 쓰인 유일한 전처리는 선택 사항인 자동 크롭(5.2절)이며, 메모리 실패 뒤의 재실행에만 쓰입니다.

코드에서glob, 대기열 항목, 영속성, 정리 주기

4. 모델 넷

4.1 콤보 박스가 고르는 것

네 항목은 같은 코드를 실행합니다. 폴드 0과 선택한 장치로 예측 요청이 만들어지고, 가중치 폴더와 레이블 표만 달라집니다. 변형 셋(소아, 비인두 상악, 범용)은 각각 파일 셋으로 내려받고, DentalSegmentator는 자기 저장소의 최신 릴리스 zip으로 옵니다. 내려받기에는 체크섬도 이어받기도 없어서, 중단된 내려받기는 잘린 체크포인트를 남기고 다음 실행은 이를 완전한 것으로 받아들입니다.

코드에서네 분기, 내려받기 경로, 체크포인트 확인

4.2 nnU-Net, 코드에서 확인함

정말로 nnU-Net v2입니다. 만들어지는 명령이 데이터셋, 트레이너, 계획, 설정(3D full resolution), 폴드 하나(학습된 모델의 사본 하나), 스텝 0.5(각 패치는 최대 크기의 절반만큼 움직임), 테스트 시 미러링 없음(뒤집은 사본에 대한 평균 없음)을 지정합니다. 인터페이스가 제공하는 유일한 설정은 장치(cuda, cpu, mps)입니다. 폴드 0만 쓰며 앙상블은 절대 아닙니다.

코드에서명령줄, 기본값, 프로세스 전체 환경 변수

4.3 아키텍처와 계획: 확인할 수 있는 것

저장소에 계획 파일이 들어 있는 번들은 DentalSegmentator뿐입니다. 단계 여섯 개(첫 단계 특징 32개, 마지막 단계 320개)의 단순 합성곱 3D U-Net, 128 × 160 × 112 복셀의 패치, 약 0.45 × 0.31 × 0.45 mm의 간격, 배치 2, CT 정규화입니다. 나머지 세 모델의 계획은 내려받을 때 들어오므로, 코드만으로는 그에 대해 더 말할 수 없습니다.

5. 학습되지 않은 핵심부

5.1 레이블 맵 재구성과 기하 복원

분할은 한 번의 내보내기로 하나의 레이블 맵이 되고, 조회 표로 한 번에 공식 값으로 재매핑됩니다. 이전 버전은 세그먼트마다 볼륨 전체를 한 번씩 래스터화했습니다. 전체 구강 CBCT의 UniversalLab에서는 55번입니다.

5.2 자동 크롭(메모리 실패 뒤의 재실행)

잘린 하위 볼륨은 간격과 축을 유지하고 원점만 움직이며 보간은 전혀 없습니다. 예측 뒤에 레이블 맵은 단순한 오프셋으로 원래 크기의 배열에 다시 붙여 넣어지므로, 출력은 언제나 촬영된 그대로의 스캔 격자 위에 있습니다.

코드에서크롭 함수, 그 상수, 다시 붙여 넣기

5.3 메모리 안전 장치: 세 겹의 방어선

코드 주석이 실제 사례를 듭니다. 스캔 하나가 125 GB 기계에서 114 GB를 채웠고, 시스템에 의해 종료되었으며, 워커가 메모리를 쥔 채 살아 남았습니다. 그래서 프로세스의 시점마다 하나씩 방어선이 셋 있습니다. 실행 전의 추정, 실행 중의 모니터, 실행 뒤의 복구입니다.

실행 중에는 메모리를 3초마다 표본으로 잡고, 일시적 급등이 멀쩡한 스캔을 죽이지 않도록 연속 두 번의 초과가 있어야 프로세스를 종료합니다. nnU-Net이 자기 워커를 시작하기 때문에 직접 자식만이 아니라 프로세스 트리 전체를 종료하며, 고아 프로세스도 쓸어 냅니다.

코드에서추정, 표본 추출기, 프로세스 트리 종료, 잔여 프로세스 정리

5.4 완료 감지의 대체 경로

nnU-Net이 “done” 줄을 출력하면 타이머가 출력 파일의 크기를 지켜보고, 같은 값이 두 번 읽히면 프로세스가 끝났다는 신호를 보내지 않았더라도 마무리를 강제합니다. 60초 뒤에 포기합니다. 스캔마다 워치독(기본 60분)도 있어서 스캔을 실패로 표시하고 다음으로 넘어갑니다.

6. 출력

어떤 형식이 체크되어 있든 모듈은 항상 <scan>_Segmentation.nii.gz를 쓰며, 원본 볼륨의 기하를 따르는 레이블 맵입니다. 대기열이 스캔이 이미 끝났다고 판단하려고 찾는 파일도 이것입니다. 다른 형식은 같은 폴더에 들어갑니다.

  • STL, OBJ: 세그먼트마다 파일 하나.
  • 레이블별 VTK: 레이블마다 파일 하나이며, 정리되고, 스무딩되고(windowed-sinc 60회 반복), 40 % 줄이고, RAS에서 LPS로 뒤집힙니다.
  • 병합 VTK: 모든 레이블을 담은 파일 하나이며, 같은 방식으로 만들고 상수 레이블 배열을 가집니다.
  • 세그먼트별 NIfTI: 세그먼트마다 이진 파일 하나이며, 위의 레이블 맵과 혼동하지 마십시오.
  • glTF: SlicerOpenAnatomy 확장을 통하며, 데시메이션을 조절할 수 있습니다(기본 0.9).

메시 내보내기가 실패해도 스캔은 실패로 처리되지 않습니다. NIfTI는 이미 기록되었고, 스캔은 경고와 함께 done으로 표시됩니다.

8. 환경

9. 함정과 취약 지점

각 항목은 코드에서 확인했으며, 근거와 함께 코드 페이지에 기술되어 있다.

  • NasoMaxillaDentSeg 세그먼트의 이름이 잘못 바뀝니다. 마지막 넷이 틀린 이름, 색, 불투명도를 받고 하악관이 출력에서 사라질 수 있습니다. 근거.
  • UniversalLab은 두개궁을 분할한다고 설명되어 있지만 인터페이스와 README에서 그렇고, 그런 레이블은 없습니다. 근거.
  • DentalSegmentator 가중치를 내려받으면 나머지 세 모델이 지워집니다. 근거.
  • 릴리스 확인이 취약하고 어떤 내려받기도 검사되지 않습니다. 최신 릴리스의 첫 에셋이며 체크섬이 없습니다. 근거.
  • NRRD는 읽히지 않고 하위 폴더는 순회되지 않습니다. 같은 이름의 스캔 둘은 같은 결과를 덮어씁니다. 근거.
  • 폴드 하나, 앙상블은 절대 아님: 번들에 있는 추가 폴드는 무시됩니다. 근거.
  • nnU-Net이 모델을 가리키게 하는 환경 변수는 Slicer 프로세스 전체에 설정되며, 대기열이 순차적이기 때문에 여기서만 해롭지 않습니다. 근거.
  • 죽은 코드: 섬 제거와 후처리 함수는 한 번도 호출되지 않습니다. 근거.
  • 빌드 파일의 설치 목록이 불완전합니다. 모델 폴더의 일부만 나열됩니다. 근거.

10. 문헌

DentalSegmentator가 발표되었습니다. Dot G. 외, DentalSegmentator: robust open source deep learning-based CT and CBCT image segmentation, Journal of Dentistry 147:105130, 2024(doi:10.1016/j.jdent.2024.105130). nnU-Net v2를 쓰며, 학습에 7개 기관의 CT와 CBCT 스캔 470개, 스캔 256개의 홀드아웃 시험으로 Dice는 내부 92.2 ± 6.3 %, 외부 94.2 ± 7.4 %입니다. 이 모델에 대해서는 코드와 논문이 일치합니다. 방법론의 토대는 Isensee 외, nnU-Net, Nature Methods 18(2):203-211, 2021입니다.

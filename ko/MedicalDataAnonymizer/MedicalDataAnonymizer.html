MedicalDataAnonymizer

텍스트 문서(DOCX, TXT, PDF, CSV, XML, ODT)에서 Microsoft Presidio를 이용해 민감한 엔터티를 탐지하고 치환한다. 이 모듈은 의료 영상을 전혀 건드리지 않는다. DICOM 익명화 도구가 아니다.

미발표 CLI 없음 (Slicer 위젯) UI 스레드, conda 없음 참고문헌
용어 함정

이름만 보면 DICOM 익명화 도구 같다. 전혀 그렇지 않다. MedicalDataAnonymizer는 텍스트 문서를 비식별화한다. 방식은 Presidio + spaCy다. DICOM 태그(PatientName, PatientID, UID…)는 하나도 읽거나 수정하지 않으며, 영상에 얼굴 제거(defacing)를 적용하는 일도 없다. 확장 기능 전체를 통틀어 얼굴 제거 도구가 아예 없다.

0. 이 모듈이 아닌 것

이름만 보면 DICOM 익명화 도구 같다. 전혀 그렇지 않으며, 명령 하나로 확인할 수 있다:

$ grep -rin "dicom\|pydicom\|deface" Medical_Data_Anonymizer_Module/
(no result)
$ grep -rlni "deface" --include="*.py" --include="*.md" .
(no result anywhere in the repository)

직접적인 결과:

  • DICOM 태그는 하나도 지워지거나 치환되지 않는다: PatientName(0010,0010)도, PatientID(0010,0020)도, PatientBirthDate도, StudyDate도, InstitutionName도, UID도, private tag도, BurnedInAnnotation도 그대로다;
  • 얼굴 제거 없음: CBCT나 스캐너 영상에서 재구성할 수 있는 얼굴은 어떤 방법으로도 변경되지 않는다(얼굴 마스크도, 블러링도, 표면 제거도 없다). 확장 기능 전체 어디에도 얼굴 제거 도구가 없다;
  • 지원 형식(.docx, .txt, .pdf, .csv, .xml, .odt, Medical_Data_Anonymizer_Module.py:506)에는 .dcm, .nii.gz, .nrrd, .vtk, 랜드마크 .json 중 어느 것도 포함되지 않는다.

데이터 공유 가능 여부를 판단해야 하는 사용자는 곧바로 §7을 읽을 것.

1. 파이프라인에서의 위치

CLI 없는 고립된 도구다. 아무것도 이를 호출하지 않고, 이 도구도 저장소의 다른 것을 호출하지 않는다. 모든 것이 767줄짜리 파일 하나에 들어 있으며, 그중 약 350줄이 Qt 스타일시트다: Medical_Data_Anonymizer_Module.py.

Medical_Data_Anonymizer_ModuleLogic과 …Test는 빈 클래스(pass)다. 모든 로직이 위젯 안에 있으므로 Slicer의 메인 스레드에서 실행된다. 처리 중에는 인터페이스가 멈추며, slicer.app.processEvents()만이 진행 표시줄을 갱신한다.

2. 입력: 형식별 텍스트 추출

입력 폴더를 재귀적으로 훑는다(os.walk). ~$로 시작하는 파일(Word 잠금 파일)은 무시한다. 각 파일은 분석 전에 문자열 하나로 축소된다:

형식추출그 과정에서 잃는 것
.docxpython-docx, "\n".join(p.text for p in doc.paragraphs)표, 머리글/바닥글, 각주, 텍스트 상자, 메모, 파일 메타데이터
.txtUTF-8 원시 읽기—
.pdfpdfplumber, page.extract_text(). 예외 발생 시 extract_tables()로 두 번째 시도이미지, 스캔된 PDF(OCR 없음) → 빈 텍스트
.csvcsv.reader, 각 행을 " ".join(row)로 평탄화열 구조
.xmlElementTree + 재귀 extract_text_from_xml()(텍스트 + tail)태그와 속성: 속성 값은 전혀 읽지 않는다
.odtodfpy, text.P의 텍스트 노드표, 스타일, 메타데이터

손실은 충실도만의 문제가 아니다. 출력 문서는 이 문자열로부터 재구성된다. 추출되지 않은 것은 익명화되지 않지만, 옮겨지지도 않는다. 사라진다. 반대로 추출되지 않은 부분(DOCX 표, XML 속성)에 있는 민감한 내용은 탐지되지도, 옮겨지지도 않는다. 유출은 없지만 데이터가 소리 없이 사라진다.

주목할 예외: 파일의 메타데이터(DOCX 작성자, PDF의 Producer)는 아무것도 읽지 않는다. 파일을 처음부터 다시 만들기 때문에 이것도 사라진다.

3. 탐지 엔진

저장소에 모델은 없고, spaCy 모델 외에 모듈이 직접 내려받는 가중치도 없다. "Anonymize Files"를 클릭할 때마다 Presidio 엔진 두 개가 인스턴스화되며(…py:493), stderr는 SuppressStderr 클래스로 차단된다:

analyzer = AnalyzerEngine()      # default config
anonymizer = AnonymizerEngine()

인자 없는 AnalyzerEngine()은 Presidio의 기본 NLP 설정, 즉 spaCy en_core_web_lg를 사용한다. install_dependencies()가 내려받는 유일한 모델이다(spacy.cli.download, …py:411).

두 계열의 인식기(recognizer)가 합쳐진다: spaCy의 통계적 NER(PERSON, LOCATION, DATE_TIME)과 패턴·체크섬 기반 인식기(PHONE_NUMBER, EMAIL_ADDRESS, US_SSN, MEDICAL_LICENSE, US_DRIVER_LICENSE, CREDIT_CARD, US_BANK_NUMBER, IP_ADDRESS, URL).

함정

언어가 영어로 고정되어 있다: analyzer.analyze(..., language='en')(…py:713). "with automatic language detection"이라는 주석이 있고 langdetect도 설치되지만, 이 패키지는 한 번도 임포트되지 않는다. 죽은 의존성이다. 프랑스어 기록 폴더도 영어 모델을 거치며, 재현율은 예상대로다.

신뢰도 임계값: score_threshold, 슬라이더 0.0–1.0, 기본값 0.5. 임계값 미만의 탐지 결과는 흔적 없이 버려진다.

4. 엔터티와 치환 방식

체크박스 12개, 그중 7개가 기본으로 선택되어 있다(…py:90):

Presidio 엔터티UI 레이블기본값
PERSON 예측Names (patients, doctors)(이름: 환자, 의사)✔
PHONE_NUMBER 계산Phone Numbers(전화번호)✔
EMAIL_ADDRESS 계산Email Addresses(이메일 주소)✔
DATE_TIME 예측Dates and Times(날짜와 시간)✔
LOCATION 예측Addresses and Locations(주소와 장소)✔
US_SSN 계산Social Security Numbers(사회보장번호)✔
MEDICAL_LICENSE 계산Medical License Numbers(의료 면허 번호)✔
US_DRIVER_LICENSE, CREDIT_CARD, US_BANK_NUMBER, IP_ADDRESS, URL 계산—✘

"Advanced Options"에 있는 네 가지 방식(…py:720):

방식구현결과
replace(기본값)operators = {} → None으로 전달 → Presidio 기본 연산자<PERSON>, <DATE_TIME>, …
redact엔터티마다 OperatorConfig("redact")해당 부분이 사라지고 텍스트가 붙는다
hashOperatorConfig("hash")탐지된 텍스트의 솔트 없는 SHA-256
maskOperatorConfig("mask", {"masking_char": "*", "chars_to_mask": 100, "from_end": False})해당 부분 전체를 별표로 가림

hash에 관해: README는 "cryptographic hashes for consistent anonymization"(일관된 익명화를 위한 암호학적 해시)이라고 말한다. 일관성 주장은 사실이지만(같은 이름은 항상 같은 다이제스트를 낸다), 솔트도 키도 없다. 이름, 생년월일, 사회보장번호처럼 값의 공간이 작으면 다이제스트는 무차별 대입으로 몇 초 만에 재식별될 수 있다. 보호 수단이 아니라 공개된 가명으로 취급해야 한다.

5. 출력과 대응표

출력 폴더에 평평하게 저장된다. 입력의 하위 폴더 계층은 재현되지 않는다.

입력출력비고
x.docxx_anonymized.docx재구성된 문서, 줄마다 문단 하나, 서식 없음
x.txtx_anonymized.txt—
x.pdfx_anonymized.pdfreportlab으로 재생성, Preformatted 블록 하나
x.csvx_anonymized.csv아래 참조
x.xmlx_anonymized.xml.xml 확장자를 단 일반 텍스트: 태그가 하나도 남지 않으며, 코드 주석도 이를 인정한다("XML anonymization is complex")
x.odtx_anonymized.txt확장자 변경

CSV가 가장 파괴적이다. 파일은 각 행을 공백으로 평탄화해 읽은 뒤, writer.writerow(line.split())로 다시 쓰인다(…py:632). 공백이 든 셀은 여러 열로 쪼개지고, 빈 셀은 사라진다. 열 정렬이 보존되지 않는다. 측정값 CSV는 쓸 수 없는 상태로 나온다.

대응표인 file_mappings.csv는 출력 폴더에 저장된다(…py:648):

열내용
Original File Name원본 파일 이름
Anonymized File Name생성된 이름, 또는 ERROR
UUID파일마다 뽑은 uuid.uuid4(), 실패 시에는 예외 메시지

이것은 사람을 재식별하기 위한 표가 아니다. 탐지된 이름과 그 치환값 사이의 대응이 전혀 없다. 그리고 UUID는 순전히 장식이다. 생성되지만(…py:531) 한 번도 사용되지 않는다. 내용에도, 출력 파일 이름에도 나타나지 않는다. 따라서 문서 간에 안정적인 가명화 장치는 없다.

함정

이 file_mappings.csv 파일은 익명화된 문서 바로 옆에 저장된다. 출력 폴더를 공유하면 원본 파일 이름 목록을 공유하는 셈이다.

7. 한계: 제거되지 않는 것

데이터셋을 공유할 수 있는지 판단하는 데 가장 유용한 절이다.

구조상 범위 밖

  1. 모든 영상. DICOM, NIfTI, NRRD, 메시: 읽지도, 수정하지도 않는다. 헤더 태그는 하나도 정리되지 않고, 얼굴도 지워지지 않는다(§0).
  2. 파일과 폴더 이름. Dupont_Jean_2019.docx는 Dupont_Jean_2019_anonymized.docx가 된다. 환자 이름이 파일 이름에 고스란히 남고, file_mappings.csv에도 그대로 복사된다. 입력 계층(.../Patients/Dupont_Jean/)도 흔히 그만큼 식별력이 있는데, 이는 평탄화된다. 그리고 두 하위 폴더에 같은 이름의 파일이 있으면 두 번째 파일이 첫 번째 파일을 소리 없이 덮어쓴다.

탐지의 사각지대

  1. 병원 식별자. MRN, 차트 번호, 접수 번호(accession number), 검사 식별자, 병상 번호를 위한 인식기가 없다. 제공되는 엔터티 12개 어디에도 없고, Presidio에도 기본으로는 없다.
  2. 미국 외의 모든 것. 선택 가능한 엔터티는 US_SSN, US_DRIVER_LICENSE, US_BANK_NUMBER다. 프랑스 NIR, NHS 번호, 여권 번호, ITIN은 탐지 대상이 아니다.
  3. HIPAA의 간접 식별자는 처리되지 않는다: 89세 초과 연령, 드문 날짜, 직업, 소규모 집단 소속. Presidio는 날짜 일반화를 하지 않는다. DATE_TIME은 통째로 치환되거나 전혀 치환되지 않는다.
  4. 언어. 분석은 영어로 고정되어 있다(§3). 영어가 아닌 말뭉치에서는 PERSON/LOCATION/DATE_TIME의 재현율이 무너지며, 경고는 전혀 없다.
  5. 0.5 임계값은 기본적으로 덜 확실한 탐지 결과를 모두 버린다. 대개 드문 이름, 영미권이 아닌 이름, 약어 형태다.
  6. 추출되지 않은 내용(DOCX 표, XML 속성, 스캔된 PDF, 머리글과 바닥글)은 분석되지 않는다. 출력으로 새어 나가지는 않지만, 받는 사람이 원본도 함께 받는다면 익명화는 그 내용을 전혀 다루지 않은 것이다.

소리 없는 실패 — 가장 심각한 발견 사항

  1. anonymize_text_presidio()는 다음으로 끝난다(…py:748):

    확인된 버그 — 소리 없는 실패
    except Exception as e:
    logger.error(f"Error in Presidio anonymization: {e}")
    return text  # Return original text if anonymization fails

    어떤 분석 오류든(설치된 Presidio 버전이 인식하지 못하는 엔터티, spaCy 모델 누락, 너무 긴 텍스트) 원문을 그대로 담은 _anonymized 파일을 만들어 낸다. 인터페이스에는 "Complete!" 상태가 표시되고, Python 콘솔에 빨간 줄 하나만 남는다. 사후 확인도, 탐지된 엔터티 수도, 보고서도 없다. 익명화되지 않은 문서는 읽어 보지 않고는 제대로 처리된 문서와 구별할 수 없다.

실무적 결론. 이 모듈의 출력만으로는 데이터셋을 비식별화되었다고 선언할 수 없다. 이는 영어 자유 텍스트에 대한 1차 처리로서 검토가 필요하며, 다음으로 보완해야 한다: 파일 이름 변경, 영상용 전용 DICOM 익명화 도구, 볼륨에 얼굴이 포함된다면 얼굴 제거.

8. 실행 환경

모든 것이 Slicer의 Python에서 실행되며, "Install Dependencies" 버튼(…py:392)으로 확인 절차도, 버전 고정도 없이 설치된다:

presidio-analyzer, presidio-anonymizer, pandas, python-docx, pdfplumber,
odfpy, lxml, langdetect, reportlab    then    spacy.cli.download("en_core_web_lg")

참고:

  • spacy는 pip_install 목록에 없고, 임포트만 된다(…py:409). presidio-analyzer가 의존성으로 끌어오기 때문에 동작한다. 이 임포트가 실패하면 블록 전체가 except로 떨어져 "Error installing dependencies."를 표시한다.
  • 설치 후 Slicer 재시작을 요청한다(대화 상자). spaCy 모델 로드를 고려하면 타당하다.
  • lxml은 설치되지만 쓰이지 않는다(코드는 xml.etree.ElementTree를 사용). langdetect는 설치되지만 한 번도 임포트되지 않는다.
  • os.environ['PRESIDIO_SUPPRESS_WARNINGS'] = '1'과 warnings.filterwarnings('ignore')가 모듈 수준에서 설정되므로, 확장 기능이 로드되자마자 적용된다. Presidio의 경고만이 아니라 Slicer 전체의 경고를 억제한다.
  • GPU도, conda도, CLI도 없다. AnalyzerEngine()과 spaCy 로드(몇 초)가 실행할 때마다 인터페이스 스레드에서 일어난다.

9. 함정과 취약 지점

  • 원문을 그대로 반환하는 소리 없는 실패(§7.9).
  • 평탄화된 출력 폴더: 이름 충돌, 메시지 없는 덮어쓰기.
  • CSV 재구성: line.split() 때문이다. XML은 일반 텍스트로 격하되고, ODT는 .txt로 이름이 바뀐다.
  • UUID는 생성되지만 적용되지 않는다: "대응표"로는 통제된 재식별을 할 수 없다.
  • file.replace(".docx", "_anonymized.docx"): str.replace는 모든 출현을 치환하므로, 이름에 확장자가 두 번 들어 있으면 예상치 못한 결과가 나온다.
  • 출력 PDF에는 페이지 나눔이 없다(Preformatted 블록 하나). 긴 문서는 프레임을 넘치거나 reportlab 예외를 일으킬 수 있으며, 이 경우 파일은 ERROR로 집계되지만 처리는 계속된다.
  • 모든 것이 UI 스레드에서 실행된다: 폴더가 크면 Slicer가 멈춘 것처럼 보인다.
  • README는 모듈을 과장한다: HIPAA 준수와 "AI-powered text analysis"를 이야기하지만, 코드는 영어 텍스트에 대해 Presidio를 기본값으로 호출할 뿐이며 검증도 없다.
  • README는 Medical_Data_Anonymizer_Module/Resources/Icons/icon.png를 가리키지만, 실제로 있는 파일의 이름은 Medical_Data_Anonymizer_Module.png다.
  • Medical_Data_Anonymizer_ModuleLogic / …Test는 빈 껍데기다. 테스트도 없고, 스크립트로 호출할 수 있는 것도 없다.

10. 문헌과 참고 자료

이 모듈을 다룬 논문은 없다. 저장소에도 어떤 말뭉치에 대한 평가(재현율, 정밀도)도 없다.

사용된 구성 요소는 문서화되어 있다:

  • Microsoft Presidio — 탐지·익명화 엔진. 사전 정의된 인식기와 연산자의 정확한 목록이 있다(replace, redact, hash, mask, encrypt. 마지막 것은 키로 되돌릴 수 있는데, 모듈은 이를 제공하지 않는다).
  • spaCy en_core_web_lg — 기본으로 쓰이는 영어 NER 모델.
  • HIPAA Safe Harbor, 45 CFR §164.514(b)(2) — 제거해야 할 식별자 18개 범주. §7의 판독 기준으로 유용하다. 파일 이름, 의무기록 식별자, 영상 식별자가 여기에 포함되지만 이 모듈은 이를 처리하지 않는다.

전체 참고문헌: SOURCES.html — 검색을 수행했으며, 모듈 자체에 대해서는 결과가 없었다. 이 폴더에는 비정형 임상 텍스트에 대한 Presidio의 유일한 발표된 평가와, i2b2/n2c2 텍스트 비식별화 경진 대회 링크가 있다. 이들은 이 코드를 기술하지는 않지만 판독 기준을 제공한다.

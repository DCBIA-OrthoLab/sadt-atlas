MedicalDataAnonymizer

Microsoft Presidio를 통해 텍스트 문서(DOCX, TXT, PDF, CSV, XML, ODT)의 민감한 엔티티를 탐지하고 치환하며, 모듈은 의료 영상을 전혀 건드리지 않는다. 이것은 DICOM 익명화 도구가 아니다. 이 페이지는 파이프라인을 단계별로 설명하며, 코드 세부 사항은 코드 페이지에 있다.

미발표 CLI 없음(Slicer 위젯) UI 스레드, conda 없음 참고문헌 VISOR: 로컬 사본만 코드(개발자용) 가이드

이 페이지는 레거시 Slicer 모듈(3c67957의 SlicerAutomatedDentalTools, 2026-10-26)을 설명한다. VISOR에는 이것을 위한 서버 도구가 없다. 클라이언트 확장은 Slicer 안에서 실행되며 아무것도 보내지 않는 이전 사본을 배포하는데, 이것은 VISOR가 업로드하는 파일의 비식별화가 아니다(그것은 명세만 있고 구현되지 않았다. VISOR의 비식별화). 이 모듈의 VISOR 페이지를 참조.

개요: 무엇이 들어가고 무엇이 나오는가

MedicalDataAnonymizer
입력텍스트 문서 폴더(Word, 텍스트, PDF, CSV, XML, ODT), 재귀적으로 검색됨
탐지Microsoft Presidio: 이름, 장소, 날짜를 위한 통계적 영어 모델과, 숫자, 이메일 및 유사한 식별자를 위한 체크섬이 있는 패턴
치환네 가지 방법 중 하나: 라벨, 제거, 해시, 별표
출력입력마다 재구성된 _anonymized 문서 하나, 모두 평평한 폴더 하나에, 그리고 file_mappings.csv

모듈은 텍스트만 익명화한다. 영어 자유 텍스트에 대한 첫 번째 처리이며, 데이터셋이 비식별화되었다고 선언하는 방법이 아니다(7절).

0. 모듈이 아닌 것

이름은 DICOM 익명화 도구를 암시하지만 전혀 그렇지 않으며, VISOR의 사본도 마찬가지이다. 모듈 전체에서 “DICOM”이나 “deface”를 검색하면 아무것도 나오지 않으므로 다음과 같다.

  • DICOM 태그는 읽히거나 바뀌지 않는다. 환자 이름이나 식별자도, 날짜도, 기관도, 고유 식별자도, 비공개 태그도 아니다.
  • 디페이싱은 전혀 적용되지 않는다. CBCT나 스캐너에서 재구성할 수 있는 얼굴은 손대지 않으며, 확장 어디에도 디페이싱 도구가 없다.
  • 지원되는 형식에는 영상이나 메시 형식도, 랜드마크 파일도 들어 있지 않다.

데이터를 공유해도 되는지 판단하는 사람은 먼저 7절을 읽어야 한다.

코드에서그것을 증명하는 검색, 지원되는 형식과 그 줄

1. 파이프라인에서의 위치

명령줄 작업이 없는 고립된 도구이다. 어떤 것도 이것을 호출하지 않으며, 이것도 아무것도 호출하지 않는다. 모든 로직이 위젯에 있으므로 Slicer의 메인 스레드에서 실행되어, 처리 중 인터페이스가 멈추고 진행률 표시줄만 갱신된다.

코드에서단일 파일, 빈 로직 클래스, UI 스레드

2. 입력: 형식별 텍스트 추출

폴더는 재귀적으로 훑으며 Word 잠금 파일은 무시한다. 각 파일은 분석 전에 문자열 하나로 축소되고, 출력은 그 문자열로부터 다시 만들어진다. 추출되지 않은 것은 분석되지도 이월되지도 않고 사라진다.

  • Word: 단락. 표, 머리글, 바닥글, 각주, 텍스트 상자, 주석, 메타데이터는 사라진다.
  • 텍스트: 있는 그대로 읽는다.
  • PDF: 텍스트 레이어. 스캔된 PDF는 빈 텍스트를 준다.
  • CSV: 각 행이 한 줄로 평탄화되므로 열 구조가 사라진다.
  • XML: 텍스트 내용만. 태그와 속성은 읽히지 않는다.
  • ODT: 단락. 표, 스타일, 메타데이터는 사라진다.

추출되지 않은 부분의 민감한 내용은 탐지되지 않지만 출력에도 도달하지 않는다. 유출은 없지만 데이터가 조용히 사라진다. Word 작성자 같은 파일 메타데이터도 파일이 다시 만들어지므로 사라진다.

코드에서라이브러리 호출과 각각이 잃는 것을 담은 형식 표

3. 탐지 엔진

모델은 포함되어 있지 않다. 모듈은 spaCy의 영어 모델을 설치하고 클릭할 때마다 기본 설정으로 Presidio 엔진을 만든다. 인식기 두 계열이 나란히 작동한다.

통계적인 것은 이름, 장소, 날짜를 찾는다. 규칙 기반인 것은 전화번호, 이메일, 미국 사회보장번호, 운전면허와 은행 번호, 의료 면허, 신용카드, IP 주소, URL을 패턴, 체크섬, 문맥 단어로 찾는다.

언어는 영어로 고정되어 있다. 프랑스어 노트 폴더는 영어 모델을 거치며 예상할 수 있듯 탐지가 낮고, 모듈은 이에 대해 아무 말도 하지 않는다. 언어 탐지기가 설치되지만 한 번도 쓰이지 않는다(세부 사항).

코드에서엔진 호출 두 개, 모델 다운로드, 고정된 언어

4. 엔티티와 치환 방법

엔티티 유형 열두 가지를 체크할 수 있고 기본으로 일곱 개가 체크되어 있다. 이름, 전화번호, 이메일 주소, 날짜와 시간, 위치, 사회보장번호, 의료 면허 번호이다. 나머지 다섯 개(운전면허, 신용카드, 은행 번호, IP 주소, URL)는 꺼져 있다. 이름, 날짜, 위치는 통계 모델에서 나오고(예측됨), 나머지는 규칙에서 나온다(계산됨).

해시는 탐지된 텍스트의 평범한 SHA-256이다. Presidio 2.2.355에서는 같은 이름이 항상 같은 다이제스트를 내므로 일관성이 유지되지만, 솔트도 키도 없으면 이름, 생년월일, 사회보장번호처럼 작은 공간에 대한 해시는 모든 후보를 시도해 되돌릴 수 있다. 보호가 아니라 공개된 가명으로 다뤄야 한다. 모듈은 Presidio 버전을 고정하지 않으며, 2.2.366은 해시되는 각 구간에 무작위 32바이트로 솔트를 더하므로, 거기서는 한 이름의 다이제스트가 출현마다 다르다.

코드에서기본값을 담은 엔티티 표와 연산자 설정

5. 출력과 매핑 표

모든 것이 출력 폴더에 평평하게 기록된다. 하위 폴더는 재현되지 않으며, 서로 다른 하위 폴더에 같은 이름의 파일 둘이 있으면 두 번째가 첫 번째를 덮어쓴다. Word, 텍스트, PDF 파일은 자기 형식으로 다시 만들어지고(PDF는 페이지 나눔 없는 블록 하나로), ODT 파일은 텍스트 파일이 되며, XML 파일은 .xml 이름 아래의 평문이 된다.

매핑 표 file_mappings.csv는 파일마다 원래 이름, 생성된 이름, UUID 하나를 나열한다. 이것은 재식별 표가 아니다. 탐지된 이름과 그 대체물 사이의 연결이 없으며, UUID는 생성된 뒤 어디에도 쓰이지 않는다. 익명화된 문서 옆에 놓이므로, 출력 폴더를 공유하면 원본 파일 이름의 목록도 공유된다.

코드에서출력 표, CSV 다시 쓰기, 매핑 열

7. 한계: 제거되지 않는 것

데이터셋을 공유해도 되는지 판단하는 데 가장 유용한 절이다.

  1. 모든 영상: 영상 파일이나 헤더에 있는 어떤 것도 읽히거나 바뀌지 않는다.
  2. 파일과 폴더 이름: 파일 이름에 있는 환자의 이름은 출력 이름과 매핑 표에 그대로 남으며, 폴더 계층은 평탄화된다.
  3. 병원 식별자: 기록 번호, 접수 번호, 병상 번호에는 인식기가 없다.
  4. 미국 것이 아닌 모든 것: 미국 번호만 검색되며, 프랑스 NIR, NHS 번호, 여권은 검색되지 않는다.
  5. 간접 식별자: 89세 초과의 나이, 드문 날짜, 직업. 날짜는 통째로 치환되거나 전혀 치환되지 않는다.
  6. 언어: 영어가 아닌 텍스트에서는 탐지가 무너지며 경고가 없다.
  7. 0.5 임계값은 덜 확실한 탐지를 버리지만, 어느 탐지가 그런지는 인식기에 달려 있다. spaCy의 이름, 장소, 날짜 탐지는 모두 같은 고정 점수를 받으므로(Presidio 2.2.355와 2.2.366의 기본값 0.85), 0.5 임계값은 드문 이름과 흔한 이름을 가르지 못하며 주로 패턴 기반 인식기에 작용한다.
  8. 추출되지 않은 내용: 표, 속성, 스캔된 페이지, 머리글.
  9. 조용한 실패, 가장 심각한 발견 사항. 분석이 어떤 오류든 일으키면 모듈은 원본 텍스트를 그대로 담은 _anonymized 파일을 쓰고, “Complete!”라고 보고하며, Python 콘솔에 빨간 줄 한 줄을 남긴다. 발견된 엔티티를 세거나 나중에 확인하는 것은 없다(세부 사항).

실제로 출력은 영어 자유 텍스트에 대한 첫 번째 처리이며 검토되어야 하고, 파일 이름 바꾸기, 영상을 위한 전용 DICOM 익명화 도구, 볼륨이 얼굴을 포함하는 경우 디페이싱이 필요하다.

코드에서아홉 가지 한계의 전문과 조용한 실패의 코드

8. 환경

모든 것은 Slicer의 Python에서 실행되며, 확인 없이 고정된 버전도 없이 버튼 하나로 설치되고, 이어서 영어 spaCy 모델의 다운로드와 Slicer 재시작 요청이 뒤따른다. GPU도, conda도, 명령줄 작업도 없다. 엔진을 로드하는 데 실행할 때마다 인터페이스 스레드에서 몇 초가 걸린다. 경고는 모듈이 로드되자마자 Slicer 전체에서 꺼진다.

코드에서패키지 목록, 죽은 의존성, 모듈 수준 경고 필터

9. 알려진 문제

  • 원본 텍스트를 반환하는 조용한 실패(세부 사항).
  • 평평한 출력 폴더는 같은 이름의 파일을 메시지 없이 덮어쓴다(모든 함정).
  • CSV 파일은 재구조화되고, XML은 평문으로 열화되며, ODT는 텍스트로 이름이 바뀐다(모든 함정).
  • 매핑 표의 UUID는 생성되지만 적용되지 않는다(세부 사항).
  • 모든 것이 인터페이스 스레드에서 실행되므로 큰 폴더에서는 Slicer가 멈춘 것처럼 보인다(모든 함정).
  • README는 코드가 영어 텍스트에 대한 기본 Presidio 호출인데도 HIPAA 준수와 AI 기반 분석을 이야기한다(모든 함정).
  • 모듈에는 테스트가 없고 스크립트로 호출할 수 있는 것도 없다(모든 함정).
코드에서파일 이름 replace를 포함해 줄과 함께 보는 모든 함정

10. 문헌과 참고자료

이 모듈을 다루는 논문은 없으며, 저장소에는 어떤 코퍼스에 대한 평가(재현율, 정밀도)도 없다.

사용된 구성 요소는 문서화되어 있다.

  • Microsoft Presidio: 탐지 및 익명화 엔진이며, 사전 정의된 인식기와 연산자의 정확한 목록이 있다(replace, redact, hash, mask, encrypt. 마지막 것은 키로 되돌릴 수 있으며 모듈은 제공하지 않는다).
  • spaCy en_core_web_lg: 기본으로 쓰이는 영어 NER 모델.
  • HIPAA Safe Harbor, 45 CFR §164.514(b)(2): 제거해야 하는 식별자 18개 범주. §7의 읽기 틀로 유용하다. 파일 이름, 의무 기록 식별자, 영상 식별자가 여기에 나오며, 이 모듈은 그것들을 다루지 않는다.

전체 참고문헌: SOURCES.html, 검색을 마쳤으며 모듈 자체에 대한 결과는 없다. 이 폴더에는 비정형 임상 텍스트에 대한 Presidio의 유일한 발표된 평가와, 이 코드를 설명하지는 않지만 그 읽기 틀을 제공하는 i2b2/n2c2 텍스트 비식별화 캠페인에 대한 링크가 있다.

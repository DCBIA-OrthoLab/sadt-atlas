MedicalDataAnonymizer, 레거시: 코드

개발자용: 레거시 Slicer 모듈 MedicalDataAnonymizer가 코드에서 하는 일을 다룬다(3c67957의 SlicerAutomatedDentalTools). file:line 참조, 코드 블록, 엔티티, 환경, 확인된 조용한 실패가 있다. 같은 파이프라인에 대한 읽기 쉬운 설명은 아틀라스 페이지에 있다.

미발표 CLI 없음(Slicer 위젯) UI 스레드, conda 없음 참고문헌 VISOR: 로컬 사본만 코드 아틀라스 (해설) 가이드
두 코드 베이스

아래에 번호가 붙은 모든 내용은 레거시 Slicer 모듈(3c67957의 SlicerAutomatedDentalTools, 2026-10-26)을 설명한다. VISOR에는 이것을 위한 서버 도구가 없다. VISOR 클라이언트 확장은 Slicer 안에서 실행되며 아무것도 보내지 않는 이전 사본을 배포하는데, 이것은 VISOR가 업로드하는 파일의 비식별화가 아니다(그것은 명세만 있고 구현되지 않았다. VISOR의 비식별화 참조). 자세한 내용은 이 모듈의 VISOR 페이지에 있다.

어휘의 함정 · VISOR에서도 마찬가지

VISOR에서도 마찬가지다. 클라이언트 사본은 텍스트 전용이며(AutomatedDentalToolsRemote README.md:215), 이름이 암시할 수 있는 영상 비식별화는 클라이언트에 존재하지 않는다(README.md:31-34).

이름은 DICOM 익명화 도구를 암시하지만 전혀 그렇지 않다. MedicalDataAnonymizer는 텍스트 문서를 비식별화한다. Presidio + spaCy를 통해서이다. DICOM 태그(PatientName, PatientID, UID…)는 읽히거나 수정되지 않으며, 영상에는 디페이싱이 적용되지 않는다. 확장 전체에 디페이싱 도구가 아예 없다.

0. 모듈이 아닌 것

쉬운 설명과 수식: 아틀라스 페이지.

이름은 DICOM 익명화 도구를 암시하지만 전혀 그렇지 않으며, 명령 하나로 확인할 수 있다.

$ grep -rin "dicom\|pydicom\|deface" Medical_Data_Anonymizer_Module/
(no result)
$ grep -rlni "deface" --include="*.py" --include="*.md" .
(no result anywhere in the repository)

직접적인 결과:

  • DICOM 태그는 하나도 지워지거나 바뀌지 않는다. PatientName(0010,0010)도, PatientID(0010,0020)도, PatientBirthDate도, StudyDate도, InstitutionName도, UID도, 비공개 태그도, BurnedInAnnotation도 아니다.
  • 디페이싱 없음: CBCT나 스캐너에서 재구성할 수 있는 얼굴은 어떤 방법으로도 바뀌지 않는다(얼굴 마스크도, 블러도, 표면 제거도 없다). 확장 전체에 디페이싱 도구가 없다.
  • 지원되는 형식(.docx, .txt, .pdf, .csv, .xml, .odt, Medical_Data_Anonymizer_Module.py:514)에는 .dcm, .nii.gz, .nrrd, .vtk, 랜드마크 .json 중 어느 것도 들어 있지 않다.

데이터를 공유해도 되는지 판단하는 운영자는 §7을 곧바로 읽어야 한다.

1. 파이프라인에서의 위치

쉬운 설명과 수식: 아틀라스 페이지.

CLI가 없는 고립된 도구이다. 어떤 것도 이것을 호출하지 않으며, 이것도 저장소의 다른 어떤 것도 호출하지 않는다. 모든 것이 774줄짜리 파일 하나, Medical_Data_Anonymizer_Module.py에 있으며 그중 약 350줄이 Qt 스타일시트이다.

Medical_Data_Anonymizer_ModuleLogic과 …Test는 빈 클래스이다(pass). 모든 로직이 위젯에 있으므로 Slicer의 메인 스레드에서 실행되어 처리 중 인터페이스가 멈추며, 진행률 표시줄만 slicer.app.processEvents()로 갱신된다.

2. 입력: 형식별 텍스트 추출

쉬운 설명과 수식: 아틀라스 페이지.

입력 폴더를 재귀적으로 훑으며(os.walk), ~$로 시작하는 파일(Word 잠금 파일)은 무시한다. 각 파일은 분석 전에 문자열 하나로 축소된다.

형식추출도중에 사라지는 것
.docxpython-docx, "\n".join(p.text for p in doc.paragraphs)표, 머리글/바닥글, 각주, 텍스트 상자, 주석, 파일 메타데이터
.txt원시 UTF-8 읽기–
.pdfpdfplumber, page.extract_text(). 예외가 나면 extract_tables()로 두 번째 시도이미지, 스캔된 PDF(OCR 없음) → 빈 텍스트
.csvcsv.reader, 각 행을 " ".join(row)로 평탄화열 구조
.xmlElementTree + 재귀적 extract_text_from_xml()(텍스트 + tail)태그와 속성: 속성 값은 읽히지 않는다
.odtodfpy, text.P의 텍스트 노드표, 스타일, 메타데이터

손실은 충실도의 문제만이 아니다. 출력 문서는 이 문자열로부터 다시 만들어진다. 추출되지 않은 것은 익명화되지 않지만 이월되지도 않고 사라진다. 반대로 추출되지 않은 부분(DOCX 표, XML 속성)에 있는 민감한 내용은 탐지되지도 이월되지도 않는다. 유출은 없지만 데이터가 조용히 사라진다.

눈에 띄는 예외가 있다. 어떤 것도 파일의 메타데이터(DOCX 작성자, PDF의 Producer)를 읽지 않는다. 파일이 처음부터 다시 만들어지므로 이것도 사라진다.

3. 탐지 엔진

쉬운 설명과 수식: 아틀라스 페이지.

저장소에는 모델이 없으며, 모듈 자체가 내려받는 가중치도 spaCy 모델을 제외하면 없다. "Anonymize Files"를 클릭할 때마다 Presidio 엔진 두 개가 생성되며(…py:499-502), stderr는 SuppressStderr 클래스로 우회된다.

analyzer = AnalyzerEngine()      # default config
anonymizer = AnonymizerEngine()

인자 없는 AnalyzerEngine()은 Presidio의 기본 NLP 설정, 즉 spaCy en_core_web_lg를 쓴다. install_dependencies()가 내려받는 유일한 모델이다(spacy.cli.download, …py:432).

인식기 두 계열이 결합된다. spaCy의 통계적 NER(PERSON, LOCATION, DATE_TIME)과 패턴 및 체크섬 기반 인식기(PHONE_NUMBER, EMAIL_ADDRESS, US_SSN, MEDICAL_LICENSE, US_DRIVER_LICENSE, CREDIT_CARD, US_BANK_NUMBER, IP_ADDRESS, URL)이다.

함정 · VISOR에서도 마찬가지

VISOR에서도 마찬가지다(클라이언트 사본). 배포된 사본에도 같은 코드가 있다. language='en'은 AutomatedDentalToolsRemote Medical_Data_Anonymizer_ModuleRemote/Medical_Data_Anonymizer_ModuleRemote.py:716에, pip_install('langdetect')는 :405에 있다(3c67957의 레거시: :724와 :413. 이 콜아웃에 인용된 줄은 이전 리비전의 것이다).

언어는 영어로 고정되어 있다. analyzer.analyze(..., language='en')(…py:724)이며, "with automatic language detection"이라는 주석이 있고 langdetect가 설치되는데도, 이것은 import되지 않는 죽은 의존성이다. 프랑스어 노트 폴더가 영어 모델을 거치며, 예상할 수 있는 재현율을 얻는다.

신뢰도 임계값: score_threshold, 슬라이더 0.0–1.0, 기본값 0.5. 임계값 미만의 탐지는 흔적 없이 버려진다. Presidio의 검사는 result.score >= score_threshold(analyzer_engine.py, __remove_low_scores, 2.2.355와 2.2.366에서 동일)이므로 임계값과 같은 점수는 유지된다.

4. 엔티티와 치환 방법

쉬운 설명과 수식: 아틀라스 페이지.

체크박스 열두 개, 기본으로 일곱 개가 체크됨(…py:98-115):

Presidio 엔티티UI 라벨기본값
PERSON 예측됨Names (patients, doctors)✔
PHONE_NUMBER 계산됨Phone Numbers✔
EMAIL_ADDRESS 계산됨Email Addresses✔
DATE_TIME 예측됨Dates and Times✔
LOCATION 예측됨Addresses and Locations✔
US_SSN 계산됨Social Security Numbers✔
MEDICAL_LICENSE 계산됨Medical License Numbers✔
US_DRIVER_LICENSE, CREDIT_CARD, US_BANK_NUMBER, IP_ADDRESS, URL 계산됨–✘

"Advanced Options"의 방법 네 가지(…py:129-132):

방법구현결과
replace (default)operators = {} → None으로 전달됨 → Presidio의 기본 연산자<PERSON>, <DATE_TIME>, …
redact엔티티마다 OperatorConfig("redact")해당 부분이 사라지고 텍스트가 다시 붙는다
hashOperatorConfig("hash")presidio-anonymizer 2.2.355에서는 탐지된 텍스트의 솔트 없는 SHA-256이고, 2.2.366에서는 구간마다 무작위 32바이트 솔트가 더해진다(operators/hash.py)
maskOperatorConfig("mask", {"masking_char": "*", "chars_to_mask": 100, "from_end": False})해당 부분 전체를 덮는 별표

hash에 대해: README는 "cryptographic hashes for consistent anonymization"이라고 말한다. 일관성 주장은 presidio-anonymizer 2.2.355에서는 성립하지만(같은 이름은 항상 같은 다이제스트를 낸다), 솔트도 키도 없다. 이름, 생년월일, 사회보장번호 같은 값처럼 값 공간이 작으면 다이제스트는 무차별 대입으로 몇 초 만에 재식별될 수 있다. 보호가 아니라 공개된 가명으로 다뤄야 한다. 모듈은 버전을 고정하지 않으며(pip_install('presidio-anonymizer'), :407), 2.2.366은 솔트를 넘기지 않는 한 모든 구간에 os.urandom(32)로 솔트를 더하는데 모듈은 이를 하지 않는다. 그 버전에서는 같은 이름도 매번 다른 다이제스트를 얻으며, 일관성 주장은 거짓이다.

5. 출력과 매핑 표

쉬운 설명과 수식: 아틀라스 페이지.

출력 폴더에 평평하게 기록된다. 입력의 하위 폴더 계층은 재현되지 않는다.

입력출력참고
x.docxx_anonymized.docx재구성된 문서, 줄마다 단락 하나, 스타일 없음
x.txtx_anonymized.txt–
x.pdfx_anonymized.pdfreportlab이 재생성하며, Preformatted 블록 하나
x.csvx_anonymized.csv아래 참조
x.xmlx_anonymized.xml.xml 확장자 아래의 평문: 태그가 남지 않으며, 코드 주석도 이를 인정한다("XML anonymization is complex")
x.odtx_anonymized.txt확장자 변경

CSV의 경우가 가장 파괴적이다. 파일은 각 행을 공백으로 평탄화하여 읽혔고, 그다음 writer.writerow(line.split())으로 다시 쓰인다(…py:640). 공백이 들어 있는 셀은 여러 열로 쪼개지고 빈 셀은 사라지므로 열 정렬이 유지되지 않는다. 측정값 CSV는 쓸 수 없게 되어 나온다.

매핑 표 file_mappings.csv는 출력 폴더에 기록된다(…py:656):

열내용
Original File Name원본 파일의 이름
Anonymized File Name생성된 이름, 또는 ERROR
UUID파일마다 뽑은 uuid.uuid4(), 실패하면 예외 메시지

이것은 사람에 대한 재식별 표가 아니다. 탐지된 이름과 그 대체물 사이의 매핑이 전혀 들어 있지 않다. 그리고 UUID는 순전히 장식이며, 생성되지만(…py:539) 쓰이지 않는다. 내용에도 출력 파일 이름에도 나타나지 않는다. 따라서 문서 간에 안정적인 가명화 메커니즘이 없다.

함정 · VISOR에서도 마찬가지

VISOR에서도 마찬가지다(클라이언트 사본). 배포된 사본에서도 같은 동작이다(AutomatedDentalToolsRemote Medical_Data_Anonymizer_ModuleRemote/Medical_Data_Anonymizer_ModuleRemote.py:500,649-670. 레거시 :508,656-677).

이 file_mappings.csv 파일은 익명화된 문서 바로 옆에 기록된다. 출력 폴더를 공유하는 것은 원본 파일 이름의 목록을 공유하는 것과 같다.

6. 예측되는 것과 계산되는 것

쉬운 설명과 수식: 아틀라스 페이지.

블록성격위치
텍스트 추출계산됨 결정론적, 형식 라이브러리별위젯, UI 스레드
PERSON / LOCATION / DATE_TIME의 탐지예측됨 네트워크: spaCy NER en_core_web_lg(CNN + 임베딩), Presidio를 통해위젯, CPU
숫자(SSN, 전화, 카드, 면허…)의 탐지계산됨 정규식 + 체크섬과 문맥 키워드동일
치환계산됨 결정론적(replace / redact / SHA-256 / mask)presidio-anonymizer
문서 재구성계산됨 결정론적, 형식별위젯

저장소에서 학습되거나 포함된 모델은 없으며, en_core_web_lg는 설치 시 spacy.cli.download로 받아 온다.

7. 한계: 제거되지 않는 것

쉬운 설명과 수식: 아틀라스 페이지.

데이터셋을 공유해도 되는지 판단하는 데 가장 유용한 절이다.

구조상 범위 밖

  1. 모든 영상. DICOM, NIfTI, NRRD, 메시는 읽히지도 수정되지도 않는다. 어떤 헤더 태그도 정리되지 않고 어떤 얼굴도 지워지지 않는다(§0).
  2. 파일과 폴더 이름. Dupont_Jean_2019.docx는 Dupont_Jean_2019_anonymized.docx가 된다. 환자의 이름이 파일 이름에 그대로 남으며, file_mappings.csv에도 그대로 복사된다. 입력 계층도 흔히 똑같이 식별력이 있는데(.../Patients/Dupont_Jean/), 평탄화되며, 두 하위 폴더에 같은 이름의 파일이 있으면 두 번째가 조용히 첫 번째를 덮어쓴다.

탐지의 사각지대

  1. 병원 식별자. MRN, 차트 번호, 접수 번호, 검사 식별자, 병상 번호에 대한 인식기가 없다. 제공되는 열두 개 엔티티 어디에도 나타나지 않으며, Presidio에도 기본으로 없다.
  2. 미국 것이 아닌 모든 것. 선택할 수 있는 엔티티는 US_SSN, US_DRIVER_LICENSE, US_BANK_NUMBER이며, 프랑스 NIR, NHS 번호, 여권 번호, ITIN은 검색되지 않는다.
  3. HIPAA의 간접 식별자는 다뤄지지 않는다. 89세 초과의 나이, 드문 날짜, 직업, 소규모 집단의 구성원 자격이다. Presidio는 날짜 일반화를 하지 않는다. DATE_TIME은 통째로 치환되거나 전혀 치환되지 않는다.
  4. 언어. 분석은 영어로 고정되어 있다(§3). 영어가 아닌 코퍼스에서는 PERSON/LOCATION/DATE_TIME의 재현율이 아무 경고도 없이 무너진다.
  5. 0.5 임계값은 그 미만의 점수를 받은 탐지를 버린다. 어느 것이 버려지는지는 인식기에 달려 있다. spaCy 엔티티(이름, 장소, 날짜)는 모두 고정된 점수 하나를 받으므로(Presidio 2.2.355와 2.2.366 소스에서 ner_strength / default_score = 0.85), 0.5는 드물거나 앵글로색슨계가 아닌 이름을 걸러 내지 않으며, 패턴 기반 인식기에 작용한다. 실제 설치본에서는 테스트하지 않았다.
  6. 추출되지 않은 내용(DOCX 표, XML 속성, 스캔된 PDF, 머리글과 바닥글)은 분석되지 않는다. 출력으로 새지는 않지만, 수신자가 원본도 함께 받는다면 익명화는 그것을 한 번도 다루지 않은 셈이다.

조용한 실패: 가장 심각한 발견 사항

  1. anonymize_text_presidio()는 다음으로 끝난다(…py:757-759):

    확인된 버그: 조용한 실패 · VISOR에서도 마찬가지

    VISOR에서도 마찬가지다(클라이언트 사본). 배포된 사본에도 같은 폴백이 있으며(AutomatedDentalToolsRemote Medical_Data_Anonymizer_ModuleRemote/Medical_Data_Anonymizer_ModuleRemote.py:750-751) 같은 "Complete!" 메시지도 있다(:673). 레거시는 :758-759와 :680이다.

    logger.error(f"Error in Presidio anonymization: {e}")
    return text  # Return original text if anonymization fails

    어떤 분석 오류(설치된 Presidio 버전이 인식하지 못하는 엔티티, 없는 spaCy 모델, 너무 긴 텍스트)든 원본 텍스트가 그대로 들어 있는 _anonymized 파일을 만들어 내며, 인터페이스에는 "Complete!" 상태가, Python 콘솔에는 빨간 줄 한 줄이 나온다. 사후 검사도, 탐지된 엔티티의 개수도, 보고서도 없다. 익명화되지 않은 문서는 읽어 보지 않고는 깨끗한 문서와 구별할 수 없다.

실무적 결론. 이 모듈의 출력만으로는 데이터셋이 비식별화되었다고 선언하기에 충분하지 않다. 이것은 영어 자유 텍스트에 대한 첫 번째 처리이며 검토되어야 하고, 파일 이름 바꾸기, 영상을 위한 전용 DICOM 익명화 도구, 볼륨이 얼굴을 포함하는 경우 디페이싱으로 보완되어야 한다.

9. 함정과 취약한 지점

쉬운 설명과 수식: 아틀라스 페이지.

  • 원본 텍스트를 반환하는 조용한 실패(§7.9).
  • 평탄화된 출력 폴더: 이름 충돌, 메시지 없이 덮어씀.
  • line.split()에 의해 CSV가 재구조화되고, XML은 평문으로 열화되며, ODT는 .txt로 이름이 바뀐다.
  • UUID는 생성되지만 적용되지 않는다: "매핑 표"는 통제된 재식별을 허용하지 않는다.
  • file.replace(".docx", "_anonymized.docx"): str.replace는 모든 출현을 바꾸므로, 확장자가 두 번 들어 있는 이름은 예상치 못한 결과를 낸다.
  • 출력 PDF에는 페이지 나눔이 없다(Preformatted 블록 하나). 긴 문서는 프레임을 넘치거나 reportlab 예외를 일으킬 수 있으며, 그 경우 파일은 ERROR로 세어지지만 처리는 계속된다.
  • 모든 것이 UI 스레드에서 실행된다. 큰 폴더에서는 Slicer가 멈춘 것처럼 보인다.
  • README는 모듈을 과장한다. 코드가 영어 텍스트에 대한 기본 Presidio 호출이며 검증이 없는데도 HIPAA 준수와 "AI-powered text analysis"를 이야기한다.
  • README는 Medical_Data_Anonymizer_Module/Resources/Icons/icon.png를 가리키지만 실제로 있는 파일의 이름은 Medical_Data_Anonymizer_Module.png이다.
  • Medical_Data_Anonymizer_ModuleLogic / …Test는 빈 껍데기이다. 테스트도 없고 스크립트로 호출할 수 있는 것도 없다.

10. 문헌과 참고자료

쉬운 설명과 수식: 아틀라스 페이지.

이 모듈을 다루는 논문은 없으며, 저장소에는 어떤 코퍼스에 대한 평가(재현율, 정밀도)도 없다.

사용된 구성 요소는 문서화되어 있다.

  • Microsoft Presidio: 탐지 및 익명화 엔진이며, 사전 정의된 인식기와 연산자의 정확한 목록이 있다(replace, redact, hash, mask, encrypt. 마지막 것은 키로 되돌릴 수 있으며 모듈은 제공하지 않는다).
  • spaCy en_core_web_lg: 기본으로 쓰이는 영어 NER 모델.
  • HIPAA Safe Harbor, 45 CFR §164.514(b)(2): 제거해야 하는 식별자 18개 범주. §7의 읽기 틀로 유용하다. 파일 이름, 의무 기록 식별자, 영상 식별자가 여기에 나오며, 이 모듈은 그것들을 다루지 않는다.

전체 참고문헌: SOURCES.html, 검색을 마쳤으며 모듈 자체에 대한 결과는 없다. 이 폴더에는 비정형 임상 텍스트에 대한 Presidio의 유일한 발표된 평가와, 이 코드를 설명하지는 않지만 그 읽기 틀을 제공하는 i2b2/n2c2 텍스트 비식별화 캠페인에 대한 링크가 있다.

AMASSS

AMASSS는 구조물마다 신경망 하나를 두고, 머리 스캔을 복셀 하나씩 해부학적 구조물로 나눈다. 이 페이지는 레거시 Slicer 모듈에서 실행이 어떻게 진행되는지를 단계별로 설명하며, 학습이 아니라 계산에 해당하는 부분(스캔의 정규화, 신경망 패치의 블렌딩, 마스크 병합, 표면 생성)은 수식과 함께 다룬다. 코드에 확인해 볼 만한 대목이 있으면 코드 페이지로 가는 링크를 달았다.

코드(개발자용) Gillot 2022 · PLOS ONE AMASSS_CLI Slicer의 Python, conda 없음 VISOR 참고문헌

개요: 무엇이 들어가고 무엇이 나오는가

AMASSS는 3D 머리 스캔(CBCT)을 받아 하악, 상악, 두개저, 상기도, 경추, 피부와 정합용 마스크 3개로 나눈다. 구조물마다 신경망 하나를 쓰며, 각 신경망은 모든 복셀에 대해 “이 복셀은 내 구조물에 속하는가?”라는 질문 하나에 답한다. 이 모듈은 Slicer의 자체 Python에서 명령줄 프로그램을 시작하는 Slicer 위젯이다.

입력처리 과정출력
스캔(.nii, .nii.gz, .nrrd...) 하나 또는 스캔이 든 폴더, 그리고 원하는 구조물각 스캔을 변환하고, 구조물마다 전용 신경망으로 하나씩 차례로 예측한 뒤, 마스크를 조립한다구조물별 이진 마스크 및/또는 스캔당 병합 레이블 맵 하나, 선택적으로 3D 표면(.vtk)

이 페이지는 레거시 Slicer 모듈(3c67957 시점의 SlicerAutomatedDentalTools, 2026-10-26)을 설명한다. 서버 이식판은 VISOR의 AMASSS이다.

1. 체인에서의 위치

AMASSS는 독립된 모듈이면서 동시에 구성 요소이기도 하다. AREG_CBCT는 이를 두 번 사용한다(먼저 정합용 마스크(구조물당 파일 하나)를 만들고, 나중에 결과물인 분할을 만든다). VFACE는 비대칭 분석 체인 안에서, MRI2CBCT는 CBCT의 두개저를 위해 한 번 사용한다. 모두 같은 명령줄 프로그램을 실행한다. AMASSS는 다른 모듈을 호출하지 않는다. 이 프로그램은 nnU-Net(필요할 때만 import) 외에 torch, SimpleITK, VTK, cc3d, NumPy와 ADT 공용 헬퍼 라이브러리를 import한다.

AREG와 관련해 중요한 구분이 있다. 마스크 구조물 3개(CBMASK, MANDMASK, MAXMASK)는 두개저, 하악, 상악의 후처리가 아니다. 이들은 따로 학습된 모델로, 해상도(0.4 mm 대신 0.3 mm)와 학습 세트 크기(모델 설명 기준 76 대신 50)가 다르다.

코드에서파일과 줄이 적힌 호출자 표

2. 관련 파일

두 부분으로 이루어진다. 선택 사항을 모으는 Slicer 위젯과, 모든 작업(모델 탐색, 추론, 조립)을 하는 명령줄 프로그램이다. 둘 다 Slicer의 Python에서 실행되며 conda 환경은 쓰지 않는다. 그래픽 카드는 필수가 아니지만, 배치 처리에서는 단일 코어 리샘플링이 시간을 지배하므로 CPU로는 사실상 쓸 수 없다. 프로그램은 열두 개의 인자를 위치로 받는다.

코드에서파일 표와 순서대로 정리한 위치 인자 열두 개

3. 입력과 전처리

3.1 파일 탐색

파일이나 폴더를 받을 수 있다. 폴더는 재귀적으로 탐색하는데, AREG가 정합된 스캔을 하위 폴더에 쓰기 때문이다. 볼륨 확장자를 가진 파일만 유지한다. 두 종류의 이름은 건너뛴다. MASK를 포함하는 이름, 그리고 입력이 분할이 아닌 경우 밑줄로 둘러싸인 예측 ID(기본값 _Pred_)를 포함하는 이름이다. 후자는 이전 실행의 출력이므로(다시 분할하면 빈 마스크가 나온다) 제외한다. 이 두 필터는 폴더에만 적용되며, 직접 지정한 단일 파일은 걸러지지 않는다.

3.2 변환

각 스캔은 발견된 순서대로 번호가 붙은 이름(p_001, p_002...)으로 폴더 하나에 복사된다. .nii.gz는 그대로 복사하고, 나머지는 다시 읽어서 다시 쓴다. nnU-Net이 파일 확장자로 리더를 고르기 때문이다. 복셀 타입은 건드리지 않는다. nnU-Net이 알아서 float로 변환하기 때문이다.

3.3 AMASSS가 더는 하지 않는 것

이 저장소에는 강도 정규화, 윈도잉, 리샘플링이 작성되어 있지 않다. 예전 윈도잉 함수는 아무도 호출하지 않는 빈 껍데기이다. 실제로 적용되는 전처리는 모두 nnU-Net 고유의 것이며, 모델마다의 plan에 기술된다. 0이 아닌 영역으로 자르기, 강도 정규화, 그 다음 목표 간격으로 리샘플링하는 순서이다.

코드에서탐색 필터, 변환 함수, 죽은 윈도잉 함수

4. 모델

4.1 번들과 그 탐색

요청된 구조물마다 프로그램은 모델 폴더 안에서, 단일 fold의 학습된 체크포인트가 있는 모델 폴더를 찾는다. 체크포인트가 없는 구조물은 사용 불가로 표시하고 나머지로 실행을 계속한다. “Download latest models” 버튼은 압축 파일(약 2 GB)을 한 번 내려받는다. AREG와 VFACE가 자동으로 내려받는 것도 같은 파일이다.

4.2 번들에 실제로 들어 있는 것

폴더 아홉 개, 구조물당 하나이며 각각 학습된 fold 하나만 가진다. 두 계열로 나뉜다. 전체 시야 모델(하악, 상악, 두개저, 경추, 상기도, 피부)은 등방성 0.4 mm에 128 복셀 패치를 쓰고, 정합 마스크 3개는 0.3 mm에 정육면체가 아닌 다른 패치(112 × 160 × 128 복셀)를 쓴다. 아홉 모델 모두 같은 구조를 공유한다. nnU-Net이 구성하는 단순 합성곱 3D U-Net으로, 6단계에 잔차 블록은 없다.

각 모델은 이진이다. 배경과 구조물 하나만 안다. 병합 볼륨에서 구조물의 최종 값은 모델이 아니라 프로그램이 정한다.

코드에서모델 탐색, plan 필드, 아키텍처 블록

4.4 추론

프로그램은 자체 슬라이딩 윈도를 쓰지 않는다. 각 모델 plan의 패치 크기를 바탕으로 nnU-Net이 처리한다. 프로그램이 고르는 파라미터는 step 0.5(step은 패치의 절반 이하이므로 패치가 최소 절반은 겹친다), 가우시안 가중 켬, 테스트 시 미러링 끔뿐이다.

루프는 스캔 단위가 아니라 구조물 단위이다. 모든 스캔이 모델 하나를 통과한 뒤에야 다음 모델을 로드하므로, 체크포인트는 N × S번이 아니라 S번 로드된다. 모델 경로는 명시적으로 지정한다. 프로세스 전역 환경 변수를 쓰면 두 실행이 서로의 경로를 덮어쓸 수 있기 때문이다. 실패한 구조물은 기록하고 실행은 계속하며, 전부 실패했을 때만 실패로 끝난다.

5. 알고리즘의 핵심(학습되지 않음)

5.1 GPU 리샘플링

코드 주석에 따르면 단일 코어 리샘플링은 신경망보다 약 일곱 배의 비용이 들기 때문에, 프로그램은 그래픽 카드에서 실행되는 torch 리샘플러로 대체한다. 수치 차이는 의도적으로 감수한다. torch에는 3D 3차 보간이 없어서 입력의 보간이 3차에서 1차로 바뀐다. 카드의 메모리가 부족하면 해당 구조물은 더 느린 리샘플러로 다시 실행한다.

코드에서리샘플러 대체, 그 안전장치, 메모리 폴백

5.2 조립과 기록

각 스캔에 대해 구조물별 예측을 다시 읽어 이진 마스크(0보다 큰 모든 값)로 바꾼다. 그런 다음 마스크를 구조물당 하나씩 쓰거나, 병합하거나, 둘 다 한다. 병합 맵은 구조물이 최소 두 개 필요하다. 순서는 우선순위 순서이다. 마지막에 쓴 구조물이 공유 복셀에서 앞의 것을 덮어쓴다. 목록에는 아무것에도 대응하지 않는 코드가 둘 있다. CAN(어느 사전에도 없음)과 RC(치근관: 모델도 없고 표에 레이블도 없어서 하악의 레이블로 대체될 것이다)이며, 둘 다 죽은 항목이다.

각 마스크는 16비트 정수로 변환되고 스캔의 간격, 방향, 원점이 부여된다. 기하가 다를 때만 확인하여 최근접 이웃으로 리샘플링하는데, 정상적인 경우에는 일어나지 않는다.

코드에서조립 함수, 병합 순서, 기하 검사

5.3 후처리: 더 이상 없는 것

구멍 메우기, 연결 성분 선택, 형태학 연산은 적용되지 않는다. 이를 위한 함수가 둘 남아 있지만 아무도 호출하지 않는다. 이전 버전은 두 구조물을 제외한 모든 구조물을 정리하고 피부를 잘라 냈다. nnU-Net 이식에서 이 호출들이 제거되었으므로, 이제 정리는 번들에 nnU-Net 자체의 후처리가 들어 있다면 그것에 의존한다.

5.4 VTK 표면 생성

모드는 둘이다. 병합은 모든 레이블을 이어 붙인 파일 하나, 분리는 구조물당 파일 하나이다. 각 셀은 구조물의 색에서 가져온 일정한 색 하나를 갖는다. 메시는 이미지 자체의 좌표로 기록되며 LPS와 RAS 사이의 뒤집기는 없다.

코드에서표면 함수, 평활화, 두 가지 모드

6. 후처리와 출력

이름은 스캔 이름과 예측 ID로 만든다. 구조물당 파일 하나, 병합 파일 하나, 표면을 요청했다면 .vtk 파일 하나이다. 스캔별 폴더 옵션을 쓰면 모든 것이 스캔 이름을 딴 결과 폴더에 들어가고, 그렇지 않으면 출력 폴더에 바로 들어간다. 임시 폴더는 실행 시작과 끝에 모두 비워지며, 입력 사본은 추론이 끝나는 즉시 삭제된다.

위젯 쪽에서는 표면을 마지막에 장면에 로드하지만, 원본 옆에 저장된 단일 파일 입력이고 표면 상자가 체크된 경우에만 그렇다.

8. 환경

모든 것이 Slicer의 Python에서 실행된다. 라이브러리는 Predict를 누르고 확인하면 설치된다. 버전은 대부분 고정하지 않는다. NumPy는 1.26.4로 고정되어 있는데, 여기서 쓰는 torch 빌드가 NumPy 1.x 기준으로 만들어져 있어 NumPy 2에서는 import가 깨지기 때문이다. WSL도 conda도 없다. IOS 모듈(FlexReg, AREG_IOS, ALI_IOS)과 달리 AMASSS는 외부 환경을 쓰지 않는다. 버전 표는 코드 페이지에 있다.

각 항목은 코드에서 확인했으며, 근거와 함께 코드 페이지에 기술되어 있다.

  • small-field 옵션은 아무 일도 하지 않는다. 체크해도 상자 목록만 바뀐다. 근거.
  • DICOM 입력은 무시된다. 패널은 이를 제공하지만 프로그램에는 변환 기능이 없다. 근거.
  • 치근관은 기본으로 체크되어 있다. 모델이 없는데도 그렇다. 근거.
  • 임시 폴더는 공유되며 비워진다. 그래서 동시에 실행한 두 작업이 서로의 결과를 지운다. 근거.
  • 케이스 번호와 파일의 대응은 메모리에만 유지된다. 충돌이 나면 이름 없는 예측만 남는다. 근거.
  • 구조물 코드는 파일 이름에서 다시 읽는다. 분리 표면을 만들 때 예측 ID나 스캔 이름에 밑줄이 있으면 오류가 난다. 근거.
  • 위젯과 프로그램이 스캔 수를 서로 다르게 센다(확장자, 건너뛰는 이름). 근거.
  • 위젯의 정리 작업은 Slicer 작업 폴더 기준 상대 경로를 삭제한다. 이 경로는 임시 폴더와 무관하다. 근거.
  • 죽은 코드: 일부 함수와 위젯 부분이 아무 일도 하지 않는다. 근거.
  • 논문과 코드가 다르다. 논문은 MONAI UNETR을 기술하지만, 코드는 nnU-Net을 실행한다. 근거.

10. 문헌

2022년 PLOS ONE 논문(Gillot et al.)은 128 복셀 크롭, 트랜스포머 인코더, 합성곱 디코더를 갖춘 MONAI UNETR 모델을 기술한다. 오늘 실행되는 코드는 레거시와 VISOR 모두에서 순수 합성곱 nnU-Net v2 신경망이다. 비교는 코드 페이지에 있고, 참고 자료는 SOURCES.md에 있다.

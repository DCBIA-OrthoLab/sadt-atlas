DOCShapeAXI

2분기 신경망(멀티헤드 어텐션 점군 + 멀티뷰 EfficientNet-B0 렌더링)으로 .vtk 메시를 분류하고, 그 뒤에 항상 Grad-CAM 단계를 실행해 메시에 점별 스칼라로 기록한다.

Prieto 2024 · SPIE DOCShapeAXI_CLI conda 환경: shapeaxi 참고문헌

Dental Oral and Craniofacial Shape Analysis eXplainability and Interpretability. 사용자 동작은 하나뿐이다. 데이터 유형, 입력 폴더, 출력 폴더를 고른다. 나머지(어떤 체크포인트, 어떤 구조, 클래스 몇 개)는 모두 데이터 유형에서 추론된다.

1. 파이프라인에서의 위치

독립형이다. 저장소 안에서 DOCShapeAXI를 호출하는 곳은 없다. 입력 메시는 다른 곳(과두는 AMASSS, 기도 분할 등)에서 이미 분할·추출되었다고 가정한다. 모듈은 자체 표면을 만들지 않는다.

호출 대상시점방법
DOCShapeAXI_CLI작업마다conda run -n shapeaxi python -m DOCShapeAXI_CLI <8 args>
model_path.json(raw.githubusercontent.com에 있음)CLI 시작 시 .ckpt가 없으면requests.get 후 urlretrieve
shapeaxi pip 패키지항상saxi_nets_lightning, saxi_dataset, saxi_transforms, saxi_gradcam, post_process, utils
DOCShapeAXI_utils.install_pytorchpytorch3d가 없으면conda run -n shapeaxi python -m DOCShapeAXI_utils.install_pytorch <pip>

shapeaxi 환경은 공유된다. FlexReg, ALI, AREG, ASO와 함께 쓴다. 버전이 바뀌면 이들 모두에 영향이 미친다.

모델 json은 로컬 사본이 아니라 GitHub의 main 브랜치에서 읽는다 (DOCShapeAXI_CLI.py:118). 설치된 버전이 자신보다 나중에 공개된 가중치를 내려받을 수 있다.

3. 입력과 전처리

3.1 CSV

CLI는 args.input_dir를 평면적으로 나열하고, .vtk 파일만 남겨, <output_dir>/files_<data_type>.csv에 헤더 surf와 함께 한 줄에 파일 이름 하나씩 기록한다(csv_edit, DOCShapeAXI_CLI.py:102). 경로는 상대 경로이며, SaxiDataset이 mount_point = input_dir와 결합한다.

data_type에 공백이 들어 있으므로("Mandibular Condyle") csv 이름은 files_Mandibular Condyle.csv가 된다. csv는 아직 없을 때만 다시 생성된다(DOCShapeAXI_CLI.py:282). 출력 폴더를 비우지 않고 입력 폴더에 메시를 추가하면 그 메시는 처리되지 않는다.

3.2 기하 정규화

EvalTransform → UnitSurfTransform → utils.GetUnitSurf → ScaleSurf:

  1. 중심 = 경계 상자(bounding box)의 중점(중심점(centroid)이 아님);
  2. 점들을 이 중심으로 평행이동;
  3. 스케일 인자 1 / ||bounds_max - center||를 균일하게 적용.

따라서 메시는 실제 크기와 무관하게 단위 구 안에 들어간다. 절대 크기 정보는 모두 사라진다. 모양이 같은 작은 과두와 큰 과두는 신경망에게 동일하다.

확인된 버그 (shapeaxi 패키지)

알아 둘 점: saxi_predict는 model.hparams.scale_factor(condyles 체크포인트에서 0.0507)를 읽어 EvalTransform(scale_factor)에 넘기지만 (DOCShapeAXI_CLI.py:206), UnitSurfTransform.__call__은 utils.GetUnitSurf(surf)를 그 값을 전달하지 않고 호출한다(입력이 vtkPolyData일 때). 따라서 학습 시 익힌 스케일 인자는 추론 시 조용히 무시되고, 대상자별 정규화로 대체된다. 이는 저장소가 아닌 shapeaxi 패키지의 버그지만, 실제 전처리를 바꾼다. 한편 saxi_gradcam은 인자 없는 EvalTransform()으로 데이터셋을 만든다. 결과적으로 두 단계는 서로 일관된다.

3.3 DataLoader가 반환하는 것

SaxiDataset(..., CN=True, class_column=None, scalar_column=None) → 대상자마다 (V, F, CN):

  • V: 정규화 후 정점 (1, Nv, 3);
  • F: 삼각형 (1, Nf, 3);
  • CN: 색으로 인코딩된 법선. utils.ComputeNormals 후 GetColorArray(surf,"Normals")를 255로 나눔 → [0,1] 범위의 (1, Nv, 3).

메시 스칼라는 한 번도 읽지 않는다(surf_property=None). 들어가는 것은 기하와 법선뿐이다. batch_size=1이고 패딩이 없으므로, 크기가 다른 메시도 문제없이 통과한다.

URL은 모두 shapeaxi-ckpt-v1 릴리스에 있다: .../releases/download/shapeaxi-ckpt-v1/{airways_2_class, airways_4_class, airways_4_regress, cleft_4_class, condyles_4_class}.ckpt. 비대칭에 주의: json 키는 clefts_4_class인데 원격 파일 이름은 cleft_4_class.ckpt다. 체크포인트는 캐시가 아니라 출력 폴더 안으로 복사된다(<output_dir>/<model>.ckpt). 새 출력 폴더마다 72 MB를 다시 내려받는다.

4.2 실제로 쓰이는 구조

이것은 PointNet이 아니며, 원래 ShapeAXI 논문의 ResNet-18 fly-by-CNN도 아니다. SaxiMHAFBClassification(MHA Fly-By)은 후기 융합(late fusion)되는 두 분기를 가진다.

확인됨

아래 값들(K=128, 헤드 256개, 42시점, image_size=224…)은 소스 코드를 읽어서만이 아니라 hyper_parameters와 ico_verts 버퍼로 확인했다. 둘 다 condyles_4_class.ckpt 체크포인트 자체에 들어 있다.

분기 A — 점군.

  • sample_points_from_meshes(X_mesh, 4096)(pytorch3d): 표면에서 4096점을 균일 샘플링;
  • MHAEncoder: Linear(3→256) 후 sample_levels = [4096, 2048, 512, 128]의 4단계. 각 단계에서 MHA_KNN(K=128 최근접 이웃으로 제한된 멀티헤드 어텐션, 헤드 256개) 후 잔차 FeedForward (은닉 64). 단계 사이에서는 다음 수준까지 무작위로 부분 샘플링하며, 인덱스를 넘겨 원래 점마다의 가중치를 누적한다 (x_w);
  • Linear(256→256), FeedForward, 그다음 SelfAttention(가산적 어텐션 Linear(256→64) → tanh → Linear(64→1) → sigmoid, 정규화 후 가중 합)이 128개 토큰을 하나의 256 벡터로 축약한다.

분기 B — 멀티뷰.

  • 카메라는 세분된 정이십면체의 꼭짓점에 놓인다(subdivision_level=2, radius=1.35). 체크포인트의 ico_verts 버퍼 형태는 (42, 3)이다. 대상자마다 42시점;
  • pytorch3d 렌더링: FoVPerspectiveCameras, 원점을 향한 look_at_rotation, AmbientLights(방향성 음영 없음), HardPhongShader, RasterizationSettings(image_size=224, blur_radius=0, faces_per_pixel=1, max_faces_per_bin=200000);
  • 각 시점은 4채널 텐서다. RGB(TexturesVertex로 설정한 색 인코딩 법선) + z-버퍼. 그래서 in_channels=4;
  • TimeDistributed(EfficientNetBN('efficientnet-b0', spatial_dims=2, in_channels=4, num_classes=256))(MONAI): 42개 시점을 배치 차원으로 펼쳐 같은 CNN에 통과시킨 뒤 (1, 42, 256)으로 다시 형태를 바꾼다;
  • FeedForward, 42개 시점에 대한 자기 어텐션으로서의 nn.MultiheadAttention(256, 256 heads, batch_first=True), 그다음 SelfAttention → 256 벡터.

융합. torch.cat([x_points, x_views], dim=1) → 512, 그다음 fc = Linear(512, num_classes). 회귀에서는 Linear(512, 1)과 MSE 손실.

렌더링은 매번 다시 수행된다. 이미지 캐시는 없다.

4.3 신경망이 문자 그대로 출력하는 것과 그로부터 클래스를 도출하는 방법

x = model(X_pc, X_views)                       # (1, num_classes) — raw logits
if args.nn == 'SaxiMHAFBClassification':
    x = softmax(x).detach()
    x = torch.argmax(x, dim=1, keepdim=True)   # the class integer
predictions.append(x)

(DOCShapeAXI_CLI.py:227)

  • 분류: argmax만 남는다. softmax 확률은 계산된 뒤 버려진다. 모듈 밖으로 나가는 신뢰도 측정값은 없다;
  • 회귀: Linear(512,1)의 원시 값을 그대로 기록한다(폐쇄 비율, 학습 시 0–100 척도);
  • 어차피 softmax는 argmax에 아무 영향도 주지 않는다.

상위(upstream) 코드에서 보이는 학습 세부 사항: 분류에서 타깃은 원-핫이 아니라 부드러운 클래스 확률이다 (soft_class_probabilities: [12.5, 37.5, 62.5, 87.5]에 중심을 두고 widths = 12.5인 가우시안). 따라서 중증도 4개 클래스는 실제로는 0–100 척도 위 연속량의 4분위이며, 같은 기도 데이터셋에 회귀 모델이 존재하는 이유도 이것으로 설명된다.

5. 설명 가능성 메커니즘

참고

모듈에서 가장 특징적인 부분이며, 예측 후 항상 실행된다. 옵션도 체크박스도 아니다 (saxi_gradcam, DOCShapeAXI_CLI.py:126).

a) 대상 층.

target_layer = getattr(model.convnet.module, '_blocks')
mv_cam = LayerGradCam(model, target_layer[-1], device_ids=[0])

model.convnet.module은 EfficientNet-B0이고, _blocks[-1]은 그 마지막 MBConv 블록이다.

함정

중대한 결과: 돌출도는 멀티뷰 분기만 설명한다. 융합 벡터의 절반을 담당하는 점군 분기는 맵 어디에도 나타나지 않는다. 인코더가 만들어 낼 수 있는 x_w(점별 가중치)는 회수되지도 기록되지도 않는다.

b) 클래스마다 맵 하나. for class_idx in range(num_classes) 루프에서 mv_cam.attribute(inputs=(X_pc, X_views), target=class_idx, attr_dim_summation=False)를 호출한다. Captum은 클래스 class_idx의 로짓을 블록의 활성값까지 역전파하고, 평균 기울기를 곱해, 활성 맵 해상도(224×224에서 EfficientNet-B0이면 7×7)의 텐서를 42개 시점 모두에 대해 한 번에 반환한다. attr_dim_summation=False는 채널 차원을 유지하며, 이 차원은 바로 뒤 mv_att.sum(dim=1)로 합쳐진다.

c) 재조정(scale_cam_image, DOCShapeAXI_CLI.py:43, pytorch-grad-cam에서 가져옴): cv2.resize로 224×224, 1번째와 99번째 백분위수에서 클리핑, 그다음 [-1, 1]로 아핀 재매핑. 백분위수 클리핑은 이상치 픽셀 하나가 전체 동적 범위를 잠식하지 않게 한다. 따라서 출력은 부호가 있는 값이며 확률이 아니다.

d) 메시로 재투영(gradcam_process, shapeaxi 안) — 이 메커니즘의 핵심:

P_faces = torch.zeros(1, F.shape[1])
V_gcam  = -1 * torch.ones(V.shape[1])
for pf, gc in zip(PF.squeeze(), GCAM):          # one view at a time
    P_faces[:, pf] = torch.maximum(P_faces[:, pf], gc)
faces_pid0 = F[0, :, 0].to(torch.int64)
V_gcam[faces_pid0] = P_faces
V_gcam[V_gcam < 0] = 0
  • PF는 래스터라이저의 pix_to_face다. 모든 시점의 모든 픽셀에 대해 보이는 삼각형의 인덱스다. 따라서 픽셀 값은 면으로 옮겨진다;
  • 시점 간 집계는 평균이 아니라 최댓값이다. 한 번만 보였고 돌출적이라고 판단된 영역은 그 값을 유지한다;
  • 면에서 정점으로 가는 단계는 조잡하다. 각 면의 값은 그 첫 번째 정점(F[0,:,0])에 기록된다. 어떤 삼각형의 첫 번째 점으로도 쓰이지 않은 정점은 -1로 남았다가 0으로 재설정된다. 따라서 맵에는 구조적인 0이 흩어져 있다;
  • 한 번도 래스터화되지 않는 면(내부, 영구 가림)은 0으로 남는다.

e) 평활화와 기록.

surf.GetPointData().AddArray(mv_att_upscaled)
psp.MedianFilter(surf, mv_att_upscaled)
utils.WriteSurf(surf, out_surf_path)

MedianFilter는 각 값을 위상적 이웃의 중앙값으로 바꾼다 (1회, 제자리). "첫 번째 정점" 방식이 남긴 구멍을 부분적으로 메우는 것이 이 단계다. 이 필터는 vtkDataArray를 수정하는데, 이 배열은 메시에 이미 추가된 것이므로, 기록되는 것은 실제로 필터링된 버전이다.

배열 이름은 gradcam_process 안에 고정되어 있다.

경우스칼라 이름
num_classes > 1grad_cam_target_class_0, _1, …
회귀(num_classes == 1)grad_cam_max(target_class는 None으로 유지)

파일은 클래스 반복마다 다시 기록되며 배열이 누적된다. 최종 .vtk에는 N개의 맵이 모두 들어 있다. README가 Models 모듈 → Scalars → Active Scalar에서 ColdToHotRainbow 색상표와 함께 선택하라고 하는 것이 이것이다.

6. 후처리와 출력

<log_path>"<task>,<predict|explainability>,<index>,<num_classes>"

열 누적은 의도된 것이다 (DOCShapeAXI_CLI.py:240). 예측 csv가 이미 있으면 다시 읽어 들여 기반으로 삼는다. 그래서 기도 데이터셋에는 binary_prediction, severity_prediction, regression_prediction이 나란히 남는다. 따름 정리: 같은 출력 폴더에 다시 실행하면 열을 제자리에서 덮어쓰고, 오래된 열은 결코 지우지 않는다.

로그는 매번 다시 쓰는 한 줄짜리 파일이다(대상자마다 'w+'). 위젯은 그 mtime을 감시하고, predict/explainability 필드가 바뀌면 진행 표시줄을 0으로 되돌린다(DOCShapeAXI.py:694).

설치 순서에는 제약이 있다. shapeaxi는 pytorch3d를 의존성으로 선언하는데, 이는 PyPI에 없으므로 빈 환경에서 요청하면 pip가 실패한다. 그래서 먼저 torch만으로 환경을 만들고, 그다음 install_pytorch가 torch 버전을 읽어 wheel을 고른 뒤, 마지막으로 shapeaxi를 설치한다. verify_gpu()는 GPU에서 실제 knn_points까지 실행한다. import는 되지만 감지된 아키텍처용 커널이 없는 wheel은 파이프라인 도중이 아니라 바로 그 자리에서 잡힌다.

check_if_pytorch3d()(DOCShapeAXI.py:844)는 import pytorch3d.renderer 와 shapeaxi.dental_model_seg.saxi_nets_lightning.DentalModelSeg 접근을 검사한다. 따라서 이 검사는 위의 패치도 함께 확인한다.

9. 함정과 취약 지점

확인된 버그

CLI는 shapeaxi 1.0.x API에 맞춰 작성되었는데, 환경은 2.0.2를 설치한다. 모듈이 동작을 멈추면 가장 먼저 확인할 부분이다.

shapeaxi 1.0.10shapeaxi 2.0.2
시그니처forward(self, X_pc, X_views)forward(self, X_mesh)
반환값xx, x_w, X
클래스 수 hparamout_classesnum_classes

CLI는 model(X_pc, X_views)를 호출하고 반환값을 텐서로 쓴다 (DOCShapeAXI_CLI.py:227). 2.0.2에서는 이것이 TypeError다(위치 인자 3개). 게다가 공개된 체크포인트에는 out_classes가 들어 있는데, 2.0.2의 __init__은 이를 더 이상 읽지 않는다. load_from_checkpoint 호출은 순전파 이전에 이미 실패할 것이다. 다시 말해 이 모듈은 설치 스크립트가 설치하지 않는 고정 버전 shapeaxi<2를 기대한다. 버전을 고정하거나, CLI를 새 API로 이식하고(X_mesh 전달, 삼중 반환값 풀기) 체크포인트를 다시 생성해야 한다.

  • strict=False가 load_from_checkpoint에 쓰인다 (DOCShapeAXI_CLI.py:198). 누락되거나 남는 가중치가 조용히 통과한다. 부분적으로만 불러온 모델도 그대로 예측한다.
  • 모델 다운로드는 출력 폴더가 이미 존재할 때만 일어난다(if os.path.exists(args.output_dir): if not os.path.exists(...), DOCShapeAXI_CLI.py:277). 폴더가 없으면 다운로드가 건너뛰어지고 오류는 나중에 체크포인트를 불러올 때 드러난다. CLI는 output_dir을 결코 만들지 않는다.
  • process.log는 모듈 자체의 트리 안에 기록된다 (os.path.dirname(__file__), DOCShapeAXI.py:811). 빈 파일 DOCShapeAXI/process.log가 저장소에 커밋되어 있다. 읽기 전용 설치(/opt, Program Files)에서는 DOCShapeAXILogic 생성 시 예외가 발생한다.
확인된 버그

gradcam_save()(DOCShapeAXI_CLI.py:62)는 shutil.copy를 호출하지만 shutil은 파일 안에서 한 번도 import되지 않는다. 무해하다. 이 함수는 호출되지 않는다. CLI 상단에 정의된 클래스 MultiHead와 SelfAttention (:84, :93)도 인스턴스화되지 않으며, subprocess import도 마찬가지다.

  • 학습된 스케일 인자가 무시된다(§3.2 참조). 언젠가 UnitSurfTransform이 scale_factor를 전달하게 되면, 이 저장소에서는 아무것도 바뀌지 않았는데 전처리가 달라진다.
  • 신뢰도가 보고되지 않는다. argmax 클래스만 나온다. 이름에 "explainability"가 들어간 도구로서는 이것이 사각지대다. 돌출도 맵은 신경망이 어디를 보았는지는 알려 주지만, 얼마나 확신이 없었는지는 결코 알려 주지 않는다.
  • 돌출도는 두 분기 중 하나만 다룬다(§5a 참조). 주로 점군 기하에 의해 내려진 결정은 정보가 없는 멀티뷰 맵을 만들며, 그 사실을 알려 주는 표시는 없다.
  • num_workers=4가 설명 가능성 DataLoader에 쓰인다 (DOCShapeAXI_CLI.py:144). 반면 예측은 워커를 쓰지 않는다. GPU가 42개 시점을 렌더링하는 동안 네 프로세스가 .vtk 파일을 병렬로 읽는다.
  • 모델 선택은 콤보 레이블의 단어를 거친다. .ui에서 "Mandibular Condyle"을 "Condyles"로 바꾸면 find_model_name이 깨진다. 이 함수는 (None, None)을 반환하고, 다음 호출에서 TypeError가 난다 (os.path.join(output_dir, None + '.ckpt')).
  • check_input_parameters(DOCShapeAXI.py:469)는 같은 조건을 두 번 검사하며, else 분기("Unknown error")에는 도달할 수 없다.
  • count_num_subjects는 최상위 .vtk 파일만 센다. csv_edit과 일관되지만, 둘 다 재귀적이지 않다.
  • DOCShapeAXI/__pycache__/DOCShapeAXI.cpython-312.pyc가 버전 관리에 커밋되어 있다.

코드는 논문과 다르다. 논문은 정이십면체 분할 위의 멀티뷰 렌더링을 ResNet-18과 가산적 어텐션으로 처리하는 구조를 설명하며, 과두는 이진 분류로 다룬다. 여기서 배포되는 체크포인트는 SaxiMHAFB* 모델이다. 42시점에 대한 EfficientNet-B0 + KNN 어텐션을 쓰는 두 번째 점군 분기로, 후자는 논문에 없다. 그리고 condyles_4_class 체크포인트는 4개 중증도 클래스다. SPIE 논문의 수치를 내려받는 모델의 수치로 제시하지 말 것.

2. 기도 데이터셋. Explainable Artificial Intelligence to Quantify Adenoid Hypertrophy-related Upper Airway Obstruction using 3D Shape Analysis, Mattos et al., J Dent 2025. 이 논문은 코드의 구조를 정확히 설명한다.

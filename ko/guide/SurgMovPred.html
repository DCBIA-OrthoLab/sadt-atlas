SurgMovPred — 수술 후 예상 골 이동량 추정

SurgMovPred는 볼륨이나 메시를 보지 않습니다. 두부계측(cephalometric) 측정값 스프레드시트를 받아, 악교정 수술 후 예상되는 골 변위를 수치로 추정합니다. 예를 들어 Pogonion이나 후비극(posterior nasal spine) 같은 점이 공간의 세 축을 따라 얼마나 움직여야 하는지입니다. 영상도, 신경망도 쓰지 않습니다. 예측값마다 하나씩, 서로 독립된 작은 통계 모델 112개가 표의 행마다 적용됩니다.

영상
  • Surgical Movement Prediction: Machine learning model to help surgery preparation 28초 (개요) · DCBIA Videos 채널

언제 쓰는가

환자마다 두부계측 측정값 세트 — 수술 전 상태와 목표 교합 결과 — 를 이미 갖추고 있고, 그에 해당하는 골 변위를 한 명씩이 아니라 환자 묶음 전체에 대해 한 번에 빠르게 수치로 추정하고 싶을 때 사용하십시오. 직접 세우는 수술 계획을 보완하는 수치 도구이지, 3D 시각화 도구가 아닙니다.

스프레드시트 전용 도구

SurgMovPred는 볼륨, 표면, Slicer 랜드마크를 전혀 읽지 않으며, 3D 장면(scene)도 건드리지 않습니다. 장면에는 아무것도 만들어지거나 표시되지 않습니다. 모든 일은 디스크에서 일어납니다. 스프레드시트 폴더가 들어가고, 스프레드시트 폴더가 나옵니다.

입력 스프레드시트 형식

이 모듈에서 대부분의 사람이 막히는 곳이 여기입니다. 입력으로 기대하는 형식이 꽤 구체적인데, 형식이 맞지 않아도 분명한 경고가 나오지 않습니다.

  • 파일 하나가 아니라 폴더입니다. 안에 있는 모든 .csv, .xlsx, .ods 파일을 읽어 하나의 큰 표로 쌓으며, 열이 실제로 일치하는지는 확인하지 않습니다. 하위 폴더는 탐색하지 않습니다.
  • 통합 문서당 시트 하나만 읽습니다. Excel이나 .ods 파일은 첫 번째 시트만 읽습니다. 통합 문서에 시트가 여러 개 (인구통계, 원시 측정값…) 있다면 환자별 측정값이 있는 시트가 맨 앞에 오도록 하십시오.
  • 열 머리글은 자동으로 가볍게 정리됩니다: 따옴표와 괄호를 없애고, 불필요한 문자와 공백을 밑줄로 바꾸고, 겹친 밑줄을 하나로 줄이고, "total"을 대문자로 시작하게 하며, 숫자로 시작하는 머리글에는 접두어를 붙입니다. 따라서 대개는 자신의 머리글을 그대로 둘 수 있습니다. SM-A-FH 는 자동으로 SM_A_FH가 되고, 아포스트로피는 Jarabak's ratio 같은 이름을 위해 일부러 유지됩니다.
  • 그렇다고 필요한 열이 빠져도 된다는 뜻은 아닙니다. 112개 모델은 각각 약 145개 측정값으로 된 정확한 목록을 기대합니다. 두부계측 기준 평면에 대한 점 위치, 연조직 점, 표준 2D 두부계측 측정값(SNA, ANB, Wits…), 그리고 두 세트로 중복된 교합 측정값 — 하나는 시작 상태, 다른 하나는 아마도 목표 상태 (어디에도 명시되어 있지 않으며, 입력에 둘 다 있다는 점에서 추론한 것입니다) — 입니다. 두 세트 중 하나에 대해서는 약간의 허용 범위가 있지만, 그 이상은 없습니다. 가장 안전한 방법은 모듈과 함께 제공되는 예제 스프레드시트에서 출발해 값만 바꾸는 것입니다.
  • 환자 ID 열. 흔히 쓰는 머리글 (#, ID, Patient ID, Patient Number, Subject…) 중에서 자동으로 찾습니다. 일치하는 것이 없으면 출력에는 빈 ID 열만 남습니다. 실행은 끝나지만 결과를 환자와 다시 연결할 수 없게 됩니다.
  • 결측값은 절대 채워지지 않습니다. 빈 셀은 끝까지 빈 채로 남습니다. 추정되지도 않고, 그렇다고 그 행의 나머지를 건너뛰게 만들지도 않습니다.

필요한 것, 얻는 것

준비할 것

  • 위에서 설명한 형식의 스프레드시트 폴더 (.csv, .xlsx, 또는 .ods)
  • 학습된 모델 (전용 버튼으로 한 번만 다운로드, 약 700 MB)
  • 출력 폴더

나오는 것

  • 출력 폴더에 내용이 같은 스프레드시트 두 개 (.xlsx와 .csv)
  • 입력 환자당 한 행, 예측된 변위값당 한 열
  • 입력 스프레드시트와 Slicer 장면은 건드리지 않습니다

사용 절차

  1. 모델을 다운로드합니다. 전용 버튼, 약 700 MB이며 한 번만 하면 되지만 첫 실행 전에 반드시 필요합니다.
  2. 입력 폴더를 준비합니다. 위 형식을 따르십시오. 통합된 스프레드시트 하나든 여러 파일이든 상관없고, 기대하는 열만 있으면 됩니다.
  3. 세 폴더를 지정합니다: 입력, 다운로드한 모델, 출력.
  4. 실행합니다. 조정할 것은 없습니다. 임계값도, 대상 선택도, 골격 분류 옵션도 없습니다. 조립된 표의 모든 행에 대해 112개 값이 한꺼번에 예측됩니다.
  5. 출력 스프레드시트 두 개를 가져갑니다. 지정한 폴더에 있습니다.

결과를 읽는 법 — 그리고 과하게 해석하지 않는 법

출력의 각 열은 상악골, 하악골 또는 이부성형(genioplasty) 분절의 특정 점에 대한 예측 변위값으로, 두부계측 좌표계의 세 성분(앞/뒤, 좌/우, 위/아래)으로 표현되며, 네 번째 "Total" 열은 아마도 전체 크기일 것입니다. 단위는 도구 어디에도 적혀 있지 않습니다. 아마 밀리미터겠지만, 이는 추론이지 명시된 사실이 아닙니다.

분절 전체가 아니라 점 하나하나가 따로 예측됩니다

출력값 112개는 값마다 하나씩, 서로 독립된 모델 112개에서 나옵니다. 예를 들어 상악골에 대해 예측된 점 열 개가 서로 일관성을 유지한다는 보장은 없습니다. 결과는 골 블록의 강체 변환이 아니라, 서로 따로 계산된 점별 변위의 모음일 뿐입니다. 이 숫자들을 서로 대조해 보기 전에는 이것으로 전체 이동을 재구성하지 마십시오.

표에는 신뢰구간도 신뢰도 점수도 없습니다. 모든 셀은 오차 범위가 붙지 않은 단일 값입니다. 그리고 예측은 스프레드시트에서 끝납니다. SurgMovPred는 Slicer에서 아무것도 움직이지 않고, 변환을 만들지 않으며, 뷰를 열지 않습니다. 값을 시각화하거나 적용하려면 직접 수술 계획 소프트웨어로 옮겨야 합니다.

문제가 생기면

Apply를 누를 때마다 의존성이 재설치됩니다

Apply(적용)를 누르면 모든 것이 이미 잘 동작하고 있어도 항상 numpy를 강제로 재설치합니다. 그만큼 실행이 느려지고, 이미 실행 중인 Slicer 세션 안에서 핵심 수치 라이브러리를 바꿔 끼우면 그것에 의존하는 다른 도구가 불안정해질 수 있습니다. SurgMovPred를 쓴 뒤 다른 모듈이 이상하게 동작하기 시작하면, 다른 원인을 찾기 전에 Slicer를 다시 시작하십시오.

출력에서 열이 빠진 것은 충돌이 아닙니다

기대한 값 중 하나가 결과에 없더라도 눈에 보이는 오류는 나지 않습니다. 해당 모델이 필요로 하는 열 중 하나를 머리글 정리 후에 찾지 못해서 그냥 건너뛴 것입니다. 경고는 스프레드시트가 아니라 Slicer 로그에 남습니다. 출력에 예측된 열이 거의 없다면, 다른 곳을 살피기 전에 머리글을 예제 스프레드시트와 비교해 보십시오.

통합 문서에서 어느 시트가 앞에 있는지 확인하십시오

.xlsx나 .ods 파일은 첫 번째 시트만 읽습니다. 환자별 측정값이 첫 번째 시트에 없으면, SurgMovPred는 아무 말 없이 다른 시트 — 또는 빈 시트 — 를 읽습니다.

테스트 파일 버튼은 저절로 아무것도 채우지 않습니다

아카이브를 다운로드하기는 하지만, 입력·출력 폴더를 채우는 것은 다른 모듈(VFACE)의 테스트 데이터가 이미 컴퓨터에 있을 때뿐입니다. 그 데이터가 없는 컴퓨터에서는 버튼을 눌러도 눈에 보이는 변화가 없습니다.

실행할 때마다 모든 모델이 로드됩니다

SurgMovPred는 실행하자마자 112개 모델을 모두 메모리에 올립니다. 환자 한 명이나 실제로 관심 있는 값 하나만 필요해도 마찬가지이며, 스프레드시트를 읽기도 전에 RAM을 약 1.5 GB 씁니다. 메모리가 부족한 컴퓨터라면 이를 감안하십시오.

더 읽을거리

이 모듈을 설명하는 논문은 없습니다. 유일한 공개 설명은 NA-MIC 프로젝트 보고서이며, 모듈이 실행하는 모델은 어디에서도 평가되지 않았습니다.

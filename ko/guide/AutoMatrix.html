AutoMatrix: 파일 묶음 전체에 행렬 적용하기

AutoMatrix는 ITK 변환 행렬 하나 이상을 볼륨과 랜드마크 파일이 든 폴더 전체에 한 번에 적용합니다. 신경망도 GPU도 필요 없습니다. 계산 단계가 아니라 일괄 처리 도구이며, 행렬 자체는 다른 곳에서 실행한 정합에서 나옵니다.

실행하는 두 가지 방법

이 페이지는 레거시 Slicer 모듈을 설명합니다. VISOR 서버로 사용하려면 VISOR 사용과 VISOR 사용하기를 참조하십시오.

언제 쓰는가

정합 모듈(AREG, ASO, FlexReg 등)을 실행해 변환 행렬(.tfm)을 얻었습니다. 이제 같은 환자의 다른 파일, 즉 분할, 두 번째 볼륨, 랜드마크 모음에 같은 행렬을 적용하고 싶습니다. 각각을 Slicer에서 손으로 열지 않고서요. 또는 환자 시리즈 전체에 그 정합을 실행해 놓고 폴더 전체를 한 번에 처리하고 싶을 수도 있습니다. AutoMatrix는 이럴 때 쓰는 도구입니다. 스스로는 아무것도 정합하지 않고, 이미 계산해 둔 변환을 그대로 다시 적용합니다.

행렬 하나, 움직임 하나

VISOR에서도 마찬가지입니다. 서버는 랜드마크 점을 변환의 역으로 움직이므로, 스캔과 랜드마크는 같은 상대적 움직임을 유지합니다.

볼륨에 적용하면 행렬은 그 내용을 움직입니다. 랜드마크 파일에 적용하면 점들을 정확히 같은 움직임으로 움직입니다. 그래서 AutoMatrix를 거친 뒤에도 스캔과 랜드마크가 정렬된 채로 유지되며, 단 둘 모두에 같은 행렬을 사용한 경우에 한합니다.

파일과 행렬이 짝지어지는 방식

AutoMatrix는 어떤 행렬이 어떤 환자에 속하는지 손으로 지정하라고 요구하지 않습니다. 파일 이름을 비교해 짝을 추정합니다. 스캔 이름에서 알려진 키워드 목록(_Seg, _Or, _MAND, _CB, _T1, _T2 같은 시점 표시 등)을 제거하고, 행렬 이름에서는 조금 다른 목록을 제거하여 양쪽에 환자 식별자만 남깁니다. 두 식별자가 같으면 그 파일과 행렬은 짝지어집니다.

함정은 이 두 키워드 목록이 같지 않다는 점입니다. 확실하게 동작하는 규칙은 모든 파일 이름을 환자 식별자로 시작하고, 밑줄을 붙인 뒤, 필요한 나머지를 쓰는 것입니다. 동작하는 예: patient1_T1_MA.nii.gz와 patient1_left_MA.tfm은 둘 다 patient1로 줄어듭니다. 스캔 쪽에서는 _T1이, 행렬 쪽에서는 _left가 제거되기 때문입니다. 실패하는 예: 시점 표시가 없는 patient1_MA.nii.gz는 스캔 쪽에서는 patient1_MA로, 행렬 쪽에서는 patient1로 줄어들어 둘이 더는 일치하지 않으며, 그 파일은 행렬을 전혀 받지 못합니다.

지름길이 있습니다. 폴더 대신 행렬 파일 하나를 지정하면, 이름 매칭 없이 입력 폴더의 모든 환자에게 그대로 적용됩니다.

필요한 것, 얻는 것

준비할 것

  • .nii, .nii.gz 또는 .nrrd 볼륨 폴더, 그리고/또는 Slicer 랜드마크 파일(.mrk.json)
  • ITK 행렬(.tfm, .h5 또는 .mat), 또는 스캔과 같은 규칙으로 이름을 붙인 행렬 폴더
  • 볼륨이 분할이면 이것을 선택합니다. 레이블이 보간으로 뭉개지지 않도록 하는 전용 상자입니다
  • 선택 사항: 출력 격자(크기, 방향)를 강제하는 참조 파일

나오는 것

  • 짝지어진 각 파일의 변환된 사본, 입력과 같은 폴더 구조로 배치됩니다
  • 원본 파일은 절대 수정되지 않습니다
  • 랜드마크 파일에서는 정의된 것으로 표시된 점만 움직입니다
  • 새 행렬은 만들어지지 않습니다. AutoMatrix는 변환을 소비할 뿐 쓰지 않습니다

단계

  1. 입력 폴더를 지정합니다. 변환할 스캔 및/또는 랜드마크 파일이며, 폴더 전체가 한 번에 처리됩니다.
  2. 행렬 또는 행렬 폴더를 지정합니다. 이름이 위의 환자 + 접미사 규칙을 따르는지 확인하거나, 파일 하나를 직접 지정해 모든 환자에게 적용하십시오.
  3. 볼륨이 레이블맵이면 분할 상자를 선택합니다.
  4. 출력 격자를 강제하려면 참조 파일을 지정합니다. 지정하지 않으면 각 파일은 자신의 입력 볼륨 격자를 유지하며, 변환으로 시야 밖으로 밀려난 부분은 사라집니다.
  5. 출력 접미사를 고르고, 접미사에 행렬 이름을 덧붙일지 정합니다. 환자 한 명에게 행렬이 둘 이상이면 반드시 필요합니다(아래 참조).
  6. 출력 폴더를 지정한 뒤 실행합니다. 진행 표시줄이 파일이 처리되는 대로 따라갑니다.

행렬을 찾지 않고 좌우 뒤집기

좌우 대칭만 필요하다면 행렬을 직접 만들 필요가 없습니다. 미러 모드가 준비된 반사 행렬을 내려받아 행렬 필드에 대신 채워 주며, 자체 출력 접미사(_mir)를 사용합니다.

미러의 기준이 환자의 중심이 아님

레거시 모듈(3c67957), VISOR와는 다릅니다. 미러 행렬은 서버가 호스팅하는 파일이며 미러 행렬 사용 상자로 적용합니다. 패널은 참조 볼륨을 제공하지 않으며, 참조가 없으면 VISOR의 출력 격자가 변환을 따라가므로 세계 원점에 대한 반사에서는 결과가 비어 버릴 수 있습니다. VISOR 사용을 참조하십시오.

반사는 환자 자신의 시상면이 아니라 장면 원점의 시상면을 기준으로 일어납니다. 환자가 장면 중앙에 있지 않으면 결과가 뒤집히면서 동시에 이동합니다. 이후에 정합 단계를 거쳐 그 어긋남을 바로잡을 계획을 세우십시오.

문제가 생기면

안내된 일부 형식이 더 이상 동작하지 않음

레거시 모듈(3c67957), VISOR에서는 일부 바뀌었습니다. VISOR 패널은 더 이상 메시나 .npy 행렬을 제공하지 않으며, 아무것도 이를 세지 않습니다. 단순한 4x4 행렬이 들어 있는 .txt 파일은 그곳에서 받아들여집니다.

인터페이스는 여전히 구강 내 표면의 입력 스캔으로 메시(.vtk, .vtp, .stl, .off, .obj)를, 행렬로 .npy를 제공하고 둘 다 진행 표시줄에 집계되지만, 어느 쪽도 출력을 만들지 못합니다. 그런 종류의 파일은 모두 오류 로그에 한 줄만 남기고 건너뛰어집니다. .txt 행렬은 단순한 4×4 배열이 아니라 실제 ITK 변환 파일일 때만 동작합니다.

매칭 실패에 경고가 없음

레거시 모듈(3c67957), VISOR와는 다릅니다. 짝을 찾지 못한 파일과 변환은 AutoMatrix_report.json(without_a_transform, transforms_without_a_file)에 이름이 기록되고, 아무것도 쓰지 못한 실행은 오류로 중단됩니다. Slicer의 상태 줄에는 표시되지 않습니다. VISOR 사용을 참조하십시오.

스캔 이름과 행렬 이름이 같은 환자 식별자로 줄어들지 않으면(위 참조) 그 파일은 변환되지 않습니다. 오류 메시지도, 눈에 보이는 경고도 없습니다. 출력에서 어떤 환자가 빠졌다면, 가장 먼저 그 환자의 파일 이름을 확인하십시오.

한 출력이 다른 출력을 덮어쓸 수 있음

레거시 모듈(3c67957), VISOR에는 해당하지 않습니다. 환자 한 명에게 변환이 여러 개이면, 옵션과 관계없이 각 출력에 해당 변환의 이름이 붙습니다.

출력 파일에 행렬 이름을 덧붙이는 옵션을 해제했는데 환자 한 명에게 행렬이 둘 이상이면, 모든 결과가 같은 파일 이름을 얻습니다. 각각이 앞의 것을 덮어쓰고, 마지막에 처리된 행렬의 결과만 남습니다. 환자 한 명에 행렬을 둘 이상 적용할 때는 항상 이 옵션을 선택한 채로 두십시오.

랜드마크 파일이 조용히 사라질 수 있음

레거시 모듈(3c67957), VISOR에서는 일부 바뀌었습니다. 실패는 로그 한 줄이 아니라 보고서의 해당 환자 항목 아래에 기록되며, 환자의 볼륨은 여전히 만들어지므로 스캔과 랜드마크가 서로 어긋날 수 있습니다. 보고서를 확인하십시오.

일부 변환(조밀 변형장, B-스플라인)은 수학적으로 역변환할 수 없습니다. 그런 경우 해당 랜드마크 파일은 로그에 경고만 남기고 건너뛰어지는 반면, 볼륨 자체는 여전히 변환되므로 스캔과 랜드마크가 서로 어긋나도 화면에는 이를 알려 주는 것이 없습니다.

행렬은 연쇄되지 않음

VISOR에서도 마찬가지입니다. 각 변환은 원본 파일에 적용됩니다.

환자 한 명에게 행렬이 여러 개이면 각각이 원본 입력 파일에 따로 적용됩니다. 행렬마다 출력 파일 하나가 나오며, 하나를 적용한 뒤 다음 것을 잇는 합성은 이루어지지 않습니다.

인용 방법

논문은 없으며, 발표할 내용도 없습니다. 이 모듈은 변환 행렬을 파일에 일괄 적용합니다. 중요한 것은 Slicer에서 행렬이 무엇인지, 그리고 어느 좌표계로 표현되는지 아는 것입니다.

모듈 자체를 다룬 문헌이 없으므로, 확장 기능을 소프트웨어로 인용하십시오:

SlicerAutomatedDentalTools. DCBIA-OrthoLab. https://github.com/DCBIA-OrthoLab/SlicerAutomatedDentalTools

학술지 양식이 요구한다면 접속 날짜를 덧붙이십시오.

배경 문헌, 도구 자체의 인용이 아님

  • Documentation 3D Slicer: Transforms. Slicer에서 선형 변환이 무엇인지, 어떻게 적용하고 어떻게 역변환하는지 설명합니다.
  • Documentation 3D Slicer: Coordinate systems. RAS와 LPS, 그리고 올바른 행렬도 잘못된 좌표계에 적용하면 환자가 뒤집히는 이유를 설명합니다.

이 도구의 전체 참고문헌(찾아낸 것과 찾아봤지만 없었던 것)은 출처 페이지에 있습니다.

실제로 어떻게 동작하는가 → 아틀라스 페이지: ITK 변환 규약, 파일과 행렬의 상세한 매칭 로직, 실제로 읽는 형식, 코드에서 발견된 모든 함정.

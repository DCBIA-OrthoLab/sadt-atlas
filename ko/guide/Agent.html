Agent: 로컬 어시스턴트가 도구를 고르게 하기

Agent는 전적으로 내 컴퓨터에서 실행되는 대화형 어시스턴트입니다. 하고 싶은 일을 평범한 말로 설명하면, 고른 모드에 따라 확장 기능의 도구 하나를 파라미터가 이미 채워진 상태로 제안하거나 그냥 답해 줍니다.

영상
  • AI Agent directly in 3D Slicer to help you learn dental and cranofacial imaging30초 (개요) · DCBIA Videos 채널
레거시 모듈 페이지

이 페이지는 레거시 Slicer 모듈을 설명합니다. VISOR 확장에는 여전히 컴퓨터에서 실행되는 이 패널의 사본이 들어 있고, VISOR 서버에는 어떤 패널도 호출하지 않는 별도의 Agent 도구가 있습니다. VISOR로 쓰는 Agent와 VISOR 사용하기를 보십시오.

시도하기 전에 읽으십시오

저장소의 현재 상태에서 Agent는 실행하려는 도구를 찾지 못합니다. 수동으로 설정하지 않으면 도구를 실행하려는 모든 시도가 실패합니다. 아무것도 실행하지 않고 답만 하는 모드는 영향을 받지 않으며 정상적으로 동작합니다.

언제 쓰는가

확장 기능의 어느 모듈이 필요한 것에 맞는지 찾아다니거나 명령줄을 손으로 만들고 싶지 않을 때 쓰십시오. "이 CBCT들을 방향 정렬해 줘", "이 스캔들을 분할해 줘"처럼 작업을 설명하면, Agent가 요청에서 이해한 파라미터와 함께 도구를 제안합니다. 아무것도 실행할 필요가 없는 질문에는 "Ask" 모드에서 단순한 상담 상대로도 쓸 수 있습니다.

먼저 설치할 것

Agent는 내 컴퓨터에서 로컬로 실행되는 언어 모델 서버인 Ollama에 의존합니다. 아직 없으면 모듈이 다운로드해서 시작하도록 제안합니다. 어느 쪽이든 첫 질문을 하기 전에 첫 실행에서 수 기가바이트를 다운로드할 것을 예상하십시오. 언어 모델만 해도 5 GB를 조금 넘습니다.

Slicer 쪽에서는 손으로 설치할 것이 없습니다

필요한 Python 패키지는 첫 실행 때 Slicer 자체의 Python 안에 자동으로 설치됩니다.

필요한 것, 얻는 것

준비할 것

  • 평범한 말로 쓴 요청, 영어 또는 프랑스어
  • 원하는 모드: 실제로 무언가를 실행하려면 Agent (Automated), 그냥 대화하려면 Ask (Interactive)
  • 해당한다면, 관련된 폴더를 드롭 영역에 끌어다 놓기

나오는 것

  • Agent 모드에서는: 고른 도구, 그 파라미터, 확인 대화상자, 그리고 승인하면 실행
  • Ask 모드에서는: 자유 텍스트 답변이 나오고 아무것도 실행되지 않습니다
  • 도구가 실패하면 자동 복구 시도를 최대 두 번 하며, 시도마다 자체 확인을 거칩니다

단계

  1. Ollama가 실행 중인지 확인합니다. 필요하면 Agent가 설치하고 시작하게 하고, 첫 실행 때 모델 다운로드가 끝나기를 기다리십시오.
  2. 모드를 고릅니다. 도구를 실제로 실행하려면 "Agent (Automated)", 답만 받으려면 "Ask (Interactive)".
  3. 원하는 것을 설명합니다. 동료에게 설명하듯이 평범한 말로 쓰십시오.
  4. 요청이 특정 데이터와 관련되어 있으면 관련 폴더를 드롭 영역에 끌어다 놓습니다. Agent가 어느 것이 무엇인지 추측해 보려 합니다.
  5. 메시지를 보냅니다. Agent 모드에서는 도구와 그 파라미터가 제안되고, Ask 모드에서는 답이 곧바로 돌아옵니다.

확인 대화상자 읽기

Agent 모드에서는 사용자가 "Yes"라고 하지 않으면 아무것도 실행되지 않으며, 대화상자에는 결정된 모든 파라미터가 key=value 쌍으로 나열됩니다. 도구가 실제로 시작되기 전에, 잘못 추측한 폴더나 의도와 맞지 않는 값을 잡아낼 수 있는 유일한 지점입니다.

모든 줄을 꼼꼼히 읽으십시오

대부분의 도구에서 Agent가 넘긴다고 생각하는 것과 도구가 실제로 기대하는 것 사이의 대응이 어긋나 있습니다. 그래서 실행이 잘못된 값으로 시작되는데도 미리 경고하는 오류가 없을 수 있습니다. 확인 대화상자가 유일하게 실질적인 점검입니다.

승인하면 실행된 도구가 끝날 때까지 Slicer 인터페이스가 멈춥니다. 정상이며, 기다리는 것 말고는 할 일이 없습니다.

문제가 생기면

"아무것도 실행되지 않거나, 오류가 이해되지 않습니다"

저장소의 현재 상태에서 Agent는 실행하려는 스크립트를 스스로 찾지 못합니다. 사용자가 직접 위치를 알려 주지 않으면 실행은 시작도 되기 전에 실패합니다. 뒤따르는 자동 복구 단계도 이를 고칠 수 없습니다. 문제는 파라미터가 아니라 스크립트의 경로에 있기 때문입니다.

잘못된 값으로 시작하는 실행

위를 보십시오. 승인하기 전에 항상 확인 대화상자를 확인하십시오. 파라미터 불일치는 보통 오류 메시지가 아니라 그 대화상자에서 눈으로만 드러납니다.

그래픽 카드가 없으면 모든 것이 느립니다

모델 서버가 GPU 없이 실행 중이면 답변마다 대략 1분 반이 걸린다고 예상하십시오. 주고받는 대화는 초가 아니라 분 단위로 쌓입니다.

인용 방법

논문은 없습니다. 이 모듈은 개발 중이며, NA-MIC 프로젝트 보고서 하나로만 설명되어 있습니다.

연구에서 이 도구(Agent)를 사용했다면 다음을 인용하십시오:

Dumont P, Buisson A, Prieto JC, Cevidanes L, Pieper S. AI-Agent for SlicerAutomatedDentalTools. 45th NA-MIC Project Week, Boston, 2026.

projectweek.na-mic.org. 프로젝트 보고서입니다. 에이전트가 무엇을 하도록 설계되었는지, 작업이 어디까지 진행되었는지 다룹니다.

배경 문헌, 도구 자체의 인용이 아님

  • Qwen Team, arXiv 2025: Qwen3 Technical Report. 어느 도구로 안내할지 결정하고 그 도구의 매개변수를 추출하는 모델입니다.
  • Reimers & Gurevych, EMNLP 2019: Sentence-BERT: Sentence Embeddings using Siamese BERT-Networks. 질문을 색인된 문서와 어떻게 비교하는지 설명합니다. 에이전트가 답하기 전에 무엇을 보게 될지 결정하는 단계입니다.
  • Nogueira & Cho, arXiv 2019: Passage Re-ranking with BERT. 검색된 구절에 이어서 적용하는 재순위화로, 상위에 오르는 결과를 크게 개선합니다.

이 도구의 전체 참고문헌(찾아낸 것과 찾아봤지만 없었던 것)은 출처 페이지에 있습니다.

실제 동작 방식 → 아틀라스 페이지: 2단계 라우팅, 관여하는 두 모델, 모듈이 스크립트를 찾지 못하는 이유, 매니페스트에 있는 도구의 실제 상태.

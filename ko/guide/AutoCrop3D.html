AutoCrop3D: 볼륨 시리즈를 자르기

AutoCrop3D는 볼륨 폴더를 공통 관심 영역으로, 또는 환자마다 따로 정한 영역으로 일괄 자릅니다. 네트워크도, 다운로드할 모델도 없습니다. 복셀 값은 전혀 건드리지 않는 기하학적 자르기이며 거의 즉시 끝납니다.

실행하는 두 가지 방법

이 페이지는 레거시 Slicer 모듈을 설명합니다. VISOR 서버로 사용하는 방법은 VISOR와 함께와 VISOR 사용하기를 보십시오.

언제 쓰는가

시리즈가 너무 크거나 시야가 너무 들쭉날쭉해서 그대로 처리할 수 없을 때 언제든 쓸 수 있습니다. 분할 도구(AMASSS, BatchDentalSeg) 앞에서 실행하면 처리할 양을 줄이고, 뒤에서 실행하면 유용한 영역만 남깁니다. AutoCrop3D는 이미 만든 분할로부터 빠른 미리 보기용 VTK 메시를 생성할 수도 있습니다.

관심 영역 준비하기

자를 영역은 Slicer ROI 파일(.mrk.json) 하나에서만 나옵니다. 장면에서 대표적인 환자 위에 Markups > ROI 상자를 놓고, 조정한 뒤 저장하십시오. 사용 방법은 두 가지입니다. 폴더의 모든 볼륨에 ROI 하나를 적용하거나, 환자마다 ROI 하나씩을 쓰는 것이며, 후자에서는 짝이 맞도록 각 ROI 파일 이름에 해당 볼륨과 같은 접두사를 붙이십시오(아래 참고).

ROI는 축에 정렬된 상자여야 하며, 있는 그대로 저장해야 합니다

레거시 모듈(3c67957), VISOR와는 조금 다릅니다. 서버가 좌표계를 읽으므로 RAS로 저장된 ROI는 변환됩니다. 실제로 회전된 박스는 여전히 축에 정렬된 형태로 잘리지만, 이제 실행 보고서가 이를 알려 줍니다(roi_orientation_ignored). 기울어진 영상을 위한 “아래 참조” 옵션은 그곳에 없습니다. 자세한 내용: VISOR 사용.

빠른 자르기 경로는 ROI 파일에 선언된 방향과 좌표계를 완전히 무시합니다. 중심과 크기만 읽고, 볼륨의 축에 정렬된 박스라고 가정합니다. 회전된 ROI는 회전되지 않은 것처럼 처리되고, 잘못된 좌표계로 저장된 ROI는 오류 메시지 없이 중심이 어긋납니다. 빠른 경로는 Slicer가 기본으로 저장하는 방식의 똑바른 박스에서만 동작합니다. 실제로 회전된 ROI는 아래를 참조하십시오.

필요한 것, 얻는 것

준비할 것

  • 볼륨 폴더: .nii.gz, .nii, .nrrd.gz, .nrrd, .gipl.gz 또는 .gipl
  • ROI 파일(.mrk.json) 또는 환자마다 ROI 하나가 들어 있는 폴더
  • 출력 접미사(기본값은 “cropped”)

나오는 것

  • 입력마다 잘린 볼륨 하나, 입력 폴더 구조를 그대로 따릅니다
  • 선택 사항: 잘린 분할마다 VTK 메시 하나
  • 변환 파일 없음: 기하 정보는 전부 볼륨 자체에 들어 있습니다

단계

  1. ROI를 배치하고 저장합니다. 시리즈 전체에 박스 하나를 쓰거나, 환자마다 볼륨 이름에 맞춰 이름을 붙인 박스를 하나씩 씁니다.
  2. 입력 볼륨 폴더를 지정합니다. AutoCrop3D는 폴더 전체를 한 번에 처리합니다.
  3. ROI 파일 또는 폴더를 지정합니다. 파일 하나는 모든 환자에게 적용되고, 여러 개이면 환자별로 짝지어집니다.
  4. 출력 접미사를 고르고, 필요하면 “입력과 같은 크기 유지”를 선택합니다. 원래의 전체 기하 정보가 보존되고 ROI 바깥은 모두 0이 됩니다.
  5. 회전된 ROI에만 해당: “기울어진 영상에 Crop Volume 모듈 사용”을 선택하되, 그 전에 아래 경고를 읽으십시오.
  6. 출력 폴더를 지정한 뒤 실행합니다.

보존되는 것

이것이 이 도구의 핵심입니다. 기본 자르기 경로는 리샘플링을 하지 않습니다. 복셀 블록을 추출하고 볼륨의 원점만 다시 계산하며, 간격, 방향, 복셀 값은 원본과 비트 단위로 동일하게 유지됩니다. 실제로 전체 볼륨에서 계산한 정합 행렬은 물리 좌표가 전혀 움직이지 않았으므로 잘린 볼륨에서도 그대로 유효합니다. 정합한 뒤에 잘라도 아무것도 다시 계산할 필요가 없습니다.

문제가 생기면

ROI 파일이 정확히 하나뿐인 폴더 → 오류

레거시 모듈(3c67957), VISOR에는 해당하지 않습니다. 정확히 하나의 ROI가 들어 있는 폴더는 모든 스캔에 적용됩니다.

환자별 ROI를 쓰는데 폴더에 .mrk.json 파일이 하나뿐이면, 모듈은 이를 모든 볼륨에 적용하지 않고 오류로 중단합니다. 이 경우에는 폴더가 아니라 그 파일을 공유 ROI 하나로 직접 지정하십시오.

환자별 ROI: 밑줄에서 매칭이 깨짐

레거시 모듈(3c67957), VISOR에는 해당하지 않습니다. 스캔과 ROI가 하나의 이름 규칙을 거치므로 Patient_01_Scan.nii.gz와 Patient_01_ROI.mrk.json이 짝지어집니다. ROI가 없는 스캔은 패널의 상태 줄(최대 다섯 개 이름)과 보고서에 이름이 표시되고, 아무것도 자르지 못한 실행은 빈 폴더로 끝나지 않고 메시지와 함께 실패합니다.

볼륨 이름과 ROI 이름은 비교할 때 같은 방식으로 분리되지 않습니다. 밑줄이 없는 환자 ID(MA0001_Scan.nii.gz / MA0001_ROI.mrk.json)는 문제없이 짝지어집니다. ID 자체에 밑줄이 있으면 짝이 깨져 해당 환자는 건너뛰어지고, 나머지 일괄 처리는 멈추지 않습니다(경고가 로그에 기록됩니다).

자르기 자체는 받아들이는 형식을 인터페이스가 거부함

레거시 모듈(3c67957), VISOR에는 해당하지 않습니다. 패널은 서버의 설명으로 생성되며, 압축하지 않은 .nii, .nrrd, .gipl 파일의 폴더도 받아들여집니다. 유일한 예외는 .nrrd.gz로, 메시지와 함께 파일별로 거부됩니다(gzip된 NRRD에는 ITK 리더가 없습니다).

인터페이스의 입력 검사는 압축된 볼륨(.nii.gz, .nrrd.gz, .gipl.gz)만 인식합니다. 압축하지 않은 .nii 또는 .nrrd 파일의 폴더는 자르기 자체가 문제없이 처리하는데도 거부됩니다(“Wrong type of patient file detected”). 압축을 풀거나, 같은 일괄 처리에 두 종류를 섞지 마십시오.

“기울어진 영상에 Crop Volume 모듈 사용”: 먼저 읽어 보십시오

레거시 전용. VISOR 패널에는 이런 체크박스가 없습니다. 이 엔진은 실행 중인 Slicer가 필요하여 이식되지 않았습니다.

실제로 회전된 ROI를 다루는 유일한 방법이지만, 두 가지가 달라집니다. 첫째, 볼륨을 ROI 자체의 좌표계로 리샘플링하므로 복셀 값이 수정되고, “리샘플링 없음, 정합 행렬 그대로 유효”라는 이점이 더 이상 적용되지 않습니다. 둘째, 처리하는 환자마다 Slicer 장면 전체를 비웁니다. 보관하려는 데이터를 불러 놓았다면 사용하지 마십시오.

분할에서 VTK 메시 생성하기

레거시 모듈(3c67957), VISOR와는 다릅니다. 명시적인 표면 옵션이 있습니다(기본값 segmentations, 또는 all, none). 기본값에서는 파일 이름에 seg, segmentation, mask, pred, label, labels 중 하나가 온전한 단어로 들어 있는 파일만 메시를 얻으며, 폴더 이름은 고려되지 않고, 메시는 스캔 자체의 공간에 놓이며, 각 구조물이 자신의 색을 유지합니다.

출력 경로 어디에든 “seg”가 나타나면 자동으로 작동합니다(예: Segmentations/ 폴더). 부차적이고 취약한 기능으로 보십시오. 메시가 잘린 볼륨과 정확히 맞는다는 보장이 없고, 모든 구조물이 같은 색으로 나오며, 레이블이 여섯 개를 넘는 분할은 오류 메시지 없이 메시를 전혀 만들지 못합니다.

인용 방법

유틸리티 모듈입니다. 자체 논문이 없으며 필요하지도 않습니다. Slicer가 이미 할 수 있는 자르기(cropping)를 일괄로 적용합니다.

모듈 자체를 다룬 문헌이 없으므로, 확장 기능을 소프트웨어로 인용하십시오:

SlicerAutomatedDentalTools. DCBIA-OrthoLab. https://github.com/DCBIA-OrthoLab/SlicerAutomatedDentalTools

학술지 양식이 요구한다면 접속 날짜를 덧붙이십시오.

배경 문헌, 도구 자체의 인용이 아님

  • Documentation 3D Slicer: Crop Volume. 이 모듈의 바탕이 되는 Slicer 모듈입니다. 여기서 보이는 보간, 샘플링 계수, 등방성이 실제로 무엇을 뜻하는지 설명합니다.
  • Barone et al., Orthod Craniofac Res 2025: Deep Learning-Based Three-Dimensional Analysis Reveals Distinct Patterns of Condylar Remodelling After Orthognathic Surgery in Skeletal Class III Patients. 이 일괄 자르기를 준비 단계로 사용한 연구실의 연구입니다. 이 모듈의 쓰임새를 보여 주는 예입니다.

이 도구의 전체 참고문헌(찾아낸 것과 찾아봤지만 없었던 것)은 출처 페이지에 있습니다.

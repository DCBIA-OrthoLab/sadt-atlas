VISOR 사용하기: 3D Slicer에서 서버로 도구 실행하기

VISOR에서는 계산이 더 이상 사용자의 컴퓨터에서 실행되지 않습니다. Slicer에서 도구를 고르면 선택한 파일이 서버로 전송되고, 서버가 계산하며, 결과가 장면으로 돌아옵니다. 이 페이지는 설정해야 할 것, 제공해야 할 것, 환자 데이터를 보내기 전에 확인할 것을 다룹니다. VISOR가 어떻게 만들어졌는지는 VISOR 아틀라스에 있습니다.

클라이언트: 구현 및 테스트됨 비식별화: 미구현 MRI2CBCT: 미배포
환자 데이터를 사용하기 전에

VISOR 클라이언트는 디스크에 있는 그대로 파일을 보냅니다. 비식별화되는 것은 없습니다. 컴퓨터를 떠나는 것을 참조하십시오.

달라지는 점

이 사이트의 나머지는 레거시 확장인 SlicerAutomatedDentalTools를 설명하며, 각 모듈은 사용자의 컴퓨터에서 실행됩니다. VISOR는 다른 Slicer 확장인 AutomatedDentalToolsRemote입니다. 이 확장의 모듈은 원격 서버 위의 얇은 패널입니다.

  • 계산이 컴퓨터를 떠납니다. 분할을 실행할 수 없는 노트북도 분할을 요청할 수 있습니다.
  • Slicer의 Python에 설치할 것이 없고, 내려받을 모델도 없습니다. 확장은 다른 확장에 대한 의존성을 선언하지 않으며, 모델은 서버에 있습니다.
  • 양식은 서버에서 옵니다. 도구의 패널은 열 때 서버가 공개하는 설명으로부터 만들어집니다. 서버에 추가된 필드는 확장의 새 릴리스 없이도 Slicer에 나타납니다.
  • 서버, 주소, 키가 필요합니다. 서버를 마련하는 것은 서버의 주제이지 이 페이지의 주제가 아닙니다. 배포를 참조하십시오.

출처: AutomatedDentalToolsRemote CMakeLists.txt:10,15 및 README.md:3-8, 150-165(커밋 19b95e8).

확장 설치하기

README와 빌드 파일이 말하는 것은 다음과 같으며, 여기서는 그 이상을 가정하지 않습니다.

  • 확장은 AutomatedDentalToolsRemote입니다. 3D Slicer의 안정판과 나이틀리 버전 모두에서 동작하며, 모듈은 Automated Dental Tools Remote 범주 아래에 나타납니다.
  • 확장 의존성이 나열되어 있지 않으므로(EXTENSION_DEPENDS "NA") SlicerConda, SlicerDentalModelSeg, NNUNet은 필요 없습니다.
  • README는 전환 기간 동안 Extensions Catalog에 등재되어 있다고 밝힙니다.
  • 레거시 확장과 나란히 설치하지 마십시오. README는 둘 중 하나만 쓰라고 요청합니다. 많은 모듈의 이름이 같고, Slicer는 같은 이름의 모듈 둘 중 하나만 유지하기 때문입니다.

Slicer를 서버에 연결하기

Server Tools Settings(범주 Automated Dental Tools Remote.Advanced)를 엽니다. 여기에 무언가를 저장하기 전까지 주소는 아무 곳에도 닿지 않는 자리 표시자(https://set-your-server.invalid)이므로, 어떤 파일도 컴퓨터를 떠나지 않습니다.

준비할 것

  • Server URL: 공인 인증 기관이 서명한 인증서를 가진 https:// 주소.
  • API key: 서버의 API 토큰(필드는 가려져 있습니다). README는 관리자 토큰이 아니라 API 토큰을 쓰라고 합니다.
  • Timeout: 1에서 3600초, 기본값은 600.

바꿀 수 없는 것

  • http://는 안 되며, http://localhost도 안 됩니다.
  • 인증서는 항상 검사됩니다. 패널에는 “Verify TLS: Always on”이 표시되며 체크할 것은 없습니다.
  • 리디렉션은 절대 따라가지 않습니다.

Save를 클릭합니다. 변경은 즉시 적용되고 재시작 후에도 유지됩니다. http:// 주소를 입력하면 Slicer가 아무것도 저장하기 전에 거부합니다. Restore defaults는 저장한 것을 지웁니다.

자신의 컴퓨터에 있는 서버도 같은 규칙을 따릅니다. 클라이언트는 서버 자체의 자체 서명 인증서를 받아들이지 않으므로, 공개 주소(예: tailscale serve 주소(https://<name>.<tailnet>.ts.net)), 또는 Let's Encrypt나 기관 인증서를 쓰는 리버스 프록시를 통해 접속합니다.

서버에 연결할 수 있습니까? “Test connection” 버튼은 없습니다. 패널 맨 위에 “Server: online” 또는 “Server: offline” 줄이 표시되며, 모듈을 열 때와 저장할 때마다 갱신됩니다. 이는 키가 필요 없는 서버의 /health 페이지에만 요청하므로, “online”이 키가 받아들여진다는 근거는 아닙니다. 잘못된 키는 첫 실행에서 드러납니다(문제가 생겼을 때 참조).

키는 평문으로 저장됨

Slicer는 키를 사용자의 자체 설정 파일에 평문으로 저장합니다. 가려진 필드는 화면에서만 숨길 뿐입니다. Slicer 설정을 읽을 수 있는 사람은 누구나 키를 읽을 수 있습니다.

HTTPS에는 대체 수단이 없음

HTTPS 규칙이나 인증서 검사를 완화하는 설정, 플래그, 파일은 없습니다. 클라이언트의 이전 버전이 저장한 http:// 주소는 시작할 때 무시됩니다.

도구 실행하기

  1. 모듈 목록에서 도구를 고릅니다. 열 때 서버로부터 양식이 만들어집니다. 서버에 연결할 수 없으면 패널이 도구를 불러오지 못했다고 알리고 Retry 버튼을 제공합니다.
  2. 양식을 채웁니다. 제공해야 할 것은 도구마다 다르며, 필드 이름은 서버에서 오므로 각 도구 자체의 가이드 페이지를 읽으십시오.
  3. Apply를 누릅니다. 패널은 아무것도 전송하기 전에 먼저 양식을 검사합니다(알 수 없는 인자, 없는 파일, 빠진 필수 필드).
  4. 진행 상황을 지켜보다가 필요하면 취소합니다.

입력으로 줄 수 있는 것

  • 파일은 이름도 바이트도 그대로 전송됩니다.
  • 폴더는 파일과 하위 폴더의 이름을 유지하는 아카이브로 묶여 전송됩니다.
  • Slicer 장면의 노드(볼륨, 모델, 관심 영역)는 노드가 아니라 도구와 인자의 이름을 따른 임시 파일로 내보내집니다. 예를 들어 AutoCrop3D는 이런 식으로 장면에서 관심 영역을 가져옵니다.
  • 호스팅된 테스트 파일은 서버가 도구에 제공하는 샘플입니다. 하나를 고르면 먼저 내려받은 뒤(백그라운드에서 이루어지므로 Slicer 창은 계속 쓸 수 있습니다) 입력으로 사용합니다. 같은 세션에서 같은 항목을 다시 고르면 내려받은 것을 재사용합니다.
  • 서버에서 선택한 모델은 서버가 공개하는 목록에서 이름으로 고릅니다. 이름만 전달되며 모델 파일이 컴퓨터에서 전송되는 일은 결코 없습니다. 목록이 비어 있고 인자를 줄 다른 방법이 없으면, 패널이 서버 관리자에게 문의하라는 경고를 표시합니다.

큰 입력은 나누어 전송되고 부분마다 검증됩니다. 서버가 코호트 폴더에 대한 크기 계획을 공개하면, 패널은 이를 배치로 나누며 각 배치는 일반적인 한 번의 실행입니다.

진행 상황, 취소, 연결 끊김

  • 패널은 서버 자체의 단계를 보고합니다. 요청 수신, 입력 파일 준비, GPU 대기, 서버에서 실행 중, 결과 패키징, 완료입니다. 경과 시간이 그 옆에서 흘러갑니다. 대기열에 들어간 실행은 “queued”로 표시됩니다.
  • Cancel은 서버에서의 실행도 중지합니다. 실행마다 Cancel이 하나 있으며, 여러 실행이 있으면 “Cancel all”로, 코호트에서는 “Cancel the cohort”로 표시됩니다. 취소된 실행은 오류로 보고되지 않습니다.
  • 서버가 작업하는 동안 연결이 끊기면 패널이 스스로 진행 스트림에 다시 연결하여, 이미 보여 준 것을 반복하지 않고 중단된 지점에서 이어갑니다. 이것이 기본으로 켜져 있는 분리 모드입니다. 입력이 준비되는 즉시 요청이 끝나고 결과는 진행 스트림으로 도착하므로, 설정의 타임아웃은 더 이상 실행이 지속될 수 있는 시간의 상한이 아닙니다.
검토를 위해 멈추면 차단 방식으로 실행됨

“stop after” 단계를 켜면(품질 검토 참조) 실행은 분리 모드를 쓰지 않습니다. 서버가 원래 요청에 대한 응답으로 검토용 자료를 돌려줍니다. 이때는 Server Tools Settings의 타임아웃이 적용되며, 연결이 끊기면 응답을 잃습니다.

출처: AutomatedDentalToolsRemote ServerToolsCoreLib/base_widget.py:730-742,1037-1050,1150-1195,1302-1330,2024-2105,2688-2691,3080-3087,3270-3345; client.py:1094-1106,1303-1437; slicer_io.py:51-63,171-189; config.py:78-90(커밋 19b95e8).

결과 가져오기

  • 실행이 끝나면 패널은 결과를 (병렬 범위로) 내려받고, 아카이브를 검사한 뒤, 출력 폴더에 풉니다. 기본적으로 그 폴더는 Documents의 “Slicer Output”입니다.
  • 아카이브에 절대 경로, .., 링크, 100 000개를 넘는 항목, 또는 20 GB를 넘는 크기가 들어 있으면 아무것도 쓰기 전에 거부됩니다.
  • “Load the results into the scene when done” 체크박스는 도구가 만든 것, 즉 도구에 따라 볼륨, 레이블 맵, 모델, 랜드마크를 가져옵니다. 기본값으로는 최대 12개 항목이 불러와지며, 그보다 많으면 한 번에 불러오기에는 너무 많다고 패널이 알려 줍니다.
  • 일부 도구는 자체 옵션이나 메시지를 추가합니다. ALI는 실행 보고서를 요약하고 랜드마크 파일이 20개를 넘으면 확인을 요청합니다. VFACE에는 “Load the heat maps” 상자가 있고, AutoMatrix에는 “Use the mirror matrix” 상자가 있습니다. CNE는 장면에 아무것도 불러오지 않고 상태 표시줄에 요약을 보여 줍니다.
  • 서버에 있는 결과 사본은 내려받은 뒤 삭제됩니다.

출처: AutomatedDentalToolsRemote ServerToolsCoreLib/base_widget.py:1389-1425,1431,1455,1590-1620; slicer_io.py:247-331; config.py:97-98; client.py:1748-1773; ALIRemote/ALIRemote.py:53,134-252; VFACERemote/VFACERemote.py:138-162; AutoMatrixRemote/AutoMatrixRemote.py:132-201; CNERemote/CNERemote.py:72-103(커밋 19b95e8).

VISU로 품질 검토하기

일부 도구는 한 단계 뒤에 멈춰서 중간 결과를 확인하게 할 수 있습니다. 그러면 양식에 다중 선택 stop_after가 있는 “Quality control” 절이 나타나며, 기본으로 체크된 것은 없습니다. 다른 도구를 호출하는 도구가 이를 제공하며, 예로 구강 스캔용 ALI나 VFACE가 있습니다.

  1. 멈춤. 서버는 체크한 단계 뒤에 일시 정지합니다. 패널은 “Stopped after <step>, waiting for your review”를 표시하고, 그때까지 만들어진 것을 내려받아 그 위에서 VISU를 엽니다.
  2. 검토. VISU는 한 번에 환자 한 명을 보여 줍니다. 스캔, 마스크, 표면, 랜드마크가 함께 나옵니다. 화살표 키로 이전 또는 다음 사례로 갑니다. 환자에 표시하려면 Flag를, 이동하려면 Go to next flagged를 사용합니다. “Drawn on <scan>” 줄을 읽으십시오(랜드마크가 어느 스캔 위에 그려졌는지, 그리고 그것이 점 옆에서 발견되었는지 가정된 것인지를 알려 줍니다).
  3. 수정. 랜드마크는 점을 끌어서 Save할 수 있습니다. 옮긴 점만 이름으로 대응시켜 다시 기록됩니다. Undo my changes와 Revert to what is on disk가 이를 되돌립니다. 정합 조정은 도구 자체의 변환에 합쳐지지 않고, 장면 옆에 별도의 변환 파일로 저장됩니다.
  4. 계속. 내용이 바뀐 파일만 되돌려 보내지고, 이어서 서버가 실행을 재개합니다.
  5. 되돌아가기. 이전 단계(랜드마크나 정합)를 수정할 수 있으면 플래그에 “Go back and edit this patient”라고 표시됩니다. 일부 환자에 표시를 하고 나면 초록색 버튼에 “Go back to <step> for N patient(s)”라고 표시됩니다. 수정 내용이 기록되고, 표시된 환자는 그 단계부터 다시 처리되며, 나머지 환자는 이미 가진 결과를 그대로 유지합니다.

VISU를 찾을 수 없거나 멈춘 지점에 볼 것이 아무것도 만들어지지 않았다면, 패널이 그렇게 알리고 즉시 실행을 재개하여 사용자의 데이터가 든 채로 서버에서 일시 정지된 상태로 남는 것이 없게 합니다.

컴퓨터를 떠나는 것

비식별화되는 것은 없음

현재 VISOR에는 비식별화 도구가 없습니다. 선택한 것은 디스크에 있는 그대로 서버로 전송됩니다. 파일 이름, DICOM 헤더, 그리고 그것들이 담고 있는 모든 식별자가 포함됩니다. 비식별화 파이프라인이 클라이언트 저장소에 명세되어 있지만 README는 이것이 구현되지 않았다고 밝히며, 코드를 검색해도 구현이 발견되지 않습니다.

  • 안내문. 이 컴퓨터가 아닌 서버 주소를 저장하면, Slicer는 서버마다 한 번 “Files are uploaded unmodified. This client does not de-identify anything... De-identify your data before selecting it, or confine use to data that carries no protected health information.”라고 표시합니다. 이것은 경고일 뿐 검사가 아닙니다. 아무것도 막지 않습니다.
  • 폴더는 이름을 유지합니다. 폴더는 원래의 파일 및 하위 폴더 이름과 함께 묶입니다. 장면 노드는 일반적인 이름으로 내보내지므로 노드 이름은 나가지 않습니다.
  • CNE는 임상 노트를 보냅니다. 텍스트 모델이 서버에서 실행됩니다. 노트가 올라가고 추출 결과가 돌아옵니다. 아무것도 컴퓨터를 떠나지 않는다고 말하는 레거시 CNE 페이지는 VISOR에는 적용되지 않습니다.
  • 전송만. HTTPS가 전송을 보호합니다. 클라이언트 쪽에서 그 외의 파일 암호화는 없습니다.
  • Medical Data Anonymizer는 여전히 있지만, 이 컴퓨터에서 텍스트 문서를 처리하며 전송되는 것에 포함되지 않습니다.
  • 클라이언트는 소속 기관이 통제하는 서버로만 연결하고, 운영하는 쪽과의 계약이 보내는 데이터를 포함하는지 확인하십시오. README도 같은 것을 요청합니다.

서버가 보호하는 것과 보호하지 않는 것을 포함한 보안 전반은 VISOR 보안에 있습니다.

문제가 생기면

대부분의 실패에서 Slicer는 서버 자체의 메시지를 표시합니다. 각각의 의미는 다음과 같습니다.

“The server URL must start with https://”

http:// 주소를 입력했거나 Slicer가 이전 버전의 주소를 발견했습니다. 공개 https:// 주소를 사용하십시오. 자신의 컴퓨터에 있는 서버를 포함해 이 규칙을 피할 방법은 없습니다.

401: 인증 실패

키가 틀렸거나 없습니다. 상태 페이지에는 키가 필요 없으므로 패널은 그래도 “Server: online”이라고 표시할 수 있습니다. Server Tools Settings에서 키를 다시 입력하고 Save를 누르십시오.

점검 시간대의 503

서버가 업데이트되는 동안에는 새 작업을 503과 Retry-After: 10 헤더로 거부하며, 최대 300초 동안 그렇습니다. 클라이언트는 그 헤더를 읽지 않습니다. 서버의 메시지나 “Server error (503)”가 보입니다. 기다렸다가 Apply를 다시 누르십시오. 이미 진행 중인 결과 읽기는 막히지 않습니다.

422: 잘못된 인자

서버가 문제의 인자를 지명합니다. 예를 들어 허용 목록 밖의 옵션입니다. 지명된 필드를 고치십시오. 파일 형식 메시지가 있는 “400”은 그 도구가 파일 확장자를 받아들이지 않는다는 뜻입니다.

413: 파일이 너무 큼

서버는 한도를 넘는 업로드를 거부하며, 기본값은 파일당 500 MB입니다. 큰 코호트에서는 거대한 아카이브 하나 대신 폴더를 주어 배치로 나눌 수 있게 하십시오.

500: “The tool failed on the server”

도구 안의 충돌에 대해 클라이언트가 보여 주는 것은 이것이 전부이며, 의도된 것입니다. 세부 정보에 서버 내부 정보가 들어 있을 수 있기 때문입니다. 서버를 운영하는 사람에게 로그를 읽어 달라고 요청하십시오.

  • 타임아웃. Server Tools Settings의 타임아웃(기본값 600초)은 열려 있는 상태로 유지되는 요청에 적용됩니다. 기본값인 분리 모드에서는 긴 실행이 이에 의해 끊기지 않습니다. 서버에는 기본적으로 실행 시간 제한이 없습니다.
  • 대기열에서 기다림. 실행은 GPU를 기다릴 수 있습니다. 패널에 “Waiting for the GPU”라고 표시되며, 기다리는 동안 취소할 수 있습니다. 서버는 동시에 실행되는 수도 제한하므로, 다섯 번째 실행은 대기열에 올라온 것으로 표시되기도 전에 기다릴 수 있습니다.
  • 서버 오프라인. 도구 목록을 불러올 수 없으면 패널이 그렇게 알리고 Retry를 표시합니다. 주소와 Server Tools Settings의 “Server: online”을 확인하십시오.
  • config.py의 변경이 효과가 없음. Server Tools Settings에 저장한 것이 컴파일된 기본값보다 항상 우선합니다.

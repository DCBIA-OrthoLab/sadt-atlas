GreedyReg: ITK-SNAP 엔진으로 CBCT 스캔 두 개 정합하기

GreedyReg는 ITK-SNAP의 greedy 엔진을 구동하여 같은 환자의 CBCT 스캔 두 개(T1과 T2)를 정렬합니다. 주된 계산에 신경망은 없고 설치할 것도 없습니다. 결과는 예측이 아니라 고전적인 강도 기반 최적화에서 나옵니다.

실행하는 두 가지 방법

이 페이지는 레거시 Slicer 모듈을 설명합니다. VISOR 서버로 사용하려면 VISOR 사용과 VISOR 사용하기를 참조하십시오.

언제 쓰는가

같은 모달리티의 CBCT 스캔 두 개를 정합할 때 사용합니다. 예를 들어 전후 추적 관찰에서 계산을 세밀하게 통제하고 싶을 때, 즉 어떤 지표를 쓸지, 자유도를 몇으로 할지, 선택적으로 최적화를 한 영역에 집중시키는 마스크를 쓸지 정하려 할 때입니다. 이 도구는 체인의 끝에 있습니다. SADT의 다른 어떤 것도 그 결과를 소비하지 않습니다. 결과 변환을 Slicer의 다른 곳에서 재사용해야 한다면 이 모듈은 맞지 않습니다. 그 행렬은 greedy 전용으로 남으며 Slicer 변환 파일이 아닙니다.

모드 셋, 실제 정합은 하나

레거시 모듈(3c67957), VISOR와는 다릅니다. 서버 도구에는 모드가 하나뿐이며, 폴더 두 개에 대한 Automatic Registration에 해당합니다. Manual Alignment와 Distant Registration은 그곳에 없습니다. 자세한 내용: VISOR 사용.

Automatic Registration만이 실제로 강도 기반 정합을 수행합니다. Manual Alignment와 Distant Registration은 나중에 다듬을 출발점만 준비합니다.

필요한 것, 얻는 것

준비할 것

  • .nii.gz CBCT 스캔 폴더 두 개: 하나는 fixed 볼륨(T1), 하나는 moving 볼륨(T2)
  • 문자 다음에 숫자로 시작하는 파일 이름, 예를 들어 A01_T1.nii.gz: GreedyReg가 같은 환자의 T1과 T2를 짝짓는 것은 이 규칙 덕분이며, 다른 이름 규칙은 경고 없이 짝지어지지 않습니다
  • 선택 사항: fixed 볼륨의 공간에 있는 마스크(분할 또는 레이블맵)
  • 선택 사항: 초기화 행렬, 또는 모듈 안에서 한 수동 사전 정렬

나오는 것

  • T1 격자로 리샘플링된 T2, .nii.gz와 찾아낸 아핀 행렬
  • Distant 모드에서는 출발 행렬만 나오며, 정합된 볼륨은 나오지 않습니다
  • 만들어지는 행렬은 Slicer의 변환 형식이 아니라 greedy 고유의 형식입니다. 그대로는 변환 노드로 불러와지지 않으며, SADT의 다른 어떤 것도 이를 재사용하지 않습니다

세 가지 모드와 선택 기준

  • Manual Alignment. moving 볼륨을 손으로 움직입니다(슬라이더, 또는 빠른 중심 맞춤용 “Center T2 on T1” 버튼). 두 CBCT 스캔이 이미 가깝고, 실제 계산을 실행하기 전에 대략적인 조정만 남았을 때 유용합니다.
  • Automatic Registration. 실제로 정합하는 유일한 모드입니다. greedy 엔진이 영상 강도로부터 강체 또는 아핀 변환을 최적화합니다. 여기서 지표(이질적인 강도에는 기본값인 NMI, 국소 상관에는 NCC, 두 볼륨의 모달리티가 같으면 SSD)와 자유도(강체 또는 완전 아핀)를 고릅니다.
  • Distant Registration (Large Misalignment). 처음부터 기하학적으로 멀리 떨어진 두 스캔을 위한 모드입니다. “Distant”는 그 간격을 가리키는 말이지 원격 계산이 아닙니다. 엔진과 예측 가중치를 한 번 내려받는 것 외에는 어떤 것도 컴퓨터를 떠나지 않으며, 환자 데이터는 결코 나가지 않습니다. 이 모드는 해부학적 랜드마크 몇 개(두개저, 하악 또는 상악, 한 번에 한 부위)를 예측하고 이로부터 출발 행렬을 도출합니다. 정합된 볼륨은 만들지 않으므로, 항상 이어서 Automatic Registration으로 다듬으십시오.

실제로는 두 CBCT 스캔이 이미 대략 겹쳐 있다면 곧바로 Manual 다음 Automatic으로 가십시오. 멀리 떨어져 있다면 Distant Registration으로 시작한 뒤 Automatic으로 다듬으십시오.

단계

  1. 볼륨을 나눕니다. fixed CBCT 스캔(T1)용 폴더 하나, moving 스캔(T2)용 폴더 하나로 나누며, 각 파일 이름에는 같은 환자 식별자가 들어 있어야 합니다.
  2. 필요하면 마스크를 추가합니다. 마스크는 fixed 볼륨의 공간에 있어야 합니다. 최적화가 그래디언트를 찾는 곳이 바로 거기이기 때문입니다.
  3. 어긋남이 크면 사전 정렬합니다. 작은 차이는 Manual 모드에서 손으로, 큰 차이는 Distant Registration으로 합니다.
  4. Automatic Registration으로 전환합니다. 지표와 자유도(강체 또는 아핀)를 고른 뒤 실행합니다.
  5. 시리즈의 경우 T1/T2 폴더 전체를 바로 지정하십시오. 일괄 처리가 식별자로 짝지어진 쌍들을 차례로 이어서 처리합니다.
  6. Slicer를 닫기 전에 결과를 저장하십시오. 그 이유는 아래를 참조하십시오.

문제가 생기면

Distant 모드에서는 “Save Registered Volume”이 아무것도 하지 않음

레거시 전용. VISOR에는 Distant 모드도 “Save Registered Volume” 버튼도 없습니다.

이 모드는 정합된 볼륨이 아니라 출발 행렬만 만듭니다. 버튼은 항상 “No result to save!”라고 답합니다. 대신 “Save Transform Matrix”를 사용하거나, 저장할 만한 볼륨을 얻으려면 곧바로 Automatic Registration으로 가십시오.

Distant 모드의 오해하기 쉬운 체크박스

레거시 전용. VISOR에는 Distant 모드가 없습니다.

구조물 여러 개(두개저, 하악, 상악)를 체크해도 합쳐지지 않습니다. 어떤 상자를 체크했는지와 관계없이 고정된 우선순위(두개저, 그다음 하악, 그다음 상악)로 정해진 한 부위만 실제로 사용됩니다.

일괄 처리에서는 실패 하나가 전체를 멈추며, 항상 분명하지는 않음

레거시 모듈(3c67957), VISOR에는 해당하지 않습니다. 실패한 환자는 보고서에 기록되고 나머지는 계속 진행됩니다. 쌍을 하나도 정합하지 못했을 때만 실행이 오류로 중단됩니다. Distant 모드에 관한 언급은 적용되지 않습니다.

폴더 전체를 처리할 때 처음 실패한 사례가 전체 실행을 멈춥니다. 이어서 하기도, 남은 사례 목록도 없습니다. Distant 모드에서 랜드마크 예측이 실패해도 분명한 오류로 나타나지 않을 수 있으며, 눈에 보이는 유일한 징후가 로그의 조용한 “only 0 matched landmarks”일 수 있습니다.

임시 폴더가 정리되지 않음

레거시 전용. VISOR에서는 서버가 환자마다 작업 폴더를 지웁니다.

자동 정합 뒤이든 수동 세션 뒤이든 모듈은 작업 폴더를 비우지 않습니다. 긴 시리즈에서는 디스크 사용량이 쌓입니다. 가끔 직접 정리하되, 반드시 결과를 저장한 뒤에 하십시오. Automatic 모드에서 “Save Registered Volume”이 파일을 가져오는 곳도 그곳이기 때문입니다.

그 이후

측정에 쓰기 전에 Slicer에서 정합된 볼륨을 fixed CBCT 위에 겹쳐 항상 눈으로 결과를 확인하십시오. 그리고 내보낸 행렬은 Slicer나 ITK 변환이 아니라 단순한 greedy 형식 파일이라는 점을 기억하십시오. 이 모듈 밖에서 재사용하려면 GreedyReg가 직접 수행하지 않는 변환이 필요합니다.

인용 방법

연구에서 이 도구(GreedyReg)를 사용했다면 다음을 인용하십시오:

Venet L, Pati S, Yushkevich P, Bakas S. Accurate and Robust Alignment of Variable-Stained Histologic Images Using a General-Purpose Greedy Diffeomorphic Registration Tool. arXiv:1904.11929, 2019.

arXiv:1904.11929. 이 모듈이 단순히 구동만 하는 엔진인 greedy의 논문입니다. 분량이 짧으며, 저자들이 인용을 요청하는 논문입니다.

배경 문헌, 도구 자체의 인용이 아님

  • Yushkevich et al., NeuroImage 2006: User-guided 3D active contour segmentation of anatomical structures: Significantly improved efficiency and reliability. greedy가 파생된 ITK-SNAP의 참고문헌입니다. 이 모듈은 ITK-SNAP의 용어 일부를 가져다 씁니다.
  • Documentation de greedy: greedy, command reference. 엔진의 전체 옵션 목록입니다. 인터페이스의 설정 하나가 무엇을 뜻하는지 알고 싶을 때 참고합니다.

이 도구의 전체 참고문헌(찾아낸 것과 찾아봤지만 없었던 것)은 출처 페이지에 있습니다.

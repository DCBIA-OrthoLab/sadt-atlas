VFACE

스스로는 아무것도 학습하거나 분할하지 않는 오케스트레이터. 다른 모듈 여섯 개를 연결해 CBCT를 자신의 거울상에 정합하고, 그 차이를 계측한 뒤, LightGBM 모델 세 개로 골격성 안면 비대칭을 분류한다.

SPIE Medical Imaging 2026 vface_cli conda 환경: 없음 (Slicer의 Python) 참고문헌

CBCT에서 골격성 안면 비대칭을 자동으로 분류한다. VFACE는 스스로 아무것도 학습하거나 분할하지 않는다. 저장소의 다른 모듈 여섯 개를 연결하고, 그 결과에서 선형 및 각도 계측값을 추출한 뒤, 마지막에 LightGBM 분류기 세 개를 적용하는 오케스트레이터다. 처리 사슬에서 가장 상위 수준의 모듈이며, 여기서 가장 중요한 정보는 호출 트리다.

임상 원리는 한 문장으로 요약된다. T2는 환자 자신의 거울상이다. 두 번째 스캔은 없다. 스캔의 방향을 정렬하고, 정중시상면을 기준으로 미러링한 뒤, 원본에 정합한다. 계측되는 모든 값은 환자와 그 자신의 거울상 사이의 차이다.

1. 파이프라인에서의 위치

저장소에서 VFACE를 호출하는 것은 없다. CMakeLists.txt:54는 이를 말단 모듈로 추가한다. 반면 VFACE는 프로세스 여덟 개를 호출하며, 그중 일곱 개가 확장의 다른 모듈이다. 전체 계획은 CreateListProcess() (createlistprocess.py:117)가 한 번에 만든다. 이 함수는 딕셔너리 리스트 {Process, Parameter, Module, Display, Review*}를 반환하고, 위젯이 이를 한 항목씩 풀어 실행한다.

3. 입력과 전처리

입력: 환자당 하나씩 T1 CBCT가 든 폴더 (.nii, .nii.gz, .nrrd, .nrrd.gz, .gipl, .gipl.gz). 분할도 랜드마크도 없다. VFACE는 원본 볼륨에서 시작한다. checkInputFolder() (VFACE.py:1221)는 빈 폴더로는 시작을 거부한다.

환자 식별: patientIdFromFileName (functionaq3dc.py:1369)은 이름을 _Scan, _Or, _MAND, _MD, _MAX, _MX, _CB, _lm, _T2, _T1, _Cl, .에서 자른다. 같은 처리가 createlistprocess에 세 번 중복되어 있다(TIMEPOINT-SUFFIX 표시). _T1/_T2만 인식되며, _T3는 짝짓기를 조용히 깨뜨린다.

리샘플링: spacing [0.3, 0.3, 0.3], resample_size = "None", center = "True" — 볼륨 자체의 크기는 유지되고 간격만 바뀐다. 출력은 <out>/T1 Resample/CBCT.

중심화 (pre_aso_cbct, model_folder=False): 순수하게 기하학적이다. 볼륨 중심을 원점으로 평행 이동하고, 옆에 .tfm을 기록한다 (PRE_ASO_CBCT.py:217). 여기에는 신경망이 관여하지 않는다.

방향 정렬: 같은 중심화된 스캔 위에 서로 다른 좌표계 두 개를 만든다.

좌표계ALI에 요청하는 랜드마크골드 스탠더드접미사
MAXANS, IF, PNS, UL6O, UR1O, UR6OOcclusal and Midsagittal Plane_MAX_Or
CBBa, LPo, N, RPo, S, LOr, ROrFrankfurt Horizontal and Midsagittal Plane_CB_Or

semi_aso_cbct는 랜드마크 3개로 초기화한 뒤, 환자의 랜드마크를 골드의 랜드마크에 맞추는 강체 vtkIterativeClosestPointTransform(1000회 반복, StartByMatchingCentroidsOn)을 수행하고 (utils.py:620), <pat>_<suffix>_transform.tfm = (ASO ∘ 중심화)의 역변환을 기록한다. 그 뒤에는 정중시상면이 x = 0에 놓이며, 이것이 미러가 유효하기 위한 조건이다.

미러. Matrix_mirror.tfm(AutoMatrixMirror 릴리스에 포함)은 AffineTransform이며, 파라미터는 -1 0 0 0 1 0 0 0 1, 평행 이동은 0이다. 즉 LPS에서 x축을 따른 순수 반사, 다시 말해 정중시상면에 대한 대칭이다. AutoMatrix는 이를 볼륨에는 sitk.ResampleImageFilter로, .mrk.json 파일에는 transform.GetInverse().TransformPoint로 적용한다 (Automatrix_CLI.py:171).

좌표계: 모든 것이 LPS다. ALI는 "coordinateSystem": "LPS"를 기록하고(io.py:36), derive_landmarks도 마찬가지이며, createDictPatient는 원시 position 필드를 변환 없이 읽는다. 계측 성분의 부호는 여기서 바로 결정된다(§5.1). 모듈 안에서 RAS↔LPS 뒤집기는 saveAdjustedRegistration()(수동 검토)과 segmentation_logic의 VTK 내보내기(기록 전 Scale(-1,-1,1))에만 있다.

4.1 ALI-CBCT

신경망 강화학습 에이전트, monai DenseNet.

강화학습 에이전트: 랜드마크마다 에이전트 하나가 agent_FOV = [64,64,64] 이웃 안에서 움직이며, 스케일은 spacing = [1, 0.3] mm 두 단계, speed_per_scale = [1,1], spawn_radius = 10이다. 가능한 이동은 여섯 가지 (MOVEMENT_MATRIX_6, constants.py:22). 출력: .mrk.json 하나를 해부학적 그룹(CB, U, L, CI)마다 만들며, 이름은 <scan>_lm_Pred_<group>.mrk.json.

계측용으로 요청하는 랜드마크는 중복 제거된 합집합, 즉 MAND 목록과 CB 목록의 Point 1 / Point 2 / Line 열을 합친 것이다 (createlistprocess.py:141). dict.fromkeys 덕분에 두 목록에 공통인 랜드마크가 에이전트를 두 번 띄우지 않는다.

4.2 AMASSS — 마스크

신경망 3D UNet.

호출은 두 번: CB 기준 정렬 스캔에 CBMASK,MANDMASK, MAX 기준 정렬 스캔에 MAXMASK. merge="SEPARATE", genVtk=False, prediction_ID="seg". 생성되는 이름: <base>_seg_<STRUCT>MASK.nii.gz (AMASSS_CLI.py:601). 이 마스크는 정합의 고정 영상을 마스킹하는 데만 쓰이며, 계측에는 쓰이지 않는다.

4.3 BDS / DentalSegmentator — 표면

신경망 nnU-Net 3d_fullres.

run_bds는 run_dental_segmentation(model="DentalSegmentator", device="cuda", export_formats = VTK | VTK_MERGED)를 호출한다. nnU-Net은 5클래스 레이블 맵(Upper Skull, Mandible, Upper Teeth, Lower Teeth, Mandibular canal, segmentation_logic.py:600)을 만들고, 이것이 표면으로 변환된다:

  • _exportMergedVTK: vtkDiscreteMarchingCubes(존재하는 레이블 값마다 윤곽 하나, 값이 아니라 위치로 인덱싱 — 코드의 주석이 수정된 버그를 설명한다), vtkWindowedSincPolyDataFilter 60회 반복, passband 0.05, 셀 단위 법선, 레이블마다 vtkQuadricDecimation 0.4, 그리고 기록 전 IJK→RAS→LPS;
  • _exportVTKPerLabel: 각 세그먼트의 "Closed surface" 표현에 같은 처리를 적용해 구조마다 파일 하나.

가중치는 저장소에 없다. dataset.json과 plans.json만 버전 관리되며, PythonDependencyChecker는 Dataset111_453CT/nnUNetTrainer__nnUNetPlans__3d_fullres/fold_0/checkpoint_final.pth의 존재를 확인한 뒤 download_info.json의 URL을 다운로드한다 (~220 MB). 제공되는 다른 모델 세 개(PediatricDentalsegmentator, NasoMaxillaDentSeg, UniversalLabDentalsegmentator)는 다운로드 코드는 있지만 VFACE가 한 번도 선택하지 않는다. 여기서는 사용되지 않는 코드이며, 게다가 이들의 Path(__file__).parent/"Resources" 경로는 한 단계 어긋나 있다(VFACE_utils/Resources/...). 기본 모델의 경로는 수정되어 있다(segmentation_logic.py:457).

4.4 정합 — AREG-CBCT

계산 Elastix, 학습 없음.

VoxelBasedRegistration은 T1을 해당 AMASSS 마스크로 마스킹한 뒤 강체 Elastix를 실행한다(make_rigid_param_map_deterministic, utils.py:527): 해상도 3단계, 피라미드 8,8 4,4 2,2, AdvancedMattesMutualInformation 64 bins, ConjugateGradient 1500회 반복, ImageSampler = Grid, NumberOfThreads = 1(결정론성). 학습 없음.

출력: Registered Scan/<Cranial Base|Maxilla|Mandible>/<pat>_OutReg/ 안에 <pat>_<CB|MAX|MAND>Scan_Reg.nii.gz와 <pat>_<CB|MAX|MAND>_Reg_matrix.tfm.

함정

취약한 세부 사항: 마스크는 파일 이름의 키워드로 선택되며 (CB→["cb"], MAND→["mand","md"], MAX→["max","mx"]) 처음 찾은 것이 이긴다(utils.py:160). 그런데 <pat>_CB_Or_seg_MANDMASK.nii.gz에도 "cb"가 들어 있다. 두개저 정합이 하악골 마스크로 마스킹되지 않는 것은 알파벳 순서 (CBMASK < MANDMASK) 덕분일 뿐이다. 이름을 조금만 바꿔도 깨진다.

5. 알고리즘의 핵심 — 계측

5.1 계측 유형 여덟 가지

모두 AQ3DCLogic.createMeasurement (functionaq3dc.py:1995)가 xlsx의 Type of measurement 열로부터 생성한다. 매칭은 문자열 완전 일치다. 위치는 LPS 기준이다(x = 왼쪽, y = 뒤쪽, z = 위쪽).

유형 (정확한 문자열)입력공식 (Measure.py)
Distance between 2 points T1 / T2같은 시점의 P1, P2d = p2 − p1; (lr, ap, si) = (−dx, −dy, dz); 3D = ‖d‖; 소수점 셋째 자리로 반올림
Distance between 2 points T1 T2P1 @T1, P2 @T2동일하지만 두 점 집합 사이에서 교차한다. 이것이 비대칭 계측이다
Distance point line T1 / T2P, 선 (L1, L2)d = reject(P − L2, L1 − L2) = 선에 직교하는 성분. L1 ≈ L2(atol=1e-5)이면 d = P − L1
Distance point line T1 T2계측 두 개Diff2Measure: T2의 lr/ap/si 빼기 T1의 값. 3D는 ‖(lr,ap,si)‖로 다시 계산
Angle between 2 lines T1 / T2같은 시점의 선 2개아래 참고
Angle between 2 lines T1 T2T1 선 2개, T2 선 2개성분별 Diff2Measure
Angle line T1 and line T2선 @T1, 선 @T2같은 각도 계산이며, 선이 서로 다른 시점에서 온다

각도 공식 (Angle.__computeAngles, Measure.py:664). u = p2 − p1, v = p4 − p3. 각 축 a([2, 0, 1] 순서)에 대해 — 각각 yaw (축면), pitch (시상면), roll (관상면):

  1. 성분 a를 버리고(2D 투영) 정규화한다;
  2. θ = degrees(arctan2(‖u × v‖, u · v));
  3. p2 == p3이면(두 선이 꼭짓점을 공유): θ ← 180 − θ — 이로써 RCo-RGo / RGo-Me가 해부학적 하악각(gonial angle)이 된다;
  4. 부호: z = u_x·v_y − u_y·v_x. yaw 축에서는 부호가 z를 따르고, pitch와 roll에서는 반전된다.

complement_checkbox 블록(180° 보각)은 주석 처리되어 있다: Measure.py:679.

성분의 의미. manageMeaningComponent()가 레이블을 채운다 (골격 계측은 R/L, A/P, S/I, 치아는 M/D, B/L, E/I, T1↔T2 각도는 ClockWise/CounterC). 반환되는 *_Component 값은 절댓값이며, 레이블로부터 부호를 되돌려 주는 것은 reorganizeStat (createlistprocess.py:1597)이다.

함정

여기에는 서로 반대인 두 규약이 공존한다. 골격 선에서는 Vertical = −|si|가 방향이 S(위쪽)일 때 적용되는 반면, 치아 선에서는 Vertical = −|si|가 방향이 I일 때 적용된다. 이 열들을 재사용하기 전에 확인할 필요가 있다. Angle between 2 lines T1 각도는 manageMeaningComponent의 어떤 분기에도 해당하지 않는다(치아도, T1↔T2도 아님). 레이블은 비어 있고 값은 부호가 없는 채로 남는다.

5.4 reorganizeStat, 이어서 postprocess — 계측에서 특징으로

CB_LPF_RPF/RPF_LPF_Roll

세 가지 성격, 세 가지 동작:

  • VIEW: 불러와 표시하며, 아무것도 다시 쓰지 않는다.
  • LANDMARKS: loadEditableMarkups가 노드와 모든 점에 SetLocked(False)를 강제하고, 표시를 보이게 한다 — ALI는 점을 잠긴 상태, 숨긴 상태로 기록하기 때문이다. 시작 위치가 기록되며, Continue 시 savePauseEdits는 점이 하나 이상 움직인 파일만 다시 쓴다(VFACE.py:2095).
  • REGISTRATION: setUpAdjustment가 정합된 스캔을 T1 위에 반투명으로 겹쳐 놓고, 상호작용 핸들이 달린 vtkMRMLLinearTransformNode에 연결한다. Continue 시 saveAdjustedRegistration (VFACE.py:2126)이 RAS 변위를 LPS로 변환하고 (flip = diag(-1,-1,1), lps = flip @ ras @ flip) AREG 자체의 .tfm에 합성한다: sitk.CompositeTransform([areg, nudge.GetInverse()]). 하류의 AutoMatrix가 행렬을 하나만 적용할 수 있기 때문이다. 이어서 보정된 볼륨을 harden하고 다시 기록한다.

계획에는 중요한 순서 제약이 두 가지 있다. 정량화 블록은 시각화 블록 앞에 놓인다. 그래야 유일하게 쓸모 있는 편집 가능 일시 정지(t1_landmarks)가 nnU-Net 분할 다섯 번 뒤에 오지 않는다. 그리고 enterPauseForReview는 아무것도 직접 불러오지 않는다. QTimer.singleShot(0, self.beginReview)를 걸어 둘 뿐이다. 이 호출은 VTK 옵저버 콜백 안에서 일어나는데, 거기서는 Qt 이벤트 루프가 돌고 있지 않으며 볼륨을 불러오면 읽는 쪽이 없는 Slicer의 stdout 파이프가 가득 차 버린다( _briefCliOutput, outputToFile과 같은 계열의 버그).

buildPauseQueue (VFACE.py:1713)는 찾은 파일을 날짜가 아니라 환자 식별자로 거른다. 재사용한 출력 폴더에는 이전 실행의 환자들이 들어 있기 때문이다. belongsToRun은 기대한 id를 _ 경계에서 확장한 id도 받아들인다(히트맵은 C_0001_Mandible_ModelDistance 형태로 나온다). 파일이 있었는데도 필터가 검토 대상을 모두 비워 버리면, 요청된 일시 정지를 건너뛰는 대신 필터가 해제된다.

7.2 일괄 탐색: 있는 것

확인됨

예전 프로젝트 노트의 내용과 달리, AREG로부터의 이식은 완료되었다(2609bc4, 브랜치 vface-review-rebuild).

  • Previous patient / Next patient (VFACE.py:2324). 환자를 바꾸기 전에 현재 편집을 저장한다;
  • 환자 이름과 i / n 위치가 reviewPatientLabel에 표시된다;
  • 플래그 지정: onReviewToggleFlag가 현재 환자를 self.review_flagged에 표시한다;
  • 선택적 되돌리기: onReviewGoBack (VFACE.py:2351)은 가장 가까운 수정 가능 단계까지 거슬러 올라가고(previousCorrectableStep, LANDMARKS 또는 REGISTRATION에서만 멈춤), 중간 단계들을 list_process 앞쪽에 다시 넣은 뒤, 플래그된 환자에게만 한정한다. 이때 restrictStepToPatients를 쓴다 — 심볼릭 링크로 된 임시 폴더 (대체 수단은 shutil.copy), 트리 구조는 보존된다;
  • review_flagged_carry는 다시 실행한 환자 목록을 다음 검토 대기열 구성에 넘겨, 나머지 환자는 이미 승인된 결과를 유지하게 한다;
  • clearReviewTempFolders는 실행이 끝나면 링크 폴더를 정리한다.

Continue 버튼의 이름은 Next step이다. 환자 사이를 이동하는 것과 실행을 진행하는 것은 별개의 동작이다.

7.3 일괄 탐색: 정말로 빠진 것

빈틈은 INPUT_KEYS에 있다 (review_steps.py:162):

INPUT_KEYS = ("input", "input_patient", "input_matrix")
확인된 버그

한정할 수 있는 것은 ALI, PRE_ASO, SEMI_ASO(input)와 AutoMatrix(input_patient, input_matrix)뿐이다. VFACE 파이프라인에 빠진 것: inputVolume (AMASSS), t1_folder / t2_folder / mask_folder_t1 (AREG), input_folder_CBCT (resample), input_path (BDS), t1_path / t2_path (AQ3DC), t1_dir / t2_dir (히트맵), source_folder 등 (derive_landmarks). 반면 AREG는 inputVolume, t1_folder, t2_folder, T1, T2, IOS_folder, CBCT_folder, input_folder_CBCT를 다룬다 (Review.py:717).

구체적인 결과:

  • t1_masks에서 되돌리기 → ASO는 플래그된 환자 한 명에 대해서만 다시 실행되지만, AMASSS 두 번은 일괄 전체에 대해 다시 시작된다(가장 느린 단계);
  • registration_max 또는 _mand에서 되돌리기 → Elastix 정합이 일괄 전체에 대해 다시 실행된다;
  • bone_surfaces에서 되돌리기 → BDS 다섯 번이 모두 일괄 전체에 대해 다시 시작된다.

이를 "고치기" 전에 알아 둘 점: AQ3DC / postprocess / 분류를 한정하면 해롭다. 이 단계들은 처음부터 다시 만드는 집계 xlsx를 쓰므로, 한정하면 플래그되지 않은 환자들의 행이 지워진다. 올바른 수정은 볼륨/스캔 키를 추가하는 것이지, 모든 폴더 키를 추가하는 것이 아니다.

그보다 덜한 한계 두 가지:

  • previousCorrectableStep은 executed_steps에서 현재 단계를 동일성(identity)으로 찾는다. 첫 번째 되돌리기 뒤에는 이력에 원래 단계와 한정된 사본이 함께 있으므로, 두 번째 되돌리기는 필요 이상으로 긴 목록을 다시 실행한다;
  • 표시되는 카운터(Paused at step N/M)는 되돌리기로 되감기지 않는다. NumberProcess는 늘고, ActualProcess는 줄지 않는다.

VFACE에는 AREG의 _normalisedId / _matchAcrossNaming (P1 ↔ P_0001 짝짓기)에 해당하는 것도 없지만, 문제가 되지 않는다. 모달리티가 하나뿐이기 때문이다.

VTK Files/{T1 CB,T1 MAX,T2 CB,T2 MAND,T2 MAX}BDS 표면, LPSVisualization이면 예

히트맵 (batch_process, createlistprocess.py:2219)은 T1 표면과 짝지어진 T2 표면 사이의 부호 있는 vtkDistancePolyDataFilter 결과이며, 세 영역(merged CB, Mandible, Upper_Skull)에 대해 계산한다. 각 쌍은 별도의 프로세스(_batch_worker.py)에서 실행된다. VTK 필터가 C++ 쪽에 할당하는 locator를 gc.collect()가 해제하지 못하기 때문이다. 워커는 최대 min(4, cpu_count // 2)개까지 병렬로 돌고, 타임아웃은 600 s, stdout/stderr는 파일로 보낸다(파이프는 절대 쓰지 않는다 — 출력이 많은 워커가 막혀 버린다). 누적 점이 1M을 넘으면 워커는 0.5로, 2M을 넘으면 0.7로 decimation한 뒤, decimation된 메시에서 거리를 계산하고 원래 메시에 다시 보간한다(vtkPointLocator 사용). 출력 배열의 이름은 Distance다.

정리, 그리고 그 함정. OnEndProcess (VFACE.py:2766)는 "Keep Intermediate files"가 체크되어 있지 않으면 모든 하위 폴더를 삭제한다(OutputFolder 안에서 위 목록만 제외). 여기서 버그 두 개가 수정되었으며, 알아 둘 가치가 있다:

output = (self._parameterNode.OutputFolder or "").strip()
if not output or not os.path.isabs(output) or not os.path.isdir(output):

Path("")는 Path(".")와 같고, 그러면 iterdir()가 Slicer의 현재 작업 디렉터리를 순회한다. 출력 폴더를 지정하지 않은 실행은 작업 디렉터리 트리의 하위 폴더를 모두 지워 버렸을 것이다. 또 검사 코드는 "Quantification"을 확인했는데 메뉴에는 "Quantitative"라고 되어 있어서, 정리 과정이 Measurements와 Classification — 결과물 그 자체 — 을 지웠을 것이다. 출력 폴더 최상위의 파일은 결코 삭제되지 않는다(item.is_dir()만 처리한다).

10. 함정과 취약 지점

  • derive_landmarks는 "Full pipeline" 밖에서는 동작할 수 없다. "File already Oriented" / "already Registered" 모드에서 SplitOriented (createlistprocess.py:1877)는 .nii* / .nrrd* 파일만 Oriented T1 Scans/에 복사하고, .tfm 파일은 복사하지 않는다. 그러면 "Deriving T1 Landmarks (MAX)" 단계가 환자마다 missing an orientation transform을 기록하고, T1 Landmarks/MAX는 비어 있으며, Measurements_MAX.xlsx도 비고, 분류에서 특징 14개 중 5개가 빠진다.
  • CMFReg는 정합을 바꾸지 않는다. 아무도 읽지 않는 T2_Masks 폴더를 추가할 뿐이다(§1).
  • 하드코딩된 _T1/_T2 접미사. TIMEPOINT-SUFFIX로 표시된 사본 세 개가 createlistprocess에 있다. _T3는 짝짓기를 조용히 깨뜨린다. 참조 노트는 GetPatients 위, AREG_CBCT/AREG_CBCT_utils/utils.py:70에 있다.
  • 키워드 기반 마스크 선택: CBMASK가 MANDMASK를 이기는 것은 알파벳 순서 덕분일 뿐이다(§4.4).
  • _index_measurements는 반복되는 랜드마크 레이블에 대해 첫 행만 유지한다. 같은 점 쌍에 대한 서로 다른 유형의 계측 두 개 (예: T1에서와 T1↔T2에서의 B/B)는 서로를 가린다.
  • writeMeasurementExcel은 index=False 없이 기록한다: xlsx 파일에 불필요한 Unnamed: 0 열이 생긴다.
  • 계측 목록은 파일 이름으로 매칭된다(이름에 대문자 CB, MAND, MAX, FEAT). 파일 이름이 MAX_and_MAND.xlsx라면 먼저 일치하는 분기로 들어간다.
  • Python 단계는 인터페이스를 멈춘다. 스레드가 없다. startPythonProcess는 함수를 직접 호출하며, fd 1과 2를 임시 파일로 리다이렉트한다 (outputToFile, VFACE.py:2537) — torch와 nnU-Net은 C에서 출력하므로 sys.stdout을 바꾸는 것만으로는 부족하다.
  • spacing 파라미터는 Python 리스트로 전달된다([0.3,0.3,0.3]). XML에서는 <string>으로 선언된 파라미터이고, CLI는 spacing.split(",")을 한다. Slicer의 직렬화 덕분에 동작하며 MRI2CBCT도 같은 방식이지만, 암묵적이다.
  • 눈에 띄는 사용되지 않는 코드: AQ3DCWidget 위젯 전체( functionaq3dc.py의 ~1200줄, 테스트 밖에서는 한 번도 인스턴스화되지 않음); Measure.isUtilMeasure(호출이 주석 처리됨, functionaq3dc.py:2182); check_skeletal와 SKELETAL_LM_RL( Measure.py); GetDictPatients / GetMatrixPatients; 계산만 되고 쓰이지 않는 T1/T2 변수(reorganizeStat); QCheckBox로 하는 keep_sign 초기화(run_aq3dc. 값은 이미 True이며 None인 적이 없다); VFACELogic.process, VFACETest, registerSampleData(Slicer 템플릿의 상용구 코드, VFACE1/VFACE2 URL은 일반 테스트 데이터를 가리킨다); segmentation_logic.py의 대체 분할 모델 세 개.
  • "Test Files" 버튼은 AREG의 아카이브 (Or_FullyAuto.zip)를 다운로드하고, 그 T2를 삭제한 뒤(VFACE는 자체 T2를 만든다) 입력을 T1로 지정한다. VFACE 전용 테스트 아카이브는 없다.

11. 문헌

대응하는 발표 논문은 "Automated classification of skeletal facial asymmetry in CBCT using a reproducible 3D Slicer workflow for patient-specific decision support", SPIE Medical Imaging 2026, vol. 13929, art. 139292J, doi:10.1117/12.3087010 (SPIE 페이지)이다. 공개 초록은 Class III 환자 170명과 같은 상류 처리 사슬을 설명한다: 표준화된 전처리, 미러링, 복셀 정합, 해부학적 계측값 추출.

코드 / 논문 불일치

코드는 마지막 단계에서 논문과 갈라진다. 초록은 비지도 접근법 — 차원 축소(PCA, t-SNE, UMAP) 후 Spectral Clustering, 실루엣 점수는 UMAP+RBF가 가장 좋음 — 을 설명한다. 반면 모듈에는 고정된 14개 특징으로 학습된 지도 학습 이진 LightGBM 분류기 세 개가 들어 있다. 둘은 같은 모델이 아니다. 저장소의 어떤 것도 LightGBM의 학습 레이블과 논문의 군집을 연결하지 않으며, 학습 스크립트는 버전 관리되어 있지 않다.

상류 구성 요소에 대해서는 각 모듈의 참고문헌을 따른다:

  • AMASSS / ALI-CBCT — Automated Orientation and Registration of CBCT Scans (LNCS)
  • SlicerDentalSegmentator (Dataset111_453CT 가중치)
  • SlicerAutomatedDentalTools

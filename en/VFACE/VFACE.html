VFACE

An orchestrator that learns and segments nothing itself: it chains six other modules to register a CBCT onto its own mirror image, measures the gap, and classifies skeletal facial asymmetry with three LightGBM models.

SPIE Medical Imaging 2026 vface_cli conda env: none (Slicer's Python) Bibliography

Automatic classification of skeletal facial asymmetry on CBCT. VFACE learns nothing and segments nothing itself: it is an orchestrator that chains six other modules from the repository, extracts linear and angular measurements from them, and finishes with three LightGBM classifiers. It is the highest-level module in the chain — the call tree is the central piece of information here.

The clinical principle fits in one sentence: T2 is the patient's own mirror image. There is no second scan. The scan is oriented, mirrored across the mid-sagittal plane, registered onto the original, and everything that gets measured is a gap between the patient and their own reflection.

1. Where it sits in the pipeline

Nothing in the repository calls VFACE: CMakeLists.txt:54 adds it as a terminal module. It does, however, call eight processes, seven of which are other modules of the extension. Everything is built in a single pass by CreateListProcess() (createlistprocess.py:117), which returns a list of dictionaries {Process, Parameter, Module, Display, Review*}; the widget unwinds it one item at a time.

3. Inputs and preprocessing

Input: a folder of T1 CBCTs, one per patient (.nii, .nii.gz, .nrrd, .nrrd.gz, .gipl, .gipl.gz). No segmentation, no landmark: VFACE starts from the raw volume. checkInputFolder() (VFACE.py:1221) refuses to start on an empty folder.

Patient identity: patientIdFromFileName (functionaq3dc.py:1369) cuts the name on _Scan, _Or, _MAND, _MD, _MAX, _MX, _CB, _lm, _T2, _T1, _Cl, .. The same chain is duplicated three times in createlistprocess (marked TIMEPOINT-SUFFIX): only _T1/_T2 are recognized, a _T3 silently breaks the pairing.

Resampling: spacing [0.3, 0.3, 0.3], resample_size = "None", center = "True" — the volume's own size is kept, only the spacing changes. Output in <out>/T1 Resample/CBCT.

Centering (pre_aso_cbct, model_folder=False): purely geometric, translation of the volume's center to the origin, plus a .tfm written alongside (PRE_ASO_CBCT.py:217). No network is involved here.

Orientation: two distinct frames, built on the same centered scan.

FrameLandmarks requested from ALIGold standardSuffix
MAXANS, IF, PNS, UL6O, UR1O, UR6OOcclusal and Midsagittal Plane_MAX_Or
CBBa, LPo, N, RPo, S, LOr, ROrFrankfurt Horizontal and Midsagittal Plane_CB_Or

semi_aso_cbct does a 3-landmark init then a rigid vtkIterativeClosestPointTransform (1000 iterations, StartByMatchingCentroidsOn) of the patient's landmarks onto the gold's (utils.py:620), and writes <pat>_<suffix>_transform.tfm = the inverse of (ASO ∘ centering). After that, the mid-sagittal plane sits at x = 0, which is the condition for the mirror to be valid.

The mirror. Matrix_mirror.tfm (shipped with the AutoMatrixMirror release) is an AffineTransform with parameters -1 0 0 0 1 0 0 0 1, zero translation: a pure reflection along the x axis in LPS, i.e. symmetry relative to the mid-sagittal plane. AutoMatrix applies it to volumes via sitk.ResampleImageFilter and to .mrk.json files via transform.GetInverse().TransformPoint (Automatrix_CLI.py:171).

Coordinate system: everything is in LPS. ALI writes "coordinateSystem": "LPS" (io.py:36), so does derive_landmarks, and createDictPatient reads the raw position field with no conversion. The signs of the measurement components follow directly from this (§5.1). The module's only RAS↔LPS flips are in saveAdjustedRegistration() (manual review) and in the VTK exports of segmentation_logic (Scale(-1,-1,1) before writing).

4.1 ALI-CBCT

network reinforcement learning agents, monai DenseNet.

Reinforcement learning agents: one agent per landmark, moving within a neighborhood of agent_FOV = [64,64,64], two scales spacing = [1, 0.3] mm, speed_per_scale = [1,1], spawn_radius = 10. Six possible moves (MOVEMENT_MATRIX_6, constants.py:22). Output: one .mrk.json per anatomical group (CB, U, L, CI), named <scan>_lm_Pred_<group>.mrk.json.

The landmarks requested for the measurements are the deduplicated union of the Point 1 / Point 2 / Line columns of the MAND and CB lists (createlistprocess.py:141) — dict.fromkeys keeps a landmark shared by both from triggering two agents.

4.2 AMASSS — the masks

network 3D UNet.

Two calls: CBMASK,MANDMASK on the CB-oriented scan, MAXMASK on the MAX-oriented scan, merge="SEPARATE", genVtk=False, prediction_ID="seg". Names produced: <base>_seg_<STRUCT>MASK.nii.gz (AMASSS_CLI.py:601). These masks are only used to mask the fixed image of the registration, not to measure anything.

4.3 BDS / DentalSegmentator — the surfaces

network nnU-Net 3d_fullres.

run_bds calls run_dental_segmentation(model="DentalSegmentator", device="cuda", export_formats = VTK | VTK_MERGED). nnU-Net produces a 5-class label map (Upper Skull, Mandible, Upper Teeth, Lower Teeth, Mandibular canal, segmentation_logic.py:600), converted into surfaces:

  • _exportMergedVTK: vtkDiscreteMarchingCubes (one contour per present label value, indexed by position rather than by value — the code's own comment explains the fixed bug), vtkWindowedSincPolyDataFilter 60 iterations, passband 0.05, per-cell normals, vtkQuadricDecimation 0.4 per label, then IJK→RAS→LPS before writing;
  • _exportVTKPerLabel: the same chain on the "Closed surface" representation of each segment, one file per structure.

The weights are not in the repository: only dataset.json and plans.json are versioned, and PythonDependencyChecker tests for the presence of Dataset111_453CT/nnUNetTrainer__nnUNetPlans__3d_fullres/fold_0/checkpoint_final.pth before downloading the URL from download_info.json (~220 MB). The three other models offered (PediatricDentalsegmentator, NasoMaxillaDentSeg, UniversalLabDentalsegmentator) have their download code but are never selected by VFACE: dead code here, and their Path(__file__).parent/"Resources" paths are, for that matter, off by one level (VFACE_utils/Resources/...), unlike the corrected path of the default model (segmentation_logic.py:457).

4.4 The registration — AREG-CBCT

computed Elastix, no learning.

VoxelBasedRegistration masks T1 with the corresponding AMASSS mask then launches rigid Elastix (make_rigid_param_map_deterministic, utils.py:527): 3 resolutions, pyramid 8,8 4,4 2,2, AdvancedMattesMutualInformation 64 bins, ConjugateGradient 1500 iterations, ImageSampler = Grid, NumberOfThreads = 1 (determinism). No learning.

Outputs: Registered Scan/<Cranial Base|Maxilla|Mandible>/<pat>_OutReg/ containing <pat>_<CB|MAX|MAND>Scan_Reg.nii.gz and <pat>_<CB|MAX|MAND>_Reg_matrix.tfm.

Trap

Fragile detail: the mask is chosen by keyword in the file name (CB→["cb"], MAND→["mand","md"], MAX→["max","mx"]) and the first one found wins (utils.py:160). But <pat>_CB_Or_seg_MANDMASK.nii.gz also contains "cb". It is only alphabetical order (CBMASK < MANDMASK) that keeps the cranial-base registration from being masked by the mandible. Any renaming breaks this.

5. The algorithmic core — the measurements

5.1 The eight measurement types

All instantiated by AQ3DCLogic.createMeasurement (functionaq3dc.py:1995), from the Type of measurement column of the xlsx — matched by exact string equality. Positions are in LPS (x = left, y = posterior, z = superior).

Type (exact string)InputsFormula (Measure.py)
Distance between 2 points T1 / T2P1, P2 at the same time pointd = p2 − p1; (lr, ap, si) = (−dx, −dy, dz); 3D = ‖d‖; rounded to 3 decimals
Distance between 2 points T1 T2P1 @T1, P2 @T2identical, but crossed between the two point sets: this is the asymmetry measurement
Distance point line T1 / T2P, line (L1, L2)d = reject(P − L2, L1 − L2) = the component orthogonal to the line; if L1 ≈ L2 (atol=1e-5), d = P − L1
Distance point line T1 T2two measurementsDiff2Measure: lr/ap/si of T2 minus those of T1; 3D recomputed as ‖(lr,ap,si)‖
Angle between 2 lines T1 / T22 lines, same time pointsee below
Angle between 2 lines T1 T22 T1 lines, 2 T2 linesDiff2Measure component by component
Angle line T1 and line T2line @T1, line @T2the same angle computation, lines coming from different time points

Angle formula (Angle.__computeAngles, Measure.py:664). u = p2 − p1, v = p4 − p3. For each axis a of [2, 0, 1] — respectively yaw (axial plane), pitch (sagittal plane), roll (coronal plane):

  1. drop component a (2D projection), normalize;
  2. θ = degrees(arctan2(‖u × v‖, u · v));
  3. if p2 == p3 (the two lines share their vertex): θ ← 180 − θ — this is what turns RCo-RGo / RGo-Me into an anatomical gonial angle;
  4. sign: z = u_x·v_y − u_y·v_x; for the yaw axis the sign follows z, for pitch and roll it is flipped.

The complement_checkbox block (complement to 180°) is commented out: Measure.py:679.

Component meaning. manageMeaningComponent() fills in labels (R/L, A/P, S/I for skeletal measurements; M/D, B/L, E/I for teeth; ClockWise/CounterC for T1↔T2 angles). The returned *_Component values are absolute values; it is reorganizeStat (createlistprocess.py:1597) that gives them back a sign from the label.

Trap

Two opposite conventions coexist here: for a skeletal line Vertical = −|si| when the direction is S (superior), whereas for a dental line Vertical = −|si| when the direction is I. Worth checking before reusing these columns. An Angle between 2 lines T1 angle falls into no branch of manageMeaningComponent (neither dental, nor T1↔T2): its labels stay empty and its value stays unsigned.

Outside the repository, downloaded by the Default button into <Documents>/SlicerDownloads/V_FACE/DefaultList. The file name decides its role (SplitMeasurements, createlistprocess.py:1829): CB/CRANIAL, MAND/MANDIBLE, MAX/MAXILLA, FEAT/FEATURE.

CB's 16 T1↔T2 distances (= direct asymmetry): RFZyg/LFZyg, ROr/LOr, A/A, ANS/ANS, IF/IF, RInfOr/LInfOr, RMZyg/LMZyg, RPF/LPF, UR6MB/UL6MB, B/B, Pog/Pog, Me/Me, RGo/LGo, RCo/LCo, RAF/LAF, LR6MB/LL6MB. Note the pattern: a midline point is compared to itself in the mirror (A/A, B/B, Me/Me), a lateral point is compared to its contralateral counterpart (RGo/LGo) since the mirror has swapped sides.

The 10 T1-only distances are classic anatomical lengths: RCo-Pog, LCo-Pog, RGo-Pog, LGo-Pog, RCo-RGo, LCo-LGo, RAF-RCo, LAF-LCo, UR6MB-LR6MB, UL6MB-LL6MB.

The 4 angles: RCo-RGo / RGo-Me and LCo-LGo / LGo-Me (gonial angles, T1 only, shared vertex hence complemented to 180°); LAF-RAF / RAF-LAF and LPF-RPF / RPF-LPF as Angle line T1 and line T2. Reversing the order of the points in the T2 line is deliberate: since the mirror has swapped left and right, writing RAF-LAF on the T2 side brings the two vectors back to being near-collinear, so the measured angle tends toward 0 for a symmetric patient.

create_list_landmark (createlistprocess.py:2054) does pd.read_excel(path) without sheet_name=None: only the first sheet is read. A landmark appearing only in the Angle between 2 lines sheet would never be requested from ALI. It does not show up with the default list because its 9 angle landmarks all also appear in the distances sheet.

5.3 derive_landmarks — MAX landmarks without a second ALI pass

createlistprocess.py:1428. ALI is only run once, in the CB frame. The landmarks in the MAX frame are obtained through rigid composition:

to_centred   = sitk.ReadTransform(<pat>_CB_Or_transform.tfm)
from_centred = sitk.ReadTransform(<pat>_MAX_Or_transform.tfm).GetInverse()
moved = from_centred.TransformPoint(to_centred.TransformPoint(p))

Both ASO .tfm files share the same centered scan as their reference, so centering cancels out and the composition is exact. Gain: a few minutes per patient, and a single manual editing point — correcting a landmark at the t1_landmarks pause automatically propagates to the MAX frame. Grouping into output files reuses ALI's GROUP_LABELS, read via ast.parse on constants.py to avoid importing torch (createlistprocess.py:1373).

5.4 reorganizeStat then postprocess — from measurement to feature

run_aq3dc produces one row per (patient × measurement) with 16 columns (R-L Component/Meaning, A-P, S-I, 3D Distance, Yaw, Pitch, Roll). reorganizeStat flattens this into signed columns Transverse, AP, Vertical, 3D, Yaw, Pitch, Roll, plus BL, MD, Rotation, Arch, Segment for dental lines. Columns that are entirely "x" are dropped, so Measurements_MAND.xlsx and Measurements_MAX.xlsx have no angular columns.

postprocess (createlistprocess.py:2540) takes the reverse path: it decodes each column name of features.xlsx to figure out which row of which xlsx to read.

CB_LPF_RPF/RPF_LPF_Roll
└┬┘ └──────┬────────┘└┬─┘
 │         │          └ component  ("RL"->Transverse, "IS"->Vertical, "AP", Pitch, Yaw, Roll)
 │         └ landmarks ("/" -> angle label "LPF-RPF / RPF-LPF")
 └ source file (CB, MAND, MAX)

When the remainder contains more than 2 segments, the feature is an average: CB_RAF_RCo_LAF_LCo_AP = the average of the AP components of RAF - RCo and LAF - LCo. Output: Measurements/PostProcess_Measurements.xlsx, one row per patient, empty Asymmetry/Mand/Max columns.

The model therefore rests, for ~90%, on two measurements: the transverse deviation of the chin (Me against its mirror) and the vertical difference between the two ramus branches.

Chaining the three models (classify_symmetry, VFACE_CLI.py:134):

  1. columns containing / are renamed by clean_name (/ → _), which makes CB_LAF_RAF/RAF_LAF_Yaw match the feature_name_ stored in the model, CB_LAF_RAF_RAF_LAF_Yaw;
  2. model_sym_asym.predict(df[feature_name_]) → Asymmetry ∈ {"Asymmetric" (class 0), "Symmetric" (class 1)};
  3. Mand and Max are initialized to "False", then only the asymmetric cases go through mand_asym (7 features, 5 of them from the CB block) and max_asym (7 features), each returning "True"/"False";
  4. the two sub-models are independent: both can be "True" (mandibular and maxillary asymmetry), neither is exclusive.

Output: Classification/Classification.xlsx = the features table augmented with the three columns. This is the final deliverable.

7.1 The pauses

Added by commit 2609bc4. A step in the plan can carry Review* keys; the widget stops at the end of the step, loads the results into the scene, and waits. The catalogue lives in review_steps.py, kept separate from the pipeline so the panel can list the pauses before CreateListProcess has even created a single folder.

Three natures, three behaviors:

  • VIEW: loaded and displayed, nothing is rewritten.
  • LANDMARKS: loadEditableMarkups forces SetLocked(False) on the node and on every point, and makes the display visible — ALI writes its points locked and hidden. The starting positions are recorded; at Continue, savePauseEdits only rewrites the files where at least one point has moved (VFACE.py:2095).
  • REGISTRATION: setUpAdjustment overlays the registered scan at half opacity onto T1, attaches it to a vtkMRMLLinearTransformNode with interaction handles. At Continue, saveAdjustedRegistration (VFACE.py:2126) converts the RAS displacement to LPS (flip = diag(-1,-1,1), lps = flip @ ras @ flip) and composes it into AREG's own .tfm: sitk.CompositeTransform([areg, nudge.GetInverse()]), because AutoMatrix downstream can only apply a single matrix. The corrected volume is then hardened and rewritten.

Two important ordering constraints in the plan: the quantification block is placed before the visualization block, so that the only useful editable pause (t1_landmarks) does not arrive after five nnU-Net segmentations; and enterPauseForReview loads nothing directly — it arms a QTimer.singleShot(0, self.beginReview), because this happens inside a VTK observer callback, where the Qt event loop is not running and where loading a volume would fill Slicer's stdout pipe with no reader (the same family of bug as _briefCliOutput and outputToFile).

buildPauseQueue (VFACE.py:1713) filters the files found by patient identity, never by date: a reused output folder contains the patients from earlier runs. belongsToRun accepts an id that extends an expected id at a _ boundary (heatmaps come out as C_0001_Mandible_ModelDistance). If the filter empties the review entirely while files did exist, it is disarmed rather than skipping a requested pause.

7.2 Batch navigation: what exists

Verified

Contrary to what an older project note states, the port from AREG has been done (2609bc4, branch vface-review-rebuild).

  • Previous patient / Next patient (VFACE.py:2324), which save the current edit before switching patients;
  • the patient's name and their i / n position in reviewPatientLabel;
  • flagging: onReviewToggleFlag marks the current patient in self.review_flagged;
  • selective rollback: onReviewGoBack (VFACE.py:2351) walks back to the nearest correctable step (previousCorrectableStep, which only stops on LANDMARKS or REGISTRATION), reinjects the intermediate steps at the head of list_process, and restricts them to the flagged patients via restrictStepToPatients — a temp folder of symbolic links (shutil.copy as fallback), tree structure preserved;
  • review_flagged_carry passes the list of replayed patients on to the next review queue build, so the others keep their accepted results;
  • clearReviewTempFolders cleans up the link folders at the end of the run.

The Continue button is named Next step: moving between patients and advancing the run are two distinct actions.

7.3 Batch navigation: what is genuinely missing

The gap is in INPUT_KEYS (review_steps.py:162):

INPUT_KEYS = ("input", "input_patient", "input_matrix")
Confirmed bug

Only ALI, PRE_ASO, SEMI_ASO (input) and AutoMatrix (input_patient, input_matrix) can be narrowed. Missing, for the VFACE pipeline: inputVolume (AMASSS), t1_folder / t2_folder / mask_folder_t1 (AREG), input_folder_CBCT (resample), input_path (BDS), t1_path / t2_path (AQ3DC), t1_dir / t2_dir (heatmaps), source_folder &co (derive_landmarks). AREG, for its part, covers inputVolume, t1_folder, t2_folder, T1, T2, IOS_folder, CBCT_folder, input_folder_CBCT (Review.py:717).

Concrete consequences:

  • rollback from t1_masks → ASO is replayed for the single flagged patient, but both AMASSS runs start over on the whole batch (the slowest step);
  • rollback from registration_max or _mand → the Elastix registration is replayed for the whole batch;
  • rollback from bone_surfaces → all five BDS runs start over on the whole batch.

Worth noting before "fixing" this: narrowing AQ3DC / postprocess / the classification would be harmful, because these steps write an aggregated xlsx rebuilt from scratch — restricting them would erase the rows of the unflagged patients. The proper fix is to add the volume/scan keys, not every folder key.

Two other, lesser limits:

  • previousCorrectableStep looks up the current step in executed_steps by identity; after a first rollback, the history holds both the original steps and their narrowed copies, and a second rollback replays a list longer than needed;
  • the displayed counter (Paused at step N/M) is not rewound by a rollback: NumberProcess increases, ActualProcess does not go back down.

VFACE also lacks the equivalent of AREG's _normalisedId / _matchAcrossNaming (pairing P1 ↔ P_0001), but this does not matter to it: it only has one modality.

The heatmaps (batch_process, createlistprocess.py:2219) are signed vtkDistancePolyDataFilter results between the T1 surface and the paired T2 surface, over three zones (merged CB, Mandible, Upper_Skull). Each pair runs in its own process (_batch_worker.py) because the VTK filter allocates locators on the C++ side that gc.collect() does not free; up to min(4, cpu_count // 2) workers in parallel, 600 s timeout, stdout/stderr sent to files (never pipes — a chatty worker would block). Beyond 1M cumulative points the worker decimates to 0.5, beyond 2M to 0.7, computes the distance on the decimated meshes then reinterpolates onto the original mesh via vtkPointLocator. The output array is called Distance.

Cleanup, and its trap. OnEndProcess (VFACE.py:2766), if "Keep Intermediate files" is unchecked, deletes every subfolder of OutputFolder except the list above. Two bugs were fixed there and are worth knowing about:

Path("") equals Path("."), and iterdir() would then walk Slicer's current working directory: a run with no output folder set would wipe out the working directory tree of all its subfolders. And the test checked for "Quantification" while the menu says "Quantitative", so that cleanup would erase Measurements and Classification — the results themselves. Files at the root of the output folder are never deleted (only item.is_dir() is processed).

10. Traps and fragile spots

  • derive_landmarks cannot work outside "Full pipeline". In "File already Oriented" / "already Registered" mode, SplitOriented (createlistprocess.py:1877) only copies the .nii* / .nrrd* files into Oriented T1 Scans/, not the .tfm files. The "Deriving T1 Landmarks (MAX)" step then logs missing an orientation transform for every patient, T1 Landmarks/MAX stays empty, so does Measurements_MAX.xlsx, and the classification is missing five features out of fourteen.
  • CMFReg does not change the registration, it only adds a T2_Masks folder that nothing reads (§1).
  • Hardcoded _T1/_T2 suffixes, three copies marked TIMEPOINT-SUFFIX in createlistprocess. A _T3 silently breaks the pairing. The reference note sits above GetPatients in AREG_CBCT/AREG_CBCT_utils/utils.py:70.
  • Keyword-based mask selection: CBMASK only beats MANDMASK by alphabetical order (§4.4).
  • _index_measurements keeps the first row for a repeated landmark label. Two measurements of different types on the same pair of points (e.g. B/B in T1 and in T1↔T2) would shadow each other.
  • writeMeasurementExcel writes without index=False: the xlsx files carry a stray Unnamed: 0 column.
  • Measurement lists are matched by file name (CB, MAND, MAX, FEAT uppercase in the name). A file named MAX_and_MAND.xlsx would fall into whichever branch matches first.
  • The Python steps freeze the interface. No thread: startPythonProcess calls the function directly, with fd 1 and 2 redirected to a temporary file (outputToFile, VFACE.py:2537) — torch and nnU-Net write from C, where replacing sys.stdout would not be enough.
  • The spacing parameter is passed as a Python list ([0.3,0.3,0.3]) to a parameter declared <string> in the XML, and the CLI does spacing.split(","). It works because of Slicer's serialization, and MRI2CBCT does the same thing, but it is implicit.
  • Notable dead code: the whole AQ3DCWidget widget (~1200 lines of functionaq3dc.py, never instantiated outside tests); Measure.isUtilMeasure (the call is commented out, functionaq3dc.py:2182); check_skeletal and SKELETAL_LM_RL in Measure.py; GetDictPatients / GetMatrixPatients; the T1/T2 variables computed and never used in reorganizeStat; the QCheckBox initialization of keep_sign in run_aq3dc (the value is already True, never None); VFACELogic.process, VFACETest and registerSampleData (Slicer template boilerplate, the VFACE1/VFACE2 URLs point to generic test data); the three alternative segmentation models of segmentation_logic.py.
  • The "Test Files" button downloads AREG's archive (Or_FullyAuto.zip), deletes its T2 (VFACE builds its own) and points the input to the T1. There is no test archive of VFACE's own.

11. Literature

The corresponding published work is "Automated classification of skeletal facial asymmetry in CBCT using a reproducible 3D Slicer workflow for patient-specific decision support", SPIE Medical Imaging 2026, vol. 13929, art. 139292J, doi:10.1117/12.3087010 (SPIE page). The public abstract describes 170 Class III patients, and the same upstream chain: standardized preprocessing, mirroring, voxel registration, extraction of anatomical measurements.

Code / paper divergence

The code diverges from the paper at the last step. The abstract describes an unsupervised approach — dimensionality reduction (PCA, t-SNE, UMAP) then Spectral Clustering, with UMAP+RBF giving the best silhouette score. The module, on the other hand, ships three supervised binary LightGBM classifiers trained on 14 fixed features. The two are not the same model; nothing in the repository links the LightGBMs' training labels to the paper's clusters, and the training script is not versioned.

For the upstream building blocks, the references are those of their own modules:

  • AMASSS / ALI-CBCT — Automated Orientation and Registration of CBCT Scans (LNCS)
  • SlicerDentalSegmentator (Dataset111_453CT weights)
  • SlicerAutomatedDentalTools

Agent — sources

Unpublished. No paper covers this module or its approach. There is, however, an official record that had to be found: a NA-MIC project report.

The report describes the intent, not the state

A NA-MIC Project Week report (PW45, Boston, 2026) signed by its authors was retrieved here. It describes the module in its intent, not in its actual state — it announces llama3:latest where the code hardcodes qwen3:8b, and its "next step" (LLM integration, deployment inside Slicer) is already done in the repository. The other useful references are purely technical: the model served by Ollama, the preselection cross-encoder, and the dataset it comes from.

Neighborhood

None of the following works describe this module.

  • MS MARCO (Bajaj, retrieved): the reranker was trained to rank web passages for Bing queries. Here it is fed Slicer module cards and operator prompts — a domain and a register it was not trained for, and for which no evaluation exists in the repository.
  • Qwen3 (retrieved): the generic model's technical report. Neither the module's system prompt, nor its constrained JSON output format, nor its repair loop appear in it — and no temperature, seed, num_ctx, or think is passed by the code.
  • Ollama and llama.cpp, the server and inference engine actually used: no publication. ollama.com · github.com/ggml-org/llama.cpp.
  • Another agent, another project: Tu P., Dominguez M., Kikinis R., Pieper S., Kim S., Interactive Workflow Replay and Step-Back Navigation for Slicer Agent, 45th NA-MIC Project Week, Boston, 2026 (link). It covers puxuntu/Slicer_agent, an agent that generates and executes Python inside the Slicer scene — different code, a different team, presented at the same project week. Not to be confused with this module, which calls the extension's CLIs and writes no code.
  • LLM in this lab, different task: Gaydamour A. et al., Cevidanes L., AI-Driven Multimodal TMJ Patient Modeling: From Unstructured Notes to Precision Treatment, CLIP 2025, LNCS vol. 16126, p. 42-52 (10.1007/978-3-032-05479-1_5). BART and DeepSeek-R1 fine-tuned to extract 56 clinical indicators from patient notes. Unrelated to routing toward Slicer modules.

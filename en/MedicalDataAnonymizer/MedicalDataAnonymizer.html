MedicalDataAnonymizer

Detection and replacement of sensitive entities in text documents (DOCX, TXT, PDF, CSV, XML, ODT) via Microsoft Presidio, the module never touches a medical image: this is not a DICOM anonymiser. This page explains the pipeline step by step; the code details are on the code page.

unpublished no CLI (Slicer widget) UI thread, no conda Bibliography VISOR: local copy only Code (developers) Guide

This page describes the legacy Slicer module (SlicerAutomatedDentalTools at 3c67957, 2026-10-26). VISOR has no server tool for it: its client extension ships an older copy that runs inside Slicer and sends nothing, and that is not the de-identification of the files VISOR uploads, which is specified and not built (De-identification in VISOR). See the VISOR page for this module.

Overview: what goes in, what comes out

MedicalDataAnonymizer
Inputa folder of text documents (Word, text, PDF, CSV, XML, ODT), searched recursively
DetectionMicrosoft Presidio: a statistical English model for names, places and dates, and patterns with checksums for numbers, e-mails and similar identifiers
Replacementone of four methods: label, removal, hash or asterisks
Outputone rebuilt _anonymized document per input, all in one flat folder, plus file_mappings.csv

The module anonymises text only. It is a first pass over English free text, not a way to declare a dataset de-identified (section 7).

0. What the module is not

The name suggests a DICOM anonymiser. It is nothing of the sort, and the same holds for the copy in VISOR. Searching the whole module for “DICOM” or “deface” finds nothing, so:

  • no DICOM tag is read or changed: not the patient name or identifier, not the dates, not the institution, not the unique identifiers, not private tags;
  • no defacing is ever applied: the face that can be rebuilt from a CBCT or a scanner is untouched, and there is no defacing tool anywhere in the extension;
  • the supported formats cover none of the image or mesh formats, nor a landmark file.

Anyone deciding whether data can be shared should read section 7 first.

1. Position in the pipeline

An isolated tool with no command-line job: nothing calls it, it calls nothing. All the logic is in the widget, hence on Slicer’s main thread, so the interface freezes during processing and only the progress bar is refreshed.

In the codeThe single file, the empty logic class and the UI thread

2. Inputs: text extraction, format by format

The folder is walked recursively, ignoring Word lock files. Each file is reduced to one character string before analysis, and the output is rebuilt from that string. What was not extracted is neither analysed nor carried over: it disappears.

  • Word: the paragraphs. Tables, headers, footers, footnotes, text boxes, comments and metadata are lost.
  • Text: read as it is.
  • PDF: the text layer; a scanned PDF gives empty text.
  • CSV: each row is flattened into one line, so the column structure is lost.
  • XML: the text content only; tags and attributes are never read.
  • ODT: the paragraphs; tables, styles and metadata are lost.

Sensitive content in a part that was not extracted is not detected, but it does not reach the output either: there is no leak, but a silent loss of data. File metadata, such as a Word author, also disappears since the files are recreated.

In the codeThe format table with library calls and what each loses

3. The detection engine

No model is bundled; the module installs the English model of spaCy and builds the Presidio engines with their default settings at every click. Two families of recognisers work side by side.

The statistical one finds names, places and dates. The rule-based one finds phone numbers, e-mails, US social security, driver licence and bank numbers, medical licences, credit cards, IP addresses and URLs, from patterns, checksums and context words.

The language is locked to English: a folder of French notes goes through an English model, with the lower detection you would expect, and the module says nothing about it. A language detector is installed but never used (details).

In the codeThe two engine calls, the model download and the fixed language

4. Entities and replacement methods

Twelve entity types can be ticked and seven are ticked by default: names, phone numbers, e-mail addresses, dates and times, locations, social security numbers and medical licence numbers. The five others (driver licence, credit card, bank number, IP address, URL) are off. Names, dates and locations come from the statistical model (predicted); the others come from rules (computed).

The hash is a plain SHA-256 of the detected text. In Presidio 2.2.355 the same name always gives the same digest, which keeps things consistent, but without a salt or a key a hash over a space as small as names, birth dates or social security numbers can be reversed by trying every candidate. Treat it as a public pseudonym, not as protection. The module does not pin the Presidio version, and 2.2.366 salts each hashed span with 32 random bytes, so there the digests of one name differ from one occurrence to the next.

In the codeThe entity table with defaults and the operator configurations

5. Outputs and the mapping table

Everything is written flat into the output folder: sub-folders are not reproduced, and two files with the same name in different sub-folders make the second overwrite the first. Word, text and PDF files are rebuilt in their own format (the PDF in one unpaginated block), an ODT file becomes a text file, and an XML file becomes plain text under an .xml name.

The mapping table file_mappings.csv lists the original name, the produced name and a UUID per file. It is not a re-identification table: it holds no link between a detected name and its replacement, and the UUID is generated and then never used anywhere. It sits next to the anonymised documents, so sharing the output folder shares the list of original file names.

7. Limits: what is NOT removed

The most useful section for deciding whether a dataset can be shared.

  1. All images: nothing in an image file or header is read or changed.
  2. File and folder names: a patient’s name in a file name survives into the output name and into the mapping table, and the folder hierarchy is flattened.
  3. Hospital identifiers: record, accession and bed numbers have no recogniser.
  4. Anything not American: only US numbers are searched, not a French NIR, an NHS number or a passport.
  5. Indirect identifiers: ages over 89, rare dates, occupations; dates are replaced whole or not at all.
  6. The language: detection collapses on non-English text, with no warning.
  7. The 0.5 threshold drops less certain detections, but which detections that is depends on the recognisers: the spaCy name, place and date detections all get the same fixed score (0.85 by default in Presidio 2.2.355 and 2.2.366), so a 0.5 threshold does not separate rare names from common ones; it mostly acts on the pattern-based recognisers.
  8. Content that was not extracted: tables, attributes, scanned pages, headers.
  9. Silent failure, the most serious finding. If the analysis raises any error, the module writes an _anonymized file that contains the original text unchanged, reports “Complete!”, and leaves one red line in the Python console. Nothing counts the entities found or checks afterwards (details).

In practice the output is a first pass over English free text, to be reviewed, and it needs renaming of the files, a dedicated DICOM anonymiser for images, and defacing if a volume covers the face.

In the codeThe nine limits in full, with the code of the silent failure

8. Environment

Everything runs in Slicer’s Python, installed by one button without confirmation and with no pinned versions, followed by a download of the English spaCy model and a request to restart Slicer. No GPU, no conda, no command-line job; loading the engines takes a few seconds on the interface thread at every run. Warnings are switched off for the whole of Slicer as soon as the module loads.

9. Known problems

  • The silent failure that returns the original text (details).
  • The flat output folder overwrites same-named files without a message (all traps).
  • CSV files are restructured, XML degrades to plain text and ODT is renamed to text (all traps).
  • The UUID of the mapping table is generated and never applied (details).
  • Everything runs on the interface thread, so Slicer seems frozen on a large folder (all traps).
  • The README speaks of HIPAA compliance and AI-powered analysis where the code is a default Presidio call on English text (all traps).
  • The module has no tests and nothing callable by script (all traps).

10. Literature and references

No paper covers this module; nor is there an evaluation (recall, precision) in the repository, on any corpus.

The building blocks used are documented:

  • Microsoft Presidio: the detection and anonymisation engine, with the exact list of its predefined recognizers and operators (replace, redact, hash, mask, encrypt, the latter, reversible with a key, is not offered by the module).
  • spaCy en_core_web_lg: the English NER model used by default.
  • HIPAA Safe Harbor, 45 CFR §164.514(b)(2): the 18 categories of identifiers to remove. Useful as a reading grid for §7: file names, medical record identifiers, and image identifiers appear there, and this module does not handle them.

Full bibliography: SOURCES.html, search done, negative result on the module itself. The folder contains the only published evaluation of Presidio on unstructured clinical text, and links to the i2b2/n2c2 text de-identification campaigns, which do not describe this code but do provide its reading grid.

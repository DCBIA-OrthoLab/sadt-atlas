MedicalDataAnonymizer

Detection and replacement of sensitive entities in text documents (DOCX, TXT, PDF, CSV, XML, ODT) via Microsoft Presidio — the module never touches a medical image: this is not a DICOM anonymiser.

unpublished no CLI (Slicer widget) UI thread, no conda Bibliography
Vocabulary trap

The name suggests a DICOM anonymiser. It is nothing of the sort: MedicalDataAnonymizer de-identifies text documents via Presidio + spaCy. No DICOM tag (PatientName, PatientID, UID…) is read or modified, and no defacing is ever applied to an image — the extension as a whole contains no defacing tool at all.

0. What the module is not

The name suggests a DICOM anonymiser. It is nothing of the sort, and it can be checked with a single command:

$ grep -rin "dicom\|pydicom\|deface" Medical_Data_Anonymizer_Module/
(no result)
$ grep -rlni "deface" --include="*.py" --include="*.md" .
(no result anywhere in the repository)

Direct consequences:

  • no DICOM tag is ever erased or replaced: not PatientName (0010,0010), not PatientID (0010,0020), not PatientBirthDate, not StudyDate, not InstitutionName, not the UIDs, not the private tags, not BurnedInAnnotation;
  • no defacing: the reconstructible face in a CBCT or scanner is never altered, by any method (no facial mask, no blurring, no surface removal). There is no defacing tool anywhere in the whole extension;
  • the supported formats (.docx, .txt, .pdf, .csv, .xml, .odt, Medical_Data_Anonymizer_Module.py:506) cover none of .dcm, .nii.gz, .nrrd, .vtk, or a landmarks .json.

An operator deciding whether data can be shared should read §7 directly.

1. Position in the pipeline

An isolated tool, without a CLI. Nothing calls it, and it calls nothing else in the repository. Everything lives in a single 767-line file, ~350 of which are Qt stylesheets: Medical_Data_Anonymizer_Module.py.

Medical_Data_Anonymizer_ModuleLogic and …Test are empty classes (pass): all the logic lives in the widget, hence on Slicer's main thread — the interface freezes during processing, only slicer.app.processEvents() refreshes the progress bar.

2. Inputs: text extraction, format by format

Recursive walk of the input folder (os.walk); files starting with ~$ (Word lock files) are ignored. Each file is reduced to a single character string before analysis:

FormatExtractionWhat is lost along the way
.docxpython-docx, "\n".join(p.text for p in doc.paragraphs)tables, headers/footers, footnotes, text boxes, comments, file metadata
.txtraw UTF-8 read—
.pdfpdfplumber, page.extract_text(); on exception, a second attempt via extract_tables()images, scanned PDFs (no OCR) → empty text
.csvcsv.reader, each row flattened by " ".join(row)the column structure
.xmlElementTree + recursive extract_text_from_xml() (text + tail)tags and attributes: attribute values are never read
.odtodfpy, text nodes of text.Ptables, styles, metadata

The loss is not just a matter of fidelity: the output documents are rebuilt from this string. What wasn't extracted isn't anonymised, but it isn't carried over either — it disappears. Conversely, sensitive content sitting in a part that wasn't extracted (a DOCX table, an XML attribute) is neither detected nor carried over: no leak, but a silent loss of data.

A notable exception: nothing reads a file's metadata (a DOCX author, a PDF's Producer). It disappears too, since the files are recreated from scratch.

3. The detection engine

No model in the repository, no weights downloaded by the module itself apart from the spaCy model. Two Presidio engines are instantiated on every click of "Anonymize Files" (…py:493), with stderr short-circuited by a SuppressStderr class:

analyzer = AnalyzerEngine()      # default config
anonymizer = AnonymizerEngine()

AnalyzerEngine() with no argument uses Presidio's default NLP configuration, that is spaCy en_core_web_lg — the only model that install_dependencies() downloads (spacy.cli.download, …py:411).

Two families of recognizers combine: spaCy's statistical NER (PERSON, LOCATION, DATE_TIME) and pattern- and checksum-based recognizers (PHONE_NUMBER, EMAIL_ADDRESS, US_SSN, MEDICAL_LICENSE, US_DRIVER_LICENSE, CREDIT_CARD, US_BANK_NUMBER, IP_ADDRESS, URL).

Trap

The language is locked to English: analyzer.analyze(..., language='en') (…py:713), despite the comment "with automatic language detection" and the installation of langdetect, which is never imported — a dead dependency. A folder of French notes goes through an English model, with the recall you would expect.

Confidence threshold: score_threshold, slider 0.0–1.0, default 0.5. Detections below the threshold are dropped without a trace.

4. Entities and replacement methods

Twelve checkboxes, seven checked by default (…py:90):

Presidio entityUI labelDefault
PERSON predictedNames (patients, doctors)✔
PHONE_NUMBER computedPhone Numbers✔
EMAIL_ADDRESS computedEmail Addresses✔
DATE_TIME predictedDates and Times✔
LOCATION predictedAddresses and Locations✔
US_SSN computedSocial Security Numbers✔
MEDICAL_LICENSE computedMedical License Numbers✔
US_DRIVER_LICENSE, CREDIT_CARD, US_BANK_NUMBER, IP_ADDRESS, URL computed—✘

Four methods, in "Advanced Options" (…py:720):

MethodImplementationResult
replace (default)operators = {} → passed as None → Presidio's default operator<PERSON>, <DATE_TIME>, …
redactOperatorConfig("redact") per entitythe occurrence disappears, the text closes back up
hashOperatorConfig("hash")unsalted SHA-256 of the detected text
maskOperatorConfig("mask", {"masking_char": "*", "chars_to_mask": 100, "from_end": False})asterisks over the whole occurrence

On hash: the README speaks of "cryptographic hashes for consistent anonymization." The consistency claim is true (the same name always yields the same digest), but there is neither salt nor key: over a value space as small as a name, a date of birth, or a social security number, the digest can be re-identified by brute force in seconds. Treat it as a public pseudonym, not as protection.

5. Outputs and the mapping table

Written flat into the output folder — the input's subfolder hierarchy is not reproduced.

InputOutputNote
x.docxx_anonymized.docxrebuilt document, one paragraph per line, no styling
x.txtx_anonymized.txt—
x.pdfx_anonymized.pdfregenerated by reportlab, a single Preformatted block
x.csvx_anonymized.csvsee below
x.xmlx_anonymized.xmlplain text under an .xml extension: no tags remain, and the code comment admits it ("XML anonymization is complex")
x.odtx_anonymized.txtextension change

The CSV case is the most destructive: the file was read by flattening each row with spaces, then it is rewritten with writer.writerow(line.split()) (…py:632). Any cell containing a space is split across several columns, and empty cells disappear: column alignment is not preserved. A CSV of measurements comes out unusable.

The mapping table, file_mappings.csv, written into the output folder (…py:648):

ColumnContent
Original File Namename of the source file
Anonymized File Nameproduced name, or ERROR
UUIDuuid.uuid4() drawn per file, or the exception message on failure

This is not a re-identification table for people: it contains no mapping between a detected name and its replacement. And the UUID is purely decorative — it is generated (…py:531) then never used: it appears neither in the content nor in the output file's name. So there is no stable pseudonymisation mechanism across documents.

Trap

This file_mappings.csv file is written right alongside the anonymised documents: sharing the output folder amounts to sharing the list of original file names.

BlockNatureWhere
Text extractioncomputed deterministic, by format librarywidget, UI thread

No model is trained or bundled in the repository; en_core_web_lg is pulled by spacy.cli.download at install time.

7. Limits: what is NOT removed

The most useful section for deciding whether a dataset can be shared.

Out of scope by construction

  1. All images. DICOM, NIfTI, NRRD, meshes: never read, never modified. No header tag is cleaned, no face is erased (§0).
  2. File and folder names. Dupont_Jean_2019.docx becomes Dupont_Jean_2019_anonymized.docx. The patient's name survives intact in the file name, and it is copied verbatim into file_mappings.csv. The input hierarchy, often just as identifying (.../Patients/Dupont_Jean/), is flattened — and if two subfolders each contain a file with the same name, the second silently overwrites the first.

Blind spots of the detection

  1. Hospital identifiers. No recognizer for an MRN, a chart number, an accession number, a study identifier, a bed number. They appear in none of the twelve entities on offer, and Presidio has none by default.
  2. Anything not American. The selectable entities are US_SSN, US_DRIVER_LICENSE, US_BANK_NUMBER: a French NIR, an NHS number, a passport number, or an ITIN are not searched for.
  3. HIPAA's indirect identifiers are not handled: age over 89, rare dates, occupations, membership in a small group. Presidio performs no date generalisation — DATE_TIME is replaced wholesale or not at all.
  4. The language. Analysis is locked to English (§3): on a non-English corpus, recall for PERSON/LOCATION/DATE_TIME collapses, with no warning whatsoever.
  5. The 0.5 threshold drops all less certain detections by default — typically rare names, non-Anglo-Saxon names, and abbreviated forms.
  6. Content that wasn't extracted (DOCX tables, XML attributes, scanned PDFs, headers and footers) is not analysed. It doesn't leak into the output, but if the recipient also receives the originals, the anonymisation never covered it.

Silent failure — the most serious finding

  1. anonymize_text_presidio() ends with (…py:748):

    Confirmed bug — silent failure
    except Exception as e:
    logger.error(f"Error in Presidio anonymization: {e}")
    return text  # Return original text if anonymization fails

    Any analysis error (an entity not recognized by the installed Presidio version, a missing spaCy model, text that's too long) produces an _anonymized file containing the original text intact, with a "Complete!" status in the interface and a single red line in the Python console. There is no after-the-fact check, no count of detected entities, no report. A non-anonymised document is indistinguishable from a clean one without reading it.

Practical conclusion. This module's output is not enough on its own to declare a dataset de-identified. It is a first pass over English-language free text, to be reviewed, and it needs to be completed by: renaming the files, a dedicated DICOM anonymiser for the images, and defacing if the volumes cover the face.

8. Environment

Everything runs in Slicer's Python, installed by the "Install Dependencies" button (…py:392), with no confirmation and no pinned versions:

presidio-analyzer, presidio-anonymizer, pandas, python-docx, pdfplumber,
odfpy, lxml, langdetect, reportlab    then    spacy.cli.download("en_core_web_lg")

Notes:

  • spacy is not in the pip_install list: it is only imported (…py:409). It works because presidio-analyzer pulls it in as a dependency; if that import fails, the whole block falls into the except and shows "Error installing dependencies."
  • A Slicer restart is requested after installation (dialog box), which is consistent with loading a spaCy model.
  • lxml is installed but unused (the code uses xml.etree.ElementTree); langdetect is installed and never imported.
  • os.environ['PRESIDIO_SUPPRESS_WARNINGS'] = '1' and warnings.filterwarnings('ignore') are set at module level, so as soon as the extension loads: they suppress warnings for all of Slicer, not just Presidio's.
  • No GPU, no conda, no CLI: AnalyzerEngine() and loading spaCy (a few seconds) happen on the interface thread, on every run.

9. Traps and fragile points

  • Silent failure returning the original text (§7.9).
  • Flattened output folder: name collisions, overwriting with no message.
  • CSV restructured by line.split(), XML degraded to plain text, ODT renamed to .txt.
  • UUID generated but never applied: the "mapping table" allows no controlled re-identification.
  • file.replace(".docx", "_anonymized.docx"): str.replace replaces every occurrence; a name containing the extension twice produces an unexpected result.
  • The output PDF has no pagination (a single Preformatted block): a long document can overflow the frame or raise a reportlab exception, in which case the file is counted as ERROR but processing continues.
  • Everything runs on the UI thread: on a large folder, Slicer appears frozen.
  • The README overstates the module: it talks about HIPAA compliance and "AI-powered text analysis" where the code is a default Presidio call on English text, with no validation.
  • The README points to Medical_Data_Anonymizer_Module/Resources/Icons/icon.png while the file actually present is named Medical_Data_Anonymizer_Module.png.
  • Medical_Data_Anonymizer_ModuleLogic / …Test are empty shells: no tests, and nothing callable by script.

10. Literature and references

No paper covers this module; nor is there an evaluation (recall, precision) in the repository, on any corpus.

The building blocks used are documented:

  • Microsoft Presidio — the detection and anonymisation engine, with the exact list of its predefined recognizers and operators (replace, redact, hash, mask, encrypt — the latter, reversible with a key, is not offered by the module).
  • spaCy en_core_web_lg — the English NER model used by default.
  • HIPAA Safe Harbor, 45 CFR §164.514(b)(2) — the 18 categories of identifiers to remove. Useful as a reading grid for §7: file names, medical record identifiers, and image identifiers appear there, and this module does not handle them.

Full bibliography: SOURCES.html — search done, negative result on the module itself. The folder contains the only published evaluation of Presidio on unstructured clinical text, and links to the i2b2/n2c2 text de-identification campaigns, which do not describe this code but do provide its reading grid.

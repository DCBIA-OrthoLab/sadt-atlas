DOCShapeAXI

Classification of .vtk meshes by a two-branch network (multi-head-attention point cloud + multi-view EfficientNet-B0 rendering), systematically followed by a Grad-CAM pass written as a per-point scalar on the mesh.

Prieto 2024 · SPIE DOCShapeAXI_CLI conda env: shapeaxi Bibliography

Dental Oral and Craniofacial Shape Analysis eXplainability and Interpretability. A single user action: pick a data type, an input folder, an output folder. Everything else — which checkpoint, which architecture, how many classes — is inferred from the data type.

1. Place in the pipeline

Standalone: nothing in the repository calls DOCShapeAXI. The input meshes are assumed to be already segmented and extracted elsewhere (AMASSS for condyles, airway segmentation, etc.); the module does not produce its own surfaces.

The shapeaxi environment is shared with FlexReg, ALI, AREG and ASO: any version change ripples through all of them.

The model json is read from the main branch on GitHub, not from the local copy (DOCShapeAXI_CLI.py:118): an installed version can download weights published after it.

3. Inputs and preprocessing

3.1 The CSV

The CLI flat-lists args.input_dir, keeps the .vtk files, and writes <output_dir>/files_<data_type>.csv with the header surf and one file name per line (csv_edit, DOCShapeAXI_CLI.py:102). Paths are relative; SaxiDataset joins them with mount_point = input_dir.

data_type contains spaces ("Mandibular Condyle"), so the csv is named files_Mandibular Condyle.csv. The csv is regenerated only if it does not already exist (DOCShapeAXI_CLI.py:282): adding meshes to the input folder without emptying the output folder will not get them processed.

3.2 Geometric normalization

EvalTransform → UnitSurfTransform → utils.GetUnitSurf → ScaleSurf:

  1. center = midpoint of the bounding box (not the centroid);
  2. translate the points to this center;
  3. scale factor 1 / ||bounds_max - center||, applied uniformly.

The mesh thus fits inside the unit sphere, independently of its actual size. All absolute-scale information is lost — a small condyle and a large condyle of the same shape are identical to the network.

Confirmed bug (shapeaxi package)

Worth knowing: saxi_predict reads model.hparams.scale_factor (0.0507 in the condyles checkpoint) and passes it to EvalTransform(scale_factor) (DOCShapeAXI_CLI.py:206), but UnitSurfTransform.__call__ calls utils.GetUnitSurf(surf) without forwarding it when the input is a vtkPolyData. The scale factor learned at training time is therefore silently ignored at inference, replaced by a per-subject normalization. This is a bug in the shapeaxi package, not in the repository, but it does change the actual preprocessing. saxi_gradcam, for that matter, builds its dataset with EvalTransform() with no argument: the two passes end up consistent with each other.

3.3 What the DataLoader returns

SaxiDataset(..., CN=True, class_column=None, scalar_column=None) → (V, F, CN) per subject:

  • V: vertices (1, Nv, 3) after normalization;
  • F: triangles (1, Nf, 3);
  • CN: normals encoded as color, utils.ComputeNormals then GetColorArray(surf,"Normals") divided by 255 → (1, Nv, 3) in [0,1].

No mesh scalar is ever read (surf_property=None): only the geometry and the normals go in. batch_size=1, no padding, so meshes of different sizes pass through without issue.

4.2 The architecture actually used

This is not a PointNet, nor is it the ResNet-18 fly-by-CNN from the original ShapeAXI paper. SaxiMHAFBClassification (MHA Fly-By) has two late-fused branches.

Verified

The values below (K=128, 256 heads, 42 views, image_size=224…) are confirmed by the hyper_parameters and the ico_verts buffer of the condyles_4_class.ckpt checkpoint itself, not just by reading the source code.

Branch A — point cloud.

  • sample_points_from_meshes(X_mesh, 4096) (pytorch3d): uniform sampling of 4096 points on the surface;
  • MHAEncoder: Linear(3→256), then 4 stages with sample_levels = [4096, 2048, 512, 128]. At each stage, MHA_KNN (multi-head attention restricted to the K=128 nearest neighbors, 256 heads) then a residual FeedForward (hidden 64). Between stages, random subsampling down to the next level, carrying indices forward to accumulate a weight per original point (x_w);
  • Linear(256→256), FeedForward, then SelfAttention (additive attention Linear(256→64) → tanh → Linear(64→1) → sigmoid, normalized then weighted sum) which reduces the 128 tokens to a single 256-vector.

Branch B — multi-view.

  • cameras at the vertices of a subdivided icosahedron (subdivision_level=2, radius=1.35). The checkpoint's ico_verts buffer has shape (42, 3): 42 views per subject;
  • pytorch3d rendering: FoVPerspectiveCameras, look_at_rotation toward the origin, AmbientLights (no directional shading), HardPhongShader, RasterizationSettings(image_size=224, blur_radius=0, faces_per_pixel=1, max_faces_per_bin=200000);
  • each view is a 4-channel tensor: RGB (the color-encoded normals set as TexturesVertex) plus the z-buffer. Hence in_channels=4;
  • TimeDistributed(EfficientNetBN('efficientnet-b0', spatial_dims=2, in_channels=4, num_classes=256)) from MONAI: the 42 views are flattened into the batch dimension, run through the same CNN, then reshaped back to (1, 42, 256);
  • FeedForward, nn.MultiheadAttention(256, 256 heads, batch_first=True) as self-attention over the 42 views, then SelfAttention → a 256-vector.

Fusion. torch.cat([x_points, x_views], dim=1) → 512, then fc = Linear(512, num_classes). For regression, Linear(512, 1) and MSE loss.

The rendering is redone on every pass: there is no image cache.

4.3 What the network literally outputs, and how a class is derived from it

x = model(X_pc, X_views)                       # (1, num_classes) — raw logits
if args.nn == 'SaxiMHAFBClassification':
    x = softmax(x).detach()
    x = torch.argmax(x, dim=1, keepdim=True)   # the class integer
predictions.append(x)

(DOCShapeAXI_CLI.py:227)

  • classification: only the argmax is kept. The softmax probabilities are computed then discarded; no confidence measure leaves the module;
  • regression: the raw value from Linear(512,1) is written as-is (obstruction ratio, on a 0–100 scale at training time);
  • the softmax has no effect on the argmax anyway.

A training detail visible in the upstream code: in classification, the target is not a one-hot but soft class probabilities (soft_class_probabilities: Gaussians centered on [12.5, 37.5, 62.5, 87.5] with widths = 12.5). The 4 severity classes are therefore in reality quartiles of a continuous quantity on a 0–100 scale, which explains why a regression model exists on the same airway dataset.

5. The explainability mechanism

Note

This is the module's most distinctive part, and it runs systematically after prediction — neither an option nor a checkbox (saxi_gradcam, DOCShapeAXI_CLI.py:126).

a) The targeted layer.

target_layer = getattr(model.convnet.module, '_blocks')
mv_cam = LayerGradCam(model, target_layer[-1], device_ids=[0])

model.convnet.module is the EfficientNet-B0; _blocks[-1] is its last MBConv block.

Pitfall

Major consequence: the saliency describes only the multi-view branch. The point-cloud branch, which contributes half of the fused vector, appears nowhere in the map. The x_w (per-point weight) that the encoder is capable of producing is neither retrieved nor written out.

b) One map per class. A loop over for class_idx in range(num_classes) with mv_cam.attribute(inputs=(X_pc, X_views), target=class_idx, attr_dim_summation=False): Captum backpropagates the logit of class class_idx to the block's activations, multiplies by the averaged gradients, and returns a tensor at the resolution of the activation map (7×7 for EfficientNet-B0 on 224×224), for all 42 views at once. attr_dim_summation=False keeps the channel dimension, which is collapsed right after by mv_att.sum(dim=1).

c) Rescaling (scale_cam_image, DOCShapeAXI_CLI.py:43, adapted from pytorch-grad-cam): cv2.resize to 224×224, clipping at the 1st and 99th percentiles, then an affine remap into [-1, 1]. Percentile clipping keeps one outlier pixel from swamping the whole dynamic range; the output is therefore signed, not a probability.

d) Reprojection onto the mesh (gradcam_process, in shapeaxi) — the core of the mechanism:

P_faces = torch.zeros(1, F.shape[1])
V_gcam  = -1 * torch.ones(V.shape[1])
for pf, gc in zip(PF.squeeze(), GCAM):          # one view at a time
    P_faces[:, pf] = torch.maximum(P_faces[:, pf], gc)
faces_pid0 = F[0, :, 0].to(torch.int64)
V_gcam[faces_pid0] = P_faces
V_gcam[V_gcam < 0] = 0
  • PF is the rasterizer's pix_to_face: for every pixel of every view, the index of the visible triangle. The pixel's value is thus carried back onto the face;
  • cross-view aggregation is a maximum, not an average: a region seen only once and judged salient keeps its value;
  • the face-to-vertex step is crude: the value of each face is written onto its first vertex (F[0,:,0]). Vertices never used as the first point of a triangle stay at -1, then get reset to 0. The map is therefore scattered with structural zeros;
  • faces that are never rasterized (interior, permanent occlusions) stay at 0.

e) Smoothing and writing.

surf.GetPointData().AddArray(mv_att_upscaled)
psp.MedianFilter(surf, mv_att_upscaled)
utils.WriteSurf(surf, out_surf_path)

MedianFilter replaces every value with the median of its topological neighbors (1 pass, in place): this is what partly recovers the holes left by the "first vertex" carry-over. It modifies the vtkDataArray already added to the mesh, so it is indeed the filtered version that gets written.

The array name is fixed inside gradcam_process:

CaseScalar name
num_classes > 1grad_cam_target_class_0, _1, …
regression (num_classes == 1)grad_cam_max (target_class stays None)

The file is rewritten on every class iteration, accumulating the arrays: the final .vtk carries all N maps. This is what the README has you select in the Models module → Scalars → Active Scalar, with the ColdToHotRainbow table.

The column accumulation is intentional (DOCShapeAXI_CLI.py:240): if the prediction csv already exists, it is read back in and used as a base, which is why an airway dataset ends up with binary_prediction, severity_prediction and regression_prediction side by side. Corollary: rerunning on the same output folder overwrites the columns in place and never clears out the old ones.

The log is a single-line file rewritten each time ('w+' for every subject); the widget watches its mtime and resets the progress bar to zero when the predict/explainability field changes (DOCShapeAXI.py:694).

Pitfall

Two sources of randomness at inference: the sampling of the 4096 points (torch.randint in MHAEncoder.sample_points and in sample_points_from_meshes) is not seeded. Two runs can produce two slightly different saliency maps, and in borderline cases two different classes.

9. Pitfalls and fragile points

Confirmed bug

The CLI is written for the shapeaxi 1.0.x API, the environment installs 2.0.2. This is the first thing to check if the module stops working:

shapeaxi 1.0.10shapeaxi 2.0.2
signatureforward(self, X_pc, X_views)forward(self, X_mesh)
return valuexx, x_w, X
class-count hparamout_classesnum_classes

The CLI calls model(X_pc, X_views) and uses the return value as a tensor (DOCShapeAXI_CLI.py:227): on 2.0.2 this is a TypeError (3 positional arguments). And the published checkpoints carry out_classes, which the 2.0.2 __init__ no longer reads — the load_from_checkpoint call would fail even before the forward pass. In other words: this module expects a pinned shapeaxi<2 version that the install script does not install. Either pin it, or port the CLI to the new API (pass X_mesh, unpack the triplet) and regenerate the checkpoints.

  • strict=False on load_from_checkpoint (DOCShapeAXI_CLI.py:198): missing or extra weights pass silently. A partially loaded model still predicts regardless.
  • The model download is conditioned on the output folder already existing (if os.path.exists(args.output_dir): if not os.path.exists(...), DOCShapeAXI_CLI.py:277). If the folder does not exist, the download is skipped and the error surfaces later, at checkpoint loading. The CLI never creates output_dir.
  • process.log is written inside the module's own tree (os.path.dirname(__file__), DOCShapeAXI.py:811), and the empty file DOCShapeAXI/process.log is checked into the repository. On a read-only install (/opt, Program Files), creating the DOCShapeAXILogic raises an exception.
Confirmed bug

gradcam_save() (DOCShapeAXI_CLI.py:62) calls shutil.copy while shutil is never imported in the file. Harmless: the function is never called. Same for the classes MultiHead and SelfAttention defined near the top of the CLI (:84, :93), never instantiated, and for the subprocess import.

  • The learned scale factor is ignored (see §3.2). Should UnitSurfTransform ever forward its scale_factor, the preprocessing will change without anything moving in this repository.
  • No confidence is reported: only the argmax class comes out. For a tool whose name contains "explainability," this is the blind spot — the saliency map tells you where the network looked, never how unsure it was.
  • The saliency covers only one of the two branches (see §5a). A decision driven mainly by the point-cloud geometry will produce an uninformative multi-view map, with nothing flagging it.
  • num_workers=4 in the explainability DataLoader (DOCShapeAXI_CLI.py:144) while prediction uses none: four processes read the .vtk files in parallel while the GPU renders 42 views.
  • Model selection goes through the words of the combo label. Renaming "Mandibular Condyle" to "Condyles" in the .ui breaks find_model_name, which would return (None, None) and, on the next call, a TypeError on os.path.join(output_dir, None + '.ckpt').
  • check_input_parameters (DOCShapeAXI.py:469) tests the same condition twice, the else branch ("Unknown error") is unreachable.
  • count_num_subjects only counts top-level .vtk files — consistent with csv_edit, but neither one is recursive.
  • DOCShapeAXI/__pycache__/DOCShapeAXI.cpython-312.pyc is checked into version control.

10. Literature

Three references, not to be confused with one another:

1. The framework. ShapeAXI: Shape Analysis Explainability and Interpretability, Prieto, Miranda, Gurgel, Anchling, Hutin, Barone, Al Turkestani, Aliaga, Yatabe, Bianchi, Cevidanes — Proc. SPIE Medical Imaging, April 2024, DOI 10.1117/12.3007053. It reports 79.78% on condyles and 81.58% on cleft severity — precisely two of the three datasets supported here.

Code / paper divergence

The code diverges from the paper. The paper describes a multi-view render over an icosahedron subdivision processed by a ResNet-18 plus additive attention, with condyles handled as binary classification. The checkpoints distributed here are SaxiMHAFB* models: EfficientNet-B0 on 42 views plus a second point-cloud branch with KNN attention, absent from the paper, with a condyles_4_class checkpoint at 4 severity classes. Do not present the SPIE paper's figures as those of the downloaded models.

2. The airway dataset. Explainable Artificial Intelligence to Quantify Adenoid Hypertrophy-related Upper Airway Obstruction using 3D Shape Analysis, Mattos et al., J Dent 2025. This one describes exactly the code's architecture: an ImageNet-pretrained EfficientNet-B0 multi-view branch + multi-head attention, a 4096-point point-cloud branch with KNN attention, and explainability via "SurfGradCAM" — the mechanism from §5. The three tasks (4-class, binary, obstruction-ratio regression) correspond to the three airways_* checkpoints. AUC 0.77–0.94, R = 0.854 for the ratio.

3. The origin of the Slicer module: lucieDLE/DOC-ShapeAXI, cited by the repository's README.md.

Nothing is published on the Alveolar Bone Defect in Cleft dataset beyond the "cleft severity" experiment in the SPIE paper.

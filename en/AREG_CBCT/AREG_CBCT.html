AREG_CBCT

Rigid T1/T2 registration of CBCT scans onto a reference bone region (cranial base, mandible, or maxilla): plain elastix, mutual information, no network — everything learned sits upstream, in the masks and the landmarks.

Anchling 2023 · LNCS 14242 areg_cbct Slicer's Python — no conda, CPU only Bibliography

1. Where it sits in the pipeline

AREG/AREG.py is a single widget that drives three modalities: CBCT (AREG/AREG_Method/CBCT.py), IOS (AREG/AREG_Method/IOS.py) and IOS-on-CBCT (AREG/AREG_Method/IOSCBCT.py). It computes nothing itself: each Method.Process() returns a list of step dictionaries, and the widget runs them one after another.

A step always has the following shape:

{"Process": slicer.modules.areg_cbct,   # Slicer CLI module
 "Parameter": {...},                    # dict passed as-is to slicer.cli.run
 "Module": "AREG_CBCT for Mandible",    # label shown in the UI
 "ReviewId": "cbct_registration",       # optional review pause
 "ReviewFolder": ".../Mandible",
 "ReviewReferenceFolder": "<T1 folder>",
 "Display": DisplayAREGCBCT(nb_scan)}   # progress translation -> progress bar

Outgoing calls of the CBCT mode, in execution order:

Nothing in the repository calls AREG: it is a terminal tool. Its .tfm files are, however, reused by AutoMatrix and the analysis modules.

3. The three modes and the exact chain

The mode is chosen by CbModeType; SwitchType() (AREG.py:930) instantiates the matching class. All three share the same tail end — center T2, run AREG per region, final AMASSS — and only differ upstream:

ModeClassUpstreamT1 masks
Semi-AutomatedSemi_CBCT (CBCT.py:266)nonesupplied by the operator ("T1 Masks" field)
Fully-AutomatedAuto_CBCT (CBCT.py:446)noneAMASSS CBMASK/MANDMASK/MAXMASK, written into the input T1 folder predicted
Orientation & RegistrationOr_Auto_CBCT (CBCT.py:731)PRE_ASO → ALI_CBCT → SEMI_ASO on T1, into <T1 folder>OrAMASSS on <T1 folder>Or predicted

The reference region is an operator choice, not something inferred: the "Regions of Reference for Registration" checkboxes — Cranial Base, Mandible, Maxilla (CBCT.py:198) — are translated into CB / MAND / MAX by TranslateModels. Checking two regions launches two independent registrations, each with its own output folder.

4. Inputs, pairing, preprocessing

Formats. .nii.gz, .nii, .nrrd, .nrrd.gz, .gipl, .gipl.gz. For DICOM input, convertdicom2nifti (utils.py:720) converts a per-patient subfolder via sitk.ImageSeriesReader, falling back to dicom2nifti, into <folder>/NIFTI/<patient>.nii.gz.

T1/T2 pairing — GetPatients (utils.py:91). The patient identifier is whatever remains of the file name after a chain of split() calls on a fixed list of markers (_Scan, _Or, _MAND, _CB, _lm, _T2, _T1, _Cl…). Then:

  • an image file whose name contains mask, seg or pred → segmentation;
  • otherwise → scanT1 / scanT2;
  • if segmentationType is given, a second pass looks in mask_folder_t1 (or the T1 folder by default) for files whose name contains cb, mand/md, or max/mx depending on the region, and the first one found wins. This pass never checks that the file actually is a mask: a scan named P1_T1_MAX.nii.gz would be taken for the segmentation.
Trap

Keyword-based mask lookup (cb, mand/md, max/mx) never checks that the file found is really a segmentation: a scan named P1_T1_MAX.nii.gz would silently be taken for the segmentation.

T2 is read with segmentationType=None: only the fixed image gets masked, never the moving one.

Centering T2 — pre_aso_cbct. Despite its name and its model_folder parameter pointing at Models/Orientation/PreASO, this CLI uses no network at all: it computes T = -physical_center_of_the_image (PRE_ASO_CBCT.py:163), resamples with the inverse and writes the TranslationTransform as a .tfm alongside. Direction prediction by a DenseNet once existed, commented out, and was removed (commit 4296774). The model_folder and SmallFOV arguments are dead, but the PreASO weights are still downloaded.

Masking the fixed image — MaskedImage (utils.py:584):

fixed_seg_sitk.SetOrigin(fixed_image_sitk.GetOrigin())   # origin forced
fixed_image_masked = applyMask(fixed_image_sitk, fixed_seg_sitk, label=SegLabel)
sitk.WriteImage(sitk.Cast(fixed_image_masked, sitk.sitkInt16),
                os.path.join(temp_folder, "fixed_image_masked.nii.gz"))

applyMask binarizes if a label is requested, otherwise passes the mask as-is to sitk.Mask (any non-zero voxel is kept). The temporary file is always named the same: the temp folder is a single one for the whole batch (CBCT.py:306), so each patient overwrites the previous one — harmless sequentially, fatal if the CLI were ever parallelized.

Trap

The masking temp folder is a single one for the whole batch and the file is always called fixed_image_masked.nii.gz: each patient overwrites the previous one — harmless sequentially, fatal if the CLI were ever parallelized.

SegLabel is in practice always None: the LabelSelectcomboBox combo box is hard-hidden (AREG.py:548) and SegmentationLabels stays [0], which the CLI re-translates into None. GetSegmentationLabel (CBCT.py:177), which read the labels present in the mask, is called nowhere: dead code.

5. The algorithmic core — the registration

Everything happens in VoxelBasedRegistration (utils.py:598):

  1. read the moving T2 as itk.F;
  2. mask the fixed T1 (above), read it back as itk.F;
  3. a single ElastixReg(fixed_image_masked, moving_image, initial_transform=None);
  4. MatrixRetrieval → SimpleITK transform;
  5. ComputeFinalMatrix([t]) → Euler3DTransform;
  6. resample T2.

The library is itk-elastix (itk.ElastixRegistrationMethod), not SimpleITK or ANTs. Parameters, all made explicit in make_rigid_param_map_deterministic (utils.py:527), layered on top of elastix's default "rigid" map:

There is no more coarse step. The ApproxReg parameter behind the "Include Approximation Step" checkbox goes all the way down to VoxelBasedRegistration(approx=...) and is never read there: ElastixApprox and make_rigid_param_map_stochastic (RandomCoordinate sampler, 10000 samples, AdaptiveStochasticGradientDescent, 2 levels, on the unmasked images) were removed by commit 350a8de on 2025-09-23, along with the use of initial_transform in ElastixReg (utils.py:573), which is called with None everywhere. The only "coarse to fine" left is the 3-level pyramid; the coarse pre-alignment is now handled by PRE_ASO's centering of T2 and by AutomaticTransformInitialization.

Matrix retrieval — MatrixRetrieval (utils.py:830) reads TransformParameters: 3 angles then 3 translations, reordered into a sitk.Euler3DTransform. ComputeFinalMatrix (utils.py:851) composes the list (rotations multiplied, translations added) — with a single-element list, it is a plain copy-through. The composition code is therefore never exercised, and the addition of translations would only be valid anyway if the intermediate rotations were the identity.

Resampling — ResampleImage (utils.py:472): linear interpolation, DefaultPixelValue = 0, and SetReferenceImage(image) where image is the moving image itself. The registered volume therefore keeps T2's grid (size, spacing, origin), not T1's. Output cast to int16.

6. What runs upstream: exact arguments

AMASSS — registration masks (CBCT.py:456):

{"inputVolume": <T1 folder>,                  # or <T1 folder>Or
 "modelDirectory": <model_folder_1>/AMASSS_Models,
 "skullStructure": "CBMASK,MANDMASK,MAXMASK",  # depending on checked boxes
 "merge": "SEPARATE", "genVtk": False, "save_in_folder": False,
 "output_folder": <T1 folder>,                # next to the scans
 "vtk_smooth": 5, "prediction_ID": "seg",
 "temp_fold": <Documents>/Slicer_temp_AMASSS,
 "SegmentInput": False, "DCMInput": False}

The name written is <base>_seg_<STRUCT>.<ext> (AMASSS_CLI.py:600) — so P1_T1_seg_MANDMASK.nii.gz, which the second pass of GetPatients finds via the mand keyword. AMASSS is today an nnU-Net v2 called as a subprocess (AMASSS_CLI.py:54), with a separate model per group (FF, SKIN, CBMASK, MANDMASK, MAXMASK) predicted.

AMASSS — final segmentations. Two steps, inputVolume = <T1 folder> then inputVolume = <output folder>, genVtk=True, merge depending on the "Merge Segmentations" checkbox, save_in_folder=True in Semi mode and False elsewhere. The second one recursively walks the <Region>/<patient>_OutReg/ tree and skips its own outputs thanks to the _seg_ suffix.

ALI_CBCT (Orientation mode only, CBCT.py:756):

{"input": <temp>, "dir_models": <model_folder_3>,
 "lm_type": "'N', 'S', 'Ba', 'RPo', 'LPo', 'LOr', 'ROr'",
 "output_dir": <temp>, "temp_fold": <Documents>/Slicer_temp_ALI,
 "DCMInput": False, "spacing": "[1,0.3]", "speed_per_scale": "[1,1]",
 "agent_FOV": "[64,64,64]", "spawn_radius": "10"}

Multi-scale reinforcement agents (1 mm then 0.3 mm), FOV 64³ voxels, a DNet network = 3D DenseNet MONAI (growth_rate=34, blocks (6,12,24,16)) followed by a 6-output MLP = the 6 directions of displacement (brain.py:48) predicted. The landmark list depends on the reference plane: IF ANS PNS UR1O UR6O UL6O (occlusal) or N S Ba RPo LPo LOr ROr (Frankfort).

SEMI_ASO_CBCT: gold_folder = <model_folder_2>/<reference>, output_folder = <T1 folder>Or, add_inname = "Or". Alignment via vtkIterativeClosestPointTransform, rigid, on the landmarks (1000 iterations, StartByMatchingCentroidsOn), after discarding outlier landmarks computed.

7. Outputs

Written by AREG_CBCT.py:152:

<output>/<Cranial Base|Mandible|Maxilla>/<patient>_OutReg/
    <patient>_<CB|MAND|MAX>Scan<add_name>.nii.gz    # registered T2, int16
    <patient>_<CB|MAND|MAX><add_name>_matrix.tfm    # the transform

The subfolder name comes from translate() (utils.py:714): CB → Cranial Base. add_name is concatenated with no separator.

Conventions of the .tfm: sitk.WriteTransform of an Euler3DTransform, so LPS and the ITK convention (the transform maps output space to input space). No flip is needed anywhere in the CLI, everything there is SimpleITK/elastix; the only place in the CBCT chain that conjugates by diag(-1,-1,1,1) is the manual correction, which starts from a Slicer matrix in RAS (Review.py:489).

The centering .tfm written by PRE_ASO next to the centered T2 is not composed with AREG's: to bring the original T2 back onto T1, the two files must be chained by hand.

8. Review pauses and batch navigation

Added by commit 2609bc4 ("Pause VFACE at chosen steps"… and AREG before it). In "Review and manual adjustment," the operator checks the steps where the run should stop; the selection is stored in QSettings under AREG/ReviewSteps (AREG.py:1922).

The breakpoints available in CBCT (getReviewSteps, CBCT.py:258), and what they allow (CATALOGUE, Review.py:568):

IdAfterNature
cbct_landmarks_orientationALI_CBCT (Orientation mode)editable: points can be moved and are rewritten
cbct_orientedSEMI_ASOview only
cbct_masksAMASSS masksview only
cbct_centered_t2PRE_ASO T2view only
cbct_registrationAREG_CBCTadjustable: the registered scan can be moved
cbct_segmentationfinal AMASSS on T2view only

Mechanics of the pause. markProcessesForReview (AREG.py:1936) sets ReviewPause=True on the steps whose ReviewId is checked. At the end of a CLI run, enterReviewPause (AREG.py:1949) returns True and defers beginReview via QTimer.singleShot(0, ...) — mandatory: this happens inside a VTK observer callback, where the Qt event loop is not running and where loading a volume would fill the stdout pipe that Slicer is no longer draining.

ReviewSession.build (Review.py:118) builds the queue: one item per patient found in ReviewFolder, restricted to patients from this run (runPatientIds() reads the input T1 folder — a reused output folder holds the results of months of work). For AREG, ReviewFolder is scoped to <output>/<Region>: otherwise the mandible pause would also show the cranial base, and the operator's adjustment would fold into whichever matrix came first.

For cbct_registration, the registered scan is loaded on top of the T1 (foregroundOpacity=0.5) and attached to a vtkMRMLLinearTransformNode with its interaction handles (Review.py:366). On exit, _saveAdjustment (Review.py:457) converts the RAS displacement to LPS (flip @ ras @ flip), inverts it, and writes sitk.CompositeTransform([original, nudge.GetInverse()]) into the existing .tfm — whatever consumes it downstream applies a single matrix per patient and cannot chain them. The scan is then hardened and rewritten in place (Review.py:510). If the matrix is the identity within 1e-9, nothing is written.

Batch navigation:

  • Previous / Next patient (AREG.py:2117): walk the queue without ever advancing the run; saveEdits() is called before each change, so corrections are kept.
  • Flag (AREG.py:2131): marks a patient "to redo". The button only appears if a correctable step exists further back.
  • Go back (AREG.py:2138): previousCorrectableStep() (AREG.py:2052) walks executed_steps back to the last step of type LANDMARKS or REGISTRATION — read-only steps are skipped. Intermediate steps are replayed only for the flagged patients: restrictStepToPatients (Review.py:727) builds a temp folder holding only these patients, via symbolic links (a CBCT weighs 200 MB), tree structure preserved, then rewrites the step's input key (t1_folder, t2_folder, input, inputVolume…: INPUT_KEYS, Review.py:717). The narrowed steps are inserted at the head of list_Processes_Parameters. The links are cleared at the end of the run by clearReviewTempFolders.
  • Next step (AREG.py:2181): saves the current patient, logs how many patients were accepted without being opened, and resumes the run.

ReviewMatrixFolder and ReviewKind are read by Review.build but set nowhere: unused extension points (the matrix is therefore always looked up inside ReviewFolder itself).

AREG_CBCT contains no network at all: no torch, no monai, no .pth. The only learning in the chain serves to produce the mask that delimits the reference region and, in Orientation mode, the landmarks.

10. Environment

Everything is installed into Slicer's Python by install_function (AREG.py:86) when the launch button is clicked, after a confirmation dialog:

itk==5.4.0, itk-elastix==0.19.2 (the registration engine), dicom2nifti==2.6.2, torch==2.2.0 (cu118 wheel on Windows), monai==1.3.2, nnunetv2>=2.8.0 and torchvision (Linux/macOS only), numpy<2.0.0 re-forced afterward if numpy ≥ 2 is detected, plus connected-components-3d, einops, nibabel, pandas. pydicom is pinned to ==3.0.2, Slicer's own version: downgrading it breaks dicomweb-client and highdicom, hence every DICOM module in Slicer.

Trap

check_lib_installed (AREG.py:68) does not compare versions: the constraint is ignored as soon as the package is present, whatever its version.

11. Traps and fragile spots

The _T1 / _T2 suffixes. Commit 05d1fec flagged every site with the keyword TIMEPOINT-SUFFIX. The reference note sits above GetPatients (utils.py:68).

Trap

The problem: the patient id is whatever remains of the name after splitting on a fixed list of markers, and the only time points on that list are _T1 and _T2. A P001_T3.nii.gz keeps the id P001_T3, pairs with nothing, and the pair is silently dropped — no exception. The actual time point does not come from the name but from the time_point argument, i.e. from the folder; only the id extraction is at fault.

The sites, within AREG's scope:

FileLineForm
AREG_CBCT/AREG_CBCT_utils/utils.py101chain of split(), scans and landmarks
AREG_CBCT/AREG_CBCT_utils/utils.py144the same one, copied for the masks pass

Outside AREG, the same chains live in ASO/ASO_Method/CBCT.py (line 42), MRI2CBCT/MRI2CBCT_utils/utils_CBCT.py (line 41), MRI2CBCT_CLI/MRI2CBCT_CLI_utils/TMJ_crop.py (line 21) and twice in VFACE/VFACE_utils/createlistprocess.py (line 2099). The fix proposed in the note is re.sub(r"_[Tt]\d+$", "", ...) applied everywhere, keeping the split order (a long marker must be cut before a short marker that would match inside it). It has not been done deliberately: the currently supported answer is to rename the inputs.

Confirmed bug

elastix's center of rotation is lost. MatrixRetrieval only reads TransformParameters and never CenterOfRotationPoint. An elastix EulerTransform is worth R·(x − c) + t + c; the reconstructed sitk.Euler3DTransform has its center at the origin and is worth R·x + t. The two only coincide if c is the origin or if R = I. Since AutomaticTransformInitialization is active and the center of rotation is derived from the fixed image (T1, which is only centered in Orientation mode), the gap (I − R)·c is generally non-zero. And the gap is not limited to the .tfm: the output volume is not elastix's own result image, it is rebuilt by ResampleImage(sitk.ReadImage(moving_image_path), transform) (utils.py:686) from that same matrix. The .tfm and the registered volume are therefore consistent with each other, but both drift from what elastix actually optimized.

CenterOfRotationPoint appears nowhere in the repository (verified by grep), and MatrixRetrieval is duplicated identically in MRI2CBCT_CLI/MRI2CBCT_CLI_utils/AREG_MRI.py:78: the same gap applies to the MRI↔CBCT registration.

Note

A hypothesis to test rather than to believe: if the module still gives correct results in practice, it is likely because the volumes already arrive close to the origin — PRE_ASO recenters T2 and ASO orients T1 — so that c ≈ 0 and (I − R)·c stays small. That makes the result dependent on a prior centering that is guaranteed nowhere. Measure the gap on a real case before drawing conclusions.

Other points:

  • ApproxReg / "Include Approximation Step" does nothing since September 2025. The checkbox still defaults to checked in the UI.
  • The <T2 folder>_Center folder is created next to the user's input folder, same as <T1 folder>Or. PRE_ASO skips files already present: a second run with modified inputs reuses the old ones.
  • In Fully-Auto mode, AMASSS writes the masks into the input T1 folder. At the cbct_registration pause, since ReviewReferenceFolder is that same folder, every mask for the patient gets loaded into the scene alongside the scan.
  • The fixed_image_masked.nii.gz file is rewritten for each patient in the same temp folder.
  • SwitchType (AREG.py:1030) re-shows the NIFTI/DCM selector after SwitchModeCBCT has hidden it: the net result is that DICOM input is only offered in Orientation mode, the opposite of what SwitchModeCBCT appears to intend. And in that mode, DCMInput is passed to the AREG step whose folders already hold NIfTI.
  • startStep is called twice for the first CBCT step (AREG.py:1542 then AREG.py:1557): executed_steps ends up with a duplicate, which previousCorrectableStep absorbs because it looks for the last occurrence.
  • A manually corrected .tfm becomes a CompositeTransform, not an Euler3DTransform: a downstream consumer that assumes a simple transform might fail to read it back.
  • Dead code found: TestReference (CBCT.py:61, which would call NumberScan with a single argument and raise a TypeError), GetSegmentationLabel, getGPUUsage, GetMatrixPatients and ModifiedDictPatients (no caller ever passes matrix_folder or todo_str), ElastixReg(initial_transform=...), and DisplayAREGIOSCBCT defined twice in Progress.py (line 135).

12. Literature

The reference paper is Anchling, Hutin, Huang, Barone, Roberts, Miranda, Gurgel, Al Turkestani, Tinawi, Bianchi, Yatabe, Ruellas, Prieto, Cevidanes, "Automated Orientation and Registration of Cone-Beam Computed Tomography Scans," LNCS 14242, 2023, p. 43-58 — Springer, PMC11104011. Reported accuracy: < 3° and < 2 mm against experts, under 5 min per case.

The code diverges from the paper on three verified points:

  1. the paper describes a two-stage registration — "VBR between the full images, then with the masked image as a refinement step," 10,000 iterations on the masked pass. The code now runs only one masked pass at 1500 iterations;
  2. the paper reports SimpleElastix; the code uses itk-elastix (itk.ElastixRegistrationMethod);
  3. the paper obtains its masks via AMASSS / UNETR MONAI; AMASSS is today an nnU-Net v2.

On the underlying question — voxel-based superimposition on the cranial base — the lab's historical reference is Cevidanes et al., Superimposition of 3D cone-beam CT models of orthognathic surgery patients (2005, PubMed 16227481).

Not to be confused with Accuracy and Reproducibility of Voxel Based Superimposition…, PLOS One 2011, which is not from the lab: it is by Nada, Maal, Kuijpers-Jagtman et al. (Radboud UMC, Nijmegen). It is an independent validation of the method, which gives it more weight, not less — but attributing it to the group would be a mistake.

Repositories: lucanchling/AREG, DCBIA-OrthoLab/SlicerAutomatedDentalTools. The review pauses and batch navigation are described in no publication: internal development.

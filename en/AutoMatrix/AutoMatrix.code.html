AutoMatrix, legacy: the code

For developers: what the legacy AutoMatrix module does in the code, with file:line references, code blocks, the formats actually read, the matching rules and the pitfalls. The readable explanation of the same pipeline, with the maths, is on the atlas page.

unpublished Code Atlas (explanation) Legacy page VISOR code Bibliography
Two code bases

Everything numbered below describes the legacy Slicer module (SlicerAutomatedDentalTools at 3c67957, 2026-10-26). The VISOR port, which runs the same tool on a server, is described in VISOR: how this tool runs now.

VISOR references read SADT-VISOR AutoMatrix/pipeline.py:127: that is tools/AutoMatrix/src/sadt_automatrix/pipeline.py at 6ba2a78. VISOR-serve is e9a7e5d, AutomatedDentalToolsRemote is 19b95e8. Legacy lines are written Automatrix_CLI.py:279@3c67957; a bare legacy line number on this page is also read at 3c67957. Automatrix_CLI.py is Automatrix_CLI/Automatrix_CLI.py; AutoMatrix.py, AutoMatrix.ui and AutoMatrix_Method/ are under AutoMatrix/.

Batch application of one or more ITK transformations to a folder of volumes and landmark files. No network, no conda, no GPU: sitk.ReadTransform + sitk.ResampleImageFilter, and a file ↔ matrix match by name splitting. The whole point of this page lies in the transformation conventions and in the gap between what the UI promises and what the CLI actually does.

1. Position in the pipeline

Plain-language explanation and maths: atlas page.

AutoMatrix is called by no other module in the repository. It is, however, a consumer of the .tfm files produced by the registration modules:

ProducerFile producedTransformation type

MRI2CBCT_REGISTER.py:96 <pid>/<pid>_<side>_MRI_transform[_tag].tfm (:34-36) affine, already RAS→LPS-conjugated and inverted (MRI2CBCT_core/frames.py:39-50)

The UI's "From AReg" checkbox hardcodes AREG_CBCT's naming convention (§6), including the default value of a text field belonging to another module.

3. Transformation formats read, and those that aren't

Plain-language explanation and maths: atlas page.

The UI (AutoMatrix.py:829,832) and the README (README.md:416-418) advertise .npy, .h5, .tfm, .mat, .txt. GetPatients collects all of them. The CLI then does, with no distinction (Automatrix_CLI.py:257-261):

try:
    tfm = sitk.ReadTransform(matrix)
except Exception as e:
    logger.error(f"ERROR reading transform {matrix}: {e}")
    continue

sitk.ReadTransform only knows ITK's TransformIO classes. Tested with Slicer 5.12's SimpleITK 2.5.5:

ExtensionActual result
.tfm, .txtOK if and only if it's an Insight Transform File V1.0. A text file containing a raw 4×4 matrix is rejected: ITK ERROR: Tags must be delimited
.h5, .hdf5OK (HDF5TransformIO)
.matOK (MatlabTransformIO)
.npyFails: Could not create Transform IO object for reading file
Confirmed bug

Legacy (3c67957); changed in VISOR. The legacy list still carries .npy (Automatrix_CLI.py:110@3c67957) and the read failure is logged and skipped (:258-261). The port no longer lists it: transforms are .tfm .mat .h5 .hdf5 .txt (SADT-VISOR AutoMatrix/pipeline.py:46), and a folder holding only other files is refused with a ValueError (SADT-VISOR AutoMatrix/__init__.py:79-84; that message names four extensions and leaves out .hdf5). A .npy is still not read, but nothing advertises it.

.npy support is therefore broken: every .npy file produces an error line and is skipped. This is a regression introduced by the move to the CLI (commit 7bc362b): the widget version read np.load(matrix) and built a vtkMRMLTransformNode (the extension_mat == ".npy" branch, visible with git show 7bc362b^:AutoMatrix/AutoMatrix.py).

Not true in VISOR. A .txt holding a plain 4x4 matrix is read by a fallback when sitk.ReadTransform refuses it (SADT-VISOR AutoMatrix/pipeline.py:138-180). Run on 2026-11-09: a four-line matrix in P1_matrix.txt produced one transformed volume.

Same story for "text matrices": that isn't a matrix format, it's ITK's text format.

A successful read gives back a sitk.Transform whose concrete type is preserved: isinstance(tfm, sitk.CompositeTransform) works, verified.

4. The transformation convention: the point that breaks everything

Plain-language explanation and maths: atlas page.

4.1 Direction of the transformation

Plain-language explanation and maths: atlas page.

ITK is fixed → moving: a sitk.Transform passed to a resampler maps the output physical point to the input physical point to sample from. The visible content therefore moves according to T⁻¹.

The code exploits this on both sides, and it is consistent:

  • Volumes (Automatrix_CLI.py:182): resampler.SetTransform(transform), the transformation is passed as-is, the content moves by T⁻¹.
  • Landmarks (Automatrix_CLI.py:149,156): 
    tfm_inverted = transform.GetInverse()
point['position'] = list(tfm_inverted.TransformPoint(point['position']))
    T⁻¹ is explicitly applied to the point, so it moves like the volume's content.
Verified

Also true in VISOR (SADT-VISOR AutoMatrix/pipeline.py:121 hands the transform to the resampler; :83 and :99 invert it for the points).

Key takeaway: the same .tfm applied to a scan and to its landmarks moves them with the same motion. This is the property that makes the module usable, and it is also the only place in the code where an inversion appears.

Pitfall

Legacy (3c67957); changed in VISOR. Legacy: warning and return, no file (Automatrix_CLI.py:148-152@3c67957). VISOR: the RuntimeError is no longer swallowed (SADT-VISOR AutoMatrix/pipeline.py:74-78,83); it is recorded under cases[patient].failed (SADT-VISOR AutoMatrix/__init__.py:144-155) and the volume of that patient is still written, so the two outputs can still disagree, but the report says so. A zero displacement field raises on GetInverse() (run on 2026-11-09). The run fails only if nothing at all was written (:164). The Slicer panel does not display the failures, see the findings in the VISOR section.

GetInverse() can raise RuntimeError (non-invertible transformation: dense displacement field, B-spline). The case is caught and the landmark file is simply skipped with a warning: the corresponding volume, meanwhile, will have been transformed. The two outputs can therefore silently fall out of sync.

4.2 RAS / LPS: where the flip happens, nowhere

Plain-language explanation and maths: atlas page.

There is no flip in AutoMatrix. This is correct, and here is why:

  • ITK .tfm files are in LPS by construction.
  • sitk.ReadImage / WriteImage work in LPS. Both sides agree, nothing to do for volumes.
  • The repository's .mrk.json files are hardcoded to LPS, everywhere: ALI_CBCT/ALI_CBCT_utils/io.py:39, ALI_IOS/ALI_IOS_utils/io.py:74, FlexReg/FlexReg_utils/mgl_patch.py:222, VFACE/VFACE_utils/functionaq3dc.py:1724, and, since ASO_CBCT and AREG_CBCT now re-export WriteJson rather than carrying their own, ADTLib/io/landmarks.py:92. This is also Slicer's default on write. So point['position'] is already in LPS, and applying it directly to an ITK transformation is correct.
Pitfall

Also true in VISOR (SADT-VISOR AutoMatrix/pipeline.py:71-104 never reads it). Run on 2026-11-09: a file declaring RAS with control point [1,2,3] and a translation (5,0,0) came out with x = -4 and still declared RAS. Legacy: Automatrix_CLI.py:154-156@3c67957.

The fragile part is that the coordinateSystem field is never read. FlexReg does read it (FlexReg.py:2221); AutoMatrix does not. A json declaring "coordinateSystem": "RAS", which older annotations or other tools write, will be transformed with x and y of the wrong sign, with no message. The output file will even keep its original coordinateSystem: RAS, since the json is read back and rewritten as-is.

For reference, the modules that produce the matrices do the flip themselves: FlexReg_CLI.py:100-105 computes flip @ matrix_array @ flip with flip = np.diag([-1, -1, 1, 1]) and then inverts, before writing the .tfm (:107-109). AutoMatrix consumes the result of that work and therefore has nothing left to redo.

4.3 Composition

Plain-language explanation and maths: atlas page.

Pitfall

Also true in VISOR (each transform is applied to the original file, SADT-VISOR AutoMatrix/__init__.py:130-143). Legacy: Automatrix_CLI.py:256@3c67957.

There isn't any. When a patient has several matrices, the loop (Automatrix_CLI.py:256) applies each one to the original input file, independently, producing one output per matrix. There is no chaining.

The only composition that exists is the one ITK has already done: a .tfm containing several transformations is read back as a sitk.CompositeTransform and applied as a whole.

4.4 Harden

Plain-language explanation and maths: atlas page.

None. There is no more vtkMRMLTransformNode in the pipeline. The pre-CLI version created one and did model.SetAndObserveTransformNodeID(...) then model.HardenTransform() before slicer.util.exportNode(..., world=True). That whole block is gone. The widget's saveOutput method (AutoMatrix.py:894-904), which called exportNode, is still there but is no longer called: dead code.

6. Resampling and reference image

Plain-language explanation and maths: atlas page.

resampler.SetInterpolator(sitk.sitkNearestNeighbor if is_seg else sitk.sitkLinear)
resampler.SetDefaultPixelValue(0)

if reference is not None:
    resampler.SetReferenceImage(reference)

(Automatrix_CLI.py:183-187.) The interpolator comes from the "Check this box if using segmentations" checkbox (is_seg, :206). Nearest neighbor for a labelmap, linear otherwise: correct, and it's up to the user to declare it, nothing is auto-detected.

The output grid is chosen as follows (Automatrix_CLI.py:165-175 and :276-279), in decreasing priority:

  1. Composite transformation → the reference is guessed from the matrix's path: matrix.replace("_transform.tfm", ".nii.gz"), falling back to .nii. This isn't a bug: ASO_CBCT writes <patient>_<add>_transform.tfm and <patient>_<add>.nii.gz in the same folder, so the oriented scan next to the matrix is exactly the right grid. If the file is missing, a warning is issued and it falls back to the input image.
  2. Matrix name containing mirror (case-insensitive) → the reference is forced to the input image, the UI's reference file is ignored. Dispatch based on the file name.
  3. Reference file provided (reference_file != "None", the field's default value, AutoMatrix.ui:257; read at Automatrix_CLI.py:209-216) → its geometry is imposed on all outputs.
  4. Otherwise the input image itself: size, spacing, origin and direction unchanged. A transformation that moves content out of the field of view makes it disappear, filled in with DefaultPixelValue = 0.
Confirmed bug

Legacy (3c67957); the opposite in VISOR. At 3c67957 the branch is unreachable because the caller supplies the image itself when there is no reference (Automatrix_CLI.py:279@3c67957). In the port that branch is the default path: no reference means the input size, spacing and direction, and an origin moved to transform.TransformPoint(origin) (SADT-VISOR AutoMatrix/pipeline.py:127-133, pinned by a test, tests/test_run_options.py:265-277). See the finding "Without a reference the output box follows the transform" in the VISOR section.

The reference is None branch of ResampleImage (Automatrix_CLI.py:186-194@3c67957) is unreachable: the caller always passes a reference. It is also wrong: it does new_origin = transform.TransformPoint(image.GetOrigin()) when the resampler's convention would call for T⁻¹.

7. Mirror mode

Plain-language explanation and maths: atlas page.

Mirror() (AutoMatrix.py:307) and DownloadMirror() (:384-405) download Mirror.zip from a personal GitHub release (GaelleLeroux/DCBIA_Apply_matrix, ADT/ADTLib/model_registry.py:80-82), unzip it into <Documents>/SlicerDownloads/Mirror_matrix/ and fills the matrix field with Mirror/Matrix_mirror.tfm. The file's actual content:

#Insight Transform File V1.0
Transform: AffineTransform_double_3_3
Parameters: -1 0 0 0 1 0 0 0 1 0 0 0
FixedParameters: 0 0 0
Pitfall

Legacy statement (3c67957); a second consequence in VISOR. In the port a reflection applied with no reference leaves the output box empty, because the origin is sent through the reflection too (SADT-VISOR AutoMatrix/pipeline.py:133). Run on 2026-11-09 with a reflection matrix diag(-1,1,1) on a 20-voxel cube centred on the origin: the output origin moved from -10 to +10 and none of the 1000 non-zero voxels remained; given the volume as its own reference, all 1000 remained. Details and the unmerged fix in the VISOR section.

That is diag(-1, 1, 1) in LPS, centered at the origin: a reflection about the plane x_LPS = 0. Since x_LPS points toward the patient's left, this is indeed a left/right swap, but about the sagittal plane of the world frame's origin, not the patient's own sagittal plane. A patient who isn't centered comes out translated in addition to mirrored, which a later registration has to correct for.

The determinant is −1. For a volume, ResampleImageFilter handles this without any problem. For a mesh, it would flip face orientation and normals: a moot point here since meshes are no longer processed.

The mode forces ComboBoxMatrix to "File", the suffix to _mir, and unchecks checkBoxMatrixName (AutoMatrix.py:319-321).

Plain-language explanation and maths: atlas page.

Pitfall

Legacy only (3c67957); not present in VISOR. Both sides now go through one function (SADT-VISOR AutoMatrix/pipeline.py:33-42). Run on 2026-11-09: patient1_MA.nii.gz and patient1_MA.tfm pair. The lists diverge: the matrix side removes _MA, _Left/_Right, the _Mir and _SegOr variants; the scan side removes _Seg, _Scan, _lm. Hence the README's requirement: the patient name first, an underscore, then the rest. But patient1_MA.nii.gz without a timestamp gives the key patient1_MA on the scan side and patient1 on the matrix side: no matrix will be matched, with no message.

When the matrix path is a file rather than a folder, it is attached to every patient (Automatrix_CLI.py:138-140).

Confirmed bug

11. Environment

Plain-language explanation and maths: atlas page.

Nothing to install: SimpleITK, numpy, vtk, qt are already in Slicer. No conda, no CUDA. The only network access is the mirror matrix download, and only if the Mirror checkbox is checked.

Confirmed bug

Legacy only (3c67957); not present in VISOR. The legacy mechanism, for the record, is emit_event(PATIENT_DONE) (Automatrix_CLI.py:27,287@3c67957), defined in ADT/ADTLib/progress_protocol.py: the pulse 0, 2, 0 with a PULSE_PAUSE of 0.2 s (:41,59), read as 200 by isProgress (Progress.py:40-47@3c67957). In the port, progress.report(index, total, "patient") appends one JSON line to the file named by SADT_PROGRESS_FILE (SADT-VISOR AutoMatrix/__init__.py:117, SADT-VISOR AutoMatrix/progress.py:60-103) and the server reads it (VISOR-serve server/execution/runner.py:212).

The progress bar is not fed by a log file despite the log_path parameter: DisplayAutomatrix.isProgress (AutoMatrix_Method/Progress.py:40-49) checks the mtime of log_path, but the CLI never writes to that file (args.log_path is parsed at Automatrix_CLI.py:301 and never used). Progress actually flows through the <filter-progress> pulse 0, 2, 0 that emit_event(PATIENT_DONE) prints after each input file (Automatrix_CLI.py:287; ADT/ADTLib/progress_protocol.py:59-71) and the is_event(kwds["progress"], PATIENT_DONE) test, that is == 200, in isProgress: an indirect, fragile protocol that depends on a time.sleep(0.2) between each print.

12. Pitfalls and fragile points

Plain-language explanation and maths: atlas page.

Summary

Legacy (3c67957); status in VISOR, bullet by bullet. Still true: no composition, coordinateSystem never read, non-defined landmarks left in the old frame (SADT-VISOR AutoMatrix/pipeline.py:95-96, run on 2026-11-09: an undefined point stayed at [7,7,7]), .npy and meshes unsupported (no longer advertised). Not true: .txt with a raw 4x4 matrix (accepted by a fallback), overwriting when the name option is off, truncation by .split(extension_scan)[0] (replaced by Path and relpath, SADT-VISOR AutoMatrix/__init__.py:323-342). Legacy only: OnEndProcess, CheckGoodEntre, onPredictButton, "From AReg", the dead code and the XML metadata.

  • .npy does not work (§3), though advertised by the UI and the README.
  • Meshes no longer work (§5), though advertised by the UI and the README. Regression from commit 7bc362b.
  • .txt does not accept a raw 4×4 matrix (§3), only ITK's text format.
  • The landmarks' coordinateSystem is never read (§4.2).
  • No composition: N matrices for one patient give N files, not a chain (§4.3).
  • Outputs overwritten if checkBoxMatrixName is unchecked with several matrices (§9).
  • OnEndProcess divides by self.nb_scans (AutoMatrix.py:745-747@3c67957) with no guard: an empty input folder causes a ZeroDivisionError at the end of processing.
  • CheckGoodEntre is logically wrong (AutoMatrix.py:808@3c67957): the extension test is len(dico['.vtk'])==0 and len(dico['.vtp']) and len(dico['.stl']) and …, where only the first term is a comparison. The rest are integers evaluated as booleans, so the "Folder empty or wrong type" warning only fires in an unlikely conjunction. A genuinely empty folder passes validation.
  • onPredictButton does not stop on error: TestProcess returns a tuple (ok, out), so the isinstance(error, str) check at AutoMatrix.py:581@3c67957 is always false, and processing starts even with empty fields.
  • .split(extension_scan)[0] cuts at the first occurrence: a path whose folder contains the same substring as the extension would be truncated.
  • Non-defined landmarks left in the old coordinate frame, mixed with transformed points in the same file (§5).
  • The "From AReg" path, dead and broken (§8).
  • Dead code: the widget's saveOutput / UpdateProgressBar / UpdateTime, AutoMatrixLogic.process, ResampleImage's reference is None branch, registerSampleData referencing missing .png files.
  • Automatrix_CLI.xml's metadata is still the Slicer template's (FirstName LastName (Institution), NIH grant NXNNXXNNNNNN-NNXN).

13. Literature

Plain-language explanation and maths: atlas page.

No paper covers AutoMatrix: it's a batch-application utility written for the lab (Gaëlle Leroux, UoM/DCBIA). The scientific content lives entirely in the modules that produce the matrices, AREG, ASO, MRI2CBCT, FlexReg, and is covered in their respective pages.

For the transformation convention, the up-to-date reference is ITK / Slicer documentation rather than a paper:

  • Transforms: Slicer user guide (fixed→moving direction, Slicer's RAS vs. ITK's LPS)
  • Coordinate systems: Slicer developer guide
  • SimpleITK: Transforms and Resampling
  • SlicerAutomatedDentalTools
  • DCBIA_Apply_matrix: the original repository, which still hosts the mirror matrix and the test sets cited by the README

AutoMatrix

Applies one or more ITK transformations, already computed elsewhere, in batch to a folder of volumes and landmark files — no network, no conda, no GPU.

unpublished Automatrix_CLI computed — no network no conda, no GPU Bibliography

Batch application of one or more ITK transformations to a folder of volumes and landmark files. No network, no conda, no GPU: sitk.ReadTransform + sitk.ResampleImageFilter, and a file ↔ matrix match by name splitting. The whole point of this page lies in the transformation conventions and in the gap between what the UI promises and what the CLI actually does.

1. Position in the pipeline

AutoMatrix is called by no other module in the repository. It is, however, a consumer of the .tfm files produced by the registration modules:

ProducerFile producedTransformation type
AREG_CBCT.py:157 <out>/<Region>/<patient>_OutReg/<patient>_<CB|MAND|MAX><add_name>_matrix.tfm affine / rigid
SEMI_ASO_CBCT.py:176 <patient>_<add_name>_transform.tfm sitk.CompositeTransform (utils.py:802)
AREG_MRI.py:227 <mri>_reg_transform.tfm composite
Review.py:499 and VFACE.py:2168 registration + manual nudge CompositeTransform([areg, nudge.GetInverse()])
FlexReg_CLI.py:186 <T2><suffix>.tfm affine, already RAS→LPS-conjugated and inverted

The UI's "From AReg" checkbox hardcodes AREG_CBCT's naming convention (§6), including the default value of a text field belonging to another module.

3. Transformation formats read — and those that aren't

The UI (AutoMatrix.py:1012) and the README advertise .npy, .h5, .tfm, .mat, .txt. GetPatients collects all of them. The CLI then does, with no distinction (Automatrix_CLI.py:285):

try:
    tfm = sitk.ReadTransform(matrix)
except Exception as e:
    logger.error(f"ERROR reading transform {matrix}: {e}")
    continue

sitk.ReadTransform only knows ITK's TransformIO classes. Tested with Slicer 5.12's SimpleITK 2.5.5:

ExtensionActual result
.tfm, .txtOK if and only if it's an Insight Transform File V1.0. A text file containing a raw 4×4 matrix is rejected: ITK ERROR: Tags must be delimited
.h5, .hdf5OK (HDF5TransformIO)
.matOK (MatlabTransformIO)
.npyFails: Could not create Transform IO object for reading file
Confirmed bug

.npy support is therefore broken: every .npy file produces an error line and is skipped. This is a regression introduced by the move to the CLI (commit 7bc362b): the widget version read np.load(matrix) and built a vtkMRMLTransformNode (the extension_mat == ".npy" branch, visible with git show 7bc362b^:AutoMatrix/AutoMatrix.py).

Same story for "text matrices": that isn't a matrix format, it's ITK's text format.

A successful read gives back a sitk.Transform whose concrete type is preserved — isinstance(tfm, sitk.CompositeTransform) works, verified.

4. The transformation convention — the point that breaks everything

4.1 Direction of the transformation

ITK is fixed → moving: a sitk.Transform passed to a resampler maps the output physical point to the input physical point to sample from. The visible content therefore moves according to T⁻¹.

The code exploits this on both sides, and it is consistent:

  • Volumes (Automatrix_CLI.py:209): resampler.SetTransform(transform) — the transformation is passed as-is, the content moves by T⁻¹.
  • Landmarks (Automatrix_CLI.py:176): 
    tfm_inverted = transform.GetInverse()
point['position'] = list(tfm_inverted.TransformPoint(point['position']))
    T⁻¹ is explicitly applied to the point, so it moves like the volume's content.
Verified

Key takeaway: the same .tfm applied to a scan and to its landmarks moves them with the same motion. This is the property that makes the module usable, and it is also the only place in the code where an inversion appears.

Pitfall

GetInverse() can raise RuntimeError (non-invertible transformation: dense displacement field, B-spline). The case is caught and the landmark file is simply skipped with a warning — the corresponding volume, meanwhile, will have been transformed. The two outputs can therefore silently fall out of sync.

4.2 RAS / LPS: where the flip happens — nowhere

There is no flip in AutoMatrix. This is correct, and here is why:

  • ITK .tfm files are in LPS by construction.
  • sitk.ReadImage / WriteImage work in LPS. Both sides agree, nothing to do for volumes.
  • The repository's .mrk.json files are hardcoded to LPS, everywhere: ALI_CBCT/io.py:36, ASO_CBCT/utils.py:278, AREG_CBCT/utils.py:373, ALI_IOS/io.py:85, mgl_patch.py:193, VFACE/functionaq3dc.py#L1733. This is also Slicer's default on write. So point['position'] is already in LPS, and applying it directly to an ITK transformation is correct.
Pitfall

The fragile part is that the coordinateSystem field is never read. FlexReg does read it (FlexReg.py:2434); AutoMatrix does not. A json declaring "coordinateSystem": "RAS" — which older annotations or other tools write — will be transformed with x and y of the wrong sign, with no message. The output file will even keep its original coordinateSystem: RAS, since the json is read back and rewritten as-is.

For reference, the modules that produce the matrices do the flip themselves: FlexReg_CLI.py:186 computes flip @ M @ flip with flip = np.diag([-1,-1,1,1]) and then inverts, before writing the .tfm. AutoMatrix consumes the result of that work and therefore has nothing left to redo.

4.3 Composition

Pitfall

There isn't any. When a patient has several matrices, the loop (Automatrix_CLI.py:283) applies each one to the original input file, independently, producing one output per matrix. There is no chaining.

The only composition that exists is the one ITK has already done: a .tfm containing several transformations is read back as a sitk.CompositeTransform and applied as a whole.

4.4 Harden

None. There is no more vtkMRMLTransformNode in the pipeline. The pre-CLI version created one and did model.SetAndObserveTransformNodeID(...) then model.HardenTransform() before slicer.util.exportNode(..., world=True). That whole block is gone. The widget's saveOutput method (AutoMatrix.py:861), which called exportNode, is still there but is no longer called: dead code.

5. Data types handled

GetPatients collects .vtk .vtp .stl .off .obj .nii .nii.gz .nrrd .mrk.json (Automatrix_CLI.py:72). The CLI then only distinguishes two cases:

is_landmark = scan.endswith(".mrk.json")
...
image = sitk.ReadImage(scan)     # everything else
Confirmed bug

Meshes are no longer processed. Tested: sitk.ReadImage on a vtkPolyData written as .vtk fails with sitk::ERROR: Unable to determine ImageIO reader. Same for .stl, .obj, .off, .vtp. The exception is caught (Automatrix_CLI.py:310), logged as ERROR processing ..., and the file is skipped. Yet the UI still offers them, CheckGoodEntre validates them, the progress counter counts them, and README.md:422 still advertises IOS support.

This is the second regression from the move to the CLI: the widget version loaded meshes with slicer.util.loadModel and did a real HardenTransform. A .vtk structured points file (an image, not a surface), on the other hand, would pass through via VTKImageIO.

TypeRead byTransformed byWritten by
.nii, .nii.gz, .nrrdsitk.ReadImageResampleImageFiltersitk.WriteImage
.mrk.jsonjson.load, markups[0]['controlPoints']T⁻¹.TransformPoint point by pointjson.dump(indent=2)
.vtk .vtp .stl .off .obj——— (silent failure)

For landmarks, only markups[0] is processed, and only points whose positionStatus == 'defined' are moved; the others are left in place, i.e. in the old coordinate frame.

6. Resampling and reference image

resampler.SetInterpolator(sitk.sitkNearestNeighbor if is_seg else sitk.sitkLinear)
resampler.SetDefaultPixelValue(0)
resampler.SetReferenceImage(reference)

The interpolator comes from the "Check this box if using segmentations" checkbox (is_seg). Nearest neighbor for a labelmap, linear otherwise — correct, and it's up to the user to declare it, nothing is auto-detected.

The output grid is chosen as follows (Automatrix_CLI.py:191 and :301), in decreasing priority:

  1. Composite transformation → the reference is guessed from the matrix's path: matrix.replace("_transform.tfm", ".nii.gz"), falling back to .nii. This isn't a bug: ASO_CBCT writes <patient>_<add>_transform.tfm and <patient>_<add>.nii.gz in the same folder, so the oriented scan next to the matrix is exactly the right grid. If the file is missing, a warning is issued and it falls back to the input image.
  2. Matrix name containing mirror (case-insensitive) → the reference is forced to the input image, the UI's reference file is ignored. Dispatch based on the file name.
  3. Reference file provided (reference_file != "None", the field's default value, AutoMatrix.ui:255) → its geometry is imposed on all outputs.
  4. Otherwise the input image itself: size, spacing, origin and direction unchanged. A transformation that moves content out of the field of view makes it disappear, filled in with DefaultPixelValue = 0.
Confirmed bug

The reference is None branch of ResampleImage (Automatrix_CLI.py:215) is unreachable — the caller always passes a reference. It is also wrong: it does new_origin = transform.TransformPoint(image.GetOrigin()) when the resampler's convention would call for T⁻¹.

7. Mirror mode

Mirror() (AutoMatrix.py:304) downloads Mirror.zip from a personal GitHub release (GaelleLeroux/DCBIA_Apply_matrix), unzips it into <Documents>/SlicerDownloads/Mirror_matrix/ and fills the matrix field with Mirror/Matrix_mirror.tfm. The file's actual content:

#Insight Transform File V1.0
Transform: AffineTransform_double_3_3
Parameters: -1 0 0 0 1 0 0 0 1 0 0 0
FixedParameters: 0 0 0
Pitfall

That is diag(-1, 1, 1) in LPS, centered at the origin: a reflection about the plane x_LPS = 0. Since x_LPS points toward the patient's left, this is indeed a left/right swap — but about the sagittal plane of the world frame's origin, not the patient's own sagittal plane. A patient who isn't centered comes out translated in addition to mirrored, which a later registration has to correct for.

The determinant is −1. For a volume, ResampleImageFilter handles this without any problem. For a mesh, it would flip face orientation and normals — a moot point here since meshes are no longer processed.

The mode forces ComboBoxMatrix to "File", the suffix to _mir, and unchecks checkBoxMatrixName.

8. File ↔ matrix matching

GetPatients (Automatrix_CLI.py:60) builds {patient_key: {'scan': [...], 'matrix': [...]}}. The key is obtained through a chain of .split() calls that is not the same on both sides:

Tokens removed (in order)
scan_Seg _seg _Scan _scan _Or _OR _MAND _MD _MAX _MX _CB _lm _T2 _T1 _Cl _MR, then .split('.')[0], then _T0…_T49
matrix_SegOr _Left _left _Right _right _Or _OR _MAND _MD _MAX _MX _CB _lm _T2 _T1 _Cl _MA _Mir _mir _Mirror _mirror _MR, then .split('.')[0], then _T0…_T49
Pitfall

The lists diverge: the matrix side removes _MA, _Left/_Right, the _Mir and _SegOr variants; the scan side removes _Seg, _Scan, _lm. Hence the README's requirement: the patient name first, an underscore, then the rest. The example patient1_T1_MA.nii.gz ↔ patient1_left_MA.tfm works because _T1 is trimmed on the scan side and _left on the matrix side. But patient1_MA.nii.gz without a timestamp gives the key patient1_MA on the scan side and patient1 on the matrix side: no matrix will be matched, with no message.

When the matrix path is a file rather than a folder, it is attached to every patient (Automatrix_CLI.py:167).

Confirmed bug

Duplicated code that has already diverged. GetPatients exists in two copies that are identical but for one token: the CLI version strips a leading _SegOr, General_tools.py:249 does not. And it's the General_tools copy that feeds NbScan, so the progress bar's denominator can differ from the number of files actually processed.

The "From AReg" path

suffix_map (Automatrix_CLI.py:227) bypasses all the matching logic for landmark files:

suffix_map = {
    "_CB": ("Cranial Base", "CBReg_matrix.tfm"),
    "_L":  ("Maxilla",      "MAXReg_matrix.tfm"),
    "_U":  ("Mandible",     "MANDReg_matrix.tfm"),
}
matrix_path = os.path.join(args.matrix_lineEdit, subdir,
                           f"{patient_id}_OutReg", f"{patient_id}_{matrix_filename}")
Confirmed bug

Three problems, all verifiable:

  1. _L and _U are swapped relative to the convention used in the rest of the repository. AREG_IOS/dataset.py:231 and AREG/IOS.py:122 define Lower = ["Lower", "_L", "L_", "Mandibule", "Md"] and Upper = ["Upper", "_U", "U_", "Maxilla", "Mx"]. Here _L points to Maxilla and _U to Mandible.
  2. matrix_lineEdit does not exist in the CLI's argparse (Automatrix_CLI.py:329: the arguments are input_patient, input_matrix, reference_file, suffix, matrix_name, fromAreg, output_folder, log_path, is_seg). This branch therefore raises AttributeError as soon as it's taken.
  3. It is never taken: CheckBoxSuffixBased (labeled "From AReg") is hidden at setup by self.ui.CheckBoxSuffixBased.setVisible(False) (AutoMatrix.py:296), so fromAreg is always "False". Dead code — which explains why 1 and 2 were never noticed.

The name MAXReg_matrix.tfm does match AREG_CBCT's reality, though: it writes patient + "_" + reg_type + add_name + "_matrix.tfm" with add_name defaulting to Reg (AREG.ui:571) — so this path depends on the default value of an editable text field belonging to another module.

9. Outputs

matrix_suffix = f"_{Path(matrix).stem}" if args.matrix_name == "True" else ""
out_suffix    = f"{args.suffix}{matrix_suffix}"
out_file      = outpath.split(extension_scan)[0] + out_suffix + extension_scan

The input directory tree is reproduced in the output folder (scan.replace(input_patient, output_folder)). Default suffix _apply, checkBoxMatrixName checked by default (AutoMatrix.ui:342).

Pitfall

The README is stale on this point: it advertises patient1_T1_MA_apply_matrix1.nii.gz. The old version extracted the part of the matrix name that came after the patient key (basename.split(ext)[0].split(key)[1]); the CLI uses the entire Path(matrix).stem. The actual output for patient1_MAXReg_matrix.tfm is therefore patient1_T1_MA_apply_patient1_MAXReg_matrix.nii.gz.

Pitfall

Unchecking "Add matrix name" with several matrices per patient causes outputs to overwrite one another: the same file name for every matrix.

No .tfm is ever produced: AutoMatrix consumes transformations, it doesn't write any.

11. Environment

Nothing to install: SimpleITK, numpy, vtk, qt are already in Slicer. No conda, no CUDA. The only network access is the mirror matrix download, and only if the Mirror checkbox is checked.

Confirmed bug

The progress bar is not fed by a log file despite the log_path parameter: DisplayAutomatrix.isProgress (Progress.py:39) checks the mtime of log_path, but the CLI never writes to that file. Progress actually flows through the <filter-progress>0 / 2 / 0</filter-progress> sequence emitted by the CLI after each scan (Automatrix_CLI.py:314) and the if kwds["progress"] == 200 in isProgress — an indirect, fragile protocol that depends on a time.sleep(0.2) between each print.

12. Pitfalls and fragile points

Summary
  • .npy does not work (§3), though advertised by the UI and the README.
  • Meshes no longer work (§5), though advertised by the UI and the README. Regression from commit 7bc362b.
  • .txt does not accept a raw 4×4 matrix (§3), only ITK's text format.
  • The landmarks' coordinateSystem is never read (§4.2).
  • No composition: N matrices for one patient give N files, not a chain (§4.3).
  • Outputs overwritten if checkBoxMatrixName is unchecked with several matrices (§9).
  • OnEndProcess divides by self.nb_scans (AutoMatrix.py:953) with no guard: an empty input folder causes a ZeroDivisionError at the end of processing.
  • CheckGoodEntre is logically wrong (AutoMatrix.py:1013): the extension test is len(dico['.vtk'])==0 and len(dico['.vtp']) and len(dico['.stl']) and …, where only the first term is a comparison. The rest are integers evaluated as booleans, so the "Folder empty or wrong type" warning only fires in an unlikely conjunction. A genuinely empty folder passes validation.
  • onPredictButton does not stop on error: TestProcess returns a tuple (ok, out), so the isinstance(error, str) check at AutoMatrix.py:766 is always false, and processing starts even with empty fields.
  • .split(extension_scan)[0] cuts at the first occurrence: a path whose folder contains the same substring as the extension would be truncated.
  • Non-defined landmarks left in the old coordinate frame, mixed with transformed points in the same file (§5).
  • The "From AReg" path, dead and broken (§8).
  • Dead code: the widget's saveOutput / UpdateProgressBar / UpdateTime, AutoMatrixLogic.process, ResampleImage's reference is None branch, registerSampleData referencing missing .png files.
  • Automatrix_CLI.xml's metadata is still the Slicer template's (FirstName LastName (Institution), NIH grant NXNNXXNNNNNN-NNXN).

13. Literature

No paper covers AutoMatrix: it's a batch-application utility written for the lab (Gaëlle Leroux, UoM/DCBIA). The scientific content lives entirely in the modules that produce the matrices — AREG, ASO, MRI2CBCT, FlexReg — and is covered in their respective pages.

For the transformation convention, the up-to-date reference is ITK / Slicer documentation rather than a paper:

  • Transforms — Slicer user guide (fixed→moving direction, Slicer's RAS vs. ITK's LPS)
  • Coordinate systems — Slicer developer guide
  • SimpleITK — Transforms and Resampling
  • SlicerAutomatedDentalTools
  • DCBIA_Apply_matrix — the original repository, which still hosts the mirror matrix and the test sets cited by the README

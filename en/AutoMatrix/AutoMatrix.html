AutoMatrix

AutoMatrix applies one or more transforms to a folder of volumes and landmark files. This page explains how, step by step: which way each file moves, how a file finds its matrix, and where the result lands. Files, lines, code blocks and pitfalls are on the code page.

unpublished Atlas (explanation) Code (developers) no conda no GPU purely computational VISOR Bibliography

Two code bases. This page describes the legacy Slicer module (SlicerAutomatedDentalTools at 3c67957, 2026-10-26). The VISOR port, which runs the same tool on a server, is described in VISOR: how this tool runs now. Where VISOR differs, a sentence says so.

Overview: what goes in, what comes out

A registration module finds a transform: how to move one scan onto another. AutoMatrix takes that file and applies it to the other files of the patient. No network, no conda, no GPU: it is a transform read from a file, a resampler, and a match between file names.

InOut
volumes (.nii, .nii.gz, .nrrd) and landmark files (.mrk.json), or a folder of themthe same files moved by their transform, with a suffix (_apply proposed), in a copy of the input folders
transforms (.tfm, .mat, .h5, .txt), or a folder of themno transform file: AutoMatrix consumes transforms and writes none

1. Position in the pipeline

No module calls AutoMatrix. It consumes the transform files produced by the registration modules:

ProducerFile producedTransform type
AREG_CBCTone matrix per patient and region (_matrix.tfm)affine or rigid
SEMI_ASO_CBCT<patient>_<name>_transform.tfma composite of several transforms
MRI2CBCT_REGISTER<id>_<side>_MRI_transform.tfmaffine, already converted between RAS and LPS and inverted
Review and VFACEregistration plus a manual nudgea composite
FlexReg<T2><suffix>.tfmaffine, already converted and inverted

The “From AReg” checkbox of the panel hardcodes AREG_CBCT’s naming (below).

2. Files involved

A widget (selectors, validation, mirror, progress bar), a helper that builds the parameters of the command-line module, a copy of the pairing code used only for counting, and the command-line module that does all the work. The module runs inside Slicer’s own Python. Part of the module now lives in the shared ADTLib layer.

3. Transformation formats read, and those that aren’t

The panel advertises .npy, .h5, .tfm, .mat and .txt. The command-line module hands every one of them to ITK, which only knows its own transform formats. Tested with Slicer 5.12’s SimpleITK 2.5.5:

ExtensionActual result
.tfm, .txtread only if it is an ITK transform text file; a raw 4×4 matrix is rejected
.h5, .hdf5read (but the folder search lists .h5 only: a .hdf5 is read only when given as a single file)
.matread (Matlab format)
.npyfails: every .npy file is logged and skipped

VISOR no longer lists .npy and accepts a .txt holding a plain 4×4 matrix.

4. The transformation convention: the point that breaks everything

4.1 Direction of the transformation

ITK (the imaging toolkit behind SimpleITK, which reads the transforms and resamples the images here) goes from the output to the input: a transform given to a resampler (the step that writes a new image on a chosen grid) maps an output point to the input point to read from. The visible content therefore moves by the inverse of the transform. The code uses this on both sides, consistently: the volume is resampled with T as it is, and each landmark point is moved by the explicit inverse.

If a transform cannot be inverted (a dense displacement field or a B-spline: both raise an error on inversion in Slicer 5.12’s SimpleITK 2.5.5, tried on 2026-11-10), the landmark file of that patient is skipped with a warning while its volume is still transformed: the two outputs can silently fall out of step.

In the codeThe resampler and the explicit inverse, with the lines

4.2 RAS / LPS: where the flip happens, nowhere

There is no flip in AutoMatrix, and that is correct. ITK transform files and image reading and writing are in LPS, and the landmark files of the repository are hardcoded to LPS, as is Slicer’s default on write. A point can therefore be given directly to the transform. The fragile part is that the coordinateSystem field of a landmark file is never read: a file that declares RAS would be moved with x and y of the wrong sign, with no message. The modules that produce the matrices do the conversion themselves; AutoMatrix consumes the result.

In the codeWhere each module hardcodes LPS

4.3 Composition

There is none. When a patient has several matrices, each is applied to the original file, independently, giving one output per matrix. The only composition is the one ITK already did: a .tfm holding several transforms is read back as a composite and applied as a whole.

In the codeThe loop that applies each matrix to the original

4.4 Harden

None. The old version attached the transform to a scene node and “hardened” it; that block is gone, and the code that exported the node is dead.

6. Resampling and reference image

Nearest neighbour for a label map, linear otherwise. In the legacy module the user declares it with a checkbox; nothing is detected. VISOR detects it per file.

The output grid is chosen in this order: (1) for a composite transform, the reference is guessed from the matrix name, which works because ASO_CBCT writes the oriented scan next to its matrix; (2) a matrix whose name contains mirror uses the input image as its own reference; (3) a reference file given by the user imposes its geometry; (4) otherwise the input image itself.

In the codeThe interpolator and the four-way choice of the grid

7. Mirror mode

The mirror button downloads a small matrix from a release of the lab’s own repository and fills the matrix field with it. Its content is an affine transform whose matrix is diag(-1, 1, 1) with no translation.

Its determinant is −1, which a resampler handles without difficulty for a volume. The mode forces the suffix to _mir and unticks “Add the matrix name”. In VISOR, a reflection applied with no reference leaves the output box empty (see the grid card there).

In the codeThe download and the file content

8. File ↔ matrix matching

A patient key is built from each file name, and a scan meets the matrix of the same key. If the matrix path is a single file, it is attached to every patient. The key comes from a chain of cuts that is not the same on both sides.

In the codeGetPatients and the two token lists

The “From AReg” path

A hard-coded table maps a landmark file suffix to an AREG_CBCT matrix name, bypassing all the matching. It is dead and broken: its two jaw letters are swapped compared with the rest of the repository, it reads a parameter that the command-line module does not have, and the checkbox is hidden so the path is never taken. VISOR removed it.

In the codeThe suffix table and the three problems

9. Outputs

The output name is the file name, then the suffix (_apply proposed), then, when “Add the matrix name” is ticked (it is by default), the entire name of the matrix. For patient1_MAXReg_matrix.tfm that gives patient1_T1_MA_apply_patient1_MAXReg_matrix.nii.gz, not what the old README promised. Unticking the option with several matrices per patient makes the outputs overwrite one another; VISOR forces the name in that case. The input folders are reproduced in the output folder. No .tfm is ever produced.

10. What is predicted vs what is computed

BlockNature
Transform readingcomputed ITK transform readers
File ↔ matrix matchingcomputed string splitting
Volumescomputed resampling, linear or nearest neighbour
Landmarkscomputed inverse transform, point by point
Mirror matrixcomputed fixed downloaded file, diag(-1,1,1)

No neural network anywhere.

11. Environment

Nothing to install: SimpleITK, numpy, VTK and Qt are already in Slicer. No conda, no CUDA. The only network access is the mirror matrix download, and only if the Mirror box is ticked.

12. Pitfalls and fragile points

Each point is checked in the code and described, with its evidence, on the code page.

  • .npy does not work, though advertised. Evidence.
  • Meshes no longer work, though advertised. Evidence.
  • A raw 4×4 text matrix is rejected by the legacy reader. Evidence.
  • The landmark frame is never read. Evidence.
  • No composition: N matrices give N files, not a chain. Evidence.
  • Outputs overwrite each other if the matrix name is not added. Evidence.
  • A matrix without a time point finds no scan, silently. Evidence.
  • The mirror is about the origin of the coordinate system, not the patient’s midline. Evidence.
  • A matrix that cannot be inverted leaves a volume without its landmarks. Evidence.
  • Two copies of the pairing code have already diverged. Evidence.
  • “From AReg” is dead and broken. Evidence.
  • Progress flows through a fragile indirect protocol. Evidence.
  • The widget has several other defects (a division by zero on an empty folder, a wrong validation, dead code). Summary.

13. Literature

No paper covers AutoMatrix: it is a batch-application utility written for the lab. The scientific content lives in the modules that produce the matrices (AREG, ASO, MRI2CBCT, FlexReg). For the transformation convention the reference is the documentation:

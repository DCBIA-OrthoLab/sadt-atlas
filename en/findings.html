Confirmed bug AREG_CBCTelastix's center of rotation is lost.

elastix's center of rotation is lost. MatrixRetrieval only reads TransformParameters and never CenterOfRotationPoint . An elastix EulerTransform is worth R·(x − c) + t + c ; the reconstructed sitk.Euler3DTransform has its center at the origin and is worth R·x + t . The two only coincide if c is the origin or if R = I . Since AutomaticTransformInitialization is active and the center of rotation is derived from the fixed image (T1, which is only centered in Orientation mode), the gap (I − R)·c is generally non-zero.

If you use this model, check each segment individually before trusting its name.

Pitfall guideNo compatible graphics card

In Butterfly mode, the palatal patch inference requires a CUDA GPU, full stop. On a machine without a compatible GPU, this mode fails outright. Use MGL on those machines, or process the upper arch elsewhere.

Pitfall guideNo matrix is written

Registration produces surfaces that are already transformed, not a matrix file. Unlike AREG_IOS or AREG_CBCT, you cannot reopen the result and nudge it with the mouse: if the alignment is off, the fix is to rerun — with different landmarks or a different setting — not to correct it by hand.

Pitfall guideNote too long

There's no chunking: a note longer than the model can read in one pass fails entirely instead of being processed in pieces. The margin is especially tight in Ortho mode.

Pitfall guideNotes sorted into per-patient subfolders

CNE only looks at files sitting directly in the folder you chose, not at anything inside subfolders. A folder organized with one subfolder per patient will produce no output at all, with no error message.

Pitfall guideOcclusion: name your files Upper / Lower unambiguously

Occlusion mode pairs the upper and lower arches by file name ( Upper / _U_ or Lower / _L_ ). A file whose name carries none of these markers is silently treated as a lower arch — with no error message. Check your file names before turning this option on.

Pitfall guideOne output can overwrite another

If you uncheck the option that appends the matrix name to the output file, and a patient has more than one matrix, every result gets the same file name: each one overwrites the last, and only the final matrix processed survives. Keep this option checked whenever you're applying more than one matrix per patient.

Pitfall guideOne scanned arch means the patient is dropped

Every patient must provide both arches, scan and landmarks included. If even one is missing — say, only one arch was ever scanned — the patient disappears from the result with no visible error, only a line in the log.

Pitfall guideOnly T0, T1 and T2 are recognized

The clinical timepoint is read from the file name, and only those three values count. A file marked T3 or beyond matches nothing: the patient is simply left out.

Pitfall guidePer-patient ROI: matching breaks on an underscore

Volume names and ROI names aren't split the same way when they're compared. Patient IDs without an underscore ( MA0001_Scan.nii.gz / MA0001_ROI.mrk.json ) match fine; an underscore inside the ID itself breaks the pairing and that patient gets skipped, without stopping the rest of the batch (a warning is written to the log).

Pitfall guideRead every line, carefully

For most tools, the mapping between what Agent believes it's passing and what the tool actually expects is off. A run can therefore start with wrong values without any error warning you beforehand — the confirmation dialog is your only real check.

Pitfall guideRoot canal is checked by default, with no model

"Root canal" is checked by default in the structure list, but the published model bundle has no model for it. Checking it produces neither an error nor a segmentation: the failure is silent, the structure is simply missing from the result.

Pitfall guideScanned PDF

PDF text extraction doesn't do OCR: if your PDF is actually a scanned image, the extracted text is empty and the note can't produce anything.

Pitfall guideSome advertised formats no longer work

The interface still offers meshes ( .vtk , .vtp , .stl , .off , .obj ) as input scans for intraoral surfaces, and matrices as .npy — both get counted in the progress bar, but neither produces any output: each file of that kind is simply skipped, with a line in the error log. A .txt matrix only works if it's an actual ITK transform file, not a plain 4×4 array.

Pitfall guideSteeply tilted arch: the patch can overshoot

The butterfly patch's outline is decided by flattening the arch into a projection. On a strongly tilted arch, that projection can pick up points that are actually far away in height, producing a patch that spills past the intended area — check the preview before committing.

Pitfall guideSwitching models later can wipe the others' weights

Re-downloading or updating DentalSegmentator's weights clears the entire models folder, including anything already downloaded for PediatricDentalsegmentator, NasoMaxillaDentSeg, and UniversalLabDentalsegmentator. If you switch between models, expect to re-download them.

Pitfall guideTables inside a .docx

Only paragraph text is read from a Word document; table content is skipped. If your key information sits in a table, it never reaches the model.

Pitfall guideTemporary folders are never cleaned up

Whether after an automatic registration or a manual session, the module does not clear its working folders. On a long series, disk usage builds up; clean them yourself from time to time — but only after saving your results, since that is also where "Save Registered Volume" pulls its file from in Automatic mode.

Pitfall guideThe CBCT surface threshold is fixed

The surface extracted from the CBCT for registration always uses the same threshold value, whatever your scanner or reconstruction. On a CBCT whose units aren't calibrated, the resulting surface may not correspond to bone or teeth at all, and the registration then runs against noise.

Pitfall guideThe Ortho model won't download

The file the module asks for the Ortho model doesn't exist at the address listed on Hugging Face: the download fails with "Download failed or was cancelled", with no further explanation. TMJ mode downloads fine. If you pick Ortho today, expect this failure — it isn't something on your end.

Pitfall guideThe ROI must be an axis-aligned box, saved as-is

The fast crop path completely ignores the orientation and coordinate system declared in the ROI file: it only reads the center and size, and assumes a box aligned with the volume's axes. A rotated ROI gets treated as if it weren't, and an ROI saved in the wrong coordinate system shifts the center with no error message at all. The fast path only works with straight boxes, saved the way Slicer stores them by default; for a genuinely rotated ROI, see below.

Pitfall guideThe dashboard progress bar never moves

Unlike the Summarize path, the Dashboard progress bar stays still for the whole run. That isn't a sign it's stuck: let it run and wait for dashboard.png to show up in the output folder.

Pitfall guideThe first run needs internet access

Building the network downloads generic pretrained weights before the trained model is applied on top. Without a connection on the first attempt, processing fails.

Pitfall guideThe heaviest module in the extension

VFACE is not a standalone tool: it's an orchestrator that chains, one after another, six other modules of the extension (resampling, orientation, bone segmentation, registration, dental surface segmentation, classification). On a batch of patients, expect the full run to be long — on the order of an hour per patient depending on your machine — and it keeps the other tools busy while it runs. Plan to launch it when you don't need the other modules at the same time, typically overnight on a series.

Pitfall guideThe interface rejects formats the crop itself accepts

The interface's input check only recognizes compressed volumes ( .nii.gz , .nrrd.gz , .gipl.gz ). A folder of uncompressed .nii or .nrrd files gets rejected ("Wrong type of patient file detected") even though the crop itself handles them fine: decompress them, or don't mix the two in the same batch.

Pitfall guideThe map only shows part of what mattered

The model decides by combining two sources: the shape of a sampled point cloud and a rendering of several views of the mesh. The explainability map only describes the second one. If a decision leaned mostly on the point-cloud geometry, the map you see will look faint — with nothing to tell you that's the reason, rather than the decision genuinely having no clear focus.

Pitfall guideThe mirror isn't centered on your patient

The reflection happens across the sagittal plane of the scene's origin, not the patient's own sagittal plane. If your patient isn't already centered in the scene, the result will come out both mirrored and shifted — plan on a registration step afterward to correct the offset.

Pitfall guideThe model download button does nothing

Clicking the download button creates the expected folder but never puts a file in it: the field stays empty and a warning message appears. Get the model archive yourself from the GitHub releases page of the SlicerAutomatedDentalTools repository (the BART.zip file, under the "MedX" release), unzip it, then point the module at that folder.

Pitfall guideThe output folder has to exist before you launch

If the folder you point to doesn't exist yet, the model download is simply skipped, and the error only surfaces later, when the model tries to load. Create the output folder yourself before starting.

Pitfall guideThe saved matrix can drift slightly from the best alignment found

The .tfm file and the registered CBCT stay consistent with each other, but both can drift a bit from the alignment the registration actually found as optimal. The gap depends on where the skull sits in the volume, and stays small when your images are already well centered — which is the case after a run through Orientation & Registration. If you reuse this matrix elsewhere, in AutoMatrix for instance, always check the overlay by eye before trusting it.

Pitfall guideThe test-files button doesn't fill anything in by itself

It does download an archive, but it only fills in the input and output folders if another module's test data (VFACE's) is already present on the machine. On a machine without it, clicking the button has no visible effect.

Pitfall guideThe written matrix doesn't quite match the produced image

The transform file ( .tfm ) saved at the end of registration doesn't fully capture the internal computation: a reference point for the final rotation is lost on writing. The already-registered MRI the module gives you is reliable; but if you reload the matrix in another program to apply it yourself, expect a slight mismatch with the result produced here.

Pitfall guideThis does not anonymise images

Despite the name, no DICOM tag is touched — not the patient's name, birth date, study identifier, or institution — and no face is removed from a CBCT or scanner volume. If images are what you need de-identified, this tool does nothing for you: you need a dedicated DICOM anonymiser, plus separate defacing if the volumes cover the face.

Pitfall guideTwo files with the same name, only one comes out

The output folder is written flat: the input's subfolder structure isn't reproduced, and if two subfolders each hold a file with the same name, the second one silently overwrites the first. Rename ahead of time if that's a risk.

Pitfall guideTwo model files in the folder

With more than one model file in the models folder, whichever name sorts first alphabetically gets used, with no warning. Keep a single .pth file in that folder to avoid any ambiguity.

Pitfall guideTwo paths that crash the module

In manual approximation, "Confirm & Save Alignment" crashes if the MRI volume was picked from the scene's drop-down list: only loading it through "Load from Folders Above" works reliably. And in resampling, processing T2 MRIs without also filling in the T1 fields crashes the step — always fill in both, even if one of the two folders stays empty.

Pitfall guideTwo runs, not necessarily the same result

The points sampled from the mesh are not drawn the same way twice. Two passes on the same files can therefore produce slightly different saliency maps, and in cases sitting near the boundary between two classes, a different predicted class.

Pitfall guideTwo runs, two different summaries

The model isn't deterministic: running the Summarize path again on the exact same documents won't reproduce the previous summary word for word. If you need to compare results over time, keep the _summary.txt files you already have rather than regenerating them.

Pitfall guideUniversalLabDentalsegmentator does not segment the skull

Its description in the interface — and the upstream model's own documentation — suggests it includes the skull. It doesn't: its 55 structures are teeth, mandible, maxilla, and the mandibular canal, with no "skull" structure at all. Don't reach for this model expecting a cranial segmentation.

If an output file already exists under the expected name, ASO does not rewrite it and still reports success. After fixing a setting, point to an empty output folder rather than rerunning on the same one.

Note guideSix tabs, not one button

Each tab has its own button and writes its files to its own folder; nothing in the module stops you from running them out of order or skipping one. Two tabs are genuinely optional (the left/right crop and the joint crop); the others only look optional — without them, the final registration starts with no starting point and won't converge.

Note guideThe interface looks frozen

That's expected: processing runs on Slicer's main thread. On a large folder, leave it running and don't close Slicer, even though nothing else responds in the meantime.

Note guideThe progress bar can announce more patients than it will deliver

The interface's counter also recognizes .nrrd , .nii and .gipl for the CBCT. The engine itself only accepts .nii.gz : a patient counted at the start may never actually be processed.

Note guideThree modes, one real registration

Only Automatic Registration actually performs an intensity-based registration. Manual Alignment and Distant Registration only prepare a starting point, to be refined afterward.

Note guideThree ways to get there

Depending on what you already have — nothing, raw scans, or landmarks already placed — the module offers three modes that don't ask for the same input files. See "Three modes" below before you start.

Note guideTwo data types, two ways of working

You first tell ASO what kind of files you have: CBCT for a volume, IOS for an intraoral scan. For each, two modes are available. Fully-Automated asks only for your raw scans: ASO places the landmarks it needs itself (via a network, for a CBCT) or segments the teeth (for a scan) before orienting. Semi-Automated skips that prediction step and works directly on landmarks or teeth you have already identified — faster, but it assumes that preparatory work already exists.

Note guideTwo engines, one window

The module picks the right engine on its own based on your data: CBCT for a volume, IOS for an intraoral scan. All you do is say what type your files are and which points you want.

Note guideTwo independent paths

MedX has two tabs, two buttons, and nothing chains them together automatically. Summarize reads your documents and writes one summary file per patient. Dashboard reads those summaries back and produces the figure page. Once summarization finishes, it's on you to switch tabs and launch the dashboard yourself — it doesn't start on its own.

Note guideTwo modes, one per arch

Butterfly (upper arch): the module predicts the stable palatal patch itself, with a network, and uses it as the registration anchor. MGL (lower arch): there's no palate down there, so the module builds a band along the mucogingival line instead, from landmarks it places automatically.

Note guideTwo ways to build the stable area

On an upper arch, the area is anchored on the palate: pick four reference teeth and FlexReg builds a butterfly-shaped patch around them, or draw its outline directly with the mouse. On a lower arch, with no palate to act as a stable plate, FlexReg instead relies on the mucogingival line — placed automatically — then thickens it into a band running along the gum.

Note guideWhich one to pick

Already have masks? Semi-Automated. No masks, but T1 scans already oriented the same way? Fully-Automated. Neither? Orientation & Registration. In all three modes, you check one or more reference regions ( Cranial Base , Mandible , Maxilla ): each one runs its own independent registration, with its own output.

Note guideYour files aren't being picked up

Only .nii , .nii.gz , .gipl , and .gipl.gz are recognized, and only at the top level of the chosen folder — a scan in NRRD or sitting in a subfolder is silently ignored. Two different folders containing a scan with the same base name will overwrite the same output: give your files unique names.

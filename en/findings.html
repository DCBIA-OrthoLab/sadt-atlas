Also true with VISOR . The server moves landmark points through the inverse of the transform, so a scan and its landmarks keep the same relative motion. Applied to a volume, the matrix moves its content. Applied to a landmark file, it moves the points by exactly the same motion. That's what keeps a scan and its landmarks aligned after going through AutoMatrix: as long as you use the same matrix for both.

Note guideOutput folder and file formats

The output folder must already exist: AREG_IOS doesn't create missing subfolders. And your files keep their original extension on write even though the content is always rewritten in VTK format: a .stl or .obj coming out is not a strictly valid STL or OBJ file, so keep it for Slicer rather than handing it to another program.

Note guideRe-running on the same folder

Prediction columns are overwritten in place on every re-run, but columns left over from a different task are never cleared out: they sit side by side in the csv.

Note guideRerunning on a folder that already has output does nothing

If an output file already exists under the expected name, ASO does not rewrite it and still reports success. After fixing a setting, point to an empty output folder rather than rerunning on the same one.

Note guideThe interface looks frozen

That's expected: processing runs on Slicer's main thread. On a large folder, leave it running and don't close Slicer, even though nothing else responds in the meantime.

Note guideThe log disappears

The run log lives with the intermediate files, which are deleted after a successful run unless you tick "Keep the intermediate files".

Note guideThe progress bar can announce more patients than it will deliver

The interface's counter also recognizes .nrrd , .nii and .gipl for the CBCT. The engine itself only accepts .nii.gz : a patient counted at the start may never actually be processed.

Note guideThree ways to get there

Depending on what you already have, nothing, raw scans, or landmarks already placed, the module offers three modes that don't ask for the same input files. See "Three modes" below before you start.

Note guideTwo data types, two ways of working

You first tell ASO what kind of files you have: CBCT for a volume, IOS for an intraoral scan. For each, two modes are available. Fully-Automated asks only for your raw scans: ASO places the landmarks it needs itself (via a network, for a CBCT) or segments the teeth (for a scan) before orienting. Semi-Automated skips that prediction step and works directly on landmarks or teeth you have already identified: faster, but it assumes that preparatory work already exists.

Note guideTwo engines, one window

The module picks the right engine on its own based on your data: CBCT for a volume, IOS for an intraoral scan. All you do is say what type your files are and which points you want.

Note guideTwo independent paths

MedX has two tabs, two buttons, and nothing chains them together automatically. Summarize reads your documents and writes one summary file per patient. Dashboard reads those summaries back and produces the figure page. Once summarization finishes, it's on you to switch tabs and launch the dashboard yourself: it doesn't start on its own.

Note guideTwo modes, one per arch

Butterfly (upper arch): the module predicts the stable palatal patch itself, with a network, and uses it as the registration anchor. MGL (lower arch): there's no palate down there, so the module builds a band along the mucogingival line instead, from landmarks it places automatically.

Note guideTwo ways to build the stable area

On an upper arch, the area is anchored on the palate: pick four reference teeth and FlexReg builds a butterfly-shaped patch around them, or draw its outline directly with the mouse. On a lower arch, with no palate to act as a stable plate, FlexReg instead relies on the mucogingival line, placed automatically, then thickens it into a band running along the gum.

Note guideVISU also works on any folder

You can open VISU on any folder a tool wrote, with no server involved: it pairs the scan, the masks, the surfaces and the landmarks of each patient by file name. The only thing it fetches from a server is hosted sample datasets.

Note guideWhat it registers

The module does not match the two images' brightness. It asks a network to find the cranial base on the CBCT and another to find it on the MRI, then fits the two surfaces together. So the result is only as good as those two outlines, which is why it can pause to let you check them.

Note guideWhich one to pick

Already have masks? Semi-Automated. No masks, but T1 scans already oriented the same way? Fully-Automated. Neither? Orientation & Registration. In all three modes, you check one or more reference regions ( Cranial Base , Mandible , Maxilla ): each one runs its own independent registration, with its own output.

Note guideWrong side

The side of a single-joint MRI comes from its position in the file. If it is wrong, swap it at the first pause. If you did not pause, the module can still recover by trying the other side, but only when the first answer was a flip.

Note guideYour files aren't being picked up (legacy module only)

Only .nii , .nii.gz , .gipl , and .gipl.gz are recognized, and only at the top level of the chosen folder: a scan in NRRD or sitting in a subfolder is silently ignored. Two different folders containing a scan with the same base name will overwrite the same output: give your files unique names. With VISOR, NRRD files and subfolders are read, and the output keeps your folder tree, so same-named scans in different folders no longer collide.

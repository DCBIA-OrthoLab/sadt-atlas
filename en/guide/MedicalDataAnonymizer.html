MedicalDataAnonymizer — de-identify a text document

MedicalDataAnonymizer finds and replaces personal data — names, dates, addresses, ID numbers — inside text documents (.docx, .txt, .pdf, .csv, .xml, .odt). It is not a DICOM anonymiser: it never reads, modifies, or erases a single medical image.

On video
  • Medical Data Anonymizer: Your AI model who anonymize all your medical text files 41 s (overview) · DCBIA Videos channel
This does not anonymise images

Despite the name, no DICOM tag is touched — not the patient's name, birth date, study identifier, or institution — and no face is removed from a CBCT or scanner volume. If images are what you need de-identified, this tool does nothing for you: you need a dedicated DICOM anonymiser, plus separate defacing if the volumes cover the face.

A failure can look like a success

If processing a document fails, for any reason, the output file comes out with the original text untouched — and the interface still reports "Complete!" No counter, no report, no visible warning marks the difference: a document that was never anonymised is indistinguishable from a clean one until you open it yourself. Reopen and read through every output file before handing it off or publishing it.

When to use it

For a first pass over a batch of English-language reports, letters, or notes that need the most visible mentions stripped before you share or export them — not to declare a dataset de-identified in one step. The output still needs a read-through, and it doesn't substitute for renaming files or handling the images separately.

What it needs, what you get

What to provide

  • A folder of text documents: .docx, .txt, .pdf, .csv, .xml, or .odt
  • The dependencies installed once (a dedicated button), with Slicer restarted afterward
  • The categories of data to detect, checked in the list — seven are checked by default (names, phone numbers, emails, dates, addresses, US social security numbers, medical license numbers)

What comes out

  • A copy of each document, suffixed _anonymized, in the output folder
  • A file_mappings.csv file listing original and output file names — don't hand this out together with the documents
  • Your original files are left untouched, but their name is carried over as-is into the output files and into file_mappings.csv

Steps

  1. Install the dependencies (once), using the dedicated button. The module downloads Presidio and an English text-analysis model; Slicer then asks to be restarted.
  2. Point it to the source folder. It's walked in full, subfolders included; there's no need to process documents one at a time.
  3. Check the categories to detect. Only add what you actually need beyond the seven checked by default (credit card, IP address, URL, US driver's license…).
  4. Pick a replacement method in "Advanced Options": tag replacement (<PERSON>, the default), redaction, masking with asterisks, or hashing. A hash stays the same for a given name across documents, but it's neither salted nor keyed — treat it as a public pseudonym, not encryption.
  5. Set an output folder, then run "Anonymize Files". The interface freezes while it works — that's expected, let the progress bar run to the end.

Check the result

Before sharing anything, reopen every _anonymized file and compare it against the original: that's the only way to catch a silent failure (see above). Then rename the files yourself — the patient's name survives in the output file name — and don't attach file_mappings.csv to anything sent outside your team: it lists original file names, not a usable re-identification key.

What the detection misses

  • The language is fixed to English. A folder in French or any other language runs through the same model, with no warning, and recall drops sharply.
  • The default confidence threshold drops the least certain hits — typically rare or non-Anglo-Saxon names.
  • Hospital identifiers — medical record number, accession number, study ID, bed number — aren't searched for by any of the categories on offer.
  • Non-US ID numbers — a French social security number, an NHS number, a passport — aren't covered; only US formats are recognised.
  • Content that couldn't be extracted from a file (tables in a .docx, attributes in a .xml, a scanned PDF) is never analysed — it's neither carried over nor de-identified.
  • A .csv comes out with its columns rebuilt from the detected text: the original alignment isn't guaranteed.

If something's off

Dependency installation fails

It needs internet access to download Presidio and the language model. If installation errors out, check the connection and try again; Slicer will need restarting once it succeeds either way.

Two files with the same name, only one comes out

The output folder is written flat: the input's subfolder structure isn't reproduced, and if two subfolders each hold a file with the same name, the second one silently overwrites the first. Rename ahead of time if that's a risk.

A .csv comes out unreadable

It's the most fragile format here: columns aren't preserved as-is. For tabular data you need to keep usable, anonymise a separate text copy and rebuild the table by hand.

The interface looks frozen

That's expected: processing runs on Slicer's main thread. On a large folder, leave it running and don't close Slicer, even though nothing else responds in the meantime.

Further reading

No publication: the module assembles existing pieces (Presidio, spaCy). What is worth reading is what those pieces let through — automatic anonymisation is never complete.

Around the method

  • Alrazihi et al., Surgical Neurology International 2025 — Evaluating the accuracy of automated and semi-automated anonymization tools for unstructured health records. Evaluates Presidio itself on free-text records: the share of identifying data that survives the pass.
  • Stubbs & Uzuner, J Biomed Inform 2015 — Annotating longitudinal clinical narratives for de-identification: The 2014 i2b2/UTHealth corpus. The field's reference corpus and its annotation scheme: what counts, and what does not, as identifying data.
  • U.S. Department of Health & Human Services — Guidance Regarding Methods for De-identification of Protected Health Information. The HIPAA rule itself: the 18 identifiers to remove, and the only two methods that hold legally.

The tool's full bibliography — what was found, and what was looked for without success — is in its sources.

MedX — summarize reports, then build a dashboard

Despite the name, MedX never looks at an image: it reads written clinical reports (.pdf, .docx, .txt), has a local language model turn each one into a structured summary, and can then roll a whole cohort of those summaries into a single page of figures. Two distinct steps, worth knowing before you start.

When to use it

When you have a pile of free-text reports — clinical exam, radiographic exam, consultation notes — and want the clinical indicators out of them (age, pain, sleep, mouth opening, and so on) without reading each one by hand. Once you have those summaries, the second half of MedX lets you see the whole cohort at a glance: age breakdowns, associated disorders, average scores.

Two independent paths

MedX has two tabs, two buttons, and nothing chains them together automatically. Summarize reads your documents and writes one summary file per patient. Dashboard reads those summaries back and produces the figure page. Once summarization finishes, it's on you to switch tabs and launch the dashboard yourself — it doesn't start on its own.

What it needs, what you get

Summarize path

What to provide

  • A flat folder of reports as .pdf, .docx, or .txt (no subfolders)
  • File names where everything before the first "_" is the patient ID — several files sharing that ID are grouped and summarized together
  • The summarization model, downloaded once

What comes out

  • One <patient-id>_summary.txt file per patient, in free text
  • Your source documents are left untouched

Dashboard path

What to provide

  • The summary folder produced by the Summarize path (files must end in _summary.txt)

What comes out

  • A dashboard.png image: age, sleep, joint and muscle pain, mouth opening, across the whole cohort
  • A patient_data.csv table with one row per patient

Steps

Summarize the reports

  1. Download the model. Only needed once; without it, the Summarize path has nothing to work from.
  2. Point it to the folder of reports, named with a patient ID before the first "_".
  3. Set an output folder, then launch. A progress bar tracks patients as they're processed.
  4. Read through the summaries you get before relying on them — see below.

Build the dashboard

  1. Switch to the Dashboard tab. This doesn't happen on its own after summarization.
  2. Set the summary folder from the previous step as input.
  3. Set an output folder, then launch. On the first run, Slicer may ask to install a couple of Python packages (pandas, matplotlib) — accept.
  4. Check "Load in 3D Slicer" if you want the dashboard image to open directly in a view of the scene.

Reading the result

Each report's summary comes from a generative model: it writes free text, not a guaranteed form. The key: value format the dashboard expects is a habit the model learned, not an enforced rule — a malformed line is simply dropped, and silently missing from the dashboard. The model also samples part of its output: running the summary again on the same document doesn't produce the exact same text twice. For both reasons, a summary MedX generates is a starting point to read through, not a validated report — don't use it as-is for a clinical decision.

If something's off

The model download button does nothing

Clicking the download button creates the expected folder but never puts a file in it: the field stays empty and a warning message appears. Get the model archive yourself from the GitHub releases page of the SlicerAutomatedDentalTools repository (the BART.zip file, under the "MedX" release), unzip it, then point the module at that folder.

The dashboard progress bar never moves

Unlike the Summarize path, the Dashboard progress bar stays still for the whole run. That isn't a sign it's stuck: let it run and wait for dashboard.png to show up in the output folder.

An empty input folder crashes the module

Running either path on a folder with no usable document raises an error instead of a clean message. Check that the folder you picked actually has files in it before you launch.

Two runs, two different summaries

The model isn't deterministic: running the Summarize path again on the exact same documents won't reproduce the previous summary word for word. If you need to compare results over time, keep the _summary.txt files you already have rather than regenerating them.

Further reading

On MedX itself

  • Gaydamour et al., CLIP 2025 (LNCS 16126) — AI-Driven Multimodal TMJ Patient Modeling: From Unstructured Notes to Precision Treatment. The paper for the pipeline MedX is the text link in: going from free reports to usable data.

Around the method

  • Lewis et al., ACL 2020 — BART: Denoising Sequence-to-Sequence Pre-training for Natural Language Generation, Translation, and Comprehension. The upstream model MedX fine-tunes. Explains what the summariser can do — and that it rephrases, so it can invent.
  • Bianchi et al., Seminars in Orthodontics 2021 — Decision Support Systems in Temporomandibular Joint Osteoarthritis. The clinical context: which decision these extracted data are meant to serve.

The tool's full bibliography — what was found, and what was looked for without success — is in its sources.

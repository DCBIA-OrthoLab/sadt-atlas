GreedyReg — register two CBCT scans with the ITK-SNAP engine

GreedyReg aligns two CBCT scans of the same patient (a T1 and a T2) by driving the ITK-SNAP greedy engine. No neural network in the main computation, nothing to install: the result comes from a classic intensity-based optimization, not a prediction.

When to use it

To register two CBCT scans of the same modality — a before/after follow-up, for instance — when you want fine control over the computation: which metric, how many degrees of freedom, optionally a mask to focus the optimization on one region. It is an end-of-chain tool: nothing else in SADT consumes its result. If you need the resulting transform to be reused elsewhere in Slicer, this is not the right module — its matrix stays specific to greedy and is not a Slicer transform file.

Three modes, one real registration

Only Automatic Registration actually performs an intensity-based registration. Manual Alignment and Distant Registration only prepare a starting point, to be refined afterward.

What you need, what you get

To provide

  • Two folders of CBCT scans in .nii.gz: one for the fixed volume (T1), one for the moving volume (T2)
  • File names starting with letters then digits, for example A01_T1.nii.gz — that is what lets GreedyReg pair a T1 with its T2 for the same patient; any other naming is never paired, with no warning
  • Optional: a mask (segmentation or labelmap), in the space of the fixed volume
  • Optional: an initialization matrix, or a manual pre-alignment done inside the module

What comes out

  • The T2 resampled into the T1 grid, as .nii.gz, plus the affine matrix found
  • In Distant mode: only a starting matrix, never a registered volume
  • The matrix produced is in greedy's own format, not Slicer's transform format: it does not load as a transform node as-is, and nothing else in SADT reuses it

The three modes, and which one to pick

  • Manual Alignment. You move the moving volume by hand (sliders, or the "Center T2 on T1" button for a quick centering). Useful when the two CBCT scans are already close and only a rough adjustment is missing before running the actual computation.
  • Automatic Registration. The only mode that actually registers: the greedy engine optimizes a rigid or affine transform from image intensities. This is where you pick the metric (NMI by default, for heterogeneous intensities; NCC for a local correlation; SSD if both volumes share the same modality) and the degrees of freedom (rigid or full affine).
  • Distant Registration (Large Misalignment). For two scans that start out geometrically far apart. "Distant" describes that gap, not a remote computation: nothing leaves your machine besides the one-time download of the engine and of the prediction weights, never patient data. This mode predicts a handful of anatomical landmarks (cranial base, mandible, or maxilla — one region at a time) and derives a starting matrix from them. It never produces a registered volume: always follow it with Automatic Registration to refine.

In practice: if your two CBCT scans are already roughly superimposed, go straight to Manual then Automatic. If they are far apart, start with Distant Registration, then refine with Automatic.

Steps

  1. Split your volumes. One folder for the fixed CBCT scans (T1), one for the moving ones (T2), with the same patient identifier in each file name.
  2. Add a mask if needed. It must be in the space of the fixed volume: that is where the optimization will look for its gradient.
  3. Pre-align if the misalignment is large. By hand in Manual mode for a small gap, via Distant Registration for a large one.
  4. Switch to Automatic Registration. Pick the metric and the degrees of freedom (rigid or affine), then run.
  5. For a series, point directly at the full T1/T2 folders: batch processing chains the pairs matched by identifier.
  6. Save the result before closing Slicer — see below why that matters.

If something goes wrong

"Save Registered Volume" does nothing in Distant mode

This mode does not produce a registered volume, only a starting matrix: the button always answers "No result to save!". Use "Save Transform Matrix" instead, or go straight to Automatic Registration to get a volume worth saving.

Misleading checkboxes in Distant mode

Checking several structures (cranial base, mandible, maxilla) does not combine them. Only one region is actually used, chosen by a fixed priority order (cranial base first, then mandible, then maxilla), regardless of which boxes you checked.

In batch, one failure stops everything, not always clearly

On a full folder, the first case that fails halts the entire run: no resume, no list of the remaining cases. In Distant mode, a failed landmark prediction does not always surface as an obvious error: the only visible sign can be a quiet "only 0 matched landmarks" in the log.

Temporary folders are never cleaned up

Whether after an automatic registration or a manual session, the module does not clear its working folders. On a long series, disk usage builds up; clean them yourself from time to time — but only after saving your results, since that is also where "Save Registered Volume" pulls its file from in Automatic mode.

And after

Always check the result by eye, overlaying the registered volume on the fixed CBCT in Slicer, before using it for a measurement. And keep in mind that the exported matrix is a plain greedy-format file, not a Slicer or ITK transform: reusing it outside this module needs a conversion that GreedyReg does not perform itself.

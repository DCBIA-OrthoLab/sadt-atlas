FlexReg — register two scans by drawing the stable area yourself

FlexReg registers two intraoral scans of the same patient taken at different times. Instead of letting a network guess which area hasn't moved, you mark it yourself, with the mouse, on the upper or lower arch.

When to use it

Reach for FlexReg when AREG_IOS — the automatic version — can't find a good registration area on its own: a partially edentulous arch, an unusual palate shape, or simply a case where you'd rather keep control over what counts as the fixed reference. FlexReg is the "draw it yourself" version of the same registration: both tools produce and read the same kind of landmark, so you can start in one and continue in the other.

Two ways to build the stable area

On an upper arch, the area is anchored on the palate: pick four reference teeth and FlexReg builds a butterfly-shaped patch around them, or draw its outline directly with the mouse. On a lower arch, with no palate to act as a stable plate, FlexReg instead relies on the mucogingival line — placed automatically — then thickens it into a band running along the gum.

What you need, what you get

To provide

  • Two scans of the same patient, as .vtk or .stl (.stl is converted automatically)
  • A "moving" scan (the more recent one) and a "fixed" scan (the reference)
  • Teeth identified crown by crown — if not, FlexReg runs the segmentation itself, at the cost of a wait on that first pass
  • A graphics card (GPU) — required to build the patch

What comes out

  • A registered scan in .vtk, saved next to the original
  • A transformation matrix (.tfm) reusable by the other tools in the repository
  • A preview shown in the scene before anything is saved

Steps

  1. Load both scans. Mark which one is moving (the one being aligned) and which one is the fixed reference.
  2. Check the tooth identification. If the arch has no segmentation array yet, FlexReg computes one on its own the first time — expect extra time on that run only.
  3. Build the stable area. On an upper arch, pick four reference teeth and shape the butterfly patch with the sliders (position, length, width), or draw its outline freehand. On a lower arch, let FlexReg place the mucogingival landmarks, then adjust the band's height around them.
  4. Preview. The preview button runs the registration into a temporary folder and shows the result in the scene without saving anything — use it to judge whether the area you chose gives a good alignment.
  5. Run the final registration once you're satisfied, and pick where to write the result.

How long it takes

Building the patch and running the registration take a few seconds per pair of scans on a GPU, once the area is drawn. The slow step is crown segmentation on the first pass over an unidentified arch — that wait happens once per scan and isn't repeated afterward.

If it gets stuck

A graphics card is mandatory

Building the patch and running the registration only work with a compatible GPU. Without one, these steps fail outright — this isn't a performance nicety, it's a hard requirement of the module.

"The registration only looks at the teeth I checked"

FlexReg aligns only the area you marked out — never the whole arch. If the result looks off away from that area, that's expected: the rest of the mesh simply follows the motion computed on the patch, it isn't registered independently.

Mucogingival landmarks can be unreliable

On the lower arch, some automatically placed points can be markedly less trusted than the others (the measured error jumps from roughly 1 mm to over 4 mm in those cases). FlexReg drops them by default and bridges the gap by interpolation — so a point can look "missing" even though it was detected.

DICOM import

Start from already-exported .vtk or .stl files. The registration itself doesn't read DICOM.

Input file gets overwritten

Drawing the stable area and running crown segmentation both rewrite the input file, not a copy. Always keep a backup of your original scans before you start.

Steeply tilted arch: the patch can overshoot

The butterfly patch's outline is decided by flattening the arch into a projection. On a strongly tilted arch, that projection can pick up points that are actually far away in height, producing a patch that spills past the intended area — check the preview before committing.

What happens next

The registered scan and its transformation matrix are ready to use directly in AREG_IOS and in the other tools in the repository that overlay scans across time. As with any automatic registration, a quick visual check before using it for a measurement is still good practice.

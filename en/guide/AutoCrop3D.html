AutoCrop3D — crop a series of volumes

AutoCrop3D batch-crops a folder of volumes to a shared region of interest, or to a separate region per patient. No network, no model to download: it's a geometric crop, near-instant, that never touches your voxel values.

When to use it

Any time a series is too large or too inconsistent in field of view to process as is: run it before a segmenter (AMASSS, BatchDentalSeg) to shrink what needs processing, or after one to keep only the useful region. AutoCrop3D can also generate a VTK mesh from a segmentation you already produced, for a quick preview.

Preparing the region of interest

The region to crop comes from a single Slicer ROI file (.mrk.json) and nothing else: place a Markups > ROI box in the scene on a representative patient, adjust it, and save it. Two ways to use it: one ROI applied to every volume in the folder, or one ROI per patient — in that case, name each ROI file with the same prefix as its matching volumes, so the pairing works (see below).

The ROI must be an axis-aligned box, saved as-is

The fast crop path completely ignores the orientation and coordinate system declared in the ROI file: it only reads the center and size, and assumes a box aligned with the volume's axes. A rotated ROI gets treated as if it weren't, and an ROI saved in the wrong coordinate system shifts the center with no error message at all. The fast path only works with straight boxes, saved the way Slicer stores them by default; for a genuinely rotated ROI, see below.

What it needs, what you get

What to provide

  • A folder of volumes — .nii.gz, .nii, .nrrd.gz, .nrrd, .gipl.gz, or .gipl
  • An ROI file (.mrk.json), or a folder with one ROI per patient
  • An output suffix ("cropped" by default)

What comes out

  • One cropped volume per input, mirroring the input folder structure
  • Optional: a VTK mesh per cropped segmentation
  • No transform file — the geometry lives entirely in the volume itself

Steps

  1. Place and save your ROI. One box for the whole series, or one per patient, named to match its volumes.
  2. Point it to the input volume folder. AutoCrop3D processes the whole folder in one go.
  3. Set the ROI file or folder. A single file gets applied to everyone; several get matched per patient.
  4. Choose an output suffix, and if you need it, "Keep the same size as input" to preserve the full original geometry, with everything outside the ROI set to zero.
  5. Rotated ROI only: check "Use module Crop Volume for tilted images" — read the warning below before you do.
  6. Set an output folder, then run it.

What's preserved

This is the whole point of the tool: the default crop path never resamples. It just extracts a block of voxels and recomputes the volume's origin; spacing, orientation and voxel values stay bit-for-bit identical to the original. In practice, a registration matrix computed on the full volume stays valid, unchanged, on the cropped volume, because the physical coordinates never moved — you can crop after registering without recomputing anything.

If something's off

A folder with exactly one ROI file → error

If you're using per-patient ROIs but the folder holds only a single .mrk.json file, the module errors out instead of applying it to every volume. In that case, point it directly at that file as a single shared ROI rather than at the folder containing it.

Per-patient ROI: matching breaks on an underscore

Volume names and ROI names aren't split the same way when they're compared. Patient IDs without an underscore (MA0001_Scan.nii.gz / MA0001_ROI.mrk.json) match fine; an underscore inside the ID itself breaks the pairing and that patient gets skipped, without stopping the rest of the batch (a warning is written to the log).

The interface rejects formats the crop itself accepts

The interface's input check only recognizes compressed volumes (.nii.gz, .nrrd.gz, .gipl.gz). A folder of uncompressed .nii or .nrrd files gets rejected ("Wrong type of patient file detected") even though the crop itself handles them fine: decompress them, or don't mix the two in the same batch.

"Use module Crop Volume for tilted images": read first

This is the only way to handle a genuinely rotated ROI, but it changes two things. First, it resamples the volume into the ROI's own frame: voxel values get modified, so the "no resampling, registration matrix still valid" benefit no longer applies. Second, it clears the entire Slicer scene for every patient it processes: don't use it if you have data loaded that you want to keep.

Generating a VTK mesh from a segmentation

Triggers automatically whenever "seg" appears anywhere in the output path (a Segmentations/ folder, for instance). Treat it as a secondary, fragile feature: the mesh isn't guaranteed to line up exactly with the cropped volume, every structure comes out in the same color, and a segmentation with more than six labels produces no mesh at all — with no error message.

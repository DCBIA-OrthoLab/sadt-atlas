BatchDentalSeg — segment CT/CBCT scans in bulk

BatchDentalSeg segments your dento-maxillo-facial CT and CBCT volumes assembly-line style: point it at a folder, and it applies the same set of labels to every scan, one at a time. The choice that matters here isn't a network setting — it's the model. Each one segments different structures.

When to use it

Whenever you have several CT or CBCT scans that need the same anatomical structures segmented — skull, mandible, teeth, mandibular canal, or a tooth-by-tooth breakdown. BatchDentalSeg is a standalone tool: no other module in the repository calls it, and it doesn't prepare anything for a downstream module. It's an endpoint, not a step in a pipeline.

One extension to install first

BatchDentalSeg relies on the external Slicer extension NNUnet to run the computation. It doesn't install itself: get it through the Extensions Manager, then restart Slicer. Without it, the module shows a message and refuses to start.

Choosing a model

Four models are offered in the dropdown. They share the same engine and the same window, but they don't segment the same thing:

ModelWhat it segmentsBuilt for
DentalSegmentator 5 structures: upper skull (maxilla included), mandible, upper teeth, lower teeth, mandibular canal Permanent dentition (adult)
PediatricDentalsegmentator The same 5 structures, same breakdown Mixed dentition (child) — only the training data differs
NasoMaxillaDentSeg 6 structures: the maxilla is detached from the skull and output as its own structure When you need the maxilla isolated from the rest of the facial mass
UniversalLabDentalsegmentator 55 structures: all 32 permanent teeth numbered individually, 20 primary teeth, mandible, maxilla, mandibular canal Tooth-by-tooth segmentation, mixed or permanent dentition

Only DentalSegmentator is backed by a peer-reviewed publication (Journal of Dentistry, 2024, 453 CT scans from 7 institutions). The other three models are released by the team without an independent validation paper — treat their published training numbers as internal claims.

NasoMaxillaDentSeg: don't trust the displayed names or colors

On this model, the label and color shown on screen for four of the six segments don't match the real structure — for instance, what's displayed as "Upper Teeth" is actually the maxilla. This isn't just a display glitch: the value written into the exported file follows the wrong name too, and the mandibular canal segment can be dropped entirely from the export when no match is found. If you use this model, check each segment individually before trusting its name.

UniversalLabDentalsegmentator does not segment the skull

Its description in the interface — and the upstream model's own documentation — suggests it includes the skull. It doesn't: its 55 structures are teeth, mandible, maxilla, and the mandibular canal, with no "skull" structure at all. Don't reach for this model expecting a cranial segmentation.

What you need, what you get

To provide

  • A folder of scans in .nii, .nii.gz, .gipl, or .gipl.gz — no NRRD, and subfolders aren't scanned
  • The model you want, picked from the menu
  • An output folder

What comes out

  • Always: <name>_Segmentation.nii.gz, the label map on the original scan's geometry
  • Optionally: STL/OBJ meshes, VTK per structure or merged, binary NIfTI per structure, glTF
  • Your original scans are left untouched

Steps

  1. Install the NNUnet extension if you haven't already, and restart Slicer.
  2. Pick a model from the dropdown, based on which structures you need (table above). The first time you use a given model, its weights are downloaded automatically.
  3. Point it at the input folder. BatchDentalSeg processes the whole folder at once; scans that already have a segmentation can be skipped automatically (checked by default).
  4. Check the output formats you need beyond the label map, which is always written.
  5. Set the output folder and the device (GPU or CPU), then run. A queue works through the scans one at a time with a progress bar; its state is saved continuously, so you can close Slicer and pick up later where you left off.

Memory and time

A full-mouth CBCT can demand a lot of RAM during inference — the module's own notes cite a real case of a scan that filled 114 of a machine's 125 GB and got killed by the system. Three lines of defense are in place:

  • before starting, a scan whose estimated memory need exceeds your budget (85% of free RAM by default) is marked failed without ever starting;
  • during the run, a confirmed overrun on two consecutive checks stops the scan cleanly instead of letting the system lock up;
  • a Free memory button lets you reclaim memory by hand if any processes are left hanging after an abrupt stop.

If a scan fails for this reason, Retry failed offers an automatic crop around the tissue (15 mm margin) before trying again — the output is still placed back on the scan's original grid afterward. On a long batch, a cleanup pause happens every five segmentations.

The computation runs without a graphics card, but expect roughly one hour per scan instead of a few minutes. If the chosen device isn't available, the question of falling back to CPU is only asked once for the whole queue.

If something goes wrong

Switching models later can wipe the others' weights

Re-downloading or updating DentalSegmentator's weights clears the entire models folder, including anything already downloaded for PediatricDentalsegmentator, NasoMaxillaDentSeg, and UniversalLabDentalsegmentator. If you switch between models, expect to re-download them.

Your files aren't being picked up

Only .nii, .nii.gz, .gipl, and .gipl.gz are recognized, and only at the top level of the chosen folder — a scan in NRRD or sitting in a subfolder is silently ignored. Two different folders containing a scan with the same base name will overwrite the same output: give your files unique names.

And after

The label map is always written, whatever other formats you checked: open it in Slicer to check the segmentation before using it for a measurement or an export. With UniversalLabDentalsegmentator, the network sometimes mixes up left and right; a dedicated button corrects the laterality using the central incisors, without touching the original result. If a mesh export fails, the scan is still marked done — the label map is what counts.

Further reading

The original model is published and documented. The three variants added later — pediatric, universal labelling, naso-maxillary — are not: no training set, no evaluation.

On BatchDentalSeg itself

  • Dot et al., Journal of Dentistry 2024 — DentalSegmentator: Robust open source deep learning-based CT and CBCT image segmentation. The model this module runs: the five structures segmented, the training data, and the measured accuracy. Free to read.

Around the method

  • Isensee et al., Nature Methods 2021 — nnU-Net: a self-configuring method for deep learning-based biomedical image segmentation. The framework every model in the module rests on.
  • Sinard et al., Orthod Craniofac Res 2025 — Automated Cone Beam Computed Tomography Segmentation of Multiple Impacted Teeth With or Without Association to Rare Diseases: Evaluation of Four Deep Learning-Based Methods. An independent evaluation on hard cases — multiple impacted teeth — showing where the model holds and where it gives way.

The tool's full bibliography — what was found, and what was looked for without success — is in its sources.

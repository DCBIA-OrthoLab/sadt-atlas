CLIC — find and classify impacted canines on a CBCT

CLIC scans a CBCT slice by slice and flags impacted canines, telling you for each one where it sits relative to the bone: buccal, bicortical, or palatal. You start from the raw volume — no prior segmentation or landmarking needed.

The progress bar doesn't move — that's expected

While the tool runs, the progress bar stays at zero and nothing shows up in the Slicer scene, even after processing has finished. This is not a crash: the result file is written to disk in the output folder regardless. You have to go find it and load it yourself — see below where it lands.

When to use it

When you have a CBCT with one or more impacted canines and want to know, without inspecting each one by eye, which side of the cortical bone it sits on. CLIC has no dependency on other modules — you don't need to have run AMASSS, ASO, or ALI first.

What you need, what you get

Provide

  • A folder of CBCT scans in .nii or .nii.gz
  • The trained model, downloaded once
  • An output folder, chosen explicitly

You get

  • One subfolder per scan, holding a .nii.gz label map
  • Three possible voxel values: buccal, bicortical, palatal
  • Directly overlayable on the source scan, no registration needed
Accepted formats that don't actually work

The file picker also lists .nrrd, .mha, and .mhd. Don't use them: processing can only read .nii/.nii.gz, and fails on the other formats regardless of what the picker allowed.

Linux only

The module has no working path on Windows, whatever the README says. Run it on a Linux Slicer installation.

Steps

  1. Download the model. The dedicated button fetches the trained network. Do this once.
  2. Point it at the input folder. A flat folder of .nii.gz files — not a folder of subfolders.
  3. Choose an output folder. This step is mandatory: without one, processing fails before it even starts.
  4. Run. The first run also sets up the computing environment, so it takes longer than later ones.
  5. Wait it out, even if nothing moves on screen. Processing goes scan by scan with no visual feedback in between.

Where to find the result

Once processing is done, open the output folder you chose: it holds one subfolder per processed scan, and inside each, a .nii.gz file carrying the suffix shown in the interface (seg by default). Load that file into Slicer yourself as a segmentation volume — it's already aligned to the source scan, no registration required. Values 1, 2, and 3 correspond to buccal, bicortical, and palatal respectively.

If it gets stuck

Cancel does nothing

It stops neither the running computation nor the underlying process. If you genuinely need to stop, close Slicer.

The first run needs internet access

Building the network downloads generic pretrained weights before the trained model is applied on top. Without a connection on the first attempt, processing fails.

Two model files in the folder

With more than one model file in the models folder, whichever name sorts first alphabetically gets used, with no warning. Keep a single .pth file in that folder to avoid any ambiguity.

Further reading

The module has no publication yet: its only public description is a NA-MIC project page.

On CLIC itself

  • NA-MIC Project Week 43, Montréal 2025 — Interpretable Deep Learning for the Detection and Classification of Impacted Canines and severity of root resorption. The project report: the goal, the data, and where the work stood at that point.

Around the method

  • He et al., ICCV 2017 — Mask R-CNN. The architecture the module runs: detect objects and produce their masks at the same time.
  • Swaity et al., Scientific Reports 2023 — Deep learning driven segmentation of maxillary impacted canine on cone beam computed tomography images. The same problem addressed by another team, with the error measured on an independent series.
  • Pirayesh et al., BMC Oral Health 2024 — A hierarchical deep learning approach for diagnosing impacted canine-induced root resorption. On the root resorption side: how severity is graded, and how that compares with a human observer.

The tool's full bibliography — what was found, and what was looked for without success — is in its sources.

AMASSS — segmenting structures from a CBCT

AMASSS automatically segments the anatomical structures of a craniofacial CBCT — mandible, maxilla, cranial base, upper airway, cervical vertebra, skin — each predicted by a network trained for that structure alone. You don't tune contrast or windowing by hand: the module handles that itself.

When to use it

Whenever you need bone, airway, or skin segmentations from a CBCT — for a single patient or for an entire batch at once. AMASSS also runs behind the scenes in two other tools: AREG_CBCT uses it to register two CBCT scans of the same patient, and VFACE uses it for its asymmetry analysis. If you use either of those, part of AMASSS's work is already being done for you, without opening this module.

What it can segment

Six structures have a trained model available in the published bundle:

Each structure is predicted by a network that only knows that one structure: segmenting the mandible and the maxilla runs two independent computations, not a single multi-structure model. A few other entries appear in some settings lists (teeth, root canal, mandibular canal) but have no trained model in the published bundle — checking them segments nothing (details below).

What you need, what you get

To provide

  • A CBCT, or a folder of several CBCT scans, in .nii, .nii.gz, .nrrd, or .nrrd.gz
  • The trained models, to download once
  • The structures you want, checked in the list

What comes out

  • One binary mask per structure, or a single merged map where each structure carries its own value
  • If requested, 3D surface(s) (.vtk) colored by structure, ready to display
  • Your original scans are left untouched

Step by step

  1. Download the models. The "Download latest models" button opens a GitHub release page in your browser: unlike AREG_CBCT or VFACE, AMASSS does not download anything on its own — you fetch and install the archive yourself.
  2. Point it at the input. A single CBCT or an entire folder; AMASSS finds scans even inside subfolders.
  3. Check the structures you want from the list.
  4. Choose the output format. Separate segmentations, merged, or both; also check surface generation if you want .vtk meshes ready to display in the scene.
  5. Set an output folder and run with the "Predict" button. This is when dependencies get installed if they're still missing — not when the module opens.

How long it takes

AMASSS runs without a graphics card, but that's more theoretical than practical: on a batch of scans, the image-resampling step alone (without a GPU) costs roughly seven times the cost of the network itself. With a GPU, expect a reasonable computation per structure and per scan; without one, a batch of several patients quickly becomes impractical. One thing works in your favor: models are loaded once per structure, not once per scan — processing an entire folder at once costs little more than processing a single CBCT, structure by structure.

If something's stuck

"Small FOV" changes nothing about the computation

The checkbox that switches to a "high definition" list (teeth, root canal, and mandibular canal included) only changes which checkboxes are shown on screen. It does not reduce the field of view or the resolution of the computation — don't expect it to run faster or produce a finer result.

Root canal is checked by default, with no model

"Root canal" is checked by default in the structure list, but the published model bundle has no model for it. Checking it produces neither an error nor a segmentation: the failure is silent, the structure is simply missing from the result.

DICOM import

The interface offers "DICOM Files" as an input type, but no DICOM conversion actually happens before the computation runs: a DICOM input produces nothing. Use .nii.gz or .nrrd files instead.

Don't run two modules at once

AMASSS unconditionally wipes its temporary working folder every time it starts. That same folder is shared with AREG_CBCT and VFACE, which call AMASSS behind the scenes. If you run two of these modules at the same time on the same machine, one can wipe the other's working folder mid-run — let one computation finish before starting another.

And after

No automatic cleanup is applied to the segmentations produced — no hole filling, no keeping only the largest connected component: what you get is the network's raw output. Check it before using it for a measurement or a registration. For a single-file input with surface generation checked, the .vtk meshes are loaded directly into the scene once the computation finishes.

Further reading

The paper below describes the UNETR version of the module. What runs today is a switch to nnU-Net that nobody has published: citing it to describe AMASSS as it runs means describing an architecture that is no longer there.

On AMASSS itself

  • Gillot et al., PLOS ONE 2022 — Automatic multi-anatomical skull structure segmentation of cone-beam computed tomography scans using 3D UNETR. The structures segmented, the training data and the measured accuracy. Open access.

Around the method

  • Isensee et al., Nature Methods 2021 — nnU-Net: a self-configuring method for deep learning-based biomedical image segmentation. The foundation of the current version: a method that picks its own architecture and settings from the dataset.
  • Hatamizadeh et al., WACV 2022 — UNETR: Transformers for 3D Medical Image Segmentation. The architecture of the PLOS ONE paper, i.e. of the module's historic version.

The tool's full bibliography — what was found, and what was looked for without success — is in its sources.

Agent — let a local assistant pick the tool

Agent is a conversational assistant that runs entirely on your machine. You describe what you want to do, in plain language, and it proposes a tool from the extension already filled in with its parameters — or it just answers you, depending on the mode you pick.

Read this before you try it

As the repository stands today, Agent cannot locate the tools it wants to launch. Unless you configure it manually, any attempt to run a tool fails. The mode that only answers, without executing anything, is not affected and works normally.

When to use it

Use it when you don't want to hunt down which module in the extension matches what you need, or build a command line by hand: you describe the task — "orient these CBCTs", "segment these scans" — and Agent proposes a tool with the parameters it understood from your request. It also works as a plain consultant, in "Ask" mode, for questions that don't need anything run.

What to install first

Agent relies on a language-model server running locally on your machine, Ollama. If it isn't already present, the module offers to download and start it for you. Either way, expect the first launch to download several gigabytes — the language model alone is a bit over 5 GB — before you can ask your first question.

Nothing to install by hand on the Slicer side

The required Python packages install themselves automatically on first launch, inside Slicer's own Python.

What it needs, what you get

What to provide

  • A request written in plain language, in English or French
  • The mode you want: Agent (Automated) to actually run something, Ask (Interactive) to just talk
  • If relevant, the folders involved, dropped into the drop zone

What comes out

  • In Agent mode: a chosen tool, its parameters, a confirmation dialog, then execution if you approve
  • In Ask mode: a free-text reply, nothing is launched
  • If the tool fails, up to two automatic repair attempts, each with its own confirmation

Steps

  1. Make sure Ollama is running. If needed, let Agent install and start it for you, and wait out the model download on first launch.
  2. Pick a mode. "Agent (Automated)" to actually launch a tool, "Ask (Interactive)" to only get an answer.
  3. Describe what you want, in plain language, the way you'd explain it to a colleague.
  4. Drop the relevant folders into the drop zone if your request involves specific data — Agent will try to guess which is which.
  5. Send the message. In Agent mode, a tool and its parameters are proposed; in Ask mode, the answer comes straight back.

Reading the confirmation dialog

In Agent mode, nothing runs without a "Yes" from you, in a dialog that lists every parameter it settled on, as key=value pairs. This is the only point where you can catch a wrongly guessed folder or a value that doesn't match what you meant, before the tool actually starts.

Read every line, carefully

For most tools, the mapping between what Agent believes it's passing and what the tool actually expects is off. A run can therefore start with wrong values without any error warning you beforehand — the confirmation dialog is your only real check.

Once you approve, Slicer's interface freezes until the launched tool finishes running: that's expected, there's nothing to do but wait.

If something's off

"Nothing launches, or the error makes no sense"

As the repository stands, Agent can't find the scripts it wants to run on its own: unless you tell it yourself where they are, execution fails before it even starts. The automatic repair step that follows can't fix this — the problem isn't in the parameters, it's in the script's path.

A run starting with wrong values

See above: always check the confirmation dialog before approving. A parameter mismatch usually shows up only by eye, in that dialog — not in an error message.

Everything is slow without a graphics card

If the model server is running without a GPU, expect each reply to take roughly a minute and a half. A back-and-forth conversation adds up to minutes, not seconds.

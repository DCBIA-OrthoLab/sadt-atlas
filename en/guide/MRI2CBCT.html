MRI2CBCT — align an MRI and a CBCT of the TMJ

MRI2CBCT registers an MRI onto a CBCT of the temporomandibular joint (TMJ), so you can look at both exams in the same frame. It's a long pipeline — six independent steps, one per tab — but each one is short and sets up the next.

When to use it

Whenever you have, for the same patient, an MRI and a CBCT of the TMJ and you want them superimposed: bone shows up better on the CBCT, soft tissue (disc, capsule) better on the MRI, and registering the two lets you look at both at once instead of comparing them from memory. This isn't a one-click tool: plan on going through all six tabs, in order, for each patient.

Six tabs, not one button

Each tab has its own button and writes its files to its own folder; nothing in the module stops you from running them out of order or skipping one. Two tabs are genuinely optional (the left/right crop and the joint crop); the others only look optional — without them, the final registration starts with no starting point and won't converge.

What it needs, what it gives back

To provide

  • A CBCT and an MRI (T1 and/or T2) of the same patient
  • A segmentation of the condyle on the CBCT — you can supply it, or let the module produce it itself during the joint-crop step
  • Files named <ID>_CBCT…, <ID>_MR… or <ID>_MRI…, as .nii.gz — this shared identifier is what ties a patient's files together from one step to the next

What comes out

  • The MRI registered onto the CBCT, and the matrix of the applied transformation
  • Two volumes you can now overlay in the same scene — not a merged file
  • One folder per intermediate step, kept or deleted through a checkbox

Tab by tab

  1. MRI orientation / centering. Rewrites the header of the MRI volume (the voxels themselves don't move) to a fixed convention, and recenters the origin to match. If you check "Bilateral MRI", it also fixes the inter-slice spacing that this kind of acquisition often loses when converted to NIfTI. Mandatory in practice: the final registration has no starting transform and no search margin, so the MRI and CBCT need to already sit in comparable orientations before you get there.
  2. Left/right crop (optional). Useful if your acquisition covers both TMJs in a single volume: splits the CBCT, MRI and segmentation into a left half and a right half, to be processed side by side afterward.
  3. Resampling. Brings the CBCT, MRI and segmentation to a comparable spacing and recenters them — the defaults are 443 × 443 × 119 voxels at 0.3 mm, but each row of the table can be turned off to keep the input's own size and spacing. Mandatory in practice: without a comparable spacing, the final registration can't compare the two images properly.
  4. Approximation. Provides the rough starting alignment, without which the final registration won't converge. Two ways to get there: automatic, where the module locates the condyle on the CBCT to get an anchor point, then positions the MRI by comparing that point to the MRI's own center of mass; or manual, with rotation and translation sliders or handles you drag in the scene, plus a button to center the MRI on the CBCT before fine-tuning by hand. Either way, this step writes a new, already-moved MRI volume: that volume — not a separate transform file — is what you point to as the input MRI for the final registration.
  5. Joint crop (optional). Locates the condyle again, then reduces the CBCT, MRI and segmentation to a box centered on the joint. Tightens the field of view and speeds up registration; it can also produce the condyle segmentation the next step needs, if you haven't supplied one.
  6. Registration. The final step, the one that does the actual work. It needs a CBCT, an already-approximated MRI (step 4), and a segmentation of the condyle on the CBCT. The module then inverts the MRI's contrast (so bone turns bright there too, as it is on the CBCT), normalizes both modalities, masks both with the same segmentation, and registers the MRI onto the CBCT using a method based on mutual information — a comparison that doesn't assume the two images look alike, which matters since MRI and CBCT don't share the same kind of contrast.

If it gets stuck

An install prompt keeps coming back

Automatic dependency installation fails every time (a misspelled package name that doesn't exist). You'll see an installation error before almost every button, but the action carries on anyway regardless. If the rest of your setup is already in place, that changes nothing; but if condyle segmentation later fails without a clear message, this is the likely cause — the real dependency was never installed on its own, and you'll need to install it yourself.

Two paths that crash the module

In manual approximation, "Confirm & Save Alignment" crashes if the MRI volume was picked from the scene's drop-down list: only loading it through "Load from Folders Above" works reliably. And in resampling, processing T2 MRIs without also filling in the T1 fields crashes the step — always fill in both, even if one of the two folders stays empty.

The written matrix doesn't quite match the produced image

The transform file (.tfm) saved at the end of registration doesn't fully capture the internal computation: a reference point for the final rotation is lost on writing. The already-registered MRI the module gives you is reliable; but if you reload the matrix in another program to apply it yourself, expect a slight mismatch with the result produced here.

Files skipped without a word

Normalization and registration only accept .nii.gz — a .nii file is silently ignored, with no error. And during resampling, two files with the same name coming from different subfolders overwrite each other without warning. Use unique names per patient and check that every file you expect actually comes out.

Afterward

The original CBCT is never modified: only the MRI is moved and then registered. Open both volumes together in Slicer to visually check the overlay before using it for any measurement. If the final registration can't find a good alignment, the problem is almost always a too-rough starting approximation (step 4) rather than the registration itself — redo that step before trying again.

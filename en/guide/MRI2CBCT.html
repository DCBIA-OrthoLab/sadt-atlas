MRI2CBCT: align an MRI and a CBCT of the TMJ

MRI2CBCT registers an MRI onto a CBCT of the temporomandibular joint (TMJ), so you can look at both exams in the same frame. It is now one button: choose the folders, press Run, and the module prepares, orients, segments and registers for every patient.

When to use it

Whenever you have, for the same patient, an MRI and a CBCT of the TMJ and you want them superimposed: bone shows up better on the CBCT, soft tissue (disc, capsule) better on the MRI, and registering the two lets you look at both at once instead of comparing them from memory. You no longer go through tabs one by one: a single Run does the whole chain for every patient found in both folders.

What it registers

The module does not match the two images' brightness. It asks a network to find the cranial base on the CBCT and another to find it on the MRI, then fits the two surfaces together. So the result is only as good as those two outlines, which is why it can pause to let you check them.

What it needs, what it gives back

To provide

  • An MRI folder and a CBCT folder (.nii.gz, .nii or .nrrd)
  • Files whose names start with the patient ID (P01, B038…): this is how the two folders are paired. One CBCT per patient, one or two MRIs.
  • An output folder
  • A one-time setup: Python packages and models, about 5 GB, downloaded for you

What comes out

  • Per patient, a folder with each MRI joint registered onto the original CBCT, its cranial-base mask, and the transform file
  • A summary.csv with a verdict for every joint: OK, SMALL, FLAG or FLIP
  • Two volumes you can overlay in the same scene, not a merged file; the CBCT is never modified

What happens when you press Run

  1. Preparing the MRIs. Pairs the patients and, by default, resamples each MRI to 0.3 mm and splits a volume that holds both joints into a left and a right half. A volume with a gap between two stacks is rebuilt using the "acquisition slice spacing" you set (3.0 mm by default). The side of a single-joint MRI is read from where it sits in the file.
  2. Orienting the CBCT. Three automatic steps (the ones of the ASO module) put the head in the standard Frankfurt and midsagittal orientation.
  3. Cranial base on the CBCT. The AMASSS network outlines it.
  4. Cranial base on the MRI. A second network, Dataset516, outlines it on each joint. The default uses five model folds; one fold is faster on a computer without a GPU.
  5. Registering. Fits the MRI outline onto the CBCT outline. If the first answer is a flip (turned the wrong way), the module tries more attempts, a half-turn, the other side of the head, and finally a mirrored MRI, before giving up and marking the result _FLAGGED.

Options and checks

  • Use test files downloads a sample patient (one CBCT, two MRIs), fills the three folders, and keeps the expected result in a reference folder so you can compare.
  • Resample and Separate left and right are on by default. Turn separation off if each of your MRIs is already a single joint or a whole head.
  • Advanced: put the registered MRI on the CBCT's voxel grid (off by default: the MRI keeps its own voxels and only its position changes), keep the intermediate files, set the number of registration workers.
  • Review: tick "Pause during the run" and choose where. At each pause the images open in Slicer with the outline over them. At the first pause you can swap left and right for a patient if the side is wrong.

If it gets stuck

Restart after the first setup

If PyTorch had to be installed or replaced for your graphics card, the panel asks you to restart Slicer and press Run again. On Linux, the registration library needs a system with glibc 2.31 or newer.

A patient is skipped

A file with no ID at the start of its name, an MRI without a CBCT (or the reverse), or a patient with more than one CBCT is left out, and the panel lists them before it starts. Keep your output folder outside the MRI and CBCT folders: the folders are read recursively, so an earlier run's results could be picked up as new scans.

Read the verdict, not only the file name

A joint can come out FLAG (weak overlap) and still be saved under a normal file name; only summary.csv and the message at the end say so. SMALL means the MRI outline was very small, the case that most often fails. Anything tagged _FLAGGED, FLIP or _MIRRORED deserves a look before you rely on it.

Wrong side

The side of a single-joint MRI comes from its position in the file. If it is wrong, swap it at the first pause. If you did not pause, the module can still recover by trying the other side, but only when the first answer was a flip.

The log disappears

The run log lives with the intermediate files, which are deleted after a successful run unless you tick "Keep the intermediate files".

Afterward

The original CBCT is never modified. Open the registered MRI and the CBCT together in Slicer to check the overlay before using it for any measurement. If you need the transform for something else, load the original MRI and apply the .tfm to it: nothing is interpolated that way. A registration the verdict marks as flawed is better rerun with a review pause on the two outlines than adjusted by hand.

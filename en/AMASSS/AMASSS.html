AMASSS

Automatic multi-structure segmentation of craniofacial CBCT scans: one binary nnU-Net v2 network per anatomical structure, assembled and merged by the CLI.

Gillot 2022 · PLOS ONE AMASSS_CLI Slicer's Python, no conda Bibliography

1. Where it sits in the chain

AMASSS is both a terminal module (the AMASSS widget) and a building block reused by three other tools, all of which call the same CLI through slicer.modules.amasss_cli.

CallerFileUsage
AMASSS widgetAMASSS.py:1638operator-driven segmentation
AREG_CBCT (semi-auto, fully-auto, oriented)CBCT.py:341, 470, 555, 840, 918two distinct roles: registration masks (merge=SEPARATE, genVtk=False) before AREG, then deliverable segmentations afterwards
VFACEcreatelistprocess.py:126segmentation within the asymmetry-analysis chain

AMASSS calls nothing else: no conda subprocess, no other module. Its only external dependency is the pip package nnunetv2, imported lazily in the functions that use it.

An important distinction for AREG: the CBMASK / MANDMASK / MAXMASK codes are not post-processing steps applied to the CB / MAND / MAX segmentations — they are separately trained models, on different data and at a different resolution (§4).

2. Files involved

FileRoleWhere it runs
AMASSS/AMASSS.pySlicer widget, 1654 lines, of which ~450 are light/dark stylesheetsSlicer's Python

AMASSS_CLI/AMASSS_CLI.xmldeclaration of the 12 positional parameters—

The CLI is not launched inside a conda environment: slicer.cli.run starts it in Slicer's Python, and since the September 2026 port (109e1ed) nnU-Net inference runs in this same process, no longer in a child nnUNetv2_predict.

CUDA is not required: ResolveDevice() (AMASSS_CLI.py:81) falls back to CPU while logging it. In practice CPU is unusable on a batch (single-core scipy resampling dominates, cf. §5.1).

The arguments are positional and read by index from sys.argv (AMASSS_CLI.py:922), with no argparse despite the import. The order in the XML is therefore authoritative: inputVolume (file or folder), modelDirectory, skullStructure (comma-separated codes), merge (MERGE / SEPARATE / both, split on [, ]+), genVtk, save_in_folder, output_folder, vtk_smooth, prediction_ID (default Pred), temp_fold (wiped on startup), SegmentInput, DCMInput (never used).

Pitfall

The widget also builds param["highDefinition"] (AMASSS.py:935): this parameter does not exist in the XML, it is silently dropped. See §9.

3. Inputs and preprocessing

3.1 File discovery

main() accepts a file or a folder, walked with a recursive os.walk (AMASSS_CLI.py:676) — necessary because AREG writes its registered scans to <output>/<Region>/<patient>_OutReg/. Extensions kept: .nii, .nii.gz, .nrrd, .nrrd.gz. Two filters: any name containing MASK is skipped, and if isSegmentInput is false, any name containing _<prediction_ID>_ is skipped too — it is the output of a previous run, and re-segmenting it would produce an empty mask.

Pitfall

The widget, for its part, counts files with a different extension list (.gipl included) and different exceptions ["Seg","seg","Pred"] (AMASSS.py:682): the "Number of scans to process" counter and what the CLI actually processes can diverge.

3.2 Conversion

PrepareScanForNnunet() (AMASSS_CLI.py:557) copies each scan into a single folder <temp>/nnunet_input/ under the name p_<NNN>_0000.nii.gz (NNN = three-digit index, in discovery order). A .nii.gz is copied as-is; everything else is re-read and rewritten by SimpleITK. This is not cosmetic: the earlier version did a shutil.copy of an NRRD to a .nii.gz name, and nnU-Net's reader picks its format from the extension — NRRD, Slicer's default format, was therefore broken in practice. The voxel type is left untouched, since nnU-Net casts to float32 itself.

3.3 What AMASSS no longer does

No intensity normalization, no windowing, no resampling is written in this repository. CorrectHisto() (AMASSS_CLI.py:271) still exists, with an emptied body: it reads the image, casts it to float32 and returns it — no percentiles, no clipping, no write, despite its (min_porcent, max_porcent, i_min, i_max) signature. It is called nowhere: dead code.

All the effective preprocessing is nnU-Net's own, described by the plans.json of each model (§4.2): resampling to the target spacing, then CTNormalization (clipping to the 0.5% / 99.5% percentiles of the foreground intensities of the training set, then centering-scaling by the mean and standard deviation of that same set). The per-model values live in the bundle's plans.json, not in the repository.

4. The models

4.1 The bundle and its discovery

FindModelFolder() (AMASSS_CLI.py:89) looks, for each structure code, for:

<modelDirectory>/<CODE>/**/<Dataset...>__nnUNetPlans__3d_fullres/fold_0/checkpoint_final.pth

A candidate is only accepted once the fold_0 checkpoint is confirmed present; otherwise the structure is declared unavailable and the run continues with the others. Discovery happens once for the whole run.

Download: the Download latest models button simply opens a browser (AMASSS.py:738) on MODEL_LINK, the releases/tag/AMASSS_CBCT page — no automatic download on the AMASSS side. The archive is AMASSS_Models.zip, which AREG (CBCT.py:124, 617) and VFACE (VFACE.py:959) do download automatically. ALI still goes through a personal repository, lucanchling/AMASSS_CBCT v1.0.2 (AMASSS_Models.zip + Masks_Models.zip, CBCT.py:107). The README still points to ALL_NEW_MODELS.zip and a commented-out line to ALL_MODELS.zip: relics of the monai era, these archives held raw .pth files.

4.2 What the bundle actually contains

Surveyed on the decompressed bundle (AMASSS_Models.zip, outside the repository): nine folders, one per code, each containing Dataset001_myseg/nnUNetTrainer__nnUNetPlans__3d_fullres/ with dataset.json, plans.json and fold_0/checkpoint_final.pth. A single fold.

Two families, distinguished by their plans.json: full-FOV (MAND, MAX, CB, CV, UAW, SKIN) at 0.4 mm isotropic, patch 128³, numTraining = 76; and masks (CBMASK, MANDMASK, MAXMASK) at 0.3 mm isotropic, patch 112 × 160 × 128, numTraining = 50.

Architecture, identical across both families (architecture field of the plans.json):

dynamic_network_architectures.architectures.unet.PlainConvUNet
n_stages = 6            features_per_stage = [32, 64, 128, 256, 320, 320]
kernel_sizes = 6 x [3,3,3]          n_conv_per_stage = [2,2,2,2,2,2]
n_conv_per_stage_decoder = [2,2,2,2,2]
norm_op = InstanceNorm3d (eps 1e-5, affine)   conv_bias = True
Code / paper divergence

This is not a monai.networks.nets.UNet: neither channels, nor strides, nor num_res_units appear anywhere. PlainConvUNet is the convolutional U-Net that nnU-Net configures itself, with no residual blocks; the strides come from the plan ([1,1,1] then five × [2,2,2] for full-FOV, last stage [1,2,2] for the masks, because of the patch's anisotropy). batch_size = 2, use_mask_for_norm = [false] everywhere. The 2022 PLOS ONE paper describes a UNETR MONAI model with a 128³ crop (transformer encoder + convolutional decoder); the code that runs today is a purely convolutional nnU-Net v2 PlainConvUNet. See §10.

Each model is binary. The dataset.json files only declare {background: 0, <one structure>: 1} — and for the six full-FOV models the label name was left as "Skin" by copy-paste, even for MAND or CB. This name is never read: the output is binarized with (arr > 0) (AMASSS_CLI.py:586) and it is the CLI that assigns the final value.

Codes with no model in the bundle: RC (root canal), TEETH, MCAN. The last two are disabled in the UI (UNAVAILABLE_MODELS); RC is not — it is even in DEFAULT_SELECT (AMASSS.py:256), checked by default, and it ends up in missing_structures with a logger.warning.

LABELS["SMALL"] (MAND:1, RC:2, MAX:4), MODELS_GROUP (AMASSS_CLI.py:256) — which described the multi-class models of the older version, with FF producing MAND/CB/UAW/MAX/CV from a single network — and NTRANSLATE are no longer read anywhere: dead code.

4.4 Inference

No sliding_window_inference is written here: nnU-Net handles the sliding window itself, from the patch_size of its plan. The only parameter the CLI chooses is the step size.

BuildPredictor() (AMASSS_CLI.py:114) sets tile_step_size = 0.5 (50% overlap, hard-coded in the signature), use_gaussian = True (gaussian weighting of the patches), use_mirroring = False (the equivalent of --disable_tta: no mirror augmentation at test time), device from ResolveDevice(), and verbose / verbose_preprocessing / allow_tqdm set to False. The perform_everything_on_device kwarg (renamed from perform_everything_on_gpu partway through the 2.x series) is chosen by introspecting the signature.

PredictFolder() (AMASSS_CLI.py:206) loads the checkpoint (initialize_from_trained_model_folder(..., use_folds=(0,), checkpoint_name="checkpoint_final.pth")) then calls predict_from_files_sequential on the entire folder. Three structuring choices, all commented in the code:

  1. Explicit model path, no nnUNet_results. os.environ is global to the process: two concurrent AMASSS runs would overwrite each other's model path.
  2. Loop per structure, not per scan: all the scans in a single input folder, one folder prediction per structure. The checkpoint is loaded S times instead of N × S.
  3. Sequential version: predict_from_files uses spawn, and under Slicer a worker would re-import this module and pay the full cost of importing torch again; it would also need its own CUDA context for GPU resampling.

Progress is still counted in scan × structure steps (AMASSS_CLI.py:815) so as not to change the scale expected by the widgets, even though the work is grouped by structure: the bar advances in scan_count-sized steps.

A structure that fails is recorded in failed_structures and the run continues; the run only fails if all of them fail.

5. The algorithmic core (not learned)

5.1 GPU resampling

EnableGpuResampling() (AMASSS_CLI.py:150) is the CLI's main optimization. According to the code comment, single-core scipy resampling costs roughly seven times as much as the network.

The mechanism: nnU-Net resolves its resampling functions by name, through recursive_find_resampling_fn_by_name, from the configuration dict. Rewriting the two names redirects both ends, with no monkeypatch:

configuration["resampling_fn_data"]          = "resample_torch_fornnunet"
configuration["resampling_fn_probabilities"] = "resample_torch_fornnunet"
configuration[f"{key}_kwargs"] = {"is_seg": False, "device": torch.device(device), "mode": "linear"}

Three safeguards: the substitution only happens if both keys are exactly resample_data_or_seg_to_shape (a plan that asks for something else is left untouched); PlansManager hands out a deepcopy, so mutating the dict affects neither the shared plans nor a concurrent run; both properties are @property @lru_cache, hence the getattr(manager_class, key).fget.cache_clear(), without which a value read before the switch would survive. Numerical difference accepted deliberately: the data go from order-3 to order-1 interpolation (torch has no 3D cubic interpolation); the probabilities were already order-1.

Automatic fallback on torch.cuda.OutOfMemoryError → empty_cache() then replaying the structure with the scipy resampler (AMASSS_CLI.py:244): the cloud version has an explicit gpu_resampling argument, which is impossible here since the parameter list is frozen by the XML and its callers.

5.2 Assembly and writing

AssembleScanOutputs() (AMASSS_CLI.py:575), per scan: reads p_<NNN>.nii.gz from each pred_<STRUCT> folder (missing → warning, structure skipped), binarizes with (arr > 0), then

  • SEPARATE if requested or if there is only one structure (a "merged" made of a single structure is just that structure);
  • MERGE if requested and ≥ 2 structures: np.where(mask == 1, label, merged) in the order of merging_order = ["SKIN","CV","UAW","CB","MAX","MAND","CAN","RC","CBMASK","MANDMASK","MAXMASK"]. This is a priority order: the last structure written overwrites the previous ones on shared voxels. "CAN" does not exist in any dictionary (the canal code is MCAN), a dead entry; .get(struct, 1) would fall back an unknown code to label 1.

SaveSeg() (AMASSS_CLI.py:524) casts to int16, explicitly copies back spacing, direction and origin from the reference scan, then goes through MatchReferenceGeometry() (AMASSS_CLI.py:502), which only resamples (nearest neighbor) if the geometry differs — a no-op in the normal case. The earlier version wrote a temporary volume and re-read it to force the geometry: two gzip round trips of a full CBCT per structure, for nothing.

5.3 Post-processing: what's no longer there

No hole filling, no connected-component selection, no morphology is applied. Two functions remain, called nowhere:

  • CleanArray() (AMASSS_CLI.py:422) — binary dilation of radius r, BinaryFillhole, erosion of radius r, then cc3d.connected_components and keeping the largest component;
  • CropSkin() (AMASSS_CLI.py:489) — filling, erosion of thickness thickness, difference of the two to keep only the shell, then the largest component.

In the monai version, CleanArray(sep_arr, 2) was applied to every structure except CV and RC, and CropSkin(sep_arr, 5) to the skin. The nnU-Net port removed these calls: cleanup now relies entirely on nnU-Net's internal post-processing (the bundle's postprocessing.pkl, if it exists). cc3d is still imported for these two dead functions, and so is Write() (AMASSS_CLI.py:287).

5.4 VTK surface generation

SavePredToVTK() (AMASSS_CLI.py:305), called from SaveSeg when genVtk is true. Per label: writes a temporary NRRD <temp>/temp.nrrd of the binary mask, vtkNrrdReader → vtkDiscreteMarchingCubes with GenerateValues(1, 1, 1) (a single contour of value 1 — hence going through a binary mask rather than the label map) → vtkSmoothPolyDataFilter for vtk_smooth iterations (5 everywhere in the repository) → vtkUnsignedCharArray "Colors", one constant color per cell taken from LABEL_COLORS.

Two modes, chosen on the _MERGED suffix of the file name: in merged mode, it loops over np.unique(arr) and concatenates with vtkAppendPolyData into a single .vtk; in separate mode, struct = base.split('_')[-1] — the structure code is re-extracted from the file name to look up the color.

Meshes are written in the image coordinate system, with no LPS/RAS flip: these are vtkPolyData derived directly from the NRRD's indices.

6. Post-processing and outputs

Naming — base = scan name without extension, ext = original extension:

ModeFileContent
SEPARATE<base>_<prediction_ID>_<STRUCT><ext>computed binary int16 mask, one per structure
MERGE<base>_<prediction_ID>_MERGED<ext>computed int16 label map per LABELS["LARGE"]

With save_in_folder, everything goes into <output_folder>/<base>_<prediction_ID>_SegOut/; otherwise directly into <output_folder>.

Confirmed bug

The temporary folder is wiped and recreated at both startup and the end. nnunet_input is deleted as soon as inference finishes, before assembly — otherwise a batch would keep a full NIfTI copy of every CBCT until the very end; a scan's predictions are deleted as assembly proceeds. temp_fold is unconditionally rmtree'd on startup (AMASSS_CLI.py:648), and the widget, AREG and VFACE all pass <Documents>/Slicer_temp_AMASSS: two concurrent runs erase each other's working folder. Details in §9.

On the widget side, OnEndProcess() (AMASSS.py:1089) loads the output folder's .vtk files into the scene (opacity 0.1 for the skin, 0.2 for the mandible/maxilla if a root canal is present). This loading only happens if vtk_output_folder is non-null, so only for a "single file" input saved to its original folder with the surface checkbox checked (AMASSS.py:944). LOADED_VTK_FILES is a module-level global: the nodes stay referenced for the whole session, even after the scene is closed.

8. Environment

Everything runs in Slicer's Python. Installation is triggered by the Predict button (AMASSS.py:851), not when the module opens, and goes through a confirmation dialog.

PackageVersion pinnedReason readable in the code
torch, torchvision, torchaudio>=2.2.0 (CUDA wheels)download.pytorch.org/whl/cu118 or cu121 index depending on the detected CUDA version
nnunetv22.8.0inference backend
numpy1.26.4 (NUMPY_PINNED_VERSION)torch 2.2.0 is built against numpy 1.x; numpy ≥ 2 breaks every torch import with _ARRAY_API not found
pydicom3.0.2do not downgrade: pydicom 2.x breaks dicomweb-client and highdicom, hence every DICOM module in Slicer
dicom2nifti2.6.2compatibility with pydicom 3
itk, blosc2, einops, nibabelunpinnednnU-Net dependencies

fix_numpy_version() (AMASSS.py:55) is called again after all the installs: pip resolves each install independently, and nnunetv2 (which requires numpy>=1.24) can pull in numpy 2.x along the way.

On Windows, check_lib_installed() compares the cuXXX suffixes of the three torch packages and only validates the install if they match; CUDA version detection caps at cu121 and falls back to cu118 below 12.1.

No WSL, no conda: unlike the IOS modules (FlexReg, AREG_IOS, ALI_IOS), AMASSS uses no external environment at all.

9. Pitfalls and fragile points

Confirmed bug — small FOV broken

highDefinition / "small FOV" no longer does anything it claims to. The smallFOVCheckBox switches the offered structure list to GROUPS_HD_SEG (AMASSS.py:747) — mandible, maxilla, teeth, root canal, mandibular canal, three of which have no model. The param["highDefinition"] flag is not declared in the XML, slicer.cli.run drops it, and the CLI no longer has any SMALL code path anyway (spacing [0.16, 0.16, 0.32] and MODELS_GROUP["SMALL"] disappeared with the port). Checking the box only changes the list of checkboxes.

Confirmed bug — DICOM input ignored

isDCMInput is read then ignored: dicom2nifti is imported at the top of the file and never used, no DICOM → NIfTI conversion exists anywhere in the CLI, even though the UI offers "DICOM Files" as an input type. A DICOM input produces nothing — no file ends up with a recognized extension.

Pitfall

RC checked by default with no model available: DEFAULT_SELECT includes "Root canal", and the published bundle has no RC folder. Silent failure.

Confirmed bug — shared temporary folder

Temporary folder overwritten. temp_fold is unconditionally rmtree'd on startup (AMASSS_CLI.py:648), and the widget, AREG and VFACE all pass <Documents>/Slicer_temp_AMASSS: two concurrent runs erase each other's working folder.

Pitfall

Fragile case index: the p_NNN → file mapping only lives in scan_records, in memory; a crash during assembly leaves anonymous predictions in the temporary folder.

Pitfall

struct = base.split('_')[-1] in SavePredToVTK: a prediction_ID or a scan name containing an underscore after the structure code raises a KeyError on LABELS["LARGE"][struct].

Pitfall

Counting mismatch between the widget (extensions including .gipl, exceptions Seg/seg/Pred) and the CLI (.gipl not recognized, exception on _<prediction_ID>_ and MASK).

Pitfall

The widget's cleanup() (AMASSS.py:1348) does shutil.rmtree(os.path.join("..", "temp")): a path relative to Slicer's current working directory, unrelated to temp_fold. The exception is swallowed.

Note — dead code worth knowing about

CLI: CorrectHisto, CleanArray, CropSkin, Write, MODELS_GROUP, LABELS["SMALL"], NTRANSLATE. Widget: GetSegGroup, createProgressDialog, UpdateRunBtn (which would read self.scan_ready, never defined → AttributeError), self.center_all, self.save_adjusted and their two checkboxes, kept visible and never read.

10. Literature

AMASSS is published once:

Gillot M., Baquero B., Le C., Deleat-Besson R., Bianchi J., Ruellas A., …, Cevidanes L., Prieto J.C. Automatic multi-anatomical skull structure segmentation of cone-beam computed tomography scans using 3D UNETR. PLOS ONE 17(10):e0275033, 2022. doi:10.1371/journal.pone.0275033 — PMID 36223330, PMC9555672

Code / paper divergence

The code has diverged from the paper, completely. The paper describes a UNETR (transformer encoder + convolutional decoder, MONAI library): 128³ patches, feature_size=16, hidden_size=768, mlp_dim=3072, 12 attention heads, 5% dropout, trained on 618 CBCTs from 7 centers for five structures, with 0.4 mm isotropic resampling and contrast adjustment by cumulative histogram at the 1% / 99% percentiles. Reported Dice scores: skin 0.971, mandible 0.962, maxilla 0.853, cranial base 0.788, cervical vertebra 0.760.

This is what the historical version of the CLI did — Create_UNETR(...), sliding_window_inference(input_img, [128,128,128], nbr_GPU_worker, net, overlap=precision/100, sw_device=DEVICE, ...), CorrectHisto + ScaleIntensityd(0,1) + Spacingd(pixdim=[0.4,0.4,0.4]) or [0.16,0.16,0.32] in high definition, then CleanArray/CropSkin — readable in the repository up to commit 61bbb15 "ENH: AMASSS with nnunet." The high-definition spacing and the UI's precision were parameters of the code, not of the paper; a Create_SwinUNETR(feature_size=48) coexisted there, commented out.

None of that remains in the current code: nnU-Net v2, PlainConvUNet, one binary network per structure. The 0.4 mm spacing survives, but comes from the weights' plans.json; the high-definition path and the morphological post-processing are gone. No publication describes the nnU-Net version of AMASSS: citing the PLOS ONE paper to describe the module as it runs today amounts to describing an architecture that is no longer executed.

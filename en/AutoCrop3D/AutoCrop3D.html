AutoCrop3D

AutoCrop3D batch-crops a folder of volumes to a box drawn in Slicer, by extracting voxels in the original grid: no interpolation, no network, no conda. This page explains how, step by step. Files, lines and pitfalls are on the code page.

unpublished Atlas (explanation) Code (developers) no conda no GPU purely computational VISOR Bibliography

Two code bases. This page describes the legacy Slicer module (SlicerAutomatedDentalTools at 3c67957, 2026-10-26). The VISOR port, which runs the same tool on a server, is described in VISOR: how this tool runs now. Where VISOR differs, a sentence says so.

Overview: what goes in, what comes out

The clinician draws a box (a region of interest) in Slicer and saves it as a file. AutoCrop3D keeps only the voxels inside that box, for every volume of a folder. Nothing is predicted: it is geometry, and the voxels that remain are the original ones.

InOut
a folder of volumes (.nii.gz, .nii, .nrrd, .gipl and compressed forms), including segmentationsfor each volume, the same volume reduced to the box, named with a suffix (cropped by default), in a copy of the input folders
one box file, or a folder with one box per patient (.mrk.json)for a segmentation, a surface (.vtk) beside it

1. Position in the pipeline

Nothing in the repository calls AutoCrop3D, and it calls nothing but Slicer. In practice it sits before the segmenters (AMASSS, BATCHDENTALSEG) or after them: the surface step only starts if the output name contains seg, so it is meant to receive segmentations produced elsewhere. No model, no download.

2. Files involved

A widget (checks the input, offers the second path), a command-line module that does all the cropping, a small pairing helper, and the surface builder. The file list and where each one runs are on the code page. The command-line module runs inside Slicer’s own Python: nothing to install.

In the codeThe files and where each runs

3. What defines the crop box

The box is a markups ROI file (.mrk.json). Only its centre and its size are read. The corners are the centre minus and plus half the size, on each axis. The box does not come from a segmentation: nothing in the module derives a box from a label map.

Two things in the file are ignored by the default path: the coordinate system it was saved in, and its rotation. A box saved in RAS would have its first two coordinates the wrong way round, with no message; a rotated box is treated as its own axis-aligned bounding box. That is why a second path exists for tilted boxes (section 5). VISOR reads the coordinate system and flags a rotation.

4. How the box is applied: index extraction, no resampling

The key point: no interpolation. The corners are converted to voxel positions and the block between them is copied as it is.

Keeping the original size is an option: the cropped block is pasted back at the same place in an empty volume with the geometry of the original, everything outside the box set to zero. No transform file is read or written; the geometry lives in the header of the image.

5. The alternative path: Slicer’s Crop Volume module

A checkbox, “Use module Crop Volume for tilted images”, hands the work to Slicer’s own module. It runs inside the widget, not in the command-line module. With interpolation on, Crop Volume resamples in the box’s own frame, which is what lets it handle a rotated box, at the cost of changing the voxel values. The two paths do not produce the same file, on purpose. It loads the box and the volume as scene nodes, so it alone reads the coordinate system and the rotation. VISOR does not port this path.

In the codeprocessCropVolume() and its parameters

6. Batch mode and patient ↔ box pairing

With a single box file, it is applied to every volume. With several, each volume looks up its box by a patient key built from the file name; a volume with no box is skipped with a warning. The trouble is that the two sides compute the key by different rules: the volume name goes through a chain of cuts that remove words like Scan or T1, while the box name is cut at its first underscore.

A patient name containing an underscore therefore breaks the pairing. With names without an underscore, everything works.

7. Generating a VTK mesh from a segmentation

When the output name contains seg, the cropped label map is also turned into a surface: a margin of empty voxels is added, marching cubes extracts the outline, and the outline is smoothed (5 passes). The legacy margin is 50, 50 and 10 voxels, but only on the lower side of each axis, so a structure that touches the upper face of the crop stays open there.

Every cell of the mesh gets the same colour, taken from the largest label (the table holds six colours). The mesh is not moved into the patient’s space, so it is expected not to line up with the cropped volume in Slicer (a deduction, not tested). VISOR pads both sides in millimetres, colours each label and moves the mesh into patient space.

10. Environment

Nothing to install: the module uses what Slicer already ships (SimpleITK, numpy, VTK, Qt). No CUDA, no WSL, no conda.

11. Pitfalls and fragile points

Each point is checked in the code and described, with its evidence, on the code page.

  • The box’s coordinate system and rotation are ignored: wrong result, silently. Evidence.
  • A folder holding one box crashes. Evidence.
  • The widget and the command-line module look for different extensions, so a folder of uncompressed files is refused. Evidence.
  • Truncation loses up to one voxel on the upper side of each axis. Evidence.
  • No check that the box meets the volume: an empty crop fails inside a swallowed error. Evidence.
  • A name replacement that is too broad can rename a folder that shares the file’s name. Evidence.
  • Crop Volume clears the whole scene for every patient. Evidence.
  • The scene is touched from another thread on that path. Evidence.
  • The suffix is only applied to .nii.gz on that path. Evidence.
  • The unit test tests nothing. Evidence.
  • Dead code remains in the module. Evidence.
  • The surface step pads only the lower side, and colours every cell alike. Padding, colour.

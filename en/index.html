SlicerAutomatedDentalTools — how each tool works

One page per tool, organised around the pipeline: what is computed, what is predicted by a network, when the model gets called, what it actually does, what the preprocessing is, and what comes out.

This is not a user manual. Code links point to the ~/Projects/UNC/SlicerAutomatedDentalTools repository.

Where to start

From the bottom of the chain to the top. The first two steps are the ones everything else depends on.

#PageWhy this one first
1FlexRegThe simplest, everything is explicit. Introduces the LPS/RAS conventions, crown segmentation, and patch-based ICP.
2ALI and AMASSSThe two landmark providers everything else depends on.
3ASOOrientation, a prerequisite for most registrations.
4AREG_IOS then AREG_CBCTThe registrations themselves.
5VFACEHighest in the chain: it stacks all the others.

The three shared building blocks

Almost every module rests on the same three components. Understanding them once means not re-reading the same mechanics across five pages.

Shared conda environment

Coupling worth knowing

ALI, AREG, ASO, DOCShapeAXI and FlexReg share the same conda environment shapeaxi, on Python 3.12. A change to the Python version breaks all of them at once. Details in FlexReg, Environment section.

Folder layout

One folder per tool. Each one holds:

  • <Tool>.html — the pipeline, read from the code;
  • SOURCES.html — the bibliography: what's deposited here, what's meant to be read online, and the "neighbourhood" (related work that does not describe the code);
  • the retrieved documents, as PDF where the publisher allows it, otherwise as .xml (JATS, the full text) with a readable .txt alongside it.

The original .md files are kept next to the HTML pages.

29 PDFs and 54 full texts, all verified: the PDFs are paginated, the XML files carry a text body. Nothing was obtained by working around a paywall — arXiv, PLOS, PMC/NCBI, HAL, institutional repositories, author pages, and author-deposited versions. Anything paywalled is given as a link with its DOI.

Retrieving a text the publisher doesn't serve

Author manuscripts deposited with the NIH are free to read but often invisible to the usual routes. What works, tested:

curl -sL "https://eutils.ncbi.nlm.nih.gov/entrez/eutils/efetch.fcgi?db=pmc&id=<number without PMC>"

What fails on the same articles: pmc.ncbi.nlm.nih.gov/.../pdf/ (anti-bot HTML), Europe PMC's fullTextXML (empty), the BioC API (open access subset only). And for MDPI, mdpi-res.com/d_attachment/... serves the real PDF where mdpi.com/.../pdf returns a page.

What isn't published anywhere

Checked against Crossref, OpenAlex, Europe PMC, arXiv, HAL and the full NA-MIC tree: FlexReg and its MGL track, ALI_IOS, AREG_IOSCBCT, CLIC, CNE, AutoCrop3D, AutoMatrix, MedicalDataAnonymizer, the three variants of BatchDentalSeg, and the nnU-Net version of AMASSS. For several of these, a NA-MIC Project Week page is the only written description that exists — they are deposited in the relevant folders.

GreedyReg: affine registration with greedy

Affine or rigid registration of T1 and T2 CBCT scans, by driving the registration engine Greedy as a subprocess, with no network in the main path. This page explains how, step by step, with the maths; the files, lines and pitfalls are on the code page.

Code (developers) Guide Venet 2019 · arXiv GreedyReg_CLI conda env: none (Slicer's Python) VISOR Bibliography

Overview: what goes in, what comes out

At the second visit the patient never lies exactly as at the first. GreedyReg brings the second CBCT (T2, the moving scan) into the frame of the first (T1, the fixed one). It offers three modes: align by hand, let Greedy optimise, or start from landmarks when the two scans are far apart.

What it is
Inputa T1 and a T2 CBCT (.nii.gz), alone or as two folders paired by patient; optionally a mask of a stable structure and a starting matrix
IdeaGreedy optimises a similarity measure from coarse to fine over 6 (rigid) or 12 (affine) numbers
OutputT2 resampled into the T1 grid, and the matrix found

Everything numbered below describes the legacy Slicer module (SlicerAutomatedDentalTools at 3c67957, 2026-10-26). The VISOR port, which runs part of this tool on a server, is described in VISOR: how this tool runs now. It is a partial port: only the folder-to-folder Greedy registration exists there. The Manual mode and the Distant (landmark) mode have no counterpart in the server tool.

1. Position in the chain

Nothing in the repository calls GreedyReg. It is a terminal tool, driven by the operator, and it feeds no other module. The widget assembles the parameters and lets a command-line tool launch Greedy; the only other tool involved is ALI_CBCT, in Distant mode.

In the codeThe calls, who launches what, and why the widget never runs greedy itself

2. Files involved

The widget (about 1600 lines, 700 of them user interface) holds the three modes; a helper file does the pairing, the matrix algebra and the ALI parsing; the command-line tool loops over the pairs and builds the two Greedy commands. Greedy itself is an external executable. Everything runs in Slicer’s Python, with no conda environment and no GPU.

In the codeEach file with its role and where it runs

3. The greedy binary: where it comes from

The executable is not in the repository: if it is missing, a banner offers to download the ITK-SNAP 4.2.2 archive for the platform and extract only greedy from it. The Windows path is the most fragile (the installer is run silently, then uninstalled). There is no integrity check on the downloaded archive.

In the codeThe three download sources and the Windows extraction

4. The three modes, and what actually sets them apart

ModeWhat is computedOutput
Manual Alignmentnothing: the operator moves a transform in the scenea matrix in the scene, used as the start
Automatic Registrationcomputed Greedy optimises an intensity metric, rigid or affineregistered volume and matrix
Distant Registrationpredicted computed landmarks from ALI_CBCT, then a closed-form rigid fitonly a matrix, to be refined afterward

“Distant” does not mean remote computation: it refers to two scans that start geometrically far apart. Everything runs locally; the only outgoing requests are the downloads of the tool and of the ALI weights, never patient data.

In the codeThe vocabulary trap and the files each mode touches

4.1 Manual mode

The operator moves T2 with sliders (three rotations, three translations), with a “Center T2 on T1” button, or with the handles of Slicer. No intensity is compared. The resulting matrix is handed to Greedy as its starting point.

In the codeThe slider composition order, the centering and the prototype wheel

4.2 Automatic mode

The widget exports both volumes into a temporary folder under a fixed fake name, writes the starting matrix, and runs the command-line tool in batch mode on a folder with a single pair. There is no dedicated single-case path. The registered volume is loaded when it finishes; the temporary folder is never deleted.

In the codeThe temporary tree, the polling and the save button

4.3 Distant mode

One region only is kept, by priority (cranial base, then mandible, then maxilla): ticking several does not add their landmarks. ALI_CBCT, an agent that walks through the volume, places 4 or 5 landmarks of that region on both scans; the coordinates are converted from LPS to RAS, and if at least 3 landmarks are common to both scans, a rigid transform is computed from them.

In the codeThe region table, the ALI parameters and the SVD code

5. The greedy command line

The command is always the same, with no option exposed beyond the metric and the degrees of freedom. The flags, in plain terms:

  • Affine mode: Greedy’s diffeomorphic mode, its default and its reason for existing, is never used here.
  • The metric: NMI (normalised mutual information, the legacy default, for heterogeneous intensities), NCC over a window of radius 4 voxels (9×9×9), or SSD (sum of squared differences, for the same modality).
  • The order: T1 is the fixed image, T2 the moving one.
  • The schedule: four resolution levels, 100, 100, 50 and 25 iterations from the coarsest.
  • A random search over 100 rigid transforms precedes the optimisation, with a spread of 10 degrees in angle and 20 in offset; the unit of the offset is ambiguous in Greedy’s own documentation.
  • The degrees of freedom: 6 for rigid, 12 for affine; 7 (rigid plus one scale) is not offered.
  • The start: always a given matrix.
  • The mask, if any, belongs to the fixed volume: the metric is only computed inside it.

A second call, always run, resamples T2 into the grid of T1 by linear interpolation with the matrix found. Each call is capped at 600 seconds; a pair makes two calls.

In the codeThe exact command lines and the table of every flag

6. Inputs, pairing, masks, initialization

A patient is recognised by the letters and digits at the start of the file name, upper-cased: A01_t1.nii.gz gives A01. A pair exists when the same identifier is found in the T1 and in the T2 folder; a file named 01_T1.nii.gz (digits first) is never paired, silently. A mask is exported from a segmentation or a labelmap and turned into a 0/1 image: all segments of a multi-label segmentation are merged. Without a starting matrix, the tool writes an identity with a one-micron nudge in x, because an exact identity makes Greedy behave differently (the original code comment says it would treat it as no initialisation). There is no intensity preprocessing: the files are given as they are.

In the codeThe regular expression, the mask code and the nudged identity

7. Batch mode

There are two independent batches. Automatic: a single command-line run over the folders, which loops over the pairs; the output goes into the T2 folder itself, the mask folder (if filled in) is passed on and turned into a 0/1 image by the command-line tool, no start matrix is passed, and the first failing case stops the whole batch. Distant: the widget loops case by case with an ALI queue per pair, and the result is not a registered volume but a rewritten header: the voxels do not move, only the voxel-to-world affine is corrected by the rotation and translation found.

In the codeThe two loops and the header rewrite

8. Outputs

For each patient: <ID>_registered.nii.gz (T2 in the T1 grid), <ID>_warp.mat (Greedy’s four-line text matrix) and, in the Distant batch, <ID>_t2_aligned.nii.gz. The matrix is in Greedy’s own convention: it maps the RAS coordinates of the fixed volume to those of the moving one.

[xmoving;1]=M[xfixed;1]

It is not an ITK transform file and does not load in Slicer despite its .mat extension. An ITK or Slicer transform on disk is in LPS, so a conversion (a conjugation by the flip of x and y, and possibly an inverse) would be needed, and nothing in the module does it. GreedyReg is a dead end: nobody consumes its matrix.

In the codeThe file table, the format and the conversion that does not exist

9. Initialization convention: very likely inverted

The manual matrix is a Slicer transform, which maps the moving volume to the world: moving to fixed. The starting matrix of Greedy is of the nature of its output, which maps fixed to moving. The two are inverses of one another, so the manual pre-alignment is very likely handed to Greedy backwards. For a pure shift of 20 mm, the right start is the shift of one direction and the wrong one is the opposite shift, which leaves the search 40 mm from the answer instead of 0. It does not always show: the random search and the four-level schedule forgive a lot, and a bad start only slows the convergence. This is unconfirmed; it should be checked with a pure 20 mm translation before fixing.

In the codeThe matrix written and the convention of the rest of the repository

11. Environment

Slicer’s Python runs both the widget and the command-line tool; the command-line tool needs only nibabel, installed after a confirmation. The Distant mode adds heavier libraries (DICOM conversion, MONAI), with pinned versions that matter: another choice breaks Slicer’s own DICOM modules. torch is assumed already present. Greedy needs no GPU; ALI can use one. There is no conda and no WSL.

In the codeThe libraries, their versions and the commit that pinned them

12. Traps and fragile points

  • The batch writes its outputs into the T2 input folder, so a second run can register the previous result again (details).
  • The matrix is not a Slicer transform: wrong format, wrong frame, wrong direction (details).
  • The manual initialisation is likely inverted (details).
  • The time step flag has no effect in affine mode (details).
  • In Distant mode the “Save Registered Volume” button never has anything to save (details), and the three structure boxes do not combine their landmarks (details).
  • ALI can fail silently, leaving the user with only “0 matched landmarks” (details).
  • Temporary folders are never cleaned up on the widget side (details).
  • One failing pair stops the whole batch (details).
  • A multi-segment mask is flattened and its space is not checked (details).

13. Literature

The engine is published, the module is not.

  • greedy: a tool by Paul Yushkevich (PICSL, UPenn), bundled with ITK-SNAP. The usual reference for citing it is Venet, Pati, Yushkevich, Bakas, Accurate and Robust Alignment of Variable-Stained Histologic Images Using a General-Purpose Greedy Diffeomorphic Registration Tool (arXiv:1904.11929). Documentation: greedy.readthedocs.io, code: pyushkevich/greedy. Note: the paper and the tool are about diffeomorphic registration; GreedyReg only uses the affine/rigid mode (-a), which is merely its initialization step.
  • ALI_CBCT: Gillot et al., Automatic landmark identification in cone-beam computed tomography, Orthodontics & Craniofacial Research, 2023, virtual agents navigating a multi-scale volumetric space, reported mean error of 1.54 ± 0.87 mm across 32 landmarks. Original repository: Maxlo24/ALI_CBCT.
  • GreedyReg itself: no publication. The approach, "manual pre-alignment then intensity-based affine, with a mask", is that of ITK-SNAP's Registration panel, of which this module is a transposition into Slicer; that is the only lineage the code can claim.

Full bibliography: SOURCES.html, verified references, the files retrieved into this folder (the greedy paper, the ALI_CBCT paper), and a detailed distinction between what the greedy paper describes and what this module actually executes.

GreedyReg

Affine/rigid registration of T1/T2 CBCT scans by driving ITK-SNAP's greedy binary as a subprocess, with no network in the main path and no dedicated conda environment.

Venet 2019 · arXiv GreedyReg_CLI conda env: none (Slicer's Python) Bibliography

Registration of T1/T2 CBCT scans by calling ITK-SNAP's greedy binary as a subprocess. No network is trained or called in the main path: the only network the module uses is for "distant" initialization, and that is ALI_CBCT, borrowed as-is.

1. Position in the chain

Nothing in the repository calls GreedyReg. It is a terminal tool, driven by the operator, and it feeds the input of no other module.

CalledHowWhen
GreedyReg_CLIslicer.cli.run(slicer.modules.greedyreg_cli, …)every automatic registration, single-case or batch
greedy binarysubprocess.run from the CLItwo invocations per case (registration then resampling)
ALI_CBCTslicer.cli.run(slicer.modules.ali_cbct, …)"Distant Registration" mode only
Verified

The Slicer module never launches greedy itself: it assembles the parameters (Logic.py:286) and lets the CLI do it. The docstring of GreedyRegLogic states this explicitly, and it checks out: no subprocess in the widget outside of the binary download.

Note

Important point for anyone taking this over: there is no conda environment. The comment at Logic.py:76 says so — the CLI runs in Slicer's own Python, so a slicer.util.pip_install issued from the widget is immediately visible to the subprocess. No GPU either: greedy is CPU-only.

The first two lines of GreedyReg.py clear the module's __pycache__ on every import — a leftover from development.

3. The greedy binary: where it comes from

greedyBinaryPath() looks for GreedyReg_CLI/bin/{linux|mac|windows}/greedy[.exe]. If it is missing, a red banner offers downloadGreedyBinary() (Logic.py:106), which fetches an ITK-SNAP 4.2.2 archive from SourceForge and extracts only bin/greedy from it:

PlatformSourceExtraction
Linuxitksnap-4.2.2-20241202-Linux-x86_64.tar.gztarfile, member …/bin/greedy, chmod 755
macOS (arm64)itksnap-4.2.2-20241202-MacOS-arm64.tar.gzsame
Windowsitksnap-4.2.2-20241202-win64-AMD64.exe (NSIS installer)7-Zip if present, otherwise a silent install followed by uninstall

The Windows path is the most fragile, and the code documents this well (Logic.py:161): NSIS's /D= does not support quotes, so the install happens in %SystemDrive%\_greedyreg_nsis_tmp (a path with no spaces), greedy.exe is copied out, then Uninstall.exe /S runs.

Trap

No integrity check (no checksum) on the downloaded archive.

4. The three modes, and what actually sets them apart

ModeWhat is computedWho computes itOutput
Manual Alignment nothing: the operator moves a vtkMRMLLinearTransformNode widget matrix in the scene, used as -ia
Automatic Registration affine or rigid, by optimizing an intensity metric computed greedy binary, via the CLI registered .nii.gz + .mat
Distant Registration closed-form rigid (SVD/Kabsch) on 3-5 predicted landmarks predicted computed widget + ALI_CBCT only a matrix, to be refined afterward
Vocabulary trap

The word "Distant" does not mean remote computation. The panel is titled "Distant Registration (Large Misalignment)": it refers to two scans that start geometrically far apart (a large initial misalignment). Everything runs locally. No network, no socket, no encryption, no attestation: there is not a single outgoing request in the module besides urllib.request.urlretrieve to SourceForge (the greedy binary) and to the repository's GitHub releases (ALI weights). The only contact with the outside world is therefore downloading tools, never sending patient data.

4.1 Manual mode

Two sets of controls act on the same transform node:

  • six ctkSliderWidget sliders (rotations ±180°, translations ±200 mm), composed in this order: Translate then RotateX, RotateY, RotateZ (GreedyReg.py:1192);
  • "Center T2 on T1": a pure translation between the centers of the two volumes, computed in IJK then converted to RAS by GetIJKToRASMatrix (Logic.py:381);
  • Slicer's native handles (SetEditorScalingEnabled(False) → never any scaling);
  • an admitted prototype, "Sensitivity Demo": a Qt wheel reparented onto the Red/Yellow/Green views. The rotation axis depends on the view (Red→Z, Yellow→X, Green→Y), dragging outside the wheel translates within the slice plane (0.5 mm/pixel × gain), and the wheel's size tracks the zoom (baseFov / fovMean, clamped to 0.55-1.90). The comment at GreedyReg.py:499 explains why: the native handles recompute their delta from the raw mouse position, so damping the matrix afterward has no visible effect.

The moving volume is not hardened before export: slicer.util.exportNode(node, path) defaults to world=False (verified in slicer/util.py), so the manual transform reaches greedy only through the -ia file. See §9 for the convention problem this raises.

4.2 Automatic mode

onRunRegistration() (GreedyReg.py:1204) builds a directory tree inside tempfile.mkdtemp(): T1/, T2/, INIT/, MASK/, OUTPUT/, exports both volumes under the fake identifier CASE0001, writes the init, then calls the CLI in single-pair batch mode. There is no dedicated code path for the single-case run: it is a batch run over a folder with one file.

A 1 s QTimer polls the cliNode; at the end, the registered volume is loaded from the temporary folder. This folder is never deleted (no rmtree in the widget): the results survive until system cleanup, which is also what the "Save Registered Volume" button depends on, since it is a plain shutil.copy.

4.3 Distant mode

onRunDistantRegistration() (GreedyReg.py:1406):

  1. only one region is kept, by priority order cranial base > mandible > maxilla (_selectedDistantRegion, GreedyReg.py:1397): checking several boxes does not add up their landmarks, the first one found wins;
  2. both volumes are exported as .nii.gz into a temporary folder;
  3. a job queue for ALI is built: one job per (scan × model subfolder), run in series by chaining ModifiedEvent observers (GreedyReg.py:1493);
  4. the output json files are read back, coordinates converted LPS → RAS ([-x, -y, z], Logic.py:517);
  5. if ≥ 3 landmarks are common to both scans, rigidFromLandmarks() computes a rigid transform by SVD; otherwise an explicit failure.

Regions and landmarks (REGION_CONFIG, Logic.py:20):

RegionLandmarksWeight folders
MANDMASKRGo, LGo, Gn, Me, PogLower_Bones_1, Lower_Bones_2
MAXMASKA, ANS, LOr, ROr, PNSUpper_Bones_v2
CBMASKS, N, RPo, LPoCranial_Base

The weights come from the repository's v0.1-v2.0_models release, one .zip per folder, extracted into Documents/SlicerDownloads/GreedyReg/ALIModels/<folder>/.

The network being called. ALI_CBCT does not produce a heatmap: it is reinforcement learning. One agent per landmark navigates the volume, observes a cube of agent_FOV = [64,64,64] voxels, and picks a move from MOVEMENTS; the DNet network (a 1024-channel transition layer, out_channels = len(MOVEMENTS["id"])) is reloaded per landmark from the folder's .pth files (ALI_CBCT.py:159). Parameters imposed by GreedyReg (Logic.py:471): spacing = [1, 0.3] mm (coarse then fine search), speed_per_scale = [1,1], spawn_radius = 10, DCMInput = false.

The rigid computation (Logic.py:535) is a computed classic Kabsch: centering, H = movingᵀ·fixed, SVD, R = Vᵀ·Uᵀ, reflection correction if det(R) < 0, t = c_fixed − R·c_moving. The resulting matrix thus goes from moving to fixed, in RAS — exactly the convention of a Slicer transform node, where it is placed as-is.

Verified

The completion message is honest: "Distant registration complete! Now run Automatic Registration to refine." This mode does not register, it initializes.

5. The greedy command line

buildRegistrationCommand() (GreedyReg_CLI.py:100) always produces exactly this, with no option exposed beyond the metric and the number of degrees of freedom:

greedy -d 3 -a \
  -m NMI | -m NCC 4x4x4 | -m SSD \
  -i <T1.nii.gz> <T2.nii.gz> \
  -o <ID>_warp.mat \
  -n 100x100x50x25 \
  -e 0.5 \
  -search 100 10 20 \
  -dof 6|12 \
  -ia <init.mat> \
  [-gm <binarized mask>]
FlagValueMeaning (greedy docs)
-d 3fixedimage dimension
-afixedaffine/rigid mode. Greedy's diffeomorphic mode, which is its default and its reason for existing, is never used here
-m NMIindex 0 (UI default)normalized mutual information, for heterogeneous intensities
-m NCC 4x4x4index 1local cross-correlation, radius in voxels
-m SSDindex 2sum of squared differences, same modality
-i fixed movingT1 then T2fixed order: -i <fixed> <moving>
-o<ID>_warp.mat4×4 affine matrix (text)
-n 100x100x50x25fixed4 levels of multi-resolution pyramid, 100/100/50/25 iterations from coarsest to finest (greedy's default is 100x100, 2 levels)
-e 0.5fixedtime step — has no effect in affine mode: the greedy docs state plainly that "-s and -e have no effect" for -a. Dead line
-search 100 10 20fixedrandom search over 100 rigid transforms before optimization: σ_angle = 10°, σ_offset = 20 (voxels per the docs' prose, physical units per its usage text — the ambiguity is in greedy, not here)
-dof 6 / 12"Rigid"/"Affine" combo box6 = rigid, 12 = full affine. -dof 7 (rigid + uniform scale) is not offered
-iaalways providedinitialization matrix. Never -ia-identity, never -ia-image-centers
-gmif a mask is givenmask of the fixed volume: the metric's gradients are only computed inside it

Then a second call, always run, in resampling mode:

greedy -d 3 -rf <T1> -rm <T2> <ID>_registered.nii.gz -r <ID>_warp.mat

-rf sets the reference space (the fixed volume), -rm the input/output pair. The output volume is therefore the original T2 resampled into the T1 grid, with linear interpolation (the default for -ri). Each call is capped at timeout = 600 s.

6. Inputs, pairing, masks, initialization

Trap

Pairing. ID_PATTERN = ^([A-Za-z]+\d+) applied to the file name, uppercased (GreedyReg_CLI.py:37). A01_t1.nii.gz → identifier A01. A pair exists when the same identifier is found in both the T1 folder and the T2 folder; masks (.nii/.nii.gz) and inits (.mat) are optional and matched by the same identifier. A file named 01_T1.nii.gz (digits first) or Patient-01.nii.gz is never paired, silently.

findBatchPairs() in the widget duplicates this logic for the "Found N pairs" label; the comment warns that the two implementations must stay in sync.

Mask. Exported from a vtkMRMLSegmentationNode or a labelmap to .nii.gz, then binarized on the CLI side: (get_fdata() > 0).astype(float32) (GreedyReg_CLI.py:92). All segments of a multi-label segmentation are therefore merged into a single mask. This is the only real use of nibabel, along with the affine rewrite of the distant batch.

Trap

Initialization. Without an init file, writeIdentityInit() writes the identity with matrix[0,3] = 0.001 — a one-micron translation. The comment explains why: "so Greedy doesn't treat it as identity." This behavior is documented nowhere on greedy's side; it is an empirical workaround, and should be treated as such.

No intensity preprocessing: no normalization, no cropping, no preliminary resampling, no orientation conversion. The NIfTI files are passed as-is, and greedy works in the RAS physical space of the headers.

7. Batch mode

Two independent batches, which do not do the same thing.

Automatic batch (GreedyReg.py:1537). The widget does not loop: it launches a single GreedyReg_CLI run over the folders, and it is the CLI that iterates (main(), GreedyReg_CLI.py:141), emitting <filter-progress> / <filter-comment> tags read by Slicer's CLI infrastructure. The output folder is the T2 folder itself. No mask is binarized upstream, no init is passed (initFolder=""): the batch always starts from the nudged identity. First case that fails → sys.exit(1) → the whole batch stops.

Distant batch (GreedyReg.py:1606). Here, the widget loops case by case, with an ALI job queue per pair. The result is not a registered volume but a rewritten header (GreedyReg.py:1690):

newAffine[:3, :3] = R @ movingImg.affine[:3, :3]
newAffine[:3, 3]  = R @ movingImg.affine[:3, 3] + t
nib.save(nib.Nifti1Image(movingImg.get_fdata(), newAffine, movingImg.header), out)
Verified

The voxels do not move, only the voxel→world affine changes. This is correct: the NIfTI affine is in RAS, same as the Kabsch matrix. Output: <ID>_t2_aligned.nii.gz, written into the T2 folder. Greedy is not called at all in this batch.

8. Outputs

FileContentWhere
<ID>_registered.nii.gzT2 resampled into the T1 gridsingle case: temporary folder; batch: T2 folder
<ID>_warp.mat4×4 greedy affine matrixsame
<ID>_t2_aligned.nii.gzT2 voxels unchanged, affine correctedT2 folder (distant batch)

Transform format, and the conversion that does not exist. <ID>_warp.mat is a plain four-line text file, in greedy's own convention: a 4×4 matrix that maps fixed-volume RAS coordinates to moving-volume RAS coordinates ([ras(moving);1] = M · [ras(fixed);1], greedy docs, "Affine mode" section).

The "Save Transform Matrix" button does a plain shutil.copy of this file (GreedyReg.py:1288).

Trap

There is no conversion to .tfm or to anything ITK-related anywhere in the module. Anyone taking this over needs to know:

  • it is not an ITK transform file (TxtTransform), so it does not load as a transform in Slicer despite its .mat extension;
  • an ITK/Slicer transform on disk is in LPS, this one is in RAS: it needs conjugation by diag(-1,-1,1,1), on top of a possible inverse;
  • the expected conversion goes through c3d_affine_tool (recommended by the greedy docs), or the same code as FlexReg_CLI.py:186, which does exactly that for its own matrices.

Compared with FlexReg, which produces a reusable SimpleITK .tfm consumed by other modules in the repository, GreedyReg is a dead end: nobody consumes its matrix.

9. Initialization convention: very likely inverted

Manual mode writes the Slicer transform node's matrix, as-is, into <ID>_init.mat (Logic.py:277).

  • This matrix is a MatrixTransformToParent applied to the moving volume: it maps the moving volume's own coordinates to world coordinates, i.e. moving → fixed.
  • -ia expects a matrix of the same nature as the one produced by -o, i.e. fixed → moving.
Likely trap, unconfirmed

The two are inverses of one another. The manual pre-alignment is therefore very likely handed to greedy backwards (transposed rotation, opposite-sign translation). The rest of the repository knows this convention: FlexReg_CLI.py:186 explicitly inverts, with the comment "ITK convention: fixed -> moving."

Why it does not always show: -search 100 10 20 samples 100 random rigid transforms before optimization, and the 4-level pyramid forgives a lot. A bad starting point slows convergence and makes it more fragile, it does not prevent it. To be checked with a simple test (a pure 20 mm translation along X, comparing the written init and the returned matrix) before fixing it.

12. Traps and fragile points

Confirmed bug

The batch writes its outputs into the T2 input folder. A01_registered.nii.gz and A01_t2_aligned.nii.gz both map to the identifier A01 under ID_PATTERN. On a second run, the {id: path} dictionary keeps only one entry per identifier, the one encountered last in os.listdir: the previous run's result can therefore end up being registered again, non-deterministically. There is no exclusion filter on the produced suffixes.

Trap

The .mat produced is not a Slicer transform (§8): RAS, fixed→moving direction, plain text format.

Trap

The manual mode's init is likely inverted (§9).

Trap

-e 0.5 is a no-op in affine mode. Possibly confusing for anyone who thinks they are tuning an optimization step size.

Confirmed bug

Dead button: "Save Registered Volume" in the Distant panel reads self._distantResult, which is never assigned — it will always answer "No result to save!". Distant mode does not produce a volume anyway.

Confirmed bug

Misleading checkboxes in distant mode: the three structures are independent checkboxes, but _selectedDistantRegion() returns only one of them, by a fixed priority order. Checking "Mandible + Maxilla" does not combine the 10 landmarks.

Trap

Silent ALI failure: ALI_CBCT logs weight problems as a warning and exits with code 0. The code guards against this by systematically printing GetOutputText() (GreedyReg.py:1508), but the user only sees "only 0 matched landmarks."

Confirmed bug

Temporary folders are never cleaned up on the widget side (mkdtemp ×3, no rmtree). The CLI, on the other hand, does clean up its caseTmpDir per case.

Trap

One failure stops the entire batch (sys.exit(1) in the CLI's loop), with no resume and no list of the remaining cases.

Trap

Multi-segment mask flattened by the > 0 threshold, and the mask must be in the space of the fixed volume: -gm applies to the fixed volume, which the UI indicates ("Mask (T1)") but nothing verifies.

Note

Module metadata left unfilled: contributors = ["Your Lab"], acknowledgementText = "".

Trap

The widget contains roughly 500 lines of Qt style sheets and widgets (StandaloneRotationWheel, SliceTranslationOverlay) explicitly flagged as a prototype in the comments; they modify the same transform node as the sliders, so the two sets of controls step on each other without resynchronizing (the sliders are not refreshed after a wheel movement).

13. Literature

The engine is published, the module is not.

  • greedy: a tool by Paul Yushkevich (PICSL, UPenn), bundled with ITK-SNAP. The usual reference for citing it is Venet, Pati, Yushkevich, Bakas, Accurate and Robust Alignment of Variable-Stained Histologic Images Using a General-Purpose Greedy Diffeomorphic Registration Tool (arXiv:1904.11929). Documentation: greedy.readthedocs.io, code: pyushkevich/greedy. Note: the paper and the tool are about diffeomorphic registration; GreedyReg only uses the affine/rigid mode (-a), which is merely its initialization step.
  • ALI_CBCT: Gillot et al., Automatic landmark identification in cone-beam computed tomography, Orthodontics & Craniofacial Research, 2023 — virtual agents navigating a multi-scale volumetric space, reported mean error of 1.54 ± 0.87 mm across 32 landmarks. Original repository: Maxlo24/ALI_CBCT.
  • GreedyReg itself: no publication. The approach — "manual pre-alignment then intensity-based affine, with a mask" — is that of ITK-SNAP's Registration panel, of which this module is a transposition into Slicer; that is the only lineage the code can claim.

Full bibliography: SOURCES.html — verified references, the files retrieved into this folder (the greedy paper, the ALI_CBCT paper), and a detailed distinction between what the greedy paper describes and what this module actually executes.

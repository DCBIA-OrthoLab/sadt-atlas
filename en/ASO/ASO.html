ASO

Looks for a rigid rotation that brings a CBCT or an intraoral scan into the frame of a reference case (the "gold"), through a 3-point initialization followed by ICP — never an optimal least-squares registration.

Anchling 2023 · LNCS 14242 PRE_ASO_CBCT SEMI_ASO_CBCT PRE_ASO_IOS SEMI_ASO_IOS conda env: shapeaxi (IOS auto only) Bibliography

1. Where it sits in the pipeline

Nothing in the repository calls ASO. ASO, however, calls three tools, and AREG_IOS consumes its output directly: AREG_IOS.py:324 looks for <patient>_SegOr.tfm in the T1 and T2 folders — exactly the name written by PRE_ASO_IOS.py:422 — and composes inv(areg_matrix @ inv(matrix_aso)) to produce a single matrix from raw scan to registered.

3. The shared geometric principle

The target is not an analytical frame ("occlusal plane = z=0") but a reference patient case, downloaded from a release: scan + fiducials for the CBCT, two meshes + two jsons for the IOS. The choice of frame is thus offloaded into the data: Occlusal and Midsagittal Plane or Frankfurt Horizontal and Midsagittal Plane (CBCT.py:68) are two different golds, the same code producing two different orientations.

In both backends the estimation follows the same two-stage scheme:

  1. A 3-point initialization — a translation followed by two rotations around hand-built axes, never a least-squares Procrustes/Kabsch;
  2. a vtkIterativeClosestPointTransform in RigidBody mode on the anchor point clouds, to refine.

This is the point to remember: the matrix is not an optimal solution in the least-squares sense over N correspondences. It is built through successive rotations on a chosen triplet, then polished by an ICP that, for its part, re-pairs the points by nearest neighbor rather than by label.

4.2 PRE_ASO_CBCT — recentering, no more network computed

Despite its name and its six arguments, this CLI now does only one thing (PRE_ASO_CBCT.py:163):

T = -np.array(img.TransformContinuousIndexToPhysicalPoint(np.array(img.GetSize()) / 2.0))
translation = sitk.TranslationTransform(3); translation.SetOffset(T.tolist())
img_trans = ResampleImage(img, translation.GetInverse())

ResampleImage keeps the size (ratio = 1), the spacing and the direction, and sets new_origin = orig_origin - orig_center. Since the applied transform exactly cancels this offset, no real interpolation takes place: only the physical origin moves, and the volume ends up centered on the world origin. This is the prerequisite for §4.4, where the rotation is applied around the origin.

The arguments model_folder, SmallFOV and temp_folder are parsed and never used. PreASOResample (ResamplePreASO.py:199, an isotropic 128³ resampling) is imported but never called, and DenseNet (Net.py:39, a 3D monai DenseNet169 regressing a unit direction vector via cosine loss) is commented out in __init__.py. There is no longer any pre-orientation network in ASO_CBCT at all: its training code remains, the PreASOModels.zip weights are still downloaded and validated (CBCT.py:133, TestModel requires a .ckpt), for nothing.

Output: the recentered volume under its original name, and <name without extension>.tfm containing the translation T — not inverted, even though it is translation.GetInverse() that was applied to the volume.

Confirmed bug

convertdicom2nifti (utils.py:504) tries sitk.ImageSeriesReader then falls back to dicom2nifti. This fallback is broken: it calls search(output_folder, "nii.gz"), but search (utils.py:189) is declared as def search(self, path, *args) — the first argument is absorbed by self, args is empty, the returned dict is empty, and the ["nii.gz"] access raises a KeyError.

4.3 ALI_CBCT — the landmark provider predicted

Called on the temporary folder, both for input and output, with hard-coded constants (CBCT.py:515): spacing="[1,0.3]", speed_per_scale="[1,1]", agent_FOV="[64,64,64]", spawn_radius="10", and lm_type reformatted into a literal Python list by format_lm_string (CBCT.py:481). ALI_CBCT is a two-scale search agent system (1 mm then 0.3 mm, a FOV 64³ voxels around the agent); it writes one json per anatomical group, <id>_lm_Pred_<group>.mrk.json (environment.py:138), in LPS. The weights are <Landmark>_Net*.pth files downloaded one per landmark from ALI_CBCT/releases/download/models_v01/<LM>.zip.

This is the whole point of MergeJson (utils.py:65), the first call made by SEMI_ASO_CBCT: gluing the per-group jsons back into a single <patient>_lm_MERGED.mrk.json — and deleting the source files (os.remove).

4.4 SEMI_ASO_CBCT — the orientation computed

a) Pruning outlier landmarks. GetLandmarkToRemove (utils.py:413) compares the full distance matrix and the direction matrix between all the landmarks of the scan and those of the gold. Actual constants: distance gap > 15 mm, angular gap > 0.4 rad (and -1 if < 0.1 rad, meaning a very consistent pair offsets a doubtful one). A landmark is dropped if its total count exceeds the number of landmarks, or if its angular count alone exceeds half of it. The analysis covers all landmarks in the json, not only the checked ones.

b) The optimal triplet. FindOptimalLandmarks (utils.py:161) randomly draws triplets (A, B, C), runs the initialization for each, and keeps the one that minimizes the final average distance. Bounds: n(n-1)(n-2) distinct triplets or 2500 draws, whichever comes first.

c) The initialization, InitICP (utils.py:649):

  1. translation bringing A_source onto A_target;
  2. rotation about the axis cross(v2, v1) by the angle arccos of the dot product, where v1 = abs(B - A) on the source side and v2 = abs(B - A) on the target side — component-wise absolute values, which folds both vectors into the positive octant and is not the angle between the actual vectors;
  3. a third rotation whose axis is abs(B - A) itself, not a cross product: it is a roll around the axis just aligned, with its angle computed from C.

RotationMatrix (utils.py:921) is the quaternion-based Rodrigues formula, identical to the one in FlexReg and ASO_IOS. A crucial point: TransformMatrix = RotationTransformMatrix # @ TranslationTransformMatrix — the translation from step 1 is deliberately excluded from the returned matrix. It is used to compute the rotations, not to move the volume.

d) The ICP. ICP_Transform (utils.py:620) converts the two dictionaries into vertex vtkPolyData and runs a vtkIterativeClosestPointTransform: SetModeToRigidBody(), SetMaximumNumberOfIterations(1000), StartByMatchingCentroidsOn(). Its translation is then zeroed out: TransformMatrixBis[:3, 3] = [0, 0, 0].

e) Composition. TransformList accumulates [translation, R2, R3, R_icp], then (utils.py:803):

for i in range(len(TransformList) - 1, 0, -1):   # stops at 1: the translation is discarded
    TransformSITK.AddTransform(TransformList[i])
TransformSITKFinal = sitk.CompositeTransform(TransformSITK)
TransformSITKFinal.AddTransform(input_transform)   # the PRE_ASO .tfm
TransformSITKFinal = TransformSITKFinal.GetInverse()
TransformSITK = TransformSITK.GetInverse()

The final result is therefore a pure rotation around the world origin. This is consistent because PRE_ASO_CBCT centered the volume on that origin — and this is precisely what the semi mode lacks.

ResampleImage (utils.py:835) calls SetReferenceImage(image): same grid, same size, same spacing, linear interpolation, DefaultPixelValue = 0. The volume rotates within its existing box, nothing is resampled to a different resolution, and whatever falls outside the FOV is lost.

f) Outputs, in output_folder with the same relative tree structure as the input:

FileContent
<patient>_<suffix>.nii.gzreoriented volume, always .nii.gz regardless of the input format
<patient>_lm_<suffix>.mrk.jsonrotated landmarks, written by WriteJson in LPS
<patient>_<suffix>_transform.tfmTransformSITKFinal, ITK convention (fixed → moving)

All three writes are guarded by if not os.path.exists(...): rerunning on a non-empty output folder rewrites nothing and still ends in success.

5. ASO_IOS

5.1 Automatic mode — crown centroids

a) Segmentation bypass. __BypassCrownseg__ (IOS.py:196) opens each mesh and looks for a PredictedID, UniversalID or Universal_ID array. Already-segmented meshes are copied directly into the segmentation's output folder with the suffix _Seg; the others go to the input folder to be segmented, with exotic formats converted to .vtk along the way.

b) DentalModelSeg predicted, via conda (IOS.py:275):

conda run -n shapeaxi python -m CrownSegmentationcli \
  None <csv> <out> 0 latest 0 Universal_ID 0 Seg <vtk_folder> <dentalmodelseg_path>

Argument order: surf, input_csv, out, overwrite, model, crown_segmentation, array_name, fdi, suffix, vtk_folder, dentalmodelseg_path. overwrite = "0" and suffix = "Seg": unlike FlexReg, ASO does not overwrite the input file, it produces a <name>_Seg.vtk in a temporary folder. The network is the same one (multi-view Fly-by-CNN, universal 1–32 numbering in Universal_ID), bundled in the pip package shapeaxi: the latest architecture and weights cannot be determined from this repository.

The dentalmodelseg_path computed in Process is dead: run_conda_tool (ASO.py:1417) replaces it with the result of a which dentalmodelseg inside the environment. The if os.path.isfile(path_input) branch (IOS.py:266) is dead too — path_input is always a folder created by os.makedirs — and it references a self.input that does not exist. path_preor is created and never used.

Execution is synchronous and blocking: run_conda_tool loops on process.is_alive() while calling slicer.app.processEvents(), tracks progress by re-reading the log, then removes the step from the queue before onPredictButton launches slicer.cli.run on the next one.

c) PrePreAso — the orientation computed, the core (pre_icp.py:103). organizeLandmark (pre_icp.py:43) sorts the 3 or 4 chosen teeth into (left, middle(s), right) using the universal numbering: on the upper arch (1–16) the number increases from right to left, so max → left; on the lower arch (17–32) it's the reverse.

vtkMeanTeeth (icp.py:415) averages the vertices carrying each Universal_ID. With 4 teeth, the two middle centroids are averaged together → it always comes back to three points.

make_vector builds, for each triplet, a local basis: normal = cross(m→d, m→g) (the normal of the plane through the three points), perpen = the right→left direction, direction = cross(normal, perpen). Then:

  1. rotation about the axis cross(normal_source, normal_target) by the angle arccos(dot) — the plane of the scan's three centroids is brought onto the gold's;
  2. direction_source is rotated by this matrix, then a second rotation about the axis cross(direction_source, direction_target) fixes the roll within this plane;
  3. a translation that makes the centroids of the two triplets coincide.

No scaling. The 4×4 matrix is returned along with the transformed mesh.

d) The refinement. ICP([InitIcp(), vtkICP()], option=vtkMeanTeeth(dents)) (PRE_ASO_IOS.py:292). The option is applied to both meshes before the chain runs: the ICP only ever sees the 3 or 4 centroids, never the crown geometry. InitIcp (icp.py:136) is the class version of ASO_CBCT's InitICP — the same abs(), the same roll axis, the same FindOptimalLandmarks with 2500 draws. vtkICP is the same rigid vtkIterativeClosestPointTransform, but with 100 iterations instead of 1000, and its translation is not zeroed out.

Confirmed bug

A telling detail: InitIcp.__call__ does an np.save of source and target into ASO_IOS_utils/cache/, and FindOptimalLandmarks reloads the .npy on every iteration instead of copying the dict in memory — a workaround for a mutation, at the cost of a write into the module's installed tree (both .npy files were once committed then removed, commit a334a10).

The final matrix is output_icp["matrix"] @ matrix: ICP after PrePreAso.

5.2 Semi mode — supplied landmarks computed

SEMI_ASO_IOS.py. Same machinery, option becomes SelectKey(liste_de_landmarks) (icp.py:480): a simple key filter over the landmark dictionaries. No more PrePreAso, no more segmentation — InitIcp then vtkICP on the named landmarks.

Landmark names are built by a Cartesian product in the UI: {dent}{repère} with repère ∈ O, MB, DB (occlusal) or CB, CL, OIP, R, RIP (cervical), then listlandmark2diclandmark splits them by arch based solely on the initial U/L (utils.py:272).

The matrix obtained from the landmarks is then applied to the full mesh.

5.3 Occlusion

A checkbox that forces a single arch (ASO.py:1850): the chosen arch drives the orientation, and the same matrix is applied to the opposite arch (file[jaw.inv()], PRE_ASO_IOS.py:473) to preserve the occlusal relationship. Upper/lower pairing is done by file name, via Files_vtk_link / Files_vtk_json_semilink (data_file.py): the recognized markers are Upper/_U_ and Lower/_L_.

Pitfall

UpperOrLower (utils.py:180) defaults to "Lower" when no marker is found: a poorly named file is silently treated as mandibular.

saveMatrixAsTfm (utils.py:300) inverts the matrix (ITK fixed → moving convention) and writes it as an AffineTransform. No LPS↔RAS conjugation: ASO_IOS never flips anything, meshes are read and rewritten in the file's own coordinates (LPS for a .vtk), and the matrix is expressed in that same frame. 6. Comparison with FlexReg's orientation

FlexReg_Method/orientation.py and ASO_IOS_utils/pre_icp.py are the same algorithm, copy-pasted. make_vector is identical character for character; the bodies of orientation() and PrePreAso() differ only on three points:

ASO_IOS PrePreAsoFlexReg orientation
Targetthe gold mesh's centroids, read with the same vtkMeanTeeththree hard-coded points, [[-0.5,-0.5,0], [0,0,0], [0.5,-0.5,0]]
Teeth3 or 4 chosen by the operator, sorted by organizeLandmark3, 5, 12, 14 hard-coded (UR6, UR4, UL4, UL6)
Return(mesh, matrix)mesh alone

transformation.py is likewise duplicated between the two (same RotationMatrix, TransformSurf, TransformDict, formatting aside), and ASO_IOS's icp.py holds the classes from which FlexReg_Method/util.py reuses vtkTeeth, vtkMeanTeeth and vtkMeshTeeth.

Practical consequence: FlexReg produces a canonical and reproducible frame (occlusal plane ≈ z=0, +y anterior), which then lets it reason in 2D within the XY plane. ASO_IOS produces an orientation relative to a reference patient — no guarantee that the occlusal plane lands on z=0, and no ICP refinement in FlexReg where ASO adds one.

8. Environment

Two distinct regimes, and this is a source of confusion.

The CLIs run in Slicer's Python. install_function (ASO.py:69) pip_installs whatever is missing there: itk, torch==2.2.0, pytorch_lightning, dicom2nifti==2.6.2, pydicom==3.0.2 and monai at 1.3.2 (Python ≥ 3.10) or 0.7.0 otherwise.

Pitfall

torch, pytorch_lightning and monai are only used by Net.py and by ALI_CBCT: in semi-CBCT mode and in IOS, ASO installs them for nothing, with the risk of overwriting another module's version of torch (the dialog says so itself: "Doing it could break other modules").

The conda environment is only set up for the automatic IOS mode, by onCheckRequirements (ASO.py:1867):

No GPU is required by ASO itself; it is required by dentalmodelseg.

9. Pitfalls and fragile points

Confirmed bug

The semi-CBCT mode is broken as it stands. SEMI_ASO_CBCT.py:113 requires data["tfm"], introduced by commit 1bfb51f at the same time as the matrix output. This .tfm only exists because PRE_ASO_CBCT writes it — but the semi mode does not run PRE_ASO_CBCT and works on the user's raw folder. Result: a KeyError for any patient whose folder does not already contain a .tfm, caught and logged as "missing required files," with the patient counted as a failure without interrupting the others. The mode therefore only works if a .tfm happens to sit next to the scan — typically after a prior pass through Fully mode, since PRE_ASO_CBCT.py:217 writes its own into the scan's folder. Verified: GetPatients (utils.py:1042) only fills the tfm key if a .tfm file is present in the input tree.

And even without that, the semi mode has no recentering. Since the orientation is a pure rotation around the world origin (§4.4e), an off-center volume ends up outside its own FOV, DefaultPixelValue = 0.

Confirmed bug

MergeJson deletes files in the input folder. In semi mode, input_dir is the user's folder: all of its .mrk.json files without MERGED in their name are merged and then erased (utils.py:111).

Pitfall

The coordinate system of the jsons is never checked. LoadJsonLandmarks reads position raw; ALI and ASO write LPS, but a fiducial exported as RAS from Slicer will be read with x and y flipped, with no warning.

Pitfall

Inconsistent minimum landmark count. The UI requires 3 checked landmarks (TestCheckbox, CBCT.py:85) but ICP bails out as soon as len(list_landmark) <= 3 (utils.py:754). So 4 are actually needed, and more if pruning removes some.

  • The ICP re-pairs by nearest neighbor. vtkIterativeClosestPointTransform ignores labels: on landmarks that are pairwise close (left/right pairs), it can lock in a crossed pairing that the initialization had already gotten wrong.
  • The abs() calls in InitICP. The vectors are folded into the positive octant before the angle calculation, in both backends. Since the retained triplet is the one that minimizes the measured error, the search compensates for this — but nothing should be concluded from the geometry of this step taken in isolation.
Pitfall

Nothing is rewritten if the file already exists. All three CBCT outputs are guarded by if not os.path.exists. A second pass after fixing a parameter produces no visible effect and still ends in success.

Confirmed bug

Patient identifiers diverge between ASO and AREG. PatientNumber (utils.py:295) cuts on _U/_L, while AREG_IOS rebuilds it as patient_id.split("_")[0] (AREG_IOS.py:321). A name like P01_T1_U.vtk gives P01_T1 on one side and P01 on the other: ASO's .tfm is never found, and AREG settles for a logger.warning. Incidentally there are two PatientNumber functions in this file, the one at line 229 (first group of digits) being shadowed by the one at line 295.

  • Dead code: Net.py (DenseNet) and PreASOResample on the CBCT side; the search with a phantom self; DisplayALIIOS; Files_vtk_json_link; vtkMiddleTeeth; npSameNumberPoint (the source.shape[0] < target.shape[0] branch, which references an undefined target_points); the orphan file LinearTransform_t.tfm, referenced nowhere.
  • PRE_ASO_CBCT's .tfm is written non-inverted, even though it is its inverse that was applied to the volume. It is later composed and then inverted as a block in SEMI_ASO_CBCT; worth checking before reusing this file on its own.
  • Time-point suffixes. PatientScanLandmark (CBCT.py:36) only cuts on _T1/_T2; a _T3 breaks the pairing. The comment is already there in the code.

10. Literature

The reference paper for ASO_CBCT is Automated Orientation and Registration of Cone-Beam Computed Tomography Scans (Anchling, Hutin, Cevidanes et al., Lecture Notes in Computer Science, 2023). Its description matches the code: ALI_CBCT identifies the landmarks regardless of the input orientation, then the orientation is obtained "by first aligning 3 randomly chosen landmarks, then refining with ICP." Reported errors: < 3° and < 2 mm against experts. The paper does not mention the DenseNet pre-orienter, consistent with the fact that it is no longer connected.

For ALI_CBCT itself: Automatic landmark identification in cone-beam computed tomography (Gillot et al., Orthodontics & Craniofacial Research, 2023).

ASO_IOS has no paper of its own. The closest published text is AReg IOS: Automatic Registration on IntraOral Scans (Hutin, Anchling, Cevidanes et al., LNCS 2023), which describes the initial alignment by shared tooth centroids — that is, exactly PrePreAso. The rest (tooth selection by the operator, ICP refinement on 3 centroids, occlusion mode) is unpublished internal development.

ASO — sources

ASO's bibliography: what has been deposited in this folder, what is still to be read online, and the neighborhood — the works that underpin the method without describing the code.

29 PDFs / 54 full texts total in the repository ← Pipeline page

ASO_CBCT is published, in a MICCAI workshop proceedings chapter (LNCS 14242, 2023) that it shares with AREG_CBCT: the same text describes the orientation (ASO) and the registration (AREG). The chapter is paywalled at Springer, but the author manuscript is freely readable on PMC (PMC11104011); PMC blocks automated PDF downloads, so it could not be deposited here (see "To read online"). ASO_IOS has no paper of its own: the closest published text is AReg IOS (Hutin et al., LNCS 14350, 2023), which describes the initial alignment by shared tooth centroids, that is, PrePreAso.

The chapter's ASO_CBCT description matches the code (ALI_CBCT landmarks, alignment of 3 landmarks followed by ICP refinement); the DenseNet pre-orienter, absent from the paper, is indeed no longer connected. Watch out, however, for the AREG side of the same chapter: it no longer describes the current registration code (one pass instead of two, itk-elastix instead of SimpleElastix, AMASSS on nnU-Net v2 instead of UNETR) — details in ../AREG_CBCT/SOURCES.md.

Neighborhood

These works do not describe ASO; they underpin the method or show it in use.

  • Ruellas 2016, Common 3-dimensional coordinate system. This is the article that defines the common coordinate system toward which ASO orients: it first shows that head orientation changes the displacement values measured in 3D, then proposes building a common frame from landmarks. ASO's orientation "gold standard," and the reference landmarks shipped with the module, come from this convention. It speaks of neither ASO nor deep learning: everything in it is manual.
  • Gillot 2023, ALI_CBCT. The reinforcement-learning landmark detector that ASO_CBCT depends on to find the points regardless of the input orientation. Describes the 32 landmarks and the multi-scale agent, not the orientation step. Own page: ../ALI/.
  • Barone 2024 (AJODO). Clinical use, not validation: the article states that "deep-learning-based automated tools were used for orientation, registration, bone segmentation and landmark identification" of CBCTs in 3D Slicer. That is ASO + AREG + AMASSS + ALI under real conditions, on 17 operated Class III patients.
  • NA-MIC Project Week pages, no DOI: PW38 2023 Gran Canaria — ASO_CBCT (Anchling, Hutin, Gillot, Baquero, Bianchi, Ruellas, Miranda, Barone, Gurgel, Yatabe, Al Turkestani, Joshi, Cevidanes, Prieto) — this is where the "under testing" pre-orienter that was never connected is described; and PW38 — Automatic Standardize Orientation IOS (Hutin, Anchling, Gurgel, Miranda, Al Turkestani, Barone, Cevidanes, Prieto), the only written description of the complete ASO_IOS pipeline — pre-orientation by molars and incisor, ICP on 3 centroids, ALI_IOS landmarks, occlusion mode.
  • Code repositories, no DOI: lucanchling/ASO, DCBIA-OrthoLab/ASO, DCBIA-OrthoLab/SlicerAutomatedDentalTools.

What was searched for and not found

  • Open-access author version of the LNCS chapter anywhere other than PMC: Deep Blue (University of Michigan), HAL/DUMAS, Unpaywall, OpenAlex. Nothing.
  • A paper of its own for ASO_IOS, and a paper on ALI_IOS (the landmark detector on IOS used by ASO_IOS): nothing in Europe PMC, Crossref or OpenAlex. Confirms the page.
  • Separate clinical validation of the orientation alone (IADR / AADOCR / AAO posters, an ASO reproducibility article): nothing indexed. The published figures for ASO remain those of the LNCS chapter (< 3° and < 2 mm against experts). IADR abstracts do not carry a DOI; if any exist, they must be found through the IADR abstract archive.
  • A publication describing the DenseNet pre-orienter: nothing, beyond the paragraph on the PW38 Project Week page.

How the full text was retrieved

The chapter is paywalled at Springer, but the author manuscript deposited with the NIH is open access. Two recipes fail on it and one works — noted here to avoid retracing the steps:

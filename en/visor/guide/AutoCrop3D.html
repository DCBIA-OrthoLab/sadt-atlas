AutoCrop3D with VISOR

What changes when you run AutoCrop3D through a VISOR server from 3D Slicer: what to provide, what is the same, what is different. The legacy module has its own page.

VISOR Legacy page Atlas (VISOR)

Through a VISOR server the module is called AutoCrop3D Remote. You still draw the box in Slicer; the files are sent to the server, cropped there, and the results come back to a folder you choose. The panel is built from what the server publishes, in three groups: Inputs, Options and Outputs. Nothing is installed or downloaded on your computer, and the crop needs no model.

What you provide

  • The scans: one volume or a folder (.nii.gz, .nii, .nrrd, .gipl.gz, .gipl), uploaded to the server. A .nrrd.gz is refused with a message: decompress it to .nrrd first. A server can also host test files; the dropdown then offers MG_test_scan.nii.gz. The default upload limit is 500 MB, and a folder goes up as a single request because AutoCrop3D cannot be split by patient.
  • The region of interest: pick the ROI you drew, straight from the scene (the ROI row lists the ROI nodes of the scene), or give a .mrk.json file or a folder of them. The hosted test box is called ROI_box.
  • Options: keep the original size, whether to produce a mesh (surfaces), the mesh margin in millimetres, the mesh smoothing, and the output suffix (cropped by default). Then choose an output folder.

What stays the same

  • The crop is the same arithmetic: the box is mapped to voxel indices of the original grid and the block is extracted, with no resampling. The port keeps even the truncation toward zero, on purpose.
  • One ROI for everybody, or one ROI per patient matched by name. Output files keep the input folder layout.
  • Results are unpacked into the output folder you chose; up to 12 are loaded into the scene, shown with the CT-AAA volume rendering preset.

What is different

  • No "Crop Volume for tilted images". A rotated ROI is cropped as its axis-aligned box and the report carries roi_orientation_ignored.
  • A ROI saved in RAS is understood. The coordinate system declared in the file is read.
  • Naming mistakes are named. The panel ends with a line such as "N of M scan(s) cropped. No ROI for: …". The run report lists the same scans.
  • A box that misses the volume is an error (the ROI does not overlap this volume), and a box that only partly overlaps is cropped and flagged clamped_to_the_volume.
  • Earlier results are not cropped again. If the scans folder also holds files ending in _cropped (or your suffix) from a previous run, they are left aside.
  • No per-scan progress. The tool does not report progress while it runs; the run report AutoCrop3D_report.json, unpacked with the results, gives the duration and the outcome of each scan.
A mesh needs a segmentation-like file name

With the default surfaces = segmentations, a file called P1_Seg.nii.gz gets a mesh and a file called Mandible.nii.gz does not (checked on 2026-11-09 against the port's own rule). A folder name does not count. Rename the file, or set surfaces to all. The mesh is placed in the scan's own space, so it lies over the cropped scan in Slicer.

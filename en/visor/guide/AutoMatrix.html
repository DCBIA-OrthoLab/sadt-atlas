AutoMatrix with VISOR

What changes when you run AutoMatrix through a VISOR server from 3D Slicer: what to provide, what is the same, what is different. The legacy module has its own page.

VISOR Legacy page Atlas (VISOR)

Through a VISOR server the module is called AutoMatrix Remote. You choose the files and the transforms in Slicer; they are sent to the server, which pairs them by patient, moves them, and sends the results back to a folder you choose. The panel is built from what the server publishes. Nothing is installed or downloaded on your computer.

What you provide

  • Files to transform: a scan, a segmentation, a landmark file (.mrk.json) or a folder of them. A server can host test sets (AutoMatrixRelease1 to 4) that appear in the dropdown.
  • Transforms: .tfm, .mat, .h5, .hdf5 or .txt, a file or a folder. A file holding a plain 4×4 matrix (four lines of four numbers, which is what GreedyReg writes as .mat) is read too, as an affine matrix taken as written.
  • Same transform for every patient: tick it when you give a single transform for the whole folder. Without it, a transform whose name matches no patient is used only if there is exactly one patient; with several patients nothing is written and the run stops with an error.
  • Include the transform name and Output suffix (Reg by default, so P1_T1.nii.gz comes back as P1_T1_Reg.nii.gz).
  • Use the mirror matrix: one tick fills Transforms with the server's hosted mirror matrix and ticks "Same transform for every patient". It is greyed out if the server does not host that file.

Two settings are hidden in the panel: how to resample (the server decides file by file whether a volume is a labelmap, so there is no segmentation box any more) and the reference volume.

What stays the same

  • Volumes are resampled with the transform; landmark points move through its inverse, so a scan and its landmarks keep the same motion.
  • Several transforms for one patient give one output each, never a chain. The landmark coordinateSystem is still not read.
  • The output keeps the input folder layout; up to 12 results are loaded into the scene.

What is different

  • One naming rule for scans and matrices (P1_scan.nii.gz pairs with P1_matrix.tfm). Where it fails, a fallback imitates the legacy cuts, and the report says which patients were paired that way (paired_by).
  • Unpaired files are reported in AutoMatrix_report.json.
  • No meshes and no .npy; the supported volumes are .nii.gz .nii .nrrd .gipl and their .gz forms (.nrrd.gz is looked for but cannot be read).
  • A transform that cannot be inverted (a deformation field) makes that patient's landmark file fail; the failure is in the report.
The final status line is wrong

The message shown in Slicer's status bar when the run ends always says "AutoMatrix: 0 file(s) written.", and never mentions unpaired files. It reads two fields that the report does not have. Judge the run from the output folder and from AutoMatrix_report.json (summary.files_written, without_a_transform, transforms_without_a_file).

Without a reference volume the result can land beside the data

The panel offers no reference volume. With none, the output keeps the input size but takes the transform's image of the origin as its origin. Tested on 2026-11-09 by calling the server's tool directly with a substitute reflection matrix on a small volume centred on the origin: the output was empty, and it was complete when the volume was its own reference. A plain translation also shifts the content and can cut part of it. This is what the mirror box uses. A fix exists on an unmerged branch (fix/automatrix-mirrors-into-an-empty-box, commit ce4f6fb), so look at the result before you rely on it. Details in the Atlas page.

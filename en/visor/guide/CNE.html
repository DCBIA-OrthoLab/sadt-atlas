CNE with VISOR

What changes when you run CNE through a VISOR server from 3D Slicer: what to provide, what is the same, what is different. The legacy module has its own page.

VISOR Legacy page Atlas (VISOR)

With a VISOR server the extraction runs on the server, not on your computer, and the CNE panel is a form that sends your notes there. Details of the code are on the Atlas page; connecting and running in general are in Using VISOR.

Your notes are uploaded

The text of the notes you select leaves your workstation and is read by the server. The current client does not de-identify anything before sending, so the legacy guide's "Nothing leaves your machine" does not apply here. Remove identifying information first, and only use a server your institution has approved for clinical text. What is and is not protected is on Security and privacy in VISOR.

What changes in the panel

  • Nothing is installed in Slicer: no extra packages, no model download of several gigabytes. The model is on the server.
  • The model is the one selected in the Model field, not one picked for your note type. Some client texts say the model can be left on "automatic" and that the server then picks the one for your note type. That is out of date: the field has no "automatic" entry, it lists the models hosted on the server, and nothing checks that your choice matches the note type beyond a warning in the report.
  • Only the TMJ model is hosted at the moment. You can still choose Ortho as the note type, but there is no Ortho model to pair with it. If the model you pick is named for the other type, the run goes ahead and puts a warning in the report.
  • Notes may be in subfolders (one folder per patient works), and extensions such as .PDF are found whatever their case.
  • You can also set the longest answer per note (2048 tokens by default), the temperature and the context window. The processor is not a choice in the panel: the server's language-model engine is the CPU build, so the extraction runs on the CPU.
  • The notes field can offer a test note hosted on the server (one synthetic TMJ note).

What is different in the results

  • For each note you get two files, Extraction_<note file name>.json and a readable .txt, with the source extension kept: B_001.txt gives Extraction_B_001.txt.txt. Notes sharing a name but not an extension no longer overwrite each other.
  • A CNE_report.json file says which model ran, with which settings, which notes were extracted and why others were not. The status bar shows a one-line summary and the number of warnings.
  • The model's answer is never saved as raw text when it cannot be read: the note is reported as failed. A scanned, image-only PDF is refused by name instead of producing an invented extraction, and an answer cut off at the length limit is a failure, not a file. Table content in Word files is read.
  • There is no Dashboard button in the VISOR panel. The legacy Dashboard reads Extraction_*.txt files with the old names, so it is not a drop-in on these results.

Still true: the content comes from the model alone, so read every extraction before relying on it. Nothing cuts a long note into pieces to fit the context window, and Ortho mode sends no instruction to its model.

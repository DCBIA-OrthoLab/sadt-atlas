FlexReg with VISOR

What changes when you run FlexReg through a VISOR server from 3D Slicer: what to provide, what is the same, what is different. The legacy module has its own page.

VISOR Legacy page Atlas (VISOR)

Through VISOR, the module is FlexReg Remote. The patch and the registration run on a server; the preview of the patch outline stays in Slicer. Using VISOR explains how to connect Slicer to a server; this page covers what is specific to FlexReg.

What changes in the panel

  • Joysticks. The four corners of the palatal patch are four 2D joysticks (ratio from the middle of the arch to the tooth, and shift forward or backward in millimetres), plus one joystick that moves the whole patch. A value outside their range is refused by the server.
  • Preview. With "Preview the patch while I drag" checked (it is by default), the outline of the patch is redrawn in the 3D view as you move a joystick, without waiting for the server. It needs the arch to be a surface loaded in the Slicer scene; with a folder of arches, there is no preview. Only the outline is drawn: the filled patch used for the registration is computed by the server when you press Apply.
  • What to do: Patch (build the patch and write the surface), Register (register on a patch already in the file) or Patch and register (the default). To register, pick the reference surface.
  • Two choices of patch: the palate (butterfly), or the mucogingival line, which has to be in the file already.
  • Input: a labelled arch as .vtk, .vtp or .stl, or a folder of them; the server may offer test arches.
  • Not available: the free-hand outline, patch deletion, the lower-arch band computed from the landmarks, the second arch following the first, and automatic crown segmentation. The arch must already carry its tooth labels.

What stays the same

The construction of the butterfly patch and the rigid registration on it are the same code as in the legacy module, and the transformation is written as a .tfm in the same way.

What is different in the results

  • Nothing is overwritten. For each arch you get <name>_Reg (the suffix is editable) in the output folder, with your folder tree reproduced, plus the .tfm when you registered, plus a FlexReg_report.json.
  • If a tooth needed by the patch is missing from an arch, that arch is reported as failed with a message; the legacy module wrote the arch back without a patch and looked successful.
  • The output keeps your input extension but is always written as a VTK file.
The reference must already carry its patch

In "Patch and register", the patch is built on the arch you register, not on the reference. Both meshes must have the patch: build it on the reference first (mode Patch on that arch), then use the result as the reference. Otherwise the run stops with an error that is not reported per arch, and a batch ends without a report. (Reference: SADT-VISOR sadt_flexreg/__init__.py:121, 155-157, 177, read from the code, not run.)

The mucogingival line cannot be created by VISOR

Choosing "Mucogingival line" only works on a file that already has that region marked. Nothing in VISOR computes it, and in Patch mode that choice copies your arch unchanged and still reports success.

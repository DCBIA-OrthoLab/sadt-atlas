AMASSS with VISOR

What changes when you run AMASSS through a VISOR server from 3D Slicer: what to provide, what is the same, what is different. The legacy module has its own page.

VISOR Legacy page Atlas (VISOR)

Through VISOR, the module is AMASSS Remote: the computation runs on a server, not on your computer. Using VISOR explains how to connect Slicer to a server; this page covers what is specific to AMASSS.

What changes in the panel

  • Nothing to install, no model to download. The "Download latest models" button and the first-run installation of libraries are gone: the models are on the server, and you cannot pick or send your own.
  • Input: one scan or a whole folder, as before. A folder is zipped and sent; a large cohort is cut into batches by the panel (by default at most 400 MB or 25 files per batch). If the server offers test files, you can pick one instead of your own scan.
  • Structures: nine are offered, shown as chips. Mandible, maxilla, cranial base, cervical vertebra and upper airway are checked by default; skin and the three masks (cranial base, mandible, maxilla) are not. Teeth, root canal and mandibular canal are not offered. At least one structure and one output form must be selected.
  • Outputs: merged and/or separate segmentations, a prediction identifier (default Pred), and surface generation. Surface smoothing and reduction, the device and the resampling choices exist but are hidden in the panel.
  • Not available: "small FOV" and DICOM input.

What stays the same

One network per structure, the same label values in the merged map (mandible 1, cranial base 2, upper airway 3, maxilla 4, cervical vertebra 5, skin 6, then the three masks 7 to 9), and no cleanup of the network's raw output.

What is different in the results

  • Results come back as a zip that the panel unpacks into the output folder you pick. For each scan there is a folder <scan>_<ID>_SegOut, and at the root an AMASSS_report.json that says which structures were done, which failed, and what happened to each scan.
  • File extensions can change: .nii comes back as .nii.gz, .gipl as .gipl.gz, and .nrrd.gz as .nrrd.
  • Surfaces are written in binary and reduced by 90 % of their triangles by default, so they are much lighter than the legacy ones.
  • At most 12 results are loaded into the scene; the rest stay in the output folder. Your scan is shown in 3D with the CT-AAA volume rendering preset.
A scan can be skipped without a message

When you give a folder, files whose name ends in _CB, _MAND, _MAX, _CV, _UAW, _SKIN, _CBMASK, _MANDMASK, _MAXMASK, _MERGED, _Seg or _SegOut, or that contain _Pred_ (your prediction identifier), are taken for earlier AMASSS outputs and left out. Only a count is logged, not the names. If you named a patient's scan P01_CB.nii.gz, rename it, or pass that file on its own: a single file is never filtered. (Reference: SADT-VISOR sadt_amasss/pipeline.py:69-132.)

Graphics memory

If the server's graphics card runs out of memory on a structure, that structure is missing from the result and listed as failed in the report; the legacy module retried it with the resampling done on the CPU. The run only fails if every structure fails (SADT-VISOR sadt_amasss/pipeline.py:475-488).

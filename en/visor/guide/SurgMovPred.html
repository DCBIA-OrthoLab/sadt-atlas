SurgMovPred with VISOR

What changes when you run SurgMovPred through a VISOR server from 3D Slicer: what to provide, what is the same, what is different. The legacy module has its own page.

VISOR Legacy page Atlas (VISOR)

Through VISOR, SurgMovPred runs on a server and Slicer only shows its panel. The prediction itself is the same: the same 112 models, applied row by row to your table. What changes is what you have to provide.

  • One input instead of two folders. The legacy panel asked for an input folder and a model folder; here you give only the measurements, a single .csv, .xlsx or .ods table, or a folder of tables. There is no model folder to download or to point to: the server holds the models and the panel hides that choice. The server may also offer its hosted example table (patients_to_predict.xlsx, 101 patients) as a test file.
  • Input rules are unchanged. A folder is read flat, without its subfolders; only the first sheet of a workbook is read; headers are cleaned the same way; the patient identifier column is detected by the same names; a model whose columns are not all present is skipped, with the same _T0 tolerance (VISOR:SADT-VISOR tools/Surg_Mov_Pred/src/sadt_surgmovpred/pipeline.py:143-147,223-236).
  • The result is saved, not loaded. As before, you choose an output folder. The server returns a zip holding predictions_outputs.xlsx and predictions_outputs.csv, the panel unpacks it there, and nothing appears in the Slicer scene. Both files start with an unnamed column of row numbers before IDPatient (pipeline.py:283-284).
  • No dependency is installed on your machine. The numpy reinstall at every Apply belongs to the legacy module only; the server runs the tool in its own environment.
  • Stable output order. The models are read in sorted order, so the columns come in the same order on every run, and the files of a folder are stacked in sorted order (pipeline.py:143-147,173).
Two cases now stop with an error

If a header cannot be cleaned into a column name, the run stops and names the column (VISOR:SADT-VISOR tools/Surg_Mov_Pred/src/sadt_surgmovpred/pipeline.py:57). If no model at all can predict from your table, the run stops with an error instead of producing empty files (pipeline.py:260). A table that only lacks some columns still yields fewer predicted columns without an error.

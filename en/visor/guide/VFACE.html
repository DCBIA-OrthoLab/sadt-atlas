VFACE with VISOR

What changes when you run VFACE through a VISOR server from 3D Slicer: what to provide, what is the same, what is different. The legacy module has its own page.

VISOR Legacy page Atlas (VISOR)

Through VISOR, VFACE runs on a server and Slicer only shows its panel. The measurements, the classification and the chain of six modules are the ones described in the legacy guide; what changes is where they run and what you have to provide.

Only on servers built from two feature branches

The server side of VFACE exists only on development branches (SADT-VISOR tool/vface and VISOR-serve conf/vface-deployment), not on their main. A VISOR server built from main does not offer VFACE, even though the VFACE panel ships with the Slicer extension. Ask whoever runs your server.

  • No download step. The button that fetches the weights is gone: the segmentation, landmark and classifier models, the orientation references, the mirror transform and the measurement list all live on the server, and the panel does not show them.
  • What you choose in the panel: the CBCT volumes (a folder, or one of the hosted test scans), where to start from (full pipeline, already oriented, already registered), the study (asymmetry assessment or longitudinal), what to produce, and the regions to measure: cranial base, mandible, maxilla. A longitudinal study asks for the follow-up volumes; starting from "already registered" asks for the transforms of your own registration.
  • What you get back: a zip that unpacks into the output folder, with, depending on what you asked for, the measurement workbooks per region, the feature table, the classification workbook, and always a run report (VFACE_report.json). If you ask for heat maps, a box loads them into the scene when the run ends, up to twelve at a time.
  • No pauses. The review stops of the legacy module, where you check the intermediate results and correct landmarks or a registration, are not ported (VISOR:SADT-VISOR tools/VFACE/README.md:29-32). The run goes to the end on its own, and the panel has no option to stop it halfway.
  • The measurement list is the server's. The panel does not ask for one: the tool uses the default list hosted on the server (VISOR:SADT-VISOR tools/VFACE/src/sadt_vface/layout.py:54-58, dispatch.py:321-322). Unlike the legacy module, it reads every sheet of that list (aq3dc.py:122).
Heat maps are not offered by the current server setup

The server file for VFACE says it publishes no surface model, and the tool refuses a heat-map request without one (VISOR:VISOR-serve server/deployment.toml:277-279; VISOR:SADT-VISOR tools/VFACE/src/sadt_vface/dispatch.py:452-458). Ask for measurements and classification. This was read in the code, not tried on a server.

Not yet checked on a patient

The VISOR version of VFACE has been tested with simulated modules, but it has not been run with the six real ones, and its results have not been compared with the legacy module's on a patient or validated clinically (VISOR:SADT-VISOR tools/VFACE/README.md:184-193). Treat a verdict obtained this way as unverified.

ASO with VISOR

What changes when you run ASO through a VISOR server from 3D Slicer: what to provide, what is the same, what is different. The legacy module has its own page.

VISOR Legacy page Atlas (VISOR)

Through a VISOR server the orientation is computed on the server and the Slicer module, ASORemote, only sends your files and loads what comes back. How to connect and what the server does with your data is in Using VISOR. This page is only what changes for ASO compared with the legacy module. It is written from the code of the server and of the panel, not from a session on a live server. The details, with the code references, are in ASO on VISOR.

What changes in the panel

  • You choose the data type, not the mode. The panel asks for the Input Type, CBCT or IOS. The Semi or Fully choice is not drawn: the server decides from your data. For a CBCT, a scan that already has a landmark file beside it is oriented on those landmarks; a scan without one gets its landmarks predicted by the server (ALI_CBCT). If you give a folder of landmark files (Landmark folder, in the Advanced section), those are used first.
  • Nothing to download. The reference patient (the "gold") and the models stay on the server and are chosen for you.
  • CBCT landmarks: a list of 115 points in tabs; the default is the seven used for the standard orientation (Ba, S, N, RPo, LPo, ROr, LOr). Keep at least 3 ticked.
  • Intraoral scans: tabs for the 32 teeth (6 ticked by default), the landmark types, the jaws, and the occlusion choice (each jaw on its own, or one jaw driving the other).
  • The output suffix is a field of its own (default Or).

What stays the same

The principle (a 3-landmark start, then a rigid ICP onto the reference), the reoriented scan, a transform file written beside it for the registration tools, and your scans left in place.

What is different

  • Semi-automatic CBCT needs no transform file, and the server always recentres every scan first, so a semi-automatic run on its own is fine. The legacy guide's warning against running it alone (Choosing a mode) does not apply here.
  • Your landmark files are not deleted. The server merges them in memory and writes nothing in your input folder.
  • Rerunning writes again. Each run goes to a fresh output folder on the server and every file is written, whether or not an earlier one existed.
  • Intraoral file names must name the jaw (for example U, Upper, L, Lower, Max, Mand). A file with no jaw word is skipped and counted, not treated as a lower arch.
  • Intraoral Fully-Automated needs numbered teeth, and so does any jaw without a landmark file. ASO itself does not segment: a mesh without tooth labels is refused. The registration modules that call ASO run the segmentation first (Crown_Seg).
  • Transform names. CBCT: <patient>_<suffix>_transform.tfm. Intraoral: <patient>_<Upper|Lower>_<suffix>.tfm for each jaw.
  • The results are not compared with the legacy module's. The developers state that a numerical comparison of oriented volumes is still owed (SADT-VISOR tools/ASO/README.md), and with the default settings the search for the first 3 landmarks is exhaustive and repeatable here, where the legacy draws at random.
  • Time: not measured here for ASO. A CBCT without landmarks also waits for the landmark prediction (ALI_CBCT, asked for the seven landmarks by default). The server's default configuration sets no time limit.
A landmark file with the wrong name is replaced, without a message

If a scan has a landmark file that does not pair with it by name (for example P1.mrk.json next to P1_CBCT.nii.gz), the server cannot see it, predicts new landmarks instead and orients on those, even in the semi-automatic setting. The report says the landmarks came from ALI_CBCT and lists no unmatched file. This was reproduced with the tool's test helpers (and without a prediction tool the same input fails and names the file). Name your landmark files after the scan (the failure message names the rule, built on _scan and _lm) and read landmark_source in ASO_report.json.

Intraoral, five teeth ticked

Without a landmark file, the coarse alignment needs 3 or 4 teeth per jaw. With 5 ticked, the request is accepted and each jaw fails afterwards (read in the code; not run).

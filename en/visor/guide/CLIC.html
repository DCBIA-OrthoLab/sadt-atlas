CLIC with VISOR

What changes when you run CLIC through a VISOR server from 3D Slicer: what to provide, what is the same, what is different. The legacy module has its own page.

VISOR Legacy page Atlas (VISOR)

With a VISOR server the computation runs on the server, not on your workstation, and the CLIC panel is a form that sends your scans there. Details of the code are in the Atlas page; connecting and running in general are in Using VISOR.

What changes in the panel

  • Nothing is installed in Slicer: no computing environment to build, no model to download. The trained model is already on the server, and you do not choose it.
  • You provide a CBCT in .nii or .nii.gz, one file or a folder. Subfolders are searched, so a folder of one subfolder per patient works. Files in other formats (.nrrd, .mha...) are skipped; if nothing readable is left, the run is refused with a message saying so.
  • Results land in the output folder you choose in the panel. You can also change the score threshold (0.7 by default: detections below it are not painted) and the suffix added to the file names (seg by default). Which device runs the computation is decided by the server.
  • The scan field may offer test files hosted on the server. The one listed for CLIC is a whole-head CBCT with no known impacted canine: it shows that the round trip works, not that the classification is right.
  • Your scans are uploaded to the server. What protects them in transit, and what does not, is on Security and privacy in VISOR.

What stays the same

The method is unchanged: the volume is read slice by slice, each slice is classified on its own, and values 1, 2 and 3 mean buccal, bicortical and palatal. Neighbouring slices can still disagree about the same tooth, and nothing gives you one class per patient.

What is different in the results

  • Results come back as one archive, unpacked into your output folder. The folder tree of your input is reproduced, and each file is named <scan>_seg.nii.gz (the legacy module produced X.nii_seg.nii.gz inside an X.nii folder).
  • The panel can load up to 12 of the segmentations into the scene when the run ends, so you no longer have to find and load them yourself.
  • A CLIC_report.json file is written next to them. It names the three classes and says, per scan, which were detected and which scans failed. The panel does not display it: open the file. When a large folder is sent in several batches, the report you end up with describes only one of them.
  • If one scan of a folder cannot be read, the others are still processed.
An empty result is not an error

When nothing clears the threshold on a scan, you get an all-zero segmentation and the run is reported as successful, even if it happens on every scan of the folder. The report carries the note "no detection cleared the score threshold" for each such scan. An empty result can be a true answer or a wrong model, so read the report before concluding that there is no impacted canine.

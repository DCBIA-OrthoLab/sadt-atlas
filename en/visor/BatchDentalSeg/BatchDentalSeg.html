BatchDentalSeg on VISOR

How BatchDentalSeg runs in VISOR (client and server), what changed from the legacy Slicer module, and what the code of the port does, step by step. The legacy module is described on its own page.

VISOR Batch_Dental_Seg Legacy page Guide (VISOR) Bibliography

VISOR runs BatchDentalSeg on a server: Slicer sends the scans and the name of a hosted model, and receives label volumes, per-label files or meshes. One nnU-Net v2 network, chosen among four bundles, labels every structure of a scan in a single pass, and one call covers the whole batch. This page says what runs where, follows the pipeline from the input file to the run report, lists the arguments the server publishes, and compares each step with the legacy module. Everything here was read in the code, not observed on a running server, and nothing here says that a given server is deployed.

References name the repository first: SADT-VISOR (tool code, tool/vface @ 6ba2a78), VISOR-serve (server, @ e9a7e5d), AutomatedDentalToolsRemote (Slicer client, @ 19b95e8) and legacy (SlicerAutomatedDentalTools @ 3c67957). A bare file name such as pipeline.py, catalogs.py, layout.py, nnunet_runner.py, low_memory.py, mesh_export.py, progress.py or __init__.py is in the SADT-VISOR package tools/Batch_Dental_Seg/src/sadt_batchdentalseg/. SegmentationWidget.py, Queue.py and PythonDependencyChecker.py are legacy files of BATCHDENTALSEG/BATCHDENTALSEGLib/ (the widget has 3037 lines at 3c67957).

1. Position in the chain

Batch_Dental_Seg is a leaf: it calls no other tool, and one tool calls it. Its run() takes no supervisor argument at all (SADT-VISOR __init__.py:13-26), so it cannot reach another tool even by mistake.

3. The pipeline

segment() (SADT-VISOR pipeline.py:216-398) is a straight line. The bundle is checked before any scan is read, every scan is converted into one folder, nnU-Net runs once over that folder, then each scan is written back on its own grid. Only the network step is learned.

3.1 Inputs and discovery

discover_scans() (pipeline.py:87-107) takes one file as is, or walks a folder recursively with os.walk and keeps the files whose extension is in sadt_naming.VOLUME: .nii.gz .nrrd.gz .gipl.gz .nii .nrrd .gipl, compared in lower case (SADT-VISOR naming/src/sadt_naming/__init__.py:36). In a folder, a file is skipped when it looks like an earlier output of this tool:

def is_previous_output(filename, suffix):                      # pipeline.py:72-84
    base, _extension = split_scan_extension(os.path.basename(filename))
    if suffix and base.endswith(f"_{suffix}"):
        return True
    return any(base.endswith(f"_{suffix}_{name.replace(' ', '-')}")
               for model in catalogs.MODELS.values()
               for name in model.labels)

With the default prediction_ID = "Seg", that is any base name ending in _Seg or in _Seg_<label> for any label of any of the four models, so a folder can be run again in place (see the finding in §8 about scans whose own name ends that way). No scan at all raises ToolInputError (pipeline.py:243-248). The input tree is kept: input_root is the folder, or the parent of a single file (pipeline.py:250), and every case is described in the report by its path relative to it, never by an absolute path (pipeline.py:264-265).

3.2 The model: one name, one bundle, one label table

resolve_model() (pipeline.py:110-133) runs before any scan is read. The folder name of the model path is looked up in catalogs.MODELS; an unknown name is refused with the list of known models. Inside the folder, find_model_folder() walks the tree for the directory that holds dataset.json, plans.json and fold_0/checkpoint_final.pth, all three checked (nnunet_runner.py:57-73): the four bundles do not share one layout, DentalSegmentator arriving as a zip with its own Dataset<n>/ tree (nnunet_runner.py:37-41). An incomplete bundle is refused with the command that stages it again (pipeline.py:126-132).

MODELS = {model.name: model for model in (                     # catalogs.py:126-152
    Model("DentalSegmentator",  _FIVE_LABELS,      "Adult dental CT/CBCT. ..."),
    Model("PediatricDentalSeg", _FIVE_LABELS,      "Paediatric dental CT/CBCT, ..."),
    Model("NasoMaxillaDentSeg", _NASO_LABELS,      "Six segments: the maxilla is separated ..."),
    Model("UniversalLab",       _UNIVERSAL_LABELS, "Every tooth labelled individually ..."),
)}

Because the label table follows the folder name, a caller cannot pair one bundle with another's labels: there is no second argument to get wrong (catalogs.py:120-125). The values are the integers the network emits, and the code writes them unchanged.

3.3 Conversion to the nnU-Net layout

Every scan is converted into one folder, <output_dir>/.batchdentalseg_work/nnunet_in/, under a positional case id (pipeline.py:256-277):

case_id = f"case_{index:04d}"                                   # pipeline.py:275
_convert_to_nifti(scan, os.path.join(nnunet_input, f"{case_id}_0000.nii.gz"))

def _convert_to_nifti(scan_path, destination):                  # pipeline.py:140-149
    sitk.WriteImage(sitk.ReadImage(scan_path), destination)

A read plus a write, never a rename: nnU-Net picks its reader from the extension, so an NRRD renamed to .nii.gz would be read wrong. The voxel type is left alone; nnU-Net casts to float32 itself (pipeline.py:143-145). The ids are positional because nnU-Net writes its output under the input's id, and two scans called scan.nii.gz in different subfolders would collide (pipeline.py:256-259). A scan that cannot be read is recorded as failed with "could not be read" and skipped; only when none can be read does the run stop (pipeline.py:278-298).

No intensity windowing, no crop and no resampling is written in this package. All of the preprocessing is nnU-Net's own, from each bundle's plans.json: transposition, resampling to the plan's spacing, CT normalisation. The legacy auto-crop is not ported, on purpose: upstream applied it only after a failed memory check, and it changes what the network sees (pipeline.py:18-21).

3.4 Inference: one call for the whole batch

predict_folder() (nnunet_runner.py:192-232) is called once with the whole input folder (pipeline.py:302-306), so the checkpoint is loaded once per run, not once per scan. The predictor is built through nnU-Net's Python API, with the renamed keyword chosen by introspection:

options = {                                                     # nnunet_runner.py:86-95
    "tile_step_size": float(tile_step_size),   # argument, default 0.5
    "use_gaussian": True,
    "use_mirroring": False,                    # no test-time mirroring
    "device": torch.device(device),
    "verbose": False, "verbose_preprocessing": False, "allow_tqdm": False,
}
# + perform_everything_on_device (or _on_gpu) = device.startswith("cuda")   :97-100

predictor.initialize_from_trained_model_folder(                 # :204-208
    model_folder, use_folds=(0,), checkpoint_name="checkpoint_final.pth")

The model path is explicit: no nnUNet_results environment variable, which is process-global (nnunet_runner.py:202-203). device falls back from cuda to cpu with a warning when no card is visible (nnunet_runner.py:46-54). Two paths follow (nnunet_runner.py:210-232):

  • GPU resampling applied: predict_from_files_sequential, everything in this process, because spawned workers would each need their own CUDA context;
  • otherwise (CPU, gpu_resampling=false, or plans with another resampler): predict_from_files with 2 preprocessing and 2 export workers. Those workers are what the container's shm_size is for (VISOR-serve docker-compose.yml:225-229).

Progress has only two measurable ends: reading counts scans from 0 to 10 %, writing from 90 to 100 %, and in between one line says "segmenting N scan(s) in one pass" (pipeline.py:269-274, 301, 313; progress.py:89-103). If the inference call raises, the scratch folder is removed and the whole batch fails (pipeline.py:302-309).

3.5 GPU resampling and the per-class argmax

With gpu_resampling = true (the default) on a CUDA device, _enable_gpu_resampling() (nnunet_runner.py:124-189) rewrites the two resampler names in the predictor's configuration, only if both are nnU-Net's stock resample_data_or_seg_to_shape:

for key in ("resampling_fn_data", "resampling_fn_probabilities"):   # nnunet_runner.py:167-177
    configuration[key] = "resample_torch_fornnunet"
    configuration[f"{key}_kwargs"] = {"is_seg": False,
                                      "device": torch.device(device),
                                      "mode": "linear"}

The input volume therefore goes from spline order 3 to order 1, which the code names as the whole numerical difference (nnunet_runner.py:169-172). The third resampler, the one for the crop mask, is deliberately left on scipy (nnunet_runner.py:110-116). The cached properties are cleared so the swap takes effect (:179-183).

The same function then calls low_memory.install(predictor) (nnunet_runner.py:185-188). That replaces the probabilities resampler again, by one that resamples the network output one class at a time and keeps a running maximum and label, and it replaces nnU-Net's argmax by a pass-through, since what arrives is already the argmax:

for index in range(data.shape[0]):                              # low_memory.py:62-79
    one = resample_torch_fornnunet(data[index:index + 1].to(device), shape, ...)[0]
    ...
    higher = one > best
    best = torch.where(higher, one, best)
    labels = torch.where(higher, index, labels)
return labels.unsqueeze(0).cpu()                                 # :86

Both halves are installed together or not at all: the factory that builds a fresh label manager for predict_from_files_sequential is wrapped on the instance as well (low_memory.py:100-151). According to the module docstring, the arithmetic is the same as the stock path (0 differing voxels out of 95 682 560 on a UniversalLab run) and the peak drops from about 30.6 to 1.25 GiB of VRAM (low_memory.py:14-26); those numbers were not reproduced here. Ties between classes are broken toward the lower index in both cases (one > best, strict), which matches an argmax.

3.6 Back on the scan grid, and writing

For each case, the prediction nnunet_out/<case_id>.nii.gz is read; a missing one marks that scan failed and the loop continues (pipeline.py:312-321). The label volume is then put back on the source scan's exact grid:

if (mask.GetSize() == reference.GetSize()                       # pipeline.py:162-171
        and np.allclose(mask.GetSpacing(), reference.GetSpacing(), atol=1e-4)):
    mask.CopyInformation(reference)          # same grid: copy origin and direction
    return mask
return sitk.Resample(mask, reference, sitk.Transform(),
                     sitk.sitkNearestNeighbor, 0, mask.GetPixelID())

The output tree mirrors the input tree under output_dir (pipeline.py:329-336), and names are built from the scan's base name and prediction_ID:

No morphological cleanup, island removal or hole filling is applied: the label volume is nnU-Net's output on the scan's grid.

3.7 Surfaces

mesh_export.write() (mesh_export.py:177-236) does nothing unless a mesh format is in export_formats. It builds each present label's surface once and writes it in every requested format, so ticking STL and OBJ together pays for one marching-cubes pass (:212-225).

smoother = vtk.vtkWindowedSincPolyDataFilter()                  # mesh_export.py:89-110
smoother.SetNumberOfIterations(max(0, int(smoothing)))          # write(smoothing=30)
smoother.SetPassBand(0.05)
smoother.BoundarySmoothingOn()
smoother.SetFeatureEdgeSmoothing(False)
smoother.NonManifoldSmoothingOn()
smoother.NormalizeCoordinatesOn()

Feature-edge smoothing is off on purpose: on a raw marching-cubes mesh every voxel step is a sharp edge, and protecting those edges would keep the staircase (mesh_export.py:94-107). Decimation uses vtkDecimatePro with topology preserved and a feature angle of 60 (:120-130); its default of 0 was chosen for parity with the legacy module's STL export, measured on one label according to the docstring (__init__.py:84-100). No normals are written (:132-139). STL and VTK are written binary, OBJ as text, which has no binary form (:45-49, 165-172). The mask reaches VTK through a temporary NRRD with a unique name, removed after reading (:66-118); mesh_export.py applies no explicit RAS or LPS transform, unlike the legacy VTK export, which flipped to LPS (legacy SegmentationWidget.py:2958).

3.8 Report and cleanup

BatchDentalSeg_report.json (pipeline.py:364-396) is written at the root of output_dir after the scratch folder is removed (pipeline.py:392):

{ "tool": "Batch_Dental_Seg", "model": ..., "model_description": ...,
  "labels": {"Upper Skull": 1, ...},        # the full table of the bundle used
  "device": ..., "prediction_ID": ..., "separate_segments": ...,
  "gpu_resampling": ...,                    # true only if asked AND device is cuda
  "tile_step_size": ..., "export_formats": [...], "surface_decimation": ...,
  "cases": {"case_0000": {"input": "<relative path>", "status": "ok", "produced": [...]}, ...},
  "summary": "N/M scan(s) segmented", "duration_seconds": ... }

The case ids are positional and the inputs are relative paths, so the report names no absolute path. tool is derived from the tool's folder name (pipeline.py:49-57).

A run started from the panel therefore always asks for cuda (the tool falls back to the CPU without a card), GPU resampling, step 0.5 and no mesh decimation; these four can only be changed by calling the API directly. Inputs. A single file is taken as is. In a folder, files whose base name ends in _<ID> or _<ID>_<label-name> are skipped as earlier outputs, so a folder can be re-run in place (pipeline.py:72-107). Outputs. The scan's relative folder is mirrored under output_dir (pipeline.py:329-336). With NIFTI: <base>_<ID><ext> (label volume), and with separate_segments one binary file per label present, <base>_<ID>_<label-name><ext> with spaces and slashes replaced by a dash (pipeline.py:184-209, 342-350). At the root, BatchDentalSeg_report.json (§3.8).

Resources and time limits. No section for this tool in deployment.toml, so the server defaults apply: no time limit, upload cap 500 MB, cohort batches of at most 400 MB or 25 files (VISOR-serve server/config.py:77, 240, 192, 196). scans is the only required path once model and output_dir are set aside, so it is the axis a cohort is split along (server/registry/conventions.py:158). Concurrency is decided by memory and core admission (server/execution/admission.py:1-12).

Staged by the server's setup script into DATA/<tool>/models/<bundle>/, one folder per bundle so the three same-named files of each do not overwrite each other, with the checkpoint under fold_0/ (VISOR-serve scripts/data-manifest.yml:531-541). The tool never downloads during a run (pipeline.py:15-17). The server spells the data folder DATA/BatchDentalSeg/ (server/registry/conventions.py:10; server/registry/deployment.py:311-315). Of the eleven manifest entries, two carry a sha256 (PediatricDentalSeg's dataset.json and plans.json, data-manifest.yml:563, 568); the checkpoints have a size only. The hosted test scan is AMASSS's public MG_test_scan.nii.gz (:587-593).

Resources. No timeout and no upload cap declared, so the defaults of §4 apply; no resource entry for this tool in deployment.toml; shm_size: 8gb for the CPU path's workers.

8. Findings in VISOR

VFACE asks for surfaces and gets label volumes

VFACE's heat-map path calls this tool with three arguments only, scans, model and prediction_ID="Seg" (SADT-VISOR tools/VFACE/src/sadt_vface/tools.py:359-364), so export_formats keeps its default ["NIFTI"] (SADT-VISOR __init__.py:22-24) and no mesh is written (pipeline.py:342-354; mesh_export.py:187-189). VFACE then looks for .vtk or .vtp files only (heatmap.py:29, 194-204), finds none, and ends with "No heat map could be drawn" (heatmap.py:246-251). Read in code, not executed. The deployment read here publishes no surface_model for VFACE anyway (VISOR-serve server/deployment.toml:277-279), so the path is not reachable from that server's panel.

The tool's README is out of date on mesh exports and memory

The README of the tool says "No vtk: the mesh exports are not ported" and lists them as not ported (tools/Batch_Dental_Seg/README.md:28, 95); the docstring of pipeline.py says the same (SADT-VISOR pipeline.py:23-24). The code says otherwise: mesh_export.py writes STL, OBJ and VTK, export_formats is an argument (__init__.py:22-24) and vtk 9.6.2 is a dependency (pyproject.toml:23). Only glTF is really missing. The README also counts 38 non-GPU tests (README.md:267) where the file has 55 test functions. Its advice to turn gpu_resampling off for UniversalLab on a card under about 40 GiB (README.md:241-256, repeated in __init__.py:69-73) was last edited in commit d2fb0d8; the per-class resampler, which the code installs with the GPU resampler on every bundle (nnunet_runner.py:185-188), came after, in c8899c8, and its docstring announces a much lower peak (low_memory.py:20-26). The code is the reference here; the peak itself was not measured for this page.

A scan named ..._Seg is invisible in a folder

With the default identifier, patient_Seg.nii.gz inside a folder is taken for an earlier output and ignored without any message (SADT-VISOR pipeline.py:79-80, 104-105). A single file passed as scans is processed even if its name looks like an output (pipeline.py:96-97).

GPU resampling is on by default and changes the numbers

When it applies, the input volume is resampled on the GPU in linear mode instead of nnU-Net's cubic spline; the code states that this is the whole numerical difference and that gpu_resampling=false turns it off (SADT-VISOR nnunet_runner.py:167-177). The report records the value requested on a CUDA device, and false on CPU; a bundle whose plans opt out is only mentioned in the log (pipeline.py:374-378; nnunet_runner.py:163-165). The argument is hidden in the panel.

cuDNN autotuning is not switched off

BatchDentalSeg never sets torch.backends.cudnn.benchmark (no occurrence in the package), and nnU-Net's predictor sets it to true on CUDA (nnunetv2/inference/predict_from_raw_data.py:60-61, nnunetv2 as installed in the tool's environment). AMASSS switches it off explicitly (SADT-VISOR AMASSS sadt_amasss/nnunet_runner.py:116). The tool's README says nnU-Net on CUDA is not bit-deterministic (README.md:113): do not expect a bit-identical mask from two runs of the same scan.

An empty export list gives "ok" with no file (direct call only)

Called directly in Python, run(..., export_formats=[]) reports each scan as ok with an empty produced list and a summary "1/1 scan(s) segmented", and writes nothing (SADT-VISOR pipeline.py:342-355, 362-386; mesh_export.py:187-189); the tool itself does not check the list. A request through the server is refused before the run, since the layout asks for at least one format (layout.py:31-33; VISOR-serve server/base.py:855-858), and the panel asks for one too.

Per-label files depend on the NIfTI format

separate_segments splits the label volume, so it only works when NIFTI is selected: with meshes only, nothing is written for it even if the box is ticked (SADT-VISOR pipeline.py:339-350).

The label table travels with the result, but Slicer does not read it

The report holds the full labels table (SADT-VISOR pipeline.py:364-371). The Slicer panel defines no RUN_REPORT (default empty: ServerToolsCoreLib/base_widget.py:1493) and loads label volumes with a plain loadLabelVolume (slicer_io.py:560); a comment in the module speaks of a colour table (BATCHDENTALSEGRemote.py:79-82) but no code applies one.

One inference call: progress has two ends

The whole folder goes through one nnU-Net call, so the bar covers reading (0 to 10 %) and writing (90 to 100 %) and says "segmenting N scan(s) in one pass" in between, without inventing intermediate values (SADT-VISOR pipeline.py:269-274, 301). An exception from that call fails the whole batch after cleaning the scratch folder (pipeline.py:302-309).

Verified: an unreadable scan does not stop the batch

A scan that cannot be read is reported failed ("could not be read") and the others are segmented; only when none can be read does the run stop with an input error (SADT-VISOR pipeline.py:273-298).

9. Literature

The networks are the DentalSegmentator family; the bibliography is the tool's own and is not repeated here: BatchDentalSeg sources, and the literature section of the legacy page. The manifest points at the same release URLs the legacy module downloads from: the three DCBIA-OrthoLab releases (VISOR-serve scripts/data-manifest.yml:542-581; legacy ADT/ADTLib/model_registry.py:59-64) and, for DentalSegmentator, the archive recorded in the legacy Resources/ML/download_info.json (data-manifest.yml:582-586). Whether the files behind those URLs are byte for byte the ones a legacy install fetched cannot be told from the code: neither side records a hash for any checkpoint.

GreedyReg on VISOR

GreedyReg lines up two CBCT scans of the same patient, taken at two visits, by moving the second until it looks like the first. The comparison is made on the grey values themselves, by the registration engine Greedy. This page explains how, step by step, with the maths. Where the code does something worth checking, a link leads to the code page. The legacy module is described on its own page.

VISOR Code (developers) Legacy page Guide (VISOR)

Overview: what goes in, what comes out

At the second visit the patient never lies exactly as at the first. To compare the two CBCTs, T2 must be brought into the frame of T1. GreedyReg does it from the images alone: it searches for the rotation and translation (or a general affine matrix) under which T2 resembles T1 the most, then resamples T2 into T1’s grid. No network is involved.

What it is
Inputa folder of first-visit scans (T1, the fixed images) and a folder of second-visit scans (T2, the moving ones), paired by patient; optionally one mask per patient and one starting transform per patient
IdeaGreedy optimises a similarity measure (NCC by default) from coarse to fine, over 6 (rigid) or 12 (affine) numbers
Outputper patient, T2 resampled into the T1 grid (.nii.gz) and the transform found (.mat), plus GreedyReg_report.json

1. Position in the chain

GreedyReg calls no tool and no tool calls it. Its natural upstream is a segmentation that gives the mask of a stable structure, typically the cranial base from AMASSS, but the clinician brings that mask as a file: the tool does not fetch it. In the legacy module the Distant mode called ALI_CBCT for landmarks; that path does not exist in VISOR.

In the codeThe state of the port, the client module and the calls

2. Files involved

The tool is a small Python package: one file with the entry point, the pairing and the per-patient loop, one with the Greedy commands, one panel hint file, and the shared pairing rule of the AREG family. The Slicer module is 138 lines, with no client-side library.

In the codeEach file with its size and role, on the server and in the client

3. What runs where

Slicer picks the folders and uploads them; nothing is computed there. The server pairs the scans, prepares the masks and the starting transforms, runs Greedy twice per pair (search, then resampling), and returns the output folder zipped. The panel unpacks it and loads the registered volumes, up to 12; the .mat transforms are not loaded.

In the codeThe server and client sides of each step

4. The pipeline, step by step

One call registers a whole cohort, patient by patient.

In the codeThe order of the calls in the entry point

4.1 Pairing T1 with T2 computed

The choices (metric, transform type) are checked first, so a bad metric is one error and not one per patient. The two folders are then walked recursively and files are keyed by a patient name: the extension, any suffix a previous run left, and the time-point token are removed; 01_T1.nii.gz gives 01 and C_0001_T1_Or.nii.gz gives C_0001. A folder that holds two time points is refused, so T1 is never paired against T1. A patient present in only one folder is reported, and no patient in both is an error.

In the codeThe shared pairing rule, its extensions and the timepoint refusal

4.2 Masks and initial transforms computed

A mask is keyed like its scan; structure tokens such as a region name are dropped only from a file whose name says it is a mask. A .mat transform is keyed the same way, so the transforms of one run can be fed back as the start of the next. Masks and transforms that match no patient are listed in the report.

In the codeThe two discovery functions and their key rules

4.3 The start of the search computed

With a given transform, Greedy starts from it as is. Otherwise the tool writes an identity with a tiny nudge in x (0.001): an exact identity makes Greedy behave differently (the original code comment says it reads it as “no initialisation given”), so the tool nudges it. A mask is turned into a 0/1 image (anything above zero) and keeps its own geometry; the tool does not check that it lies in the space of T1.

In the codeThe nudged identity, the mask binarisation and the docstring that explains them

4.4 The two Greedy calls computed

The affine search uses T1 as the fixed image and T2 as the moving one. Three measures are offered: NCC (local normalised cross-correlation), NMI (normalised mutual information, for images whose grey values do not correspond) and SSD (sum of squared differences, for the same modality). The multi-resolution schedule and the preliminary random search are fixed and not exposed. An unknown metric is refused, where the legacy fell through to SSD.

Then the second call resamples T2 into the grid of T1 with the transform found. Each call runs in its own separate (child) process and is limited to 600 seconds; a pair makes two calls, so it can take up to 1200 seconds. If Greedy fails, the error carries Greedy’s own message.

In the codeThe exact command lines, the separate process and the timeouts

4.5 Outputs and report computed

Per pair, the output folder mirrors the input tree and holds <patient>_<suffix>.nii.gz (always .nii.gz) and <patient>_transform.mat, a plain-text matrix in Greedy’s own format (not a Slicer transform file). The report records, for each patient, its status, the files, the mask and the starting transform used, and what the matrix maps (the T2 image to the T1 frame, what the resampling consumes). A failure records its reason; the report is written only if at least one pair registered.

In the codeThe report keys, the scratch handling and the progress messages

5. What you can choose

  • T1 and T2: two folders, one scan per patient in each.
  • Masks (advanced): one per patient; the comparison is then made inside the mask, which belongs to T1. Useful with a stable structure such as the cranial base.
  • Initial transforms (advanced): one .mat per patient as the starting point.
  • The metric: NCC (default), NMI or SSD.
  • The transform: Rigid (default, 6 degrees of freedom) or Affine (12).
  • The suffix of the registered volume (registered by default).
In the codeEvery argument with its type, default and rule, and the report keys

6. What is predicted vs computed

BlockNature
Pairing, masks, initial transformscomputed file-name rules
Affine searchcomputed Greedy, NCC / NMI / SSD optimisation, 6 or 12 degrees of freedom, on the CPU
Resamplingcomputed Greedy
Mask of a stable structurepredicted when it comes from a segmentation network such as AMASSS, outside this tool

GreedyReg on VISOR runs no network. The legacy Distant mode was its only predicted step, and it is not ported.

In the codeWhere each block runs

7. Environment

A Python 3.11 environment with picsl_greedy (the pinned wheel that holds Greedy), nibabel and numpy; no torch and no model. Greedy runs on the CPU, although the server queues the tool for a GPU slot it does not use. Each Greedy call is capped at 600 s; the run itself has no time limit.

In the codeThe pinned versions, the hosted test file, the limits and the thread measurement

8. What changed from the legacy logic

  • The engine: a pinned picsl_greedy wheel in a child process, instead of a downloaded ITK-SNAP binary.
  • The command is the same flag by flag; an unknown metric is now refused.
  • Pairing: a shared rule, recursive, with unmatched patients reported, instead of one regular expression on the first letters and digits.
  • A failing patient costs one patient; the legacy stopped the whole batch.
  • Outputs go to a separate folder, with a report.
  • Defaults: NCC and Rigid, where the legacy list began with NMI.
  • Absent: the Manual mode, the Distant mode (landmarks from ALI_CBCT) and the single-pair mode.
In the codeThe full table with legacy and VISOR references

9. Known issues in VISOR

  • The Slicer client describes a tool the server does not have: modes, landmarks and a second tool that do not exist, so its help text promises more than the tool does (details).
  • The last message in the panel reads a report field that does not exist, so it shows a question mark and counts failed pairs as registered (details).
  • Two files do not make a pair: the tool pairs folders, not files, so giving it one T1 file and one T2 file finds nothing (details).
  • The hosted test cohort is refused as offered, because it holds both time points in one folder, so the example data cannot be run as is (details).
  • Only each Greedy call is time-limited, not the whole run, so a large cohort can run for a long time (details).
  • No report is written when nothing registered, so the reasons only appear in the error message (details).
  • The .mat is not a Slicer transform (it cannot be loaded as one), and nobody checks that a mask lies in the space of T1 (details).

10. Literature

AREG_CBCT on VISOR: the code

For developers: what the VISOR port of AREG_CBCT does in the code, with file:line references, signatures, arguments, environment, the differences from the legacy code and the findings. The readable explanation of the same pipeline, with the maths, is on the atlas page. The legacy module is on its own page.

Code Atlas (explanation) VISOR AREG_CBCT reached as AREG, mode CBCT engine CPU only, elastix Legacy page Guide (VISOR) Bibliography

AREG_CBCT registers a follow-up CBCT (T2) onto the baseline CBCT (T1) of the same patient with a rigid elastix registration, confined to a stable region of T1. In VISOR the whole computation runs on a server; Slicer only shows the form, sends the folders and opens what comes back. This page describes that port, read at SADT-VISOR 6ba2a78 (branch tool/vface), VISOR-serve e9a7e5d and AutomatedDentalToolsRemote 19b95e8. The legacy module it is compared with is SlicerAutomatedDentalTools 3c67957, described on its own page; legacy paths below are at that commit.

Abbreviations used on this page: cbct/ is SADT-VISOR tools/AREG/AREG_CBCT/src/sadt_areg_cbct/, common/ is SADT-VISOR tools/AREG/common/src/sadt_areg_common/, and server/ paths are in VISOR-serve. “Observed” marks what was executed (tests, scripts/describe.py, short Python probes) during the study of the port; everything else was read in the code.

1. Position in the chain

Plain-language explanation and maths: atlas page.

A client never names AREG_CBCT. The Slicer module sends AREG, a facade declared in the server's deployment file, with mode = "CBCT"; the server swaps the facade for its target and runs this engine. The engine itself computes only the pairing and the registration: the masks and the orientation come from two other tools it calls through the supervisor (sup.run), each in its own environment.

3.1 Inputs, DICOM and pairing

Plain-language explanation and maths: atlas page.

Shape of the inputs. register creates <output_dir>/.areg_work/ and turns each input into a directory: a folder is used as is, a single file is hard-linked (or copied) into a folder of its own, because the server streams every upload of a request into one work directory and a file's parent would otherwise contain the other time point (cbct/dispatch.py:360-378,420-424). Scan files are recognised by extension, .nii.gz .nrrd.gz .gipl.gz .nii .nrrd .gipl (common/pairing.py:36); the pickers filter nothing, on purpose, because the facade would refuse to publish a t1 that means a volume in one mode and a surface in another (cbct/__init__.py:24-31).

DICOM. With dicom_input set, each tree is converted into .areg_work/dicom_t1 and dicom_t2 (cbct/dispatch.py:211-213). convert_tree walks the whole tree, reads each series with SimpleITK's GDCM reader and falls back to dicom2nifti in an empty staging folder (cbct/dicom.py:39,81-107). Its docstring lists the three legacy behaviours it removes: writing into <input>/NIFTI/, looking one level down only, and renaming an arbitrary earlier file in the fallback (cbct/dicom.py:1-22).

Cohort folders. timepoint_root descends into <cohort>/T1 and <cohort>/T2 when the folder sent is a whole cohort, which is how the hosted test entries are laid out; a folder that holds several time points mixed together is refused rather than paired by chance (cbct/dispatch.py:219-220, common/pairing.py:313-361).

Patient key. A file belongs to the subject named by patient_stem: the extension is removed, then everything from a suffix a previous run left (_lm_Pred _Scanreg _MERGED _OutReg _SegOr _scan _Scan _Seg _seg _Or _OR _lm) is cut, provided the suffix sits on token boundaries, then the time-point tokens t1 t2 t0 are dropped as whole tokens (common/pairing.py:175-211, common/catalogs.py:148,158-161). The key is the relative folder plus that stem, so P1_T1_scan.nii.gz in the T1 folder pairs with P1_T2.nii.gz in the T2 folder. Observed in the study: P1.2_scan gives P1_2, P001_T3 stays P001_T3.

matched = pairing.pair(t1_root, t2_root, suffix)          # dispatch.py:259
report["unmatched"] = matched.unmatched_report()
if not matched:
    raise ToolInputError("No subject appears in both the T1 and the T2 folder. ...")

A subject present at one time point only is listed under unmatched; a run in which nothing pairs stops with an error that states the naming rule and the counts (cbct/dispatch.py:259-268).

3.2 Orientation and masks: the two supervised calls

Plain-language explanation and maths: atlas page.

Before a file is read, main refuses what cannot work: no region selected, Semi-Automated without t1_masks, an automatic mode with no supervisor (tools.require, with advice on which mode to use instead), the Oriented mode without a reference, an automatic mode with no AMASSS bundle (cbct/dispatch.py:105-153, cbct/tools.py:45-69). An empty segmentation_model is resolved to DATA/AREG/models/AMASSS_Models when that folder exists (cbct/dispatch.py:83-102,504-505); the reference is never resolved for you in this engine.

Orientation, Oriented + Fully-Automated only (cbct/dispatch.py:229-236, cbct/tools.py:93-107). The T1 folder alone is sent; the T2 is never oriented.

sup.run("ASO",
        input=<T1 folder>, reference=<orientation reference>,
        modality="CBCT", automation="Fully-Automated",
        output_suffix="Or"
        [, landmark_model=...])        # only if one was named; hidden in the panel

No cbct_landmarks is sent, so ASO uses its default, the Frankfurt set Ba S N RPo LPo ROr LOr (SADT-VISOR tools/ASO/src/sadt_aso/__init__.py:51), and asks ALI_CBCT for those seven points. The folder ASO returns replaces the T1 root for the rest of the run, and the report records oriented_t1: true.

Masks, Fully-Automated and Oriented (cbct/dispatch.py:246-256, cbct/tools.py:110-139). One AMASSS call covers the region masks and the structures ticked under “AMASSS segmentation”:

structures = ["CBMASK" | "MANDMASK" | "MAXMASK" for each ticked region]
           + [codes of ticked segmentations not already there]   # CB CV MAND MAX SKIN UAW
sup.run("AMASSS",
        scans=<T1 folder>, model=<AMASSS_Models>,
        structures=structures, merge=["SEPARATE"],
        prediction_ID="seg", generate_surface=False)

The region codes come from common/catalogs.py:68-84, the segmentation codes from :96-103. The folder AMASSS returns is read as one more mask root. The structures that were asked to come back are copied out of the supervisor's scratch into <output_dir>/Segmentations/<AMASSS folder>/, matched on the code that ends the file stem (cbct/dispatch.py:160-195). Only the T1 is segmented.

Finding the mask of a region (cbct/pipeline.py:102-139, common/pairing.py:376-404). Mask roots are tried in order, the caller's t1_masks first, then the T1 folder (Semi-Automated) or AMASSS's output; the first root that has a patient's mask wins. A file is a mask of region CB only if its stem carries a segmentation token (mask seg pred segmentation) and one of the region's tokens (cb cbmask cranialbase cranial; mand md mandmask mandible; max mx maxmask maxilla), each as a whole token (common/catalogs.py:117-125). AMASSS writes one <scan>_<id>_SegOut/ folder per scan, so its masks key to a different relative path than their scans; find_masks falls back to the last component of the key, and only when that leaf is unambiguous across the tree. A patient with no mask for a region gets status: "failed" for that region, with a reason that gives the naming rule in Semi-Automated mode (cbct/dispatch.py:283-289,309-321).

3.3 The registration

Plain-language explanation and maths: atlas page.

register_patient does the whole job for one patient and one region (cbct/pipeline.py:38-99):

fixed = sitk.ReadImage(t1_path)
mask = sitk.ReadImage(mask_path)
masked, note = elastix.apply_mask(fixed, mask, label=segmentation_label)
moving = sitk.ReadImage(t2_path)
transform = elastix.register(masked, moving)        # fixed = the masked T1
resampler = sitk.ResampleImageFilter()
resampler.SetReferenceImage(moving)                 # the T2's own grid
resampler.SetTransform(transform)
resampler.SetInterpolator(sitk.sitkLinear)
resampler.SetDefaultPixelValue(0)
registered = sitk.Cast(resampler.Execute(moving), sitk.sitkInt16)

Masking (cbct/elastix.py:133-183). apply_mask refuses a mask whose size differs from the scan's, or whose spacing differs by more than 1e-4, then copies the scan's geometry onto the mask (identical sampling means any remaining origin or direction difference is float drift). With segmentation_label set it binarises on that label and refuses a label the mask does not hold, naming the labels present; with 0 it uses the whole mask and, if the mask holds several labels, returns a note that ends up in the report. The voxels outside the mask are zeroed with sitk.Mask: elastix receives no separate fixed mask, which is why ErodeMask is inert (cbct/elastix.py:109-112).

elastix (cbct/elastix.py:190-209). Both images go to itk.ElastixRegistrationMethod as float32 itk images built in memory with their origin, spacing and direction (cbct/elastix.py:253-264); nothing is written to disk and the result image is not requested. The parameter map is elastix's default rigid map with these entries overwritten (cbct/elastix.py:82-126):

ParameterValueComment in the code
TransformEulerTransform (from the rigid map)6 degrees of freedom
NumberOfThreads, ImageSampler, NewSamplesEveryIteration1, Grid, falsedeterminism: two runs give the same transform
NumberOfResolutions3, smoothing pyramidscoarse to fine
MetricAdvancedMattesMutualInformation, 64 bins, normalised gradient
OptimizerConjugateGradient, 1500 iterations, step 2.0 to 0.001, tolerances 1e-6
AutomaticTransformInitializationtrue, GeometricalCenteradded explicitly: it replaces the legacy pre-centring of T2
AutomaticScalesEstimationtrue
ImagePyramidScheduleremovedsix values for a 3D image over three levels were discarded by elastix; removing them was verified bit-identical (cbct/elastix.py:68-75)
ErodeMask, NumberOfSpatialSamplestrue, 30000kept for fidelity, both inert here

Turning the result into a transform (cbct/elastix.py:212-250). elastix reports three Euler angles, a translation and a centre of rotation, the transform being y = R(x − c) + c + t. The port reads CenterOfRotationPoint and sets it on the SimpleITK transform:

transform = sitk.Euler3DTransform()
transform.SetCenter(center)                       # CenterOfRotationPoint
transform.SetRotation(angleX=values[0], angleY=values[1], angleZ=values[2])
transform.SetTranslation(values[3:6])

An AffineTransform is converted the same way; any other kind raises instead of producing a plausible wrong result (cbct/elastix.py:235-250). The transform maps a point of the T1 frame to the matching point of the T2 frame, the direction ResampleImageFilter consumes, and the report says so in so many words (cbct/elastix.py:190-196, cbct/pipeline.py:92).

Errors are per region. A RegistrationError (mask geometry, absent label, unknown transform kind) or a RuntimeError from elastix marks that region failed with its reason, and the loop goes on (cbct/dispatch.py:290-304). A patient is “ok” when at least one region registered (cbct/dispatch.py:324-328).

3.4 Outputs and the report

Plain-language explanation and maths: atlas page.

The tool returns one path, so there are no named outputs: the output folder is archived and streamed. For each region and patient (cbct/pipeline.py:72-83):

<output_dir>/
  <CB|MAND|MAX>/<relative folder>/
      <patient>_<CODE>_<suffix><ext>              # registered T2, T2 grid, Int16
      <patient>_<CODE>_<suffix>_transform.tfm     # T1 frame -> T2 frame
  Segmentations/<AMASSS folder>/...               # only the structures ticked
  AREG_report.json

The extension follows the T2 in its compressed form: .nii becomes .nii.gz, .gipl becomes .gipl.gz, and the image is written with compression (common/pairing.py:40,58-59, cbct/pipeline.py:76-80). The .tfm is written by sitk.WriteTransform, in the ITK (LPS) convention. The default suffix is Reg; a suffix holding a path separator is refused (cbct/dispatch.py:489-491). The scratch folder .areg_work/ is removed before the report is written (cbct/dispatch.py:455).

AREG_report.json (cbct/dispatch.py:43,426-431,457-459) has this shape; keys marked optional appear only in the modes that produce them:

{"modality": "CBCT", "automation": "...", "output_suffix": "Reg",
 "regions": ["Cranial base", ...], "segmentation_label": null,
 "oriented_t1": true,                  # optional, Oriented mode
 "segmented_t1": ["CBMASK", ...],      # optional, automatic modes
 "segmentations": ["Segmentations/..."],   # optional, ticked structures
 "unmatched": {...},
 "patients": {"<key>": {"status": "ok" | "failed",
     "regions": {"CB": {"status": "ok", "region": "Cranial base",
                        "mask": "<mask file>",
                        "transform_maps": "T1 space -> T2 space (...)",
                        "outputs": [...], "note": "..."}}}},
 "summary": {"patients": N, "registered": n, "failed": m}}

The per-region entry is built at cbct/pipeline.py:85-99, the summary at cbct/dispatch.py:381-387.

8. Findings in VISOR

Plain-language explanation and maths: atlas page.

Elastix transform now exact

The centre of rotation is read and applied, and the centre reaches the transform (cbct/elastix.py:212-240, SADT-VISOR tools/AREG/AREG_CBCT/tests/test_elastix.py:50) and the unit tests recover a known rigid transform on a phantom to within 0.2 mm (tests/test_run.py:69-98, TestElastix). Observed: pytest in the tool's environment, 101 passed.

Unpaired subjects are reported

A subject present at one time point only is listed under unmatched in AREG_report.json instead of vanishing (cbct/dispatch.py:259-260). Read in code.

Oriented mode with the Occlusal reference

The legacy code derived the landmark list from the chosen reference (AREG/AREG_Method/CBCT.py:629-630@3c67957: six Occlusal landmarks or seven Frankfurt ones). The VISOR call to ASO sends none (cbct/tools.py:93-107), ASO's default is the Frankfurt set Ba S N RPo LPo ROr LOr (SADT-VISOR tools/ASO/src/sadt_aso/__init__.py:51), and ASO refuses a selection the reference cannot support, because the two published references carry disjoint landmark sets (SADT-VISOR tools/ASO/src/sadt_aso/dispatch.py:435-458, called at line 629). So an Occlusal reference chosen in this mode should end in that refusal. Read in code; the chain was not run.

The scratch folder is not removed when a run fails

register deletes .areg_work/ after the engine returns, with no try/finally (cbct/dispatch.py:397-460, shutil.rmtree at line 455; the engine runs at lines 433-450), while its comment says it is removed whether or not the run succeeded (cbct/dispatch.py:452-454). AREG_IOSCBCT has the finally (SADT-VISOR tools/AREG/AREG_IOSCBCT/src/sadt_areg_ioscbct/dispatch.py:357-358). An exception that is not caught per patient would leave the copies of the inputs, the converted DICOM and the oriented T1 in the output folder that the server archives. Read in code; not triggered.

Declared but unused

torch==2.8.0 is a dependency of the engine (SADT-VISOR tools/AREG/AREG_CBCT/pyproject.toml:11) that no module of cbct/ imports (observed: grep for import torch and from torch, no match). The AREG README puts the whole environment sync, with CUDA wheels, at about 5.8 GB (SADT-VISOR tools/AREG/README.md:143). In the shared package, common/scans.py is imported by no file of tools/AREG (grep, read in code); the extension table actually used is common/pairing.py:36.

A docstring promises a mask rule the code does not have

The docstring of discover_masks says a file also counts as a mask “when it is the only candidate in a folder that holds nothing but masks” (common/pairing.py:379-382). The loop accepts a file only when it carries both a segmentation token and a region token (common/pairing.py:397-401). AMASSS's own names (<scan>_seg_CBMASK) satisfy both, so the automatic modes are not affected; a mask folder sent in Semi-Automated mode with names lacking either token finds no mask. Read in code.

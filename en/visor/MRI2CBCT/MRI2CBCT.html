MRI2CBCT: not ported to VISOR

MRI2CBCT does not run on a VISOR server. This page says exactly what exists of it in the VISOR repositories: no server tool, an older client module kept but not built, and model files listed for a server that has no tool to use them. The module itself is described on its legacy page.

VISOR: not ported Legacy page Guide (VISOR)

State at the reference commits: SADT-VISOR 6ba2a78, VISOR-serve e9a7e5d, AutomatedDentalToolsRemote 19b95e8; legacy is SlicerAutomatedDentalTools at 3c67957. Everything below was read in the code and the manifests. The MRI2CBCT that the legacy page documents is the rewritten module of 3c67957 (MRI2CBCT_core/, the PREPARE, SEGMENT_MRI and REGISTER command-line modules); it is ported nowhere, neither as a server tool nor as a client panel.

What the client copy is, and is not

AutomatedDentalToolsRemote keeps MRI2CBCTRemote/MRI2CBCTRemote.py (2397 lines) and MRI2CBCT_CLIRemote/, six command-line modules: APPROX, ORIENT_CENTER_MRI, RESAMPLE_CBCT_MRI, REG, LR_CROP, TMJ_CROP. This is the earlier module, the one the legacy rewrite replaced (see the legacy page, section 1). It is not a server client: it is a local widget that runs its command-line modules through slicer.cli.run and installs torch itself (pip_install("torch==2.2.0 ..."), MRI2CBCTRemote.py:117). Since it is not built, no user of the VISOR extension gets it. A future port would start from the legacy rewrite, not from this copy.

The listed model belongs to the old module

The manifest comment says the TMJ crop network is "fetched by MRI2CBCT's install_nnunet()" (VISOR-serve scripts/data-manifest.yml:708). That function exists only in the unbuilt client copy (MRI2CBCTRemote.py:1244). In the legacy rewrite, the matching constant TMJ_CROP_MODEL is referenced by nothing (legacy ADT/ADTLib/model_registry.py:70; see the legacy page's dead-code list). Placing that file on a server does not prepare a port of the current module.

What VISOR did reuse

Only the resample step, and as a copy. SADT-VISOR tools/VFACE/src/sadt_vface/resample.py vendors the generic "put the cohort on one voxel grid and recentre it" behaviour that the legacy VFACE gets from MRI2CBCT_RESAMPLE_CBCT_MRI, with every MRI-specific branch switched off (resample.py:1-34). SADT-VISOR PROVENANCE.md:53-56 records the cost: if MRI2CBCT is ever ported, the two copies can drift apart without anything failing. See VFACE on VISOR.

None of the findings on the legacy page can be checked against VISOR code, since there is none: they all describe the legacy rewrite at 3c67957.

AREG_IOSCBCT on VISOR

How AREG_IOSCBCT runs in VISOR (client and server), what changed from the legacy Slicer module, and what the code of the port does, step by step. The legacy module is described on its own page.

VISOR AREG_IOSCBCT reached as AREG, mode IOS to CBCT no torch, pure geometry Legacy page Guide (VISOR) Bibliography

AREG_IOSCBCT places an intraoral scan in the frame of a CBCT of the same patient, taken at the same visit: a rigid fit on landmarks both sides share, then an ICP of the mesh against a surface contoured from the CBCT. In VISOR the whole computation runs on a server, and the landmarks, when you do not send them, come from other tools the server calls; Slicer only shows the form, sends the folders and opens what comes back. This page describes that port, read at SADT-VISOR 6ba2a78 (branch tool/vface), VISOR-serve e9a7e5d and AutomatedDentalToolsRemote 19b95e8. The legacy module it is compared with is SlicerAutomatedDentalTools 3c67957, described on its own page; legacy paths below are at that commit, and AREG_IOSCBCT.py is AREG_IOSCBCT/AREG_IOSCBCT.py there.

Abbreviations used on this page: ioscbct/ is SADT-VISOR tools/AREG/AREG_IOSCBCT/src/sadt_areg_ioscbct/, common/ is SADT-VISOR tools/AREG/common/src/sadt_areg_common/, and server/ paths are in VISOR-serve. “Observed” marks what was executed (tests, scripts/describe.py, short Python probes run with the tool's own environment on the published test files); everything else was read in the code.

1. Position in the chain

A client sends AREG with mode = "IOS to CBCT", and the server swaps the facade for this engine. The engine has no network of its own and imports neither torch nor pytorch3d (ioscbct/__init__.py:9-14): tooth labels, landmarks and orientation are all asked of other tools, and what is left in the engine is geometry.

3.1 The supervised calls

The mode is checked first; Registration is the default, and the one that needs no other tool (ioscbct/__init__.py:46-48, ioscbct/dispatch.py:283-288). In the two other modes main refuses at once when Crown_Seg, ALI_IOS and ALI_CBCT, plus ASO for Fully-Automated, cannot be reached, and resolves the orientation reference to DATA/AREG/models/CBCT_Gold_Frankfurt_Horizontal_Midsagittal_Plane when none is named (ioscbct/dispatch.py:190-199,311-331). Then, in this order (ioscbct/dispatch.py:332-339, ioscbct/tools.py:102-177):

cbct = sup.run("ASO", input=cbct, reference=<Frankfurt>,          # Fully only
               modality="CBCT", automation="Fully-Automated" [, landmark_model])
ios  = sup.run("Crown_Seg", meshes=ios, suffix="Seg" [, model=crown_model])
ios_lm  = sup.run("ALI_IOS", input=ios, networks=["Occlusal"])          # unless sent
cbct_lm = sup.run("ALI_CBCT", input=cbct,
                  landmarks=["UR1O","UR3O","UR6O","UL1O","UL3O","UL6O",
                             "LR1O","LR3O","LR6O","LL1O","LL3O","LL6O"])   # unless sent

ALI_CBCT is asked for those twelve points by name, not by region, because asking by region would run every agent of every region containing one of them (ioscbct/tools.py:122-137); ALI_IOS is asked for its occlusal network alone (ioscbct/tools.py:140-156). The intraoral meshes are labelled but not oriented: ASO is called only on the CBCT. Progress waypoints are 0.1, 0.3 and 0.5, and the registration starts at 0.6 (ioscbct/tools.py:129-130,148-149,167-168, ioscbct/dispatch.py:355).

3.2 Pairing the two modalities

The two modalities are named by different conventions, so patient_key keeps only what they share, the digits: the time-point tokens t0 t1 t2 are removed, then every non-digit, then the leading zeros, so P001_T2_U.vtk and P_0001_T2.nii.gz both key to 1 (ioscbct/pipeline.py:30-52). discover walks both folders in sorted order, keeps every mesh (.vtk, .stl) of a key and the first CBCT of a key, and reports a key present on one side only (ioscbct/pipeline.py:55-106). The crudeness of that key is the first finding.

Landmark files are read as Slicer markups, or as a plain {label: [x, y, z]} object (ioscbct/pipeline.py:109-133), indexed by their path relative to the folder (ioscbct/dispatch.py:87-108), narrowed to the patient's key (:111-135), and matched to a mesh by its jaw token (u upper l lower); a single file without a jaw token, which is what ALI_CBCT writes for a whole CBCT, serves both arches, the labels themselves (UR1O against LR1O) separating them (ioscbct/dispatch.py:138-175).

3.3 The CBCT surface, and the level it is contoured at

Once per patient, all the patient's CBCT landmarks merged, volume.read reads the volume and returns the contoured surface and a verdict on each landmark (ioscbct/dispatch.py:57-84, ioscbct/volume.py:148-175):

array = sitk.GetArrayFromImage(image)
ijk_to_lps[:3, :3] = direction @ diag(spacing);  ijk_to_lps[:3, 3] = origin
level = surface_threshold(array, ijk_to_lps, landmark_positions)
on_enamel = landmarks_on_enamel(array, ijk_to_lps, landmarks, level)
surface = pv.wrap(array.transpose(2, 1, 0)).contour(isosurfaces=[level])
return surface.transform(ijk_to_lps, inplace=False), on_enamel

The level is read off the scan, with the same rule as the legacy at 3c67957 (ioscbct/volume.py:96-117):

  • the enamel plateau is the median, over the CBCT landmarks, of the brightest voxel within 2 voxels of each (PROBE_RADIUS_VOXELS = 2, ioscbct/volume.py:27,46-60,77-79,91);
  • the surround is the median of the voxels between -300 and 300 HU in the box the landmarks span (SOFT_TISSUE_BAND, ioscbct/volume.py:32,85-92);
  • the level is half-way between the two; 400 is only the fallback, used when no landmark falls inside the scan or when the crowns are no brighter than their surround (FALLBACK_LEVEL = 400.0, ioscbct/volume.py:36,105-112);
  • an explicit level argument would win, but no caller passes one (ioscbct/volume.py:101-103, ioscbct/dispatch.py:77).

Observed on the published test scan (P_0001_T2_Or.nii.gz and its 12 CBCT landmarks, the files the viewer below is built from, run through volume.surface_threshold and volume.landmarks_on_enamel in the tool's environment): enamel 2783, surround 146, level 1464, far above the 400 fallback; and UL3O reads 274 at its brightest, under the level, so it is judged not to lie on a tooth.

The same level then judges each landmark: one whose neighbourhood never reaches it is not on enamel, which in a closed bite usually means the network put it on the opposing arch (ioscbct/volume.py:120-145). The contour takes bone and enamel alike above that level; the transpose puts SimpleITK's (k, j, i) array back in pyvista's (i, j, k) order, and ijk_to_lps takes the surface back to LPS, the frame both ALI tools write (ioscbct/volume.py:161-175).

3.4 The landmark fit

shared_landmarks intersects the two label sets, refuses fewer than 3 common labels, and reports the labels dropped (ioscbct/pipeline.py:136-155). align_by_landmarks is the closed-form rigid fit of vtkLandmarkTransform in RigidBody mode, IOS as source and CBCT as target, and it raises on sets of different sizes instead of returning the identity (ioscbct/geometry.py:34-74). Around it, fit_rigid_without_outliers and prealign decide which pairs count and whether the result is accepted (ioscbct/geometry.py:168-321):

RuleConstantEffect
Fewer than 3 pairsMIN_LANDMARK_PAIRS = 3identity, accepted: false, reason “too few pairs” (:289-294)
Landmark not on enamelverdict of 3.3set aside before any fit, provided 3 pairs remain (:229-242)
Outlier trimmingLANDMARK_OUTLIER_FLOOR_MM = 3.0, LANDMARK_OUTLIER_IMPROVEMENT = 0.75, MIN_LANDMARK_PAIRS_AFTER_TRIM = 4one pair per round: the pair whose removal gives the best fit is dropped if it sits more than 3 mm off and the fit without it is at most 75% of the residual; never below 4 pairs (:244-275)
Residual too largeMAX_LANDMARK_RESIDUAL_MM = 10.0identity, accepted: false, reason “residual too large” (:301-307)
Landmarks nearly in a lineMIN_LANDMARK_SPREAD_RATIO = 0.10warning only; the spread goes to the report (:199-209,309-321)

A refused pre-alignment is not an error: the ICP then starts from the pose the orientation left, the identity (ioscbct/geometry.py:278-285).

3.5 The ICP

register_one crops the CBCT surface to the box of the arch's CBCT landmarks plus 25 mm, moves the mesh by the pre-alignment, then runs icp_point_to_plane (ioscbct/pipeline.py:158-212, ioscbct/geometry.py:395-450):

  • moving points: the crowns only, when the mesh carries Universal_ID and at least 10% of it is crown; labels 0 and 33 are gingiva, which has no counterpart in a CBCT (GINGIVA_LABELS, MIN_CROWN_SHARE, ioscbct/geometry.py:368-372,453-476);
  • correspondences: nearest CBCT point within ICP_MAX_DIST_MM = 1.0, whose normal agrees with the mesh's by more than 0.5, which keeps the opposing arch out in a closed bite (:338,343,543-555);
  • step: point-to-plane, linearised in the rotation, solved by least squares; a rank-deficient system or a rotation over 0.5 rad falls back to a point-to-point Procrustes step (:479-521,571-577);
  • stop: after 300 iterations, or once the largest shift stays under 0.001 mm for 3 iterations (:346-348,585-586);
  • normal sign: the run is done with the CBCT normals read both ways, and the reading with the better fitness, then the lower RMSE, is kept (:600-651);
  • floor: an ICP that matched under 5% of the arch is an error for that mesh, so an unregistered mesh is never written under a registered name (MIN_ICP_FITNESS = 0.05, ioscbct/pipeline.py:192-202);
  • drift: the RMS of the fitted landmarks before and after the ICP goes to the report, with a warning above 1 mm (ioscbct/pipeline.py:215-244).

The final matrix is refinement @ matrix, the ICP composed after the landmark fit (ioscbct/pipeline.py:212). Without a surface (the volume could not be contoured) the mesh is placed on its landmarks only and icp stays null in the report (ioscbct/pipeline.py:184-185).

8. Findings in VISOR

Patients and time points that differ only by letters are merged

patient_key keeps the digits and nothing else (ioscbct/pipeline.py:30-52). Observed on 6ba2a78: A12_T1_Upper.vtk, B12_T1_Upper.vtk and P1_visit2_U.vtk all give '12', while P001_T2_U.vtk and P_0001_T2.nii.gz both give '1', which is intended. With four meshes P001_T1_{U,L}.vtk and P001_T2_{U,L}.vtk beside three CBCTs P_0001_T1.nii.gz, P_0001_T2.nii.gz and Q001_T1.nii.gz, discover returned a single patient '1' holding the four meshes and the first CBCT in sort order, and an empty unpaired: the other two CBCTs disappeared unreported (setdefault, ioscbct/pipeline.py:74,81). Landmark files are narrowed to the patient key, then matched to a mesh by the jaw token alone, the first in sort order winning: observed, the landmark set picked for P001_T2_L.vtk among P001_T1_L and P001_T2_L was the T1 one (_for_patient and _match_landmarks, ioscbct/dispatch.py:111-175). The tool is documented as not longitudinal (ioscbct/__init__.py:3-7) but nothing enforces it or reports it.

The isosurface level can no longer be set

The legacy accepted AREG_CBCT_SURFACE_THRESHOLD (AREG_IOSCBCT.py:92,943-950@3c67957). VISOR keeps the rule and the fallback of 400, and the warning it logs on falling back advises to “pass a level explicitly” (ioscbct/volume.py:96-112), but the only caller never does: volume.read(scan_path, merged) (ioscbct/dispatch.py:77) and run() has no such argument. Read in code.

On the published test scan the level is 1464, not 400

Observed with the tool's own functions on P_0001_T2_Or.nii.gz and its 12 CBCT landmarks: enamel 2783, soft tissue 146, level 1464 (ioscbct/volume.py:96-117). At that level UL3O (brightest 274) is judged off enamel, and the landmark fit of the upper arch is made without it (ioscbct/geometry.py:229-236). So “400” is only what VISOR uses when it cannot read a scan, and the surface any figure draws at 400 is not the one the VISOR ICP registers on. The viewer in 3.4 says so.

The documentation of max_dist is wrong

The docstring says that 0 uses 1.5, “which is upstream's” (ioscbct/__init__.py:83-85). The code uses ICP_MAX_DIST_MM = 1.0 (ioscbct/dispatch.py:352, ioscbct/geometry.py:338), with a comment saying that upstream's signature says 1.5 and every call site passes 1.0 (ioscbct/geometry.py:335-338). DEFAULT_MAX_DIST = 1.5 is the default of icp_point_to_point alone (ioscbct/geometry.py:25,77-78), a function no module of the engine calls (grep: only tests/test_geometry.py does); the fallback the ICP actually uses is _point_to_point_step, which takes no distance (ioscbct/geometry.py:509-521,576-577). The field is hidden in the panel (ioscbct/layout.py:84), so the wrong sentence reaches API users only.

A kept estimator describes an upstream that no longer exists

The docstring of icp_point_to_point says it was renamed from upstream's run_icp_point_to_plane because that function computes point-to-point (ioscbct/geometry.py:81-86), and the comment above the ICP constants says it is kept as the fallback for a degenerate system (ioscbct/geometry.py:331-334). At 3c67957 upstream's run_icp_point_to_plane has a real point-to-plane step (AREG_IOSCBCT.py:579-608,719), and in VISOR the degenerate case falls back to _point_to_point_step, not to this function. Harmless, but misleading for whoever compares the two code bases. Read in code.

The pre-alignment verdict is data, not a log line

Each mesh carries prealignment (accepted or not, why, landmarks fitted, residual, spread) and the ICP statistics, including the drift of the landmarks before and after (ioscbct/pipeline.py:158-212). A volume that cannot be contoured does not stop the run: the meshes are placed on their landmarks and the report says that the ICP did not run (ioscbct/dispatch.py:57-84). Read in code.

The scratch folder is always removed

Unlike AREG_CBCT and AREG_IOS, the engine wraps its work in a try/finally that deletes .areg_work/ (ioscbct/dispatch.py:306-358). Read in code.

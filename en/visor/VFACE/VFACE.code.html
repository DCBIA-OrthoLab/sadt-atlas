VFACE on VISOR: the code

For developers: what the VISOR port of VFACE does in the code, with file:line references, signatures, arguments, environment, the differences from the legacy code and the findings. The readable explanation of the same pipeline, with the maths and the 3D viewer, is on the atlas page.

VISOR Code Atlas (explanation) branch tool/vface only Legacy page Guide (VISOR) Bibliography
A port on two feature branches

The VFACE tool exists only on the branch tool/vface of SADT-VISOR (6ba2a78, 22 commits ahead of main), and its server section [tools.VFACE] only on the branch conf/vface-deployment of VISOR-serve (e9a7e5d). git ls-tree main tools/ on SADT-VISOR lists no VFACE folder, and the deployment.toml of VISOR-serve's main has no VFACE section. A server built from the main branches does not publish VFACE, even though the Slicer module VFACERemote is on the client's main. Everything below describes those two branches.

A patient is compared against themselves. In an asymmetry assessment there is no second scan: the baseline is oriented, mirrored across the mid-sagittal plane, registered back onto itself region by region, and what is measured is how far each landmark has moved from its own reflection. A longitudinal study is the same chain with a real follow-up in the mirror's place (SV:__init__.py:5-15). VFACE itself learns nothing and runs no network: every model it needs belongs to another tool, except the classifier, which it reads with LightGBM.

Citations use short names: SV is SADT-VISOR tools/VFACE/src/sadt_vface/ at 6ba2a78, README.md and pyproject.toml are in tools/VFACE/ of the same repository; VS is VISOR-serve at e9a7e5d; R is AutomatedDentalToolsRemote at 19b95e8; legacy is SlicerAutomatedDentalTools at 3c67957, where clp is VFACE/VFACE_utils/createlistprocess.py and VFACE_CLI.py is VFACE_CLI/VFACE_CLI.py. Everything was read in the code; nothing on this page comes from a run, and nothing here says that a server is deployed. For the server itself, see the architecture and a run, step by step.

3. The pipeline

Plain-language explanation and maths: atlas page.

dispatch.py states the chain in its first lines (SV:dispatch.py:5-6):

resample -> orient (per frame) -> segment (per frame) -> the second scan
         -> register (per region) -> landmarks -> measure -> classify

3.1 Three modes, two studies, three outputs

Plain-language explanation and maths: atlas page.

Three enumerations, which are the legacy combo boxes (SV:catalogs.py:1-15, 25-49). Each mode starts where the previous one leaves off (SV:dispatch.py:14-20):

ArgumentValueWhat runs
modeFull pipeline (default)Resample, orientation into both frames, masks, second scan, registration, then the outputs (SV:dispatch.py:463-468, 477-499)

3.2 Everything is checked before a volume is read

Plain-language explanation and maths: atlas page.

Before the first scan is touched, main() fills the empty bundle arguments from the deployment, rejects an unknown mode, study, output or region by name (SV:dispatch.py:364-376), and _run() refuses a mode whose callees cannot be reached or whose bundle is missing (SV:dispatch.py:424-458). "A request that cannot work has to come back in a second, not after an hour" is the code's own rule (SV:dispatch.py:424-425).

ConditionTools requiredBundle required
Full pipelineASO–

tools.require only checks that a supervisor exists: without one (a direct call, a test) it raises SupervisorRequired, answered as HTTP 501, with advice on the mode that works without that tool (SV:tools.py:77-88; SV:errors.py:14-19). Whether the callee is actually served is checked by the server at start-up from the schema's calls field, which describe.py derives by reading tools.py (SV:tools.py:30-35).

3.3 Bundles the deployment resolves

Plain-language explanation and maths: atlas page.

Seven arguments are filled from DATA/VFACE/models/<name> when the caller leaves them empty, because the server's convention would otherwise hand each of them the whole models/ folder, which holds six bundles at once (SV:dispatch.py:300-332, 348-358; VS:server/deployment.toml:263-272):

_BUNDLES = {

    "classifier_model": "VFACE_classifier",
    "cranial_base_reference": "CBCT_Gold_Frankfurt_Horizontal_Midsagittal_Plane",
    "maxilla_reference": "CBCT_Gold_Occlusal_Midsagittal_Plane",
    "mirror_reference": "Mirror_matrix",
    "measurements": "DefaultList",
    "feature_template": "DefaultList",     # the file features.xlsx inside it
}

Source: SV:dispatch.py:315-323. A name the caller sends wins; a bundle folder that does not exist resolves to "" and the check of 3.2 then names it (SV:dispatch.py:326-332). landmark_model is absent on purpose, since ALI_CBCT resolves its own weights from the same data root (SV:dispatch.py:311-313). surface_model is absent too, and nothing else fills it: see Findings.

3.4 The chain, step by step

Plain-language explanation and maths: atlas page.

The default request (Full pipeline, Asymmetry assessment, Measurements and classification, three regions), as dispatch._run executes it. Each callee writes into its own numbered slot under <job>/sup/; VFACE's own intermediates go to .vface_work/.

t1: a folder of raw CBCTs, searched recursively

Preparation

  1. resample to 0.3 mm isotropic, centred, folder tree kept .vface_work/resampled/
  2. ASO ×2, Fully-Automated: Frankfort + mid-sagittal (7 landmarks), then occlusal + mid-sagittal (6 landmarks) scans *CB_Or* and *MAX_Or* + .tfm
  3. AMASSS ×2: CBMASK and MANDMASK on the CB frame, MAXMASK on the MAX frame <scan>_seg_SegOut/

Second scan

  1. AutoMatrix ×2 applies the mirror to the oriented scans of each frame: this is where the “T2” comes from files suffixed mir

Registration

  1. AREG_CBCT ×3, Semi-Automated, one region per call, on the masks of 1.3 <region>/<patient>_<region>_Reg.nii.gz + _transform.tfm

Measurements

  1. pad the CB-frame scans by 30 mm, then ALI_CBCT places every landmark the lists name .vface_work/padded/, then <scan>_lm_Pred.mrk.json
  2. derive those landmarks into the MAX frame by a rigid transform .vface_work/landmarks/MAX/
  3. AutoMatrix ×2 mirrors the landmarks of each frame files suffixed mir
  4. AutoMatrix ×3 moves them by each patient's matrix, one call per region files suffixed reg
  5. AQ3DC ×3 measures distances and angles Measurements/Measurements_{CB,MAND,MAX}.xlsx
  6. signed features, one row per patient Measurements/PostProcess_Measurements.xlsx
  7. three LightGBM models Classification/Classification.xlsx

Fifteen sup.run calls for the default request: 2 ASO, 2 AMASSS, 2 + 2 + 3 AutoMatrix, 3 AREG_CBCT, 1 ALI_CBCT, counted from SV:dispatch.py:131-141, 160-164, 179-187, 211-215, 227-235, 256-262, 487-494, plus whatever ASO and AREG_CBCT call themselves. The heat-map branch adds two Batch_Dental_Seg calls per region (SV:heatmap.py:219-226).

Progress is reported at fixed waypoints, through the supervisor when there is one so that the events of a chain land in one file: resample 2 %, orient 10, segment 30, second scan 45, register 55, landmarks 75, measure 90, classify 97 (SV:dispatch.py:47-74).

3.5 Resample

Plain-language explanation and maths: atlas page.

The legacy full pipeline begins by calling MRI2CBCT's resample CLI with every MRI-specific input set to "None". VISOR has no MRI2CBCT tool, so the fifteen lines that are actually reached are copied into resample.py (SV:resample.py:1-33; README.md:53-79). The grid size is kept and the spacing changes, so at a finer spacing the field of view shrinks around the centre:

size = list(image.GetSize())                       # kept, not recomputed
if centre:
    output_extent = np.array(size) * np.array(output_spacing)
    input_extent  = np.array(size) * np.array(image.GetSpacing())
    origin = origin - (output_extent - input_extent) / 2.0
resampler.SetInterpolator(sitk.sitkLinear)
resampler.SetOutputSpacing(output_spacing)          # DEFAULT_SPACING = (0.3, 0.3, 0.3)
resampler.SetDefaultPixelValue(float(np.min(...)))  # the volume's own minimum, not 0

Source: SV:resample.py:48, 67-87. Padding with the volume's minimum avoids a shell of soft-tissue intensity around the head (SV:resample.py:60-62). Output paths keep the scan's folder relative to t1, where the legacy flattened them (SV:resample.py:29-33, 113). An unreadable volume is recorded under not_resampled in the report and the cohort continues; a cohort where nothing could be resampled is refused (SV:resample.py:111-132).

3.6 Orientation into two frames

Plain-language explanation and maths: atlas page.

A scan is oriented twice, and every later step works in one frame or the other (SV:catalogs.py:52-76). The mandible is worked in the cranial-base frame, because it is measured by how it sits relative to the skull; only the maxilla gets the occlusal frame (SV:catalogs.py:88-91).

FrameReference (subfolder of the gold bundle)Landmarks sent to ASOSuffixRegions worked in it
CBFrankfurt Horizontal and Midsagittal PlaneBa, LPo, N, RPo, S, LOr, ROrCB_OrCranial base (CBMASK), Mandible (MANDMASK)
MAXOcclusal and Midsagittal PlaneANS, IF, PNS, UL6O, UR1O, UR6OMAX_OrMaxilla (MAXMASK)

Source: SV:catalogs.py:63-76, 104-117. Each frame is one ASO call in Fully-Automated mode, which for a CBCT means ASO predicts its landmarks through ALI_CBCT and then registers on them: the PRE_ASO, ALI and SEMI_ASO steps the legacy spelled out one by one (SV:tools.py:116-145). Both frames are oriented whatever regions were asked for, because the landmarks are predicted in the CB frame and derived into the MAX frame (SV:dispatch.py:479-486); catalogs.frames_needed exists but nothing in the package calls it. In the two modes that skip the orientation, a scan whose name carries neither suffix, or both, is left out and listed under scans_without_a_frame; a frame with no scan at all is refused (SV:dispatch.py:105-123, 473-474).

3.7 Registration masks

Plain-language explanation and maths: atlas page.

One AMASSS call per frame, for the structures of the regions that frame holds, so the CB frame asks for CBMASK and MANDMASK in one pass (SV:catalogs.py:134-145). A frame no requested region registers on gets no call at all: AMASSS refuses an empty structure list, and a cranial-base-only request used to die there after both orientations had been paid for (SV:dispatch.py:479-494). The structures are the mask variants, CBMASK/MANDMASK/MAXMASK, not the anatomical CB/MAND/MAX: a registration handed a segmentation where it expects a mask would "run, produce a transform, and report success on the wrong anatomy" (SV:catalogs.py:93-99). merge=["SEPARATE"] gives one binary file per structure, so a region's mask can be looked up by name (SV:tools.py:151-153).

3.8 The second scan: where the two studies part

Plain-language explanation and maths: atlas page.

The mirror is a single transform, mirror_reference, applied with same_transform_for_every_patient=True, because it is a reflection of the frame and not something fitted per patient (SV:tools.py:179-188). It is only valid because the orientation has already put the mid-sagittal plane where the reflection expects it. The scans are mirrored with content="Scan", the landmarks later with content="Automatic", since content chooses how voxels are resampled and the landmark folders hold markups (SV:dispatch.py:229-233). A longitudinal study without t2, or an asymmetry assessment without a mirror bundle, is refused with a message naming the other study (SV:dispatch.py:155-171).

3.9 Registration, one region per call

Plain-language explanation and maths: atlas page.

For each requested region, AREG_CBCT registers the second scan of that region's frame onto the baseline of the same frame, on that region's mask (SV:dispatch.py:177-187). Semi-Automated, because the scans are already oriented and segmented: asking AREG to orient again would orient the mirror independently of the original, and "a mirror is only a mirror while it shares the original's frame" (SV:tools.py:218-222). The region name sent is AREG's display name (Cranial base, Mandible, Maxilla: SV:catalogs.py:104-117).

AREG_CBCT groups its results by region, so the folder it returns holds no transform. _region_folder steps one level down when there is exactly one subfolder holding a transform (.tfm, .mat, .h5, .txt), and otherwise refuses with the list of what it found plus the per-patient reasons read from AREG_report.json (SV:tools.py:236-317). In that region folder AREG_CBCT writes both the registered scan and its transform, <patient>_<region>_Reg.nii.gz and <patient>_<region>_Reg_transform.tfm (SADT-VISOR tools/AREG/AREG_CBCT/src/sadt_areg_cbct/pipeline.py:72-83): the landmark step uses the transforms, the heat-map step the scans.

3.10 Landmarks: found once, then derived and moved

Plain-language explanation and maths: atlas page.

Which landmarks. Only those the measurement lists name, collected into one sorted set (SV:dispatch.py:200-206): ALI_CBCT runs one search agent per landmark, at about a minute each, so a whole region catalogue would cost hours (SV:tools.py:330-336; README.md:142-144).

Padding. The CB-frame scans are copied with 30 mm of room on each side before the search, padded with the scan's own minimum; the origin moves with the padding, so the points come back in the original scan's space (SV:landmarks.py:36, 186-228). The reason given is ALI's agent refusing any position outside the unpadded size, which made it give up on a point one or two voxels from the border, such as Me (SV:landmarks.py:5-11). A scan that cannot be padded is searched as it is and listed under not_padded.

Derivation into the MAX frame. Both orientations come from the same centred scan, so a point's position in the maxillary frame follows from its position in the cranial-base frame through the two orientation transforms, without a second search (SV:landmarks.py:252-334):

to_centred   = sitk.ReadTransform(from_source[patient])              # CB-frame .tfm
from_centred = sitk.ReadTransform(to_target[patient]).GetInverse()  # MAX-frame .tfm, inverted
moved = from_centred.TransformPoint(to_centred.TransformPoint(points[label]))

Source: SV:landmarks.py:292-307. A patient missing one of the two transforms is skipped and recorded under not_derived; if no patient can be derived the run stops (SV:landmarks.py:280-330). Patients are paired across files by patient_of, which cuts the file name at the first decoration token (scan, or, cb, lm, t1, seg, reg, mir, the AREG region names...) matched as a whole token, never as a substring (SV:landmarks.py:46-55, 80-98).

The compared set. For an asymmetry assessment, the baseline's own landmarks mirrored by AutoMatrix; for a longitudinal study, landmarks predicted by ALI_CBCT on the padded follow-up (SV:dispatch.py:224-250). Then each region's compared set is moved by that region's registration, one AutoMatrix call per region with same_transform_for_every_patient=False, so each patient's matrix is paired with that patient by name (SV:dispatch.py:252-262; SV:tools.py:191-212).

Coordinates. The landmarks travel as .mrk.json markups between ALI_CBCT, AutoMatrix and VFACE, and derive_into_frame applies SimpleITK transforms to the stored positions directly (SV:landmarks.py:292-307). No RAS/LPS conversion appears in the VFACE package; the frame convention is therefore the one the callees write, which this page did not re-read.

3.11 Measurements (AQ3DC)

Plain-language explanation and maths: atlas page.

The lists. measurements is a folder of Excel workbooks, one per region, matched to its region by file name: CB/CRANIAL/CRANIOFACIAL, MAND/MANDIBLE/ MANDIBULAR, MAX/MAXILLA/MAXILLARY, first match wins, Excel lock files skipped (SV:dispatch.py:543-582). Every sheet of a workbook is read (SV:aq3dc.py:111-122). The default lists are the DefaultList bundle.

The kinds. A row names a kind of measurement and its landmarks; the timepoint sits on each point, not on the row, and that is what makes "the distance between a landmark and its own mirror" expressible (SV:aq3dc.py:7-11):

Spelling in the listKindPoints and their timepoints
Distance between 2 points T1 / T2distance between two points2, both at T1 (or both at T2)
Distance between 2 points T1 T2distance between two points2: one at T1, one at T2
Distance point line T1 / T2point to line3, same timepoint
Angle between 2 lines T1 / T2angle between two lines4, same timepoint
Angle line T1 and line T2angle between a T1 line and a T2 line4: two at T1, two at T2

Source: SV:aq3dc.py:50-66; arithmetic in SV:measure.py:103-198. Each row gives R-L, A-P and S-I components with a sign meaning, a 3D distance, and yaw, pitch and roll for angles; a column a kind does not fill holds x (SV:aq3dc.py:30-44). The sign meanings, which say which way a positive number points, are the clinical content and are reproduced from the legacy tables, dental and skeletal apart (SV:measure.py:10-17, 261-330). One legacy oddity is kept on purpose: the side of a midpoint such as Mid_ROr_LOr always resolves to M, because changing it would change the sign of a feature the classifier was trained on (README.md:81-94). A patient present at only one timepoint, a missing landmark or a degenerate measurement is skipped and recorded (not_measured, landmarks_absent, measurements_degenerate: SV:aq3dc.py:283-322). A region with no row at all stops the run (SV:dispatch.py:278-282).

3.12 Feature table and classification

Plain-language explanation and maths: atlas page.

Signed features. to_stats turns each row's magnitude and label back into a signed number; which label is negative depends on whether the row is dental or skeletal, and for a tooth on its arch and segment (SV:features.py:1-11, 101-175). The vertical axis keeps both legacy conventions, which are opposite:

# dental row
stats["Vertical"].append(str(_signed(row["S-I Component"], row["S-I Meaning"], ("I",))))
# skeletal row

3.13 Heat maps

Plain-language explanation and maths: atlas page.

For each region, Batch_Dental_Seg is asked for surfaces twice: on the oriented baseline of that region's frame, and on AREG's region folder, which holds the registered scans. Surfaces are paired by patient, and each pair gives one map, the baseline surface carrying its signed distance to the other (SV:heatmap.py:207-244):

total = baseline.GetNumberOfPoints() + compared.GetNumberOfPoints()
reduction = 0.7 if total > 2_000_000 else 0.5 if total > 1_000_000 else 0.0
# decimate both (vtkQuadricDecimation), vtkDistancePolyDataFilter with SignedDistanceOn,
# ComputeSecondDistanceOff, then carry the distances back onto every original point
# through a vtkPointLocator

Paraphrased from SV:heatmap.py:34-41, 95-191. Both surfaces are cleaned and triangulated first (SV:heatmap.py:73-92). Maps are written as legacy VTK version 4.2, which every Slicer in use reads, to Heat maps/<region>/<patient>_<region>_heatmap.vtk (SV:heatmap.py:56-70, 233). The legacy ran each pair in its own subprocess to release VTK memory inside Slicer; a VISOR tool is already its own process, so only the subsampling is kept (SV:heatmap.py:11-18). A run that draws no map at all is refused (SV:heatmap.py:246-251).

8. Findings in VISOR

Plain-language explanation and maths: atlas page.

Never run with its six real callees

The README states that no supervised chain has been executed with the six tools: the calls are covered by a fake supervisor asserting the parameters, plus a test that reads the six published schemas. It also states that nothing has been compared with the legacy output on a patient, and that nothing is validated clinically (README.md:184-193). The 174 passing tests (README.md:183) are evidence for the arithmetic and the wiring, not for a patient's result.

Heat maps: Batch_Dental_Seg is not asked for surfaces

segment_surfaces sends Batch_Dental_Seg only scans, model and prediction_ID (SV:tools.py:359-364). Batch_Dental_Seg's export_formats defaults to ["NIFTI"] (SADT-VISOR tools/Batch_Dental_Seg/src/sadt_batchdentalseg/__init__.py:22-24), and a mesh is written only for a mesh format in that list (pipeline.py:342-353 of the same package). VFACE then looks for .vtk and .vtp only (SV:heatmap.py:29, 194-204), finds no pair, and refuses with "No heat map could be drawn" (SV:heatmap.py:246-251). Read in code, not executed. With "Measurements and heat maps" this refusal comes after the measurements were written, and the run ends in error.

Heat-map outputs have no surface bundle on this deployment

The server file says "surface_model is Batch_Dental_Seg's, and this deployment publishes none" (VS:server/deployment.toml:277-279). The tool does not look for one in DATA (surface_model is not in SV:dispatch.py:315-323), the panel hides the field (SV:layout.py:100-104), and a request for heat maps without it is refused with "Heat maps are drawn on segmented surfaces, and 'surface_model' names the bundle that makes them" (SV:dispatch.py:452-458). Read in the code, not executed: the two outputs that include heat maps cannot succeed unless a caller supplies that bundle, and even then the previous finding applies.

A longitudinal study is also classified

In VISOR, _classify runs whenever measurements are asked for, whatever the study (SV:dispatch.py:521-533). The legacy built the feature table and ran the classifier only for an asymmetry assessment (clp:1141-1175). In a longitudinal study the features are T1-to-follow-up differences, while the models were trained to read a patient against their mirror, so the Asymmetry column of such a run has no stated meaning. Read in code, not executed.

Cohort batching splits t1 and not t2

The server splits a cohort on the single required path argument (VS:server/registry/conventions.py:158-188). For VFACE that is t1: t2 and registration_transforms are optional, and the bundles are excluded as models. The comment of batch_axis_for excludes tools with two required paired folders, but nothing excludes a pair whose second folder is optional. So a longitudinal cohort above 25 files or 400 MB would be cut along t1 with t2 left whole or unsplit, depending on what the client sends with each batch. Deduced from the code, not executed; deployment.toml sets no batch_axis or batch_enabled for VFACE.

Error advice points to fields that do not exist

When a callee is missing, the refusal tells the user to send "your own segmentation masks in 'masks'" and "your own landmark files in 'landmarks'" (SV:tools.py:53-56, 66-69). The signature has no masks and no landmarks argument (SV:__init__.py:22-49).

The data manifest still says "NOT PORTED YET"

VS:scripts/data-manifest.yml:654 labels VFACE "NOT PORTED YET", although the tool exists on tool/vface and has a server section. The manifest also lists only V_FACE_Models.zip, DefaultList.zip and Testing.zip (:656-673), whereas the tool resolves six bundle folders under DATA/VFACE/models/ (SV:dispatch.py:315-323). Do not use the manifest to tell what is served.

Two measurement types of the legacy list are skipped

The legacy builds ten kinds of measurement, among them Distance point line T1 T2 and Angle between 2 lines T1 T2, each the difference of two measures (Diff2Measure, functionaq3dc.py:2014-2024; Measure.py:805-905). SPELLINGS has eight entries and neither of these (SV:aq3dc.py:50-59). A row of the list with either is dropped with the warning “is not a measurement this tool makes; that row of the list is skipped” (SV:aq3dc.py:163-166), and the run goes on. The default lists do not use them (counted: 16 distances T1 T2, 10 distances T1 and 4 angles in the cranial-base list, 15 in the mandible list, 7 in the maxilla list), so nothing is lost with the shipped lists; a list written for the Slicer module that does use one loses those rows from the result, with only a warning in the log.

Six callees, not seven; a cap of ten, not five

Comments say VFACE orchestrates "seven tools" (VS:server/deployment.toml:258; R:VFACERemote/VFACERemote.py:14). The tool calls six (SV:tools.py), and its published schema lists six. SV:tools.py:17-20 and README.md:111-113 give the runner's nesting cap as five; the server at e9a7e5d sets MAX_SUPERVISOR_DEPTH = 10 (VS:server/execution/runner.py:196), and its comment still names AREG_IOSCBCT, ASO, ALI_CBCT, three levels, as the deepest real chain (runner.py:185-189), where VFACE's is four.

Verified: the heat-map branch finds registered scans in AREG's folder

draw_cohort hands Batch_Dental_Seg the region folder that _region_folder selected for its transforms (SV:heatmap.py:224-226; SV:tools.py:236-262). AREG_CBCT writes the registered scan and its transform side by side in that folder (SADT-VISOR tools/AREG/AREG_CBCT/src/sadt_areg_cbct/pipeline.py:72-83), so the folder does hold volumes to segment. Read in code, not executed.

Arithmetic parity is tested

The distances, angles, sign blocks and statistics tables are transcribed from the legacy code and compared with this port on random input: 6,200 distances, 3,000 angles, 65,536 dental distance labels and others (README.md:166-172; tools/VFACE/tests/test_matches_upstream.py). This was read from the README and the test file, not re-run for this page.

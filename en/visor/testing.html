Tests, naming and provenance

How a VISOR tool is laid out, tested, named and traced back to the legacy code it was ported from, and what the continuous integration does and does not guarantee. Several rules written in the repository's own documents no longer match its code or its CI; this page says which.

SADT-VISOR 6ba2a78 VISOR-serve e9a7e5d AutomatedDentalToolsRemote 19b95e8 legacy ADT 3c67957
How to read this page

Citations are repository file:line at the commits above; SADT-VISOR is the repository of the tools, VISOR-serve the server, Remote the Slicer client. Test counts are counted in the source (def test_, parametrised cases not expanded) unless a run is named. Only scripts/tests (89 passed, 4 skipped), naming/tests (26 passed), scripts/run_tool.py --help and scripts/audit.py were executed for this page; no tool environment was built and no GPU test was run. The legacy extension (commit 3c67957) is what the rest of this atlas describes; its own tests are on the ADTLib page and are a different suite.

1. Layout of a tool

SADT-VISOR holds "one isolated Python project per SlicerAutomatedDentalTools tool", each with its own interpreter, its own virtualenv and its own lockfile, and tools never import each other (SADT-VISOR README.md:3-5). The repository contains no server code (README.md:7-8). A tool is a folder with:

FileRole
pyproject.toml with a [tool.sadt] tabletool = true and name = "<ApiName>": this table is what makes a folder a tool, for the CI, the server registry and the image build alike (CONTRIBUTING.md:50-59; example tools/AMASSS/pyproject.toml:33-35)
src/sadt_<name>/__init__.pydefines the single public function run(...); no base class and no registry (README.md:41-58)
uv.lockcommitted; CI syncs with --frozen, which fails if the lock is stale (CONTRIBUTING.md:603)
tests/test_run.py, tests/test_integration.pythe two test levels below; tools/_template/ is the copy-me skeleton
README.mdincluding a "Provenance" block (section 4)

The folder name is the API name (the tool's virtualenv is looked up at <TOOLS_DIR>/<name>/.venv/bin/python, CONTRIBUTING.md:70-77); two grouping folders, tools/ALI/ and tools/AREG/, hold engines (ALI_CBCT, ALI_IOS, AREG_CBCT, AREG_IOS, AREG_IOSCBCT) and a common/ package. A shared package has a pyproject.toml without [tool.sadt]: installable, never discovered and never served. There is no [tool.uv.workspace], because one common lock would force torch 1.13 and 2.4 into the same resolution (CONTRIBUTING.md:578-583). The nineteen folders that declare [tool.sadt]: Agent, ALI_CBCT, ALI_IOS, AMASSS, AREG_CBCT, AREG_IOS, AREG_IOSCBCT, ASO, AutoCrop3D, AutoMatrix, Batch_Dental_Seg, CLIC, CNE, Crown_Seg, DOCShapeAXI, FlexReg, GreedyReg, Surg_Mov_Pred, VFACE (counted with the same find as the CI).

The schema the client renders is not written by hand. scripts/describe.py derives it from the signature of run(): allowed annotations are Path, str, int, float, bool, Literal[...], list[...] of those, and tuple[float, float] (published as vec2); no Optional, no union, no None default (describe.py:38-46,193-296). Every argument needs a line in the Args: block of the docstring (describe.py:807-841). Anything it cannot represent ends in exit code 2 with nothing on stdout (:1185-1187). The old hand-kept "ArgSpec" tables were dropped because they "drifted" (describe.py:8-11).

2. The three levels of tests

Level 1: in process, synthetic inputs

tests/test_run.py exists in each of the 19 tools and in the template (AREG/common, a shared package, has none). The rule is to call run() end to end, check that the expected files exist, have a plausible size and match a reference within a documented tolerance (CONTRIBUTING.md:605-609). In practice the fixtures are fabricated inside the test: SimpleITK volumes of 8, 16 or 48 voxels per side, VTK meshes of three triangles, seven-point skulls, .npy arrays, scikit-learn models fitted on the fly, and the nnU-Net or shapeaxi engine replaced by a stub (tools/AMASSS/tests/data/README.md:1-9, tools/ASO/tests/data/README.md:1-9, tools/AREG/TESTING.md:3-12). Counts by tool (def test_): Agent 206, ALI_IOS 183, AREG_IOSCBCT 172, VFACE 164, Crown_Seg 162, GreedyReg 158, ASO 145, AutoMatrix 139, CNE 130, CLIC 124, Surg_Mov_Pred 105, AutoCrop3D 103, AREG_CBCT 94, DOCShapeAXI 91, ALI_CBCT 66, AMASSS 61, AREG_IOS 56, Batch_Dental_Seg 55, AREG/common 40, FlexReg 21, the template 17.

Level 2: out of process, with the testkit

testkit/ (package sadt-testkit) offers run_tool(name, **params) (sadt_testkit/__init__.py:192), tool_schema (:248), is_built (:152) and the exceptions ToolNotBuilt and ToolFailed. It starts the tool in its own interpreter, from a neutral working directory, with a stdlib-only driver that is "a miniature of the server's runner" (same coercion by annotation, same result file, same exception class names; _driver.py:1-16). It exists to check what only shows from outside: the tool writes nothing outside output_dir, and the published schema agrees with the signature. The rule is skip, never fail, when the other tool is not built (CONTRIBUTING.md:629-632). Used by Agent, ALI_CBCT, AREG_IOSCBCT, ASO, VFACE and the template, one file each; ASO's LocalSup is a dozen lines wrapping run_tool to stand in for the server's supervisor.

Level 3: real data, never in CI

Tests on real models and scans carry the marks gpu and models; the files come from the deployment's DATA/ and are named by environment variables (SADT_AMASSS_MODELS, SADT_AMASSS_SCAN, SADT_ALI_CBCT_MODELS, SADT_CROWNSEG_MODEL, SADT_SURGMOVPRED_MODELS, SADT_CLIC_MODEL and others). The CI excludes gpu because its runner has no CUDA device, and the repository says that this makes them the author's responsibility: run them by hand and state the outcome in the pull request (CONTRIBUTING.md:638-640). Eight tools also set addopts = "-m 'not gpu and not models'" (Agent, CLIC, CNE, Surg_Mov_Pred, Crown_Seg, VFACE, AREG_IOSCBCT, ALI_IOS), to be overridden with -m models -o addopts=. No patient data is ever committed; CONTRIBUTING.md:611-614 asks for "a download script plus checksums", and no download.sh or *.sha256 exists: each tests/data/README.md says "Nothing is committed here" and points to environment variables or to the model manifest of VISOR-serve.

What the CI runs

One workflow, .github/workflows/ci.yml (105 lines), on pull requests and on pushes to main.

What the CI does not run

  • Tests marked gpu, excluded by -m "not gpu" (ci.yml:66-74).
  • Cross-tool integration. Each tool has its own job, so no other tool's virtualenv exists and the tests skip themselves (ci.yml:69-70, is_built). The chains ASO to ALI, AREG to ASO, VFACE to AREG are never exercised in CI.
  • The 26 tests of naming/, the 40 tests of tools/AREG/common/tests/ (neither has [tool.sadt], so neither is in the matrix, and no other job runs them) and ALI's common, which has no tests at all although its pyproject.toml declares testpaths = ["tests"].
  • The pyflakes sweep that CONTRIBUTING.md:681-685 asks for before a PR: no occurrence in the workflow.
  • Anything about numerical reproducibility across torch or MONAI versions; that is left to the manual validations in each tool's README.
The mark that the command line overrides

The eight tools whose addopts excludes models are run by the CI with -m "not gpu". On a throwaway pytest project built to check it, a -m given on the command line replaced the one in addopts, so the models tests were collected. They then skip only through their own skipif on the environment variable. Of 25 uses of mark.models, 9 were followed by a skipif within four lines (a rough count); whether each one skips in CI was not checked one by one. Not observed in a real CI run.

3. Naming: sadt_naming

"Naming" covers two things. The API name of a tool comes from [tool.sadt] name, else from the folder; an acronym stays as is (ALI, AMASSS) and words are capitalised and joined by _ (Batch_Dental_Seg); the Python package stays lower case (CONTRIBUTING.md:61-65,81-89). Renaming is a breaking change for every client (:91-93). Note that describe.py does not read [tool.sadt] name: the published name is the folder name (describe.py:1157).

The vocabulary of file names is the package naming/ (sadt_naming), standard library only (dependencies = [], naming/pyproject.toml:3-12). It holds the extension families (VOLUME with six extensions, composed first so that .nii.gz wins over .gz; SURFACE, MARKUPS, TRANSFORM, NOTES, TABLE), thirteen output markers that tools append (_lm_Pred, _Scanreg, _MERGED, _OutReg, _SegOr, _SegOut and others, matched as whole tokens and case-sensitively), thirteen jaw spellings (u up upper maxilla max mx l low lower mandible mand md and French variants) and the timepoints t0 t1 t2 (naming/src/sadt_naming/__init__.py:36-175). It splits UpperT1 into jaw and timepoint (:217) and truncates a name at its first marker without ever truncating a name that merely starts with one (:252).

26 tests (naming/tests/test_naming.py, 26 passed when run for this page) pin it: compound extensions, .nrrd.gz written back as .nrrd because ITK has no .nrrd.gz writer, the "contract" that the module imports nothing but os (a tool restricts by declaring less, never by editing the table), patient1 read as no jaw rather than Lower, MAXILLOFACIAL_03 not read as a maxilla, P_Seg1_T1 distinct from P_Seg2_T1. Two known limits are pinned as such: MAX_01 is read as upper, and T1Upper is not read. Those 26 tests are not run by any CI job (previous section).

Who uses it. Three tools depend on it: AMASSS, ASO and Batch_Dental_Seg (sadt-naming = { path = "../../naming" } in each pyproject.toml). Who keeps its table clean. Nobody compares the implementations. The "patient key" exists at least four more times: ASO's own PATIENT_SUFFIXES (tools/ASO/src/sadt_aso/cbct/pipeline.py:34-48), AREG's catalogs.py:158, pairing.py:175 (patient_stem), ALI's extension lists (ALI/common/.../discovery.py) and AutoMatrix's patient_of (pipeline.py:33). The docstring of sadt_naming admits that its jaw and timepoint rule was adopted from sadt_areg_common.pairing to avoid a third reading (:203-207). The guard against drift is made of duplicated boundary tests instead: 23 tests in ASO, 27 in AREG/common, a characterisation table of 400+ real names (3 tests, rows marked # WAS: where a fix moved a result) and 10 pairing tests. Two vendored files must stay byte-identical, progress.py (14 copies) and scans.py (2 copies), and a test compares their SHA-256 hashes (scripts/tests/test_vendored_copies.py:27); that one does run in CI, in the scripts job.

The contribution rules also require a round-trip test: read your own outputs with your own input rule (CONTRIBUTING.md:384-427). The founding case was Upper_new_9.vtk and Upper_new_9_Upper_O_Pred.json, read as two patients by the semi-automatic IOS mode of ASO.

4. Provenance

The repository imports no upstream history wholesale, so provenance is recorded by hand in four layers, strongest first.

  1. PROVENANCE.md (:14-23): one row per tool with upstream path, upstream commit, port date and "Algorithm modified". The row is filled by the pull request that migrates the tool (:25-27).
  2. A "Provenance" block at the top of each tool's README, from the template (tools/_template/README.md:7-20; CONTRIBUTING.md:649-655).
  3. git log --follow: for AMASSS, ASO, ALI, Batch_Dental_Seg, Surg_Mov_Pred and Crown_Seg the server-side history was carried by git subtree split. AREG's does not follow (PROVENANCE.md:29-33).
  4. Tests that assert the README's claims: test_provenance.py in Surg_Mov_Pred and Crown_Seg (pins, interpreter, plumbing removed, published schema), and test_matches_upstream.py in VFACE, which re-types the upstream code (distances, angles, signs) and compares it with the port on about 91 000 random cases (PROVENANCE.md:23).

Gaps in the record, verified

Eight tools in tools/ have no row in PROVENANCE.md: Agent, AutoCrop3D, AutoMatrix, CLIC, CNE, DOCShapeAXI, FlexReg and GreedyReg (the table has eight rows, for 19 tools; a search for [<name>] finds none of them). The sentence "Every tool is in this table" (PROVENANCE.md:68-70) and CONTRIBUTING.md:651-655 are therefore false for this branch, and no test checks it. Their READMEs carry partial provenance: AutoCrop3D names a commit (b1ae78c), AutoMatrix, CLIC, CNE, GreedyReg and Agent name files without a commit, FlexReg and DOCShapeAXI only say "Ported from" in prose. An older copy of the repository, under its former name sadt-tools (state of 2026-08-20), has a DOCShapeAXI row (ea37083, 2026-08-14) that was never carried over. For ASO, ALI and AREG the upstream commit is "unrecorded" (PROVENANCE.md:35-43), and the table says that "no -- repackaging only" is then "a claim about code that cannot be pointed at". Crown_Seg has no upstream: it is written against shapeaxi 2.0.2 (:21).

The archive/AREG tag was not found

PROVENANCE.md:32-33 and tools/AREG/README.md:21 say AREG's server-side source is kept at the tag archive/AREG of VISOR-serve, parked under server/tools/_AREG/. In the local clone of VISOR-serve, git tag lists nothing and server/tools/ holds only _dispatch_probe, Example_Tool and Test_Tool. The tag may exist on the remote only; this was not queried.

5. The server contract, and what is out of date

docs/SERVER_CONTRACT.md describes what the server expects of a tool: discovery, invocation, the work moved to the server (unzipping with a cap, GPU admission, ownership of output_dir, model resolution), error mapping by exception class name, and chaining. Its header says "re-checked against the server, 2026-08-18" on VISOR-serve 10be711 with uncommitted work (:8-12). Since then several of its statements, and some of README.md and CONTRIBUTING.md, no longer match the code.

A cycle is refused by name, not by depth (CONTRIBUTING.md:227)
The registry "does not walk a grouping folder" (SERVER_CONTRACT.md:58-64)MAX_TOOL_DEPTH = 2 covers tools/ALI/ALI_CBCT (VISOR-serve server/registry/__init__.py:111-114)

What still holds, by the code: an empty string is coerced to "absent" for a Path (testkit/.../_driver.py:36-37), the result is written to a file and never read from stdout (_driver.py:75-79), and run() returns a Path or a dict[str, Path] (_driver.py:43-53).

Defect confirmed by running it: run_tool.py and the grouped engines

scripts/run_tool.py looks for tools/<name> one level deep (run_tool.py:64-92,381). Run for this page, python3 scripts/run_tool.py ALI_CBCT --help answers "There is no tool called 'ALI_CBCT' under tools/. Available: AMASSS, ASO, Agent, ..." and the list contains neither ALI nor AREG. The example in README.md:150-156 (run_tool.py ALI_CBCT --input ...) and the sentence that VFACE -> AREG_CBCT -> ASO -> ALI_CBCT is "four levels with no special case" (:166-169) cannot run through this script. sadt_testkit does handle the grouping folder. Its LocalSupervisor also has no cycle check and no depth cap, unlike the server (run_tool.py:300-364). The script is described as a "developer convenience, not the deployment path" (:15-17).

audit.py skips the grouping folders

scripts/audit.py iterates tools/ one level deep (audit.py:242-245). Run for this page, it prints "not migrated yet (no pyproject.toml): ALI, AREG", which is wrong, and leaves the five engines out of its torch, Python and disk report while listing _template as if it were a tool.

Also unreferenced: nothing in SADT-VISOR calls declareQualityControl (the points where a run pauses for a human check), and the in-repo LocalSupervisor does not have the method; the server does (VISOR-serve server/execution/runner.py:2214). The same is true of vec2: it exists in describe.py:229 and in neither README.md nor CONTRIBUTING.md.

6. The client's tests

The Slicer client (Remote) carries 1484 unittest tests across 12 suites, all green when they were run for this atlas (unittest only, with Qt, CTK and Slicer stubbed): 1047 in ServerToolsCore/Testing/Python (22 files, with qt_stubs.py standing in for Qt, CTK and Slicer; test_transfer.py and test_run_progress.py use real sockets against a hostile test server that drops parts and sends wrong sums), 83 for SlicerCloud (real subprocesses), 140 for VISU, and a suite of their own for most module wrappers (for example ASO 44, AREG 32, AutoMatrix 25, GreedyReg 22, CNE 16). Some modules have none: AMASSS, CLIC, Batch_Dental_Seg, VFACE, SurgMovPred, Crown_Seg, ExampleTool, Medical Data Anonymizer and Agent.

The socket tests check the protocol against a fake server written by the same team, not against VISOR-serve. There is no end-to-end test that starts the server, a tool and the client together.

7. The benchmarks are measurements, not tests

VISOR-serve benchmarks/ reproduces the timing figures of an accompanying paper (campaigns B1 latency, B2 network phases, B3 supervisor cost, B4 concurrency, B5 byte parity between the local and the HTTP path). The recorded runs date from August 2026, on the August code of the tools, from working trees marked "dirty"; there are summaries for B1, B3 and B4 only. They check nothing and no parity claim can be drawn from them: in the last B5 session, the same-path control showed that most tools do not reproduce byte for byte even against themselves (their reports carry durations and paths), and only AREG_IOSCBCT matched fully between the two paths. The figures and their limits are on the deployment page.

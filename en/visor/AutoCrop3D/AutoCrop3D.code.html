AutoCrop3D on VISOR: the code

For developers: what the VISOR port of AutoCrop3D does in the code, with file:line references, signatures, arguments, environment, the differences from the legacy module and the findings. The readable explanation of the same pipeline, with the maths, is on the atlas page.

VISOR Code Atlas (explanation) Legacy page Guide (VISOR)

In VISOR, AutoCrop3D is a Python package that runs on the server: the Slicer side only draws or picks the box, sends the files and loads what comes back. The crop itself is the legacy arithmetic, kept on purpose; what changed is everything around it, how scans are paired with ROIs, what is checked, what is reported. This page follows the port from the request to the files that come back: position, files, each step of the crop and of the surface with the code that does it, the published arguments, the environment, the differences with the legacy module and the findings. It describes the port in SADT-VISOR (branch tool/vface, 6ba2a78, 2026-09-30), served by VISOR-serve (e9a7e5d) and driven from Slicer by the AutomatedDentalToolsRemote extension (19b95e8). The port was made from upstream commit b1ae78c (2026-05-26, SADT-VISOR AutoCrop3D/README.md:15-16), which predates the 3c67957 state described on the legacy page. No claim is made here about a deployed server: everything below is read from the code, and the tool's test suite was run on the package.

1. Position in the chain

Plain-language explanation and maths: atlas page.

AutoCrop3D is a utility at the head of a chain: it reduces a CBCT, or its segmentation, to the region a clinician drew, before another tool works on it. In VISOR it calls nothing and nothing calls it. The ROI is drawn in Slicer, which is why the client keeps that part.

4. The pipeline, step by step

Plain-language explanation and maths: atlas page.

One call of run() crops every scan it finds (SADT-VISOR AutoCrop3D/__init__.py:76-167).

4.1 Finding the scans and the ROIs computed

Plain-language explanation and maths: atlas page.

_discover_scans takes a file, or walks a folder recursively, keeps .nii.gz .nrrd.gz .gipl.gz .nii .nrrd .gipl (pipeline.py:26), skips hidden files, and sets aside files that look like this run's earlier output (pairing.is_previous_output, a whole trailing token, so Cropped_01 is not excluded); those are used only if nothing else is found (__init__.py:289-311). _discover_rois accepts three shapes: one .mrk.json file, a folder holding exactly one (both used for every scan), or a folder of several, matched by patient (__init__.py:314-368). Two ROIs with the same patient key are refused by name rather than one silently winning (:345-367).

4.2 The patient key computed

Plain-language explanation and maths: atlas page.

One function serves both the scans and the ROIs (pipeline.py:60-113). It splits the stem into tokens and drops, as whole tokens and never the first word, the vocabulary of the legacy chained splits plus the ROI words (pipeline.py:51-57, 97-108):

IDENTITY_TOKENS_TO_DROP = frozenset({
    "scan", "scans", "seg", "segmentation", "segmentations", "or", "mand",
    "md", "max", "mx", "cb", "lm", "cl", "merged", "mask", "pred",
    "roi", "rois", "mrk", "crop", "cropped", "box", "bbox",
})

The timepoint is kept, so P01_T1 and P01_T2 can have two boxes, and a patient called MAX_01 stays MAX_01 (pipeline.py:75-81, 100-105). Run on 2026-11-09: Patient_01_Scan and Patient_01_ROI both give Patient_01. A scan whose key has no ROI raises _NoRoi and is listed in without_a_roi (__init__.py:134-141, 206-208).

4.3 Reading the box computed

Plain-language explanation and maths: atlas page.

read_roi takes center and size of the first markup and refuses, by file name, a file that is not JSON, has no markup or has no box (pipeline.py:158-187). Then the frame (pipeline.py:194-201):

system = str(document.get("coordinateSystem", markup.get("coordinateSystem", "LPS"))).upper()
center = [float(value) for value in center]
if system in ("RAS", "0"):
    center = [-center[0], -center[1], center[2]]
elif system not in ("LPS", "1"):
    raise ValueError(...)

The centre ends up in LPS, the frame of ITK's physical points. The size is taken in absolute value (:215). A rotation in orientation is not applied: the box stays axis-aligned, a warning is logged and roi_orientation_ignored is set, but only for a real rotation; a signed axis permutation, which maps the box onto itself, does not count (pipeline.py:203-211, 228-249).

4.4 From the box to indices, and the crop computed

Plain-language explanation and maths: atlas page.

The two physical corners go through TransformPhysicalPointToContinuousIndex and are truncated toward zero, exactly as the legacy .astype(int) did; the corners are swapped per axis if needed, then clamped to the volume (pipeline.py:269-283):

lower_point = [c - s / 2.0 for c, s in zip(roi.center, roi.size)]
upper_point = [c + s / 2.0 for c, s in zip(roi.center, roi.size)]
lower = [int(value) for value in image.TransformPhysicalPointToContinuousIndex(lower_point)]
upper = [int(value) for value in image.TransformPhysicalPointToContinuousIndex(upper_point)]
...
clamped = any(lower[axis] < 0 or upper[axis] > size[axis] for axis in range(3))

The crop is a SimpleITK slice, image[lower[0]:upper[0], lower[1]:upper[1], lower[2]:upper[2]]: no resampling, no interpolation, and origin, spacing and direction carried over, so the cropped volume sits exactly where its voxels were. An empty range is refused with "The ROI does not overlap this volume" (pipeline.py:286-301). With keep_original_size, the crop is copied back into a blank image of the original size and geometry, everything else zero (pipeline.py:304-329; numpy indexes (z, y, x), the bounds are (x, y, z), :320-325).

4.5 Writing and naming computed

Plain-language explanation and maths: atlas page.

The output mirrors the input tree under output_dir (__init__.py:223-226, 277-286), and the name keeps compound extensions: P1_scan.nii.gz with suffix cropped gives P1_scan_cropped.nii.gz; an empty suffix adds nothing (pipeline.py:332-344). The format follows the extension (sitk.WriteImage, __init__.py:226). A .nrrd.gz is refused for that scan only, with the reason (__init__.py:210-214).

4.6 The surface of a cropped label map computed

Plain-language explanation and maths: atlas page.

Built when surfaces is all, or segmentations and the file name holds a whole token among seg, segmentation, mask, pred, label, labels (__init__.py:246, 265-274; pipeline.py:124-134).

  1. Labels. The non-zero values actually present (pipeline.py:400-412). None: no file is written, the report says surface: null (pipeline.py:457-459; __init__.py:257-261).
  2. Margin. surface_padding_mm converted to whole voxels per axis, at least one, then sitk.ConstantPad(image, margin, margin, 0) on both bounds, so a structure touching the box is closed (pipeline.py:415-426, 461-462).
  3. Marching cubes. The padded volume is written to padded.nii.gz in the run's temporary directory and read back with vtkNIFTIImageReader; vtkDiscreteMarchingCubes with one contour per label present (pipeline.py:463-478).
  4. Smoothing. vtkSmoothPolyDataFilter, surface_smoothing_iterations passes, feature angle 120 and relaxation 0.6 as constants (pipeline.py:434-435, 480-485).
  5. Patient space. The NIfTI reader leaves the qform to the caller, so the surface is moved by origin + direction @ diag(spacing / reader_spacing), one 4×4 matrix and no resampling (pipeline.py:502-541). The .vtk then overlays the cropped volume (tests/test_run.py:1242, passed).
  6. Colour and write. Each cell gets the colour of its label: the legacy six-entry table, then a golden-ratio hue for higher labels (pipeline.py:359-384, 544-585). Written with vtkPolyDataWriter at its default settings as <stem>_<suffix>_vtk.vtk next to the volume (pipeline.py:347-351, 491-494); the temporary volume is removed in a finally (:495-497).

AutoCrop3D_report.json at the root of output_dir (__init__.py:96-109, 154-162, 228-261):

{"tool": "AutoCrop3D", "suffix": ..., "keep_original_size": ..., "surfaces": ..., "roi": ...,

                               "roi_coordinate_system", "surface"?, "surface_labels"?}},

It is written before the final check. If nothing was cropped, run() raises a ValueError that says why: either every scan failed (the first five reasons), or no scan matched an ROI, with up to eight scan keys and ROI keys side by side so the mismatch is visible (__init__.py:162-194). A failure on one scan is recorded and the others go on (:142-149).

9. Findings in VISOR

Plain-language explanation and maths: atlas page.

Server paths in the report

When a surface is written, the report names it with an absolute server path: entry["surface"] = str(surface_path) and the same string appended to produced (SADT-VISOR AutoCrop3D/__init__.py:253-255), while the comment just above says the report must stay relative to output_dir because it travels to the client (:231-232). The volume entry is relative (:236). The only test of the rule checks produced[0] (tests/test_run.py:1424-1441), which is the volume. Reproduced on 2026-11-09 by calling run() on a synthetic label map named P1_Seg.nii.gz: produced held P1_Seg_cropped.nii.gz and an absolute …/out/P1_Seg_cropped_vtk.vtk, and surface the same absolute path.

Default surface rule depends on the file name

With the default surfaces = "segmentations", a surface is built only when the file name holds a whole token among seg, segmentation, mask, pred, label, labels (SADT-VISOR AutoCrop3D/pipeline.py:124-134). Checked on 2026-11-09 with the package's own is_segmentation_name: P1_Seg.nii.gz qualifies, Mandible.nii.gz does not and gets no surface unless surfaces = "all". The legacy test was a substring seg anywhere in the output path (AutoCrop3D_CLI.py:143@3c67957).

A cohort is not split

scans and roi are both required path arguments, so the server offers no batch axis (VISOR-serve server/registry/conventions.py:158-190, the comment names AutoCrop3D) and the whole folder goes in one request, under the 500 MB default upload limit (VISOR-serve server/config.py:240). The hosted test scan alone is 98 611 496 bytes (data-manifest.yml:792-794).

Client tests not registered

AutomatedDentalToolsRemote AutoCrop3DRemote/Testing/Python/test_autocrop3d_client.py holds 15 tests, but AutoCrop3DRemote/CMakeLists.txt has no add_test or add_subdirectory and Testing/ has no CMakeLists.txt, so the suite is not attached to ctest. The root CMakeLists.txt:29 does add the module. AutoMatrixRemote and GreedyRegRemote do register theirs (AutoMatrixRemote/CMakeLists.txt:34, GreedyRegRemote/CMakeLists.txt:34, each an add_subdirectory(Testing)).

Stale documentation around the port

AutomatedDentalToolsRemote README.md:508-546 still describes the old module: an icon path under AutoCrop3D/ (the folder is AutoCrop3DRemote), .nrrd.gz accepted (the tool refuses it, pipeline.py:37), "Seg somewhere in the name" (now whole tokens), a ROI made through "Volume Rendering". The package's own README also announces 102 tests (README.md:200) where the suite holds 103. The code is what this page follows.

A rotated ROI is still cropped as an axis-aligned box

The rotation is not applied; the crop uses the box's centre and size along the volume's index axes, as in the legacy CLI, and the report says so with roi_orientation_ignored and a log warning (SADT-VISOR AutoCrop3D/pipeline.py:203-211). The legacy module's second engine for tilted boxes, Slicer's Crop Volume, has no headless equivalent and is not ported (README.md:159-177). The truncation of indices toward zero is also kept on purpose (pipeline.py:257-264, 272-273).

Thirteen legacy defects corrected, each with a test

The port lists its thirteen corrections, each with the name of its test, in SADT-VISOR AutoCrop3D/README.md:107-125; the suite ran green (103 passed, 2026-11-09). The unmatched-patient message of the Slicer panel names up to five patients (AutomatedDentalToolsRemote AutoCrop3DRemote/AutoCrop3DRemote.py:129-136).

AutoCrop3D on VISOR

AutoCrop3D cuts a scan down to a box drawn by the clinician, so that the next tool works on a smaller volume. This page explains how, step by step: how a scan finds its box, how the box becomes a block of voxels, and how a surface is made from a cropped segmentation. Files, lines, arguments and findings are on the code page. The legacy module is on its own page.

VISOR Atlas (explanation) Code (developers) Legacy page Guide (VISOR)

Overview: what goes in, what comes out

The clinician draws a box (a region of interest, ROI) in Slicer. AutoCrop3D keeps only the voxels inside that box, for one scan or for a whole folder. Nothing is predicted: it is geometry, and the voxels that remain are the original ones, not recomputed.

InOut
one scan or a folder of scans (.nii.gz, .nii, .nrrd, .gipl), including segmentationsfor each scan, the same volume reduced to the box, named with a suffix (cropped by default)
one box, or a folder with one box per patient (.mrk.json)for a segmentation, a smoothed surface (.vtk) beside it
a report, AutoCrop3D_report.json: what was cropped, what failed, which scans had no box

1. Position in the chain

AutoCrop3D sits at the head of a chain: it shrinks a CBCT, or its segmentation, before another tool works on it. It calls no other tool and no other tool calls it. The box is drawn in Slicer, which is why the Slicer side stays; the computation runs on the server, on the CPU, with no network and no weights.

2. Files involved

The tool is two Python files (the run and its report; the geometry and the surface), a set of tests, and a short Slicer panel. The list, with line counts, is on the code page.

4. The pipeline, step by step

One call crops every scan it finds. A failure on one scan costs only that scan: the others go on.

4.1 Finding the scans and the boxes computed

Scans are searched in the folder and its subfolders; hidden files are skipped, and files that look like an earlier output of the same run (a name ending in the suffix) are set aside unless nothing else is found. The boxes come in three shapes: one file, a folder with exactly one file (both used for every scan), or a folder with one box per patient. Two boxes for the same patient are refused by name rather than letting one win silently.

In the codeDiscovery of scans and boxes, with the lines

4.2 The patient key computed

The time point is kept, so P01_T1 and P01_T2 can have two different boxes. A scan whose key has no box is listed in the report, not guessed.

In the codeThe vocabulary of dropped words, the function

4.3 Reading the box computed

A box is a centre and a size. The file says in which frame the centre is written: ITK, which will convert it, works in LPS, so a centre saved in RAS has its first two coordinates flipped. An unknown frame is an error, not a guess.

cLPS=(−cx,−cy,cz)

The formula applies when the file says RAS. The size is taken as a positive number. A rotation stored in the file is not applied: the box stays aligned with the volume’s axes, and the report says when a real rotation was ignored.

In the codeReading the box, the frame test, the rotation check

4.4 From the box to voxels, and the crop computed

The crop is a plain slice of the volume: no resampling and no interpolation, and the scan’s origin, spacing and direction are carried over, so the cropped volume sits exactly where its voxels were. Since no voxel moves in millimetres, a registration computed on the full scan should still apply to the cropped one (deduced from the geometry being kept, not tested).

In the codeBounds, clamping, the slice, the putting back, with the lines

4.5 Writing and naming computed

The output folder mirrors the input folders. The name keeps compound extensions: P1_scan.nii.gz with suffix cropped gives P1_scan_cropped.nii.gz. The format follows the extension. A gzipped NRRD (.nrrd.gz) is refused for that scan only, with the reason, because the reader does not exist.

In the codeNaming and writing, the refusal of gzipped NRRD

4.6 The surface of a cropped label map computed

A surface is built when the option says all, or segmentations (the default) and the file name holds a whole word among seg, segmentation, mask, pred, label, labels. Six steps turn a block of labels into a mesh: the labels present, a margin, marching cubes (one outline per label), smoothing, a move into the patient’s space, and a colour per label with the file.

Smoothing then moves each vertex toward the average of its neighbours; five passes by default, with a fixed feature angle (120, VTK’s threshold for a sharp edge) and relaxation factor (0.6, how far each vertex moves toward that average at each pass). The mesh is built in the grid’s own units, so it is moved into the patient’s space by one matrix: without it, the surface would not overlay the cropped volume.

p=o+D(s⊙i)
  • pa point of the mesh, in patient space
  • oorigin of the scan
  • Ddirection matrix of the scan
  • svoxel size
  • ithe position in the grid; ⊙ multiplies component by component

Each cell then gets the colour of its label (six fixed colours, then a generated one).

In the codeThe six steps of the surface, with the VTK calls

4.7 The report computed

The report lists each cropped scan with its patient, its box and the indices used, flags whether the box was clamped to the volume or had a rotation ignored, then the failures and the scans without a box, with counts and the duration. It is written even when nothing was cropped; in that case the run stops with an error that says why, with the scan names and the box names side by side so the mismatch is visible.

In the codeThe report, field by field

5. What you can choose

  • Scans and box: a file or a folder for each (both required).
  • Keep original size: off by default. On, the crop is put back in a volume of the original size, zero outside the box.
  • Surfaces: only for segmentations (default), for every file, or none.
  • Surface margin: 5 mm of background by default before the surface is built.
  • Smoothing passes: 5 by default.
  • Suffix: cropped by default, may be empty.

9. Known issues in VISOR

Each point is checked in the code and described, with its evidence, on the code page; the list also appears in the findings.

  • Server paths in the report. When a surface is written, the report names it with an absolute server path instead of a relative one. Evidence.
  • The default surface rule depends on the file name. Mandible.nii.gz gets no surface unless the option is set to all. Evidence.
  • A cohort is not split. A whole folder goes up in one request, under the upload limit. Evidence.
  • The client tests are not registered with the build, so they do not run. Evidence.
  • Documentation around the port is out of date. Evidence.
  • A rotated box is still cropped as an aligned box, and the report says so. Evidence.

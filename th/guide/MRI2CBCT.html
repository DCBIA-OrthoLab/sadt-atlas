MRI2CBCT: จัดแนวภาพ MRI และ CBCT ของ TMJ

MRI2CBCT ลงทะเบียนภาพ MRI ลงบน CBCT ของข้อต่อขากรรไกร (TMJ) เพื่อให้คุณดูการตรวจทั้งสองอย่างในกรอบเดียวกันได้ ตอนนี้เหลือปุ่มเดียว: เลือกโฟลเดอร์ กด Run แล้วโมดูลจะเตรียมข้อมูล จัดแนว แบ่งส่วน และลงทะเบียนภาพให้ผู้ป่วยทุกคน

ใช้เมื่อใด

ใช้เมื่อคุณมี MRI และ CBCT ของ TMJ ของผู้ป่วยคนเดียวกัน และต้องการซ้อนทับกัน: กระดูกเห็นชัดกว่าบน CBCT ส่วนเนื้อเยื่ออ่อน (หมอนรองข้อต่อ แคปซูล) เห็นชัดกว่าบน MRI และการลงทะเบียนภาพทั้งสองทำให้คุณดูทั้งคู่ได้พร้อมกัน แทนที่จะเทียบจากความจำ คุณไม่ต้องไล่ไปทีละแท็บอีกต่อไป: การกด Run ครั้งเดียวทำทั้งห่วงโซ่ให้ผู้ป่วยทุกคนที่พบในทั้งสองโฟลเดอร์

สิ่งที่ลงทะเบียนภาพ

โมดูลไม่ได้จับคู่ความสว่างของภาพทั้งสอง แต่ให้เครือข่ายหนึ่งหาฐานกะโหลกบน CBCT และอีกเครือข่ายหนึ่งหาบน MRI แล้วจึงนำสองพื้นผิวมาประกบกัน ดังนั้นผลลัพธ์จะดีเท่ากับเส้นขอบสองเส้นนั้นเท่านั้น จึงเป็นเหตุผลที่มันหยุดรอให้คุณตรวจได้

สิ่งที่ต้องใช้ สิ่งที่จะได้

สิ่งที่ต้องเตรียม

  • โฟลเดอร์ MRI และโฟลเดอร์ CBCT (.nii.gz, .nii หรือ .nrrd)
  • ไฟล์ที่ชื่อขึ้นต้นด้วยรหัสผู้ป่วย (P01, B038…): นี่คือวิธีจับคู่สองโฟลเดอร์ CBCT หนึ่งชุดต่อผู้ป่วย MRI หนึ่งหรือสองชุด
  • โฟลเดอร์เอาต์พุต
  • การตั้งค่าครั้งเดียว: แพ็กเกจ Python และโมเดล ราว 5 GB ดาวน์โหลดให้เอง

สิ่งที่ได้ออกมา

  • ต่อผู้ป่วยหนึ่งคน จะได้โฟลเดอร์ที่มี MRI ของข้อต่อแต่ละข้างที่ลงทะเบียนภาพลงบน CBCT ต้นฉบับ มาสก์ฐานกะโหลก และไฟล์ transform
  • ไฟล์ summary.csv ที่มีผลตัดสินของข้อต่อทุกข้าง: OK, SMALL, FLAG หรือ FLIP
  • วอลุ่มสองชุดที่ซ้อนทับกันได้ในฉากเดียวกัน ไม่ใช่ไฟล์ที่ผสานแล้ว CBCT ไม่ถูกแก้ไขเลย

เกิดอะไรขึ้นเมื่อกด Run

  1. การเตรียม MRI จับคู่ผู้ป่วย และโดยค่าเริ่มต้นจะ resample MRI แต่ละชุดเป็น 0.3 mm และแยกวอลุ่มที่มีข้อต่อทั้งสองข้างออกเป็นครึ่งซ้ายและครึ่งขวา วอลุ่มที่มีช่องว่างระหว่างสองชุดภาพจะถูกสร้างใหม่โดยใช้ "ระยะห่างของสไลซ์ที่ถ่าย" ที่คุณกำหนด (ค่าเริ่มต้น 3.0 mm) ด้านของ MRI ข้อต่อเดียวอ่านจากตำแหน่งของมันในไฟล์
  2. การจัดแนว CBCT สามขั้นตอนอัตโนมัติ (ขั้นตอนของโมดูล ASO) ทำให้ศีรษะอยู่ในแนว Frankfurt และแนว midsagittal มาตรฐาน
  3. ฐานกะโหลกบน CBCT เครือข่าย AMASSS ระบุขอบเขตของมัน
  4. ฐานกะโหลกบน MRI เครือข่ายที่สอง Dataset516 ระบุขอบเขตของมันบนข้อต่อแต่ละข้าง ค่าเริ่มต้นใช้โมเดลห้า fold; หนึ่ง fold เร็วกว่าบนคอมพิวเตอร์ที่ไม่มี GPU
  5. การลงทะเบียนภาพ ประกบขอบเขตของ MRI ลงบนขอบเขตของ CBCT ถ้าคำตอบแรกเป็น flip (หันผิดทาง) โมดูลจะลองเพิ่มอีกหลายครั้ง ได้แก่ หมุนครึ่งรอบ อีกด้านของศีรษะ และสุดท้ายคือ MRI ที่กลับด้านกระจก ก่อนจะยอมแพ้และทำเครื่องหมายผลลัพธ์ว่า _FLAGGED

ตัวเลือกและการตรวจสอบ

  • Use test files ดาวน์โหลดผู้ป่วยตัวอย่าง (CBCT หนึ่งชุด MRI สองชุด) เติมสามโฟลเดอร์ และเก็บผลลัพธ์ที่คาดหวังไว้ในโฟลเดอร์ reference เพื่อให้คุณเปรียบเทียบได้
  • Resample และ Separate left and right เปิดอยู่โดยค่าเริ่มต้น ให้ปิดการแยกถ้า MRI แต่ละชุดของคุณเป็นข้อต่อเดียวหรือทั้งศีรษะอยู่แล้ว
  • ขั้นสูง: วาง MRI ที่ลงทะเบียนภาพแล้วลงบนกริดวอกเซลของ CBCT (ปิดไว้โดยค่าเริ่มต้น: MRI คงวอกเซลของตัวเองและเปลี่ยนเฉพาะตำแหน่ง) เก็บไฟล์ระหว่างทาง กำหนดจำนวน worker ของการลงทะเบียนภาพ
  • การตรวจทาน: ติ๊ก "Pause during the run" และเลือกว่าจะหยุดตรงไหน ทุกครั้งที่หยุด ภาพจะเปิดใน Slicer พร้อมเส้นขอบซ้อนอยู่ ที่การหยุดครั้งแรก คุณสลับซ้ายกับขวาของผู้ป่วยได้ถ้าด้านผิด

หากเกิดปัญหา

เริ่มใหม่หลังการตั้งค่าครั้งแรก

ถ้าต้องติดตั้งหรือเปลี่ยน PyTorch ให้เข้ากับการ์ดจอของคุณ แผงจะขอให้เริ่ม Slicer ใหม่แล้วกด Run อีกครั้ง บน Linux ไลบรารีการลงทะเบียนภาพต้องใช้ระบบที่มี glibc 2.31 ขึ้นไป

ผู้ป่วยถูกข้าม

ไฟล์ที่ไม่มีรหัสผู้ป่วยที่ต้นชื่อ MRI ที่ไม่มี CBCT (หรือกลับกัน) หรือผู้ป่วยที่มี CBCT มากกว่าหนึ่งชุด จะถูกตัดออก และแผงจะแสดงรายการก่อนเริ่ม ให้เก็บโฟลเดอร์เอาต์พุตของคุณไว้นอกโฟลเดอร์ MRI และ CBCT: โฟลเดอร์ถูกอ่านแบบเรียกซ้ำ ผลของการรันก่อนหน้าจึงอาจถูกหยิบไปเป็นภาพสแกนใหม่

อ่านผลตัดสิน อย่าดูแค่ชื่อไฟล์

ข้อต่อหนึ่งข้างอาจได้ FLAG (ซ้อนทับกันอ่อน) แต่ยังถูกบันทึกด้วยชื่อไฟล์ปกติ มีเพียง summary.csv และข้อความตอนท้ายที่บอกเรื่องนี้ SMALL หมายความว่าขอบเขตของ MRI เล็กมาก ซึ่งเป็นกรณีที่ล้มเหลวบ่อยที่สุด สิ่งที่ติดแท็ก _FLAGGED, FLIP หรือ _MIRRORED ควรตรวจดูก่อนนำไปใช้

ด้านผิด

ด้านของ MRI ข้อต่อเดียวมาจากตำแหน่งของมันในไฟล์ ถ้าผิด ให้สลับที่การหยุดครั้งแรก ถ้าไม่ได้หยุด โมดูลยังกู้คืนได้ด้วยการลองอีกด้าน แต่เฉพาะเมื่อคำตอบแรกเป็น flip

log หายไป

log ของการรันอยู่กับไฟล์ระหว่างทาง ซึ่งถูกลบหลังการรันที่สำเร็จ เว้นแต่คุณติ๊ก "Keep the intermediate files"

ขั้นต่อไป

CBCT ต้นฉบับไม่ถูกแก้ไขเลย เปิด MRI ที่ลงทะเบียนภาพแล้วกับ CBCT พร้อมกันใน Slicer เพื่อตรวจการซ้อนทับก่อนนำไปใช้วัดอะไรก็ตาม ถ้าคุณต้องการ transform ไปใช้อย่างอื่น ให้โหลด MRI ต้นฉบับ แล้วใช้ไฟล์ .tfm กับมัน: ด้วยวิธีนี้จะไม่มีการ interpolate เกิดขึ้น การลงทะเบียนภาพที่ผลตัดสินระบุว่ามีปัญหา ควรรันใหม่พร้อมการหยุดตรวจทานบนเส้นขอบทั้งสองมากกว่าปรับด้วยมือ

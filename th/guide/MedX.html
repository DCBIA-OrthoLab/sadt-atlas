MedX: สรุปรายงาน แล้วสร้างแดชบอร์ด

แม้ชื่อจะเป็นเช่นนั้น MedX ไม่เคยมองภาพ: มันอ่านรายงานทางคลินิกที่เขียนไว้ (.pdf, .docx, .txt) ให้โมเดลภาษาในเครื่องแปลงแต่ละฉบับเป็นสรุปที่มีโครงสร้าง และจากนั้นรวมสรุปทั้งกลุ่มประชากรเป็นหน้าภาพเดียวได้ สองขั้นตอนที่แยกจากกัน ควรรู้ก่อนเริ่ม

หน้าโมดูล Legacy

หน้านี้อธิบายโมดูลตามที่เป็นก่อนถูกถอดออกจากส่วนขยาย legacy เมื่อ 2026-09-17 ไม่มีอยู่ในเวอร์ชันปัจจุบันแล้ว มันไม่เคยมีให้ใช้ผ่านเซิร์ฟเวอร์ VISOR: ดู MedX กับ VISOR และ การใช้ VISOR

ใช้เมื่อใด

เมื่อคุณมีรายงานข้อความอิสระเป็นกอง การตรวจทางคลินิก การตรวจทางรังสี บันทึกการปรึกษา และอยากได้ตัวชี้วัดทางคลินิก (อายุ ความปวด การนอน การอ้าปาก และอื่น ๆ) ออกมาโดยไม่ต้องอ่านทีละฉบับด้วยมือ เมื่อมีสรุปเหล่านั้นแล้ว ครึ่งหลังของ MedX ให้คุณเห็นทั้งกลุ่มประชากรได้ในแวบเดียว: การแยกตามอายุ ความผิดปกติที่เกี่ยวข้อง คะแนนเฉลี่ย

สองเส้นทางอิสระ

MedX มีสองแท็บ สองปุ่ม และไม่มีอะไรเชื่อมต่อกันโดยอัตโนมัติ Summarize อ่านเอกสารของคุณและเขียนไฟล์สรุปหนึ่งไฟล์ต่อผู้ป่วยหนึ่งคน Dashboard อ่านสรุปเหล่านั้นกลับมาและสร้างหน้าภาพ เมื่อการสรุปเสร็จ คุณต้องสลับแท็บและเริ่มแดชบอร์ดเอง: มันไม่เริ่มเอง

สิ่งที่ต้องใช้ สิ่งที่จะได้

เส้นทาง Summarize

สิ่งที่ต้องเตรียม

  • โฟลเดอร์แบนของรายงานเป็น .pdf, .docx หรือ .txt (ไม่มีโฟลเดอร์ย่อย)
  • ชื่อไฟล์ที่ทุกอย่างก่อน "_" แรกคือรหัสผู้ป่วย: หลายไฟล์ที่ใช้รหัสเดียวกันจะถูกจัดกลุ่มและสรุปร่วมกัน
  • โมเดลสรุป ดาวน์โหลดครั้งเดียว

สิ่งที่ได้ออกมา

  • ไฟล์ <patient-id>_summary.txt หนึ่งไฟล์ต่อผู้ป่วยหนึ่งคน เป็นข้อความอิสระ
  • เอกสารต้นทางของคุณไม่ถูกแตะต้อง

เส้นทาง Dashboard

สิ่งที่ต้องเตรียม

  • โฟลเดอร์สรุปที่สร้างโดยเส้นทาง Summarize (ไฟล์ต้องลงท้ายด้วย _summary.txt)

สิ่งที่ได้ออกมา

  • ภาพ dashboard.png: อายุ การนอน ความปวดข้อต่อและกล้ามเนื้อ การอ้าปาก ของทั้งกลุ่มประชากร
  • ตาราง patient_data.csv ที่มีหนึ่งแถวต่อผู้ป่วยหนึ่งคน

ขั้นตอน

สรุปรายงาน

  1. ดาวน์โหลดโมเดล ต้องทำเพียงครั้งเดียว ถ้าไม่มี เส้นทาง Summarize จะไม่มีอะไรให้ทำงาน
  2. ชี้ไปที่โฟลเดอร์รายงาน ตั้งชื่อด้วยรหัสผู้ป่วยก่อน "_" แรก
  3. ตั้งโฟลเดอร์ผลลัพธ์ แล้วเริ่มรัน แถบความคืบหน้าตามผู้ป่วยที่ถูกประมวลผล
  4. อ่านสรุปที่ได้ให้ทั่วก่อนพึ่งพา: ดูด้านล่าง

สร้างแดชบอร์ด

  1. สลับไปที่แท็บ Dashboard สิ่งนี้ไม่เกิดเองหลังการสรุป
  2. ตั้งโฟลเดอร์สรุปจากขั้นก่อนหน้าเป็นอินพุต
  3. ตั้งโฟลเดอร์ผลลัพธ์ แล้วเริ่มรัน ในการรันครั้งแรก Slicer อาจขอติดตั้งแพ็กเกจ Python สองสามตัว (pandas, matplotlib): ให้ยอมรับ
  4. ติ๊ก "Load in 3D Slicer" ถ้าต้องการให้ภาพแดชบอร์ดเปิดตรงในมุมมองของฉาก

การอ่านผลลัพธ์

สรุปของแต่ละรายงานมาจากโมเดลเชิงสร้าง: มันเขียนข้อความอิสระ ไม่ใช่รูปแบบที่รับประกัน รูปแบบ key: value ที่แดชบอร์ดคาดหวังเป็นนิสัยที่โมเดลเรียนรู้ ไม่ใช่กฎที่บังคับ: บรรทัดที่เสียรูปจะถูกทิ้งไปเฉย ๆ และหายไปจากแดชบอร์ดอย่างเงียบ ๆ โมเดลยังสุ่มบางส่วนของผลลัพธ์ด้วย: การรันสรุปอีกครั้งบนเอกสารเดียวกันไม่ได้ให้ข้อความเดิมเป๊ะสองครั้ง ด้วยทั้งสองเหตุผล สรุปที่ MedX สร้างจึงเป็นจุดเริ่มต้นที่ต้องอ่านผ่าน ไม่ใช่รายงานที่ผ่านการตรวจสอบ: อย่าใช้ตามที่เป็นเพื่อตัดสินใจทางคลินิก

หากมีสิ่งผิดปกติ

ปุ่มดาวน์โหลดโมเดลไม่ทำอะไร

การคลิกปุ่มดาวน์โหลดสร้างโฟลเดอร์ที่คาดหวังแต่ไม่ใส่ไฟล์ลงไปเลย: ช่องยังว่างและมีข้อความเตือนปรากฏ ให้ดึงไฟล์เก็บถาวรของโมเดลเองจากหน้า GitHub releases ของรีโพซิทอรี SlicerAutomatedDentalTools (ไฟล์ BART.zip ใต้รีลีส "MedX") แตกไฟล์ แล้วชี้โมดูลไปที่โฟลเดอร์นั้น

แถบความคืบหน้าของแดชบอร์ดไม่เคยขยับ

ต่างจากเส้นทาง Summarize แถบความคืบหน้าของ Dashboard นิ่งตลอดการรัน นั่นไม่ใช่สัญญาณว่ามันค้าง: ปล่อยให้รันและรอให้ dashboard.png ปรากฏในโฟลเดอร์ผลลัพธ์

โฟลเดอร์อินพุตว่างทำให้โมดูลพัง

การรันเส้นทางใดก็ตามบนโฟลเดอร์ที่ไม่มีเอกสารใช้ได้จะเกิดข้อผิดพลาดแทนที่จะเป็นข้อความที่สะอาด ตรวจว่าโฟลเดอร์ที่คุณเลือกมีไฟล์อยู่จริงก่อนเริ่ม

สองการรัน สองสรุปที่ต่างกัน

โมเดลไม่ deterministic: การรันเส้นทาง Summarize อีกครั้งบนเอกสารเดียวกันเป๊ะจะไม่ทำซ้ำสรุปก่อนหน้าคำต่อคำ ถ้าคุณต้องการเปรียบเทียบผลลัพธ์ข้ามเวลา ให้เก็บไฟล์ _summary.txt ที่มีอยู่แล้วไว้ แทนที่จะสร้างใหม่

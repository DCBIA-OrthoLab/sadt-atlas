MedX: สรุปรายงาน แล้วสร้าง dashboard

แม้ชื่อจะเป็นเช่นนั้น MedX ไม่เคยดูภาพ: มันอ่านรายงานทางคลินิกที่เขียนไว้ (.pdf, .docx, .txt) ให้โมเดลภาษาในเครื่องเปลี่ยนแต่ละฉบับเป็นสรุปมีโครงสร้าง แล้วรวมสรุปทั้งกลุ่มตัวอย่างเป็นหน้ารูปหนึ่งหน้าได้ สองขั้นตอนที่แยกกัน ควรรู้ก่อนเริ่ม

เมื่อไรควรใช้

เมื่อคุณมีรายงานข้อความอิสระกองหนึ่ง การตรวจทางคลินิก การตรวจทางรังสี บันทึกการปรึกษา และต้องการตัวบ่งชี้ทางคลินิกออกมา (อายุ อาการปวด การนอน การอ้าปาก และอื่น ๆ) โดยไม่ต้องอ่านทีละฉบับด้วยมือ เมื่อได้สรุปเหล่านั้นแล้ว ครึ่งหลังของ MedX ให้คุณเห็นทั้งกลุ่มตัวอย่างได้ในพริบตา: การแบ่งตามอายุ ความผิดปกติที่เกี่ยวข้อง คะแนนเฉลี่ย

สองเส้นทางอิสระ

MedX มีสองแท็บ สองปุ่ม และไม่มีสิ่งใดต่อพวกมันเข้าด้วยกันโดยอัตโนมัติ Summarize อ่านเอกสารของคุณและเขียนไฟล์สรุปหนึ่งไฟล์ต่อผู้ป่วย Dashboard อ่านสรุปเหล่านั้นกลับและสร้างหน้ารูป เมื่อการสรุปเสร็จ คุณต้องสลับแท็บและเริ่ม dashboard เอง: มันไม่เริ่มเอง

สิ่งที่ต้องใช้ และสิ่งที่ได้

เส้นทาง Summarize

สิ่งที่ต้องเตรียม

  • โฟลเดอร์แบนของรายงานเป็น .pdf, .docx หรือ .txt (ไม่มีโฟลเดอร์ย่อย)
  • ชื่อไฟล์ที่ทุกอย่างก่อน "_" ตัวแรกคือรหัสผู้ป่วย: หลายไฟล์ที่ใช้รหัสเดียวกันจะถูกจัดกลุ่มและสรุปรวมกัน
  • โมเดลสรุป ดาวน์โหลดครั้งเดียว

สิ่งที่ได้ออกมา

  • ไฟล์ <patient-id>_summary.txt หนึ่งไฟล์ต่อผู้ป่วย เป็นข้อความอิสระ
  • เอกสารต้นฉบับของคุณไม่ถูกแตะต้อง

เส้นทาง Dashboard

สิ่งที่ต้องเตรียม

  • โฟลเดอร์สรุปที่เส้นทาง Summarize สร้าง (ไฟล์ต้องลงท้ายด้วย _summary.txt)

สิ่งที่ได้ออกมา

  • รูป dashboard.png: อายุ การนอน อาการปวดข้อต่อและกล้ามเนื้อ การอ้าปาก ทั่วทั้งกลุ่มตัวอย่าง
  • ตาราง patient_data.csv หนึ่งแถวต่อผู้ป่วย

ขั้นตอน

สรุปรายงาน

  1. ดาวน์โหลดโมเดล ต้องทำเพียงครั้งเดียว; ถ้าไม่มี เส้นทาง Summarize ไม่มีอะไรให้ทำงานด้วย
  2. ชี้ไปที่โฟลเดอร์รายงาน ตั้งชื่อด้วยรหัสผู้ป่วยก่อน "_" ตัวแรก
  3. กำหนดโฟลเดอร์เอาต์พุต แล้วเริ่ม แถบความคืบหน้าติดตามผู้ป่วยขณะถูกประมวลผล
  4. อ่านสรุปที่ได้ก่อนนำไปใช้: ดูด้านล่าง

สร้าง dashboard

  1. สลับไปที่แท็บ Dashboard สิ่งนี้ไม่เกิดเองหลังการสรุป
  2. กำหนดโฟลเดอร์สรุปจากขั้นก่อนเป็นอินพุต
  3. กำหนดโฟลเดอร์เอาต์พุต แล้วเริ่ม ในการรันครั้งแรก Slicer อาจขอติดตั้งแพ็กเกจ Python สองสามตัว (pandas, matplotlib): ให้ยอมรับ
  4. ติ๊ก "Load in 3D Slicer" ถ้าต้องการให้รูป dashboard เปิดตรง ๆ ในมุมมองของฉาก

การอ่านผลลัพธ์

สรุปของแต่ละรายงานมาจากโมเดลเชิงสร้าง: มันเขียนข้อความอิสระ ไม่ใช่แบบฟอร์มที่รับประกัน รูปแบบ key: value ที่ dashboard คาดหวังเป็นนิสัยที่โมเดลเรียนรู้ ไม่ใช่กฎที่บังคับ: บรรทัดที่รูปแบบผิดจะถูกทิ้ง และหายไปจาก dashboard อย่างเงียบ ๆ โมเดลยังสุ่มบางส่วนของเอาต์พุต: การรันสรุปซ้ำบนเอกสารเดียวกันไม่ได้ข้อความเดิมสองครั้ง ด้วยทั้งสองเหตุผล สรุปที่ MedX สร้างเป็นจุดเริ่มต้นให้อ่านทบทวน ไม่ใช่รายงานที่ผ่านการตรวจสอบ: อย่าใช้ตามที่เป็นเพื่อการตัดสินใจทางคลินิก

ถ้ามีอะไรผิดปกติ

ปุ่มดาวน์โหลดโมเดลไม่ทำอะไร

การคลิกปุ่มดาวน์โหลดสร้างโฟลเดอร์ที่คาดไว้ แต่ไม่เคยใส่ไฟล์ลงไป: ช่องยังว่างและมีข้อความเตือนปรากฏ ให้ดึงไฟล์เก็บโมเดลเองจากหน้า GitHub releases ของที่เก็บโค้ด SlicerAutomatedDentalTools (ไฟล์ BART.zip ใต้ release "MedX") แตกไฟล์ แล้วชี้โมดูลไปที่โฟลเดอร์นั้น

แถบความคืบหน้าของ dashboard ไม่เคยขยับ

ต่างจากเส้นทาง Summarize แถบความคืบหน้าของ Dashboard นิ่งตลอดการรัน นั่นไม่ได้แปลว่ามันค้าง: ปล่อยให้รันและรอให้ dashboard.png ปรากฏในโฟลเดอร์เอาต์พุต

โฟลเดอร์อินพุตว่างทำให้โมดูลล่ม

การรันเส้นทางใดก็ตามบนโฟลเดอร์ที่ไม่มีเอกสารที่ใช้ได้จะยกข้อผิดพลาดแทนข้อความที่สะอาด ตรวจว่าโฟลเดอร์ที่คุณเลือกมีไฟล์อยู่จริงก่อนเริ่ม

รันสองครั้ง ได้สองสรุปต่างกัน

โมเดลไม่กำหนดแน่นอน: การรันเส้นทาง Summarize ซ้ำบนเอกสารเดิมทุกประการจะไม่ได้สรุปเดิมคำต่อคำ ถ้าต้องการเปรียบเทียบผลตามเวลา ให้เก็บไฟล์ _summary.txt ที่มีอยู่แล้วแทนการสร้างใหม่

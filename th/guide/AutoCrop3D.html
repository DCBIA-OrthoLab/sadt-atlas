AutoCrop3D — ครอปวอลุ่มทั้งชุด

AutoCrop3D ครอปวอลุ่มทั้งโฟลเดอร์แบบกลุ่มตามบริเวณที่สนใจ (ROI) ร่วมกัน หรือตามบริเวณแยกของผู้ป่วยแต่ละราย ไม่มีโครงข่ายประสาทเทียม ไม่มีโมเดลให้ดาวน์โหลด: เป็นการครอปเชิงเรขาคณิตที่เสร็จเกือบทันที และไม่แตะต้องค่าวอกเซลของคุณเลย

ใช้เมื่อใด

เมื่อชุดข้อมูลใหญ่เกินไป หรือขอบเขตภาพ (field of view) ไม่สม่ำเสมอเกินกว่าจะประมวลผล ตามสภาพเดิม: ใช้ก่อนเครื่องมือแบ่งส่วน (AMASSS, BatchDentalSeg) เพื่อลดสิ่งที่ต้อง ประมวลผล หรือใช้หลังเพื่อเก็บเฉพาะบริเวณที่มีประโยชน์ AutoCrop3D ยังสามารถ สร้างเมช VTK จากการแบ่งส่วน (segmentation) ที่คุณสร้างไว้แล้ว เพื่อดูตัวอย่างอย่างรวดเร็วได้ด้วย

การเตรียมบริเวณที่สนใจ

บริเวณที่จะครอปมาจากไฟล์ ROI ของ Slicer ไฟล์เดียว (.mrk.json) และ ไม่มีแหล่งอื่น: วางกล่อง Markups > ROI ในฉากบนผู้ป่วยที่เป็น ตัวแทน ปรับขนาด แล้วบันทึก ใช้ได้สองแบบ: ROI เดียวใช้กับทุกวอลุ่ม ในโฟลเดอร์ หรือ ROI หนึ่งไฟล์ต่อผู้ป่วยหนึ่งราย — ในกรณีหลัง ให้ตั้งชื่อไฟล์ ROI แต่ละไฟล์ด้วย คำนำหน้าเดียวกับวอลุ่มที่ตรงกัน เพื่อให้การจับคู่ทำงาน (ดูด้านล่าง)

ROI ต้องเป็นกล่องที่ขนานกับแกน และบันทึกตามสภาพเดิม

เส้นทางการครอปแบบเร็วละเลยการวางแนวและระบบพิกัด ที่ระบุในไฟล์ ROI โดยสิ้นเชิง: อ่านเพียงจุดศูนย์กลางและขนาด และถือว่ากล่อง ขนานกับแกนของวอลุ่ม ROI ที่หมุนจะถูกจัดการเหมือนไม่ได้หมุน และ ROI ที่บันทึกในระบบพิกัดผิดจะทำให้จุดศูนย์กลางเลื่อนไปโดยไม่มีข้อความแจ้งข้อผิดพลาด เลย เส้นทางแบบเร็วใช้ได้เฉพาะกับกล่องตรง ที่บันทึกตามแบบที่ Slicer เก็บ โดยค่าเริ่มต้น สำหรับ ROI ที่หมุนจริง ดูด้านล่าง

สิ่งที่ต้องใช้ สิ่งที่จะได้

สิ่งที่ต้องเตรียม

  • โฟลเดอร์ของวอลุ่ม — .nii.gz, .nii, .nrrd.gz, .nrrd, .gipl.gz หรือ .gipl
  • ไฟล์ ROI (.mrk.json) หรือโฟลเดอร์ที่มี ROI หนึ่งไฟล์ต่อผู้ป่วยหนึ่งราย
  • ส่วนต่อท้ายของเอาต์พุต ("cropped" เป็นค่าเริ่มต้น)

สิ่งที่จะได้

  • วอลุ่มที่ครอปแล้วหนึ่งไฟล์ต่ออินพุตหนึ่งไฟล์ โดยคงโครงสร้างโฟลเดอร์อินพุตไว้
  • ไม่บังคับ: เมช VTK หนึ่งไฟล์ต่อการแบ่งส่วนที่ครอปแล้ว
  • ไม่มีไฟล์การแปลง — เรขาคณิตอยู่ในตัววอลุ่มเองทั้งหมด

ขั้นตอน

  1. วางและบันทึก ROI กล่องเดียวสำหรับทั้งชุด หรือหนึ่งกล่อง ต่อผู้ป่วย โดยตั้งชื่อให้ตรงกับวอลุ่ม
  2. ระบุโฟลเดอร์วอลุ่มอินพุต AutoCrop3D ประมวลผล ทั้งโฟลเดอร์ในครั้งเดียว
  3. ระบุไฟล์หรือโฟลเดอร์ ROI ไฟล์เดียวจะใช้กับ ทุกราย หลายไฟล์จะจับคู่ตามผู้ป่วย
  4. เลือกส่วนต่อท้ายของเอาต์พุต และหากต้องการ เลือก "Keep the same size as input" เพื่อคงเรขาคณิตต้นฉบับทั้งหมด โดยทุกส่วนนอก ROI มีค่าเป็นศูนย์
  5. เฉพาะ ROI ที่หมุน: เลือก "Use module Crop Volume for tilted images" — อ่านคำเตือนด้านล่างก่อนเลือก
  6. ระบุโฟลเดอร์เอาต์พุต แล้วเริ่มรัน

สิ่งที่คงไว้

นี่คือจุดประสงค์หลักของเครื่องมือ: เส้นทางการครอปโดยค่าเริ่มต้นไม่เคยรีแซมเปิล มัน เพียงดึงบล็อกของวอกเซลออกมาและคำนวณจุดกำเนิดของวอลุ่มใหม่ spacing การวางแนว และค่าวอกเซลยังคงเหมือนต้นฉบับทุกบิต ในทางปฏิบัติ เมทริกซ์การลงทะเบียนภาพ (registration) ที่คำนวณบนวอลุ่มเต็มยังคงใช้ได้โดยไม่ต้องเปลี่ยนบน วอลุ่มที่ครอปแล้ว เพราะพิกัดกายภาพไม่เคยเลื่อน — คุณจึงครอปหลัง การลงทะเบียนภาพได้โดยไม่ต้องคำนวณสิ่งใดใหม่

หากเกิดปัญหา

โฟลเดอร์ที่มีไฟล์ ROI เพียงไฟล์เดียว → เกิดข้อผิดพลาด

หากคุณใช้ ROI แยกตามผู้ป่วย แต่โฟลเดอร์มีไฟล์ .mrk.json เพียงไฟล์เดียว โมดูลจะเกิดข้อผิดพลาดแทนที่จะใช้ไฟล์นั้นกับทุก วอลุ่ม ในกรณีนี้ ให้ชี้ไปที่ไฟล์นั้นโดยตรงในฐานะ ROI เดียวที่ใช้ร่วมกัน แทนที่จะ ชี้ไปที่โฟลเดอร์ที่มีไฟล์นั้น

ROI แยกตามผู้ป่วย: การจับคู่เสียเมื่อมีขีดล่าง

ชื่อวอลุ่มและชื่อ ROI ถูกแยกส่วนต่างกันเมื่อนำมาเปรียบเทียบ ID ผู้ป่วยที่ไม่มีขีดล่าง (MA0001_Scan.nii.gz / MA0001_ROI.mrk.json) จับคู่ได้ปกติ ขีดล่างภายใน ID เอง ทำให้การจับคู่เสียและผู้ป่วยรายนั้นถูกข้าม โดยไม่หยุดการทำงานส่วนที่เหลือของ กลุ่ม (มีคำเตือนเขียนไว้ใน log)

ส่วนติดต่อปฏิเสธรูปแบบไฟล์ที่การครอปเองรับได้

การตรวจสอบอินพุตของส่วนติดต่อรู้จักเฉพาะวอลุ่มที่บีบอัด (.nii.gz, .nrrd.gz, .gipl.gz) โฟลเดอร์ของ ไฟล์ .nii หรือ .nrrd ที่ไม่บีบอัดจะถูกปฏิเสธ ("Wrong type of patient file detected") แม้ว่าการครอปเองจะจัดการได้ดี: ให้บีบอัดไฟล์ หรืออย่าผสมสองแบบในกลุ่มเดียวกัน

"Use module Crop Volume for tilted images": อ่านก่อน

นี่เป็นวิธีเดียวที่จัดการ ROI ที่หมุนจริงได้ แต่มันเปลี่ยนสอง อย่าง อย่างแรก มันรีแซมเปิลวอลุ่มลงในกรอบพิกัดของ ROI เอง: ค่าวอกเซล ถูกเปลี่ยน ข้อดี "ไม่รีแซมเปิล เมทริกซ์การลงทะเบียนภาพยังใช้ได้" จึงไม่ เป็นจริงอีกต่อไป อย่างที่สอง มันล้างฉากของ Slicer ทั้งหมดสำหรับผู้ป่วยทุกรายที่ประมวลผล: อย่าใช้หากคุณโหลดข้อมูลที่ต้องการเก็บไว้

การสร้างเมช VTK จากการแบ่งส่วน

ทำงานโดยอัตโนมัติเมื่อมีคำว่า "seg" อยู่ที่ใดก็ได้ในพาธเอาต์พุต (เช่น โฟลเดอร์ Segmentations/) ให้ถือเป็นฟีเจอร์รองที่เปราะบาง: ไม่รับประกันว่าเมชจะตรงกับวอลุ่มที่ครอปแล้วพอดี ทุก โครงสร้างออกมาเป็นสีเดียวกัน และการแบ่งส่วนที่มีมากกว่าหก label จะไม่ได้เมชเลย — โดยไม่มีข้อความแจ้งข้อผิดพลาด

อ่านเพิ่มเติม

โมดูลอรรถประโยชน์: ไม่มีงานตีพิมพ์ของตัวเองและไม่จำเป็นต้องมี โมดูลนี้ทำการครอปภาพแบบกลุ่มในแบบที่ Slicer ทำได้อยู่แล้ว

เกี่ยวกับวิธีการ

  • Documentation 3D Slicer — Crop Volume. โมดูลของ Slicer ที่อยู่เบื้องหลัง: ความหมายที่แท้จริงของการประมาณค่าในช่วง (interpolation) ตัวคูณการสุ่มตัวอย่าง และความเป็นไอโซทรอปิกที่คุณเห็นในหน้านี้
  • Barone et al., Orthod Craniofac Res 2025 — Deep Learning-Based Three-Dimensional Analysis Reveals Distinct Patterns of Condylar Remodelling After Orthognathic Surgery in Skeletal Class III Patients. งานวิจัยของห้องปฏิบัติการที่ใช้การครอปภาพแบบกลุ่มนี้เป็นขั้นเตรียมข้อมูล — ตัวอย่างของประโยชน์ของโมดูล

บรรณานุกรมทั้งหมดของเครื่องมือนี้ — ทั้งสิ่งที่พบ และสิ่งที่ค้นแล้วไม่พบ — อยู่ในหน้าแหล่งอ้างอิง

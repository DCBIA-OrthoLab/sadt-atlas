การใช้ VISOR: รันเครื่องมือบนเซิร์ฟเวอร์จาก 3D Slicer

เมื่อใช้ VISOR การคำนวณจะไม่รันบนคอมพิวเตอร์ของคุณอีกต่อไป คุณเลือกเครื่องมือใน Slicer ไฟล์ที่เลือกจะถูกส่งไปยังเซิร์ฟเวอร์ เซิร์ฟเวอร์คำนวณ แล้วผลลัพธ์กลับเข้ามาในฉากของคุณ หน้านี้ครอบคลุมสิ่งที่ต้องตั้งค่า สิ่งที่ต้องเตรียม และสิ่งที่ต้องตรวจก่อนส่งข้อมูลผู้ป่วย วิธีสร้าง VISOR อยู่ในแอตลาส VISOR

ไคลเอนต์: พัฒนาและทดสอบแล้ว การลบข้อมูลระบุตัวตน: ยังไม่พัฒนา MRI2CBCT: ไม่ได้จัดส่ง
ก่อนใช้ข้อมูลผู้ป่วย

ไคลเอนต์ VISOR ส่งไฟล์ของคุณตามที่อยู่บนดิสก์ ไม่มีอะไรถูกลบข้อมูลระบุตัวตน ดูสิ่งที่ออกจากเครื่องของคุณ

สิ่งที่เปลี่ยนไปสำหรับคุณ

ส่วนที่เหลือของไซต์นี้อธิบายส่วนขยายlegacy คือ SlicerAutomatedDentalTools ซึ่งแต่ละโมดูลรันบนคอมพิวเตอร์ของคุณเอง VISOR เป็นส่วนขยาย Slicer อีกตัวหนึ่ง คือ AutomatedDentalToolsRemote โมดูลของมันเป็นเพียงแผงบางๆ ที่ครอบเซิร์ฟเวอร์ระยะไกล

  • การคำนวณออกจากคอมพิวเตอร์ของคุณ แล็ปท็อปที่รันการแบ่งส่วนไม่ได้ก็ยังขอผลการแบ่งส่วนได้
  • ไม่ต้องติดตั้งอะไรลงใน Python ของ Slicer และไม่ต้องดาวน์โหลดโมเดล: ส่วนขยายไม่ประกาศการพึ่งพาส่วนขยายอื่น และโมเดลอยู่บนเซิร์ฟเวอร์
  • ฟอร์มมาจากเซิร์ฟเวอร์ แผงของเครื่องมือถูกสร้างตอนที่คุณเปิด จากคำอธิบายที่เซิร์ฟเวอร์เผยแพร่ ฟิลด์ที่เพิ่มบนเซิร์ฟเวอร์จะปรากฏใน Slicer โดยไม่ต้องออกส่วนขยายรุ่นใหม่
  • คุณต้องมีเซิร์ฟเวอร์ ที่อยู่ และคีย์ การตั้งค่าเซิร์ฟเวอร์เป็นหัวข้อของเซิร์ฟเวอร์ ไม่ใช่ของหน้านี้ ดูการติดตั้งใช้งาน

ติดตั้งส่วนขยาย

ข้อความต่อไปนี้มาจาก README และไฟล์ build เท่านั้น ไม่มีการสันนิษฐานเพิ่ม

  • ส่วนขยายคือ AutomatedDentalToolsRemote ใช้ได้กับ 3D Slicer ทั้งรุ่น stable และ nightly และโมดูลของมันปรากฏในหมวด Automated Dental Tools Remote
  • มันไม่ระบุการพึ่งพาส่วนขยายใดเลย (EXTENSION_DEPENDS "NA"): คุณไม่ต้องมี SlicerConda, SlicerDentalModelSeg หรือ NNUNet สำหรับมัน
  • README ระบุว่ามันอยู่ใน Extensions Catalog ในช่วงเปลี่ยนผ่าน
  • อย่าติดตั้งควบคู่กับส่วนขยาย legacy README ขอให้ใช้อย่างใดอย่างหนึ่ง เพราะหลายโมดูลใช้ชื่อเหมือนกัน และ Slicer เก็บโมดูลไว้เพียงตัวเดียวจากสองโมดูลที่ชื่อเหมือนกัน

เชื่อมต่อ Slicer กับเซิร์ฟเวอร์

เปิดServer Tools Settings (หมวด Automated Dental Tools Remote.Advanced) จนกว่าคุณจะบันทึกอะไรที่นี่ ที่อยู่จะเป็นค่าตัวอย่าง (https://set-your-server.invalid) ที่ไปไม่ถึงที่ใด จึงไม่มีไฟล์ใดออกจากเครื่องของคุณ

สิ่งที่ต้องเตรียม

  • Server URL: ที่อยู่ https:// ที่ใบรับรองลงนามโดยหน่วยงานสาธารณะ
  • API key: โทเคน API ของเซิร์ฟเวอร์ (ช่องนี้ถูกปิดบังตัวอักษร) README บอกให้ใช้โทเคน API ไม่ใช่โทเคนผู้ดูแล
  • Timeout: 1 ถึง 3600 วินาที ค่าเริ่มต้น 600

สิ่งที่คุณเปลี่ยนไม่ได้

  • ไม่รับ http:// แม้แต่ http://localhost
  • ใบรับรองถูกตรวจเสมอ: แผงแสดง "Verify TLS: Always on" โดยไม่มีช่องให้ติ๊ก
  • ไม่เคยตามการเปลี่ยนเส้นทาง (redirect)

คลิกSave การเปลี่ยนแปลงมีผลทันทีและถูกเก็บไว้ข้ามการรีสตาร์ต ถ้าคุณพิมพ์ที่อยู่ http:// Slicer จะปฏิเสธก่อนบันทึกอะไรทั้งสิ้น Restore defaults ล้างสิ่งที่คุณบันทึกไว้

เซิร์ฟเวอร์บนคอมพิวเตอร์ของคุณเองก็ใช้กฎเดียวกัน: ไคลเอนต์ไม่ยอมรับใบรับรองที่เซิร์ฟเวอร์ลงนามเอง คุณจึงเข้าถึงมันผ่านที่อยู่สาธารณะ เช่นที่อยู่ tailscale serve (https://<name>.<tailnet>.ts.net) หรือ reverse proxy ที่ใช้ใบรับรอง Let's Encrypt หรือของสถาบัน

เซิร์ฟเวอร์เข้าถึงได้หรือไม่ ไม่มีปุ่ม "Test connection" แผงแสดงบรรทัด "Server: online" หรือ "Server: offline" ที่ด้านบน รีเฟรชตอนเปิดโมดูลและหลังการบันทึกทุกครั้ง มันถามเฉพาะหน้า /health ของเซิร์ฟเวอร์ซึ่งไม่ต้องใช้คีย์: "online" ไม่ได้พิสูจน์ว่าคีย์ของคุณถูกยอมรับ คีย์ผิดจะปรากฏตอนรันครั้งแรก (ดูถ้ามีอะไรผิดพลาด)

คีย์ถูกเก็บเป็นข้อความธรรมดา

Slicer บันทึกคีย์ไว้ในไฟล์การตั้งค่าของผู้ใช้ของคุณเองเป็นข้อความธรรมดา ช่องที่ปิดบังตัวอักษรเพียงซ่อนมันบนหน้าจอ ใครก็ตามที่อ่านการตั้งค่า Slicer ของคุณได้ก็อ่านคีย์ได้

HTTPS ไม่มีทางถอยกลับ

ไม่มีการตั้งค่า แฟล็ก หรือไฟล์ใดที่ผ่อนปรนกฎ HTTPS หรือการตรวจใบรับรอง ที่อยู่ http:// ที่ไคลเอนต์รุ่นเก่าบันทึกไว้จะถูกละเลยตอนเริ่มต้น

รันเครื่องมือ

  1. เลือกเครื่องมือ ในรายการโมดูล มันสร้างฟอร์มจากเซิร์ฟเวอร์ตอนเปิด ถ้าเข้าถึงเซิร์ฟเวอร์ไม่ได้ แผงจะบอกว่าโหลดเครื่องมือไม่ได้และมีปุ่ม Retry
  2. กรอกฟอร์ม สิ่งที่คุณต้องให้ขึ้นอยู่กับเครื่องมือ ชื่อฟิลด์มาจากเซิร์ฟเวอร์ ให้อ่านหน้าคู่มือของแต่ละเครื่องมือ
  3. กด Apply แผงตรวจฟอร์มก่อน (อาร์กิวเมนต์ที่ไม่รู้จัก ไฟล์ที่ขาด ฟิลด์ที่จำเป็นแต่ว่าง) ก่อนที่จะส่งอะไรไป
  4. ดูความคืบหน้า และยกเลิกได้ถ้าจำเป็น

สิ่งที่ให้เป็นอินพุตได้

  • ไฟล์ ถูกส่งตามที่เป็น ชื่อเดิมและไบต์เดิม
  • โฟลเดอร์ ถูกแพ็กเป็นอาร์ไคฟ์ที่เก็บชื่อไฟล์และโฟลเดอร์ย่อยไว้ แล้วจึงส่ง
  • โหนดของฉาก Slicer (วอลุ่ม โมเดล หรือบริเวณที่สนใจ) ถูกส่งออกเป็นไฟล์ชั่วคราว ตั้งชื่อตามเครื่องมือและอาร์กิวเมนต์ ไม่ใช่ตามโหนด เช่น AutoCrop3D รับบริเวณที่สนใจจากฉากด้วยวิธีนี้
  • ไฟล์ทดสอบที่โฮสต์ไว้ คือตัวอย่างที่เซิร์ฟเวอร์เสนอให้เครื่องมือ การเลือกไฟล์หนึ่งจะดาวน์โหลดก่อน (เบื้องหลัง หน้าต่าง Slicer ยังใช้งานได้) แล้วจึงใช้เป็นอินพุต การเลือกรายการเดิมอีกครั้งในเซสชันเดียวกันจะใช้ไฟล์ที่ดาวน์โหลดไว้ซ้ำ
  • โมเดลที่เลือกบนเซิร์ฟเวอร์ ถูกเลือกตามชื่อจากรายการที่เซิร์ฟเวอร์เผยแพร่ มีเพียงชื่อที่เดินทาง ไฟล์โมเดลไม่เคยถูกส่งจากคอมพิวเตอร์ของคุณ ถ้ารายการว่างและอาร์กิวเมนต์ไม่มีวิธีอื่นให้ระบุ แผงจะแสดงคำเตือนให้ถามผู้ดูแลเซิร์ฟเวอร์

อินพุตขนาดใหญ่ถูกส่งเป็นส่วน ๆ และตรวจทีละส่วน ถ้าเซิร์ฟเวอร์เผยแพร่แผนขนาดสำหรับโฟลเดอร์ cohort แผงจะแบ่งมันเป็นชุด แต่ละชุดคือการรันตามปกติหนึ่งครั้ง

ความคืบหน้า การยกเลิก การเชื่อมต่อขาด

  • แผงรายงานระยะของเซิร์ฟเวอร์เอง: รับคำขอแล้ว กำลังเตรียมไฟล์อินพุต รอ GPU กำลังรันบนเซิร์ฟเวอร์ กำลังแพ็กผลลัพธ์ เสร็จสิ้น เวลาที่ผ่านไปเดินอยู่ข้างๆ การรันที่อยู่ในคิวแสดง "queued"
  • Cancel หยุดการรันบนเซิร์ฟเวอร์ด้วย มี Cancel หนึ่งปุ่มต่อการรันหนึ่งครั้ง เมื่อมีหลายการรันจะเป็น "Cancel all" และ cohort จะเป็น "Cancel the cohort" การรันที่ถูกยกเลิกไม่ถูกรายงานว่าเป็นข้อผิดพลาด
  • ถ้าการเชื่อมต่อขาด ขณะที่เซิร์ฟเวอร์ทำงานอยู่ แผงจะเชื่อมต่อสตรีมความคืบหน้าใหม่เองและทำต่อจากจุดที่ค้างไว้ โดยไม่แสดงซ้ำสิ่งที่แสดงไปแล้ว นี่คือโหมด detached ซึ่งเปิดเป็นค่าเริ่มต้น: คำขอจบทันทีที่อินพุตถูกเตรียมเสร็จ และผลลัพธ์มาถึงบนสตรีมความคืบหน้า timeout ในการตั้งค่าจึงไม่จำกัดว่าการรันจะนานเท่าไรอีกต่อไป
การหยุดเพื่อตรวจทานรันแบบบล็อก

ถ้าคุณเปิดใช้ขั้น "stop after" (ดูการตรวจทานคุณภาพ) การรันจะไม่ใช้โหมด detached: เซิร์ฟเวอร์ส่งข้อมูลสำหรับตรวจทานกลับมาในคำตอบของคำขอเดิม ตรงนั้น timeout จาก Server Tools Settings มีผล และการเชื่อมต่อที่ขาดจะทำให้คำตอบหาย

การตรวจทานคุณภาพด้วย VISU

บางเครื่องมือหยุดหลังจากขั้นหนึ่งได้เพื่อให้คุณตรวจผลระหว่างทาง ฟอร์มจะแสดงส่วน "Quality control" ที่มีตัวเลือกหลายข้อ stop_after โดยไม่มีอะไรถูกติ๊กเป็นค่าเริ่มต้น เครื่องมือที่เรียกเครื่องมืออื่นมีตัวเลือกนี้ เช่น ALI สำหรับสแกนในช่องปาก หรือ VFACE

  1. หยุด เซิร์ฟเวอร์หยุดชั่วคราวหลังขั้นที่คุณติ๊ก แผงแสดง "Stopped after <step>, waiting for your review" ดาวน์โหลดสิ่งที่สร้างได้จนถึงตอนนั้น และเปิดVISUบนข้อมูลนั้น

  3. แก้ไข สำหรับ landmark คุณลากจุดและ Save ได้ เฉพาะจุดที่คุณย้ายเท่านั้นที่ถูกเขียนใหม่ โดยจับคู่ตามชื่อ Undo my changes และ Revert to what is on disk คืนค่าให้ การปรับการลงทะเบียนถูกบันทึกเป็นไฟล์ transform แยกต่างหากข้างฉาก ไม่เคยรวมเข้ากับ transform ของเครื่องมือเอง

ไม่มีอะไรถูกลบข้อมูลระบุตัวตน

วันนี้ VISOR ไม่มีเครื่องมือลบข้อมูลระบุตัวตน สิ่งที่คุณเลือกถูกส่งไปยังเซิร์ฟเวอร์ตามที่อยู่บนดิสก์: ชื่อไฟล์ ส่วนหัว DICOM และตัวระบุทุกอย่างที่มันมี ไปป์ไลน์การลบข้อมูลระบุตัวตนถูกระบุไว้ในที่เก็บของไคลเอนต์ แต่ README ระบุว่ายังไม่พัฒนา และการค้นหาในโค้ดไม่พบการพัฒนาใดเลย

  • ประกาศ หลังจากคุณบันทึกที่อยู่เซิร์ฟเวอร์ที่ไม่ใช่คอมพิวเตอร์เครื่องนี้ Slicer จะแสดงหนึ่งครั้งต่อเซิร์ฟเวอร์: "Files are uploaded unmodified. This client does not de-identify anything... De-identify your data before selecting it, or confine use to data that carries no protected health information." มันเป็นคำเตือน ไม่ใช่การตรวจ: มันไม่หยุดอะไรเลย
  • โฟลเดอร์เก็บชื่อของมัน โฟลเดอร์ถูกแพ็กพร้อมชื่อไฟล์และโฟลเดอร์ย่อยเดิม โหนดของฉากถูกส่งออกภายใต้ชื่อทั่วไป ดังนั้นชื่อโหนดของมันจึงไม่ออกไป
  • CNE ส่งบันทึกทางคลินิก โมเดลข้อความรันบนเซิร์ฟเวอร์: บันทึกขึ้นไป และสิ่งที่สกัดได้กลับมา หน้า CNE ของ legacy ซึ่งบอกว่าไม่มีอะไรออกจากเครื่องของคุณ ใช้ไม่ได้กับ VISOR
  • การขนส่งเท่านั้น HTTPS ปกป้องการถ่ายโอน ไม่มีการเข้ารหัสไฟล์เพิ่มเติมจากนั้นทางฝั่งไคลเอนต์

  • ชี้ไคลเอนต์ไปยังเซิร์ฟเวอร์ที่สถาบันของคุณควบคุมเท่านั้น และตรวจว่าข้อตกลงกับผู้ดำเนินการเซิร์ฟเวอร์ครอบคลุมข้อมูลที่คุณส่ง README ขอสิ่งเดียวกัน

หากมีสิ่งผิดพลาด

สำหรับความล้มเหลวส่วนใหญ่ Slicer แสดงข้อความของเซิร์ฟเวอร์เอง ต่อไปนี้คือความหมายของแต่ละข้อความ

"The server URL must start with https://"

คุณพิมพ์ที่อยู่ http:// หรือ Slicer พบที่อยู่จากรุ่นเก่า ใช้ที่อยู่ https:// สาธารณะ ไม่มีทางเลี่ยงกฎนี้ รวมถึงสำหรับเซิร์ฟเวอร์บนคอมพิวเตอร์ของคุณเอง

401: authentication failed

คีย์ผิดหรือขาด แผงอาจยังแสดง "Server: online" ได้เพราะหน้า health ไม่ต้องใช้คีย์ ป้อนคีย์ใหม่ใน Server Tools Settings แล้ว Save

503 ระหว่างช่วงบำรุงรักษา

ขณะเซิร์ฟเวอร์กำลังอัปเดต มันปฏิเสธงานใหม่ด้วย 503 และส่วนหัว Retry-After: 10 นานสูงสุด 300 วินาที ไคลเอนต์ไม่อ่านส่วนหัวนั้น: คุณเห็นข้อความของเซิร์ฟเวอร์ หรือ "Server error (503)" รอแล้วกด Apply อีกครั้ง การอ่านผลลัพธ์ที่กำลังดำเนินอยู่ไม่ถูกบล็อก

422: invalid arguments

เซิร์ฟเวอร์ระบุชื่ออาร์กิวเมนต์ที่ผิด เช่นตัวเลือกที่อยู่นอกรายการที่ยอมรับ แก้ฟิลด์ที่มันระบุ "400" ที่มีข้อความเรื่องชนิดไฟล์หมายความว่านามสกุลไฟล์ไม่ถูกยอมรับโดยเครื่องมือนั้น

413: file too large

เซิร์ฟเวอร์ปฏิเสธการอัปโหลดที่เกินขีดจำกัด ค่าเริ่มต้นคือ 500 MB ต่อไฟล์ สำหรับ cohort ขนาดใหญ่ ให้ส่งโฟลเดอร์แทนอาร์ไคฟ์ขนาดมหึมาก้อนเดียว เพื่อให้แบ่งเป็นชุดได้

500: "The tool failed on the server"

นี่คือทั้งหมดที่ไคลเอนต์แสดงเมื่อเครื่องมือล่มภายใน โดยเจตนา: รายละเอียดอาจมีข้อมูลภายในของเซิร์ฟเวอร์ ให้ถามผู้ดูแลเซิร์ฟเวอร์ให้อ่านล็อกของมัน

  • Timeout timeout ใน Server Tools Settings (ค่าเริ่มต้น 600 วินาที) ใช้กับคำขอที่เปิดค้างอยู่ ในโหมด detached ซึ่งเป็นค่าเริ่มต้น การรันที่ยาวจะไม่ถูกตัดโดยมัน เซิร์ฟเวอร์ไม่มีขีดจำกัดเวลารันเป็นค่าเริ่มต้น
  • การรอในคิว การรันอาจรอ GPU: แผงอ่านว่า "Waiting for the GPU" และคุณยกเลิกได้ขณะรอ เซิร์ฟเวอร์ยังจำกัดจำนวนการรันที่ทำงานพร้อมกัน การรันที่ห้าจึงอาจรอก่อนที่จะปรากฏว่าอยู่ในคิวด้วยซ้ำ
  • เซิร์ฟเวอร์ออฟไลน์ ถ้าโหลดรายการเครื่องมือไม่ได้ แผงจะบอกและแสดง Retry ตรวจที่อยู่และ "Server: online" ใน Server Tools Settings
  • การเปลี่ยน config.py ไม่มีผล สิ่งที่คุณบันทึกใน Server Tools Settings ชนะค่าเริ่มต้นที่คอมไพล์ไว้เสมอ

Crown Segmentation (ติดป้ายสแกนในช่องปากทีละซี่ฟัน) มีโมดูลใน VISOR แต่ยังไม่มีหน้าคู่มือ หน้าแอตลาสของมันอธิบายไว้ โมดูลในเครื่อง ไม่ได้รันโดยเซิร์ฟเวอร์: Medical Data Anonymizer และ Agent ไม่ได้จัดส่ง: MRI2CBCT

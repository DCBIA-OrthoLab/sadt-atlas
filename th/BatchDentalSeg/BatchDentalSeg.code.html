BatchDentalSeg, legacy: โค้ด

สำหรับนักพัฒนา: โมดูล Slicer แบบ legacy ทำอะไรในโค้ด พร้อมการอ้างอิง file:line ซิกเนเจอร์ ตาราง และข้อควรระวัง คำอธิบายที่อ่านง่ายของไปป์ไลน์เดียวกัน พร้อมคณิตศาสตร์ อยู่ในหน้าแอตลาส คิวที่ขับ nnUNetv2_predict ไปทั่วชุดสแกน CT/CBCT ด้วยชุดน้ำหนักโมเดลสลับกันได้สี่ชุด คือ DentalSegmentator และอีกสามรุ่น พร้อมงานกันพลาด คืนเรขาคณิต และส่งออกทั้งหมดที่ห่อรอบมัน

โค้ด แอตลาส (คำอธิบาย) Dot 2024 · J Dent BATCHDENTALSEG nnUNetv2_predict ไม่มี conda: Python ของ Slicer + nnunetv2 VISOR บรรณานุกรม

การแบ่งส่วนทันต-ขากรรไกร-ใบหน้าของสแกน CT/CBCT เป็นชุด โมดูลไม่ใช่โครงข่าย: มันคือคิวและตัวควบคุมที่ห่อ nnUNetv2_predict พร้อมชุดน้ำหนักโมเดลสลับกันได้สี่ชุด การเรียนรู้ทั้งหมดเกิดนอกรีโพซิทอรีนี้ สิ่งที่เขียนไว้ที่นี่คือการเลือกโมเดล การกันพลาดด้านหน่วยความจำ การคืนเรขาคณิต และการส่งออก

โค้ดสองชุด

ทุกอย่างที่มีเลขกำกับด้านล่างอธิบายโมดูล Slicer แบบ legacy (SlicerAutomatedDentalTools ที่ 3c67957, 2026-10-26) การพอร์ต VISOR ซึ่งรันเครื่องมือเดียวกันบนเซิร์ฟเวอร์ มีหน้าของตัวเอง: BatchDentalSeg บน VISOR

1. ตำแหน่งในไปป์ไลน์

ไม่มีโมดูลอื่นในรีโพซิทอรีที่เรียก BatchDentalSeg และ BatchDentalSeg ไม่เรียกโมดูลอื่นในรีโพซิทอรี มันเป็นเครื่องมือปลายทาง แต่มันพึ่งส่วนขยาย Slicer ภายนอก คือ NNUNet (SlicerNNUNetLib) ซึ่งใช้สามคลาสจากมัน

ที่ถูกเรียกที่มาบทบาท
SlicerNNUNetLib.InstallLogicส่วนขยาย NNUNetsetupPythonRequirements(): ติดตั้ง nnunetv2 ใน Python ของ Slicer
SlicerNNUNetLib.Parameterส่วนขยาย NNUNetตรวจสอบโครงสร้างไดเรกทอรีของโมเดลและสร้างบรรทัดคำสั่ง
SlicerNNUNetLib.SegmentationLogicส่วนขยาย NNUNetเขียนวอลุ่มเป็น NIfTI ลงโฟลเดอร์ชั่วคราว เรียก nnUNetv2_predict เป็น QProcess และโหลดการแบ่งส่วนกลับเข้ามา
OpenAnatomyExportส่วนขยาย SlicerOpenAnatomyใช้ส่งออก glTF เท่านั้น; ติดตั้งทันทีถ้ายังไม่มี

4.2 nnU-Net ตรวจสอบแล้วในโค้ด

ใช่ นี่คือ nnU-Net v2 ไม่ใช่แค่ชื่อ หลักฐานอยู่ในห่วงโซ่การเรียก: Parameter.asArgList() สร้างตามตัวอักษรว่า

nnUNetv2_predict -i <tmp>/input -o <tmp>/output
  -d Dataset111_453CT -tr nnUNetTrainer -p nnUNetPlans -c 3d_fullres
  -f 0 -npp 1 -nps 1 -step_size 0.5 -device cuda -chk checkpoint_final.pth --disable_tta

-d, -tr, -p, -c ถูกอนุมานจากชื่อโฟลเดอร์: โฟลเดอร์แม่ให้ Dataset… และชื่อโฟลเดอร์การกำหนดค่าถูกแยกที่ __ เป็น (trainer, plan, configuration) จึงเป็นที่มาของข้อกำหนด Dataset<id>/<trainer>__<plan>__<conf>/fold_<i>/checkpoint_final.pth

พารามิเตอร์ที่ไม่เปิดให้ผู้ใช้ ค่าเริ่มต้นจาก SlicerNNUNetLib.Parameter: stepSize = 0.5, disableTta = True (ไม่มี mirror augmentation ตอนทดสอบ), folds = "0" (fold เดียว ไม่เคยเป็น ensemble), nProcessPreprocessing = nProcessSegmentationExport = 1 บังคับเป็น 0 บน macOS (nnU-Net ค้างตอนเขียนที่นั่นเพราะ multiprocessing)

การวางแพตช์และน้ำหนักแบบเกาส์เซียนเป็นของ nnU-Net ไม่ใช่ของโมดูล: ก้าวไม่เกิน step_size เท่าของแพตช์ และถูกหดให้แพตช์ไปจบที่ขอบภาพ จึงซ้อนทับอย่างน้อยครึ่งหนึ่งสำหรับ 0.5 (nnunetv2 2.8.1, inference/sliding_window_prediction.py:30-54); น้ำหนักเป็นเกาส์เซียนที่มีการกระจายหนึ่งในแปดของแพตช์ (:11-16, เรียกที่ inference/predict_from_raw_data.py:626) label ของ voxel คือ argmax ของ label ทั้งหมด (utilities/label_handling/label_handling.py:178) ซึ่งคืนค่าสูงสุดตัวแรกเมื่อเสมอกัน (พฤติกรรมที่บันทึกไว้ของ NumPy และ PyTorch)

การตั้งค่าอย่างเดียวที่ UI เสนอคืออุปกรณ์: cuda / cpu / mps ถ้าใช้ไม่ได้ จะถามครั้งเดียวสำหรับคิวทั้งหมด (_deviceFallbackAccepted) และในโหมดUnattended ระบบยอมรับการถอยไปใช้ CPU โดยอัตโนมัติ

nnUNet_raw, nnUNet_preprocessed และ nnUNet_results ทั้งหมดชี้ไปที่โฟลเดอร์โมเดล: ตัวแปรสภาพแวดล้อมระดับโพรเซสสามตัว เขียนโดย SegmentationLogic._startInferenceProcess เนื่องจาก os.environ เป็นของส่วนกลาง การอนุมานสองงานพร้อมกันในเซสชัน Slicer เดียวกันจะเหยียบกัน; ที่นี่คิวทำงานตามลำดับอย่างเคร่งครัด ปัญหาจึงไม่เกิด

5.3 ตัวกันหน่วยความจำ: แนวป้องกันสามชั้น

คอมเมนต์ในโค้ดให้กรณีจริง: สแกนหนึ่งกินหน่วยความจำ 114 GB บนเครื่อง 125 GB ถูก OOM killer ฆ่า และทิ้ง worker ของ multiprocessing ที่ยังมีชีวิตและถือหน่วยความจำไว้

a) ประมาณการล่วงหน้า _estimatePeakRamGb() (SegmentationWidget.py:1173) เนื่องจากปริมาตรทางกายภาพของขอบเขตการมองเห็นไม่ขึ้นกับระยะห่าง จำนวน voxel ที่ resample แล้วจึงเท่ากับ fovMm3 / targetVoxelMm3 จุดสูงสุดเกิดใน convert_predicted_logits_to_segmentation_with_correct_shape ซึ่งต่อหนึ่งคลาสมีสิ่งเหล่านี้อยู่พร้อมกัน: ตัวสะสม sliding-window (torch.half บนกริดที่ resample แล้ว, 2 ไบต์) สำเนา float64 ของมัน (data = data.astype(float) บนอาร์เรย์ 4D ทั้งก้อนในคราวเดียว, 8 ไบต์) และ reshaped_final (torch.half บนกริดเดิม, 2 ไบต์) จึงได้ logitsGb = (10 × C × Vresampled + 2 × C × Voriginal) / 2³⁰ บวก 8 × (Voriginal + Vresampled) สำหรับค่าชั่วคราว float64 ของ skimage.resize บวก _RAM_FIXED_OVERHEAD_GB = 4.0 (torch, น้ำหนักโมเดล, worker) spacing และจำนวน label อ่านจากโฟลเดอร์การกำหนดค่าเดียวกัน เพื่อไม่ให้เอาระยะห่างของโมเดลหนึ่งไปไขว้กับจำนวน label ของอีกโมเดล

งบ = free RAM × ramLimitSpinBox (ค่าเริ่มต้น 85%) เกินกว่านี้ สแกนจะถูกทำเครื่องหมาย failed พร้อมเหตุผล โดยไม่เริ่ม nnU-Net เลย เว้นแต่จะล้างช่องติ๊ก Skip scans too large for the free RAM (ramPreflightCheckBox, ติ๊กไว้เป็นค่าเริ่มต้น, SegmentationWidget.py:446-447): ถ้าเช่นนั้นค่าประมาณจะถูกบันทึกลง log เท่านั้น (SegmentationWidget.py:1248-1253) งบถูกใช้กับหน่วยความจำที่ว่างในขณะนั้น (vm.available, SegmentationWidget.py:1243-1244) ทั้งที่ spin box ติดป้ายว่า “% of system RAM”

b) เฝ้าสังเกตระหว่างทำงาน: _onMemCheck สุ่มทุก _RAM_SAMPLE_MS = 3000 ms; ต้องเกินติดต่อกัน _RAM_CONSECUTIVE_HITS = 2 ครั้งจึงจะฆ่า (การพุ่งชั่วคราวต้องไม่ตัดสินโทษสแกนที่ดี)

c) กู้คืนหน่วยความจำ: _killInferenceTree() ฆ่าทั้งต้นไม้ เพราะ QProcess.kill() เอื้อมถึงเฉพาะโพรเซสลูกโดยตรง แต่ nnU-Net ใช้ multiprocessing _reclaimStrayProcesses() กวาดโพรเซสที่บรรทัดคำสั่งมี nnunetv2_predict, nnunetv2/inference หรือ nnunet และไม่เป็นของใครอีกแล้ว ปุ่ม Free memory ทำสิ่งนี้ด้วยมือ

ครอปอัตโนมัติคำนวณ เชิงเรขาคณิต (เกณฑ์อากาศ + กล่องขอบเขต)วิดเจ็ต, numpy
การคืนลงกริดเดิมคำนวณ การเลื่อนดัชนี ไม่มี interpolationวิดเจ็ต, numpy
การสร้างlabel mapใหม่คำนวณ ส่งออกครั้งเดียว + LUTวิดเจ็ต, VTK/numpy
การแก้ mirrorคำนวณ เชิงเรขาคณิต (ระนาบซาจิตทัลบนฟันตัด)วิดเจ็ต, numpy

8. สภาพแวดล้อม

ติดตั้งหนึ่งครั้งต่อเซสชัน เมื่อApplyครั้งแรก โดย _runSetupThenStartQueue() (SegmentationWidget.py:1749):

  1. pip install light-the-torch แล้ว python -m light_the_torch install torch torchvision: ltt เลือก wheel CUDA ที่ตรงกับไดรเวอร์ที่ตรวจพบ ไม่ตรึงเวอร์ชัน;
  2. pip install numexpr>=2.10.2;
  3. pip install numpy<2.0 numexpr>=2.10.2 psutil ผ่าน PipRunner ซึ่งเป็น QProcess ที่คืนการควบคุมให้ UI;
  4. SlicerNNUNetLib.InstallLogic().setupPythonRequirements(): nnunetv2 อยู่นอกรีโพซิทอรีนี้;
  5. PythonDependencyChecker.downloadWeightsIfNeeded(): น้ำหนักโมเดลของ DentalSegmentator เท่านั้น

numpy<2.0 ด้วยเหตุผลเดียวกับใน AMASSS: wheel ของ torch ปัจจุบันคอมไพล์กับ numpy 1.x

ต้องติดตั้งส่วนขยาย NNUNet ด้วยมือ: การไม่มีมันถูกตรวจพบ (import SlicerNNUNetLib) และขึ้นข้อความขอให้ติดตั้งแล้วเริ่มใหม่ ส่วน SlicerOpenAnatomy ติดตั้งตัวเองตอนส่งออก glTF ครั้งแรก

ไม่มีสภาพแวดล้อม conda ไม่มี WSL GPU เป็นทางเลือก (ใช้ cpu, mps ได้) โดยต้องแลกกับ "ประมาณหนึ่งชั่วโมงต่อสแกน" ตามข้อความสำรอง

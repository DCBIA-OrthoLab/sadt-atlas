BatchDentalSeg

BatchDentalSeg ติดป้ายฟันและขากรรไกรของสแกน CT และ CBCT เป็นชุด ด้วยโครงข่ายหลาย label ตัวเดียวที่ให้ label แก่ทุก voxel ในรอบเดียว หน้านี้อธิบายโมดูลทีละขั้น พร้อมคณิตศาสตร์ของส่วนที่เป็นการคำนวณไม่ใช่การเรียนรู้: สแกนถูก normalise อย่างไร แพตช์ของโครงข่ายถูกผสมกันอย่างไร หน่วยความจำถูกประมาณอย่างไร สแกนถูกครอปอย่างไร และซ้ายขวาถูกแก้อย่างไร ตรงที่โค้ดทำสิ่งที่ควรตรวจสอบ จะมีลิงก์ไปที่หน้าโค้ด

โค้ด (นักพัฒนา) Dot 2024 · J Dent BATCHDENTALSEG nnUNetv2_predict ไม่มี conda: Python ของ Slicer + nnunetv2 VISOR บรรณานุกรม

ภาพรวม: อะไรเข้า อะไรออก

BatchDentalSeg รับสแกน CT หรือ CBCT ของศีรษะและติดป้ายฟันกับขากรรไกรในแต่ละสแกน โครงข่าย 3D ตัวเดียวมองทั้งสแกนและให้ label แก่ทุก voxel ในรอบเดียว: ไม่ใช่หนึ่งโครงข่ายต่อหนึ่งโครงสร้างแบบ AMASSS ตัวโมดูลเองคือคิวที่ห่อโครงข่ายนั้น: เลือกโมเดล กันหน่วยความจำ คืนเรขาคณิต และเขียนการส่งออก

เข้าเกิดอะไรขึ้นออก
โฟลเดอร์ของสแกน (.nii, .nii.gz, .gipl, .gipl.gz) และหนึ่งในสี่โมเดลแต่ละสแกนผ่าน nnU-Net ทีละสแกน; label mapถูกวางกลับบนกริดของสแกนเองlabel map ต่อสแกน (<scan>_Segmentation.nii.gz) และเลือกได้ว่าจะมี STL, OBJ, VTK, glTF หรือไฟล์ NIfTI หนึ่งไฟล์ต่อ segment

หน้านี้อธิบายโมดูล Slicer แบบ legacy (SlicerAutomatedDentalTools ที่ 3c67957, 2026-10-26) การพอร์ตบนเซิร์ฟเวอร์คือ BatchDentalSeg บน VISOR

1. ตำแหน่งในไปป์ไลน์

ไม่มีโมดูลอื่นของรีโพซิทอรีที่เรียก BatchDentalSeg และมันก็ไม่เรียกโมดูลใด: เป็นเครื่องมือปลายทาง มันพึ่งส่วนขยาย Slicer ภายนอกคือ NNUNet สำหรับติดตั้ง nnU-Net ตรวจโฟลเดอร์โมเดล และรันการทำนายเป็นโพรเซสลูก มันเป็นตัวแปรแบบชุดของ DentalSegmentator ซึ่งนำวิดเจ็ต ไอคอน และการดาวน์โหลดน้ำหนักโมเดลมาใช้ซ้ำ

ในโค้ดตารางคลาสที่เรียกจากส่วนขยาย NNUNet

2. ไฟล์ที่เกี่ยวข้อง

โค้ดส่วนใหญ่เป็นไฟล์วิดเจ็ตเดียวราว 3000 บรรทัด: อินเทอร์เฟซ คิว การเลือกโมเดล ตัวกันหน่วยความจำ การครอป label และการส่งออก ไฟล์คิวเล็ก ๆ เก็บรายการสแกนไว้บนดิสก์ และตัวตรวจดาวน์โหลดและรีเฟรชน้ำหนักโมเดลของ DentalSegmentator ทุกอย่างรันใน Python ของ Slicer; nnU-Net เองถูกเปิดเป็นโพรเซสลูก ทีละสแกน น้ำหนักโมเดลมาถึงตอนรัน

ในโค้ดตารางไฟล์พร้อมจำนวนบรรทัด และสิ่งที่ไฟล์ build ติดตั้ง

3. อินพุต การท่องโฟลเดอร์ การตั้งชื่อ

3.1 สิ่งที่รับ

โฟลเดอร์ถูกแสดงรายการโดยไม่เข้าโฟลเดอร์ย่อย สำหรับสี่รูปแบบ: .nii, .nii.gz, .gipl, .gipl.gz NRRD ซึ่งเป็นรูปแบบเริ่มต้นของ Slicer ไม่ถูกรู้จัก

3.2 คิว

หนึ่งรายการคือหนึ่งสแกน ไม่ใช่หนึ่งโฟลเดอร์ จึงซ้อนหลายโฟลเดอร์ที่ใช้โมเดลต่างกันในเซสชันเดียวกันได้ สแกนจะถูกข้ามถ้าผลลัพธ์มีอยู่แล้วหรืออยู่ในคิวแล้ว สถานะของคิวถูกเขียนใหม่หลังแต่ละสแกน เซสชันที่ถูกฆ่ากลางการอนุมานจึงทำต่อจากที่หยุด ทุกห้าสแกน (ค่าเริ่มต้น) การล้างจะคืนการ์ดจอและหน่วยความจำ

3.3 สิ่งที่โครงข่ายเห็นจริง ๆ

วิดเจ็ตไม่พรีโปรเซสอะไร: มันส่งออกสแกนเป็นไฟล์ NIfTI และที่เหลือทั้งหมดเป็นของ nnU-Net nnU-Net เรียงแกนของสแกนใหม่ตามที่แผนขอ ครอปไปที่บริเวณที่ไม่ใช่ศูนย์ normalise ความเข้ม และต่อจากนั้นจึง resample ไปที่ระยะห่างของแผน (ลำดับตามโค้ดของ nnU-Net เอง ตรวจใน 2.8.1; เวอร์ชันที่การติดตั้งแบบ legacy รันไม่ได้ถูกบันทึกไว้) การ normalise ที่แสดงด้านล่างคือแบบที่แผนของ DentalSegmentator ประกาศ; สำหรับอีกสามโมเดลดูหัวข้อ 4.3

อ่านได้เฉพาะแผนของ DentalSegmentator ในรีโพซิทอรี (ในรีโพซิทอรี legacy): เปอร์เซ็นไทล์ −110 และ 3067, ค่าเฉลี่ย 1274, ส่วนเบี่ยงเบนมาตรฐาน 558 อีกสามชุดมีไฟล์แผนของตัวเอง ดังนั้นสูตรนี้สำหรับพวกมันเป็นข้อสันนิษฐาน ไม่ได้ตรวจ

พรีโปรเซสอย่างเดียวที่เขียนในรีโพซิทอรีนี้คือครอปอัตโนมัติที่เป็นทางเลือก (หัวข้อ 5.2) สงวนไว้เล่นซ้ำหลังหน่วยความจำล้มเหลว

ในโค้ดglob รายการในคิว การคงอยู่ และวงจรการล้าง

4. สี่โมเดล

4.1 combo box เลือกอะไร

ทั้งสี่รายการรันโค้ดเดียวกัน: คำขอทำนายถูกสร้างด้วย fold 0 และอุปกรณ์ที่เลือก ต่างกันเฉพาะโฟลเดอร์น้ำหนักโมเดลและตาราง label สามรุ่นย่อย (pediatric, naso-maxilla และ universal) ดาวน์โหลดเป็นสามไฟล์ต่อรุ่น; DentalSegmentator มาเป็น zip ของ release ล่าสุดของรีโพซิทอรีของมัน การดาวน์โหลดไม่มี checksum และไม่มีการดาวน์โหลดต่อ การดาวน์โหลดที่ถูกขัดจังหวะจึงทิ้งcheckpointที่ถูกตัดไว้ ซึ่งการรันครั้งถัดไปเข้าใจผิดว่าครบ

ในโค้ดสี่กิ่ง เส้นทางดาวน์โหลด และการตรวจ checkpoint

4.2 nnU-Net ตรวจสอบแล้วในโค้ด

มันคือ nnU-Net v2 จริง ๆ: คำสั่งที่มันสร้างระบุชุดข้อมูล trainer แผน และการกำหนดค่า (3D full resolution) หนึ่ง fold (สำเนาที่ฝึกแล้วของโมเดลหนึ่งชุด) ก้าว 0.5 (แต่ละแพตช์ขยับไม่เกินครึ่งหนึ่งของขนาดมัน) ไม่มี mirroring ตอนทดสอบ (ไม่มีการเฉลี่ยบนสำเนาที่พลิกของสแกน) การตั้งค่าอย่างเดียวที่อินเทอร์เฟซเสนอคืออุปกรณ์ (cuda, cpu หรือ mps) fold 0 เท่านั้น ไม่เคยเป็น ensemble

ในโค้ดบรรทัดคำสั่ง ค่าเริ่มต้น และตัวแปรสภาพแวดล้อมระดับโพรเซส

4.3 สถาปัตยกรรมและแผน: อะไรตรวจสอบได้

เฉพาะชุดของ DentalSegmentator ที่ส่งไฟล์แผนมาในรีโพซิทอรี: 3D U-Net แบบ convolutional ธรรมดาหกสเตจ (32 ฟีเจอร์ที่สเตจแรก 320 ที่สุดท้าย) แพตช์ 128 × 160 × 112 voxel ระยะห่างประมาณ 0.45 × 0.31 × 0.45 mm batch 2 และ CT normalisation แผนของอีกสามโมเดลมาพร้อมการดาวน์โหลด จึงพูดอะไรเพิ่มเกี่ยวกับมันจากโค้ดไม่ได้

ในโค้ดสรุปแผนและหมายเหตุเรื่องรูปแบบ

4.4 label ที่สร้าง แยกตามโมเดล

ตารางในวิดเจ็ตกำหนดค่าที่เขียนลงไฟล์เอาต์พุต สองโมเดลแรกใช้ห้า label เดียวกัน และต่างกันเฉพาะข้อมูลที่ใช้ฝึก (ฟันแท้เทียบกับฟันผสม)

โมเดล UniversalLab ไม่แบ่งส่วนหลังคากะโหลก ขัดกับคำอธิบายในอินเทอร์เฟซและ README (ดูข้อควรระวัง)

ในโค้ดฟังก์ชัน label แท็กของ segment และการเรียงเลข UniversalLab

5. แกนที่ไม่ได้เรียนรู้

5.1 การสร้าง label map ใหม่และการคืนเรขาคณิต

การแบ่งส่วนถูกแปลงเป็นlabel mapหนึ่งอันในการส่งออกครั้งเดียว แล้วแมปเป็นค่าทางการด้วยตารางค้นหาในรอบเดียว เวอร์ชันก่อนหน้า rasterise ทั้งวอลุ่มหนึ่งครั้งต่อ segment: 55 ครั้งสำหรับ UniversalLab บน CBCT เต็มปาก

ในโค้ดการส่งออกครั้งเดียวและตารางค้นหา

5.2 ครอปอัตโนมัติ (เล่นซ้ำหลังหน่วยความจำล้มเหลว)

ปริมาตรย่อยที่ครอปคงระยะห่างและแกนไว้ เลื่อนเฉพาะ origin และไม่มีการ interpolate หลังการทำนาย label map ถูกวางกลับในอาร์เรย์ขนาดเดิมด้วยการเลื่อนอย่างง่าย เอาต์พุตจึงอยู่บนกริดของสแกนตามที่ถ่ายเสมอ

ในโค้ดฟังก์ชันครอป ค่าคงที่ และการวางกลับ

5.3 ตัวกันหน่วยความจำ: แนวป้องกันสามชั้น

คอมเมนต์ในโค้ดให้กรณีจริง: สแกนหนึ่งกินหน่วยความจำ 114 GB บนเครื่อง 125 GB ถูกระบบฆ่า และทิ้ง worker ที่ยังมีชีวิตและถือหน่วยความจำไว้ จึงมีแนวป้องกันสามชั้น หนึ่งชั้นต่อหนึ่งช่วงของโพรเซส: ประมาณการก่อนเปิดรัน ตัวเฝ้าสังเกตระหว่างรัน และการกู้คืนหลังรัน

ระหว่างรัน หน่วยความจำถูกสุ่มทุก 3 วินาที และต้องเกินติดต่อกันสองครั้งจึงจะฆ่าโพรเซส เพื่อให้การพุ่งชั่วคราวไม่ตัดสินโทษสแกนที่ดี ต้นไม้โพรเซสทั้งหมดถูกฆ่า ไม่ใช่เฉพาะโพรเซสลูกโดยตรง เพราะ nnU-Net เปิด worker ของตัวเอง และโพรเซสกำพร้าจะถูกกวาด

ในโค้ดตัวประมาณ ตัวสุ่ม การฆ่าต้นไม้โพรเซส และการกวาดโพรเซสตกค้าง

5.4 การตรวจจับความเสร็จแบบสำรอง

เมื่อ nnU-Net พิมพ์บรรทัด “done” ตัวจับเวลาเฝ้าดูขนาดไฟล์เอาต์พุต และการอ่านได้ค่าเท่ากันสองครั้งบังคับให้จบ แม้โพรเซสจะไม่เคยส่งสัญญาณ; มันยอมแพ้หลัง 60 วินาที แต่ละสแกนยังมี watchdog (60 นาทีเป็นค่าเริ่มต้น) ที่ทำเครื่องหมายว่า failed และไปต่อ

ในโค้ดตัวจับเวลาสำรองและ watchdog ต่อสแกน

5.5 การแก้ mirror (เฉพาะ UniversalLab)

ถ้าขาดฟันตัดหนึ่งในสี่ซี่ การแก้ไขจะถูกปฏิเสธ ผลลัพธ์ไปอยู่ในโหนดใหม่ <name>_Mirrored และต้นฉบับยังคงอยู่

ในโค้ดฟังก์ชัน mirror พจนานุกรม label และการคำนวณระนาบ

5.6 หลังประมวลผลที่ขาดหายไป

ไม่มีการล้างทางสัณฐานวิทยา: สิ่งที่ออกมาคือเอาต์พุตดิบของ nnU-Net พร้อมหลังประมวลผลภายในของมันเองถ้าชุดมีมาให้ มีฟังก์ชันลบ island สองตัวอยู่ แต่ไม่มีอะไรเรียกมัน

ในโค้ดฟังก์ชันตายและสิ่งที่เหลือ

6. เอาต์พุต

ไม่ว่าจะติ๊กรูปแบบใด โมดูลเขียน <scan>_Segmentation.nii.gz เสมอ ซึ่งเป็นlabel mapบนเรขาคณิตของวอลุ่มเดิม นี่ยังเป็นไฟล์ที่คิวมองหาเพื่อตัดสินว่าสแกนเสร็จแล้ว รูปแบบอื่นไปที่โฟลเดอร์เดียวกัน:

  • STL, OBJ: หนึ่งไฟล์ต่อ segment
  • VTK ต่อ label: หนึ่งไฟล์ต่อ label ทำความสะอาด smooth (windowed-sinc 60 รอบ) ลดลง 40 % และพลิกจาก RAS เป็น LPS
  • VTK แบบรวม: หนึ่งไฟล์ที่มีทุก label สร้างแบบเดียวกัน พร้อมอาร์เรย์ label คงที่
  • NIfTI ต่อ segment: หนึ่งไฟล์ไบนารีต่อ segment อย่าสับสนกับ label map ด้านบน
  • glTF: ผ่านส่วนขยาย SlicerOpenAnatomy พร้อม decimation ที่ปรับได้ (ค่าเริ่มต้น 0.9)

การส่งออกเมชล้มเหลวไม่ทำให้สแกนล้มเหลว: NIfTI ถูกเขียนไปแล้ว และสแกนถูกทำเครื่องหมาย done พร้อมคำเตือน

ในโค้ดตารางเอาต์พุตพร้อมทุกฟังก์ชันและตัวกรอง

7. อะไรคือค่าที่ทำนาย และอะไรคือค่าที่คำนวณ

บล็อกลักษณะ
เรียงแกนใหม่ ครอปไปที่บริเวณที่ไม่ใช่ศูนย์ normalise ความเข้ม resample (ตามลำดับนี้)คำนวณ กำหนดแน่นอน ขับโดยแผน
การแบ่งส่วนทำนาย 3D U-Net, หนึ่ง fold, ไม่มี mirroring ตอนทดสอบ
ครอปอัตโนมัติคำนวณ เกณฑ์อากาศและกล่องขอบเขต
การคืนลงกริดเดิมคำนวณ การเลื่อนดัชนี ไม่มี interpolation
การสร้างlabel mapใหม่คำนวณ การส่งออกครั้งเดียวและตารางค้นหา
การแก้ mirrorคำนวณ ระนาบซาจิตทัลผ่านฟันตัด
เมชคำนวณ marching cubes, smoothing, decimation
ค่าประมาณหน่วยความจำและตัวกันคำนวณ เลขคณิตบนสแกนและแผน

การเรียนรู้อย่างเดียวคือของcheckpointทั้งสี่ ซึ่งอยู่นอกรีโพซิทอรีนี้

ในโค้ดตารางเดียวกันพร้อมที่ที่แต่ละบล็อกรัน

8. สภาพแวดล้อม

ไลบรารีถูกติดตั้งหนึ่งครั้งต่อเซสชัน เมื่อกด Apply ครั้งแรก: torch (บิลด์ที่ตรงกับไดรเวอร์ที่ตรวจพบ ไม่ตรึงเวอร์ชัน), NumPy ต่ำกว่า 2 เพราะ wheel ของ torch ปัจจุบันถูกสร้างกับ NumPy 1, psutil และ nnU-Net ผ่านส่วนขยาย NNUNet ซึ่งต้องติดตั้งด้วยมือ ไม่มี conda ไม่มี WSL การ์ดจอเป็นทางเลือก แต่ข้อความสำรองพูดถึงประมาณหนึ่งชั่วโมงต่อสแกนบน CPU

ในโค้ดลำดับการติดตั้งทีละขั้น

9. ข้อควรระวังและจุดเปราะบาง

แต่ละข้อถูกตรวจในโค้ดและอธิบายพร้อมหลักฐานในหน้าโค้ด

  • segment ของ NasoMaxillaDentSeg ถูกเปลี่ยนชื่อผิด: สี่ตัวสุดท้ายได้ชื่อ สี และความโปร่งแสงผิด และ mandibular canal อาจหายจากเอาต์พุต หลักฐาน
  • UniversalLab ถูกอธิบายว่าแบ่งส่วนหลังคากะโหลก ในอินเทอร์เฟซและ README แต่ไม่มี label นั้น หลักฐาน
  • การดาวน์โหลดน้ำหนักโมเดล DentalSegmentator ลบอีกสามโมเดลทิ้ง หลักฐาน
  • release ถูกระบุอย่างเปราะบางและไม่มีการดาวน์โหลดใดถูกตรวจ: asset แรกของ release ล่าสุด ไม่มี checksum หลักฐาน
  • ไม่อ่าน NRRD และไม่เดินเข้าโฟลเดอร์ย่อย; สองสแกนที่ชื่อเดียวกันเขียนทับผลลัพธ์เดียวกัน หลักฐาน
  • fold เดียว ไม่เคยเป็น ensemble: fold เพิ่มเติมในชุดถูกเมินเฉย หลักฐาน
  • ตัวแปรสภาพแวดล้อมที่ชี้ nnU-Net ไปที่โมเดลถูกตั้งสำหรับทั้งโพรเซส Slicer, ไม่เป็นอันตรายที่นี่เพียงเพราะคิวทำงานตามลำดับ หลักฐาน
  • โค้ดตาย: ฟังก์ชันลบ island และหลังประมวลผลไม่เคยถูกเรียก หลักฐาน
  • รายการติดตั้งไม่สมบูรณ์ในไฟล์ build: ระบุเพียงบางส่วนของโฟลเดอร์โมเดล หลักฐาน
ในโค้ดทุกข้อควรระวังพร้อมไฟล์และบรรทัด

10. วรรณกรรม

DentalSegmentator ถูกเผยแพร่แล้ว: Dot G. et al., DentalSegmentator: robust open source deep learning-based CT and CBCT image segmentation, Journal of Dentistry 147:105130, 2024 (doi:10.1016/j.jdent.2024.105130) ใช้ nnU-Net v2 กับสแกน CT และ CBCT 470 ชุดจาก 7 สถาบันสำหรับการฝึก และการทดสอบ hold-out 256 สแกน ได้ Dice 92.2 ± 6.3 % ภายในและ 94.2 ± 7.4 % ภายนอก สำหรับโมเดลนี้ โค้ดและบทความตรงกัน รากฐานเชิงวิธีวิทยาคือ Isensee et al., nnU-Net, Nature Methods 18(2):203-211, 2021

สามรุ่นย่อยไม่ผูกกับสิ่งตีพิมพ์ใดในรีโพซิทอรี README ประกาศ CBCT 513 สแกนในฟันผสมสำหรับสองรุ่น และ 135 สแกนสำหรับรุ่นที่สาม โดยไม่มีเอกสารอ้างอิงและไม่มีชุดทดสอบ: ตัวเลขเหล่านี้เป็นข้ออ้างภายในจนกว่าจะมีสิ่งตีพิมพ์ครอบคลุม ข้อความเต็มของเอกสารอ้างอิงอยู่ในหน้าโค้ดและใน SOURCES.md

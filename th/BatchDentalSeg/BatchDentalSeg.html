1. ตำแหน่งใน pipeline

ไม่มีโมดูลอื่นใดในที่เก็บโค้ดเรียก BatchDentalSeg และ BatchDentalSeg ก็ไม่เรียกโมดูลอื่นใดในที่เก็บโค้ด เป็นเครื่องมือปลายทาง อย่างไรก็ตาม มันพึ่งส่วนขยาย Slicer ภายนอกคือ NNUNet (SlicerNNUNetLib) ซึ่งใช้สามคลาสจากมัน

ถูกเรียกต้นกำเนิดบทบาท
SlicerNNUNetLib.InstallLogicส่วนขยาย NNUNetsetupPythonRequirements(): ติดตั้ง nnunetv2 ใน Python ของ Slicer
SlicerNNUNetLib.Parameterส่วนขยาย NNUNetตรวจสอบโครงสร้างไดเรกทอรีของโมเดลและสร้างบรรทัดคำสั่ง
SlicerNNUNetLib.SegmentationLogicส่วนขยาย NNUNetเขียนวอลุ่มเป็น NIfTI ลงโฟลเดอร์ชั่วคราว เปิด nnUNetv2_predict เป็น QProcess และโหลดการแบ่งส่วนกลับ
OpenAnatomyExportส่วนขยาย SlicerOpenAnatomyสำหรับการส่งออก glTF เท่านั้น ติดตั้งทันทีหากไม่มี

โมดูลเป็นรุ่นแบบชุดของ DentalSegmentator (ส่วนขยาย gaudot/SlicerDentalSegmentator) ซึ่งนำวิดเจ็ต ไอคอน และกลไกดาวน์โหลดน้ำหนักมาใช้ซ้ำ ผู้ร่วมพัฒนาที่ประกาศใน BATCHDENTALSEG.py:30 ผสมทีมเดิม (Dot, Gajny, Fenioux, Pelletier) กับส่วนที่ UoM เพิ่ม (Tulissi)

4.2 nnU-Net ตรวจสอบในโค้ดแล้ว

ใช่ นี่คือ nnU-Net v2 ไม่ใช่แค่ชื่อ หลักฐานอยู่ในห่วงโซ่การเรียก: Parameter.asArgList() สร้างตามตัวอักษรว่า

nnUNetv2_predict -i <tmp>/input -o <tmp>/output
  -d Dataset111_453CT -tr nnUNetTrainer -p nnUNetPlans -c 3d_fullres
  -f 0 -npp 1 -nps 1 -step_size 0.5 -device cuda -chk checkpoint_final.pth --disable_tta

-d, -tr, -p, -c ถูกอนุมานจากชื่อโฟลเดอร์: โฟลเดอร์แม่ให้ Dataset… และชื่อโฟลเดอร์ configuration ถูกแยกที่ __ เป็น (trainer, plan, configuration) จึงมีข้อกำหนด Dataset<id>/<trainer>__<plan>__<conf>/fold_<i>/checkpoint_final.pth

พารามิเตอร์ที่ไม่เปิดให้ผู้ใช้ ค่าเริ่มต้นจาก SlicerNNUNetLib.Parameter: stepSize = 0.5, disableTta = True (ไม่มี mirror augmentation ตอนทดสอบ), folds = "0" (fold เดียว ไม่เคยเป็น ensemble), nProcessPreprocessing = nProcessSegmentationExport = 1 บังคับเป็น 0 บน macOS (nnU-Net ค้างตอนเขียนที่นั่นเพราะ multiprocessing)

การตั้งค่าเดียวที่ UI เสนอคืออุปกรณ์: cuda / cpu / mps ถ้าใช้ไม่ได้ จะถามเพียงหนึ่งคำถามสำหรับทั้งคิว (_deviceFallbackAccepted) และในโหมด Unattended การถอยไปใช้ CPU จะถูกยอมรับอัตโนมัติ

nnUNet_raw, nnUNet_preprocessed และ nnUNet_results ถูกชี้ไปที่โฟลเดอร์โมเดลทั้งหมด: ตัวแปรสภาพแวดล้อมระดับ process สามตัว เขียนโดย SegmentationLogic._startInferenceProcess เนื่องจาก os.environ เป็นค่าสากล การอนุมานสองงานพร้อมกันในเซสชัน Slicer เดียวกันจะเหยียบกัน ที่นี่คิวเป็นลำดับอย่างเคร่งครัด จึงไม่เกิดปัญหา

4.3 สถาปัตยกรรมและ plan: สิ่งที่ตรวจสอบได้

มีเพียง Dataset111_453CT (DentalSegmentator) ที่มีไฟล์ JSON อยู่ในที่เก็บโค้ด สรุปจาก plans.json:

plan ของอีกสามโมเดลไม่สามารถระบุได้จากที่เก็บโค้ด: มาพร้อมกับการดาวน์โหลด ทุกสิ่งที่รู้เกี่ยวกับพวกมันมาจากพจนานุกรมที่ฮาร์ดโค้ดในวิดเจ็ต (§4.4) และจาก README

4.4 label ที่สร้างขึ้น แยกตามโมเดล

_get_active_label_map() (SegmentationWidget.py:1847) คือตารางอ้างอิงหลัก: มันตัดสินค่าที่เขียนลงใน NIfTI เอาต์พุต

DentalSegmentator และ PediatricDentalsegmentator, 5 label เหมือนกัน ยืนยันโดย dataset.json ของชุด 111: 1 Upper Skull (รวม maxilla) 2 Mandible 3 Upper Teeth 4 Lower Teeth 5 Mandibular canal สิ่งที่ทำให้ต่างกันจึงไม่ใช่เอาต์พุต แต่เป็นข้อมูลที่ใช้ฝึก: ฟันแท้ (453CT, 7 สถาบัน) กับฟันผสม (380CT) โค้ดปฏิบัติต่อทั้งสองอย่างเหมือนกันทุกประการ: ตาราง label เดียวกัน สีเดียวกัน การประมวลผลหลังเหมือนกัน; มีเพียง _modelBasePath ที่ต่างกัน

NasoMaxillaDentSeg, 6 label maxilla แยกออกจากกะโหลก: 1 Upper Skull, 2 Mandible, 3 Maxilla, 4 Upper Teeth, 5 Lower Teeth, 6 Mandibular canal

UniversalLabDentalsegmentator, 55 label: ฟันแท้ 32 ซี่ถูกกำหนดเลขทีละซี่ (1 = กรามซี่ที่สามขวาบน, upper right 3rd molar → 32 = กรามซี่ที่สามขวาล่าง, lower right 3rd molar วนรอบส่วนโค้งฟันบนแล้วส่วนโค้งฟันล่าง) จากนั้นฟันน้ำนม 20 ซี่ (33 → 52) แล้ว Mandible = 53, Maxilla = 54, Mandibular canal = 55 ไม่มี "Upper Skull": โมเดลนี้ไม่แบ่งส่วนเพดานกะโหลก ขัดกับที่คำอธิบายใน UI ของมันแสดงและที่ README ระบุ การกำหนดเลขไม่ได้เป็นไปตามอำเภอใจ: label ต่อ label ค่า 1–32 ตรงกับระบบเลขฟัน Universal พอดี (1 = กรามซี่ที่สามขวาบน … 32 = กรามซี่ที่สามขวาล่าง) และ 33–52 คืออักษร A–T ของฟันน้ำนม ดังนั้นค่าเทียบ FDI ของ label จึงคงที่ รูปด้านล่างแสดงทั้งสองระบบ

ข้อควรระวัง

คำอธิบายที่แสดงใน UI สำหรับ UniversalLabDentalsegmentator และ README ของที่เก็บโค้ดประกาศการแบ่งส่วนเพดานกะโหลก โมเดลจริงไม่มี label "Upper Skull": มันเพียงกำหนดเลขให้ฟัน บวก mandible/maxilla/canal

  • threshold อากาศ/เนื้อเยื่อที่ทนต่อสเกล: ถ้า array.min() < −800 เราอยู่ในหน่วย Hounsfield และ threshold คือ −500 มิฉะนั้นคือ min + 0.15 × (p99.5 − min);
  • กรอบล้อมของวอกเซลที่เหนือ threshold ขยายด้วย _CROP_MARGIN_MM = 15.0 mm ที่แปลงเป็นวอกเซลต่อแกน;
  • ถ้าเก็บวอกเซลไว้มากกว่า _CROP_MIN_GAIN = 0.85 การครอปจะถูกยกเลิก: ได้น้อยกว่า 15% ไม่คุ้มกับความเสี่ยง;
  • วอลุ่มย่อยคง spacing และแกนไว้ เลื่อนเฉพาะ origin (ijkToRas.MultiplyPoint([i0,j0,k0,1])) ไม่มีการ interpolate

_restoreCropToOriginalGrid() วาง label map กลับเข้าอาร์เรย์ขนาดเดิมด้วยการเลื่อนดัชนีอย่างง่าย: เอาต์พุตจึงอยู่บนกริดของภาพสแกนที่ถ่ายมาเสมอ

5.3 ตัวป้องกันหน่วยความจำ: แนวป้องกันสามชั้น

คอมเมนต์ในโค้ดให้กรณีจริง: ภาพสแกนหนึ่งชุดใช้ไป 114 GB บนเครื่อง 125 GB ถูก OOM killer ฆ่า และทิ้ง worker ของ multiprocessing ที่ยังถือหน่วยความจำไว้

ก) ประมาณการล่วงหน้า _estimatePeakRamGb() (SegmentationWidget.py:1183) เนื่องจากปริมาตรทางกายภาพของ field of view ไม่ขึ้นกับ spacing จำนวนวอกเซลที่ resample แล้วจึงเท่ากับ fovMm3 / targetVoxelMm3 จุดสูงสุดเกิดใน convert_predicted_logits_to_segmentation_with_correct_shape ที่ซึ่งต่อหนึ่งคลาสมีสิ่งต่อไปนี้อยู่พร้อมกัน: ตัวสะสม sliding-window (torch.half บนกริดที่ resample แล้ว 2 ไบต์) สำเนา float64 ของมัน (data = data.astype(float) บนอาร์เรย์ 4D ทั้งก้อนในครั้งเดียว 8 ไบต์) และ reshaped_final (torch.half บนกริดเดิม 2 ไบต์) จึงได้ logitsGb = (10 × C × Vresampled + 2 × C × Voriginal) / 2³⁰ บวก 8 × (Voriginal + Vresampled) สำหรับค่าชั่วคราว float64 ของ skimage.resize บวก _RAM_FIXED_OVERHEAD_GB = 4.0 (torch น้ำหนัก worker) spacing และจำนวน label อ่านจากโฟลเดอร์ configuration เดียวกัน เพื่อไม่ให้เอา spacing ของโมเดลหนึ่งไปไขว้กับจำนวน label ของอีกโมเดลหนึ่ง

งบ = free RAM × ramLimitSpinBox (ค่าเริ่มต้น 85%) เกินกว่านี้ ภาพสแกนจะถูกทำเครื่องหมาย failed พร้อมเหตุผล โดยไม่เริ่ม nnU-Net เลย

ข) เฝ้าติดตามระหว่างทำงาน: _onMemCheck สุ่มตัวอย่างทุก _RAM_SAMPLE_MS = 3000 ms; ต้องเกิน _RAM_CONSECUTIVE_HITS = 2 ครั้งติดกันจึงฆ่า (การพุ่งชั่วคราวต้องไม่ตัดสินโทษภาพสแกนที่ดี)

ค) การกู้คืนหน่วยความจำ: _killInferenceTree() ฆ่าทั้งต้นไม้ เพราะ QProcess.kill() ถึงเพียง process ลูกโดยตรง แต่ nnU-Net ทำ multiprocessing _reclaimStrayProcesses() กวาด process ที่บรรทัดคำสั่งมี nnunetv2_predict, nnunetv2/inference หรือ nnunet และไม่มีเจ้าของอีกแล้ว ปุ่ม Free memory ทำสิ่งนี้ด้วยมือ

5.4 การตรวจจับการเสร็จสิ้นแบบสำรอง

_checkInferenceCompletionFallback() (SegmentationWidget.py:2618): เมื่อบรรทัด "done with volume" ปรากฏในเอาต์พุตของ nnU-Net ตัวจับเวลาจะตรวจขนาดไฟล์เอาต์พุตทุก 1.5 วินาที; อ่านได้ค่าเท่ากันสองครั้งติดกัน ⇒ บังคับให้เสร็จ แม้สัญญาณของ QProcess ชื่อ finished จะไม่เคยมาถึง ยอมแพ้หลัง 40 ครั้ง (60 วินาที)

ราวกั้นเพิ่มเติม: watchdog ต่อภาพสแกน (itemTimeoutSpinBox ค่าเริ่มต้น 60 นาที) ทำเครื่องหมายภาพสแกนว่าล้มเหลวและไปชุดถัดไป _finishCurrentItem เป็นจุดออกเดียว ป้องกันด้วย _itemFinalized ไม่ให้เดินหน้าซ้ำสอง

5.5 การแก้ภาพสะท้อน (เฉพาะ UniversalLab)

  2. ระนาบซาจิตทัล = ค่าเฉลี่ยของเซนทรอยด์ R ของฟันตัดซี่กลางทั้งสี่ (label 8, 9, 24, 25); ถ้าขาดซี่ใด การแก้ไขจะถูกปฏิเสธ;
  3. สำหรับแต่ละ label ที่มีด้านซ้ายขวา วอกเซลที่อยู่ผิดด้านของระนาบจะได้ค่าของ label สมมาตร (ตารางที่สร้างโดยแทน left ↔ right ในชื่อ); {53, 54, 55} ได้รับการป้องกัน

7. สิ่งที่ทำนายเทียบกับสิ่งที่คำนวณ

บล็อกธรรมชาติที่ไหน
การประมวลผลเบื้องต้น (การสลับแกน การ resample CTNormalization)คำนวณ กำหนดแน่นอน ขับด้วย plans.jsonnnUNetv2_predict process ลูก
การแบ่งส่วนทำนาย เครือข่าย PlainConvUNet 3D, 1 fold, ไม่มี TTAเหมือนกัน
ครอปอัตโนมัติคำนวณ เรขาคณิต (threshold อากาศ + กรอบล้อม)วิดเจ็ต numpy

การสร้าง label map ใหม่คำนวณ ส่งออกครั้งเดียว + LUTวิดเจ็ต VTK/numpy
การแก้ภาพสะท้อนคำนวณ เรขาคณิต (ระนาบซาจิตทัลบนฟันตัด)วิดเจ็ต numpy

การประมาณและตัวป้องกันหน่วยความจำคำนวณ เลขคณิตบน FOV และ planวิดเจ็ต psutil

DentalSegmentator ตีพิมพ์แล้ว:

Dot G., Chaurasia A., Dubois G., Savoldelli C., Haghighat S., Azimian S., Rahbar Taramsari A., Sivaramakrishnan G., Issa J., Dubey A., Schouman T., Gajny L. DentalSegmentator: robust open source deep learning-based CT and CBCT image segmentation. Journal of Dentistry 147:105130, 2024. doi:10.1016/j.jdent.2024.105130 , PMID 38878813

nnU-Net v2 (v2.2 ตามประกาศ Zenodo ของน้ำหนัก) ภาพสแกน CT และ CBCT 470 ชุดจาก 7 สถาบันสำหรับการฝึก 5 โครงสร้าง ทดสอบแบบ hold-out บน 256 ชุด (ภายใน 133 ภายนอก 123): DSC 92.2 ± 6.3% ภายใน 94.2 ± 7.4% ภายนอก dataset.json ที่ส่งมาที่นี่ประกาศ numTraining = 453 สอดคล้องกับคลังข้อมูลที่อธิบาย

ตรวจสอบแล้ว

สำหรับโมเดลนี้ โค้ดและบทความตรงกัน น้ำหนักยังเผยแพร่ภายใต้ CC-BY-4.0 บน Zenodo (concept DOI 10.5281/zenodo.10829674) แต่โมดูลนี้ดึงจาก GitHub releases ไม่ใช่จาก Zenodo

Isensee F., Jaeger P.F., Kohl S.A.A., Petersen J., Maier-Hein K.H. nnU-Net: a self-configuring method for deep learning-based biomedical image segmentation. Nature Methods 18(2):203-211, 2021. doi:10.1038/s41592-020-01008-z

SADT Atlas

อภิธานศัพท์

คำศัพท์ 47 คำที่หน้าเครื่องมือต่าง ๆ ถือว่าผู้อ่านรู้จักอยู่แล้ว นิยามตามที่ ใช้ในคลังโค้ดนี้ ไม่ใช่นิยามเชิงนามธรรม

กรอบพิกัดและเรขาคณิต · การลงทะเบียนภาพ · โครงข่ายและการเรียนรู้ · ข้อความและโมเดลภาษา · กายวิภาคและชนิดภาพ

กรอบพิกัดและเรขาคณิต

direction (เมทริกซ์ทิศทาง)
เมทริกซ์ 3×3 ที่บอกการวางตัวของแกนกริดวอกเซลในพื้นที่ทางกายภาพ เมื่อรวมกับ origin และ spacing จะได้ transform จากดัชนีไปเป็นมิลลิเมตร
พื้นผิวค่าเท่า (isosurface)
พื้นผิวที่เชื่อมทุกจุดในวอลุ่มที่มีค่าความเข้มเท่ากัน AREG_IOSCBCT สกัดพื้นผิวนี้ที่ threshold 400 เพื่อให้ ICP มีเป้าหมายเชิงเรขาคณิต
LPS
Left–Posterior–Superior: แกนทั้งสามชี้ไปทางซ้ายของผู้ป่วย ด้านหลัง และด้านบน เป็นกรอบพิกัดที่ DICOM, ITK และไฟล์ .vtk ของคลังโค้ดนี้ใช้ ALI_CBCT และ ALI_IOS ต่างเขียน "coordinateSystem": "LPS" ลงใน JSON
เมช (mesh)
พื้นผิวที่อธิบายด้วย vertex และหน้าสามเหลี่ยม ต่างจากวอลุ่มของวอกเซล ภาพสแกน IOS เป็นเมช ส่วนภาพ CBCT เป็นวอลุ่ม
marching cubes
อัลกอริทึมที่สร้างพื้นผิวค่าเท่า: เดินไปบนกริดทีละลูกบาศก์และสร้างสามเหลี่ยมที่ตัดผ่าน threshold ที่กำหนดในแต่ละลูกบาศก์ ผลลัพธ์คือเมช ไม่ใช่วอลุ่ม
origin (จุดกำเนิด)
ตำแหน่งทางกายภาพของวอกเซลที่ดัชนี (0,0,0) เป็นข้อมูลเมตาเพียงตัวเดียวในสามตัวที่การครอปเปลี่ยนโดยไม่ต้อง resample
RAS
Right–Anterior–Superior: แบบแผนของ Slicer ซึ่งตรงข้ามกับ LPS ในสองแกนแรก การแปลงระหว่างสองแบบทำเพียงคูณ x และ y ด้วย −1 บั๊กเรื่องเครื่องหมายแทบทั้งหมดในคลังโค้ดนี้สืบย้อนไปได้ถึงการแปลง LPS↔RAS ที่ลืมทำ หรือทำซ้ำสองครั้ง
spacing (ระยะห่างวอกเซล)
ขนาดทางกายภาพของวอกเซลเป็นมิลลิเมตรตามแต่ละแกนทั้งสาม วอลุ่ม "isotropic 0.3" มี spacing [0.3, 0.3, 0.3] การ resample เปลี่ยน spacing แต่การครอปไม่เปลี่ยน
วอกเซล (voxel)
พิกเซลสามมิติ: หนึ่งช่องในกริดของวอลุ่ม เก็บค่าความเข้ม ซึ่งเป็นหน่วย Hounsfield หาก CBCT ได้รับการสอบเทียบ

การลงทะเบียนภาพ

affine
12 องศาอิสระ: แบบแข็งเกร็ง บวกการย่อขยายและการเฉือน เส้นตรงยังคงตรงและขนานกัน แต่ระยะทางไม่คงเดิม
elastix
ไลบรารีการลงทะเบียนภาพที่ควบคุมด้วยไฟล์พารามิเตอร์ AREG_CBCT และ MRI2CBCT เรียกใช้ผ่าน itk-elastix สำหรับการลงทะเบียนภาพแบบวอกเซลต่อวอกเซล
ICP
Iterative Closest Point: สำหรับจุด moving แต่ละจุด หาเพื่อนบ้านที่ใกล้ที่สุดในเป้าหมาย ประมาณ transform แบบแข็งเกร็งที่ทำให้เข้าใกล้กัน แล้ววนซ้ำ ลู่เข้าได้ดีก็ต่อเมื่อจุดเริ่มต้นอยู่ใกล้อยู่แล้ว — จึงต้องจัดแนวล่วงหน้าด้วย landmark เสมอ
Kabsch
อัลกอริทึมที่แก้ปัญหา Procrustes: ย้ายกลุ่มจุดทั้งสองให้มีจุดกึ่งกลางที่ centroid แยกเมทริกซ์ความแปรปรวนร่วมด้วยการแยกค่าเอกฐาน แล้วประกอบการหมุนกลับขึ้นมา การแก้ค่า determinant ช่วยตัดการสะท้อนออก
จุดสังเกตทางกายวิภาค (landmark)
จุดทางกายวิภาคที่ระบุได้ วางด้วยมือหรือทำนายโดยโครงข่าย ใช้เป็นจุดอ้างอิงในการจัดแนว หรือเป็นคู่จุดที่สอดคล้องกันสำหรับการจัดแนวล่วงหน้า เก็บเป็น .mrk.json
mrk.json
รูปแบบรายการจุดของ Slicer (markups) เก็บพิกัด label ของจุด และ coordinateSystem ที่บอกว่าเป็น LPS หรือ RAS
Procrustes
ปัญหาการจัดแนวชุดจุดสองชุดที่จับคู่กันแล้วให้ดีที่สุด: การหมุนและการเลื่อนแบบใดที่ทำให้ผลรวมกำลังสองของผลต่างน้อยที่สุด ต่างจาก ICP ตรงที่รู้คู่ที่สอดคล้องกันล่วงหน้า
การลงทะเบียนภาพ (registration)
การหา transform ที่นำภาพหรือพื้นผิว "moving" เข้าสู่กรอบพิกัดของภาพ "fixed" เรียกว่าแบบตามยาว (longitudinal) เมื่อทั้งสองมาจากผู้ป่วยคนเดียวกันต่างวันเวลา และแบบต่างชนิด (multimodal) เมื่อมาจากเครื่องมือถ่ายภาพต่างชนิดกัน
แข็งเกร็ง (rigid)
transform ที่มี 6 องศาอิสระ: การหมุนสามแกน การเลื่อนสามแกน คงระยะทางไว้ — จึงไม่มีการย่อขยาย ไม่มีการเฉือน ไม่มีการเปลี่ยนรูป
SVD
การแยกค่าเอกฐาน (singular value decomposition) ในที่นี้เป็นเครื่องมือคำนวณเบื้องหลัง Kabsch และเบื้องหลังการประมาณกรอบพิกัดเฉพาะที่จากกลุ่มจุด
tfm
นามสกุลของไฟล์ transform ของ ITK เก็บเมทริกซ์ ไม่ใช่ภาพ เมื่อโมดูลไม่เขียนไฟล์นี้ ผู้ใช้จะปรับผลลัพธ์ด้วยเมาส์เองไม่ได้ — ซึ่งเป็นกรณีของ AREG_IOSCBCT

โครงข่ายและการเรียนรู้

agent การเรียนรู้แบบเสริมกำลัง (reinforcement learning)
ALI_CBCT ไม่ได้แบ่งส่วน แต่เคลื่อน agent ไปในวอลุ่มทีละก้าว แต่ละตัวเรียนรู้ที่จะเข้าใกล้ landmark ของตน การค้นหาหยุดเมื่อ agent เริ่มแกว่งไปมา แล้วดำเนินต่อที่ความละเอียดสูงขึ้น
checkpoint
ไฟล์น้ำหนักที่ฝึกแล้ว การอ่าน hyperparameter ในไฟล์นี้มักเป็นวิธีเดียวที่เชื่อถือได้ในการรู้ว่าโมเดลทำอะไรจริง — ความไม่ตรงกันระหว่างโค้ดกับบทความหลายกรณีในคลังโค้ดนี้ยืนยันได้ด้วยวิธีนี้
cross-encoder
โมเดลที่รับคำค้นและเอกสารพร้อมกันแล้วให้คะแนนความเกี่ยวข้อง ต่างจาก embedding ที่เข้ารหัสแยกกันแล้วจึงเปรียบเทียบ แม่นยำกว่า แต่คำนวณล่วงหน้าไม่ได้
การกลั่นโมเดล (distillation)
การฝึกโมเดลขนาดเล็กให้ทำงานเลียนแบบโมเดลขนาดใหญ่ MiniLM-L6 ที่ Agent ใช้ได้มาจากการกลั่นโมเดล 12 ชั้น
EfficientNet
ตระกูลโครงข่ายคอนโวลูชันสำหรับภาพที่ปรับขนาดความลึก ความกว้าง และความละเอียดไปพร้อมกัน เป็นสาขาหลายมุมมองของ DOCShapeAXI
fly-by
เทคนิคการ render เมช 3D จากหลายมุมมอง รันการทำนายของโครงข่าย 2D บนแต่ละมุมมอง แล้วฉายผลทำนายกลับลงบนพื้นผิว ช่วยเลี่ยงการทำคอนโวลูชันใน 3D
Grad-CAM
วิธีอธิบายผลของโมเดล: gradient ของคลาสที่ทำนายใช้ถ่วงน้ำหนัก activation map ของชั้นหนึ่ง ได้เป็นแผนที่ของสิ่งที่มีผล ใน DOCShapeAXI ครอบคลุมเฉพาะสาขาหลายมุมมอง
heatmap
แผนที่ที่โครงข่ายทำนาย ซึ่งค่าสูงสุดบอกตำแหน่งที่ต้องการหา ALI_IOS ใช้วิธีนี้ระบุตำแหน่ง landmark บนภาพที่ render
LightGBM
ไลบรารี gradient-boosted decision tree VFACE ฝังไว้สามตัว เป็นแบบไบนารีและแบบมีผู้สอน ขณะที่บทความของ VFACE อธิบายการจัดกลุ่มแบบไม่มีผู้สอน
MONAI
ไลบรารี PyTorch เฉพาะทางภาพทางการแพทย์: transform สถาปัตยกรรม การอนุมานแบบ sliding window
nnU-Net
เฟรมเวิร์กการแบ่งส่วน (segmentation) ที่เลือกสถาปัตยกรรม การเตรียมข้อมูล และ hyperparameter เองจากข้อมูล เป็นสิ่งที่ AMASSS ใช้อยู่ในปัจจุบัน แม้บทความจะอธิบาย UNETR
UNETR
สถาปัตยกรรมการแบ่งส่วนที่มี encoder แบบ transformer และ decoder แบบคอนโวลูชัน อธิบายไว้ในบทความของ AMASSS แต่ในโค้ดถูกแทนที่ด้วย nnU-Net

ข้อความและโมเดลภาษา

BART
โมเดล encoder–decoder ที่ฝึกไว้ล่วงหน้าสำหรับการสร้างข้อความ MedX ใช้รุ่น large-cnn ที่ปรับแต่งสำหรับการสรุปความ
GGUF
รูปแบบไฟล์น้ำหนักของ llama.cpp ออกแบบมาสำหรับการอนุมานบน CPU และ quantisation เป็นรูปแบบที่ทั้ง Ollama และ CNE ต้องใช้
llama.cpp
เอนจินอนุมานสำหรับโมเดลภาษา เขียนด้วย C++ ปรับให้เหมาะกับ CPU ทำงานอยู่ภายใต้ Ollama และทำงานโดยตรงภายใต้ CNE
Ollama
เซิร์ฟเวอร์ภายในเครื่องที่ดาวน์โหลด cache และให้บริการโมเดลภาษาผ่าน HTTP API ที่พอร์ต 11434 ตัดสินใจใช้ GPU เอง — จึงเป็นที่มาของข้อควรระวังเรื่องการติดตั้งผ่าน snap
Presidio
ไลบรารีของ Microsoft สำหรับตรวจหาและแทนที่ข้อมูลส่วนบุคคลในข้อความ ผสมกฎเข้ากับการรู้จำชื่อเฉพาะ (named-entity recognition)
quantisation
การลดความแม่นยำของน้ำหนัก — โดยทั่วไปจาก 16 บิตลงเหลือ 4 — เพื่อลดขนาดและเร่งการอนุมาน โดยแลกกับคุณภาพบางส่วน Q4_K_M คือชื่อของรูปแบบหนึ่ง
spaCy
ไลบรารีประมวลผลภาษาธรรมชาติ ให้ Presidio ใช้รู้จำชื่อเฉพาะ — บุคคล สถานที่ วันที่

กายวิภาคและชนิดภาพ

ส่วนโค้งฟัน (arch)
ฟันทั้งชุดบนขากรรไกรข้างหนึ่ง บนและล่างถูกจัดการเป็นอินพุตสองชุดแยกกันในแทบทุกโมดูล
CBCT
Cone Beam Computed Tomography: เครื่องสแกนลำรังสีรูปกรวย ให้วอลุ่ม 3D ปริมาณรังสีต่ำ ความละเอียดเชิงพื้นที่สูง แต่ค่าความเข้มมักไม่ได้สอบเทียบเป็นหน่วย Hounsfield — ทำให้ threshold ที่ฝังตายตัวในโค้ดเปราะบาง
condyle (ปุ่มข้อต่อขากรรไกร)
หัวของขากรรไกรล่าง ซึ่งขยับข้อต่ออยู่ในแอ่งกระดูกขมับ เป็นโครงสร้างสำคัญในการวิเคราะห์ความไม่สมมาตร
FOV
Field Of View: ขอบเขตทางกายภาพที่การถ่ายภาพครอบคลุม "FOV เล็ก" เก็บภาพได้เพียงบริเวณเดียว ซึ่งเปลี่ยนว่าจะใช้โมเดลใดได้
IOS
Intra Oral Scan: รอยพิมพ์ฟันแบบออปติคัลของส่วนโค้งฟัน ได้จากเครื่องสแกนในช่องปาก เป็นพื้นผิว ไม่ใช่วอลุ่มเลย
บดเคี้ยว (occlusal)
เกี่ยวกับพื้นผิวสัมผัสระหว่างฟันบนและฟันล่าง suffix O ของ landmark (UR6O) หมายถึงจุดบดเคี้ยวของฟันซี่นั้น
TMJ
Temporomandibular Joint ข้อต่อขากรรไกร เป็นเป้าหมายของ MRI2CBCT และส่วนหนึ่งของ MedX
Universal_ID
อาร์เรย์ label ที่ dentalmodelseg ใส่ไว้บนเมช IOS: แต่ละ vertex ได้รับหมายเลขของฟันที่ตนเป็นส่วนหนึ่ง ตามระบบหมายเลข universal

AREG_IOSCBCT, legacy: โค้ด

สำหรับนักพัฒนา: โมดูล Slicer แบบ legacy AREG_IOSCBCT ทำอะไรในโค้ด (SlicerAutomatedDentalTools ที่ 3c67957) พร้อมอ้างอิง file:line ซิกเนเจอร์ อาร์กิวเมนต์ สภาพแวดล้อม และข้อควรระวัง คำอธิบายที่อ่านง่ายของไปป์ไลน์เดียวกัน พร้อมคณิตศาสตร์ อยู่ในหน้าแอตลาส พอร์ต VISOR มีหน้าโค้ดของตัวเอง

โค้ด แอตลาส (คำอธิบาย) ยังไม่เผยแพร่ areg_ioscbct Python ของ Slicer ไม่มีโครงข่ายใน CLI VISOR คู่มือ บรรณานุกรม

ไม่เกี่ยวกับ AREG_IOS ซึ่งเป็นแบบตามยาว (T1 → T2 ชนิดภาพเดียวกัน): ที่นี่กลุ่มจุดสองกลุ่มมาจากเซนเซอร์ต่างกัน และไม่มี "แพตช์คงที่" ร่วมกัน

การจับคู่สองขั้นตอนต่อเนื่องกัน ไม่มีโครงข่ายภายใน CLI:

  1. landmark occlusal 12 จุดที่ทำนายทั้งสองฝั่งด้วยโครงข่ายสองแบบ (ALI_CBCT บนวอลุ่ม, ALI_IOS บนเมช) → transform แบบ Procrustes แข็งเกร็ง (vtkLandmarkTransform) ที่ใช้เป็นการจัดแนวล่วงหน้า;
  2. ICPของพื้นผิว IOS ไปยังisosurfaceของ CBCT ที่สกัดด้วย marching cubes ที่ ระดับที่อ่านจากภาพสแกน (400 เป็นเพียงค่าสำรอง ดู 4.1)

ดังนั้น CLI เองจึงเป็นเรขาคณิตล้วน ๆ ความฉลาดอยู่ต้นน้ำ ในโมดูลที่ orchestrator วางซ้อนไว้ข้างหน้า

โค้ดสองชุด

ทุกอย่างที่มีเลขกำกับด้านล่างอธิบายโมดูล Slicer แบบ legacy (SlicerAutomatedDentalTools ที่ 3c67957, 2026-10-26) พอร์ต VISOR ซึ่งรันเครื่องมือเดียวกันบนเซิร์ฟเวอร์ มีหน้าของตัวเอง: AREG_IOSCBCT บน VISOR หมายเหตุที่เปิดกล่องบางกล่องด้านล่าง (“เฉพาะ Legacy”, “เป็นจริงใน VISOR ด้วย”) เปรียบเทียบกับพอร์ตนั้นที่ SADT-VISOR 6ba2a78 ในหมายเหตุเหล่านั้น ioscbct/ หมายถึง SADT-VISOR tools/AREG/AREG_IOSCBCT/src/sadt_areg_ioscbct/

แก้ไขแล้ว: ระดับ isosurface ถูกอ่านจากภาพสแกน (3c67957)

callout ฉบับก่อนหน้าบอกว่า threshold 400 ถูกกำหนดตายตัวและไม่เคยเปิดให้ปรับ ที่ 3c67957 ไม่เป็นทั้งสองอย่าง: ระดับคือจุดกึ่งกลางระหว่างเคลือบฟันกับเนื้อเยื่ออ่อนที่วัดจากภาพสแกน 400 คือค่าสำรอง และ AREG_CBCT_SURFACE_THRESHOLD ใช้แทนที่ได้ (AREG_IOSCBCT/AREG_IOSCBCT.py:92,847-966) ความไวต่อการสร้างภาพยังเกิดในกรณีใช้ค่าสำรอง ซึ่งล็อกรายงานเป็นคำเตือน

ใน VISOR ใช้กฎเดียวกัน (SADT-VISOR ioscbct/volume.py:96-117,148-175) และค่าสำรองคือ 400 (ioscbct/volume.py:36) แต่การแทนที่โดยระบุชัดเจนหายไป: ดูข้อค้นพบเรื่องระดับที่ AREG_IOSCBCT บน VISOR

  • run_icp_point_to_plane เป็น point-to-plane ตามชื่อ ใช้เวกเตอร์แนวฉาก: เวกเตอร์แนวฉากของ CBCT ตัดสินว่าการจับคู่ใดถูกเก็บ และให้ระนาบสัมผัสของขั้นตอน หน้าฉบับก่อนหน้าบอกว่าฟังก์ชันเป็น point-to-point โดยคำนวณเวกเตอร์แนวฉากแล้วทิ้ง ซึ่งไม่ตรงกับ 3c67957 (AREG_IOSCBCT.py:579-608,688-692) ขั้น Procrustes (:609) เป็นทางสำรองเมื่อระบบเสื่อม
  • สองชนิดภาพ CBCT เพียงหนึ่งอันต่อคีย์ผู้ป่วย แต่ต้องมีทั้งสองส่วนโค้งฟัน ผู้ป่วยที่สแกนเฉพาะส่วนโค้งฟันบนจะเกิด KeyError ('ios_lower') และหลุดจากการรัน: ข้อผิดพลาดถูกบันทึกพร้อม traceback (AREG_IOSCBCT.py:1303-1305) และผู้ป่วยรายอื่นดำเนินต่อ
  • CBCT ต้องเป็น .nii.gz แต่ NumberScan ฝั่งวิดเจ็ตนับ .nrrd .nii .gipl และรูปแบบ .gz ของมัน (IOSCBCT.py:25): แถบความคืบหน้าจึงประกาศผู้ป่วยที่ CLI จะไม่เห็นเลย
  • ช่วงเวลาถูกจำกัดที่ T0–T2 โดย [Tt]([0-2]): ดูคอมเมนต์ TIMEPOINT-SUFFIX ที่ AREG_IOSCBCT.py:1068 และหมายเหตุกลางใน AREG_CBCT/AREG_CBCT_utils/utils.py:56; _T10 ถึง _T29 ถูกอ่านเป็น T1 หรือ T2
  • ตัวระบุชนกันหลังทำให้เป็นมาตรฐาน: P001 และ P1 กลายเป็นคีย์เดียวกัน จึงเป็นผู้ป่วยคนเดียวกัน ไม่มีอะไรตรวจจับเรื่องนี้ใน getPatients มีเพียงวิดเจ็ตที่เตือนภายหลังว่ามีผู้สมัครหลายราย (Review.py:280)
  • โค้ดที่ตายครึ่งหนึ่ง: load_data() อ่าน lm_cbct_u/l และ lm_ios_u/l ผ่าน get_landmarks() (ดัชนีตามตำแหน่ง ไม่มีป้าย AREG_IOSCBCT.py:971-974) และ main() เขียนทับทั้งสี่ทันทีด้วยอาร์เรย์ที่จับคู่ตามป้ายจาก _pair_landmarks() (AREG_IOSCBCT.py:1204-1207) ไม่ได้สูญเปล่าทั้งหมด: load_data() ใช้อาร์เรย์ CBCT เพื่ออ่านระดับ contour และตัดสินว่า landmark ใดอยู่บนเคลือบฟัน (:988-999) และคืนคำตัดสินนั้นเป็น on_enamel ซึ่ง main() ส่งให้ align_by_landmarks (:1217-1226); อาร์เรย์สี่ตัวที่คืนมาคือส่วนที่ไม่ได้ใช้ เช่นเดียวกัน PatientScanLandmark (IOSCBCT.py:33) ไม่ถูกเรียกที่ใดในโมดูลนี้ (คำนิยามอื่นเพียงที่เดียวอยู่ใน ASO_Method/CBCT.py)
  • DisplayAREGIOSCBCT(0) (นิยามครั้งเดียว Progress.py:127) ถูกสร้างด้วย nb_progress_total = 0 ในทั้งสามโหมด: self.progress / 0 → ZeroDivisionError ถ้าแถบความคืบหน้าถูกอัปเดต มันถูกอัปเดตเฉพาะเมื่อเงื่อนไข is_event(progress, PATIENT_DONE) and updateProgressBar == False (Progress.py:141; PATIENT_DONE = 200, ADT/ADTLib/progress_protocol.py:36) ซึ่งอธิบายว่าทำไมไม่มีใครสังเกต
  • fitness และ inlier_rmse ถูกอ่านหลังลูป ICP เมื่อ max_iterations = 0 (เป็นไปไม่ได้ที่นี่ แต่เปราะบาง) หรือออกที่ break แรกเมื่อการจับคู่ < 3 ตัวแปรเหล่านี้ถูกนิยามอยู่ แต่โค้ดไม่ป้องกันกรณีนั้น
  • pyvista ถูกติดตั้งใน Python ของ Slicer ตรึงที่เวอร์ชัน 0.47.3 เป็น dependency หนักที่มีอยู่เพื่อโมดูลนี้เท่านั้น (pv.wrap, contour, transform, read, save) และแทนด้วย VTK โดยตรงได้ ซึ่งมีอยู่แล้ว
การจัดแนวล่วงหน้าอาจเป็นเมทริกซ์เอกลักษณ์โดยไม่มีสัญญาณ

Legacy (3c67957); เบาลงใน VISOR การจัดแนวล่วงหน้าของ legacy ถูกข้ามพร้อมบรรทัดในล็อก (AREG_IOSCBCT.py:416,425@3c67957) VISOR ใส่คำตัดสินไว้ในรายงาน ต่อเมช: prealignment.accepted และ reason (ioscbct/geometry.py:293-294,306-307,319-321) การจัดแนวล่วงหน้าที่ถูกปฏิเสธยังไม่ใช่ข้อผิดพลาด: เมชจะถูกเขียนถ้า ICP ยังใช้ได้ และ ICP ที่จับคู่ได้น้อยกว่า 5% ของส่วนโค้งฟันจะถูกปฏิเสธ (ioscbct/pipeline.py:192-202)

บันทึกเป็นคำเตือน ไม่เคยเป็นข้อผิดพลาด: การรันทั้งหมดอาจไม่ได้ประโยชน์จากการจัดแนวล่วงหน้าเลยและยังคงให้ไฟล์ออกมา ตรวจบรรทัดล็อก Skipping the pre-alignment ก่อนพึ่งพาการรันเป็นชุด

8. วรรณกรรม

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

ยังไม่เผยแพร่

ไม่มีบทความใดครอบคลุม AREG_IOSCBCT ตามที่ implement ที่นี่ สายงานที่กลุ่มเผยแพร่ครอบคลุมการจัดทิศทางและการลงทะเบียน CBCT (Automated Orientation and Registration of CBCT Scans, LNCS 2023) และการลงทะเบียน IOS แบบตามยาว (AReg IOS, LNCS 2023) โมดูล landmark ที่มันใช้แต่ละอันมีบทความของตัวเอง (ALI_CBCT) ส่วนที่เป็น IOS↔CBCT ต่างชนิดภาพดูเหมือนเป็นงานประกอบภายในที่ยังไม่เผยแพร่

งานในแนวระเบียบวิธีใกล้เคียงในวรรณกรรม เพื่อเปรียบเทียบ ไม่ใช่เป็นคำอธิบายของโค้ดนี้:

  • Novel Procedure for Automatic Registration between CBCT and Intraoral Scan Data Supported with 3D Segmentation: ปัญหาเดียวกัน แต่มีการแบ่งส่วนตัวฟันทั้งสองฝั่ง แล้ว RANSAC + ICP ความคลาดเคลื่อนที่รายงาน 0.234 ± 0.019 mm AREG_IOSCBCT เลือกทางที่เบากว่าอย่างชัดเจน: landmark แทนการแบ่งส่วนเชิงปริมาตร isosurface ที่กำหนด threshold แทนตัวฟันที่แบ่งส่วน
  • Automatic multimodal registration of CBCT and intraoral scans: a systematic review and meta-analysis: การทบทวนอย่างเป็นระบบ วางแนวทางเรขาคณิต (เชื่อถือได้ ต้นทุนต่ำ) เทียบกับแนวทางที่เรียนรู้
  • Fully automatic integration of dental CBCT images and full-arch intraoral impressions: รูปแบบที่ระบุทีละซี่และแก้ความคลาดเคลื่อนจากการเย็บภาพ

ข้อมูลอ้างอิงในที่เก็บ:

  • SlicerAutomatedDentalTools
  • AREG (คลังโค้ดต้นฉบับ)
  • ALIDDM: น้ำหนักโมเดล ALI_IOS

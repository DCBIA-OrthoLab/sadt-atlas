data_type มีช่องว่าง ("Mandibular Condyle") csv จึงชื่อ files_Mandibular Condyle.csv csv ถูกสร้างใหม่เฉพาะเมื่อยังไม่มีอยู่ (DOCShapeAXI_CLI.py:285): การเพิ่มเมชลงโฟลเดอร์อินพุตโดยไม่ล้างโฟลเดอร์ผลลัพธ์จะไม่ทำให้เมชเหล่านั้นถูกประมวลผล

3.2 การทำให้เรขาคณิตเป็นมาตรฐาน

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

EvalTransform → UnitSurfTransform → utils.GetUnitSurf → ScaleSurf:

  1. center = จุดกึ่งกลางของbounding box (ไม่ใช่ centroid)
  2. เลื่อนจุดมาที่ center นี้
  3. scale factor 1 / ||bounds_max - center|| ใช้อย่างสม่ำเสมอ

เมชจึงพอดีภายในทรงกลมหนึ่งหน่วย โดยไม่ขึ้นกับขนาดจริง ข้อมูลของขนาดสัมบูรณ์ทั้งหมดสูญหาย: condyle เล็กและ condyle ใหญ่ที่มีรูปทรงเดียวกันเหมือนกันทุกประการสำหรับโครงข่าย

บั๊กที่ยืนยันแล้ว (แพ็กเกจ shapeaxi ตามที่ติดตั้งสำหรับโมดูล legacy)

ลงวันที่แล้ว: อ่านใน shapeaxi 1.0.10 (สำเนาที่ติดตั้งในสภาพแวดล้อม shapeaxi ของ Slicer 5.12.3) และใน 1.1.1 (ดาวน์โหลดมาสำหรับรอบนี้ นอกจาก __about__.py แล้ว สองแพ็กเกจเหมือนกันทุกไบต์) และ transform เหมือนกันใน 2.0.2 และ 2.0.3 เครื่องมือ VISOR สร้างชุดข้อมูลแบบเดียวกัน โดยส่ง scale_factor ให้ EvalTransform ในทั้งสองรอบ (SADT-VISOR tools/DOCShapeAXI/src/sadt_docshapeaxi/engine.py:25-28) เทียบกับ shapeaxi==1.1.1 ที่ปักหมุด (pyproject.toml:30) 1.1.1 ก็เพิกเฉยต่อค่านั้นเช่นกัน: saxi_transforms.py ของมันเหมือนกับของ 1.0.10 (DOCShapeAXI บน VISOR) ควรรู้: saxi_predict อ่าน model.hparams.scale_factor (0.0507 ใน checkpoint ของ condyle) และส่งให้ EvalTransform(scale_factor) (DOCShapeAXI_CLI.py:209) แต่ UnitSurfTransform.__call__ (saxi_transforms.py:48-57) เรียก utils.GetUnitSurf(surf) โดยไม่ส่งต่อค่า เมื่ออินพุตเป็น vtkPolyData scale factor ที่เรียนรู้ตอนฝึกจึงถูกเพิกเฉยอย่างเงียบ ๆ ตอน inference และถูกแทนด้วยการทำให้เป็นมาตรฐานต่อรายบุคคล นี่เป็นบั๊กในแพ็กเกจ shapeaxi ไม่ใช่ในรีโพซิทอรี แต่มันเปลี่ยนการประมวลผลเบื้องต้นจริง saxi_gradcam สร้างชุดข้อมูลด้วย EvalTransform() ไม่มีอาร์กิวเมนต์: สองรอบจึงสอดคล้องกันเอง

3.3 สิ่งที่ DataLoader คืนมา

SaxiDataset(..., CN=True, class_column=None, scalar_column=None) → (V, F, CN) ต่อบุคคล:

  • V: vertex (1, Nv, 3) หลังทำให้เป็นมาตรฐาน
  • F: สามเหลี่ยม (1, Nf, 3)
  • CN: normal ที่เข้ารหัสเป็นสี utils.ComputeNormals แล้ว GetColorArray(surf,"Normals") หารด้วย 255 → (1, Nv, 3) ใน [0,1]

ไม่มีสเกลาร์ของเมชถูกอ่านเลย (surf_property=None): เข้าไปเฉพาะเรขาคณิตและ normal batch_size=1 ไม่มี padding เมชขนาดต่างกันจึงผ่านได้โดยไม่มีปัญหา

4.2 สถาปัตยกรรมที่ใช้จริง

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

นี่ไม่ใช่ PointNet และไม่ใช่ fly-by-CNN แบบ ResNet-18 จากบทความ ShapeAXI ดั้งเดิม SaxiMHAFBClassification (MHA Fly-By) มีสองสาขาที่รวมกันตอนท้าย

ตรวจสอบแล้ว (checkpoint แบบ legacy ไฟล์เดียวกันใน VISOR)

data manifest ของ VISOR-serve ระบุ checkpoint ห้าไฟล์เดียวกันจาก release shapeaxi-ckpt-v1 เดียวกัน (scripts/data-manifest.yml:597-614) และแคตตาล็อกของเครื่องมือใช้คีย์ตามคลาสโครงข่ายเดียวกัน (catalog.py:24-25,50-71) ค่าด้านล่างไม่ได้วัดซ้ำบนสำเนาของ VISOR (DOCShapeAXI บน VISOR) ค่าด้านล่าง (K=128, 256 head, 42 มุมมอง, image_size=224…) ยืนยันจากการอ่านครั้งก่อนของ hyper_parameters และบัฟเฟอร์ ico_verts ของ checkpoint condyles_4_class.ckpt การอ่านนั้นไม่ได้ทำซ้ำในรอบนี้ (ไม่มี .ckpt บนเครื่อง) ตัวเลขชุดเดียวกันนี้เป็นค่าเริ่มต้นในโค้ดด้วย (saxi_nets_lightning.py:2392-2405, shapeaxi 1.0.10)

สาขา A: point cloud

  • sample_points_from_meshes(X_mesh, 4096) (pytorch3d): สุ่มตัวอย่างอย่างสม่ำเสมอ4096 จุดบนพื้นผิว
  • MHAEncoder: Linear(3→256) แล้ว 4 ขั้นด้วย sample_levels = [4096, 2048, 512, 128] ในแต่ละขั้น MHA_KNN (multi-head attention ที่จำกัดอยู่กับเพื่อนบ้านใกล้สุด K=128 256 head) แล้ว FeedForward แบบ residual (hidden 64) ระหว่างขั้น สุ่มลดจำนวนจุดลงถึงระดับถัดไป พร้อมส่งดัชนีต่อไปเพื่อสะสมน้ำหนักต่อจุดเดิม (x_w)
  • Linear(256→256), FeedForward แล้ว SelfAttention (additive attention Linear(256→64) → tanh → Linear(64→1) → sigmoid ทำให้เป็นมาตรฐานแล้วรวมแบบถ่วงน้ำหนัก) ซึ่งลด 128 โทเค็นเหลือเวกเตอร์ 256 ตัวเดียว

สาขา B: multi-view

  • กล้องที่ vertex ของicosahedron ที่แบ่งย่อย (subdivision_level=2, radius=1.35: ค่าเริ่มต้นของ --radius, saxi_nets_lightning.py:2396 รัศมีที่ใช้จริงคือ self.hparams.radius, :2371 อ่านจาก checkpoint และไม่มี checkpoint ให้อ่านซ้ำ) บัฟเฟอร์ ico_verts ของ checkpoint มีรูปร่าง (42, 3): 42 มุมมองต่อบุคคล
  • การเรนเดอร์ด้วย pytorch3d: FoVPerspectiveCameras, look_at_rotation ไปยังจุดกำเนิด, AmbientLights (ไม่มีการแรเงาตามทิศทาง), HardPhongShader, RasterizationSettings(image_size=224, blur_radius=0, faces_per_pixel=1, max_faces_per_bin=200000)
  • แต่ละมุมมองคือเทนเซอร์ 4 ช่อง: RGB (normal ที่เข้ารหัสเป็นสี ตั้งเป็น TexturesVertex) บวก z-buffer จึงได้ in_channels=4
  • TimeDistributed(EfficientNetBN('efficientnet-b0', spatial_dims=2, in_channels=4, num_classes=256)) จาก MONAI: 42 มุมมองถูกแผ่เข้ามิติ batch ผ่าน CNN ตัวเดียวกัน แล้ว reshape กลับเป็น (1, 42, 256)
  • FeedForward, nn.MultiheadAttention(256, 256 heads, batch_first=True) เป็น self-attention ข้าม 42 มุมมอง แล้ว SelfAttention → เวกเตอร์ 256

การรวม torch.cat([x_points, x_views], dim=1) → 512 แล้ว fc = Linear(512, num_classes) สำหรับ regression ใช้ Linear(512, 1) และ loss แบบ MSE

การเรนเดอร์ทำใหม่ทุกรอบ: ไม่มีแคชภาพ

  • classification: เก็บเฉพาะ argmax ความน่าจะเป็นจาก softmax ถูกคำนวณแล้วทิ้ง ไม่มีค่าความมั่นใจออกจากโมดูล
  • regression: ค่าดิบจาก Linear(512,1) ถูกเขียนตามเดิม (อัตราส่วนการอุดตัน ในสเกล 0–100 ตอนฝึก)
  • softmax ไม่มีผลต่อ argmax อยู่แล้ว

รายละเอียดการฝึกที่เห็นได้ในโค้ดต้นทาง: ใน classification เป้าหมายไม่ใช่ one-hot แต่เป็นความน่าจะเป็นของคลาสแบบ soft (soft_class_probabilities: Gaussian ที่มีศูนย์กลางที่ [12.5, 37.5, 62.5, 87.5] ด้วย widths = 12.5) สี่คลาสความรุนแรงจึงเป็นควอร์ไทล์ของปริมาณต่อเนื่องในสเกล 0–100 ซึ่งอธิบายว่าทำไมมีโมเดล regression บนชุดข้อมูลทางเดินหายใจเดียวกัน

b) หนึ่งแผนที่ต่อคลาส ลูปบน for class_idx in range(num_classes) ด้วย mv_cam.attribute(inputs=(X_pc, X_views), target=class_idx, attr_dim_summation=False): Captum ย้อนส่ง logit ของคลาส class_idx ไปยัง activation ของบล็อก คูณด้วยเกรเดียนต์เฉลี่ย และคืนเทนเซอร์ที่ความละเอียดของแผนที่ activation (7×7 สำหรับ EfficientNet-B0 บน 224×224) สำหรับทั้ง 42 มุมมองพร้อมกัน attr_dim_summation=False คงมิติของช่องไว้ ซึ่งถูกยุบทันทีหลังจากนั้นด้วย mv_att.sum(dim=1)

c) การปรับสเกล (scale_cam_image, DOCShapeAXI_CLI.py:46 ดัดแปลงจาก pytorch-grad-cam): cv2.resize เป็น 224×224 clip ที่เปอร์เซ็นไทล์ที่ 1 และ 99 แล้วแมปแบบ affine เข้า [-1, 1] การ clip เปอร์เซ็นไทล์กันไม่ให้พิกเซลผิดปกติเพียงจุดเดียวกลืนช่วงไดนามิกทั้งหมด ผลลัพธ์จึงมีเครื่องหมาย ไม่ใช่ความน่าจะเป็น การแมปหารด้วย max - min ของแผนที่ที่ clip แล้วโดยไม่มีตัวป้องกัน (DOCShapeAXI_CLI.py:58): แผนที่ที่ทุกค่าเท่ากันให้ 0/0 พื้นผิวจึงได้ค่า NaN VISOR เพิ่มตัวป้องกัน (SADT-VISOR pipeline.py:192-197)

d) การฉายกลับลงเมช (gradcam_process ใน shapeaxi อ่านใน 1.0.10 saxi_gradcam.py:112-144 เหมือนกันใน 1.1.1) แกนกลางของกลไก:

  • PF คือ pix_to_face ของ rasterizer: สำหรับทุกพิกเซลของทุกมุมมอง ดัชนีของสามเหลี่ยมที่มองเห็น หรือ -1 บนพื้นหลัง (saxi_nets_lightning.py:2455-2456) ค่าของพิกเซลถูกพากลับไปที่หน้า
  • หน้าเริ่มต้นที่ 0 และการอัปเดตคือ maximum(old, new) ดังนั้นข้ามมุมมอง การรวมค่าเป็นค่าสูงสุด ไม่ใช่ค่าเฉลี่ย และค่าลบไม่เคยรอด: บนเมชช่วงคือ [0, 1] ค่าของหน้าจึงเป็น max(0, max over views) ไม่ใช่ max s บริเวณที่เห็นครั้งเดียวและถูกตัดสินว่าเด่นจะคงค่าไว้
  • ภายในหนึ่งมุมมอง หลายพิกเซลแสดงหน้าเดียวกัน P_faces[:, pf] = ... จึงเขียนผ่านดัชนีที่ซ้ำ และ PyTorch ไม่บอกว่าการเขียนครั้งไหนถูกเก็บ: ไม่ใช่ค่าสูงสุดของพิกเซล ทดลองบน CPU กับ torch 2.12.1 (ดัชนี [0,0,0,1,-1,-1], ค่า [.9,.1,.5,.3,.8,.2]): หน้า 0 จบที่ 0.5 ซึ่งเป็นค่าสุดท้ายของสามพิกเซล ไม่ใช่ 0.9 ไม่ได้ทดลองบน GPU ซึ่งไม่รับประกันลำดับ
  • สำหรับพิกเซล -1 การทำดัชนีเดียวกันเขียนลงในหน้าสุดท้ายของเมช (ดัชนีลบของ Python) ในทุกมุมมอง ค่าของหน้านั้นคือสิ่งที่พื้นหลังเขียน การทดสอบเดียวกันแสดงว่าหน้าสุดท้ายถูกเขียนทับ (0.2) เพียงหนึ่งหน้าจากทั้งเมช
  • ขั้น face-to-vertex หยาบ: ค่าของแต่ละหน้าถูกเขียนลงในvertex แรกของมัน (F[0,:,0]) vertex ที่เป็น vertex แรกของหลายหน้าเก็บค่าเพียงหนึ่งในนั้น (ดัชนีซ้ำอีกครั้ง) vertex ที่ไม่เคยเป็นจุดแรกของสามเหลี่ยมใดค้างอยู่ที่ -1 แล้วถูกรีเซ็ตเป็น 0 ด้วยบรรทัดสุดท้าย แผนที่จึงกระจายไปด้วยศูนย์เชิงโครงสร้าง
  • หน้าที่ไม่เคยถูก rasterize (ด้านใน, ส่วนที่ถูกบังถาวร) ค้างอยู่ที่ 0

หมายเหตุเรื่องเวอร์ชัน shapeaxi 2.0.2 และ 2.0.3 ซึ่งเป็นสิ่งที่ตัวติดตั้งดึงมาทุกวันนี้ (shapeaxi>=2.0.2) มีฟังก์ชันเดียวกันแต่ไม่มีบรรทัดสุดท้าย (saxi_gradcam.py:31-62 ใน 2.0.2: ไม่มี V_gcam[V_gcam<0]=0) vertex ที่ไม่ใช่ vertex แรกของใครจึงจะค้างที่ -1 ที่นั่น โมดูลนี้รันบน 2.x ไม่ได้อยู่แล้ว (ดูบั๊กด้านล่าง) พฤติกรรมที่อธิบายตรงนี้จึงเป็นของ 1.x ที่คำสั่งถูกเขียนให้

1. เฟรมเวิร์ก ShapeAXI: Shape Analysis Explainability and Interpretability, Prieto, Miranda, Gurgel, Anchling, Hutin, Barone, Al Turkestani, Aliaga, Yatabe, Bianchi, Cevidanes, Proc. โค้ดต่างจากบทความ (เป็นจริงใน VISOR ด้วย)

เป็นจริงใน VISOR ด้วย: เครื่องมือโหลดโครงข่าย SaxiMHAFBClassification และ SaxiMHAFBRegression ตัวเดียวกัน (SADT-VISOR catalog.py:24-25,50-71 ดูDOCShapeAXI บน VISOR) โค้ดต่างจากบทความ บทความอธิบายการเรนเดอร์ multi-view บนการแบ่งย่อย icosahedron ที่ประมวลผลด้วย ResNet-18 บวก additive attention โดยจัดการ condyle เป็นการจำแนก binary checkpoint ที่แจกจ่ายที่นี่คือโมเดล SaxiMHAFB*: EfficientNet-B0 บน 42 มุมมอง บวกสาขา point cloud ที่สอง ด้วย KNN attention ซึ่งไม่มีในบทความ และมี checkpoint condyles_4_class ที่ความรุนแรง 4 คลาส อย่านำตัวเลขของบทความ SPIE ไปนำเสนอเป็นของโมเดลที่ดาวน์โหลด

2. ชุดข้อมูลทางเดินหายใจ Explainable Artificial Intelligence to Quantify Adenoid Hypertrophy-related Upper Airway Obstruction using 3D Shape Analysis, Mattos et al., J Dent 2025 ฉบับนี้อธิบายสถาปัตยกรรมของโค้ดตรงทุกประการ: สาขา multi-view EfficientNet-B0 ที่ pretrain บน ImageNet + multi-head attention, สาขา point cloud 4096 จุดด้วย KNN attention และ explainability ผ่าน "SurfGradCAM" กลไกจาก§5 ทั้งสามงาน (4 คลาส, binary, regression อัตราส่วนการอุดตัน) สอดคล้องกับ checkpoint airways_* ทั้งสาม AUC 0.77–0.94, R = 0.854 สำหรับอัตราส่วน

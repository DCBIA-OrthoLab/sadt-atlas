การจำแนกเมช .vtk ด้วยโครงข่ายสองสาขา (point cloud แบบ multi-head attention + การเรนเดอร์หลายมุมมองด้วย EfficientNet-B0) ตามด้วยรอบ Grad-CAM ทุกครั้ง ซึ่งเขียนผลเป็นสเกลาร์ต่อจุดลงบนเมช

Prieto 2024 · SPIE DOCShapeAXI_CLI สภาพแวดล้อม conda: shapeaxi บรรณานุกรม

Dental Oral and Craniofacial Shape Analysis eXplainability and Interpretability. ผู้ใช้ทำเพียงอย่างเดียว: เลือกชนิดข้อมูล โฟลเดอร์อินพุต และ โฟลเดอร์เอาต์พุต ส่วนที่เหลือ — checkpoint ใด สถาปัตยกรรมใด กี่ คลาส — อนุมานจากชนิดข้อมูลทั้งสิ้น

1. ตำแหน่งใน pipeline

ทำงานแยกเป็นอิสระ: ไม่มีสิ่งใดในรีโพสิทอรีเรียก DOCShapeAXI เมชอินพุต ถือว่าถูกแบ่งส่วนและสกัดมาจากที่อื่นเรียบร้อยแล้ว (AMASSS สำหรับ condyle การแบ่งส่วนทางเดินหายใจ ฯลฯ) โมดูลไม่สร้างพื้นผิวของตัวเอง

สิ่งที่ถูกเรียกเมื่อใดอย่างไร
DOCShapeAXI_CLIทุกงานconda run -n shapeaxi python -m DOCShapeAXI_CLI <8 args>
model_path.json บน raw.githubusercontent.comเมื่อ CLI เริ่มทำงาน หากไม่มี .ckptrequests.get แล้วจึง urlretrieve
แพ็กเกจ pip shapeaxiตลอดเวลาsaxi_nets_lightning, saxi_dataset, saxi_transforms, saxi_gradcam, post_process, utils
DOCShapeAXI_utils.install_pytorchหากไม่มี pytorch3dconda run -n shapeaxi python -m DOCShapeAXI_utils.install_pytorch <pip>

สภาพแวดล้อม shapeaxi ถูกใช้ร่วมกันกับ FlexReg, ALI, AREG และ ASO: การเปลี่ยนเวอร์ชันใดก็ตามส่งผลกระทบต่อทุกตัว

ไฟล์ json ของโมเดลถูกอ่านจากสาขา main บน GitHub ไม่ใช่จากสำเนา ในเครื่อง (DOCShapeAXI_CLI.py:118): เวอร์ชันที่ติดตั้งไว้แล้วอาจดาวน์โหลด น้ำหนักที่เผยแพร่หลังจากนั้นได้

3. อินพุตและการเตรียมข้อมูล

3.1 ไฟล์ CSV

CLI ไล่รายชื่อไฟล์ใน args.input_dir แบบไม่ลงลึกในโฟลเดอร์ย่อย เก็บไฟล์ .vtk ไว้ แล้วเขียน <output_dir>/files_<data_type>.csv ด้วยหัวคอลัมน์ surf และชื่อไฟล์หนึ่งชื่อ ต่อหนึ่งบรรทัด (csv_edit, DOCShapeAXI_CLI.py:102) พาธเป็นแบบสัมพัทธ์ SaxiDataset จะต่อพาธเหล่านั้นกับ mount_point = input_dir

data_type มีช่องว่างอยู่ภายใน ("Mandibular Condyle") ดังนั้นชื่อไฟล์ csv จึงเป็น files_Mandibular Condyle.csv ไฟล์ csv จะถูกสร้างใหม่เฉพาะเมื่อยังไม่มี อยู่ (DOCShapeAXI_CLI.py:282): การเพิ่ม เมชเข้าไปในโฟลเดอร์อินพุตโดยไม่ล้างโฟลเดอร์เอาต์พุตจะทำให้เมชเหล่านั้นไม่ถูก ประมวลผล

3.2 การนอร์มัลไลซ์เชิงเรขาคณิต

EvalTransform → UnitSurfTransform → utils.GetUnitSurf → ScaleSurf:

  1. จุดศูนย์กลาง = จุดกึ่งกลางของกรอบสี่เหลี่ยมหุ้ม (bounding box) ไม่ใช่เซนทรอยด์
  2. เลื่อนจุดทั้งหมดไปที่จุดศูนย์กลางนี้
  3. ตัวคูณมาตราส่วน 1 / ||bounds_max - center|| ใช้แบบเท่ากันทุกแกน

เมชจึงพอดีอยู่ภายในทรงกลมหนึ่งหน่วย โดยไม่ขึ้นกับขนาดจริงของมัน ข้อมูลมาตราส่วนสัมบูรณ์สูญหายทั้งหมด — condyle ขนาดเล็กกับ condyle ขนาดใหญ่ที่มีรูปทรงเดียวกันจะเหมือนกันสำหรับโครงข่าย

บั๊กที่ยืนยันแล้ว (แพ็กเกจ shapeaxi)

ควรรู้ไว้: saxi_predict อ่าน model.hparams.scale_factor (เท่ากับ 0.0507 ใน checkpoint ของ condyle) แล้วส่งต่อให้ EvalTransform(scale_factor) (DOCShapeAXI_CLI.py:206) แต่ UnitSurfTransform.__call__ เรียก utils.GetUnitSurf(surf) โดยไม่ ส่งค่านั้นต่อไป เมื่ออินพุตเป็น vtkPolyData ตัวคูณมาตราส่วนที่เรียนรู้มา ตอนฝึกจึงถูกเพิกเฉยอย่างเงียบ ๆ ในขั้นการอนุมาน และถูกแทนด้วย การนอร์มัลไลซ์แยกตามแต่ละผู้ป่วย นี่เป็นบั๊กในแพ็กเกจ shapeaxi ไม่ใช่ใน รีโพสิทอรี แต่มันเปลี่ยนการเตรียมข้อมูลที่เกิดขึ้นจริง ส่วน saxi_gradcam ก็สร้าง dataset ของมัน ด้วย EvalTransform() โดยไม่มีอาร์กิวเมนต์: สองรอบนี้จึงลงเอยว่า สอดคล้องกันเอง

3.3 สิ่งที่ DataLoader คืนกลับมา

SaxiDataset(..., CN=True, class_column=None, scalar_column=None) → (V, F, CN) ต่อหนึ่งผู้ป่วย:

  • V: จุดยอด (1, Nv, 3) หลังการนอร์มัลไลซ์
  • F: สามเหลี่ยม (1, Nf, 3)
  • CN: เวกเตอร์ตั้งฉากที่เข้ารหัสเป็นสี ผ่าน utils.ComputeNormals แล้ว GetColorArray(surf,"Normals") หารด้วย 255 → (1, Nv, 3) ในช่วง [0,1]

ไม่มีการอ่านสเกลาร์ของเมชเลย (surf_property=None): เข้าไปเฉพาะ รูปทรงเชิงเรขาคณิตและเวกเตอร์ตั้งฉาก ค่า batch_size=1 ไม่มี padding ดังนั้นเมช ที่มีขนาดต่างกันจึงผ่านเข้าไปได้โดยไม่มีปัญหา

4.2 สถาปัตยกรรมที่ใช้งานจริง

นี่ไม่ใช่ PointNet และก็ไม่ใช่ ResNet-18 แบบ fly-by-CNN จากบทความ ShapeAXI ต้นฉบับ SaxiMHAFBClassification (MHA Fly-By) มีสองสาขา ที่หลอมรวมกันในขั้นท้าย

ตรวจสอบแล้ว

ค่าด้านล่าง (K=128, 256 heads, 42 มุมมอง, image_size=224…) ได้รับ การยืนยันจาก hyper_parameters และบัฟเฟอร์ ico_verts ของ checkpoint condyles_4_class.ckpt เอง ไม่ใช่เพียงจากการอ่านซอร์สโค้ด

สาขา A — point cloud

  • sample_points_from_meshes(X_mesh, 4096) (pytorch3d): การสุ่มตัวอย่างแบบสม่ำเสมอ 4096 จุด บนพื้นผิว
  • MHAEncoder: Linear(3→256) แล้ว 4 ขั้นด้วย sample_levels = [4096, 2048, 512, 128] ในแต่ละขั้นจะมี MHA_KNN (multi-head attention ที่จำกัดอยู่กับเพื่อนบ้าน ใกล้สุด K=128 จุด 256 heads) แล้วตามด้วย FeedForward แบบ residual (hidden 64) ระหว่างขั้น จะมีการสุ่มลดจำนวนจุดลงไปสู่ระดับถัดไป พร้อมส่งต่อดัชนีเพื่อสะสมน้ำหนักต่อจุดต้นฉบับหนึ่งจุด (x_w)
  • Linear(256→256), FeedForward แล้วจึง SelfAttention (additive attention Linear(256→64) → tanh → Linear(64→1) → sigmoid นอร์มัลไลซ์แล้วคิดผลรวม แบบถ่วงน้ำหนัก) ซึ่งย่อ token 128 ตัวลงเป็นเวกเตอร์ 256 มิติตัวเดียว

สาขา B — หลายมุมมอง

  • กล้องวางอยู่ที่จุดยอดของทรงยี่สิบหน้าที่แบ่งย่อย (subdivision_level=2, radius=1.35) บัฟเฟอร์ ico_verts ของ checkpoint มีรูปทรง (42, 3): 42 มุมมอง ต่อหนึ่งผู้ป่วย
  • การเรนเดอร์ด้วย pytorch3d: FoVPerspectiveCameras, look_at_rotation หันเข้าหาจุดกำเนิด AmbientLights (ไม่มีการให้แสงเงาแบบมีทิศทาง), HardPhongShader, RasterizationSettings(image_size=224, blur_radius=0, faces_per_pixel=1, max_faces_per_bin=200000)
  • แต่ละมุมมองเป็นเทนเซอร์ 4 ช่อง: RGB (เวกเตอร์ตั้งฉากที่เข้ารหัสเป็นสี กำหนดเป็น TexturesVertex) บวกกับ z-buffer จึงเป็นเหตุให้ in_channels=4
  • TimeDistributed(EfficientNetBN('efficientnet-b0', spatial_dims=2, in_channels=4, num_classes=256)) จาก MONAI: 42 มุมมองถูกยุบรวมเข้าไปใน มิติ batch ผ่าน CNN ตัวเดียวกัน แล้วจัดรูปกลับเป็น (1, 42, 256)
  • FeedForward, nn.MultiheadAttention(256, 256 heads, batch_first=True) ทำหน้าที่ เป็น self-attention เหนือ 42 มุมมอง แล้วจึง SelfAttention → เวกเตอร์ 256 มิติ

การหลอมรวม torch.cat([x_points, x_views], dim=1) → 512 แล้วจึง fc = Linear(512, num_classes) สำหรับการถดถอยจะเป็น Linear(512, 1) และใช้ MSE loss

การเรนเดอร์ทำใหม่ทุกรอบ ไม่มีแคชรูปภาพ

4.3 สิ่งที่โครงข่ายคายออกมาตรง ๆ และวิธีได้คลาสมาจากค่านั้น

x = model(X_pc, X_views)                       # (1, num_classes) — raw logits
if args.nn == 'SaxiMHAFBClassification':
    x = softmax(x).detach()
    x = torch.argmax(x, dim=1, keepdim=True)   # the class integer
predictions.append(x)

(DOCShapeAXI_CLI.py:227)

  • การจำแนก: เก็บไว้เฉพาะ argmax ความน่าจะเป็นจาก softmax ถูกคำนวณแล้วทิ้งไป ไม่มีค่าความเชื่อมั่นใดออกจากโมดูล
  • การถดถอย: ค่าดิบจาก Linear(512,1) ถูกเขียนออกตามนั้น (อัตราส่วนการอุดกั้น บนมาตรา 0–100 ตามที่ใช้ตอนฝึก)
  • อย่างไรก็ดี softmax ไม่มีผลต่อ argmax อยู่แล้ว

รายละเอียดการฝึกที่เห็นได้ในโค้ดต้นน้ำ: ในการจำแนก เป้าหมาย ไม่ใช่ one-hot แต่เป็นความน่าจะเป็นของคลาสแบบนุ่ม (soft_class_probabilities: การแจกแจงเกาส์เซียนที่มีศูนย์กลางที่ [12.5, 37.5, 62.5, 87.5] และ widths = 12.5) ความรุนแรง 4 คลาสจึงแท้จริงแล้วเป็น ควอร์ไทล์ของปริมาณต่อเนื่อง บนมาตรา 0–100 ซึ่งอธิบายได้ว่าทำไมจึงมี โมเดลถดถอยอยู่บนชุดข้อมูลทางเดินหายใจชุดเดียวกัน

5. กลไกการอธิบายผล

หมายเหตุ

นี่เป็นส่วนที่โดดเด่นที่สุดของโมดูล และมันทำงานทุกครั้ง หลังการทำนาย ไม่ใช่ตัวเลือก และไม่ใช่ช่องกาถูก (saxi_gradcam, DOCShapeAXI_CLI.py:126)

ก) ชั้นที่ถูกเล็ง

target_layer = getattr(model.convnet.module, '_blocks')
mv_cam = LayerGradCam(model, target_layer[-1], device_ids=[0])

model.convnet.module คือ EfficientNet-B0 และ _blocks[-1] คือบล็อก MBConv ตัวสุดท้ายของมัน

ข้อควรระวัง

ผลสืบเนื่องที่สำคัญ: ค่าความสำคัญอธิบายเพียง สาขาหลายมุมมองเท่านั้น สาขา point cloud ซึ่งมีส่วนครึ่งหนึ่งของ เวกเตอร์ที่หลอมรวม ไม่ปรากฏอยู่ในแผนที่เลย ค่า x_w (น้ำหนักต่อจุด) ที่ encoder สามารถผลิตได้นั้นไม่ถูกดึงออกมาและไม่ถูกเขียนออกไป

ข) แผนที่หนึ่งใบต่อหนึ่งคลาส วนลูป for class_idx in range(num_classes) ด้วย mv_cam.attribute(inputs=(X_pc, X_views), target=class_idx, attr_dim_summation=False): Captum แพร่ย้อนกลับค่า logit ของคลาส class_idx ไปยัง activation ของบล็อกนั้น คูณด้วยเกรเดียนต์เฉลี่ย แล้วคืนค่า เทนเซอร์ที่ความละเอียดของ activation map (7×7 สำหรับ EfficientNet-B0 บนภาพ 224×224) สำหรับทั้ง 42 มุมมองในคราวเดียว ค่า attr_dim_summation=False คงมิติ ช่องสัญญาณไว้ ซึ่งถูกยุบทิ้งทันทีหลังจากนั้นด้วย mv_att.sum(dim=1)

ค) การปรับช่วงค่า (scale_cam_image, DOCShapeAXI_CLI.py:43 ดัดแปลงจาก pytorch-grad-cam): cv2.resize ไปเป็น 224×224 ตัดค่าที่ percentile ที่ 1 และ 99 แล้วแมปแบบแอฟฟีนเข้าไปใน [-1, 1] การตัดที่ percentile ป้องกันไม่ให้ พิกเซลค่าผิดปกติเพียงจุดเดียวกลืนช่วงพลวัตทั้งหมด เอาต์พุตจึงเป็นค่า ที่มีเครื่องหมาย ไม่ใช่ความน่าจะเป็น

ง) การฉายกลับลงบนเมช (gradcam_process ใน shapeaxi) — เป็น แกนกลางของกลไกนี้:

โค้ดเบนออกจากบทความ บทความอธิบายการเรนเดอร์หลายมุมมอง บนการแบ่งย่อยทรงยี่สิบหน้า ประมวลผลด้วย ResNet-18 บวก additive attention โดยจัดการ condyle เป็นการจำแนกแบบไบนารี ส่วน checkpoint ที่แจกจ่ายในที่นี้เป็นโมเดล SaxiMHAFB*: EfficientNet-B0 บน 42 มุมมอง บวกสาขา point cloud อีกสาขาหนึ่ง ที่ใช้ KNN attention ซึ่งไม่มีอยู่ในบทความ พร้อม checkpoint condyles_4_class ที่มีความรุนแรง 4 คลาส อย่านำ ตัวเลขจากบทความ SPIE มาเสนอว่าเป็นตัวเลขของโมเดลที่ดาวน์โหลดมา

DOCShapeAXI

DOCShapeAXI จำแนกพื้นผิว 3 มิติ เช่น ทางเดินหายใจหรือข้อต่อขากรรไกร ด้วยโครงข่ายสองสาขา (point cloud และภาพถ่ายพื้นผิวหลายภาพ) แล้วแสดงตำแหน่งบนพื้นผิวที่โครงข่ายมองเสมอ หน้านี้อธิบายวิธีการทีละขั้นพร้อมคณิตศาสตร์ รายละเอียดที่นักพัฒนาต้องใช้ (ไฟล์ บรรทัด อาร์กิวเมนต์ ข้อควรระวัง) อยู่ในหน้าโค้ด

Prieto 2024 · SPIE โค้ด (นักพัฒนา) VISOR DOCShapeAXI_CLI conda env: shapeaxi บรรณานุกรม

Dental Oral and Craniofacial Shape Analysis eXplainability and Interpretability การกระทำของผู้ใช้เพียงครั้งเดียว: เลือกชนิดข้อมูล โฟลเดอร์อินพุต โฟลเดอร์ผลลัพธ์ ที่เหลือทั้งหมด ไม่ว่าจะเป็นcheckpointใด สถาปัตยกรรมใด จำนวนกี่คลาส ถูกอนุมานจากชนิดข้อมูล

หน้านี้อธิบายโมดูล Slicer แบบ legacy (SlicerAutomatedDentalTools ที่ 3c67957, 2026-10-26) ส่วนพอร์ต VISOR ซึ่งรันเครื่องมือเดียวกันบนเซิร์ฟเวอร์ อธิบายไว้ในDOCShapeAXI บน VISOR จุดที่ต่างกันถูกระบุไว้ในเนื้อหา

ภาพรวม: อะไรเข้า อะไรออก

DOCShapeAXI
อินพุตโฟลเดอร์พื้นผิว .vtk ที่ถูกแบ่งส่วนไว้แล้วที่อื่น และชนิดข้อมูล: condyleขากรรไกรล่าง การอุดตันทางเดินหายใจส่วนนาโซฟาริงซ์ หรือรอยบกพร่องของกระดูกเบ้าฟันใน cleft
แนวคิดโครงข่ายมองแต่ละพื้นผิวเป็นกลุ่มจุดและเป็นภาพ 42 ภาพที่ถ่ายรอบมัน รวมสิ่งที่ทั้งสองบอก แล้วให้คลาส (หรืออัตราส่วนการอุดตัน) รอบที่สอง ซึ่งรันเสมอ ระบายบนพื้นผิวว่าแต่ละส่วนมีน้ำหนักเท่าไร
เอาต์พุตตารางที่มีหนึ่งคลาสต่อพื้นผิว และสำเนาของแต่ละพื้นผิวที่มีแผนที่ “ตำแหน่งที่มอง” หนึ่งแผนที่ต่อคลาส

1. ตำแหน่งในไปป์ไลน์

ทำงานเดี่ยว: ไม่มีอะไรในรีโพซิทอรีเรียก DOCShapeAXI เมชอินพุตถือว่าถูกแบ่งส่วนและสกัดไว้แล้วที่อื่น (AMASSS สำหรับcondyle การแบ่งส่วนทางเดินหายใจ ฯลฯ) โมดูลไม่สร้างพื้นผิวของตัวเอง

คำสั่งรันในสภาพแวดล้อม conda ชื่อ shapeaxi ซึ่งใช้ร่วมกันกับ FlexReg, ALI, AREG และ ASO: การเปลี่ยนเวอร์ชันใด ๆ ที่นั่นส่งผลต่อทั้งหมด ถ้าcheckpointไม่อยู่บนดิสก์ คำสั่งจะดาวน์โหลดจากบรานช์ main ของรีโพซิทอรี GitHub เวอร์ชันที่ติดตั้งแล้วจึงอาจดึงน้ำหนักที่เผยแพร่หลังจากมัน

ในโค้ดการเรียกที่โมดูลทำ วิธีที่ต่อกัน และการดาวน์โหลด model_path.json

2. ไฟล์ที่เกี่ยวข้อง

โมดูลประกอบด้วยแผง Slicer 830 บรรทัด (จัดการ conda การเลือกโมเดล แถบความคืบหน้า) คำสั่ง 310 บรรทัดที่ทำการทำนายและการอธิบาย JSON เล็ก ๆ ของ URL checkpoint ห้ารายการ และตัวติดตั้งที่เลือก wheel PyTorch3D ที่ถูกต้อง งานจริงส่วนใหญ่อยู่ในแพ็กเกจ shapeaxi นอกรีโพซิทอรี สถาปัตยกรรมของมันถูกอ่านจากแพ็กเกจที่ติดตั้งและตรวจเทียบกับค่าตั้งที่เก็บใน checkpoint ของcondyleเอง

ในโค้ดตารางไฟล์พร้อมจำนวนบรรทัดและที่ที่แต่ละส่วนทำงาน

3. อินพุตและการประมวลผลก่อน

3.1 รายการพื้นผิว

คำสั่งไล่รายการโฟลเดอร์อินพุต เก็บไฟล์ .vtk และเขียนชื่อของมัน หนึ่งชื่อต่อบรรทัด ลงใน CSV ในโฟลเดอร์ผลลัพธ์ CSV นั้นถูกสร้างใหม่เฉพาะเมื่อยังไม่มีอยู่: การเพิ่มพื้นผิวลงโฟลเดอร์อินพุตโดยไม่ล้างโฟลเดอร์ผลลัพธ์จะไม่ทำให้พื้นผิวเหล่านั้นถูกประมวลผล

3.2 การทำให้เรขาคณิตเป็นมาตรฐาน

ก่อนอื่นใด ทุกพื้นผิวถูกปรับให้มีขนาดและตำแหน่งมาตรฐาน

ข้อมูลของขนาดสัมบูรณ์ทั้งหมดสูญหาย: condyleเล็กและ condyle ใหญ่ที่มีรูปทรงเดียวกันเหมือนกันทุกประการสำหรับโครงข่าย scale factorที่เรียนรู้ตอนฝึกถูกเก็บในcheckpoint แต่แพ็กเกจที่ติดตั้งไม่เคยส่งต่อมันให้ขั้นนี้ จึงถูกเพิกเฉยอย่างเงียบ ๆ ตอน inference นี่เป็นบั๊กของแพ็กเกจ ไม่ใช่ของรีโพซิทอรี และมีรายละเอียดในหน้าโค้ด

ในโค้ดสายโซ่ transform และบั๊ก shapeaxi ที่ทิ้ง scale factor ที่เรียนรู้

3.3 สิ่งที่โครงข่ายได้รับ

สำหรับทุกพื้นผิว: จุด สามเหลี่ยม และnormal ของพื้นผิวที่เข้ารหัสเป็นสี (แต่ละองค์ประกอบของ normal หนึ่งหน่วยถูกแมปจาก [-1, 1] ไป [0, 1]) ไม่มีสเกลาร์ของเมชถูกอ่าน: เข้าไปเฉพาะเรขาคณิตและ normal ประมวลผลทีละพื้นผิว เมชขนาดต่างกันจึงไม่ต้องใช้ padding

4. โมเดล

4.1 ตารางการตัดสินใจ

ชนิดข้อมูลที่เลือกในแผง ผ่านคำหนึ่งคำของป้ายของมัน เลือกcheckpoint คลาสโครงข่าย และจำนวนคลาส:

ชนิดข้อมูลงานCheckpointคลาส
Condyleขากรรไกรล่างseveritycondyles_4_class4
การอุดตันทางเดินหายใจส่วนนาโซฟาริงซ์binaryairways_2_class2
การอุดตันทางเดินหายใจส่วนนาโซฟาริงซ์severityairways_4_class4
การอุดตันทางเดินหายใจส่วนนาโซฟาริงซ์regression (อัตราส่วน)airways_4_regress1
รอยบกพร่องของกระดูกเบ้าฟันใน cleftseverityclefts_4_class4

มีเพียงกรณีทางเดินหายใจที่ต่อการรันเต็มสามครั้ง (binary, severity, regression) อีกสองกรณีทำครั้งเดียว ใน severity ใน VISOR ชื่อ checkpoint อย่างเดียวตัดสินทั้งหมดนี้ โดยไม่ต้องแยกวิเคราะห์ป้าย

ในโค้ดฟังก์ชันที่เลือกโมเดล URL ดาวน์โหลด และความไม่สมมาตรของการตั้งชื่อ

4.2 สถาปัตยกรรมที่ใช้จริง

นี่ไม่ใช่ PointNet และไม่ใช่ ResNet-18 ของบทความ ShapeAXI ดั้งเดิม โครงข่ายมีสองสาขา รวมกันตอนท้าย ค่าที่ให้ไว้ที่นี่ยืนยันจากค่าตั้งที่เก็บใน checkpoint ของ condyle ไม่ใช่จากซอร์สเพียงอย่างเดียว

สาขา A, point cloud สุ่ม 4096 จุดอย่างสม่ำเสมอบนพื้นผิว encoder รัน attention สี่ขั้นที่แต่ละจุดมองเฉพาะเพื่อนบ้านใกล้สุด 128 จุด (256 attention head) โดยสุ่มลดจุดระหว่างขั้น จากนั้นattention poolingลด 128 โทเค็นที่เหลือเป็นเวกเตอร์หนึ่งตัวที่มีตัวเลข 256 ตัว

สาขา B, ภาพ กล้องตั้งอยู่บน vertex ของ icosahedron ที่แบ่งย่อย 42 ตัว แต่ละภาพถูกเรนเดอร์ด้วยแสงแวดล้อมเท่านั้น สีของพื้นผิว (normal) จึงไม่ถูกแรเงา และมีช่องความลึกนอกเหนือจากช่องสีสามช่อง EfficientNet-B0 ตัวเดียวกัน (จากMONAI) ถูกใช้กับแต่ละภาพจาก 42 ภาพ attention ข้ามภาพและ attention pooling ให้เวกเตอร์ที่สองที่มีตัวเลข 256 ตัว การเรนเดอร์ทำใหม่ทุกรอบ: ไม่มีแคชภาพ

การรวม เวกเตอร์สองตัวถูกต่อกัน (ตัวเลข 512 ตัว) และเลเยอร์เชิงเส้นหนึ่งชั้นให้หนึ่งคะแนนต่อคลาส สำหรับ regression เลเยอร์มีเอาต์พุตเดียว

ในโค้ดเลเยอร์ ขนาด การตั้งค่าการเรนเดอร์ และวิธีที่ checkpoint ยืนยันมัน

4.3 สิ่งที่โครงข่ายส่งออก และคลาสถูกได้มาอย่างไร

สำหรับ classification เก็บเฉพาะคะแนนสูงสุด: ความน่าจะเป็นถูกคำนวณแล้วทิ้ง จึงไม่มีค่าความมั่นใจออกจากโมดูล สำหรับ regression ค่าดิบถูกเขียนตามเดิม (อัตราส่วนการอุดตัน ในสเกล 0 ถึง 100 ตอนฝึก) รายละเอียดการฝึกที่เห็นได้ในโค้ดต้นทาง: เป้าหมายไม่ใช่ one-hot แต่เป็นความน่าจะเป็นแบบ soft Gaussian ที่มีศูนย์กลางที่ 12.5, 37.5, 62.5 และ 87.5 สี่คลาสความรุนแรงจึงเป็นควอร์ไทล์ของปริมาณต่อเนื่อง ซึ่งเป็นเหตุที่มีโมเดล regression บนข้อมูลทางเดินหายใจชุดเดียวกัน

ในโค้ดการเรียกทำนาย softmax แล้ว argmax และรายละเอียด soft label

5. กลไก explainability

นี่คือส่วนที่โดดเด่นที่สุดของโมดูล และมันทำงานเสมอหลังการทำนาย: ไม่ใช่ตัวเลือก ไม่ใช่ช่องทำเครื่องหมาย ใน VISOR ปิดได้

หนึ่งแผนที่ต่อคลาส โครงข่ายถูกถามทีละคลาสว่าส่วนใดของภาพผลักคะแนนของคลาสนั้น ทำบนบล็อกสุดท้ายของสาขาภาพเท่านั้น: saliency อธิบายเฉพาะสาขา multi-view สาขา point cloud ซึ่งมีส่วนร่วมครึ่งหนึ่งของเวกเตอร์ที่รวมกัน ไม่ปรากฏในแผนที่เลย

กลับบนเมช แต่ละพิกเซลของแต่ละภาพรู้ว่ามันแสดงสามเหลี่ยมใด ค่าของมันจึงถูกพาไปที่สามเหลี่ยมนั้นได้ ข้าม 42 ภาพ การรวมค่าเป็นค่าสูงสุด ไม่ใช่ค่าเฉลี่ย: บริเวณที่เห็นครั้งเดียวและถูกตัดสินว่าเด่นจะคงค่าไว้ สามเหลี่ยมเริ่มที่ 0 ค่าลบ (ตำแหน่งที่ดึงคะแนนคลาสลง) จึงถูกทิ้ง และแผนที่บนเมชอยู่ระหว่าง 0 ถึง 1 ขั้นจากสามเหลี่ยมไปเป็นจุดหยาบ: ค่าของแต่ละสามเหลี่ยมถูกเขียนลงในvertex แรกของมัน vertex ที่ไม่เคยเป็นจุดแรกของสามเหลี่ยมใด และสามเหลี่ยมที่ไม่เคยมองเห็น ค้างอยู่ที่ศูนย์ แผนที่จึงกระจายไปด้วยศูนย์ จากนั้นmedian filterแทนที่ทุก vertex รวมถึงที่มีค่าแล้ว ด้วยค่ามัธยฐานของเพื่อนบ้าน ซึ่งเติมช่องว่างได้มาก และทำให้ค่าที่มีอยู่เรียบด้วย

แผนที่ถูกเก็บเป็นอาร์เรย์หนึ่งชุดต่อคลาสบนสำเนาของพื้นผิว ส่วนcheckpointแบบ regression มีเพียงชุดเดียวด้วยชื่อที่ต่างออกไป ไฟล์ถูกเขียนใหม่ทุกคลาส พื้นผิวสุดท้ายจึงมีแผนที่ครบทุกอัน ใน Slicer แสดงผ่านโมดูล Models, scalars ด้วยตารางสีจากเย็นไปร้อน

ในโค้ดการเรียก Grad-CAM ลูป ชื่ออาร์เรย์ และฟังก์ชัน shapeaxi ที่เกี่ยวข้อง

โฟลเดอร์ explainability มีโฟลเดอร์ย่อยหนึ่งโฟลเดอร์ต่อหนึ่งงานสำเนาของแต่ละพื้นผิวบวกอาร์เรย์ Grad-CAM
ไฟล์ล็อกบรรทัดเดียวตัวนับงาน ขั้น และความคืบหน้า ซึ่งแผงอ่านเพื่อขยับแถบความคืบหน้า

คอลัมน์การทำนายสะสมโดยตั้งใจ: ถ้า CSV การทำนายมีอยู่แล้ว มันจะถูกอ่านกลับเข้ามาและใช้เป็นฐาน ชุดข้อมูลทางเดินหายใจจึงจบด้วยคอลัมน์ binary, severity และ regression เคียงกัน การรันซ้ำบนโฟลเดอร์เดิมเขียนทับคอลัมน์ในที่เดิมและไม่เคยล้างคอลัมน์เก่า

ในโค้ดตารางผลลัพธ์พร้อมรูปแบบชื่อไฟล์ กฎการสะสม และรูปแบบล็อก

7. อะไรคือสิ่งที่ทำนาย อะไรคือสิ่งที่คำนวณ

บล็อกลักษณะ
การทำให้เป็นมาตรฐานเข้าทรงกลมหนึ่งหน่วยคำนวณ เชิงเรขาคณิต
normal ที่เข้ารหัสเป็นสีคำนวณ เชิงเรขาคณิต
การสุ่ม 4096 จุดคำนวณ สุ่ม ไม่ตั้ง seed
42 ภาพขนาด 224 x 224คำนวณ rasterization
คลาสหรืออัตราส่วนทำนาย point-cloud encoder, EfficientNet-B0, attention
แผนที่ Grad-CAMทำนาย ได้มาจากเกรเดียนต์ของโครงข่าย (เฉพาะสาขาภาพ)
สามเหลี่ยมไปเป็นจุด ค่าสูงสุดข้ามภาพคำนวณ เชิงเรขาคณิต
Median filter บนเมชคำนวณ เพื่อนบ้านเชิงทอพอโลยี

ความสุ่มสองแหล่งตอน inference (การสุ่มจุดไม่ตั้ง seed) ทำให้การรันสองครั้งอาจให้แผนที่ต่างกันเล็กน้อย และในกรณีก้ำกึ่งอาจได้สองคลาสที่ต่างกัน เรื่องนี้ยังจริงใน VISOR

8. สภาพแวดล้อม

Legacy สร้างสภาพแวดล้อม conda ชื่อ shapeaxi ด้วย Python 3.12 และหนึ่งไลบรารี คือ SimpleITK จากนั้นตัวติดตั้งแยกต่างหากใส่ PyTorch (build ที่ปักหมุด หรือตัวที่มีอยู่แล้วถ้ามี wheel PyTorch3D สำหรับมัน) เลือก wheel PyTorch3D ที่ตรงกับ PyTorch และ CUDA นั้น เพิ่มไลบรารีที่ปักหมุดอีกหนึ่งตัว และสุดท้ายติดตั้ง shapeaxi ลำดับถูกบังคับ: shapeaxi ต้องการ PyTorch3D ซึ่งไม่อยู่บน PyPI GPU ไม่จำเป็น แต่การเรียก Grad-CAM สมมติว่าใช้ GPU 0 ตัวติดตั้งขอ shapeaxi 2.0.2 ขึ้นไป ขณะที่คำสั่งถูกเขียนสำหรับอินเทอร์เฟซ 1.x: ความไม่ตรงกันนั้นคือสิ่งแรกที่ต้องตรวจถ้าโมดูลหยุดทำงาน

ในโค้ดเวอร์ชันพร้อมเลขบรรทัด ลำดับการติดตั้ง และการตรวจ GPU

9. ข้อควรระวังและจุดเปราะบาง

แต่ละข้อถูกตรวจในโค้ดและอธิบายพร้อมหลักฐานในหน้าโค้ด

  • เวอร์ชัน shapeaxi ไม่ตรงกัน คำสั่งถูกเขียนสำหรับ shapeaxi 1.x แต่ตัวติดตั้งดึง 2.x แก้ใน VISOR โดยปักหมุด 1.1.1 หลักฐาน
  • scale factorที่เรียนรู้ถูกเพิกเฉย การประมวลผลเบื้องต้นเป็นแบบต่อบุคคล ไม่ว่าcheckpointจะบอกอะไร หลักฐาน
  • saliency ครอบคลุมเพียงหนึ่งในสองสาขา การตัดสินใจที่ขับเคลื่อนโดย point cloud ให้แผนที่ที่ไม่มีข้อมูล โดยไม่มีอะไรเตือน หลักฐาน
  • ไม่มีการรายงานความมั่นใจ ออกมาเฉพาะคลาสสูงสุด หลักฐาน
  • การสุ่มที่ไม่ตั้ง seed การรันสองครั้งอาจต่างกัน หลักฐาน
  • การโหลด checkpoint แบบผ่อนปรน น้ำหนักที่ขาดหรือเกินผ่านไปอย่างเงียบ ๆ หลักฐาน
  • การดาวน์โหลดขึ้นกับว่าโฟลเดอร์ผลลัพธ์ต้องมีอยู่ ถ้าไม่มี ข้อผิดพลาดจะปรากฏทีหลัง ตอนโหลด หลักฐาน
  • ความคืบหน้าคือไฟล์บรรทัดเดียวที่แผงสอบถามเป็นระยะ มันอยู่ในโฟลเดอร์ชั่วคราวของ Slicer และถูกเขียนใหม่หลังแต่ละพื้นผิว แผงดูเพียงเวลาแก้ไขของมัน หน้านี้ฉบับก่อนบอกว่ามันอยู่ในโฟลเดอร์ของโมดูลเอง ซึ่งไม่จริงอีกต่อไป หลักฐาน
  • การเลือกโมเดลผ่านคำของป้ายชนิดข้อมูล การเปลี่ยนชื่อป้ายทำให้มันพัง หลักฐาน

10. วรรณกรรม

สามอ้างอิง ซึ่งอย่าสับสนกัน เฟรมเวิร์ก: ShapeAXI: Shape Analysis Explainability and Interpretability, Prieto et al., Proc. SPIE Medical Imaging, April 2024, DOI 10.1117/12.3007053 รายงาน 79.78% บนcondyle และ 81.58% บนความรุนแรงของ cleft ชุดข้อมูลทางเดินหายใจ: Mattos et al., J Dent 2025 ซึ่งอธิบายสถาปัตยกรรมนี้ตรงทุกประการ (สาขา EfficientNet-B0 ที่ pretrain บน ImageNet พร้อม attention สาขา 4096 จุดพร้อม neighbour attention และกลไก Grad-CAM ของส่วนที่ 5) ด้วย AUC 0.77 ถึง 0.94 และ R = 0.854 สำหรับอัตราส่วน ต้นกำเนิดของโมดูล Slicer: lucieDLE/DOC-ShapeAXI ไม่มีสิ่งใดตีพิมพ์เกี่ยวกับชุดข้อมูล cleft นอกจากการทดลองความรุนแรงของ cleft ในบทความ SPIE

โค้ดต่างจากบทความ SPIE: บทความอธิบาย ResNet-18 และงาน condyle แบบ binary ขณะที่checkpointที่แจกจ่ายที่นี่เป็นโครงข่ายสองสาขาที่มีสี่คลาสความรุนแรง อย่านำตัวเลขของบทความไปนำเสนอเป็นของโมเดลที่ดาวน์โหลด รายละเอียด

SlicerAutomatedDentalTools — แต่ละเครื่องมือทำงานอย่างไร

หนึ่งหน้าต่อหนึ่งเครื่องมือ จัดเรียงตาม pipeline: อะไรที่คำนวณ อะไร ที่โครงข่ายทำนาย โมเดลถูกเรียกเมื่อใด ทำอะไรจริง การเตรียมข้อมูลเป็นอย่างไร และได้อะไรออกมา

นี่ไม่ใช่คู่มือผู้ใช้ ลิงก์ไปยังโค้ดชี้ไปที่คลังโค้ด ~/Projects/UNC/SlicerAutomatedDentalTools

จากล่างสุดของสายไปถึงบนสุด สองขั้นแรกคือสิ่งที่ทุกอย่างที่เหลือต้องอาศัย

ทุกหน้า

การลงทะเบียนภาพ

FlexRegการลงทะเบียนภาพ IOS ด้วย patch ที่วาดด้วยมือ AREG_IOSการลงทะเบียนภาพ IOS ด้วย patch ที่ทำนาย — FlexReg แบบอัตโนมัติ AREG_CBCTการลงทะเบียนภาพ CBCT T1/T2 AREG_IOSCBCTการลงทะเบียนภาพต่างชนิด IOS ↔ CBCT GreedyRegการลงทะเบียนภาพ CBCT แบบ ITK-SNAP เอนจิน Greedy MRI2CBCTการลงทะเบียนภาพต่างชนิด MRI ↔ CBCT

การแบ่งส่วน

AMASSSการแบ่งส่วนโครงสร้างกะโหลกและใบหน้าบน CBCT BatchDentalSegDentalSegmentator และรุ่นย่อย แบบกลุ่ม

จุดสังเกตและการจัดแนว

ALIการวาง landmark อัตโนมัติ CBCT และ IOS ASOการจัดแนวภาพสแกนอัตโนมัติ CBCT และ IOS

การวิเคราะห์และการจำแนก

VFACEการจำแนกความไม่สมมาตรของใบหน้า DOCShapeAXIการจำแนกรูปร่าง 3D พร้อมคำอธิบายผล CLICการจำแนกและระบุตำแหน่งฟันเขี้ยวคุด SurgMovPredการทำนายการเคลื่อนที่จากการผ่าตัด

เครื่องมือเสริม

AutoCrop3Dการครอปวอลุ่มแบบกลุ่ม โดยไม่ resample AutoMatrixการนำ transform ไปใช้แบบกลุ่ม

ข้อความและภาษาธรรมชาติ

กลุ่มนี้ไม่ได้ประมวลผลภาพเลย: รันโมเดลภาษา กับข้อความทางคลินิกสำหรับสามตัวแรก และกับ คำขอของผู้ใช้สำหรับตัวสุดท้าย แยกไว้เป็นกลุ่มของตัวเองเพราะดูจากชื่อไม่ออก

CNEClinical Notes Extraction — การสกัดข้อมูลจากบันทึกทางคลินิก ด้วย llama.cpp และโมเดล GGUF ภายในเครื่อง MedXการสรุปรายงาน (BART-large-cnn ที่ปรับแต่งแล้ว ภายในเครื่อง) และแดชบอร์ด MedicalDataAnonymizerการลบข้อมูลระบุตัวตนในเอกสารข้อความ (Presidio + spaCy) — ไม่ใช่ตัวทำ DICOM ให้เป็นนิรนาม Agentการเรียกโมดูลอื่นด้วยภาษาธรรมชาติ

สภาพแวดล้อม conda ที่ใช้ร่วมกัน

การผูกกันที่ควรรู้

ALI, AREG, ASO, DOCShapeAXI และ FlexReg ใช้สภาพแวดล้อม conda เดียวกัน shapeaxi บน Python 3.12 การเปลี่ยนรุ่น Python จะทำให้ทั้งหมด พังพร้อมกัน รายละเอียดใน FlexReg ส่วนสภาพแวดล้อม

โครงสร้างโฟลเดอร์

หนึ่งโฟลเดอร์ต่อหนึ่งเครื่องมือ แต่ละโฟลเดอร์มี:

  • <Tool>.html — pipeline ที่อ่านจากโค้ด
  • SOURCES.html — บรรณานุกรม: สิ่งที่เก็บไว้ที่นี่ สิ่งที่ควรอ่าน ออนไลน์ และ "เครื่องมือใกล้เคียง" (งานที่เกี่ยวข้องซึ่งไม่ได้อธิบายโค้ด)
  • เอกสารที่ได้มา เป็น PDF หากสำนักพิมพ์อนุญาต มิฉะนั้นเป็น .xml (JATS ข้อความเต็ม) พร้อม .txt ที่อ่านได้วางคู่กัน

ไฟล์ .md ต้นฉบับถูกเก็บไว้ข้างหน้า HTML

PDF 29 ไฟล์และข้อความเต็ม 54 ชิ้น ตรวจสอบแล้วทั้งหมด: PDF มีการแบ่งหน้า ไฟล์ XML มีเนื้อความ ไม่มีสิ่งใดได้มาจากการหลบเลี่ยง paywall — มาจาก arXiv, PLOS, PMC/NCBI, HAL, คลังสถาบัน หน้าของผู้เขียน และฉบับที่ผู้เขียนนำฝากไว้ สิ่งที่ติด paywall ให้ไว้เป็นลิงก์พร้อม DOI

การดึงข้อความที่สำนักพิมพ์ไม่ให้บริการ

ต้นฉบับของผู้เขียนที่นำฝากไว้กับ NIH อ่านได้ฟรี แต่มักมองไม่เห็นผ่านช่องทางปกติ วิธีที่ได้ผล ทดสอบแล้ว:

curl -sL "https://eutils.ncbi.nlm.nih.gov/entrez/eutils/efetch.fcgi?db=pmc&id=<number without PMC>"

วิธีที่ล้มเหลวกับบทความเดียวกัน: pmc.ncbi.nlm.nih.gov/.../pdf/ (HTML กันบอต) fullTextXML ของ Europe PMC (ว่าง) BioC API (เฉพาะ open access subset) และสำหรับ MDPI mdpi-res.com/d_attachment/... ให้ PDF จริง ขณะที่ mdpi.com/.../pdf คืนหน้าเว็บ

สิ่งที่ไม่ได้ตีพิมพ์ที่ใดเลย

ตรวจสอบกับ Crossref, OpenAlex, Europe PMC, arXiv, HAL และโครงสร้าง NA-MIC ทั้งหมด: FlexReg และแนวทาง MGL ALI_IOS AREG_IOSCBCT, CLIC, CNE, AutoCrop3D, AutoMatrix, MedicalDataAnonymizer รุ่นย่อยทั้งสาม ของ BatchDentalSeg และรุ่น nnU-Net ของ AMASSS สำหรับหลายตัวในนี้ หน้า NA-MIC Project Week เป็น คำอธิบายที่เป็นลายลักษณ์อักษรเพียงแห่งเดียวที่มีอยู่ — ซึ่งเก็บไว้ในโฟลเดอร์ที่เกี่ยวข้องแล้ว

เว็บไซต์แบบสแตติก ไม่มี dependency ภายนอก เปิดให้บริการด้วย python3 -m http.server จากโฟลเดอร์นี้ หรือเปิด index.html โดยตรง

SlicerAutomatedDentalTools: แต่ละเครื่องมือทำงานอย่างไร

หนึ่งหน้าต่อเครื่องมือ จัดตามไปป์ไลน์: อะไรถูกคำนวณ อะไรถูกโครงข่ายทำนาย โมเดลถูกเรียกเมื่อไร มันทำอะไรจริง ๆ การประมวลผลก่อนหน้าคืออะไร และอะไรออกมา

นี่ไม่ใช่คู่มือผู้ใช้ ลิงก์โค้ดชี้ไปยังที่เก็บ ~/Projects/UNC/slicer/SlicerAutomatedDentalTools

สองโค้ดเบส: legacy และ VISOR

หน้าเครื่องมือที่ลิสต์ไว้ด้านล่างอธิบายโมดูล Slicer แบบ legacy (SlicerAutomatedDentalTools ที่ 3c67957, 2026-10-26) ทีมกำลังย้ายเครื่องมือไปสู่ VISOR: ไคลเอนต์ Slicer ที่ส่งงานไปยังเซิร์ฟเวอร์อนุมาน ซึ่งแต่ละเครื่องมือรันในสภาพแวดล้อม Python ของตัวเอง

ดังนั้นแต่ละโมดูลมีได้ถึงสี่หน้า ที่ด้านบนของแถบด้านข้าง ตัวเลือก Legacy | VISOR เลือกรุ่น และตัวเลือก Guide | Atlas ใต้มันเลือกระหว่างมุมมองของผู้ใช้กับโค้ด: คู่มือ legacy, แอตลาส legacy, คู่มือ VISOR, แอตลาส VISOR การสลับจะอยู่ที่เครื่องมือเดิม หน้า VISOR ด้านล่างอธิบายวิธีสร้างระบบ ภาษาอื่นอธิบายเฉพาะโค้ด legacy ในตอนนี้

VISOR

ภาพรวมVISOR คืออะไร legacy เทียบกับ VISOR เครื่องมือใดถูกพอร์ตแล้ว และคอมมิตที่การสำรวจนี้อ่าน สถาปัตยกรรมไคลเอนต์และเซิร์ฟเวอร์ ทะเบียนเครื่องมือและสคีมา facade กราฟการเรียก การรันทีละขั้นอัปโหลด การรับเข้า การทำงาน ความคืบหน้า ผลลัพธ์ จุดหยุดควบคุมคุณภาพ การแพ็กเกจและการติดตั้งใช้งานอิมเมจ virtualenv หนึ่งตัวต่อเครื่องมือ ข้อมูล การตั้งค่า เบนช์มาร์ก ความปลอดภัยและความเป็นส่วนตัวอะไรปกป้องการรันในวันนี้ อะไรเป็นเพียงข้อกำหนด และอะไรมีอยู่แค่เป็นต้นแบบ การทดสอบและที่มาเครื่องมือถูกทดสอบ ตั้งชื่อ และสืบย้อนไปยังโค้ด legacy อย่างไร Crown_Segการกำหนดเลขฟัน เครื่องมือที่มีอยู่เฉพาะใน VISOR การใช้ VISOR (คู่มือ)เชื่อมต่อ Slicer กับเซิร์ฟเวอร์และรันเครื่องมือ

สามส่วนประกอบพื้นฐานที่ใช้ร่วมกัน

เกือบทุกโมดูลตั้งอยู่บนสามองค์ประกอบเดียวกัน การทำความเข้าใจมันครั้งเดียวหมายถึงไม่ต้องอ่านกลไกเดิมซ้ำตลอดห้าหน้า

ทุกหน้า

การลงทะเบียนภาพ

FlexRegการลงทะเบียน IOS ด้วยแพตช์ที่วาดด้วยมือ AREG_IOSการลงทะเบียน IOS ด้วยแพตช์ที่ทำนาย: FlexReg อัตโนมัติ AREG_CBCTการลงทะเบียน CBCT T1/T2 AREG_IOSCBCTการลงทะเบียน IOS ↔ CBCT ข้ามโมดัลลิตี GreedyRegการลงทะเบียน CBCT แบบ ITK-SNAP เอนจิน Greedy MRI2CBCTการลงทะเบียน MRI ↔ CBCT ข้ามโมดัลลิตี

การแบ่งส่วน

AMASSSการแบ่งส่วนโครงสร้างกะโหลกใบหน้าบน CBCT BatchDentalSegDentalSegmentator และรุ่นต่าง ๆ แบบเป็นชุด

Landmark และการปรับทิศทาง

ALIการวาง landmark อัตโนมัติ CBCT และ IOS ASOการปรับทิศทางสแกนอัตโนมัติ CBCT และ IOS

การวิเคราะห์และการจำแนกประเภท

VFACEการจำแนกความไม่สมมาตรของใบหน้า DOCShapeAXIการจำแนกรูปร่าง 3D พร้อมความสามารถในการอธิบาย CLICการจำแนกและการระบุตำแหน่งเขี้ยวที่ฝังคุด SurgMovPredการทำนายการเคลื่อนที่จากการผ่าตัด

ยูทิลิตี

AutoCrop3Dการตัดวอลุ่มเป็นชุดโดยไม่ resample AutoMatrixการใช้ transform เป็นชุด

ข้อความและภาษาธรรมชาติ

พวกนี้ไม่ประมวลผลภาพเลย: รันโมเดลภาษา กับข้อความทางคลินิกสำหรับสามตัวแรก และกับคำขอของผู้ปฏิบัติงานสำหรับตัวสุดท้าย แยกเป็นกลุ่มของตัวเองเพราะชื่อไม่ได้บอกเป็นนัย

CNEClinical Notes Extraction: การสกัดจากบันทึกทางคลินิก llama.cpp ในเครื่องและโมเดล GGUF MedXการสรุปรายงาน (fine-tune แล้ว, BART-large-cnn ในเครื่อง) และแดชบอร์ด MedicalDataAnonymizerการลบข้อมูลระบุตัวตนในเอกสารข้อความ (Presidio + spaCy) ไม่ใช่ตัวลบข้อมูลระบุตัวตนของ DICOM Agentการเรียกโมดูลอื่นจากภาษาธรรมชาติ

โค้ดร่วม

ไม่ใช่เครื่องมือ: คือโค้ดที่ยี่สิบโมดูลนำเข้า หนึ่งหน้า เพราะตอนนี้พฤติกรรมของโมดูลขึ้นอยู่กับมัน

ADTLibชั้นที่ยี่สิบโมดูลนำเข้า: อะไรถูกกำจัดความซ้ำซ้อน และสัญญาที่ทั้งหมดใช้ร่วมกัน

สิ่งที่การอ่านพบ

พบระหว่างการจัดทำเอกสาร ไม่ใช่ระหว่างการตามหาบั๊ก คอลัมน์ "verified" แยกสิ่งที่ถูกทำซ้ำหรือยืนยันโดยตรงจากโค้ด ออกจากสิ่งที่หน้าหนึ่งรายงานและยังต้องตรวจ

ที่ไหนอาการตรวจสอบแล้ว
MedicalDataAnonymizeranonymize_text_presidio ทำ return text เมื่อเกิดข้อยกเว้นใด ๆ: ไฟล์ _anonymized เก็บข้อความที่ไม่ถูกแตะต้อง และ UI แสดง "Complete!"ใช่ อ่านทีละบรรทัด
CLICเครื่องหมาย [SEG]/[PROGRESS] ถูกส่งผ่าน logger.info พร้อมคำนำหน้า ตัวอ่านทดสอบ startswith: การแบ่งส่วนไม่เคยถูกโหลดเข้า Slicerใช่
BatchDentalSegNasoMaxillaDentSeg: รายการเปลี่ยนชื่อเรียงลำดับผิด 4 ส่วนสุดท้ายได้ชื่อและสีผิดใช่
AREG_CBCTMatrixRetrieval เพิกเฉย CenterOfRotationPoint (ไม่มีในทั้งที่เก็บ) วอลุ่มเอาต์พุตถูก resample อีกครั้งด้วยเมทริกซ์นี้ ดังนั้น .tfm และภาพจึงเคลื่อนห่างกันจาก elastixใช่ ต้องวัดบนหนึ่งเคส
MRI2CBCTข้อต่อที่ถูกพลิกแล้วแก้ไม่ได้ถูกเขียนจากท่าของขั้น 0 ไม่ใช่ท่าที่ดีที่สุดจาก 150 การสุ่ม ผลลัพธ์ FLAG เก็บชื่อไฟล์ที่สะอาด (มีเพียง summary.csv ที่ระบุ FLAG)ใช่ อ่านทีละบรรทัด
ASOโหมด semi-CBCT ต้องการ .tfm ที่มีเพียง PRE_ASO เท่านั้นที่เขียน: ล้มเหลวทีละผู้ป่วย เว้นแต่จะมี .tfm วางอยู่ในโฟลเดอร์อยู่แล้วใช่
AMASSS"FOV เล็ก" เสีย (highDefinition หายจาก .xml) อินพุต DICOM ถูกเพิกเฉย temp_fold ใช้ร่วมกับ AREG และ VFACE พร้อม rmtree แบบไม่มีเงื่อนไขรายงานแล้ว
AutoMatrixการรองรับ .npy และเมชถูกโฆษณาไว้แต่อ่านไม่ได้ตั้งแต่ 7bc362bทดสอบโดยเอเจนต์
CNEโมเดล Ortho ขอ model-q4_0.gguf แต่ repo HF มีเพียง model-q4_k_m.gguf (404)ทดสอบโดยเอเจนต์
DOCShapeAXICLI เขียนตาม API ของ shapeaxi 1.0.x ขณะที่ install_pytorch ติดตั้ง >=2.0.2รายงานแล้ว
Agentresolve_tool_path มองหาโฟลเดอร์ CLI files ที่ไม่มีในที่เก็บ 14 จาก 16 ซิกเนเจอร์ไม่ตรงกับ argparse จริงรายงานแล้ว
SurgMovPredpip_install("numpy==2.4.0") โดยไม่มีเงื่อนไขทุกครั้งที่กด Applyรายงานแล้ว
VFACEINPUT_KEYS ไม่ครอบคลุม inputVolume / t1_folder / input_path: การ rollback แบบเลือกรันขั้นที่ช้าซ้ำทั้งชุดรายงานแล้ว

PDF 29 ไฟล์และข้อความฉบับเต็ม 54 ฉบับ ตรวจแล้วทั้งหมด: PDF มีเลขหน้า ไฟล์ XML มีเนื้อความ ไม่มีอะไรได้มาโดยหลบเลี่ยง paywall: arXiv, PLOS, PMC/NCBI, HAL, คลังของสถาบัน หน้าของผู้เขียน และฉบับที่ผู้เขียนฝากไว้ สิ่งใดที่ติด paywall ให้เป็นลิงก์พร้อม DOI

การดึงข้อความที่สำนักพิมพ์ไม่ให้บริการ

ต้นฉบับของผู้เขียนที่ฝากไว้กับ NIH อ่านได้ฟรีแต่มักมองไม่เห็นจากเส้นทางปกติ สิ่งที่ใช้ได้ ทดสอบแล้ว:

curl -sL "https://eutils.ncbi.nlm.nih.gov/entrez/eutils/efetch.fcgi?db=pmc&id=<number without PMC>"

สิ่งที่ล้มเหลวกับบทความชุดเดียวกัน: pmc.ncbi.nlm.nih.gov/.../pdf/ (HTML กันบอต), fullTextXML ของ Europe PMC (ว่าง), BioC API (เฉพาะชุดย่อย open access) และสำหรับ MDPI mdpi-res.com/d_attachment/... ให้ PDF จริงในที่ที่ mdpi.com/.../pdf คืนเป็นหน้าเว็บ

สิ่งที่ไม่ถูกตีพิมพ์ที่ใดเลย

ตรวจกับ Crossref, OpenAlex, Europe PMC, arXiv, HAL และต้นไม้ NA-MIC ทั้งหมด: FlexReg และแทร็ก MGL ของมัน, ALI_IOS, AREG_IOSCBCT, CLIC, CNE, AutoCrop3D, AutoMatrix, MedicalDataAnonymizer, สามรุ่นของ BatchDentalSeg และรุ่น nnU-Net ของ AMASSS สำหรับหลายตัวในนี้ หน้า NA-MIC Project Week เป็นคำอธิบายที่เขียนไว้เพียงหน้าเดียวที่มีอยู่: ฝากไว้ในโฟลเดอร์ที่เกี่ยวข้อง

CNE บน VISOR: โค้ด

สำหรับนักพัฒนา: สิ่งที่การพอร์ต CNE ใน VISOR ทำในโค้ด พร้อมการอ้างอิง file:line signature อาร์กิวเมนต์ สภาพแวดล้อม ความต่างจากโค้ด legacy และข้อค้นพบ คำอธิบายที่อ่านง่ายของไปป์ไลน์เดียวกัน พร้อมการคำนวณเล็ก ๆ ที่มีอยู่ในนั้น อยู่ในหน้าแอตลาส

VISOR โค้ด แอตลาส (คำอธิบาย) หน้า Legacy คู่มือ (VISOR)

การอ้างอิงในหน้านี้ระบุ repository แล้วพาธในนั้น แล้วบรรทัด: SADT-VISOR คือแค็ตตาล็อกเครื่องมือ (commit 6ba2a78), VISOR-serve คือเซิร์ฟเวอร์ (e9a7e5d), Remote คือไคลเอนต์ Slicer (AutomatedDentalToolsRemote 19b95e8), legacy คือ SlicerAutomatedDentalTools ที่ 3c67957 พาธเปล่า ๆ เช่น readers.py:41 อยู่ใน SADT-VISOR tools/CNE/src/sadt_cne/ ทุกอย่างอ่านจากโค้ด ไม่มีอะไรในหน้านี้ถูกรัน ยกเว้นการตรวจสถานะ HTTP ที่ลงวันที่ไว้ด้านล่าง ภาพรวมของ stack: VISOR

3.5 การอ่านคำตอบและการเขียน

  3. มิฉะนั้นไม่เขียนอะไรและบันทึกล้มเหลว (__init__.py:299-305) legacy เขียนคำตอบดิบ

wheel index ที่ตรึงสำหรับ llama-cpp-python คือของ CPU (SADT-VISOR tools/CNE/pyproject.toml:60-67) คอมเมนต์สามอันไม่ตรงกับมัน: ส่วนหัวของไฟล์เดียวกันกล่าวถึง "CUDA 12.4 wheel index below" (:8-23); คำอธิบายที่เผยแพร่ของ device ว่า "it needs the CUDA build of llama.cpp, which this tool pins" (__init__.py:82-84); และไฟล์ compose ของ VISOR-serve บอกว่า CNE รันในบริการ CPU ไม่ได้เพราะมาพร้อม build CUDA (docker-compose.yml:105-110) โค้ดคือ build สำหรับ CPU คำขอ cuda จึงถูกรายงานว่าถูกเมิน README ของเครื่องมือตรงกับโค้ด (SADT-VISOR tools/CNE/README.md:154-165) อย่าอ่านว่า "CNE ต้องใช้ GPU" จากที่ใด

ไม่มีตัวป้องกันความยาวของบันทึก

ข้อกังวลของ legacy เรื่องบันทึกยาว (หน้า legacy, §11) ปิดได้เพียงครึ่งเดียว คำตอบที่ถูกตัดตอนนี้ถูกปฏิเสธ (__init__.py:293-297) และ max_tokens มีค่าเริ่มต้น 2048 แทน 500 แต่ไม่มีอะไรเทียบบันทึกกับหน้าต่างบริบท หรือตรวจว่า max_tokens เหลือที่ในนั้น: context_for ปฏิเสธเฉพาะค่าติดลบ (extraction.py:146-153) ด้วยค่าเริ่มต้นของ Ortho ขีดจำกัดคำตอบเพียงอย่างเดียวเท่ากับหน้าต่าง (2048 และ 2048, :49, __init__.py:51) ใน llama-cpp-python 0.3.36 (llama.py:1343-1358) engine ยกข้อผิดพลาดเฉพาะเมื่อ prompt อย่างเดียวถึง n_ctx มิฉะนั้นมันลด max_tokens เหลือ n_ctx ลบ prompt และบันทึกไม่เคยถูกตัด ดังนั้นกับ Ortho บันทึกผ่านตราบที่คำตอบจบภายในที่ที่บันทึกเหลือไว้ และล้มเหลว (finish_reason == "length") เมื่อไม่จบ สิ่งใดที่ engine ยกจะทำให้บันทึกเดียวนั้นล้มเหลว (__init__.py:200-212)

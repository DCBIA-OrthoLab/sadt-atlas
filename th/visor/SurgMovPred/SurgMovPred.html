SurgMovPred บน VISOR

SurgMovPred ทำนายการเคลื่อนหลังผ่าตัดของจุด landmark 28 จุด จากตารางค่าวัดและแผนการผ่าตัด หน้านี้อธิบายวิธีการทีละขั้นพร้อมคณิตศาสตร์: อะไรเข้ามา แต่ละขั้นทำอะไรกับมัน และอะไรออกไป ไฟล์ บรรทัด อาร์กิวเมนต์ และข้อค้นพบอยู่ในหน้าโค้ด โมดูล Slicer แบบ legacy อยู่ในหน้าของมันเอง

โค้ด (สำหรับนักพัฒนา) VISOR ตัวถดถอย 112 ตัว CPU เท่านั้น หน้า legacy Guide (VISOR)

ชื่อไฟล์ หมายเลขบรรทัด และข้อค้นพบทุกข้ออยู่ในหน้าโค้ด ที่เก็บโค้ดที่อ้างถึงในหน้านี้: แคตตาล็อกเครื่องมือ SADT-VISOR ที่ 6ba2a78, VISOR-serve ที่ e9a7e5d, ไคลเอนต์ Slicer AutomatedDentalToolsRemote ที่ 19b95e8 และโมดูล legacy SlicerAutomatedDentalTools ที่ 3c67957 ทุกอย่างอ่านจากโค้ด ไม่ได้รันอะไรสำหรับหน้านี้

ภาพรวม: อะไรเข้า อะไรออก

SurgMovPred ทำนายว่ากระดูกจะถูกเคลื่อนไปไกลแค่ไหนในการผ่าตัดขากรรไกร มันอ่านตารางที่มีหนึ่งแถวต่อผู้ป่วย (ค่าวัด cephalometric ก่อนผ่าตัด รวมการเคลื่อนที่ที่วางแผนไว้) และคืนตารางของการเคลื่อนหลังผ่าตัดที่ทำนาย: จุด landmark 28 จุด จุดละสี่ค่า มันไม่อ่านสแกนหรือเมชใด ๆ และไม่เปลี่ยนอะไรใน Slicer

SurgMovPred บน VISOR
อินพุตตาราง CSV, XLSX หรือ ODS ของค่าวัดและแผนหนึ่งตาราง หรือโฟลเดอร์แบบแบนของตารางเหล่านั้น
วิธีการโมเดลที่ฝึกแล้ว 112 ตัว ตัวละหนึ่ง target แต่ละตัวปรับสเกลอินพุต 145 ค่าใหม่ และทำนายด้วยstack ของตัวถดถอยสามตัว
เอาต์พุตตารางสองตารางที่มีเนื้อหาเหมือนกัน คือ predictions_outputs.xlsx และ .csv: ตัวระบุผู้ป่วย แล้วหนึ่งคอลัมน์ต่อ target ที่ทำนาย
ที่ไหนบนเซิร์ฟเวอร์ ใช้เฉพาะโปรเซสเซอร์; แผง Slicer อัปโหลดตารางและบันทึกผลลัพธ์ทั้งสอง

อัลกอริทึมคือของ legacy ไม่เปลี่ยน สิ่งที่เปลี่ยนคือลำดับ การจัดการข้อผิดพลาด และสภาพแวดล้อม (สิ่งที่เปลี่ยน)

1. ตำแหน่งในสายโซ่

SurgMovPred เป็นเครื่องมือปลายทาง (leaf): ไม่เรียกเครื่องมืออื่น และไม่มีเครื่องมืออื่นเรียกมัน เหมือนในโมดูล legacy แผง Slicer เป็นไคลเอนต์บางที่สร้างจากคำอธิบายเครื่องมือของเซิร์ฟเวอร์ เครื่องมือถูกแพ็กเกจภายใต้ชื่อ Surg_Mov_Pred และเซิร์ฟเวอร์ยอมรับการสะกดแบบเก่าด้วย มีเทสต์อัตโนมัติครอบคลุมในที่เก็บโค้ดของมัน และ README รายงานว่าผลลัพธ์ตรงกับการพัฒนาบนเซิร์ฟเวอร์รุ่นก่อนบนผู้ป่วย 101 ราย และโมเดล 112 ตัว (อ่านมา ไม่ได้รันซ้ำสำหรับหน้านี้)

ในโค้ดชื่อ API โฟลเดอร์เครื่องมือ การประกาศฝั่งเซิร์ฟเวอร์ ที่มา และจำนวนเทสต์

1.1 อะไรรันที่ไหน

เซิร์ฟเวอร์ทำทุกอย่าง: อ่านตาราง ทำความสะอาดชื่อคอลัมน์ รันโมเดล 112 ตัวบนโปรเซสเซอร์ และเขียนตารางสองตาราง แผงมีหนึ่งช่อง คือค่าวัด อัปโหลดตาราง (โฟลเดอร์ถูกบีบเป็น zip ก่อนส่ง) แล้วบันทึกอาร์ไคฟ์ที่ส่งกลับมาไว้ข้างไฟล์ที่คุณเลือก ไม่มีสิ่งใดถูกโหลดเข้าฉาก Slicer

ในโค้ดหน้าที่ของเซิร์ฟเวอร์และไคลเอนต์ พร้อมบรรทัดที่เป็นตัวกำหนด

2. ไฟล์ที่เกี่ยวข้อง

เครื่องมือประกอบด้วยไฟล์ Python เล็ก ๆ สองไฟล์ (ฟังก์ชัน run และไปป์ไลน์) ไฟล์ layout ที่ซ่อนอาร์กิวเมนต์ model และเปลี่ยนชื่อช่อง ไฟล์นิยามสภาพแวดล้อม และเทสต์ โมดูล legacy คือแผง 878 บรรทัดบวกสคริปต์บรรทัดคำสั่ง 323 บรรทัด

ในโค้ดตารางไฟล์พร้อมจำนวนบรรทัด

3. ไปป์ไลน์

ในแต่ละรอบ เครื่องมือโหลดไฟล์โมเดลทั้งหมดและอ่านตารางหนึ่งครั้ง จากนั้นสำหรับแต่ละ target จาก 112 ตัวตามลำดับ มันหาคอลัมน์ที่โมเดลนั้นต้องการ ปรับสเกล ทำนาย และเก็บผลไว้ ตอนท้ายประกอบเป็นตารางเดียว คลิกกล่องเพื่ออ่านหัวข้อของมัน

ในโค้ดฟังก์ชันที่อยู่เบื้องหลังแต่ละกล่องของแผนภาพ

3.1 การโหลดแพ็กเกจโมเดล

แต่ละ target มีโฟลเดอร์ของตัวเองพร้อมหนึ่งไฟล์ คือแพ็กเกจที่เก็บสี่อย่าง ได้แก่ ชื่อของ target รายการคอลัมน์อินพุต 145 คอลัมน์ที่มันคาดไว้เรียงตามลำดับ scaler ที่ฟิตแล้ว และโมเดลที่ฟิตแล้ว เครื่องมือโหลดทุกแพ็กเกจที่พบใต้โฟลเดอร์โมเดลตามลำดับที่เรียงแล้ว คอลัมน์ของผลลัพธ์จึงออกมาในลำดับเดียวกันทุกรอบ แพ็กเกจที่อ่านไม่ได้จะถูกบันทึกลง log และข้าม และถ้าไม่มีแพ็กเกจใดโหลดได้ การรันจะหยุด ทั้ง 112 แพ็กเกจคาดหวังคอลัมน์ชุดเดียวกัน 145 คอลัมน์ 28 คอลัมน์ลงท้ายด้วย _T0 (สถานะก่อนผ่าตัด) และ 25 คอลัมน์ลงท้ายด้วย _Total (การเคลื่อนรวมที่วางแผนไว้) ตารางจึงต้องมีทั้งแผนและค่าวัด

ในโค้ดลูปโหลด คีย์ในแพ็กเกจ ข้อกำหนดเรื่อง LightGBM และคำเตือนเวอร์ชันที่ถูกปิด

3.2 การอ่านค่าวัด

ไฟล์ถูกอ่านตามนามสกุล (CSV, XLSX, ODS) โฟลเดอร์ไม่ถูกค้นหาแบบเรียกซ้ำ และตารางของมันถูกเรียงลำดับแล้วซ้อนต่อกันเป็นแนวตั้ง คอลัมน์ตัวระบุผู้ป่วยหาได้โดยลองรายการชื่อที่ใช้บ่อย (#, id, patient id และอื่น ๆ) ถ้าไม่พบ คอลัมน์ตัวระบุของผลลัพธ์จะถูกปล่อยว่างพร้อมคำเตือน ชื่อคอลัมน์ถูกทำความสะอาดให้เป็นการสะกดที่ใช้ตอนฝึกโมเดล: ลบเครื่องหมายคำพูดและวงเล็บ สิ่งที่ไม่ใช่ตัวอักษร ตัวเลข underscore หรือ apostrophe กลายเป็น underscore และชื่อที่ขึ้นต้นด้วยตัวเลขจะได้คำนำหน้า ชื่อที่ทำความสะอาดไม่ได้เป็นข้อผิดพลาด

ในโค้ดโค้ดการอ่าน รูปแบบตัวระบุทั้งแปด และกฎการทำความสะอาดพร้อมบรรทัด

3.3 หนึ่ง target ต่อหนึ่งแพ็กเกจ

สำหรับแต่ละแพ็กเกจ เครื่องมือมองหาแต่ละคอลัมน์ที่ต้องการในตาราง ความยืดหยุ่นอย่างเดียวคือ suffix _T0 ที่ขาดไป: โมเดลที่ขอ X_T0 ยอมรับคอลัมน์ชื่อ X คอลัมน์อื่นใดที่ขาดจะทำให้ target นั้นหายไปจากผลลัพธ์พร้อมคำเตือน เซลล์ว่างไม่ถูกเติมค่า: โมเดลปฏิเสธมัน ข้อผิดพลาดถูกบันทึกลง log และ target นั้นถูกตัดออกสำหรับผู้ป่วยทุกราย คอลัมน์ถูกเรียงตามลำดับที่โมเดลคาดไว้ ปรับสเกล แล้วส่งให้โมเดล

ความล้มเหลวขณะทำนายหนึ่ง target จะถูกบันทึกลง log แล้ววนลูปต่อ เฉพาะเมื่อไม่มี target ใดถูกทำนายเลยเท่านั้นที่การรันจะหยุดด้วยข้อผิดพลาด แทนที่จะเขียนตารางที่ไม่มีผลทำนาย

ในโค้ดลูปพร้อมการหา feature กฎการข้าม และกรณีข้อผิดพลาด

3.4 ผลลัพธ์

ผลทำนายกลายเป็นตารางเดียวโดยมีตัวระบุผู้ป่วยเป็นคอลัมน์ข้อมูลแรก เขียนสองครั้ง เป็น Excel และเป็น CSV ทั้งสองขึ้นต้นด้วยคอลัมน์ที่ไม่มีชื่อซึ่งระบุเลขแถว ซึ่งมีผลเมื่ออ่านตำแหน่งคอลัมน์ ทั้งสองไฟล์ถูกส่งคืนให้ไคลเอนต์ และไม่มีไฟล์รายงาน

ในโค้ดสองไฟล์ รูปแบบคอลัมน์ และค่าที่ส่งคืน

4. สิ่งที่เลือกได้

  • ค่าวัด: ตารางเดียว หรือโฟลเดอร์แบบแบนของตาราง นี่เป็นช่องเดียวที่แสดงในแผง
  • ไม่มีให้เลือก: โมเดล (ใช้ชุดของเซิร์ฟเวอร์เอง) โฟลเดอร์ผลลัพธ์ (เซิร์ฟเวอร์เป็นผู้กำหนด) และตัวเลือกใด ๆ เรื่อง target หรือค่าขีดจำกัด จะพยายามทำนายทั้ง 112 target เสมอ
ในโค้ดตารางอาร์กิวเมนต์ ชนิดผลลัพธ์ และสิ่งที่เซิร์ฟเวอร์ประกาศเรื่องทรัพยากร

5. ค่าทำนายหรือค่าคำนวณ

ขั้นตอนลักษณะ
การอ่าน การตรวจหาตัวระบุ การทำความสะอาดชื่อคอลัมน์ การจับคู่คอลัมน์คำนวณ กำหนดแน่นอน
การปรับสเกลอินพุตคำนวณด้วย scaler ที่ฟิตแล้วของแพ็กเกจแต่ละชุดเอง
การเคลื่อนหลังผ่าตัดแต่ละค่าทำนายด้วยstack ของตัวถดถอย (scikit-learn ที่มี LightGBM อยู่ข้างใน) หนึ่งตัวต่อ target ชุดที่จัดส่งมี 112 ตัว
การประกอบและเขียนตารางคำนวณ
ในโค้ดตารางที่บอกว่าแต่ละบล็อกรันที่ไหน

6. สภาพแวดล้อม

เครื่องมือมีสภาพแวดล้อม Python ของตัวเองบนเซิร์ฟเวอร์ (Python 3.12 พร้อมเวอร์ชันที่ตรึงของ numpy, pandas, scikit-learn, LightGBM และตัวอ่านสเปรดชีต) และไม่มีซอฟต์แวร์การ์ดจอเลย โมเดลถูกวางไว้บนเซิร์ฟเวอร์เป็นอาร์ไคฟ์เดียวขนาดประมาณ 740 MB (706 MiB) ไม่มีสิ่งใดถูกติดตั้งตอนรัน

ในโค้ดเวอร์ชันที่ตรึงพร้อมบรรทัด อาร์ไคฟ์โมเดล และคอมเมนต์เรื่องเวลา

7. สิ่งที่เปลี่ยนไปจากตรรกะ legacy

  • เครื่องมือรันบนเซิร์ฟเวอร์ในสภาพแวดล้อมของตัวเอง แทนที่จะรันใน Python ของ Slicer พร้อมการติดตั้งแพ็กเกจทุกครั้งที่กด Apply
  • อินพุตเป็นไฟล์หรือโฟลเดอร์แบบแบนได้ legacy รับเฉพาะโฟลเดอร์ และการอ่านโฟลเดอร์ของมันไม่มีลำดับที่คงที่
  • โมเดลและตารางถูกอ่านตามลำดับที่เรียงแล้ว การรันสองครั้งจึงให้แถวและคอลัมน์เดียวกันในลำดับเดียวกัน
  • ชื่อคอลัมน์ที่ทำความสะอาดไม่ได้เป็นข้อผิดพลาด แทนที่จะเป็นชื่อแทนที่ใช้ร่วมกันซึ่งทำให้สองคอลัมน์ชนกัน
  • การรันที่ไม่มีโมเดลใดทำนายได้เป็นข้อผิดพลาด แทนที่จะเป็นตารางสองตารางที่ไม่มีผลทำนาย
  • ส่งคืนไฟล์ผลลัพธ์ทั้งสอง และอ่านไฟล์ ODS ได้เพราะติดตั้งตัวอ่านไว้
ในโค้ดตารางเทียบ legacy กับ VISOR พร้อมบรรทัด

8. ปัญหาที่ทราบ

  • ไฟล์ผลลัพธ์ทั้งสองขึ้นต้นด้วยคอลัมน์ดัชนีที่ไม่มีชื่อ ดูข้อค้นพบ
  • คอมเมนต์บางส่วนในไคลเอนต์อธิบายไฟล์ผลลัพธ์เพียงไฟล์เดียว ดูข้อค้นพบ
  • README ของเครื่องมือระบุชื่อโฟลเดอร์ข้อมูลที่ล้าสมัย ดูข้อค้นพบ
  • target ถูกทำนายอย่างอิสระต่อกัน การเคลื่อนที่ของจุดบนส่วนกระดูกเดียวกันจึงไม่จำเป็นต้องสอดคล้องกัน และไม่มีสิ่งใดถูกนำไปใช้กับฉาก ดูข้อค้นพบ
  • target ที่ถูกข้ามมองเห็นได้เฉพาะใน log ของเซิร์ฟเวอร์ ดูข้อค้นพบ
  • ด้านดี ลำดับทำซ้ำได้ และผลลัพธ์ว่างไม่เงียบอีกต่อไป ดูการตรวจสอบ
ในโค้ดcallout ทั้งหกพร้อมหลักฐาน

9. เอกสารอ้างอิง

วิธีการและสิ่งตีพิมพ์เป็นของเครื่องมือ ไม่ว่าอะไรจะรันมัน: ดูหน้าแหล่งอ้างอิงของ SurgMovPred VISOR ไม่ได้เพิ่มโมเดลใหม่

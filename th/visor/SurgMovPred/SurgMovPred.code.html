SurgMovPred บน VISOR: โค้ด

สำหรับนักพัฒนา: สิ่งที่พอร์ต VISOR ของ SurgMovPred ทำในโค้ด พร้อมการอ้างอิง file:line โค้ด อาร์กิวเมนต์ สภาพแวดล้อม ความต่างจากโค้ด legacy และข้อค้นพบ คำอธิบายที่อ่านง่ายพร้อมคณิตศาสตร์อยู่ในหน้าแอตลาส

โค้ด แอตลาส (คำอธิบาย) VISOR ตัวถดถอย 112 ตัว CPU เท่านั้น หน้า legacy Guide (VISOR)

การอ้างอิงในหน้านี้ระบุที่เก็บโค้ด จากนั้นเส้นทางภายในนั้น แล้วบรรทัด: SADT-VISOR คือแคตตาล็อกเครื่องมือ (commit 6ba2a78), VISOR-serve คือเซิร์ฟเวอร์ (e9a7e5d), Remote คือไคลเอนต์ Slicer (AutomatedDentalToolsRemote 19b95e8), legacy คือ SlicerAutomatedDentalTools ที่ 3c67957 เส้นทางเปล่า เช่น pipeline.py:173 อยู่ใน SADT-VISOR tools/Surg_Mov_Pred/src/sadt_surgmovpred/; README.md และ pyproject.toml ที่ไม่ระบุที่เก็บโค้ดอยู่ใน tools/Surg_Mov_Pred/ ทุกอย่างอ่านจากโค้ด ไม่มีสิ่งใดในหน้านี้มาจากการรัน ภาพรวมของสแตก: VISOR และสถาปัตยกรรมของมัน

model เป็นตัวเลือกและถูกซ่อน เมื่อว่าง run() ใช้ <data_root>/Surg_Mov_Pred/models (__init__.py:19,22-34,71) จากนั้น load_model_packages หยิบ stacking_package.pkl ทุกไฟล์ใต้โฟลเดอร์นั้นตามลำดับที่เรียงแล้ว และโหลดแต่ละไฟล์ด้วย joblib (pipeline.py:162-195):

package_files = sorted(model.glob("**/stacking_package.pkl"))   # legacy: list(...), filesystem order

แพ็กเกจที่อ่านไม่ได้จะถูกบันทึกลง log และข้าม; ถ้าไม่มีแพ็กเกจใดโหลดได้ จะเกิด RuntimeError (pipeline.py:180-192) คอมเมนต์ใน layout.py:16-24 อธิบายชุดที่จัดส่ง: 112 แพ็กเกจ แต่ละแพ็กเกจขอคอลัมน์ชุดเดียวกัน 145 คอลัมน์ ซึ่ง 28 คอลัมน์มี suffix _T0 (สถานะก่อนผ่าตัด) และ 25 คอลัมน์มี suffix _Total (การเคลื่อนรวมที่วางแผนไว้) ตารางจึงต้องมีทั้งแผนและค่าวัด จึงเป็นที่มาของป้าย "Measurements and plan" ตัวถดถอยแบบ stackingมี sub-estimator ของ LightGBM ดังนั้นต้องติดตั้ง lightgbm ไว้ joblib.load จึงจะสำเร็จ (pyproject.toml:18-20) แพ็กเกจถูก pickle ไว้ภายใต้ scikit-learn 1.6.1 และถูกโหลดภายใต้ 1.7.2 คำเตือนเรื่องเวอร์ชันถูกปิดไว้โดยเจตนา เหมือนที่ upstream ทำ (pipeline.py:101-115, README.md:72-75)

3.2 การอ่านค่าวัด

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

  • หนึ่งไฟล์หรือโฟลเดอร์แบบแบน ไฟล์ถูกอ่านตามนามสกุล: .csv ด้วย read_csv, .xlsx ด้วย read_excel, .ods ด้วย read_excel(engine="odf") (pipeline.py:22,118-129) โฟลเดอร์ไม่ถูกไล่อ่านแบบเรียกซ้ำ: ไฟล์ที่มีนามสกุลหนึ่งในสามแบบนี้ โดยไม่สนตัวพิมพ์เล็กใหญ่ จะถูกเรียงลำดับและต่อกันตามแถว (:132-159) Legacy อ่านได้เฉพาะโฟลเดอร์ โดย glob นามสกุลทั้งตัวพิมพ์เล็กและตัวพิมพ์ใหญ่ แล้วตัดซ้ำด้วย set() ลำดับแถวจึงเปลี่ยนไปในแต่ละรอบ (legacy SurgMovPred_CLI/SurgMovPred_CLI.py:151-157)
  • ตัวระบุผู้ป่วย find_id_column ลองแปดรูปแบบตามลำดับ (#, id, id patient, patient id, patient number, subject id, patient, subject ไม่สนตัวพิมพ์เล็กใหญ่) จากนั้นลองคอลัมน์ใดก็ได้ที่ชื่อมีทั้ง "patient" และ "id" (pipeline.py:65-98) ถ้าไม่พบ IDPatient จะถูกปล่อยว่างพร้อมคำเตือน (:303-312)
  • ชื่อคอลัมน์ถูกทำความสะอาดให้เป็นรูปแบบตอนฝึกด้วย clean_name: ตัดช่องว่าง ลบเครื่องหมายคำพูด แบ็กสแลช และวงเล็บ ทุกลำดับอักขระที่ไม่ใช่ตัวอักษร ตัวเลข underscore และ apostrophe กลายเป็น underscore หนึ่งตัว total กลายเป็น Total และชื่อที่ขึ้นต้นด้วยตัวเลขจะได้ f_ นำหน้า (pipeline.py:27-50) ชื่อที่ทำความสะอาดไม่ได้จะทำให้เกิด ValueError (:51-60); legacy คืนค่า 'f_unnamed' คอลัมน์สองคอลัมน์แบบนั้นจึงบังกัน (legacy SurgMovPred_CLI.py:63-66)

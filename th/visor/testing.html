1. โครงสร้างของเครื่องมือ

SADT-VISOR เก็บ "one isolated Python project per SlicerAutomatedDentalTools tool" โดยแต่ละตัวมีอินเทอร์พรีเตอร์ virtualenv และ lockfile ของตัวเอง และเครื่องมือไม่นำเข้ากันเอง (SADT-VISOR README.md:3-5) ที่เก็บโค้ดไม่มีโค้ดเซิร์ฟเวอร์ (README.md:7-8) เครื่องมือคือโฟลเดอร์ที่มี:

ไฟล์บทบาท
pyproject.toml ที่มีตาราง [tool.sadt]tool = true และ name = "<ApiName>": ตารางนี้คือสิ่งที่ทำให้โฟลเดอร์เป็นเครื่องมือ สำหรับ CI, registry ของเซิร์ฟเวอร์ และการ build อิมเมจเหมือนกัน (CONTRIBUTING.md:50-59; ตัวอย่าง tools/AMASSS/pyproject.toml:33-35)
src/sadt_<name>/__init__.pyกำหนดฟังก์ชันสาธารณะเดียว run(...); ไม่มีคลาสฐานและไม่มี registry (README.md:41-58)
uv.lockคอมมิตไว้; CI sync ด้วย --frozen ซึ่งล้มเหลวหาก lock ล้าสมัย (CONTRIBUTING.md:603)
tests/test_run.py, tests/test_integration.pyการทดสอบสองระดับด้านล่าง; tools/_template/ คือโครงที่ให้คัดลอก
README.mdรวมบล็อก "Provenance" (ส่วนที่ 4)

ชื่อโฟลเดอร์คือชื่อ API (virtualenv ของเครื่องมือถูกหาที่ <TOOLS_DIR>/<name>/.venv/bin/python, CONTRIBUTING.md:70-77); โฟลเดอร์จัดกลุ่มสองโฟลเดอร์ tools/ALI/ และ tools/AREG/ เก็บเอนจิน (ALI_CBCT, ALI_IOS, AREG_CBCT, AREG_IOS, AREG_IOSCBCT) และแพ็กเกจ common/ แพ็กเกจร่วมมี pyproject.toml ที่ไม่มี [tool.sadt]: ติดตั้งได้ แต่ไม่ถูกค้นพบและไม่ถูก serve ไม่มี [tool.uv.workspace] เพราะ lock ร่วมอันเดียวจะบังคับให้ torch 1.13 และ 2.4 อยู่ในการ resolve เดียวกัน (CONTRIBUTING.md:578-583) สิบเก้าโฟลเดอร์ที่ประกาศ [tool.sadt]: Agent, ALI_CBCT, ALI_IOS, AMASSS, AREG_CBCT, AREG_IOS, AREG_IOSCBCT, ASO, AutoCrop3D, AutoMatrix, Batch_Dental_Seg, CLIC, CNE, Crown_Seg, DOCShapeAXI, FlexReg, GreedyReg, Surg_Mov_Pred, VFACE (นับด้วย find เดียวกับ CI)

สคีมาที่ไคลเอนต์เรนเดอร์ไม่ได้เขียนด้วยมือ scripts/describe.py derive มันจากซิกเนเจอร์ของ run(): annotation ที่อนุญาตคือ Path, str, int, float, bool, Literal[...], list[...] ของสิ่งเหล่านั้น และ tuple[float, float] (เผยแพร่เป็น vec2); ไม่มี Optional ไม่มี union ไม่มีค่าเริ่มต้นเป็น None (describe.py:38-46,193-296) ทุกอาร์กิวเมนต์ต้องมีบรรทัดในบล็อก Args: ของ docstring (describe.py:807-841) สิ่งใดที่มันแทนไม่ได้จบด้วยรหัสออก 2 โดยไม่มีอะไรบน stdout (:1185-1187) ตาราง "ArgSpec" ที่เก็บด้วยมือแบบเก่าถูกยกเลิกเพราะมัน "drifted" (describe.py:8-11)

2. การทดสอบสามระดับ

ระดับ 1: ในโปรเซส อินพุตสังเคราะห์

tests/test_run.py มีอยู่ในทั้ง 19 เครื่องมือและใน template (AREG/common ซึ่งเป็นแพ็กเกจร่วม ไม่มี) กฎคือเรียก run() ตั้งแต่ต้นจนจบ ตรวจว่าไฟล์ที่คาดไว้มีอยู่ มีขนาดที่สมเหตุสมผล และตรงกับอ้างอิงภายในความคลาดเคลื่อนที่บันทึกไว้ (CONTRIBUTING.md:605-609) ในทางปฏิบัติ fixture ถูกประดิษฐ์ขึ้นภายในการทดสอบ: วอลุ่ม SimpleITK ขนาด 8, 16 หรือ 48 voxel ต่อด้าน เมช VTK ของสามเหลี่ยมสามรูป กะโหลกเจ็ดจุด อาร์เรย์ .npy โมเดล scikit-learn ที่ฟิตทันที และเอนจิน nnU-Net หรือ shapeaxi ที่ถูกแทนด้วย stub (tools/AMASSS/tests/data/README.md:1-9, tools/ASO/tests/data/README.md:1-9, tools/AREG/TESTING.md:3-12) จำนวนตามเครื่องมือ (def test_): Agent 206, ALI_IOS 183, AREG_IOSCBCT 172, VFACE 164, Crown_Seg 162, GreedyReg 158, ASO 145, AutoMatrix 139, CNE 130, CLIC 124, Surg_Mov_Pred 105, AutoCrop3D 103, AREG_CBCT 94, DOCShapeAXI 91, ALI_CBCT 66, AMASSS 61, AREG_IOS 56, Batch_Dental_Seg 55, AREG/common 40, FlexReg 21, template 17

ระดับ 2: นอกโปรเซส ด้วย testkit

testkit/ (แพ็กเกจ sadt-testkit) มี run_tool(name, **params) (sadt_testkit/__init__.py:192), tool_schema (:248), is_built (:152) และข้อยกเว้น ToolNotBuilt กับ ToolFailed มันเปิดเครื่องมือในอินเทอร์พรีเตอร์ของมันเอง จากไดเรกทอรีทำงานที่เป็นกลาง ด้วยไดรเวอร์ที่ใช้เฉพาะ stdlib ซึ่งเป็น "a miniature of the server's runner" (การแปลงตาม annotation เหมือนกัน ไฟล์ผลลัพธ์เดียวกัน ชื่อคลาสข้อยกเว้นเดียวกัน; _driver.py:1-16) มันมีไว้ตรวจสิ่งที่เห็นได้จากภายนอกเท่านั้น: เครื่องมือไม่เขียนอะไรนอก output_dir และสคีมาที่เผยแพร่ตรงกับซิกเนเจอร์ กฎคือข้าม ไม่ล้มเหลว เมื่อเครื่องมืออื่นยังไม่ถูก build (CONTRIBUTING.md:629-632) ใช้โดย Agent, ALI_CBCT, AREG_IOSCBCT, ASO, VFACE และ template ไฟล์ละหนึ่ง; LocalSup ของ ASO ยาวราวสิบกว่าบรรทัดห่อ run_tool เพื่อทำหน้าที่แทน supervisor ของเซิร์ฟเวอร์

ระดับ 3: ข้อมูลจริง ไม่เคยอยู่ใน CI

การทดสอบบนโมเดลและสแกนจริงมี mark gpu และ models; ไฟล์มาจาก DATA/ ของการติดตั้งใช้งานและระบุชื่อด้วยตัวแปร environment (SADT_AMASSS_MODELS, SADT_AMASSS_SCAN, SADT_ALI_CBCT_MODELS, SADT_CROWNSEG_MODEL, SADT_SURGMOVPRED_MODELS, SADT_CLIC_MODEL และอื่น ๆ) CI ตัด gpu ออกเพราะ runner ไม่มีอุปกรณ์ CUDA และที่เก็บโค้ดบอกว่านี่ทำให้มันเป็นความรับผิดชอบของผู้เขียน: รันด้วยมือและระบุผลใน pull request (CONTRIBUTING.md:638-640) เครื่องมือแปดตัวยังตั้ง addopts = "-m 'not gpu and not models'" (Agent, CLIC, CNE, Surg_Mov_Pred, Crown_Seg, VFACE, AREG_IOSCBCT, ALI_IOS) เพื่อให้ override ด้วย -m models -o addopts= ไม่มีข้อมูลผู้ป่วยถูกคอมมิตเลย; CONTRIBUTING.md:611-614 ขอ "a download script plus checksums" และไม่มี download.sh หรือ *.sha256 อยู่: tests/data/README.md แต่ละไฟล์บอกว่า "Nothing is committed here" และชี้ไปที่ตัวแปร environment หรือ manifest ของโมเดลของ VISOR-serve

CI รันอะไร

หนึ่ง workflow คือ .github/workflows/ci.yml (105 บรรทัด) บน pull request และบน push ไปที่ main

งานทำอะไรสิ่งที่รับประกัน
discover (:16-36)หา pyproject.toml ทุกไฟล์ที่ลึกลงไปสองหรือสามระดับซึ่งมี [tool.sadt]matrix ถูกอ่านจากดิสก์: การเพิ่มเครื่องมือไม่เคยหมายถึงการแก้ CI; กฎเดียวกับ registry ของเซิร์ฟเวอร์และ Dockerfile; _template และแพ็กเกจร่วมถูกยกเว้น
tool (:38-74) หนึ่งงานต่อเครื่องมือ (19) fail-fast: falseuv sync --frozen; describe.py ในอินเทอร์พรีเตอร์ของเครื่องมือเอง; pytest -m "not gpu"lock ตรงกับ pyproject.toml; เครื่องมือนำเข้าได้โดยไม่ต้องมีสแต็ก CUDA และซิกเนเจอร์ของมันให้สคีมา ("a schema the client cannot render never reaches main"); ชุดทดสอบที่ไม่ใช่ GPU ผ่าน
scripts (:76-88)pytest scripts/tests แล้ว scripts/audit.pyการทดสอบของ describe.py, run_tool.py, audit.py และสำเนา vendored (ผ่าน 89 ข้าม 4 เมื่อรันสำหรับหน้านี้); audit.py เป็นรายงานแบบอ่านอย่างเดียวและไม่เคยทำให้งานล้มเหลว
testkit (:93-105)build tools/_template แล้วรันชุดทดสอบของ testkit เองเครื่องมือทดสอบที่ทุกการทดสอบการรวมระบบเชื่อถือก็ถูกทดสอบเอง

CI ไม่ได้รันอะไร

  • การทดสอบที่ mark gpu ถูกตัดออกโดย -m "not gpu" (ci.yml:66-74)
  • การรวมระบบข้ามเครื่องมือ แต่ละเครื่องมือมีงานของตัวเอง จึงไม่มี virtualenv ของเครื่องมืออื่นอยู่ และการทดสอบข้ามตัวเอง (ci.yml:69-70, is_built) ลูกโซ่ ASO ไป ALI, AREG ไป ASO, VFACE ไป AREG ไม่เคยถูกทดสอบใน CI
  • การทดสอบ 26 ตัวของ naming/ การทดสอบ 40 ตัวของ tools/AREG/common/tests/ (ทั้งสองไม่มี [tool.sadt] จึงไม่อยู่ใน matrix และไม่มีงานอื่นรันมัน) และ common ของ ALI ซึ่งไม่มีการทดสอบเลยทั้งที่ pyproject.toml ของมันประกาศ testpaths = ["tests"]
  • การกวาด pyflakes ที่ CONTRIBUTING.md:681-685 ขอให้ทำก่อน PR: ไม่พบใน workflow
  • ทุกอย่างเกี่ยวกับการทำซ้ำเชิงตัวเลขข้ามเวอร์ชัน torch หรือ MONAI; ปล่อยให้เป็นการตรวจสอบด้วยมือใน README ของแต่ละเครื่องมือ
mark ที่บรรทัดคำสั่ง override

เครื่องมือแปดตัวที่ addopts ตัด models ออกถูก CI รันด้วย -m "not gpu" บนโปรเจกต์ pytest ทิ้งขว้างที่สร้างเพื่อตรวจสอบ -m ที่ให้ทางบรรทัดคำสั่งแทนที่ตัวใน addopts ดังนั้นการทดสอบ models จึงถูกเก็บ พวกมันข้ามผ่าน skipif ของตัวเองบนตัวแปร environment เท่านั้น จาก 25 การใช้ mark.models มี 9 ที่ตามด้วย skipif ภายในสี่บรรทัด (นับคร่าว ๆ); ไม่ได้ตรวจทีละตัวว่าแต่ละตัวข้ามใน CI หรือไม่ ไม่ได้สังเกตใน CI จริง

3. การตั้งชื่อ: sadt_naming

"Naming" ครอบคลุมสองอย่าง ชื่อ API ของเครื่องมือมาจาก [tool.sadt] name หรือไม่ก็จากโฟลเดอร์; ตัวย่อคงเดิม (ALI, AMASSS) และคำถูกทำให้ขึ้นต้นด้วยตัวใหญ่แล้วต่อด้วย _ (Batch_Dental_Seg); แพ็กเกจ Python คงเป็นตัวพิมพ์เล็ก (CONTRIBUTING.md:61-65,81-89) การเปลี่ยนชื่อเป็นการเปลี่ยนที่ทำให้เสียความเข้ากันได้สำหรับทุกไคลเอนต์ (:91-93) หมายเหตุ: describe.py ไม่อ่าน [tool.sadt] name: name ที่เผยแพร่คือชื่อโฟลเดอร์ (describe.py:1157)

ศัพท์ของชื่อไฟล์ คือแพ็กเกจ naming/ (sadt_naming) ใช้เฉพาะไลบรารีมาตรฐาน (dependencies = [], naming/pyproject.toml:3-12) มันเก็บกลุ่มนามสกุล (VOLUME หกนามสกุล ประกอบก่อนเพื่อให้ .nii.gz ชนะ .gz; SURFACE, MARKUPS, TRANSFORM, NOTES, TABLE) เครื่องหมายผลลัพธ์สิบสามตัวที่เครื่องมือต่อท้าย (_lm_Pred, _Scanreg, _MERGED, _OutReg, _SegOr, _SegOut และอื่น ๆ จับคู่เป็นโทเค็นทั้งคำและแยกตัวพิมพ์) การสะกดขากรรไกรสิบสามแบบ (u up upper maxilla max mx l low lower mandible mand md และรูปแบบภาษาฝรั่งเศส) และช่วงเวลา t0 t1 t2 (naming/src/sadt_naming/__init__.py:36-175) มันแยก UpperT1 เป็นขากรรไกรและช่วงเวลา (:217) และตัดชื่อที่เครื่องหมายแรกโดยไม่เคยตัดชื่อที่เพียงขึ้นต้นด้วยเครื่องหมายนั้น (:252)

7. Benchmark เป็นการวัด ไม่ใช่การทดสอบ

VISOR-serve benchmarks/ ทำซ้ำตัวเลขเวลาของบทความประกอบ (แคมเปญ B1 latency, B2 เฟสเครือข่าย, B3 ต้นทุน supervisor, B4 concurrency, B5 ความเท่ากันระดับไบต์ระหว่างเส้นทางในเครื่องและ HTTP) การรันที่บันทึกไว้มาจากเดือนสิงหาคม 2026 บนโค้ดเดือนสิงหาคมของเครื่องมือ จากต้นไม้ทำงานที่ mark ว่า "dirty"; มีสรุปสำหรับ B1, B3 และ B4 เท่านั้น มันไม่ตรวจอะไร และไม่อาจสรุปข้ออ้างเรื่อง parity ได้: ในเซสชัน B5 ล่าสุด การควบคุมเส้นทางเดียวกันแสดงว่าเครื่องมือส่วนใหญ่ไม่ให้ผลซ้ำทุกไบต์แม้กับตัวเอง (รายงานของมันมีระยะเวลาและพาธ) และมีเพียง AREG_IOSCBCT ที่ตรงกันเต็มที่ระหว่างสองเส้นทาง ตัวเลขและขีดจำกัดอยู่ในหน้าการติดตั้งใช้งาน

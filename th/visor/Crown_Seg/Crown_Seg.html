Crown_Seg: การเลขฟัน เฉพาะ VISOR

Crown_Seg เขียนเลขฟันของทุกซี่ของสแกนพื้นผิว intraoral ลงในอาร์เรย์ต่อจุดยอด เพื่อให้เครื่องมือlandmarkและการลงทะเบียนที่ตามมาหาฟันเจอ มันไม่มีหน้าของตัวเองในแอตลาสฉบับ legacy เพราะ repository ของ legacy ไม่มีเครื่องมือนี้: งานทำโดยโมดูล command line ของ Slicer ภายนอก ที่เรียกจากสี่โมดูล VISOR ทำให้มันเป็นเครื่องมือของตัวเอง ที่เรียกโดยเครื่องมืออื่นสามตัว หน้านี้อธิบายทีละขั้น รายละเอียดที่นักพัฒนาต้องใช้อยู่ในหน้าโค้ด

เฉพาะ VISOR SADT-VISOR 6ba2a78 VISOR-serve e9a7e5d Remote 19b95e8 โค้ด (นักพัฒนา)

ไม่มีโมดูล legacy repository ของ legacy (SlicerAutomatedDentalTools ที่ 3c67957) ไม่มีโมดูล Crown_Seg สิ่งที่มีคือการเรียกโมดูล CrownSegmentationcli ของส่วนขยาย SlicerDentalModelSeg ที่แยกต่างหาก และสำเนาเล็ก ๆ ของการเรียกเดียวกันใน command line ของ ALI_IOS ความสอดคล้องที่แน่นอนอยู่ในส่วนคู่เทียบใน Legacy วิธีที่ VISOR รันเครื่องมือบนเซิร์ฟเวอร์อธิบายในสถาปัตยกรรม หลักฐาน

ภาพรวม: อะไรเข้า อะไรออก

เข้าออก
เมชพื้นผิว intraoral หนึ่งชิ้น (.vtk หรือ .stl) หรือโฟลเดอร์ของมัน และระบบการเลขฟันที่ใช้ (Universal หรือ FDI)สำเนาของแต่ละเมชเป็น .vtk พร้อมอาร์เรย์เลขฟันต่อจุดยอด (Universal 1 ถึง 32, เหงือก 33 หรือค่าเทียบเท่า FDI) และ run_report.json ที่บอกว่าเกิดอะไรกับแต่ละเมช

1. สถานะและที่อยู่

รายการสถานะ
ชื่อ APICrown_Seg เครื่องมือฝั่งเซิร์ฟเวอร์ที่ประกาศในไฟล์โปรเจกต์ของตัวเอง
EnvironmentPython 3.11 พร้อมสภาพแวดล้อมของตัวเอง (torch, vtk, numpy) engine สำหรับ segmentation เป็นส่วนเสริมที่ไม่บังคับ เพื่อให้ import แพ็กเกจและเผยแพร่ schema ได้โดยไม่มี stack ของ GPU
เอนจินไม่ได้พอร์ต: ฟังก์ชัน segmentation ฟันของ shapeaxi เองถูกเรียกโดยตรง ด้วยตัวเลือกที่ command line ของมันจะสร้าง วิธีแก้เฉพาะหน้าของเครื่องมือเองหนึ่งอย่างซ่อมพาธ import ที่ shapeaxi 2.0.x ย้าย
น้ำหนักโมเดลcheckpoint หนึ่งไฟล์ (6.6 MB จาก release Fly-by-CNN 3.0) จัดเตรียมบนเซิร์ฟเวอร์ และอีกครั้งที่ที่ ALI_IOS ส่งโฟลเดอร์โมเดลของตัวเองต่อได้ โฟลเดอร์ที่ให้เป็นโมเดลถูกค้นแบบเรียกซ้ำหาไฟล์ .pth ที่ชื่อมี val-loss ผู้สมัครสองไฟล์ถูกปฏิเสธโดยระบุชื่อทั้งสอง
ไคลเอนต์แผงเล็ก ๆ (“Crown Segmentation”): ฟอร์มที่สร้างจาก schema และช่องทำเครื่องหมายสำหรับโหลดเมชที่มี label เป็นโมเดล ไม่เกิน 12 ไม่มีไอคอนและไม่มีเทสต์
เรียกไม่มี: เป็นใบ
ทรัพยากรที่ประกาศไม่มี: ไม่มี timeout, width หรือขีดจำกัดการอัปโหลดของตัวเอง การกวาดจำนวนเธรดที่บันทึกในคอมเมนต์ของโค้ด admission ของเซิร์ฟเวอร์ระบุว่าการรันใช้ราว 55 วินาทีไม่ว่าจะกี่เธรด (การวัดที่ยกมาจากโค้ด ไม่ได้รันซ้ำที่นี่)
สถานะพัฒนาแล้ว พร้อมไฟล์เทสต์ 8 ไฟล์ README ของ AREG พี่น้องอธิบายสายโซ่ว่ายังไม่ได้ตรวจสอบครบวงจรกับเครื่องมือจริง เครื่องมือไม่มีสภาพแวดล้อมของตัวเองบนเครื่องนี้ จึงไม่ได้รันเทสต์และ engine ของมัน
ในโค้ดไฟล์และบรรทัดของทุกแถว เวอร์ชันที่ตรึง และการค้นหา checkpoint

2. ใครเรียกมัน

ผู้เรียกเมื่อใด
ALI_IOSเมชใดของชุดที่ไม่มีอาร์เรย์ label ก่อนถึงlandmark จากนั้นอ่านรายงานและเปลี่ยนชื่อแต่ละผลลัพธ์เป็นชื่ออินพุต เมชที่ล้มเหลวถูกตัดทิ้งเฉพาะตัว
AREG_IOSโหมด Fully-Automated สำหรับทั้งสองสแกน (T1 และ T2)
AREG_IOSCBCTโหมด Semi-Automated และ Fully-Automated ไม่ใช่ Registration
ASOไม่เคย: เมช intraoral ที่ไม่มี landmark และไม่มีอาร์เรย์ label ถูกปฏิเสธด้วยข้อความ “Run Crown_Seg over them first”

ใน deployment ของ AREG ฟิลด์ model ถูกซ่อน Crown_Seg จึงหาcheckpointของตัวเอง

ในโค้ดบรรทัดการเรียกในผู้เรียกแต่ละราย และการตั้งค่า deployment

3. ไฟล์ที่เกี่ยวข้อง

ไม่มีไฟล์ legacy ให้เทียบ: งานของ legacy อยู่ในส่วนขยายภายนอก (ดูส่วนคู่เทียบใน Legacy) เครื่องมือมีไฟล์หลักสองไฟล์: หนึ่งเก็บค่าเริ่มต้นของอาร์กิวเมนต์และการเรียก และอีกไฟล์ที่ยาวกว่าเก็บทุกอย่างที่เหลือ (ค่าคงที่ การ import shapeaxi และการซ่อมมัน การเลือกอุปกรณ์ การค้นหาcheckpoint การค้นหาเมช สองสาขา การเรียก shapeaxi และรายงาน) บวกไฟล์ layout ไฟล์ errors และไฟล์เทสต์ 8 ไฟล์

ในโค้ดตารางไฟล์พร้อมจำนวนบรรทัด และแผงไคลเอนต์

4. ไปป์ไลน์

4.1 สิ่งที่เครื่องมือทำรอบ engine

  1. checkpoint ก่อน น้ำหนักถูกหาก่อนมีอะไรถูกสร้าง คำขอที่ถูกปฏิเสธจึงทิ้งโฟลเดอร์ผลลัพธ์ไว้ตามที่พบ
  2. การค้นหา .vtk หรือ .stl หนึ่งไฟล์ หรือโฟลเดอร์ที่เดินค้นแบบเรียกซ้ำและเรียงลำดับ ไม่พบอะไรถูกปฏิเสธ
  3. การจัดเรียง เมื่อskip segmented เปิดอยู่ (ค่าเริ่มต้น) แต่ละเมชถูกเปิดและอ่านเฉพาะชื่ออาร์เรย์ของจุด ถ้ามีชื่อใดของ PredictedID, UniversalID, Universal_ID หรือ FDI_ID เมชจะไปสาขาคัดลอก
  4. สาขาคัดลอก แต่ละเมชที่มี label ถูกเขียนเป็น .vtk ในโฟลเดอร์ผลลัพธ์ โดย .stl ถูกแปลง label ไม่ถูกแตะ
  5. สาขา segment เมชที่เหลือถูกลิสต์ในตารางงานเล็ก ๆ อุปกรณ์ถูกแก้เป็น GPU หรือ CPU และเรียก shapeaxi ครั้งเดียวสำหรับทั้งรายการ

ถ้า import shapeaxi ไม่ได้ การรันไปต่อสำหรับสาขาคัดลอกและบันทึกว่า engine ใช้ไม่ได้ เมชที่ต้องใช้เครือข่ายจึงไม่มีผลลัพธ์และถูกทำเครื่องหมายว่าล้มเหลว

ในโค้ดตัวเลือกที่ส่งให้ shapeaxi อย่างแน่นอน การซ่อมการ import และลำดับของขั้นตอน

4.2 ภายใน shapeaxi

เครือข่ายคือเครือข่าย segmentation ฟันของ shapeaxi ที่มี 34 คลาสเอาต์พุต แต่ละพื้นผิวถูกโหลดทีละชิ้นและเรนเดอร์จากหลายมุมมอง สำหรับแต่ละพิกเซลเครือข่ายคืนคะแนนของคลาสต่าง ๆ พร้อมหน้าของเมชที่พิกเซลนั้นแสดง

นั่นให้หนึ่ง label ต่อหน้า และ label ของแต่ละหน้าถูกให้กับจุดยอดแรกของมัน จากนั้น label ถูกทำความสะอาด

การทำความสะอาดลบ island ก่อนสำหรับเลเบลเหงือก (33) ด้วยเกณฑ์ 500 จากนั้นสำหรับทุกเลเบลด้วย 200 แล้วทำ closing แต่ละเลเบลด้วย dilation ตามด้วย erosion สองรอบ ผลลัพธ์ถูกเขียนไปยังพาธที่คาดเดาได้ ซึ่ง Crown_Seg คำนวณใหม่แทนการอ่านเอาต์พุตของ shapeaxi และเมชแต่ละชิ้นจะถูกทำเครื่องหมายว่า segmented ถ้าไฟล์ของมันมีอยู่ และ failed ถ้าไม่มี

ในโค้ดคลาสของเครือข่าย data loader การเรียกหลังประมวลผล และกฎของพาธเอาต์พุต

4.3 การเลขฟัน: Universal และ FDI

ค่า Universalค่า FDIฟัน
1 ถึง 818 ลงมาถึง 11บนขวา จากฟันกรามซี่ที่สามถึงฟันตัดกลาง
9 ถึง 1621 ขึ้นไปถึง 28บนซ้าย จากฟันตัดกลางถึงฟันกรามซี่ที่สาม
17 ถึง 2438 ลงมาถึง 31ล่างซ้าย จากฟันกรามซี่ที่สามถึงฟันตัดกลาง
25 ถึง 3241 ขึ้นไปถึง 48ล่างขวา จากฟันตัดกลางถึงฟันกรามซี่ที่สาม
33 (เหงือก)0เหงือก

shapeaxi เขียนจำนวนเต็มที่แปลงแล้วกลับภายใต้ชื่ออาร์เรย์เดิม เพราะสองระบบใช้ช่วงตัวเลขซ้อนกันเป็นส่วนใหญ่ อาร์เรย์ FDI ที่ชื่อ Universal_ID จะถูกอ่านโดยไม่มีข้อผิดพลาดเป็นฟันซี่อื่น: FDI 18 คือฟันกรามซี่ที่สามบนขวา ส่วน Universal 18 คือฟันกรามล่างซ้าย ดังนั้น Crown_Seg จึงตั้งชื่ออาร์เรย์ตามระบบเลข: ถ้าปล่อยว่าง ชื่ออาร์เรย์จะเป็น Universal_ID หรือ FDI_ID ตัวอ่านปลายทางทุกตัวมองหาเฉพาะชื่อ Universal ดังนั้นเมช FDI จะถูก ALI_IOS, ASO หรือ AREG_IOS ปฏิเสธ แทนที่จะถูกอ่านผิด ผู้เรียกแบบ legacy ทุกรายขอเลข Universal ผลลัพธ์ FDI จึงเป็นของใหม่ในทางปฏิบัติ และ Universal ยังคงเป็นค่าเริ่มต้น

ในโค้ดตารางค้นหา กฎชื่ออาร์เรย์ และการตรวจสอบในเครื่องมือปลายทาง

5. สิ่งที่เลือกได้

การตั้งค่าค่าเริ่มต้นทำอะไร
เมชจำเป็นไฟล์หรือโฟลเดอร์ เฉพาะ .vtk และ .stl โฟลเดอร์ถูกค้นหาแบบเรียกซ้ำ
ส่วนต่อท้ายSegเติมต่อท้ายชื่อเอาต์พุตแต่ละไฟล์
ระบบเลขฟันUniversalUniversal หรือ FDI
ข้ามที่ segment แล้วเปิดส่งเมชที่มีอาร์เรย์เลเบลอยู่แล้วผ่านไปโดยไม่เปลี่ยนแปลง

อีกสี่การตั้งค่าเป็นเรื่องเทคนิคและซ่อนจากแพทย์: โมเดล (ว่างหมายถึงโฟลเดอร์ของเครื่องมือเอง) ชื่ออาร์เรย์ (ว่างหมายถึงตามระบบเลข) อุปกรณ์ (ค่าเริ่มต้น cuda และถอยไปใช้ CPU พร้อมคำเตือนเมื่อมองไม่เห็นการ์ด) และจำนวน worker ที่โหลดข้อมูล (อย่างน้อย 1)

เอาต์พุต เครื่องมือคืนโฟลเดอร์เอาต์พุตของมัน อาจมีสองต้นไม้โฟลเดอร์: เมชที่เครือข่าย segment จะอยู่ใต้โฟลเดอร์ที่ตั้งชื่อตามตารางงาน ส่วนเมชที่มีเลเบลอยู่แล้วจะถูกคัดลอกไว้ข้างพาธสัมพัทธ์ของมัน ผู้เรียกควรอ่าน run_report.json แทนการเดา รายงานนี้ระบุต่อเมชหนึ่งสถานะ (segmented, already segmented, engine unavailable หรือ failed) อินพุตและไฟล์ที่ผลิต พร้อมสรุปจำนวนและระยะเวลา การรันทั้งหมดจะล้มเหลวก็ต่อเมื่อไม่มีเมชใดถูกผลิตเลย shapeaxi พิมพ์พาธของทุกเมชที่มันบันทึก และพาธนั้นมีชื่อไฟล์ของผู้ป่วย จึงต้องกลืนเอาต์พุตนั้นทิ้ง

ในโค้ดชนิดของอาร์กิวเมนต์ที่เผยแพร่ คีย์ของรายงาน และการจัดการความเป็นส่วนตัวของล็อก

7. คู่เทียบใน Legacy

ไม่มี Crown_Seg แบบ legacy ที่จะเทียบทีละบรรทัด มีสี่ตำแหน่งในที่เก็บ legacy ที่ 3c67957 ที่ทำงานนี้ และตารางบอกว่าแต่ละตำแหน่งตรงกับส่วนใดของ Crown_Seg

ส่วนของ legacyสิ่งที่มันทำคู่เทียบใน VISOR
โมดูล CrownSegmentationcli ของ extension SlicerDentalModelSeg ซึ่งถูกเรียกโดย ALI, ASO, AREG และ FlexRegรัน executable ของการ segment โมเดลฟันในสภาพแวดล้อม shapeaxi ใน subprocess และไม่สนใจ return code ของมัน โมดูลที่หายไปทำให้การรันหยุดพร้อมคำขอให้ติดตั้ง extensionตัวเครื่องมือ Crown_Seg เอง เรียกผ่านตัวควบคุม (supervisor) จาก ALI_IOS, AREG_IOS และ AREG_IOSCBCT ไม่ต้องติดตั้ง extension เมชที่ไม่มีเอาต์พุตจะถูกทำเครื่องหมายว่า failed เพียงชิ้นเดียว
การข้ามและการทดสอบว่า segment แล้วในเมธอด Slicer ของ ALIแยกเมชเป็นกลุ่มที่มีอาร์เรย์เลเบลและกลุ่มที่ไม่มี คัดลอกกลุ่มแรกเป็น <name>_Seg<ext> ลงในโฟลเดอร์แบนข้ามที่ segment แล้ว พร้อมชื่อที่สี่ FDI_ID สำเนาถูกแปลงเป็น .vtk และรักษาต้นไม้โฟลเดอร์ไว้
สองขั้นตอนเดียวกันในบรรทัดคำสั่งของ ALI_IOSบรรพบุรุษที่ใกล้ที่สุดในที่เก็บ: executable ตัวเดียวกัน ด้วยตัวเลือกคงที่และตารางหนึ่งบรรทัด การทดสอบของมันยังกำหนดให้อาร์เรย์เลเบลมีมากกว่าหนึ่งค่า และอ่าน .vtk กับ .vtpทดสอบเฉพาะชื่ออาร์เรย์ บน .vtk และ .stl ALI_IOS ถามเครื่องมือแทนการเรียก shell
พารามิเตอร์ของการเรียก ตามที่ ALI สร้างโมเดล "latest" ซึ่งถอยไปใช้โมเดลเริ่มต้นของ shapeaxi ที่ดาวน์โหลดจาก URL เลข Universal ไม่เขียนทับ ส่วนต่อท้าย Segcheckpointที่จัดเตรียมไว้ถูกส่งเป็นโมเดล ระบบเลขมาแทนแฟลก FDI และชื่ออาร์เรย์ตามมา
การเรียกของ FlexRegเปิดการเขียนทับและไม่มีส่วนต่อท้าย: การเรียกเขียนทับไฟล์ที่ได้รับไม่มีการเขียนอะไรนอกโฟลเดอร์เอาต์พุตเลย อินพุตไม่ถูกแก้ไข
แพตช์ของไลบรารีที่ติดตั้งในชั้นที่ใช้ร่วมกันเขียนไฟล์ shapeaxi ที่ติดตั้งใหม่ เพื่อให้พาธคลาสหนึ่งชี้ไปยังคลาสที่ย้ายไปการซ่อม import ตอนรันแทนการแก้ไฟล์

สิ่งที่ไม่เปลี่ยนคือเอนจินและการหลังประมวลผลของมัน: ทั้งสองฝั่งรันการ segment ฟันของ shapeaxi เอง ดังนั้นตัวเลขที่มันเขียนมาจากเครือข่ายเดียวกัน การเรียก shapeaxi ที่ไม่เขียนอะไรให้เมชหนึ่งเคยมองไม่เห็น ตอนนี้เป็นกรณี failed ของเมชนั้นเพียงชิ้นเดียว และเป็นข้อผิดพลาดก็ต่อเมื่อไม่มีเมชใดออกมาเลย

ในโค้ดตารางเดียวกันพร้อมไฟล์และบรรทัดของทุกส่วน

8. ปัญหาที่ทราบ

  • การเลขแบบ FDIทับบนเมชที่มีเลเบลอยู่แล้ว: สำเนาคงจำนวนเต็ม Universal ไว้ ขณะที่รายงานประกาศว่าเป็น FDI หลักฐาน
  • รู้จักสี่ชื่อที่นี่ สามชื่อที่ปลายทาง: เมชที่มีแต่ FDI_ID ผ่าน Crown_Seg ได้ และถูกเครื่องมือถัดไปปฏิเสธ หลักฐาน
  • เมชแบบ .vtp หรือ .obj มองไม่เห็นสำหรับ Crown_Seg ทั้งที่ AREG_IOS รับได้ หลักฐาน
  • สองต้นไม้เอาต์พุต: อ่านรายงานแทนการใช้ glob หลักฐาน
  • กราฟเครื่องมือในเอกสารของเซิร์ฟเวอร์ล้าสมัย หลักฐาน
  • เอกสารบางส่วนขัดกับโค้ด (ระบุว่าต้องมีโมเดล ชื่อโฟลเดอร์ จำนวนเทสต์) หลักฐาน
  • สิ่งที่เครื่องมือปกป้อง: คำขอที่ถูกปฏิเสธไม่ทิ้งอะไรไว้ อินพุตไม่ถูกแก้ไข และชื่อไฟล์ไม่อยู่ในล็อก หลักฐาน
  • การทำซ้ำได้: การทำนายดิบเหมือนกับพอร์ตอ้างอิงทุกบิต อาร์เรย์หลังประมวลผลต่างกันไปในแต่ละรัน หลักฐาน

AMASSS บน VISOR: โค้ด

สำหรับนักพัฒนา: พอร์ต VISOR ของ AMASSS ทำอะไรในโค้ด พร้อมการอ้างอิง file:line ซิกเนเจอร์ อาร์กิวเมนต์ สภาพแวดล้อม ความต่างจากโค้ด legacy และข้อค้นพบ คำอธิบายที่อ่านง่ายของไปป์ไลน์เดียวกัน พร้อมคณิตศาสตร์ อยู่ในหน้าแอตลาส AMASSS รันใน VISOR อย่างไร (ไคลเอนต์และเซิร์ฟเวอร์) อะไรเปลี่ยนไปจากโมดูล Slicer แบบ legacy และโค้ดของพอร์ตทำอะไร: เครือข่าย nnU-Net v2 แบบไบนารีหนึ่งตัวต่อโครงสร้างกายวิภาคหนึ่งชิ้น ซึ่งตอนนี้ทำนายเคียงข้างกันบนเซิร์ฟเวอร์ โมดูล legacy อธิบายอยู่ในหน้าของมันเอง

โค้ด แอตลาส (คำอธิบาย) VISOR sadt_amasss หน้า Legacy Guide (VISOR) บรรณานุกรม

VISOR รัน AMASSS บนเซิร์ฟเวอร์: Slicer เพียงส่งสแกนและรับการแบ่งส่วนกลับ หน้านี้ตามการรันตั้งแต่แผงจนถึงรายงาน: อะไรรันที่ไหน ไฟล์ไหนทำอะไร แต่ละขั้นของไปป์ไลน์พร้อมโค้ดที่ทำมัน อาร์กิวเมนต์ที่เซิร์ฟเวอร์เผยแพร่ และพอร์ตต่างจากโมดูล legacy อย่างไร ทุกอย่างที่นี่อ่านจากโค้ด ไม่ได้สังเกตบนเซิร์ฟเวอร์ที่กำลังรัน และไม่มีอะไรที่นี่บอกว่าเซิร์ฟเวอร์ใดถูกติดตั้งใช้งาน

การอ้างอิงระบุชื่อรีโพซิทอรีก่อน: SADT-VISOR (โค้ดเครื่องมือ tools/AMASSS @ 6ba2a78), VISOR-serve (เซิร์ฟเวอร์ @ e9a7e5d), AutomatedDentalToolsRemote (ไคลเอนต์ Slicer @ 19b95e8) และ legacy (SlicerAutomatedDentalTools @ 3c67957) ชื่อไฟล์เปล่า ๆ เช่น pipeline.py, catalog.py, layout.py, nnunet_runner.py, vtk_export.py, progress.py, errors.py หรือ __init__.py อยู่ในแพ็กเกจ SADT-VISOR tools/AMASSS/src/sadt_amasss/ ส่วน AMASSS_CLI.py (AMASSS_CLI/) และ AMASSS.py (AMASSS/) เป็นไฟล์ legacy โฟลเดอร์ AMASSS เหมือนกันทุกประการบนสาขา main ของ SADT-VISOR และที่ 6ba2a78 (ไม่มี diff บน tools/AMASSS)

ผลลัพธ์ถูกโหลดเฉพาะเมื่อการรันผลิตไฟล์ที่โหลดได้ 12 ไฟล์หรือน้อยกว่า เกินกว่านั้นจะไม่โหลดอะไรเลย และกล่องโต้ตอบชี้ไปที่โฟลเดอร์ (AutomatedDentalToolsRemote AMASSSRemote/AMASSSRemote.py:82; ServerToolsCoreLib/base_widget.py:1596-1602) รูปแบบคือ *.nii.gz, *.nii, *.nrrd, *.nrrd.gz เป็น label map และ *.vtk เป็นโมเดล (AMASSSRemote.py:92-98): อินพุต .gipl ซึ่งมาสก์ของมันกลับมาเป็น .gipl.gz (SADT-VISOR naming/src/sadt_naming/__init__.py:60) ผลิตไฟล์ที่ถูกบันทึกแต่ไม่ถูกโหลด

ตรวจสอบแล้ว: ไม่มีโฟลเดอร์ทำงานที่ใช้ร่วมกันระหว่างการรัน

แต่ละการรันทำงานภายใต้ <output_dir>/.amasss_work ของตัวเอง และลบมันเมื่อการอนุมานเริ่มแล้ว ไม่ว่าจะสำเร็จหรือล้มเหลว (SADT-VISOR pipeline.py:59-62, 330-331, 342-366) โฟลเดอร์ถูกสร้างก่อนค้นหาสแกนและโมเดล (pipeline.py:331-336) การรันที่ไม่พบสแกนจึงทิ้งมันไว้ ว่างเปล่า บั๊กสองข้อของ legacy เรื่องโฟลเดอร์ชั่วคราวที่ใช้ร่วมกันและถูกล้าง (legacy §6 และ legacy §9) ไม่เกิดขึ้นที่นี่

ตรวจสอบแล้ว: รายงานที่มีโครงสร้างและการตรวจสอบตั้งแต่เนิ่น ๆ

รายงานแสดงโครงสร้างที่ไม่มีโมเดล โครงสร้างที่ล้มเหลว และสถานะ ข้อผิดพลาด และระยะเวลาต่อสแกน (SADT-VISOR pipeline.py:497-558) ค่าโครงสร้างหรือโหมดการรวมที่ไม่รู้จักถูกปฏิเสธก่อนการอนุมานใด ๆ (pipeline.py:306-327) CLI ของ legacy ไม่ตรวจทั้งสอง: โครงสร้างที่ไม่รู้จักกลายเป็นโมเดลที่ขาด และโหมดการรวมที่ไม่รู้จักถูกจับทีละสแกนหลังการอนุมาน (AMASSS_CLI.py:723-732, 623-627) การ autotune ของ cuDNN ถูกปิด (nnunet_runner.py:116) คอมเมนต์ในโค้ดให้เหตุผล: การ autotune ทำให้สแกนเดียวกันให้มาสก์ต่างกันตามภาระของการ์ด (nnunet_runner.py:104-115)

ตรวจสอบแล้ว: ไม่มีชื่อไฟล์ในล็อกหรือความคืบหน้า

เครื่องมือเรียกสแกนด้วยตำแหน่งในชุดหรือด้วย id ของเคส ในล็อกและในข้อความความคืบหน้าที่เซิร์ฟเวอร์เก็บและแสดง (SADT-VISOR pipeline.py:116-118, 414-417, 584-587; progress.py:13-15, 100) legacy บันทึกพาธของสแกนที่อ่านไม่ได้ (legacy AMASSS_CLI.py:713) ชื่อไฟล์ยังอยู่ใน cases[].input ของรายงาน (pipeline.py:399) ซึ่งกลับไปยังผู้เรียกพร้อมผลลัพธ์

แพทย์ไม่เคยส่งโมเดล

โมเดลถูกเผยแพร่เป็นชื่อ ไม่เคยเป็นอาร์กิวเมนต์ไฟล์ น้ำหนักโมเดลจึงอัปโหลดจากแล็ปท็อปไม่ได้ (VISOR-serve server/registry/conventions.py:14-16) และอาร์กิวเมนต์ถูกซ่อนในแผง AMASSS (SADT-VISOR layout.py:32) ดูความปลอดภัยและความเป็นส่วนตัว

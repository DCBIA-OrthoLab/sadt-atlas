AREG_IOSCBCT บน VISOR: โค้ด

สำหรับนักพัฒนา: การพอร์ต VISOR ของ AREG_IOSCBCT ทำอะไรในโค้ด พร้อมการอ้างอิง file:line ซิกเนเจอร์ อาร์กิวเมนต์ สภาพแวดล้อม ความต่างจากโค้ด legacy และข้อค้นพบ คำอธิบายที่อ่านง่ายของไปป์ไลน์เดียวกัน พร้อมคณิตศาสตร์ อยู่ในหน้าแอตลาส โมดูล legacy มีหน้าโค้ดของตัวเอง

VISOR โค้ด แอตลาส (คำอธิบาย) AREG_IOSCBCT เข้าถึงเป็น AREG โหมด IOS to CBCT ไม่มี torch เรขาคณิตล้วน หน้า Legacy คู่มือ (VISOR) บรรณานุกรม

AREG_IOSCBCT วางสแกนในช่องปากในเฟรมของ CBCT ของผู้ป่วยคนเดียวกันที่ถ่ายในการมาพบครั้งเดียวกัน: การฟิตแบบแข็งบน landmark ที่ทั้งสองฝั่งมีร่วมกัน แล้ว ICP ของเมชเทียบกับพื้นผิวที่วาดเส้นขอบจาก CBCT ใน VISOR การคำนวณทั้งหมดรันบนเซิร์ฟเวอร์ และ landmark เมื่อคุณไม่ส่งมา มาจากเครื่องมืออื่นที่เซิร์ฟเวอร์เรียก Slicer เพียงแสดงฟอร์ม ส่งโฟลเดอร์ และเปิดสิ่งที่กลับมา หน้านี้อธิบายการพอร์ตนั้น อ่านที่ SADT-VISOR 6ba2a78 (สาขา tool/vface), VISOR-serve e9a7e5d และ AutomatedDentalToolsRemote 19b95e8 โมดูล legacy ที่ใช้เทียบคือ SlicerAutomatedDentalTools 3c67957 อธิบายในหน้าของตัวเอง พาธ legacy ด้านล่างอยู่ที่คอมมิตนั้น และ AREG_IOSCBCT.py คือ AREG_IOSCBCT/AREG_IOSCBCT.py ที่นั่น

ตัวย่อที่ใช้ในหน้านี้: ioscbct/ คือ SADT-VISOR tools/AREG/AREG_IOSCBCT/src/sadt_areg_ioscbct/, common/ คือ SADT-VISOR tools/AREG/common/src/sadt_areg_common/ และพาธ server/ อยู่ใน VISOR-serve “Observed” ทำเครื่องหมายสิ่งที่ถูกรัน (การทดสอบ, scripts/describe.py, โพรบ Python สั้น ๆ ที่รันด้วย environment ของเครื่องมือเองบนไฟล์ทดสอบที่เผยแพร่) ส่วนที่เหลือทั้งหมดอ่านจากโค้ด

3.1 การเรียกภายใต้ supervisor

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

ระบบตรวจโหมดก่อนเป็นอันดับแรก โหมด Registration เป็นค่าเริ่มต้น และเป็นโหมดเดียวที่ไม่ต้องใช้เครื่องมืออื่น (ioscbct/__init__.py:46-48, ioscbct/dispatch.py:283-288) ในอีกสองโหมด main จะปฏิเสธทันทีเมื่อเข้าถึง Crown_Seg, ALI_IOS และ ALI_CBCT ไม่ได้ (และ ASO สำหรับ Fully-Automated) และเมื่อไม่ได้ระบุจุดอ้างอิงทิศทาง จะใช้ DATA/AREG/models/CBCT_Gold_Frankfurt_Horizontal_Midsagittal_Plane (ioscbct/dispatch.py:190-199,311-331) จากนั้นทำตามลำดับนี้ (ioscbct/dispatch.py:332-339, ioscbct/tools.py:102-177):

cbct = sup.run("ASO", input=cbct, reference=<Frankfurt>,          # Fully only
               modality="CBCT", automation="Fully-Automated" [, landmark_model])
ios  = sup.run("Crown_Seg", meshes=ios, suffix="Seg" [, model=crown_model])
ios_lm  = sup.run("ALI_IOS", input=ios, networks=["Occlusal"])          # unless sent
cbct_lm = sup.run("ALI_CBCT", input=cbct,
                  landmarks=["UR1O","UR3O","UR6O","UL1O","UL3O","UL6O",
                             "LR1O","LR3O","LR6O","LL1O","LL3O","LL6O"])   # unless sent

ALI_CBCT ถูกขอให้หาสิบสองจุดนั้นตามชื่อ ไม่ใช่ตามบริเวณ เพราะการขอตามบริเวณจะรันทุกเอเจนต์ของทุกบริเวณที่มีจุดใดจุดหนึ่งอยู่ (ioscbct/tools.py:122-137) ส่วน ALI_IOS ถูกขอเฉพาะเครือข่าย occlusal ของมัน (ioscbct/tools.py:140-156) เมชในช่องปากถูกติดป้ายแต่ ไม่ได้ปรับทิศทาง: ASO ถูกเรียกกับ CBCT เท่านั้น จุดบอกความคืบหน้าคือ 0.1, 0.3 และ 0.5 และการ registration เริ่มที่ 0.6 (ioscbct/tools.py:129-130,148-149,167-168, ioscbct/dispatch.py:355)

3.2 การจับคู่สองโมดาลิตี

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

สองโมดาลิตีตั้งชื่อตามธรรมเนียมที่ต่างกัน patient_key จึงเก็บไว้เฉพาะสิ่งที่ใช้ร่วมกัน คือตัวเลข: ตัดโทเคนจุดเวลา t0 t1 t2 ออก แล้วตัดทุกอักขระที่ไม่ใช่ตัวเลข แล้วตัดเลขศูนย์นำหน้า ดังนั้น P001_T2_U.vtk และ P_0001_T2.nii.gz จึงได้คีย์เป็น 1 เหมือนกัน (ioscbct/pipeline.py:30-52) discover เดินผ่านทั้งสองโฟลเดอร์ตามลำดับที่เรียงแล้ว เก็บเมช (.vtk, .stl) ทุกไฟล์ของแต่ละคีย์ และเก็บ CBCT ไฟล์แรกของแต่ละคีย์ และรายงานคีย์ที่มีอยู่ในฝั่งเดียว (ioscbct/pipeline.py:55-106) ความหยาบของคีย์นี้คือ ข้อค้นพบแรก

ไฟล์ landmark ถูกอ่านเป็น Slicer markups หรือเป็นออบเจกต์ธรรมดา {label: [x, y, z]} (ioscbct/pipeline.py:109-133) จัดดัชนีด้วยพาธเทียบกับโฟลเดอร์ (ioscbct/dispatch.py:87-108) จำกัดให้เหลือเฉพาะคีย์ของผู้ป่วย (:111-135) และจับคู่กับเมชด้วยโทเคนขากรรไกร (u upper l lower) ไฟล์เดียวที่ไม่มีโทเคนขากรรไกร ซึ่งเป็นสิ่งที่ ALI_CBCT เขียนสำหรับ CBCT ทั้งก้อน ใช้ได้กับทั้งสองส่วนโค้งฟัน โดยให้ป้ายชื่อเองเป็นตัวแยก (UR1O เทียบกับ LR1O) (ioscbct/dispatch.py:138-175)

3.3 พื้นผิว CBCT และระดับที่ใช้สร้างเส้นชั้นความสูง

array = sitk.GetArrayFromImage(image)
ijk_to_lps[:3, :3] = direction @ diag(spacing);  ijk_to_lps[:3, 3] = origin
level = surface_threshold(array, ijk_to_lps, landmark_positions)
on_enamel = landmarks_on_enamel(array, ijk_to_lps, landmarks, level)
surface = pv.wrap(array.transpose(2, 1, 0)).contour(isosurfaces=[level])
return surface.transform(ijk_to_lps, inplace=False), on_enamel

ระดับถูกอ่านจากสแกน ด้วยกฎเดียวกับ legacy ที่ 3c67957 (ioscbct/volume.py:96-117):

  • ที่ราบของเคลือบฟัน คือค่ามัธยฐาน ในบรรดา landmark ของ CBCT ของ voxel ที่สว่างที่สุดภายในระยะ 2 voxel จากแต่ละจุด (PROBE_RADIUS_VOXELS = 2, ioscbct/volume.py:27,46-60,77-79,91);
  • สิ่งแวดล้อม คือค่ามัธยฐานของ voxel ที่อยู่ระหว่าง -300 ถึง 300 HU ในกล่องที่ landmark ครอบคลุม (SOFT_TISSUE_BAND, ioscbct/volume.py:32,85-92);
  • ระดับอยู่กึ่งกลางระหว่างสองค่านั้น 400 เป็นเพียงค่าสำรอง ใช้เมื่อไม่มี landmark ใดตกอยู่ในสแกน หรือเมื่อตัวฟันไม่สว่างกว่าสิ่งแวดล้อม (FALLBACK_LEVEL = 400.0, ioscbct/volume.py:36,105-112);
  • อาร์กิวเมนต์ level ที่ระบุตรง ๆ จะมีผลเหนือกว่า แต่ไม่มีผู้เรียกรายใดส่งมา (ioscbct/volume.py:101-103, ioscbct/dispatch.py:77)

สังเกตบนสแกนทดสอบที่เผยแพร่ (P_0001_T2_Or.nii.gz และ landmark CBCT 12 จุดของมัน ซึ่งเป็นไฟล์ที่ตัวแสดงผลด้านล่างสร้างจากมัน รันผ่าน volume.surface_threshold และ volume.landmarks_on_enamel ในสภาพแวดล้อมของเครื่องมือ): เคลือบฟัน 2783, สิ่งแวดล้อม 146, ระดับ 1464 สูงกว่าค่าสำรอง 400 มาก และ UL3O อ่านได้ 274 ที่สว่างที่สุด ต่ำกว่าระดับ จึงถูกตัดสินว่าไม่ได้อยู่บนฟัน

ระดับเดียวกันนี้ใช้ตัดสินแต่ละ landmark ด้วย: จุดที่บริเวณรอบ ๆ ไม่เคยถึงระดับนั้นไม่ได้อยู่บนเคลือบฟัน ซึ่งในการสบฟันแน่นมักหมายความว่าเครือข่ายวางมันไว้บนส่วนโค้งฟันฝั่งตรงข้าม (ioscbct/volume.py:120-145) เส้นชั้นความสูงจับทั้งกระดูกและเคลือบฟันที่อยู่เหนือระดับนั้นเหมือนกัน การ transpose ใส่อาร์เรย์ (k, j, i) ของ SimpleITK กลับเป็นลำดับ (i, j, k) ของ pyvista และ ijk_to_lps พาพื้นผิวกลับเข้า LPS ซึ่งเป็นกรอบที่เครื่องมือ ALI ทั้งสองเขียน (ioscbct/volume.py:161-175)

3.5 ICP

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

register_one ครอปพื้นผิว CBCT ให้เหลือกล่องของ landmark CBCT ของส่วนโค้งฟันนั้นบวก 25 mm ย้ายเมชด้วย pre-alignment แล้วรัน icp_point_to_plane (ioscbct/pipeline.py:158-212, ioscbct/geometry.py:395-450):

  • จุดที่ขับเคลื่อนการฟิต: เฉพาะตัวฟัน (ส่วนโค้งฟันทั้งหมด รวม เหงือก ยังคงเคลื่อนตามเมทริกซ์ที่ตัวฟันลงตัว ioscbct/geometry.py:623-624) เมื่อเมชมี Universal_ID และอย่างน้อย 10% ของมันเป็นตัวฟัน ป้าย 0 และ 33 คือเหงือก ซึ่งไม่มีคู่เทียบใน CBCT (GINGIVA_LABELS, MIN_CROWN_SHARE, ioscbct/geometry.py:368-372,453-476);
  • การจับคู่จุด: จุด CBCT ที่ใกล้ที่สุดภายใน ICP_MAX_DIST_MM = 1.0 ซึ่งเวกเตอร์ปกติของมันสอดคล้องกับของเมชเกิน 0.5 ซึ่งกันส่วนโค้งฟันฝั่งตรงข้ามออกในการสบฟันแน่น (:338,343,543-555);
  • ก้าว: point-to-plane เชิงเส้นในค่าการหมุน แก้ด้วยกำลังสองน้อยที่สุด ระบบที่ rank ไม่เต็มหรือการหมุนเกิน 0.5 rad จะถอยไปใช้ก้าว Procrustes แบบ point-to-point (:479-521,571-577);
  • หยุด: หลัง 300 รอบ หรือเมื่อการเลื่อนที่ใหญ่ที่สุดต่ำกว่า 0.001 mm ติดต่อกัน 3 รอบ (:346-348,585-586);
  • เครื่องหมายของเวกเตอร์ปกติ: รันโดยอ่าน เวกเตอร์ปกติของ CBCT ทั้งสองทิศ แล้วเก็บการอ่านที่มี fitness ดีกว่า และถ้าเท่ากันก็ที่ RMSE ต่ำกว่า (:600-651);
  • เกณฑ์ขั้นต่ำ: ICP ที่จับคู่ได้ต่ำกว่า 5% ของส่วนโค้งฟันถือเป็นข้อผิดพลาดของเมชนั้น เมชที่ไม่ได้ registration จึงไม่เคยถูกเขียนภายใต้ชื่อของเมชที่ registration แล้ว (MIN_ICP_FITNESS = 0.05, ioscbct/pipeline.py:192-202);
  • การเคลื่อนที่: ค่า RMS ของ landmark ที่ฟิตก่อนและหลัง ICP ถูกส่งไปที่รายงาน พร้อมคำเตือนเมื่อเกิน 1 mm (ioscbct/pipeline.py:215-244)

เมทริกซ์สุดท้ายคือ refinement @ matrix คือ ICP ที่ประกอบต่อจากการฟิต landmark (ioscbct/pipeline.py:212) หากไม่มีพื้นผิว (ตีเส้นชั้นความสูงของวอลุ่มไม่ได้) เมชจะถูกวางตาม landmark เท่านั้น และ icp จะเป็น null ในรายงาน (ioscbct/pipeline.py:184-185)

ผู้ป่วยและจุดเวลาที่ต่างกันแค่ตัวอักษรถูกรวมเข้าด้วยกัน

patient_key เก็บเฉพาะตัวเลขและไม่เก็บอะไรอื่น (ioscbct/pipeline.py:30-52) สังเกตที่ 6ba2a78: A12_T1_Upper.vtk, B12_T1_Upper.vtk และ P1_visit2_U.vtk ให้ '12' ทั้งหมด ส่วน P001_T2_U.vtk และ P_0001_T2.nii.gz ให้ '1' ทั้งคู่ ซึ่งตั้งใจไว้ เมื่อมีเมชสี่ไฟล์ P001_T1_{U,L}.vtk และ P001_T2_{U,L}.vtk คู่กับ CBCT สามไฟล์ P_0001_T1.nii.gz, P_0001_T2.nii.gz และ Q001_T1.nii.gz discover คืนผู้ป่วยเพียงรายเดียวคือ '1' ที่ถือเมชทั้งสี่และ CBCT ไฟล์แรกตามลำดับการเรียง และ unpaired ว่างเปล่า: CBCT อีกสองไฟล์หายไปโดยไม่มีรายงาน (setdefault, ioscbct/pipeline.py:74,81) ไฟล์ landmark ถูกจำกัดด้วยคีย์ผู้ป่วย แล้วจับคู่กับเมชด้วยโทเคนขากรรไกรเพียงอย่างเดียว โดยไฟล์แรกตามลำดับการเรียงชนะ: สังเกตได้ว่าชุด landmark ที่ถูกเลือกให้ P001_T2_L.vtk ระหว่าง P001_T1_L และ P001_T2_L คือชุด T1 (_for_patient และ _match_landmarks, ioscbct/dispatch.py:111-175) เครื่องมือนี้มีเอกสารระบุว่าไม่รองรับข้อมูลตามเวลา (ioscbct/__init__.py:3-7) แต่ไม่มีอะไรบังคับหรือรายงานเรื่องนี้

ตั้งระดับ isosurface ไม่ได้อีกแล้ว

legacy ยอมรับ AREG_CBCT_SURFACE_THRESHOLD (AREG_IOSCBCT.py:92,943-950@3c67957) VISOR เก็บกฎและ ค่าสำรอง 400 ไว้ และคำเตือนที่บันทึกเมื่อถอยไปใช้ค่าสำรองแนะนำให้ “pass a level explicitly” (ioscbct/volume.py:96-112) แต่ผู้เรียกเพียงรายเดียวไม่เคยทำ: volume.read(scan_path, merged) (ioscbct/dispatch.py:77) และ run() ไม่มีอาร์กิวเมนต์เช่นนั้น อ่านจากโค้ด

บนสแกนทดสอบที่เผยแพร่ ระดับคือ 1464 ไม่ใช่ 400

สังเกตด้วยฟังก์ชันของเครื่องมือเองบน P_0001_T2_Or.nii.gz และ landmark CBCT 12 จุดของมัน: เคลือบฟัน 2783, เนื้อเยื่ออ่อน 146, ระดับ 1464 (ioscbct/volume.py:96-117) ที่ระดับนั้น UL3O (สว่างที่สุด 274) ถูกตัดสินว่า ไม่อยู่บนเคลือบฟัน และการฟิต landmark ของส่วนโค้งฟันบนทำโดยไม่มีมัน (ioscbct/geometry.py:229-236) ดังนั้น “400” เป็นเพียงค่าที่ VISOR ใช้เมื่ออ่านสแกนไม่ได้ และพื้นผิวที่รูปใด ๆ วาดที่ 400 ไม่ใช่พื้นผิวที่ ICP ของ VISOR ใช้ registration ตัวแสดงผลใน 3.4 บอกเรื่องนี้ไว้

เอกสารของ max_dist ผิด

docstring บอกว่า 0 ใช้ 1.5 “which is upstream's” (ioscbct/__init__.py:83-85) แต่โค้ดใช้ ICP_MAX_DIST_MM = 1.0 (ioscbct/dispatch.py:352, ioscbct/geometry.py:338) พร้อมคอมเมนต์ว่าลายเซ็นของ upstream บอก 1.5 และทุกจุดเรียกส่ง 1.0 (ioscbct/geometry.py:335-338) DEFAULT_MAX_DIST = 1.5 เป็นค่าเริ่มต้นของ icp_point_to_point เท่านั้น (ioscbct/geometry.py:25,77-78) ซึ่งเป็นฟังก์ชันที่ไม่มีโมดูลใดของเอนจินเรียก (grep: มีเพียง tests/test_geometry.py) ก้าวสำรองที่ ICP ใช้จริงคือ _point_to_point_step ซึ่งไม่รับระยะ (ioscbct/geometry.py:509-521,576-577) ช่องนี้ถูกซ่อนในแผง (ioscbct/layout.py:84) ประโยคที่ผิดจึงไปถึงเฉพาะผู้ใช้ API

ตัวประมาณที่เก็บไว้บรรยายถึง upstream ที่ไม่มีอยู่อีกแล้ว

docstring ของ icp_point_to_point บอกว่าถูกเปลี่ยนชื่อจาก run_icp_point_to_plane ของ upstream เพราะฟังก์ชันนั้นคำนวณ point-to-point (ioscbct/geometry.py:81-86) และคอมเมนต์เหนือค่าคงที่ของ ICP บอกว่าเก็บไว้เป็นทางสำรองสำหรับระบบที่เสื่อม (ioscbct/geometry.py:331-334) ที่ 3c67957 run_icp_point_to_plane ของ upstream มีก้าว point-to-plane จริง (AREG_IOSCBCT.py:579-608,719) และใน VISOR กรณีเสื่อมจะถอยไปที่ _point_to_point_step ไม่ใช่ฟังก์ชันนี้ ไม่เป็นอันตราย แต่ทำให้เข้าใจผิดสำหรับผู้ที่เทียบโค้ดสองฐาน อ่านจากโค้ด

คำตัดสินของ pre-alignment เป็นข้อมูล ไม่ใช่บรรทัดบันทึก

แต่ละเมชมี prealignment (ได้รับการยอมรับหรือไม่ เพราะอะไร landmark ที่ฟิต ค่าตกค้าง การกระจาย) และสถิติของ ICP รวมถึงการเคลื่อนที่ของ landmark ก่อนและหลัง (ioscbct/pipeline.py:158-212) วอลุ่มที่ตีเส้นชั้นความสูงไม่ได้ไม่ทำให้การรันหยุด: เมชถูกวางตาม landmark และรายงานบอกว่า ICP ไม่ได้รัน (ioscbct/dispatch.py:57-84) อ่านจากโค้ด

ต่างจาก AREG_CBCT และ AREG_IOS เอนจินห่อการทำงานของมันด้วย try/finally ที่ลบ .areg_work/ (ioscbct/dispatch.py:306-358) อ่านจากโค้ด

AutoMatrix บน VISOR

AutoMatrix ใช้ transform การลงทะเบียนกับสแกน เซกเมนเทชัน และไฟล์ landmark ทีละทั้งโฟลเดอร์ หน้านี้อธิบายทีละขั้น: ไฟล์และ transform หากันเจออย่างไร แต่ละอันขยับไปทางไหน และผลลัพธ์ไปตกที่ใด ไฟล์ บรรทัด อาร์กิวเมนต์ และข้อค้นพบอยู่ในหน้าโค้ด โมดูล legacy อยู่ในหน้าของมันเอง

VISOR แอตลาส (คำอธิบาย) โค้ด (นักพัฒนา) หน้า Legacy คู่มือ (VISOR)

ภาพรวม: อะไรเข้า อะไรออก

เครื่องมือลงทะเบียน (AREG, GreedyReg, FlexReg) หา transform: วิธีย้ายสแกนหนึ่งไปทับอีกสแกนหนึ่ง AutoMatrix นำไฟล์นั้นไปใช้กับไฟล์อื่นของผู้ป่วยคนเดียวกัน: สแกน เซกเมนเทชัน หรือชุดจุด landmark ไม่มีการทำนายใดๆ: เป็นเรขาคณิต

เข้าออก
สแกนและเซกเมนเทชัน (.nii.gz, .nrrd, .gipl), landmark (.mrk.json) หรือโฟลเดอร์ของไฟล์เหล่านั้นไฟล์เดียวกันที่ถูกย้ายด้วย transform ของมัน พร้อมคำต่อท้าย (ค่าเริ่มต้นคือ Reg) ในสำเนาของโฟลเดอร์อินพุต
transform (.tfm, .mat, .h5, .hdf5, .txt) หรือโฟลเดอร์ของไฟล์เหล่านั้นรายงาน AutoMatrix_report.json: อะไรถูกจับคู่ อะไรล้มเหลว อะไรไม่มีคู่

1. ตำแหน่งในสายโซ่

AutoMatrix เป็นเครื่องมือเดียวในกลุ่มที่เครื่องมือ VISOR ตัวอื่นเรียกใช้: VFACE เรียกมันสองทาง คือเพื่อสะท้อน (สแกนของการศึกษาความไม่สมมาตร และ landmark ของมัน) และเพื่อย้าย landmark ด้วย transform การลงทะเบียนของผู้ป่วยแต่ละคน หนึ่งการเรียกต่อหนึ่งบริเวณ ตัวมันเองไม่เรียกอะไร transform ของมันมักมาจากการลงทะเบียน หรือจากเมทริกซ์กระจกเงาที่โฮสต์ไว้ การคำนวณรันบนเซิร์ฟเวอร์ด้วย CPU ไม่ใช้เครือข่ายและไม่มีน้ำหนักโมเดล

ในโค้ดใครเรียกใคร แผงไคลเอนต์ เทสต์

2. ไฟล์ที่เกี่ยวข้อง

เครื่องมือเป็นแพ็กเกจที่มีไฟล์ Python สี่ไฟล์ (การรันและรายงาน; คีย์ รูปแบบไฟล์ และเรขาคณิต; เลย์เอาต์ของแผง; ความคืบหน้า) ชุดเทสต์ และแผง Slicer สั้นๆ ที่มีช่อง “Use the mirror matrix” รายการพร้อมจำนวนบรรทัดอยู่ในหน้าโค้ด

ในโค้ดไฟล์ จำนวนบรรทัด สิ่งที่อยู่ที่อื่น

3. อะไรรันที่ไหน

ขั้นตอนเซิร์ฟเวอร์Slicer
เลือกไฟล์และ transformรับไฟล์ โดยแต่ละอินพุตอยู่ในโฟลเดอร์ของตัวเอง เพื่อไม่ให้ชื่ออาร์กิวเมนต์รั่วเข้าไปในคีย์ผู้ป่วยตัวเลือกสำหรับไฟล์หรือโฟลเดอร์ ไฟล์ทดสอบที่โฮสต์ไว้เลือกได้ในรายการ
จับคู่ อ่าน สุ่มตัวอย่างใหม่ ย้ายจุดทั้งหมดไม่มี
ค่าที่คืนโฟลเดอร์ผลลัพธ์ บีบอัดเป็น zip ทั้ง cohort ถูกส่งในคำขอเดียว โดยมีขีดจำกัดเริ่มต้น 500 MBแตกไฟล์ อ่านรายงาน โหลดผลลัพธ์ได้สูงสุด 12 รายการ
ในโค้ดอะไรรันที่ไหน ขีดจำกัดของเซิร์ฟเวอร์

4. ไปป์ไลน์ ทีละขั้น

หนึ่งการเรียกใช้ transform ของผู้ป่วยทุกคนกับทุกไฟล์ของผู้ป่วยคนนั้น

4.1 การค้นหาและคีย์ผู้ป่วย คำนวณ

ค้นหาไฟล์ในโฟลเดอร์และโฟลเดอร์ย่อย ข้ามไฟล์ที่ซ่อน และใส่คีย์ทุกไฟล์ด้วยฟังก์ชันเดียวกัน ถ้าไม่มีไฟล์เลย หรือไม่มี transform เลย การรันจะหยุดก่อนอ่านอะไร

ในโค้ดการค้นหา คลังคำที่ตัดทิ้ง

4.2 การจับคู่สำรอง คำนวณ

หลังกฎปกติ โอกาสที่สองทำได้เพียงเพิ่มคู่ ไม่เปลี่ยนคู่ที่มีอยู่ กฎที่ใช้แต่ละข้อถูกบันทึกในรายงาน ตามลำดับ:

  1. เมื่อใช้ตัวเลือก “same transform for every patient” และมี transform เพียงตัวเดียว transform นั้นจะไปยังผู้ป่วยทุกคน
  2. ผู้ป่วยที่ยังไม่มีคู่จะถูกใส่คีย์ใหม่ด้วยการตัดของโมดูล legacy และจับคู่กับ transform ที่ไม่มีใครเอาไป
  3. ผู้ป่วยหนึ่งคนกับ transform หนึ่งตัว ที่ยังไม่มีคู่: ใช้ transform นั้น

ไฟล์ที่ไม่มี transform และ transform ที่ไม่มีไฟล์ ถูกระบุไว้ในรายงานแทนที่จะถูกเมิน

ในโค้ดกฎสำรองสามข้อ พร้อมหมายเลขบรรทัด

4.3 การอ่าน transform คำนวณ

transform ถูกอ่านด้วย ITK (ชุดเครื่องมือภาพแบบโอเพนซอร์สที่ SimpleITK ห่อไว้ ไลบรารีที่ทำการอ่านและสุ่มตัวอย่างใหม่ที่นี่) ถ้า ITK ปฏิเสธไฟล์แต่ไฟล์มีเมทริกซ์ 4×4 ธรรมดา (สี่บรรทัดบรรทัดละสี่ตัวเลข ซึ่งเป็นสิ่งที่ Greedy เขียนภายใต้ชื่อ .mat) มันจะถูกแปลงเป็น affine transform (การแปลงเชิงเส้นบวกการเลื่อน): ตัวเลขสามตัวแรกของสามแถวแรกประกอบเป็นเมทริกซ์ A ตัวเลขสุดท้ายของแต่ละแถวเป็นการเลื่อน t มิฉะนั้นข้อผิดพลาดจะระบุชื่อไฟล์ เมื่อผู้ป่วยมีหลาย transform แต่ละตัวถูกใช้กับไฟล์ต้นฉบับ ไม่มีตัวใดถูกประกอบรวมกับตัวอื่น

T(x)=Ax+t
  • Ttransform
  • xจุดหนึ่งในหน่วยมิลลิเมตร
  • Aส่วน 3×3 ของเมทริกซ์ (การหมุน การปรับขนาด การสะท้อน)
  • tการเลื่อน ตัวเลขสุดท้ายของแต่ละแถวในสามแถวแรก
ในโค้ดread_transform และทางสำรอง 4x4 แบบข้อความ

4.4 Landmark: จุดผ่านผกผัน คำนวณ

ในไฟล์ landmark ทุกกลุ่มของจุดถูกย้าย จุดที่ไม่มีสถานะนับว่ากำหนดแล้ว สถานะอื่นใดถูกปล่อยไว้ที่เดิม กรอบพิกัดที่ประกาศในไฟล์ไม่ถูกอ่าน: จุดถูกย้ายตามที่เขียนไว้

ในโค้ดจุดผ่านผกผัน พร้อมหมายเลขบรรทัด

4.5 ภาพ: การแก้ค่าระหว่างจุดและกล่องผลลัพธ์ คำนวณ

สแกนหรือเซกเมนเทชัน? การเลือกกำหนดการแก้ค่าระหว่างจุด โดยค่าเริ่มต้นอ่านจากvoxel: ภาพจุดลอยตัวคือสแกน เช่นเดียวกับภาพที่มีค่าติดลบ ค่าที่มากกว่า 1000 หรือค่าที่แตกต่างกันเกิน 128 ค่า นอกนั้นเป็น label map คำตอบถูกบันทึกต่อไฟล์

ผลลัพธ์ไปตกที่ใด ถ้าระบุภาพ reference จะใช้กริดของมัน ถ้าไม่ระบุ (ค่าเริ่มต้น เพราะ reference ถูกซ่อน) ผลลัพธ์มีขนาด spacing และ direction ของอินพุต และ origin ของมันถูกย้ายด้วย transform

ในโค้ดสแกนหรือ label map ตัวแก้ค่าระหว่างจุด กริดผลลัพธ์

4.6 ชื่อ ความล้มเหลว รายงาน คำนวณ

ผลลัพธ์สะท้อนโฟลเดอร์อินพุต ชื่อคือชื่อเดิม ตามด้วยคำต่อท้าย แล้วตามด้วยชื่อของ transform เมื่อเปิดตัวเลือกนั้นหรือเมื่อผู้ป่วยมีหลาย transform (เพื่อไม่ให้ transform สองตัวเขียนไฟล์เดียวกัน) ตัวอย่างเช่น p1.nii.gz กับ p1_CBReg_matrix.tfm และ p1_MANDReg_matrix.tfm ได้ p1_Reg_p1_CBReg_matrix.nii.gz และ p1_Reg_p1_MANDReg_matrix.nii.gz (run on 2026-11-09) ไฟล์ที่ล้มเหลวถูกบันทึกพร้อมข้อผิดพลาดของมัน และไฟล์อื่นทำงานต่อ ถ้าไม่มีอะไรถูกเขียน การรันจะหยุดพร้อมเหตุผลแรกๆ มิฉะนั้น AutoMatrix_report.json จะระบุต่อผู้ป่วย: transform ไฟล์ที่ย้าย ความล้มเหลว แล้วจึงไฟล์และ transform ที่ไม่มีคู่

ในโค้ดชื่อ ความล้มเหลว และฟิลด์ของรายงาน

5. สิ่งที่เลือกได้

  • ไฟล์และ transform: ไฟล์หรือโฟลเดอร์อย่างละหนึ่ง (จำเป็นทั้งคู่)
  • Same transform for every patient: ปิดเป็นค่าเริ่มต้น ต้องมี transform เพียงตัวเดียว
  • Include the transform name: ปิดเป็นค่าเริ่มต้น บังคับเปิดเมื่อผู้ป่วยมีหลาย transform
  • Output suffix: ค่าเริ่มต้นคือ Reg เว้นว่างได้
  • ซ่อนในแผง: วิธีสุ่มตัวอย่างใหม่ (อัตโนมัติเป็นค่าเริ่มต้น) และ reference volume
  • Use the mirror matrix (แผง Slicer): เติม Transforms ด้วยไฟล์กระจกเงาที่โฮสต์ไว้ และติ๊กตัวเลือก same-transform
ในโค้ดอาร์กิวเมนต์ที่เผยแพร่และสิ่งที่ไคลเอนต์ทำ

6. อะไรทำนาย อะไรคำนวณ

บล็อกลักษณะ
การจับคู่คำนวณ กฎการตั้งชื่อไฟล์
สแกนหรือเซกเมนเทชันคำนวณ การทดสอบค่าสามแบบและการนับค่าที่แตกต่างกัน
การสุ่มตัวอย่างใหม่ จุด landmarkคำนวณ SimpleITK
ตัว transform เองคำนวณมาก่อนหน้า โดยการลงทะเบียน (AREG, GreedyReg, FlexReg) หรือเมทริกซ์กระจกเงาตายตัว

ไม่มีสิ่งใดใน AutoMatrix ที่เป็นการทำนาย

7. สภาพแวดล้อม

เครื่องมือมีสภาพแวดล้อมของตัวเองบนเซิร์ฟเวอร์ (SimpleITK และ numpy ไม่มีโมเดล ไม่ใช้เครือข่าย) เวอร์ชัน ไฟล์ทดสอบที่โฮสต์ไว้ พฤติกรรมของเธรด และหน่วยความจำอยู่ในหน้าโค้ด

ในโค้ดเวอร์ชัน ไฟล์ทดสอบที่โฮสต์ไว้ เธรด หน่วยความจำ

8. อะไรเปลี่ยนไปจากตรรกะของ legacy

ข้อตกลงของ transform เป็นแบบ legacy สิ่งที่เปลี่ยนคือส่วนรอบๆ

หัวข้อLegacyVISOR
คีย์ผู้ป่วยรายการตัดสองชุดที่ต่างกันสำหรับไฟล์และ transformกฎเดียวสำหรับทั้งสอง การตัดแบบ legacy เป็นเพียงโอกาสที่สองที่บันทึกไว้
transform เดียวสำหรับทุกคนtransform เดี่ยวใดก็ได้ไปยังผู้ป่วยทุกคนเฉพาะเมื่อร้องขอ หรือมีผู้ป่วยหนึ่งคนกับ transform หนึ่งตัว
รูปแบบอินพุตภาพและlandmark เมชถูกพบโดยการค้นหาแต่ล้มเหลวเมื่ออ่านภาพและ landmark ไม่มีเมช
การอ่าน transformบันทึกความล้มเหลวในล็อกแล้วข้ามรับเมทริกซ์ข้อความ 4×4 ธรรมดา มิฉะนั้นเป็นข้อผิดพลาดที่ระบุชื่อ
กล่องผลลัพธ์ เมื่อไม่มี referenceภาพอินพุตเองขนาดและทิศทางของอินพุต origin ถูกย้ายด้วย transform
เมทริกซ์กระจกเงาเมทริกซ์ที่ชื่อ mirror ใช้ภาพเป็น reference ของตัวเองไม่มีการจัดการพิเศษ
การแก้ค่าระหว่างจุดช่องทำเครื่องหมายเดียวสำหรับทั้งการรันอัตโนมัติ ต่อไฟล์
กลุ่ม landmark และสถานะกลุ่มแรกเท่านั้น “defined” อย่างเคร่งครัดทุกกลุ่ม ไม่มีสถานะนับว่ากำหนดแล้ว
หลาย transformผลลัพธ์เขียนทับกันเมื่อไม่เพิ่มชื่อเมทริกซ์บังคับใส่ชื่อ transform

9. ปัญหาที่ทราบใน VISOR

แต่ละประเด็นถูกตรวจสอบในโค้ดและอธิบายพร้อมหลักฐานในหน้าโค้ด รายการนี้ยังปรากฏในข้อค้นพบด้วย

  • บรรทัดสถานะบอก “0 file(s) written” เสมอ ใน Slicer และไฟล์ที่ไม่มีคู่ไม่เคยถูกแจ้ง หลักฐาน
  • เมื่อไม่มี reference กล่องผลลัพธ์ตาม transform: การสะท้อน เช่นเมทริกซ์กระจกเงา ทำให้กล่องว่างเปล่า มีการแก้ไขอยู่บน branch ที่ยังไม่ได้ merge หลักฐาน
  • รายการไฟล์ที่ produced ว่างเสมอสำหรับ volume หลักฐาน
  • transform ที่ผกผันไม่ได้ไม่หยุดการรัน: landmarkล้มเหลว แต่ volume ถูกเขียน หลักฐาน
  • เอกสารของโมดูล Remote ขัดกับโค้ด หลักฐาน
  • ไม่อ่านกรอบพิกัดที่ประกาศของไฟล์ landmark หลักฐาน
  • README และ data manifest ล้าสมัยในส่วนของเครื่องมือนี้ หลักฐาน

10. วรรณกรรม

AutoMatrix ใช้ transform และไม่มีวิธีการของตัวเองให้อ้างอิง บรรณานุกรมของเครื่องมืออยู่ที่ แหล่งอ้างอิงของ AutoMatrix สำหรับกลไกของ VISOR ที่ทุกเครื่องมือใช้ร่วมกัน ดูสถาปัตยกรรมและการรันทีละขั้น ส่วนการใช้งานแผง ดูคู่มือ VISOR

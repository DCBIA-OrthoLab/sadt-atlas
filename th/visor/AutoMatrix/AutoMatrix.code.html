AutoMatrix บน VISOR: โค้ด

สำหรับนักพัฒนา: สิ่งที่พอร์ต VISOR ของ AutoMatrix ทำในโค้ด พร้อมการอ้างอิงแบบ file:line ซิกเนเจอร์ อาร์กิวเมนต์ สภาพแวดล้อม ความต่างจากโมดูล legacy และข้อค้นพบ คำอธิบายที่อ่านง่ายของไปป์ไลน์เดียวกัน พร้อมคณิตศาสตร์ อยู่ในหน้าแอตลาส

VISOR โค้ด แอตลาส (คำอธิบาย) หน้า Legacy คู่มือ (VISOR)

ใน VISOR AutoMatrix เป็นแพ็กเกจ Python ที่รันบนเซิร์ฟเวอร์: Slicer ส่งไฟล์และ transform เซิร์ฟเวอร์จับคู่ตามผู้ป่วย สุ่มตัวอย่าง volume ใหม่ ย้ายจุด landmark และส่งผลลัพธ์กลับ ข้อตกลงของ transform เป็นแบบ legacy (volume ถูกสุ่มตัวอย่างใหม่ผ่าน transform ส่วนจุดเคลื่อนผ่านผกผันของมัน) สิ่งที่เปลี่ยนคือกฎการจับคู่ กริดผลลัพธ์เมื่อไม่ระบุ reference รูปแบบไฟล์ และรายงานว่าจับคู่อะไรได้และอะไรล้มเหลว หน้านี้ตามพอร์ตตั้งแต่คำขอจนถึงไฟล์ที่ส่งกลับมา: ตำแหน่ง ไฟล์ แต่ละขั้นพร้อมโค้ดที่ทำ อาร์กิวเมนต์ที่เผยแพร่ สภาพแวดล้อม ความต่างจากโมดูล legacy และข้อค้นพบ หน้านี้อธิบายพอร์ตใน SADT-VISOR (branch tool/vface, 6ba2a78, 2026-09-30) ซึ่งให้บริการโดย VISOR-serve (e9a7e5d) และควบคุมจาก Slicer ด้วย extension AutomatedDentalToolsRemote (19b95e8) พอร์ตทำจากสถานะ upstream ที่เก่ากว่า 3c67957 (ไฟล์ AutoMatrix และ Automatrix_CLI เปลี่ยนระหว่าง b1ae78c กับ 3c67957) ดังนั้นรายละเอียดบางอย่างของหน้า legacy ซึ่งอ่านที่ 3c67957 อาจต่างจากสิ่งที่พอร์ตเริ่มต้นมา ที่นี่ไม่ได้อ้างว่ามีเซิร์ฟเวอร์ที่ใช้งานจริง: ทุกอย่างอ่านจากโค้ด และพฤติกรรมที่ทำเครื่องหมาย "run on 2026-11-09" ทำซ้ำได้โดยเรียก run() ของแพ็กเกจในเวอร์ชวลเอนไวรอนเมนต์ของมันเองบน volume สังเคราะห์

4.2 การจับคู่สำรอง คำนวณ

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

  2. ผู้ป่วยที่ยังไม่มีคู่จะถูกใส่คีย์ใหม่ด้วยการตัดสตริงย่อยแบบ legacy ซึ่งต่างกันสองฝั่งโดยตั้งใจ (pipeline.py:200-237) และจับคู่กับ transform ที่ไม่มีใครเอาไป: "legacy file names" (__init__.py:222-249)
  3. ผู้ป่วยหนึ่งคนกับ transform หนึ่งตัว ที่ยังไม่มีคู่: ใช้ "the only transform, applied to every patient" (:258-262)

    affine.SetTranslation([row[3] for row in matrix[:3]])
    return affine

เมื่อไม่มี reference (ค่าเริ่มต้น และเป็นอาร์กิวเมนต์ที่ซ่อน) ผลลัพธ์คงขนาดและทิศทางของอินพุต และใช้ origin เป็น transform.TransformPoint(origin) (SADT-VISOR AutoMatrix/pipeline.py:133) กริดของ legacy คือกริดของภาพเอง (Automatrix_CLI.py:279@3c67957) รันเมื่อ 2026-11-09 บน volume ขนาด 20×20×20 ที่ voxel ขนาด 1 mm มี origin ที่ -10 mm ในแต่ละแกน ภายในมีบล็อก 10×10×10 (voxel ที่ไม่เป็นศูนย์ 1000 ตัว) ที่ดัชนี 2 ถึง 11 สุ่มตัวอย่างใหม่แบบเซกเมนเทชัน: การเลื่อนตำแหน่ง (5,0,0) ย้าย origin ไปที่ -5 และเก็บ voxel ไว้ 200 จาก 1000 ตัว การสะท้อน diag(-1,1,1) (ใช้แทนไฟล์กระจกเงาที่โฮสต์ไว้ ซึ่งไม่ได้ดาวน์โหลดเนื้อหา) ย้าย origin จาก -10 ไป +10 และไม่เก็บอะไรเลย การสะท้อนเดียวกันโดยให้ volume เป็น reference ของตัวเองเก็บไว้ทั้ง 1000 ตัว นี่คือเส้นทางของช่อง "Use the mirror matrix" และของการสะท้อนของ VFACE (SADT-VISOR tools/VFACE/src/sadt_vface/tools.py:179-187 ไม่มี reference) เทสต์ตรึงพฤติกรรมของการเลื่อนตำแหน่งไว้ (tests/test_run_options.py:265-277, tests/test_resample.py:108-115) และหนึ่งเทสต์พึ่งพามัน (tests/test_resample.py:44-53)

ยังไม่ได้ส่งมอบ มีการแก้ไขอยู่บน branch fix/automatrix-mirrors-into-an-empty-box (commit ce4f6fb, 2026-09-28, ทั้งในเครื่องและ origin): เก็บ origin ของอินพุตไว้ เว้นแต่ transform เป็นการเลื่อนตำแหน่งล้วน branch นั้นไม่ใช่บรรพบุรุษของ tool/vface (6ba2a78) พฤติกรรมที่อธิบายข้างต้นจึงเป็นของทรีนี้

produced ว่างเสมอสำหรับ volume

แต่ละ case เริ่มด้วย "produced": [] (SADT-VISOR AutoMatrix/__init__.py:127-128) และการต่อท้ายเพียงที่เดียวอยู่ในกิ่ง landmark (:332) รันเมื่อ 2026-11-09 กับ volume: outputs มีไฟล์ และ produced เป็น [] คอมเมนต์ที่ :125-126 บอกว่า produced เป็นรายการแบบแบนที่ทุกเครื่องมือในแค็ตตาล็อกตอบ AutoCrop3D เติมมันสำหรับ volume ของตัวเอง (SADT-VISOR tools/AutoCrop3D/src/sadt_autocrop3d/__init__.py:236) ผลที่ตามมาสำหรับไคลเอนต์ที่อ่านมันยังไม่ได้ตามรอย

transform ที่ผกผันไม่ได้ไม่หยุดการรัน

สำหรับ transform ที่ผกผันไม่ได้ ไฟล์ landmark ของผู้ป่วยนั้นล้มเหลวและถูกระบุใน cases[patient].failed ขณะที่ volume ของผู้ป่วยถูกเขียน (SADT-VISOR AutoMatrix/__init__.py:144-155) รันเมื่อ 2026-11-09 กับ displacement field ศูนย์ที่เก็บเป็น .h5: GetInverse ยก Unable to create inverse! volume ถูกเขียน และ files_written เป็น 1 การรันจะ raise ก็ต่อเมื่อไม่มีอะไรถูกเขียนเลย (:164) และในกรณีนั้นไม่มีรายงานถูกเขียน เพราะรายงานถูกบันทึกหลังการตรวจนั้น (:184) แผง Slicer ไม่แสดง failed (ดูข้อค้นพบเรื่องบรรทัดสถานะ)

FlexReg บน VISOR: โค้ด

สำหรับนักพัฒนา: พอร์ต VISOR ของ FlexReg ทำอะไรในโค้ด พร้อมการอ้างอิง file:line ซิกเนเจอร์ อาร์กิวเมนต์ สภาพแวดล้อม ความแตกต่างจากโค้ด legacy และข้อค้นพบ คำอธิบายที่อ่านง่ายของไปป์ไลน์เดียวกัน พร้อมคณิตศาสตร์ อยู่ในหน้าแอตลาส โมดูล legacy มีหน้าโค้ดของตัวเอง

VISOR โค้ด แอตลาส (คำอธิบาย) หน้า Legacy Guide (VISOR)

VISOR แยก FlexReg เป็นสองส่วน เซิร์ฟเวอร์สร้าง patch เพดานปากและลงทะเบียนส่วนโค้งฟันหนึ่งไปบนอีกส่วนหนึ่ง ส่วนแผง Slicer แสดงตัวอย่างเส้นขอบของ patch ขณะที่คุณย้ายมุมของมันเท่านั้น หน้านี้ตามพอร์ตตั้งแต่คำขอไปจนถึงไฟล์ที่กลับมา: ใครเรียกมัน ไฟล์ใดรองรับมัน แต่ละขั้นของไปป์ไลน์ฝั่งเซิร์ฟเวอร์พร้อมโค้ดที่ทำ อาร์กิวเมนต์ที่เผยแพร่ สภาพแวดล้อม สิ่งที่เปลี่ยนจากโมดูล legacy และสิ่งที่การรีวิวโค้ดพบ ทุกอย่างที่นี่อ่านจากโค้ดที่ commit ด้านล่าง ไม่ได้สังเกตบนเซิร์ฟเวอร์ที่กำลังรัน (ไม่มีสภาพแวดล้อม FlexReg ให้รันเทสต์) และไม่มีอะไรที่นี่บอกว่าเซิร์ฟเวอร์ใดถูก deploy

การอ้างอิงระบุที่เก็บก่อน: SADT-VISOR (โค้ดเครื่องมือ tool/vface @ 6ba2a78), VISOR-serve (เซิร์ฟเวอร์ @ e9a7e5d), AutomatedDentalToolsRemote (ไคลเอนต์ Slicer @ 19b95e8) และ legacy (SlicerAutomatedDentalTools @ 3c67957) ชื่อไฟล์เปล่า ๆ เช่น __init__.py, pipeline.py, layout.py, make_butterfly.py, orientation.py, propagation.py, ICP.py, vtkSegTeeth.py หรือ util.py อยู่ในแพ็กเกจ SADT-VISOR tools/FlexReg/src/sadt_flexreg/ ส่วน FlexRegRemote.py และ FlexRegLib/ อยู่ในโฟลเดอร์ไคลเอนต์ FlexRegRemote/ ในคอลัมน์ "Legacy" FlexReg_CLI.py และ FlexReg.py คือ CLI และ widget ของ legacy และชื่ออื่นอยู่ใต้ FlexReg_CLI/FlexReg_Method/ หรือ FlexReg/FlexReg_utils/ พาธฝั่งเซิร์ฟเวอร์ เช่น server/config.py อยู่ใน VISOR-serve

3. อะไรรันที่ไหน

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

เซิร์ฟเวอร์ไคลเอนต์ (Slicer)
อ่านพื้นผิว (RAS) สร้าง patch เพดานปาก (การวางทิศทาง centroid ของฟันสี่ซี่ เส้นขอบ geodesic fill) รวมอาร์เรย์ patch ทำ ICP แบบแข็งบน patch เขียนพื้นผิวที่ลงทะเบียนแล้ว .tfm และรายงาน (SADT-VISOR __init__.py:49-202)ตัวอย่าง patch: ขณะลากจอยสติ๊ก เส้นขอบของ patch ถูกคำนวณใหม่ใน Slicer และวาดในฉาก โดยไม่ต้องไปกลับกับเซิร์ฟเวอร์ (FlexRegRemote.py:156-193)
ขั้น GPU เพียงขั้นเดียว: geodesic fill ของ patch (propagation.py:31, 60, 66-68)ฟอร์ม สร้างจาก schema ของเซิร์ฟเวอร์: อาร์กิวเมนต์ vec2 กลายเป็นจอยสติ๊ก (FlexRegRemote.py:21-24, 71)
patch จริงที่การลงทะเบียนใช้จริง คำนวณครั้งเดียวตอน Applyไลบรารีตัวอย่าง FlexRegLib ที่ต้องใช้ vtk และ numpy และไม่ใช้ GPU (FlexRegRemote/CMakeLists.txt:6-23)

ตัวอย่างวาดเฉพาะเส้นขอบ (with_fill=False, FlexRegRemote.py:182-187): การเติม patch ทำโดยเซิร์ฟเวอร์ ด้วยการแพร่ geodesic จากจุดกลาง ไลบรารีฝั่งไคลเอนต์ก็เติมโดยประมาณด้วยการทดสอบจุดในรูปหลายเหลี่ยมได้ ซึ่งแผงไม่ทำ (FlexRegLib/butterfly_preview.py:285-306) ตัวอย่างเปิดโดยค่าเริ่มต้น ("Preview the patch while I drag", FlexRegRemote.py:105-114) และทำงานเมื่อช่อง surfaces ชี้ไปที่พื้นผิวที่อยู่ในฉาก Slicer แล้วเท่านั้น: กับโฟลเดอร์ (batch) ไม่มีตัวอย่าง (FlexRegRemote.py:220-231) การวางทิศทางและ centroid ถูกแคชต่อพื้นผิวและต่อชุดฟัน (prepare) และมีเพียงเส้นขอบที่ถูกคำนวณใหม่ทุกครั้งที่ขยับ pad (FlexRegRemote.py:166-187) โหนด contour ถูกเก็บไว้นอกฉากที่บันทึก (SetSaveWithScene(False), FlexRegRemote.py:244)

ตัวอย่างเล่นเส้นขอบของเซิร์ฟเวอร์ซ้ำด้วยค่าคงที่เดียวกัน: เป้าหมายการวางทิศทางและฟัน (FlexRegLib/butterfly_preview.py:28-29) รัศมี 0.7 (:30) การพลิกเครื่องหมายของการปรับด้านหลัง (:35-40) และ Bézier สะท้อน (:54-66) เทียบกับ make_butterfly.py:77, 82-83, 110-111, 136-148 บนเซิร์ฟเวอร์ เลขฟันที่ซ่อนสี่ตัวยังมีอยู่เป็น widget ในไคลเอนต์ (แถวที่ซ่อนถูกสร้างแต่ไม่ถูกเรนเดอร์: ServerToolsCoreLib/formgen.py:2272-2278, 2366-2420) ตัวอย่างจึงอ่านค่าเริ่มต้นของมัน เพราะถูกซ่อน มันจึงไม่ถูกส่ง และเซิร์ฟเวอร์ใช้ค่าเริ่มต้นเดียวกัน

4.3 patch เพดานปาก ("butterfly") คำนวณ

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

สร้างเฉพาะเมื่อโหมดมี Patch และ patch คือเพดานปาก (__init__.py:155-158) โดย build_butterfly ซึ่งเรียก butterflyPatch ของ legacy ด้วยดัชนี 1 และเปลี่ยนฟันที่หายไปเป็นข้อผิดพลาดของอินพุตที่ระบุชื่อมัน (pipeline.py:123-162) ภายใน make_butterfly.py เป็นเรขาคณิตล้วน ๆ ยกเว้นการเติม:

  1. การวางทิศทาง พื้นผิวถูกคัดลอกและวางทิศทางให้ centroid ของฟันซี่ 3, 5, 12, 14 (UR6, UR4, UL4, UL6) ไปอยู่ที่ [[-0.5,-0.5,0],[0,0,0],[0.5,-0.5,0]] (make_butterfly.py:82-83 orientation.py:42-115): ระนาบสบฟันใกล้ z = 0, +y ไปทางด้านหน้า ฟันสี่ซี่นี้คงที่ ไม่ว่าฟันใดจะขับเคลื่อนมุม
  2. Centroid vtkMeanTeeth เฉลี่ย vertex ของฟันสี่ซี่ที่เลือกใน Universal_ID (make_butterfly.py:79, 84) shift ของทั้ง patch และการปรับของแต่ละมุมถูกบวกเข้าไป การปรับถูกกลับเครื่องหมายที่มุมด้านหลัง เพื่อให้ค่าบวกยืด patch ที่ทั้งสองปลาย (make_butterfly.py:106-111)
  3. มุม แต่ละมุมเป็น affine combination ของ centroid ของมันเองกับตัวตรงข้าม (make_butterfly.py:94-97, 113-117): 
    ratio_anterior_right = (1 - ratio_anterior_right)/2
...
landmark_anterior_right = (1 - ratio_anterior_right) * c_ar + ratio_anterior_right * c_al
    ratio 1 วางมุมบนฟันของมัน ratio 0 วางที่กึ่งกลางส่วนโค้งฟัน เพราะน้ำหนักรวมเป็น 1 shift ที่บวกกับทั้งสี่ centroid จึงออกมาจากการประมาณค่าโดยไม่เปลี่ยน: patch เคลื่อนแบบแข็ง
  4. เส้นขอบ ส่วนหน้าหนึ่งส่วนและส่วนหลังหนึ่งส่วน (ขั้น 0.01) และ Bézier กำลังสองสองเส้นผ่าน (มุมหลัง จุดกลางด้านหลัง มุมหน้า) สะท้อนข้ามคอร์ดของมันเพื่อให้โป่งออกด้านนอก (make_butterfly.py:123-151)
  5. การทำเครื่องหมาย ทุก vertex ที่ใกล้เส้นขอบกว่า radius = 0.7 วัดบน V[:, :2] (การฉายบนระนาบสบฟัน) ถูกตั้งเป็น 1 (make_butterfly.py:77, 127-157)
  6. การเติม Dilation ท่วมเมชทีละเพื่อนบ้านจาก vertex ที่ใกล้กลางของสี่มุมที่สุด หยุดที่เส้นขอบที่ทำเครื่องหมายไว้ เป็นชุดละ 1000 บน CUDA (make_butterfly.py:159-161 propagation.py:65-98) อาร์เรย์ Butterfly1 ถูกเพิ่มลงในพื้นผิวเดิม ไม่ใช่สำเนาที่วางทิศทางแล้ว (make_butterfly.py:165-170)

การแบ่งส่วนตัวฟันwidget รันเมื่อเลเบลหายไป (FlexReg.py:3481-3488)ไม่มี: Universal_ID ต้องมีอยู่
ตัวอย่าง patchในโมดูล Slicer (FlexReg_utils/butterfly_preview.py)เก็บไว้ในไคลเอนต์ Slicer (FlexRegRemote/FlexRegLib/butterfly_preview.py) เฉพาะเส้นขอบ
พารามิเตอร์ของ patchตัวเลขอิสระที่พิมพ์ใน widgetคู่ vec2 พร้อมขอบเขตที่เซิร์ฟเวอร์บังคับ (layout.py:45-89 VISOR-serve server/base.py:734-768)
.tfmอินเวอร์สของเมทริกซ์ประกอบ (FlexReg_CLI.py:100-110)โครงสร้างเดียวกัน (pipeline.py:227-246)
ความล้มเหลวของหนึ่งพื้นผิวการเรียก CLI หนึ่งครั้งต่อสแกน ขับโดย widgetบันทึกในรายงานและ batch ทำต่อ เฉพาะข้อผิดพลาดของอินพุต (__init__.py:177-181)
Environmenttorch ติดตั้งใน Python ของ Slicer (install_pytorch.py)สภาพแวดล้อมของเซิร์ฟเวอร์ ไม่มีอะไรติดตั้งใน Slicer (FlexRegRemote.py:8-12)

9. ข้อค้นพบใน VISOR

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

"Patch and register" ใส่ patch เฉพาะพื้นผิวที่เคลื่อน ไม่ใช่ reference

patch ถูกสร้างบน surfaces เท่านั้น (SADT-VISOR __init__.py:155-157) reference ถูกอ่านครั้งเดียวและใช้ตามที่เป็น (__init__.py:121) ICP เลือกจุดของอาร์เรย์ patch ในทั้งสองเมช (ICP.py:70-72 pipeline.py:209-210) reference ที่ไม่มีอาร์เรย์ Butterfly ล้มเหลวด้วย NoSegmentationSurf (vtkSegTeeth.py:59-61) และอาร์เรย์ศูนย์ทั้งหมดล้มเหลวด้วย ToothNoExist (vtkSegTeeth.py:75) ทั้งสองไม่ใช่ข้อผิดพลาดของอินพุต ซึ่งสำคัญสำหรับ batch: ดูข้อค้นพบถัดไป ในทางปฏิบัติ reference ต้องมี patch ของมันอยู่แล้ว เช่นจากการรันก่อนหน้าในโหมด Patch บนมัน docstring ของ reference ไม่ได้บอกเรื่องนี้ (__init__.py:89-90) ขณะที่ widget ของ legacy บอก ("Create the patch on T1 and T2 before registration", legacy FlexReg.py:1116-1118)

เฉพาะข้อผิดพลาดของอินพุตที่ถูกรายงานต่อพื้นผิว exception อื่นหยุดทั้ง batch

ลูปจับเฉพาะ ToolInputError (SADT-VISOR __init__.py:177) และรายงานถูกเขียนหลังลูป (__init__.py:191) exception อื่นใด เช่นสองอย่างที่ยกโดย reference ที่ไม่มี patch เลขฟันนอกช่วง 1 ถึง 32 (util.py:143-151) หรือไม่มี GPU ใน Dilation (propagation.py:31) จบการรันสำหรับทุกพื้นผิวที่เหลือและไม่ทิ้งรายงาน อ่านจากโค้ด ไม่ได้รัน

"Mucogingival line" ไม่สามารถถูกผลิตโดยสิ่งใดใน VISOR

อาร์เรย์ Bottom_MGL (SADT-VISOR pipeline.py:27) ไม่ถูกสร้างโดยไฟล์ใดของเครื่องมือหรือของไคลเอนต์ Slicer ส่วน legacy สร้างมันใน widget (legacy FlexReg_utils/mgl_patch.py:117) แผงยังเสนอตัวเลือกนี้ (__init__.py:53 layout.py:95) Register กับมันล้มเหลวต่อพื้นผิวถ้าเมชไม่มีอาร์เรย์ (pipeline.py:203-207) และโหมด Patch กับเส้น mucogingival ไม่สร้างอะไรเลย: การสร้างถูกกันไว้ด้วย patch == "Palate (butterfly)" (__init__.py:155-157) พื้นผิวจึงถูกคัดลอกและรายงานเป็น ok

ถ้าไม่มี Universal_ID จะใช้อาร์เรย์สุดท้าย

เมื่อเมชไม่มีอาร์เรย์ Universal_ID การค้นหาเลเบลฟันถอยไปใช้ GetLabelSurface ซึ่งลูปใช้ continue ในที่ที่ต้องใช้ break และคืนอาร์เรย์ point-data ตัวสุดท้าย (SADT-VISOR sadt_flexreg/util.py:25-28, 32-44) legacy แก้เรื่องนี้ใน ADTLib (legacy FlexReg_CLI/FlexReg_Method/util.py:24-30) ตัวอย่างใน Slicer กลับเลือกอาร์เรย์องค์ประกอบเดียวตัวแรก (FlexRegLib/butterfly_preview.py:136-152) ขณะที่คอมเมนต์ของมันบอกว่าเซิร์ฟเวอร์เลือกแบบเดียวกัน: ตัวอย่างและเซิร์ฟเวอร์อาจใช้อาร์เรย์ต่างกันบนส่วนโค้งฟันเดียวกัน

ฟันสี่ซี่สำหรับวางทิศทางคงที่

ส่วนโค้งฟันถูกวางทิศทางบนฟันซี่ 3, 5, 12 และ 14 ไม่ว่าจะเลือกฟันใดสำหรับมุม (SADT-VISOR make_butterfly.py:82-83) ไคลเอนต์ใช้ค่าคงที่เดียวกัน (AutomatedDentalToolsRemote FlexRegRemote/FlexRegLib/butterfly_preview.py:29) ส่วนโค้งฟันที่ขาดซี่ใดซี่หนึ่งในนั้นล้มเหลว แม้ฟันสี่ซี่ที่เลือกจะมีอยู่ อาร์กิวเมนต์ tooth_* ทั้งสี่ถูกซ่อนในแผง (layout.py:101-104)

ขอบเขตของจอยสติ๊กถูกบังคับโดยเซิร์ฟเวอร์

Ratio ใน [0, 1] การปรับใน [-5, 5] mm การเลื่อนใน [-15, 15] mm (SADT-VISOR layout.py:24-28, 57-59, 81-83) ค่านอกช่วงถูกปฏิเสธ (VISOR-serve server/base.py:759-768) คอมเมนต์ใน layout.py:22-23 ยังบอกว่าตัวเลขที่ใหญ่กว่าที่พิมพ์ในกล่อง "still works" ซึ่งไม่เป็นจริงอีกต่อไป

ชื่อเอาต์พุตอาจโกหกเรื่องรูปแบบ

เอาต์พุตคงนามสกุลอินพุต (SADT-VISOR __init__.py:163) แต่ถูกเขียนเป็นไฟล์ VTK legacy แบบไบนารีเสมอ (pipeline.py:90-94) ดังนั้นอินพุต .stl หรือ .vtp ได้ไฟล์ที่มีนามสกุลนั้นแต่เนื้อหาเป็น VTK อ่านจากโค้ด ไม่ได้ตรวจว่า Slicer ทำอะไรกับไฟล์แบบนี้ legacy เขียน .vtk เสมอ (legacy FlexReg_CLI.py:321)

พาธเซิร์ฟเวอร์แบบสัมบูรณ์ในรายงาน สมมติว่าใช้ GPU ทุกโหมด

รายงานเก็บพาธเซิร์ฟเวอร์แบบสัมบูรณ์ของเอาต์พุตและของ transform (SADT-VISOR __init__.py:170, 175) ทั้งที่ข้อความความคืบหน้าหลีกเลี่ยงชื่อไฟล์โดยตั้งใจ (__init__.py:144-146) และเพราะเครื่องมือไม่ประกาศ device เซิร์ฟเวอร์จึงเข้าคิว GPU แม้แต่ให้ Register (VISOR-serve server/execution/dispatch.py:95-116)

เอกสารของเครื่องมืออธิบายการพลิกของ legacy ผิด

docstring ของ pipeline.py (SADT-VISOR pipeline.py:8-14), README (tools/FlexReg/README.md:32-36) และ docstring ของ test_a_surface_leaves_in_the_convention_it_arrived_in (tests/test_run.py:62-65) บอกว่า CLI ของ legacy พลิกไป RAS ตอนอ่านและไม่เคยพลิกกลับ ที่ 3c67957 มันพลิกกลับก่อนเขียน (legacy FlexReg_CLI.py:295-305) โค้ด VISOR ถูกต้อง มีเพียงความต่างที่ระบุไว้ที่ไม่เป็นจริงสำหรับ commit นั้น ในทำนองเดียวกัน docstring ของโมดูลบอกว่า curve และ delete "stay in the Slicer module" (__init__.py:19) แต่ FlexRegRemote.py ไม่มีทั้งสองอย่าง

การสร้าง patch จริงไม่มีเทสต์

marker gpu ถูกประกาศ (SADT-VISOR tools/FlexReg/pyproject.toml:32-34) แต่ไม่มีเทสต์ใดใช้ และเทสต์ฟันที่หายไปแทน butterflyPatch ด้วยของปลอม (tests/test_run.py:336-349) ตัวเลขใน README ของเครื่องมือ (patch บนส่วนโค้งฟัน 294,260 จุด) ไม่มีเทสต์รองรับในที่เก็บ

AREG_IOS กับ VISOR

สิ่งที่เปลี่ยนไปเมื่อคุณรัน AREG_IOS ผ่านเซิร์ฟเวอร์ VISOR จาก 3D Slicer: ต้องเตรียมอะไร อะไรเหมือนเดิม อะไรต่างไป โมดูล legacy มีหน้าของตัวเอง

VISOR หน้า Legacy แอตลาส (VISOR)

AREG_IOS ลงทะเบียนการสแกนในช่องปากติดตามผล (T2) เข้ากับการสแกนพื้นฐาน (T1) ของผู้ป่วยคนเดียวกัน บนแพตช์ที่การรักษาไม่ขยับ: เพดานปาก หรือแถบตามแนว mucogingival เมื่อใช้ VISOR การลงทะเบียนถูกคำนวณบนเซิร์ฟเวอร์ รวมถึงเครือข่ายที่ทำนายแพตช์เพดานปาก: ใน Slicer คุณกรอกแบบฟอร์ม ส่งโฟลเดอร์ และรับผลลัพธ์กลับมา หน้านี้เขียนจากโค้ดของ VISOR (SADT-VISOR 6ba2a78, VISOR-serve e9a7e5d, AutomatedDentalToolsRemote 19b95e8) ส่วนรายละเอียดอยู่ในหน้าแอตลาส

อะไรเปลี่ยนในแผง

  • เปิด AREG Remote (หมวด “Automated Dental Tools Remote”) แล้วเลือก IOS ในช่องแรก โหมด
  • ระดับอัตโนมัติ: Fully-Automated (ค่าเริ่มต้น) ติดป้ายฟันและปรับทิศทางสแกนบนเซิร์ฟเวอร์ Semi-Automated คาดหวังสแกนที่มีป้ายฟันและทิศทางร่วมกันอยู่แล้ว
  • แพตช์ลงทะเบียน แทนสองโหมดของโมดูล legacy: เพดานปาก (ฟันบน) ทำนายแพตช์เพดานปากและลงทะเบียนฟันบน โดยฟันล่างตามไป แนว mucogingival (ฟันล่าง) ลงทะเบียนฟันล่างเพียงอย่างเดียว
  • ไม่ต้องดาวน์โหลดโมเดลและไม่ต้องมีการ์ดจอบนเครื่องของคุณ โมเดลแพตช์ reference การปรับทิศทาง และโมเดลครอบฟันถูกเลือกโดยเซิร์ฟเวอร์ และช่องของมันถูกซ่อน
  • สำหรับแพตช์ mucogingival Mucogingival landmarks (landmark 13 จุดของคุณเองต่อสแกนฟันล่าง ไม่บังคับ: มิฉะนั้นเซิร์ฟเวอร์ทำนายให้) และ Patch height (mm)

สิ่งที่คุณต้องเตรียม

  • T1 และ T2: โฟลเดอร์ละหนึ่ง หรือ cohort ทดสอบที่โฮสต์ รูปแบบ .vtk .vtp .stl .obj เพราะสองช่วงเวลาเป็นสองโฟลเดอร์ ชื่อไฟล์จึงไม่จำเป็นต้องมี T1 หรือ T2 อีกแล้ว
  • เมชแต่ละอันยังต้องระบุฟันของมันในชื่อ เป็นคำแยก (U, Upper, Maxilla, L, Lower, Mandible…) เมชที่ไม่ระบุจะถูกรายงานและตัดออก ไม่ถูกเดา ฟันอ่านจากชื่อไฟล์เท่านั้น ชื่อโฟลเดอร์จึงไม่สำคัญอีกแล้ว
  • ผู้ป่วยถูกรู้จักจากพาธโฟลเดอร์ย่อยบวกส่วนที่เหลือของชื่อ ซึ่งต้องตรงกันระหว่าง T1 และ T2

อะไรยังเหมือนเดิม

ICP แบบแข็งบนแพตช์ที่เสถียร แพตช์สองแบบเดิม และฟันอีกข้างถูกพาไปตามการลงทะเบียนเพดานปาก อินพุตของคุณไม่ถูกแก้ไข

อะไรต่างกันในผลลัพธ์

  • ไฟล์ transform (.tfm) ถูกเขียนสำหรับผู้ป่วยทุกคน ทั้งสองโหมดและทั้งสองแพตช์ เมื่อเซิร์ฟเวอร์ปรับทิศทางสแกนของคุณก่อน transform จะถูกประกอบกับการปรับทิศทางนั้นเพื่อให้อ้างถึงสแกนที่คุณส่ง
  • ผลลัพธ์คงโครงโฟลเดอร์ของคุณ เมื่อใช้แพตช์เพดานปาก มันยังมีฟันล่างของแต่ละช่วงเวลา ที่ย้ายไปพร้อมฟันบน เมื่อใช้แพตช์ mucogingival จะกลับมาเฉพาะฟันล่าง AREG_report.json ระบุสำหรับผู้ป่วยแต่ละคนว่าทำอะไรไป การปรับทิศทางแบบ canonical ของแพตช์เพดานปากที่ล้มเหลวถูกเขียนไว้ที่นั่นเป็นหมายเหตุ แทนที่จะอยู่แค่ในบันทึก
  • แถบ mucogingival ถูกสร้างโดยไม่มีสามการปรับปรุงของโมดูล legacy (ตัวกรอง landmark ที่น่าสงสัย การจำกัดเฉพาะ landmark ที่มีทั้งสองช่วงเวลา และจุดเริ่มต้นของ ICP ที่อิง landmark) และมันตัดฟันล่าง 18 ถึง 31 ออก ขณะที่ legacy ตัด 17 ถึง 32 ให้เปรียบเทียบสองสามรายก่อนผสมผลของ legacy และ VISOR ในการศึกษาเดียว
  • เครือข่ายเพดานปากรันบน GPU ของเซิร์ฟเวอร์ หรือบน CPU เมื่อไม่มี GPU
พิมพ์ความสูงแพตช์สำหรับแพตช์ mucogingival

ช่อง Patch height (mm) เริ่มที่ 0 และ 0 ไม่ได้หมายถึง “use the default”: มันหมายถึงไม่มีแถบเลย การลงทะเบียนจึงใช้เพียงราว 13 จุด landmark โมดูล legacy เริ่มที่ 5 mm พิมพ์ความสูง (5 คือค่าเริ่มต้นของเอนจินเอง) ก่อนกด Apply ไม่มีค่าสูงสุด จึงควรให้อยู่ภายในเหงือกส่วนที่ยึดติด ค่าที่ใช้ถูกเขียนในรายงาน สังเกตได้จากการเรียกเครื่องมือ VISOR: การรันที่ไม่มีความสูงส่งถึงเอนจินด้วย 0

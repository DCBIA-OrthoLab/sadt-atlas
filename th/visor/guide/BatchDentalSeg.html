BatchDentalSeg กับ VISOR

สิ่งที่เปลี่ยนไปเมื่อคุณรัน BatchDentalSeg ผ่านเซิร์ฟเวอร์ VISOR จาก 3D Slicer: ต้องเตรียมอะไร อะไรเหมือนเดิม อะไรต่างไป โมดูล legacy มีหน้าของตัวเอง

VISOR หน้า Legacy แอตลาส (VISOR)

เมื่อใช้ VISOR โมดูลคือ BatchDentalSegmentator Remote: การแบ่งส่วนรันบนเซิร์ฟเวอร์ การใช้ VISOR อธิบายวิธีเชื่อมต่อ Slicer กับเซิร์ฟเวอร์ หน้านี้ครอบคลุมสิ่งที่เฉพาะกับ BatchDentalSeg

อะไรเปลี่ยนในแผง

  • ไม่ต้องติดตั้ง extension ไม่ต้องดาวน์โหลดน้ำหนักโมเดล ไม่มีการตั้งค่าหน่วยความจำ: การคำนวณและหน่วยความจำเป็นของเซิร์ฟเวอร์ การครอปอัตโนมัติ ปุ่ม "Free memory" ปุ่มแก้ซ้ายขวาของ UniversalLab และคิวที่บันทึกไว้ไม่มีในโมดูล remote
  • โมเดลถูกเลือกจากรายการโมเดลที่โฮสต์บนเซิร์ฟเวอร์ ชื่อคือ DentalSegmentator, PediatricDentalSeg, NasoMaxillaDentSeg และ UniversalLab คุณส่งน้ำหนักโมเดลของตัวเองไม่ได้
  • อินพุต: หนึ่งสแกนหรือโฟลเดอร์ หรือไฟล์ทดสอบที่เซิร์ฟเวอร์โฮสต์ โฟลเดอร์ถูกค้นหาแบบเรียกซ้ำและอาจมีไฟล์ NRRD, NIfTI หรือ GIPL cohort ใหญ่ถูกแผงตัดเป็นแบตช์ (ค่าเริ่มต้นไม่เกิน 400 MB หรือ 25 ไฟล์ต่อแบตช์)
  • รูปแบบผลลัพธ์ เป็นชิป: NIFTI (volume ฉลาก), STL, OBJ, VTK (หนึ่งเมชต่อโครงสร้าง) และ VTK (merged) (หนึ่งเมชที่มีค่า Label ต่อเซลล์) ต้องเลือกอย่างน้อยหนึ่งอย่าง glTF ไม่ได้เสนออีกแล้ว "One binary file per structure" ใช้ได้เฉพาะร่วมกับ NIFTI
  • ซ่อน: อุปกรณ์ การ resample บน GPU การซ้อนทับของไทล์ และการลดเมช แผงขอ GPU เสมอด้วยค่าเริ่มต้น (เครื่องมือถอยไปใช้ CPU พร้อมคำเตือนหากเซิร์ฟเวอร์ไม่มีการ์ด)

อะไรยังเหมือนเดิม

โมเดลทั้งสี่ โครงสร้างและหมายเลขฉลากของมัน fold เดียวไม่มี ensemble ไม่มีการล้างผลของเครือข่ายด้วยมอร์โฟโลยี และผลถูกวางกลับบนกริดเดิมของสแกนคุณ

อะไรต่างกันในผลลัพธ์

  • volume ฉลากชื่อ <scan>_Seg บวกนามสกุล (ตัวระบุแก้ไขได้) ไม่ใช่ <scan>_Segmentation.nii.gz และนามสกุลถูกบีบอัด (.nii กลับมาเป็น .nii.gz, .gipl เป็น .gipl.gz)
  • volume ฉลากไม่ถูกเขียนเสมอไปอีกแล้ว: มีเฉพาะเมื่อเลือก NIFTI
  • BatchDentalSeg_report.json มาพร้อมผลลัพธ์ มันระบุแต่ละสแกน (case_0000, ... ตามลำดับ ไม่ใช่ตามชื่อผู้ป่วย) ว่าสำเร็จหรือไม่ และตารางหมายเลขฉลากของโมเดล
  • สแกนที่อ่านไม่ได้ถูกรายงานว่าล้มเหลว และที่เหลือยังถูกแบ่งส่วนต่อ
  • เมชถูกสร้างต่างจากของ legacy: เป็นค่าเริ่มต้น เมช VISOR ถูกปรับให้เรียบด้วย 30 รอบและไม่ถูกลด ขณะที่ VTK ของ legacy ถูกปรับให้เรียบด้วย 60 รอบและลด 40 % อย่าคาดหวังไฟล์ที่เหมือนกับของ legacy
  • แผงโหลดลงฉากไม่เกิน 12 ผลลัพธ์ volume ฉลากถูกโหลดเป็น label map ธรรมดา รายงานไม่ถูกใช้ตั้งชื่อหรือใส่สีให้ segment
สแกนชื่อ ..._Seg ในโฟลเดอร์ถูกเพิกเฉย

ด้วยตัวระบุเริ่มต้น ไฟล์เช่น patient_Seg.nii.gz ที่พบในโฟลเดอร์ถูกถือเป็นผลลัพธ์ก่อนหน้าและถูกข้ามโดยไม่มีข้อความ ให้เปลี่ยนชื่อ หรือเลือกไฟล์นั้นเดี่ยว ๆ: ไฟล์เดี่ยวถูกประมวลผลเสมอ (อ้างอิง: SADT-VISOR sadt_batchdentalseg/pipeline.py:72-107)

การ resample บน GPU

เป็นค่าเริ่มต้น เซิร์ฟเวอร์ resample สแกนบน GPU ซึ่งเปลี่ยนตัวเลขเล็กน้อยมากเมื่อเทียบกับการ resample ของ nnU-Net เอง ฟิลด์รายงาน gpu_resampling บอกว่าขอบน GPU หรือไม่ เพราะการตั้งค่านี้ถูกซ่อนในแผง หากคุณต้องการ pipeline nnU-Net ที่แน่นอน ให้ถามผู้ดูแลเซิร์ฟเวอร์

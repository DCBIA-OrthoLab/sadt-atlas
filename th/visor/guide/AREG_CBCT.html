AREG_CBCT กับ VISOR

สิ่งที่เปลี่ยนไปเมื่อคุณรัน AREG_CBCT ผ่านเซิร์ฟเวอร์ VISOR จาก 3D Slicer: ต้องเตรียมอะไร อะไรเหมือนเดิม อะไรต่างไป โมดูล legacy มีหน้าของตัวเอง

VISOR หน้า Legacy แอตลาส (VISOR)

AREG_CBCT ลงทะเบียน CBCT ติดตามผล (T2) เข้ากับ CBCT พื้นฐาน (T1) ของผู้ป่วยคนเดียวกัน บนบริเวณที่ไม่เปลี่ยนระหว่างสองครั้ง เมื่อใช้ VISOR การลงทะเบียนถูกคำนวณบนเซิร์ฟเวอร์: ใน Slicer คุณกรอกแบบฟอร์ม ส่งโฟลเดอร์ และรับผลลัพธ์กลับมา สิ่งที่คุณทำเหมือนเดิมในเชิงหลักการ แต่แผงและรายละเอียดบางอย่างต่างกัน หน้านี้เขียนจากโค้ดของ VISOR (SADT-VISOR 6ba2a78, VISOR-serve e9a7e5d, AutomatedDentalToolsRemote 19b95e8) ส่วนวิธีการและเหตุผลอยู่ในหน้าแอตลาส

อะไรเปลี่ยนในแผง

  • เปิดโมดูล AREG Remote (หมวด “Automated Dental Tools Remote”) หนึ่งโมดูลรองรับการลงทะเบียน AREG สามแบบ: ช่องแรก โหมด คือที่ที่คุณเลือก CBCT ช่องอื่นจะตามโหมด
  • ระดับอัตโนมัติ คงสามตัวเลือกไว้ (Semi-Automated, Fully-Automated, Oriented + Fully-Automated) และเริ่มที่ Fully-Automated
  • ไม่ต้องดาวน์โหลด: โมเดลการแบ่งส่วนและการปรับทิศทางอยู่บนเซิร์ฟเวอร์ และช่องสำหรับโมเดลการแบ่งส่วนไม่แสดง
  • จุดหยุดตรวจทาน (“Review and manual adjustment”) ช่อง Merge Segmentations และ Include Approximation Step ไม่อยู่ในแผง
  • ช่องทำเครื่องหมาย Load the results into the scene when done ถูกติ๊กไว้เป็นค่าเริ่มต้น มันโหลด volume ที่ลงทะเบียนแล้ว ไม่เคยโหลด .tfm และไม่โหลดอะไรเลยเมื่อมีไฟล์กลับมามากกว่า 12 ไฟล์

สิ่งที่คุณต้องเตรียม

  • T1 และ T2: โฟลเดอร์ละหนึ่ง หรือ cohort ทดสอบที่โฮสต์ซึ่งเลือกจากรายการเหนือตัวเลือกไฟล์ โฟลเดอร์ cohort เดียวที่มี T1/ และ T2/ ก็ยอมรับ รูปแบบที่ยอมรับ: .nii.gz .nrrd.gz .gipl.gz .nii .nrrd .gipl ติ๊ก Input is DICOM สำหรับชุด DICOM
  • Register on: บริเวณ เหมือนเดิม แต่ละบริเวณให้การลงทะเบียนและโฟลเดอร์ผลลัพธ์ของตัวเอง
  • ใน Semi-Automated ต้องมี T1 masks ซึ่งจำเป็น มาสก์ถูกรู้จักเมื่อชื่อของมันมีคำบอกมาสก์ (mask, seg, pred หรือ segmentation) และคำบอกบริเวณเป็นส่วนแยกของชื่อ
  • ใน Oriented + Fully-Automated ต้องมี Orientation reference ซึ่งจำเป็น
  • AMASSS segmentation (โหมดอัตโนมัติ): ติ๊กโครงสร้างที่คุณอยากได้กลับมาดูด้วย มันไม่เปลี่ยนสิ่งที่การลงทะเบียนใช้

อะไรยังเหมือนเดิม

การลงทะเบียนแบบแข็งของ elastix จำกัดอยู่ในบริเวณที่คุณเลือกบน T1 โดยย้าย T2 เข้ากรอบของ T1 สำหรับผู้ป่วยและบริเวณแต่ละรายการคุณได้ T2 ที่ลงทะเบียนแล้วและ .tfm ของมัน อินพุตของคุณไม่ถูกแก้ไข

อะไรต่างกันในผลลัพธ์

  • ผลลัพธ์อยู่ในหนึ่งโฟลเดอร์ต่อรหัสบริเวณ (CB, MAND, MAX) บวก AREG_report.json ที่ราก: สำหรับผู้ป่วยและบริเวณแต่ละรายการ ว่าสำเร็จหรือไม่ ใช้มาสก์ใด และหมายเหตุเมื่อมีสิ่งผิดปกติ
  • transform ที่เขียนตอนนี้รวมจุดศูนย์กลางการหมุนที่ elastix ใช้ โมดูล legacy ทิ้งมันไป ทำให้ transform ของมันอาจต่างจากการลงทะเบียนที่ elastix พบจริง ด้วยปริมาณที่เพิ่มขึ้นตามระยะของสแกนจากจุดกำเนิด หน้าแอตลาส ให้ตัวเลข
  • T2 ไม่ถูกจัดกึ่งกลางล่วงหน้าอีกแล้ว และในโหมด Oriented มีเพียง T1 ที่ถูกปรับทิศทาง
  • มีเพียง T1 ที่ถูกแบ่งส่วน: การแบ่งส่วนของ T2 ที่ลงทะเบียนแล้วซึ่งโมดูล legacy คืนได้ไม่ถูกผลิตขึ้น
  • ผู้ป่วยที่พบในโฟลเดอร์เพียงหนึ่งจากสองโฟลเดอร์ไม่ถูกทิ้งโดยเงียบ: มันถูกระบุในรายงาน และการรันที่ไม่มีอะไรจับคู่กันจะหยุดด้วยข้อผิดพลาดที่อธิบายกฎการจับคู่
โหมด Oriented: เลือก reference แบบ Frankfurt

ขั้นตอนปรับทิศทางขอ landmark เริ่มต้นจาก ASO คือชุด Frankfurt ไม่ว่าคุณจะเลือก reference ใด reference แบบ Occlusal มี landmark อื่น และ ASO ปฏิเสธการรวมที่รองรับไม่ได้ หากคุณเลือก reference แบบ Occlusal ในโหมดนี้ ให้คาดว่าจะถูกปฏิเสธ นี่อ่านจากโค้ด ไม่ได้รันสายนี้

FlexReg กับ VISOR

สิ่งที่เปลี่ยนไปเมื่อคุณรัน FlexReg ผ่านเซิร์ฟเวอร์ VISOR จาก 3D Slicer: ต้องเตรียมอะไร อะไรเหมือนเดิม อะไรต่างไป โมดูล legacy มีหน้าของตัวเอง

VISOR หน้า Legacy แอตลาส (VISOR)

เมื่อใช้ VISOR โมดูลคือ FlexReg Remote แพตช์และการลงทะเบียนรันบนเซิร์ฟเวอร์ ส่วนตัวอย่างเส้นขอบของแพตช์อยู่ใน Slicer การใช้ VISOR อธิบายวิธีเชื่อมต่อ Slicer กับเซิร์ฟเวอร์ หน้านี้ครอบคลุมสิ่งที่เฉพาะกับ FlexReg

อะไรเปลี่ยนในแผง

  • จอยสติก สี่มุมของแพตช์เพดานปากคือจอยสติก 2D สี่ตัว (อัตราส่วนจากกลางส่วนโค้งฟันถึงซี่ฟัน และการเลื่อนไปข้างหน้าหรือข้างหลังเป็นมิลลิเมตร) บวกอีกหนึ่งตัวที่ย้ายแพตช์ทั้งหมด ค่าที่อยู่นอกช่วงของมันถูกเซิร์ฟเวอร์ปฏิเสธ
  • ตัวอย่าง เมื่อติ๊ก "Preview the patch while I drag" (เป็นค่าเริ่มต้น) เส้นขอบของแพตช์ถูกวาดใหม่ในมุมมอง 3D ขณะที่คุณเลื่อนจอยสติก โดยไม่รอเซิร์ฟเวอร์ มันต้องการให้ส่วนโค้งฟันเป็นพื้นผิวที่โหลดในฉาก Slicer หากเป็นโฟลเดอร์ของส่วนโค้งฟัน จะไม่มีตัวอย่าง มีเพียงเส้นขอบที่ถูกวาด: แพตช์ที่เติมเต็มที่ใช้ลงทะเบียนถูกเซิร์ฟเวอร์คำนวณเมื่อคุณกด Apply
  • ต้องทำอะไร: Patch (สร้างแพตช์และเขียนพื้นผิว), Register (ลงทะเบียนบนแพตช์ที่อยู่ในไฟล์แล้ว) หรือ Patch and register (ค่าเริ่มต้น) เพื่อลงทะเบียน เลือกพื้นผิว reference
  • สองตัวเลือกของแพตช์: เพดานปาก (butterfly) หรือแนว mucogingival ซึ่งต้องอยู่ในไฟล์แล้ว
  • อินพุต: ส่วนโค้งฟันที่ติดป้ายแล้วเป็น .vtk, .vtp หรือ .stl หรือโฟลเดอร์ของมัน เซิร์ฟเวอร์อาจเสนอส่วนโค้งฟันทดสอบ
  • ไม่มีให้ใช้: เส้นขอบวาดด้วยมือ การลบแพตช์ แถบฟันล่างที่คำนวณจากlandmark ส่วนโค้งฟันที่สองตามส่วนแรก และการแบ่งส่วนครอบฟันอัตโนมัติ ส่วนโค้งฟันต้องมีป้ายฟันอยู่แล้ว

อะไรยังเหมือนเดิม

การสร้างแพตช์ butterfly และการลงทะเบียนแบบแข็งบนมันเป็นโค้ดเดียวกับในโมดูล legacy และ transformation ถูกเขียนเป็น .tfm ในแบบเดียวกัน

อะไรต่างกันในผลลัพธ์

  • ไม่มีอะไรถูกเขียนทับ สำหรับแต่ละส่วนโค้งฟันคุณได้ <name>_Reg (ส่วนต่อท้ายแก้ไขได้) ในโฟลเดอร์ผลลัพธ์ พร้อมต้นไม้โฟลเดอร์ของคุณ บวก .tfm เมื่อคุณลงทะเบียน บวก FlexReg_report.json
  • หากฟันที่แพตช์ต้องใช้หายไปจากส่วนโค้งฟัน ส่วนโค้งนั้นถูกรายงานว่าล้มเหลวพร้อมข้อความ โมดูล legacy เขียนส่วนโค้งกลับโดยไม่มีแพตช์และดูเหมือนสำเร็จ
  • ผลลัพธ์คงนามสกุลอินพุตของคุณ แต่ถูกเขียนเป็นไฟล์ VTK เสมอ
reference ต้องมีแพตช์อยู่แล้ว

ใน "Patch and register" แพตช์ถูกสร้างบนส่วนโค้งฟันที่คุณลงทะเบียน ไม่ใช่บน reference เมชทั้งสองต้องมีแพตช์: สร้างบน reference ก่อน (โหมด Patch บนส่วนโค้งนั้น) แล้วใช้ผลลัพธ์เป็น reference มิฉะนั้นการรันหยุดด้วยข้อผิดพลาดที่ไม่ถูกรายงานต่อส่วนโค้งฟัน และแบตช์จบโดยไม่มีรายงาน (อ้างอิง: SADT-VISOR sadt_flexreg/__init__.py:121, 155-157, 177 อ่านจากโค้ด ไม่ได้รัน)

VISOR สร้างแนว mucogingival ไม่ได้

การเลือก "Mucogingival line" ใช้ได้เฉพาะกับไฟล์ที่มีบริเวณนั้นถูกทำเครื่องหมายอยู่แล้ว ไม่มีอะไรใน VISOR คำนวณมัน และในโหมด Patch ตัวเลือกนั้นคัดลอกส่วนโค้งฟันของคุณโดยไม่เปลี่ยนและยังรายงานว่าสำเร็จ

BatchDentalSeg บน VISOR

BatchDentalSeg ใส่ป้ายกำกับฟันและขากรรไกรในสแกน CT และ CBCT เป็นแบตช์ ด้วยเครือข่ายหลายป้ายกำกับตัวเดียวที่ให้ป้ายกำกับแก่ทุก voxel ในรอบเดียว หน้านี้อธิบายว่าการรันใน VISOR ดำเนินไปอย่างไรทีละขั้น พร้อมคณิตศาสตร์ของส่วนที่เป็นการคำนวณมากกว่าการเรียนรู้: สแกนถูกทำให้เป็นบรรทัดฐานอย่างไร patch ของเครือข่ายถูกผสมกันอย่างไร ป้ายกำกับของแต่ละ voxel ถูกเลือกอย่างไร ตรงที่โค้ดทำอะไรที่ควรตรวจ จะมีลิงก์ไปยังหน้าโค้ด โมดูล legacy อธิบายอยู่ในหน้าของมันเอง

โค้ด (นักพัฒนา) VISOR Batch_Dental_Seg หน้า Legacy คู่มือ (VISOR) บรรณานุกรม

ภาพรวม: อะไรเข้า อะไรออก

BatchDentalSeg รับสแกน CT หรือ CBCT ของศีรษะและใส่ป้ายกำกับฟันและขากรรไกรในแต่ละสแกน เครือข่าย 3 มิติตัวเดียว ที่เลือกจากสี่ตัว ให้ป้ายกำกับแก่ทุก voxel ในรอบเดียว ไม่ใช่หนึ่งเครือข่ายต่อหนึ่งโครงสร้างอย่างใน AMASSS ใน VISOR สแกนถูกส่งไปยังเซิร์ฟเวอร์ ซึ่งเรียก nnU-Net หนึ่งครั้งต่อแบตช์ของสแกนที่เซิร์ฟเวอร์ส่งให้เครื่องมือ (หัวข้อ 4 ระบุขนาดแบตช์)

เข้าเกิดอะไรขึ้นออก
สแกนหรือโฟลเดอร์ ชื่อของหนึ่งในสี่โมเดลที่โฮสต์ไว้ และรูปแบบการส่งออกสแกนถูกแปลง nnU-Net หนึ่งรอบใส่ป้ายกำกับทุกสแกนของแบตช์ และ label volume แต่ละอันถูกวางกลับบนกริดของสแกนของมันlabel volume หนึ่งอันต่อสแกน ไฟล์ต่อป้ายกำกับ (ถ้าเลือก) พื้นผิว STL, OBJ, VTK และ BatchDentalSeg_report.json

1. ตำแหน่งในสายโซ่

เครื่องมือเป็นใบของต้นไม้: ไม่เรียกเครื่องมืออื่น และมีเครื่องมือหนึ่งตัวเรียกมัน VFACE ใช้มันสำหรับheat mapของตัวเอง โดยขอโมเดลและ prediction ID ไม่ได้พอร์ตโดยตั้งใจ: การครอปอัตโนมัติ ตัวป้องกันหน่วยความจำ การแก้ไขกระจกเงา คิวถาวร และการส่งออก glTF เซิร์ฟเวอร์รับช่วงการรับเข้าและหน่วยความจำ

ในโค้ดผู้เรียก สถานะของพอร์ต และตารางเครื่องมือ

1.1 อะไรรันที่ไหน

  • บนเซิร์ฟเวอร์: การอ่านและแปลงสแกน การเรียก nnU-Net หนึ่งครั้งสำหรับทั้งแบตช์ การวางป้ายกำกับกลับบนกริดของสแกน การเขียน label volume ไฟล์ต่อป้ายกำกับ เมช และรายงาน
  • ใน Slicer: การเลือกสแกน ชื่อโมเดล และรูปแบบการส่งออก การแตกไฟล์อาร์ไคฟ์ผลลัพธ์ และการโหลดผลลัพธ์สูงสุด 12 รายการ ไม่มีสิ่งใดเกี่ยวกับกายวิภาคหรือโมเดลอยู่ในแผง
  • ไม่มีอะไรติดตั้งใน Slicer: ไม่มี extension NNUNet ไม่มี torch ไม่ดาวน์โหลดโมเดล bundle ของโมเดลถูกโฮสต์บนเซิร์ฟเวอร์และเผยแพร่เป็นชื่อ น้ำหนักโมเดลจึงไม่เคยถูกส่งจากแล็ปท็อป
ในโค้ดตารางว่ารันที่ไหน พร้อมไฟล์และบรรทัด

2. ไฟล์ที่เกี่ยวข้อง

เครื่องมือเป็นแพ็กเกจธรรมดาที่มีฟังก์ชันสาธารณะหนึ่งตัว ไปป์ไลน์ ตารางของโมเดลทั้งสี่และป้ายกำกับของมัน wrapper รอบ nnU-Net โมดูลสำหรับการสุ่มตัวอย่างใหม่ที่ประหยัดหน่วยความจำ ตัวส่งออกเมช และเลย์เอาต์ของแผง เซิร์ฟเวอร์และแผง Slicer เพิ่มอาร์กิวเมนต์ที่ซ่อน เมนูโมเดล ขีดจำกัดหน่วยความจำสำหรับ worker ของ nnU-Net และการโหลดผลลัพธ์

ในโค้ดตารางไฟล์พร้อมจำนวนบรรทัด และไฟล์นอกเครื่องมือ

3. ไปป์ไลน์

เส้นตรง: โมเดลถูกตรวจก่อนอ่านสแกนใดๆ ทุกสแกนถูกแปลงลงโฟลเดอร์เดียว nnU-Net รันครั้งเดียวบนโฟลเดอร์นั้น แล้วแต่ละสแกนถูกเขียนกลับบนกริดของตัวเอง เฉพาะขั้นของเครือข่ายที่เป็นขั้นที่เรียนรู้ กล่องแต่ละกล่องของแผนภาพลิงก์ไปยังหัวข้อของมัน

ในโค้ดฟังก์ชันประสานงาน

3.1 อินพุตและการค้นหา

ไฟล์เดี่ยวถูกรับตามที่เป็น โฟลเดอร์ถูกเดินแบบเรียกซ้ำและเก็บไฟล์ที่มีนามสกุลของ volume ยกเว้นไฟล์ที่ชื่อดูเหมือนผลลัพธ์ก่อนหน้าของเครื่องมือ (ลงท้ายด้วย prediction ID หรือ prediction ID กับชื่อป้ายกำกับ) ดังนั้นโฟลเดอร์รันซ้ำในที่เดิมได้ โครงสร้างอินพุตถูกเก็บไว้: แต่ละ case ถูกอธิบายในรายงานด้วยพาธสัมพัทธ์กับอินพุต ไม่เคยเป็นพาธสัมบูรณ์

ในโค้ดการค้นหาและตัวกรองผลลัพธ์ก่อนหน้า

3.2 โมเดล: หนึ่งชื่อ หนึ่ง bundle หนึ่งตารางป้ายกำกับ

ชื่อโมเดลถูกค้นก่อนอ่านสแกนใดๆ ชื่อที่ไม่รู้จักถูกปฏิเสธพร้อมรายการโมเดลที่รู้จัก และ bundle ที่ไม่ครบก็ถูกปฏิเสธเช่นกัน ชื่อยังเลือกตารางป้ายกำกับด้วย ผู้เรียกจึงจับคู่ bundle หนึ่งกับป้ายกำกับของอีกอันไม่ได้

ฉากด้านล่างคือวิวเวอร์ของหน้า legacy นำมาใช้ซ้ำตามที่เป็น: เรขาคณิตของมันมาจากการรัน UniversalLab แบบ legacy บนตัวอย่างที่ Slicer เผยแพร่เอง และไม่มีการรัน VISOR ใดสร้างมัน สิ่งที่มันแสดงยังคงเป็นจริงสำหรับ VISOR โดยมีความต่างที่ระบุไว้ใต้ภาพ

3.3 การแปลงเป็นโครงสร้างของ nnU-Net

ทุกสแกนถูกอ่านและเขียนใหม่ลงโฟลเดอร์เดียวภายใต้ case id ตามตำแหน่ง (case_0000, case_0001...) ไม่เคยเปลี่ยนชื่อ: nnU-Net เลือกตัวอ่านจากนามสกุล ดังนั้น NRRD ที่เปลี่ยนชื่อจะถูกอ่านผิด id เป็นแบบตามตำแหน่งเพราะ nnU-Net เขียนผลลัพธ์ใต้ id ของอินพุต และสแกนสองตัวที่ชื่อเหมือนกันในโฟลเดอร์ย่อยต่างกันจะชนกัน สแกนที่อ่านไม่ได้ถูกบันทึกว่า failed และข้าม

แพ็กเกจนี้ไม่เขียน windowing หรือการครอป การสุ่มตัวอย่างใหม่เพียงอย่างเดียวที่มันเพิ่มคือแบบการ์ดจอที่เป็นทางเลือกใน 3.5 และแบบที่วางผลลัพธ์กลับบนกริดของสแกน (3.6) การประมวลผลก่อนที่เหลือเป็นของ nnU-Net ขับเคลื่อนด้วยแผนของแต่ละ bundle การครอปอัตโนมัติแบบ legacy ไม่ได้พอร์ตโดยตั้งใจ เพราะมันเปลี่ยนสิ่งที่เครือข่ายเห็น

อ่านได้เฉพาะแผนของ DentalSegmentator ในรีโพซิทอรี (ในรีโพซิทอรี legacy): เปอร์เซ็นไทล์ −110 และ 3067, ค่าเฉลี่ย 1274, ส่วนเบี่ยงเบนมาตรฐาน 558 อีกสามชุดมีไฟล์แผนของตัวเอง ดังนั้นสูตรนี้สำหรับพวกมันเป็นข้อสันนิษฐาน ไม่ได้ตรวจ

ในโค้ดcase id การแปลง และสแกนที่อ่านไม่ได้

3.4 การอนุมาน: หนึ่งการเรียกสำหรับทั้งแบตช์

nnU-Net ถูกเรียกครั้งเดียวด้วยทั้งโฟลเดอร์อินพุตที่ได้รับ (cohort ขนาดใหญ่ถึงเครื่องมือเป็นหลายโฟลเดอร์แบบนั้น) ดังนั้น checkpoint ถูกโหลดครั้งเดียวต่อการรัน ไม่ใช่ครั้งเดียวต่อสแกน การตั้งค่าเหมือนใน legacy: fold 0 (สำเนาที่ฝึกแล้วเพียงชุดเดียวของโมเดล ไม่ใช่ ensemble) step 0.5 (แต่ละ patch ขยับไม่เกินครึ่งหนึ่งของขนาดมัน) การถ่วงน้ำหนักแบบ Gaussian (น้ำหนักรูประฆังด้านล่าง) ไม่มี test-time mirroring (ไม่มีการเฉลี่ยบนสำเนาสแกนที่พลิก) อุปกรณ์ถอยไปใช้ CPU พร้อมคำเตือน เมื่อมองไม่เห็นการ์ด ความคืบหน้ามีปลายที่วัดได้เพียงสองด้าน: การอ่านนับสแกนจาก 0 ถึง 10 % การเขียนจาก 90 ถึง 100 % และตรงกลางมีหนึ่งบรรทัดที่บอก “segmenting N scan(s) in one pass”

ในโค้ดตัวเลือกของ predictor สองเส้นทางการอนุมาน และความคืบหน้า

3.5 การสุ่มตัวอย่างใหม่บน GPU และ argmax ต่อคลาส

โดยค่าเริ่มต้น บนการ์ดจอ (โค้ดเรียกว่าอุปกรณ์ CUDA ซึ่งเป็นอินเทอร์เฟซการคำนวณของ NVIDIA) เครื่องมือสลับการสุ่มตัวอย่างใหม่ของ nnU-Net เป็นของ torch volume อินพุตเปลี่ยนจากการแก้ค่าระหว่างจุดแบบ cubic เป็น linear ซึ่งโค้ดระบุว่าเป็นความต่างเชิงตัวเลขทั้งหมด

จากนั้นมันไปไกลกว่านั้น: ผลลัพธ์ของเครือข่ายถูกสุ่มตัวอย่างใหม่ทีละคลาส โดยเก็บค่าสูงสุดสะสมและป้ายกำกับของมัน เพื่อไม่ให้ชุดคะแนนคลาสทั้งหมดอยู่ในหน่วยความจำพร้อมกัน ตาม docstring ของโค้ดเอง ผลลัพธ์เหมือนกัน (0 voxel ที่ต่างจาก 95 682 560 ในการรัน UniversalLab) และค่าสูงสุดลดจากประมาณ 30.6 เหลือ 1.25 GiB (กิบิไบต์) ของหน่วยความจำวิดีโอ ตัวเลขเหล่านั้นไม่ได้ทำซ้ำที่นี่

ในโค้ดการสลับตัวสุ่มตัวอย่างใหม่และ argmax สะสมต่อคลาส

3.6 กลับบนกริดของสแกน และการเขียน

สำหรับแต่ละสแกน การทำนายถูกอ่านและวางกลับบนกริดที่ตรงกับสแกนต้นฉบับพอดี: ถ้าขนาดและ spacing ตรงกัน (ภายใน 0.0001) เรขาคณิตจะถูกคัดลอกเฉยๆ ไม่เช่นนั้น label volume ถูกสุ่มตัวอย่างใหม่แบบ nearest neighbour ทรีผลลัพธ์สะท้อนทรีอินพุต เมื่อเลือก NIfTI ไฟล์คือ <base>_<ID> บวกนามสกุลแบบบีบอัด เมื่อใช้ตัวเลือกต่อป้ายกำกับ หนึ่งไฟล์ไบนารีต่อป้ายกำกับที่มีอยู่ ตั้งชื่อตามป้ายกำกับ ไม่มีการทำความสะอาด การลบเกาะ หรือการอุดรู: volume คือผลลัพธ์ของ nnU-Net บนกริดของสแกน

ในโค้ดการคืนเรขาคณิตและตารางผลลัพธ์

3.7 พื้นผิว

ไม่มีอะไรเกิดขึ้นเว้นแต่ร้องขอรูปแบบเมช แต่ละป้ายกำกับที่มีอยู่ได้หนึ่งพื้นผิว สร้างครั้งเดียวและเขียนในทุกรูปแบบที่ขอ ดังนั้นการติ๊ก STL และ OBJ พร้อมกันจึงเสียค่า marching cubes เพียงรอบเดียว mask ถูกหาเส้นขอบ เมชถูกทำให้เรียบด้วยตัวกรอง windowed sinc (30 รอบ pass band 0.05 ตัวกรองที่ขยับแต่ละจุดยอดเข้าหาค่าเฉลี่ยของเพื่อนบ้านโดยหดรูปร่างให้น้อยที่สุดเท่าที่เป็นไปได้ การทำให้เรียบแบบ feature-edge ปิดไว้โดยตั้งใจ เพราะบนเมช marching-cubes ดิบ ทุกขั้นของ voxel เป็นขอบคม) และลดจำนวนหน้าได้ตามต้องการ (ปิดเป็นค่าเริ่มต้น เพื่อให้เทียบเท่ากับการส่งออก STL ของ legacy) STL และ VTK เขียนเป็นไบนารี OBJ เป็นข้อความ ไม่มีการพลิก RAS หรือ LPS อย่างชัดแจ้ง ต่างจากการส่งออก VTK ของ legacy

ในโค้ดตัวเขียนเมช ตัวกรองการทำให้เรียบและการลดจำนวนหน้า

3.8 รายงานและการล้าง

BatchDentalSeg_report.json มีโมเดลและตารางป้ายกำกับครบถ้วน การตั้งค่าที่ใช้ และหนึ่งรายการต่อ case พร้อมสถานะและไฟล์ที่สร้าง case id เป็นแบบตามตำแหน่งและอินพุตเป็นพาธสัมพัทธ์ รายงานจึงไม่ระบุพาธสัมบูรณ์ โฟลเดอร์ทำงานถูกลบก่อน แล้วจึงเขียนรายงาน ถ้าการเรียกอนุมาน raise โฟลเดอร์ถูกลบและทั้งแบตช์ล้มเหลว โดยไม่มีรายงานถูกเขียน

ในโค้ดโครงสร้างของรายงาน

4. สิ่งที่เลือกได้

การตั้งค่าทำอะไรแสดงในแผง
สแกนไฟล์ หรือโฟลเดอร์ที่เดินแบบเรียกซ้ำใช่
โมเดลหนึ่งในสี่โมเดลที่โฮสต์ไว้ใช่ เป็นเมนู
รูปแบบการส่งออกNIfTI, STL, OBJ, VTK, VTK (merged) อย่างน้อยหนึ่งรายการใช่ เป็นชิป
Separate segmentsหนึ่งไฟล์ไบนารีต่อป้ายกำกับ (ต้องมี NIfTI)ใช่
Prediction IDแท็กในชื่อผลลัพธ์ (Seg เป็นค่าเริ่มต้น)ใช่
อุปกรณ์ การสุ่มตัวอย่างใหม่บน GPU ขนาดก้าว การลดจำนวนหน้าของพื้นผิวการตั้งค่าทางเทคนิค (การ์ดจอ เปิดการสุ่มตัวอย่างใหม่บน GPU ก้าว patch 0.5 ไม่ลดจำนวนหน้าของเมช)ไม่ ซ่อน

ไม่มีการประกาศขีดจำกัดเวลา จึงใช้ค่าเริ่มต้นของเซิร์ฟเวอร์ (ไม่มี) โดยมีเพดานอัปโหลด 500 MB และแบตช์ cohort ไม่เกิน 400 MB หรือ 25 ไฟล์

ในโค้ดทุกอาร์กิวเมนต์ ตัวที่ซ่อน อินพุต เอาต์พุต และขีดจำกัด

5. อะไรคือค่าที่ทำนายและอะไรคือค่าที่คำนวณ

บล็อกลักษณะ
การค้นหา การแปลงเป็น NIfTIคำนวณ
การจัดลำดับใหม่ ครอปเหลือส่วนที่ไม่เป็นศูนย์ การทำให้เป็นบรรทัดฐานแบบ CT การสุ่มตัวอย่างใหม่ (ตามลำดับนี้)คำนวณ กำหนดได้แน่นอน ขับเคลื่อนด้วยแผนของbundle
เซกเมนเทชันของทุกโครงสร้างทำนาย เครือข่าย nnU-Net หลายป้ายกำกับ 3 มิติหนึ่งตัว, fold 0
Sliding window การถ่วงน้ำหนักคำนวณ
การสุ่มตัวอย่างผลลัพธ์ใหม่และ argmaxคำนวณ ต่อคลาสด้วยค่าสูงสุดสะสม (GPU) หรือของ nnU-Net เอง
กลับสู่กริดของสแกน ไฟล์ต่อป้ายกำกับคำนวณ
พื้นผิวคำนวณ marching cubes การทำให้เรียบ การลดจำนวนหน้าที่เป็นทางเลือก
การทำความสะอาดเชิง morphologyไม่มี ทั้งใน VISOR และใน legacy
ในโค้ดตารางเดียวกันพร้อมไฟล์และบรรทัด

6. สภาพแวดล้อม

เครื่องมือรันในเวอร์ชวลเอนไวรอนเมนต์ของตัวเอง สร้างจากไฟล์ล็อก ไม่มีอะไรติดตั้งใน Slicer เวอร์ชันตามอิมเมจของเซิร์ฟเวอร์: Python 3.11, torch 2.8.0, nnU-Net 2.8.1, SimpleITK, NumPy และ VTK โมเดลถูกจัดวางโดยสคริปต์ติดตั้งของเซิร์ฟเวอร์ หนึ่งโฟลเดอร์ต่อbundle และเครื่องมือไม่เคยดาวน์โหลดอะไรระหว่างการรัน มีเพียงสองไฟล์ของ manifest ที่มี checksum ตารางอยู่ในหน้าโค้ด

ในโค้ดเวอร์ชันที่ตรึงไว้ โมเดล และทรัพยากร

7. สิ่งที่เปลี่ยนไปจากตรรกะ legacy

หัวข้อLegacyVISOR
รันที่ไหนภายใน Slicer ทีละสแกนบนเซิร์ฟเวอร์ หนึ่งการเรียกสำหรับทั้งแบตช์
เอนจินอนุมานบรรทัดคำสั่ง nnU-Net ผ่าน extensionอินเทอร์เฟซ Python ของ nnU-Net พร้อมพาธโมเดลที่ระบุชัดเจน
อินพุตสี่นามสกุล ระดับบนสุดเท่านั้น ไม่มี NRRDเพิ่ม NRRD; แบบเรียกซ้ำ
ชื่อชนกันสแกนสองตัวที่ชื่อเดียวกันเขียนทับผลลัพธ์เดียวทรีผลลัพธ์สะท้อนทรีอินพุต
ชื่อผลลัพธ์<stem>_Segmentation.nii.gz ตายตัว<base>_<ID> พร้อมนามสกุลแบบบีบอัด
การข้ามสแกนที่เสร็จแล้วช่องทำเครื่องหมาย ตามผลลัพธ์ที่มีอยู่เมินเฉพาะชื่อที่ดูเหมือนผลลัพธ์
น้ำหนักโมเดลดาวน์โหลดตอน Apply ครั้งแรกเซิร์ฟเวอร์จัดวางให้ ไม่ดาวน์โหลดระหว่างการรัน
การครอป ตัวป้องกันหน่วยความจำ การแก้ไขกระจกเงามีไม่มี โดยตั้งใจ
การ resampleค่าเริ่มต้นของ nnU-Netบน GPU เป็นค่าเริ่มต้น อินพุตแบบ linear เอาต์พุตต่อคลาส
การแมปป้ายกำกับใหม่ตารางค้นหาบนเซกเมนต์ที่ส่งออกไม่มี: จำนวนเต็มของเครือข่ายถูกเขียนตามที่เป็น
VTK ต่อป้ายกำกับการทำให้เรียบ 60 รอบ ลดจำนวนหน้า 40 % พลิกเป็น LPS30 รอบ ไม่ลดจำนวนหน้าเป็นค่าเริ่มต้น ไม่มีการพลิกอย่างชัดแจ้ง
glTFมีไม่มี
การส่งออกเมชที่ล้มเหลวคำเตือน NIfTI ถูกเขียนไปแล้วสแกนถูกทำเครื่องหมาย failed ในรายงาน
อุปกรณ์cuda, cpu, mpscuda หรือ cpu พร้อมการถอยกลับ
สถานะคิวบันทึกในไฟล์ไม่มี ข้อผิดพลาดเป็นต่อสแกนในรายงาน

8. ข้อค้นพบใน VISOR

แต่ละประเด็นถูกตรวจสอบในโค้ดและอธิบายพร้อมหลักฐานในหน้าโค้ด รายการนี้ยังปรากฏในข้อค้นพบด้วย

  • VFACE ขอพื้นผิวแต่ได้ label volume: การเรียกของมันทิ้งรูปแบบการส่งออกไว้ที่ NIfTI จึงไม่พบเมช และวาดheat map ไม่ได้ หลักฐาน
  • README ของเครื่องมือล้าสมัยเรื่องการส่งออกเมชและหน่วยความจำ หลักฐาน
  • สแกนที่ชื่อ ..._Seg มองไม่เห็นในโฟลเดอร์ เมื่อใช้ prediction ID เริ่มต้น หลักฐาน
  • การสุ่มตัวอย่างใหม่บน GPU เปิดเป็นค่าเริ่มต้นและเปลี่ยนตัวเลขเล็กน้อย หลักฐาน
  • ไม่ได้ปิดการปรับแต่งอัตโนมัติของ cuDNN (cuDNN คือไลบรารีของ NVIDIA สำหรับ convolution ของเครือข่าย การปรับแต่งอัตโนมัติให้มันเลือกอัลกอริทึมต่างกันในแต่ละรอบ) การรันสองครั้งของสแกนเดียวจึงอาจไม่ได้ mask ที่เหมือนกันทุกบิต หลักฐาน
  • รายการส่งออกที่ว่างให้ “ok” โดยไม่มีไฟล์ เมื่อเรียกเครื่องมือโดยตรง หลักฐาน
  • ไฟล์ต่อป้ายกำกับต้องมี NIfTI: ถ้าเลือกเมชอย่างเดียว จะไม่มีอะไรถูกเขียนสำหรับมัน หลักฐาน
  • ตารางป้ายกำกับเดินทางไปกับผลลัพธ์ แต่ Slicer ไม่อ่าน หลักฐาน
  • ความคืบหน้ามีสองปลาย เพราะทั้งโฟลเดอร์ผ่านการเรียกเดียว หลักฐาน
  • ข้อดีที่ตรวจแล้ว: สแกนที่อ่านไม่ได้ไม่หยุดแบตช์ หลักฐาน
ในโค้ดทุกข้อค้นพบพร้อมหลักฐาน

9. เอกสารอ้างอิง

เครือข่ายเหล่านี้อยู่ในตระกูล DentalSegmentator บรรณานุกรมเป็นของเครื่องมือเองและไม่ซ้ำที่นี่: แหล่งอ้างอิงของ BatchDentalSeg และส่วนวรรณกรรมของหน้า legacy manifest ชี้ไปยังที่อยู่รีลีสเดียวกับที่โมดูล legacy ดาวน์โหลด ไฟล์หลังที่อยู่เหล่านั้นเป็นไบต์ต่อไบต์เดียวกับที่การติดตั้ง legacy ดึงมาหรือไม่ บอกจากโค้ดไม่ได้ เพราะทั้งสองฝั่งไม่บันทึก hash ของ checkpoint ใดเลย

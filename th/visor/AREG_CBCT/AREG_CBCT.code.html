AREG_CBCT บน VISOR: โค้ด

สำหรับนักพัฒนา: พอร์ต VISOR ของ AREG_CBCT ทำอะไรในโค้ด พร้อมการอ้างอิง file:line ซิกเนเจอร์ อาร์กิวเมนต์ สภาพแวดล้อม ความต่างจากโค้ด legacy และข้อค้นพบ คำอธิบายที่อ่านง่ายของไปป์ไลน์เดียวกัน พร้อมคณิตศาสตร์ อยู่ในหน้าแอตลาส โมดูล legacy อยู่ในหน้าของมันเอง

โค้ด แอตลาส (คำอธิบาย) VISOR AREG_CBCT เข้าถึงในชื่อ AREG โหมด CBCT เอนจิน CPU เท่านั้น elastix หน้า Legacy Guide (VISOR) บรรณานุกรม

AREG_CBCT ลงทะเบียน CBCT ติดตามผล (T2) เข้ากับ CBCT ฐาน (T1) ของผู้ป่วยคนเดียวกันด้วยการลงทะเบียน elastix แบบแข็ง จำกัดอยู่ในบริเวณที่คงที่ของ T1 ใน VISOR การคำนวณทั้งหมดรันบนเซิร์ฟเวอร์ Slicer เพียงแสดงฟอร์ม ส่งโฟลเดอร์ และเปิดสิ่งที่ส่งกลับมา หน้านี้อธิบายพอร์ตนั้น อ่านที่ SADT-VISOR 6ba2a78 (สาขา tool/vface), VISOR-serve e9a7e5d และ AutomatedDentalToolsRemote 19b95e8 โมดูล legacy ที่ใช้เปรียบเทียบคือ SlicerAutomatedDentalTools 3c67957 อธิบายในหน้าของมันเอง พาธของ legacy ด้านล่างอยู่ที่ commit นั้น

ตัวย่อที่ใช้ในหน้านี้: cbct/ คือ SADT-VISOR tools/AREG/AREG_CBCT/src/sadt_areg_cbct/, common/ คือ SADT-VISOR tools/AREG/common/src/sadt_areg_common/ และพาธ server/ อยู่ใน VISOR-serve “Observed” ทำเครื่องหมายสิ่งที่ถูกรันจริง (เทสต์ scripts/describe.py โพรบ Python สั้น ๆ) ระหว่างการศึกษาพอร์ต ส่วนที่เหลือทั้งหมดอ่านจากโค้ด

register_patient ทำงานทั้งหมดสำหรับผู้ป่วยหนึ่งรายและบริเวณหนึ่ง (cbct/pipeline.py:38-99):

fixed = sitk.ReadImage(t1_path)

การใส่มาสก์ (cbct/elastix.py:133-183) apply_mask ปฏิเสธมาสก์ที่ขนาดต่างจากสแกน หรือที่ระยะห่างต่างกันเกิน 1e-4 แล้วจึงคัดลอกเรขาคณิตของสแกนไปใส่มาสก์ (การสุ่มตัวอย่างเหมือนกันหมายความว่าความต่างของจุดกำเนิดหรือทิศทางที่เหลือคือการคลาดเคลื่อนของ float) เมื่อกำหนด segmentation_label ฟังก์ชันจะทำเป็นไบนารีตามเลเบลนั้น และปฏิเสธเลเบลที่มาสก์ไม่มี พร้อมระบุเลเบลที่มีอยู่ ถ้าเป็น 0 จะใช้มาสก์ทั้งหมด และถ้ามาสก์มีหลายเลเบลจะส่งบันทึกหมายเหตุกลับมา ซึ่งไปจบอยู่ในรายงาน voxel นอกมาสก์ถูกทำให้เป็นศูนย์ด้วย sitk.Mask โดย elastix ไม่ได้รับ fixed mask แยกต่างหาก นี่คือเหตุผลที่ ErodeMask ไม่มีผลใด ๆ (cbct/elastix.py:109-112)

VISOR: เครื่องมือรุ่นถัดไป

ส่วนที่เหลือของแอตลาสนี้อ่านส่วนขยาย legacy ซึ่งอัลกอริทึมทุกตัวรันอยู่ภายใน Slicer ส่วน VISOR คือรุ่นใหม่ที่ย้ายการคำนวณไปไว้บนเซิร์ฟเวอร์: ไคลเอนต์ Slicer แบบบาง เซิร์ฟเวอร์อนุมานทั่วไปที่ไม่รู้จักเครื่องมือทันตกรรมใดเลย และแค็ตตาล็อกของเครื่องมือ โดยแต่ละตัวอยู่ในโฟลเดอร์ของตัวเองพร้อมสภาพแวดล้อม Python ของตัวเอง หน้านี้เป็นภาพรวม ส่วนหน้าที่รายการไว้ตอนท้ายลงรายละเอียดของกลไก

ภาพตรวจสอบ ณ วันที่ 2026-11-09 สามที่เก็บโค้ด ภาษาอังกฤษเท่านั้น
ภาษาอื่น

เว็บไซต์ฉบับภาษาฝรั่งเศส สเปน อิตาลี เกาหลี โปรตุเกส และไทย อธิบายเฉพาะโค้ด legacy (SlicerAutomatedDentalTools, คอมมิต 3c67957) ไม่มีหน้า VISOR ข้อความใดในหน้าเครื่องมือฉบับแปลที่พูดถึงที่ที่การคำนวณรัน หรือสภาพแวดล้อมที่ต้องใช้ ล้วนเป็นข้อความเกี่ยวกับ legacy ฉบับแปลจะถูกทำใหม่ภายหลัง

1. VISOR คืออะไร

VISOR คือสามที่เก็บโค้ด โดยแต่ละที่ดูแลหนึ่งชั้น ไม่มีที่ใดเป็น fork ของส่วนขยาย legacy: อัลกอริทึมถูกพอร์ตมา ("a repackaging exercise, not a rewrite", SADT-VISOR CONTRIBUTING.md:309-315) ส่วนโครงสร้างรอบ ๆ เป็นของใหม่

Remote, ไคลเอนต์AutomatedDentalToolsRemote, ไคลเอนต์: ส่วนขยาย Slicer ที่มีโฟลเดอร์โมดูล 23 โฟลเดอร์ แต่ละโฟลเดอร์เป็นแผงบาง ๆ ครอบเซิร์ฟเวอร์ แผงถูกสร้างขึ้นตอนรันจากตัวบรรยายเครื่องมือของเซิร์ฟเวอร์ ดังนั้นช่องที่เพิ่มบนเซิร์ฟเวอร์จะปรากฏใน Slicer โดยไม่ต้องออกไคลเอนต์รุ่นใหม่ Slicer ไม่ติดตั้งอะไรและไม่ดาวน์โหลดโมเดลสำหรับโมดูลที่พอร์ตมา
VISOR-serve, เซิร์ฟเวอร์เซิร์ฟเวอร์อนุมาน: FastAPI, Python 3.13, ไม่มี torch มันค้นหาเครื่องมือ เผยแพร่สคีมาของเครื่องมือ จัดคิวและรับรันเข้าทำงาน และเปิดแต่ละรันในอินเทอร์พรีเตอร์ของเครื่องมือนั้นเอง ตั้งใจให้ไม่รู้จักเครื่องมือทันตกรรมใดด้วยชื่อ
SADT-VISOR, เครื่องมือแค็ตตาล็อก: โปรเจกต์ Python แบบแยกอิสระหนึ่งโปรเจกต์ต่อหนึ่งเครื่องมือ รวม 19 ตัว แต่ละตัวมี .venv ของตัวเองและ uv.lock ที่คอมมิตไว้ เครื่องมือคือฟังก์ชันสาธารณะหนึ่งฟังก์ชัน run() สคีมาได้มาจากซิกเนเจอร์ของมัน

โค้ด: ไคลเอนต์ AutomatedDentalToolsRemote CMakeLists.txt:24-48, ServerToolsCoreLib/formgen.py:1-30; เซิร์ฟเวอร์ VISOR-serve server/registry/__init__.py:114; แค็ตตาล็อก SADT-VISOR README.md:3-5, 41-58

2. ทำไมจึงมีอยู่

Legacy ใส่ทุกอย่างไว้ใน Slicer: วิดเจ็ต การดาวน์โหลดโมเดล และสภาพแวดล้อม Python ที่แต่ละโมดูลสร้างเอง ผลที่ตามมาสองข้อปรากฏซ้ำในหน้า legacy ของแอตลาสนี้: แล็ปท็อปที่ไม่มี GPU รัน segmentation ไม่ได้ และเครื่องมือที่ปักหมุดไลบรารีที่เข้ากันไม่ได้ต้องอยู่ใน conda environment แยกกันที่สร้างบนเครื่องของผู้ใช้ README ของ SADT-VISOR เองระบุรายการความขัดแย้งที่ทำซ้ำได้ในเวอร์ชันที่ปักหมุดของ upstream: SurgMovPred ขอ numpy==2.4.0 ขณะที่ AREG, MedX และ CLIC ต้องการ numpy<2.0.0 มี conda environment สองตัวที่ใช้ชื่อ shapeaxi เหมือนกัน (Python 3.9 และ 3.12) และ torch ถูกปักหมุดที่ 2.2.0 ในห้าโมดูลและปล่อยไม่ปักหมุดในโมดูลอื่น (SADT-VISOR README.md:10-28)

VISOR ตอบด้วยสองการเคลื่อนไหว การคำนวณไปอยู่บนเครื่องเดียวที่มี GPU และแต่ละเครื่องมือคงเวอร์ชันของตัวเองไว้ เพราะ "the versions are part of the science" (SADT-VISOR README.md:25-28) ต้นทุนดิสก์ของ environment จำนวนมากแก้ด้วยการสร้างให้ wheel ที่เหมือนกันใช้ inode ร่วมกัน: scripts/audit.py วัดบน checkout ที่อ่าน พบ virtual environment 7 ตัวที่ขนาดปรากฏ 19.6 GB และขนาดไม่ซ้ำกัน 8.3 GB (SADT-VISOR scripts/audit.py:201-204, รันเมื่อ 2026-11-09)

3. Legacy และ VISOR เทียบกันทีละด้าน

เฉพาะสิ่งที่โค้ดของทั้งสองฝั่งแสดง "Legacy" คือ SlicerAutomatedDentalTools ที่ 3c67957; "VISOR" คือสามที่เก็บโค้ดที่คอมมิตตามรายการด้านล่าง

คำถามLegacyVISOR
ที่ที่การคำนวณรัน บนเครื่องของผู้ใช้ ภายใน Slicer: วิดเจ็ต โมดูล CLI และซับโปรเซสของ Python ใน Slicer บนเซิร์ฟเวอร์ SchemaTool.invoke ผ่าน dispatch เสมอ เซิร์ฟเวอร์ไม่เคยนำเข้าเครื่องมือที่แพ็กเกจไว้ (VISOR-serve server/registry/schema_tool.py:812-822)
สภาพแวดล้อม Python สร้างบนเครื่องของผู้ใช้โดย ADTLib/env/conda.py สำหรับโมดูลส่วนใหญ่; GreedyReg ไม่มีและใช้ Python ของ Slicer เอง หนึ่ง .venv และหนึ่ง uv.lock ที่คอมมิตไว้ต่อหนึ่งเครื่องมือ ไม่มี lockfile ของ workspace ร่วม (SADT-VISOR CONTRIBUTING.md:578-583)
อินเทอร์เฟซ วิดเจ็ต Qt ที่เขียนด้วยมือสำหรับแต่ละโมดูล (วิดเจ็ต GreedyReg ยาว 1,704 บรรทัด ราว 700 บรรทัดเป็น UI ของ Qt) สร้างจากสคีมาโดย formgen.py; คลาส Remote ส่วนใหญ่มีไม่มากไปกว่า TOOL_NAME กับ hook ไม่กี่ตัว (AutomatedDentalToolsRemote ServerToolsCoreLib/formgen.py:1-30)
รายการอาร์กิวเมนต์มาจากไหน ไม่มีสคีมาฝั่งเซิร์ฟเวอร์: อาร์กิวเมนต์อยู่ในวิดเจ็ตและ CLI ของแต่ละโมดูลเอง ได้มาจากซิกเนเจอร์ของ run() โดย scripts/describe.py; ตารางที่เขียนด้วยมือแบบเก่า "drifted" (SADT-VISOR scripts/describe.py:8-11) ดูส่วนสคีมา
การเคลื่อนย้ายข้อมูล พาธและไฟล์ในเครื่อง อัปโหลดเป็นส่วน ๆ ต่อได้เมื่อขาดตอน แต่ละส่วนตรวจด้วย SHA-256 จากนั้นดาวน์โหลดผลลัพธ์แบบสตรีมหรือแบบ ranged (VISOR-serve server/main.py:857-912, server/wire/transfer.py) ดูการรันทีละขั้น
เครื่องมือหนึ่งเรียกอีกตัว จาก Slicer: slicer.cli.run(slicer.modules.ali_cbct, …) (GreedyReg, โหมด Distant) จากเครื่องมือ ผ่าน supervisor: sup.run("ALI_CBCT", …) เริ่มซับโปรเซสของโปรเซสแม่ โดยไม่มีคำขอ HTTP ใหม่และไม่มีการรับเข้าใหม่ (VISOR-serve server/execution/runner.py:1808) ดูsupervisor
ทบทวนหลังการตรวจคุณภาพ โมดูล Slicer หยุดชั่วคราว รวบรวมการแก้ไข และย้อนกลับเอง (ตัวอย่างเช่น AREG_CBCT, Review.py) เซิร์ฟเวอร์หยุดหลังการเรียกที่ประกาศไว้ (stop_after) เก็บงานไว้ และรับ POST /runs/{id}/resume หรือ /rewind พร้อมการแก้ไข (VISOR-serve server/main.py:1685, 1750)
เวลาจำกัดของการรัน timeout ต่อการเรียกภายในโมดูล (GreedyReg: 600 s ต่อการเรียกซับโปรเซส) ไม่มีโดยค่าเริ่มต้น: TOOL_TIMEOUT_SECONDS = 0 และไม่มี timeout_seconds ใน deployment.toml (VISOR-serve server/config.py:77)
ไม่อยู่ในรายการนี้โดยเจตนา

ความเร็ว ความแม่นยำ และความเท่าเทียมของผลลัพธ์ไม่ได้นำมาเปรียบเทียบที่นี่ benchmark ของเซิร์ฟเวอร์ (VISOR-serve benchmarks/) วัดก่อนที่เอนจินการรับเข้าจะถูกเขียนใหม่เมื่อ 2026-09-21 และเซสชัน parity เพียงครั้งเดียวที่มีบันทึกพบผลลัพธ์ที่ตรงกันทุกไบต์เพียงหนึ่งเครื่องมือจากหก ไม่มีส่วนใดของเว็บไซต์นี้อ้างว่า VISOR ให้ผลซ้ำกับ legacy ทุกบิต

4. สถานะของแต่ละเครื่องมือ

"Served" หมายความว่าโฟลเดอร์อยู่ในแค็ตตาล็อก SADT-VISOR และ VISOR-serve ค้นพบและโหลดมัน อินสแตนซ์ที่กำลังรันรายการชื่อเดียวกัน 23 ชื่อเมื่อ 2026-10-20 ไม่ได้หมายความว่าเป็นการติดตั้งใช้งานจริง ซึ่งไม่มีอะไรที่นี่ยืนยันได้ "Slicer module" คือโฟลเดอร์ของ AutomatedDentalToolsRemote ที่เรียกเครื่องมือ แต่ละเครื่องมือมีสองหน้าในแอตลาสนี้: หน้า VISOR บอกว่าอะไรรันบนเซิร์ฟเวอร์และอะไรเปลี่ยนไป หน้า legacy อธิบายโมดูล Slicer ดั้งเดิม

AutoCrop3D บน VISOR: โค้ด

สำหรับนักพัฒนา: สิ่งที่การพอร์ต AutoCrop3D สู่ VISOR ทำในโค้ด พร้อมการอ้างอิง file:line ลายเซ็น อาร์กิวเมนต์ สภาพแวดล้อม ความต่างจากโมดูล legacy และข้อค้นพบ คำอธิบายที่อ่านง่ายของไปป์ไลน์เดียวกัน พร้อมคณิตศาสตร์ อยู่ในหน้าแอตลาส

VISOR โค้ด แอตลาส (คำอธิบาย) หน้า legacy Guide (VISOR)

ใน VISOR AutoCrop3D เป็นแพ็กเกจ Python ที่รันบนเซิร์ฟเวอร์: ฝั่ง Slicer แค่วาดหรือเลือกกล่อง ส่งไฟล์ และโหลดสิ่งที่ส่งกลับมา การครอปเองคือเลขคณิตของ legacy ที่คงไว้โดยตั้งใจ สิ่งที่เปลี่ยนคือทุกอย่างรอบ ๆ มัน วิธีจับคู่สแกนกับ ROI สิ่งที่ถูกตรวจ สิ่งที่ถูกรายงาน หน้านี้ตามการพอร์ตจากคำขอไปถึงไฟล์ที่ส่งกลับ: ตำแหน่ง ไฟล์ แต่ละขั้นของการครอปและของพื้นผิวพร้อมโค้ดที่ทำ อาร์กิวเมนต์ที่เผยแพร่ สภาพแวดล้อม ความต่างกับโมดูล legacy และข้อค้นพบ มันอธิบายการพอร์ตใน SADT-VISOR (branch tool/vface, 6ba2a78, 2026-09-30) ที่ให้บริการโดย VISOR-serve (e9a7e5d) และควบคุมจาก Slicer ด้วยส่วนขยาย AutomatedDentalToolsRemote (19b95e8) การพอร์ตทำจาก commit upstream b1ae78c (2026-05-26, SADT-VISOR AutoCrop3D/README.md:15-16) ซึ่งเก่ากว่าสถานะ 3c67957 ที่อธิบายในหน้า legacy ไม่มีข้อกล่าวอ้างเกี่ยวกับเซิร์ฟเวอร์ที่ deploy แล้วที่นี่: ทุกอย่างด้านล่างอ่านจากโค้ด และชุดเทสต์ของเครื่องมือถูกรันบนแพ็กเกจ

เมื่อใช้ค่าเริ่มต้น surfaces = "segmentations" จะสร้างพื้นผิวก็ต่อเมื่อชื่อไฟล์มีโทเค็นครบคำหนึ่งใน seg, segmentation, mask, pred, label, labels (SADT-VISOR AutoCrop3D/pipeline.py:124-134) ตรวจเมื่อ 2026-11-09 ด้วย is_segmentation_name ของแพ็กเกจเอง: P1_Seg.nii.gz เข้าเงื่อนไข ส่วน Mandible.nii.gz ไม่เข้าและไม่ได้พื้นผิว เว้นแต่ตั้ง surfaces = "all" เงื่อนไขของ legacy เป็นการหาสตริงย่อย seg ที่ใดก็ได้ในพาธผลลัพธ์ (AutoCrop3D_CLI.py:143@3c67957)

ไม่แบ่งกลุ่มผู้ป่วย (cohort)

scans และ roi เป็นอาร์กิวเมนต์ path ที่จำเป็นทั้งคู่ เซิร์ฟเวอร์จึงไม่มีแกนสำหรับแบตช์ (VISOR-serve server/registry/conventions.py:158-190 คอมเมนต์ระบุชื่อ AutoCrop3D) และทั้งโฟลเดอร์ถูกส่งในคำขอเดียว ภายใต้ขีดจำกัดการอัปโหลดเริ่มต้น 500 MB (VISOR-serve server/config.py:240) สแกนทดสอบที่โฮสต์ไว้ไฟล์เดียวก็ใหญ่ถึง 98 611 496 ไบต์ (data-manifest.yml:792-794)

เทสต์ฝั่งไคลเอนต์ไม่ได้ลงทะเบียน

AutomatedDentalToolsRemote AutoCrop3DRemote/Testing/Python/test_autocrop3d_client.py มีเทสต์ 15 รายการ แต่ AutoCrop3DRemote/CMakeLists.txt ไม่มี add_test หรือ add_subdirectory และ Testing/ ไม่มี CMakeLists.txt ชุดเทสต์จึงไม่ได้ผูกกับ ctest ส่วน CMakeLists.txt:29 ที่ราก เพิ่มโมดูลนี้เข้าไปจริง AutoMatrixRemote และ GreedyRegRemote ลงทะเบียนของตัวเอง (AutoMatrixRemote/CMakeLists.txt:34, GreedyRegRemote/CMakeLists.txt:34 ที่ละแห่งเป็น add_subdirectory(Testing))

เอกสารที่ล้าสมัยรอบการพอร์ต

AutomatedDentalToolsRemote README.md:508-546 ยังอธิบายโมดูลเก่า: พาธไอคอนใต้ AutoCrop3D/ (โฟลเดอร์จริงคือ AutoCrop3DRemote) รับ .nrrd.gz (เครื่องมือปฏิเสธ, pipeline.py:37) "Seg somewhere in the name" (ตอนนี้เป็นโทเค็นครบคำ) และสร้าง ROI ผ่าน "Volume Rendering" README ของแพ็กเกจเองก็ประกาศว่ามีเทสต์ 102 รายการ (README.md:200) ในขณะที่ชุดเทสต์มี 103 รายการ หน้านี้ยึดตามโค้ด

ROI ที่หมุนยังถูกครอปเป็นกล่องที่ขนานกับแกน

ไม่มีการใช้การหมุน การครอปใช้จุดศูนย์กลางและขนาดของกล่องตามแกนดัชนีของ volume เหมือน CLI ของ legacy และรายงานบอกเรื่องนี้ด้วย roi_orientation_ignored พร้อมคำเตือนในล็อก (SADT-VISOR AutoCrop3D/pipeline.py:203-211) เอนจินตัวที่สองของโมดูล legacy สำหรับกล่องที่เอียง คือ Crop Volume ของ Slicer ไม่มีตัวเทียบเท่าแบบ headless จึงไม่ได้พอร์ต (README.md:159-177) การตัดทิ้งเศษของดัชนีเข้าหาศูนย์ก็คงไว้โดยตั้งใจเช่นกัน (pipeline.py:257-264, 272-273)

แก้ข้อบกพร่องของ legacy สิบสามข้อ แต่ละข้อมีเทสต์

การพอร์ตมีรายการแก้ไขสิบสามข้อ พร้อมชื่อเทสต์ของแต่ละข้อ ใน SADT-VISOR AutoCrop3D/README.md:107-125 ชุดเทสต์รันผ่านทั้งหมด (ผ่าน 103 รายการ, 2026-11-09) ข้อความผู้ป่วยที่จับคู่ไม่ได้ของแผง Slicer ระบุผู้ป่วยได้สูงสุดห้าคน (AutomatedDentalToolsRemote AutoCrop3DRemote/AutoCrop3DRemote.py:129-136)

DOCShapeAXI บน VISOR: โค้ด

สำหรับนักพัฒนา: พอร์ต VISOR ของ DOCShapeAXI ทำอะไรในโค้ด พร้อมการอ้างอิง file:line ซิกเนเจอร์ อาร์กิวเมนต์ สภาพแวดล้อม ความแตกต่างจากโค้ด legacy และข้อค้นพบ คำอธิบายที่อ่านง่ายของไปป์ไลน์เดียวกัน พร้อมคณิตศาสตร์ อยู่ในหน้าแอตลาส

VISOR โค้ด แอตลาส (คำอธิบาย) หน้า Legacy Guide (VISOR)

การอ้างอิงในหน้านี้ระบุที่เก็บ แล้วพาธในที่เก็บนั้น แล้วบรรทัด: SADT-VISOR คือแคตตาล็อกเครื่องมือ (commit 6ba2a78), VISOR-serve คือเซิร์ฟเวอร์ (e9a7e5d), Remote คือไคลเอนต์ Slicer (AutomatedDentalToolsRemote 19b95e8), legacy คือ SlicerAutomatedDentalTools ที่ 3c67957 พาธเปล่า ๆ เช่น catalog.py:50 อยู่ใน SADT-VISOR tools/DOCShapeAXI/src/sadt_docshapeaxi/ ทุกอย่างอ่านจากโค้ด ไม่มีสิ่งใดในหน้านี้ถูกรัน ยกเว้นสองการตรวจที่ระบุไว้ตรงที่ปรากฏ (การเปรียบเทียบไฟล์ shapeaxi 1.0.10 กับ 1.1.1 และเทสต์ CPU เล็ก ๆ ของดัชนีซ้ำ) ภาพรวมของสแตก: VISOR

1. ตำแหน่งในสายโซ่

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

  • สถานะ: พอร์ตแล้ว มีในโค้ด พร้อมเทสต์ในเครื่องมือ (SADT-VISOR tools/DOCShapeAXI/tests/test_run.py ฟังก์ชันเทสต์ 91 ฟังก์ชัน ไม่ได้รันสำหรับหน้านี้) เซิร์ฟเวอร์ที่ตั้งค่าด้วยสคริปต์จัดเตรียมของ VISOR-serve เท่านั้นจะรันไม่ได้: backbone EfficientNet ที่มันต้องการไม่ได้ถูกจัดเตรียมโดยสคริปต์ใดเลย (ดูข้อค้นพบใน VISOR)
  • ชื่อ API DOCShapeAXI (SADT-VISOR tools/DOCShapeAXI/pyproject.toml:57-59) โมดูล __init__.py, catalog.py, engine.py, pipeline.py
  • แผงฝั่งไคลเอนต์ DOCShapeAXIRemote แผงบาง ๆ (Remote DOCShapeAXIRemote/DOCShapeAXIRemote.py:63,67,69 ถูก build, CMakeLists.txt:34) โหลดผลลัพธ์ .vtk และ .vtp เป็นโมเดล สูงสุด 12 ชิ้น (:82,88-92)
  • เรียก / ถูกเรียกโดย: ไม่มี ไม่มีอาร์กิวเมนต์ sup (__init__.py:18-25) และไม่มีเครื่องมืออื่นระบุชื่อ DOCShapeAXI
  • ข้อมูลที่โฮสต์: checkpoint ทั้งห้าอยู่ใน data manifest (VISOR-serve scripts/data-manifest.yml:597-614) ไม่มีชุดทดสอบ โดยตั้งใจ: ไม่มีข้อมูลสาธารณะใดเป็นทางเดินหายใจ condyle หรือปากแหว่ง (:616-622) ส่วนหัวของ manifest ยังเขียนว่า "NOT PORTED YET" (:595) ซึ่งผิด: เครื่องมือและไคลเอนต์ของมันมีอยู่

3.1 ชื่อ checkpoint หนึ่งชื่อกำหนดการวิเคราะห์

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

Legacy ให้ผู้เรียกส่ง data_type, task, model, nn และ num_classes เป็นอาร์กิวเมนต์ตามตำแหน่งแยกกัน (legacy DOCShapeAXI_CLI/DOCShapeAXI_CLI.py:299-307) ดังนั้น checkpoint สองคลาสจึงอาจถูกรันด้วยสเกลสี่คลาสได้ VISOR รับอาร์กิวเมนต์เดียวคือ model และค้นหาชื่อฐานของมันในตาราง (catalog.py:50-71, __init__.py:54) ชื่อที่ไม่รู้จักเป็น ValueError ที่ระบุทั้งห้าชื่อที่รู้จัก (catalog.py:74-88) การค้นหาเกิดก่อนการตรวจว่าไฟล์มีอยู่หรือไม่ (__init__.py:54-57)

3.2 พื้นผิว อุปกรณ์ และเครือข่าย

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

  • การค้นพบไฟล์: .vtk ไฟล์เดียว หรือโฟลเดอร์ที่เดินเรียกซ้ำ ข้ามไฟล์ซ่อน เรียงลำดับ (pipeline.py:22,40-64) ถ้าไม่พบอะไรเป็น ValueError "DOCShapeAXI reads surfaces, not volumes" (__init__.py:59-64) จุดเมานต์ที่ให้ shapeaxi คือโฟลเดอร์อินพุต หรือโฟลเดอร์ของไฟล์สำหรับไฟล์เดียว (:71)
  • อุปกรณ์: cuda ถอยไปใช้ cpu พร้อมคำเตือนเมื่อมองไม่เห็นการ์ด (pipeline.py:67-72)
  • เครือข่าย: load_network ตรวจว่าคลาสที่แคตตาล็อกระบุมีอยู่ใน shapeaxi.saxi_nets_lightning จากนั้นตรวจว่า backbone EfficientNet ถูกจัดเตรียมแล้ว แล้วทำ allowlist คลาสที่ checkpoint ทำ pickle ไว้ และโหลดมัน (pipeline.py:130-151):
network_class = getattr(saxi_nets_lightning, network_name, None)   # else ValueError
check_backbone_is_staged()      # <torch hub dir>/checkpoints/efficientnet-b0-355c32eb.pth, else FileNotFoundError
allow_checkpoint_globals()      # shapeaxi transform classes + torchvision Compose
model = network_class.load_from_checkpoint(checkpoint, strict=False)
model.eval(); model.to(device)

allowlist มีอยู่เพราะ torch 2.6 ทำให้ weights_only=True เป็นค่าเริ่มต้น และ checkpoint เหล่านี้พก transform ตอนฝึกไว้ใน hyper_parameters (pipeline.py:108-127) strict=False คงไว้จาก legacy (legacy DOCShapeAXI_CLI.py:135,201)

3.3 รอบการทำนาย

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

รายการไฟล์เป็น pandas DataFrame ที่สร้างในหน่วยความจำ (legacy เขียน CSV ลงโฟลเดอร์เอาต์พุตด้วยโหมด 'a', DOCShapeAXI_CLI.py:111-118) ป้อนให้ SaxiDataset ของ shapeaxi ด้วย EvalTransform(scale_factor) โดย scale factor อ่านจาก hyperparameters ของ checkpoint (engine.py:11-34) จากนั้น shapeaxi 1.1.1 ก็ไม่สนใจมัน (ดูการตรวจด้านล่าง) แล้ว ทีละพื้นผิว (engine.py:37-64):

mesh = model.create_mesh(vertices, faces, normals)
points = model.sample_points_from_meshes(mesh, model.hparams.sample_levels[0])
views, _ = model.render(mesh)
output = model(points, views)
if not analysis.is_regression:
    output = torch.argmax(softmax(output).detach(), dim=1, keepdim=True)
predictions.append(float(output.reshape(-1)[0].cpu()))

การทำนายแต่ละครั้งถูกบันทึกพร้อมพาธของพื้นผิวเทียบกับจุดเมานต์ และ class (จำนวนเต็ม) หรือ score (ทศนิยม สำหรับ regression) (__init__.py:81-90) การสุ่มจุดและการเรนเดอร์เป็นของ shapeaxi ทั้งเครื่องมือและ legacy ไม่ได้กำหนด random seed (ไม่มี seed หรือ manual_seed ในซอร์สของเครื่องมือ)

3.4 รอบการอธิบาย (Grad-CAM)

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

เฉพาะเมื่อ explain เป็น true (__init__.py:92-95) dataset ถูกสร้างใหม่และแต่ละพื้นผิวถูกเรนเดอร์อีกครั้ง จากนั้นสำหรับแต่ละคลาส k ใน range(analysis.classes) (engine.py:67-114):

cam = LayerGradCam(model, model.convnet.module._blocks[-1], device_ids=[0])
attribution = cam.attribute(inputs=(points, views), target=k, attr_dim_summation=False)
attribution = attribution.sum(dim=1).cpu().detach()
scaled = scale_attribution(attribution.numpy(), (224, 224))   # resize, clip 1/99 percentiles, rescale to [-1, 1]
projected = gradcam_process(_Namespace(device, target_class=k), scaled, faces, per_face, vertices)
surface.GetPointData().AddArray(projected)                    # array grad_cam_target_class_<k>
post_process.MedianFilter(surface, projected)
  • Resize: torch.nn.functional.interpolate, bilinear, align_corners=False แทน cv2.resize ของ legacy คอมเมนต์บอกว่ามีเทสต์ตรึงทั้งสองให้ตรงกันที่ 1e-5 (pipeline.py:163-184, pyproject.toml:45-51)
  • Normalisation: clip ที่ เปอร์เซ็นไทล์ที่ 1 และ 99 แล้วแมปไปเป็น [-1, 1] แผนที่แบนราบกลายเป็นศูนย์แทน NaN (pipeline.py:186-199)
  • เลเยอร์ไหน: บล็อกสุดท้ายของสาขา EfficientNet 2D เหมือนใน legacy (DOCShapeAXI_CLI.py:150-151) แผนที่อธิบายสาขามุมมองหลายมุม ไม่ใช่สาขาพอยต์คลาวด์
  • การฉายภาพ: gradcam_process เป็นของ shapeaxi (saxi_gradcam.py:112-144 ใน 1.0.10 และ 1.1.1 โค้ดเดียวกัน) หน้า (face) เริ่มที่ 0 และรับ maximum(old, new) มุมมองแล้วมุมมองเล่า ดังนั้นบนเมช หน้าหนึ่งเก็บ max(0, max over views) และช่วงคือ [0, 1] ค่าไปที่ vertex แรกของหน้า และ vertex ที่ไม่ใช่ vertex แรกของหน้าใดถูกรีเซ็ตเป็น 0 (:134) ภายในหนึ่งมุมมอง พิกเซลที่แสดงหน้าเดียวกันใช้ดัชนีร่วมกัน และการเขียนที่คงอยู่ไม่ถูกกำหนด (ครั้งสุดท้ายบน CPU ไม่ใช่ค่าสูงสุด) พิกเซลพื้นหลังมีดัชนี -1 และเขียนลงบนหน้าสุดท้าย เทสต์ CPU และรายละเอียดอยู่ในหน้าโค้ด legacy ส่วน 5d ไม่มีอะไรถูกรันบน GPU
  • Median filter: post_process.MedianFilter (post_process.py:294-308) แทนที่ทุก vertex ทั้งที่มีค่าและที่ว่าง ด้วยค่ามัธยฐานของเพื่อนบ้านโดยไม่รวมตัวมันเอง (utils.py:363-376) ไม่ใช่เฉพาะที่ว่าง
  • ชื่ออาร์เรย์: ดัชนีคลาสถูกส่งเป็น target_class เสมอ ซึ่งตั้งชื่ออาร์เรย์ (engine.py:104-106,117-129) Legacy ตั้งเฉพาะเมื่อ num_classes > 1 (DOCShapeAXI_CLI.py:171-174) ดังนั้น checkpoint แบบ regression ตอนนี้ก็ได้ชื่อต่อคลาสด้วย คือ grad_cam_target_class_0 อ่านจากโค้ด

ตรวจสอบแล้ว: ความไม่ตรงกันของ shapeaxi ใน legacy ถูกแก้ที่นี่

โค้ด legacy เขียนสำหรับ API ของ shapeaxi 1.x ขณะที่ตัวติดตั้งขอ 2.0.2 ขึ้นไป (legacy ADT/ADTLib/env/install_pytorch.py:385) VISOR ปัก shapeaxi==1.1.1 พร้อมเหตุผลในคอมเมนต์ (pyproject.toml:18-30) และหาคลาสเครือข่ายจาก saxi_nets_lightning ที่มันอยู่ (pipeline.py:135-145) checkpoint ไม่ถูกคัดลอกลงโฟลเดอร์เอาต์พุตอีกต่อไป EvalTransform ของ shapeaxi 1.1.1 ก็ไม่ใช้ scale_factor เช่นกัน: UnitSurfTransform.__call__ ไม่เคยส่งต่อมัน (saxi_transforms.py:48-57) เหมือนกันใน 1.0.10 และ 1.1.1 (สองแพ็กเกจต่างกันเฉพาะ __about__.py เปรียบเทียบทีละไฟล์สำหรับรอบนี้ ดาวน์โหลด 1.1.1 จาก package index)

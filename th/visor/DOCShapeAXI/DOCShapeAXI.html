DOCShapeAXI บน VISOR

DOCShapeAXI มองพื้นผิว 3D เช่นทางเดินหายใจหรือข้อต่อขากรรไกร และตอบคำถามทางคลินิกเกี่ยวกับรูปร่างของมัน: อยู่ในคลาสความรุนแรงใด หรือถูกกีดขวางมากเพียงไร จากนั้นแสดงตำแหน่งบนพื้นผิวที่เครือข่ายมอง หน้านี้อธิบายวิธีการทีละขั้นพร้อมคณิตศาสตร์ ตรงที่โค้ดทำสิ่งที่ควรตรวจ จะมีลิงก์ไปยังหน้าโค้ด โมดูล legacy อยู่ในหน้าของมันเอง

VISOR โค้ด (นักพัฒนา) 5 checkpoint 2 คลาสของเครือข่าย หน้า Legacy Guide (VISOR)

ภาพรวม: อะไรเข้า อะไรออก

DOCShapeAXI
อินพุตพื้นผิว 3D หนึ่งหรือหลายชิ้น (.vtk) ที่ถูก segment จากที่อื่นมาแล้ว เช่น ทางเดินหายใจหรือ condyle และชื่อไฟล์เครือข่ายที่ฝึกแล้ว (checkpoint)
แนวคิดเครือข่ายมองแต่ละพื้นผิวสองแบบพร้อมกัน คือเป็นกลุ่มจุดและเป็นภาพจำนวนมากที่ถ่ายจากรอบ ๆ มุมมองทั้งสองของรูปร่างถูกรวมเป็นคลาสหรือคะแนน จากนั้นรอบที่สองแสดงว่าส่วนใดของพื้นผิวมีน้ำหนักมากที่สุด
เอาต์พุตสำหรับแต่ละพื้นผิว มีคลาส (หรือตัวเลขสำหรับ checkpoint แบบ regression) ในรายงาน JSON และมีสำเนาของพื้นผิวพร้อมแผนที่ "ตำแหน่งที่มอง" หนึ่งแผนที่ต่อคลาสเป็นทางเลือก

เครือข่ายและวิธี Grad-CAM เป็นของ legacy: ไม่มีอะไรถูกฝึกใน VISOR สิ่งที่เปลี่ยนคือทุกอย่างรอบ ๆ มัน: ชื่อ checkpoint บอกเครื่องมือแล้วว่าจะรันการวิเคราะห์แบบใด ไม่มี CSV อีกต่อไป และรอบการอธิบายปิดได้ (อะไรเปลี่ยนไป)

1. รันที่ไหน

ใน VISOR Slicer เหลือเพียงแผงเดียว มันส่งพื้นผิวและชื่อ checkpoint ไปยังเซิร์ฟเวอร์ ซึ่งทำงานทั้งหมดและส่งอาร์ไคฟ์กลับมาหนึ่งไฟล์ DOCShapeAXI ไม่เรียกเครื่องมืออื่น และไม่มีเครื่องมืออื่นเรียกมัน เครื่องมือถูกพัฒนาและทดสอบแล้ว แต่เซิร์ฟเวอร์ที่เตรียมด้วยสคริปต์จัดเตรียมมาตรฐานเท่านั้นยังรันมันไม่ได้: image backbone หนึ่งตัวที่เครือข่ายต้องใช้ไม่ได้ถูกวางไว้โดยสคริปต์ใดเลย (ปัญหาที่ทราบ)

ในโค้ดแผง ชื่อ API ข้อมูลที่โฮสต์ และตำแหน่งในสายโซ่ พร้อมไฟล์และบรรทัด

1.1 อะไรรันที่ไหน

ขั้นตอนเซิร์ฟเวอร์ไคลเอนต์ (Slicer)
เลือกพื้นผิว checkpoint โฟลเดอร์เอาต์พุตเผยแพร่ฟอร์มแผงที่สร้างขึ้นอัตโนมัติ พื้นผิวถูกอัปโหลด
เครือข่าย การทำนาย Grad-CAM การเขียนพื้นผิวทุกอย่างไม่มี
ผลลัพธ์พื้นผิวที่มีแผนที่ Grad-CAM และรายงาน JSON เป็นหนึ่งอาร์ไคฟ์แตกไฟล์ออก และโหลดพื้นผิวได้สูงสุด 12 ชิ้นเป็นโมเดล (ตัวเลือก)
บรรทัดสถานะ–หนึ่งประโยคที่สร้างจากรายงาน (ตอนนี้แสดงเครื่องหมายคำถาม)

กลไกการรัน: กายวิภาคของการรัน สิ่งที่ปกป้องการอัปโหลด: ความปลอดภัยและความเป็นส่วนตัว

2. ไฟล์ที่เกี่ยวข้อง

เครื่องมือคือโมดูล Python สั้น ๆ สี่โมดูล (แคตตาล็อกของ checkpoint เครือข่ายและสองรอบ ตัวช่วยค้นหาและโหลด และจุดเข้าที่ผูกทั้งหมดเข้าด้วยกัน) สภาพแวดล้อมที่ปักเวอร์ชัน และเทสต์ Legacy มีแผง 830 บรรทัดบวกคำสั่ง 310 บรรทัด มีเพียงส่วนการคำนวณที่ถูกพอร์ต ตารางเต็มพร้อมจำนวนบรรทัดและไฟล์ฝั่งเซิร์ฟเวอร์และไคลเอนต์อยู่ในหน้าโค้ด

ในโค้ดทุกไฟล์พร้อมจำนวนบรรทัด และสิ่งที่เกี่ยวกับ DOCShapeAXI บนเซิร์ฟเวอร์และไคลเอนต์

3. ไปป์ไลน์

3.1 ชื่อ checkpoint หนึ่งชื่อกำหนดการวิเคราะห์

Legacy ขอการตั้งค่าห้าอย่างจากผู้เรียก ซึ่งล้วนตามมาจาก checkpoint หนึ่งตัว (รวมแปดอาร์กิวเมนต์พร้อมโฟลเดอร์และพาธล็อก) ดังนั้น checkpoint สองคลาสจึงอาจถูกรันด้วยสเกลสี่คลาสได้ VISOR รับสิ่งเดียวคือชื่อ checkpoint และค้นหาในตารางคงที่ห้ารายการ ชื่อที่ไม่รู้จักถูกปฏิเสธพร้อมรายการชื่อที่รู้จัก

ชื่อไฟล์กายวิภาคงานคลาส
airways_2_class.ckptการอุดตันทางเดินหายใจส่วนนาโซฟาริงซ์binary2
airways_4_class.ckptการอุดตันทางเดินหายใจส่วนนาโซฟาริงซ์severity4
airways_4_regress.ckptการอุดตันทางเดินหายใจส่วนนาโซฟาริงซ์regression (คะแนน)1
condyles_4_class.ckptcondyleขากรรไกรล่างseverity4
cleft_4_class.ckptรอยบกพร่องของกระดูกเบ้าฟันใน cleftseverity4
ในโค้ดตารางในโค้ด คลาสเครือข่ายของแต่ละ checkpoint และลำดับของการตรวจ

3.2 พื้นผิว อุปกรณ์ และเครือข่าย

  • พื้นผิว: ไฟล์เดียว หรือโฟลเดอร์ที่ค้นหาผ่านโฟลเดอร์ย่อยทั้งหมดตามลำดับคงที่ ถ้าไม่พบอะไรเป็นข้อผิดพลาด ("DOCShapeAXI reads surfaces, not volumes")
  • อุปกรณ์: การ์ดจอถ้ามี ไม่เช่นนั้นโปรเซสเซอร์ พร้อมคำเตือน
  • เครือข่าย: เครื่องมือโหลดเครือข่ายที่ตารางระบุ ตรวจว่า image backbone ที่ต้องใช้อยู่บนเซิร์ฟเวอร์แล้ว (มันไม่ยอมดาวน์โหลดกลางคำขอ) จากนั้นจึงโหลด checkpoint
ในโค้ดลำดับการโหลด allowlist ของคลาสที่ checkpoint อาจสร้างคืน และ strict=False

3.3 รอบการทำนาย

แต่ละพื้นผิวผ่านเครือข่ายทีละชิ้น รายการไฟล์ถูกสร้างในหน่วยความจำ และ shapeaxi ปรับทุกพื้นผิวให้มีขนาดและตำแหน่งมาตรฐานก่อนมอง เครื่องมือส่ง scale factor ของ checkpoint เองให้ แต่ shapeaxi ที่ปักไว้ (1.1.1) ไม่เคยใช้ค่านั้น: แต่ละพื้นผิวถูกปรับสเกลด้วยตัวมันเอง จากนั้นเครือข่ายรับอินพุตสองอย่างที่สร้างจากพื้นผิวเดียวกัน และแต่ละอย่างถูกแปลงเป็นเวกเตอร์ 256 ตัวเลขหนึ่งเวกเตอร์

นอกจากภาพแล้ว เครือข่ายสุ่ม4096 จุดบนพื้นผิว สาขาแรกประมวลผลกลุ่มจุดนี้ด้วย attention ที่จำกัดอยู่ที่เพื่อนบ้านใกล้ที่สุดของทุกจุด สาขาที่สองรันเครือข่ายภาพ (EfficientNet-B0) บนแต่ละภาพ แล้วทำ attention ข้ามภาพ

คลาสคือคะแนนสูงสุด คะแนนอื่นไม่ถูกคืน ดังนั้นรายงานจึงไม่มีตัวชี้วัดความเชื่อมั่น การสุ่มจุดเป็นแบบสุ่มและไม่ได้ตั้ง seed ดังนั้นสองการรันบนพื้นผิวเดียวกันอาจต่างกันเล็กน้อย

ในโค้ดการเรียกของลูปการทำนาย วิธีบันทึกคลาสหรือคะแนน และ seed ที่หายไป

3.4 รอบการอธิบาย (Grad-CAM)

เฉพาะเมื่อ explain เปิดอยู่ สิ่งที่ส่วนนี้พูดเกี่ยวกับ shapeaxi อ่านจากเวอร์ชัน 1.0.10 และ 1.1.1 ซึ่งมีโค้ดเดียวกันสำหรับส่วนนี้ พื้นผิวถูกเรนเดอร์อีกครั้ง และสำหรับแต่ละคลาสตามลำดับ เครือข่ายถูกถามว่าส่วนใดของภาพดันคะแนนของคลาสนั้น ทำบนสาขาภาพเท่านั้น: แผนที่ไม่บอกอะไรเกี่ยวกับสาขากลุ่มจุด

ผลลัพธ์ถูกเก็บบนพื้นผิวเป็นอาร์เรย์ตัวเลขที่มีชื่อหนึ่งอาร์เรย์ต่อคลาส checkpoint แบบ regression มีหนึ่งคลาส จึงมีหนึ่งอาร์เรย์ ใน Slicer อาร์เรย์เหล่านี้แสดงเป็นสีบนพื้นผิวได้

ในโค้ดการเรียก Grad-CAM การ resize การ clip เปอร์เซ็นไทล์ ชื่ออาร์เรย์ และที่ที่พื้นผิวถูกเขียน

3.5 เอาต์พุตและรายงาน

พื้นผิวที่เขียนถูกเติมส่วนต่อท้ายที่เลือก (ค่าเริ่มต้น _pred) ต่อท้ายชื่อ ดังนั้น P01.vtk กลายเป็น P01_pred.vtk รายงาน JSONถูกเขียนเสมอ มันระบุ checkpoint กายวิภาค งาน จำนวนคลาส อุปกรณ์ ว่าทำการอธิบายหรือไม่ และสำหรับแต่ละพื้นผิว พาธและคลาสหรือคะแนนของมัน ไม่มี CSV อีกต่อไป

ในโค้ดคีย์ของรายงาน รายงานตัวอย่าง และค่าที่เครื่องมือคืน

4. สิ่งที่เลือกได้

  • พื้นผิว: ไฟล์ .vtk หนึ่งไฟล์ หรือโฟลเดอร์
  • Checkpoint: หนึ่งในห้าไฟล์ที่โฮสต์ ชื่อของมันอย่างเดียวกำหนดกายวิภาค งาน จำนวนคลาส และเครือข่าย
  • Explain: เปิดโดยค่าเริ่มต้น ถ้าปิด จะเขียนเฉพาะรายงาน และการรันเร็วขึ้น (คำอธิบายของเครื่องมือเองบอกว่า "several times" ไม่ได้วัดอะไรเลย)
  • ส่วนต่อท้าย: เติมต่อท้ายชื่อของแต่ละพื้นผิวที่เขียน
  • อุปกรณ์: เซิร์ฟเวอร์เป็นผู้เติม ไม่แสดงในแผง
ในโค้ดหกอาร์กิวเมนต์พร้อมชนิด ค่าเริ่มต้น และสิ่งที่แผงแสดง เอาต์พุต และขีดจำกัดทรัพยากร

5. อะไรทำนาย และอะไรคำนวณ

บล็อกลักษณะ
ชื่อ checkpoint ไปเป็นกายวิภาค งาน คลาส เครือข่ายคำนวณ ตารางคงที่
เมช การสุ่มจุด การเรนเดอร์ภาพเรขาคณิตที่คำนวณ การสุ่มจุดเป็นแบบสุ่มและไม่มี seed
คลาสหรือคะแนนความรุนแรงทำนาย เครือข่ายสองสาขา (กลุ่มจุดบวกภาพ)
เลือกคะแนนสูงสุดคำนวณ
แผนที่ Grad-CAMคำนวณจาก gradient ของเครือข่าย แผนที่อธิบายเครือข่าย ไม่ได้ทำนายสิ่งใหม่
การขยาย การ clip การระบายสีเมช median filterคำนวณ

6. สภาพแวดล้อม

เครื่องมือรันในสภาพแวดล้อม Python ของมันเองบนเซิร์ฟเวอร์ พร้อมเวอร์ชันที่ปักไว้: Python 3.11, shapeaxi 1.1.1 (checkpointทั้งห้าพกการตั้งค่าที่ shapeaxi 2.x ปฏิเสธ), PyTorch3D สำหรับภาพ และ Captum สำหรับ Grad-CAM การมีหนึ่งสภาพแวดล้อมต่อเครื่องมือคือสิ่งที่ทำให้ DOCShapeAXI อยู่บนไลบรารีรุ่นเก่าได้ข้าง Crown_Seg ที่อยู่บนรุ่นใหม่ image backbone (ไฟล์ 20 MB) ต้องวางไว้ในแคช PyTorch ของเซิร์ฟเวอร์ล่วงหน้า Legacy ติดตั้งสภาพแวดล้อม conda ที่ใช้ร่วมกันจากแผงแทน

ในโค้ดเวอร์ชันที่ปักไว้พร้อมเลขบรรทัด น้ำหนักและ backbone ที่คาดหวัง และขีดจำกัด

7. สิ่งที่เปลี่ยนไปจากตรรกะ legacy

สถาปัตยกรรมเครือข่าย อินพุตกลุ่มจุดและหลายมุมมอง เลเยอร์ Grad-CAM และการ clip ที่ เปอร์เซ็นไทล์ ของมัน เหมือนกัน

8. ปัญหาที่ทราบใน VISOR

แต่ละข้อด้านล่างอ่านจากโค้ดและอธิบายพร้อมหลักฐานในหน้าโค้ด รายการนี้ยังปรากฏในข้อค้นพบด้วย

  • ข้อกำหนดเบื้องต้นที่ไม่มีใครจัดเตรียม ไฟล์ image backbone ไม่ได้ถูกวางโดยสคริปต์จัดเตรียมใดเลย เซิร์ฟเวอร์มาตรฐานจึงล้มเหลวในการเรียกครั้งแรก หลักฐาน
  • บรรทัดสถานะแสดงเครื่องหมายคำถาม แผงอ่านสองคีย์ที่รายงานไม่มี หลักฐาน
  • ไคลเอนต์อธิบายสิ่งที่ไม่มีอยู่ คอมเมนต์ของมันเอ่ยถึงตารางการทำนายและตัวเลือก task เครื่องมือไม่มีทั้งสองอย่าง หลักฐาน
  • อินพุตสองไฟล์ที่ชื่อเดียวกันชนกัน มันถูกเขียนไปที่ไฟล์เอาต์พุตเดียวกัน หลักฐาน
  • ยังเป็นจริงจาก legacy การสุ่มจุดโดยไม่มี seed และแผนที่ saliency ของสาขาเดียวเท่านั้น หลักฐาน
  • คอมเมนต์ที่ขัดกับ pin ไม่เป็นอันตราย แต่ทำให้เข้าใจผิด หลักฐาน

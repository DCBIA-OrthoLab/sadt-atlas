ASO บน VISOR: โค้ด

สำหรับนักพัฒนา: พอร์ต VISOR ของ ASO ทำอะไรในโค้ด พร้อมการอ้างอิง file:line ซิกเนเจอร์ อาร์กิวเมนต์ สภาพแวดล้อม ความต่างจากโค้ด legacy และข้อค้นพบ คำอธิบายที่อ่านง่ายของไปป์ไลน์เดียวกัน พร้อมคณิตศาสตร์ อยู่ในหน้าแอตลาส ตัวแสดงผล 3 มิติทั้งสองอยู่ในหน้าแอตลาส

VISOR โค้ด แอตลาส (คำอธิบาย) หน้า Legacy คู่มือ (VISOR)

VISOR รันเครื่องมือทันตกรรมบนเซิร์ฟเวอร์: Slicer เหลือเพียงแผงที่ส่งข้อมูลและโหลดผลลัพธ์ (ดูสถาปัตยกรรม) หน้านี้อธิบายพอร์ต VISOR ของ ASO ที่อ่านจากโค้ดของรีโพซิทอรีที่ระบุด้านล่าง และเทียบกับโมดูล Slicer แบบ legacy ที่ 3c67957 ซึ่งมีหน้าของตัวเอง "Run for this page" (รันสำหรับหน้านี้) ระบุสิ่งที่ถูกรันระหว่างตรวจสอบ ส่วนที่เหลือทั้งหมดอ่านจากโค้ด ตัวย่อ: ASO/ = SADT-VISOR 6ba2a78, tools/ASO/src/sadt_aso/; พาธ tools/… อื่น ๆ ก็อยู่ใน SADT-VISOR เช่นกัน; VISOR-serve = VISOR-serve e9a7e5d, ไฟล์ใต้ server/; Remote = AutomatedDentalToolsRemote 19b95e8; legacy = SlicerAutomatedDentalTools 3c67957 ซึ่ง ASO_CBCT_utils/, SEMI_ASO_CBCT/ และ PRE_ASO_CBCT/ อยู่ใต้ ASO_CBCT/, ASO_IOS_utils/ และ PRE_ASO_IOS/ อยู่ใต้ ASO_IOS/, และ ASO_Method/ อยู่ใต้ ASO/

สรุปในย่อหน้าเดียว: ASO หมุนสแกนให้ไปอยู่ในกรอบของเคสอ้างอิงที่โฮสต์บนเซิร์ฟเวอร์ สำหรับ CBCT มันจัดกึ่งกลางวอลุ่มบนจุดกำเนิดทางกายภาพ ได้ landmark มา (ผู้ใช้ส่งมา พบข้างสแกน หรือ ALI_CBCTทำนายผ่าน supervisor) เลือกสามตัวที่ดีที่สุด สร้างการหมุนหยาบจากไตรเพล็ตนั้น ปรับละเอียดด้วย ICP แบบแข็ง และสุ่มตัวอย่างวอลุ่มใหม่ (หัวข้อ 4) สำหรับเมชในช่องปาก มันทำแบบเดียวกันบนเซนทรอยด์ของฟันหรือบน landmark ที่ส่งมา โดยไม่ต้องแบ่งส่วนเลย (หัวข้อ 5) ใน ASO เองไม่มีเครือข่าย: ขั้นตอนเดียวที่เรียนรู้ได้ในการรัน ASO คือของ ALI_CBCT

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

ข้อควรระวัง · ไฟล์ landmark ที่ตั้งชื่อผิดถูกแทนที่ด้วยการทำนายอย่างเงียบ ๆ

เมื่อมี supervisor (ซึ่งเซิร์ฟเวอร์ให้กับเครื่องมือที่ขอ) ผู้ป่วยที่ไม่มีไฟล์ markups ที่ จับคู่กับสแกนของตนจะถูกส่งไปทำนาย แม้ใน Semi-Automated: _needs_prediction คืน not patients[key]["markups"] (ASO/dispatch.py:651-661) รายการไฟล์ที่ไม่มีคู่ถูกล้างเมื่อมีผู้ป่วยรายใดถูกทำนาย (:684-685) และรายงานบอกว่า landmark_source เป็น ALI_CBCT หรือ mixed รันสำหรับหน้านี้ด้วยตัวช่วยของ tools/ASO/tests/test_run.py: สแกน P1_CBCT.nii.gz กับไฟล์ P1.mrk.json (ชื่อที่จับคู่ไม่ได้) Semi-Automated, supervisor ปลอม: landmark_source = ALI_CBCT, unmatched_markups = [] เคสถูกปรับทิศทางด้วยสถานะ ok หากไม่มี supervisor อินพุตเดียวกันจะล้มเหลวและระบุชื่อไฟล์ (landmark_source = alongside the scans, unmatched_markups = ['P1.mrk.json']) จุดที่วางด้วยมือถูกเมินโดยไม่มีคำเตือน แผงซ่อน automation ผู้ใช้จึงบังคับให้รัน Semi แบบเข้มงวดไม่ได้

ข้อควรระวัง · รายงานไม่บันทึก max_triplets หรือ seed

docstring ของ run() บอกว่ารายงานบันทึกทั้งสองค่า (ASO/__init__.py:119-121) แต่ไม่มีคีย์ชื่อนั้นถูกเขียนที่ใดในซอร์สของเครื่องมือ (รายงานถูกสร้างใน ASO/dispatch.py ที่ :155-161, :616-617, :670, :694, :819, :823, :931) README ของเครื่องมือกล่าวซ้ำคำอ้างนี้ (tools/ASO/README.md:166) อ่านจากโค้ด

ข้อควรระวัง · max_triplets ที่เป็น 0 หรือน้อยกว่าทำให้ CBCT ทั้งชุดเสียไปพร้อมข้อความที่ทำให้เข้าใจผิด

ตัวอย่างว่างเปล่าและ best_triplet ยกข้อผิดพลาด "Need at least three landmarks…" (ASO/geometry.py:353-357, :378-379) มีเพียง RegistrationError ที่ถูกจับต่อผู้ป่วย CBCT (ASO/dispatch.py:797) ValueError จึงทำให้การรันทั้งหมดจบ รันสำหรับหน้านี้: ผู้ป่วยที่ถูกต้องสองราย Semi-Automated, max_triplets=0: orient ยก ValueError นั้น และไม่มีผู้ป่วยรายใดถูกปรับทิศทาง อาร์กิวเมนต์ถูกซ่อน จึงมีเพียงการเรียก API ตรง ๆ ที่เข้าถึงได้ (กฎการซ่อนคือรายการอาร์กิวเมนต์เชิงเทคนิคใน VISOR-serve server/registry/conventions.py:48-54 ซึ่งระบุ seed และ max_triplets ส่วน layout.py ไม่มีรายการสำหรับสองค่านี้)

ข้อควรระวัง · IOS ที่มีจำนวนฟันผิดปกติล้มเหลวช้า

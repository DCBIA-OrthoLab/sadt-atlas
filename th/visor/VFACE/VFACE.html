VFACE บน VISOR

VFACE ตัดสินว่าใบหน้ามีความไม่สมมาตรของโครงกระดูกหรือไม่ จากสแกน CBCT เพียงอย่างเดียว มันจัดทิศทางสแกน สะท้อนมัน register ภาพสะท้อนกลับเข้ากับต้นฉบับทีละบริเวณ วัดว่าlandmarkแต่ละจุดเคลื่อนไปไกลเท่าใดจากภาพสะท้อนของตัวมันเอง และจำแนกผลด้วยโมเดลเล็ก ๆ สามตัว หน้านี้อธิบายวิธีการทีละขั้นพร้อมคณิตศาสตร์ ตรงที่โค้ดทำสิ่งที่ควรตรวจสอบ จะมีลิงก์ไปยังหน้าโค้ด โมดูล legacy อยู่ในหน้าของมันเอง

VISOR โค้ด (สำหรับนักพัฒนา) เฉพาะ branch tool/vface หน้า legacy Guide (VISOR) บรรณานุกรม

ผู้ป่วยถูกเปรียบเทียบกับตัวเอง ในการประเมินความไม่สมมาตรไม่มีสแกนที่สอง: baseline ถูกจัดทิศทาง สะท้อนข้ามระนาบ mid-sagittal แล้ว register กลับเข้ากับตัวเองทีละบริเวณ และสิ่งที่วัดคือ landmark แต่ละจุดเคลื่อนไปไกลเท่าใดจากภาพสะท้อนของตัวมันเอง การศึกษาตามยาวคือห่วงโซ่เดียวกัน โดยใช้สแกนติดตามผลจริงแทนที่ภาพสะท้อน VFACE เองไม่เรียนรู้อะไรและไม่รันเครือข่ายใด: ทุกโมเดลที่ต้องใช้เป็นของเครื่องมืออื่น ยกเว้นตัวจำแนก ซึ่งมันอ่านด้วย LightGBM

เครื่องมือ VFACE มีอยู่เฉพาะบน feature branch ของแคตตาล็อกเครื่องมือ และส่วนของเซิร์ฟเวอร์เฉพาะบน feature branch ของเซิร์ฟเวอร์ เซิร์ฟเวอร์ที่สร้างจาก main branch จึงไม่เผยแพร่มัน (รายละเอียด) ทุกอย่างด้านล่างอ่านจากโค้ด ไม่มีสิ่งใดในหน้านี้มาจากการรัน และไม่มีข้อความใดที่บอกว่ามีเซิร์ฟเวอร์ที่ deploy อยู่

ภาพรวม: อะไรเข้า อะไรออก

VFACE
อินพุตโฟลเดอร์ของสแกน CBCT หนึ่งสแกนต่อผู้ป่วย (ค้นหาในโฟลเดอร์ย่อยด้วย); สำหรับการศึกษาตามยาว มีโฟลเดอร์ที่สองของสแกนติดตามผล
แนวคิดนำทุกสแกนเข้าสู่ท่ามาตรฐาน สร้างภาพสะท้อน register ภาพสะท้อนกลับทีละบริเวณ และอ่านช่องว่างที่เหลือระหว่างlandmarkแต่ละจุดกับคู่สะท้อนของมันเป็นความไม่สมมาตร
เอาต์พุตตาราง Excel ของการวัดต่อบริเวณและตารางของ feature; การจำแนกต่อผู้ป่วย (ไม่สมมาตรหรือไม่ ขากรรไกรล่างเกี่ยวข้องหรือไม่ ขากรรไกรบนเกี่ยวข้องหรือไม่); ทางเลือกคือพื้นผิวที่ลงสีตามระยะแบบมีเครื่องหมาย (heat map); รายงาน JSONที่ระบุทุกอย่างที่ถูกข้าม

หกเครื่องมือด้วยภาษาง่าย ๆ

  • ASO นำสแกนเข้าสู่ท่ามาตรฐาน โดยใช้ landmark
  • AMASSS วาดเค้าโครงกระดูกของแต่ละบริเวณ (มาสก์) เพื่อให้ registration มองเพียงบริเวณเดียว
  • AutoMatrix ใช้เมทริกซ์กับสแกนหรือไฟล์ landmark: การสะท้อน แล้วตามด้วย registration ของผู้ป่วยแต่ละคน
  • AREG_CBCT register CBCT หนึ่งเข้ากับอีกอัน
  • ALI_CBCT วาง landmark บน CBCT
  • Batch_Dental_Seg สร้างพื้นผิวกระดูกจากสแกน สำหรับ heat map

ยังมีอีกสองชื่อที่ปรากฏซ้ำ: AQ3DC คือโค้ดการวัด (ระยะและมุมระหว่าง landmark) และ LightGBM คือไลบรารีที่อ่านโมเดลการจำแนกสามตัว ซึ่งเป็นชุดของต้นไม้ตัดสินใจเล็ก ๆ

1. รันที่ไหน

รายการค่า
ชื่อใน SlicerVFACE แผงบางที่สร้างจากฟอร์มของเซิร์ฟเวอร์; ไม่มีอะไรติดตั้งบนแล็ปท็อป
มีอยู่ที่ไหนบน feature branch ของแคตตาล็อกเครื่องมือและ feature branch ของเซิร์ฟเวอร์ ไม่ใช่บน main branch ของทั้งสอง
เรียกหกเครื่องมืออื่น: ASO, AMASSS, AutoMatrix (สองครั้ง ด้วยการตั้งค่าต่างกัน), AREG_CBCT, ALI_CBCT และ Batch_Dental_Seg
ถูกเรียกโดยไม่มีเครื่องมือใด
สถานะพัฒนาแล้วและทดสอบหน่วยด้วย callee จำลอง; ไม่เคยรันตลอดสายกับเครื่องมือจริงทั้งหก; ยังไม่ผ่านการตรวจสอบทางคลินิก ดูปัญหาที่ทราบ
ในโค้ดตารางพร้อมการอ้างอิง file:line: โฟลเดอร์เครื่องมือ การประกาศฝั่งเซิร์ฟเวอร์ แผง การเรียก สถานะ

อะไรรันที่ไหน

ที่ไหนอะไร
เซิร์ฟเวอร์ ตัว VFACE เองตรวจคำขอ รีแซมเปิล เรียงสแกนที่จัดทิศทางแล้วตามเฟรม padding และแปลงlandmark การวัด ตาราง feature ตัวจำแนกสามตัว แผนที่ระยะ และรายงาน; โฟลเดอร์ทำงานของมันถูกลบตอนท้าย
เซิร์ฟเวอร์ หกเครื่องมือแต่ละตัวรันในโปรเซสและสภาพแวดล้อมของตัวเอง และเขียนลงช่องที่เซิร์ฟเวอร์ให้; VFACE อ่านเส้นทางที่แต่ละการเรียกคืนกลับมา
ไคลเอนต์ (Slicer)หนึ่งคำขอ; โฟลเดอร์ถูกบีบเป็น zip ก่อนอัปโหลด; ผลลัพธ์ถูกแตกไฟล์ลงโฟลเดอร์ที่เลือก และทางเลือกคือโหลดพื้นผิวได้สูงสุด 12 ไฟล์ เวิร์กบุ๊ก Excel อยู่ในโฟลเดอร์ต่อไป: Slicer ไม่มีตัวโหลดสำหรับมัน

การเรียกทั้งหก

ทุกการเรียกระบุเครื่องมือด้วยสตริง และส่งชื่ออาร์กิวเมนต์ที่เครื่องมือนั้นเผยแพร่ ไม่ใช่คำศัพท์ของ VFACE เอง เทสต์หนึ่งอ่านฟอร์มที่เผยแพร่ทั้งหกและตรวจว่าทุกอาร์กิวเมนต์ที่ส่งมีอยู่จริง

ขั้นตอนเครื่องมือสิ่งที่ VFACE ขอสิ่งที่อ่านกลับ
การจัดทิศทาง หนึ่งครั้งต่อเฟรมASOจัดทิศทางสแกนเข้ากับเคสอ้างอิงของเฟรม อัตโนมัติเต็มรูปแบบ พร้อมรายการ landmark ของเฟรมนั้นสแกนที่จัดทิศทางแล้วและไฟล์ transform ของมัน
มาสก์สำหรับ registration หนึ่งครั้งต่อเฟรมAMASSSมาสก์ไบนารีหนึ่งไฟล์สำหรับแต่ละโครงสร้างที่บริเวณของเฟรมต้องใช้โฟลเดอร์ของมาสก์
สะท้อน สแกนก่อน แล้วจึง landmarkAutoMatrixใช้ transform การสะท้อน เหมือนกันสำหรับผู้ป่วยทุกคนไฟล์ที่สะท้อนแล้ว
Registration หนึ่งบริเวณต่อหนึ่งการเรียกAREG_CBCTregister สแกนที่สองเข้ากับ baseline บนมาสก์ของบริเวณนั้นโฟลเดอร์ transform ของบริเวณ
ย้าย landmark ที่ใช้เปรียบเทียบAutoMatrixใช้เมทริกซ์ registration ของผู้ป่วยแต่ละคนไฟล์ landmark ที่ย้ายแล้ว
LandmarkALI_CBCTวางเฉพาะ landmark ที่รายการการวัดระบุชื่อไฟล์ landmark
พื้นผิวสำหรับ heat mapBatch_Dental_Segแบ่งส่วนพื้นผิวจากสแกนไฟล์พื้นผิว (แต่ดูปัญหาที่ทราบ)

สองในหกถูกกำกับดูแลเอง (ASO เข้าถึง ALI_CBCT, AREG_CBCT เข้าถึง AMASSS และ ASO) กราฟการเรียกจึงเป็นต้นไม้ที่เซิร์ฟเวอร์สร้างด้วยการเรียกซ้ำ; VFACE ไม่ได้จัดการสิ่งใดเลย

ในโค้ดแต่ละการเรียกพร้อมอาร์กิวเมนต์ที่ส่ง สิ่งที่อ่านกลับ และ file:line ของการเรียก

2. ไฟล์ที่เกี่ยวข้อง

เครื่องมือประกอบด้วยโมดูล Python สั้น ๆ ราวสิบสองโมดูล: จุดเริ่มต้น ตัวจ่ายงานที่ระบุห่วงโซ่ การเรียกทั้งหก แคตตาล็อกของโหมดและบริเวณ การรีแซมเปิล การจัดการlandmark การวัด feature ตัวจำแนก และheat map ตารางเต็มพร้อมจำนวนบรรทัด และสิ่งที่เกี่ยวกับ VFACE ฝั่งเซิร์ฟเวอร์และไคลเอนต์ อยู่ในหน้าโค้ด

ในโค้ดทุกไฟล์ของเครื่องมือพร้อมจำนวนบรรทัด และไฟล์ของเซิร์ฟเวอร์กับไคลเอนต์

3. ไปป์ไลน์

ห่วงโซ่ตามที่ตัวจ่ายงานระบุ: รีแซมเปิล จัดทิศทาง (ต่อเฟรม) แบ่งส่วน (ต่อเฟรม) สแกนที่สอง register (ต่อบริเวณ) landmark วัด จำแนก

3.1 สามโหมด สองการศึกษา สามผลลัพธ์

เหล่านี้คือ combo box ของ legacy แต่ละโหมดเริ่มจากที่โหมดก่อนหน้าหยุดไว้

3.2 ทุกอย่างถูกตรวจก่อนอ่านวอลุ่ม

ก่อนอ่านสแกนใด เครื่องมือตรวจทั้งคำขอ: อาร์กิวเมนต์ว่างที่เซิร์ฟเวอร์เติมได้จะถูกเติม โหมด การศึกษา ผลลัพธ์ หรือบริเวณที่ไม่รู้จักถูกปฏิเสธตามชื่อ และโหมดที่เครื่องมือเข้าถึงไม่ได้ก็เช่นกัน กฎของโค้ดเอง: คำขอที่ทำงานไม่ได้ต้องตอบกลับภายในหนึ่งวินาที ไม่ใช่หลังจากหนึ่งชั่วโมง

ในโค้ดตารางเครื่องมือและ bundle ที่ต้องมีต่อเงื่อนไข และวิธีที่การปฏิเสธถูกยก

3.3 Bundle ที่ deployment หาให้

โมเดล ตัวจำแนก เคสอ้างอิงสองเคสสำหรับการจัดทิศทาง เมทริกซ์การสะท้อน รายการการวัดเริ่มต้น และเทมเพลต feature ถูกจัดหาโดยโฟลเดอร์ข้อมูลของเซิร์ฟเวอร์เองเมื่อผู้เรียกปล่อยว่าง โมเดล landmark ถูกเว้นไว้โดยตั้งใจ เพราะ ALI_CBCT หา weights ของตัวเอง; โมเดลพื้นผิวก็ถูกเว้นไว้เช่นกัน และไม่มีสิ่งใดเติมให้ (ปัญหาที่ทราบ)

ในโค้ดตาราง bundle ในโค้ด และที่ที่แต่ละชื่อถูกหา

3.4 ห่วงโซ่ ทีละขั้น

คำขอเริ่มต้น: full pipeline, asymmetry assessment, การวัดและการจำแนก, สามบริเวณ

โฟลเดอร์ของสแกน CBCT ดิบ หนึ่งสแกนต่อผู้ป่วย รวมโฟลเดอร์ย่อย

การเตรียมการ

  2. ASO ×2, Fully-Automated: Frankfort + mid-sagittal (7 landmark) แล้ว occlusal + mid-sagittal (6 landmark)
  3. AMASSS ×2: CBMASK และ MANDMASK บนเฟรม CB, MAXMASK บนเฟรม MAX

สแกนที่สอง

  1. AutoMatrix ×2 ใช้การสะท้อนกับสแกนที่จัดทิศทางแล้วของแต่ละเฟรม: ตรงนี้คือที่มาของ “T2”

3.5 รีแซมเปิล

ไปป์ไลน์เต็มของ legacy เริ่มด้วยการเรียกคำสั่งรีแซมเปิลของ MRI2CBCT โดยปิดทุกอินพุตที่เฉพาะกับ MRI VISOR ไม่มีเครื่องมือ MRI2CBCT จึงคัดลอกไม่กี่บรรทัดที่ถูกใช้จริงไว้ใน VFACE

ขนาดกริดคงเดิมและระยะห่างเปลี่ยน วอลุ่มที่อ่านไม่ได้ถูกบันทึกในรายงานและกลุ่มผู้ป่วยทำต่อ; กลุ่มที่ไม่มีอะไรรีแซมเปิลได้เลยจะถูกปฏิเสธ เส้นทางผลลัพธ์คงโฟลเดอร์ของแต่ละสแกน ขณะที่ legacy ทำให้แบนราบ

ในโค้ดโค้ดรีแซมเปิลที่คัดลอกมาพร้อมบรรทัด ค่าเริ่มต้น และกฎความล้มเหลว

3.6 การจัดทิศทางเข้าสองเฟรม

สแกนถูกจัดทิศทางสองครั้ง และทุกขั้นตอนหลังจากนั้นทำงานในเฟรมใดเฟรมหนึ่ง ขากรรไกรล่างทำงานในเฟรมฐานกะโหลก เพราะวัดจากตำแหน่งที่มันอยู่เทียบกับกะโหลก; มีเพียงขากรรไกรบนที่ได้เฟรม occlusal

กรอบเคสอ้างอิงLandmark ที่ใช้บริเวณที่ทำงานในเฟรมนั้น
ฐานกะโหลกFrankfurt horizontal และระนาบ mid-sagittalBa, LPo, N, RPo, S, LOr, ROrฐานกะโหลก ขากรรไกรล่าง
ขากรรไกรบนระนาบ occlusal และ mid-sagittalANS, IF, PNS, UL6O, UR1O, UR6Oกระดูกขากรรไกรบน

แต่ละเฟรมคือการเรียก ASO หนึ่งครั้งในโหมดอัตโนมัติเต็มรูปแบบ ซึ่งสำหรับ CBCT หมายความว่า ASO ทำนาย landmark ของมันผ่าน ALI_CBCT แล้ว register ตามนั้น การฟิตเป็นของ ASO ไม่เปลี่ยนจาก legacy: เริ่มจาก landmark สามจุด (ที่ดีที่สุดจากสามจุดไม่เกิน 2500 ชุด คือชุดที่เหลือระยะเฉลี่ยน้อยที่สุด) จากนั้นรูทีน iterative closest point ของ VTK ในโหมด rigid-body ซึ่งเริ่มด้วยการจับคู่เซนทรอยด์ทั้งสอง จำกัดที่ 1000 รอบ และทำให้ระยะกำลังสองระหว่างจุดที่จับคู่กันน้อยที่สุด เก็บไว้เฉพาะการหมุน เพราะสแกนถูกจัดกึ่งกลางที่จุดกำเนิดอยู่แล้ว ทั้งสองเฟรมถูกจัดทิศทางไม่ว่าจะขอบริเวณใด เพราะ landmark ถูกทำนายในเฟรมฐานกะโหลกและแปลงเข้าเฟรมขากรรไกรบน ในสองโหมดที่ข้ามการจัดทิศทาง สแกนที่ชื่อไม่มี suffix ใดเลย หรือมีทั้งสอง จะถูกตัดออกและระบุไว้ในรายงาน

ในโค้ดตารางเฟรมพร้อม file:line, suffix และวิธีจัดการสแกนที่ไม่มีเฟรม

3.7 มาสก์สำหรับ registration

หนึ่งการเรียก AMASSS ต่อเฟรม สำหรับโครงสร้างของบริเวณที่เฟรมนั้นมี เฟรมฐานกะโหลกจึงขอมาสก์ฐานกะโหลกและขากรรไกรล่างในรอบเดียว เฟรมที่ไม่มีบริเวณที่ขอ registration อยู่เลยจะไม่ถูกเรียกเลย โครงสร้างคือแบบมาสก์ ไม่ใช่แบบกายวิภาค: registration ที่ได้รับ segmentation ในที่ที่คาดหวังมาสก์จะรัน สร้าง transform และรายงานความสำเร็จบนกายวิภาคที่ผิด มีการเขียนไฟล์ไบนารีหนึ่งไฟล์ต่อโครงสร้าง จึงค้นหามาสก์ของบริเวณตามชื่อได้

ในโค้ดชื่อโครงสร้าง การตั้งค่า merge และกฎสำหรับเฟรมที่ไม่มีบริเวณ

3.8 สแกนที่สอง: จุดที่สองการศึกษาแยกทางกัน

การสะท้อนเป็น transform เดียวที่ใช้ด้วยค่าเดียวกันสำหรับผู้ป่วยทุกคน เพราะเป็นการสะท้อนของเฟรม ไม่ใช่สิ่งที่ฟิตต่อผู้ป่วยแต่ละราย มันใช้ได้ก็เพราะการจัดทิศทางได้วางระนาบ mid-sagittal ไว้ตรงที่การสะท้อนคาดหวังแล้วเท่านั้น การศึกษาตามยาวที่ไม่มีโฟลเดอร์ติดตามผล หรือ asymmetry assessment ที่ไม่มีbundleการสะท้อน จะถูกปฏิเสธด้วยข้อความที่ระบุชื่อการศึกษาอีกแบบ

ในโค้ดการเรียกสะท้อน การตั้งค่า content สำหรับสแกนและ landmark และการปฏิเสธ

3.9 Registration หนึ่งบริเวณต่อหนึ่งการเรียก

สำหรับแต่ละบริเวณที่ขอ AREG_CBCT register สแกนที่สองของเฟรมของบริเวณนั้นเข้ากับ baseline ของเฟรมเดียวกัน บนมาสก์ของบริเวณนั้น ใช้ในโหมดกึ่งอัตโนมัติ เพราะสแกนถูกจัดทิศทางและแบ่งส่วนแล้ว: การขอให้มันจัดทิศทางอีกจะทำให้ภาพสะท้อนถูกจัดทิศทางเป็นอิสระจากต้นฉบับ และภาพสะท้อนเป็นภาพสะท้อนได้ก็ต่อเมื่อใช้เฟรมเดียวกับต้นฉบับ

AREG_CBCT จัดกลุ่มผลลัพธ์ตามบริเวณ โฟลเดอร์ที่คืนมาจึงไม่มี transform อยู่เอง; VFACE ลงไปหนึ่งระดับเมื่อมีโฟลเดอร์ย่อยพอดีหนึ่งโฟลเดอร์ที่เก็บ transform และมิฉะนั้นจะปฏิเสธพร้อมรายการสิ่งที่พบ ในโฟลเดอร์นั้น AREG_CBCT เขียนทั้งสแกนที่ registration แล้วและ transform ของมัน: ขั้น landmark ใช้ transform ส่วนขั้น heat map ใช้สแกน

ในโค้ดวิธีหาโฟลเดอร์บริเวณ ชื่อไฟล์ และข้อความปฏิเสธ

3.10 Landmark: หาหนึ่งครั้ง แล้วแปลงและย้าย

landmark ตัวไหน เฉพาะที่รายการการวัดระบุชื่อ รวบรวมเป็นเซตเดียว: ALI_CBCT รันเอเจนต์ค้นหาหนึ่งตัวต่อ landmark ใช้ประมาณหนึ่งนาทีต่อจุด แคตตาล็อกของทั้งบริเวณจึงจะใช้เวลาหลายชั่วโมง

Padding สแกนฐานกะโหลกถูกคัดลอกพร้อมพื้นที่ 30 mm ทุกด้านก่อนค้นหา เติมด้วยค่ามืดที่สุดของสแกนเอง; จุดกำเนิดเลื่อนตาม padding จุดจึงกลับมาอยู่ในพื้นที่ของสแกนต้นฉบับ เหตุผล: เอเจนต์ของ ALI ปฏิเสธตำแหน่งใด ๆ นอกขนาดที่ไม่ได้ padding ทำให้มันยอมแพ้กับจุดที่อยู่ห่างขอบหนึ่งหรือสอง voxel เช่น menton

การแปลงเข้าเฟรมขากรรไกรบน ทั้งสองการจัดทิศทางมาจากสแกนที่จัดกึ่งกลางชิ้นเดียวกัน ตำแหน่งของจุดในเฟรมขากรรไกรบนจึงได้จากตำแหน่งในเฟรมฐานกะโหลกผ่าน orientation transform ทั้งสอง โดยไม่ต้องค้นหารอบที่สอง ผู้ป่วยที่ขาด transform ตัวใดตัวหนึ่งจากสองตัวจะถูกข้ามและบันทึกไว้; ถ้าไม่มีผู้ป่วยรายใดแปลงได้ การรันจะหยุด

ชุดที่ใช้เปรียบเทียบ สำหรับ asymmetry assessment คือ landmark ของ baseline เองที่ AutoMatrix สะท้อน; สำหรับ longitudinal study คือ landmark ที่ ALI_CBCT ทำนายบนสแกนติดตามผลที่ padding แล้ว จากนั้นชุดที่ใช้เปรียบเทียบของแต่ละบริเวณถูกย้ายด้วย registration ของบริเวณนั้น หนึ่งการเรียก AutoMatrix ต่อบริเวณ เพื่อให้เมทริกซ์ของผู้ป่วยแต่ละคนถูกจับคู่กับผู้ป่วยคนนั้นตามชื่อ

พิกัด landmark เดินทางเป็น markups .mrk.json ระหว่าง ALI_CBCT, AutoMatrix และ VFACE และ transform ถูกใช้กับตำแหน่งที่เก็บไว้โดยตรง ไม่มีการแปลง RAS/LPS ปรากฏใน VFACE; ข้อตกลงเรื่องเฟรมเป็นแบบที่ callee เขียน ซึ่งหน้านี้ไม่ได้อ่านซ้ำ

ในโค้ดโค้ด padding สนิปเพ็ตการแปลงพร้อมบรรทัด และกฎที่จับคู่ไฟล์ตามผู้ป่วย

Feature ที่มีเครื่องหมาย ขนาดและป้ายของแต่ละแถวถูกแปลงกลับเป็นตัวเลขที่มีเครื่องหมาย; ป้ายใดนับเป็นลบขึ้นกับว่าแถวนั้นเป็นฟันหรือโครงกระดูก แกนแนวตั้งเก็บข้อตกลงของ legacy ไว้ทั้งสองแบบ ซึ่งตรงข้ามกัน จากนั้นเวิร์กบุ๊กเทมเพลตระบุชื่อคอลัมน์ของตาราง feature และเติมหนึ่งแถวต่อผู้ป่วยจากตารางของบริเวณที่ถูกต้อง; คอลัมน์ที่ระบุ landmark ที่การรันไม่เคยสร้างขึ้นจะถูกปล่อยว่าง

การวัดที่ผ่านการประมวลผลต่อคำนวณ ตาราง feature หนึ่งแถวต่อผู้ป่วย
การจำแนกทำนาย ตาราง feature บวกสามคำตอบ
Heat map หนึ่งไฟล์ต่อผู้ป่วยและบริเวณคำนวณ พื้นผิว baseline พร้อมอาร์เรย์ระยะที่มีเครื่องหมาย
รายงาน JSONโหมด การศึกษา ผลลัพธ์ บริเวณ ระยะเวลา และทุกการข้ามรายผู้ป่วย

รายงานถูกเขียนแม้การรันจะล้มเหลว และโฟลเดอร์ทำงานถูกลบในขั้นเดียวกัน รายการบางรายการในรายงานเป็นเส้นทางสัมพัทธ์ของอินพุต

ในโค้ดเส้นทางผลลัพธ์พร้อมบรรทัด และทุกคีย์ของรายงาน

4. สิ่งที่เลือกได้

  • วอลุ่ม CBCT: โฟลเดอร์ ค้นหาผ่านโฟลเดอร์ย่อย (จำเป็น)
  • Starting from: full pipeline, file already oriented หรือ file already registered
  • Study: asymmetry assessment (ค่าเริ่มต้น) หรือ longitudinal study; แบบหลังแสดงโฟลเดอร์ที่สองสำหรับสแกนติดตามผล
  • What to produce: measurements and classification, measurements และ heat map หรือ heat map อย่างเดียว
  • Regions to measure: ฐานกะโหลก ขากรรไกรล่าง และขากรรไกรบน ทั้งสามเป็นค่าเริ่มต้น
  • Transform สำหรับการรันที่เริ่มจากไฟล์ที่ registration แล้ว: หนึ่งโฟลเดอร์ย่อยต่อบริเวณ
  • ทุกอย่างอื่น (เคสอ้างอิง โมเดล รายการการวัด ตัวจำแนก) เซิร์ฟเวอร์เป็นผู้เติมและซ่อนไว้ในแผง
ในโค้ดตารางอาร์กิวเมนต์เต็มพร้อมชนิด ค่าเริ่มต้น และวิธีที่แผงแสดงแต่ละตัว

6. สภาพแวดล้อม

VFACE รันในสภาพแวดล้อม Python ของตัวเองบนเซิร์ฟเวอร์ พร้อมเวอร์ชันที่ตรึงไว้: Python 3.11, SimpleITK, NumPy, SciPy, VTK, pandas, openpyxl, LightGBM, joblib และ scikit-learn (โมเดลทั้งสามเป็น wrapper แบบ scikit-learn ของ LightGBM และการ unpickle ตัวหนึ่งจะ import มัน; legacy ไม่เคยติดตั้งมัน) VFACE ไม่มี GPU และไม่มี PyTorch: เครือข่ายทุกตัวเป็นของเครื่องมือที่มันเรียก แต่ละตัวมีสภาพแวดล้อมของตัวเอง การรันเต็มรูปแบบจึงต้องสร้างและให้บริการเครื่องมือทั้งหกบนเซิร์ฟเวอร์เดียวกัน ไม่ได้ประกาศขีดจำกัดเวลา จึงใช้ค่าเริ่มต้นของเซิร์ฟเวอร์

ในโค้ดเวอร์ชันพร้อมหมายเลขบรรทัด โฟลเดอร์ข้อมูล ขีดจำกัด และเทสต์

7. สิ่งที่เปลี่ยนไปจากตรรกะ legacy

พอร์ตทำจากโค้ด legacy ตามที่เป็นอยู่เมื่อ 2026-09-18

ขั้นตอนLegacyVISOR
การประสานงานการเรียกบรรทัดคำสั่งประมาณ 40 ครั้งที่ต่อกันด้วย callback ของ Qtตัวจ่ายงานหนึ่งตัวที่เรียกหกเครื่องมือผ่านเซิร์ฟเวอร์
Resampleการเรียกคำสั่ง MRI2CBCTบรรทัดเดียวกันที่คัดลอกมา; คงโครงสร้างโฟลเดอร์
การจัดทิศขั้นการจัดกึ่งกลาง landmark และการจัดทิศทางแยกกันการเรียก ASO หนึ่งครั้งต่อเฟรม
สแกนที่สองตัวเลือก register ด้วย CMFReg หรือการสะท้อนด้วย AutoMatrixไม่มี CMFReg; การสะท้อน หรือสแกนติดตามผลจริง
LandmarkALI บน T1 แล้วอีกครั้งบน T2 ต่อเฟรมALI ครั้งเดียวในเฟรมฐานกะโหลกบนสแกนที่ padding แล้ว จากนั้นแปลง; เฉพาะชื่อที่รายการต้องใช้
ตัวตนของผู้ป่วยตัดตามสตริงย่อยของชื่อโทเค็นทั้งตัว
รายการการวัดอ่านการวัดจากทุกชีต; รายการ landmark ที่จะขอ จากชีตแรกเท่านั้นทุกชีตสำหรับทั้งสองอย่าง
ชนิดของการวัดสตริงชนิดสิบแบบ รวมถึง “Distance point line T1 T2” และ “Angle between 2 lines T1 T2” (ผลต่างของสองการวัด)แปดแบบ: แถวของสองชนิดนั้นชนิดใดชนิดหนึ่งจะถูกข้ามพร้อมคำเตือน (รายละเอียด)
ตาราง featurelandmark ที่ขาดทำให้การประมวลผลหลังการวัดหยุดคอลัมน์ถูกปล่อยว่าง
การจำแนกสามโมเดล เฉพาะ asymmetry assessmentโมเดลเดียวกัน รันสำหรับทั้งสองการศึกษา; คอลัมน์ถูกเลือกด้วยชื่อของแต่ละโมเดลเอง; โมเดลย่อยที่ล้มเหลวถูกบันทึก
Heat mapหนึ่งโปรเซสทำงานต่อคู่ ลดจุดเมื่อเกินหนึ่งล้านจุด (ครึ่งหนึ่ง) และสองล้านจุด (70 %)ในโปรเซสเดียว ด้วยเกณฑ์เดียวกัน; พื้นผิวจาก Batch_Dental_Seg แทนตัวแบ่งส่วนเริ่มต้น
หยุดและตรวจทานแผงตรวจทานที่มีจุดหยุดและการนำทางเป็นแบตช์ไม่ได้พอร์ต
การล้างข้อมูลไล่โฟลเดอร์ย่อยของโฟลเดอร์ผลลัพธ์ (บั๊กในอดีต)ลบเฉพาะโฟลเดอร์ทำงานของตัวเอง
การติดตั้งติดตั้งด้วย pip และดาวน์โหลดอาร์ไคฟ์สิบไฟล์ลงแล็ปท็อปไม่มีอะไรถูกติดตั้งหรือดาวน์โหลดใน Slicer
ในโค้ดตารางเดียวกันพร้อมการอ้างอิง file:line ของ legacy และ VISOR

8. ปัญหาที่ทราบใน VISOR

แต่ละประเด็นถูกอ่านในโค้ดและอธิบายพร้อมหลักฐานในหน้าโค้ด; รายการนี้ปรากฏในข้อค้นพบด้วย

  • ไม่เคยรันกับเครื่องมือจริงทั้งหก ทดสอบเฉพาะ callee จำลองและเลขคณิต; ยังไม่มีสิ่งใดผ่านการตรวจสอบทางคลินิก หลักฐาน
  • Heat map: ไม่ได้ขอพื้นผิวจากเครื่องมือพื้นผิว โดยค่าเริ่มต้นมันเขียนเฉพาะวอลุ่ม จึงไม่พบคู่ใดเลยและการรันถูกปฏิเสธ หลักฐาน
  • Heat map ไม่มีbundleพื้นผิวใน deployment นี้ คำขอสำหรับมันจะถูกปฏิเสธ หลักฐาน
  • longitudinal study ก็ถูกจำแนกด้วย โมเดลถูกฝึกให้อ่านผู้ป่วยเทียบกับภาพสะท้อนของตัวเอง คำตอบจึงไม่มีความหมายที่ระบุไว้ในกรณีนั้น หลักฐาน
  • กลุ่มผู้ป่วยถูกแบ่งตามโฟลเดอร์ baseline เท่านั้น โฟลเดอร์ติดตามผลไม่ถูกแบ่งไปด้วย หลักฐาน
  • คำแนะนำเมื่อเกิดข้อผิดพลาดระบุฟิลด์ที่ไม่มีอยู่ หลักฐาน
  • data manifest ยังระบุว่า “not ported yet” และระบุ bundle น้อยกว่าที่เครื่องมือใช้ หลักฐาน
  • การวัดสองชนิดในรายการของ legacy ถูกข้าม แถวชนิด “Distance point line T1 T2” หรือ “Angle between 2 lines T1 T2” จะถูกทิ้งพร้อมคำเตือน โดยไม่หยุดการรัน หลักฐาน
  • คอมเมนต์นับเครื่องมือผิด เรียกหก ไม่ใช่เจ็ด; เพดานการซ้อนคือสิบ ไม่ใช่ห้า หลักฐาน

9. เอกสารอ้างอิง

บรรณานุกรมเป็นของเครื่องมือ อยู่ที่ SOURCES; หน้า legacy อภิปรายไว้ในหัวข้อวรรณกรรมของหน้านั้น ประเด็นหนึ่งคงเดิมทุกประการ: งานที่ตีพิมพ์อธิบายการจัดกลุ่มแบบไม่มีผู้สอนของการวัด ขณะที่โค้ด ทั้ง legacy และ VISOR อ่านการวัดด้วยตัวจำแนกแบบมีผู้สอน LightGBM สามตัว README ของ VISOR ไม่อ้างอิงสิ่งตีพิมพ์ใด

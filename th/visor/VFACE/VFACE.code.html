VFACE บน VISOR: โค้ด

สำหรับนักพัฒนา: สิ่งที่พอร์ต VISOR ของ VFACE ทำในโค้ด พร้อมการอ้างอิง file:line ลายเซ็น อาร์กิวเมนต์ สภาพแวดล้อม ความต่างจากโค้ด legacy และข้อค้นพบ คำอธิบายที่อ่านง่ายของไปป์ไลน์เดียวกัน พร้อมคณิตศาสตร์และตัวแสดงภาพ 3D อยู่ในหน้าแอตลาส

VISOR โค้ด แอตลาส (คำอธิบาย) เฉพาะ branch tool/vface หน้า legacy Guide (VISOR) บรรณานุกรม
พอร์ตบนสอง feature branch

เครื่องมือ VFACE มีอยู่เฉพาะบน branch tool/vface ของ SADT-VISOR (6ba2a78 นำหน้า main อยู่ 22 commit) และส่วนเซิร์ฟเวอร์ [tools.VFACE] มีอยู่เฉพาะบน branch conf/vface-deployment ของ VISOR-serve (e9a7e5d) git ls-tree main tools/ บน SADT-VISOR ไม่แสดงโฟลเดอร์ VFACE และ deployment.toml ของ main ใน VISOR-serve ไม่มีส่วน VFACE เซิร์ฟเวอร์ที่สร้างจาก branch main จะไม่เผยแพร่ VFACE ทั้งที่โมดูล Slicer VFACERemote อยู่บน main ของไคลเอนต์ ทุกอย่างด้านล่างนี้อธิบายสอง branch ดังกล่าว

ผู้ป่วยถูกเปรียบเทียบกับตัวเอง ในการประเมินความไม่สมมาตรไม่มีสแกนที่สอง: baseline ถูกจัดทิศทาง สะท้อนข้ามระนาบ mid-sagittal แล้ว registration กลับเข้ากับตัวเองทีละบริเวณ และสิ่งที่วัดคือ landmark แต่ละจุดเคลื่อนไปไกลเท่าใดจากภาพสะท้อนของตัวมันเอง การศึกษาตามยาวคือห่วงโซ่เดียวกัน โดยใช้การติดตามผลจริงแทนที่ภาพสะท้อน (SV:__init__.py:5-15) VFACE เองไม่เรียนรู้อะไรและไม่รันเครือข่ายใด: ทุกโมเดลที่ต้องใช้เป็นของเครื่องมืออื่น ยกเว้นตัวจำแนก ซึ่งมันอ่านด้วย LightGBM

การอ้างอิงใช้ชื่อย่อ: SV คือ SADT-VISOR tools/VFACE/src/sadt_vface/ ที่ 6ba2a78, README.md และ pyproject.toml อยู่ใน tools/VFACE/ ของที่เก็บโค้ดเดียวกัน; VS คือ VISOR-serve ที่ e9a7e5d; R คือ AutomatedDentalToolsRemote ที่ 19b95e8; legacy คือ SlicerAutomatedDentalTools ที่ 3c67957 ซึ่ง clp คือ VFACE/VFACE_utils/createlistprocess.py และ VFACE_CLI.py คือ VFACE_CLI/VFACE_CLI.py ทุกอย่างอ่านจากโค้ด ไม่มีสิ่งใดในหน้านี้มาจากการรัน และไม่มีข้อความใดที่บอกว่ามีเซิร์ฟเวอร์ที่ deploy อยู่ สำหรับตัวเซิร์ฟเวอร์ ดูสถาปัตยกรรมและการรันทีละขั้น

เซิร์ฟเวอร์ ตัว VFACE เองการตรวจสอบโหมด รีแซมเปิล (vendored, SV:resample.py) การเรียงสแกนที่จัดทิศทางแล้วตามเฟรม padding ของ landmark และการแปลงระหว่างเฟรม (SV:landmarks.py) การวัด (SV:measure.py, SV:aq3dc.py) ตาราง feature (SV:features.py) โมเดล LightGBM สามตัว (SV:classify.py) แผนที่ระยะ (SV:heatmap.py) และ VFACE_report.json โฟลเดอร์ทำงาน <output_dir>/.vface_work ถูกลบตอนท้าย (SV:dispatch.py:380, 409)

3.7 มาสก์สำหรับ registration

หนึ่งการเรียก AMASSS ต่อเฟรม สำหรับโครงสร้างของบริเวณที่เฟรมนั้นมี เฟรม CB จึงขอ CBMASK และ MANDMASK ในรอบเดียว (SV:catalogs.py:134-145) เฟรมที่ไม่มีบริเวณที่ขอ registration อยู่เลยจะไม่ถูกเรียกเลย: AMASSS ปฏิเสธรายการโครงสร้างว่าง และคำขอที่มีเฉพาะฐานกะโหลกเคยล้มที่นั่นหลังจากจ่ายค่าจัดทิศทางทั้งสองครั้งไปแล้ว (SV:dispatch.py:479-494) โครงสร้างคือแบบมาสก์ คือ CBMASK/MANDMASK/MAXMASK ไม่ใช่แบบกายวิภาค CB/MAND/MAX: registration ที่ได้รับ segmentation ในที่ที่คาดหวังมาสก์จะ "run, produce a transform, and report success on the wrong anatomy" (SV:catalogs.py:93-99) merge=["SEPARATE"] ให้ไฟล์ไบนารีหนึ่งไฟล์ต่อโครงสร้าง จึงค้นหามาสก์ของบริเวณตามชื่อได้ (SV:tools.py:151-153)

3.9 Registration หนึ่งบริเวณต่อหนึ่งการเรียก

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

สำหรับแต่ละบริเวณที่ขอ AREG_CBCT register สแกนที่สองของเฟรมของบริเวณนั้นเข้ากับ baseline ของเฟรมเดียวกัน บนมาสก์ของบริเวณนั้น (SV:dispatch.py:177-187) เป็น Semi-Automated เพราะสแกนถูกจัดทิศทางและแบ่งส่วนแล้ว: การขอให้ AREG จัดทิศทางอีกจะทำให้ภาพสะท้อนถูกจัดทิศทางเป็นอิสระจากต้นฉบับ และ "a mirror is only a mirror while it shares the original's frame" (SV:tools.py:218-222) ชื่อบริเวณที่ส่งคือชื่อที่แสดงของ AREG (Cranial base, Mandible, Maxilla: SV:catalogs.py:104-117)

AREG_CBCT จัดกลุ่มผลลัพธ์ตามบริเวณ โฟลเดอร์ที่คืนมาจึงไม่มี transform _region_folder ลงไปหนึ่งระดับเมื่อมีโฟลเดอร์ย่อยที่เก็บ transform อยู่พอดีหนึ่งโฟลเดอร์ (.tfm, .mat, .h5, .txt) มิฉะนั้นจะปฏิเสธพร้อมรายการสิ่งที่พบและเหตุผลรายผู้ป่วยที่อ่านจาก AREG_report.json (SV:tools.py:236-317) ในโฟลเดอร์บริเวณนั้น AREG_CBCT เขียนทั้งสแกนที่ registration แล้วและ transform ของมัน คือ <patient>_<region>_Reg.nii.gz และ <patient>_<region>_Reg_transform.tfm (SADT-VISOR tools/AREG/AREG_CBCT/src/sadt_areg_cbct/pipeline.py:72-83): ขั้น landmark ใช้ transform ส่วนขั้น heat map ใช้สแกน

Padding สแกนเฟรม CB ถูกคัดลอกพร้อมพื้นที่ 30 mm ทุกด้านก่อนค้นหา เติมด้วยค่าต่ำสุดของสแกนเอง; จุดกำเนิดเลื่อนตาม padding จุดจึงกลับมาอยู่ในพื้นที่ของสแกนต้นฉบับ (SV:landmarks.py:36, 186-228) เหตุผลที่ให้ไว้คือเอเจนต์ของ ALI ปฏิเสธตำแหน่งใด ๆ นอกขนาดที่ไม่ได้ padding ทำให้มันยอมแพ้กับจุดที่อยู่ห่างขอบหนึ่งหรือสอง voxel เช่น Me (SV:landmarks.py:5-11) สแกนที่ padding ไม่ได้จะถูกค้นหาตามเดิมและระบุไว้ใต้ not_padded

การแปลงเข้าเฟรม MAX ทั้งสองการจัดทิศทางมาจากสแกนที่จัดกึ่งกลางชิ้นเดียวกัน ตำแหน่งของจุดในเฟรมขากรรไกรบนจึงได้จากตำแหน่งในเฟรมฐานกะโหลกผ่าน orientation transform ทั้งสอง โดยไม่ต้องค้นหารอบที่สอง (SV:landmarks.py:252-334):

moved = from_centred.TransformPoint(to_centred.TransformPoint(points[label]))

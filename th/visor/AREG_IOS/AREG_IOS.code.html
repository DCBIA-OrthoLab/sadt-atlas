AREG_IOS บน VISOR: โค้ด

สำหรับนักพัฒนา: พอร์ต VISOR ของ AREG_IOS ทำอะไรในโค้ด พร้อมการอ้างอิง file:line ซิกเนเจอร์ อาร์กิวเมนต์ สภาพแวดล้อม ความต่างจากโค้ด legacy และข้อค้นพบ คำอธิบายที่อ่านง่ายของไปป์ไลน์เดียวกัน พร้อมคณิตศาสตร์ อยู่ในหน้าแอตลาส ส่วนโมดูล legacy อยู่ในหน้าของมันเอง

โค้ด แอตลาส (คำอธิบาย) VISOR AREG_IOS เข้าถึงในชื่อ AREG โหมด IOS torch 2.11, pytorch3d, GPU หรือ CPU หน้า legacy Guide (VISOR) บรรณานุกรม

AREG_IOS ลงทะเบียนสแกนในช่องปากครั้งติดตามผล (T2) ไปยังสแกนฐาน (T1) ของผู้ป่วยคนเดียวกัน ด้วย ICP แบบแข็งเกร็งบนแพตช์ที่การรักษาไม่ขยับ: เพดานปากบนส่วนโค้งฟันบน หรือแถบตามแนว mucogingival บนส่วนโค้งฟันล่าง ใน VISOR การคำนวณทั้งหมดรันบนเซิร์ฟเวอร์ รวมถึงเครือข่ายที่หาแพตช์เพดานปาก Slicer แสดงเพียงฟอร์ม ส่งโฟลเดอร์ และเปิดสิ่งที่ส่งกลับมา หน้านี้อธิบายพอร์ตนั้น อ่านที่ SADT-VISOR 6ba2a78 (สาขา tool/vface), VISOR-serve e9a7e5d และ AutomatedDentalToolsRemote 19b95e8 โมดูล legacy ที่ใช้เปรียบเทียบคือ SlicerAutomatedDentalTools 3c67957 ซึ่งอธิบายในหน้าของมันเอง พาธของ legacy ด้านล่างเป็นของคอมมิตนั้น

คำย่อที่ใช้ในหน้านี้: ios/ คือ SADT-VISOR tools/AREG/AREG_IOS/src/sadt_areg_ios/, common/ คือ SADT-VISOR tools/AREG/common/src/sadt_areg_common/ และพาธ server/ อยู่ใน VISOR-serve คำว่า “Observed” ระบุสิ่งที่ถูกรันจริง (เทสต์, scripts/describe.py, โปรบ Python สั้น ๆ) ระหว่างศึกษาพอร์ต ส่วนที่เหลือทั้งหมดอ่านจากโค้ด

main แก้ชุดที่โฮสต์ไว้สองชุดก่อนอย่างอื่น: registration_model ที่เว้นว่างกลายเป็น DATA/AREG/models/AREG_model และ ios_reference ที่เว้นว่างกลายเป็น DATA/AREG/models/IOS_Gold_files (ios/dispatch.py:87-97,457-459) จากนั้น _check_ios ปฏิเสธก่อนอ่านไฟล์ใด ๆ ในกรณีเหล่านี้: แพตช์ที่ไม่รู้จัก เพดานปากที่หา checkpoint ไม่พบ แพตช์ mucogingival ที่ไม่มี landmark และไม่มี supervisor ให้เรียก ALI_IOS ความสูงที่ติดลบ Fully-Automated ที่ไม่มี supervisor หรือไม่มีข้อมูลอ้างอิง (ios/dispatch.py:100-139) Fully-Automated ต้องใช้ Crown_Seg และ ASO สำหรับทั้งสองแพตช์

t1 = sup.run("ASO", input=t1, reference=<IOS_Gold_files>, modality="IOS",

การเรียก ASO ไม่ส่ง ios_occlusion (ios/tools.py:96-102) และค่าเริ่มต้นของ ASO คือ “Orient each jaw independently” (SADT-VISOR tools/ASO/src/sadt_aso/__init__.py:63-65) จากนั้นการลงทะเบียนเลื่อนส่วนโค้งอีกข้างด้วยเมทริกซ์ของส่วนโค้งที่ลงทะเบียน “so the captured occlusion survives” (ios/pipeline.py:13-15,209-224) แต่ถ้าสองขากรรไกรถูกปรับทิศทางแยกกัน การสบฟันที่บันทึกในสแกนก็ไม่ใช่สิ่งที่ถูกส่งต่อ legacy ส่ง occlusion = "true" เมื่อโฟลเดอร์มีส่วนโค้งล่าง (AREG/AREG_Method/IOS.py:621,633) อ่านจากโค้ด ไม่มีการรันเปรียบเทียบสองเอาต์พุต จึงไม่ทราบขนาดของผล

ไม่มีค่าสูงสุดของความสูงแพตช์

การตรวจปฏิเสธเฉพาะความสูงติดลบและไม่มีอย่างอื่น (ios/dispatch.py:119-123) วิดเจ็ต legacy เก็บค่าไว้ใน [0, 20] mm (AREG/AREG.py:42-44,870-882) อ่านจากโค้ด

โฟลเดอร์ scratch ไม่ถูกลบเมื่อการรันล้มเหลว

register ลบ .areg_work/ หลังเอนจินคืนค่า โดยไม่มี try/finally (ios/dispatch.py:348-413, shutil.rmtree ที่บรรทัด 408; เอนจินรันที่บรรทัด 385-403) ข้อยกเว้นที่ไม่ถูกจับต่อผู้ป่วยจะทิ้งสำเนาของอินพุตและเมชที่มีป้ายกำกับและปรับทิศทางแล้วไว้ในโฟลเดอร์เอาต์พุตที่เก็บถาวร AREG_IOSCBCT มี finally อ่านจากโค้ด ไม่ได้ทำให้เกิด

การปรับทิศทางที่ล้มเหลวถูกเขียนในรายงาน

แพตช์ยังถูกทำนาย แต่ notes ในรายการของผู้ป่วยระบุว่ามันถูกทำนายโดยไม่มีการปรับทิศทางมาตรฐาน พร้อมเหตุผล (ios/butterfly.py:117-131, ios/pipeline.py:247-249) อ่านจากโค้ด

ทรานส์ฟอร์มถูกเขียนเสมอ

ผู้ป่วยที่ลงทะเบียนทุกคนได้ .tfm ในทั้งสองโหมดและกับทั้งสองแพตช์ พร้อมประโยคในรายงานบอกว่ามันแมปไปทางใด (ios/pipeline.py:226-244) อ่านจากโค้ด

Crown_Seg ไม่ได้ถูกบอกว่าให้ใช้อุปกรณ์ใด

label_crowns ส่งเพียง meshes, suffix และ model ที่ไม่บังคับ (ios/tools.py:124-130) Crown_Seg จึงใช้ค่าเริ่มต้นของตัวเอง โดยใช้การตั้งค่าอุปกรณ์ของเซิร์ฟเวอร์เมื่อผู้เรียกไม่ระบุ และถอยไปใช้ CPU พร้อมคำเตือนเมื่อไม่เห็นการ์ด ดูCrown_Seg บน VISOR ไม่ใช่ข้อบกพร่อง แต่เป็นความไม่สมมาตรกับ ALI_IOS ซึ่งส่งอุปกรณ์ของมันต่อไป อ่านจากโค้ด

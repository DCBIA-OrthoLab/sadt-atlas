Agent บน VISOR

Agent อ่านประโยคเช่น “segment the skull of these scans” และเสนอว่าจะรันเครื่องมืออื่นตัวไหนด้วยการตั้งค่าอะไร โมเดลภาษาที่ให้บริการโดย Ollama เป็นผู้เลือก โค้ดปกติตรวจทุกคำตอบ และไม่มีอะไรรันเว้นแต่ถูกสั่ง ใน VISOR มีสองสิ่งที่ไม่เกี่ยวกันถูกเรียกว่า Agent: เครื่องมือใหม่บนเซิร์ฟเวอร์ และ AgentRemote สำเนาของแผง Slicer แบบ legacy ที่ยังรันทุกอย่างบนเวิร์กสเตชัน หน้านี้อธิบายทั้งสองทีละขั้น รายละเอียดที่นักพัฒนาต้องใช้อยู่ในหน้าโค้ด ส่วนโมดูล legacy อยู่ในหน้าของมันเอง

VISOR: บางส่วน โมเดลภาษา 1 ตัว เรียก 2 หรือ 1 ครั้ง โค้ด (สำหรับนักพัฒนา) หน้า legacy Guide (VISOR)

สถานะที่ commit อ้างอิง: SADT-VISOR 6ba2a78, VISOR-serve e9a7e5d, AutomatedDentalToolsRemote 19b95e8 (Remote) legacy คือ SlicerAutomatedDentalTools ที่ 3c67957 ทุกอย่างอ่านจากโค้ด: ไม่มี Ollama ให้ใช้ จึงไม่ได้รันอะไร

ออกข้อเสนอ: เครื่องมือไหน ด้วยค่าอาร์กิวเมนต์อะไร โมเดลมั่นใจแค่ไหน และค่าที่จำเป็นตัวไหนยังขาด อาจมีผลลัพธ์ของเครื่องมือเมื่อรันแล้วคำตอบที่เขียนเป็น Markdown ไม่มีอะไรถูกเสนอหรือรัน
การเรียกโมเดลสอง ครั้งหนึ่งเลือกเครื่องมือ อีกครั้งกรอกอาร์กิวเมนต์ของมันหนึ่ง

1. ตำแหน่งในสายโซ่

เครื่องมือเซิร์ฟเวอร์ Agentโมดูลไคลเอนต์ AgentRemote
สถานะimplement แล้ว พร้อมฟังก์ชันเทสต์ 206 ตัว (ตัวที่ต้องใช้ Ollama ถูกข้ามโดยค่าเริ่มต้น ไม่ได้รันตัวใดสำหรับหน้านี้) ไม่มีเอกสารการรันบนเซิร์ฟเวอร์ที่ deploy แล้วที่นี่: ต้องจัดหา Ollama แยกต่างหากส่งมอบและ build แล้ว แต่เป็นสำเนาของวิดเจ็ต legacy ไม่ใช่ไคลเอนต์ของเซิร์ฟเวอร์
แผงไม่มีในไคลเอนต์: ไม่มีอะไรเรียกเครื่องมือนี้ตามชื่อแผง Qt ของตัวเอง โดยไม่ใช้เครื่องมือเซิร์ฟเวอร์
เรียกendpoint ของ Ollama หนึ่งตัวผ่าน HTTP รายการเครื่องมือของเซิร์ฟเวอร์เอง และถ้าถูกขอ เครื่องมือเซิร์ฟเวอร์อีกหนึ่งตัวโมดูลบรรทัดคำสั่งของตัวเอง แล้วสคริปต์ของโมดูลที่เลือกบนเวิร์กสเตชัน
ถูกเรียกโดยไม่มีอะไรในที่เก็บโค้ดที่อ่านสำหรับหน้านี้ผู้ใช้

README ของไคลเอนต์บอกไว้ชัดเจน: Medical Data Anonymizer, VISU และ Agent “run on this machine and send nothing” ข้อความช่วยเหลือของแผงยังบอกว่าเอเจนต์ “powered locally by the qwen3:8b model through Ollama”

Ollama เป็นข้อกำหนดเบื้องต้นที่ไม่มีใคร deploy เครื่องมือเซิร์ฟเวอร์ต้องใช้ endpoint ของ Ollama: ตัวที่ให้เป็นอาร์กิวเมนต์ มิฉะนั้นตัวที่ตัวแปร OLLAMA_HOST ระบุ มิฉะนั้นพอร์ต Ollama ของเครื่องเอง มันไม่เคยติดตั้ง เริ่ม หรือ pull โมเดล และไม่มีอะไรใน VISOR-serve กล่าวถึง Ollama image จึงไม่มี Ollama ติดมา หากไม่มี endpoint ที่เข้าถึงได้ เครื่องมือจะหยุดด้วยคำตอบ “service unavailable” หลักฐาน

ในโค้ดจำนวนเทสต์ ตำแหน่งไฟล์ การเรียกฝั่งละอัน และกฎ endpoint ของ Ollama

1.1 อะไรรันที่ไหน

ขั้นตอนเครื่องมือเซิร์ฟเวอร์สำเนาฝั่งไคลเอนต์ (Slicer)
แค็ตตาล็อกของเครื่องมือรายการสดที่เซิร์ฟเวอร์เก็บ หรือสำเนา JSON ที่บันทึกไว้ของมันmanifest ที่เขียนด้วยมือ 17 รายการ
การคัดเลือกเบื้องต้นการจัดอันดับด้วยคำสำคัญ (BM25) ผู้สมัคร 8 รายเป็นค่าเริ่มต้นเครือข่ายจัดอันดับขนาดเล็ก (cross-encoder) 3 อันดับแรก
การเลือกและอาร์กิวเมนต์Ollama, qwen3:8b เป็นค่าเริ่มต้น, temperature 0Ollama ในเครื่อง ชื่อโมเดลเดียวกัน
การทำงานเฉพาะเมื่อถูกสั่ง และปฏิเสธใน 3 กรณี (ดู 3.5)กล่องโต้ตอบ ใช่/ไม่ แล้วโมดูลถูกเปิดบน thread ของ Slicer เอง ซ่อมได้สูงสุด 2 ครั้ง
ในโค้ดโค้ดเบื้องหลังแต่ละช่องของตารางนี้ พร้อมไฟล์และบรรทัด

2. ไฟล์ที่เกี่ยวข้อง

เครื่องมือเซิร์ฟเวอร์เป็นแพ็กเกจ Python ขนาดเล็กที่มีไฟล์สั้น ๆ ราวสิบสองไฟล์ แต่ละไฟล์มีหน้าที่เดียว: อ่านแค็ตตาล็อก จัดอันดับ คุยกับโมเดล routing เขียน prompt ตรวจสอบค่า รันเครื่องมือที่เลือก แยกวิเคราะห์ประวัติ และอธิบายแผง ไม่มี dependency นอกไลบรารีมาตรฐาน สำเนาฝั่งไคลเอนต์คือวิดเจ็ต legacy บวกโมดูลบรรทัดคำสั่งและ manifest

ในโค้ดรายการไฟล์พร้อมจำนวนบรรทัด สำหรับเครื่องมือเซิร์ฟเวอร์ โมดูล legacy และสำเนาฝั่งไคลเอนต์

3. ไปป์ไลน์ของเครื่องมือเซิร์ฟเวอร์

ห้าขั้นที่คำนวณเตรียมคำถาม การเรียกโมเดลหนึ่งหรือสองครั้งตอบมัน และโค้ดตรวจทุกคำตอบก่อนใช้

3.1 แค็ตตาล็อก

เอเจนต์ legacy มีรายการเครื่องมือและอาร์กิวเมนต์ที่เขียนด้วยมือเอง ซึ่งเลื่อนหลุดจากเครื่องมือจริง เครื่องมือเซิร์ฟเวอร์รับแค็ตตาล็อกเป็นอินพุต: สำเนา JSON ที่บันทึกไว้ของสิ่งที่เซิร์ฟเวอร์เผยแพร่ ถ้ามีให้ มิฉะนั้นรายการสดของเซิร์ฟเวอร์เอง อ่านโดยไม่มี token ถ้าไม่มีทั้งสองก็หยุด จากนั้นรายการถูกตรวจ: ต้องไม่ว่าง ชื่อสองชื่อต้องไม่เหมือนกันเมื่อไม่สนตัวพิมพ์และตัวคั่น และชนิดของทุกอาร์กิวเมนต์ต้องเป็นชนิดที่รู้จัก สำหรับแต่ละอาร์กิวเมนต์ เครื่องมือเก็บชนิด ว่าจำเป็นหรือไม่ คำอธิบาย choices และค่าเริ่มต้น อาร์กิวเมนต์ที่โมเดลกรอกได้คือตัวที่ไม่ใช่โฟลเดอร์ผลลัพธ์และไม่ถูกซ่อน

ในโค้ดอ่านแค็ตตาล็อกที่ไหน อะไรถูกปฏิเสธ และเก็บอะไรไว้ในแต่ละอาร์กิวเมนต์

3.2 การเลือกผู้สมัคร

ตารางคำพ้องความหมายที่การจัดอันดับใช้เก็บคำศัพท์ ไม่ใช่ชื่อเครื่องมือ การจัดอันดับของ legacy เป็น cross-encoder แบบนิวรอล เมื่อล้มเหลวมันคืนเครื่องมือสามตัวแรกของไฟล์อย่างเงียบ ๆ ในขณะที่การจัดอันดับของเซิร์ฟเวอร์หยุดด้วยข้อผิดพลาดแทนที่จะเดา

ในโค้ดโค้ด BM25 น้ำหนักของแต่ละช่อง ตารางคำพ้องความหมาย และทางสำรองแบบทุกเครื่องมือ

3.3 การเรียกโมเดลครั้งแรก: เครื่องมือไหน?

โมเดลเห็นคำขอและผู้สมัคร ซึ่งแต่ละรายเขียนครบถ้วน (legacy ตัดคำอธิบายที่ 140 อักขระ) มันต้องตอบด้วยออบเจกต์ JSON หนึ่งตัว: ชื่อเครื่องมือ confidence และเหตุผลหนึ่งประโยค หรือไม่มีเครื่องมือพร้อม confidence 0.2 หรือต่ำกว่าเมื่อไม่มีตัวใดเหมาะ บล็อกการให้เหตุผลและ code fence รอบคำตอบถูกตัดออกก่อนอ่าน จากนั้นชื่อถูกตรวจกับผู้สมัคร:

  • ไม่มีเครื่องมือ หรือคำว่า “null”: ไม่เลือกอะไร
  • ชื่อที่พบในหมู่ผู้สมัคร ตรงตัวหรือหลังทำให้ตัวพิมพ์และตัวคั่นเป็นบรรทัดฐาน: เลือก
  • อย่างอื่นทั้งหมด: ไม่มีเครื่องมือ confidence ถูกจำกัดที่ 0.2 และชื่อที่แต่งขึ้นถูกบันทึกพร้อมคำเตือน
ในโค้ดคำขอที่ส่งไป Ollama prompt ของ router การดึง JSON และการตรวจชื่อ

3.4 การเรียกโมเดลครั้งที่สอง: ค่าอะไร?

การเรียกที่สองขอค่าของอาร์กิวเมนต์ที่กรอกได้ของเครื่องมือที่เลือก พร้อมชนิด choices และค่าเริ่มต้น และโฟลเดอร์ที่ผู้ใช้ให้ prompt ห้ามแต่งค่าหรือพาธขึ้นเอง ค่าเริ่มต้นไม่ถูกคัดลอกลงในข้อเสนอ และอาร์กิวเมนต์ที่จำเป็นที่ยังไม่มีค่าถูกแสดงเป็นขาด ไม่เคยเดา

ในโค้ดprompt ของ extraction กฎการตรวจสอบ และการแปลงบูลีน ตัวเลข และลิสต์

3.5 สิ่งที่ถูกเปิดใช้

เมื่อทุกเงื่อนไขเป็นจริง เครื่องมือที่เลือกรันเป็นการเรียกภายใต้ supervisor ตามปกติในสภาพแวดล้อมของตัวเอง ด้วยอาร์กิวเมนต์ที่ตั้งชื่อ และผลลัพธ์ของมันไปอยู่ในโฟลเดอร์ run/ ภายในผลลัพธ์ของ Agent เอง สิ่งที่มันคืนถูกบันทึกในไฟล์การตัดสินใจ หากเรียกเครื่องมือนอกเซิร์ฟเวอร์โดยไม่มี supervisor การขอให้รันเป็นข้อผิดพลาด โมเดลที่เลือก Agent เองจะถูกการตรวจวงจรของ supervisor หยุดตอนรัน

ในโค้ดประตูในโค้ด การเรียกภายใต้ supervisor และการปฏิเสธวงจร

3.6 โหมด Ask

ในโหมด Ask การเรียกโมเดลหนึ่งครั้งด้วย prompt ของ advisor และรายการผู้สมัคร ไม่บังคับเป็น JSON สร้างคำตอบ Markdown ที่เขียนลง advice.md ไม่มีอะไรถูกเสนอหรือรัน ไม่ว่า execute จะบอกอย่างไร ค่าโหมดอื่นใดถูกถือเป็นโหมด Agent เซิร์ฟเวอร์ตรวจชื่อที่อนุญาตสองชื่อก่อนเรียกเครื่องมือ

ในโค้ดการเรียก advisor การทดสอบโหมด และลำดับของการตรวจ

3.7 ผลลัพธ์

ไฟล์สิ่งที่มันเก็บ
routing.jsonการตัดสินใจ: เครื่องมือ ค่าอาร์กิวเมนต์ confidence เหตุผล ผู้สมัครอื่นพร้อมคะแนนจัดอันดับ ค่าที่จำเป็นที่ขาด ข้อผิดพลาด และมีอะไรถูกรันหรือไม่
Agent_report.jsonสิ่งที่เครื่องมือเห็น: แหล่งและขนาดของแค็ตตาล็อก ผู้สมัครและคะแนน endpoint โมเดล การตั้งค่า sampling คำเตือน ระยะเวลา
advice.mdเฉพาะโหมด Ask: คำตอบที่เขียน
run/ผลลัพธ์ของเครื่องมือที่รัน ถ้ามี

ทางเลือกที่แสดงคือผู้สมัครถัดไปของการจัดอันดับ ไม่ใช่ทางเลือกที่โมเดลเสนอ

ในโค้ดคีย์ที่แน่นอนของไฟล์ JSON ทั้งสองและบรรทัดที่เขียนมัน

6. สภาพแวดล้อม

  • Python 3.11 ไม่มี dependency นอกไลบรารีมาตรฐาน การเชื่อมต่อกับ Ollama ใช้ HTTP ธรรมดา
  • เซิร์ฟเวอร์ Ollama ที่ pull qwen3:8b (หรือแท็กที่เลือก) ไว้แล้ว ไม่อยู่ใน image และไม่อยู่ใน VISOR-serve
  • ไม่มีข้อมูลที่โฮสต์ ไม่มีทรัพยากรที่ประกาศ อนุญาต 300 วินาทีต่อการเรียกโมเดล

โมดูล legacy ดาวน์โหลดและเริ่มไบนารี Ollama เอง และ pull โมเดลตามต้องการ (โมเดลภาษา) เครื่องมือเซิร์ฟเวอร์ไม่ทำทั้งสองอย่าง สำเนาฝั่งไคลเอนต์ยังพึ่ง Ollama ในเครื่องและ cross-encoder ใน Python ของ Slicer

7. สิ่งที่เปลี่ยนไปจากตรรกะ legacy

หัวข้อLegacy (3c67957)เครื่องมือเซิร์ฟเวอร์ VISOR
แค็ตตาล็อกmanifest ที่เขียนด้วยมือ 16 รายการregistry สดของเซิร์ฟเวอร์
การจัดอันดับCross-encoder, 3 อันดับแรกBM25 การจัดอันดับที่ไม่มีสัญญาณเก็บทุกเครื่องมือไว้
การจัดอันดับล้มเหลวเครื่องมือสามตัวแรกของไฟล์ อย่างเงียบ ๆข้อผิดพลาด ไม่เคยเป็นการเดาอย่างเงียบ ๆ
การทดสอบโหมดโหมด Agent ถ้าข้อความตรงทุกตัวอักษร มิฉะนั้นเป็นที่ปรึกษาโหมด Ask ทดสอบก่อน อย่างอื่นทั้งหมดเป็น Agent
โฟลเดอร์สตริงเดียวที่แยกด้วยจุลภาคลิสต์จริง จุลภาคในชื่อจึงไม่แยกมันอีกต่อไป
คำตอบของ routerชื่อถูกส่งตรงเข้าตัวสร้างคำสั่งตรวจกับผู้สมัคร มิฉะนั้น “ไม่มีเครื่องมือ”
การทำงานกล่องโต้ตอบ ใช่/ไม่ แล้วอาร์กิวเมนต์ตามตำแหน่งอาร์กิวเมนต์ execute บวกการปฏิเสธสามกรณี อาร์กิวเมนต์ที่ตั้งชื่อผ่าน supervisor
ลูปซ่อมซ่อมได้สูงสุด 2 ครั้งไม่มีในเครื่องมือเซิร์ฟเวอร์ คงไว้ในสำเนาฝั่งไคลเอนต์
Ollamaไบนารีที่โมดูลดาวน์โหลดและเริ่มเองไม่เคยติดตั้ง เริ่ม หรือ pull
ประวัติJSON ที่รูปแบบผิดกลายเป็นประวัติว่างอย่างเงียบ ๆข้อผิดพลาดที่ชัดเจน
การตรวจสอบทดสอบนามสกุลกับชื่อที่มี “folder” หรือ “dir” ฉีดค่าเริ่มต้นชนิดและ choices เทียบกับ schema จริง ไม่เพิ่มค่าเริ่มต้น
ข้อความ promptคำอธิบายถูกตัดที่ 140 อักขระ 8 แท็กข้อความเต็ม

8. ปัญหาที่ทราบ

  • เครื่องมือเซิร์ฟเวอร์ที่ไม่มีไคลเอนต์ ไคลเอนต์ที่ไม่มีเครื่องมือเซิร์ฟเวอร์ ไม่มีแผงใดเข้าถึงเครื่องมือเซิร์ฟเวอร์ และแผงไคลเอนต์ไม่เคยติดต่อเซิร์ฟเวอร์ หลักฐาน
  • การรันปิดเป็นค่าเริ่มต้น พร้อมการปฏิเสธสามกรณี นี่คือการป้องกัน ไม่ใช่ปัญหา หลักฐาน
  • ไม่มีการตรวจตอนเริ่มว่าเครื่องมือที่เรียกมีอยู่จริง ชื่อมาจาก registry และ Agent เองไม่ถูกตัดออก การเรียกตัวเองจะถูกปฏิเสธตอนรัน หลักฐาน
  • พาธยังเป็นคำของโมเดล ไม่มีอะไรตรวจว่าพาธที่เสนอมีอยู่จริงหรือเป็นชนิดที่ถูกต้อง เครื่องมือที่รันเป็นตัวรายงานพาธผิด หลักฐาน
  • สำเนาฝั่งไคลเอนต์ยังมีข้อบกพร่องของ legacy: cross-encoder ถอยอย่างเงียบ ๆ Slicer ค้างระหว่างงาน สคริปต์โมดูลที่ไม่ได้ส่งมอบอีกต่อไป หลักฐาน
  • manifest ของสำเนาฝั่งไคลเอนต์ล้าสมัย: ระบุ MedX ซึ่งไม่มีอยู่อีกต่อไป และระบุ MRI2CBCT ไม่ได้ หลักฐาน

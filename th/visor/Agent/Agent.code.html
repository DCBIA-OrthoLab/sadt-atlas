3.1 แค็ตตาล็อก อ่านจาก GET /tools

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

เอเจนต์ legacy มี manifest ของเครื่องมือและพารามิเตอร์ที่เขียนด้วยมือเอง ซึ่งเลื่อนหลุดจากเครื่องมือจริง เครื่องมือเซิร์ฟเวอร์รับแค็ตตาล็อกเป็นอินพุต (catalog.py:1-23,52-83):

  1. catalog_file ไฟล์ JSON ที่เก็บสิ่งที่ GET /tools คืน ถ้าระบุ
  2. มิฉะนั้น <SADT_API>/tools อ่านด้วย urllib โดยไม่มี token (catalog.py:86-100) SADT_API คือที่อยู่ของเซิร์ฟเวอร์เองที่เห็นจากเครื่องมือ (VISOR-serve server/config.py:75, server/execution/dispatch.py:575)
  3. ไม่มีทั้งสอง: CatalogError ที่ระบุทั้งสองอย่าง และ 422

normalise รับลิสต์หรือ {"tools": [...]} และปฏิเสธอย่างอื่น แค็ตตาล็อกว่าง ชื่อสองชื่อที่เหมือนกันเมื่อไม่สนตัวพิมพ์และตัวคั่น ชนิดอาร์กิวเมนต์นอกเหนือจาก path, str, int, float, bool และลิสต์ของมัน และ choices ที่ไม่ใช่ลิสต์ (catalog.py:103-223) สำหรับแต่ละอาร์กิวเมนต์ มันเก็บชนิด แฟล็กจำเป็น คำอธิบาย choices ค่าเริ่มต้น และคีย์การนำเสนอ hidden, label, section อาร์กิวเมนต์ที่โมเดลกรอกได้คือตัวที่ไม่ใช่ output_dir และไม่ถูกซ่อน (fillable_arguments, catalog.py:250-262) ไม่มีอะไรใน catalog.py ที่ตัด Agent เองออกจากแค็ตตาล็อก

3.2 การเลือกผู้สมัคร

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

เครื่องมือแต่ละตัวกลายเป็นถุงคำจากชื่อ (น้ำหนัก 4) คำอธิบาย (3) และชื่อกับคำอธิบายของอาร์กิวเมนต์ (1) พร้อมตารางคำพ้องความหมายของคำศัพท์ ไม่ใช่ของเครื่องมือ (ranking.py:32-110,148-169) คำขอถูกให้คะแนนด้วย BM25:

idf  = log(1 + (N - df + 0.5) / (df + 0.5))
norm = K1 * (1 - B + B * len(doc) / avg_len)          # K1 = 1.2, B = 0.4
score += weight * idf * tf * (K1 + 1) / (tf + norm)   # ranking.py:183-219

ในผลรวมนั้น tf คือจำนวนที่ถ่วงน้ำหนักของคำในเอกสาร: แต่ละครั้งที่ปรากฏเพิ่ม 4, 3 หรือ 1 ตามช่อง (ranking.py:156-168) และ len(doc) คือผลรวมของน้ำหนักเหล่านั้น (:194) weight คือน้ำหนักของคำในคำขอ: 1.0 สำหรับคำที่พิมพ์ 0.55 (SYNONYM_DISCOUNT, :43,171-180) สำหรับคำที่เพิ่มจากกลุ่มคำพ้องความหมาย (:207,215)

select_candidates เก็บ candidates อันดับแรก (8 เป็นค่าเริ่มต้น) แต่คืนแค็ตตาล็อกทั้งหมดเมื่อ candidates เป็น 0 ครอบคลุมแค็ตตาล็อก หรือเมื่อไม่มีเครื่องมือใดได้คะแนนเหนือศูนย์ (ranking.py:222-239) การที่มันคัดให้แคบลงหรือไม่ถูกบันทึกเป็น candidates_narrowed ในรายงาน cross-encoder ของ legacy เมื่อล้มเหลวจะคืนเครื่องมือสามตัวแรกตามลำดับในไฟล์ (legacy Agent_CLI/Agent_CLI_utils/utils.py:94)

3.3 การเรียก Router

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

POST /api/chat หนึ่งครั้งด้วย stream: false, keep_alive: "30m", format: "json" และ options {temperature, seed} (llm.py:45,62-103) system prompt ขอออบเจกต์ JSON หนึ่งตัว {"tool", "confidence", "reason"} เครื่องมือที่เลือกจากรายการ CANDIDATES เท่านั้น และ null พร้อม confidence 0.2 หรือต่ำกว่าเมื่อไม่มีตัวใดเหมาะ (prompts.py:15-30) ผู้สมัครถูกเขียนครบถ้วน โดยไม่มีการตัดที่ 140 อักขระแบบ legacy (prompts.py:1-8,67-103) parse_json_object ตัดบล็อก <think> และ code fence ออก แล้วเอาออบเจกต์ที่สมดุลตัวแรก (llm.py:131-181) จากนั้น choose_tool ตรวจชื่อ (routing.py:22-55):

  • null, "null" หรือ "None": ไม่มีเครื่องมือ
  • ชื่อที่พบในหมู่ผู้สมัคร ตรงตัวหรือหลังการทำให้เป็นบรรทัดฐาน (catalog.find_tool, catalog.py:236-247): เลือก
  • อย่างอื่นทั้งหมด: ไม่มีเครื่องมือ confidence ถูกจำกัดที่ 0.2 และชื่อนั้นถูกบันทึกเป็น rejected_tool_name พร้อมคำเตือน (__init__.py:197-222)

3.4 การเรียก extraction และการตรวจสอบ

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

การเรียกที่สองขอ {"extracted": {...}, "confidence", "notes"} พร้อมอาร์กิวเมนต์ที่กรอกได้ของเครื่องมือที่เลือก ชนิด choices และค่าเริ่มต้นของมัน และโฟลเดอร์ (routing.py:58-84, prompts.py:32-48,105-140) prompt ห้ามแต่งค่าหรือพาธขึ้นเอง จากนั้น validation.validate (validation.py:39-77):

  • ทิ้งชื่อใดที่เครื่องมือไม่รับ และบอกไว้
  • ถือ null เป็น "ไม่ได้ระบุ"
  • แปลงบูลีนจาก true/yes/y/1/on และตรงข้ามของมัน จำนวนเต็มและทศนิยม ลิสต์ และตรวจ choices (validation.py:80-209) ความล้มเหลวคือข้อผิดพลาดในการตัดสินใจ และค่านั้นถูกทิ้ง

8. ข้อค้นพบใน VISOR

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

เครื่องมือเซิร์ฟเวอร์ที่ไม่มีไคลเอนต์ ไคลเอนต์ที่ไม่มีเครื่องมือเซิร์ฟเวอร์

เครื่องมือเซิร์ฟเวอร์ไม่สามารถเข้าถึงได้จากแผงใด ๆ และแผงไคลเอนต์ไม่เคยติดต่อเซิร์ฟเวอร์ ไม่มีอะไรใน AutomatedDentalToolsRemote สร้างคำขอสำหรับ Agent และ AgentRemote.py ไม่ import ServerToolsCoreLib ทั้งสองใช้ชื่อและแท็กโมเดลร่วมกัน ไม่มีอะไรอื่น

การรันปิดเป็นค่าเริ่มต้น พร้อมการปฏิเสธสามกรณี

execute มีค่าเริ่มต้นเป็น false (__init__.py:43) เมื่อเป็น true การรันยังถูกปฏิเสธหากไม่ได้เลือกเครื่องมือ หากขาดอาร์กิวเมนต์ที่จำเป็น หรือหาก confidence ต่ำกว่า 0.5 (routing.py:104-125) คอมเมนต์ในซอร์สเรียกเกณฑ์นั้นว่าเกณฑ์ขั้นต่ำกันโมเดลที่ยอมรับว่ากำลังเดา ไม่ใช่เกณฑ์คุณภาพ (routing.py:16-19)

ไม่มีการตรวจตอนเริ่มว่าเครื่องมือที่เรียกมีอยู่จริง

การเรียกถูกเขียนเป็น supervisor.run(...) แทน sup.run(...) โดยตั้งใจ เพื่อไม่ให้ตัวสร้าง schema บันทึก dependency แบบตายตัว (execution.py:9-29,68-70) ชื่อที่ไปถึงมันมาจากแค็ตตาล็อก ชื่อจึงดีได้เท่า registry ที่อ่านมา แค็ตตาล็อกไม่ได้ตัด Agent ออก การเรียกตัวเองจะถูกการตรวจวงจรของ supervisor ปฏิเสธ (VISOR-serve server/execution/runner.py:1814-1817) ตอนรัน

พาธยังเป็นคำของโมเดล

พาธเดียวที่โมเดลเห็นคือ folders และมันถูกบอกให้ใช้ตามตัวอักษร (prompts.py:32-48) แต่ไม่มีอะไรตรวจว่าพาธที่เสนอมีอยู่จริงหรือเป็นชนิดที่ถูกต้อง: schema บอก path โดยไม่บอกว่าเป็นไฟล์หรือโฟลเดอร์ และการตรวจนามสกุลของ legacy ถูกตัดออกโดยตั้งใจ (validation.py:9-17) เครื่องมือที่รันเป็นตัวที่รายงานพาธผิด บนเซิร์ฟเวอร์ พาธเหล่านั้นก็เป็นพาธของเซิร์ฟเวอร์ ไม่ใช่ของผู้ใช้ อ่านจากโค้ด

สำเนาฝั่งไคลเอนต์ยังมีข้อบกพร่องของ legacy

AgentRemote และ Agent_CLIRemote เป็นดีไซน์ legacy ข้อค้นพบของ legacy (ข้อควรระวังของ legacy) จึงยังใช้กับมัน: cross-encoder ยังถอยไปใช้เครื่องมือ k ตัวแรก (Remote Agent_CLIRemote/Agent_CLIRemote_utils/utils.py:94) งานยังรันแบบซิงโครนัสบน thread ของ Slicer (AgentRemote.py:767) พาธของโมดูลยังถูกหาผ่าน AGENT_CLI_TOOLS_DIR (utils.py:150-156) ในขณะที่โมดูล CLI ที่ manifest ระบุถูกลบออกจากส่วนขยายแล้ว (Remote CMakeLists.txt:49-56) อ่านจากโค้ด ไม่ได้รันใน Slicer

manifest ของสำเนาฝั่งไคลเอนต์ล้าสมัย

Agent_CLIRemote/manifest.yaml ระบุ medx_dashboard และ medx_summarize (บรรทัด 491 และ 509) ทั้งที่ MedX ไม่มีอยู่ในที่เก็บโค้ดใดอีกต่อไป (ดู MedX) และมันระบุ MRI2CBCT ซึ่งไม่ได้ build ไม่ได้

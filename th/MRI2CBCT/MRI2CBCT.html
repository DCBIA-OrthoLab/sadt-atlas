MRI2CBCT

การลงทะเบียนภาพ MRI → CBCT ของ TMJ ด้วยปุ่มเดียว โมดูลจับคู่โฟลเดอร์ MRI กับโฟลเดอร์ CBCT จัดแนว CBCT แต่ละชุด ทำนายฐานกะโหลกบนภาพสแกนทั้งสองด้วยเครือข่ายสองตัว แล้วลงทะเบียนสองพื้นผิวที่ทำนายได้ด้วย FPFH + RANSAC + ICP (Open3D) และไต่บันไดการกู้คืนเมื่อผลออกมาเป็น flip ตัวภาพเองไม่เคยถูกนำมาเปรียบเทียบกัน

Leroux 2024 · รุ่นก่อนหน้า, CLIP, LNCS 15196 MRI2CBCT_* CLI 3 ตัว + ยืมมา 4 ตัว Python ของ Slicer ไม่ใช้ conda บรรณานุกรม

ตั้งแต่ PR #277 และ #278 โมดูลเป็นแผงเดียว (MRI2CBCT.py, 753 บรรทัด) บนแพ็กเกจที่ไม่พึ่ง Slicer คือ MRI2CBCT_core/ เจ็ดขั้นตอนถูกต่อโซ่ด้วยปุ่ม Run ปุ่มเดียว: CLI ของตัวเอง 3 ตัว (MRI2CBCT_PREPARE, MRI2CBCT_SEGMENT_MRI, MRI2CBCT_REGISTER) และยืมมา 4 ตัวจาก ASO, ALI และ AMASSS เครือข่ายตระกูล nnU-Net สองตัวแบ่งส่วนฐานกะโหลก ตัวหนึ่งบน CBCT และอีกตัวบน MRI ส่วนที่เหลือหลังจากนั้นเป็นเรขาคณิตบนกลุ่มจุดสองกลุ่ม การรันหยุดได้หลังทุกขั้นเพื่อให้แพทย์ตรวจ

1. ตำแหน่งใน pipeline

ไม่มีใครเรียก CLI ใหม่ทั้งสามตัวนอกจากแผงของโมดูลเอง: การค้นหา MRI2CBCT_PREPARE, MRI2CBCT_SEGMENT_MRI และ MRI2CBCT_REGISTER ทั่วทั้งส่วนขยายพบเฉพาะใน plan.py และโฟลเดอร์ของตัวมันเองเท่านั้น manifest ของ Agent ยังรู้จัก CLI ของ MRI2CBCT ตัวเดียวคือ mri2cbct_resample (Agent_CLI/manifest.yaml:491) และไม่รู้จักสามตัวนี้เลย โมดูลประกาศ dependencies = [] (MRI2CBCT.py:49): ไม่พึ่ง SlicerNNUNet อีกต่อไป nnU-Net มาจาก pip

4. การจับคู่และการเตรียม MRI

4.1 การจับคู่ด้วยรหัสผู้ป่วย

pair_folders (pairing.py:81) โมดาลิตีมาจากโฟลเดอร์ที่แพทย์เลือก ไม่เคยมาจากชื่อไฟล์ (pairing.py:3-4) รหัสคืออักษรนำหน้าตามด้วยตัวเลข ^([A-Za-z]+)[_\-\s]*0*(\d+) (pairing.py:12): P01, B038, A3_scan เลขศูนย์นำหน้าไม่นับ ดังนั้น P1 กับ P01 เป็นผู้ป่วยคนเดียวกัน และตัวพิมพ์เล็กใหญ่ก็ไม่นับเช่นกัน (patient_key, :27-32) นามสกุลที่ยอมรับคือ .nii.gz, .nii และ .nrrd (:11) ค้นหาแบบเรียกซ้ำ (list_images, :41-47)

ไฟล์หรือผู้ป่วยจะถูกตัดออกพร้อมข้อความเมื่อ: อ่านรหัสไม่ได้ มี MRI แต่ไม่มี CBCT มี CBCT แต่ไม่มี MRI หรือมี CBCT มากกว่าหนึ่งชุดสำหรับรหัสเดียวกัน (pairing.py:92, :98, :106, :109, :111-113) แผงแสดงรายการเหล่านั้นและขอการยืนยันก่อนดำเนินการต่อ (MRI2CBCT.py:350) ผู้ป่วยหนึ่งคนมี MRI ได้หนึ่งหรือสองชุด

โฟลเดอร์สลับกัน folders_swapped (pairing.py:73-78) อ่านเฉพาะ header ของไฟล์ไม่เกินสี่ไฟล์ต่อโฟลเดอร์ looks_like (:50-70) ตัดสินว่าไฟล์เป็น MRI ถ้า spacing ไม่เท่ากันทุกทิศเกินกว่า 2 เท่า หรือมีขนาดด้านใดต่ำกว่า 90 mm และเป็น CBCT ถ้า isotropic ภายใน 5% และกว้างอย่างน้อย 120 mm ทุกทิศทาง นอกจากนั้นคือ "neither" แล้วแผงจะเสนอให้สลับสองโฟลเดอร์ (MRI2CBCT.py:328-336)

4.2 การเตรียม MRI แต่ละชุด

MRI2CBCT_PREPARE.py ก่อนอื่นมันลบโฟลเดอร์ _steps/ ทั้งหมดของเอาต์พุต (:23-24) แล้วลิงก์ CBCT แต่ละชุดเข้า _steps/0_cbct_in/<PID> (symlink หรือคัดลอกถ้าลิงก์ไม่สำเร็จ :45-48) จากนั้นสำหรับไฟล์ MRI แต่ละไฟล์ถาม mri_prep.plan_joints ว่าวอลุ่มนี้คืออะไร header ของ MRI คงไว้ตามเดิม: ขั้น "Orient" ก่อนหน้าเขียนทับเมทริกซ์ทิศทางด้วยเมทริกซ์ตายตัว ซึ่ง "throws away the only record of which way the slices run" (mri_prep.py:3-6) โค้ดใหม่จึงอ่านพิกัดโลกจาก header ต้นฉบับ

  • ด้านจาก header side_from_header (mri_prep.py:64-66) ตัดสินว่าแผ่นเป็นข้าง LEFT ถ้าจุดศูนย์กลางในพิกัดโลกมี LPS x > 0 มิฉะนั้นเป็น RIGHT docstring ระบุว่ากฎนี้ถูกต้อง 355 จาก 355 ครั้งบนแผ่นข้อต่อเดียวที่ทราบด้านแล้ว (ผู้ป่วย 97 คน)
  • แผ่นสองข้างที่มีช่องว่าง NIfTI เก็บช่องว่างระหว่างสองชุดภาพไม่ได้ ไฟล์จึงกระจายสไลซ์ทั้งหมดอย่างเท่ากัน ตัวอย่างใน docstring คือ B038: 18 สไลซ์ที่ 6.876 mm ซึ่งจริง ๆ คือ 9 + 9 ที่ 3.0 mm โดยมี 69 mm คั่นกลาง มีเพียงสองสไลซ์ปลายสุดที่อยู่ถูกตำแหน่ง ดังนั้นแต่ละครึ่งจึงถูกสร้างใหม่ที่ระยะห่างของการถ่ายโดยยึดที่สไลซ์ปลายของตัวเอง (split_gapped, :90-128) โดยสมมติว่าสองชุดภาพมีจำนวนสไลซ์เท่ากัน ถ้าจำนวนเป็นเลขคี่จะเพิ่ม "check the split" ลงในหมายเหตุ (:150-151) ระยะห่างของการถ่ายคือช่องในแผง ค่าเริ่มต้น 3.0 mm
  • การ resample resample_iso (:20-42) นำวอลุ่มไปที่ 0.3 mm isotropic ซึ่งเป็น spacing ที่ Dataset516 ถูกฝึก (:12-13) ใช้ linear interpolation และคงขนาดทางกายภาพไว้: ขนาด = ขอบเขต / spacing docstring บันทึกว่า resampler รุ่นก่อนคงจำนวนวอกเซลไว้และทำให้แผ่น 100 × 100 × 30 mm หดเหลือ 76.8 × 76.8 × 3 mm
  • หนึ่งข้อต่อต่อหนึ่งด้าน MRI ชุดที่สองที่จะเป็นข้อต่อ L (หรือ R) ของผู้ป่วยเช่นกันจะถูกข้ามพร้อมข้อความ (MRI2CBCT_PREPARE.py:56-58)

เอาต์พุต: _steps/1_mri/<PID>_<S>_MRI.nii.gz โดย S = L, R หรือ B พร้อม manifest ที่ระบุต่อผู้ป่วยถึงพาธ CBCT และไฟล์ต้นทาง ด้าน และหมายเหตุของข้อต่อแต่ละข้าง (:38-40, :64-66)

7. การลงทะเบียนภาพ

ต่อผู้ป่วยหนึ่งคน MRI2CBCT_REGISTER โหลดมาสก์ฐานกะโหลกของ CBCT หนึ่งครั้งและ transform ของ ASO (MRI2CBCT_REGISTER.py:50-51) แล้วลงทะเบียนข้อต่อแต่ละข้างด้วย ladder.register_joint (:70-73) ตัวภาพไม่ถูกอ่านในจุดนี้: อินพุตมีเพียงสองมาสก์

7.1 พื้นผิว

  • มาสก์ MRI (mri_surface, ladder.py:131-147): threshold ที่ 0.5 ปฏิเสธมาสก์ที่ต่ำกว่า 50 วอกเซล เก็บองค์ประกอบเชื่อมต่อที่ใหญ่ที่สุด (6-connectivity) แล้วสุ่มตัวอย่างพื้นผิว ตัวกรององค์ประกอบถูกเรียกว่าจำเป็นใน surface.py:35-41 เพราะทิศของเวกเตอร์ตั้งฉากถูกส่งต่อข้ามกราฟการเชื่อมต่อ และเกาะที่แยกออกไปจะมีเวกเตอร์ตั้งฉากกลับด้าน ปริมาตรมาสก์เป็น cm³ ถูกเก็บไว้สำหรับ QC (§7.3)
  • มาสก์ CBCT (cbct_surface, :150-157): threshold และการสุ่มตัวอย่างเหมือนกัน แต่ไม่มีตัวกรององค์ประกอบ
  • จุดบนพื้นผิว (surface_points_normals, surface.py:10-30): วอกเซลของมาสก์ลบด้วยการ erosion ของมัน สุ่มย่อยเหลือ 20 000 จุดด้วย random seed คงที่ (NPTS, reg/pipeline.py:14) พิกัดโลกใน RAS เวกเตอร์ตั้งฉากจาก gradient ของมาสก์ที่ทำให้เรียบด้วย σ = 1.5 วอกเซล
  • การตัดตามด้าน (side_cut, ladder.py:94-102): สำหรับข้อต่อที่ติดป้าย L หรือ R พื้นผิว CBCT เก็บจุดจนถึง MARGIN = 5 mm เลยค่ามัธยฐาน x ของพื้นผิวทั้งหมดในด้านที่สแกน (RAS +x คือด้านขวาของผู้ป่วย) นี่คือสิ่งที่ทำให้ลงทะเบียนภาพแผ่น MRI ข้อต่อเดียวกับ CBCT ทั้งศีรษะได้ ข้อต่อที่ติดป้าย B (ทั้งวอลุ่ม) ใช้พื้นผิวทั้งหมด

  1. ขั้น 0 การลงทะเบียนภาพที่ published (:205-216): 50 รอบสุ่ม ถ้าท่าที่ดีที่สุดไม่ใช่ FLIP ผลลัพธ์ถูกยอมรับตามนั้น
  2. สุ่มเพิ่ม (:221-227): สุ่มเพิ่มอีก EXTRA_DRAWS = 100 รอบ เก็บท่าที่ผ่านดีที่สุดจากทั้ง 150 รอบ
  3. หมุน 180° (:229-242): ท่าที่ flip ประกอบกับการหมุนครึ่งรอบรอบแต่ละแกนทั้งสาม (rot180, :105-113) รอบจุดเซนทรอยด์ของพื้นผิว MRI แต่ละท่าถูกปรับละเอียดด้วย ICP แบบ point-to-plane ขนานกัน
  4. อีกด้าน (:244-254) เฉพาะ L หรือ R: CBCT ถูกตัดเป็นซีกตรงข้ามและลอง 50 รอบสุ่ม เพราะ "the MRI side label may be wrong" ถ้าผ่าน ข้อต่อจะถูกเปลี่ยนป้ายใหม่ (side L → R) ใน log และ summary
  5. กลับด้านกระจก (:256-267): พื้นผิว MRI ถูกสะท้อนข้ามระนาบที่ตั้งฉากกับแกนดัชนีซ้าย-ขวาผ่านเซนทรอยด์ของมัน (mirror_matrix, :116-124) แล้วลงทะเบียนภาพอีกครั้ง การสะท้อนถูกประกอบเข้าใน transform ที่รายงาน มัน "fixes a left-right handedness error in the file itself; a wrong mirror fits visibly badly" QC ให้คะแนนบนส่วนแข็งเกร็ง เพราะ qc_tag อ่านการหมุนจากการสะท้อนไม่ได้ (:260-261)

12.1 Open3D บน Linux

Open3D ต้องการโฟลเดอร์ของตัวเองบน Linux: pip ของ Slicer จำกัดแท็ก manylinux ไว้ที่ 2_28 ขณะที่ wheel ของ Open3D เป็น 2_31 (env.py:12-15) wheel ทำงานได้บน glibc 2.31 ขึ้นไป แผงจึงตรวจ glibc ของระบบ (รุ่นที่เก่ากว่าจะยกข้อผิดพลาด "Open3D needs glibc 2.31 or newer", MRI2CBCT.py:612-615) และติดตั้งด้วย --no-deps --only-binary :all: --platform manylinux_2_31_x86_64 --target <py_deps> (:618-621); ระบบอื่นใช้ pip_install ธรรมดา (:623) Open3D ถูกตรวจพบบนดิสก์ ไม่ใช่ด้วยการ import เพราะ Slicer ที่กำลังรันอยู่คง open3d ที่ import ไปแล้วไว้แม้โฟลเดอร์ของมันถูกลบ ขณะที่ CLI แต่ละตัวเริ่มอินเทอร์พรีเตอร์ใหม่ (env.py:67-78) ตอนรัน ensure_open3d ใช้สำเนาของอินเทอร์พรีเตอร์เอง ไม่เช่นนั้นใช้ py_deps โดยต่อท้าย sys.path เพื่อให้ numpy และ SciPy ของ Slicer ชนะ (env.py:81-94) ladder.py เรียกมันตอน import ดังนั้น MRI2CBCT_REGISTER จึงล้มเหลวทันทีพร้อม "Open3D is not installed" หากไม่มีทั้งสองแบบ; ตัวแผงเองไม่ import ladder และเปิดได้โดยไม่มี Open3D

13. วรรณกรรม

บทความที่เชื่อมโยงจากเครื่องมือนี้คือ Novel CBCT-MRI Registration Approach for Enhanced Analysis of Temporomandibular Degenerative Joint Disease, Leroux G. et al., Clinical Image-Based Procedures (CLIP 2024), LNCS vol. 15196, Springer ตามที่บรรณานุกรมของโฟลเดอร์นี้อ่านจากบทคัดย่อ บทความอธิบายลำดับขั้นของรุ่นก่อนหน้า: การจัดแนวอัตโนมัติ การ resample การกลับค่า MRI การทำให้เป็นมาตรฐาน แล้วการลงทะเบียนภาพแบบแข็งเกร็งด้วย mutual information นั่นไม่ใช่สิ่งที่โค้ดทำอีกต่อไป การลงทะเบียนภาพปัจจุบันเป็นการค้นหาแบบทั่วทั้งภาพบนสองพื้นผิวที่ทำนายได้ และไม่ใช้ความเข้มเลย รายงาน NA-MIC สองฉบับที่เก็บไว้ข้างหน้านี้ก็เช่นกัน: PW43 (2025) เป็นรุ่น TorchReg บวก elastix ส่วน PW45 (2026) ระบุการแก้ไขสำหรับรุ่นนั้น และขั้นต่อไปคือการประมาณอัตโนมัติที่ทนทานกว่า capture range ของ elastix ที่กว้างขึ้น และการตรวจสอบด้วย target registration error

ไม่มีเอกสารใดในโฟลเดอร์ที่อธิบาย FPFH, RANSAC หรือบันได คอมเมนต์ในโค้ดพูดถึงการตั้งค่าที่ "published" สถิติของกลุ่มตัวอย่าง (5 จาก 46 เทียบกับ 0 จาก 172, reg/pipeline.py:22-23) และสคริปต์นอกที่เก็บโค้ด (run_02_register_w48.py, run_03_export.py, snap_icp.py, itk_io.py:10, surface.py:3-5); บรรณานุกรมไม่พบงานตีพิมพ์ใดที่รองรับสิ่งเหล่านี้ นั่นเป็นคำถามสำหรับผู้ดูแล ไม่ใช่สิ่งที่หน้านี้ตัดสินได้ FPFH (Rusu et al., ICRA 2009) และ Open3D (Zhou et al., 2018) เป็นการอ้างอิงตามปกติของส่วนประกอบเหล่านี้ ทั้งสองไม่ได้ดึงมาที่นี่

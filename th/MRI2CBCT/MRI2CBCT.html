MRI2CBCT

การลงทะเบียนภาพ (registration) ต่างชนิดแบบแข็งเกร็ง (rigid) MRI → CBCT ของ TMJ ด้วย elastix (Mattes mutual information) ต่อท้ายขั้นเตรียมข้อมูลที่แยกอิสระกันห้าขั้น โครงข่ายเพียงตัวเดียวทำหน้าที่แบ่งส่วน condyle บน CBCT เพื่อให้ได้จุดยึด — ตัวมันเองไม่ได้ลงทะเบียนภาพใด ๆ

Leroux 2024 · CLIP, LNCS 15196 CLI MRI2CBCT_* 6 ตัว Python ของ Slicer ไม่ใช้ conda บรรณานุกรม

การลงทะเบียนภาพต่างชนิดแบบแข็งเกร็ง MRI → CBCT ของ TMJ ประกอบด้วยหกขั้นตอนที่แยกอิสระกัน แต่ละขั้น มีปุ่มและ CLI ของตัวเอง และจบด้วยการลงทะเบียนภาพแบบแข็งเกร็งด้วย elastix โดยใช้ mutual information โครงข่ายเพียงตัวเดียวของโมดูลคือ nnU-Net ที่แบ่งส่วน condyle บน CBCT: ไม่ได้มีส่วนในการลงทะเบียนภาพโดยตรง แต่ให้ จุดยึดและกล่องสำหรับครอป

1. ตำแหน่งใน pipeline

ไม่มีสิ่งใดในคลังโค้ดเรียก MRI2CBCT และ MRI2CBCT ก็ไม่เรียกโมดูลอื่นใดใน ส่วนขยาย โมดูลประกาศว่าขึ้นกับ SlicerNNUNet (MRI2CBCT.py:150) แต่ไม่เคย import: สิ่งที่ถูกเรียกคือ executable nnUNetv2_predict ซึ่งรันเป็น subprocess

slicer.modules.fiducialregistrationslicer.cli.runSyncตอนจบการประมาณตำแหน่งอัตโนมัติ

คอมเมนต์ที่ส่วนบนของ MRI2CBCT_CLI_utils/__init__.py อ้างว่า resample_images ถูกใช้โดย AREG_IOSCBCT และ VFACE แต่การ grep ทั่วทั้งคลังโค้ดไม่พบผู้เรียกใดนอก MRI2CBCT_CLI การ import แบบ lazy ยังมีประโยชน์อยู่ (เลี่ยงการดึง torchreg เข้ามาสำหรับการ resample ธรรมดา) แต่ เหตุผลที่ระบุไว้ใช้ไม่ได้อีกต่อไป

3. ลำดับของ pipeline และสิ่งที่จำเป็นจริง

[MRI orientation/centering] → [L/R crop] → resample → approximation → [TMJ crop] → registration

ปุ่มหกปุ่มที่แยกอิสระกัน: ไม่มีสิ่งใดในโค้ดควบคุมลำดับหรือที่มา ของไฟล์ ข้อบังคับที่เข้มงวดมีเพียงข้อเดียวคือข้อบังคับของขั้นการลงทะเบียนภาพ

ขั้นสถานะเหตุผล
การจัดแนว / จัดกึ่งกลาง MRIจำเป็นโดยพฤตินัยelastix เริ่มโดยไม่มี transform ตั้งต้น และใช้ความละเอียดระดับเดียว
ครอป L/Rทางเลือกภาพสองข้าง สร้าง suffix left/right ที่ขั้น resample อ่านกลับ
Resampleจำเป็นในทางปฏิบัติMRI และ CBCT ต้องมี spacing ที่เทียบกันได้ และเป็นขั้นที่จัดกึ่งกลางด้วย
การประมาณตำแหน่ง (อัตโนมัติหรือด้วยมือ)จำเป็นโดยพฤตินัยให้การจัดแนวหยาบที่ elastix หาเองไม่ได้
ครอป TMJทางเลือกลดขอบเขตภาพ
การลงทะเบียนภาพเป้าหมายต้องใช้ CBCT + MRI + segmentation ของ CBCT

คำว่า "จำเป็นโดยพฤตินัย" เห็นได้จากโค้ด: ElastixReg ถูกเรียกด้วย initial_transform=None และ NumberOfResolutions = 1 (AREG_MRI.py:61) และข้อความข้อผิดพลาดของ process_images ระบุว่า "PLEASE MAKE SURE THE IMAGES ARE OF SIMILAR SIZE, ORIENTATION, AND APPROXIMATED" อินพุตของการลงทะเบียนภาพยังต้องเป็นไปตาม แบบแผนการตั้งชื่อที่เข้มงวด ซึ่งตรวจโดย get_corresponding_file (AREG_MRI.py:98): <ID>_CBCT*.nii.gz, <ID>_MR*.nii.gz หรือ <ID>_MRI*.nii.gz และ mask <ID>_CBCT*.nii.gz รับเฉพาะ .nii.gz ไม่รับ .nii เลย

ข้อควรระวัง

ไม่มีสิ่งใดห้ามการรันการลงทะเบียนภาพโดยไม่ผ่านขั้น orientation, resample และการประมาณตำแหน่งมาก่อน: CLI จะรับไฟล์ และ elastix จะเบี่ยงออกไปเงียบ ๆ เพราะไม่ลู่เข้า โดยไม่มีข้อความใด แยกกรณีนี้ออกจากความล้มเหลว "ปกติ"

4. การจัดแนวและจัดกึ่งกลาง MRI

MRI2CBCT_ORIENT_CENTER_MRI.py, modify_image_properties ไม่มีการ resample: เป็นการเขียน header ใหม่ อาร์เรย์ วอกเซลไม่ถูกแตะต้อง มีเพียง Direction, Spacing[2] และ Origin ที่เปลี่ยน

  1. SetDirection(new_direction) — เมทริกซ์ 3×3 ที่สร้างจากตาราง checkbox แล้วแปลงเป็นลำดับแถวต่อแถวโดย getCheckboxValuesOrient (MRI2CBCT.py:847) ค่าเริ่มต้นคือ (0,0,-1, 1,0,0, 0,-1,0) (MRI2CBCT.py:866) ซึ่งเป็นค่าที่มีคอมเมนต์ "USE THIS DIRECTION FOR MRI" อยู่ท้าย CLI ตารางบังคับให้มี ±1 เพียงตัวเดียวต่อแถวและต่อคอลัมน์: เข้าถึงได้เฉพาะเมทริกซ์การเรียงสับเปลี่ยนแบบมีเครื่องหมาย 48 แบบ เท่านั้น
  2. Spacing[2] ถูกแทนด้วย acquisition_z_spacing หากเลือก Bilateral MRI (ค่าเริ่มต้น 3.0 mm อ่านจากแท็ก DICOM 0018,0088 แล้วจึง 0018,0050 ของโหนดที่เลือกเมื่อจำเป็น MRI2CBCT.py:733) มิฉะนั้นจะส่งสตริง "None" และคง spacing เดิมไว้ นี่คือทางแก้ชั่วคราวสำหรับ ภาพสองข้างที่ spacing ระหว่างสไลซ์สูญหายตอน แปลงเป็น NIfTI
  3. origin ใหม่: [(size[i]*spacing[i])/2] เรียงสับเปลี่ยนเป็น [o[2], -o[0], o[1]] มีคอมเมนต์ว่า "FOR MRI" การเรียงสับเปลี่ยนนี้ผูกอยู่กับเมทริกซ์ค่าเริ่มต้น: การเปลี่ยน direction โดยไม่เปลี่ยนส่วนนี้ด้วยจะทำให้วอลุ่มหลุดจากกึ่งกลาง

เอาต์พุต: <id>_OR.nii หรือ <id>_OR.nii.gz ตามนามสกุลของอินพุต

ข้อควรระวัง

การเรียงสับเปลี่ยน origin ในข้อ 3 สอดคล้องกับเมทริกซ์ direction ค่าเริ่มต้นเท่านั้น การเลือก checkbox ชุดอื่นโดยไม่ แก้การเรียงสับเปลี่ยนนี้จะทำให้วอลุ่มหลุดจากกึ่งกลาง

5.2 ครอป TMJ — MRI2CBCT_TMJ_CROP.py

  1. GetPatients จับคู่ CBCT / MRI / Seg ตามรหัส (TMJ_crop.py:24: การเรียก split ต่อกันยาวบน _Scan, _T1, _CBCT, _crop…) segmentation ไม่เคยสร้าง ผู้ป่วยขึ้นเองได้ ผู้ป่วยที่ขาดอย่างใดอย่างหนึ่งในสามอย่างจะถูกข้าม
  2. segment_condyle (§6) → mask ไบนารีในกรอบพิกัดของ CBCT ครึ่งนั้น
  3. กล่องล้อมรอบ: MARGIN = 3 วอกเซล แต่ FIXED_BBOX_VOXELS = [400,400,400] ทำงานอยู่ ทำให้ margin ไม่มีผล — กล่องเป็นลูกบาศก์ 400 วอกเซลที่มีจุดกึ่งกลางที่ centroid ของ mask และถูกจำกัดให้อยู่ในวอลุ่ม
  4. มุมทั้ง 8 ถูกแปลงไปยังพิกัดโลกผ่าน cbct_half.affine CBCT เต็มและ MRI ถูกครอปตามกล่องในพิกัดโลกนี้ แต่ละภาพบนกริดของตัวเอง (crop_by_world_corners ย้อนกลับผ่าน inverse affine ของแต่ละภาพ)
  5. CBCT และ segmentation ถูก resample ลงบนกริดของ MRI ที่ครอปแล้ว (nibabel.processing.resample_from_to, order=1 สำหรับ CBCT order=0 สำหรับ label)

เอาต์พุต: MRI/<id>_MRI_TMJ_crop<side>.nii.gz, CBCT/<id>_CBCT_TMJ_crop<side>.nii.gz, CBCT seg/<id>_Seg_TMJ_crop<side>.nii.gz, CBCT seg/<id>_Mask_TMJ_crop<side>.nii.gz, Mask/<id>_Mask_TMJ_<side>.nii.gz (mask ดิบ สำหรับตรวจดู) <id> คือโทเคน แรกของชื่อไฟล์ CBCT (stem.split(".")[0].split("_")[0]) ผู้ป่วยจะถูก ข้ามหากมี MRI/<id>_MRI_TMJ_crop*.nii.gz อยู่แล้ว

การประมวลผลภายหลัง: คำนวณ

mask = pred if pred.max() > 1 else (pred > PROBA_THR)   # PROBA_THR = 0.02
mask = biggest_cc(mask)                                  # scipy.ndimage.label

nnUNetv2_predict เขียน label map (ค่าความน่าจะเป็นถูกเขียนลง .npz ที่ไม่เคยถูกอ่านกลับ) ดังนั้น pred.max() เท่ากับ 1 และสาขาที่ทำงานจริง คือ threshold 0.02 หรือก็คือ "label ≠ 0" PROBA_THR จะมี ผลก็ต่อเมื่อเป็น probability map เท่านั้น ส่วนประกอบเชื่อมต่อที่ใหญ่ที่สุดถูกเก็บไว้: ผลลัพธ์คือ condyle เดียวแบบไบนารี

7. การ resample

MRI2CBCT_RESAMPLE_CBCT_MRI.py + resample.py มีโฟลเดอร์อินพุตหกโฟลเดอร์: MRI/CBCT/Seg × T1/T2 create_csv สำรวจแบบ recursive หาไฟล์ .nii, .nii.gz, .nrrd, .nrrd.gz, .gipl, .gipl.gz และบันทึกขนาดและ spacing ของแต่ละไฟล์

ค่าเริ่มต้นของตาราง (MRI2CBCT.py:543): 443 × 443 × 119 สไลซ์ spacing 0.3 × 0.3 × 0.3 mm ปิดแต่ละแถวได้ด้วย "Keep the same size / spacing as the input scan" (จากนั้นสตริง "None" จะถูกส่งให้ CLI)

อินพุตresample_sizeการประมาณค่าในช่วงหมายเหตุ
MRIค่าจากตารางlineariso_spacing=True ทำหน้าที่จริงเป็นแฟล็ก isMRI
CBCTบังคับเป็น "None"linearเปลี่ยนเฉพาะ spacing คงขนาดเดิมไว้
Segบังคับเป็น "None"nearest neighbor (linear=False)

การบังคับนี้มีคอมเมนต์อยู่ที่บรรทัด 163: การใช้ขนาดของ MRI กับ CBCT จะ ครอปทั้งกะโหลกให้เหลือเท่าขนาดวอลุ่ม MRI ที่เล็ก

ใน resample_fn:

  • fit_spacing=True (มีการกำหนดขนาดเป้าหมาย) → output_spacing = sp·si/o_si ขนาดทางกายภาพคงเดิม และจะถูกเขียนทับภายหลังหากมีการระบุ spacing อย่างชัดเจน
  • center → output_origin -= (output_physical_size − input_physical_size)/2 โดยสำหรับ MRI ค่าชดเชยจะถูกคูณด้วยเมทริกซ์ direction ก่อน
  • การสะท้อนภาพ: หากเป็น MRI และชื่อมีคำว่า right และ center เป็น false วอลุ่มจะถูกพลิกตามแกน Z (sitk.Flip [False,False,True]) ก่อน resample แล้วพลิกกลับหลังจากนั้น ด้านได้มาจากชื่อไฟล์ ที่ขั้นครอป L/R สร้างไว้
  • DefaultPixelValue = ค่าต่ำสุดของวอลุ่มอินพุต ไม่ใช่ 0: การเติมขอบใช้ ค่าพื้นหลังจริง
  • สาขา iso_spacing == "True" เปรียบเทียบบูลีนกับสตริง: เป็นโค้ดที่ไม่ถูกใช้งาน

เอาต์พุตอยู่ใน <output>/MRI, /CBCT, /Seg ชื่อไม่เปลี่ยน พาธเอาต์พุต คือ file_path.replace(dirname(file_path), output): โครงสร้างโฟลเดอร์อินพุตใด ๆ จะถูก ทำให้แบน ไฟล์สองไฟล์ชื่อเดียวกันจากโฟลเดอร์ย่อยต่างกันจะเขียนทับกัน เงียบ ๆ

ข้อควรระวัง

การทำโฟลเดอร์ย่อยให้แบนตอน resample ทำให้ไฟล์สองไฟล์ชื่อเดียวกัน จากโฟลเดอร์ย่อยต่างกันเขียนทับกันเงียบ ๆ ตัวจัดการข้อผิดพลาดที่ควรแจ้งปัญหานี้ ก็เสียอยู่เอง (§12)

8.1 เส้นทางอัตโนมัติ

CLI MRI2CBCT_APPROX ไม่ได้ลงทะเบียนภาพ ใด ๆ: สร้างคู่จุดและการหมุนหนึ่งค่า แล้ววิดเจ็ตทำงาน ส่วนที่เหลือ (CLI เข้าถึงโมดูลของ Slicer ไม่ได้) approximation() (approximate.py:77) ทำงานต่อคู่ CBCT/MRI แต่ละคู่ (เป็นโฟลเดอร์ หรือไฟล์เดียวหากอินพุตทั้งสองเป็นไฟล์ — โหมด "Scene Volume"):

  1. segment_condyle → mask ของ condyle แบบ ทำนาย บน CBCT ครึ่งที่ถูกต้อง
  2. จุดบน CBCT = centroid ของวอกเซลใน mask แบบ คำนวณ แปลงไปยังพิกัดโลก RAS ด้วย cbct_half.affine
  3. จุดบน MRI = world_center_of_mass จุดศูนย์กลางมวลของวอกเซลที่ไม่เป็นศูนย์ ทั้งหมดของ MRI ใน RAS
  4. การหมุน = compute_rotation_correction (approx_utils.py:38): ภาพทั้งสองผ่าน nib.as_closest_canonical ส่วน 3×3 ของแต่ละ affine ถูกทำให้ตั้งฉากด้วย SVD (U @ Vt) แล้วคืนค่า R_cbct @ R_mri.T หลังการ canonicalize ใหม่ กรอบพิกัด ทั้งสองก็ใกล้ RAS อยู่แล้ว: การหมุนนี้จึงจับเฉพาะส่วนตกค้างที่ไม่ ขนานกับแกน
  5. mri_point_rotated = R @ mri_point
  6. เขียน first_approximation/points/<id>_approx_points.json: patient_id, side, cbct_point_ras, mri_point_rotated_ras, rotation_ras, mri_path, cbct_path

จากนั้น finalizeApproximation() (Approx_MRI2CBCT.py:119) ถูกเรียกจาก onProcessUpdate เมื่อ module_name == "MRI2CBCT approximation" (MRI2CBCT.py:2166): fiducial แบบจุดเดียวสองชุด (fixed = จุดบน CBCT, moving = จุด MRI ที่หมุนแล้ว) ถูกส่งให้โมดูล fiducialregistration ของ Slicer ด้วย transformType = "Translation" เมทริกซ์ RAS 4×4 ถูกประกอบขึ้น (บล็อก 3×3 = การหมุนจาก JSON คอลัมน์ 3 = การเลื่อนตำแหน่ง) วอลุ่ม MRI ถูกโหลด วางไว้ใต้ transform นี้ hardenTransform แล้วเขียนออก

กล่าวอีกอย่างคือ การหมุนได้มาจาก header ส่วนการเลื่อนตำแหน่งได้มาจาก การจับคู่ centroid ของ condyle กับจุดศูนย์กลางมวลของ MRI โครงข่าย ทำหน้าที่เพียงให้จุดบน CBCT

9. การปรับมาตรฐานความเข้ม (normalization)

ตาราง 4 คอลัมน์ × 2 แถว (MRI, CBCT): Normalization Min/Max, Percentile Min/Max มีค่าเริ่มต้นสองชุด DefaultNorm (MRI2CBCT.py:1157):

ชุดค่าMRI [min, max, p_low, p_high]CBCT [min, max, p_low, p_high]
Default 1 (ใช้เมื่อเปิดโมดูล)[0, 100, 0, 100][0, 75, 10, 95]
Default 2[0, 100, 10, 95][0, 100, 10, 95]

สองบทบาทนี้แยกจากกัน (normalize_percentile.py):

  • percentile กำหนดหน้าต่างความเข้ม np.percentile ถูกคำนวณ บนอาร์เรย์ทั้งหมด รวมพื้นหลังด้วย — ไม่ใช่เฉพาะวอกเซลที่ไม่เป็นศูนย์ บน CBCT ที่ส่วนใหญ่เป็นอากาศ p10 จะตกอยู่ในพื้นหลัง และ p95 ตัด โครงสร้างที่หนาแน่นที่สุดทิ้ง
  • min_norm / max_norm กำหนดช่วงเอาต์พุต:
normalized = np.clip((array - lo) / (hi - lo), 0, 1)
scaled     = normalized * (max_norm - min_norm) + min_norm

ด้วย Default 1 MRI ถูกตั้งหน้าต่างที่ percentile [0, 100] — จึงเป็น การ normalize แบบ min–max ล้วนโดยไม่ตัดค่า แล้วปรับสเกลเป็น [0, 100] — ขณะที่ CBCT ถูกตั้งหน้าต่างระหว่าง p10 กับ p95 แล้วปรับสเกลเป็น [0, 75] ซึ่งตั้งใจ ให้ต่ำกว่า MRI ด้วย Default 2 ทั้งสองชนิดภาพได้รับการ จัดการแบบเดียวกัน

ในโค้ดมีวิธี normalization เพียงวิธีเดียว: ไม่มีการเลือกอัลกอริทึม มีเพียงตัวเลขสี่ตัวนี้ต่อชนิดภาพ CheckNormalization (Reg_MRI2CBCT.py:54) ตรวจเพียง max > min ของทั้งสองคู่ normalize() จัดการเฉพาะไฟล์ .nii.gz (ไฟล์ .nii ถูกข้ามเงียบ ๆ) และเขียน <name>_percentile=[lo,hi]_norm=[min,max].nii.gz: ชื่อไฟล์ยาวขึ้นทุกขั้น รวมทั้งวงเล็บเหลี่ยมและจุลภาค

การลงทะเบียนภาพขั้นสุดท้ายเป็น elastix แบบแข็งเกร็งที่ใช้ Mattes mutual information จริง ใช้ความละเอียดระดับเดียว 10,000 รอบ และ 10,000 ตัวอย่างที่สุ่ม ใหม่ทุกรอบ โดยไม่มี transform ตั้งต้น — สอดคล้อง กับที่บทความด้านวิธีการระบุไว้

สรุปคือ Mattes mutual information ตามที่คาดไว้สำหรับภาพต่างชนิด ความละเอียดระดับเดียว 10,000 รอบ 10,000 ตัวอย่างที่สุ่มใหม่ ทุกรอบ ไม่มี transform ตั้งต้น ErodeMask = "true" ไม่มีผล: SetFixedMask / SetMovingMask ไม่เคยถูกเรียก เพราะการใส่ mask ทำไปแล้ว ก่อนหน้าด้วยการตั้งค่าวอกเซลเป็นศูนย์

MatrixRetrieval สร้าง sitk.Euler3DTransform ขึ้นใหม่จาก TransformParameters 6 ค่า (มุม 3 ค่า การเลื่อน 3 ค่า) ComputeFinalMatrix ประกอบ list ใหม่ ซึ่งในที่นี้มีสมาชิกเดียว จึงไม่มีผล

บั๊กที่ยืนยันแล้ว

MatrixRetrieval อ่าน TransformParameters แต่เพิกเฉย CenterOfRotationPoint ที่ parameter map เอาต์พุตของ elastix มีอยู่ด้วย sitk.Euler3DTransform ที่สร้างขึ้นใหม่จึงหมุนรอบจุดกำเนิด transform ที่เขียนออกและนำไปใช้จะตรงกับที่ elastix ประมาณได้จริง ก็ต่อเมื่อจุดศูนย์กลางการหมุนนี้อยู่ที่จุดกำเนิดเท่านั้น — ซึ่ง ไม่รับประกัน โค้ดคัดลอกมาทั้งหมดจาก AREG_CBCT/AREG_CBCT_utils/utils.py:830: ปัญหานี้ จึงมีใน AREG_CBCT ด้วย

การนำไปใช้ (AREG_MRI.py:231):

transformed_mri = sitk.Resample(original_mri_sitk, original_mri_sitk,
                                transform, sitk.sitkLinear, 0.0, ...)

transform ถูกนำไปใช้กับ MRI ต้นฉบับ ไม่ใช่ MRI ที่ใส่ mask และ เรขาคณิตอ้างอิงคือของ MRI ไม่ใช่ของ CBCT: วอลุ่มเอาต์พุตยังอยู่บน กริดของ MRI และส่วนใดที่หลุดออกนอกขอบเขตภาพเดิมหลัง การย้ายจะสูญหาย

เอาต์พุตอยู่ในโฟลเดอร์ mri=…_cbct=…: <original_MRI_name>_reg.nii.gz และ <original_MRI_name>_reg_transform.tfm (ITK transform, LPS อ่านได้โดยตรง ด้วย SimpleITK) หากไม่ได้เลือก "Keep the temporary folder" โฟลเดอร์กลาง 5 โฟลเดอร์และโฟลเดอร์แม่จะถูกลบเมื่อ CLI ทำงานเสร็จ

12. ข้อควรระวังและจุดเปราะบาง

บั๊กที่ยืนยันแล้ว

install_function() ล้มเหลวเสมอ รายการ dependency (MRI2CBCT.py:96) มี ('nnunet_version', "==2.8.0") ซึ่งเป็นแพ็กเกจที่ไม่มีอยู่บน PyPI (AMASSS ประกาศไว้ถูกต้องเป็น ('nnunetv2','2.8.0')) check_lib_installed จึงคืนค่า False เสมอ: มีหน้าต่างติดตั้งเด้งขึ้น ทุก action, pip_install ที่ raise, errorDisplay และคืนค่า False — ค่าที่ผู้เรียกทุกตัวเพิกเฉย action จึงดำเนินต่อไปอยู่ดี

บั๊กที่ยืนยันแล้ว

จุดศูนย์กลางการหมุนของ elastix สูญหาย MatrixRetrieval อ่าน TransformParameters แต่ไม่อ่าน CenterOfRotationPoint ที่ parameter map เอาต์พุตมีอยู่ด้วย sitk.Euler3DTransform ที่สร้างขึ้นใหม่จึง หมุนรอบจุดกำเนิด transform ที่เขียนออกและนำไปใช้จะตรงกับ ที่ elastix ประมาณได้ก็ต่อเมื่อจุดศูนย์กลางนั้นอยู่ที่จุดกำเนิดเท่านั้น โค้ดคัดลอก มาทั้งหมดจาก AREG_CBCT/AREG_CBCT_utils/utils.py:830: ปัญหานี้จึงมีร่วมกัน

ข้อควรระวัง

แบบแผน .tfm สองแบบสำหรับขั้นเดียวกัน การประมาณตำแหน่งด้วยมือเขียน flip @ M @ flip โดยไม่ invert (ManualApprox_MRI2CBCT.py:472) ขณะที่ FlexReg เขียน inv(flip @ M @ flip) สำหรับการแปลงแบบเดียวกัน — แบบแผนของ ITK คือ fixed → moving เส้นทางอัตโนมัติใช้ slicer.util.saveNode ซึ่งใช้แบบแผนที่ถูกต้อง

บั๊กที่ยืนยันแล้ว

"Confirm & Save" แครชหากวอลุ่มมาจากฉาก: onConfirm เรียก os.path.basename(self._mri_path) ขณะที่ _mri_path ถูกรีเซ็ตเป็น None ทันทีที่ เลือกวอลุ่มผ่าน qMRMLNodeComboBox (ManualApprox_MRI2CBCT.py:247) มีเพียง "Load from Folders Above" ที่ใช้ได้

บั๊กที่ยืนยันแล้ว

ตัวจัดการข้อผิดพลาดของ resample ก็แครชเช่นกัน: logger.warning(e, file=sys.stderr) (resample.py:240) — Logger.warning ไม่รับ file= exception ที่ดักไว้จึงกลายเป็น TypeError ที่ไม่ถูกดัก

  • utils_CBCT.py ทั้งไฟล์: เข้าถึงได้ ผ่าน NumberScan() เท่านั้น ซึ่งไม่เคยถูกเรียก เช่นเดียวกับ getGPUUsage(), getModelUrl() (คืนค่า {"MeanCBCT": "xxx", "ROI": "xxx"}), TestScanDCM, getTestFileListDCM
  • MRI2CBCTLogic.process() และ MRI2CBCTTest: โค้ด thresholding สำเร็จรูปจาก template ของ Slicer ไม่เกี่ยวกับโมดูล

  • run_resample มีอยู่สองที่: resample.py:243 และสำเนาใน MRI2CBCT_RESAMPLE_CBCT_MRI.py:32 สำเนาในไฟล์นั้นเองคือตัวที่ถูกใช้จริง
  • downloadModel() อ้างใน docstring ว่าใช้ getModelUrl แต่ดาวน์โหลด TestFile.zip ที่ฝังตายตัว สำหรับปุ่ม "Test File" ทั้งสี่ปุ่ม

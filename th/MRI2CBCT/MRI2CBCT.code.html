MRI2CBCT, legacy: โค้ด

สำหรับนักพัฒนา: โมดูล legacy MRI2CBCT ทำอะไรในโค้ด พร้อมการอ้างอิง file:line โค้ด อาร์กิวเมนต์ สภาพแวดล้อม และกับดัก คำอธิบายที่อ่านง่ายของไปป์ไลน์เดียวกัน พร้อมคณิตศาสตร์ อยู่ในหน้าแอตลาส

โค้ด แอตลาส (คำอธิบาย) Leroux 2024 · รุ่นก่อนหน้า, CLIP, LNCS 15196 CLI MRI2CBCT_* 3 ตัว + ยืมมา 4 ตัว Python ของ Slicer ไม่ใช้ conda บรรณานุกรม VISOR: ไม่ได้พอร์ต

ตั้งแต่ PR #277 และ #278 โมดูลเป็นแผงเดียว (MRI2CBCT.py, 753 บรรทัด) เหนือแพ็กเกจที่ไม่พึ่ง Slicer คือ MRI2CBCT_core/ เจ็ดขั้นถูกเชื่อมด้วยปุ่ม Run เดียว: CLI ของตัวเองสามตัว (MRI2CBCT_PREPARE, MRI2CBCT_SEGMENT_MRI, MRI2CBCT_REGISTER) และยืมจาก ASO, ALI และ AMASSS อีกสี่ตัว โครงข่ายตระกูล nnU-Net สองตัวแบ่งส่วนฐานกะโหลก ตัวหนึ่งบน CBCT และอีกตัวบน MRI ทุกอย่างหลังจากนั้นเป็นเรขาคณิตบนกลุ่มจุดสองกลุ่ม การรันหยุดชั่วคราวได้หลังขั้นใดก็ได้เพื่อให้แพทย์ตรวจ

โค้ดสองชุด

ทุกอย่างที่มีหมายเลขด้านล่างอธิบายโมดูล Slicer แบบ legacy (SlicerAutomatedDentalTools ที่ 3c67957, 2026-10-26, รุ่นที่เขียนใหม่) ไม่มีการพอร์ตไป VISOR: SADT-VISOR ไม่มีเครื่องมือ MRI2CBCT, VISOR-serve ไม่มีส่วนการติดตั้งใช้งานสำหรับมัน และโมดูลฝั่งไคลเอนต์ถูกเก็บไว้ในต้นไม้แต่ไม่ถูกสร้าง ดูสิ่งที่มีของ MRI2CBCT ใน VISOR

4.1 การจับคู่ตามรหัสผู้ป่วย

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

pair_folders (pairing.py:81) วิธีการถ่ายภาพมาจากโฟลเดอร์ที่แพทย์เลือก ไม่เคยมาจากชื่อไฟล์ (pairing.py:3-4) รหัสคือตัวอักษรนำตามด้วยตัวเลข ^([A-Za-z]+)[_\-\s]*0*(\d+) (pairing.py:12): P01, B038, A3_scan ศูนย์นำหน้าไม่นับ ดังนั้น P1 และ P01 เป็นผู้ป่วยเดียวกัน และตัวพิมพ์ก็ไม่นับ (patient_key, :27-32) นามสกุลที่รับคือ .nii.gz, .nii และ .nrrd (:11) ค้นหาแบบเรียกซ้ำ (list_images, :41-47)

ไฟล์หรือผู้ป่วยถูกตัดออกพร้อมข้อความ เมื่อ: อ่านรหัสไม่ได้ มี MRI แต่ไม่มี CBCT มี CBCT แต่ไม่มี MRI หรือมีCBCT มากกว่าหนึ่งภาพสำหรับรหัสเดียวกัน (pairing.py:92, :98, :106, :109, :111-113) แผงแสดงรายการเหล่านั้นและขอการยืนยันก่อนดำเนินต่อ (MRI2CBCT.py:350) ผู้ป่วยหนึ่งคนอาจมี MRI หนึ่งหรือสองภาพ

โฟลเดอร์ที่สลับกัน folders_swapped (pairing.py:73-78) อ่านเฉพาะส่วนหัวไฟล์ไม่เกินสี่ไฟล์ต่อโฟลเดอร์ looks_like (:50-70) เรียกไฟล์ว่า MRI ถ้า spacing ของมันไม่เท่ากันทุกทิศเกินกว่าตัวประกอบ 2 หรือมีขนาดใดต่ำกว่า 90 mm และเรียกว่า CBCT ถ้าเท่ากันทุกทิศภายใน 5% และกว้างอย่างน้อย 120 mm ในทุกทิศทาง อย่างอื่นคือ "neither" จากนั้นแผงเสนอให้สลับสองโฟลเดอร์ (MRI2CBCT.py:328-336)

4.2 การเตรียม MRI แต่ละภาพ

MRI2CBCT_PREPARE.py ก่อนอื่นมันลบโฟลเดอร์ _steps/ ทั้งหมดของเอาต์พุต (:23-24) แล้วเชื่อมแต่ละ CBCT เข้า _steps/0_cbct_in/<PID> (symlink หรือสำเนาถ้าลิงก์ล้มเหลว :45-48) จากนั้นสำหรับแต่ละไฟล์ MRI ถาม mri_prep.plan_joints ว่าวอลุ่มคืออะไร ส่วนหัวของ MRI ถูกเก็บไว้ตามเดิม: ขั้น "Orient" ก่อนหน้าเขียนทับเมทริกซ์ทิศทางด้วยค่าตายตัว ซึ่ง "throws away the only record of which way the slices run" (mri_prep.py:3-6) โค้ดใหม่จึงอ่านพิกัดโลกจากส่วนหัวดั้งเดิม

7.1 พื้นผิว

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

  • มาสก์ MRI (mri_surface, ladder.py:131-147): กำหนดเกณฑ์ที่ 0.5 ปฏิเสธมาสก์ที่ต่ำกว่า 50 voxel เก็บส่วนประกอบที่เชื่อมต่อกันที่ใหญ่ที่สุด (6-connectivity) แล้วสุ่มตัวอย่างพื้นผิว ตัวกรองส่วนประกอบถูกเรียกว่าจำเป็นใน surface.py:35-41 เพราะทิศของเวกเตอร์ตั้งฉากถูกส่งต่อผ่านกราฟการเชื่อมต่อ และเกาะที่หลุดออกไปจะได้เวกเตอร์ตั้งฉากที่กลับด้าน ปริมาตรของมาสก์ในหน่วย cm³ ถูกเก็บไว้สำหรับ QC (§7.3)
  • มาสก์ CBCT (cbct_surface, :150-157): เกณฑ์และการสุ่มตัวอย่างเดียวกัน โดยไม่มีตัวกรองส่วนประกอบ
  • จุดพื้นผิว (surface_points_normals, surface.py:10-30): voxel ของมาสก์ลบด้วย erosion ของมัน สุ่มย่อยเหลือไม่เกิน 20 000 จุด (NPTS, reg/pipeline.py:14) ด้วย random seed ตายตัว และเฉพาะเมื่อพื้นผิวมี voxel มากกว่านั้น (surface.py:21-22) พิกัดโลกใน RAS เวกเตอร์ตั้งฉากจากเกรเดียนต์ของมาสก์ที่ทำให้เรียบด้วย σ = 1.5 voxel
  • การตัดด้าน (side_cut, ladder.py:94-102): สำหรับข้อต่อที่ติดป้าย L หรือ R พื้นผิว CBCT เก็บจุดจนถึง MARGIN = 5 mm เลย x มัธยฐานของทั้งพื้นผิวในด้านที่สแกน (RAS +x คือด้านขวาของผู้ป่วย) นี่คือสิ่งที่ทำให้แผ่น MRI ข้อต่อเดียวลงทะเบียนกับ CBCT ทั้งศีรษะได้ ข้อต่อที่ติดป้าย B (ทั้งวอลุ่ม) ใช้พื้นผิวทั้งหมด

บทความที่เชื่อมจากเครื่องมือนี้คือ Novel CBCT-MRI Registration Approach for Enhanced Analysis of Temporomandibular Degenerative Joint Disease, Leroux G. et al., Clinical Image-Based Procedures (CLIP 2024), LNCS vol. 15196, Springer ตามที่บรรณานุกรมของโฟลเดอร์นี้อ่านบทคัดย่อ มันอธิบายลำดับรุ่นก่อน: การจัดทิศทางอัตโนมัติ resample การกลับ MRI normalization แล้วการลงทะเบียนแบบแข็งเกร็งด้วย mutual information นั่นไม่ใช่สิ่งที่โค้ดทำอีกต่อไป การลงทะเบียนปัจจุบันเป็นการค้นหาโดยรวมบนพื้นผิวที่ทำนายสองพื้นผิวและไม่ใช้ความเข้ม รายงาน NA-MIC สองฉบับที่เก็บไว้ข้างหน้านี้ก็เช่นกัน: PW43 (2025) เป็นรุ่น TorchReg บวก elastix ส่วน PW45 (2026) ระบุการแก้ไขของรุ่นนั้น และเป็นขั้นต่อไป การประมาณตำแหน่งอัตโนมัติที่ทนทานขึ้น capture range ของ elastix ที่กว้างขึ้น และการตรวจสอบบน target registration error

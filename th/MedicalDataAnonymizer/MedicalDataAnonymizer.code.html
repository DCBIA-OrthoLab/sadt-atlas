MedicalDataAnonymizer, legacy: โค้ด

สำหรับนักพัฒนา: โมดูล Slicer แบบ legacy MedicalDataAnonymizer ทำอะไรในโค้ด (SlicerAutomatedDentalTools ที่ 3c67957) พร้อมการอ้างอิง file:line บล็อกโค้ด เอนทิตี สภาพแวดล้อม และความล้มเหลวเงียบที่ยืนยันแล้ว คำอธิบายที่อ่านง่ายของไปป์ไลน์เดียวกันอยู่ในหน้าแอตลาส

ยังไม่ตีพิมพ์ ไม่มี CLI (วิดเจ็ต Slicer) เธรด UI ไม่มี conda บรรณานุกรม VISOR: มีเฉพาะสำเนาในเครื่อง โค้ด แอตลาส (คำอธิบาย) Guide
โค้ดสองชุด

ทุกอย่างที่มีเลขกำกับด้านล่างอธิบายโมดูล Slicer แบบ legacy (SlicerAutomatedDentalTools ที่ 3c67957, 2026-10-26) VISOR ไม่มีเครื่องมือฝั่งเซิร์ฟเวอร์สำหรับมัน ส่วนขยายไคลเอนต์ของ VISOR ส่งสำเนาที่เก่ากว่าของโมดูลมาด้วย ซึ่งรันภายใน Slicer และไม่ส่งอะไรออกไป และมันไม่ใช่การลบข้อมูลระบุตัวตนของไฟล์ที่ VISOR อัปโหลด (อันนั้นกำหนดสเปกไว้แต่ยังไม่ได้สร้าง ดูการลบข้อมูลระบุตัวตนใน VISOR) รายละเอียดอยู่ในหน้า VISOR ของโมดูลนี้

กับดักด้านคำศัพท์ · เป็นจริงใน VISOR ด้วย

เป็นจริงใน VISOR ด้วย สำเนาฝั่งไคลเอนต์รองรับเฉพาะข้อความ (AutomatedDentalToolsRemote README.md:215) และการลบข้อมูลระบุตัวตนของภาพที่ชื่ออาจชวนให้คิดนั้นไม่มีอยู่ในไคลเอนต์ (README.md:31-34)

ชื่อชวนให้คิดว่าเป็นตัวทำให้ DICOM นิรนาม แต่มันไม่ใช่เลย: MedicalDataAnonymizer ลบข้อมูลระบุตัวตนของเอกสารข้อความผ่าน Presidio + spaCy ไม่มี DICOM tag ใดถูกอ่านหรือแก้ไข (PatientName, PatientID, UID…) และไม่เคยมีการ deface ภาพ: ทั้ง extension ไม่มีเครื่องมือ deface เลย

0. สิ่งที่โมดูลไม่ใช่

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

ชื่อชวนให้คิดว่าเป็นตัวทำให้ DICOM นิรนาม แต่มันไม่ใช่เลย และตรวจได้ด้วยคำสั่งเดียว:

$ grep -rin "dicom\|pydicom\|deface" Medical_Data_Anonymizer_Module/
(no result)
$ grep -rlni "deface" --include="*.py" --include="*.md" .
(no result anywhere in the repository)

ผลโดยตรง:

  • ไม่มี DICOM tag ใดถูกลบหรือแทนที่: ไม่ใช่ PatientName (0010,0010) ไม่ใช่ PatientID (0010,0020) ไม่ใช่ PatientBirthDate ไม่ใช่ StudyDate ไม่ใช่ InstitutionName ไม่ใช่ UID ไม่ใช่private tag ไม่ใช่ BurnedInAnnotation
  • ไม่มีการ deface: ใบหน้าที่สร้างขึ้นใหม่ได้ใน CBCT หรือสแกนเนอร์ไม่เคยถูกเปลี่ยนแปลง ไม่ว่าด้วยวิธีใด (ไม่มี facial mask ไม่มีการเบลอ ไม่มีการลบพื้นผิว) ไม่มีเครื่องมือ deface ที่ใดเลยในทั้ง extension
  • รูปแบบที่รองรับ (.docx, .txt, .pdf, .csv, .xml, .odt, Medical_Data_Anonymizer_Module.py:514) ไม่ครอบคลุม .dcm, .nii.gz, .nrrd, .vtk หรือ .json ของ landmark เลย

ผู้ปฏิบัติงานที่ตัดสินใจว่าข้อมูลแบ่งปันได้หรือไม่ ควรอ่าน§7โดยตรง

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

เครื่องมือแยกเดี่ยวที่ไม่มี CLI ไม่มีอะไรเรียกมัน และมันไม่เรียกสิ่งอื่นใดในที่เก็บโค้ด ทุกอย่างอยู่ในไฟล์เดียว 774 บรรทัด โดยราว 350 บรรทัดเป็น Qt stylesheet: Medical_Data_Anonymizer_Module.py

Medical_Data_Anonymizer_ModuleLogic และ …Test เป็นคลาสว่าง (pass): ตรรกะทั้งหมดอยู่ในวิดเจ็ต จึงอยู่บนmain thread ของ Slicer อินเทอร์เฟซค้างระหว่างประมวลผล มีเพียง slicer.app.processEvents() ที่รีเฟรชแถบความคืบหน้า

2. อินพุต: การสกัดข้อความทีละรูปแบบ

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

เดินผ่านโฟลเดอร์อินพุตแบบrecursive (os.walk) ไฟล์ที่ขึ้นต้นด้วย ~$ (ไฟล์ล็อกของ Word) ถูกละเลย ไฟล์แต่ละไฟล์ถูกลดเป็นสตริงอักขระเดียวก่อนการวิเคราะห์:

รูปแบบการดึงค่าสิ่งที่หายไประหว่างทาง
.docxpython-docx, "\n".join(p.text for p in doc.paragraphs)ตาราง ส่วนหัว/ส่วนท้าย เชิงอรรถ กล่องข้อความ ความคิดเห็น เมทาดาตาของไฟล์
.txtอ่าน UTF-8 ดิบ–
.pdfpdfplumber, page.extract_text() เมื่อเกิดข้อยกเว้น ลองครั้งที่สองผ่าน extract_tables()ภาพ PDF ที่สแกน (ไม่มี OCR) → ข้อความว่าง
.csvcsv.reader แต่ละแถวถูกทำให้แบนด้วย " ".join(row)โครงสร้างคอลัมน์
.xmlElementTree + extract_text_from_xml() แบบ recursive (ข้อความ + tail)แท็กและแอตทริบิวต์: ค่าของแอตทริบิวต์ไม่เคยถูกอ่าน
.odtodfpy, โหนดข้อความของ text.Pตาราง สไตล์ เมทาดาตา

การสูญเสียไม่ใช่เรื่องความเที่ยงตรงเท่านั้น: เอกสารเอาต์พุตถูกสร้างใหม่จากสตริงนี้ สิ่งที่ไม่ได้สกัดไม่ถูกทำให้นิรนาม แต่ก็ไม่ถูกส่งต่อด้วย: มันหายไป ในทางกลับกัน เนื้อหาอ่อนไหวที่อยู่ในส่วนที่ไม่ได้สกัด (ตารางใน DOCX แอตทริบิวต์ของ XML) ไม่ถูกตรวจพบและไม่ถูกส่งต่อ: ไม่มีการรั่ว แต่ข้อมูลสูญหายอย่างเงียบ ๆ

ข้อยกเว้นที่น่าสังเกต: ไม่มีอะไรอ่านเมทาดาตาของไฟล์ (ผู้เขียนของ DOCX หรือ Producer ของ PDF) มันหายไปด้วย เพราะไฟล์ถูกสร้างใหม่จากศูนย์

3. กลไกการตรวจจับ

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

ไม่มีโมเดลในที่เก็บโค้ด และตัวโมดูลเองไม่ดาวน์โหลดน้ำหนักใด ๆ นอกจากโมเดล spaCy มีการสร้างเอนจิน Presidio สองตัวทุกครั้งที่คลิก "Anonymize Files" (…py:499-502) โดยตัดช่อง stderr ด้วยคลาส SuppressStderr:

analyzer = AnalyzerEngine()      # default config
anonymizer = AnonymizerEngine()

AnalyzerEngine() ที่ไม่มีอาร์กิวเมนต์ใช้การตั้งค่า NLP เริ่มต้นของ Presidio นั่นคือspaCy en_core_web_lg: โมเดลเดียวที่ install_dependencies() ดาวน์โหลด (spacy.cli.download, …py:432)

recognizer สองตระกูลรวมกัน: NER เชิงสถิติของ spaCy (PERSON, LOCATION, DATE_TIME) และrecognizer ที่อิงรูปแบบและ checksum (PHONE_NUMBER, EMAIL_ADDRESS, US_SSN, MEDICAL_LICENSE, US_DRIVER_LICENSE, CREDIT_CARD, US_BANK_NUMBER, IP_ADDRESS, URL)

กับดัก · เป็นจริงใน VISOR ด้วย

เป็นจริงใน VISOR ด้วย (สำเนาฝั่งไคลเอนต์) โค้ดเดียวกันในสำเนาที่ส่งมา: language='en' ที่ AutomatedDentalToolsRemote Medical_Data_Anonymizer_ModuleRemote/Medical_Data_Anonymizer_ModuleRemote.py:716 และ pip_install('langdetect') ที่ :405 (legacy ที่ 3c67957: :724 และ :413 บรรทัดที่อ้างใน callout นี้มาจากรุ่นก่อนหน้า)

ภาษาถูกล็อกไว้ที่ภาษาอังกฤษ: analyzer.analyze(..., language='en') (…py:724) ทั้งที่คอมเมนต์เขียนว่า "with automatic language detection" และมีการติดตั้ง langdetect ซึ่งไม่เคยถูก import เป็น dependency ที่ไม่ได้ใช้ โฟลเดอร์บันทึกภาษาฝรั่งเศสผ่านโมเดลภาษาอังกฤษ ด้วยค่า recall ที่คาดได้

ค่าthresholdความเชื่อมั่น: score_threshold สไลเดอร์ 0.0–1.0 ค่าเริ่มต้น 0.5 การตรวจจับที่ต่ำกว่าค่านี้ถูกทิ้งโดยไม่มีร่องรอย การทดสอบใน Presidio คือ result.score >= score_threshold (analyzer_engine.py, __remove_low_scores เหมือนกันใน 2.2.355 และ 2.2.366) ดังนั้นคะแนนที่เท่ากับ threshold จึงถูกเก็บไว้

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

กล่องกาเครื่องหมายสิบสองกล่อง ติ๊กไว้เจ็ดกล่องโดยค่าเริ่มต้น (…py:98-115):

เอนทิตีของ Presidioป้ายใน UIค่าเริ่มต้น
PERSON ทำนายNames (patients, doctors)✔
PHONE_NUMBER คำนวณPhone Numbers✔
EMAIL_ADDRESS คำนวณEmail Addresses✔
DATE_TIME ทำนายDates and Times✔
LOCATION ทำนายAddresses and Locations✔
US_SSN คำนวณSocial Security Numbers✔
MEDICAL_LICENSE คำนวณMedical License Numbers✔
US_DRIVER_LICENSE, CREDIT_CARD, US_BANK_NUMBER, IP_ADDRESS, URL คำนวณ–✘

สี่วิธี ใน "Advanced Options" (…py:129-132):

วิธีการการทำงานผลลัพธ์
replace (default)operators = {} → ส่งเป็น None → operator เริ่มต้นของ Presidio<PERSON>, <DATE_TIME>, …
redactOperatorConfig("redact") ต่อเอนทิตีส่วนที่พบหายไป ข้อความปิดช่องว่างเข้าหากัน
hashOperatorConfig("hash")SHA-256 แบบไม่มี saltของข้อความที่ตรวจพบใน presidio-anonymizer 2.2.355 ใน 2.2.366 มีการเพิ่ม salt สุ่ม 32 ไบต์ต่อ span (operators/hash.py)
maskOperatorConfig("mask", {"masking_char": "*", "chars_to_mask": 100, "from_end": False})เครื่องหมายดอกจันทับทั้งส่วนที่พบ

เรื่อง hash: README พูดถึง "cryptographic hashes for consistent anonymization." ข้ออ้างเรื่องความสอดคล้องเป็นจริงกับ presidio-anonymizer 2.2.355 (ชื่อเดียวกันให้ digest เดียวกันเสมอ) แต่ไม่มีทั้ง salt และ key: บนปริภูมิค่าที่เล็กอย่างชื่อ วันเกิด หรือเลขประกันสังคม digest สามารถระบุตัวตนกลับได้ด้วย brute force ในไม่กี่วินาที ให้ถือว่าเป็นนามแฝงสาธารณะ ไม่ใช่การป้องกัน โมดูลไม่ล็อกเวอร์ชัน (pip_install('presidio-anonymizer'), :407) และ 2.2.366 ใส่ salt ให้ทุก span ด้วย os.urandom(32) เว้นแต่จะส่ง salt เข้ามา ซึ่งโมดูลไม่ได้ทำ: กับเวอร์ชันนั้น ชื่อเดียวกันได้ digest ต่างกันทุกครั้ง และข้ออ้างเรื่องความสอดคล้องเป็นเท็จ

กรณี CSV ทำลายมากที่สุด: ไฟล์ถูกอ่านโดยทำให้แต่ละแถวแบนด้วยช่องว่าง แล้วเขียนกลับด้วย writer.writerow(line.split()) (…py:640) เซลล์ใดที่มีช่องว่างจะถูกแยกเป็นหลายคอลัมน์ และเซลล์ว่างหายไป: การจัดแนวคอลัมน์ไม่ถูกรักษาไว้ CSV ของการวัดจึงใช้การไม่ได้

ตารางการจับคู่ file_mappings.csv เขียนลงในโฟลเดอร์เอาต์พุต (…py:656):

คอลัมน์เนื้อหา
Original File Nameชื่อของไฟล์ต้นทาง
Anonymized File Nameชื่อที่สร้าง หรือ ERROR

7. ข้อจำกัด: สิ่งที่ไม่ถูกลบ

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

ส่วนที่มีประโยชน์ที่สุดสำหรับการตัดสินใจว่าชุดข้อมูลแบ่งปันได้หรือไม่

อยู่นอกขอบเขตโดยโครงสร้าง

  1. ภาพทั้งหมด DICOM, NIfTI, NRRD, เมช: ไม่เคยถูกอ่าน ไม่เคยถูกแก้ไข ไม่มี tag ในส่วนหัวใดถูกทำความสะอาด ไม่มีใบหน้าใดถูกลบ (§0)
  2. ชื่อไฟล์และโฟลเดอร์ Dupont_Jean_2019.docx กลายเป็น Dupont_Jean_2019_anonymized.docx ชื่อผู้ป่วยอยู่รอดครบในชื่อไฟล์ และถูกคัดลอกตามตัวอักษรลงใน file_mappings.csv ลำดับชั้นของอินพุตซึ่งมักระบุตัวตนได้ไม่แพ้กัน (.../Patients/Dupont_Jean/) ถูกทำให้แบน และหากโฟลเดอร์ย่อยสองโฟลเดอร์มีไฟล์ชื่อเดียวกัน ไฟล์ที่สองเขียนทับไฟล์แรกโดยไม่แจ้ง

จุดบอดของการตรวจจับ

  1. ตัวระบุของโรงพยาบาล ไม่มี recognizer สำหรับ MRN หมายเลขแฟ้ม หมายเลข accession ตัวระบุการศึกษา หมายเลขเตียง สิ่งเหล่านี้ไม่อยู่ในสิบสองเอนทิตีที่ให้เลือกเลย และ Presidio ก็ไม่มีโดยค่าเริ่มต้น
  2. ทุกอย่างที่ไม่ใช่ของอเมริกัน เอนทิตีที่เลือกได้คือ US_SSN, US_DRIVER_LICENSE, US_BANK_NUMBER: NIR ของฝรั่งเศส หมายเลข NHS หมายเลขหนังสือเดินทาง หรือ ITIN ไม่ถูกค้นหา
  3. ตัวระบุทางอ้อมของ HIPAA ไม่ถูกจัดการ: อายุเกิน 89 วันที่หายาก อาชีพ การเป็นสมาชิกของกลุ่มเล็ก Presidio ไม่ทำการ generalise วันที่: DATE_TIME ถูกแทนที่ทั้งก้อนหรือไม่ก็ไม่แทนที่เลย
  4. ภาษา การวิเคราะห์ล็อกไว้ที่ภาษาอังกฤษ (§3): บนคอร์ปัสที่ไม่ใช่ภาษาอังกฤษ recall ของ PERSON/LOCATION/DATE_TIME ตกลงอย่างรุนแรงโดยไม่มีคำเตือนใด ๆ
  5. ค่าthreshold 0.5 ทิ้งการตรวจจับที่ได้คะแนนต่ำกว่า ว่าอันไหนขึ้นกับ recognizer: เอนทิตีของ spaCy (ชื่อ สถานที่ วันที่) ได้คะแนนคงที่ค่าเดียวทั้งหมด (ner_strength / default_score = 0.85 ในซอร์สของ Presidio 2.2.355 และ 2.2.366) ดังนั้น 0.5 จึงไม่กรองชื่อที่หายากหรือไม่ใช่แองโกล-แซกซอนออก มันมีผลกับ recognizer ที่อิงรูปแบบ ยังไม่ได้ทดสอบบนการติดตั้งจริง
  6. เนื้อหาที่ไม่ได้สกัด (ตารางใน DOCX แอตทริบิวต์ของ XML PDF ที่สแกน ส่วนหัวและส่วนท้าย) ไม่ถูกวิเคราะห์ มันไม่รั่วลงในเอาต์พุต แต่หากผู้รับได้ต้นฉบับด้วย การทำให้นิรนามก็ไม่เคยครอบคลุมส่วนนั้น

ส่วนประกอบที่ใช้มีเอกสารรองรับ:

  • Microsoft Presidio: เอนจินตรวจจับและทำให้นิรนาม พร้อมรายการที่แน่นอนของ recognizer และ operator ที่กำหนดไว้ล่วงหน้า (replace, redact, hash, mask, encrypt ซึ่งอย่างหลังย้อนกลับได้ด้วย key และโมดูลไม่ได้เปิดให้ใช้)
  • spaCy en_core_web_lg: โมเดล NER ภาษาอังกฤษที่ใช้โดยค่าเริ่มต้น
  • HIPAA Safe Harbor, 45 CFR §164.514(b)(2): ตัวระบุ 18 หมวดที่ต้องลบ มีประโยชน์เป็นตารางอ่านสำหรับ§7: ชื่อไฟล์ ตัวระบุเวชระเบียน และตัวระบุของภาพปรากฏอยู่ที่นั่น และโมดูลนี้ไม่จัดการสิ่งเหล่านั้น

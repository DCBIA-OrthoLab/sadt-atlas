MedicalDataAnonymizer

การตรวจจับและแทนที่เอนทิตีอ่อนไหวในเอกสารข้อความ (DOCX, TXT, PDF, CSV, XML, ODT) ผ่าน Microsoft Presidio โมดูลไม่แตะภาพทางการแพทย์เลย: นี่ไม่ใช่ตัวทำให้ DICOM นิรนาม หน้านี้อธิบายไปป์ไลน์ทีละขั้น รายละเอียดของโค้ดอยู่ในหน้าโค้ด

ยังไม่ตีพิมพ์ ไม่มี CLI (วิดเจ็ต Slicer) เธรด UI ไม่มี conda บรรณานุกรม VISOR: มีเฉพาะสำเนาในเครื่อง โค้ด (นักพัฒนา) Guide

หน้านี้อธิบายโมดูล Slicer แบบ legacy (SlicerAutomatedDentalTools ที่ 3c67957, 2026-10-26) VISOR ไม่มีเครื่องมือฝั่งเซิร์ฟเวอร์สำหรับมัน: ส่วนขยายไคลเอนต์ส่งสำเนาที่เก่ากว่ามาด้วย ซึ่งรันภายใน Slicer และไม่ส่งอะไรออกไป และมันไม่ใช่การลบข้อมูลระบุตัวตนของไฟล์ที่ VISOR อัปโหลด ซึ่งกำหนดสเปกไว้แต่ยังไม่ได้สร้าง (การลบข้อมูลระบุตัวตนใน VISOR) ดูหน้า VISOR ของโมดูลนี้

ภาพรวม: อะไรเข้า อะไรออก

MedicalDataAnonymizer
อินพุตโฟลเดอร์ของเอกสารข้อความ (Word, ข้อความ, PDF, CSV, XML, ODT) ค้นแบบ recursive
การตรวจจับMicrosoft Presidio: โมเดลภาษาอังกฤษเชิงสถิติสำหรับชื่อ สถานที่ และวันที่ และรูปแบบพร้อม checksum สำหรับตัวเลข อีเมล และตัวระบุที่คล้ายกัน
การแทนที่หนึ่งในสี่วิธี: ป้ายกำกับ การลบ hash หรือเครื่องหมายดอกจัน
เอาต์พุตเอกสาร _anonymized ที่สร้างใหม่หนึ่งฉบับต่ออินพุตหนึ่งฉบับ ทั้งหมดอยู่ในโฟลเดอร์แบนเดียว บวก file_mappings.csv

โมดูลทำให้ข้อความเท่านั้นนิรนาม มันเป็นการผ่านครั้งแรกบนข้อความอิสระภาษาอังกฤษ ไม่ใช่วิธีประกาศว่าชุดข้อมูลถูกลบข้อมูลระบุตัวตนแล้ว (หัวข้อ 7)

0. สิ่งที่โมดูลไม่ใช่

ชื่อชวนให้คิดว่าเป็นตัวทำให้ DICOM นิรนาม แต่มันไม่ใช่เลย และสำเนาใน VISOR ก็เช่นกัน การค้นทั้งโมดูลหา “DICOM” หรือ “deface” ไม่พบอะไรเลย ดังนั้น:

  • ไม่มี DICOM tag ใดถูกอ่านหรือเปลี่ยน: ไม่ใช่ชื่อหรือรหัสผู้ป่วย ไม่ใช่วันที่ ไม่ใช่สถาบัน ไม่ใช่ตัวระบุเฉพาะ ไม่ใช่ private tag
  • ไม่เคยมีการ deface: ใบหน้าที่สร้างขึ้นใหม่ได้จาก CBCT หรือสแกนเนอร์ไม่ถูกแตะต้อง และไม่มีเครื่องมือ deface ที่ใดเลยใน extension
  • รูปแบบที่รองรับไม่ครอบคลุมรูปแบบภาพหรือเมชใด ๆ และไม่ครอบคลุมไฟล์ landmark

ใครที่ตัดสินใจว่าข้อมูลแบ่งปันได้หรือไม่ ควรอ่านหัวข้อ 7ก่อน

ในโค้ดการค้นที่พิสูจน์เรื่องนี้ และรูปแบบที่รองรับพร้อมบรรทัด

1. ตำแหน่งในไปป์ไลน์

เครื่องมือแยกเดี่ยวที่ไม่มีงานบรรทัดคำสั่ง: ไม่มีอะไรเรียกมัน มันไม่เรียกสิ่งใด ตรรกะทั้งหมดอยู่ในวิดเจ็ต จึงอยู่บนmain threadของ Slicer อินเทอร์เฟซจึงค้างระหว่างประมวลผล และมีเพียงแถบความคืบหน้าที่ถูกรีเฟรช

ในโค้ดไฟล์เดียว คลาสตรรกะที่ว่าง และเธรด UI

2. อินพุต: การสกัดข้อความทีละรูปแบบ

โฟลเดอร์ถูกเดินแบบ recursive โดยละเลยไฟล์ล็อกของ Word ไฟล์แต่ละไฟล์ถูกลดเป็นสตริงอักขระเดียวก่อนการวิเคราะห์ และเอาต์พุตถูกสร้างใหม่จากสตริงนั้น สิ่งที่ไม่ได้สกัดไม่ถูกวิเคราะห์และไม่ถูกส่งต่อ: มันหายไป

  • Word: ย่อหน้า ตาราง ส่วนหัว ส่วนท้าย เชิงอรรถ กล่องข้อความ ความคิดเห็น และเมทาดาตาหายไป
  • ข้อความ: อ่านตามที่เป็น
  • PDF: ชั้นข้อความ PDF ที่สแกนให้ข้อความว่าง
  • CSV: แต่ละแถวถูกทำให้แบนเป็นหนึ่งบรรทัด โครงสร้างคอลัมน์จึงหายไป
  • XML: เฉพาะเนื้อหาข้อความ แท็กและแอตทริบิวต์ไม่เคยถูกอ่าน
  • ODT: ย่อหน้า ตาราง สไตล์ และเมทาดาตาหายไป

เนื้อหาอ่อนไหวในส่วนที่ไม่ได้สกัดจะไม่ถูกตรวจพบ แต่ก็ไม่ถึงเอาต์พุตเช่นกัน: ไม่มีการรั่ว แต่ข้อมูลสูญหายอย่างเงียบ ๆ เมทาดาตาของไฟล์ เช่นผู้เขียนของ Word ก็หายไปด้วย เพราะไฟล์ถูกสร้างใหม่

ในโค้ดตารางรูปแบบพร้อมการเรียกไลบรารีและสิ่งที่แต่ละอันทำให้หาย

3. กลไกการตรวจจับ

ไม่มีโมเดลรวมมา โมดูลติดตั้งโมเดลภาษาอังกฤษของ spaCy และสร้างเอนจิน Presidio ด้วยการตั้งค่าเริ่มต้นทุกครั้งที่คลิก recognizer สองตระกูลทำงานเคียงข้างกัน

ตัวเชิงสถิติหาชื่อ สถานที่ และวันที่ ตัวอิงกฎหาเบอร์โทรศัพท์ อีเมล เลขประกันสังคมสหรัฐ ใบขับขี่และหมายเลขบัญชีธนาคาร ใบอนุญาตทางการแพทย์ บัตรเครดิต ที่อยู่ IP และ URL จากรูปแบบ checksum และคำบริบท

ภาษาถูกล็อกไว้ที่ภาษาอังกฤษ: โฟลเดอร์บันทึกภาษาฝรั่งเศสผ่านโมเดลภาษาอังกฤษ ด้วยการตรวจจับที่ต่ำลงตามที่คาด และโมดูลไม่บอกอะไรเลยเรื่องนี้ ตัวตรวจจับภาษาถูกติดตั้งแต่ไม่เคยถูกใช้ (รายละเอียด)

ในโค้ดการเรียกเอนจินสองครั้ง การดาวน์โหลดโมเดล และภาษาที่ตายตัว

4. เอนทิตีและวิธีการแทนที่

เลือกติ๊กได้สิบสองประเภทเอนทิตี และติ๊กไว้เจ็ดประเภทโดยค่าเริ่มต้น: ชื่อ เบอร์โทรศัพท์ ที่อยู่อีเมล วันที่และเวลา สถานที่ เลขประกันสังคม และเลขใบอนุญาตทางการแพทย์ อีกห้าประเภท (ใบขับขี่ บัตรเครดิต หมายเลขธนาคาร ที่อยู่ IP URL) ปิดอยู่ ชื่อ วันที่ และสถานที่มาจากโมเดลเชิงสถิติ (ทำนาย) ที่เหลือมาจากกฎ (คำนวณ)

Hash คือ SHA-256 ธรรมดาของข้อความที่ตรวจพบ ใน Presidio 2.2.355 ชื่อเดียวกันให้ digest เดียวกันเสมอ ซึ่งคงความสอดคล้องไว้ แต่หากไม่มี salt หรือ key hash บนปริภูมิที่เล็กอย่างชื่อ วันเกิด หรือเลขประกันสังคม ย้อนกลับได้ด้วยการลองทุกตัวเลือก ให้ถือว่าเป็นนามแฝงสาธารณะ ไม่ใช่การป้องกัน โมดูลไม่ล็อกเวอร์ชัน Presidio และ 2.2.366 ใส่ salt ไบต์สุ่ม 32 ไบต์ให้แต่ละ span ที่ hash ดังนั้นที่นั่น digest ของชื่อเดียวกันต่างกันไปในแต่ละการปรากฏ

ในโค้ดตารางเอนทิตีพร้อมค่าเริ่มต้น และการกำหนดค่า operator

5. เอาต์พุตและตารางการจับคู่

ทุกอย่างถูกเขียนแบบแบนลงในโฟลเดอร์เอาต์พุต: โฟลเดอร์ย่อยไม่ถูกทำซ้ำ และไฟล์สองไฟล์ที่ชื่อเดียวกันในโฟลเดอร์ย่อยต่างกันทำให้ไฟล์ที่สองเขียนทับไฟล์แรก ไฟล์ Word ข้อความ และ PDF ถูกสร้างใหม่ในรูปแบบของตัวเอง (PDF เป็นบล็อกเดียวที่ไม่แบ่งหน้า) ไฟล์ ODT กลายเป็นไฟล์ข้อความ และไฟล์ XML กลายเป็นข้อความล้วนภายใต้ชื่อ .xml

ตารางการจับคู่ file_mappings.csv แสดงชื่อเดิม ชื่อที่สร้าง และ UUID ต่อไฟล์ มันไม่ใช่ตารางระบุตัวตนกลับ: ไม่มีการเชื่อมระหว่างชื่อที่ตรวจพบกับสิ่งที่แทนที่ และ UUID ถูกสร้างแล้วไม่เคยถูกใช้ที่ใดเลย มันอยู่ข้างเอกสารที่ทำให้นิรนามแล้ว การแบ่งปันโฟลเดอร์เอาต์พุตจึงแบ่งปันรายการชื่อไฟล์ต้นฉบับ

ในโค้ดตารางเอาต์พุต การเขียน CSV ใหม่ และคอลัมน์ของตารางการจับคู่

6. ทำนายหรือคำนวณ

ขั้นตอนลักษณะ
การสกัดข้อความ การสร้างเอกสารใหม่ การแทนที่คำนวณ กำหนดแน่นอน
การตรวจจับชื่อ สถานที่ และวันที่ทำนาย โมเดลเชิงสถิติของ spaCy ผ่าน Presidio บนซีพียู
การตรวจจับตัวเลขและตัวระบุที่คล้ายกันคำนวณ รูปแบบ checksum และคำบริบท

ที่เก็บโค้ดไม่ได้ฝึกหรือรวมโมเดลใด ๆ มา

ในโค้ดตารางเดียวกันพร้อมที่ที่แต่ละบล็อกรัน

7. ข้อจำกัด: สิ่งที่ไม่ถูกลบ

ส่วนที่มีประโยชน์ที่สุดสำหรับการตัดสินใจว่าชุดข้อมูลแบ่งปันได้หรือไม่

  1. ภาพทั้งหมด: ไม่มีสิ่งใดในไฟล์ภาพหรือส่วนหัวถูกอ่านหรือเปลี่ยน
  2. ชื่อไฟล์และโฟลเดอร์: ชื่อผู้ป่วยในชื่อไฟล์อยู่รอดไปถึงชื่อเอาต์พุตและในตารางการจับคู่ และลำดับชั้นโฟลเดอร์ถูกทำให้แบน
  3. ตัวระบุของโรงพยาบาล: หมายเลขเวชระเบียน accession และเตียงไม่มี recognizer
  4. ทุกอย่างที่ไม่ใช่ของอเมริกัน: ค้นเฉพาะหมายเลขของสหรัฐ ไม่ค้น NIR ของฝรั่งเศส หมายเลข NHS หรือหนังสือเดินทาง
  5. ตัวระบุทางอ้อม: อายุเกิน 89 วันที่หายาก อาชีพ วันที่ถูกแทนที่ทั้งก้อนหรือไม่ก็ไม่แทนที่เลย
  6. ภาษา: การตรวจจับตกลงอย่างรุนแรงบนข้อความที่ไม่ใช่ภาษาอังกฤษ โดยไม่มีคำเตือน
  7. ค่าthreshold 0.5 ทิ้งการตรวจจับที่ไม่แน่นอนกว่า แต่การตรวจจับไหนนั้นขึ้นกับ recognizer: การตรวจจับชื่อ สถานที่ และวันที่ของ spaCy ได้คะแนนคงที่ค่าเดียวกันทั้งหมด (0.85 โดยค่าเริ่มต้นใน Presidio 2.2.355 และ 2.2.366) ดังนั้น threshold 0.5 จึงไม่แยกชื่อที่หายากออกจากชื่อที่พบบ่อย มันมีผลส่วนใหญ่กับ recognizer ที่อิงรูปแบบ
  8. เนื้อหาที่ไม่ได้สกัด: ตาราง แอตทริบิวต์ หน้าที่สแกน ส่วนหัว
  9. ความล้มเหลวเงียบ ข้อค้นพบที่ร้ายแรงที่สุด หากการวิเคราะห์เกิดข้อผิดพลาดใด ๆ โมดูลจะเขียนไฟล์ _anonymized ที่มีข้อความต้นฉบับโดยไม่เปลี่ยนแปลง รายงานว่า “Complete!” และทิ้งบรรทัดสีแดงหนึ่งบรรทัดในคอนโซล Python ไม่มีอะไรนับเอนทิตีที่พบหรือตรวจสอบภายหลัง (รายละเอียด)

ในทางปฏิบัติ เอาต์พุตเป็นการผ่านครั้งแรกบนข้อความอิสระภาษาอังกฤษ ต้องมีการทบทวน และต้องมีการเปลี่ยนชื่อไฟล์ ตัวทำให้ DICOM นิรนามโดยเฉพาะสำหรับภาพ และการ deface หากปริมาตรครอบคลุมใบหน้า

ในโค้ดข้อจำกัดทั้งเก้าฉบับเต็ม พร้อมโค้ดของความล้มเหลวเงียบ

8. สภาพแวดล้อม

ทุกอย่างรันใน Python ของ Slicer ติดตั้งด้วยปุ่มเดียวโดยไม่มีการยืนยันและไม่ล็อกเวอร์ชัน ตามด้วยการดาวน์โหลดโมเดล spaCy ภาษาอังกฤษ และคำขอให้รีสตาร์ท Slicer ไม่มี GPU ไม่มี conda ไม่มีงานบรรทัดคำสั่ง การโหลดเอนจินใช้เวลาไม่กี่วินาทีบนเธรดของอินเทอร์เฟซทุกครั้งที่รัน คำเตือนถูกปิดสำหรับ Slicer ทั้งหมดทันทีที่โมดูลโหลด

ในโค้ดรายการแพ็กเกจ dependency ที่ไม่ได้ใช้ และตัวกรองคำเตือนระดับโมดูล

9. ปัญหาที่ทราบ

  • ความล้มเหลวเงียบที่คืนข้อความต้นฉบับ (รายละเอียด)
  • โฟลเดอร์เอาต์พุตแบบแบนเขียนทับไฟล์ที่ชื่อเดียวกันโดยไม่มีข้อความ (กับดักทั้งหมด)
  • ไฟล์ CSV ถูกจัดโครงสร้างใหม่ XML ลดเหลือข้อความล้วน และ ODT ถูกเปลี่ยนชื่อเป็นข้อความ (กับดักทั้งหมด)
  • UUID ของตารางการจับคู่ถูกสร้างแต่ไม่เคยถูกใช้ (รายละเอียด)
  • ทุกอย่างรันบนเธรดของอินเทอร์เฟซ Slicer จึงดูเหมือนค้างบนโฟลเดอร์ใหญ่ (กับดักทั้งหมด)
  • README พูดถึงการปฏิบัติตาม HIPAA และการวิเคราะห์ด้วย AI ทั้งที่โค้ดเป็นการเรียก Presidio เริ่มต้นบนข้อความภาษาอังกฤษ (กับดักทั้งหมด)
  • โมดูลไม่มีการทดสอบ และไม่มีอะไรที่สคริปต์เรียกได้ (กับดักทั้งหมด)
ในโค้ดทุกกับดักพร้อมบรรทัด รวมถึงการ replace ในชื่อไฟล์

10. วรรณกรรมและเอกสารอ้างอิง

ไม่มีบทความใดครอบคลุมโมดูลนี้ และในที่เก็บโค้ดก็ไม่มีการประเมิน (recall, precision) บนคอร์ปัสใดเลย

ส่วนประกอบที่ใช้มีเอกสารรองรับ:

  • Microsoft Presidio: เอนจินตรวจจับและทำให้นิรนาม พร้อมรายการที่แน่นอนของ recognizer และ operator ที่กำหนดไว้ล่วงหน้า (replace, redact, hash, mask, encrypt ซึ่งอย่างหลังย้อนกลับได้ด้วย key และโมดูลไม่ได้เปิดให้ใช้)
  • spaCy en_core_web_lg: โมเดล NER ภาษาอังกฤษที่ใช้โดยค่าเริ่มต้น
  • HIPAA Safe Harbor, 45 CFR §164.514(b)(2): ตัวระบุ 18 หมวดที่ต้องลบ มีประโยชน์เป็นตารางอ่านสำหรับ§7: ชื่อไฟล์ ตัวระบุเวชระเบียน และตัวระบุของภาพปรากฏอยู่ที่นั่น และโมดูลนี้ไม่จัดการสิ่งเหล่านั้น

บรรณานุกรมฉบับเต็ม: SOURCES.html ค้นแล้ว ผลเป็นลบสำหรับตัวโมดูลเอง โฟลเดอร์มีการประเมิน Presidio บนข้อความทางคลินิกที่ไม่มีโครงสร้างที่ตีพิมพ์เพียงชิ้นเดียว และลิงก์ไปยังแคมเปญลบข้อมูลระบุตัวตนของข้อความ i2b2/n2c2 ซึ่งไม่ได้อธิบายโค้ดนี้ แต่ให้ตารางอ่านของมัน

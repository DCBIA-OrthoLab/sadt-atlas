MedicalDataAnonymizer

การตรวจจับและแทนที่ entity ที่อ่อนไหวในเอกสารข้อความ (DOCX, TXT, PDF, CSV, XML, ODT) ผ่าน Microsoft Presidio — โมดูลไม่แตะภาพทางการแพทย์เลย: นี่ไม่ใช่เครื่องมือปกปิดข้อมูล DICOM

ยังไม่ตีพิมพ์ ไม่มี CLI (Slicer widget) เธรด UI ไม่ใช้ conda บรรณานุกรม
ข้อควรระวังเรื่องคำศัพท์

ชื่อชวนให้คิดว่าเป็นเครื่องมือปกปิดข้อมูล DICOM แต่ไม่ใช่เลย: MedicalDataAnonymizer ลบข้อมูลระบุตัวตนในเอกสารข้อความ ผ่าน Presidio + spaCy ไม่มีแท็ก DICOM ใด (PatientName, PatientID, UID…) ถูกอ่านหรือแก้ไข และไม่มีการลบใบหน้า (defacing) กับภาพใดเลย ทั้ง extension ไม่มีเครื่องมือ defacing แม้แต่ตัวเดียว

0. สิ่งที่โมดูลนี้ไม่ใช่

ชื่อชวนให้คิดว่าเป็นเครื่องมือปกปิดข้อมูล DICOM แต่ไม่ใช่เลย และตรวจสอบได้ด้วยคำสั่งเดียว:

$ grep -rin "dicom\|pydicom\|deface" Medical_Data_Anonymizer_Module/
(no result)
$ grep -rlni "deface" --include="*.py" --include="*.md" .
(no result anywhere in the repository)

ผลที่ตามมาโดยตรง:

  • ไม่มีแท็ก DICOM ใดถูกลบหรือแทนที่เลย: ไม่ว่าจะเป็น PatientName (0010,0010), PatientID (0010,0020), PatientBirthDate, StudyDate, InstitutionName, UID ต่าง ๆ, private tags หรือ BurnedInAnnotation
  • ไม่มีการลบใบหน้า: ใบหน้าที่สร้างขึ้นใหม่ได้จากภาพ CBCT หรือภาพสแกนไม่เคยถูกเปลี่ยนแปลงด้วยวิธีใดเลย (ไม่มีมาสก์ใบหน้า ไม่มีการเบลอ ไม่มีการลบพื้นผิว) ไม่มีเครื่องมือ defacing ที่ใดใน extension ทั้งหมด
  • รูปแบบที่รองรับ (.docx, .txt, .pdf, .csv, .xml, .odt, Medical_Data_Anonymizer_Module.py:506) ไม่ครอบคลุม .dcm, .nii.gz, .nrrd, .vtk หรือ .json ของ landmark เลย

ผู้ที่ต้องตัดสินใจว่าข้อมูลแชร์ได้หรือไม่ ควรอ่าน §7 โดยตรง

1. ตำแหน่งใน pipeline

เครื่องมือแยกเดี่ยว ไม่มี CLI ไม่มีสิ่งใดเรียกใช้ และไม่เรียกสิ่งอื่นในรีโพสิทอรี ทุกอย่างอยู่ในไฟล์เดียว 767 บรรทัด ซึ่ง ~350 บรรทัดเป็น stylesheet ของ Qt: Medical_Data_Anonymizer_Module.py

Medical_Data_Anonymizer_ModuleLogic และ …Test เป็นคลาสว่าง (pass): ตรรกะทั้งหมดอยู่ใน widget จึงทำงานบนเธรดหลักของ Slicer อินเทอร์เฟซจะค้างระหว่างประมวลผล มีเพียง slicer.app.processEvents() ที่รีเฟรชแถบความคืบหน้า

2. อินพุต: การสกัดข้อความทีละรูปแบบ

ไล่อ่านโฟลเดอร์อินพุตแบบเรียกซ้ำ (os.walk) ไฟล์ที่ขึ้นต้นด้วย ~$ (ไฟล์ล็อกของ Word) จะถูกข้าม แต่ละไฟล์ถูกลดรูปเป็นสตริงอักขระเดียวก่อนวิเคราะห์:

รูปแบบการสกัดสิ่งที่สูญหายระหว่างทาง
.docxpython-docx, "\n".join(p.text for p in doc.paragraphs)ตาราง หัวกระดาษ/ท้ายกระดาษ เชิงอรรถ กล่องข้อความ ความคิดเห็น metadata ของไฟล์
.txtอ่าน UTF-8 ดิบ—
.pdfpdfplumber, page.extract_text() หากเกิด exception จะลองครั้งที่สองผ่าน extract_tables()ภาพ PDF ที่สแกนมา (ไม่มี OCR) → ข้อความว่าง
.csvcsv.reader แต่ละแถวถูกรวบเป็นบรรทัดเดียวด้วย " ".join(row)โครงสร้างคอลัมน์
.xmlElementTree + extract_text_from_xml() แบบเรียกซ้ำ (text + tail)แท็กและแอตทริบิวต์: ค่าของแอตทริบิวต์ไม่เคยถูกอ่าน
.odtodfpy, text node ของ text.Pตาราง สไตล์ metadata

การสูญหายไม่ใช่แค่เรื่องความเที่ยงตรง: เอกสารเอาต์พุตถูกสร้างใหม่จากสตริงนี้ สิ่งที่ไม่ถูกสกัดจะไม่ถูกปกปิดข้อมูล แต่ก็ไม่ถูกนำไปยังเอาต์พุตด้วย มันหายไป ในทางกลับกัน เนื้อหาที่อ่อนไหวซึ่งอยู่ในส่วนที่ไม่ถูกสกัด (ตารางใน DOCX แอตทริบิวต์ใน XML) จะไม่ถูกตรวจจับและไม่ถูกนำไปยังเอาต์พุต: ไม่รั่วไหล แต่ข้อมูลสูญหายโดยไม่มีสัญญาณเตือน

ข้อยกเว้นที่ควรสังเกต: ไม่มีสิ่งใดอ่าน metadata ของไฟล์ (ผู้เขียน DOCX หรือ Producer ของ PDF) metadata จึงหายไปด้วย เพราะไฟล์ถูกสร้างใหม่ตั้งแต่ต้น

3. เอนจินตรวจจับ

ไม่มีโมเดลในรีโพสิทอรี ไม่มีน้ำหนักที่โมดูลดาวน์โหลดเองนอกจากโมเดล spaCy เอนจิน Presidio สองตัวถูกสร้างทุกครั้งที่คลิก "Anonymize Files" (…py:493) โดย stderr ถูกตัดผ่านคลาส SuppressStderr:

analyzer = AnalyzerEngine()      # default config
anonymizer = AnonymizerEngine()

AnalyzerEngine() ที่ไม่มีอาร์กิวเมนต์ใช้การตั้งค่า NLP เริ่มต้นของ Presidio คือ spaCy en_core_web_lg ซึ่งเป็นโมเดลเดียวที่ install_dependencies() ดาวน์โหลด (spacy.cli.download, …py:411)

recognizer สองตระกูลทำงานร่วมกัน: NER เชิงสถิติของ spaCy (PERSON, LOCATION, DATE_TIME) และrecognizer ที่อิงรูปแบบและ checksum (PHONE_NUMBER, EMAIL_ADDRESS, US_SSN, MEDICAL_LICENSE, US_DRIVER_LICENSE, CREDIT_CARD, US_BANK_NUMBER, IP_ADDRESS, URL)

ข้อควรระวัง

ภาษาถูกล็อกเป็นภาษาอังกฤษ: analyzer.analyze(..., language='en') (…py:713) ทั้งที่มีคอมเมนต์ว่า "with automatic language detection" และมีการติดตั้ง langdetect ซึ่งไม่เคยถูก import เป็น dependency ที่ไม่ได้ใช้ โฟลเดอร์บันทึกภาษาฝรั่งเศสจะผ่านโมเดลภาษาอังกฤษ ได้ค่า recall ตามที่คาดได้

ค่าเกณฑ์ความเชื่อมั่น: score_threshold แถบเลื่อน 0.0–1.0 ค่าเริ่มต้น 0.5 ผลการตรวจจับที่ต่ำกว่าเกณฑ์จะถูกทิ้งโดยไม่เหลือร่องรอย

4. Entity และวิธีแทนที่

checkbox สิบสองช่อง เลือกไว้เจ็ดช่องเป็นค่าเริ่มต้น (…py:90):

Entity ของ Presidioป้ายใน UIค่าเริ่มต้น
PERSON ทำนายNames (patients, doctors)✔
PHONE_NUMBER คำนวณPhone Numbers✔
EMAIL_ADDRESS คำนวณEmail Addresses✔
DATE_TIME ทำนายDates and Times✔
LOCATION ทำนายAddresses and Locations✔
US_SSN คำนวณSocial Security Numbers✔
MEDICAL_LICENSE คำนวณMedical License Numbers✔
US_DRIVER_LICENSE, CREDIT_CARD, US_BANK_NUMBER, IP_ADDRESS, URL คำนวณ—✘

สี่วิธี ใน "Advanced Options" (…py:720):

วิธีการอิมพลีเมนต์ผลลัพธ์
replace (ค่าเริ่มต้น)operators = {} → ส่งเป็น None → operator เริ่มต้นของ Presidio<PERSON>, <DATE_TIME>, …
redactOperatorConfig("redact") ต่อ entityข้อความที่พบหายไป และข้อความรอบข้างต่อชิดกัน
hashOperatorConfig("hash")SHA-256 ที่ไม่มี salt ของข้อความที่ตรวจพบ
maskOperatorConfig("mask", {"masking_char": "*", "chars_to_mask": 100, "from_end": False})เครื่องหมายดอกจันทับข้อความที่พบทั้งหมด

เรื่อง hash: README กล่าวถึง "cryptographic hashes for consistent anonymization" ข้ออ้างเรื่องความสม่ำเสมอเป็นจริง (ชื่อเดียวกันให้ digest เดียวกันเสมอ) แต่ไม่มีทั้ง salt และ key: กับพื้นที่ค่าที่เล็กอย่างชื่อ วันเกิด หรือหมายเลขประกันสังคม digest สามารถระบุตัวตนกลับได้ด้วย brute force ภายในไม่กี่วินาที ควรถือเป็นนามแฝงสาธารณะ ไม่ใช่การป้องกัน

5. เอาต์พุตและตารางการจับคู่

เขียนแบบแบนลงในโฟลเดอร์เอาต์พุต ลำดับชั้นโฟลเดอร์ย่อยของอินพุตไม่ถูกสร้างซ้ำ

อินพุตเอาต์พุตหมายเหตุ
x.docxx_anonymized.docxเอกสารที่สร้างใหม่ หนึ่งย่อหน้าต่อบรรทัด ไม่มีการจัดรูปแบบ
x.txtx_anonymized.txt—
x.pdfx_anonymized.pdfสร้างใหม่ด้วย reportlab เป็นบล็อก Preformatted เดียว
x.csvx_anonymized.csvดูด้านล่าง

x.odtx_anonymized.txtเปลี่ยนนามสกุล

กรณี CSV ทำลายข้อมูลมากที่สุด: ไฟล์ถูกอ่านโดยรวบแต่ละแถวด้วยช่องว่าง แล้วเขียนกลับด้วย writer.writerow(line.split()) (…py:632) เซลล์ใดที่มีช่องว่างจะถูกแยกออกเป็นหลายคอลัมน์ และเซลล์ว่างจะหายไป: การเรียงคอลัมน์ไม่ถูกรักษาไว้ CSV ของค่าวัดจะออกมาใช้งานไม่ได้

ตารางการจับคู่ file_mappings.csv เขียนลงในโฟลเดอร์เอาต์พุต (…py:648):

คอลัมน์เนื้อหา
Original File Nameชื่อไฟล์ต้นทาง
Anonymized File Nameชื่อที่สร้างขึ้น หรือ ERROR
UUIDuuid.uuid4() ที่สุ่มต่อไฟล์ หรือข้อความ exception เมื่อล้มเหลว

นี่ไม่ใช่ตารางสำหรับระบุตัวตนบุคคลกลับ: ไม่มีการจับคู่ระหว่างชื่อที่ตรวจพบกับสิ่งที่ใช้แทน และ UUID เป็นเพียงของประดับ ถูกสร้างขึ้น (…py:531) แล้วไม่เคยถูกใช้: ไม่ปรากฏทั้งในเนื้อหาและในชื่อไฟล์เอาต์พุต จึงไม่มีกลไกการทำนามแฝง (pseudonymisation) ที่คงที่ข้ามเอกสาร

ข้อควรระวัง

ไฟล์ file_mappings.csv นี้ถูกเขียนไว้ข้าง ๆ เอกสารที่ปกปิดข้อมูลแล้ว: การแชร์โฟลเดอร์เอาต์พุตจึงเท่ากับการแชร์รายชื่อไฟล์ต้นฉบับ

7. ข้อจำกัด: สิ่งที่ไม่ถูกลบ

หัวข้อที่มีประโยชน์ที่สุดสำหรับการตัดสินใจว่าชุดข้อมูลแชร์ได้หรือไม่

อยู่นอกขอบเขตโดยการออกแบบ

  1. ภาพทั้งหมด DICOM, NIfTI, NRRD, เมช: ไม่เคยถูกอ่าน ไม่เคยถูกแก้ไข ไม่มีแท็กในส่วนหัวใดถูกทำความสะอาด ไม่มีใบหน้าใดถูกลบ (§0)
  2. ชื่อไฟล์และโฟลเดอร์ Dupont_Jean_2019.docx กลายเป็น Dupont_Jean_2019_anonymized.docx ชื่อผู้ป่วยยังคงอยู่ครบในชื่อไฟล์ และถูกคัดลอกตามตัวอักษรลงใน file_mappings.csv ลำดับชั้นของอินพุต ซึ่งมักระบุตัวตนได้ไม่แพ้กัน (.../Patients/Dupont_Jean/) ถูกทำให้แบน และหากโฟลเดอร์ย่อยสองโฟลเดอร์มีไฟล์ชื่อเดียวกัน ไฟล์ที่สองจะเขียนทับไฟล์แรกโดยไม่มีคำเตือน

จุดบอดของการตรวจจับ

  1. รหัสประจำตัวของโรงพยาบาล ไม่มี recognizer สำหรับ MRN หมายเลขแฟ้ม หมายเลข accession รหัสการตรวจ หมายเลขเตียง ไม่อยู่ใน entity สิบสองตัวที่มีให้เลือก และ Presidio ก็ไม่มีโดยค่าเริ่มต้น
  2. สิ่งใดก็ตามที่ไม่ใช่ของสหรัฐฯ entity ที่เลือกได้คือ US_SSN, US_DRIVER_LICENSE, US_BANK_NUMBER: NIR ของฝรั่งเศส หมายเลข NHS หมายเลขหนังสือเดินทาง หรือ ITIN จะไม่ถูกค้นหา
  3. ตัวระบุทางอ้อมตาม HIPAA ไม่ถูกจัดการ: อายุเกิน 89 ปี วันที่ที่พบไม่บ่อย อาชีพ การเป็นสมาชิกกลุ่มเล็ก Presidio ไม่ทำ generalisation ของวันที่ DATE_TIME ถูกแทนที่ทั้งหมดหรือไม่ถูกแทนที่เลย
  4. ภาษา การวิเคราะห์ถูกล็อกเป็นภาษาอังกฤษ (§3): กับคลังข้อมูลที่ไม่ใช่ภาษาอังกฤษ ค่า recall ของ PERSON/LOCATION/DATE_TIME จะลดลงอย่างมาก โดยไม่มีคำเตือนใด ๆ
  5. ค่าเกณฑ์ 0.5 ทิ้งผลการตรวจจับที่ไม่แน่นอนทั้งหมดโดยค่าเริ่มต้น ซึ่งมักเป็นชื่อที่พบไม่บ่อย ชื่อที่ไม่ใช่แบบแองโกล-แซกซอน และรูปย่อ
  6. เนื้อหาที่ไม่ถูกสกัด (ตารางใน DOCX แอตทริบิวต์ใน XML, PDF ที่สแกนมา หัวกระดาษและท้ายกระดาษ) ไม่ถูกวิเคราะห์ ไม่รั่วไหลไปยังเอาต์พุต แต่หากผู้รับได้รับไฟล์ต้นฉบับด้วย การปกปิดข้อมูลก็ไม่เคยครอบคลุมส่วนนั้น

ความล้มเหลวแบบเงียบ — ข้อค้นพบที่ร้ายแรงที่สุด

  1. anonymize_text_presidio() จบด้วย (…py:748):

    บั๊กที่ยืนยันแล้ว — ความล้มเหลวแบบเงียบ

    ข้อผิดพลาดใด ๆ ในการวิเคราะห์ (entity ที่ Presidio เวอร์ชันที่ติดตั้งไม่รู้จัก โมเดล spaCy ที่ขาดหาย ข้อความที่ยาวเกินไป) จะให้ไฟล์ _anonymized ที่มีข้อความต้นฉบับครบถ้วน พร้อมสถานะ "Complete!" ในอินเทอร์เฟซ และบรรทัดสีแดงเพียงบรรทัดเดียวในคอนโซล Python ไม่มีการตรวจสอบภายหลัง ไม่มีการนับ entity ที่ตรวจพบ ไม่มีรายงาน เอกสารที่ไม่ถูกปกปิดข้อมูลจะแยกไม่ออกจากเอกสารที่สะอาดหากไม่ได้อ่าน

ข้อสรุปในทางปฏิบัติ เอาต์พุตของโมดูลนี้เพียงอย่างเดียวไม่เพียงพอที่จะประกาศว่าชุดข้อมูลถูกลบข้อมูลระบุตัวตนแล้ว เป็นเพียงรอบแรกบนข้อความอิสระภาษาอังกฤษที่ต้องตรวจทาน และต้องเสริมด้วย: การเปลี่ยนชื่อไฟล์ เครื่องมือปกปิดข้อมูล DICOM โดยเฉพาะสำหรับภาพ และการลบใบหน้าหากวอลุ่มครอบคลุมใบหน้า

8. สภาพแวดล้อม

ทุกอย่างทำงานใน Python ของ Slicer ติดตั้งด้วยปุ่ม "Install Dependencies" (…py:392) โดยไม่มีการยืนยันและไม่ตรึงเวอร์ชัน:

presidio-analyzer, presidio-anonymizer, pandas, python-docx, pdfplumber,
odfpy, lxml, langdetect, reportlab    then    spacy.cli.download("en_core_web_lg")

หมายเหตุ:

  • spacy ไม่อยู่ในรายการ pip_install: ถูกimportเท่านั้น (…py:409) ใช้งานได้เพราะ presidio-analyzer ดึงมาเป็น dependency หาก import นั้นล้มเหลว ทั้งบล็อกจะตกไปที่ except และแสดง "Error installing dependencies."
  • มีการขอให้รีสตาร์ท Slicerหลังติดตั้ง (กล่องโต้ตอบ) ซึ่งสอดคล้องกับการโหลดโมเดล spaCy
  • lxml ถูกติดตั้งแต่ไม่ได้ใช้ (โค้ดใช้ xml.etree.ElementTree) ส่วน langdetect ถูกติดตั้งแต่ไม่เคยถูก import
  • os.environ['PRESIDIO_SUPPRESS_WARNINGS'] = '1' และ warnings.filterwarnings('ignore') ถูกตั้งที่ระดับโมดูล คือทันทีที่ extension โหลด: จึงปิดคำเตือนของ Slicer ทั้งหมด ไม่ใช่เฉพาะของ Presidio
  • ไม่มี GPU ไม่มี conda ไม่มี CLI: AnalyzerEngine() และการโหลด spaCy (ไม่กี่วินาที) เกิดขึ้นบนเธรดของอินเทอร์เฟซในทุกการรัน

9. ข้อควรระวังและจุดเปราะบาง

  • ความล้มเหลวแบบเงียบ ที่คืนข้อความต้นฉบับ (§7.9)
  • โฟลเดอร์เอาต์พุตแบบแบน: ชื่อชนกัน เขียนทับโดยไม่มีข้อความแจ้ง
  • CSV ถูกจัดโครงสร้างใหม่ ด้วย line.split(), XML ถูกลดเป็นข้อความธรรมดา, ODT ถูกเปลี่ยนชื่อเป็น .txt
  • UUID ถูกสร้างแต่ไม่เคยถูกใช้: "ตารางการจับคู่" ไม่ช่วยให้ระบุตัวตนกลับอย่างมีการควบคุมได้
  • file.replace(".docx", "_anonymized.docx"): str.replace แทนที่ทุกตำแหน่งที่พบ ชื่อที่มีนามสกุลซ้ำสองครั้งจะให้ผลที่ไม่คาดคิด
  • PDF เอาต์พุตไม่มีการแบ่งหน้า (บล็อก Preformatted เดียว): เอกสารยาวอาจล้นกรอบหรือทำให้เกิด exception ของ reportlab ซึ่งในกรณีนั้นไฟล์จะถูกนับเป็น ERROR แต่การประมวลผลยังดำเนินต่อ
  • ทุกอย่างทำงานบนเธรด UI: กับโฟลเดอร์ขนาดใหญ่ Slicer จะดูเหมือนค้าง
  • README พูดเกินจริงเกี่ยวกับโมดูล: กล่าวถึงการปฏิบัติตาม HIPAA และ "AI-powered text analysis" ขณะที่โค้ดเป็นการเรียก Presidio แบบค่าเริ่มต้นกับข้อความภาษาอังกฤษ โดยไม่มีการตรวจสอบความถูกต้อง
  • README ชี้ไปที่ Medical_Data_Anonymizer_Module/Resources/Icons/icon.png ขณะที่ไฟล์ที่มีอยู่จริงชื่อ Medical_Data_Anonymizer_Module.png
  • Medical_Data_Anonymizer_ModuleLogic / …Test เป็นเปลือกว่าง: ไม่มีการทดสอบ และไม่มีสิ่งใดเรียกได้จากสคริปต์

10. เอกสารอ้างอิง

ไม่มีบทความใดครอบคลุมโมดูลนี้ และไม่มีการประเมินผล (recall, precision) ในรีโพสิทอรีบนคลังข้อมูลใดเลย

ส่วนประกอบที่ใช้มีเอกสารประกอบ:

  • Microsoft Presidio — เอนจินตรวจจับและปกปิดข้อมูล พร้อมรายการ recognizer และ operator ที่กำหนดไว้ล่วงหน้าอย่างครบถ้วน (replace, redact, hash, mask, encrypt ซึ่งตัวหลังสุดย้อนกลับได้ด้วยกุญแจ และโมดูลไม่มีให้เลือก)
  • spaCy en_core_web_lg — โมเดล NER ภาษาอังกฤษที่ใช้เป็นค่าเริ่มต้น
  • HIPAA Safe Harbor, 45 CFR §164.514(b)(2) — ตัวระบุ 18 หมวดที่ต้องลบออก มีประโยชน์เป็นกรอบการอ่านสำหรับ §7: ชื่อไฟล์ รหัสเวชระเบียน และตัวระบุของภาพอยู่ในรายการนี้ และโมดูลนี้ไม่ได้จัดการสิ่งเหล่านั้น

CLIC, legacy: โค้ด

สำหรับนักพัฒนา: โมดูล CLIC แบบ legacy ทำอะไรในโค้ด พร้อมการอ้างอิง file:line โค้ด อาร์กิวเมนต์ สภาพแวดล้อม และข้อควรระวัง คำอธิบายที่อ่านง่ายของไปป์ไลน์เดียวกัน พร้อมคณิตศาสตร์ อยู่ในหน้าแอตลาส

โค้ด แอตลาส (คำอธิบาย) ยังไม่เผยแพร่ VISOR clic_runner.py conda env: clic_env Python 3.9 บรรณานุกรม

Classification and Localization of Impacted Canines การแบ่งส่วนอินสแตนซ์ 2D ทีละสไลซ์ของ CBCT ด้วย torchvision Mask R-CNN ซึ่งคลาสที่ทำนายเข้ารหัสตำแหน่งภายในกระดูกของเขี้ยวฝัง: buccal, bicortical, palatal

ชื่อของโมดูลสัญญาสองงาน แต่โค้ดมีโครงข่ายเดียวเท่านั้น ไม่มีโครงข่ายจำแนกแยก ไม่มีโครงข่ายระบุตำแหน่งแยก และไม่มีหัวถดถอยพิกัด การจำแนกคือ label ของอินสแตนซ์ (pr["labels"]); การระบุตำแหน่งคือมาสก์ (pr["masks"]): ทั้งสองออกมาจากรอบ Mask R-CNN เดียวกัน ทุกอย่างด้านล่างสืบเนื่องจากนี้

โค้ดสองชุด

ทุกอย่างที่มีเลขกำกับด้านล่างอธิบายโมดูล Slicer แบบ legacy (SlicerAutomatedDentalTools ที่ 3c67957, 2026-10-26) การพอร์ต VISOR ซึ่งรันเครื่องมือเดียวกันบนเซิร์ฟเวอร์ มีหน้าของตัวเอง: CLIC บน VISOR กล่องหมายเหตุด้านล่างที่ไม่เป็นจริงใน VISOR อีกแล้วจะบอกไว้ในหัวข้อ

3.2 พรีโปรเซสวอลุ่มจริง

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

มันอยู่ในสามบรรทัด (CLIC/runner/clic_runner.py:80-83):

sl = _norm(vol[..., z])                                    # min-max of the slice
t  = torch.from_numpy(sl).unsqueeze(0).repeat(3, 1, 1).float().to(device)
pr = model([t])[0]

กล่าวอีกอย่างคือ:

  • การหั่นเป็นสไลซ์แอกเซียลตามแกนที่ 3ของอาร์เรย์ nibabel ตามลำดับการจัดเก็บของไฟล์ ไม่ใช่ตามทิศทางทางกายวิภาคที่คำนวณใหม่ ไม่มีการจัดทิศ RAS/LPS โค้ดไม่เคยดู nii.affine นอกจากเพื่อเขียนมันใหม่;
  • min-max normalization ต่อสไลซ์ (_norm, CLIC/runner/clic_runner.py:44): (x - min) / (max - min) และสไลซ์ค่าคงที่กลายเป็นศูนย์ ไม่มี Hounsfield windowing ไม่มีการตัดเปอร์เซ็นไทล์ ไม่มีสถิติเชิงปริมาตร: แต่ละสไลซ์มีคอนทราสต์ของตัวเอง สไลซ์ที่มีแต่อากาศถูกยืดไปทั่วช่วงไดนามิกทั้งหมด;
  • การทำซ้ำเป็น 3 ช่องให้ตรงกับอินพุต RGB ของ backbone ImageNet;
  • ไม่มีการครอป ไม่มี ROI ไม่มีการ resample ที่ระบุชัด ไม่มีการปรับสเกล voxel

การปรับขนาดอย่างเดียวมาจาก torchvision เอง: GeneralizedRCNNTransform ที่ฝังในโมเดลมาตรฐานด้วยค่าเฉลี่ย ImageNet ([0.485,0.456,0.406] / [0.229,0.224,0.225]) และปรับขนาดให้ด้านสั้นเป็น 800 px โดยจำกัดด้านยาวที่ 1333 px นี่เป็นค่าเริ่มต้นของ torchvision ไม่ใช่การเลือกในรีโพซิทอรี: CBCT 512×512 จึงถูกขยายเป็น 800×800 ก่อนเข้า backbone

m = maskrcnn_resnet50_fpn(weights=None)
m.roi_heads.box_predictor  = FastRCNNPredictor(in_f, nc)
m.roi_heads.mask_predictor = MaskRCNNPredictor(in_fm, 256, nc)

  • RPN แล้วROI heads: box head (FastRCNNPredictor: cls_score 4 คลาส, bbox_pred 16 เอาต์พุต) และ mask head (MaskRCNNPredictor, ชั้นซ่อน 256, 4 ช่องเอาต์พุต, มาสก์ 28×28 ต่อ ROI);

10. วรรณกรรม

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

ไม่มีบทความใดครอบคลุม CLIC งานที่ตรงกันถูกประกาศภายใต้ชื่อ Interpretable Deep Learning for the Detection and Classification of Impacted Canines and severity of root resorption (Tulissi, Cevidanes, Prieto) นำเสนอที่ NA-MIC Project Week 43 (Montreal, 2025): เป็นโครงการที่กำลังดำเนินอยู่ ไม่ใช่สิ่งตีพิมพ์ โค้ดต้นฉบับมาจากรีโพซิทอรีส่วนตัว ashmoy/maskRcnn ซึ่งเป็นที่มาของสแกนทดสอบที่ README อ้างถึงด้วย (MN138.nii, UM06.nii)

อย่าสับสนกับงานข้างเคียงด้านล่าง ซึ่งไม่ได้สร้างโค้ดนี้:

  • การระบุตำแหน่ง buccal/palatal ของเขี้ยวฝังตามธรรมเนียมทำบนภาพรังสีพาโนรามิก ด้วย CNN จำแนกภาพ (ไม่ใช่ Mask R-CNN บน CBCT);
  • หลายทีมเผยแพร่การแบ่งส่วน 3Dของเขี้ยวฝังบน CBCT (U-Net เชิงปริมาตร/nnU-Net) โดยไม่จำแนกตำแหน่งคอร์เทกซ์

ความจำเพาะของ CLIC คือคลาสbicorticalนอกเหนือจากคู่ buccal/palatal ซึ่งทำนายทีละสไลซ์แบบ 2D บน CBCT ไม่ได้ถูกอธิบายในบทความเหล่านี้เลย อย่านำเสนอตัวเลขของพวกมันว่าเป็นของโมดูลนี้

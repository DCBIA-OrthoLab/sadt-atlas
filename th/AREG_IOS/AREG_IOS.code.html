AREG_IOS, legacy: โค้ด

สำหรับนักพัฒนา: โมดูล Slicer แบบ legacy ทำอะไรในโค้ด พร้อมการอ้างอิง file:line ซิกเนเจอร์ บรรทัดคำสั่งที่แน่นอน สภาพแวดล้อม และข้อควรระวัง คำอธิบายที่อ่านง่ายของไปป์ไลน์เดียวกัน พร้อมคณิตศาสตร์ อยู่ในหน้าแอตลาส การพอร์ต VISOR มีหน้าของตัวเอง

โค้ด แอตลาส (คำอธิบาย) Hutin 2023 · LNCS 14350 AREG_IOS conda env: shapeaxi VISOR บรรณานุกรม

การลงทะเบียนภาพตามยาว T1/T2 ของ Intra Oral Scan หลักการเดียวกับ FlexReg.md คือ ICP แบบแข็งเกร็งที่จำกัดอยู่ในบริเวณที่คงที่ แต่บริเวณนั้นถูกทำนายโดยเครือข่าย แทนที่จะถูกวาดโดยผู้ปฏิบัติงาน และการประมวลผลรันเป็นชุดของโฟลเดอร์ แทนที่จะทีละผู้ป่วย

สองโหมดอยู่ร่วมกันใน CLI เดียวกัน:

  • Butterfly: ฟันบน, patch เพดานปากที่ทำนายโดย MonaiUNetHRes หลายมุมมอง;
  • MGL: ฟันล่าง, แถบgeodesicรอบ mucogingival line สร้างจาก landmark MG 13 จุดที่ ALI_IOS ทำนาย เป็นโค้ดเดียวกับเส้นทาง MGL ของ FlexReg ที่คัดลอกเข้ามาใน CLI
โค้ดสองชุด

ทุกอย่างที่มีเลขกำกับด้านล่างอธิบายโมดูล Slicer แบบ legacy (SlicerAutomatedDentalTools ที่ 3c67957, 2026-10-26) การพอร์ต VISOR ซึ่งรันเครื่องมือเดียวกันบนเซิร์ฟเวอร์ มีหน้าของตัวเอง: AREG_IOS บน VISOR หมายเหตุที่เปิดกล่องบางกล่องด้านล่าง (“เฉพาะ Legacy”, “เป็นจริงใน VISOR ด้วย”) เปรียบเทียบกับการพอร์ตนั้นที่ SADT-VISOR 6ba2a78 ในหมายเหตุเหล่านั้น ios/ หมายถึง SADT-VISOR tools/AREG/AREG_IOS/src/sadt_areg_ios/ และ common/ หมายถึง SADT-VISOR tools/AREG/common/src/sadt_areg_common/

3.2 การจัดทิศมาตรฐาน (เฉพาะ Butterfly)

DatasetPatch.__getitem__ (AREG_IOS/AREG_IOS_utils/dataset.py:30) เรียก orientation() (AREG_IOS/AREG_IOS_utils/orientation.py:15) ด้วยเป้าหมาย [[-0.5,-0.5,0], [0,0,0], [0.5,-0.5,0]] และฟัน ["3","8","9","14"] = UR6, UR1, UL1, UL6

เป็นอัลกอริทึมเดียวกับ FlexReg.md §3 (การหมุน Rodrigues สองครั้งต่อเนื่อง + การเลื่อน) แต่บนlandmark ที่ต่างกัน: FlexReg ใช้ 3, 5, 12, 14 (UR6, UR4, UL4, UL6) ส่วน AREG_IOS ใช้ฟันกรามและฟันตัดซี่กลาง โดยเฉลี่ย centroid สองจุดของมันเพื่อได้จุดกึ่งกลาง ผลลัพธ์ชนิดเดียวกัน: ระนาบ occlusal ≈ z=0, +y ด้านหน้า, +x ด้านซ้ายของผู้ป่วย

กรอบเป็นระบบมือขวาที่ x = ซ้ายของผู้ป่วย และ y = ด้านหน้า ดังนั้น z = x × y ชี้ลงล่างสำหรับขากรรไกรบน: กล้อง 7 ตัวที่วางที่ z ≈ +0.9 จึงมองซุ้มฟันจากด้าน occlusal คือด้านเพดานปาก (เป็นการอนุมานทางเรขาคณิตจากเป้าหมาย ไม่ใช่ข้อกล่าวอ้างของโค้ด)

สามสิ่งที่ต้องเข้าใจ:

  1. มาสก์พื้นหลัง x * (PF >= 0) ทำให้ logit ของพิกเซลว่างเป็นศูนย์ หลัง softmax มันกลายเป็น (0.5, 0.5) ไม่ใช่ 0 ดังนั้นมันให้ครึ่งโหวตแก่คลาสทั้งสองในปริมาณเท่ากัน ความต่างระหว่างคลาส และ argmax จึงไม่ขยับ หน้าที่มีดัชนี -1 (พื้นหลัง) เขียนลงใน P_faces[:, -1] คือหน้าสุดท้ายของเมช ซึ่งเป็นหน้าเดียวที่สะสมครึ่งโหวตเท่ากันพิเศษนั้น
  2. การสะสมไม่ได้สะสมจริง P_faces[:, pf] += pred คือ index_put_ ที่ไม่มี accumulate=True: เมื่อหลายพิกเซลจากมุมมองเดียวกันตกบนหน้าเดียวกัน (กรณีทั่วไป เพราะหนึ่งหน้าครอบคลุมหลายพิกเซล) เหลือเพียงผลงานเดียว แบบไม่กำหนดแน่นอน อย่างไรก็ตาม ผลรวมข้ามทั้ง 7 มุมมองทำงานได้ (7 รอบแยกกันของลูป Python)
  3. การโหวตหน้า → vertex เสื่อมสภาพ V_labels_prediction[F[0,:,0]] = P_faces เขียนเฉพาะvertex แรกของแต่ละสามเหลี่ยม vertex ที่ไม่เคยอยู่ตำแหน่ง 0 ของรายการหน้าของมันจะคงเป็น 0 patch จึงออกมาเต็มไปด้วยช่องโหว่ตามโครงสร้าง และการประมวลผลหลังเชิง morphology คือสิ่งที่ซ่อมมัน ไม่ใช่การปรับแต่งเพื่อความสวยงาม

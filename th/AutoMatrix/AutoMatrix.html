AutoMatrix

AutoMatrix ใช้ transform หนึ่งตัวหรือหลายตัวกับโฟลเดอร์ของวอลุ่มและไฟล์ landmark หน้านี้อธิบายทีละขั้นว่าทำงานอย่างไร: แต่ละไฟล์เคลื่อนไปทางไหน ไฟล์หาเมทริกซ์ของตัวเองได้อย่างไร และผลลัพธ์ไปอยู่ที่ใด ไฟล์ บรรทัด บล็อกโค้ด และข้อควรระวังอยู่ในหน้าโค้ด

ยังไม่เผยแพร่ แอตลาส (คำอธิบาย) โค้ด (นักพัฒนา) ไม่มี conda ไม่มี GPU คำนวณล้วน ๆ VISOR บรรณานุกรม

สองโค้ดเบส หน้านี้อธิบายโมดูล Slicer แบบ legacy (SlicerAutomatedDentalTools ที่ 3c67957, 2026-10-26) การพอร์ต VISOR ซึ่งรันเครื่องมือเดียวกันบนเซิร์ฟเวอร์ อธิบายอยู่ในVISOR: เครื่องมือนี้รันอย่างไรในตอนนี้ ตรงที่ VISOR ต่างออกไป จะมีประโยคบอกไว้

ภาพรวม: อะไรเข้า อะไรออก

โมดูลการลงทะเบียนหาtransform: วิธีย้ายสแกนหนึ่งไปทับอีกสแกนหนึ่ง AutoMatrix รับไฟล์นั้นแล้วนำไปใช้กับไฟล์อื่นของผู้ป่วย ไม่มีเครือข่าย ไม่มี conda ไม่มี GPU: มีเพียง transform ที่อ่านจากไฟล์ resampler และการจับคู่ชื่อไฟล์

เข้าออก
วอลุ่ม (.nii, .nii.gz, .nrrd) และไฟล์ landmark (.mrk.json) หรือโฟลเดอร์ที่มีไฟล์เหล่านี้ไฟล์เดิมที่ถูกย้ายด้วย transform ของมัน พร้อม suffix (เสนอ _apply) ในสำเนาของโฟลเดอร์อินพุต
transform (.tfm, .mat, .h5, .txt) หรือโฟลเดอร์ที่มีไฟล์เหล่านี้ไม่มีไฟล์ transform: AutoMatrix อ่าน transform และไม่เขียนอะไรเลย

1. ตำแหน่งในไปป์ไลน์

ไม่มีโมดูลใดเรียก AutoMatrix มันอ่านไฟล์ transform ที่โมดูลการลงทะเบียนสร้างขึ้น:

ผู้สร้างไฟล์ที่สร้างชนิดของ transform
AREG_CBCTหนึ่งเมทริกซ์ต่อผู้ป่วยและบริเวณ (_matrix.tfm)affine หรือ rigid
SEMI_ASO_CBCT<patient>_<name>_transform.tfmcomposite ของหลาย transform
MRI2CBCT_REGISTER<id>_<side>_MRI_transform.tfmaffine ที่แปลงระหว่าง RAS และ LPS แล้วและกลับด้านแล้ว
Review และ VFACEการลงทะเบียนบวกการขยับด้วยมือเล็กน้อยcomposite
FlexReg<T2><suffix>.tfmaffine ที่แปลงและกลับด้านแล้ว

ช่องติ๊ก “From AReg” ของแผงฝังรูปแบบการตั้งชื่อของ AREG_CBCT ไว้ตายตัว (ด้านล่าง)

ในโค้ดผู้สร้างพร้อมบรรทัด

2. ไฟล์ที่เกี่ยวข้อง

วิดเจ็ต (ตัวเลือก การตรวจสอบ mirror แถบความคืบหน้า) ตัวช่วยที่สร้างพารามิเตอร์ของโมดูลบรรทัดคำสั่ง สำเนาของโค้ดจับคู่ที่ใช้เพื่อนับเท่านั้น และโมดูลบรรทัดคำสั่งที่ทำงานทั้งหมด โมดูลรันใน Python ของ Slicer เอง ส่วนหนึ่งของโมดูลตอนนี้อยู่ในเลเยอร์ ADTLib ที่ใช้ร่วมกัน

ในโค้ดไฟล์และที่ที่แต่ละไฟล์รัน

3. รูปแบบ transformation ที่อ่านได้ และที่อ่านไม่ได้

แผงโฆษณา .npy, .h5, .tfm, .mat และ .txt โมดูลบรรทัดคำสั่งส่งทุกรูปแบบให้ ITK ซึ่งรู้จักเฉพาะรูปแบบ transform ของตัวเอง ทดสอบกับ SimpleITK 2.5.5 ของ Slicer 5.12:

นามสกุลผลจริง
.tfm, .txtอ่านได้เฉพาะถ้าเป็นไฟล์ข้อความ transform ของ ITK; เมทริกซ์ 4×4 ดิบถูกปฏิเสธ
.h5, .hdf5อ่านได้ (แต่การค้นหาในโฟลเดอร์แสดงเฉพาะ .h5: .hdf5 อ่านได้ก็ต่อเมื่อระบุเป็นไฟล์เดี่ยว)
.matอ่านได้ (รูปแบบ Matlab)
.npyล้มเหลว: ทุกไฟล์ .npy ถูกบันทึก log และข้าม

VISOR ไม่แสดง .npy อีกแล้ว และรับ .txt ที่เป็นเมทริกซ์ 4×4 ธรรมดา

ในโค้ดลูปการอ่านและรูปแบบที่ทดสอบ

4. แบบแผนการแปลง: จุดที่ทำให้ทุกอย่างพัง

4.1 ทิศทางของการแปลง

ITK (ชุดเครื่องมือภาพเบื้องหลัง SimpleITK ซึ่งอ่าน transform และ resample ภาพที่นี่) ทำงานจากเอาต์พุตไปอินพุต: transform ที่ให้กับ resampler (ขั้นตอนที่เขียนภาพใหม่บนกริดที่เลือก) แมปจุดเอาต์พุตไปยังจุดอินพุตที่ต้องอ่านค่า เนื้อหาที่มองเห็นจึงเคลื่อนไปตามตัวผกผันของ transform โค้ดใช้หลักนี้ทั้งสองฝั่งอย่างสอดคล้องกัน: วอลุ่มถูก resample ด้วย T ตามเดิม และแต่ละจุด landmark ถูกย้ายด้วยตัวผกผันที่ระบุชัดเจน

ถ้า transform กลับด้านไม่ได้ (ฟิลด์การกระจัดแบบหนาแน่นหรือ B-spline: ทั้งสองยกข้อผิดพลาดเมื่อกลับด้านใน SimpleITK 2.5.5 ของ Slicer 5.12 ลองเมื่อ 2026-11-10) ไฟล์ landmark ของผู้ป่วยนั้นจะถูกข้ามพร้อมคำเตือน ขณะที่วอลุ่มยังถูกแปลง: เอาต์พุตทั้งสองอาจเคลื่อนไม่พร้อมกันโดยไม่มีใครรู้

ในโค้ดresampler และตัวผกผันที่ระบุชัดเจน พร้อมบรรทัด

4.2 RAS / LPS: การพลิกเกิดที่ไหน ไม่มีที่ไหนเลย

ใน AutoMatrix ไม่มีการพลิก และถูกต้องแล้ว ไฟล์ transform ของ ITK และการอ่านเขียนภาพเป็นLPS และไฟล์ landmark ของรีโพซิทอรีถูกตายตัวเป็น LPS เช่นเดียวกับค่าเริ่มต้นของ Slicer ตอนเขียน จึงส่งจุดให้ transform ได้โดยตรง ส่วนที่เปราะบางคือฟิลด์ coordinateSystem ของไฟล์ landmark ไม่เคยถูกอ่าน: ไฟล์ที่ประกาศRAS จะถูกย้ายโดย x และ y มีเครื่องหมายผิด โดยไม่มีข้อความแจ้ง โมดูลที่สร้างเมทริกซ์ทำการแปลงเอง; AutoMatrix รับผลที่ได้

ในโค้ดที่ที่แต่ละโมดูลกำหนด LPS ตายตัว

4.3 การประกอบ

ไม่มี เมื่อผู้ป่วยมีหลายเมทริกซ์ แต่ละเมทริกซ์ถูกใช้กับไฟล์ต้นฉบับ อย่างอิสระ ให้หนึ่งเอาต์พุตต่อเมทริกซ์ การประกอบเพียงอย่างเดียวคือสิ่งที่ ITK ทำไว้แล้ว: .tfm ที่เก็บหลาย transform จะถูกอ่านกลับเป็น composite และใช้ทั้งก้อน

ในโค้ดลูปที่ใช้แต่ละเมทริกซ์กับไฟล์ต้นฉบับ

4.4 Harden

ไม่มี เวอร์ชันเก่าผูก transform กับโหนดในฉากและ "harden" มัน บล็อกนั้นหายไปแล้ว และโค้ดที่ส่งออกโหนดเป็นโค้ดตาย

ในโค้ดเวอร์ชันก่อน CLI ทำอะไร

5. ชนิดข้อมูลที่จัดการ

ประเภทเกิดอะไรขึ้น
.nii, .nii.gz, .nrrdอ่านเป็นภาพ, resample, เขียน
.mrk.jsonอ่านจุดและย้ายแต่ละจุดด้วย T⁻¹; เฉพาะกลุ่มแรก และเฉพาะจุดที่ทำเครื่องหมาย defined; จุดอื่นคงอยู่ในเฟรมเดิม

ในโค้ดสองกิ่งของ CLI

6. การ resample และภาพอ้างอิง

Nearest neighbour สำหรับ label map และ linear สำหรับกรณีอื่น ในโมดูล legacy ผู้ใช้ประกาศด้วยช่องติ๊ก ไม่มีการตรวจจับ VISOR ตรวจจับทีละไฟล์

กริดเอาต์พุตถูกเลือกตามลำดับนี้: (1) สำหรับ transform แบบcomposite รีเฟอเรนซ์ถูกเดาจากชื่อเมทริกซ์ ซึ่งใช้ได้เพราะ ASO_CBCT เขียนสแกนที่จัดทิศแล้วไว้ข้างเมทริกซ์ของมัน; (2) เมทริกซ์ที่ชื่อมี mirror ใช้ภาพอินพุตเป็นรีเฟอเรนซ์ของตัวเอง; (3) ไฟล์รีเฟอเรนซ์ที่ผู้ใช้ให้มาบังคับเรขาคณิตของมัน; (4) นอกนั้นใช้ภาพอินพุตเอง

ในโค้ดตัวประมาณค่าและการเลือกกริดสี่ทาง

7. โหมด Mirror

ปุ่ม mirror ดาวน์โหลดเมทริกซ์ขนาดเล็กจาก release ของรีโพซิทอรีของแล็บเอง และเติมช่องเมทริกซ์ด้วยมัน เนื้อหาคือ transform แบบ affine ที่เมทริกซ์เป็น diag(-1, 1, 1) และไม่มีการเลื่อน

ดีเทอร์มิแนนต์ของมันคือ −1 ซึ่ง resampler จัดการได้โดยไม่ยากสำหรับวอลุ่ม โหมดนี้บังคับ suffix เป็น _mir และยกเลิกการติ๊ก “Add the matrix name” ใน VISOR การสะท้อนที่ใช้โดยไม่มีรีเฟอเรนซ์ทำให้กล่องเอาต์พุตว่างเปล่า (ดูการ์ดกริดที่นั่น)

ในโค้ดการดาวน์โหลดและเนื้อหาของไฟล์

8. การจับคู่ไฟล์ ↔ เมทริกซ์

คีย์ผู้ป่วยถูกสร้างจากชื่อไฟล์แต่ละไฟล์ และสแกนจะพบเมทริกซ์ที่มีคีย์เดียวกัน ถ้าพาธของเมทริกซ์เป็นไฟล์เดี่ยว มันจะถูกผูกกับผู้ป่วยทุกคน คีย์มาจากห่วงโซ่ของการตัดที่ ไม่เหมือนกันทั้งสองฝั่ง

ในโค้ดGetPatients และรายการโทเค็นสองรายการ

เส้นทาง “From AReg”

ตารางที่เขียนตายตัวแมปคำต่อท้ายของไฟล์ landmark ไปเป็นชื่อเมทริกซ์ของ AREG_CBCT ข้ามการจับคู่ทั้งหมด มันตายและเสีย: ตัวอักษรขากรรไกรสองตัวสลับกันเมื่อเทียบกับส่วนที่เหลือของรีโพซิทอรี มันอ่านพารามิเตอร์ที่โมดูลบรรทัดคำสั่งไม่มี และช่องติ๊กถูกซ่อนจึงไม่เคยเข้าเส้นทางนี้ VISOR ลบมันออกแล้ว

ในโค้ดตาราง suffix และสามปัญหา

9. เอาต์พุต

ชื่อเอาต์พุตคือชื่อไฟล์ ตามด้วย suffix (เสนอ _apply) แล้วเมื่อติ๊ก “Add the matrix name” (ติ๊กไว้เป็นค่าเริ่มต้น) ตามด้วยชื่อเมทริกซ์ทั้งหมด สำหรับ patient1_MAXReg_matrix.tfm จะได้ patient1_T1_MA_apply_patient1_MAXReg_matrix.nii.gz ไม่ใช่สิ่งที่ README เก่าสัญญาไว้ การเลิกติ๊กตัวเลือกนี้เมื่อผู้ป่วยแต่ละคนมีหลายเมทริกซ์ทำให้เอาต์พุตเขียนทับกัน; VISOR บังคับใช้ชื่อในกรณีนั้น โฟลเดอร์อินพุตถูกทำซ้ำในโฟลเดอร์เอาต์พุต ไม่มี .tfm ถูกสร้างเลย

ในโค้ดการสร้างชื่อ พร้อมบรรทัด

10. อะไรคือค่าที่ทำนาย และอะไรคือค่าที่คำนวณ

บล็อกลักษณะ
การอ่าน transformคำนวณ ตัวอ่าน transform ของ ITK
การจับคู่ไฟล์ ↔ เมทริกซ์คำนวณ การแยกสตริง
วอลุ่มคำนวณ resampling, linear หรือ nearest neighbour
Landmarkคำนวณ transform ผกผัน ทีละจุด
เมทริกซ์ Mirrorคำนวณ ไฟล์คงที่ที่ดาวน์โหลด, diag(-1,1,1)

ไม่มีโครงข่ายประสาทเทียมที่ไหนเลย

11. สภาพแวดล้อม

ไม่ต้องติดตั้งอะไร: SimpleITK, numpy, VTK และ Qt มีอยู่ใน Slicer แล้ว ไม่มี conda ไม่มี CUDA การเข้าถึงเครือข่ายอย่างเดียวคือการดาวน์โหลดเมทริกซ์ mirror และเฉพาะเมื่อติ๊กช่อง Mirror

ในโค้ดสิ่งที่ถูกนำเข้า และโปรโตคอลความคืบหน้า

  • เมชใช้ไม่ได้อีกแล้ว ทั้งที่โฆษณาไว้ หลักฐาน
  • เมทริกซ์ข้อความ 4×4 ดิบถูกปฏิเสธ โดยตัวอ่านแบบ legacy หลักฐาน
  • เฟรมของlandmark ไม่เคยถูกอ่าน หลักฐาน
  • ไม่มีการประกอบ transform: N เมทริกซ์ให้ N ไฟล์ ไม่ใช่โซ่ หลักฐาน
  • เอาต์พุตเขียนทับกัน ถ้าไม่เติมชื่อเมทริกซ์ หลักฐาน
  • เมทริกซ์ที่ไม่มีจุดเวลาหาสแกนไม่พบ โดยเงียบ ๆ หลักฐาน
  • mirror เป็นการสะท้อนรอบ origin ของระบบพิกัด ไม่ใช่เส้นกึ่งกลางของผู้ป่วย หลักฐาน
  • เมทริกซ์ที่กลับด้านไม่ได้ ทำให้วอลุ่มไม่มี landmark ตามไปด้วย หลักฐาน
  • โค้ดจับคู่สองสำเนา แยกทางกันไปแล้ว หลักฐาน
  • “From AReg” ตายและเสีย หลักฐาน
  • ความคืบหน้าไหลผ่านโปรโตคอลทางอ้อมที่เปราะบาง หลักฐาน
  • วิดเจ็ตมีข้อบกพร่องอื่นอีกหลายข้อ (การหารด้วยศูนย์เมื่อโฟลเดอร์ว่าง การตรวจสอบที่ผิด โค้ดตาย) สรุป

AutoMatrix

ใช้การแปลง ITK หนึ่งตัวหรือมากกว่าที่คำนวณไว้แล้วจากที่อื่น แบบกลุ่มกับโฟลเดอร์วอลุ่มและไฟล์จุดสังเกตทางกายวิภาค (landmark) — ไม่มีโครงข่าย ไม่มี conda ไม่ใช้ GPU

ยังไม่ตีพิมพ์ Automatrix_CLI คำนวณ — ไม่มีโครงข่าย ไม่มี conda ไม่ใช้ GPU บรรณานุกรม

การใช้การแปลง ITK หนึ่งตัวหรือมากกว่าแบบกลุ่มกับโฟลเดอร์ วอลุ่มและไฟล์ landmark ไม่มีโครงข่าย ไม่มี conda ไม่ใช้ GPU: sitk.ReadTransform + sitk.ResampleImageFilter และการจับคู่ไฟล์ ↔ เมทริกซ์ ด้วยการตัดแยกชื่อ สาระสำคัญทั้งหมดของหน้านี้อยู่ที่ หลักการของการแปลง และช่องว่างระหว่างสิ่งที่ UI สัญญากับสิ่งที่ CLI ทำจริง

การอ่านที่สำเร็จจะคืนค่า sitk.Transform ที่คงชนิดจริงไว้ — isinstance(tfm, sitk.CompositeTransform) ใช้ได้ ตรวจสอบแล้ว

4. หลักการของการแปลง — จุดที่ทำให้ทุกอย่างพัง

4.1 ทิศทางของการแปลง

ITK เป็นแบบ fixed → moving: sitk.Transform ที่ส่งให้ resampler จะจับคู่ จุดทางกายภาพของเอาต์พุตไปยังจุดทางกายภาพของอินพุตที่จะสุ่มค่า ดังนั้นเนื้อหาที่มองเห็นจึงเคลื่อนตาม T⁻¹

โค้ดใช้ประโยชน์จากข้อนี้ทั้งสองฝั่ง และสอดคล้องกัน:

  • วอลุ่ม (Automatrix_CLI.py:209): resampler.SetTransform(transform) — ส่งการแปลงไป ตามที่เป็น เนื้อหาเคลื่อนตาม T⁻¹
  • Landmark (Automatrix_CLI.py:176): 
    tfm_inverted = transform.GetInverse()
point['position'] = list(tfm_inverted.TransformPoint(point['position']))
    ใช้ T⁻¹ กับจุดโดยตรง จุดจึงเคลื่อนเหมือนเนื้อหา ของวอลุ่ม
ตรวจสอบแล้ว

ประเด็นสำคัญ: .tfm ไฟล์เดียวกันที่ใช้กับภาพสแกนและกับ landmark ของภาพ จะเคลื่อนทั้งสองด้วยการเคลื่อนแบบเดียวกัน นี่คือคุณสมบัติที่ทำให้โมดูลนี้ ใช้งานได้ และเป็นที่เดียวในโค้ดที่มีการกลับด้าน (inversion)

ข้อควรระวัง

GetInverse() อาจโยน RuntimeError (การแปลงที่หาอินเวิร์สไม่ได้: สนามการกระจัดหนาแน่น, B-spline) กรณีนี้ถูกดักไว้ และไฟล์ landmark ถูกข้ามไปพร้อมคำเตือน — ขณะที่วอลุ่มที่คู่กันจะ ถูกแปลงไปแล้ว เอาต์พุตทั้งสองจึงอาจไม่ตรงกันโดยไม่มีการแจ้ง

4.2 RAS / LPS: การพลิกเกิดขึ้นที่ใด — ไม่มีที่ใดเลย

AutoMatrix ไม่มีการพลิกแกน ซึ่งถูกต้อง ด้วยเหตุผลดังนี้:

  • ไฟล์ ITK .tfm อยู่ใน LPS โดยโครงสร้าง
  • sitk.ReadImage / WriteImage ทำงานใน LPS ทั้งสองฝั่ง สอดคล้องกัน ไม่ต้องทำอะไรกับวอลุ่ม
  • ไฟล์ .mrk.json ของรีโพสิทอรีถูกกำหนดตายตัวเป็น LPS ทุกที่: ALI_CBCT/io.py:36, ASO_CBCT/utils.py:278, AREG_CBCT/utils.py:373, ALI_IOS/io.py:85, mgl_patch.py:193, VFACE/functionaq3dc.py#L1733 ซึ่งเป็น ค่าเริ่มต้นของ Slicer เมื่อเขียนไฟล์ด้วย ดังนั้น point['position'] จึงอยู่ใน LPS อยู่แล้ว และ การใช้การแปลง ITK กับค่านี้โดยตรงจึงถูกต้อง
ข้อควรระวัง

ส่วนที่เปราะบางคือฟิลด์ coordinateSystem ไม่เคยถูก อ่าน FlexReg อ่านฟิลด์นี้ (FlexReg.py:2434) แต่ AutoMatrix ไม่อ่าน ไฟล์ json ที่ประกาศ "coordinateSystem": "RAS" — ซึ่ง annotation รุ่นเก่าหรือเครื่องมืออื่น เขียนไว้ — จะถูกแปลงโดยที่ x และ y มีเครื่องหมายผิด โดยไม่มี ข้อความแจ้ง ไฟล์เอาต์พุตยังคงมี coordinateSystem: RAS เดิมด้วย เพราะ json ถูกอ่านกลับและเขียนใหม่ตามที่เป็น

เพื่อเป็นข้อมูล โมดูลที่สร้างเมทริกซ์จะพลิกแกนเอง: FlexReg_CLI.py:186 คำนวณ flip @ M @ flip ด้วย flip = np.diag([-1,-1,1,1]) แล้วกลับด้าน ก่อน เขียน .tfm AutoMatrix ใช้ผลของงานนั้น จึง ไม่มีสิ่งใดต้องทำซ้ำ

4.3 การประกอบการแปลง

ข้อควรระวัง

ไม่มีเลย เมื่อผู้ป่วยมีเมทริกซ์หลายตัว ลูป (Automatrix_CLI.py:283) จะใช้แต่ละตัว กับไฟล์อินพุตต้นฉบับแยกกัน ได้เอาต์พุตหนึ่งไฟล์ต่อ เมทริกซ์ ไม่มีการต่อกัน

4.4 Harden

ไม่มี ไม่มี vtkMRMLTransformNode ใน pipeline อีกต่อไป เวอร์ชันก่อน CLI สร้างโหนดนี้และเรียก model.SetAndObserveTransformNodeID(...) แล้วตามด้วย model.HardenTransform() ก่อน slicer.util.exportNode(..., world=True) บล็อกทั้งหมดนั้นหายไปแล้ว เมธอด saveOutput ของ widget (AutoMatrix.py:861) ซึ่งเรียก exportNode ยังคงอยู่แต่ไม่ถูกเรียกอีก: โค้ดที่ไม่ถูกใช้งาน

6. การสุ่มตัวอย่างใหม่ (resampling) และภาพอ้างอิง

resampler.SetInterpolator(sitk.sitkNearestNeighbor if is_seg else sitk.sitkLinear)
resampler.SetDefaultPixelValue(0)
resampler.SetReferenceImage(reference)

ตัวประมาณค่าในช่วง (interpolator) มาจากช่องเลือก "Check this box if using segmentations" (is_seg) ใช้ nearest neighbor สำหรับ labelmap และ linear ในกรณีอื่น — ถูกต้อง และผู้ใช้ต้องระบุเอง ไม่มีการตรวจจับอัตโนมัติ

กริดของเอาต์พุตเลือกดังนี้ (Automatrix_CLI.py:191 และ :301) เรียงตามลำดับความสำคัญจากมากไปน้อย:

  1. การแปลงแบบ composite → ภาพอ้างอิงเดาจาก path ของเมทริกซ์: matrix.replace("_transform.tfm", ".nii.gz") หากไม่พบจะ ใช้ .nii แทน นี่ไม่ใช่บั๊ก: ASO_CBCT เขียน <patient>_<add>_transform.tfm และ <patient>_<add>.nii.gz ไว้ในโฟลเดอร์เดียวกัน ภาพสแกนที่จัดแนวแล้ว ซึ่งอยู่ข้างเมทริกซ์จึงเป็นกริดที่ถูกต้องพอดี หากไม่มีไฟล์นั้น จะมีคำเตือน และกลับไปใช้ภาพอินพุต
  2. ชื่อเมทริกซ์มีคำว่า mirror (ไม่สนตัวพิมพ์เล็ก-ใหญ่) → ภาพอ้างอิง ถูกบังคับเป็นภาพอินพุต ไฟล์อ้างอิงใน UI ถูกเพิกเฉย เป็นการแยกกรณีจากชื่อไฟล์
  3. มีการระบุไฟล์อ้างอิง (reference_file != "None" ซึ่งเป็น ค่าเริ่มต้นของช่อง AutoMatrix.ui:255) → เรขาคณิตของไฟล์นั้นถูกใช้กับเอาต์พุตทั้งหมด
  4. มิฉะนั้นใช้ภาพอินพุตเอง: ขนาด spacing origin และ direction ไม่เปลี่ยน การแปลงที่เคลื่อนเนื้อหาออกนอกขอบเขตภาพ จะทำให้เนื้อหานั้นหายไป และถูกเติมด้วย DefaultPixelValue = 0
บั๊กที่ยืนยันแล้ว

แขนง reference is None ของ ResampleImage (Automatrix_CLI.py:215) ไม่มีทางถูกเรียกถึง — ผู้เรียกส่งภาพอ้างอิงเสมอ และแขนงนี้ยัง ผิดด้วย: ทำ new_origin = transform.TransformPoint(image.GetOrigin()) ขณะที่หลักการของ resampler ต้องใช้ T⁻¹

นั่นคือ diag(-1, 1, 1) ใน LPS มีจุดศูนย์กลางที่จุดกำเนิด: เป็น การสะท้อนรอบระนาบ x_LPS = 0 เนื่องจาก x_LPS ชี้ไปทาง ซ้ายของผู้ป่วย นี่จึงเป็นการสลับซ้าย/ขวาจริง — แต่รอบระนาบ sagittal ของจุดกำเนิดของกรอบพิกัดโลก ไม่ใช่ระนาบ sagittal ของผู้ป่วยเอง ผู้ป่วยที่ไม่ได้อยู่กึ่งกลางจะถูกเลื่อนตำแหน่งนอกเหนือจากการสะท้อน ซึ่ง การลงทะเบียนภาพในภายหลังต้องแก้ไข

ดีเทอร์มิแนนต์เท่ากับ −1 สำหรับวอลุ่ม ResampleImageFilter จัดการได้ โดยไม่มีปัญหา สำหรับเมช จะทำให้ทิศทางของหน้าและ normal กลับด้าน — ซึ่งไม่เป็นประเด็นในที่นี้ เพราะเมชไม่ถูกประมวลผลอีกต่อไป

โหมดนี้บังคับ ComboBoxMatrix เป็น "File" ตั้งคำต่อท้ายเป็น _mir และยกเลิกการเลือก checkBoxMatrixName

สามปัญหา ตรวจสอบได้ทั้งหมด:

  1. _L และ _U สลับกันเมื่อเทียบกับหลักการที่ใช้ในส่วนอื่นของรีโพสิทอรี AREG_IOS/dataset.py:231 และ AREG/IOS.py:122 กำหนด Lower = ["Lower", "_L", "L_", "Mandibule", "Md"] และ Upper = ["Upper", "_U", "U_", "Maxilla", "Mx"] แต่ที่นี่ _L ชี้ไปที่ Maxilla และ _U ชี้ไปที่ Mandible
  2. matrix_lineEdit ไม่มีอยู่ใน argparse ของ CLI (Automatrix_CLI.py:329: อาร์กิวเมนต์คือ input_patient, input_matrix, reference_file, suffix, matrix_name, fromAreg, output_folder, log_path, is_seg) แขนงนี้ จึงโยน AttributeError ทันทีที่ถูกเรียก
  3. แขนงนี้ไม่เคยถูกเรียก: CheckBoxSuffixBased (ป้าย "From AReg") ถูก ซ่อนตอน setup ด้วย self.ui.CheckBoxSuffixBased.setVisible(False) (AutoMatrix.py:296) ดังนั้น fromAreg เป็น "False" เสมอ เป็นโค้ดที่ไม่ถูกใช้งาน — ซึ่งอธิบายว่าทำไมข้อ 1 และ 2 ไม่เคยถูก สังเกตเห็น

อย่างไรก็ตาม ชื่อ MAXReg_matrix.tfm ตรงกับความเป็นจริงของ AREG_CBCT: โมดูลนั้น เขียน patient + "_" + reg_type + add_name + "_matrix.tfm" โดย add_name มีค่าเริ่มต้นเป็น Reg (AREG.ui:571) — เส้นทางนี้จึงขึ้นกับค่าเริ่มต้นของช่องข้อความที่แก้ไขได้ซึ่งเป็นของ โมดูลอื่น

12. ข้อควรระวังและจุดเปราะบาง

สรุป
  • .npy ใช้ไม่ได้ (§3) แม้ UI และ README จะประกาศไว้
  • เมชใช้ไม่ได้แล้ว (§5) แม้ UI และ README จะประกาศไว้ เป็นการถดถอยจากคอมมิต 7bc362b
  • .txt ไม่รับเมทริกซ์ 4×4 ดิบ (§3) รับเฉพาะรูปแบบข้อความของ ITK
  • coordinateSystem ของ landmark ไม่เคยถูกอ่าน (§4.2)
  • ไม่มีการประกอบ: เมทริกซ์ N ตัวสำหรับผู้ป่วยหนึ่งรายให้ N ไฟล์ ไม่ใช่การต่อกัน (§4.3)
  • เอาต์พุตถูกเขียนทับ หากยกเลิกการเลือก checkBoxMatrixName เมื่อมีเมทริกซ์หลายตัว (§9)
  • OnEndProcess หารด้วย self.nb_scans (AutoMatrix.py:953) โดยไม่มีการป้องกัน: โฟลเดอร์อินพุตว่างทำให้เกิด ZeroDivisionError เมื่อจบการประมวลผล
  • CheckGoodEntre ผิดตรรกะ (AutoMatrix.py:1013): การทดสอบนามสกุลคือ len(dico['.vtk'])==0 and len(dico['.vtp']) and len(dico['.stl']) and … ซึ่งมีเพียงพจน์แรกที่เป็นการเปรียบเทียบ ที่เหลือเป็นจำนวนเต็มที่ถูกประเมินเป็นบูลีน คำเตือน "Folder empty or wrong type" จึงทำงานเฉพาะในเงื่อนไขร่วมที่ไม่น่าเกิดขึ้น โฟลเดอร์ที่ว่างจริงผ่านการตรวจสอบได้
  • onPredictButton ไม่หยุดเมื่อเกิดข้อผิดพลาด: TestProcess คืนค่า tuple (ok, out) การตรวจ isinstance(error, str) ที่ AutoMatrix.py:766 จึงเป็นเท็จเสมอ และการประมวลผลเริ่มขึ้นแม้ช่องจะว่าง
  • .split(extension_scan)[0] ตัดที่ตำแหน่งที่พบครั้งแรก: path ที่ชื่อโฟลเดอร์มีสตริงย่อยเดียวกับนามสกุลจะถูกตัดสั้น
  • Landmark ที่ไม่ใช่ defined คงอยู่ในกรอบพิกัดเก่า ปะปนกับจุดที่ถูกแปลงแล้วในไฟล์เดียวกัน (§5)
  • เส้นทาง "From AReg" ที่ไม่ถูกใช้และพัง (§8)
  • โค้ดที่ไม่ถูกใช้งาน: saveOutput / UpdateProgressBar / UpdateTime ของ widget, AutoMatrixLogic.process, ResampleImage ในแขนง reference is None, registerSampleData ที่อ้างถึงไฟล์ .png ที่ไม่มีอยู่
  • เมทาดาทาของ Automatrix_CLI.xml ยังเป็นของเทมเพลต Slicer (FirstName LastName (Institution), NIH grant NXNNXXNNNNNN-NNXN)

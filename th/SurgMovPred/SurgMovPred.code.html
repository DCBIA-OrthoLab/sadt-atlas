SurgMovPred, legacy: โค้ด

สำหรับนักพัฒนา: โมดูล legacy SurgMovPred ทำอะไรในโค้ด พร้อมการอ้างอิง file:line โค้ด อาร์กิวเมนต์ สภาพแวดล้อม และข้อควรระวัง คำอธิบายที่อ่านง่ายพร้อมคณิตศาสตร์อยู่ในหน้าแอตลาส

โค้ด แอตลาส (คำอธิบาย) ยังไม่ตีพิมพ์ SurgMovPred_CLI ไม่ใช้ conda: ใช้ Python ของ Slicer เอง บรรณานุกรม VISOR

การทำนายการเคลื่อนที่ของการผ่าตัดขากรรไกรจากสเปรดชีตของการวัดทางเซฟาโลเมตริก ไม่มีโครงข่ายประสาทเทียม ไม่มีภาพ ไม่มีเมช: regressor ของ scikit-learn แบบ stacking 112 ตัว หนึ่งตัวต่อหนึ่งค่าที่ต้องทำนาย ใช้ทีละแถวกับไฟล์ Excel/CSV

โค้ดสองชุด

ทุกอย่างที่มีเลขกำกับด้านล่างอธิบายโมดูล Slicer แบบ legacy (SlicerAutomatedDentalTools ที่ 3c67957, 2026-10-26) การพอร์ต VISOR ซึ่งรันเครื่องมือเดียวกันบนเซิร์ฟเวอร์ อธิบายไว้ในหน้า VISOR ของมัน การพอร์ตอยู่บนสาขา main ของ SADT-VISOR และใช้อัลกอริทึมเดียวกัน

3. อินพุตและการประมวลผลเบื้องต้น

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

รูปแบบที่รับ load_data_from_directory() (SurgMovPred_CLI.py:143) รวบรวมทุกไฟล์ *.csv, *.xlsx, *.ods ในโฟลเดอร์ (นามสกุลตัวพิมพ์เล็กและตัวพิมพ์ใหญ่) อ่านมัน (read_csv, read_excel, read_excel(engine='odf')) และต่อกัน (pd.concat(..., ignore_index=True)) ไม่ recursive ลงโฟลเดอร์ย่อย สำหรับสมุดงาน Excel อ่านเฉพาะชีตแรก: ไฟล์ทดสอบทางการมีเจ็ดชีต (all_data, demographics, Invivo_ceph, surgical_mov, dolp_ceph_T0, dolp_ceph_T1, dolp_ceph_total) และ all_data อยู่ในตำแหน่งแรก ไฟล์ที่อ่านไม่ได้ถูกบันทึกและข้าม (SurgMovPred_CLI.py:181-182) การรันล้มเหลวก็ต่อเมื่ออ่านไฟล์ไม่ได้เลยสักไฟล์ (:184-185)

การทำชื่อคอลัมน์ให้เป็นมาตรฐาน clean_name() (SurgMovPred_CLI.py:41) ใช้กับอินพุตเพื่อถอยกลับไปใช้การสะกดที่ใช้ตอนฝึก:

  1. ลบ ", \, [, ]
  2. อักขระใดนอก [0-9a-zA-Z_'] กลายเป็น _ เครื่องหมายอะพอสทรอฟีถูกเก็บไว้โดยตั้งใจ (คอมเมนต์ในโค้ด: สำหรับ Jarabak's และ SM_A'_CP)
  3. ยุบ _ ที่ซ้ำกัน ตัดที่หัวและท้าย
  4. "total" → "Total";
  5. prefix f_ หากชื่อขึ้นต้นด้วยตัวเลข

การทำความสะอาดนี้อธิบายชื่อฟีเจอร์จริง: SM-A-FH   (มีช่องว่างท้ายสองตัว ในไฟล์ทดสอบ) กลายเป็น SM_A_FH, Jarabak's ratio   กลายเป็น Jarabak's_ratio, FMA(MP-FH) Ang_2D กลายเป็น FMA_MP_FH_Ang_2D

รหัสผู้ป่วย find_id_column() (SurgMovPred_CLI.py:83) ทดสอบ 8 รูปแบบที่ไม่แยกตัวพิมพ์เล็กใหญ่ (#, id, patient id, patient number, subject, …) แล้วเป็นทางเลือกสุดท้าย คอลัมน์ใดที่มีทั้ง "patient" และ "id" ในไฟล์ทดสอบ คอลัมน์คือ # หากล้มเหลว คอลัมน์เอาต์พุต IDPatient ถูกเติมด้วย pd.NA พร้อมคำเตือนธรรมดา

การทำค่าให้เป็นมาตรฐาน แต่ละแพ็กเกจโมเดลมี StandardScaler ของตัวเองที่คำนวณไว้ (การจัดกึ่งกลาง + การปรับสเกล, with_mean=True, with_std=True) ใช้ทันทีก่อนการทำนาย (SurgMovPred_CLI.py:239) ไม่มีการเติมค่า (imputation): ค่าที่ขาดไปถึง scaler เป็น NaN และออกมาเป็น NaN แล้ว model.predict ก็ raise (SurgMovPred_CLI.py:243) ดังนั้นเป้าหมายถูกทิ้งสำหรับทุกแถว (ดูหมายเหตุด้านล่าง) หลักฐาน: แพ็กเกจมี ElasticNetCV (สตริงของ pickle) และstack ของ ElasticNetCV + GaussianProcessRegressor + LinearRegression ที่ใช้แทน รันบน scikit-learn ปัจจุบัน raise ValueError: Input X contains NaN ไม่ได้รันแพ็กเกจจริง

ความยืดหยุ่นเรื่อง suffix _T0 (SurgMovPred_CLI.py:225): หากโมเดลคาดหวัง X_T0 และคอลัมน์ชื่อ X จะถูกยอมรับ

หมายเหตุ

นี่คือความยืดหยุ่นเพียงอย่างเดียว ฟีเจอร์อื่นที่ขาดไปจะทำให้โมเดลทั้งตัวถูกข้ามพร้อมคำเตือน และคอลัมน์ที่สอดคล้องกันจะไม่มีในผลลัพธ์

เป็นจริงใน VISOR ด้วย: ความยืดหยุ่นเรื่อง _T0 และการข้ามแบบเดียวกัน (VISOR:SADT-VISOR tools/Surg_Mov_Pred/src/sadt_surgmovpred/pipeline.py:229,235) มีข้อต่างหนึ่งข้อ: หากไม่มีโมเดลใดทำนายได้เลย VISOR raise ข้อผิดพลาดแทนการเขียนตารางที่ไม่มีการทำนาย (pipeline.py:260)

เซลล์ว่างหนึ่งเซลล์ลบเป้าหมายทั้งตัว

ทุกแถวเข้า model.predict ในการเรียกครั้งเดียว (SurgMovPred_CLI.py:243) ดังนั้น NaN หนึ่งตัวในแถวใดของคอลัมน์ที่โมเดลต้องการ ทำให้การเรียกนั้น raise try/except ที่ :245-246 บันทึกมัน และเป้าหมายไม่ได้คอลัมน์ ทุกผู้ป่วย สิ่งนี้เกิดขึ้นเมื่อสเปรดชีตที่มีคอลัมน์ต่างกันถูกต่อกันด้วย (:187) VISOR รันโค้ดเดียวกัน (pipeline.py:243-250) หลักฐานเหมือนหัวข้อ 3: pickle มี ElasticNetCV และ stack ที่ใช้แทน raise เมื่อเจอ NaN ไม่ได้รันแพ็กเกจที่ส่งมา

น้ำหนักหลักของไฟล์ (13 MB สำหรับฟีเจอร์ 145 ตัว) มาจาก GaussianProcessRegressor ซึ่งเก็บเมทริกซ์ข้อมูลฝึกไว้ และจาก booster ของ LightGBM

การฝึกไม่อยู่ในที่เก็บโค้ด: ไม่มีสคริปต์ ไม่มีชุดข้อมูล ไม่มีเมตริก ไม่มี seed ไม่อาจกำหนดได้จากที่เก็บโค้ด: ขนาดของกลุ่มตัวอย่าง โปรโตคอลการตรวจสอบ ประสิทธิภาพต่อเป้าหมาย

  • การต่อไฟล์อินพุตโดยไม่ตรวจ: สเปรดชีตสองไฟล์ที่มีคอลัมน์ต่างกันให้ NaN ในคอลัมน์ที่ไฟล์หนึ่งขาด และ model.predict บน NaN raise ข้อผิดพลาดถูกจับต่อเป้าหมาย เป้าหมายเหล่านั้นจึงหายไปสำหรับทุกผู้ป่วย (หมายเหตุ) และผลลัพธ์ออกมาไม่ครบโดยแทบมองไม่เห็น
  • อ่านชีต Excel เพียงชีตเดียว สมุดงานที่ชีตแรกไม่ใช่ชีตข้อมูลให้ผลลัพธ์ว่าง
  • โหลดโมเดล 1.5 GB ทุกครั้ง แม้ทำนายเพียงแถวเดียว แม้ผู้ปฏิบัติงานสนใจเพียงเป้าหมายเดียว
  • ไม่มีความไม่แน่นอนในเอาต์พุต ทั้งที่หนึ่งในสามโมเดลฐานเป็น Gaussian process
  • ไม่มีความสอดคล้องแบบวัตถุแข็งระหว่างจุดของส่วนกระดูกเดียวกัน (§7)
  • process() ยังตั้งชื่ออาร์กิวเมนต์ว่า notesFolder_input / notesFolder_output (SurgMovPred.py:815) ซึ่งตกค้างมาจากเครื่องมือบันทึกทางคลินิก helpText และ docstring ของ parameter node ถูกเขียนใหม่และไม่มีมันอีกแล้ว

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

ไม่มีบทความใดครอบคลุม SurgMovPred ทั้งที่เก็บโค้ด release หรือ README ไม่อ้างอิงงานใดเลย และการค้นด้วยชื่อโมดูลไม่พบอะไร โมดูลไม่ได้อยู่ในรายการ README ของ extension ด้วยซ้ำ

บริบทที่ตีพิมพ์ ซึ่งไม่ควรสับสนกับคำอธิบายของโค้ดนี้:

  • Machine-learning-based approach for predicting postoperative skeletal changes for orthognathic surgical planning (PubMed 35132764): ปัญหาที่ตั้งเป็นอย่างเดียวกัน (ทำนายการเคลื่อนของโครงกระดูกหลังผ่าตัดจากการวัดก่อนผ่าตัด) แต่ไม่มีอะไรบ่งว่านี่คืองานเบื้องหลังน้ำหนักเหล่านี้
  • Oliveira, Cevidanes, Bianchi et al., Artificial intelligence as a prediction tool for orthognathic surgery assessment, Orthodontics & Craniofacial Research, 2024 ทีมเดียวกัน (UNC/Pacific) แต่เป้าหมายต่างกัน: ทำนายความจำเป็นของการผ่าตัดจาก lateral cephalogram ไม่ใช่การเคลื่อนเอง
  • Prediction of orthognathic surgery plan from 3D cephalometric analysis via deep learning (PMC10024836): เป้าหมายเดียวกัน แนวทาง deep learning ส่วน SurgMovPred เป็นโมเดลตารางแบบคลาสสิก

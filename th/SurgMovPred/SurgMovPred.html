SurgMovPred

ตารางค่าการวัดเซฟาโลเมตริกเข้า ตารางการเคลื่อนที่ของกระดูกที่ทำนายออก: ตัวถดถอย scikit-learn แบบ stacking 112 ตัว หนึ่งตัวต่อเป้าหมาย ไม่มีโครงข่ายประสาทเทียม ไม่มีภาพ และไม่มีเมช

ยังไม่ตีพิมพ์ SurgMovPred_CLI ไม่ใช้ conda — ใช้ Python ของ Slicer เอง บรรณานุกรม

การทำนายการเคลื่อนที่จากการผ่าตัดขากรรไกร (orthognathic surgery) จาก ตารางค่าการวัดเซฟาโลเมตริก ไม่มีโครงข่ายประสาทเทียม ไม่มีภาพ ไม่มี เมช: ตัวถดถอย scikit-learn แบบ stacking 112 ตัว หนึ่งตัวต่อค่าที่ต้องทำนาย นำไปใช้ ทีละแถวกับไฟล์ Excel/CSV

1. ตำแหน่งใน pipeline

3. อินพุตและการเตรียมข้อมูล

รูปแบบที่รับ load_data_from_directory() (SurgMovPred_CLI.py:141) รวบรวมทุกไฟล์ *.csv, *.xlsx, *.ods ในโฟลเดอร์ (นามสกุลทั้ง ตัวพิมพ์เล็ก และ ตัวพิมพ์ใหญ่) อ่าน (read_csv, read_excel, read_excel(engine='odf')) แล้ว ต่อรวมกัน (pd.concat(..., ignore_index=True)) ไม่ลงไปในโฟลเดอร์ย่อย สำหรับ เวิร์กบุ๊ก Excel จะอ่านเฉพาะ ชีตแรก — ไฟล์ทดสอบทางการ มีเจ็ดชีต (all_data, demographics, Invivo_ceph, surgical_mov, dolp_ceph_T0, dolp_ceph_T1, dolp_ceph_total) และ all_data อยู่ในตำแหน่งแรก

การทำชื่อคอลัมน์ให้เป็นมาตรฐาน clean_name() (SurgMovPred_CLI.py:39) ใช้กับอินพุต เพื่อให้ตรงกับการสะกดที่ใช้ตอนฝึก:

  1. ลบ ", \, [, ]
  2. อักขระใดที่อยู่นอก [0-9a-zA-Z_'] กลายเป็น _ — apostrophe ถูกเก็บไว้โดยตั้งใจ (คอมเมนต์ในโค้ด: สำหรับ Jarabak's และ SM_A'_CP)
  3. ยุบ _ ที่ซ้ำกัน และตัดออกที่ปลายทั้งสองด้าน
  4. "total" → "Total"
  5. เติมคำนำหน้า f_ หากชื่อขึ้นต้นด้วยตัวเลข

การล้างนี้อธิบายชื่อคุณลักษณะ (feature) ที่ใช้จริง: SM-A-FH   (มีช่องว่าง ต่อท้ายสองตัว ในไฟล์ทดสอบ) กลายเป็น SM_A_FH, Jarabak's ratio   กลายเป็น Jarabak's_ratio, FMA(MP-FH) Ang_2D กลายเป็น FMA_MP_FH_Ang_2D

รหัสผู้ป่วย find_id_column() (SurgMovPred_CLI.py:81) ทดสอบรูปแบบ 8 แบบโดยไม่สนตัวพิมพ์เล็กใหญ่ (#, id, patient id, patient number, subject, …) จากนั้นเป็นทางเลือกสุดท้าย รับคอลัมน์ใดก็ได้ที่มีทั้ง "patient" และ "id" ในไฟล์ทดสอบ คอลัมน์นี้คือ # หากหาไม่พบ คอลัมน์เอาต์พุต IDPatient จะถูกเติมด้วย pd.NA พร้อมคำเตือนธรรมดา

การทำค่าให้เป็นมาตรฐาน แพ็กเกจโมเดลแต่ละชุดมีตัวปรับสเกล ของตัวเอง คือ StandardScaler คำนวณ (การจัดศูนย์กลาง + การปรับสเกล with_mean=True, with_std=True) ใช้ทันทีก่อนการทำนาย (SurgMovPred_CLI.py:237) ไม่มีการเติมค่าที่ขาด: ค่าที่ขาดจะแพร่ต่อเป็น NaN ไปจนถึงเอาต์พุต

ความยืดหยุ่นต่อส่วนต่อท้าย _T0 (SurgMovPred_CLI.py:223): หากโมเดลคาดหวัง X_T0 แต่คอลัมน์ชื่อ X ก็ยอมรับ

การฝึกไม่ได้อยู่ในคลังโค้ด: ไม่มีสคริปต์ ไม่มีชุดข้อมูล ไม่มีตัวชี้วัด ไม่มี seed ไม่สามารถระบุได้จากคลังโค้ด: ขนาดกลุ่มตัวอย่าง โปรโตคอลการตรวจสอบความถูกต้อง สมรรถนะรายเป้าหมาย

9. ข้อควรระวังและจุดเปราะบาง

  • pip_install("numpy==2.4.0") ทุกครั้งที่รัน การเปลี่ยน numpy ภายใต้เซสชัน Slicer ที่กำลังทำงานคือสิ่งที่ทำให้การ import scipy ในส่วนอื่นของ ส่วนขยายพัง (scipy ของ Slicer คอมไพล์เทียบกับ numpy ของมัน) เป็นจุดที่ อันตรายที่สุดของโมดูลอย่างเห็นได้ชัด และถูกกระตุ้นโดยปุ่มหลัก
  • ปุ่ม "test files" ใช้ไม่ได้: DownloadTestFiles() (SurgMovPred.py:763) ดาวน์โหลด TestFiles.zip จริง แต่จะกรอก ช่องอินพุต/เอาต์พุตเฉพาะ if os.path.exists(.../V_FACE/DefaultList) — ส่วนที่ คัดลอกมาจากโมดูล VFACE หลงเหลืออยู่ หากไม่มีข้อมูลทดสอบของ VFACE ไฟล์บีบอัดจะถูก ดาวน์โหลดแล้วถูกละเลย
  • ประกาศรองรับ .ods แต่ไม่ติดตั้ง odfpy ใน check_dependencies (อย่างไรก็ตาม โมดูล Anonymizer ติดตั้งให้ ซึ่งอาจบดบังปัญหา บนเครื่องที่ใช้ทั้งสองโมดูล)
  • คุณลักษณะที่ขาด = โมเดลถูกข้ามอย่างเงียบ ๆ ล็อกเขียนว่า "Model 'X' skipped: missing N input feature(s)" แต่ไฟล์เอาต์พุตเพียง มีคอลัมน์น้อยลงหนึ่งคอลัมน์ ตารางที่ตั้งชื่อคอลัมน์ไม่ดีอาจให้ predictions_outputs.xlsx ที่ไม่มีคอลัมน์ค่าทำนายเลย โดยไม่ล้มเหลว
  • การต่อไฟล์อินพุตแบบไม่ตรวจสอบ: ตารางสองไฟล์ที่มี คอลัมน์ต่างกันให้ NaN และ model.predict บน NaN จะ raise — ข้อผิดพลาดถูกจับต่อเป้าหมาย ผลลัพธ์จึงออกมาไม่ครบโดยแทบ มองไม่เห็น
  • อ่าน Excel เพียงชีตเดียว เวิร์กบุ๊กที่ชีตแรกไม่ใช่ ชีตข้อมูลจะให้ผลลัพธ์ว่างเปล่า
  • โหลดโมเดล 1.5 GB ทุกครั้ง แม้มีเพียงแถวเดียวที่ต้อง ทำนาย แม้ผู้ใช้งานสนใจเพียงเป้าหมายเดียว
  • ไม่มีค่าความไม่แน่นอนในเอาต์พุต แม้โมเดลฐานหนึ่งในสามตัวจะเป็น Gaussian process
  • ไม่มีความสอดคล้องแบบแข็งเกร็งระหว่างจุดของชิ้นส่วนเดียวกัน (§7)
  • helpText docstring ของ parameter node และชื่ออาร์กิวเมนต์ของ process() อธิบายเครื่องมือที่ต่างออกไปโดยสิ้นเชิง (การสรุปบันทึกทางคลินิก)

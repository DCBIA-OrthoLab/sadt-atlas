FlexReg, legacy: โค้ด

สำหรับนักพัฒนา: สิ่งที่โมดูล Slicer แบบ legacy ชื่อ FlexReg ทำในโค้ด (SlicerAutomatedDentalTools ที่ 3c67957) พร้อมการอ้างอิง file:line ซิกเนเจอร์ อาร์กิวเมนต์ สภาพแวดล้อม และข้อควรระวัง คำอธิบายที่อ่านง่ายของไปป์ไลน์เดียวกัน พร้อมคณิตศาสตร์ อยู่ในหน้าแอตลาส พอร์ต VISOR มีหน้าโค้ดของตัวเอง

โค้ด แอตลาส (คำอธิบาย) ยังไม่ตีพิมพ์ FlexReg_CLI conda env: shapeaxi VISOR คู่มือ บรรณานุกรม
โค้ดสองชุด

ทุกอย่างที่มีเลขกำกับด้านล่างอธิบายโมดูล Slicer แบบ legacy (SlicerAutomatedDentalTools ที่ 3c67957, 2026-10-26) ส่วนพอร์ต VISOR ซึ่งรันเครื่องมือเดียวกันบนเซิร์ฟเวอร์ อธิบายไว้ในหน้าของตัวเอง FlexReg บน VISOR พอร์ต VISOR เก็บการพรีวิวแพตช์ไว้ใน Slicer และทำส่วนที่เหลือบนเซิร์ฟเวอร์ มันไม่มีเส้นโค้งอิสระ การลบแพตช์ การคำนวณแพตช์ mucogingival และการแบ่งส่วนครอบฟันอัตโนมัติ

LPS ↔ RAS การพลิก CLI อ่าน .vtk (LPS) ใช้ Scale(-1,-1,1) เพื่อทำงานใน RAS เหมือน Slicer และพลิกกลับก่อนเขียน (FlexReg_CLI.py:228, 297) การคำนวณภายในทั้งหมดจึงอยู่ใน RAS

การจัดกรอบมาตรฐาน ขั้นประมวลผลเบื้องต้นที่สำคัญ orientation.py:

  1. centroid ของฟัน Universal_ID 3, 5, 12, 14 (UR6, UR4, UL4, UL6)
  2. ฐานเฉพาะที่ในแต่ละด้าน: normal ของระนาบที่ผ่านสามจุด (ผลคูณไขว้ของเวกเตอร์สองตัวไปยังจุดกึ่งกลาง) แล้วทิศทางที่ตั้งฉาก
  3. การหมุนสองครั้งต่อเนื่อง แกน = ผลคูณไขว้ มุม = arccos ของผลคูณจุด ผ่าน RotationMatrix (Rodrigues)
  4. การเลื่อนเพื่อให้ centroid ทับกัน

เป้าหมายคือ [[-0.5,-0.5,0], [0,0,0], [0.5,-0.5,0]]: ฟันกรามขวาที่ x<0 ฟันกรามซ้ายที่ x>0 ฟันกรามน้อยที่จุดกำเนิด ผลลัพธ์: ระนาบ occlusal ≈ z=0, +y = ด้านหน้า, +x = ด้านซ้าย ไม่มีการย่อขยาย: นี่คือการลงทะเบียนภาพแบบแข็งเกร็งด้วย 3 จุด

ผลที่ตามมาโดยตรง: การคำนวณbutterflyทั้งหมดที่ตามมาเป็นการคำนวณ 2D ในระนาบ XY โดยเพิกเฉยองค์ประกอบ z

5.1 เส้นทาง A: แพตช์ Butterfly (ซุ้มฟันบน) คำนวณ

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

make_butterfly.py ไม่มีโครงข่าย เรขาคณิตล้วน

a) สี่ centroid ผู้ปฏิบัติงานเลือกฟัน 4 ซี่ (หน้าซ้าย/ขวา หลังซ้าย/ขวา) vtkMeanTeeth เฉลี่ย vertex ที่มี Universal_ID นั้น

b) พารามิเตอร์สามกลุ่ม ที่ใช้กับ centroid เหล่านี้:

พารามิเตอร์ผลรายละเอียด
shift_lr, shift_apเลื่อนทั้งแพตช์เวกเตอร์เดียวกันถูกบวกเข้ากับทั้ง 4 centroid เนื่องจาก landmark เป็นการรวมแบบ affine ที่น้ำหนักรวมเป็น 1 การเลื่อนจึงส่งผ่านการ interpolate และรูปร่างไม่เปลี่ยน
adjust (mm)ยืด / หดออฟเซ็ตใน ±y เครื่องหมายกลับที่ฟันหลัง: ค่า adjust บวกดันทั้งสองปลายออกด้านนอก
ratioความกว้างคงเดิมกำหนดพารามิเตอร์ใหม่เป็น r = (1-ratio)/2 แล้ว landmark = (1-r)·own_centroid + r·opposite_centroid ratio=1 → landmark อยู่บน centroid ของตัวเอง (แพตช์สูงสุด) ratio=0 → landmark อยู่กึ่งกลาง (แพตช์เสื่อม)

ระวังคำศัพท์: UI ใช้ top/bot CLI ใช้ anterior/posterior lineedit_teeth_left_top → tooth_anterior_left

c) เส้นขอบ สี่ชิ้น:

  • ส่วนหน้าและส่วนหลัง (Segment2D, ขั้น 0.01)
  • quadratic Bézier สองเส้น ขวาและซ้าย จุดควบคุม (posterior_landmark, posterior_midpoint, anterior_landmark) แล้วสะท้อนข้ามคอร์ด (sym = 2·proj − bezier) เพื่อให้โป่งออกด้านนอกของซุ้มฟันแทนที่จะโป่งเข้าศูนย์กลาง นี่คือสิ่งที่ให้รูปร่างของbutterfly

d) การทำเครื่องหมาย torch.cdist ระหว่างจุดของเส้นขอบกับ vertex ที่ฉายลง XY ทุก vertex ภายใน radius = 0.7 mm ถูกตั้งเป็น 1

e) การเติม Dilation() (propagation.py:56): geodesic flood fill บนเมช ไม่ใช่ morphological dilation เริ่มที่ vertex ใกล้ barycenter ของ landmark ทั้ง 4 มากที่สุด แพร่ไปทีละเพื่อนบ้าน (GetPointCells / GetCellPoints) และหยุดที่เส้นขอบซึ่งถูกตั้งเป็น 1 แล้ว ทำเป็นชุดละ nmb_treatment = 1000 บน GPU

f) การเขียน อาร์เรย์ชื่อ Butterfly{index}: แต่ละแพตช์มี index ของตัวเอง ซึ่งทำให้สะสมได้ ตอนท้ายของ CLI อาร์เรย์ Butterfly1..N ทั้งหมดถูกรวมด้วย torch.logical_or เป็นอาร์เรย์ Butterfly เดียว (FlexReg_CLI.py:277): นั่นคืออันที่ ICP และAREG_IOS อ่าน ผลถูกเขียนกลับลงในไฟล์อินพุต

โหมด delete กำหนดหมายเลขอาร์เรย์เหนือ index ที่ลบใหม่ แล้วทิ้งอันสุดท้าย แทนที่จะปล่อยช่องว่าง

พรีวิวเรียลไทม์ butterfly_preview.py เล่นเส้นขอบเดิมทุกประการซ้ำด้วย numpy ล้วน (CPU) และแทน flood fill ด้วยการทดสอบจุดในรูปหลายเหลี่ยม (matplotlib.path.Path พร้อมทางสำรอง crossing-number ของ numpy) ทิศทางและ centroid ถูกแคชต่อสแกน (prepare) จึงคำนวณใหม่เฉพาะเส้นขอบทุกครั้งที่ขยับจอยสติก ค่าคงที่: CELL = 1.0 mm สำหรับแผนที่ความสูง LIFT = 0.4 mm เหนือฟัน NB_POINTS = 120 ตัวอย่างต่อขอบ

a) การทำความสะอาดคำทำนายของ ALI DoubtfulLandmarks() อ่าน description ที่ ALI เขียนลง json เมื่อมันบังคับจุด (พิกเซล top-k การถอยไปที่ฟัน ฟันที่ขาด) ตามความเห็นของโค้ด วัดบน 364 คำทำนาย: ค่ามัธยฐานเบี่ยงจากเส้นโค้งของเพื่อนบ้าน 4.2 mm เทียบกับ 1.2 mm สำหรับส่วนที่เหลือ เครื่องหมายที่ทดสอบคือ forced, fallback, arch fit, off the aim และ extrapolated บวก confidence ใด ๆ ที่ต่ำกว่า MIN_CONFIDENCE = 0.785 (mgl_patch.py:144-162) จุดเหล่านี้ถูกทิ้งโดยค่าเริ่มต้น และ spline เชื่อมช่องว่าง: เว้นแต่จะเหลือน้อยกว่า 3 จุด จากนั้น CanonicalLandmarks (ชื่อ annotation แบบเก่า → มาตรฐาน ตรวจจากการมี LL7MG หรือ LR7MG) และ RecentreNames (การนับยึดอยู่ที่เส้นกึ่งกลางเมื่อจุดหายไปกลางซุ้มฟัน)

b) กรอบเฉพาะที่ LocalFrames(): แกนapical คือองค์ประกอบที่สามของSVD ของ landmark ที่จัดกึ่งกลางแล้ว (normal ของริบบิ้นจุด ไม่ขึ้นกับทิศทางของสแกนในพื้นที่โลก) tangent คือ np.gradient ตามซุ้มฟัน buccal คือผลคูณไขว้ของสองอย่างนั้น พลิกทุกที่ที่ชี้เข้าด้านใน OrientApical กำหนดเครื่องหมายตามครอบฟัน

c) การสร้างแถบ ในทุก compute():

  1. ออฟเซ็ตของผู้ปฏิบัติงาน (buccal / apical / tangential) ที่ใช้กับ landmark
  2. vtkParametricSpline ผ่านจุดเหล่านั้น SAMPLES_PER_SEGMENT = 25
  3. แต่ละตัวอย่างถูกยึดลงบนเมช (vtkPointLocator): spline ที่ interpolate เบี่ยงออกจากพื้นผิวในส่วนเว้าระหว่างฟัน
  4. Dijkstra (scipy.sparse.csgraph) บนกราฟขอบที่ถ่วงน้ำหนักด้วยความยาวจริง หลายต้นทางจาก vertex เหล่านี้ limit = ความสูงสูงสุด min_only=True, return_predecessors=True → แถบโตตามพื้นผิว ไม่เคยทะลุผ่านมัน (แพตช์ด้าน vestibular ไม่อาจโผล่ที่ด้าน lingual ซึ่งสันบาง)
  5. ความสูงinterpolate เชิงเส้นระหว่าง landmark (np.interp) และไม่สมมาตร: heights ด้านครอบฟัน heights_down ด้าน vestibular โดยด้านถูกตัดสินจากเครื่องหมายขององค์ประกอบ apical ความสูงที่ใช้คือของseedที่ vertex ถูกไปถึงจากมัน ดังนั้นสองส่วนที่ความสูงต่างกันอยู่ร่วมกันได้โดยไม่มีขั้น ด้านคือเครื่องหมายของ vertex ลบ seed ของมัน ฉายบนแกน apical (below, mgl_patch.py:510-513) และ vertex ถูกเก็บถ้า distance <= allowed และ allowed > 0 (:513-516) ความสูง 0 จึงไม่เก็บอะไร แม้แต่เส้นโค้ง ความสูงทั้งสองมีค่าเริ่มต้น 2.5 mm (mgl_patch.py:120 สไลเดอร์ “Upper extension” และ “Lower extension”, FlexReg.py:1867-1868, 1966-1972) แถบจึงสมมาตรโดยค่าเริ่มต้นเท่านั้น
  6. ครอบฟัน (Universal_ID 17–32, LOWER_TOOTH_LABELS = range(17, 33) รวมฟันกรามซี่ที่สาม mgl_patch.py:130-134) ถูกนำออก: มันเคลื่อนระหว่าง T1 และ T2
  7. ตัว landmark เองอยู่ในแพตช์เสมอ

ขอบเขต: MIN_HEIGHT = 0.0, MAX_HEIGHT = 5.0, DEFAULT_HEIGHT = 2.5 mm ความสูงศูนย์ทุกที่ ⇒ เหลือเพียง 13 จุด: นี่คือกรณีควบคุมโดยตั้งใจ เพื่อวัดว่าแถบเพิ่มอะไรเหนือจุดอย่างเดียว

กราฟขอบถูกสร้างด้วย np.unique(np.sort(edges)) ก่อน coo_matrix: หากไม่ลบรายการซ้ำนี้ ขอบด้านในที่ใช้ร่วมกันโดยสองสามเหลี่ยมจะถูกบวกโดยเมทริกซ์แบบ sparse ทำให้ความยาวเป็นสองเท่าและระยะเอื้อมของแพตช์ลดลงครึ่งหนึ่ง

เป็นจริงใน VISOR ด้วยสำหรับแพตช์: Dilation เรียก .cuda() โดยไม่มีทางเลือกสำรอง (SADT-VISOR sadt_flexreg/propagation.py:31, 60, 66-68) ซึ่งถูกเรียกจาก make_butterfly.py:161 ไม่เป็นจริงอีกต่อไปในส่วนที่เหลือ: การรวมอาร์เรย์ Butterfly ใช้ numpy (pipeline.py:165-188), drawPatch ไม่ถูกเรียก, การข้ามลูป icp_mgl หายไปแล้ว และเส้นทางการลงทะเบียนไม่ import torch (pipeline.py:191-224)

ไฟล์อินพุตถูกเขียนทับ (เฉพาะ legacy)

ในโหมดแพตช์ และการแบ่งส่วนอัตโนมัติก็เขียนทับด้วย (overwrite=1) ไฟล์ .stl ที่ส่งให้ dentalmodelseg จะถูกลบทิ้งเลย: นั่นคือเหตุผลทั้งหมดที่ ensureVtkInput() มีอยู่

การอ้างอิง legacy: FlexReg_CLI.py:314-315 (โหมดแพตช์เขียนไปที่ args.lineedit), FlexReg.py:3481 (แฟล็ก overwrite ของการแบ่งส่วน)

Legacy (3c67957); ไม่มีใน VISOR: อินพุตไม่ถูกแก้ไขเลย เอาต์พุตไปอยู่ใต้ output_dir พร้อมคำต่อท้าย (SADT-VISOR sadt_flexreg/__init__.py:160-163) และไม่มีการรันการแบ่งส่วน

บั๊กที่ยืนยันแล้ว: vtkICP.__call__ (เป็นจริงใน VISOR ด้วย)

vtkICP.__call__ คืนค่า source ตามเดิมแทนที่จะคืนเมชที่ถูกแปลงแล้ว ไม่เป็นปัญหาตรงนี้เพราะ list_icp มีเพียงหนึ่งวิธี แต่โซ่หลายขั้นจะใช้งานไม่ได้ตามที่เขียนไว้

เป็นจริงใน VISOR ด้วย: return source, VTKMatrixToNumpy(...) (SADT-VISOR sadt_flexreg/ICP.py:113; legacy FlexReg_CLI/FlexReg_Method/ICP.py:104) ยังคงไม่เป็นปัญหา เพราะ register ใช้เมทริกซ์ที่คืนมาเองอยู่แล้ว (pipeline.py:218-224)

การตรวจจับการแบ่งส่วนทำงานผ่านข้อยกเว้น (เฉพาะ legacy)

เมชที่แบ่งส่วนไว้ภายใต้ชื่ออาร์เรย์อื่นที่ไม่ใช่ Universal_ID จะทำให้เกิดการแบ่งส่วนใหม่ทั้งหมด

Legacy (3c67957); ไม่มีใน VISOR: ไม่มีการแบ่งส่วนใหม่ สิ่งที่ VISOR ทำแทนนั้นต่างออกไปและเงียบกว่า: ดู "Without Universal_ID, the last array is used" ในข้อค้นพบใน VISOR

โค้ดตาย: downloadModel(), setup_cli_command() / find_cli_parameters()

แพตช์ถูกตัดสินใน 2D ที่ฉายภาพ (เป็นจริงใน VISOR ด้วย)

แพตช์ butterfly ถูกตัดสินใน 2D ที่ฉายภาพ: บนส่วนโค้งฟันที่เอียงมากหลังจัดทิศทาง เส้นขอบอาจจับจุดยอดที่อยู่ห่างกันมากในแนว z

เป็นจริงใน VISOR ด้วย: ระยะทางใช้ V[:,:2] (SADT-VISOR sadt_flexreg/make_butterfly.py:127, 133, 147, 159; legacy make_butterfly.py:114, 120, 134, 146) และพรีวิวใน Slicer ก็ทำเหมือนกันที่ฝั่งไคลเอนต์ (FlexRegLib/butterfly_preview.py)

10. วรรณกรรม

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

รากฐานที่ตีพิมพ์แล้วคือ AReg IOS: Automatic Registration on IntraOral Scans (Hutin, Anchling, Cevidanes et al., Lecture Notes in Computer Science, 2023): การแบ่งส่วนตัวฟันด้วย DentalModelSeg, การจัดแนวเริ่มต้นด้วย centroid ที่ใช้ร่วมกัน, ROI เพดานปากที่แบ่งส่วนด้วยการวิเคราะห์รูปร่าง 3D แบบหลายมุมมอง แล้วจึง ICP FlexReg คือคู่เทียบแบบ "ผู้ปฏิบัติงานวาด ROI เองแทนที่จะให้ทำนาย" ของงานนี้

ไม่มีบทความใดกล่าวถึง FlexReg โดยเฉพาะ หรือกล่าวถึงตัวแปร MGL: ตัวแปรหลังดูเหมือนเป็นการพัฒนาภายในที่ยังไม่ตีพิมพ์จนถึงปัจจุบัน ตัวเลขที่อ้างในโค้ด (4.2 mm เทียบกับ 1.2 mm บน 364 การทำนาย) ไม่มีแหล่งที่มาที่ไหนนอกคอมเมนต์

  • AREG (รีโพซิทอรี)
  • ALI_IOS (รีโพซิทอรี)
  • SlicerAutomatedDentalTools
  • Automated Orientation and Registration of CBCT Scans, LNCS

Agent: ไปป์ไลน์ทั้งหมด

ผู้ช่วยภาษาธรรมชาติที่เลือกโมดูลจากส่วนขยาย ดึงพารามิเตอร์ของมัน สร้างบรรทัดคำสั่ง และเปิดใช้งาน ไม่มีเครือข่ายประสาทเทียมทางการแพทย์ถูกเรียกที่นี่: Agent ทำเพียงการเลือกเส้นทางและการกรอกฟอร์ม หน้านี้อธิบายทีละขั้น รายละเอียดที่นักพัฒนาต้องการอยู่ในหน้าโค้ด

ยังไม่ตีพิมพ์ Agent_CLI Python ของ Slicer qwen3:8b ผ่าน Ollama cross-encoder MiniLM-L6 โค้ด (นักพัฒนา) บรรณานุกรม VISOR: บางส่วน

ทุกอย่างรันในเครื่อง: โมเดลภาษาขนาด 8B ที่ให้บริการโดย Ollama และ cross-encoder ขนาดเล็กที่คัดเครื่องมือผู้สมัครไว้ล่วงหน้า

สองฐานโค้ด ทุกอย่างที่อธิบายที่นี่คือโมดูล Slicer แบบ legacy (SlicerAutomatedDentalTools ที่ 3c67957, 2026-10-26) VISOR มีเครื่องมือฝั่งเซิร์ฟเวอร์ชื่อ Agent ซึ่งเป็น router บนปลายทาง Ollama ภายนอก แต่ไม่มีไคลเอนต์เรียกใช้: แผง AgentRemote ที่ส่งมากับไคลเอนต์ VISOR เป็นสำเนาของวิดเจ็ต legacy ที่ยังรันในเครื่องอยู่ ทั้งสองอธิบายไว้ในหน้า VISOR ของ Agent หลักฐาน

ภาพรวม: อะไรเข้า อะไรออก

Agent (Automated)Ask (Interactive)
เข้าประโยคที่พิมพ์ในแชต และโฟลเดอร์ที่ลากวางบนแผงเหมือนกัน
ออกคำสั่งที่เสนอ (โมดูลใด ค่าใด) หลังผู้ใช้ยืนยัน โมดูลจะถูกเปิดคำตอบข้อความอิสระ ไม่มีอะไรถูกเปิด

1. ตำแหน่งในสายโซ่

ไม่มีใครเรียก Agent ไม่มีโมดูลอื่นของส่วนขยายใช้มัน: มันเป็นจุดเข้าปลายทาง ขาออกมีสามสิ่งที่ถูกเรียก:

ที่ถูกเรียกวิธีเรียกที่ไหน
Agent_CLIตัวรันบรรทัดคำสั่งของ Slicerโปรเซสแยก, Python ของ Slicer
โมดูลเป้าหมาย (ALI_CBCT, AMASSS_CLI, ...)เริ่มเป็นโปรเซสลูกของแผงPython ของ Slicer
Ollamaไคลเอนต์ Python ของมัน ผ่าน HTTP บนพอร์ตของเครื่องเองเซิร์ฟเวอร์ในเครื่อง ติดตั้งและเปิดโดยโมดูล

รายการเป้าหมายเป็นแบบประกาศล้วน: อยู่ใน manifest.yaml ไฟล์ YAML ที่มี 16 รายการ Agent ไม่ค้นพบอะไรด้วยตัวเอง: มันรู้จักแต่ไฟล์นี้

ในโค้ดจุดเรียกพร้อมไฟล์และบรรทัด และโค้ดที่ไม่ได้ใช้ซึ่งยังเหลืออยู่ในโมดูล

2. ไฟล์ที่เกี่ยวข้อง

แผง (แชต โซนวางไฟล์ การติดตั้ง Ollama การยืนยัน การเปิด การซ่อม) รันใน Slicer โปรแกรมบรรทัดคำสั่งแยกต่างหากทำการเลือกเส้นทางและการดึงค่า และพิมพ์ JSON ไม่รันอะไร ไฟล์ยูทิลิตีเก็บmanifest cross-encoder การเรียก Ollama การค้นหาพาธ และการสร้างคำสั่ง ตัวตรวจสอบแปลงชนิดและตรวจค่า และ manifest ระบุ 16 เครื่องมือที่เรียกใช้ได้ ไม่มีสภาพแวดล้อม conda และไม่บังคับ GPU: ทุกอย่างรันภายใน Python ของ Slicer GPU ที่ใช้มีเพียงทางอ้อม ผ่านเซิร์ฟเวอร์ Ollama

ในโค้ดตารางไฟล์พร้อมที่ที่แต่ละไฟล์รัน

3. โมเดล

3.1 โมเดลภาษา qwen3:8b ผ่าน Ollama

โมเดลเดียวรับใช้ทั้งสามการเรียก คือการเลือกเส้นทาง การดึงพารามิเตอร์ และการซ่อม: Qwen3 ขนาด 8 พันล้านพารามิเตอร์ รันโดย Ollama (จึงมี llama.cpp อยู่ข้างใต้) ในรูปแบบ GGUF ที่ Ollama กำหนด ไม่มีโมเดลเฉพาะทางและไม่มีการ fine-tune ชื่อโมเดลถูกเขียนไว้สองที่ในโค้ดและสลับได้ด้วยตัวแปรสภาพแวดล้อม แท็กเริ่มต้นหนัก 5.2 GB (อ่านจาก ollama.com ระบุจากที่เก็บโค้ดไม่ได้)

จะรันบน CPU หรือ GPU เป็นการตัดสินใจของ Ollama ไม่ใช่ของโมดูล โค้ดสรุปผลตามมาข้อหนึ่ง: บน Linux Ollama ที่ติดตั้งผ่าน snap ถูกแยกอยู่ใน sandbox มองไม่เห็น GPU ของ NVIDIA และถอยไปใช้ CPU ที่ 80 ถึง 90 วินาทีต่อคำตอบ สำหรับโมเดล 8B ซึ่งเป็นตัวเลขที่วัดมาและเขียนไว้ในโค้ด โมดูลตรวจพบและเตือน แต่แก้ไม่ได้

เมื่อไม่พบ Ollama โมดูลจะดาวน์โหลดไฟล์เก็บถาวรพกพาทางการไปไว้ในโฟลเดอร์ของตัวเอง จึงไม่ต้องใช้รหัสผ่าน root จากแผง ใช้เพียงสองการตั้งค่าการเรียก: โมเดลคงอยู่ในหน่วยความจำ 30 นาทีแทน 5 นาที และคำตอบถูกบังคับเป็น JSON สำหรับrouter การดึงค่า และการซ่อม (ไม่ใช้กับโหมดที่ปรึกษา) ไม่มีการส่ง temperature, seed หรือขนาดบริบท หากไม่มีโมเดล จะ pull แล้วเล่นการเรียกซ้ำ

ในโค้ดค่าคงที่ การทดสอบ snap ตัวติดตั้ง Ollama และสองการตั้งค่าการเรียก

3.2 cross-encoder: ms-marco-MiniLM-L-6-v2

นี่คือเครือข่ายประสาทเทียมจริงเพียงตัวเดียวที่โหลดในโปรเซส: MiniLM, 6 เลเยอร์, พารามิเตอร์ 22.7 ล้าน ฝึกกับงานจัดอันดับ passage ของ MS MARCO ดาวน์โหลดจาก Hugging Face Hub มันไม่ใช่โมเดล embedding: คำขอและข้อความของเครื่องมือถูกป้อนเข้า transformer ด้วยกัน ซึ่งให้ผลลัพธ์เป็นตัวเลขความเกี่ยวข้องหนึ่งตัวที่ไม่มีขอบเขต โปรแกรมบรรทัดคำสั่งเป็นโปรเซสใหม่ทุกข้อความ โมเดลจึงถูกโหลดใหม่ทุกครั้ง

หากโหลด cross-encoder ล้มเหลว ทางสำรองนั้นหยาบมาก: สามเครื่องมือแรกของmanifest ไม่ว่าคำถามจะเป็นอะไร และแชตไม่ได้รับแจ้ง (มีเพียงบรรทัดเดียวไปที่เอาต์พุตของโปรแกรม) ฟิลด์ priority ของ manifest ไม่เคยถูกอ่าน

ในโค้ดข้อความของแต่ละเครื่องมือถูกสร้างอย่างไร การเรียง k ที่กำหนดตายตัว และทางสำรองแบบเงียบ

4. การเลือกเส้นทาง

สองขั้น และโมเดลภาษาเข้ามาเกี่ยวข้องเฉพาะขั้นที่สอง ขั้นที่ 1 คือ cross-encoder ข้างต้น ในขั้นที่ 2 โมเดลรับคำขอและผู้สมัครสามราย รายละหนึ่งบรรทัด (ชื่อ คำอธิบายที่ตัดที่ 140 อักขระ แท็กไม่เกิน 8) และต้องตอบด้วยออบเจกต์ JSON หนึ่งชิ้น: ชื่อเครื่องมือ ค่า confidence และเหตุผลหนึ่งประโยค มีสามข้อที่ควรรู้:

  • บริบทของโฟลเดอร์ไม่ได้ส่งให้router มันถูกเพิ่มทีหลังเพื่อการดึงค่าเท่านั้น
  • ประวัติการสนทนาถูกแทรกตามที่ปรากฏบนหน้าจอ รวมถึงประโยคของแผงเอง เช่น “After reflection, I would like to run ...” router แบบ JSON จึงได้รับข้อความของอินเทอร์เฟซเป็นคำตอบก่อนหน้า
  • ค่า confidence และเหตุผลไม่มีประโยชน์ confidence ถูกแยกวิเคราะห์และเขียนออก แล้วไม่เคยอ่านกลับ: ไม่มีเกณฑ์ที่ไหนเลย และคำสั่ง “confidence at most 0.4 when nothing matches” เป็นเพียงข้อเสนอแนะต่อโมเดล

เครือข่ายความปลอดภัยเดียวเป็นแบบข้อความ: คำตอบต้องไม่เป็น null ชื่อเครื่องมือที่ไม่อยู่ในmanifestผ่านการทดสอบนี้ แล้วทำให้ตัวสร้างคำสั่งล้มเหลว ข้อผิดพลาดถูกจับและคืนเป็นข้อความข้อผิดพลาด

ในโค้ดพรอมต์ของ router การแทรกประวัติ และโค้ด tool-spec ที่ไม่ได้ใช้

5. การดึงพารามิเตอร์

การเรียกโมเดลครั้งที่สอง เมื่อเลือกเครื่องมือไว้แล้ว พารามิเตอร์ทางเทคนิค (โฟลเดอร์ชั่วคราว พาธ log) ถูกถอดออกจากสิ่งที่โมเดลเห็นและแผงเป็นผู้เติมให้ภายหลัง: ไม่ได้ขอให้โมเดลคิดขึ้นเอง พรอมต์ระบุพารามิเตอร์แต่ละตัวพร้อมชนิด ว่าจำเป็นหรือไม่ และต้องเขียนลิสต์อย่างไร แล้วกำหนดกฎเจ็ดข้อ ที่สำคัญที่สุดคือ ดึงเฉพาะสิ่งที่คำขอกล่าวถึง อย่าคิดค่าขึ้นเอง ปล่อยพารามิเตอร์ทางเลือกที่ไม่ได้กล่าวถึงให้ไม่ปรากฏ รายการพารามิเตอร์ที่จำเป็นซึ่งโมเดลส่งกลับถูกเพิกเฉย: ตัวตรวจสอบเป็นตัวที่มีผล

ตัวตรวจสอบยังบังคับข้อความ “true” หรือ “false” เป็นตัวพิมพ์เล็กในที่ที่เครื่องมือเทียบอาร์กิวเมนต์ดิบ นอกจากนั้นรายงานการตรวจสอบถูกทิ้งเกือบทั้งหมด: ข้อผิดพลาดและคำเตือนไม่ปรากฏที่ไหนเลย

พาธถูกปล่อยให้โมเดลจัดการทั้งหมด โฟลเดอร์ที่ลากวางบนแผงถูกต่อท้ายคำขอ พร้อมคำสั่งให้ถือเป็นแหล่งความจริง ไม่มีการจับคู่เชิงฮิวริสติก ไม่มีการดูภายในโฟลเดอร์ และไม่มีการตรวจว่ามีอยู่จริง: โมเดลเพียงอย่างเดียวเดาว่าพาธใดที่ลากมาเป็น T1 พาธใดเป็น T2 พาธใดเป็นโฟลเดอร์โมเดล VISOR แก้เพียงส่วนเครื่องหมายจุลภาคของเรื่องนี้: เครื่องมือฝั่งเซิร์ฟเวอร์รับโฟลเดอร์เป็นลิสต์

ในโค้ดพรอมต์การดึงค่า การตรวจสอบหกรอบ และบล็อกพาธพร้อมการแยกด้วยเครื่องหมายจุลภาค

6. การสร้างและรันคำสั่ง

ใช่ โมดูลถูกเปิดใช้งานจริง โปรแกรมบรรทัดคำสั่งเพียงสร้างคำสั่ง: มันรวมค่าเริ่มต้นของmanifestกับค่าที่ดึงมา แล้วเติมอินเทอร์พรีเตอร์ของ Slicer เองและพาธสคริปต์ไว้ข้างหน้า สำหรับ 14 จาก 16 เครื่องมือ ค่าต่าง ๆ ถูกเขียนต่อกันตามลำดับที่ manifest ประกาศไว้ (แบบตามตำแหน่ง)

จากนั้นแผงรันคำสั่ง และเฉพาะเมื่อไม่ขาดสิ่งที่จำเป็น: ฟองแชตบอกว่าอยากรันอะไร กล่องโต้ตอบ Yes/No แสดงทุกพารามิเตอร์ และเมื่อกด Yes โมดูลเริ่มทำงาน หากขาดสิ่งที่จำเป็น จะไม่เปิดอะไร: แผงแสดงรายการสิ่งที่ขาดพร้อมค่าที่รู้แล้ว และรอข้อความต่อเนื่อง การเปิดทำงานแบบซิงโครนัสและเกิดบนเธรดของอินเทอร์เฟซ: Slicer ค้างตลอดช่วงงาน ซึ่งสำหรับการแบ่งส่วนหรือการลงทะเบียนวัดเป็นสิบ ๆ นาที

ในโค้ดตัวสร้างคำสั่ง กล่องโต้ตอบ และการเรียก subprocess ที่บล็อก

7. วงจรซ่อม

เส้นทางนี้ทำงานภายในโปรเซส Slicer ไม่ใช่ในโปรแกรมบรรทัดคำสั่ง การแก้ไขวนกลับผ่านตัวตรวจสอบและตัวสร้างคำสั่ง แสดงความต่างแบบเก่าไปใหม่ และต้องมีการยืนยัน Yes/No ใหม่ ความต่างที่ว่างจะหยุดวงจร การวินิจฉัยด้วยคีย์เวิร์ดโดยไม่ใช้โมเดลเพิ่มคำแนะนำสำหรับโมเดล Ollama ที่ขาด โมดูล Python ที่ขาด regression ที่รู้จักใน transformers รุ่นล่าสุด การชนกันของ numpy 2 กับ torch wheel และการเชื่อมต่อ Ollama ล้มเหลว

ในโค้ดพรอมต์การซ่อม เทคนิค import ซ้ำ และการวินิจฉัยด้วยคีย์เวิร์ด

8. โมดูลที่เรียกใช้ได้ และสถานะจริงของมัน

manifestระบุ 16 เครื่องมือ รายการพารามิเตอร์ของมันถูกเทียบทีละไฟล์กับบรรทัดคำสั่งจริงของสคริปต์เป้าหมายแต่ละตัว ลายเซ็นถูกต้องเพียง 2 จาก 16: DOCShapeAXI และ MRI2CBCT_resample อีกสอง (BatchDentalSeg และ CLIC) เป็นโมดูล Slicer แบบสคริปต์ ไม่ใช่เครื่องมือบรรทัดคำสั่ง และรันด้วยวิธีนี้ไม่ได้ AMASSS ปฏิเสธตรง ๆ (“Expected 13 arguments”) ที่เหลือแต่ละตัวขาดหนึ่งถึงสี่พารามิเตอร์

เนื่องจากไม่มีอะไรถูกตั้งชื่อบนบรรทัดคำสั่ง ลิสต์ที่สั้นเกินไปจึงไม่ทำให้เกิดข้อผิดพลาดที่ชัดเจน: บน AREG_IOS เป็นต้น พาธไฟล์ log ไปอยู่เป็น suffix ของชื่อไฟล์ ไม่มีใน manifest และ Agent จึงเข้าถึงไม่ได้: VFACE, GreedyReg, CNE, AREG_IOSCBCT, SurgMovPred และ Medical_Data_Anonymizer

ในโค้ดตาราง 16 แถวพร้อมจำนวนพารามิเตอร์ใน manifest และจริงของแต่ละสคริปต์

พาธของสคริปต์ไม่ resolve

ปัญหาที่รากฐานกว่าลายเซ็น manifest ให้เพียงชื่อสคริปต์เปล่า การค้นหาพาธมองตามลำดับที่ โฟลเดอร์ที่ตัวแปร AGENT_CLI_TOOLS_DIR ระบุ โฟลเดอร์ “CLI files” ข้าง manifest โฟลเดอร์ของ manifest เอง แล้วขึ้นไปอีกสูงสุดสี่ระดับ ไม่มีที่ใดเลยอยู่ในที่เก็บโค้ดนี้ ซึ่งสคริปต์แต่ละตัวอยู่ในโฟลเดอร์ของโมดูลตัวเอง จึงไม่มีผู้สมัครรายใดตรง และฟังก์ชันคืนรายแรก “เพื่อให้ข้อความข้อผิดพลาดชี้ไปยังพาธที่ดีบักได้”

ตัวการเปิดเองไม่โยนข้อผิดพลาด (อินเทอร์พรีเตอร์ของ Slicer มีอยู่): เป็น Python ที่ออกด้วยโค้ด 2 บนไฟล์ที่หาไม่พบ ซึ่งกระตุ้นวงจรซ่อม แม้พาธ resolve แล้ว บางเป้าหมายก็ยังล้มเหลว: DOCShapeAXI ต้องการแพ็กเกจที่อยู่ในสภาพแวดล้อม conda ขณะที่ Agent เปิดทุกอย่างด้วย Python ของ Slicer

ในโค้ดตัว resolve ผู้สมัครทั้งสี่ และ callout เรื่องสำเนาฝั่งไคลเอนต์

9. สองโหมด

โหมดสิ่งที่ Agent_CLI ส่งคืนการทำงาน
Agent (Automated)ออบเจกต์ JSON ที่มีเครื่องมือ ค่า confidence พารามิเตอร์ สิ่งที่ขาด และคำสั่งใช่ หลังการยืนยัน
Ask (Interactive)ข้อความอิสระไม่มี

ในโหมด Ask แต่ละบรรทัดผู้สมัครยังมีรายการดิบของพารามิเตอร์ ถูกวางตามที่เป็นลงใน system prompt ของ “expert medical image analysis consultant” คำตอบไม่ถูกบังคับเป็น JSON และถูกแสดงหลังตัดอักขระ * และ # ออก README เรียกโหมดนี้ว่า “Consultant” อินเทอร์เฟซเขียนว่า “Ask (Interactive)” และโค้ดทดสอบเพียงชื่อ Agent ค่าอื่นใดจึงตกไปที่โหมดที่ปรึกษา

ในโค้ดรูปแบบเอาต์พุตทั้งสอง และการทดสอบโหมดที่แน่นอน

10. มาตรการป้องกัน

สิ่งที่มี:

  • การยืนยันที่บังคับก่อนการรันทุกครั้ง แสดงพารามิเตอร์ทั้งหมด และอีกครั้งก่อนความพยายามซ่อมทุกครั้ง
  • ไม่มีอะไรถูกเปิดตราบที่ขาดพารามิเตอร์ที่จำเป็น
  • การแปลงชนิด และการตรวจ choices ช่วงค่า และนามสกุลของชื่อที่เหมือนโฟลเดอร์
  • โฟลเดอร์ชั่วคราวถูกแผงเป็นผู้เติม ไม่ใช่โมเดล
  • ขอบเขต: ความพยายามซ่อม 2 ครั้ง ประวัติไม่เกิน 40 เทิร์น และการจับระดับรวมเพื่อให้เอาต์พุตของโปรแกรมเป็น JSON ที่แยกวิเคราะห์ได้เสมอ

สิ่งที่ไม่มี:

  • ไม่มีเกณฑ์ confidence: การเลือกเส้นทางที่ 0.1 ถูกปฏิบัติเหมือนที่ 0.95
  • ไม่มีการตรวจว่าพาธมีอยู่จริง: พาธที่โมเดลมโนขึ้นผ่านการตรวจสอบและการยืนยัน (ผู้ปฏิบัติงานต้องสังเกตเองด้วยตา) และล้มเหลวเมื่อโมดูลเริ่มทำงานเท่านั้น
  • ข้อผิดพลาดของตัวตรวจสอบไม่เคยแสดง
  • ไม่มีการป้องกันโฟลเดอร์เอาต์พุต: หากโมเดลเลือกโฟลเดอร์ข้อมูลอินพุตเป็นเอาต์พุต ไม่มีอะไรห้าม
  • ไม่มี whitelist ของไฟล์ที่รันได้ แต่การป้องกันที่แท้จริงคือพาธสคริปต์มาจากmanifest ไม่ใช่จากโมเดล: โมเดลควบคุมค่า ไม่ใช่โปรแกรมที่ถูกเปิด
ในโค้ดรายการเต็ม รวมกรณีพาธ log และพารามิเตอร์นอกสเปก

11. สภาพแวดล้อม

แผงติดตั้งห้าแพ็กเกจลงใน Python ของ Slicer ตามลำดับที่สำคัญ: ไคลเอนต์ Python ของ Ollama ตัวอ่าน YAML สำหรับmanifest transformers ที่เก่ากว่า 4.53 (regression ทำให้ import cross-encoder พัง) numpy ที่เก่ากว่า 2 (numpy 2 ทำให้ torch wheel พัง) และสุดท้ายเพื่อไม่ให้ดันเวอร์ชันที่ปักไว้คือ sentence-transformers โปรแกรมบรรทัดคำสั่งรันในโปรเซสแยก แต่ใช้แพ็กเกจของ Slicer ร่วมกัน ไม่มีการสร้างสภาพแวดล้อม conda

เซิร์ฟเวอร์ Ollama ถูกตรวจที่พอร์ตในเครื่อง เปิดเมื่อจำเป็น และรอได้ถึงราว 30 วินาทีขณะที่อินเทอร์เฟซยังตอบสนอง มันถูกตรวจอีกครั้งก่อนทุกข้อความ เพราะเซิร์ฟเวอร์ที่โมดูลเปิดไม่รอดจากการรีสตาร์ต Slicer บน Windows ไม่แสดงหน้าต่างคอนโซล ไม่รองรับ WSL ต่างจากส่วนอื่นของที่เก็บโค้ด

ในโค้ดเวอร์ชันที่ปักพร้อมเหตุผล socket probe และการรอตอนเริ่ม

12. ข้อควรระวังและจุดเปราะบาง

  • หาสคริปต์ของโมดูลไม่พบ ซึ่งบล็อกทั้งเครื่องมือ หลักฐาน
  • ลายเซ็นผิด 14 จาก 16 และการเลื่อนนั้นเงียบ หลักฐาน
  • cross-encoder ถอยกลับแบบเงียบไปที่สามเครื่องมือแรก ถูกโหลดใหม่ทุกข้อความ และคง top 3 ที่กำหนดตายตัว หลักฐาน
  • Slicer ค้างตลอดช่วงงาน หลักฐาน
  • การแปลงพาธถูกปล่อยให้โมเดลทั้งหมด หลักฐาน
  • Ollama ที่ติดตั้งด้วย snap รันบน CPU หลักฐาน
  • สามชื่อสำหรับสองโหมด หลักฐาน
  • ยังมีโค้ดที่ไม่ได้ใช้: process() ที่ไม่ได้ใช้ ตัวสร้าง tool-spec ที่ไม่ได้ใช้ แคชของ cross-encoder ที่ไม่ได้ใช้ และไฟล์อินเทอร์เฟซที่โมดูลบรรทัดคำสั่งไม่เคยโหลด หลักฐาน
  • ประวัติผสมข้อความของอินเทอร์เฟซเข้ากับบริบทของการเลือกเส้นทาง และเมื่อโหลดการสนทนาที่บันทึกไว้ซ้ำ ประวัติจะถูกสร้างใหม่โดยแยกข้อความตามอีโมจิสองตัว ข้อความที่มีอีโมจิเหล่านั้นจึงทำให้มันเพี้ยน (แชตสดเก็บเทิร์นเป็นลิสต์)
ในโค้ดจุดเปราะบางสิบสองข้อพร้อมไฟล์และบรรทัด รวมการตรวจจับธีมและจำนวนค่าที่คืน

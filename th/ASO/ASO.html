3. หลักการเชิงเรขาคณิตที่ใช้ร่วมกัน

เป้าหมายไม่ใช่กรอบอ้างอิงเชิงวิเคราะห์ ("ระนาบบดเคี้ยว = z=0") แต่เป็นเคสของผู้ป่วย อ้างอิง ที่ดาวน์โหลดมาจากรีลีส: ภาพสแกน + fiducial สำหรับ CBCT และ เมชสองชิ้น + json สองไฟล์ สำหรับ IOS การเลือกกรอบอ้างอิงจึงถูกผลักไปอยู่ใน ตัวข้อมูลเอง: Occlusal and Midsagittal Plane หรือ Frankfurt Horizontal and Midsagittal Plane (CBCT.py:68) คือ gold สองชุดที่ต่างกัน โค้ดเดียวกันจึง ให้การจัดแนวสองแบบที่ต่างกัน

ในแบ็กเอนด์ทั้งสองตัว การประมาณค่าทำตามแบบแผนสองขั้นเหมือนกัน:

  1. การตั้งต้นจากจุด 3 จุด: การเลื่อนตำแหน่งหนึ่งครั้ง ตามด้วยการหมุนสองครั้ง รอบแกนที่ประกอบขึ้นด้วยมือ ไม่ใช่ Procrustes/Kabsch แบบกำลังสองน้อยสุดเลย;
  2. vtkIterativeClosestPointTransform ในโหมด RigidBody บนกลุ่มจุดยึด เพื่อปรับละเอียด

นี่คือประเด็นที่ต้องจำไว้: เมทริกซ์ไม่ใช่คำตอบที่เหมาะที่สุดในความหมาย ของกำลังสองน้อยสุดบนคู่ที่สัมพันธ์กัน N คู่ มันถูกประกอบขึ้นจากการหมุนต่อ ๆ กัน บนสามจุดที่เลือกมา แล้วขัดเกลาด้วย ICP ซึ่งตัวมันเองก็จับคู่จุดใหม่ ด้วยเพื่อนบ้านที่ใกล้ที่สุด ไม่ใช่ด้วย label

4.2 PRE_ASO_CBCT: จัดจุดศูนย์ใหม่ ไม่มีโครงข่ายแล้ว คำนวณ

แม้ชื่อและอาร์กิวเมนต์หกตัวจะบอกเป็นอย่างอื่น ปัจจุบัน CLI นี้ทำเพียงสิ่งเดียว (PRE_ASO_CBCT.py:92):

T = -np.array(img.TransformContinuousIndexToPhysicalPoint(np.array(img.GetSize()) / 2.0))
translation = sitk.TranslationTransform(3); translation.SetOffset(T.tolist())
img_trans = ResampleImage(img, translation.GetInverse())

ResampleImage คงขนาดไว้ (ratio = 1) คงระยะห่างระหว่างวอกเซลและทิศทาง แล้วตั้ง new_origin = orig_origin - orig_center เนื่องจากการแปลงที่ใช้ หักล้างค่าเลื่อนนี้พอดี จึงไม่มีการประมาณค่าระหว่างจุดเกิดขึ้นจริงเลย มีเพียงจุดกำเนิดทางกายภาพที่ขยับ และวอลุ่มลงเอยอยู่กึ่งกลางที่จุดกำเนิดของพิกัดโลก นี่เป็นเงื่อนไขที่ §4.4 ต้องมี เพราะที่นั่นการหมุนทำรอบจุดกำเนิด

อาร์กิวเมนต์ model_folder, SmallFOV และ temp_folder ถูกแยกค่าแล้ว ไม่ถูกใช้เลย PreASOResample (ResamplePreASO.py:196 การ resample แบบ isotropic 128³) ถูก import แต่ไม่เคยถูกเรียก และ DenseNet (Net.py:30 ซึ่งเป็น DenseNet169 แบบ 3 มิติของ monai ที่ถดถอยเวกเตอร์ทิศทางหนึ่งหน่วยด้วย cosine loss) ถูกคอมเมนต์ทิ้งใน __init__.py ปัจจุบันไม่มีโครงข่ายสำหรับจัดแนวล่วงหน้าใน ASO_CBCT เหลืออยู่เลย: โค้ดฝึกของมันยังอยู่ และน้ำหนัก PreASOModels.zip ก็ยังถูกดาวน์โหลดและตรวจสอบ (CBCT.py:126, TestModel ต้องมี .ckpt) ไปเปล่า ๆ

เอาต์พุต: วอลุ่มที่จัดจุดศูนย์ใหม่แล้วในชื่อเดิม และ <name without extension>.tfm ที่บรรจุการเลื่อนตำแหน่ง T ไว้ โดยไม่ผกผัน แม้ว่าตัวที่ถูกใช้กับวอลุ่มจริงคือ translation.GetInverse()

บั๊กที่ยืนยันแล้ว

convertdicom2nifti (utils.py:507) ลองใช้ sitk.ImageSeriesReader ก่อน แล้วถอยไปใช้ dicom2nifti ทางถอยนี้พัง: มันเรียก search(output_folder, "nii.gz") แต่ search (utils.py:189) ถูกประกาศเป็น def search(self, path, *args), อาร์กิวเมนต์ตัวแรกถูกดูดไปเป็น self ทำให้ args ว่าง dict ที่คืนมาว่างเปล่า และการเข้าถึง ["nii.gz"] จึงโยน KeyError

4.3 ALI_CBCT: ผู้จัดหา landmark ทำนาย

ถูกเรียกบนโฟลเดอร์ชั่วคราว ทั้งฝั่งอินพุตและเอาต์พุต ด้วยค่าคงที่ที่ฝังตายตัว (CBCT.py:515): spacing="[1,0.3]", speed_per_scale="[1,1]", agent_FOV="[64,64,64]", spawn_radius="10" และ lm_type ที่ถูกจัดรูปใหม่เป็นลิสต์ Python ด้วย format_lm_string (CBCT.py:482) ALI_CBCT เป็นระบบเอเจนต์ค้นหา สองสเกล (1 mm แล้ว 0.3 mm โดยมี FOV ขนาด 64³ วอกเซลรอบตัว เอเจนต์) มันเขียนjson หนึ่งไฟล์ต่อกลุ่มทางกายวิภาคหนึ่งกลุ่ม คือ <id>_lm_Pred_<group>.mrk.json (environment.py:138) ในระบบ LPS น้ำหนักเป็นไฟล์ <Landmark>_Net*.pth ที่ดาวน์โหลดทีละ landmark จาก ALI_CBCT/releases/download/models_v01/<LM>.zip

นี่คือเหตุผลทั้งหมดของ MergeJson (utils.py:65) ซึ่งเป็นการเรียกครั้งแรกของ SEMI_ASO_CBCT: มันปะ json รายกลุ่มกลับเข้าเป็นไฟล์เดียว <patient>_lm_MERGED.mrk.json , แล้วลบไฟล์ต้นทางทิ้ง (os.remove)

4.4 SEMI_ASO_CBCT: การจัดแนว คำนวณ

a) การตัด landmark ที่หลุดออกไป GetLandmarkToRemove (utils.py:341) เปรียบเทียบเมทริกซ์ระยะทางเต็ม และเมทริกซ์ทิศทาง ระหว่าง landmark ทั้งหมดของภาพสแกนกับของตัว gold ค่าคงที่จริงในโค้ด: ส่วนต่างระยะทาง > 15 mm, ส่วนต่างเชิงมุม > 0.4 rad (และนับ -1 หาก < 0.1 rad หมายความว่าคู่ที่สอดคล้องกันมากช่วยหักลบคู่ที่น่าสงสัย) landmark จะถูกตัดออกหากคะแนนรวมของมันเกินจำนวน landmark ทั้งหมด หรือหากคะแนน เชิงมุมเพียงอย่างเดียวเกินครึ่งของจำนวนนั้น การวิเคราะห์นี้ครอบคลุม landmark ทั้งหมดใน json ไม่ใช่เฉพาะตัวที่ติ๊กเลือกไว้

b) สามจุดที่ดีที่สุด FindOptimalLandmarks (utils.py:161) สุ่มหยิบสามจุด (A, B, C) รันการตั้งต้นให้แต่ละชุด แล้วเก็บชุดที่ให้ระยะทางเฉลี่ยสุดท้ายน้อยที่สุด ขอบเขต: สามจุดที่ต่างกัน n(n-1)(n-2) ชุด หรือ 2500 ครั้ง แล้วแต่ว่าอะไรมาถึงก่อน

c) การตั้งต้น InitICP (utils.py:652):

  1. การเลื่อนตำแหน่งที่นำ A_source ไปทับ A_target;
  2. การหมุนรอบแกน cross(v2, v1) ด้วยมุม arccos ของผลคูณจุด โดยที่ v1 = abs(B - A) ฝั่งต้นทาง และ v2 = abs(B - A) ฝั่งเป้าหมาย: เป็นค่าสัมบูรณ์รายองค์ประกอบ ซึ่งพับเวกเตอร์ทั้งสองเข้าสู่ออกแทนต์บวก และไม่ใช่มุมระหว่าง เวกเตอร์จริง;
  3. การหมุนครั้งที่สาม ซึ่งแกนคือ abs(B - A) ตัวมันเอง ไม่ใช่ผลคูณไขว้: เป็นการกลิ้งรอบแกนที่เพิ่งจัดให้ตรงไป โดยคำนวณมุมจาก C

RotationMatrix (utils.py:936) คือสูตร Rodrigues ในรูปควอเทอร์เนียน เหมือนกันทุกตัวอักษรกับที่อยู่ใน FlexReg และ ASO_IOS จุดสำคัญ: TransformMatrix = RotationTransformMatrix # @ TranslationTransformMatrix , การเลื่อนตำแหน่งจากขั้นที่ 1 ถูกตัดออกอย่างตั้งใจจากเมทริกซ์ที่คืนมา มันถูกใช้เพื่อคำนวณการหมุน ไม่ใช่เพื่อขยับวอลุ่ม

d) ตัว ICP ICP_Transform (utils.py:620) แปลง dict ทั้งสองเป็น vtkPolyData ของจุดยอด แล้วรัน vtkIterativeClosestPointTransform: SetModeToRigidBody(), SetMaximumNumberOfIterations(1000), StartByMatchingCentroidsOn() จากนั้นการเลื่อนตำแหน่งของมันถูกล้างเป็นศูนย์: TransformMatrixBis[:3, 3] = [0, 0, 0]

e) การประกอบ TransformList สะสม [translation, R2, R3, R_icp] ไว้ แล้ว (utils.py:816):

for i in range(len(TransformList) - 1, 0, -1):   # stops at 1: the translation is discarded
    TransformSITK.AddTransform(TransformList[i])
TransformSITKFinal = sitk.CompositeTransform(TransformSITK)
TransformSITKFinal.AddTransform(input_transform)   # the PRE_ASO .tfm
TransformSITKFinal = TransformSITKFinal.GetInverse()

4.5 การจัดแนว เขียนออกมาเป็นสมการ

ทุกอย่างข้างบนเป็นการบรรยายโค้ดเป็นร้อยแก้ว ต่อไปนี้คือสิ่งเดียวกันในรูปของ คณิตศาสตร์ เพราะมีตัวเลือกสองข้อของ ASO ที่มองเห็นได้เมื่อเขียนออกมาเท่านั้น สัญกรณ์: p→A คือ landmark A บนภาพสแกนที่กำลังถูกจัดแนว และ q→A คือ landmark เดียวกันบนตัว gold

การเลื่อนตำแหน่งนี้ขยับฝั่งต้นทาง เพื่อให้คำนวณการหมุนบนจุดที่ทับกันได้ แล้วมันก็ถูกทิ้ง: TransformMatrix = RotationTransformMatrix โดยการเลื่อนตำแหน่งถูกคอมเมนต์ออกจากผลคูณ วอลุ่มไม่เคยถูกเลื่อนตำแหน่งเลย, PRE_ASO_CBCT ได้จัดมันให้อยู่กึ่งกลางที่จุดกำเนิดไว้แล้ว

อ่านขีดคู่นั้นให้ดี มันคือค่าสัมบูรณ์รายองค์ประกอบ ไม่ใช่นอร์ม เวกเตอร์ทั้งสองถูกพับเข้าสู่ออกแทนต์บวกก่อนจะวัดมุม ดังนั้นสิ่งที่ตามมาคือมุมระหว่าง |u→| and |v→|, ซึ่งไม่ใช่มุมระหว่าง u→ กับ v→ คู่ landmark ที่ชี้ไปทางหนึ่ง กับคู่บนตัว gold ที่ชี้ไปทางตรงกันข้าม ให้เวกเตอร์เดียวกัน ที่นี่

θ1=arccos(v→2⋅v→1∥v→2∥∥v→1∥) , a→1=v→2×v→1

ในโค้ด เวกเตอร์ทั้งสองถูกหารด้วยองค์ประกอบที่ใหญ่ที่สุดของตัวเองก่อน (v1_u = v1 / np.amax(v1)) นั่นเป็นการสเกลด้วยค่าบวก จึงหักล้างกันเอง ทั้งในตัวหารและในผลคูณไขว้: มันไม่เปลี่ยนอะไรเลย

การหมุนครั้งที่สองคืออีกเรื่องที่เหนือความคาดหมาย แกนของมันไม่ใช่ผลคูณไขว้ แต่เป็น v→1 ตัวมันเอง: คือแกนที่ขั้นก่อนหน้าเพิ่งจัดให้ตรงไป มันเป็นการกลิ้งรอบ แกนนั้น และมุมของมันมาจาก landmark ตัวที่สาม การกลิ้งรอบแกนที่จัดตรงแล้ว ไม่สามารถทำลายการจัดตรงนั้นได้ นั่นคือเหตุผลที่ลำดับมีความสำคัญ

R=[α2+β2−γ2−δ22(βγ+αδ)2(βδ−αγ)2(βγ−αδ)α2+γ2−β2−δ22(γδ+αβ)2(βδ+αγ)2(γδ−αβ)α2+δ2−β2−γ2]

การกลับเครื่องหมายสองครั้งหักล้างกันที่นี่: ส่วนเวกเตอร์มีเครื่องหมายลบ และเมทริกซ์ถูกเขียนในรูปทรานสโพสเมื่อเทียบกับรูปควอเทอร์เนียนตามปกติ ผลลัพธ์จึงเป็นการหมุน Rodrigues ธรรมดาด้วยมุม θ รอบ a→̂ ฟังก์ชันตัวเดียวกันนี้ใช้ทั้งใน FlexReg และ ASO_IOS

ICP มีส่วนร่วมเพียงการหมุน: คอลัมน์การเลื่อนตำแหน่งของมันถูกล้างเป็นศูนย์ อย่างชัดเจน (TransformMatrixBis[:3, 3] = [0, 0, 0]) การแปลงที่ประกอบ ออกมาจึงเป็นการหมุนบริสุทธิ์รอบจุดกำเนิดของพิกัดโลก

9. Pitfalls and fragile points

Confirmed bug

โหมด semi-CBCT พังตามที่เป็นอยู่ SEMI_ASO_CBCT.py:207 ต้องการ data["tfm"] ที่คอมมิต 1bfb51f นำเข้ามาพร้อมกับเอาต์พุตเมทริกซ์ .tfm นี้มีอยู่เพราะ PRE_ASO_CBCT เขียนเท่านั้น แต่โหมด semi ไม่รัน PRE_ASO_CBCT และทำงานบนโฟลเดอร์ดิบของผู้ใช้ ผลลัพธ์: KeyError สำหรับผู้ป่วยที่โฟลเดอร์ไม่มี .tfm อยู่แล้ว ถูกจับและบันทึกเป็น "missing required files" โดยผู้ป่วยถูกนับเป็นความล้มเหลวแต่ไม่ขัดจังหวะคนอื่น โหมดนี้จึงใช้ได้ก็ต่อเมื่อบังเอิญมี .tfm อยู่ข้างภาพสแกน: โดยทั่วไปหลังจากผ่านโหมด Fully มาก่อน เพราะ PRE_ASO_CBCT.py:146 เขียนของตัวเองลงโฟลเดอร์ของภาพสแกน ตรวจสอบแล้ว: GetPatients (utils.py:934) เติมคีย์ tfm เฉพาะเมื่อมีไฟล์ .tfm อยู่ในต้นไม้อินพุต

และแม้ไม่มีปัญหานั้น โหมด semi ก็ไม่มีการจัดกึ่งกลางใหม่ เนื่องจากการจัดแนวเป็นการหมุนล้วนรอบจุดกำเนิดโลก วอลุ่มที่ไม่อยู่กึ่งกลางจะไปจบนอก FOV ของตัวเอง, DefaultPixelValue = 0

Confirmed bug

MergeJson ลบไฟล์ในโฟลเดอร์อินพุต ในโหมด semi input_dir คือโฟลเดอร์ของผู้ใช้: ไฟล์ .mrk.json ทั้งหมดที่ชื่อไม่มี MERGED ถูกรวมแล้วลบทิ้ง (utils.py:114)

Pitfall

ระบบพิกัดของ json ไม่เคยถูกตรวจ LoadJsonLandmarks อ่าน position ดิบ; ALI และ ASO เขียน LPS แต่ fiducial ที่ส่งออกเป็น RAS จาก Slicer จะถูกอ่านโดย x และ y กลับด้าน โดยไม่มีคำเตือน

Pitfall

จำนวน landmark ขั้นต่ำไม่สอดคล้องกัน UI ต้องการ landmark ที่ติ๊ก 3 จุด (TestCheckbox, CBCT.py:78) แต่ ICP ยอมแพ้ทันทีที่ len(list_landmark) <= 3 (utils.py:767) ดังนั้นจริง ๆ ต้องใช้ 4 จุด และมากกว่านั้นถ้าการตัดทอนลบบางจุดออก

  • ICP จับคู่ใหม่ด้วยเพื่อนบ้านที่ใกล้ที่สุด vtkIterativeClosestPointTransform ไม่สนใจ label: บน landmark ที่อยู่ใกล้กันเป็นคู่ (คู่ซ้าย/ขวา) มันอาจล็อกการจับคู่ไขว้ที่การเริ่มต้นทำผิดไปแล้ว
  • การเรียก abs() ใน InitICP เวกเตอร์ถูกพับเข้าสู่ octant บวกก่อนคำนวณมุม ในทั้งสองแบ็กเอนด์ เนื่องจากสามจุดที่เก็บไว้คือชุดที่ทำให้ค่าความคลาดเคลื่อนที่วัดได้น้อยที่สุด การค้นหาจึงชดเชยเรื่องนี้ แต่ไม่ควรสรุปอะไรจากเรขาคณิตของขั้นนี้เมื่อพิจารณาโดดเดี่ยว
Pitfall

ไม่มีการเขียนใหม่ถ้าไฟล์มีอยู่แล้ว เอาต์พุต CBCT ทั้งสามถูกป้องกันด้วย if not os.path.exists การรันครั้งที่สองหลังแก้พารามิเตอร์ไม่ให้ผลที่มองเห็น และยังจบด้วยความสำเร็จ

10. Literature

บทความอ้างอิงของ ASO_CBCT คือ Automated Orientation and Registration of Cone-Beam Computed Tomography Scans (Anchling, Hutin, Cevidanes et al., Lecture Notes in Computer Science, 2023) คำอธิบายของมันตรงกับโค้ด: ALI_CBCT ระบุ landmark ไม่ว่าทิศทางอินพุตเป็นอย่างไร แล้วการจัดแนวได้มา "by first aligning 3 randomly chosen landmarks, then refining with ICP" ความคลาดเคลื่อนที่รายงาน: < 3° และ < 2 mm เทียบกับผู้เชี่ยวชาญ บทความไม่กล่าวถึงตัวจัดแนวล่วงหน้า DenseNet สอดคล้องกับการที่มันไม่ได้เชื่อมต่ออีกแล้ว

สำหรับ ALI_CBCT เอง: Automatic landmark identification in cone-beam computed tomography (Gillot et al., Orthodontics & Craniofacial Research, 2023)

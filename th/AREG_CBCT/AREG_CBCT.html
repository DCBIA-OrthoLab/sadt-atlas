AREG_CBCT

การลงทะเบียนภาพ (registration) แบบแข็งเกร็ง (rigid) ของภาพ CBCT T1/T2 บนบริเวณกระดูกอ้างอิง (ฐานกะโหลกศีรษะ ขากรรไกรล่าง หรือขากรรไกรบน): ใช้ elastix ล้วน ๆ ด้วย mutual information ไม่มีโครงข่าย — ทุกสิ่งที่ผ่านการเรียนรู้อยู่ในขั้นก่อนหน้า คือในมาสก์และจุดสังเกตทางกายวิภาค (landmark)

Anchling 2023 · LNCS 14242 areg_cbct Python ของ Slicer — ไม่มี conda ใช้ CPU เท่านั้น บรรณานุกรม

1. ตำแหน่งใน pipeline

AREG/AREG.py เป็น widget เดียวที่ควบคุมสามรูปแบบข้อมูล: CBCT (AREG/AREG_Method/CBCT.py), IOS (AREG/AREG_Method/IOS.py) และ IOS บน CBCT (AREG/AREG_Method/IOSCBCT.py) ตัวมันไม่ได้คำนวณสิ่งใดเอง: Method.Process() แต่ละตัวคืนค่ารายการ dictionary ของขั้นตอน และ widget รันขั้นตอนเหล่านั้นทีละขั้น

ขั้นตอนหนึ่งมีรูปแบบดังนี้เสมอ:

{"Process": slicer.modules.areg_cbct,   # Slicer CLI module
 "Parameter": {...},                    # dict passed as-is to slicer.cli.run
 "Module": "AREG_CBCT for Mandible",    # label shown in the UI
 "ReviewId": "cbct_registration",       # optional review pause
 "ReviewFolder": ".../Mandible",
 "ReviewReferenceFolder": "<T1 folder>",
 "Display": DisplayAREGCBCT(nb_scan)}   # progress translation -> progress bar

การเรียกออกไปของโหมด CBCT ตามลำดับการทำงาน:

4. อินพุต การจับคู่ และการเตรียมข้อมูล

รูปแบบไฟล์ .nii.gz, .nii, .nrrd, .nrrd.gz, .gipl, .gipl.gz สำหรับ อินพุต DICOM convertdicom2nifti (utils.py:720) แปลงโฟลเดอร์ย่อยของผู้ป่วยแต่ละรายผ่าน sitk.ImageSeriesReader โดยสำรองด้วย dicom2nifti ไปเป็น <folder>/NIFTI/<patient>.nii.gz

การจับคู่ T1/T2 — GetPatients (utils.py:91) รหัสผู้ป่วย คือส่วนที่เหลือของชื่อไฟล์หลังการเรียก split() ต่อกันหลายครั้งด้วย รายการเครื่องหมายคงที่ (_Scan, _Or, _MAND, _CB, _lm, _T2, _T1, _Cl…) จากนั้น:

  • ไฟล์ภาพที่ชื่อมี mask, seg หรือ pred → ผลการแบ่งส่วน
  • มิฉะนั้น → scanT1 / scanT2
  • หากระบุ segmentationType รอบที่สองจะค้นใน mask_folder_t1 (หรือโฟลเดอร์ T1 โดยค่าเริ่มต้น) หาไฟล์ที่ชื่อมี cb, mand/md หรือ max/mx ตามบริเวณ และไฟล์แรกที่พบ จะถูกใช้ รอบนี้ไม่เคยตรวจว่าไฟล์เป็นมาสก์จริงหรือไม่: ภาพสแกน ชื่อ P1_T1_MAX.nii.gz จะถูกนำไปใช้เป็นผลการแบ่งส่วน
ข้อควรระวัง

การค้นหามาสก์ด้วยคำสำคัญ (cb, mand/md, max/mx) ไม่เคย ตรวจว่าไฟล์ที่พบเป็นผลการแบ่งส่วนจริง: ภาพสแกนชื่อ P1_T1_MAX.nii.gz จะถูกนำไปใช้เป็นผลการแบ่งส่วนโดยไม่มีการแจ้ง

T2 ถูกอ่านด้วย segmentationType=None: ใส่มาสก์เฉพาะภาพ fixed เท่านั้น ไม่เคยใส่ กับภาพ moving

การจัด T2 ให้อยู่กึ่งกลาง — pre_aso_cbct แม้ชื่อและ พารามิเตอร์ model_folder จะชี้ไปที่ Models/Orientation/PreASO แต่ CLI นี้ไม่ใช้ โครงข่ายใดเลย: คำนวณ T = -physical_center_of_the_image (PRE_ASO_CBCT.py:163) resample ด้วยอินเวิร์ส และเขียน TranslationTransform เป็น .tfm ไว้ข้างกัน การทำนาย ทิศทางด้วย DenseNet เคยมีอยู่ ถูกคอมเมนต์ไว้ แล้วถูกลบออก (คอมมิต 4296774) อาร์กิวเมนต์ model_folder และ SmallFOV ไม่ถูกใช้งาน แต่น้ำหนัก PreASO ยังถูกดาวน์โหลดอยู่

การใส่มาสก์ให้ภาพ fixed — MaskedImage (utils.py:584):

fixed_seg_sitk.SetOrigin(fixed_image_sitk.GetOrigin())   # origin forced
fixed_image_masked = applyMask(fixed_image_sitk, fixed_seg_sitk, label=SegLabel)
sitk.WriteImage(sitk.Cast(fixed_image_masked, sitk.sitkInt16),
                os.path.join(temp_folder, "fixed_image_masked.nii.gz"))

applyMask แปลงเป็นไบนารีหากขอ label มิฉะนั้นส่งมาสก์ตามที่เป็นให้ sitk.Mask (วอกเซลใดที่ไม่เป็นศูนย์จะถูกเก็บไว้) ไฟล์ชั่วคราว มีชื่อเดิมเสมอ: โฟลเดอร์ชั่วคราวมีเพียงโฟลเดอร์เดียวสำหรับทั้ง ชุด (CBCT.py:306) ผู้ป่วยแต่ละรายจึงเขียนทับ รายก่อนหน้า — ไม่เป็นอันตรายเมื่อทำตามลำดับ แต่ร้ายแรงหาก CLI ถูกทำให้ขนานกันในอนาคต

ข้อควรระวัง

โฟลเดอร์ชั่วคราวสำหรับการใส่มาสก์มีเพียงโฟลเดอร์เดียวสำหรับทั้งชุด และไฟล์ ชื่อ fixed_image_masked.nii.gz เสมอ: ผู้ป่วยแต่ละรายเขียนทับ รายก่อนหน้า — ไม่เป็นอันตรายเมื่อทำตามลำดับ แต่ร้ายแรงหาก CLI ถูกทำให้ขนานกันในอนาคต

SegLabel ในทางปฏิบัติเป็น None เสมอ: combo box LabelSelectcomboBox ถูกซ่อนตายตัว (AREG.py:548) และ SegmentationLabels คงเป็น [0] ซึ่ง CLI แปลกลับเป็น None ส่วน GetSegmentationLabel (CBCT.py:177) ซึ่งอ่าน label ที่มีอยู่ ในมาสก์ ไม่ถูกเรียกที่ใดเลย: โค้ดที่ไม่ถูกใช้งาน

5. แกนอัลกอริทึม — การลงทะเบียนภาพ

ทุกอย่างเกิดขึ้นใน VoxelBasedRegistration (utils.py:598):

  1. อ่าน T2 (moving) เป็น itk.F
  2. ใส่มาสก์ให้ T1 (fixed) (ข้างต้น) แล้วอ่านกลับเป็น itk.F
  3. เรียกเพียงครั้งเดียว ElastixReg(fixed_image_masked, moving_image, initial_transform=None)
  4. MatrixRetrieval → การแปลง SimpleITK
  5. ComputeFinalMatrix([t]) → Euler3DTransform
  6. resample T2

ไลบรารีคือ itk-elastix (itk.ElastixRegistrationMethod) ไม่ใช่ SimpleITK หรือ ANTs พารามิเตอร์ทั้งหมดระบุไว้ชัดเจนใน make_rigid_param_map_deterministic (utils.py:527) ซ้อนทับบนแผนที่ "rigid" ค่าเริ่มต้นของ elastix:

ไม่มีขั้นหยาบอีกแล้ว พารามิเตอร์ ApproxReg ที่อยู่เบื้องหลัง ช่องเลือก "Include Approximation Step" ถูกส่งต่อไปจนถึง VoxelBasedRegistration(approx=...) และไม่เคยถูกอ่านที่นั่น: ElastixApprox และ make_rigid_param_map_stochastic (sampler RandomCoordinate 10000 ตัวอย่าง AdaptiveStochasticGradientDescent 2 ระดับ บนภาพที่ไม่ใส่มาสก์) ถูกลบออกโดยคอมมิต 350a8de เมื่อ 2025-09-23 พร้อมกับการใช้ initial_transform ใน ElastixReg (utils.py:573) ซึ่งถูกเรียก ด้วย None ทุกที่ "จากหยาบไปละเอียด" ที่เหลืออยู่มีเพียงพีระมิด 3 ระดับ ส่วนการจัดแนวหยาบเบื้องต้นตอนนี้ทำโดยการจัด T2 กึ่งกลางของ PRE_ASO และ โดย AutomaticTransformInitialization

การดึงเมทริกซ์ — MatrixRetrieval (utils.py:830) อ่าน TransformParameters: มุม 3 ค่าแล้วตามด้วยการเลื่อน 3 ค่า จัดลำดับใหม่เป็น sitk.Euler3DTransform ส่วน ComputeFinalMatrix (utils.py:851) ประกอบรายการเข้าด้วยกัน (คูณการหมุน และบวกการเลื่อน) — เมื่อรายการมีสมาชิกตัวเดียว ก็เป็นเพียงการส่งผ่านตรง โค้ดการประกอบจึงไม่เคยถูก ใช้งานจริง และการบวกการเลื่อนจะถูกต้องก็ต่อเมื่อ การหมุนระหว่างทางเป็นเมทริกซ์เอกลักษณ์เท่านั้น

การ resample — ResampleImage (utils.py:472): การประมาณค่าในช่วง แบบ linear, DefaultPixelValue = 0 และ SetReferenceImage(image) โดย image คือ ภาพ moving เอง วอลุ่มที่ลงทะเบียนแล้วจึงคงกริดของ T2 (ขนาด spacing origin) ไม่ใช่ของ T1 เอาต์พุตแปลงเป็น int16

บั๊กที่ยืนยันแล้ว

จุดศูนย์กลางการหมุนของ elastix สูญหาย MatrixRetrieval อ่านเพียง TransformParameters และไม่เคยอ่าน CenterOfRotationPoint EulerTransform ของ elastix มีค่าเท่ากับ R·(x − c) + t + c ส่วน sitk.Euler3DTransform ที่สร้างใหม่มีจุดศูนย์กลางที่จุดกำเนิดและมีค่าเท่ากับ R·x + t ทั้งสอง ตรงกันก็ต่อเมื่อ c เป็นจุดกำเนิดหรือ R = I เนื่องจาก AutomaticTransformInitialization เปิดใช้งาน และจุดศูนย์กลางการหมุนได้มาจากภาพ fixed (T1 ซึ่งถูกจัดกึ่งกลางเฉพาะในโหมด Orientation) ความคลาด (I − R)·c จึงโดยทั่วไปไม่เป็นศูนย์ และความคลาดไม่ได้จำกัดอยู่ที่ .tfm: วอลุ่ม เอาต์พุตไม่ใช่ภาพผลลัพธ์ของ elastix เอง แต่ถูกสร้างใหม่ด้วย ResampleImage(sitk.ReadImage(moving_image_path), transform) (utils.py:686) จากเมทริกซ์ เดียวกันนั้น .tfm และวอลุ่มที่ลงทะเบียนแล้วจึงสอดคล้องกัน แต่ทั้งคู่คลาดไปจากสิ่งที่ elastix หาค่าเหมาะสมที่สุดได้จริง

CenterOfRotationPoint ไม่ปรากฏที่ใดเลยในรีโพสิทอรี (ตรวจสอบด้วย grep แล้ว) และ MatrixRetrieval ถูกคัดลอกซ้ำแบบเหมือนกันทุกประการใน MRI2CBCT_CLI/MRI2CBCT_CLI_utils/AREG_MRI.py:78: ความคลาดเดียวกันจึงเกิดกับการลงทะเบียนภาพ MRI↔CBCT ด้วย

  • โฟลเดอร์ <T2 folder>_Center ถูกสร้างข้างโฟลเดอร์อินพุต ของผู้ใช้ เช่นเดียวกับ <T1 folder>Or PRE_ASO ข้ามไฟล์ที่มี อยู่แล้ว: การรันครั้งที่สองด้วยอินพุตที่เปลี่ยนไปจะใช้ไฟล์เก่าซ้ำ
  • ในโหมด Fully-Auto AMASSS เขียนมาสก์ลงในโฟลเดอร์ T1 อินพุต เมื่อหยุดที่ cbct_registration เนื่องจาก ReviewReferenceFolder เป็นโฟลเดอร์เดียวกันนั้น มาสก์ทุกไฟล์ของผู้ป่วยจะถูกโหลดเข้าฉากพร้อมกับภาพสแกน
  • ไฟล์ fixed_image_masked.nii.gz ถูกเขียนใหม่สำหรับผู้ป่วยแต่ละรายใน โฟลเดอร์ชั่วคราวเดียวกัน
  • SwitchType (AREG.py:1030) แสดงตัวเลือก NIFTI/DCM อีกครั้งหลังจากที่ SwitchModeCBCT ซ่อนไว้: ผลสุทธิคือ อินพุต DICOM มีให้เลือกเฉพาะในโหมด Orientation ตรงข้ามกับสิ่งที่ SwitchModeCBCT ดูเหมือนตั้งใจ และในโหมดนั้น DCMInput ถูกส่งไปยัง ขั้น AREG ซึ่งโฟลเดอร์มีไฟล์ NIfTI อยู่แล้ว
  • startStep ถูกเรียกสองครั้งสำหรับขั้น CBCT แรก (AREG.py:1542 แล้ว AREG.py:1557): executed_steps จึงมีรายการซ้ำ ซึ่ง previousCorrectableStep รับมือได้ เพราะค้นหารายการที่พบครั้งสุดท้าย
  • .tfm ที่แก้ไขด้วยมือจะกลายเป็น CompositeTransform ไม่ใช่ Euler3DTransform: ผู้ใช้ไฟล์ในขั้นถัดไปที่สมมติว่าเป็นการแปลงแบบง่าย อาจอ่านกลับไม่ได้
  • โค้ดที่ไม่ถูกใช้งานที่พบ: TestReference (CBCT.py:61 ซึ่งจะเรียก NumberScan ด้วยอาร์กิวเมนต์เดียวและโยน TypeError), GetSegmentationLabel, getGPUUsage, GetMatrixPatients และ ModifiedDictPatients (ไม่มีผู้เรียกรายใดส่ง matrix_folder หรือ todo_str), ElastixReg(initial_transform=...) และ DisplayAREGIOSCBCT ที่ถูกนิยามสองครั้งใน Progress.py (บรรทัด 135)

12. เอกสารอ้างอิง

บทความอ้างอิงคือ Anchling, Hutin, Huang, Barone, Roberts, Miranda, Gurgel, Al Turkestani, Tinawi, Bianchi, Yatabe, Ruellas, Prieto, Cevidanes, "Automated Orientation and Registration of Cone-Beam Computed Tomography Scans," LNCS 14242, 2023, p. 43-58 — Springer, PMC11104011 ความแม่นยำที่รายงาน: < 3° และ < 2 mm เมื่อเทียบกับผู้เชี่ยวชาญ ใช้เวลาต่ำกว่า 5 นาทีต่อกรณี

โค้ดไม่ตรงกับบทความในสามประเด็นที่ตรวจสอบแล้ว:

  1. บทความอธิบายการลงทะเบียนภาพสองขั้น — "VBR between the full images, then with the masked image as a refinement step" โดยรอบที่ใส่มาสก์ใช้ 10,000 รอบการวนซ้ำ แต่โค้ดปัจจุบันรันเพียงรอบเดียวแบบใส่มาสก์ที่ 1500 รอบการวนซ้ำ
  2. บทความระบุ SimpleElastix แต่โค้ดใช้ itk-elastix (itk.ElastixRegistrationMethod)
  3. บทความได้มาสก์ผ่าน AMASSS / UNETR MONAI แต่ AMASSS ในปัจจุบันเป็น nnU-Net v2

สำหรับคำถามพื้นฐาน — การซ้อนภาพแบบอิงวอกเซลบนฐานกะโหลกศีรษะ — เอกสารอ้างอิงดั้งเดิมของห้องปฏิบัติการคือ Cevidanes et al., Superimposition of 3D cone-beam CT models of orthognathic surgery patients (2005, PubMed 16227481)

อย่าสับสนกับ Accuracy and Reproducibility of Voxel Based Superimposition…, PLOS One 2011 ซึ่งไม่ได้มาจากห้องปฏิบัติการนี้: เป็นงานของ Nada, Maal, Kuijpers-Jagtman et al. (Radboud UMC, Nijmegen) เป็นการตรวจสอบความถูกต้องของวิธีการโดยอิสระ ซึ่ง ทำให้มีน้ำหนักมากขึ้น ไม่ใช่น้อยลง — แต่การระบุว่าเป็นงานของกลุ่มนี้จะเป็น ความผิดพลาด

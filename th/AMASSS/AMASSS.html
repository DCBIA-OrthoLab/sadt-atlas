AMASSS

AMASSS แบ่งภาพสแกนศีรษะออกเป็นโครงสร้างทางกายวิภาค โดยใช้เครือข่ายหนึ่งตัวต่อหนึ่งโครงสร้าง และทำทีละ voxel หน้านี้อธิบายว่าการรันหนึ่งครั้งในโมดูล Slicer แบบ legacy ดำเนินไปอย่างไรทีละขั้น พร้อมคณิตศาสตร์ของส่วนที่เป็นการคำนวณ ไม่ใช่การเรียนรู้ ได้แก่ การทำให้สแกนเป็นมาตรฐาน การผสาน patch ของเครือข่าย การรวมมาสก์ และการสร้างพื้นผิว ที่ใดที่โค้ดทำสิ่งที่ควรตรวจสอบ จะมีลิงก์ไปยังหน้าโค้ด

โค้ด (สำหรับนักพัฒนา) Gillot 2022 · PLOS ONE AMASSS_CLI Python ของ Slicer ไม่ใช้ conda VISOR บรรณานุกรม

ภาพรวม: อะไรเข้า อะไรออก

AMASSS รับภาพสแกนศีรษะ 3 มิติ (CBCT) แล้วแบ่งออกเป็นโครงสร้างทางกายวิภาค ได้แก่ ขากรรไกรล่าง ขากรรไกรบน ฐานกะโหลก ทางเดินหายใจส่วนบน กระดูกสันหลังส่วนคอ ผิวหนัง และมาสก์สำหรับลงทะเบียนภาพสามชุด โดยใช้เครือข่ายหนึ่งตัวต่อหนึ่งโครงสร้าง แต่ละเครือข่ายตอบคำถามเดียวสำหรับทุก voxel คือ “voxel นี้เป็นส่วนของโครงสร้างของฉันหรือไม่” โมดูลนี้เป็นวิดเจ็ตของ Slicer ที่เริ่มโปรแกรมบรรทัดคำสั่งใน Python ของ Slicer เอง

เข้าเกิดอะไรขึ้นออก
สแกนหนึ่งชุด (.nii, .nii.gz, .nrrd...) หรือโฟลเดอร์ของสแกน และโครงสร้างที่ต้องการแปลงสแกนแต่ละชุด ทำนายแต่ละโครงสร้างด้วยเครือข่ายของมันเอง ทีละโครงสร้าง แล้วประกอบมาสก์มาสก์ไบนารีหนึ่งชุดต่อหนึ่งโครงสร้าง และ/หรือ label map ที่รวมแล้ว หนึ่งชุดต่อสแกน พร้อมพื้นผิว 3 มิติที่เลือกได้ (.vtk)

หน้านี้อธิบายโมดูล Slicer แบบ legacy (SlicerAutomatedDentalTools ที่ 3c67957, 2026-10-26) ส่วนการพอร์ตสู่เซิร์ฟเวอร์คือ AMASSS บน VISOR

1. ตำแหน่งในสายโซ่

AMASSS เป็นทั้งโมดูลของตัวเองและส่วนประกอบสำหรับโมดูลอื่น: AREG_CBCT ใช้มันสองครั้ง ครั้งแรกสำหรับมาสก์ลงทะเบียนภาพ (หนึ่งไฟล์ต่อโครงสร้าง) และครั้งหลังสำหรับการแบ่งส่วนที่เป็นผลลัพธ์ส่งมอบ VFACE ใช้มันในสายวิเคราะห์ความไม่สมมาตร และ MRI2CBCT ใช้มันหนึ่งครั้งสำหรับฐานกะโหลกของ CBCT ทั้งหมดรันโปรแกรมบรรทัดคำสั่งตัวเดียวกัน AMASSS ไม่เรียกโมดูลอื่นเลย นอกจาก nnU-Net (นำเข้าเมื่อจำเป็นเท่านั้น) แล้ว โปรแกรมยังนำเข้า torch, SimpleITK, VTK, cc3d, NumPy และไลบรารีตัวช่วย ADT ที่ใช้ร่วมกัน

ข้อแตกต่างสำคัญสำหรับ AREG: โครงสร้างมาสก์ทั้งสาม (CBMASK, MANDMASK, MAXMASK) ไม่ใช่การประมวลผลต่อจากฐานกะโหลก ขากรรไกรล่าง และขากรรไกรบน แต่เป็นโมเดลที่ฝึกแยกต่างหาก ที่ความละเอียดต่างกัน (0.3 mm แทนที่จะเป็น 0.4 mm) และขนาดชุดฝึกต่างกัน (50 เทียบกับ 76 ในคำอธิบายโมเดล)

ในโค้ดตารางผู้เรียกพร้อมไฟล์และบรรทัด

2. ไฟล์ที่เกี่ยวข้อง

สองส่วน: วิดเจ็ต Slicer ที่รวบรวมตัวเลือก และโปรแกรมบรรทัดคำสั่งที่ทำงานทั้งหมด (ค้นหาโมเดล อนุมาน ประกอบ) ทั้งสองรันใน Python ของ Slicer ไม่มี conda environment ไม่จำเป็นต้องมีการ์ดจอ แต่กับงานเป็นชุด CPU ใช้งานจริงไม่ได้ เพราะการ resample แบบแกนเดียวกินเวลาส่วนใหญ่ โปรแกรมรับอาร์กิวเมนต์สิบสองตัวตามตำแหน่ง

ในโค้ดตารางไฟล์และอาร์กิวเมนต์ตามตำแหน่งทั้งสิบสองตัวตามลำดับ

3. อินพุตและการประมวลผลก่อน

3.1 การค้นหาไฟล์

รับได้ทั้งไฟล์และโฟลเดอร์ โฟลเดอร์จะถูกไล่อ่านแบบเรียกซ้ำ เพราะ AREG เขียนสแกนที่ลงทะเบียนแล้วลงในโฟลเดอร์ย่อย ไฟล์ที่เก็บไว้คือไฟล์ที่มีนามสกุลของวอลุ่ม ชื่อสองแบบจะถูกข้าม: ชื่อใดที่มี MASK และ ถ้าอินพุตไม่ใช่การแบ่งส่วน ชื่อใดที่มี ID ของผลทำนายคั่นด้วยขีดล่าง (_Pred_ โดยค่าเริ่มต้น) ซึ่งเป็นผลลัพธ์ของการรันก่อนหน้า (การแบ่งส่วนซ้ำจะได้มาสก์ว่าง) ตัวกรองสองข้อนี้ใช้กับโฟลเดอร์ ไฟล์เดี่ยวที่ระบุโดยตรงจะไม่ถูกกรอง

3.2 การแปลง

สแกนแต่ละชุดถูกคัดลอกลงในโฟลเดอร์เดียวภายใต้ชื่อที่มีเลขลำดับ (p_001, p_002...) ตามลำดับที่พบ ไฟล์ .nii.gz คัดลอกตามเดิม ส่วนที่เหลือถูกอ่านใหม่และเขียนใหม่ เพราะ nnU-Net เลือกตัวอ่านจากนามสกุลไฟล์ ชนิดของ voxel ไม่ถูกแตะต้อง เพราะ nnU-Net แปลงเป็น float เอง

3.3 สิ่งที่ AMASSS ไม่ทำอีกต่อไป

ไม่มีการทำให้ความเข้มเป็นมาตรฐาน การทำ windowing หรือการ resample อยู่ในคลังโค้ดนี้: ฟังก์ชัน windowing เก่าเป็นเปลือกว่างที่ไม่มีใครเรียก การประมวลผลก่อนที่มีผลจริงทั้งหมดเป็นของ nnU-Net เอง ตามที่แผนของแต่ละโมเดลกำหนด: ครอปเหลือบริเวณที่ไม่เป็นศูนย์ ทำความเข้มให้เป็นมาตรฐาน แล้ว resample ไปยัง spacing เป้าหมาย

ในโค้ดตัวกรองการค้นหาไฟล์ ฟังก์ชันแปลง และฟังก์ชัน windowing ที่ไม่ถูกใช้

4. โมเดล

4.1 bundle และการค้นหา

สำหรับแต่ละโครงสร้างที่ร้องขอ โปรแกรมมองหาในโฟลเดอร์โมเดลว่ามีโฟลเดอร์โมเดลที่มี checkpoint ที่ฝึกแล้วของ fold เดียวหรือไม่ โครงสร้างที่ไม่มี checkpoint จะถูกประกาศว่าไม่พร้อมใช้งาน และการรันดำเนินต่อกับโครงสร้างอื่น ปุ่ม “Download latest models” ดึงไฟล์เก็บถาวร (ประมาณ 2 GB) หนึ่งครั้ง ไฟล์เดียวกันนี้คือไฟล์ที่ AREG และ VFACE ดาวน์โหลดโดยอัตโนมัติ

4.2 สิ่งที่ bundle บรรจุจริง

เก้าโฟลเดอร์ หนึ่งโฟลเดอร์ต่อโครงสร้าง แต่ละโฟลเดอร์มี fold ที่ฝึกแล้วเพียงหนึ่ง แบ่งเป็นสองตระกูล: โมเดลเต็มขอบเขต (ขากรรไกรล่าง ขากรรไกรบน ฐานกะโหลก กระดูกสันหลังส่วนคอ ทางเดินหายใจส่วนบน ผิวหนัง) ที่ 0.4 mm isotropic กับ patch ขนาด 128 voxel และมาสก์ลงทะเบียนภาพสามชุดที่ 0.3 mm กับ patch ที่ต่างออกไปและไม่เป็นลูกบาศก์ (112 × 160 × 128 voxel) ทั้งเก้าใช้สถาปัตยกรรมเดียวกัน: 3D U-Net แบบคอนโวลูชันล้วนที่กำหนดค่าโดย nnU-Net มีหกขั้นและไม่มี residual block

แต่ละโมเดลเป็นไบนารี: รู้จักเพียงพื้นหลังกับหนึ่งโครงสร้าง ค่าสุดท้ายของโครงสร้างในวอลุ่มที่รวมแล้วถูกกำหนดโดยโปรแกรม ไม่ใช่โดยโมเดล

ในโค้ดการค้นหาโมเดล ฟิลด์ของแผน และบล็อกสถาปัตยกรรม

4.3 โครงสร้างและป้ายกำกับ

ตารางเดียวให้ค่า label ที่ใช้ในผลลัพธ์ที่รวมแล้ว และสีของพื้นผิว

ป้ายกำกับรหัสโครงสร้างสี RGB
1MANDกระดูกขากรรไกรล่าง216, 101, 79
2CBฐานกะโหลก128, 174, 128
3UAWทางเดินหายใจส่วนบน0, 0, 0 (ดำ)
4MAXกระดูกขากรรไกรบน230, 220, 70
5CVกระดูกสันหลังส่วนคอ111, 184, 210
6SKINผิวหนัง172, 122, 101
7, 8, 9CBMASK, MANDMASK, MAXMASKมาสก์สำหรับ registrationขาว

มีสามรหัสที่ไม่มีโมเดลในชุด: root canal, teeth และ mandibular canal สองรายการหลังถูกปิดในแผง ส่วน root canal ไม่ถูกปิด และยังถูกติ๊กไว้เป็นค่าเริ่มต้นด้วย (ดูข้อควรระวัง)

4.4 Inference

โปรแกรมไม่ได้เขียนsliding windowของตัวเอง: nnU-Net จัดการจากขนาด patch ในแผนของแต่ละโมเดล พารามิเตอร์ที่โปรแกรมเลือกเองมีเพียง step 0.5 (step ไม่เกินครึ่ง patch จึงทำให้ patch ทับกันอย่างน้อยครึ่งหนึ่ง) การถ่วงน้ำหนักแบบเกาส์เซียนเปิด และ test-time mirroring ปิด

ลูปเป็นแบบต่อโครงสร้าง ไม่ใช่ต่อสแกน: ทุกสแกนผ่านโมเดลหนึ่งตัวก่อนจะโหลดโมเดลถัดไป ดังนั้น checkpoint ถูกโหลด S ครั้งแทนที่จะเป็น N × S ครั้ง เส้นทางโมเดลระบุอย่างชัดเจน เพราะตัวแปรสภาพแวดล้อมระดับโพรเซสจะทำให้สองการรันเขียนทับเส้นทางของกันและกัน โครงสร้างที่ล้มเหลวจะถูกบันทึกไว้และการรันดำเนินต่อ จะล้มเหลวก็ต่อเมื่อทุกโครงสร้างล้มเหลว

ในโค้ดตัวเลือกของ predictor เส้นทางโมเดลที่ระบุชัดเจน และการนับความคืบหน้า

5. แกนอัลกอริทึม (ไม่ได้เรียนรู้)

5.1 การสุ่มตัวอย่างใหม่บน GPU

ตามคอมเมนต์ในโค้ด การ resample แบบแกนเดียวใช้เวลาเป็นเจ็ดเท่าของเครือข่าย โปรแกรมจึงแทนที่ด้วยตัว resample ของ torch ที่รันบนการ์ดจอ ความต่างเชิงตัวเลขเป็นสิ่งที่ยอมรับโดยเจตนา: อินพุตเปลี่ยนจากการแทรกค่าอันดับสามเป็นอันดับหนึ่ง เพราะ torch ไม่มีการแทรกค่าลูกบาศก์ 3 มิติ ถ้าการ์ดหน่วยความจำไม่พอ โครงสร้างนั้นจะถูกรันซ้ำด้วย resampler ที่ช้ากว่า

ในโค้ดการแทนที่ resampler มาตรการป้องกัน และทางสำรองเมื่อหน่วยความจำไม่พอ

5.2 การประกอบและการเขียน

สำหรับแต่ละสแกน ผลทำนายของแต่ละโครงสร้างถูกอ่านกลับและแปลงเป็นมาสก์ไบนารี (ค่าใด ๆ ที่มากกว่าศูนย์) จากนั้นมาสก์ถูกเขียนแยกตามโครงสร้าง รวมกัน หรือทั้งสองอย่าง แผนที่ที่รวมแล้วต้องมีอย่างน้อยสองโครงสร้าง ลำดับคือลำดับความสำคัญ: โครงสร้างที่เขียนทีหลังสุดจะเขียนทับโครงสร้างก่อนหน้าบนvoxelที่ซ้อนกัน รายการนี้มีรหัสสองตัวที่ไม่ตรงกับอะไรเลย คือ CAN (ไม่มีในพจนานุกรมใด) และ RC (root canal: ไม่มีโมเดลและไม่มี label ในตาราง จึงจะถอยไปใช้ label ของขากรรไกรล่าง) ทั้งสองเป็นรายการที่ไม่ถูกใช้

มาสก์แต่ละชุดถูกแปลงเป็นจำนวนเต็ม 16 บิต และกำหนด spacing, direction และ origin ของสแกน เรขาคณิตของมันถูกตรวจสอบและ resample ด้วยเพื่อนบ้านใกล้สุดเฉพาะเมื่อต่างกัน ซึ่งไม่เกิดขึ้นในกรณีปกติ

ในโค้ดฟังก์ชันการประกอบ ลำดับการรวม และการตรวจเรขาคณิต

5.3 การประมวลผลหลัง: สิ่งที่ไม่มีอีกแล้ว

ไม่มีการเติมช่องว่าง ไม่มีการเลือกชิ้นส่วนที่เชื่อมต่อกัน และไม่มี morphology ฟังก์ชันสำหรับสิ่งเหล่านี้ยังเหลืออยู่สองตัวแต่ไม่มีใครเรียก เวอร์ชันก่อนหน้าทำความสะอาดทุกโครงสร้างยกเว้นสองโครงสร้าง และครอปผิวหนัง การพอร์ต nnU-Net ลบการเรียกเหล่านี้ออก การทำความสะอาดจึงพึ่งการประมวลผลหลังของ nnU-Net เอง ถ้าชุดที่แจกมีให้

5.4 การสร้างพื้นผิว VTK

สองโหมด: แบบรวม คือหนึ่งไฟล์ที่ต่อ label ทั้งหมดไว้ด้วยกัน และแบบแยก คือหนึ่งไฟล์ต่อโครงสร้าง แต่ละเซลล์ได้สีคงที่หนึ่งสีจากสีของโครงสร้าง เมชถูกเขียนในพิกัดของภาพเอง โดยไม่มีการพลิกระหว่าง LPS กับ RAS

ในโค้ดฟังก์ชันสร้างพื้นผิว การทำให้เรียบ และสองโหมด

6. การประมวลผลหลังและเอาต์พุต

ชื่อถูกสร้างจากชื่อสแกนและ ID ของผลทำนาย: หนึ่งไฟล์ต่อโครงสร้าง หนึ่งไฟล์ที่รวมแล้ว และไฟล์ .vtk หากร้องขอพื้นผิว ถ้าใช้ตัวเลือกโฟลเดอร์ต่อสแกน ทุกอย่างจะลงในโฟลเดอร์ผลลัพธ์ที่ตั้งชื่อตามสแกน มิฉะนั้นลงในโฟลเดอร์เอาต์พุตโดยตรง โฟลเดอร์ชั่วคราวถูกล้างทั้งตอนเริ่มและตอนจบของการรัน และสำเนาอินพุตถูกลบทันทีที่การอนุมานเสร็จ

ฝั่งวิดเจ็ต พื้นผิวถูกโหลดเข้าฉากเมื่อจบ แต่เฉพาะกรณีอินพุตเป็นไฟล์เดี่ยวที่บันทึกไว้ข้างไฟล์ต้นฉบับ และติ๊กช่องพื้นผิวไว้

ในโค้ดตารางผลลัพธ์ การจัดการโฟลเดอร์ชั่วคราว และการโหลดเข้าฉาก

7. อะไรคือสิ่งที่ทำนาย อะไรคือสิ่งที่คำนวณ

บล็อกลักษณะ
การประมวลผลก่อน (ครอป การทำให้เป็นมาตรฐาน การ resample)คำนวณ กำหนดแน่นอน ขับเคลื่อนด้วยแผนของแต่ละโมเดล
การแบ่งส่วนแต่ละโครงสร้างทำนาย 3D U-Net เครือข่ายไบนารีหนึ่งตัวต่อโครงสร้าง
Sliding window, การถ่วงน้ำหนัก, step 0.5คำนวณ กำหนดแน่นอน

8. สภาพแวดล้อม

ทุกอย่างรันใน Python ของ Slicer ไลบรารีถูกติดตั้งเมื่อกด Predict หลังการยืนยัน เวอร์ชันส่วนใหญ่ไม่ตรึง; NumPy ถูกตรึงที่ 1.26.4 เพราะ build ของ torch ที่ใช้ที่นี่สร้างกับ NumPy 1.x และ NumPy 2 ทำให้การนำเข้าพัง ไม่มี WSL ไม่มี conda: ต่างจากโมดูล IOS (FlexReg, AREG_IOS, ALI_IOS) AMASSS ไม่ใช้สภาพแวดล้อมภายนอก ตารางเวอร์ชันอยู่ในหน้าโค้ด

ในโค้ดไลบรารีที่ตรึงและไม่ตรึงพร้อมเหตุผลของแต่ละรายการ

9. ข้อควรระวังและจุดเปราะบาง

แต่ละข้อถูกตรวจในโค้ดและอธิบายพร้อมหลักฐานในหน้าโค้ด

  • ตัวเลือก small-field ไม่ทำอะไรเลย: การติ๊กมันเพียงเปลี่ยนรายการช่อง หลักฐาน
  • อินพุต DICOM ถูกเพิกเฉย: แผงเสนอให้ใช้ แต่โปรแกรมไม่มีการแปลง หลักฐาน
  • Root canal ถูกติ๊กไว้เป็นค่าเริ่มต้น ทั้งที่ไม่มีโมเดล หลักฐาน
  • โฟลเดอร์ชั่วคราวถูกใช้ร่วมกันและถูกล้าง ดังนั้นสองการรันพร้อมกันจะลบงานของกันและกัน หลักฐาน
  • ความเชื่อมโยงระหว่างเลขเคสกับไฟล์ถูกเก็บไว้ในหน่วยความจำเท่านั้น หากขัดข้องจะเหลือผลทำนายที่ไม่ระบุชื่อ หลักฐาน
  • รหัสโครงสร้างถูกอ่านใหม่จากชื่อไฟล์ ตอนสร้างพื้นผิวแยก ดังนั้นขีดล่างใน ID ของผลทำนายหรือในชื่อสแกนจะทำให้เกิดข้อผิดพลาด หลักฐาน
  • วิดเจ็ตกับโปรแกรมนับสแกนต่างกัน (นามสกุล ชื่อที่ถูกข้าม) หลักฐาน
  • การทำความสะอาดของวิดเจ็ตลบเส้นทางที่สัมพันธ์กับโฟลเดอร์ทำงานของ Slicer ซึ่งไม่เกี่ยวกับโฟลเดอร์ชั่วคราว หลักฐาน
  • โค้ดที่ไม่ถูกใช้: ฟังก์ชันและส่วนของวิดเจ็ตหลายอย่างไม่ทำอะไร หลักฐาน
  • บทความกับโค้ดไม่ตรงกัน: บทความอธิบาย MONAI UNETR ส่วนโค้ดรัน nnU-Net หลักฐาน
ในโค้ดข้อควรระวังทุกข้อพร้อมไฟล์และบรรทัด

10. วรรณกรรม

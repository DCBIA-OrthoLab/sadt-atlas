AMASSS

การแบ่งส่วน (segmentation) หลายโครงสร้างอัตโนมัติของภาพ CBCT ศีรษะและใบหน้า: โครงข่าย nnU-Net v2 แบบไบนารีหนึ่งตัวต่อโครงสร้างทางกายวิภาค ประกอบและรวมผลโดย CLI

Gillot 2022 · PLOS ONE AMASSS_CLI Python ของ Slicer ไม่มี conda บรรณานุกรม

1. ตำแหน่งใน pipeline

AMASSS เป็นทั้งโมดูลปลายทาง (widget ของ AMASSS) และองค์ประกอบ ที่เครื่องมืออื่นอีกสามตัวนำไปใช้ซ้ำ ซึ่งทั้งหมดเรียก CLI ตัวเดียวกันผ่าน slicer.modules.amasss_cli

ผู้เรียกไฟล์การใช้งาน
widget ของ AMASSSAMASSS.py:1638การแบ่งส่วนที่ผู้ใช้ควบคุม
AREG_CBCT (semi-auto, fully-auto, oriented)CBCT.py:341, 470, 555, 840, 918สองบทบาทที่แยกกัน: มาสก์สำหรับการลงทะเบียนภาพ (merge=SEPARATE, genVtk=False) ก่อน AREG และผลการแบ่งส่วนที่ส่งมอบหลังจากนั้น
VFACEcreatelistprocess.py:126การแบ่งส่วนภายในสายงานวิเคราะห์ความไม่สมมาตร

AMASSS ไม่เรียกสิ่งอื่นใด: ไม่มี subprocess ของ conda ไม่มีโมดูลอื่น dependency ภายนอกเพียงตัวเดียวคือแพ็กเกจ pip nnunetv2 ซึ่ง import แบบหน่วงเวลา (lazy) ในฟังก์ชันที่ใช้งาน

ข้อแตกต่างสำคัญสำหรับ AREG: รหัส CBMASK / MANDMASK / MAXMASK ไม่ใช่ขั้นการประมวลผลภายหลังที่ใช้กับผลการแบ่งส่วน CB / MAND / MAX — แต่เป็นโมเดลที่ฝึกแยกต่างหาก บนข้อมูลคนละชุดและที่ ความละเอียดต่างกัน (§4)

2. ไฟล์ที่เกี่ยวข้อง

ไฟล์บทบาทรันที่ใด
AMASSS/AMASSS.pywidget ของ Slicer 1654 บรรทัด ในจำนวนนี้ราว 450 บรรทัดเป็น stylesheet ธีมสว่าง/มืดPython ของ Slicer
AMASSS_CLI/AMASSS_CLI.pyตรรกะทั้งหมด: การค้นหาโมเดล การอนุมาน การประกอบเอาต์พุตPython ของ Slicer ผ่าน slicer.cli.run
AMASSS_CLI/AMASSS_CLI.xmlการประกาศพารามิเตอร์ตามตำแหน่ง 12 ตัว—

CLI ไม่ได้ถูกเรียกภายในสภาพแวดล้อม conda: slicer.cli.run เริ่มการทำงานใน Python ของ Slicer และตั้งแต่การพอร์ตในเดือนกันยายน 2026 (109e1ed) การอนุมานของ nnU-Net รันในโพรเซส เดียวกันนี้ ไม่ใช่ใน nnUNetv2_predict ที่เป็นโพรเซสลูกอีกต่อไป

ไม่จำเป็นต้องมี CUDA: ResolveDevice() (AMASSS_CLI.py:81) กลับไปใช้ CPU พร้อมบันทึกลง log ใน ทางปฏิบัติ CPU ใช้งานกับชุดข้อมูลไม่ได้ (resampling ของ scipy แบบคอร์เดียว กินเวลาส่วนใหญ่ ดู §5.1)

อาร์กิวเมนต์เป็นแบบตามตำแหน่งและอ่านด้วยดัชนีจาก sys.argv (AMASSS_CLI.py:922) โดยไม่ใช้ argparse แม้จะมี การ import ลำดับใน XML จึงเป็นตัวกำหนด: inputVolume (ไฟล์หรือโฟลเดอร์), modelDirectory, skullStructure (รหัสคั่นด้วยจุลภาค), merge (MERGE / SEPARATE / ทั้งสอง แยกด้วย [, ]+), genVtk, save_in_folder, output_folder, vtk_smooth, prediction_ID (ค่าเริ่มต้น Pred), temp_fold (ถูกลบตอนเริ่มทำงาน), SegmentInput, DCMInput (ไม่เคย ถูกใช้)

ข้อควรระวัง

widget ยังสร้าง param["highDefinition"] (AMASSS.py:935) ด้วย: พารามิเตอร์นี้ไม่มีอยู่ใน XML จึงถูกทิ้งไปโดยไม่แจ้ง ดู §9

3. อินพุตและการเตรียมข้อมูล

3.1 การค้นหาไฟล์

main() รับไฟล์หรือโฟลเดอร์ ซึ่งไล่ดูด้วย os.walk แบบเวียนเกิด (AMASSS_CLI.py:676) — จำเป็นเพราะ AREG เขียนภาพที่ลงทะเบียนแล้วไว้ที่ <output>/<Region>/<patient>_OutReg/ นามสกุล ที่รับ: .nii, .nii.gz, .nrrd, .nrrd.gz มีตัวกรองสองตัว: ชื่อใดที่ มี MASK จะถูกข้าม และหาก isSegmentInput เป็นเท็จ ชื่อใดที่มี _<prediction_ID>_ ก็จะถูกข้ามด้วย — เพราะเป็นเอาต์พุตของการรันครั้งก่อน และ การแบ่งส่วนซ้ำจะได้มาสก์ว่าง

ข้อควรระวัง

ฝั่ง widget นับไฟล์ด้วยรายการนามสกุลที่ต่างออกไป (รวม .gipl) และข้อยกเว้นที่ต่างกัน ["Seg","seg","Pred"] (AMASSS.py:682): ตัวนับ "Number of scans to process" กับสิ่งที่ CLI ประมวลผลจริงจึงอาจไม่ตรงกัน

3.2 การแปลงรูปแบบ

PrepareScanForNnunet() (AMASSS_CLI.py:557) คัดลอกภาพแต่ละภาพไปยังโฟลเดอร์เดียว <temp>/nnunet_input/ ภายใต้ชื่อ p_<NNN>_0000.nii.gz (NNN = ดัชนีสามหลัก ตามลำดับที่ค้นพบ) ไฟล์ .nii.gz คัดลอกตามที่เป็น ไฟล์อื่นทั้งหมดถูกอ่านและเขียนใหม่ด้วย SimpleITK นี่ไม่ใช่เรื่องผิวเผิน: เวอร์ชันก่อนหน้าทำ shutil.copy ไฟล์ NRRD ไปเป็นชื่อ .nii.gz และตัวอ่านของ nnU-Net เลือก รูปแบบจากนามสกุล — NRRD ซึ่งเป็นรูปแบบเริ่มต้นของ Slicer จึง ใช้งานไม่ได้ในทางปฏิบัติ ชนิดของวอกเซลไม่ถูกแก้ไข เพราะ nnU-Net แปลงเป็น float32 เอง

3.3 สิ่งที่ AMASSS ไม่ทำแล้ว

ไม่มีการปรับความเข้ม (normalization) ไม่มี windowing ไม่มี resampling ที่เขียนไว้ ในรีโพสิทอรีนี้ CorrectHisto() (AMASSS_CLI.py:271) ยังมีอยู่ แต่เนื้อฟังก์ชันถูกลบออก: อ่านภาพ แปลงเป็น float32 แล้วคืนค่า — ไม่มี percentile ไม่มีการตัดค่า ไม่มีการ เขียน แม้จะมี signature (min_porcent, max_porcent, i_min, i_max) และ ไม่ถูกเรียกที่ใดเลย: เป็นโค้ดที่ไม่ถูกใช้งาน

การเตรียมข้อมูลที่มีผลจริงทั้งหมดเป็นของ nnU-Net เอง ตามที่อธิบายไว้ใน plans.json ของแต่ละโมเดล (§4.2): resampling ไปยัง spacing เป้าหมาย แล้วตามด้วย CTNormalization (ตัดค่าที่ percentile 0.5% / 99.5% ของ ความเข้มส่วน foreground ในชุดฝึก แล้วจัดกึ่งกลาง-ปรับสเกลด้วยค่าเฉลี่ยและ ส่วนเบี่ยงเบนมาตรฐานของชุดเดียวกันนั้น) ค่าของแต่ละโมเดลอยู่ใน plans.json ของชุดโมเดล ไม่ได้อยู่ในรีโพสิทอรี

4. โมเดล

4.1 ชุดโมเดลและการค้นหา

FindModelFolder() (AMASSS_CLI.py:89) ค้นหา สำหรับรหัสโครงสร้างแต่ละตัว:

<modelDirectory>/<CODE>/**/<Dataset...>__nnUNetPlans__3d_fullres/fold_0/checkpoint_final.pth

ตัวเลือกจะถูกยอมรับเมื่อ checkpoint ของ fold_0 ได้รับการยืนยันว่า มีอยู่เท่านั้น มิฉะนั้นโครงสร้างนั้นถูกประกาศว่าใช้ไม่ได้ และการรันดำเนินต่อกับ โครงสร้างอื่น การค้นหาเกิดขึ้นครั้งเดียวสำหรับการรันทั้งหมด

การดาวน์โหลด: ปุ่ม Download latest models เพียงเปิด เบราว์เซอร์ (AMASSS.py:738) ไปที่ MODEL_LINK คือหน้า releases/tag/AMASSS_CBCT — ไม่มีการดาวน์โหลดอัตโนมัติฝั่ง AMASSS ไฟล์บีบอัดคือ AMASSS_Models.zip ซึ่ง AREG (CBCT.py:124, 617) และ VFACE (VFACE.py:959) ดาวน์โหลดอัตโนมัติ ส่วน ALI ยังดาวน์โหลด ผ่านรีโพสิทอรีส่วนตัว lucanchling/AMASSS_CBCT v1.0.2 (AMASSS_Models.zip + Masks_Models.zip, CBCT.py:107) README ยังชี้ไปที่ ALL_NEW_MODELS.zip และมีบรรทัดที่ถูกคอมเมนต์ชี้ไปที่ ALL_MODELS.zip: เป็นซากจาก ยุค monai ไฟล์บีบอัดเหล่านี้เก็บไฟล์ .pth ดิบ

4.2 สิ่งที่อยู่ในชุดโมเดลจริง

สำรวจจากชุดโมเดลที่แตกไฟล์แล้ว (AMASSS_Models.zip อยู่นอกรีโพสิทอรี): เก้า โฟลเดอร์ หนึ่งโฟลเดอร์ต่อรหัส แต่ละโฟลเดอร์มี Dataset001_myseg/nnUNetTrainer__nnUNetPlans__3d_fullres/ พร้อม dataset.json, plans.json และ fold_0/checkpoint_final.pth มีเพียง fold เดียว

แบ่งเป็นสองกลุ่ม แยกได้จาก plans.json: full-FOV (MAND, MAX, CB, CV, UAW, SKIN) ที่ 0.4 mm isotropic, patch 128³, numTraining = 76 และ มาสก์ (CBMASK, MANDMASK, MAXMASK) ที่ 0.3 mm isotropic, patch 112 × 160 × 128, numTraining = 50

สถาปัตยกรรม เหมือนกันทั้งสองกลุ่ม (ฟิลด์ architecture ของ plans.json):

dynamic_network_architectures.architectures.unet.PlainConvUNet
n_stages = 6            features_per_stage = [32, 64, 128, 256, 320, 320]
kernel_sizes = 6 x [3,3,3]          n_conv_per_stage = [2,2,2,2,2,2]
n_conv_per_stage_decoder = [2,2,2,2,2]
norm_op = InstanceNorm3d (eps 1e-5, affine)   conv_bias = True
โค้ดกับบทความไม่ตรงกัน

นี่ไม่ใช่ monai.networks.nets.UNet: ไม่มี channels, strides หรือ num_res_units ปรากฏที่ใดเลย PlainConvUNet คือ U-Net แบบคอนโวลูชัน ที่ nnU-Net กำหนดค่าเอง ไม่มีบล็อก residual ส่วน strides มาจาก plan ([1,1,1] แล้วตามด้วย [2,2,2] ห้าครั้งสำหรับ full-FOV ส่วน stage สุดท้ายเป็น [1,2,2] สำหรับมาสก์ เพราะ patch ไม่เป็น isotropic) batch_size = 2, use_mask_for_norm = [false] ทุกโมเดล บทความ PLOS ONE ปี 2022 อธิบายโมเดล UNETR MONAI ที่ครอป 128³ (encoder แบบ transformer + decoder แบบคอนโวลูชัน) ขณะที่โค้ดที่รันในปัจจุบันเป็น nnU-Net v2 PlainConvUNet ที่เป็นคอนโวลูชันล้วน ดู §10

แต่ละโมเดลเป็นแบบไบนารี ไฟล์ dataset.json ประกาศเพียง {background: 0, <one structure>: 1} — และสำหรับโมเดล full-FOV ทั้งหก ชื่อ label ถูกทิ้งไว้เป็น "Skin" จากการคัดลอกวาง แม้แต่สำหรับ MAND หรือ CB ชื่อนี้ไม่เคยถูกอ่าน: เอาต์พุตถูกแปลงเป็นไบนารีด้วย (arr > 0) (AMASSS_CLI.py:586) และ CLI เป็นผู้กำหนด ค่าสุดท้าย

4.4 การอนุมาน

ไม่มี sliding_window_inference เขียนไว้ที่นี่: nnU-Net จัดการ หน้าต่างเลื่อน (sliding window) เอง จาก patch_size ใน plan พารามิเตอร์เดียวที่ CLI เลือกคือขนาดก้าว

BuildPredictor() (AMASSS_CLI.py:114) ตั้ง tile_step_size = 0.5 (ซ้อนทับ 50% ฝังไว้ใน signature), use_gaussian = True (ถ่วงน้ำหนัก patch แบบ gaussian), use_mirroring = False (เทียบเท่า --disable_tta: ไม่มีการเสริมข้อมูลแบบ mirror ตอนทดสอบ), device จาก ResolveDevice() และ verbose / verbose_preprocessing / allow_tqdm ตั้งเป็น False ส่วน kwarg perform_everything_on_device (เปลี่ยนชื่อจาก perform_everything_on_gpu ระหว่างซีรีส์ 2.x) ถูกเลือกโดยการตรวจสอบ signature (introspection)

PredictFolder() (AMASSS_CLI.py:206) โหลด checkpoint (initialize_from_trained_model_folder(..., use_folds=(0,), checkpoint_name="checkpoint_final.pth")) แล้วเรียก predict_from_files_sequential กับทั้งโฟลเดอร์ มีการเลือกเชิงโครงสร้างสามข้อ ซึ่งมีคอมเมนต์อธิบายในโค้ดทั้งหมด:

  1. ระบุ path ของโมเดลโดยตรง ไม่ใช้ nnUNet_results เพราะ os.environ เป็นค่าระดับโพรเซส: การรัน AMASSS สองครั้งพร้อมกันจะเขียนทับ path ของโมเดลของกันและกัน
  2. ลูปต่อโครงสร้าง ไม่ใช่ต่อภาพ: ภาพทั้งหมดอยู่ในโฟลเดอร์อินพุต เดียว ทำนายทั้งโฟลเดอร์ครั้งเดียวต่อโครงสร้าง checkpoint ถูกโหลด S ครั้งแทนที่จะเป็น N × S
  3. เวอร์ชันแบบลำดับ: predict_from_files ใช้ spawn และภายใต้ Slicer worker จะ import โมดูลนี้ซ้ำและเสียค่าใช้จ่ายเต็มของการ import torch อีกครั้ง ทั้งยังต้องมี CUDA context ของตนเองสำหรับ resampling บน GPU

ความคืบหน้ายังนับเป็นขั้น scan × structure (AMASSS_CLI.py:815) เพื่อไม่ให้เปลี่ยน สเกลที่ widget คาดหวัง แม้งานจะถูกจัดกลุ่มตาม โครงสร้าง: แถบเลื่อนไปทีละขั้นขนาด scan_count

โครงสร้างที่ล้มเหลวจะถูกบันทึกใน failed_structures และการรัน ดำเนินต่อ การรันจะล้มเหลวก็ต่อเมื่อทุกโครงสร้างล้มเหลว

5.1 Resampling บน GPU

EnableGpuResampling() (AMASSS_CLI.py:150) เป็น การปรับประสิทธิภาพหลักของ CLI ตามคอมเมนต์ในโค้ด resampling ของ scipy แบบคอร์เดียวใช้เวลาราวเจ็ดเท่าของโครงข่าย

กลไก: nnU-Net หาฟังก์ชัน resampling จากชื่อ ผ่าน recursive_find_resampling_fn_by_name จาก dict ของการกำหนดค่า การเขียนชื่อทั้งสองใหม่จึงเปลี่ยนทิศทางได้ทั้งสองปลาย โดยไม่ต้อง monkeypatch:

configuration["resampling_fn_data"]          = "resample_torch_fornnunet"
configuration["resampling_fn_probabilities"] = "resample_torch_fornnunet"
configuration[f"{key}_kwargs"] = {"is_seg": False, "device": torch.device(device), "mode": "linear"}

มีการป้องกันสามชั้น: การแทนที่เกิดขึ้นเฉพาะเมื่อทั้งสองคีย์เป็น resample_data_or_seg_to_shape พอดี (plan ที่ขอสิ่งอื่นจะ ไม่ถูกแตะ) PlansManager ส่ง deepcopy ออกมา การแก้ dict จึงไม่กระทบทั้ง plan ที่ใช้ร่วมกันและการรันที่เกิดพร้อมกัน และคุณสมบัติทั้งสองเป็น @property @lru_cache จึงต้องมี getattr(manager_class, key).fget.cache_clear() มิฉะนั้นค่าที่อ่านก่อนการสลับจะยังคงอยู่ ความต่างเชิงตัวเลข ที่ยอมรับโดยเจตนา: ข้อมูลเปลี่ยนจากการประมาณค่าในช่วงอันดับ 3 เป็นอันดับ 1 (torch ไม่มี การประมาณค่าแบบ cubic ใน 3D) ส่วนความน่าจะเป็นใช้อันดับ 1 อยู่แล้ว

สำรองอัตโนมัติเมื่อเกิด torch.cuda.OutOfMemoryError → empty_cache() แล้ว รันโครงสร้างนั้นซ้ำด้วย resampler ของ scipy (AMASSS_CLI.py:244): เวอร์ชันคลาวด์มีอาร์กิวเมนต์ gpu_resampling โดยตรง ซึ่งทำไม่ได้ที่นี่เพราะรายการพารามิเตอร์ ถูกตรึงไว้โดย XML และผู้เรียก

5.2 การประกอบและการเขียนไฟล์

AssembleScanOutputs() (AMASSS_CLI.py:575) ต่อภาพ: อ่าน p_<NNN>.nii.gz จากแต่ละโฟลเดอร์ pred_<STRUCT> (หากไม่มี → คำเตือน ข้ามโครงสร้างนั้น) แปลงเป็นไบนารีด้วย (arr > 0) แล้ว

  • SEPARATE หากร้องขอ หรือหากมีเพียงโครงสร้างเดียว ("ผลรวม" ที่มีโครงสร้างเดียวก็คือโครงสร้างนั้นเอง)
  • MERGE หากร้องขอและมี ≥ 2 โครงสร้าง: np.where(mask == 1, label, merged) ตามลำดับของ merging_order = ["SKIN","CV","UAW","CB","MAX","MAND","CAN","RC","CBMASK","MANDMASK","MAXMASK"] นี่คือลำดับความสำคัญ: โครงสร้างที่เขียนหลังสุดจะเขียนทับ โครงสร้างก่อนหน้าบนวอกเซลที่ซ้อนกัน "CAN" ไม่มีอยู่ใน dictionary ใดเลย (รหัสของคลองคือ MCAN) เป็นรายการที่ไม่ถูกใช้ ส่วน .get(struct, 1) จะ ให้รหัสที่ไม่รู้จักตกไปเป็น label 1

SaveSeg() (AMASSS_CLI.py:524) แปลงเป็น int16 คัดลอก spacing, direction และ origin จากภาพอ้างอิงกลับมาโดยตรง แล้วผ่าน MatchReferenceGeometry() (AMASSS_CLI.py:502) ซึ่ง resample (nearest neighbor) เฉพาะเมื่อเรขาคณิตต่างกัน — ในกรณีปกติไม่ทำอะไร เวอร์ชัน ก่อนหน้าเขียนวอลุ่มชั่วคราวแล้วอ่านกลับเพื่อบังคับเรขาคณิต: เป็นการ gzip ไป-กลับสองรอบของ CBCT ทั้งภาพต่อโครงสร้าง โดยเปล่าประโยชน์

5.3 การประมวลผลภายหลัง: สิ่งที่ไม่มีแล้ว

ไม่มีการเติมรู ไม่มีการเลือกส่วนเชื่อมต่อ (connected component) ไม่มี morphology ใดถูกใช้ ยังเหลือสองฟังก์ชันที่ไม่ถูกเรียกที่ใดเลย:

  • CleanArray() (AMASSS_CLI.py:422) — การขยาย (dilation) แบบไบนารีรัศมี r, BinaryFillhole, การกร่อน (erosion) รัศมี r แล้ว cc3d.connected_components และเก็บส่วนที่ใหญ่ที่สุด
  • CropSkin() (AMASSS_CLI.py:489) — การเติม การกร่อนความหนา thickness ผลต่างของทั้งสองเพื่อเก็บเฉพาะ เปลือก แล้วเก็บส่วนที่ใหญ่ที่สุด

ในเวอร์ชัน monai มีการใช้ CleanArray(sep_arr, 2) กับทุก โครงสร้างยกเว้น CV และ RC และใช้ CropSkin(sep_arr, 5) กับผิวหนัง การพอร์ตไปยัง nnU-Net ได้ลบการเรียกเหล่านี้ออก: การทำความสะอาดขึ้นกับ การประมวลผลภายหลังภายในของ nnU-Net ทั้งหมด (postprocessing.pkl ของชุดโมเดล หาก มี) cc3d ยังถูก import สำหรับฟังก์ชันที่ไม่ถูกใช้สองตัวนี้ เช่นเดียวกับ Write() (AMASSS_CLI.py:287)

5.4 การสร้างพื้นผิว VTK

SavePredToVTK() (AMASSS_CLI.py:305) ถูกเรียก จาก SaveSeg เมื่อ genVtk เป็นจริง ต่อ label: เขียน NRRD ชั่วคราว <temp>/temp.nrrd ของมาสก์ไบนารี, vtkNrrdReader → vtkDiscreteMarchingCubes ด้วย GenerateValues(1, 1, 1) (เส้นชั้นเดียวที่ ค่า 1 — จึงต้องผ่านมาสก์ไบนารีแทน label map) → vtkSmoothPolyDataFilter จำนวน vtk_smooth รอบ (5 ทุกที่ใน รีโพสิทอรี) → vtkUnsignedCharArray "Colors" สีคงที่หนึ่งสีต่อเซลล์ จาก LABEL_COLORS

สองโหมด เลือกจากคำต่อท้าย _MERGED ในชื่อไฟล์: ในโหมดรวม จะวนลูปบน np.unique(arr) และต่อกันด้วย vtkAppendPolyData เป็น ไฟล์เดียว .vtk ในโหมดแยก struct = base.split('_')[-1] — รหัส โครงสร้างถูกดึงกลับจากชื่อไฟล์เพื่อหาสี

เมชถูกเขียนในระบบพิกัดของภาพ โดยไม่มีการพลิก LPS/RAS: เป็น vtkPolyData ที่ได้จากดัชนีของ NRRD โดยตรง

cleanup() ของ widget (AMASSS.py:1348) ทำ shutil.rmtree(os.path.join("..", "temp")): เป็น path สัมพัทธ์กับไดเรกทอรีทำงาน ปัจจุบันของ Slicer ไม่เกี่ยวกับ temp_fold และ exception ถูกกลืนหายไป

หมายเหตุ — โค้ดที่ไม่ถูกใช้งานที่ควรรู้

10. เอกสารอ้างอิง

AMASSS ตีพิมพ์เพียงครั้งเดียว:

Gillot M., Baquero B., Le C., Deleat-Besson R., Bianchi J., Ruellas A., …, Cevidanes L., Prieto J.C. Automatic multi-anatomical skull structure segmentation of cone-beam computed tomography scans using 3D UNETR. PLOS ONE 17(10):e0275033, 2022. doi:10.1371/journal.pone.0275033 — PMID 36223330, PMC9555672

โค้ดกับบทความไม่ตรงกัน

โค้ดแยกทางจากบทความโดยสิ้นเชิง บทความอธิบาย UNETR (encoder แบบ transformer + decoder แบบคอนโวลูชัน ไลบรารี MONAI): patch 128³, feature_size=16, hidden_size=768, mlp_dim=3072, attention head 12 หัว, dropout 5% ฝึกด้วย CBCT 618 ภาพจาก 7 ศูนย์ สำหรับห้าโครงสร้าง โดยใช้ resampling แบบ isotropic 0.4 mm และปรับคอนทราสต์ด้วยฮิสโทแกรมสะสม ที่ percentile 1% / 99% ค่า Dice ที่รายงาน: ผิวหนัง 0.971 ขากรรไกรล่าง 0.962 ขากรรไกรบน 0.853 ฐานกะโหลกศีรษะ 0.788 กระดูกสันหลังส่วนคอ 0.760

นี่คือสิ่งที่ CLI เวอร์ชันในอดีตทำ — Create_UNETR(...), sliding_window_inference(input_img, [128,128,128], nbr_GPU_worker, net, overlap=precision/100, sw_device=DEVICE, ...), CorrectHisto + ScaleIntensityd(0,1) + Spacingd(pixdim=[0.4,0.4,0.4]) หรือ [0.16,0.16,0.32] ในความละเอียดสูง แล้วตามด้วย CleanArray/CropSkin — อ่านได้ในรีโพสิทอรี จนถึงคอมมิต 61bbb15 "ENH: AMASSS with nnunet." spacing ความละเอียดสูง และ precision ของ UI เป็นพารามิเตอร์ของโค้ด ไม่ใช่ของ บทความ และมี Create_SwinUNETR(feature_size=48) อยู่ร่วมกันในนั้นโดยถูกคอมเมนต์ไว้

ไม่มีสิ่งใดเหลืออยู่ในโค้ดปัจจุบัน: nnU-Net v2, PlainConvUNet โครงข่าย ไบนารีหนึ่งตัวต่อโครงสร้าง spacing 0.4 mm ยังคงอยู่ แต่มาจาก plans.json ของน้ำหนัก ส่วนเส้นทางความละเอียดสูงและการประมวลผลภายหลังเชิงสัณฐานหายไปแล้ว ไม่มีสิ่งตีพิมพ์ใดอธิบาย AMASSS รุ่น nnU-Net: การอ้าง บทความ PLOS ONE เพื่ออธิบายโมดูลตามที่รันอยู่ในปัจจุบัน เท่ากับอธิบาย สถาปัตยกรรมที่ไม่ได้ถูกรันแล้ว

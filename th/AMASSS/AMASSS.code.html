AMASSS, legacy: โค้ด

สำหรับนักพัฒนา: โมดูล Slicer แบบ legacy ทำอะไรในโค้ด พร้อมการอ้างอิง file:line ซิกเนเจอร์ ตาราง และข้อควรระวัง คำอธิบายที่อ่านง่ายของไปป์ไลน์เดียวกัน พร้อมคณิตศาสตร์ อยู่ในหน้าแอตลาส การแบ่งส่วนหลายโครงสร้างอัตโนมัติของสแกน CBCT กะโหลกและใบหน้า: หนึ่งเครือข่าย nnU-Net v2 แบบไบนารีต่อหนึ่งโครงสร้างทางกายวิภาค ประกอบและรวมโดย CLI

โค้ด แอตลาส (คำอธิบาย) Gillot 2022 · PLOS ONE AMASSS_CLI Python ของ Slicer ไม่ใช้ conda VISOR บรรณานุกรม
โค้ดสองชุด

ทุกอย่างที่มีเลขกำกับด้านล่างอธิบายโมดูล Slicer แบบ legacy (SlicerAutomatedDentalTools ที่ 3c67957, 2026-10-26) พอร์ต VISOR ซึ่งรันเครื่องมือเดียวกันบนเซิร์ฟเวอร์ อธิบายในหน้าของตัวเอง AMASSS บน VISOR

3. อินพุตและการประมวลผลก่อน

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

3.1 การค้นหาไฟล์

main() รับไฟล์หรือโฟลเดอร์ โดยเดินด้วยos.walk แบบเวียนซ้ำ (AMASSS_CLI.py:766): จำเป็นเพราะ AREG เขียนสแกนที่ registration แล้วไปที่ <output>/<Region>/<patient>_OutReg/ นามสกุลที่เก็บ: .nii, .nii.gz, .nrrd, .nrrd.gz สองตัวกรอง: ชื่อใดที่มี MASK จะถูกข้าม และถ้า isSegmentInput เป็น false ชื่อใดที่มี _<prediction_ID>_ ก็ถูกข้ามด้วย เพราะเป็นเอาต์พุตของการรันก่อนหน้า และการแบ่งส่วนซ้ำจะได้มาสก์ว่าง

ข้อควรระวัง (เฉพาะ legacy)

ฝั่งวิดเจ็ตนับไฟล์ด้วยรายการนามสกุลต่างกัน (รวม .gipl) และข้อยกเว้นต่างกัน ["Seg","seg","Pred"] (AMASSS.py:637-641, AMASSS.py:1677): ตัวนับ "Number of scans to process" กับสิ่งที่ CLI ประมวลผลจริงอาจไม่ตรงกัน

Legacy (3c67957); ไม่มีใน VISOR: เซิร์ฟเวอร์มีฟังก์ชันค้นหาเดียว (SADT-VISOR sadt_amasss/pipeline.py:88-132) และแผง Slicer ไม่มีตัวนับเฉพาะของ AMASSS

3.2 การแปลง

PrepareScanForNnunet() (AMASSS_CLI.py:555) คัดลอกแต่ละสแกนเข้าโฟลเดอร์เดียว <temp>/nnunet_input/ ภายใต้ชื่อ p_<NNN>_0000.nii.gz (NNN = ดัชนีสามหลักตามลำดับการค้นพบ นับจาก 001: enumerate(..., start=1), AMASSS_CLI.py:685, 848; พอร์ต VISOR นับจาก 000) ไฟล์ .nii.gz ถูกคัดลอกตามเดิม ส่วนที่เหลือทั้งหมดถูกอ่านและเขียนใหม่โดย SimpleITK นี่ไม่ใช่เรื่องผิวเผิน: รุ่นก่อนหน้า shutil.copy ไฟล์ NRRD ไปเป็นชื่อ .nii.gz และตัวอ่านของ nnU-Net เลือกรูปแบบจากนามสกุล NRRD ซึ่งเป็นรูปแบบเริ่มต้นของ Slicer จึงเสียในทางปฏิบัติ ชนิดของ voxel ไม่ถูกแตะ เพราะ nnU-Net แปลงเป็น float32 เอง

3.3 สิ่งที่ AMASSS ไม่ทำอีกต่อไป

ไม่มีการทำ intensity normalization, windowing หรือ resampling เขียนอยู่ในที่เก็บโค้ดนี้ CorrectHisto() (AMASSS_CLI.py:269) ยังมีอยู่ แต่เนื้อในว่างแล้ว: มันอ่านภาพ แปลงเป็น float32 และคืนค่า ไม่มีเปอร์เซนไทล์ ไม่มีการตัด ไม่มีการเขียน ทั้งที่ซิกเนเจอร์เป็น (min_porcent, max_porcent, i_min, i_max) ไม่มีที่ใดเรียกมัน: โค้ดตาย

การประมวลผลก่อนที่มีผลจริงทั้งหมดเป็นของ nnU-Net เอง บรรยายโดย plans.json ของแต่ละโมเดล (§4.2) ตามลำดับนี้: ครอปไปยังบริเวณที่ไม่ใช่ศูนย์ CTNormalization (ตัดที่เปอร์เซนไทล์ 0.5% / 99.5% ของความเข้มส่วนหน้าของชุดฝึก แล้วจัดกึ่งกลางและปรับสเกลด้วยค่าเฉลี่ยและส่วนเบี่ยงเบนมาตรฐานของชุดเดียวกัน) แล้วสุ่มตัวอย่างใหม่ไปยังระยะห่างเป้าหมาย (nnU-Net เอง nnunetv2/preprocessing/preprocessors/default_preprocessor.py:65, 82, 88 ซึ่งคอมเมนต์ระบุว่าnormalisationต้องมาก่อน resampling; preprocessing/normalization/default_normalization_schemes.py:58-72; nnU-Net 2.8.1 อ่านใน venv ของเครื่องมือ VISOR: ไลบรารีไม่ได้อยู่ในที่เก็บโค้ดนี้) ค่าต่อโมเดลอยู่ใน plans.json ของbundle ไม่ได้อยู่ในที่เก็บโค้ด

4. โมเดล

คำอธิบายแบบภาษาง่ายและคณิตศาสตร์: หน้าแอตลาส

4.1 bundle และการค้นหา

FindModelFolder() (AMASSS_CLI.py:87) มองหา สำหรับรหัสโครงสร้างแต่ละตัว:

<modelDirectory>/<CODE>/**/<Dataset...>__nnUNetPlans__3d_fullres/fold_0/checkpoint_final.pth

ผู้สมัครจะถูกยอมรับก็ต่อเมื่อ checkpoint fold_0 ยืนยันว่ามีอยู่ มิฉะนั้นโครงสร้างนั้นถูกประกาศว่าใช้ไม่ได้และการรันดำเนินต่อกับโครงสร้างอื่น การค้นหาเกิดขึ้นครั้งเดียวต่อการรันทั้งหมด

ดาวน์โหลด: ปุ่ม Download latest models ดาวน์โหลด MODEL_LINK ซึ่งเป็นไฟล์บีบอัด AMASSS_Models.zip (ราว 2 GB) หนึ่งครั้ง ไปที่ <Documents>/<Slicer>Downloads/AMASSS/Models และเติมโฟลเดอร์โมเดล (AMASSS.py:240-243, 681-695) คอมเมนต์ในโค้ดบันทึกว่าลิงก์รุ่นก่อนชี้ไปที่หน้าเว็บของรีลีสและเปิดได้แค่แท็บเบราว์เซอร์ ไฟล์บีบอัดเดียวกันนี้คือที่ AREG (AREG_Method/CBCT.py:120, 619), VFACE (VFACE.py:988) และ MRI2CBCT (MRI2CBCT_core/requirements.py:33) ดาวน์โหลดโดยอัตโนมัติ ALIยังผ่านที่เก็บโค้ดส่วนตัว lucanchling/AMASSS_CBCT v1.0.2 (AMASSS_Models.zip + Masks_Models.zip, ALI_Method/CBCT.py:93-94, URL คือ AMASSS_CBCT_UPSTREAM, ADT/ADTLib/model_registry.py:77) README ยังชี้ไปที่ ALL_NEW_MODELS.zip และบรรทัดที่ถูกคอมเมนต์ไว้ชี้ไปที่ ALL_MODELS.zip: ซากจากยุค monai ไฟล์บีบอัดเหล่านี้เก็บไฟล์ .pth ดิบ

4.2 สิ่งที่ bundle บรรจุจริง

สำรวจบนbundleที่คลายบีบอัดแล้ว (AMASSS_Models.zip, อยู่นอกที่เก็บโค้ด): เก้าโฟลเดอร์ หนึ่งโฟลเดอร์ต่อรหัส แต่ละโฟลเดอร์มี Dataset001_myseg/nnUNetTrainer__nnUNetPlans__3d_fullres/ ที่ประกอบด้วย dataset.json, plans.json และ fold_0/checkpoint_final.pth หนึ่ง fold เท่านั้น

สองตระกูล แยกด้วย plans.json ของมัน: full-FOV (MAND, MAX, CB, CV, UAW, SKIN) ที่ 0.4 mm isotropic, patch 128³, numTraining = 76 และมาสก์ (CBMASK, MANDMASK, MAXMASK) ที่ 0.3 mm isotropic, patch 112 × 160 × 128, numTraining = 50

สถาปัตยกรรม เหมือนกันทั้งสองตระกูล (ฟิลด์ architecture ของ plans.json):

dynamic_network_architectures.architectures.unet.PlainConvUNet
n_stages = 6            features_per_stage = [32, 64, 128, 256, 320, 320]
kernel_sizes = 6 x [3,3,3]          n_conv_per_stage = [2,2,2,2,2,2]
n_conv_per_stage_decoder = [2,2,2,2,2]
norm_op = InstanceNorm3d (eps 1e-5, affine)   conv_bias = True
โค้ดต่างจากบทความ (เป็นจริงใน VISOR ด้วย)

เป็นจริงใน VISOR ด้วย: พอร์ตโหลด checkpoint ของ nnU-Net v2 (checkpoint_final.pth, fold 0, *__nnUNetPlans__3d_fullres: SADT-VISOR sadt_amasss/nnunet_runner.py:33-34, 208-212) และการพึ่งพาของมันไม่มี MONAI (tools/AMASSS/pyproject.toml:11-23)

นี่ไม่ใช่ monai.networks.nets.UNet: ไม่มี channels, strides หรือ num_res_units ปรากฏที่ใดเลย PlainConvUNet คือ U-Net แบบคอนโวลูชันที่ nnU-Net กำหนดค่าเอง โดยไม่มีบล็อก residual strides มาจาก plan ([1,1,1] แล้วห้าครั้งของ [2,2,2] สำหรับ full-FOV, ขั้นสุดท้าย [1,2,2] สำหรับมาสก์ เพราะ patch ไม่เป็น isotropic) batch_size = 2, use_mask_for_norm = [false] ทุกที่ บทความ PLOS ONE ปี 2022 บรรยายโมเดล UNETR MONAI ที่ครอป 128³ (ตัวเข้ารหัส transformer + ตัวถอดรหัสคอนโวลูชัน) โค้ดที่รันทุกวันนี้เป็น nnU-Net v2 PlainConvUNet แบบคอนโวลูชันล้วน ดู §10

ทุกโมเดลเป็นแบบไบนารี ไฟล์ dataset.json ประกาศเพียง {background: 0, <one structure>: 1} และสำหรับหกโมเดล full-FOV ชื่อป้ายกำกับถูกทิ้งไว้เป็น "Skin" จากการคัดลอกวาง แม้สำหรับ MAND หรือ CB ชื่อนี้ไม่เคยถูกอ่าน: เอาต์พุตถูก binarize ด้วย (arr > 0) (AMASSS_CLI.py:584) และ CLI เป็นผู้กำหนดค่าสุดท้าย

4.4 Inference

ไม่มี sliding_window_inference เขียนไว้ที่นี่: nnU-Net จัดการsliding windowเอง จาก patch_size ของ plan พารามิเตอร์เดียวที่ CLI เลือกคือขนาดก้าว

BuildPredictor() (AMASSS_CLI.py:112) ตั้ง tile_step_size = 0.5 (ก้าวไม่เกินครึ่ง patch จึงซ้อนทับอย่างน้อย 50%: nnU-Net ทำให้สั้นลงเพื่อให้ patch สุดท้ายสิ้นสุดที่ขอบภาพ nnunetv2/inference/sliding_window_prediction.py:30-54; กำหนดตายตัวในซิกเนเจอร์), use_gaussian = True (ถ่วงน้ำหนัก patch แบบเกาส์เซียน กระจายหนึ่งในแปดของ patch logits ที่ถ่วงน้ำหนักแล้วหารด้วยผลรวมของน้ำหนัก: nnunetv2/inference/predict_from_raw_data.py:626-653), use_mirroring = False (เทียบเท่า --disable_tta: ไม่มี mirror augmentation ตอนทดสอบ), device จาก ResolveDevice() และ verbose / verbose_preprocessing / allow_tqdm ตั้งเป็น False kwarg perform_everything_on_device (เปลี่ยนชื่อจาก perform_everything_on_gpu กลางซีรีส์ 2.x) ถูกเลือกโดยการตรวจสอบซิกเนเจอร์

PredictFolder() (AMASSS_CLI.py:204) โหลด checkpoint (initialize_from_trained_model_folder(..., use_folds=(0,), checkpoint_name="checkpoint_final.pth")) แล้วเรียกpredict_from_files_sequential บนทั้งโฟลเดอร์ สามทางเลือกเชิงโครงสร้าง ทั้งหมดมีคอมเมนต์ในโค้ด:

  1. เส้นทางโมเดลที่ระบุชัด ไม่ใช้ nnUNet_results os.environ เป็น global ต่อโปรเซส: การรัน AMASSS พร้อมกันสองครั้งจะเขียนทับเส้นทางโมเดลของกันและกัน
  2. วนต่อโครงสร้าง ไม่ใช่ต่อสแกน: สแกนทั้งหมดในโฟลเดอร์อินพุตเดียว การทำนายระดับโฟลเดอร์หนึ่งครั้งต่อโครงสร้าง checkpoint ถูกโหลด S ครั้งแทนที่จะเป็น N × S
  3. เวอร์ชันแบบลำดับ: predict_from_files ใช้ spawn และภายใต้ Slicer worker จะ import โมดูลนี้ใหม่และจ่ายต้นทุนเต็มของการ import torch อีกครั้ง มันยังต้องมี CUDA context ของตัวเองสำหรับการสุ่มตัวอย่างใหม่บน GPU

ความคืบหน้ายังคงนับเป็นขั้น scan × structure (AMASSS_CLI.py:674-677) เพื่อไม่ให้เปลี่ยนสเกลที่วิดเจ็ตคาดหวัง แม้งานจะถูกจัดกลุ่มตามโครงสร้าง: แถบเดินหน้าเป็นขั้นขนาด scan_count

โครงสร้างที่ล้มเหลวถูกบันทึกใน failed_structures และการรันดำเนินต่อ การรันล้มเหลวก็ต่อเมื่อทั้งหมดล้มเหลว

5.1 การสุ่มตัวอย่างใหม่บน GPU

EnableGpuResampling() (AMASSS_CLI.py:148) เป็นการปรับแต่งหลักของ CLI ตามคอมเมนต์ในโค้ด การสุ่มตัวอย่างใหม่ด้วย scipy แบบแกนเดียวมีต้นทุนราวเจ็ดเท่าของเครือข่าย

กลไก: nnU-Net หาฟังก์ชันสุ่มตัวอย่างใหม่ตามชื่อ ผ่าน recursive_find_resampling_fn_by_name จาก dict การกำหนดค่า การเขียนสองชื่อใหม่เปลี่ยนเส้นทางทั้งสองปลาย โดยไม่ต้อง monkeypatch:

configuration["resampling_fn_data"]          = "resample_torch_fornnunet"
configuration["resampling_fn_probabilities"] = "resample_torch_fornnunet"
configuration[f"{key}_kwargs"] = {"is_seg": False, "device": torch.device(device), "mode": "linear"}

มาตรการป้องกันสามข้อ: การแทนที่เกิดขึ้นเฉพาะเมื่อทั้งสองคีย์เป็น resample_data_or_seg_to_shape พอดี (plan ที่ขออย่างอื่นจะไม่ถูกแตะ); PlansManager ส่ง deepcopy ออกมา ดังนั้นการแก้ dict ไม่กระทบ plan ที่ใช้ร่วมกันหรือการรันที่เกิดพร้อมกัน; ทั้งสอง property เป็น @property @lru_cache จึงต้องมี getattr(manager_class, key).fget.cache_clear() ซึ่งถ้าไม่มี ค่าที่อ่านก่อนการสลับจะอยู่รอด ความต่างเชิงตัวเลขที่ยอมรับโดยตั้งใจ: ข้อมูลเปลี่ยนจากการประมาณค่าอันดับ 3 เป็นอันดับ 1 (torch ไม่มีการประมาณค่าลูกบาศก์ 3D); ความน่าจะเป็นเป็นอันดับ 1 อยู่แล้ว

การถอยอัตโนมัติเมื่อเกิด torch.cuda.OutOfMemoryError → empty_cache() แล้วเล่นโครงสร้างนั้นซ้ำด้วยตัวสุ่มตัวอย่างใหม่ของ scipy (AMASSS_CLI.py:240-251): เวอร์ชันคลาวด์มีอาร์กิวเมนต์ gpu_resampling ที่ชัดเจน ซึ่งเป็นไปไม่ได้ที่นี่เพราะรายการพารามิเตอร์ถูกตรึงโดย XML และผู้เรียก

5.2 การประกอบและการเขียน

AssembleScanOutputs() (AMASSS_CLI.py:573) ต่อสแกน: อ่าน p_<NNN>.nii.gz จากแต่ละโฟลเดอร์ pred_<STRUCT> (ขาด → คำเตือน ข้ามโครงสร้าง) binarize ด้วย (arr > 0) แล้ว

  • SEPARATE ถ้าร้องขอ หรือ ถ้ามีโครงสร้างเดียว ("merged" ที่ประกอบด้วยโครงสร้างเดียวก็คือโครงสร้างนั้น)
  • MERGE ถ้าร้องขอและมีโครงสร้าง ≥ 2: np.where(mask == 1, label, merged) ตามลำดับของ merging_order = ["SKIN","CV","UAW","CB","MAX","MAND","CAN","RC","CBMASK","MANDMASK","MAXMASK"] นี่คือลำดับความสำคัญ: โครงสร้างที่เขียนทีหลังสุดเขียนทับตัวก่อนหน้าบน voxel ที่ใช้ร่วมกัน "CAN" ไม่มีในพจนานุกรมใดเลย (รหัสคลองคือ MCAN) เป็นรายการตาย "RC" เป็นรหัสที่รู้จักแต่ไม่มีโมเดลและไม่มีรายการใน LABELS["LARGE"]: .get(struct, 1) (AMASSS_CLI.py:612) จะถอยรหัสที่ไม่มีป้ายกำกับไปที่ป้ายกำกับ 1 ซึ่งเป็นของกระดูกขากรรไกรล่าง ทั้งสองจับคู่กับการทำนายไม่ได้ในทางปฏิบัติ เพราะไม่มีโมเดล

SaveSeg() (AMASSS_CLI.py:522) แปลงเป็น int16 คัดลอกกลับอย่างชัดเจนซึ่ง spacing, direction และ origin จากสแกนอ้างอิง แล้วผ่าน MatchReferenceGeometry() (AMASSS_CLI.py:500) ซึ่งสุ่มตัวอย่างใหม่ (nearest neighbor) เฉพาะเมื่อเรขาคณิตต่างกัน: ไม่ทำอะไรในกรณีปกติ รุ่นก่อนหน้าเขียนวอลุ่มชั่วคราวแล้วอ่านกลับเพื่อบังคับเรขาคณิต: gzip ไปกลับสองรอบของ CBCT เต็มต่อโครงสร้าง โดยไม่ได้อะไร

5.3 การประมวลผลหลัง: สิ่งที่ไม่มีอีกต่อไป

ไม่มีการเติมรู ไม่มีการเลือก connected component ไม่มี morphology เหลือสองฟังก์ชัน ไม่มีที่ใดเรียก:

  • CleanArray() (AMASSS_CLI.py:420): binary dilation รัศมี r, BinaryFillhole, erosion รัศมี r แล้ว cc3d.connected_components และเก็บส่วนประกอบที่ใหญ่ที่สุด
  • CropSkin() (AMASSS_CLI.py:487): เติม erosion ความหนา thickness ผลต่างของสองอย่างเพื่อเก็บเฉพาะเปลือก แล้วส่วนประกอบที่ใหญ่ที่สุด

ในเวอร์ชัน monai CleanArray(sep_arr, 2) ถูกใช้กับทุกโครงสร้างยกเว้น CV และ RC และ CropSkin(sep_arr, 5) กับผิวหนัง พอร์ต nnU-Net ถอดการเรียกเหล่านี้ออก: การทำความสะอาดพึ่งพาการประมวลผลหลังภายในของ nnU-Net ทั้งหมดแล้ว (postprocessing.pkl ของbundle ถ้ามี) cc3d ยังถูก import เพื่อสองฟังก์ชันตายนี้ และ Write() ก็เช่นกัน (AMASSS_CLI.py:285)

8. สภาพแวดล้อม

ทุกอย่างรันใน Python ของ Slicer การติดตั้งถูกกระตุ้นโดยปุ่ม Predict (AMASSS.py:869-890) ไม่ใช่ตอนเปิดโมดูล และผ่านกล่องโต้ตอบยืนยัน

แพ็กเกจเวอร์ชันที่ตรึงเหตุผลที่อ่านได้ในโค้ด
torch, torchvision, torchaudioไม่ตรึงbuild ของ CUDA อ่านจาก GPU โดย torch_install_arguments() (ADTLib) การตรึงเวอร์ชันเคยทำให้ติดธง build cu128 ที่ RTX ซีรีส์ 50 ต้องใช้ (AMASSS.py:878-882)
nnunetv2>=2.8.0backend ของ inference
numpy1.26.4 (NUMPY_PINNED_VERSION)ตามคอมเมนต์ torch 2.2.0 ถูกสร้างบน numpy 1.x; numpy ≥ 2 ทำให้ทุกการ import torch พังด้วย _ARRAY_API not found
pydicom3.0.2ห้ามดาวน์เกรด: pydicom 2.x ทำให้ dicomweb-client และ highdicom พัง ดังนั้นโมดูล DICOM ทุกตัวใน Slicer จึงพังด้วย
dicom2nifti>=2.6.2ความเข้ากันได้กับ pydicom 3
itk, blosc2, einops, nibabelไม่ตรึงการพึ่งพาของ nnU-Net

fix_numpy_version() (AMASSS.py:61) ถูกเรียกอีกครั้งหลังการติดตั้งทั้งหมด: pip แก้การติดตั้งแต่ละรายการแยกกัน และ nnunetv2 (ซึ่งต้องการ numpy>=1.24) อาจดึง numpy 2.x เข้ามาระหว่างทาง

check_lib_installed() ปฏิเสธตระกูล torch เฉพาะเมื่อสมาชิกสองตัวประกาศ build +cuXXX ต่างกัน บนทุกแพลตฟอร์ม (AMASSS.py:80-113); build ของ CUDA ที่จะติดตั้งอ่านจาก GPU โดย torch_install_arguments() บน Windows และที่อื่น (AMASSS.py:170, 191)

ไม่มี WSL ไม่มี conda: ต่างจากโมดูล IOS (FlexReg, AREG_IOS, ALI_IOS) AMASSS ไม่ใช้สภาพแวดล้อมภายนอกเลย

AMASSS ตีพิมพ์เพียงครั้งเดียว:

Gillot M., Baquero B., Le C., Deleat-Besson R., Bianchi J., Ruellas A., …, Cevidanes L., Prieto J.C. Automatic multi-anatomical skull structure segmentation of cone-beam computed tomography scans using 3D UNETR. PLOS ONE 17(10):e0275033, 2022. doi:10.1371/journal.pone.0275033 , PMID 36223330, PMC9555672

โค้ดต่างจากบทความ (เป็นจริงใน VISOR ด้วย)

เป็นจริงใน VISOR ด้วย (checkpoint ของ nnU-Net v2 ไม่มี MONAI: SADT-VISOR sadt_amasss/nnunet_runner.py:33-34, 208-212) โค้ดแตกต่างจากบทความโดยสิ้นเชิง บทความบรรยายUNETR (ตัวเข้ารหัส transformer + ตัวถอดรหัสคอนโวลูชัน ไลบรารี MONAI): patch 128³, feature_size=16, hidden_size=768, mlp_dim=3072, attention head 12 ตัว, dropout 5%, ฝึกบน CBCT 618 ชุดจาก 7 ศูนย์ สำหรับห้าโครงสร้าง ด้วยการสุ่มตัวอย่างใหม่แบบ isotropic ที่ 0.4 mm และการปรับคอนทราสต์ด้วยฮิสโทแกรมสะสมที่เปอร์เซนไทล์ 1% / 99% ค่า Dice ที่รายงาน: ผิวหนัง 0.971 กระดูกขากรรไกรล่าง 0.962 กระดูกขากรรไกรบน 0.853 ฐานกะโหลก 0.788 กระดูกสันหลังส่วนคอ 0.760

นี่คือสิ่งที่ CLI รุ่นในอดีตทำ Create_UNETR(...), sliding_window_inference(input_img, [128,128,128], nbr_GPU_worker, net, overlap=precision/100, sw_device=DEVICE, ...), CorrectHisto + ScaleIntensityd(0,1) + Spacingd(pixdim=[0.4,0.4,0.4]) หรือ [0.16,0.16,0.32] ใน high definition แล้ว CleanArray/CropSkin อ่านได้ในที่เก็บโค้ดจนถึง commit 61bbb15 "ENH: AMASSS with nnunet." spacing แบบ high-definition และ precision ของ UI เป็นพารามิเตอร์ของโค้ด ไม่ใช่ของบทความ; Create_SwinUNETR(feature_size=48) อยู่ร่วมกันที่นั่น ถูกคอมเมนต์ไว้

ไม่มีสิ่งใดเหล่านั้นเหลืออยู่ในโค้ดปัจจุบัน: nnU-Net v2, PlainConvUNet, หนึ่งเครือข่ายไบนารีต่อโครงสร้าง spacing 0.4 mm ยังอยู่ แต่มาจาก plans.json ของน้ำหนัก เส้นทาง high-definition และการประมวลผลหลังเชิง morphology หายไปแล้ว ไม่มีสิ่งตีพิมพ์ใดบรรยาย AMASSS เวอร์ชัน nnU-Net: การอ้างบทความ PLOS ONE เพื่อบรรยายโมดูลตามที่รันอยู่ทุกวันนี้เท่ากับบรรยายสถาปัตยกรรมที่ไม่ได้ถูกรันอีกต่อไป

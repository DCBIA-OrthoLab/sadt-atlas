3.3 การแบ่ง chunk: ส่วนที่ออกแบบอย่างพิถีพิถันที่สุด

split_text_by_paragraphs() (utils.py:74) แล้วจึง create_chunks_from_paragraphs() (utils.py:119)

หัวข้อส่วนสี่หัวข้อถูก hardcode ไว้ (utils.py:84 และอีกครั้งที่ :120):

section_headers = ["CLINICAL EXAMINATION", "CLINICAL EVALUATION",
                   "RADIOGRAPHIC EXAMINATION", "RADIOGRAPHIC EVALUATION"]

กฎ ตามลำดับ:

  1. แบ่ง (utils.py:88) ที่การขึ้นบรรทัดสองครั้ง จุดเริ่มของรายการลำดับเลข (\n(?=\d+\.\s)) bullet (-, *) หรือหัวข้อส่วน การแบ่งนี้แยกตัวพิมพ์เล็กใหญ่: มีเพียงหัวข้อที่เขียนด้วยตัวพิมพ์ใหญ่เท่านั้นที่ถูกตัดออก (จุดท้ายหัวข้อที่เป็นตัวเลือกถูกทิ้ง) ขณะที่การทดสอบส่วนของ create_chunks_from_paragraphs เทียบด้วยตัวพิมพ์เล็ก (:151, :157)
  2. ชิ้นส่วนถูกประกอบกลับ (utils.py:93-111) ชิ้นที่เป็นหัวข้อล้วน ๆ เปิดย่อหน้าใหม่เสมอ แม้ตามหลังชิ้นสั้น ชิ้นที่ขึ้นต้นเหมือนรายการ (^\d+\.\s|^[\-*]\s) ถูกต่อท้ายย่อหน้าก่อนหน้าไม่ว่าขนาดเท่าใด และเมื่อย่อหน้าที่กำลังสร้างสั้นกว่า 150 อักขระ ชิ้นถัดไปจะถูกต่อท้ายมัน (elif ... or (current_paragraph and len(current_paragraph) < 150), :104-106): ย่อหน้าสั้นกลืนย่อหน้าที่ตามมา ไม่ได้ถูกพับกลับเข้าย่อหน้าก่อนหน้า
  3. ทั้งส่วน (หัวข้อ + ย่อหน้าที่ตามมาจนถึงหัวข้อถัดไป) ถือเป็นบล็อกที่แบ่งไม่ได้ตราบเท่าที่ยังพอดีในchunk (utils.py:151-165): นี่คือ invariant ของการแบ่ง chunk คือส่วนทางคลินิกต้องไม่ถูกแบ่งข้ามสอง prompt
  4. หากส่วนหนึ่งไม่พอดี มันจะไปอยู่ใน chunk ใหม่เมื่อมันเล็กพอด้วยตัวเอง (:172-173) มิฉะนั้นจะถูกตัดทีละย่อหน้า (:176-184) แล้วทีละประโยค (:186-194, re.split(r'(?<=[.!?])\s+') ที่ :126) ย่อหน้าธรรมดาที่ไม่พอดีกับที่ว่างที่เหลือของ chunk จะข้ามระดับย่อหน้าและถูกเทลงทีละประโยคทันที (:198-209)

ขนาด chunk: 3500 อักขระ ค่าเริ่มต้นของ generate_combined_summary (MedX_Summarize.py:34 ส่งต่อที่ :35) ค่าเริ่มต้นของ create_chunks_from_paragraphs (1800, utils.py:119) ไม่เคยถูกใช้ ทุกการทดสอบความพอดีคือ len(current) + len(block) + 1 <= max_chunk_size (utils.py:164,179,189,198,204) ขณะที่สิ่งที่ถูกต่อท้ายคือ "\n\n" (สองอักขระ) หลังย่อหน้าหรือส่วน และช่องว่างหนึ่งตัวหลังประโยค chunk ถูกตัดช่องว่างหัวท้ายเมื่อปิด และในการทดสอบสุ่มของฟังก์ชันที่เก็บถาวร (3,000 ข้อความ) chunk ที่ยาวที่สุดมี 3,499 อักขระ

3500 อักขระเท่ากับราว 850 ถึง 950 โทเคน BPE ต่ำกว่าขีดจำกัด 1024 ของโมเดล นี่เป็นค่าประมาณ ไม่ใช่การวัดด้วย tokenizer จริง: การใช้กฎ byte-pair ของ BART (vocab.json และ merges.txt จาก BART.zip โดยประมาณรูปแบบ pre-tokenization) กับบันทึกทดสอบของ CNE ให้ราว 4.2 อักขระต่อโทเคนในบันทึก TMJ สองฉบับ และ 3.7 ในบันทึก Ortho หนึ่งฉบับ และประโยคคำสั่งเพิ่มราว 20 โทเคน prompt ถูกตัดที่ max_length=1024 ไม่ว่าอย่างไร (MedX_Summarize.py:56) โดยไม่แจ้ง: คำเตือน if ... shape[1] > model_max_tokens ที่ :58-59 ไม่มีวันทำงาน เพราะ tensor เพิ่งถูกจำกัดที่ความยาวนั้น

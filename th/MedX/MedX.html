MedX

การสกัดตัวชี้วัดทางคลินิกของ TMD จากบันทึกข้อความอิสระด้วยโมเดลภาษาที่รันในเครื่อง (BART-large-CNN ที่ fine-tune แล้ว) จากนั้นรวมกลุ่มตัวอย่างเป็นแผงภาพเดียว: เป็นข้อความตลอดสาย ไม่มีภาพทางการแพทย์ใดเข้าสู่โมดูลนี้ ไม่ว่าชื่อจะชวนให้คิดอย่างไร หน้านี้อธิบายไปป์ไลน์ทีละขั้น รายละเอียดของโค้ดอยู่ในหน้าโค้ด

ภาพรวม: อะไรเข้า อะไรออก

เส้นทาง 1: สรุปเส้นทาง 2: dashboard
อินพุตโฟลเดอร์บันทึกทางคลินิก (.pdf, .docx, .txt) บันทึกของผู้ป่วยหนึ่งรายใช้ส่วนของชื่อก่อนขีดล่างตัวแรกร่วมกันโฟลเดอร์ของสรุปที่เส้นทาง 1 เขียนไว้
เกิดอะไรขึ้นบันทึกของผู้ป่วยแต่ละรายถูกตัดเป็นchunk และโมเดล BART ที่ fine-tune แล้วเขียนบรรทัด field: value สำหรับแต่ละ chunkบรรทัดเหล่านั้นถูกแยกวิเคราะห์เป็น56 ฟิลด์ต่อผู้ป่วย นับรวมทั้งกลุ่มตัวอย่างแล้ววาดภาพ
เอาต์พุต<patient>_summary.txt หนึ่งไฟล์ต่อผู้ป่วยdashboard.png และตาราง CSV สองตาราง

ไม่มีภาพเข้าสู่โมดูล ไม่ว่าชื่อจะชวนให้คิดอย่างไร

1. ตำแหน่งในสายโซ่

MedX แยกอิสระ: ไม่มีโมดูลอื่นเรียกมัน และมันไม่เรียกโมดูลอื่น (แคตตาล็อกเครื่องมือของ Agent ระบุงานทั้งสอง แต่เพียงเป็นคำอธิบาย) สองเส้นทางเป็นอิสระต่อกัน แต่ละเส้นมีปุ่มและงานของตัวเอง Dashboard อ่านสิ่งที่ตัวสรุปเขียน แต่ไม่มีอะไรเชื่อมทั้งสอง: ผู้ปฏิบัติงานต้องรัน dashboard ซ้ำด้วยมือ ไม่มีเส้นทางใดเรียกโมเดลภาษาผ่านเครือข่าย การรับส่งข้อมูลออกภายนอกมีเพียงการดาวน์โหลดน้ำหนักจาก GitHub release

ในโค้ดงานทั้งสอง วิธีเปิดใช้แต่ละงาน และการตรวจว่าไม่มีเครือข่าย

2. ไฟล์ที่เกี่ยวข้อง

วิดเจ็ตที่มี stylesheet โหมดมืดและการจัดการ conda ไฟล์เมธอดขนาดเล็กสองไฟล์ งานสรุปพร้อมโมดูลช่วย (การอ่าน การแบ่ง chunk การโหลดโมเดล) และงาน dashboard พร้อมไฟล์สำหรับการแยกวิเคราะห์และวาดภาพ และไฟล์ของฟังก์ชันรวมค่า ตัวสรุปรันใน conda env ของตัวเอง dashboard รันใน Python ของ Slicer ใช้ GPU หากมี และไม่จำเป็นต้องมี

ในโค้ดตารางไฟล์ การเรียก conda และ CLI ที่ไม่เคยถูกรัน

3. อินพุตและการประมวลผลก่อน

สามขั้นตอนเปลี่ยนโฟลเดอร์บันทึกให้เป็นชิ้นที่โมเดลอ่านได้: จัดกลุ่มตามผู้ป่วย สกัดข้อความ และตัดเป็นchunk

3.1 การจัดกลุ่มตามผู้ป่วย

โฟลเดอร์ถูกอ่านโดยไม่ลงไปในโฟลเดอร์ย่อย ทุกอย่างก่อนขีดล่างตัวแรกในชื่อไฟล์คือรหัสผู้ป่วย และบันทึกของผู้ป่วยหนึ่งรายถูกต่อเป็นข้อความเดียวก่อนที่โมเดลจะเห็น อย่างไรก็ตาม แถบความคืบหน้าหารจำนวนผู้ป่วยที่เสร็จแล้วด้วยจำนวนไฟล์ที่พบในทุกโฟลเดอร์ย่อย ดังนั้นทันทีที่ผู้ป่วยมีบันทึกมากกว่าหนึ่งฉบับ หรือมีโฟลเดอร์ย่อย มันจะไม่ถึง 100 % บันทึกของผู้ป่วยหนึ่งรายถูกต่อกันโดยไม่มีอะไรคั่น

ในโค้ดโค้ดการจัดกลุ่มและความไม่ตรงกันของความคืบหน้า

3.2 การสกัดข้อความ

PDF ให้ข้อความของหน้า ไฟล์ Word ให้ย่อหน้า ไฟล์ข้อความถูกอ่านตามที่เป็น การทำความสะอาดเพียงอย่างเดียวคือเขียนอักขระสองตัวใหม่: เครื่องหมายอะพอสทรอฟีแบบโค้งและขีดกลาง en กลายเป็นแบบธรรมดา

ในโค้ดตัวสกัดและฟังก์ชันทำความสะอาด

3.3 การแบ่ง chunk: ส่วนที่ออกแบบอย่างพิถีพิถันที่สุด

ข้อความถูกแบ่งเป็นย่อหน้าก่อน: ที่บรรทัดว่าง ที่จุดเริ่มของรายการที่มีเลขหรือ bullet และที่หัวข้อส่วนสี่หัวข้อ (clinical examination, clinical evaluation, radiographic examination, radiographic evaluation) ซึ่งตัดออกก็ต่อเมื่อเขียนด้วยตัวพิมพ์ใหญ่ จากนั้นชิ้นส่วนถูกประกอบกลับด้วยสองกฎ รายการที่มีเลขหรือ bullet ติดกับชิ้นก่อนหน้าเสมอ ย่อหน้าที่สั้นกว่า 150 อักขระกลืนชิ้นที่มาหลังมัน ดังนั้นหัวข้อสั้นจึงดึงข้อความใต้มันมา และย่อหน้าสั้นถูกต่อเข้ากับสิ่งที่ตามมา ไม่ใช่สิ่งที่มาก่อน หัวข้อส่วนเริ่มย่อหน้าใหม่เสมอ

เมื่อส่วนหนึ่งใหญ่เกินกว่าจะอยู่ใน chunk เดียว มันถูกตัดทีละย่อหน้า และย่อหน้าที่ยังใหญ่เกินถูกตัดทีละประโยค ย่อหน้าธรรมดาที่ไม่พอดีกับที่ว่างที่เหลือของ chunk ถูกตัดทีละประโยคทันที 3,500 อักขระเท่ากับราว 850 ถึง 950 โทเคน (ค่าประมาณจากบันทึกทดสอบของ CNE ไม่ใช่การวัดด้วย tokenizer จริง) บวกอีกราว 20 สำหรับประโยคคำสั่ง จึงต่ำกว่าขีดจำกัด 1,024 ของโมเดล สิ่งที่เกินขีดจำกัดนั้นถูกตัดทิ้งโดยไม่มีคำเตือน

ในโค้ดฟังก์ชันแบ่ง chunk สองตัว นิพจน์ปกติ และอาร์กิวเมนต์ขนาด

4. โมเดล

4.1 สิ่งที่ถูกโหลดจริง

โมเดลและ tokenizer ถูกโหลดด้วยการเรียกไลบรารีมาตรฐานและไม่มีอย่างอื่น: ไม่มี adapter และไม่มี quantization แม้สภาพแวดล้อมจะติดตั้งแพ็กเกจสำหรับทั้งสองอย่าง (ของตกค้างจากการฝึก)

ในโค้ดบรรทัดที่โหลดและแพ็กเกจที่ไม่ได้ใช้

4.2 น้ำหนักโมเดล

น้ำหนักเป็นไฟล์เก็บถาวร 1.51 GB จาก GitHub release การตั้งค่าของมันแสดงว่าเป็น fine-tune ของ facebook/bart-large-cnn ซึ่งมี encoder และ decoder อย่างละ 12 เลเยอร์ (ราว 406 ล้านพารามิเตอร์ จากขนาดของไฟล์น้ำหนัก) อ่านได้ไม่เกิน 1,024 ตำแหน่ง ไม่ใช่โมเดลที่ฝึกขึ้นจากศูนย์ ปุ่มดาวน์โหลดของวิดเจ็ตไม่ได้ดาวน์โหลดอะไรจริง ๆ ต้องไปเอาไฟล์เก็บถาวรด้วยมือ (รายละเอียด)

ในโค้ดเนื้อหาของไฟล์เก็บถาวรและฟิลด์การตั้งค่า

4.3 Prompt และการสร้างข้อความ

สำหรับแต่ละchunk มีหนึ่งประโยควางไว้หน้าข้อความ: “Using the following note, extract structured key-value pairs about the patient’s symptoms and diagnoses” BART ไม่ใช่โมเดลที่ทำตามคำสั่ง ประโยคนี้จึงช่วยก็ต่อเมื่อการ fine-tune ใช้ prefix เดียวกัน ซึ่งตรวจจากที่เก็บโค้ดไม่ได้ จากนั้นโมเดลเขียนข้อความอิสระ: รูปแบบ field: value เป็นนิสัยที่เรียนรู้มา ไม่เคยถูกตรวจที่นี่

การสร้างข้อความรวมbeam search สี่ beam เข้ากับการสุ่ม ซึ่งทำให้เอาต์พุตต่างกันทุกครั้งที่รัน (ไม่มีการตั้ง seed) สรุปของ chunk ต่าง ๆ ของผู้ป่วยหนึ่งรายถูกต่อกันด้วยเส้นประ 100 ตัว

ในโค้ดprompt ตารางการสร้างข้อความฉบับเต็ม และตัวช่วยสกัดที่ไม่ได้ใช้

5. แกนอัลกอริทึม: dashboard

ไม่มีการเรียนรู้ที่นี่: การแยกวิเคราะห์ข้อความ การนับ และการวาด

5.1 จากสรุปข้อความเป็นตาราง

Dashboard อ่านไฟล์ที่ลงท้ายด้วย _summary.txt dictionary ของ56 ฟิลด์ ซึ่งทุกตัวเริ่มต้นเป็นข้อความว่าง (ความรุนแรงของอาการปวดศีรษะ การเคลื่อนของ disc ความผิดปกติของการนอน การใช้ CPAP หรือไม่ และอื่น ๆ) คือสคีมาเป้าหมายของโมดูล และเป็นที่เดียวที่เขียนไว้ แต่ละบรรทัดของสรุปถูกตัดที่เครื่องหมายทวิภาค บรรทัดที่ไม่ได้สองชิ้นพอดีจะถูกข้าม ดังนั้นค่าที่มีเครื่องหมายทวิภาคอยู่ในตัวจะหายไป และฟิลด์นอก 56 ตัวถูกละเลย

ในโค้ดโค้ดแยกวิเคราะห์และรวมค่า หกฟิลด์ตัวเลข และสาขา boolean ที่ไม่ได้ใช้

5.2 ตัวรวมค่า

แต่ละพาเนลมีหนึ่งฟังก์ชัน ทั้งหมดเป็นการจับรูปแบบบนข้อความอิสระตามด้วยการนับ: กลุ่มอายุ (ระบุว่า 12 ถึง 19, 20 ถึง 40 และมากกว่า 40) มีความผิดปกติของการนอนหรือไม่ tenderness ค่าเฉลี่ยและการกระจายของคะแนนปวดห้ารายการ การอ้าปากสูงสุดที่อ่านจากสตริงเช่น “33 mm” (หรือจากตัวเลขเปล่า ๆ ใด ๆ) ตำแหน่งที่ปวดศีรษะและปวดข้อต่อ (ด้วยรายการคำพ้องความหมาย) อาการใช่หรือไม่ใช่หกอาการ ระดับอาการปวดกล้ามเนื้อห้าระดับ และจำนวนเดือนนับจากเริ่มมีอาการที่อ่านจากวลีเช่น “1 year and 9 months ago”

พาเนลอื่นเป็นไปตามกฎของตัวเอง พายการนอนนับทุกค่ายกเว้น “unknown” รวมถึงฟิลด์ว่าง เป็นความผิดปกติของการนอน พาย tenderness จัดผู้ป่วยไว้ในส่วน “unknown” เมื่อไม่มีฟิลด์ใดในสามฟิลด์เป็นบวก และไม่ได้เป็น “false” ทั้งหมด แท่งคะแนนและแท่งการอ้าปากเป็นค่าเฉลี่ยของค่าที่มีอยู่

มีจุดอ่อนสองข้อตามมา บางฟังก์ชันเปรียบเทียบข้อความกับ true ตัวพิมพ์เล็ก ขณะที่บางฟังก์ชันทำเป็นตัวพิมพ์เล็กก่อน โมเดลที่เขียน True จะทำให้ donut ใช่หรือไม่ใช่ห้าจากหกอันเป็นศูนย์โดยไม่มีข้อความแจ้ง โดยอันของขากรรไกรเป็นอันเดียวที่ได้รับการป้องกัน (รายละเอียด) และการเคลื่อนของ disc ถูกคำนวณแต่ไม่เคยถูกวาด

ในโค้ดตารางฟังก์ชัน บั๊กเรื่องตัวพิมพ์ และการคำนวณที่ไม่ได้ใช้

5.3 ภาพ

ภาพใหญ่หนึ่งภาพ (22 คูณ 14 นิ้ว) ในกริด 2 คูณ 2: พายของอายุ ความผิดปกติของการนอน และ tenderness กับ donut เล็กสองอันของไมเกรนและปวดศีรษะที่ซ้ายบน donut หกอันทางขวา แผนภูมิแท่งของคะแนนพร้อมการกระจาย ของการอ้าปากสูงสุด และของตำแหน่งปวดศีรษะที่ซ้ายล่าง จากนั้นอาการปวดกล้ามเนื้อ บริเวณปวดข้อต่อ และอายุเทียบกับระยะเวลาที่ปวดที่ขวาล่าง

ในโค้ดสเปกของกริดและการกำหนดค่าให้ตัวเองที่ไม่ทำอะไร

6. การประมวลผลหลังและเอาต์พุต

ตัวสรุปเขียนไฟล์ข้อความหนึ่งไฟล์ต่อผู้ป่วยและไฟล์บันทึกที่เก็บจำนวนผู้ป่วยที่เสร็จแล้ว Dashboard เขียน dashboard.png ตาราง 58 คอลัมน์ patient_data.csv (56 ฟิลด์ บวกคอลัมน์ช่วยสองคอลัมน์ที่โค้ดวาดภาพเพิ่ม) และตาราง 56 คอลัมน์ dashboard_full_dataframe.csv ที่เขียนก่อนที่สองคอลัมน์นั้นจะมี หากติ๊กกล่อง ภาพจะถูกโหลดเข้า Slicer เหมือนเป็นปริมาตร ในมุมมองสไลซ์สีแดง เพราะไม่มีตัวดูภาพ

ในโค้ดตารางไฟล์ ไฟล์ CSV สองไฟล์ พาธของบันทึก และการโหลดภาพเป็นปริมาตร

7. ทำนายหรือคำนวณ

ขั้นตอนลักษณะ
การสกัดข้อความ การแบ่ง chunkคำนวณ กำหนดแน่นอน
การสกัดตัวชี้วัด 56 รายการทำนาย BART-large-CNN ที่ fine-tune แล้ว การสร้างข้อความแบบอิสระ
การแยกวิเคราะห์ การรวม การนับ และภาพคำนวณ กำหนดแน่นอน

มีเครือข่ายเดียว และมันสร้างข้อความ: มันตัดสินรูปแบบเอาต์พุต ทุกอย่างปลายน้ำสมมติว่ามันเขียนบรรทัด field: value ที่มีชื่อฟิลด์ 56 ชื่อที่คาดหวัง

ในโค้ดตารางเดียวกันพร้อมสภาพแวดล้อมและอุปกรณ์

8. สภาพแวดล้อม

ตัวสรุปต้องใช้ conda env ของตัวเอง (Python 3.12) พร้อมแพ็กเกจโมเดลภาษาและ PDF บน Windows conda ผ่าน WSL Dashboard รันใน Python ของ Slicer และต้องใช้ numpy ต่ำกว่า 2, pandas และ matplotlib

ในโค้ดรายการแพ็กเกจ การตรวจสภาพแวดล้อม และการฆ่า process group

9. ปัญหาที่ทราบ

  • ปุ่ม Download ไม่ได้ดาวน์โหลดอะไรเลย ต้องไปเอาน้ำหนักด้วยมือ (รายละเอียด)
  • ผลการตรวจสภาพแวดล้อมถูกละเลย ดังนั้นการสรุปจึงเริ่มทำงานแม้ไม่มี conda (รายละเอียด)
  • แถบความคืบหน้าของ dashboard ไม่เคยขยับ (รายละเอียด) และโฟลเดอร์อินพุตว่างทำให้เกิดการหารด้วยศูนย์ (รายละเอียด)
  • การสร้างข้อความทำซ้ำไม่ได้: beam search รวมกับการสุ่ม ไม่มี seed (รายละเอียด)
  • ผู้ป่วยคือสิ่งที่อยู่ก่อนขีดล่างตัวแรก ผู้ป่วยสองคนที่ต่างกัน หรือผู้ป่วยคนเดียวที่ใช้สองชื่อ จึงปะปนกันได้ง่าย (ข้อควรระวังทั้งหมด)
  • ค่าที่มีเครื่องหมายทวิภาคหายไปตอนแยกวิเคราะห์ (ข้อควรระวังทั้งหมด)
  • คอมเมนต์ในโค้ด dashboard ชี้ไปที่สรุปจากโมเดล Qwen 1.5B ไม่ใช่ BART ที่โมดูลส่งมา (ข้อควรระวังทั้งหมด)
  • หนึ่งในตัวรวมค่าถูกคำนวณแต่ไม่เคยถูกวาด และมีแพ็กเกจที่ติดตั้งสี่ตัวที่ไม่เคยถูก import (ข้อควรระวังทั้งหมด)
ในโค้ดข้อควรระวัง บั๊ก และโค้ดที่ไม่ได้ใช้ทุกรายการพร้อมบรรทัด

10. วรรณกรรม

บทความที่เกี่ยวข้องคือ AI-Driven Multimodal TMJ Patient Modeling: From Unstructured Notes to Precision Treatment (2025, Springer LNCS) บทความอธิบายการ fine-tune BART และ DeepSeek-R1 บนส่วนที่ผู้เขียนใส่คำอธิบายประกอบ 1,813 ส่วนจากเวชระเบียน TMD 500 ราย เพื่อสกัดตัวชี้วัดทางคลินิก 56 รายการ ซึ่งเท่ากับจำนวน key ใน initialize_key_value_summary() พอดี และป้อนให้ dashboard ของผู้ป่วยและกลุ่มตัวอย่าง บทความสรุปว่า BART ชนะ DeepSeek ในความแม่นยำของการสกัดฟิลด์ แม้คะแนน ROUGE จะต่ำกว่าเล็กน้อย ซึ่งสอดคล้องกับการที่โมดูลส่ง BART มา

ช่องว่างระหว่างบทความกับโค้ดของที่เก็บโค้ด:

  • บทความวางการสรุปไว้ในกรอบ multimodal (MRI และ CBCT ที่ register แล้ว) ไม่มีสิ่งนั้นใน MedX เลย ซึ่งอ่านเฉพาะข้อความ
  • คอมเมนต์ระหว่างพัฒนาชี้ไปที่ Qwen 1.5B ซึ่งเป็นโมเดลตัวที่สามที่บทคัดย่อของบทความไม่ได้กล่าวถึง
  • ไม่มีสคริปต์ใดในที่เก็บโค้ดที่ทำซ้ำเมตริกของบทความได้ (evaluate และ scikit-learn ถูกติดตั้งแต่ไม่ได้ใช้)

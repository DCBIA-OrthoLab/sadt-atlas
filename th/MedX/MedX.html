3.3 การแบ่งชิ้น: ส่วนที่ออกแบบอย่างพิถีพิถันที่สุด

split_text_by_paragraphs() (utils.py:83) แล้ว create_chunks_from_paragraphs() (utils.py:128)

หัวข้อส่วนสี่หัวข้อถูกฮาร์ดโค้ด:

section_headers = ["CLINICAL EXAMINATION", "CLINICAL EVALUATION",
                   "RADIOGRAPHIC EXAMINATION", "RADIOGRAPHIC EVALUATION"]

กฎตามลำดับ:

  1. แยกที่การขึ้นบรรทัดคู่ จุดเริ่มของรายการมีเลข (\n(?=\d+\.\s)) จุดนำหน้า (-, *) หรือหัวข้อส่วน;
  2. ย่อหน้าที่ต่ำกว่า 150 ตัวอักษรจะถูกรวมกลับเข้ากับย่อหน้าก่อนหน้า (รายการย่อยอยู่กับหัวข้อของมัน);
  3. ส่วนทั้งส่วน (หัวข้อ + ย่อหน้าที่ตามมาจนถึงหัวข้อถัดไป) ถูกปฏิบัติเป็นบล็อกที่แบ่งไม่ได้ตราบเท่าที่ยังพอดีในชิ้น: นี่คือค่าคงที่ของการแบ่งชิ้น ส่วนทางคลินิกต้องไม่ถูกตัดข้ามสอง prompt;
  4. ถ้าไม่พอดี ถอยไปทีละย่อหน้า แล้วทีละประโยค (re.split(r'(?<=[.!?])\s+'))

ขนาดชิ้น: 3500 ตัวอักษร ส่งเข้ามาโดย generate_combined_summary (MedX_Summarize.py:29) ค่าเริ่มต้นของ create_chunks_from_paragraphs (1800) ไม่เคยถูกใช้ 3500 ตัวอักษร ≈ 900 โทเค็น BPE ต่ำกว่าขีดจำกัด 1024 ของโมเดล แต่การแบ่งโทเค็นถูกตัดที่ max_length=1024 อยู่ดี

Beam search และการสุ่มตัวอย่างพร้อมกัน (num_beams=4 + do_sample=True) → transformers ถอยไปใช้ beam sample: เอาต์พุตไม่กำหนดแน่นอน การรันสองครั้งบนบันทึกเดียวกันไม่ได้สรุปเหมือนกัน ไม่มีการตั้ง seed

BART ไม่ใช่โมเดลที่ปรับด้วยคำสั่ง: ประโยคคำสั่งเพียงถูกต่อหน้าข้อความต้นทาง มีผลก็ต่อเมื่อ fine-tune ด้วยคำนำหน้าเดียวกันนั้น: ซึ่งตรวจสอบไม่ได้จากที่เก็บโค้ด

สิ่งที่เครือข่ายสร้างตามตัวอักษรคือข้อความอิสระ ลำดับที่ถอดรหัสผ่าน tokenizer.decode(..., skip_special_tokens=True) รูปแบบ key: value ไม่เคยถูกบังคับหรือตรวจในขั้นนี้ เป็นคุณสมบัติที่เรียนรู้ ไม่ใช่การรับประกัน สรุปของแต่ละชิ้นถูกต่อด้วยเส้นขีด 100 ตัว

ไม่มีรอบตรวจสอบคู่ key/value ฝั่ง CLI: extract_key_value_pairs() และ save_dict_to_csv() (utils.py:227) เป็นโค้ดที่ไม่ได้ใช้ ไม่เคยถูก import (__init__.py ไม่ได้ re-export)

  • เปอร์เซ็นต์ถูกหารด้วย len(df) เสมอ ไม่เคยหารด้วยจำนวนค่าที่กรอก: ฟิลด์ที่ขาดนับเป็นลบ
บั๊กที่ยืนยันแล้ว

set_upper_donuts_data ทดสอบ "true" ตัวพิมพ์เล็ก ขณะที่ตัวรวมค่าอื่นทำให้เป็นมาตรฐานด้วย .lower() ก่อนเปรียบเทียบ: ความไม่สอดคล้องด้านตัวพิมพ์ที่ยืนยันในโค้ด ซึ่งทำให้โดนัททั้งหกลดเป็น 0% อย่างเงียบ ๆ ถ้าโมเดลเขียน True/False ตัวพิมพ์ใหญ่

set_migraine_data มี return ที่ไปไม่ถึงหลังตัวแรก (dashboard_utils.py:81): เวอร์ชัน 5 หมวดเก่าที่ทิ้งไว้

10. วรรณกรรม

บทความที่ตรงกันคือ AI-Driven Multimodal TMJ Patient Modeling: From Unstructured Notes to Precision Treatment (2025, Springer LNCS) อธิบายการ fine-tune BART และ DeepSeek-R1 บนส่วนที่มีการกำกับ 1,813 ส่วนจากบันทึก TMD 500 ฉบับ เพื่อสกัดตัวบ่งชี้ทางคลินิก 56 ตัว ซึ่งเป็นจำนวนคีย์ที่แน่นอนใน initialize_key_value_summary() และป้อน dashboard ของผู้ป่วยและกลุ่มตัวอย่าง บทความสรุปว่า BART ชนะ DeepSeek ในความแม่นยำของการสกัดฟิลด์ แม้คะแนน ROUGE ต่ำกว่าเล็กน้อย; สอดคล้องกับการที่โมดูลส่ง BART มา

ช่องว่างระหว่างบทความกับโค้ดของที่เก็บโค้ด:

  • บทความวางการสรุปไว้ในกรอบหลายโมดาลิตี (MRI และ CBCT ที่ลงทะเบียนภาพแล้ว); ไม่มีสิ่งใดนั้นใน MedX ที่อ่านเฉพาะข้อความ;

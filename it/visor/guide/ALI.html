ALI con VISOR

Che cosa cambia quando si esegue ALI tramite un server VISOR da 3D Slicer: che cosa fornire, che cosa resta uguale, che cosa è diverso. Il modulo legacy ha la propria pagina.

VISOR Pagina legacy Atlante (VISOR)

Tramite un server VISOR l'analisi gira sul server, non sul tuo computer. Il modulo in Slicer si chiama ALIRemote. È un pannello che invia le scansioni al server e riporta indietro i file di landmark. Come connettersi e che cosa il server fa dei dati è spiegato in Usare VISOR; questa pagina riguarda solo ciò che cambia per ALI rispetto al modulo legacy. È scritta a partire dal codice del server e del pannello, non da una sessione su un server reale. I dettagli, con i riferimenti al codice, sono in ALI su VISOR.

Che cosa cambia nel pannello

  • Una finestra, una scelta in alto. Il primo campo è il Mode, CBCT o IOS. Svolge il ruolo del tipo di dati nella finestra legacy. L'elenco di punti che segue cambia di conseguenza (119 punti per una CBCT, 153 per una scansione intraorale).
  • Nessun modello da scaricare. I pesi addestrati restano sul server. Il modello, il dispositivo e le impostazioni di ricerca non sono mostrati nel pannello.
  • L'input. Un file o una cartella. Una cartella viene zippata e inviata per te. Il pannello può anche proporre i file di test che il server ospita.
  • I punti si scelgono in schede, una scheda per gruppo. Se non selezioni nulla, l'esecuzione CBCT posiziona tutti e 119.
  • Il risultato torna come archivio. Il pannello lo decomprime, lo salva nella cartella scelta e, con la casella "Load the predicted landmarks into the scene" selezionata (il valore predefinito), carica i file in Slicer.

Che cosa resta uguale

I nomi dei landmark, i due modi di lavorare (un volume percorso da un agent, una superficie fotografata da più lati), il formato .mrk.json, e i file originali lasciati intatti. I punti arrivano ancora bloccati, come i file legacy: sblocca un punto nel modulo Markups prima di spostarlo.

Che cosa è diverso nei file e nei risultati

  • Un file per scansione con tutti i gruppi insieme, chiamato <scan>_lm_Pred.mrk.json, dove il modulo legacy scriveva un file per gruppo (CBCT) o per arcata e per rete (IOS). La struttura delle cartelle dell'input è riprodotta nel risultato.
  • Arriva con un report: run_report.json elenca, scansione per scansione, i punti posizionati e i punti che non sono convergiti.
  • I formati intraorali supportati sono .vtk e .stl. Le mesh che portano già i numeri dei denti sono elaborate per prime; una mesh senza passa dalla segmentazione delle corone del server (Crown_Seg), poi segue.
  • I file di landmark compaiono quando vengono caricati. I file legacy erano scritti con la visualizzazione disattivata, quindi aprirne uno direttamente non mostrava nulla; i file del server sono scritti visibili.
  • I risultati intraorali non sono identici a quelli legacy. Sulla mesh che gli sviluppatori hanno confrontato, 54 punti su 73 sono usciti esattamente uguali e gli altri sono caduti sul dente corretto (README di VISOR, SADT-VISOR tools/ALI/README.md:213-226). I punti mucogengivali passano per meno passi di correzione che nell'ultimo modulo legacy.
  • DICOM. Il server converte da sé una serie DICOM, nulla viene scritto nella tua cartella.
  • Tempo. Il server annota 128 s per 119 landmark su una scansione con 8 agent contemporanei su una scheda RTX 6000 Ada (una misura scritta nella configurazione del server, non rieseguita qui). La configurazione predefinita del server non pone alcun limite di tempo a un'esecuzione.
Il messaggio di fine esecuzione dice "0 scan(s), 0 landmark(s) written"

Qualunque cosa sia accaduta. Il pannello cerca l'elenco delle scansioni sotto un nome che il server non usa più (ALIRemote.py:216 in AutomatedDentalToolsRemote 19b95e8, contro cases nel report del server). Leggi invece i file caricati e il run_report.json nella cartella dei risultati; i fallimenti sono elencati lì, e il messaggio del pannello non li elenca mai.

Scegliere la cartella di un'unica serie DICOM

Se indichi la cartella che contiene esattamente una serie DICOM, il file del risultato si chiama ._lm_Pred.mrk.json, un file nascosto, e non compare in un normale elenco di file. Metti la serie in una sottocartella della cartella che scegli, oppure mostra i file nascosti. La causa è stata verificata nel codice (le due funzioni di nomenclatura sono state eseguite); un'esecuzione completa su una serie reale non è stata ripetuta.

CBCT salvata con un altro orientamento

Il modulo legacy porta ogni CBCT a un orientamento standard (LPS) prima della ricerca. La versione server no. L'effetto sui punti posizionati non è stato misurato, quindi guarda i landmark sulla scansione prima di usarli, in particolare se il tuo volume non viene da un'esportazione DICOM.

AutoCrop3D con VISOR

Che cosa cambia quando si esegue AutoCrop3D tramite un server VISOR da 3D Slicer: che cosa fornire, che cosa resta uguale, che cosa è diverso. Il modulo legacy ha la propria pagina.

VISOR Pagina legacy Atlante (VISOR)

Tramite un server VISOR il modulo si chiama AutoCrop3D Remote. Il riquadro lo disegni ancora in Slicer; i file sono inviati al server, ritagliati lì, e i risultati tornano in una cartella che scegli. Il pannello è costruito da ciò che il server pubblica, in tre gruppi: Inputs, Options e Outputs. Nulla è installato o scaricato sul tuo computer, e il ritaglio non richiede alcun modello.

Che cosa fornire

  • Le scansioni: un volume o una cartella (.nii.gz, .nii, .nrrd, .gipl.gz, .gipl), caricati sul server. Un .nrrd.gz è rifiutato con un messaggio: decomprimilo prima in .nrrd. Un server può anche ospitare file di test; il menu a tendina offre allora MG_test_scan.nii.gz. Il limite di upload predefinito è 500 MB, e una cartella parte come richiesta unica perché AutoCrop3D non può essere suddiviso per paziente.
  • La regione di interesse: scegli la ROI che hai disegnato, direttamente dalla scena (la riga ROI elenca i nodi ROI della scena), oppure indica un file .mrk.json o una cartella di file. Il riquadro di test ospitato si chiama ROI_box.
  • Options: mantenere la dimensione originale, se produrre una mesh (surfaces), il margine della mesh in millimetri, la levigatura della mesh, e il suffisso di output (cropped per impostazione predefinita). Poi scegli una cartella di output.

Che cosa resta uguale

  • Il ritaglio è la stessa aritmetica: il riquadro è mappato sugli indici di voxel della griglia originale e il blocco è estratto, senza ricampionamento. Il port conserva perfino il troncamento verso zero, di proposito.
  • Una ROI per tutti, o una ROI per paziente abbinata per nome. I file di output conservano la struttura delle cartelle dell'input.
  • I risultati sono decompressi nella cartella di output scelta; fino a 12 sono caricati nella scena, mostrati con il preset di rendering di volume CT-AAA.

Che cosa è diverso

  • Nessun "Crop Volume for tilted images". Una ROI ruotata è ritagliata come il suo riquadro allineato agli assi e il report porta roi_orientation_ignored.
  • Una ROI salvata in RAS è compresa. Il sistema di coordinate dichiarato nel file è letto.
  • Gli errori di nome sono nominati. Il pannello termina con una riga come "N of M scan(s) cropped. No ROI for: …". Il report di esecuzione elenca le stesse scansioni.
  • Un riquadro che non incontra il volume è un errore (la ROI non si sovrappone a questo volume), e un riquadro che si sovrappone solo in parte viene ritagliato e contrassegnato con clamped_to_the_volume.
  • I risultati precedenti non vengono ritagliati di nuovo. Se la cartella delle scansioni contiene anche file che terminano con _cropped (o con il tuo suffisso) di un'esecuzione precedente, vengono messi da parte.
  • Nessun avanzamento per scansione. Lo strumento non segnala l'avanzamento mentre gira; il report di esecuzione AutoCrop3D_report.json, decompresso con i risultati, dà la durata e l'esito di ogni scansione.
Una mesh richiede un nome di file simile a una segmentazione

Con il valore predefinito surfaces = segmentations, un file chiamato P1_Seg.nii.gz ottiene una mesh e un file chiamato Mandible.nii.gz no (verificato il 2026-11-09 sulla regola propria del port). Il nome di una cartella non conta. Rinomina il file, oppure imposta surfaces su all. La mesh è posta nello spazio proprio della scansione, quindi in Slicer si sovrappone alla scansione ritagliata.

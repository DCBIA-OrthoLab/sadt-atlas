ASO con VISOR

Che cosa cambia quando si esegue ASO tramite un server VISOR da 3D Slicer: che cosa fornire, che cosa resta uguale, che cosa è diverso. Il modulo legacy ha la propria pagina.

VISOR Pagina legacy Atlante (VISOR)

Tramite un server VISOR l'orientamento è calcolato sul server e il modulo Slicer, ASORemote, si limita a inviare i file e a caricare ciò che torna. Come connettersi e che cosa il server fa dei dati è spiegato in Usare VISOR. Questa pagina riguarda solo ciò che cambia per ASO rispetto al modulo legacy. È scritta dal codice del server e del pannello, non da una sessione su un server reale. I dettagli, con i riferimenti al codice, sono in ASO su VISOR.

Che cosa cambia nel pannello

  • Si sceglie il tipo di dati, non la modalità. Il pannello chiede l'Input Type, CBCT o IOS. La scelta Semi o Fully non è disegnata: il server decide dai tuoi dati. Per una CBCT, una scansione che ha già accanto un file di landmark è orientata su quei landmark; una scansione senza ha i landmark predetti dal server (ALI_CBCT). Se indichi una cartella di file di landmark (Landmark folder, nella sezione Advanced), quelli sono usati per primi.
  • Niente da scaricare. Il paziente di riferimento (il "gold") e i modelli restano sul server e sono scelti per te.
  • CBCT landmarks: un elenco di 115 punti in schede; il valore predefinito sono i sette usati per l'orientamento standard (Ba, S, N, RPo, LPo, ROr, LOr). Tienine selezionati almeno 3.
  • Intraoral scans: schede per i 32 denti (6 selezionati per impostazione predefinita), i tipi di landmark, le arcate, e la scelta dell'occlusione (ogni arcata da sola, o un'arcata che guida l'altra).
  • Il suffisso di output è un campo a sé (predefinito Or).

Che cosa resta uguale

Il principio (una partenza su 3 landmark, poi un ICP rigido sul riferimento), la scansione riorientata, un file di trasformazione scritto accanto per gli strumenti di registrazione, e le scansioni lasciate al loro posto.

Che cosa è diverso

  • La CBCT semiautomatica non richiede alcun file di trasformazione, e il server ricentra sempre ogni scansione per prima, quindi un'esecuzione semiautomatica da sola va bene. L'avvertenza della guida legacy contro l'eseguirla da sola (Choosing a mode) qui non vale.
  • I tuoi file di landmark non vengono cancellati. Il server li unisce in memoria e non scrive nulla nella tua cartella di input.
  • Rieseguire riscrive. Ogni esecuzione va in una cartella di output nuova sul server e ogni file viene scritto, che ne esistesse o no uno precedente.
  • I nomi dei file intraorali devono nominare l'arcata (per esempio U, Upper, L, Lower, Max, Mand). Un file senza parola di arcata è saltato e contato, non trattato come un'arcata inferiore.
  • L'intraorale Fully-Automated richiede denti numerati, e così qualunque arcata senza file di landmark. ASO stesso non segmenta: una mesh senza etichette dei denti è rifiutata. I moduli di registrazione che chiamano ASO eseguono prima la segmentazione (Crown_Seg).
  • Nomi delle trasformazioni. CBCT: <patient>_<suffix>_transform.tfm. Intraorale: <patient>_<Upper|Lower>_<suffix>.tfm per ogni arcata.
  • I risultati non sono confrontati con quelli del modulo legacy. Gli sviluppatori dichiarano che un confronto numerico dei volumi orientati è ancora dovuto (SADT-VISOR tools/ASO/README.md), e con le impostazioni predefinite la ricerca dei primi 3 landmark qui è esaustiva e ripetibile, mentre il legacy sorteggia a caso.
  • Tempo: non misurato qui per ASO. Una CBCT senza landmark attende anche la predizione dei landmark (ALI_CBCT, a cui per impostazione predefinita sono chiesti i sette landmark). La configurazione predefinita del server non pone alcun limite di tempo.
Un file di landmark con il nome sbagliato viene sostituito, senza messaggio

Se una scansione ha un file di landmark che non si abbina a essa per nome (per esempio P1.mrk.json accanto a P1_CBCT.nii.gz), il server non può vederlo, predice invece nuovi landmark e orienta su quelli, anche con l'impostazione semiautomatica. Il report dice che i landmark vengono da ALI_CBCT e non elenca alcun file non abbinato. Questo è stato riprodotto con gli helper di test dello strumento (e senza uno strumento di predizione lo stesso input fallisce e nomina il file). Chiama i tuoi file di landmark come la scansione (il messaggio di errore nomina la regola, costruita su _scan e _lm) e leggi landmark_source in ASO_report.json.

Intraorale, cinque denti selezionati

Senza un file di landmark, l'allineamento grossolano richiede 3 o 4 denti per arcata. Con 5 selezionati, la richiesta è accettata e ogni arcata fallisce dopo (letto nel codice; non eseguito).

SurgMovPred con VISOR

Che cosa cambia quando si esegue SurgMovPred tramite un server VISOR da 3D Slicer: che cosa fornire, che cosa resta uguale, che cosa è diverso. Il modulo legacy ha la propria pagina.

VISOR Pagina legacy Atlante (VISOR)

Con VISOR, SurgMovPred gira su un server e Slicer mostra solo il suo pannello. La predizione in sé è la stessa: gli stessi 112 modelli, applicati riga per riga alla tua tabella. Ciò che cambia è che cosa devi fornire.

  • Un solo input invece di due cartelle. Il pannello legacy chiedeva una cartella di input e una cartella dei modelli; qui indichi solo le misure, un'unica tabella .csv, .xlsx o .ods, o una cartella di tabelle. Non c'è alcuna cartella dei modelli da scaricare o a cui puntare: il server tiene i modelli e il pannello nasconde quella scelta. Il server può anche offrire la sua tabella di esempio ospitata (patients_to_predict.xlsx, 101 pazienti) come file di test.
  • Le regole sull'input non cambiano. Una cartella è letta in piano, senza le sue sottocartelle; è letto solo il primo foglio di una cartella di lavoro; le intestazioni sono ripulite nello stesso modo; la colonna dell'identificativo del paziente è rilevata dagli stessi nomi; un modello di cui non sono presenti tutte le colonne è saltato, con la stessa tolleranza _T0 (VISOR:SADT-VISOR tools/Surg_Mov_Pred/src/sadt_surgmovpred/pipeline.py:143-147,223-236).
  • Il risultato è salvato, non caricato. Come prima, scegli una cartella di output. Il server restituisce uno zip che contiene predictions_outputs.xlsx e predictions_outputs.csv, il pannello lo decomprime lì, e nulla compare nella scena di Slicer. Entrambi i file iniziano con una colonna senza nome di numeri di riga prima di IDPatient (pipeline.py:283-284).
  • Nessuna dipendenza è installata sulla tua macchina. La reinstallazione di numpy a ogni Apply appartiene solo al modulo legacy; il server esegue lo strumento nel proprio ambiente.
  • Ordine di output stabile. I modelli sono letti in ordine alfabetico, quindi le colonne vengono nello stesso ordine a ogni esecuzione, e i file di una cartella sono impilati in ordine alfabetico (pipeline.py:143-147,173).
Due casi ora si fermano con un errore

Se un'intestazione non può essere ripulita fino a diventare il nome di una colonna, l'esecuzione si ferma e nomina la colonna (VISOR:SADT-VISOR tools/Surg_Mov_Pred/src/sadt_surgmovpred/pipeline.py:57). Se nessun modello può predire dalla tua tabella, l'esecuzione si ferma con un errore invece di produrre file vuoti (pipeline.py:260). Una tabella a cui mancano solo alcune colonne dà comunque meno colonne predette, senza errore.

AutoMatrix

Applica in batch una o più trasformazioni ITK, già calcolate altrove, a una cartella di volumi e file di landmark: nessuna rete, nessun conda, nessuna GPU.

non pubblicato Automatrix_CLI calcolato: nessuna rete senza conda, senza GPU Bibliografia

Applicazione in batch di una o più trasformazioni ITK a una cartella di volumi e file di landmark. Nessuna rete, nessun conda, nessuna GPU: sitk.ReadTransform + sitk.ResampleImageFilter, e un abbinamento file ↔ matrice per suddivisione dei nomi. Tutto il senso di questa pagina sta nelle convenzioni di trasformazione e nello scarto tra ciò che l'interfaccia promette e ciò che la CLI fa davvero.

1. Posizione nella pipeline

AutoMatrix non è chiamato da nessun altro modulo del repository. È però un consumatore dei file .tfm prodotti dai moduli di registrazione:

ProduttoreFile prodottoTipo di trasformazione
AREG_CBCT.py:157 <out>/<Region>/<patient>_OutReg/<patient>_<CB|MAND|MAX><add_name>_matrix.tfm affine / rigida
SEMI_ASO_CBCT.py:111 <patient>_<add_name>_transform.tfm sitk.CompositeTransform (utils.py:732)
AREG_MRI.py:218 <mri>_reg_transform.tfm composita
Review.py:509 e VFACE.py:2249 registrazione + ritocco manuale CompositeTransform([areg, nudge.GetInverse()])
FlexReg_CLI.py:186 <T2><suffix>.tfm affine, già coniugata RAS→LPS e invertita

La casella «From AReg» dell'interfaccia fissa nel codice la convenzione di denominazione di AREG_CBCT (§6), compreso il valore predefinito di un campo di testo appartenente a un altro modulo.

3. Formati di trasformazione letti, e quelli non letti

L'interfaccia (AutoMatrix.py:829) e il README annunciano .npy, .h5, .tfm, .mat, .txt. GetPatients li raccoglie tutti. La CLI poi fa, senza distinzione (Automatrix_CLI.py:258):

try:
    tfm = sitk.ReadTransform(matrix)
except Exception as e:
    logger.error(f"ERROR reading transform {matrix}: {e}")
    continue

sitk.ReadTransform conosce solo le classi TransformIO di ITK. Testato con SimpleITK 2.5.5 di Slicer 5.12:

EstensioneRisultato effettivo
.tfm, .txtOK se e solo se è un Insight Transform File V1.0. Un file di testo che contiene una matrice 4×4 grezza viene rifiutato: ITK ERROR: Tags must be delimited
.h5, .hdf5OK (HDF5TransformIO)
.matOK (MatlabTransformIO)
.npyFallisce: Could not create Transform IO object for reading file
Bug confermato

Il supporto di .npy è quindi rotto: ogni file .npy produce una riga di errore e viene saltato. È una regressione introdotta dal passaggio alla CLI (commit 7bc362b): la versione nel widget leggeva np.load(matrix) e costruiva un vtkMRMLTransformNode (il ramo extension_mat == ".npy", visibile con git show 7bc362b^:AutoMatrix/AutoMatrix.py).

Stessa storia per le «matrici di testo»: non è un formato di matrice, è il formato di testo di ITK.

Una lettura riuscita restituisce una sitk.Transform il cui tipo concreto è preservato: isinstance(tfm, sitk.CompositeTransform) funziona, verificato.

4. La convenzione di trasformazione: il punto che rompe tutto

4.1 Verso della trasformazione

ITK è fixed → moving: una sitk.Transform passata a un ricampionatore mappa il punto fisico di output nel punto fisico di input da campionare. Il contenuto visibile si sposta quindi secondo T⁻¹.

Il codice sfrutta questo su entrambi i lati, ed è coerente:

  • Volumi (Automatrix_CLI.py:209): resampler.SetTransform(transform), la trasformazione è passata così com'è, il contenuto si sposta di T⁻¹.
  • Landmark (Automatrix_CLI.py:181): 
    tfm_inverted = transform.GetInverse()
point['position'] = list(tfm_inverted.TransformPoint(point['position']))
    T⁻¹ è applicata esplicitamente al punto, che si muove quindi come il contenuto del volume.
Verificato

Concetto chiave: lo stesso .tfm applicato a una scansione e ai suoi landmark li sposta con lo stesso movimento. È la proprietà che rende il modulo utilizzabile, ed è anche l'unico punto del codice in cui compare un'inversione.

Insidia

GetInverse() può sollevare RuntimeError (trasformazione non invertibile: campo di spostamento denso, B-spline). Il caso viene intercettato e il file di landmark semplicemente saltato con un avviso: il volume corrispondente, intanto, sarà stato trasformato. I due output possono quindi sfasarsi in silenzio.

4.2 RAS / LPS: dove avviene il ribaltamento, da nessuna parte

In AutoMatrix non c'è alcun ribaltamento. È corretto, ed ecco perché:

  • I file ITK .tfm sono in LPS per costruzione.
  • sitk.ReadImage / WriteImage lavorano in LPS. Entrambe le parti concordano, nulla da fare per i volumi.
  • I file .mrk.json del repository sono fissati su LPS nel codice, ovunque: ALI_CBCT/ALI_CBCT_utils/io.py:39, ALI_IOS/ALI_IOS_utils/io.py:74, mgl_patch.py:184, VFACE/functionaq3dc.py#L1733 e, poiché ASO_CBCT e AREG_CBCT ora riesportano WriteJson anziché portare il proprio, ADTLib/io/landmarks.py:92. È anche il valore predefinito di Slicer in scrittura. Quindi point['position'] è già in LPS, e applicarlo direttamente a una trasformazione ITK è corretto.
Insidia

La parte fragile è che il campo coordinateSystem non viene mai letto. FlexReg lo legge (FlexReg.py:2447); AutoMatrix no. Un json che dichiara "coordinateSystem": "RAS", come scrivono annotazioni più vecchie o altri strumenti, verrà trasformato con x e y di segno sbagliato, senza alcun messaggio. Il file di output manterrà perfino il suo coordinateSystem: RAS originale, poiché il json viene riletto e riscritto così com'è.

Per riferimento, i moduli che producono le matrici fanno da sé il ribaltamento: FlexReg_CLI.py:186 calcola flip @ M @ flip con flip = np.diag([-1,-1,1,1]) e poi inverte, prima di scrivere il .tfm. AutoMatrix consuma il risultato di quel lavoro e non ha quindi nulla da rifare.

4.3 Composizione

Insidia

Non ce n'è. Quando un paziente ha più matrici, il ciclo (Automatrix_CLI.py:256) applica ciascuna al file di input originale, indipendentemente, producendo un output per matrice. Nessuna concatenazione.

L'unica composizione esistente è quella che ITK ha già fatto: un .tfm che contiene più trasformazioni viene riletto come sitk.CompositeTransform e applicato nel suo insieme.

4.4 Harden

Nessuno. Non c'è più alcun vtkMRMLTransformNode nella pipeline. La versione pre-CLI ne creava uno e faceva model.SetAndObserveTransformNodeID(...) poi model.HardenTransform() prima di slicer.util.exportNode(..., world=True). Quell'intero blocco è sparito. Il metodo saveOutput del widget (AutoMatrix.py:843), che chiamava exportNode, c'è ancora ma non viene più chiamato: codice morto.

5. Tipi di dati gestiti

GetPatients raccoglie .vtk .vtp .stl .off .obj .nii .nii.gz .nrrd .mrk.json (Automatrix_CLI.py:77). La CLI distingue poi solo due casi:

is_landmark = scan.endswith(".mrk.json")
...
image = sitk.ReadImage(scan)     # everything else
Bug confermato

Le mesh non vengono più elaborate. Testato: sitk.ReadImage su un vtkPolyData scritto come .vtk fallisce con sitk::ERROR: Unable to determine ImageIO reader. Lo stesso per .stl, .obj, .off, .vtp. L'eccezione viene intercettata (Automatrix_CLI.py:284), registrata come ERROR processing ..., e il file saltato. Eppure l'interfaccia le offre ancora, CheckGoodEntre le convalida, il contatore di avanzamento le conta e README.md:422 annuncia ancora il supporto IOS.

È la seconda regressione dovuta al passaggio alla CLI: la versione nel widget caricava le mesh con slicer.util.loadModel ed eseguiva un vero HardenTransform. Un file .vtk di structured points (un'immagine, non una superficie), invece, passerebbe tramite VTKImageIO.

6. Ricampionamento e immagine di riferimento

resampler.SetInterpolator(sitk.sitkNearestNeighbor if is_seg else sitk.sitkLinear)
resampler.SetDefaultPixelValue(0)
resampler.SetReferenceImage(reference)

L'interpolatore proviene dalla casella «Check this box if using segmentations» (is_seg). Nearest neighbor per una labelmap, lineare negli altri casi: corretto, e spetta all'utente dichiararlo, nulla viene rilevato automaticamente.

La griglia di output è scelta come segue (Automatrix_CLI.py:196 e :301), in ordine di priorità decrescente:

  1. Trasformazione composita → il riferimento è indovinato dal percorso della matrice: matrix.replace("_transform.tfm", ".nii.gz"), con ripiego su .nii. Non è un bug: ASO_CBCT scrive <patient>_<add>_transform.tfm e <patient>_<add>.nii.gz nella stessa cartella, quindi la scansione orientata accanto alla matrice è esattamente la griglia giusta. Se il file manca, viene emesso un avviso e si ripiega sull'immagine di input.
  2. Nome della matrice che contiene mirror (senza distinzione tra maiuscole e minuscole) → il riferimento è forzato all'immagine di input, il file di riferimento dell'interfaccia è ignorato. Smistamento basato sul nome del file.
  3. File di riferimento fornito (reference_file != "None", il valore predefinito del campo, AutoMatrix.ui:255) → la sua geometria è imposta a tutti gli output.
  4. Altrimenti l'immagine di input stessa: dimensione, spaziatura, origine e direzione invariate. Una trasformazione che sposta contenuto fuori dal campo di vista lo fa scomparire, riempito con DefaultPixelValue = 0.
Bug confermato

Il ramo reference is None di ResampleImage (Automatrix_CLI.py:220) è irraggiungibile: il chiamante passa sempre un riferimento. È anche sbagliato: fa new_origin = transform.TransformPoint(image.GetOrigin()) quando la convenzione del ricampionatore richiederebbe T⁻¹.

7. Modalità Mirror

Mirror() (AutoMatrix.py:307) scarica Mirror.zip da una release GitHub personale (GaelleLeroux/DCBIA_Apply_matrix), lo decomprime in <Documents>/SlicerDownloads/Mirror_matrix/ e compila il campo della matrice con Mirror/Matrix_mirror.tfm. Il contenuto effettivo del file:

#Insight Transform File V1.0
Transform: AffineTransform_double_3_3
Parameters: -1 0 0 0 1 0 0 0 1 0 0 0
FixedParameters: 0 0 0
Insidia

È diag(-1, 1, 1) in LPS, centrata nell'origine: una riflessione rispetto al piano x_LPS = 0. Poiché x_LPS punta verso la sinistra del paziente, è davvero uno scambio sinistra/destra, ma rispetto al piano sagittale dell'origine del sistema del mondo, non al piano sagittale del paziente. Un paziente non centrato esce traslato oltre che speculare, il che una registrazione successiva deve correggere.

Il determinante è −1. Per un volume, ResampleImageFilter lo gestisce senza alcun problema. Per una mesh, capovolgerebbe l'orientamento delle facce e le normali: questione irrilevante qui poiché le mesh non vengono più elaborate.

La modalità forza ComboBoxMatrix su «File», il suffisso su _mir, e deseleziona checkBoxMatrixName.

8. Abbinamento file ↔ matrice

GetPatients (Automatrix_CLI.py:65) costruisce {patient_key: {'scan': [...], 'matrix': [...]}}. La chiave si ottiene tramite una catena di chiamate .split() che non è la stessa sui due lati:

Token rimossi (in ordine)
scansione_Seg _seg _Scan _scan _Or _OR _MAND _MD _MAX _MX _CB _lm _T2 _T1 _Cl _MR, poi .split('.')[0], poi _T0…_T49
matrice_SegOr _Left _left _Right _right _Or _OR _MAND _MD _MAX _MX _CB _lm _T2 _T1 _Cl _MA _Mir _mir _Mirror _mirror _MR, poi .split('.')[0], poi _T0…_T49
Insidia

Gli elenchi divergono: il lato della matrice rimuove _MA, _Left/_Right, le varianti _Mir e _SegOr; il lato della scansione rimuove _Seg, _Scan, _lm. Da qui il requisito del README: prima il nome del paziente, un underscore, poi il resto. L'esempio patient1_T1_MA.nii.gz ↔ patient1_left_MA.tfm funziona perché _T1 viene tolto sul lato della scansione e _left su quello della matrice. Ma patient1_MA.nii.gz senza indicatore temporale dà la chiave patient1_MA sul lato della scansione e patient1 su quello della matrice: nessuna matrice verrà abbinata, senza alcun messaggio.

Quando il percorso della matrice è un file anziché una cartella, viene collegato a ogni paziente (Automatrix_CLI.py:172).

Bug confermato

Codice duplicato che è già divergente. GetPatients esiste in due copie identiche tranne che per un token: la versione della CLI elimina un _SegOr iniziale, General_tools.py:11 no. Ed è la copia di General_tools ad alimentare NbScan, quindi il denominatore della barra di avanzamento può differire dal numero di file effettivamente elaborati.

Il percorso «From AReg»

suffix_map (Automatrix_CLI.py:232) aggira tutta la logica di abbinamento per i file di landmark:

suffix_map = {
    "_CB": ("Cranial Base", "CBReg_matrix.tfm"),
    "_L":  ("Maxilla",      "MAXReg_matrix.tfm"),
    "_U":  ("Mandible",     "MANDReg_matrix.tfm"),

matrix_path = os.path.join(args.matrix_lineEdit, subdir,
                           f"{patient_id}_OutReg", f"{patient_id}_{matrix_filename}")
Bug confermato

Tre problemi, tutti verificabili:

  1. _L e _U sono scambiati rispetto alla convenzione usata nel resto del repository. AREG_IOS/AREG_IOS_utils/dataset.py:222 e AREG/AREG_Method/IOS.py:117 definiscono Lower = ["Lower", "_L", "L_", "Mandibule", "Md"] e Upper = ["Upper", "_U", "U_", "Maxilla", "Mx"]. Qui _L punta a Maxilla e _U a Mandible.
  2. matrix_lineEdit non esiste nell'argparse della CLI (Automatrix_CLI.py:294: gli argomenti sono input_patient, input_matrix, reference_file, suffix, matrix_name, fromAreg, output_folder, log_path, is_seg). Questo ramo solleva quindi AttributeError non appena viene imboccato.
  3. Non viene mai imboccato: CheckBoxSuffixBased (etichettata «From AReg») è nascosta in setup da self.ui.CheckBoxSuffixBased.setVisible(False) (AutoMatrix.py:298), quindi fromAreg vale sempre "False". Codice morto, il che spiega perché 1 e 2 non sono mai stati notati.

Il nome MAXReg_matrix.tfm corrisponde comunque alla realtà di AREG_CBCT: scrive patient + "_" + reg_type + add_name + "_matrix.tfm" con add_name predefinito Reg (AREG.ui:571), quindi questo percorso dipende dal valore predefinito di un campo di testo modificabile appartenente a un altro modulo.

11. Ambiente

Nulla da installare: SimpleITK, numpy, vtk, qt sono già in Slicer. Niente conda, niente CUDA. L'unico accesso alla rete è il download della matrice speculare, e solo se la casella Mirror è selezionata.

Bug confermato

La barra di avanzamento non è alimentata da un file di log nonostante il parametro log_path: DisplayAutomatrix.isProgress (Progress.py:40) controlla l'mtime di log_path, ma la CLI non scrive mai su quel file. L'avanzamento passa in realtà dalla sequenza <filter-progress>0 / 2 / 0</filter-progress> emessa dalla CLI dopo ogni scansione (Automatrix_CLI.py:287) e dall'if kwds["progress"] == 200 in isProgress: un protocollo indiretto e fragile che dipende da un time.sleep(0.2) tra ogni stampa.

12. Insidie e punti fragili

Riepilogo
  • .npy non funziona (§3), anche se annunciato dall'interfaccia e dal README.
  • Le mesh non funzionano più (§5), anche se annunciate dall'interfaccia e dal README. Regressione dal commit 7bc362b.
  • .txt non accetta una matrice 4×4 grezza (§3), solo il formato di testo di ITK.
  • Il coordinateSystem dei landmark non viene mai letto (§4.2).
  • Nessuna composizione: N matrici per un paziente danno N file, non una catena (§4.3).
  • Output sovrascritti se checkBoxMatrixName è deselezionata con più matrici (§9).
  • OnEndProcess divide per self.nb_scans (AutoMatrix.py:745) senza alcuna protezione: una cartella di input vuota causa uno ZeroDivisionError al termine dell'elaborazione.
  • CheckGoodEntre è logicamente sbagliata (AutoMatrix.py:790): il test sull'estensione è len(dico['.vtk'])==0 and len(dico['.vtp']) and len(dico['.stl']) and …, dove solo il primo termine è un confronto. Gli altri sono interi valutati come booleani, quindi l'avviso «Folder empty or wrong type» scatta solo in una congiunzione improbabile. Una cartella davvero vuota supera la validazione.
  • onPredictButton non si ferma in caso di errore: TestProcess restituisce una tupla (ok, out), quindi il controllo isinstance(error, str) a AutoMatrix.py:748 è sempre falso, e l'elaborazione parte anche con campi vuoti.
  • .split(extension_scan)[0] taglia alla prima occorrenza: un percorso la cui cartella contiene la stessa sottostringa dell'estensione verrebbe troncato.
  • Landmark non defined lasciati nel vecchio sistema di coordinate, mescolati a punti trasformati nello stesso file (§5).
  • Il percorso «From AReg», morto e rotto (§8).
  • Codice morto: saveOutput / UpdateProgressBar / UpdateTime del widget, AutoMatrixLogic.process, ResampleImage con il suo ramo reference is None, registerSampleData che fa riferimento a file .png mancanti.
  • I metadati di Automatrix_CLI.xml sono ancora quelli del template di Slicer (FirstName LastName (Institution), NIH grant NXNNXXNNNNNN-NNXN).

13. Letteratura

Nessun articolo copre AutoMatrix: è un'utilità di applicazione in batch scritta per il laboratorio (Gaëlle Leroux, UoM/DCBIA). Il contenuto scientifico sta interamente nei moduli che producono le matrici, AREG, ASO, MRI2CBCT, FlexReg, ed è trattato nelle rispettive pagine.

Uso di VISOR: eseguire gli strumenti su un server da 3D Slicer

Con VISOR, il calcolo non gira più sul tuo computer. Scegli uno strumento in Slicer, i file che selezioni vengono inviati a un server, il server calcola e il risultato torna nella tua scena. Questa pagina spiega che cosa devi configurare, che cosa devi fornire e che cosa controllare prima di inviare dati di pazienti. Come è costruito VISOR è spiegato nell’Atlante di VISOR.

client: implementato e testato de-identificazione: non implementata MRI2CBCT: non distribuito
Prima di usare dati di pazienti

Il client VISOR invia i tuoi file così come sono su disco. Nulla viene de-identificato. Vedi Che cosa lascia il tuo computer.

Che cosa cambia per te

Il resto di questo sito descrive l’estensione legacy, SlicerAutomatedDentalTools: ogni modulo gira sul tuo computer. VISOR è un’estensione Slicer diversa, AutomatedDentalToolsRemote. I suoi moduli sono pannelli sottili su un server remoto.

  • Il calcolo lascia il tuo computer. Un portatile che non riesce a eseguire una segmentazione può comunque richiederla.
  • Nulla da installare nel Python di Slicer, e nessun modello da scaricare: l’estensione non dichiara alcuna dipendenza da altre estensioni, e i modelli stanno sul server.
  • Il modulo di compilazione viene dal server. Il pannello di uno strumento viene costruito quando lo apri, dalla descrizione che il server pubblica. Un campo aggiunto sul server compare in Slicer senza una nuova versione dell’estensione.
  • Ti servono un server, un indirizzo e una chiave. Configurarne uno è un tema del server, non di questa pagina; vedi distribuzione.

Fonti: AutomatedDentalToolsRemote CMakeLists.txt:10,15 e README.md:3-8, 150-165 (commit 19b95e8).

Installare l'estensione

Il README e il file di build dicono quanto segue, e qui non si presume nient'altro.

  • L’estensione è AutomatedDentalToolsRemote. Funziona con le versioni stabile e nightly di 3D Slicer, e i suoi moduli compaiono nella categoria Automated Dental Tools Remote.
  • Non elenca alcuna dipendenza da altre estensioni (EXTENSION_DEPENDS "NA"): non servono SlicerConda, SlicerDentalModelSeg né NNUNet.
  • Il README afferma che è elencata nell'Extensions Catalog durante la transizione.
  • Non installarla accanto all’estensione legacy. Il README chiede di usare l’una o l’altra, perché molti moduli condividono i nomi e Slicer ne tiene solo uno tra due moduli con lo stesso nome.

Collegare Slicer a un server

Apri Server Tools Settings (categoria Automated Dental Tools Remote.Advanced). Finché non salvi qualcosa qui, l’indirizzo è un segnaposto (https://set-your-server.invalid) che non raggiunge nulla, quindi nessun file lascia il tuo computer.

Da fornire

  • URL del server: un indirizzo https:// il cui certificato è firmato da un’autorità pubblica.
  • Chiave API: il token API del server (il campo è mascherato). Il README dice di usare il token API, mai il token di amministrazione.
  • Timeout: da 1 a 3600 secondi, 600 per impostazione predefinita.

Che cosa non puoi cambiare

  • Niente http://, nemmeno http://localhost.
  • Il certificato viene sempre controllato: il pannello mostra «Verify TLS: Always on», senza nulla da spuntare.
  • I reindirizzamenti non vengono mai seguiti.

Fai clic su Save. La modifica si applica subito e viene conservata tra i riavvii. Se digiti un indirizzo http://, Slicer lo rifiuta prima di salvare qualsiasi cosa. Restore defaults cancella quanto hai salvato.

Un server sul tuo computer segue la stessa regola: il client non accetta il certificato autofirmato del server stesso, quindi lo si raggiunge tramite un indirizzo pubblico, per esempio un indirizzo tailscale serve (https://<name>.<tailnet>.ts.net), oppure un reverse proxy con un certificato Let's Encrypt o istituzionale.

Il server è raggiungibile? Non c’è un pulsante «Test connection». Il pannello mostra in alto una riga «Server: online» o «Server: offline», aggiornata quando apri il modulo e dopo ogni salvataggio. Interroga solo la pagina /health del server, che non richiede alcuna chiave: «online» non dimostra che la tua chiave sia accettata. Una chiave sbagliata emerge alla prima esecuzione (vedi Se qualcosa va storto).

La chiave è conservata in chiaro

Slicer salva la chiave nel proprio file di impostazioni per il tuo utente, come testo semplice. Il campo mascherato la nasconde solo a schermo. Chiunque possa leggere le tue impostazioni di Slicer può leggere la chiave.

HTTPS non ha alternative

Non esiste alcuna impostazione, opzione o file che allenti la regola HTTPS o il controllo del certificato. Un indirizzo http:// salvato da una versione precedente del client viene ignorato all’avvio.

Eseguire uno strumento

  1. Scegli uno strumento nell’elenco dei moduli. Costruisce il proprio modulo di compilazione dal server all’apertura. Se il server non è raggiungibile, il pannello dice che non è riuscito a caricare lo strumento e offre un pulsante Retry.
  2. Compila il modulo. Ciò che fornisci dipende dallo strumento; i nomi dei campi vengono dal server, quindi leggi la pagina della Guida di ciascuno strumento.
  3. Premi Apply. Il pannello controlla prima il modulo (argomento sconosciuto, file mancante, campo obbligatorio mancante) prima che venga inviato qualsiasi cosa.
  4. Segui l’avanzamento e annulla se serve.

Che cosa puoi dare in input

  • Un file viene inviato così com’è, stesso nome e stessi byte.
  • Una cartella viene impacchettata in un archivio che conserva i nomi dei file e delle sottocartelle, poi inviata.
  • Un nodo della scena di Slicer (un volume, un modello, una regione di interesse) viene esportato in un file temporaneo, denominato in base allo strumento e all’argomento, non al nodo. AutoCrop3D, per esempio, prende così la propria regione di interesse dalla scena.
  • Un file di prova ospitato è un campione che il server offre per lo strumento. Sceglierne uno lo scarica prima (in background, la finestra di Slicer resta utilizzabile), poi lo usa come input. Una seconda scelta della stessa voce nella stessa sessione riusa il download.
  • Un modello scelto sul server viene selezionato per nome da un elenco che il server pubblica. Viaggia solo il nome; il file del modello non viene mai inviato dal tuo computer. Se l’elenco è vuoto e l’argomento non può essere fornito in altro modo, il pannello mostra un avviso invitando a rivolgersi al responsabile del server.

Gli input di grandi dimensioni vengono inviati a parti e controllati parte per parte. Se il server pubblica un piano di dimensioni per una cartella di coorte, il pannello la divide in batch, ciascuno dei quali è un’esecuzione ordinaria.

Avanzamento, annullamento, connessione persa

  • Il pannello riporta le fasi proprie del server: richiesta ricevuta, preparazione dei file di input, attesa della GPU, esecuzione sul server, impacchettamento dei risultati, terminato. Accanto scorre il tempo trascorso. Un’esecuzione in coda mostra «queued».
  • Cancel ferma l’esecuzione anche sul server. C’è un Cancel per esecuzione; con più esecuzioni diventa «Cancel all», e una coorte «Cancel the cohort». Un’esecuzione annullata non viene segnalata come errore.
  • Se la connessione cade mentre il server lavora, il pannello si ricollega da solo al flusso di avanzamento e riprende da dove era rimasto, senza ripetere ciò che aveva già mostrato. È la modalità detached, attiva per impostazione predefinita: la richiesta termina appena gli input sono predisposti e il risultato arriva sul flusso di avanzamento, quindi il timeout nelle impostazioni non limita più la durata di un’esecuzione.
Fermarsi per la revisione usa la modalità bloccante

Se attivi un passo «stop after» (vedi Revisione della qualità), l’esecuzione non usa la modalità detached: il server restituisce il materiale di revisione nella risposta alla richiesta originale. In quel caso vale il timeout di Server Tools Settings, e una connessione persa fa perdere la risposta.

Ottenere i risultati

  • Quando l’esecuzione termina, il pannello scarica il risultato (a intervalli paralleli), controlla l’archivio e lo decomprime nella cartella di output. Per impostazione predefinita quella cartella è «Slicer Output» in Documenti.
  • Un archivio viene rifiutato prima di scrivere qualsiasi cosa se contiene percorsi assoluti, .., collegamenti, più di 100 000 voci o più di 20 GB.
  • La casella «Load the results into the scene when done» importa ciò che lo strumento ha prodotto: volumi, mappe di etichette, modelli o landmark, a seconda dello strumento. Per impostazione predefinita vengono caricati al massimo 12 elementi; oltre, il pannello ti dice che sono troppi per essere caricati in una volta.
  • Alcuni strumenti aggiungono opzioni o messaggi propri: ALI riassume il proprio rapporto di esecuzione e chiede conferma oltre i 20 file di landmark; VFACE ha una casella «Load the heat maps»; AutoMatrix ha una casella «Use the mirror matrix». CNE non carica nulla nella scena e mostra un riepilogo nella barra di stato.
  • La copia del risultato sul server viene eliminata dopo il tuo download.

Revisione della qualità con VISU

Alcuni strumenti possono fermarsi dopo un passo perché tu controlli il risultato intermedio. Il modulo di compilazione mostra allora una sezione «Quality control» con una scelta multipla stop_after; nulla è selezionato per impostazione predefinita. La offrono gli strumenti che ne chiamano altri, per esempio ALI per le scansioni intraorali o VFACE.

  1. Ferma. Il server si mette in pausa dopo il passo che hai selezionato. Il pannello mostra «Stopped after <step>, waiting for your review», scarica quanto prodotto finora e vi apre VISU.
  2. Rivedi. VISU mostra un paziente alla volta: scansione, maschere, superfici e landmark insieme. I tasti freccia passano al caso precedente o successivo. Usa Flag per contrassegnare un paziente e Go to next flagged per saltare. Leggi la riga «Drawn on <scan>» (dice su quale scansione sono disegnati i landmark, e se è stata trovata accanto ai punti o presunta).
  3. Correggi. Per i landmark puoi trascinare i punti e Save: vengono riscritti solo i punti che hai spostato, abbinati per nome. Undo my changes e Revert to what is on disk li ripristinano. Un aggiustamento di registrazione viene salvato come file di trasformazione separato accanto alla scena, mai fuso con la trasformazione propria dello strumento.
  4. Continua. Vengono rimandati indietro solo i file il cui contenuto è cambiato, poi il server riprende l’esecuzione.
  5. Torna indietro. Quando un passo precedente può essere corretto (landmark o registrazione), il flag dice «Go back and edit this patient». Dopo che ne hai contrassegnati alcuni, il pulsante verde dice «Go back to <step> for N patient(s)»: le tue correzioni vengono scritte, i pazienti contrassegnati vengono rifatti da quel passo, e tutti gli altri conservano il risultato che hanno già.

Se VISU non si trova, o l’arresto non ha prodotto nulla da guardare, il pannello lo dice e riprende subito l’esecuzione, così che nulla resti in pausa sul server con i tuoi dati dentro.

VISU funziona anche su una cartella qualsiasi

Puoi aprire VISU su qualsiasi cartella scritta da uno strumento, senza alcun server coinvolto: abbina per nome di file la scansione, le maschere, le superfici e i landmark di ciascun paziente. L’unica cosa che preleva da un server sono i dataset di esempio ospitati.

Che cosa lascia il tuo computer

Nulla viene de-identificato

Oggi in VISOR non esiste alcuno strumento di de-identificazione. Ciò che selezioni viene inviato al server così com’è su disco: nomi dei file, intestazioni DICOM e ogni identificativo che portano. Una pipeline di de-identificazione è specificata nel repository del client, ma il suo README afferma che non è implementata, e una ricerca nel codice non ne trova alcuna implementazione.

  • L’avviso. Dopo che hai salvato un indirizzo di server che non è questo computer, Slicer mostra una volta per server: «Files are uploaded unmodified. This client does not de-identify anything... De-identify your data before selecting it, or confine use to data that carries no protected health information.» È un avviso, non un controllo: non ferma nulla.
  • Le cartelle conservano i loro nomi. Una cartella viene impacchettata con i nomi originali dei suoi file e delle sue sottocartelle. Un nodo della scena viene esportato con un nome generico, quindi il nome del nodo non esce.
  • CNE invia note cliniche. Il modello di testo gira sul server: le note salgono e le estrazioni tornano. La pagina CNE legacy, che dice che nulla lascia il tuo computer, non vale per VISOR.
  • Solo trasporto. HTTPS protegge il trasferimento. Non c’è alcuna cifratura dei file oltre a questa sul lato client.
  • Il Medical Data Anonymizer esiste ancora, ma tratta documenti di testo su questo computer e non fa parte di ciò che viene inviato.
  • Punta il client solo a un server controllato dalla tua istituzione, e verifica che l’accordo con chi lo gestisce copra i dati che invii. Lo chiede anche il README.

Il quadro della sicurezza, compreso ciò che il server protegge e ciò che non protegge, è in Sicurezza di VISOR.

Se qualcosa va storto

Per la maggior parte dei guasti, Slicer mostra il messaggio stesso del server. Ecco che cosa significa ciascuno.

«The server URL must start with https://»

Hai digitato un indirizzo http://, oppure Slicer ne ha trovato uno di una versione precedente. Usa l’indirizzo pubblico https://; non c’è modo di aggirare la regola, nemmeno per un server sul tuo computer.

401: autenticazione fallita

La chiave è sbagliata o mancante. Il pannello può comunque dire «Server: online» perché la pagina di stato non richiede alcuna chiave. Reinserisci la chiave in Server Tools Settings e premi Save.

503 durante una finestra di manutenzione

Mentre il server viene aggiornato, rifiuta nuovo lavoro con un 503 e un’intestazione Retry-After: 10, per al massimo 300 secondi. Il client non legge quell’intestazione: vedi il messaggio del server, oppure «Server error (503)». Aspetta e premi di nuovo Apply. La lettura dei risultati già in corso non è bloccata.

422: argomenti non validi

Il server indica l’argomento in difetto, per esempio un’opzione al di fuori dell’elenco accettato. Correggi il campo che indica. Un «400» con un messaggio sul tipo di file significa che l’estensione del file non è accettata da quello strumento.

413: file troppo grande

Il server rifiuta un caricamento oltre il proprio limite, 500 MB per file per impostazione predefinita. Per una coorte grande, fornisci una cartella anziché un unico archivio enorme, così che possa essere divisa in batch.

500: «The tool failed on the server»

È tutto ciò che il client mostra per un crash dentro uno strumento, di proposito: i dettagli potrebbero contenere elementi interni del server. Chiedi a chi gestisce il server di leggerne il log.

  • Timeout. Il timeout in Server Tools Settings (600 s per impostazione predefinita) si applica alle richieste che restano aperte. In modalità detached, che è quella predefinita, un’esecuzione lunga non viene interrotta da esso. Il server non ha alcun limite di tempo di esecuzione per impostazione predefinita.
  • Attesa in coda. Un’esecuzione può attendere la GPU: il pannello dice «Waiting for the GPU», e puoi annullare mentre attende. Il server limita anche quante esecuzioni girano contemporaneamente, quindi una quinta esecuzione può attendere prima ancora di comparire come in coda.
  • Server offline. Se l’elenco degli strumenti non può essere caricato, il pannello lo dice e mostra Retry. Controlla l’indirizzo e «Server: online» in Server Tools Settings.
  • Una modifica in config.py non ha effetto. Ciò che hai salvato in Server Tools Settings prevale sempre sui valori predefiniti compilati.

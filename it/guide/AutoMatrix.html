AutoMatrix: applicare una matrice a un intero batch di file

AutoMatrix applica in un solo passaggio una o più matrici di trasformazione ITK a un'intera cartella di volumi e di file di landmark. Nessuna rete neurale, nessuna GPU: è uno strumento batch, non un passo di calcolo, e la matrice proviene da una registrazione eseguita altrove.

Due modi di eseguirlo

Questa pagina descrive il modulo Slicer legacy. Per usarlo tramite un server VISOR: vedi Con VISOR e Uso di VISOR.

Quando usarlo

Hai eseguito un modulo di registrazione (AREG, ASO, FlexReg…) e ne hai ottenuto una matrice di trasformazione (.tfm). Ora vuoi applicare la stessa matrice ad altri file dello stesso paziente, una segmentazione, un secondo volume, un insieme di landmark, senza aprirli uno per uno a mano in Slicer. Oppure hai eseguito quella registrazione su un'intera serie di pazienti e vuoi elaborare tutta la cartella in un colpo solo. A questo serve AutoMatrix: non registra nulla da sé, riproduce una trasformazione che hai già calcolato.

Una matrice, un movimento

Vale anche in VISOR. Il server sposta i punti dei landmark attraverso l’inversa della trasformazione, così una scansione e i suoi landmark conservano lo stesso movimento relativo.

Applicata a un volume, la matrice ne sposta il contenuto. Applicata a un file di landmark, sposta i punti con esattamente lo stesso movimento. È ciò che mantiene allineati una scansione e i suoi landmark dopo il passaggio in AutoMatrix: purché si usi la stessa matrice per entrambi.

Come file e matrici vengono abbinati

AutoMatrix non ti chiede mai di indicare a mano quale matrice va con quale paziente. Deduce l'abbinamento confrontando i nomi dei file: toglie da quello della scansione un elenco di parole chiave note (_Seg, _Or, _MAND, _CB, un indicatore temporale come _T1, _T2…), e un elenco leggermente diverso da quello della matrice, finché da ciascun lato resta un identificativo paziente. Se i due identificativi coincidono, file e matrice vengono abbinati.

Il problema: quei due elenchi di parole chiave non sono identici. La regola che funziona in modo affidabile: inizia ogni nome di file con l'identificativo del paziente, poi un underscore, poi tutto ciò che ti serve. Esempio che funziona: patient1_T1_MA.nii.gz e patient1_left_MA.tfm si riducono entrambi a patient1, perché _T1 viene tolto sul lato della scansione e _left sul lato della matrice. Esempio che fallisce: patient1_MA.nii.gz, senza indicatore temporale, si riduce a patient1_MA sul lato della scansione ma a patient1 sul lato della matrice; i due non coincidono più e quel file non riceve alcuna matrice.

C'è una scorciatoia: indica un solo file di matrice, anziché una cartella, e verrà applicato così com'è a ogni paziente della cartella di input, senza bisogno di abbinare i nomi.

Di che cosa ha bisogno, che cosa ottieni

Da fornire

  • Una cartella di volumi in formato .nii, .nii.gz o .nrrd, e/o file di landmark di Slicer (.mrk.json)
  • Una matrice ITK (.tfm, .h5 o .mat), oppure una cartella di matrici denominate secondo la stessa regola delle scansioni
  • Selezionala se i tuoi volumi sono segmentazioni: la casella apposita, perché le etichette non vengano sfumate dall'interpolazione
  • Facoltativo: un file di riferimento per imporre la griglia di output (dimensione, orientamento)

Che cosa ne esce

  • Una copia trasformata di ogni file abbinato, organizzata nella stessa struttura di cartelle dell'input
  • I tuoi file originali non vengono mai modificati
  • In un file di landmark vengono spostati solo i punti contrassegnati come definiti
  • Non viene mai prodotta una nuova matrice: AutoMatrix consuma trasformazioni, non le scrive

Passi

  1. Indica la cartella di input. Scansioni e/o file di landmark da trasformare; l’intera cartella viene elaborata in un colpo solo.
  2. Indica la matrice, oppure una cartella di matrici. Verifica che i nomi seguano la regola paziente + suffisso descritta sopra, oppure punta direttamente a un solo file per applicarlo a tutti.
  3. Seleziona la casella delle segmentazioni se i tuoi volumi sono labelmap.
  4. Fornisci un file di riferimento se vuoi imporre la griglia di output; altrimenti ogni file mantiene la griglia del proprio volume di input, e tutto ciò che la trasformazione spinge fuori dal campo di vista va perso.
  5. Scegli un suffisso di output e decidi se il nome della matrice debba esservi aggiunto: è necessario non appena un paziente ha più di una matrice (vedi sotto).
  6. Imposta una cartella di output, poi eseguilo. Una barra di avanzamento segue i file mentre vengono elaborati.

Ribaltare destra/sinistra senza cercare una matrice

Se ti serve solo uno specchio destra/sinistra, non occorre costruire una matrice propria: la modalità Mirror scarica una matrice di riflessione già pronta e la inserisce da sola nel campo della matrice, con un proprio suffisso di output (_mir).

Lo specchio non è centrato sul tuo paziente

Modulo legacy (3c67957). Diverso in VISOR. La matrice di specchio è il file ospitato dal server, applicato tramite la casella Use the mirror matrix. Il pannello non offre un volume di riferimento e, senza di esso, la griglia di output di VISOR segue la trasformazione; per una riflessione rispetto all’origine del mondo, il risultato può restare vuoto. Vedi Con VISOR.

La riflessione avviene attraverso il piano sagittale dell'origine della scena, non attraverso il piano sagittale del paziente stesso. Se il paziente non è già centrato nella scena, il risultato esce sia specchiato sia spostato: prevedi un passaggio di registrazione successivo per correggere lo scarto.

Se qualcosa non va

Alcuni formati dichiarati non funzionano più

Modulo legacy (3c67957). In parte cambiato in VISOR. Il pannello VISOR non offre più mesh né matrici .npy, e nulla le conta. Un file .txt con una semplice matrice 4x4 vi è accettato.

L'interfaccia offre ancora le mesh (.vtk, .vtp, .stl, .off, .obj) come scansioni di input per le superfici intraorali, e le matrici come .npy; entrambe vengono contate nella barra di avanzamento, ma nessuna produce un output: ogni file di quel tipo viene semplicemente saltato, con una riga nel log degli errori. Una matrice .txt funziona solo se è un vero file di trasformazione ITK, non un semplice array 4×4.

Un abbinamento fallito non dà alcun avviso

Modulo legacy (3c67957). Diverso in VISOR. I file e le trasformazioni rimasti senza coppia sono indicati in AutoMatrix_report.json (without_a_transform, transforms_without_a_file), e un’esecuzione che non scrive nulla si ferma con un errore. La riga di stato in Slicer non li mostra, vedi Con VISOR.

Se il nome di una scansione e quello di una matrice non si riducono allo stesso identificativo paziente (vedi sopra), quel file semplicemente non viene mai trasformato: nessun messaggio di errore, nessun avviso visibile. Se un paziente manca dall'output, la prima cosa da controllare sono i nomi dei suoi file.

Un output può sovrascriverne un altro

Modulo legacy (3c67957). Non è così in VISOR: quando un paziente ha più trasformazioni, ogni output prende il nome della propria trasformazione, qualunque cosa dica l’opzione.

Se deselezioni l'opzione che aggiunge il nome della matrice al file di output, e un paziente ha più di una matrice, ogni risultato riceve lo stesso nome di file: ciascuno sovrascrive il precedente e sopravvive solo l'ultima matrice elaborata. Lascia selezionata questa opzione ogni volta che applichi più di una matrice per paziente.

Un file di landmark può sparire in silenzio

Modulo legacy (3c67957). In parte cambiato in VISOR. Il fallimento viene scritto sotto quel paziente nel rapporto anziché in una riga di log, e il volume del paziente viene comunque prodotto, quindi scansione e landmark possono ancora non coincidere. Controlla il rapporto.

Alcune trasformazioni (campi di deformazione densi, B-spline) non possono essere invertite matematicamente. In tal caso, il file di landmark corrispondente viene saltato con un semplice avviso nel log, mentre il volume stesso viene comunque trasformato, quindi una scansione e i suoi landmark possono finire fuori sincronia senza nulla a schermo che lo segnali.

Le matrici non vengono concatenate

Vale anche in VISOR. Ogni trasformazione viene applicata al file originale.

Quando un paziente ha più matrici, ciascuna viene applicata separatamente al file di input originale: ottieni un file di output per matrice, mai la composizione dell'una dopo l'altra.

Come citare

Nessuna pubblicazione, e nulla da pubblicare: il modulo applica in batch matrici di trasformazione ai file. Conta sapere che cos'è una matrice in Slicer e in quale sistema di coordinate si trova.

Nulla descrive il modulo in sé, quindi cita l'estensione come software:

SlicerAutomatedDentalTools. DCBIA-OrthoLab. https://github.com/DCBIA-OrthoLab/SlicerAutomatedDentalTools

Aggiungi la data di accesso se lo stile della tua rivista la richiede.

  • Documentation 3D Slicer: Coordinate systems. RAS, LPS, e perché una matrice corretta applicata nel sistema sbagliato capovolge il paziente.

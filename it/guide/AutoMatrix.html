AutoMatrix: applicare una matrice a un intero batch di file

AutoMatrix applica una o più matrici di trasformazione ITK a un'intera cartella di volumi e file di landmark in un unico passaggio. Nessuna rete neurale, nessuna GPU: è uno strumento batch, non una fase di calcolo; la matrice stessa proviene da una registrazione eseguita altrove.

Quando usarlo

Hai eseguito un modulo di registrazione (AREG, ASO, FlexReg…) e ne hai ricavato una matrice di trasformazione (.tfm). Ora vuoi applicare quella stessa matrice ad altri file dello stesso paziente, una segmentazione, un secondo volume, un insieme di landmark, senza aprire ciascuno a mano in Slicer. Oppure hai eseguito quella registrazione su un'intera serie di pazienti e vuoi elaborare l'intera cartella in un colpo solo. A questo serve AutoMatrix: non registra nulla da solo, riesegue una trasformazione che hai già calcolato.

Una matrice, un movimento

Applicata a un volume, la matrice ne sposta il contenuto. Applicata a un file di landmark, sposta i punti esattamente con lo stesso movimento. È ciò che mantiene allineati una scansione e i suoi landmark dopo il passaggio da AutoMatrix: purché usi la stessa matrice per entrambi.

Come file e matrici vengono abbinati

AutoMatrix non ti chiede mai di indicare a mano quale matrice va con quale paziente. Indovina l'abbinamento confrontando i nomi dei file: toglie da quello della scansione un elenco di parole chiave note (_Seg, _Or, _MAND, _CB, un indicatore temporale come _T1, _T2…), e un elenco leggermente diverso da quello della matrice, fino a ottenere un identificatore di paziente su ciascun lato. Se i due identificatori coincidono, file e matrice sono abbinati.

Il problema: quei due elenchi di parole chiave non sono uguali. La regola che funziona in modo affidabile: comincia ogni nome di file con l'identificatore del paziente, poi un underscore, poi tutto ciò che ti serve. Esempio che funziona: patient1_T1_MA.nii.gz e patient1_left_MA.tfm si riducono entrambi a patient1, perché _T1 viene tolto sul lato della scansione e _left su quello della matrice. Esempio che fallisce: patient1_MA.nii.gz, senza indicatore temporale, si riduce a patient1_MA sul lato della scansione ma a patient1 su quello della matrice, i due non coincidono più, e quel file non riceve alcuna matrice.

Esiste una scorciatoia: indica un singolo file di matrice, anziché una cartella, e verrà applicato così com'è a ogni paziente della cartella di input, senza bisogno di abbinare i nomi.

Di che cosa ha bisogno, che cosa ottieni

Da fornire

  • Una cartella di volumi in .nii, .nii.gz o .nrrd, e/o file di landmark di Slicer (.mrk.json)
  • Una matrice ITK (.tfm, .h5 o .mat), oppure una cartella di matrici denominate secondo la stessa regola delle scansioni
  • Seleziona questa opzione se i tuoi volumi sono segmentazioni: l'apposita casella, perché le etichette non vengano smussate dall'interpolazione
  • Facoltativo: un file di riferimento per imporre la griglia di output (dimensione, orientamento)

Che cosa ne esce

  • Una copia trasformata di ogni file abbinato, organizzata nella stessa struttura di cartelle dell'input
  • I tuoi file originali non vengono mai modificati
  • In un file di landmark vengono spostati solo i punti contrassegnati come definiti
  • Non viene mai prodotta alcuna nuova matrice: AutoMatrix consuma trasformazioni, non le scrive

Passi

  1. Indica la cartella di input. Scansioni e/o file di landmark da trasformare; l'intera cartella viene elaborata in un colpo solo.
  2. Indica la matrice, o una cartella di matrici. Verifica che i nomi seguano la regola paziente + suffisso descritta sopra, oppure punta direttamente a un solo file per applicarlo a tutti.
  3. Seleziona la casella delle segmentazioni se i tuoi volumi sono labelmap.
  4. Fornisci un file di riferimento se vuoi imporre la griglia di output; altrimenti ogni file mantiene la griglia del proprio volume di input, e tutto ciò che la trasformazione spinge fuori dal campo di vista va perso.
  5. Scegli un suffisso di output e decidi se il nome della matrice debba esservi aggiunto: necessario non appena un paziente ha più di una matrice (vedi sotto).
  6. Imposta una cartella di output, poi eseguilo. Una barra di avanzamento segue i file man mano che vengono elaborati.

Invertire sinistra/destra senza cercare una matrice

Se ti serve solo uno specchio sinistra/destra, non occorre costruire una matrice propria: la modalità Mirror scarica una matrice di riflessione già pronta e la inserisce per te nel campo della matrice, con un proprio suffisso di output (_mir).

Lo specchio non è centrato sul tuo paziente

La riflessione avviene rispetto al piano sagittale dell'origine della scena, non al piano sagittale del paziente. Se il paziente non è già centrato nella scena, il risultato uscirà sia speculare sia spostato: prevedi un passaggio di registrazione successivo per correggere lo scostamento.

Se qualcosa non va

Alcuni formati annunciati non funzionano più

L'interfaccia offre ancora le mesh (.vtk, .vtp, .stl, .off, .obj) come scansioni di input per le superfici intraorali, e le matrici in .npy; entrambe vengono contate nella barra di avanzamento, ma nessuna produce output: ogni file di quel tipo viene semplicemente saltato, con una riga nel log degli errori. Una matrice .txt funziona solo se è un vero file di trasformazione ITK, non un semplice array 4×4.

Un abbinamento fallito non dà alcun avviso

Se il nome di una scansione e quello di una matrice non si riducono allo stesso identificatore di paziente (vedi sopra), quel file semplicemente non viene mai trasformato: nessun messaggio di errore, nessun avviso visibile. Se un paziente manca dall'output, la prima cosa da controllare sono i nomi dei suoi file.

Un output può sovrascriverne un altro

Se deselezioni l'opzione che aggiunge il nome della matrice al file di output, e un paziente ha più di una matrice, ogni risultato riceve lo stesso nome di file: ciascuno sovrascrive il precedente e sopravvive solo l'ultima matrice elaborata. Tieni questa opzione selezionata ogni volta che applichi più di una matrice per paziente.

Un file di landmark può sparire in silenzio

Alcune trasformazioni (campi di deformazione densi, B-spline) non possono essere invertite matematicamente. Quando succede, il file di landmark corrispondente viene saltato con un semplice avviso nel log, mentre il volume stesso viene comunque trasformato, quindi una scansione e i suoi landmark possono ritrovarsi fuori sincrono senza nulla a schermo che lo segnali.

Le matrici non vengono concatenate

Quando un paziente ha più matrici, ciascuna viene applicata separatamente al file di input originale: ottieni un file di output per matrice, mai una composizione dell'una dopo l'altra.

Come citare

Nessuna pubblicazione, e nulla da pubblicare: il modulo applica in batch matrici di trasformazione ai file. Conta sapere che cos'è una matrice in Slicer e in quale sistema di coordinate si trova.

Nulla descrive il modulo in sé, quindi cita l'estensione come software:

SlicerAutomatedDentalTools. DCBIA-OrthoLab. https://github.com/DCBIA-OrthoLab/SlicerAutomatedDentalTools

Aggiungi la data di accesso se lo stile della tua rivista la richiede.

Contesto, non una citazione dello strumento

  • Documentation 3D Slicer: Coordinate systems. RAS, LPS, e perché una matrice corretta applicata nel sistema sbagliato capovolge il paziente.
